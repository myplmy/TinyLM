- 제출 판정: **PASS_WITH_WARNINGS**
- 생성 문항: 4,500개
- 난이도: easy 10%, mid 70%, hard 20%

## 2. 범위와 오염 방지

생성 과정에서는 다음 금지집합의 전문을 열람하거나 별도로 덤프하지 않았다.

1. 기존 held-out v2.7 300문항 전문
2. `ko-en` 600M·1200M 학습 코퍼스 원문
3. stage1~stage10 고밀도 데이터셋

학습 캐시와의 접촉은 사용자가 승인한 기존 감사 스크립트가 토큰 캐시를 읽는 경우로만 제한했다. `Z:\TinyLM\scripts` 아래 감사 코드는 수정하지 않았다. 실행 환경은 `W:\miniforge3\envs\tinydataset\python.exe`이며, 설치된 `tokenizers`를 사용했다.

## 4. 작성 설계

### 4.1 난이도

- easy: 문두가 관계를 직접 제시하며 관계의 방향을 정확히 대응하면 풀린다.
- mid: 오답도 문두의 대상과 관계 어휘를 공유한다. 문두의 대조 조건, 방향, 역할을 실제로 읽어야 한다.
- hard: 문두에 명시된 두 개 이상의 규칙을 이어 중간 상태를 한 단계 계산해야 한다. 애매함이나 최신·전문 지식으로 난도를 만들지 않았다.

모든 문항은 닫힌 문두 안에서 답을 결정하도록 작성했다. 실제 인물·기관·제품명 대신 색, 모양, 물체, 작업 단계 등을 조합한 가상 대상을 사용했다.

### 4.2 후보 배타성 설계

정답과 오답의 핵심 명제는 관계별로 다음처럼 갈라지게 만들었다.

| 관계 | 서로 배타적으로 만든 핵심 대비 |
|---|---|
| 인과 | 정방향 원인 / 역방향 원인 / 단순 동시·선후 / 원인 없음 |
| 시간순서 | A가 먼저 / B가 먼저 / 동시 / 순서 미정 |
| 부분전체 | A가 B의 부분 / B가 A의 부분 / 내부 위치만 성립 / 부분 관계 없음 |
| 반의 | 반대 의미 / 같은 의미 / 인과 관계 / 상하위 관계 |
| 상하위 | A가 B의 하위 / B가 A의 하위 / 같은 범주 / 범주 관계 없음 |
| 목적수단 | 정방향 수단 / 역방향 수단 / 결과를 수단으로 오인 / 직접·간접 단계 오인 |
| 조건 | 필요·충분 방향 / 역방향 / 조건 불충족 / 조건과 무관 |
| 대조 | 문두의 두 속성 유지 / 둘 다 첫 속성 / 속성 역전 / 둘 다 둘째 속성 |

후보 뒤에 붙은 공통 표면 문장은 핵심 명제를 바꾸지 않는다. 오답은 거짓인 핵심 명제와 참인 공통 문장의 결합이므로 전체로도 오답으로 남는다.

### 4.3 표면형·길이 균형

초기 생성본은 후보 의미를 유지한 채 두 단계로 표면을 균형화했다.

1. 네 후보 모두에 같은 종류의 범위 제한 문장을 붙여 정답만 부정형이 되는 단서를 제거했다.
2. 실제 `ko-en` 32,768 토크나이저로 후보를 재어, 의미를 바꾸지 않는 관계 메타 문장의 자연스러운 변형 중 토큰 수가 같은 조합을 선택했다.

최종적으로 모든 문항에서 후보 네 개의 토큰 수가 같아졌다. 4,357문항은 문자 수도 네 후보가 같고, 나머지 143문항은 정답의 문자 길이가 오답의 최솟값과 최댓값 사이에 오도록 골랐다. 최대 문자 수 차이는 5자다.

## 7. 감사 한계와 사용 조건

1. 8-token 전수·전 창·후보 포함 검사는 기존 도구로 완료되지 않았다. 현재 증거는 8-token 문두 표본과 13-token 문두·후보 전수의 결합이다.
2. 금지집합 고유명사 전용 비교 도구가 없어 독립 기계 검증을 완료하지 못했다.
3. 후보 의미 배타성은 관계별 템플릿 설계와 표본 검토 근거이며, 독립된 사람의 4,500문항 전수 의미 감사 결과는 아니다.
4. 공통 표면 문장이 후보를 길게 만들고 반복률을 높였다. 모델 비교에 사용하기 전에 항목군 상관, 선택지 제거 실험, 무작위 표본 사람 검수를 권한다.
5. 모든 토큰 길이가 동률인 설계는 길이 선택기를 제거하지만 자연스러운 후보 길이 변동도 제거한다. 이후 판본에서는 정답이 중간 순위가 되도록 자연 문장 자체를 다시 쓰는 방식과 비교할 가치가 있다.

## 8. 최종 파일 무결성

- JSON 레코드: 4,500개
- JSONL 행: 4,500개
- JSON과 JSONL의 레코드 내용 및 순서: 동일
- ID 범위와 중복: `v28-0001`~`v28-4500`, 중복 0건
- 레코드 키·순서: 요청 스키마와 동일
- 제출 폴더에는 JSON, JSONL, 이 보고서만 둔다.

감사 도구와 토크나이저 환경은 수정하지 않았다. 감사용 임시 투영본과 보조 실행 파일은 최종 제출 전에 삭제했다.
