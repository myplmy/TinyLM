# TinyLM Stage 1~Stage 7 연속성 기준 문서

작성 목적: 새 세션에서 TinyLM 교육 설계를 이어갈 수 있도록 현재까지 합의된 Stage 구조, Stage 1 교육 내용, 데이터셋 비율, 교육 원칙, corpus 작성 규칙, train/validation 분할 기준을 정리한다.

> 주의: 현재 대화에서 구체적으로 확정된 것은 **Stage 1의 세부 구성과 데이터 설계 원칙**이다. Stage 2~Stage 7은 현재 대화 맥락에서 세부 토큰 비율·정확한 데이터셋 목록까지 모두 확정된 상태가 아니므로, 아래에서는 **현재까지 유지된 역할 수준의 상위 구조**를 정리하고, 확정되지 않은 세부 수치는 임의로 만들지 않는다.

---

## 1. 전체 목표

대상 모델은 약 100M 파라미터급 TinyLM이다. 교육 목표는 단순 지식 암기보다 다음 순서의 기반 능력을 형성하는 것이다.

1. 대상과 개념을 식별한다.
2. 대상의 속성과 상태를 구별한다.
3. 기능·용도·목적을 연결한다.
4. 개념 경계와 반례를 구별한다.
5. 부분–전체 및 공간·비교 관계를 이해한다.
6. 문맥 안에서 여러 개념을 동시에 유지한다.
7. 타입·부정·불확실성을 구분한다.
8. 이후 단계에서 더 복합적인 관계·추론·지시·대화·문제해결 능력으로 확장한다.

핵심 철학은 **초기에는 세계를 구성하는 기본 ontology와 관계를 먼저 가르치고, 이후 조합·추론·행동·대화 수준으로 올라가는 curriculum**이다.

---

# 2. Stage 1~Stage 7의 상위적 역할

아래는 현재 논의의 연속성을 위한 상위 역할 정의다. 정확한 Stage별 세부 데이터 비율은 향후 문서에서 별도로 확정할 수 있다.

## Stage 1 — 개념·속성·관계의 기초 ontology

목표:
- “무엇인가?”
- “어떤가?”
- “무엇과 어떤 관계인가?”
- “어떤 조건에서 달라지는가?”

핵심:
- 대상/정체성/분류
- 속성/정도/변이
- 기능/용도/목적
- 개념 경계/반례
- 부분–전체
- 상태/상태 변화
- 공간 관계
- 비교/대조
- 문맥 통합
- 타입/부정/불확실성

Stage 1의 역할은 **세계 모델의 기초 단위를 분리하고 연결하는 것**이다.

## Stage 2 — 복합 관계·의존·인과·조건적 구조

역할:
- 관계가 단순한 이항 연결을 넘어 조건과 맥락에 따라 달라짐을 학습
- 인과, 조건, 의존, 가능성, 시간 순서 등을 결합
- 여러 관계가 동시에 존재하는 상황을 해석

핵심 방향:
- 조건부 관계
- 원인–결과
- 의존성
- 가능성
- 시간적 선후
- 상태 전이
- 다중 관계 조합

## Stage 3 — 절차·행동·계획·문제 해결

역할:
- 목표를 설정하고 자원을 이용하며 제약 아래 행동하는 구조를 학습
- 규칙과 절차를 순서화
- 행동 전후의 상태 변화를 연결

핵심 방향:
- 목표
- 계획
- 단계
- 제약
- 자원
- 선택
- 우선순위
- 문제 해결
- 실패/복구

## Stage 4 — 문맥·담화·지시·대화 구조

역할:
- 여러 문장에 걸친 의미 유지
- 이전 발화와 현재 발화 연결
- 대화에서 참조·생략·의도·응답을 처리

핵심 방향:
- 담화 일관성
- 참조 해소
- 대화 상태
- 질문–응답
- 지시 추적
- 대화 목적
- 화행
- 암시와 맥락 의존

## Stage 5 — 일반화·추론·전이

역할:
- 학습한 개념을 새로운 사례에 적용
- 반례·경계·조건 변화에 강건한 일반화
- 유사 구조의 다른 도메인 전이

핵심 방향:
- 귀납·연역적 구조
- 비교 기반 일반화
- 반례 활용
- 개념 전이
- 구조 전이
- 새로운 조합
- 규칙 일반화

## Stage 6 — 지식 통합·장문맥·복합 문제

역할:
- 여러 개념군과 긴 맥락을 동시에 유지
- 정보 검색 없이도 주어진 문맥 내부의 복합 문제 해결
- 다단계 추론과 다중 제약 처리

핵심 방향:
- 장문맥 유지
- 다단계 추론
- 복합 제약
- 다중 목표
- 정보 통합
- 불확실성 관리

## Stage 7 — 지시 수행·대화·실전 사용

역할:
- 실제 사용자 요청을 이해하고 적절한 행동/응답 형식으로 출력
- instruction following과 대화 안정성을 강화
- 최종적으로 채팅/업무 수행형 능력으로 연결

핵심 방향:
- 명령 이해
- 응답 형식 준수
- 다턴 대화
- 도구·프로토콜 확장 가능성
- 안전·불확실성 처리
- 실전 task 수행

> Stage 2~7의 위 설명은 **상위 curriculum 역할**이다. 각 Stage의 구체적인 token mixture, dataset size, train/val 비율은 별도 사양서에서 확정해야 한다.

# 3. Stage 1의 확정 3M-token mixture

현재 확정된 Stage 1은 총 3M tokens이다.

```text
3M Stage 1
├── 대상·정체성·분류       540K
│   ├── train 486K
│   └── val    54K
├── 속성·정도·변이         420K
├── 기능·용도·목적         360K
├── 개념 경계·반례         420K
├── 부분–전체              300K
├── 상태·상태 변화         300K
├── 공간 관계              210K
├── 비교·대조              180K
├── 문맥 통합              150K
└── 타입·부정·불확실성    120K
```

합계:

```text
540 + 420 + 360 + 420 + 300 + 300 + 210 + 180 + 150 + 120 = 3,000K
```

# 4. Stage 1에서 무엇부터 많이 가르쳐야 하는가

Stage 1에는 두 가지 비율 체계를 구분해서 사용한다.

1. **3M-token 실제 mixture 비율**: 각 데이터셋에 실제로 배정하는 token 예산이다.
2. **교육 우선순위 비율**: 100M급 모델을 어떤 개념부터 많이 노출시키는 것이 바람직한지에 대한 교육 원칙이다.

## 4.1 3M-token 권장 초기 mixture — 실제 데이터 배분

현재 Stage 1의 권장 초기 mixture는 다음과 같다. 총량은 정확히 **3M tokens**이다.

| 영역 | 비율 | token | 비고 |
|---|---:|---:|---|
| 대상·정체성·분류 | **18%** | **540K** | train 486K + val 54K |
| 속성·정도·변이 | **14%** | **420K** | 속성의 정도·변이·조건 의존성 포함 |
| 기능·용도·목적 | **12%** | **360K** | 사물·행동·기능 목적 연결 |
| 개념 경계·반례 | **14%** | **420K** | 과잉 일반화 억제 및 경계 학습 |
| 부분–전체 | **10%** | **300K** | part–whole 방향성 포함 |
| 상태·상태 변화 | **10%** | **300K** | 현재 상태와 변화 구분 |
| 공간 관계 | **7%** | **210K** | 위치·방향·포함 등 관계 |
| 비교·대조 | **6%** | **180K** | 공통점과 차이 동시 학습 |
| 문맥 통합 | **5%** | **150K** | 여러 개념의 문맥 내 동시 활성화 |
| 타입 구분·부정·불확실성 | **4%** | **120K** | Entity/Attribute/Quantity/Relation/State/Action 및 부정·불확실성 |
| **합계** | **100%** | **3M** | |

대상·정체성·분류는 540K 중 **train 486K(90%) / validation 54K(10%)**로 분할한다. Validation은 학습 데이터와 별도로 유지하며 학습 상태·과적합 감시 및 모델 선택에 사용하고, 최종 benchmark/held-out과는 분리한다.

## 4.2 교육 우선순위 — 무엇부터 많이 가르치는가

3M mixture와 별개로, 개념을 설명하는 우선순위는 다음과 같다. 이는 전체 Stage 1 curriculum의 **교육적 중요도**를 나타내며, 각 데이터셋의 실제 token 비중을 의미하지 않는다.

| 순위 | 교육 내용 | 권장 우선순위 | 핵심 질문 |
|---|---|---:|---|
| 1 | 대상과 개념의 정체성 | **25%** | 이것은 무엇인가? |
| 2 | 속성 | **15%** | 이것은 어떤가? |
| 3 | 기능·용도 | **12%** | 이것은 무엇에 사용되는가? |
| 4 | 개념 경계·반례 | **12%** | 무엇과 무엇이 다른가? |
| 5 | 부분·전체 | **10%** | 무엇이 무엇의 일부인가? |
| 6 | 상태·상태 변화 | **8%** | 지금 어떤 상태이며 어떻게 변하는가? |
| 7 | 공간 관계 | **6%** | 어디에 있고 어떻게 배치되는가? |
| 8 | 비교·대조 | **5%** | 무엇이 같고 다른가? |
| 9 | 문맥 통합 | **4%** | 한 상황에서 여러 개념이 어떻게 함께 활성화되는가? |
| 10 | 타입 구분 + 부정 + 불확실성 | **3%** | 이 정보의 타입과 확실성은 무엇인가? |

두 표의 숫자는 의도적으로 다르다. 예를 들어 **개념 경계·반례는 실제 mixture에서는 14%로 높게 배정**하지만, 교육 우선순위 표에서는 12%로 표현한다. 이는 경계 학습을 핵심 축으로 유지하되 전체 curriculum을 단순한 10개 항목의 동일 척도로 해석하지 않기 위해서다.

# 5. Stage 1 핵심 교육 원칙

## 5.1 정체성과 속성을 섞지 않는다

정체성:

> 고양이는 동물이다.

속성:

> 고양이는 털을 가진다.

또는:

> 고양이는 민첩하다.

두 문장은 기능적으로 다르다.

- `is_a / category` → 정체성·분류
- `has_property / degree` → 속성

특히 속성 corpus에서는 **“이것은 무엇인가?”**가 아니라 **“이것은 어떤가?”**에 집중한다.

## 5.2 속성과 관계를 섞지 않는다

예:

> 컵은 용기다.

→ 정체성/분류

> 컵은 단단하다.

→ 속성

> 컵은 상자 안에 있다.

→ 공간 관계

따라서 `inside`, `above`, `part_of` 등 관계를 대상의 고유 속성으로 오인시키지 않는다.

## 5.3 같은 단어라도 정보 타입이 다르면 분리한다

예:

- 사람 → Entity
- 빨간색 → Attribute
- 세 개 → Quantity
- 책상 위 → Relation
- 열림 → State
- 달리기 → Action

이 구분은 이후 type/ontology 기반 추론의 기초가 된다.

## 5.4 개념 경계가 매우 중요하다

100M 모델은 쉽게 동시 발생을 동일성의 증거로 취급할 수 있다.

예:

> 날아다닌다고 모두 새인 것은 아니다.

> 크다고 반드시 무거운 것은 아니다.

> 금속이라고 모두 도구인 것은 아니다.

따라서 Stage 1에는 **positive example + boundary example + counterexample**가 함께 필요하다.

## 5.5 상관과 동일성을 분리한다

다음과 같은 과잉 일반화를 적극적으로 막는다.

```text
A가 B와 자주 함께 등장한다
→ A는 B다

A가 B를 자주 가진다
→ B는 A의 정의다

A에서 B가 자주 관찰된다
→ A가 B의 충분조건이다
```

Stage 1에서는 이러한 추론을 자동적으로 강화하기보다, **반례·부정·경계 사례**를 넣어 상관과 동일성을 분리한다.

## 5.6 관계는 방향성을 가진다

예:

```text
wheel --part_of--> bicycle
bicycle --has_part--> wheel
```

`part_of`와 `has_part`는 동일한 표현이 아니다.

마찬가지로:

```text
A inside B
B contains A
```

도 방향을 구분해야 한다.

## 5.7 상태는 대상 자체와 분리한다

예:

> 문은 열려 있다.

여기서 `문`은 대상이고 `열려 있음`은 상태다.

또한:

> 같은 문도 시간이 지나면 닫힐 수 있다.

를 통해 대상의 정체성과 상태 변화가 별개임을 학습한다.

# 6. 현재 Stage 1 데이터셋별 목적

## 6.1 대상·정체성·분류

질문:

> 이것은 무엇인가?

핵심:
- Entity identity
- category
- supertype/subtype
- 분류 경계
- 오분류 방지

현재 고밀도 corpus 작업에서는 매우 다양한 영역의 대상·개념을 단계적으로 확장하고 있다.

### 주요 세부 개념군
- 일상 사물
- 음식·조리·식품
- 의복·신체 착용물·개인용품
- 자연·생물·생태
- 과학·자연 현상
- 수학·논리·형식 개념
- 사회·제도·조직
- 문화·언어·예술·의사소통
- 교육·학습
- 공학·제조·인프라
- 의학·신체·건강 일반
- 상업·서비스·소비·물류
- 교통·여행·지리·도시생활
- 법률·권리·의무·분쟁
- 행정·공공서비스·정책
- 농업·축산·수산·식량 생산
- 생물학·생태 심화
- 지식·정보·데이터·기록·분류 체계
- 환경·기후·자원·에너지
- 건축·주거·공간 설계·시설 운영
- 조직·노동·고용·직업생활
- 교통·통신·미디어·디지털 사회
- 안전·재난·위험관리·비상대응
- 가족·사회생활·생활관계·인구
- 물질·재료·제품·도구·소비재
- 물리적 공간·방향·크기·형태·구조·경계
- 범용 시간 ontology
- 범용 인과·조건·의존성·가능성 ontology
- 집합·구성·소속·계층·상속·분류 관계 ontology
- 범용 정량 ontology
- 상태전이 ontology
- 관찰·증거·검증·확인·반증·판단 epistemic ontology

단, 이 목록은 **현재까지 생성한 고밀도 corpus의 개념군 이력**이며, Stage 1의 540K 전체를 이 목록이 완전히 소진했다는 뜻은 아니다.

## 6.2 속성·정도·변이

질문:

> 이것은 어떤가?

핵심:
- 정적 속성
- 정도
- 변이
- 환경 조건에 따른 변동
- 시간에 따른 변화
- 평가 속성
- 능력/성향/상태

현재는 378K-token train 목표를 위해 **4,650개 고밀도 packet** 기준으로 약 150개 단위 버전을 지속적으로 확장하고 있다.

## 6.3 기능·용도·목적

질문:

> 이것은 무엇에 사용되는가?

핵심:
- 도구 → 목적
- 대상 → 기능
- 행동 → 목적
- 수단 → 결과

향후 instruction following과 연결하기 쉬운 영역이다.

## 6.4 개념 경계·반례

질문:

> 이것과 저것을 왜 구분하는가?

핵심:
- 반례
- 필요조건/충분조건의 직관
- 인접 개념 차이
- false generalization 방지
- 조건에 따른 분류 변화

Stage 1 핵심 축 중 하나다.

## 6.5 부분–전체

핵심:
- part_of
- has_part
- 구성요소
- 구성과 전체의 방향성
- 전체와 부분의 속성 상속 오류 방지

## 6.6 상태·상태 변화

핵심:
- open/closed
- on/off
- intact/damaged
- liquid/solid 등
- 상태 변화
- 시간에 따른 변화

정체성과 상태의 분리를 강화한다.

## 6.7 공간 관계

핵심:
- inside/contains
- above/below
- near/far
- left/right
- adjacent
- boundary

중요:

## 6.8 비교·대조

핵심:

# 7. Stage 1 속성·정도·변이 corpus 작성 방식

## 7.1 기본 질문

모든 속성 packet은 가능한 한 다음 질문에 답해야 한다.

> 이것은 어떤가?

또는:

> 이 특성이 어느 정도인가?

> 조건이 바뀌면 이 특성이 어떻게 달라지는가?

## 7.2 정의형 문장보다 속성형 문장을 우선한다

권장:

> 고양이는 민첩하다.

> 이 재료는 열에 민감하다.

> 이 구조는 반복 하중에 안정적이다.

> 이 신호는 잡음에 민감하다.

비권장:

> 민첩성이란 동물이 빠르게 움직일 수 있는 능력을 말한다.

후자는 개념 정의를 가르치는 내용이고, 속성·정도·변이 corpus의 직접 목적과 다르다.

## 7.3 속성 + 정도 + 경계 조합

가능하면 하나의 개념을 다음처럼 구성한다.

```text
속성 존재
→ 정도
→ 조건 변화
→ 인접 속성과 구분
```

예:

> 이 물질은 열전도성이 높다.

> 같은 물질도 온도가 달라지면 열전도성이 변할 수 있다.

> 열전도성은 실제 전달된 열량과 같은 개념이 아니다.

## 7.4 정적 속성과 변화율을 분리한다

```text
열전도성       = 현재 속성
열전도도변화율 = 조건 변화에 따른 변화량의 비율
열민감도       = 온도 변화에 대한 반응 정도
```

이 구분은 현재 속성 corpus 전체에서 매우 중요한 원칙이다.

## 7.5 속성과 측정값을 분리한다

```text
내열성       = 성질
실제 노출온도 = 조건값
열화속도     = 변화율
내열성 평가값 = 측정/판정값
```

## 7.6 성향·능력·상태를 분리한다

예:

- 자기조절능력 → 능력
- 충동성 → 성향
- 불안수준 → 상태
- 집중도 → 현재/관찰 상태
- 판단신중성 → 성향

동일 문맥이라도 ontology가 달라진다.

# 8. 고밀도 packet 작성 포맷

현재 속성 train packet의 기본 형식은 다음과 같다.

```json
{
  "id": "S1-ATH-XXXX",
  "type": "attribute_packet",
  "split": "train",
  "text": "한국어 속성 문장",
  "concepts": ["개념1", "개념2"],
  "relations": ["attribute", "degree", "boundary"]
}
```

## 필드 원칙

### id
- `S1-ATH-` 접두사
- 버전 간 중복 금지
- 150개 단위로 연속 관리

### type
- 속성·정도·변이 train은 `attribute_packet`

### split
- train packet은 `train`
- validation은 `val`
- benchmark/held-out는 별도의 split 관리

### text
- 실제 한국어 Unicode 문자 사용
- 한국어를 `\uAC00` 식으로 저장하지 않음
- 지나치게 긴 정의문보다 짧고 밀도 높은 문장
- 속성 자체와 대상의 정체성을 혼합하지 않음

### concepts
- 핵심 개념을 명시
- 가능하면 속성명 + 관련 개념을 함께 기록

### relations
- 정보 유형을 구분
- 예: `attribute`, `degree`, `boundary`, `measurement`, `sensitivity`, `variability`, `capability`, `state` 등

# 9. 150개 단위 버전 생성 규칙

현재 고밀도 corpus는 150개 단위로 확장한다.

기본 원칙:

1. 한 버전은 하나의 명확한 concept family를 중심으로 구성한다.
2. 바로 앞 버전에서 다루지 않은 새로운 개념군으로 이동한다.
3. 동일 단어의 단순 변형만 150개 채우지 않는다.
4. 가능하면 정적 속성, 정도, 변화, 민감도, 안정성, 변동성을 조합한다.
5. 인접 개념의 경계를 일부 포함한다.
6. 너무 넓은 범위로 흩어지지 않고 하나의 ontology family를 유지한다.

현재 속성 train은 v17까지 진행된 상태이며, 총 2,550개의 packet이 축적되었다는 작업 기준을 사용했다.

# 12. Train / Validation / Held-out 원칙

Stage 1에서는 세 split을 역할에 따라 분리한다.

## Train

모델의 파라미터를 실제로 업데이트하는 데이터.

목적:
- 개념 학습
- 속성 학습
- 관계 학습
- 규칙/경계 학습

## Validation

학습 과정 중 모델 선택·과적합 감시에 사용하는 데이터.

원칙:
- train에 직접 포함하지 않는다.
- 모델의 hyperparameter/epoch/schedule 선택에 반복 사용될 수 있으므로 benchmark보다 덜 엄격하지만, training examples로 직접 쓰면 안 된다.

## Held-out / Benchmark

최종 일반화 평가 전용.

원칙:
- 모델 파라미터 업데이트에 사용하지 않는다.
- hyperparameter 선택에도 사용하지 않는 것이 이상적이다.
- 최종 benchmark로 취급해야 한다.

---

# 13. 대상·정체성·분류의 train/validation 비율

540K token을 다음과 같이 나눈다.

```text
train = 486K = 90%
val   =  54K = 10%
```

즉 **90 : 10**이다.

중요:

- 1,000개의 초기 prototype을 900 train + 100 val로 나눈 것은 초기 소규모 prototype 구조였다.
- 현재 3M Stage 1 설계에서는 **대상·정체성·분류 540K 중 486K train + 54K val**로 확장했다.
- held-out benchmark는 이 540K에 섞지 않고 별도 corpus로 관리한다.

---

# 14. Validation 분할 기준

Validation은 단순 랜덤 분할만으로 만들지 않는 것이 좋다.

기준:

1. train과 validation 사이의 직접 문장 중복 방지
2. 가능하면 동일 문구/동일 패턴의 단순 변형이 양쪽에 동시에 몰리지 않도록 함
3. 핵심 개념 coverage를 유지
4. 특정 하나의 domain이 validation 전체를 대표하지 않도록 균형 유지
5. 새로운 개념 조합을 포함하되, 완전히 benchmark만큼 공격적인 unseen split으로 만들지는 않음

대상·정체성·분류에서는 다음 기준을 권장:

- 90% token → train
- 10% token → validation
- 각 세부 concept family가 양쪽에 어느 정도 존재
- 너무 유사한 template cluster를 양쪽에 복제하지 않음

---

# 15. Held-out benchmark 분리 원칙

Held-out은 validation보다 더 엄격하다.

### 목적

> “훈련/튜닝에 쓰지 않은 새로운 조합에서도 기본 ontology 능력이 유지되는가?”

### 기존에 사용한 benchmark 축

- unseen concept
- novel relation
- boundary / counterexample

단, `unseen_concept`라는 라벨은 실제 train corpus가 정의하는 unseen 기준과 일치할 때만 강한 의미를 갖는다.

따라서 train을 변경하면 held-out의 “unseen” 의미도 다시 검증해야 한다.

---

# 16. 외부 LLM judge를 사용하지 않는 평가 원칙

현재 방향은 외부 LLM judge를 필수로 사용하지 않는 것이다.

가능한 평가:

1. teacher-forced token CE
2. paired CE difference
3. likelihood / pseudo-log-likelihood
4. 다지선다형 우도 비교
5. 결정적 문자열 채점이 가능한 경우의 exact match / F1 등
6. 구조적 정답이 있는 deterministic scorer

반대로 base LM에서 자유 생성 후 자연어 답변을 문자열 비교하는 방식은 SFT가 없을 경우 매우 불안정할 수 있다.

---

# 17. Stage 1에서 특히 중요한 anti-overgeneralization 원칙

100M급 소형 모델에서는 다음 문제가 특히 중요하다.

## 17.1 공존을 동일성으로 오인

```text
A와 B가 함께 등장
→ A = B
```

## 17.2 상관을 정의로 오인

```text
A에 B가 자주 나타남
→ B는 A의 정의
```

## 17.3 속성을 필요조건으로 오인

```text
A는 빨갛다
→ 빨간 것은 모두 A다
```

## 17.4 조건을 무시

```text
A는 대부분 B다
→ A는 항상 B다
```

따라서 다음 구조를 반복한다.

```text
positive
+ counterexample
+ boundary
+ condition
```

# 18. 속성 corpus에서 피해야 할 패턴

## 18.1 사전식 정의를 과도하게 반복

```text
X란 Y를 의미한다.
X란 Y를 의미한다.
X란 Y를 의미한다.
```

이 방식만 늘리면 정의 암기 편향이 강해진다.

## 18.2 대상과 속성을 섞은 문장

```text
고양이는 동물이다. 털이 있다.
```

한 문장 안에서 분류와 속성을 동시에 밀어 넣는 것보다 분리된 packet이 낫다.

## 18.3 같은 속성의 동의어만 반복

```text
빠르다
민첩하다
신속하다
```

단순 동의어 반복보다는:

```text
속도
속도 정도
속도 변동성
속도 안정성
속도 민감도
```

처럼 ontology를 확장한다.

## 18.4 평가값을 속성 자체로 착각

```text
정확도 95%
```

는 측정값이다.

```text
정확성이 높다.
```

는 속성이다.

둘을 구분한다.

# 20. 향후 새 세션에서의 작업 재개 규칙

새 세션에서는 다음 상태를 기준으로 이어간다.

### 현재 확정

```text
Stage 1 = 3M tokens
대상·정체성·분류 = 540K = train 486K + val 54K
속성·정도·변이 = 420K
기능·용도·목적 = 360K
```

# 21. 핵심 한 문장 요약

**Stage 1은 100M급 모델에게 세상의 기본 단위를 먼저 분리해서 가르치는 단계이며, 정체성 → 속성 → 기능 → 경계 → 부분/전체 → 상태 → 공간 → 비교 → 문맥 → 타입/부정/불확실성 순으로 ontology를 형성하고, 속성 corpus에서는 특히 “무엇인가”와 “어떤가”를 엄격히 분리하며, train/validation/held-out을 각각 학습·선택·최종검증의 역할로 분리한다.**
