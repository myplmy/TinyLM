## 0. 가장 중요한 현재 상태

이 문서를 읽은 다음 **바로 v19를 생성하지 말 것. 먼저 v18의 실제 파일 상태를 확인하고 재작성해야 한다.**

대화 기록상 v18은 한 차례 자동생성형 문구 문제를 지적받은 뒤 “300개 text를 전부 직접 재작성했다”고 정리되었으나, 현재 작업 디렉터리에 실제로 존재하는 파일을 확인하면 다음과 같다.

```text
/mnt/data/stage1_(2)attribute_high_density_train_v18.json
size: 227,329 bytes
record_count: 300
range: S1-ATH-2551 ~ S1-ATH-2850
```

현재 파일 첫 항목 예시:

```json
{
  "id": "S1-ATH-2551",
  "type": "attribute_packet",
  "split": "train",
  "text": "이 시스템은 역치민감도 수준이 높아 작은 조건 변화에도 반응이 시작되는 입력 경계가 크게 달라진다. 입력 범위가 달라지면 이 속성의 정도가 달라질 수 있어 하나의 조건에서 얻은 수준을 모든 상황에 그대로 적용하면 안 된다. 역치의 위치·선명함·변동은 실제 응답 크기나 입력의 절대량과 같은 개념이 아니다.",
  "concepts": ["역치민감도"],
  "relations": ["attribute", "threshold", "degree", "variability", "boundary"]
}
```

이 파일은 구조적으로는 유효하지만, 최신 사용자 규칙인 **“text 문구는 프로그램/보일러플레이트로 만들지 말고 모델이 직접 작성해야 하며, 문장 구조 패턴 반복과 높은 유사도를 피해야 한다”**를 만족하는 최종본이라고 보기 어렵다.

따라서 상태를 다음처럼 구분한다.

- **프로젝트 논리상 진행 위치:** v18, 300개, `S1-ATH-2551 ~ S1-ATH-2850`, 누적 2,850개까지 진행한 것으로 관리.
- **품질 승인 상태:** v18은 **재작성 필요**. 현재 파일을 그대로 학습 corpus 최종본으로 사용하지 말 것.
- **안전한 재개 순서:** v18을 같은 ID/concept family로 전면 재작성 → 검증 → 그 다음 v19 생성.

# 1. 프로젝트 전체 맥락

대상 모델은 약 **100M 파라미터급 TinyLM**이다.

Stage 1의 역할은 세계를 구성하는 기본 ontology를 분리하여 학습시키는 것이다.

핵심 질문은 다음과 같다.

```text
대상·정체성·분류      → 이것은 무엇인가?
속성·정도·변이        → 이것은 어떤가?
기능·용도·목적        → 무엇에 사용되는가?
개념 경계·반례        → 무엇과 무엇이 다른가?
부분–전체             → 무엇이 무엇의 일부인가?
상태·상태 변화        → 지금 어떤 상태이며 어떻게 변하는가?
공간 관계             → 어디에 있고 어떻게 배치되는가?
비교·대조             → 무엇이 같고 다른가?
문맥 통합             → 여러 개념이 한 상황에서 어떻게 함께 활성화되는가?
타입·부정·불확실성   → 정보 타입과 확실성은 무엇인가?
```

Stage 1 총량은 **3M tokens**이며, 현재 작업 중인 속성·정도·변이 영역은 420K 중 train 고밀도 부분을 **378K tokens / 4,650 packet** 기준으로 확장하고 있다.

기준 문서:

```text
TinyLM_Stage1_Stage7_Master_Continuity_Summary.md
```

# 2. 속성·정도·변이 corpus의 핵심 원칙

## 2.1 속성은 “이것은 어떤가?”

속성 corpus는 정체성 corpus와 엄격히 분리한다.

정체성:

> 고양이는 동물이다.

속성:

> 고양이는 민첩하다.

즉 다음을 혼동하지 않는다.

```text
is_a / category        → 정체성·분류
attribute / degree     → 속성·정도
state                   → 상태
relation                → 관계
quantity                → 양/측정값
```

## 2.2 사전식 정의문 위주로 쓰지 않는다

비권장:

> 역치민감도란 역치가 조건 변화에 따라 달라지는 정도를 의미한다.

권장 방향:

> 같은 센서라도 주변 잡음이 커지면 작동을 시작하는 입력 경계가 쉽게 움직일 수 있다. 이런 장치는 역치가 조건에 민감한 편이다. 경계가 낮다는 사실과 경계가 쉽게 움직인다는 성질은 구분해야 한다.

즉 **개념을 정의하는 문장보다, 실제 대상·상황에서 그 속성이 어떻게 나타나는지**를 쓴다.

## 2.3 하나의 packet 안에서 가능한 정보

항상 같은 순서를 강제하지 말고 필요에 따라 다음 요소를 자연스럽게 조합한다.

- 속성의 존재 또는 정도
- 조건에 따른 변화
- 시간 또는 사례별 변이
- 인접 속성과의 경계
- 대표적 반례 또는 오해 방지
- 관찰/측정값과 속성 자체의 구분

중요: **모든 레코드를 동일한 3문장 구조로 만들지 않는다.**

2문장, 3문장, 4문장 등 자연스럽게 분산할 수 있다. 핵심은 의미 밀도이지 문장 수 통일이 아니다.

# 3. 최상위 금지 규칙 — 반드시 유지

## 3.1 Python/스크립트/템플릿으로 text 생성 금지

사용자의 최신 명시 규칙:

> 파이썬 코딩을 통한 보일러플레이트 작성금지.
> corpus에서 반복이나 중첩발생, 문장간 유사도가 매우 높은 경우 학습시에 의미나 관계가 아닌 문장 구조 패턴만을 학습하게 될 가능성이 있음.
> 형식에 맞추어 작성하도록 자동화하는 것은 상관없으나, text에 들어가는 문구 자체는 반드시 ChatGPT가 직접 작성할 것.

따라서 Codex에서도 다음을 금지한다.

```text
금지:
- concept 목록 + 템플릿 문장 조합으로 text 자동 생성
- for loop로 접미사만 바꿔 300개 생성
- “X 수준이 높다 → 조건 변화 → Y와 다르다”를 반복 치환
- 문자열 포맷팅으로 의미 문장 생산
- 동일 문장 골격의 단순 paraphrase 대량 생성
```

허용:

```text
- ID 자동 부여
- JSON 구조 포장
- ensure_ascii=false 저장
- record_count 검증
- ID 연속성 검사
- concept 중복 검사
- exact text 중복 검사
- n-gram / cosine similarity 검사
- 문장 수/길이 통계
- UTF-8 / JSON 파싱 검증
```

즉 **자동화는 포맷·검증에만 사용하고, 의미를 담는 `text`는 모델이 직접 개별 작성한다.**

## 3.2 문장 골격 반복 금지

다음 패턴이 수십~수백 회 반복되지 않도록 한다.

```text
“이 시스템은 X 수준이 높아 ...”
“조건이 달라지면 이 속성의 정도가 달라질 수 있다 ...”
“X는 Y와 같은 개념이 아니다.”
```

경계 문장 자체는 필요하지만 문구와 배치가 계속 같아서는 안 된다.

변형 방법:

- 실제 사물/신호/조직/환경/행동/구조 등 주어를 다양화
- 첫 문장에서 사례를 먼저 제시하기
- 비교를 먼저 제시한 뒤 속성을 설명하기
- 부정/반례를 중간에 넣기
- 시간 변화와 조건 변화를 서로 다른 방식으로 배치
- 직접 비교, 예시, 조건문, 결과 관찰 등 담화 구조를 섞기

## 3.3 concept 이름만 바꾼 동의 구조 금지

예:

```text
역치안정성
역치변동성
역치민감도
역치회복성
```

이 네 개는 이름만 다른 것이 아니라 실제로 서로 다른 질문을 가져야 한다.

```text
역치안정성   → 같은 조건 반복에서 경계가 얼마나 유지되는가
역치변동성   → 사례/시간에 따라 경계가 얼마나 흩어지는가
역치민감도   → 조건을 조금 바꿀 때 경계가 얼마나 이동하는가
역치회복성   → 교란 후 경계가 이전 수준으로 얼마나 돌아오는가
```

# 4. JSON 기본 schema

속성 train packet 기본 형식:

```json
{
  "id": "S1-ATH-XXXX",
  "type": "attribute_packet",
  "split": "train",
  "text": "한국어 속성 문장",
  "concepts": ["핵심개념"],
  "relations": ["attribute", "degree", "boundary"]
}
```

필수 규칙:

- `id`: `S1-ATH-` 접두사
- `type`: `attribute_packet`
- `split`: `train`
- 실제 UTF-8 한국어 저장
- 한국어를 `\uXXXX`로 직렬화하지 않음
- `concepts`는 해당 packet의 핵심 개념이 드러나게 기록
- `relations`는 내용에 맞춰 `attribute`, `degree`, `variability`, `sensitivity`, `stability`, `boundary`, `measurement`, `response`, `threshold`, `saturation` 등 사용 가능

# 6. 현재 v18의 의도된 범위

파일명:

```text
stage1_(2)attribute_high_density_train_v18.json
```

권장 하위 축:

3. 포화 반응

8. 비선형 반응
9. 완충 특성
10. 감쇠·흡수·교란 억제

주요 의미 경계:


# 7. v18 재작성 절차 — Codex에서 가장 먼저 수행

## 7.1 기존 JSON의 구조만 읽는다

현재 v18에서 다음만 유지 가능:

- dataset-level metadata
- ID 2551~2850
- concept 목록
- relations는 의미가 맞으면 유지 또는 조정

**기존 text를 문장 변환/paraphrase 기반으로 대량 재활용하지 않는다.**

## 7.2 각 concept마다 text를 새로 직접 작성

각 레코드마다 먼저 내부적으로 질문한다.

```text
이 concept가 측정하는 속성은 정확히 무엇인가?
인접 concept와 무엇이 다른가?
어떤 실제 상황에서 이 차이가 드러나는가?
조건 변화/시간 변화/반례 중 무엇을 넣는 것이 가장 자연스러운가?
```

그 다음 text를 직접 작성한다.

권장:

- 다양한 도메인 사용: 센서, 재료, 생물 반응, 제어계, 네트워크, 조직, 환경, 학습 시스템, 기계, 신호 등
- 한 도메인에 몰리지 않기
- 같은 opening phrase를 반복하지 않기
- concept 이름을 반드시 첫 문장 주어로 쓰지 않아도 됨
- 적절하면 concept 용어를 뒤에서 해석적으로 연결

## 7.3 자동 검증

텍스트 작성 완료 후에만 스크립트 검증을 사용한다.

필수 검사:

```text
record_count == 300
IDs == S1-ATH-2551 ... S1-ATH-2850 연속
ID duplicate == 0
primary concept duplicate == 0 (의도된 경우 외)
empty text == 0
exact text duplicate == 0
JSON parse 정상
split == train
all type == attribute_packet
한국어 Unicode 실제 문자
\uXXXX Korean escapes == 0
```

유사도 권장 검사:

- 동일 5어절 이상 연속구가 서로 다른 record에서 반복되는지 탐색
- character 3~5 gram TF-IDF cosine similarity 상위 pair 점검
- sentence opening phrase 빈도 집계
- `따라서`, `조건이 달라지면`, `같은 개념이 아니다` 같은 연결구가 과도하게 몰리지 않는지 확인

**유사도 검사는 text를 자동 수정하기 위한 도구가 아니라 사람이/모델이 다시 직접 손볼 대상을 찾는 용도**로만 사용한다.

# 12. 품질 판단 기준

좋은 packet은 단순히 문법적으로 자연스러운 문장이 아니다.

다음 조건을 만족해야 한다.

1. 해당 concept의 의미 차이를 실제로 학습할 수 있다.
2. 인접 concept와 구별되는 정보가 있다.
3. 정의문 암기가 아니라 속성 판단으로 읽힌다.
4. 다른 레코드와 문장 구조가 과도하게 겹치지 않는다.
5. 특정 연결어/마무리 문구가 반복되지 않는다.
6. 모델이 문장 형식이 아니라 의미 관계를 학습하게 한다.
7. 가능한 경우 조건 변화, 정도, 안정/변동, 경계를 자연스럽게 포함한다.
8. 지나치게 추상적인 concept도 구체적 상황을 통해 이해 가능하게 쓴다.
