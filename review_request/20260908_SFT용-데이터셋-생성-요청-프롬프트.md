## 1. ★결론 먼저 — **지금 상태로는 SFT 에 못 쓴다. 그러나 재료는 다 있다**

사용자 물음: *"stage1_dataset(저밀도)와 고밀도 stage1 이 SFT 에 사용 가능한 상태인가."*

| 항목 | 확인 결과 |
|---|---|
| **저밀도 `stage1_dataset/train`** | 900 레코드. 필드 = `id · type · text · concepts · relations` |
| **저밀도 `train_v2`** | 같은 900 + ★**`paraphrases`(2개)** + ★**`near_negatives`(3개, `violated_relation`·`why_wrong` 포함)** |
| **고밀도 `stage1_highdensity_dataset/train`** | **227 파일 · 34,000 레코드 · 2,586,544자**(⚙1.0~1.7M 토큰). 필드 = `id · type · text · concepts · relations · boundaries · source_seed · relations_controlled` |
| 고밀도 `val` | 28 파일 · 4,200 레코드 · 300,029자 |
| **held-out v2.7** | 300 문항. ★**`prompt` · `answer` · `candidates`(4) · `correct_index` 를 가진 유일한 자산** |

🚫★★**둘 다 `instruction`/`response` 쌍이 한 건도 없다.** 전부 **서술문 코퍼스**다.
→ **SFT 데이터가 아니다.**

✅★**그러나 두 가지는 지금 바로 쓸 수 있다**:

| 용도 | 무엇 | 왜 지금 되나 |
|---|---|---|
| ★**계속 사전학습**(continued pretraining) | 고밀도 34,000 + 저밀도 900 의 `text` | `text` 한 필드면 우리 `prepare` 가 그대로 먹는다 |
| ★**SFT 생성의 스키마** | `concepts` · `relations` · `boundaries` · `near_negatives` | ★**질문·오답을 자동 생성할 재료가 이미 구조화돼 있다** |

★★**그리고 목표 형식이 이미 존재한다** — `held-out v2.7` 이 정확히 그 모양이다.
🚫**단 그것은 채점지이므로 학습에 쓰면 안 된다.** ★**같은 형식의 *학습용* 을 새로 만들어야 한다.**

## 2. ⚠️★가장 큰 위험 — **held-out 오염**

held-out v2.7 의 구성:

| split | 문항 | 뜻 |
|---|---:|---|
| `unseen_concept` | **113** | ★**학습에 안 나온 개념** — SFT 가 이것을 건드리면 벤치마크가 죽는다 |
| `novel_relation` | 90 | 개념은 봤고 관계가 새롭다 |
| `boundary` | 60 | 경계·반례 |
| `seen_concept_control` | 37 | ★일부러 본 개념(대조군) |

★**실사 결과**: held-out 문항의 주어 **214개 중 142개가 고밀도 train 의 `concepts`(40,948개)에 있다.**
이것은 **설계대로**다(`seen_concept_control` 이 그 자리). 🚫**그러나 SFT 를 같은 개념 풀에서
생성하면 `unseen_concept` 113문항이 무효가 된다** — 그러면 **우리 지능 축의 유일한 계기**를 잃는다.

★**근거**: 결과 074 §22 — 정확도를 가를 검정력이 있는 과제는 **held-out 하나**뿐이다
(필요 문항 **97** vs `arc_easy` 7,458 · `hellaswag` 7,963).

> ★★**따라서 §4 의 제외 규칙이 이 요청에서 가장 중요한 부분이다.**

## 4. ★★데이터셋 작성 LLM 에 그대로 전달할 프롬프트

> 아래 블록 전체를 복사해 전달한다. 🚫**우리 저장소 사정을 아는 표현을 뺐다** — 그쪽은 모른다.

```
[요청] TinyLM 한국어 Stage1 SFT 학습셋 생성

■ 배경
100M 급 한국어 소형 언어모델을 사전학습까지 마쳤다. 지금은 지시-응답(SFT) 학습을 한 번도
하지 않은 base LM 이라, 4지선다 우도 채점에서는 답을 고를 수 있지만 "질문에 답하는 형태"
자체를 배운 적이 없다. 그 격차를 메우는 최소 규모의 SFT 학습셋이 필요하다.

■ 기존 자산 (첨부)
1) 고밀도 서술문 코퍼스: 34,000 레코드.
   필드 = id, type, text, concepts[], relations[], boundaries[], relations_controlled[]
2) 저밀도 서술문 코퍼스 v2: 900 레코드.
   필드 = 위 + paraphrases[](2개), near_negatives[](3개; text, violated_relation, why_wrong)
3) 평가용 4지선다 300문항(★학습에 쓰면 안 되는 채점지).
   필드 = id, split, task, prompt, answer, candidates[4], correct_index,
          required_relations_canonical[], forbidden_relations_canonical[]

■ 만들 것
파일명: stage1_sft_train_v1.jsonl   (JSON Lines, UTF-8, 줄당 레코드 1개)
레코드 스키마:
{
  "id": "S1-SFT-00001",
  "source_id": "<재료가 된 서술문 레코드의 id. 없으면 null>",
  "task": "identity | attribute | function | relation | boundary | counterexample",
  "instruction": "<사용자 발화 한 문장. 물음표로 끝나는 질문이거나 명령형>",
  "input": "",
  "output": "<모델이 내야 할 답. 1~3문장. 근거를 한 문장 덧붙인다>",
  "concepts": ["<등장 개념>"],
  "relations": ["<사용된 관계 라벨>"],
  "rejected": "<틀린 답 1개. 왜 틀렸는지는 쓰지 말고 답 자체만>",
  "rejected_reason": "<틀린 이유. 사람이 읽는 칸>"
}

■ 분량과 구성
- 총 6,000 레코드. task 비율 = identity 30% / attribute 20% / function 15% /
  relation 15% / boundary 10% / counterexample 10%
- 재료의 near_negatives 를 rejected 로 재활용할 수 있으면 그렇게 한다.

■ ★★반드시 지킬 것 (이걸 어기면 전량 폐기해야 한다)
(1) 첨부 3)의 300문항에 등장하는 (주어 개념 + 관계) 조합을 하나도 만들지 않는다.
    특히 split 이 "unseen_concept" 인 113문항의 주어 개념은 어떤 형태로도 쓰지 않는다.
    "seen_concept_control" 37문항의 개념은 써도 되지만, 그 문항의 prompt/answer 문장을
    베끼거나 바꿔 쓰지 않는다.
(2) output 은 첨부 3)의 candidates 문장과 표면형이 겹치면 안 된다.
    "~라고 판단할 수 있다" 같은 그 파일 특유의 어미를 쓰지 않는다.
(3) instruction 과 output 은 서로 다른 사람이 쓴 것처럼 어휘를 겹치지 않게 한다.
    질문에 답이 그대로 들어 있으면 안 된다.
(4) rejected 는 "사실이 아닌 답" 이어야 한다. 애매하거나 부분적으로 옳은 문장은 금지.
    ★그리고 rejected 를 만들 때 부정할 대상을 output 이 아니라 instruction 에서 고른다.
      (output 에서 고르면 "지식이 많을수록 틀리는" 문항이 만들어진다.)
(5) 한 instruction 에 정답이 둘 이상 성립하면 안 된다.
(6) output 길이를 task 별로 고르게 맞춘다. 특정 task 만 길거나 짧으면 안 된다.
(7) 모든 문장은 한국어. 숫자·단위·고유명사만 원문 표기를 허용한다.

■ 함께 낼 것
- stage1_sft_train_v1_manifest.json :
  총 레코드 수, task 별 개수, 사용한 source_id 목록, ★첨부 3)과 겹친 개념 목록(있으면),
  평균/최소/최대 output 길이(문자·어절), 자기검증 결과((1)~(7) 각 항목의 위반 건수)
- 위반이 0 이 아니면 그 목록을 함께 낸다. ★0 이라고 적기 전에 실제로 세어 본다.
```

## 6. ⚠️정직하게 — **이 요청이 성과를 낼지 모른다**

- ★**SFT 가 base LM 의 *지식* 을 늘리지는 않는다.** 늘리는 것은 **형식 정합**이다.
  우리 문제(결과 074 §22)는 *"정답CE 는 맞는데 argmax 가 어긋난다"* 이고,
  **그것이 형식 문제라면 SFT 가 고치고 지식 문제라면 안 고친다.** ⚠️**어느 쪽인지 모른다.**
- ⚠️**6,000 레코드는 우리 사전학습 300M 토큰의 ⚙0.1% 미만**이다. 효과가 작을 수 있다.
- ★**그래도 여는 이유**: 이 경로가 **배포 상주를 한 바이트도 안 쓴다.**
  그리고 held-out 이 **필요 문항 97** 로 검정력이 있으므로 **효과가 있으면 보인다.**
