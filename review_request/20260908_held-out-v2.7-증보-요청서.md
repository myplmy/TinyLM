## 1. 왜 증보하나 — **개수가 아니라 변별력이다**

| 사실 | 수 |
|---|---:|
| 현재 held-out v2.7 | **300문항** |
| 계열 **간** 비교에 필요(예: `d12`−`mC`) | **97 ~ 246** ✅**충분** |
| 계열 **안** 비교에 필요(예: `d12`−`d14`) | ★**984 ~ 10,800** 🚫**모자란다** |
| ★**300문항 중 실제로 정보를 주는 문항** | ★**60 ~ 103**(66~80%가 정보 0) |

> ★★**그래서 "300 → 1,000" 이 답이 아니다.** 같은 비율로 늘리면 **새 문항의 70%도 놀게** 된다.
> ★**요구는 개수가 아니라 난이도 대역이다** — 우리 모델 정답률이 **0.3~0.7** 인 문항.

## 3. ★생성 에이전트 전달용 프롬프트 (그대로 복사)

```
[한국어 관계추론 4지선다 문항 증보 요청 — TinyLM held-out v2.8]

■ 목적
100M 급 초소형 한국어-영어 이중언어 모델의 **지능을 서로 구분**하기 위한 평가 문항이다.
사람에게 쉬운 문항은 필요 없다. **비슷한 성능의 두 모델이 서로 다른 답을 낼 문항**이 필요하다.

■ 형식 (한 줄 = 한 JSON 객체, JSONL)
{
  "id": "v28-0001",
  "ctx": "<질문 또는 문두. 한국어 서술문 1~3문장>",
  "choices": ["<후보1>", "<후보2>", "<후보3>", "<후보4>"],
  "gold": 0,
  "relation": "<관계 유형: 인과 | 시간순서 | 부분전체 | 반의 | 상하위 | 목적수단 | 조건 | 대조>",
  "difficulty_target": "<easy | mid | hard>",
  "source": "<이 문항을 만든 모델·프롬프트 식별자>"
}

■ 난이도 규약 — ★가장 중요하다
- 목표는 **mid** 다. 전체의 **70% 이상을 mid** 로 만든다.
- mid 의 정의: **상식만으로는 못 풀고, 문두를 실제로 읽어야 풀린다.**
  - 오답 후보가 **문두와 어휘를 공유**해야 한다(표면 단서로 못 고르게).
  - 정답이 **가장 긴 후보이거나 가장 짧은 후보가 되지 않게** 한다.
- easy 10% · hard 20% 로 섞되, hard 는 **애매해서 어려운 것이 아니라
  추론 단계가 하나 더 필요해서** 어려워야 한다.

■ 금지 — 하나라도 어기면 그 문항은 폐기다
1. 🚫정답이 거짓인 문항. 특히 **부정할 명사를 질문이 아니라 답에서 고르는 것**을 금지한다.
   (v2.4 에서 이 결함이 9건 나왔다. **지식과 역상관**이 되어 아는 모델이 틀린다.)
2. 🚫**길이 단서**: 정답이 최장 또는 최단인 문항이 전체의 25%를 넘지 않게 한다.
3. 🚫**위치 편향**: gold 인덱스 0/1/2/3 이 각각 22~28% 가 되게 한다.
4. 🚫**후보 중복**: 네 후보가 의미상 서로 배타적이어야 한다(둘 다 맞는 답 금지).
5. 🚫**금지집합 접촉**: 아래 §4 의 원문·고유명사와 토큰 8-gram 이 겹치면 안 된다.
6. 🚫**외래 지식**: 한국 밖의 최신 시사·전문 학술 지식을 요구하지 않는다.

■ 자체 검사 (제출 전에 생성 측이 돌린다)
- 위치 분포 · 길이 분포 · 후보 배타성 · 금지집합 겹침을 **표로 함께 제출**한다.
- **표를 못 만들면 제출하지 않는다.**

■ 수량
- <CENSUS 뒤 확정. 잠정 2,500~4,500문항 · mid 70% 이상>
```

## 7.2 🚫★유일한 실질 결함 — **정형구가 후보 문자의 40.3%**

모든 후보가 **공통 문장 두 개**를 달고 있다:

    이 설명은 문두 밖의 사실을 보탠 판단이 아니다.            (8종 · 각 12.5%)
    이 관계 문장은 문두의 두 대상을 … 함께 다룬다.            (여러 변형)

★**대가 셋**:
1. ⚠️**문항당 정보 희석** — 채점기가 보는 문자의 40%가 **모든 후보에 공통**이다. 우리가 늘리려는 것은
   정확히 그 반대(고검정력 조사 §2: *"문항당 정보 2.00 → 3.0 bit"*).
2. ⚠️**계산비 40% 증가** — 문항당 **312 토큰**(총 1,402,139 토큰). 후보 4개 × 4,500문항을
   PMI 보정까지 하면 문항당 8회 전방계산이다.
3. ⚠️**근접중복** — 생성 측 스스로 §7 에 *"공통 표면 문장 때문에 근접 중복과 문장 반복이 많다"* 고 적었다.

★**그러나 정형구를 없애라고만 하면 v2.3 의 길이 편향이 돌아온다.** → §7.3 이 **대안**을 준다.

## 7.3 ★★재작업 요청 프롬프트 — **그대로 복사해 데이터셋 팀에 전달**

```
[held-out v2.9 재작업 요청 — TinyLM]

■ 배경
v2.8 4,500문항을 수령해 감사했다. 결과부터 말하면 **품질이 좋다**.
정답 위치 25/25/25/25, 문자·토큰 길이 단서 24.1~25.0%(우연 25%), 후보 배타성 위반 0건,
D1/D2/D6/D7 전부 0건, 부정·양태 지름길 z +0.0 / +1.4.
v2.3 이 문자 길이만 맞춰 토큰 길이 편향이 남았던 문제를 **이번에는 양쪽 다 맞췄다**.
정형구가 정답을 예측하는지도 확인했는데 18.8%(우연 25%)로 **단서가 되지 않는다**.

고칠 것은 한 가지다.

■ 고칠 것 — 길이 균형을 "덧붙이기"가 아니라 "내용"으로 맞춘다
- 현재 모든 후보에 공통 문장 두 개가 붙어 있고, 그것이 후보 문자의 **40.3%** 를 차지한다.
- 문제는 편향이 아니라 **희석**이다. 후보 넷을 가르는 실제 내용이 문자의 60% 뿐이라
  같은 계산비로 얻는 정보가 줄어든다. 문항당 토큰이 312개로 커진 것도 이 때문이다.
- 요구: **정형구 몫을 후보 문자의 15% 이하**로 줄인다. 방법은 둘 중 하나다.
  (a) 정형구를 전부 빼고, 후보 넷의 **내용 문장 길이를 서로 맞춘다**(±10% 이내).
  (b) 정형구를 한 문장으로 줄이고, 그 한 문장을 **네 후보에 완전히 동일하게** 쓴다.
      (지금은 두 번째 정형구가 후보마다 달라서 문자수가 후보마다 달라진다.)
- (a)를 권한다. 길이는 **덧붙여서가 아니라 잘라서** 맞추는 것이 안전하다.
- 고친 뒤 **문자 기준과 토큰 기준 양쪽에서** 최장/최단 선택기 정답률을 다시 재서 제출한다.
  두 기준 모두 30% 이하여야 한다.

■ 함께 고쳤으면 하는 것 둘 (필수는 아니다)
1. 질문 문장이 1,956종뿐이고 한 문장이 408회 반복된다("이 기록에 맞는 인과 판단은 무엇인가?").
   질문 표현을 관계 유형마다 5종 이상으로 늘린다.
2. 문두끼리 문자 8-gram 자카드가 0.70 이상인 쌍이 있다(최고 0.9067).
   같은 템플릿에 대상 이름만 바꾼 문항을 줄인다.

■ 수량 — 아직 확정하지 않는다
- v2.8 은 4,500문항인데 이 수에는 근거가 없다. 근거는 **변별 대역 비율(D9)** 이고,
  그것은 우리가 체크포인트로 재야 한다(census). census 결과가 나온 뒤 수량을 회신한다.
- 그때까지 v2.8 은 **그대로 두고 삭제하지 않는다**. 우리가 이미 채점 경로에 물렸다.

■ 유지할 것 (바꾸지 말 것)
- 정답 위치 균등, 문자·토큰 양쪽 길이 균형
- difficulty_target / relation / source 필드
- 가상 대상(색·모양·작업 단계 조합)으로 외래 지식을 요구하지 않는 설계
- 한 줄 = 한 JSON 객체(JSONL)와 최상위 records 를 가진 JSON, 둘 다 제출

■ 제출 시 함께 낼 표
1. 후보 문자 중 정형구 몫(%)
2. 문자·토큰 각각의 최장/최단 선택기 정답률
3. 정답 위치 분포
4. 질문 문장 고유 종수와 최빈 반복 횟수
5. 문두 8-gram 자카드 ≥0.70 쌍 수
```

서로 다른 6개 TinyLM 체크포인트로 v2.9 전체를 채점했다.

1. 총수는 4,500을 유지한다. 같은 분포를 추가 증보하지 말고 기존 문항을 교체한다.

3. 단, 모델 출력에 맞춰 정답이나 표현을 고치지 않는다. ID 목록은 실패 유형을 찾는
   용도이고, 새 문항은 아래 의미 균형·추론 규칙으로 처음부터 다시 쓴다.
4. 새 문항 중 최소 1,800개는 조건·부분전체·시간순서에 우선 배정하되, 최종 8개 관계
   수량은 각 562/563으로 다시 균형화한다. 다른 관계의 정보 0 문항도 남은 범위에서 교체한다.

■ 조건 관계 — 의미형을 균형화
- 현재 정답은 충분 341, 필요 192, 필요충분 15, 독립 14다.
- v3.0에서는 `충분만 / 필요만 / 필요충분 / 독립` 네 정답 의미형을 각각 22~28%로 한다.
- 질문의 A/B 순서를 절반에서 뒤집고, 역·이·대우를 혼동하게 하는 표면 단서를 없앤다.
- 네 후보는 같은 두 사건을 사용하고 오직 논리 방향만 달라야 한다.

■ 시간순서 — 방향 label shortcut 제거
- 현재 정답은 563/563 모두 “질문에서 먼저 적힌 사건이 시간상 먼저”다.
- `A 먼저 / B 먼저 / 동시 / 문두만으로 판단 불가`를 각각 22~28%로 한다.
- 질문에서 A/B가 등장하는 순서도 정답 의미형과 독립적으로 균형화한다.
- 단순 접속사 한 단어가 답을 주지 않게 2단계 시간 연결을 쓰되, 순환·모순은 금지한다.

■ 부분전체 — 이름 바꾸기 템플릿 대신 구조 추론
- 부분→전체, 전체→부분, 서로 다른 부분, 겹침 없음의 정답 의미형을 균형화한다.
- 단순히 색·물체 이름만 바꾼 문두를 재사용하지 않는다.
- 집합 포함과 물리적 구성요소를 한 문항 안에서 혼용하지 않는다.

■ 난이도
- `mid`는 생성자가 붙인 문체 라벨이 아니라 독립 파일럿 모델의 정답률 대역으로 확인한다.
- easy > mid > hard의 평균정답률 단조성이 성립해야 한다.
- hard는 애매함이나 정답 없는 문항이 아니라 추론 단계가 하나 더 있는 문항으로 만든다.
