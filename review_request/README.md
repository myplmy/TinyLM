# `review_request/` — 사용자 검수 요청 폴더

> **신설 2026-09-03**(사용자 지시 5). **사람만 판정할 수 있는 것을 사용자에게 부탁할 때**
> 여기에 양식 파일을 만든다.

---

## 1. 왜 생겼나 — **2026-09-02 검수지가 무엇을 물었는지 불명확했다**

첫 검수지([`done/20260903_heldout-v24-30문항-검수지-완료.md`](done/20260903_heldout-v24-30문항-검수지-완료.md))는 물음을 **하나로 좁혔다**:

> *"바뀐 오답이 여전히 '틀린' 답인가?"*

★**그런데 사용자가 실제로 발견한 것은 그것이 아니었다.**

| 검수지가 물은 것 | ★**사용자가 찾은 것** |
|---|---|
| 오답이 여전히 틀린가 | 🚫★**정답 후보 자체가 거짓인 문항 9개**(결과 068 §12.3) |
| — | 🚫★**후보가 질문 내용을 하나도 안 담는다**(`novel_relation` 56.7%) |
| — | ⚠️정답 문장과 정답 후보의 관계가 불명확하다 |

→ ★★**물음을 좁힌 것이 오히려 손해였다.** 사용자는 좁힌 물음 **밖**에서 더 큰 것을 봤고,
검수지에 *"이것도 봐 주세요"* 라는 자리가 **없어서** 판정 칸에 이유를 덧붙여야 했다.

★**그리고 검수지가 설명하지 않은 것이 하나 더 있었다**: *"`answer`(정답 문장)와
`candidates`(4지선다 후보)는 **다른 필드이고 채점에는 후보만 쓴다**"* —
이 구조를 안 적어서 사용자가 *"둘이 다른 게 의도인가"* 를 물어야 했다.

## 2. 파일 이름과 ★**끝난 뒤 어디로 가나** (2026-09-06 사용자 지시 7)

```
review_request/{YYYYMMDD}_{대상}_{건수}.md                 <- ⏳진행 중
review_request/done/{YYYYMMDD}_{대상}_{건수}-완료.md       <- ✅끝난 것
```

★**끝나면 접미사를 붙여 `done/` 으로 옮긴다.** `proposal/` 과 **같은 규약**이다.

| 접미사 | 뜻 |
|---|---|
| (없음) | ⏳**진행 중** — 최상위에 둔다 |
| `-완료` | ✅요청한 것이 전부 해결됐다. ★**본문 마지막 절에 종결 근거**를 적는다 |
| `-거부` | 🚫사용자가 하지 않기로 했다. **사유**를 적는다 |
| `-보류` | ⏸선결이 생겨 멈췄다. ★**무엇이 선결이고 얼마인지 숫자로**(R36) |

🚫**요청본을 지우지 않는다**(R01) — 무엇을 물었는지와 무엇이 답인지가 **둘 다** 남아야
다음 세션이 검수의 유효 범위를 안다. 그래서 **한 파일에 이어 쓰고 옮긴다** —
🚫별도 완료본을 만들지 않는다(2026-09-06 정정: 종전 규약은 파일을 둘로 나눴는데,
실제로 써 보니 **요청과 회신이 여러 판을 오가서**(v2.5 → v2.6 → v2.7) 파일이 갈라지면
**어느 판의 답인지** 못 따라간다).

## 3. 양식 — 정본은 [`_TEMPLATE.md`](_TEMPLATE.md)

★**여섯 절을 반드시 채운다.**

| # | 절 | 왜 필요한가 |
|---|---|---|
| **1** | **무엇을 검수하나** | ★**대상 파일의 경로와 판**을 적는다 |
| ★**2** | **왜 기계가 못 하나** | ★**이것이 없으면 사용자가 "이건 도구로 되지 않나" 를 의심하며 본다.** 이미 돌린 기계 검사와 **그것이 못 보는 것**을 나란히 |
| ★**3** | ★**데이터 구조 설명** | 🚫**2026-09-02 에 빠졌던 절.** 필드가 무엇이고 **채점에 무엇이 쓰이는지**. 안 적으면 검수자가 **엉뚱한 것을 본다** |
| **4** | **판정 기준** | 기호와 뜻. ★**"애매하면 어느 쪽" 까지** 적는다 |
| ★**5** | ★**자유 관찰 칸** | 🚫**좁힌 물음 밖의 발견을 받을 자리.** 2026-09-02 에 없어서 사용자가 판정 칸에 끼워 넣었다 |
| **6** | **표본 선정 방법** | 층화·비례배분 여부. ★**전수가 아니면 "표본율 → 전수 추정" 을 어떻게 할지** |

## 4. ★쓰는 쪽에 대한 규칙

| # | 규칙 |
|---|---|
| ★**1** | ★**물음을 하나로 좁히지 않는다.** 좁힌 물음 + **자유 관찰 칸**을 함께 둔다(§1 이 그 교훈이다) |
| ★**2** | ★**데이터 구조를 먼저 설명한다** — 어느 필드가 채점에 쓰이고 어느 필드가 안 쓰이는지 |
| ★**3** | **기계가 이미 본 것을 명시**한다. 사람에게 같은 것을 두 번 시키지 않는다 |
| ★**4** | 표본이면 **모집단과 표본율**을 적는다 — 사용자의 판정을 **전수로 환산**할 수 있어야 한다 |
| ★**5** | 🚫**검수 결과를 받으면 "사용자가 잘못 이해했다" 를 기본 가정으로 두지 않는다.** 2026-09-02 검수는 **사용자가 옳았고 내 기계 검수가 틀렸다**(결과 068 §12.5) |
| **6** | 검수 결과는 **결과문서에 절로 기록**한다. 검수지에만 두면 색인이 안 된다 |
