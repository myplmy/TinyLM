# 검수 요청 — 공개 한국어 공감형 멀티턴 SFT 후보 100건 + 마커 이상 1건

> 작성 2026-09-25 · 상태 ⏳ 1차 GPT 검수와 사용자 최종 판단 대기 · 예상: GPT 30~60분, 사용자 30~60분(추정)
> 대상: `HF/sft_sources/p090_empathetic_ko_9847cd2/Empathetic_data.jsonl` · 원본 SHA-256 `BC2B24FBEE11782071A9F84FBCEE615721F729ED31A01103E6755F80F9BC80C8`
> 근거: [P090B 계획](../test_plan/P090B_chat32-기존-최선부모-SFT-3계보-검증.md) Stage0cW, [사용자 실행 원본 로그](../test_result/096_log_20260924_P090B_Stage0cW_empathetic_multiturn_contract.txt). 이 문서는 공개 원천의 **검수 요청**이며 학습 승인·번역 승인·데이터 수정 지시가 아니다.

## 1. 무엇을 검수하나

다른 GPT agent가 아래 고정 표본 100건(`multi_2` 50·`multi_3` 50)의 **전체 대화**를 먼저 읽고 행별 잠정 판정·증거를 기록한다. 원천 26,662행 중 `single` 8,094행은 이번 다회전 질문 밖이다. 엄격 복원 후보는 `multi_2` 3,812행과 `multi_3` 14,755행, 합계 18,567행이다. 0부터 세는 raw JSONL 행 24,932는 마커 순서가 깨져 자동 제외됐다. 이 한 건은 GPT가 따로 원문을 확인하되 추측 복원이나 원본 수정은 하지 않는다.

1차 결과를 받은 사용자는 **거절·불확실 행 전부**, 각 유형의 잠정 수락 중 최소 10건씩, 마커 이상 1건을 직접 확인한다. 사용자가 판정할 권리·허용 기준은 GPT의 문장 품질 의견과 분리한다. 표본에서 결함이 나오면 동일 결함의 전체 후보 검색·원인별 재표집이 선결이지, 표본 100개만 손봐서 `TRAIN_READY`로 올리지 않는다.

## 2. 왜 기계가 못 하나

| 이미 실행한 기계 검사 | 실제 결과와 한계 |
|---|---|
| 고정 SHA·유형·마커 교대 | 원본 SHA 일치, `multi_2` 3812/3812·`multi_3` 14755/14756 복원; 한 행 제외로 구조 `PARTIAL` |
| legacy 32k 직렬화·assistant mask | 후보 18,567행 모두 1024 context 이내, 빈 지도마스크 0, 지도토큰 비율 52.96%; 마스크 `PASS` |
| 첫 질문 중복·문자 패턴 | 첫 질문 중복 행 1,775, URL 포함 0, `@` 포함 0; 의미상 중복·PII 부재 증명이 아님 |
| 권리·오염·사람 품질 | 카드 수준 Apache-2.0 표기만 확인, 개별 권리·평가 오염·자연성·사실성은 모두 `NOT_RUN`; `train_ready=false` |

기계는 이전 답변이 사용자의 다음 질문과 맞는지, 최종 `output`이 실제 질문에 답하는지, 한국어가 자연스러운지, 사실·안전·개인정보·저작권 문제가 있는지 판단하지 못한다. 단순 `http`/`@` 부재도 개인정보와 베껴 쓴 문장의 부재를 보장하지 않는다. GPT는 잠정 분류자이지 최종 권리·학습 허가자가 아니다.

## 3. 데이터 구조 — 실제 SFT에서 무엇이 목표인가

| 원천 필드 | 의미 | SFT 지도 대상 |
|---|---|---|
| `type` | `multi_2` 또는 `multi_3`; 이번 표본 층화 단위 | 아니오 |
| `instruction` | 줄머리 `질문:`·`답변:` 교대, 마지막 `질문:`까지 포함 | 복원된 이전 assistant `답변:` 부분만 예 |
| `output` | 마지막 사용자 질문에 대한 최종 assistant 답변 | 예, 문장과 종료토큰 |
| `source` 등 메타 | 원천 계보·감사 추적용 | 아니오 |

검수할 때 **마지막 output만 보지 말고 이전 `답변:`과 다음 `질문:`의 관계를 모두** 본다. 첫 질문이 같더라도 뒤 문맥이 다르면 같은 대화라고 단정하지 않는다. 모델 손실은 assistant 발화와 종료 표지만 지도하며 사용자 질문/메타는 지도하지 않는다. 이 구조는 [canonical 스키마](../tinylm/chat/canonical.py)와 [복원기](../scripts/diag_p090b_empathetic_contract.py)가 소유한다.

## 4. 판정 기준과 책임 분리

| 1차 GPT 행 판정 | 기준·필수 이유코드 |
|---|---|
| `A_CANDIDATE` | 역할·문맥·최종 답변이 맞고 자연스러운 후보. **TRAIN_READY를 뜻하지 않음** |
| `REJECT` | `ROLE`(화자/교대), `CONTEXT`(앞 대화 무시), `FACT`(확인 가능한 사실 오류), `KOREAN`(비자연·번역투), `FORMAT`(목표 답변 형식), `DUP`(거의 같은 문답 반복), `PRIVACY`(식별 가능 정보), `SAFETY`(위험 응답), `COPY`(긴 외부 문구), `OTHER` 중 하나 이상과 짧은 근거 |
| `UNCERTAIN` | 의미·권리·문화/의학/법률 등 전문성·불명확한 지시로 GPT 단독 판단이 어려움. **애매하면 수락이 아니라 이 칸** |

다른 GPT agent의 제출물은 `raw_row_index_zero_based`, `type`, `verdict`, `reason_codes`, `evidence`(필요 최소 문구), `suggested_action`, `free_observation` 열을 가진 표다. 원문 전체를 응답/원격 서비스에 일괄 복사하거나 새 학습 파일을 만들지 않는다. 원천·체크포인트·캐시는 읽기 전용, 보호 `datasets/TinyDataset/**`는 접근하지 않는다.

사용자 직접 판정: (①) 거절·불확실과 수락 검산에서 GPT 판정이 맞는지, (②) 카드 Apache-2.0 표기가 **실제 배포/가공/상업적 사용 조건** 및 개별 대화 권리를 충족하는지, (③) 개인정보·안전·베낌 허용 정책, (④) 중복 제거와 source/tree 단위 train/val 분리 기준, (⑤) 한국어 능력 목표에 필요한 품질 하한과 통과/보류/거부 결정을 별도로 남긴다. 권리 해석이 불명확하면 사용하지 말고 `UNCERTAIN_RIGHTS`로 남긴다. 최종 `TRAIN_READY`는 오염·원천 권리·사람 품질·분리·마스크 게이트를 별도로 통과해야 한다.
