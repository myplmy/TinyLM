# 작업지시 — held-out 벤치마크 **결함 10건 수정** (데이터셋 담당 LLM 앞)

> **발행 2026-09-03** · 발행자 Claude Code(TinyLM) · **사용자 승인 완료**
> 대상: `datasets/TinyDataset/stage1_dataset/held-out_v2.3` · `held-out_v2.4`
> 🚫**`stage2~stage10_highdensity_dataset` 은 절대 건드리지 않는다.**

---

## 0. 한 줄

**정답으로 표시된 후보가 사실과 반대인 문항이 9건 있고, v2.4 가 새로 깬 것이 1건 더 있다.**
**질문·정답 문장은 대체로 옳다. 틀린 것은 *후보 4개 중 정답으로 지목된 것*이다.**

## 1. 왜 급한가

★**이 데이터가 우리의 유일한 한국어 판정 경로**다. 지금은 **모델 비교에 쓸 수 없다** —
결함이 **지식과 역상관**이라, 사실을 아는 모델일수록 거짓인 '정답' 을 피해서 **틀린다.**
고칠 때까지 한국어 축 실험이 전부 멈춘다.

## 2. ★결함 A — 정답 후보가 거짓인 문항 **9건** (v2.3·v2.4 **둘 다**)

```
E-058  E-089  E-106  E-119  E-132  E-133  E-134  E-140  E-144
```

### 2.1 무엇이 잘못됐나 — 예시

| | 내용 |
|---|---|
| 질문 | *"공기는 하나의 순수한 물질인가?"* |
| 정답 문장 | *"아니다. 공기는 **혼합물**이다."* ✅**이 문장은 옳다** |
| 🚫**정답으로 표시된 후보** | *"공기는 **혼합물** 범주에 속하지 **않는다**"* |

### 2.2 ★근본 원인 — **하나다**

생성기가 **부정할 명사를 질문이 아니라 *답*에서 골랐다.**

- 올바른 부정 대상 = 질문의 *"순수한 물질"*
- 실제로 부정한 것 = 답의 *"혼합물"*

→ 결과적으로 **정답 문장과 정면으로 모순되는 문장이 '정답' 으로 표시**됐다.

### 2.3 무엇을 해야 하나

각 문항에서 **정답으로 표시된 후보 문장만** 고친다. 부정의 대상을 **질문의 명사**로 되돌린다.

- 예: *"공기는 혼합물 범주에 속하지 않는다"* → *"공기는 순수한 물질이 아니다"*
- ★**정답 문장(`gold`)과 의미가 일치**해야 한다.

### 2.4 ★★기계 전수 결과 — **9건이 아니라 25건이다** (2026-09-03 실측)

사람 검수는 **30문항 표본**이었다. `check_heldout_defects.py` 로 300문항을 전수하니
같은 형태가 **25건** 나왔다. ★**표본 추정의 2.8배**다.

```
E-021 E-052 E-058 E-088 E-089 E-106 E-107 E-119 E-134 E-140 E-141 E-153 E-162
E-192 E-193 E-214 E-228 E-231 E-235 E-271 E-272 E-273 E-275 E-286 E-300
```

★★**v2.1 · v2.2 · v2.3 · v2.4 에서 목록이 완전히 같다** — 🚫**개정으로 고쳐진 적이 한 번도 없다.**
생성기 결함이 처음부터 있었고 판올림이 그것을 건드리지 않았다.

⚠️**사람이 찾은 9건 중 6건이 여기 있고 3건(`E-132`·`E-133`·`E-144`)은 없다.**
→ ★**둘을 합집합으로 처리한다**(25 ∪ 9 = **28건**). 기계는 재현율이 100%가 아니고,
**사람이 본 것을 기계가 못 봤다고 해서 결함이 아닌 것이 아니다.**

### 2.5 ⚠️추가 발견 — **v2.4 가 추상화를 더 늘렸다**

후보 4개에 **질문의 내용어가 하나도 없는 문항**(D3):

| 판 | D3 건수 / 300 |
|---|---:|
| v2.1 · v2.2 | 119 (39.7%) |
| v2.3 | ★**110 (36.7%)** — 가장 좋다 |
| ★**v2.4** | 🚫**132 (44.0%)** — **+22건 악화** |

★**길이를 맞추려는 재작성이 내용어를 걷어냈다.** §5 의 별건과 같은 뿌리다.
→ ⚠️**이것이 v2.4 승격을 보류하는 두 번째 이유**다(첫째는 §3 의 `E-020`).

## 3. ★결함 B — v2.4 가 새로 깬 것 **1건**

| 문항 | 무엇 | v2.3 | v2.4 |
|---|---|---|---|
| **E-020** | 오답 후보 #2 의 낱말을 `양치류` → `양치식물` 로 고쳤더니 ★**정답 문장과 같아졌다** | ✅정상 | 🚫**중복** |

→ **오답이 정답과 같아지면 그 문항은 정답이 둘**이다. `양치류` 로 되돌리거나 **다른 오답으로 교체**한다.

## 4. 🚫**바꾸지 말 것** — 이것을 어기면 데이터가 더 나빠진다

| # | 무엇 | 왜 |
|---|---|---|
| **1** | ★**질문과 정답 문장(`gold`)** | 사람 검수 30문항에서 *"정답 문장 자체는 대체로 타당"* 으로 확인됐다 |
| **2** | ★★**후보 4개가 같은 문장 틀을 쓰는 구조** | 🚫**결함이 아니라 의도된 설계**다. v2.3 이 이 틀로 **최장선택 편향을 39.0% → 25.0%** 로 내렸다. 틀을 흩으면 길이 편향이 되살아난다 |
| **3** | **결함 목록(§2·§3) 밖의 문항** | 건드리면 v2.3 과의 비교가 끊긴다 |
| **4** | `answer` 필드 | ★**채점에 쓰이지 않는다**(자유생성 시절 유물). 지금 채점은 **후보만** 본다 |
| **5** | 문항 수 300 · ID 체계 | 대조가 깨진다 |

## 5. ⚠️별건 — **지금 고치지 말고 보고만 할 것**

`novel_relation` 후보의 **56.7%(51/90)** 가 *"첫째 대상"* · *"둘째 대상"* 같은 **추상 대명사**다.
후보에 질문의 내용어가 없어 ★**개념 지식이 아니라 대명사 결합을 재고 있다.**

🚫**§4-2(의도된 틀)와 섞지 말 것** — **틀이 같은 것은 설계**고, **내용어가 없는 것은 결함**이다.
→ **이번 작업 범위 밖이다.** 별도 지시를 기다린다.

## 6. ★재검증 — **기계 검사를 통과해야 납품이다**

🚫**종전 기계 검수는 이 결함을 한 건도 못 잡았다.** 구조(정답 불변·금지관계 정합·중복·문자폭)만
보고 **의미를 안 봤다.** 그래서 검사 두 개를 새로 만들었다:

그럴 때는 **문항 번호와 이유를 적어 회신**한다(무시하지 않는다).

## 9. ★★그대로 복사해 붙일 프롬프트

> 사용자 지적(2026-09-04): *"현재 수정지시문을 그대로 LLM에도 줘도 되는것인지 어떤지 알수없음."*
>
> ★**맞다. 위 §0~§8 은 그대로 주면 안 된다.** 이유 셋:
> ①우리 저장소 규약·함정 번호·결과문서 번호가 섞여 있어 **바깥 LLM 이 못 읽는다**
> ②`review_request/`·`scripts/` 같은 **우리 경로**를 전제한다
> ③*"발행자 주"* 처럼 **작업자에게 줄 내용이 아닌 것**이 들어 있다.
>
> → ★**아래 코드블록만** 복사해서 준다. 위 §0~§8 은 **우리 쪽 기록**이다.

```text
당신은 한국어 벤치마크 데이터셋을 수정하는 작업을 맡았습니다.
아래 지시를 정확히 따라 주세요. 지시에 없는 것은 바꾸지 마세요.

== 1. 데이터 형식 ==

JSON 파일의 records 배열에 300개 문항이 있습니다. 한 문항의 구조:

  id                 문항 번호 (예: E-089)
  prompt             질문
  answer             정답 문장 (평서문)
  candidates         후보 문장 4개 (배열)
  correct_index      candidates 중 정답의 위치 (0~3)

채점은 candidates 만 사용합니다. 모델이 네 후보의 우도를 비교해 하나를 고릅니다.
answer 필드는 채점에 쓰이지 않습니다. (과거 형식의 잔재입니다.)

== 2. 고쳐야 할 결함 ==

[결함 A] correct_index 가 가리키는 후보가 answer 와 의미가 반대입니다.

  예시 — 문항 E-089
    prompt   : 공기는 하나의 순수한 물질인가?
    answer   : 아니다. 공기는 혼합물이다.            <- 이 문장은 옳습니다
    정답 후보: 공기는 혼합물 범주에 속하지 않는다.    <- 틀렸습니다

  원인: 부정할 대상을 질문("순수한 물질")이 아니라 답("혼합물")에서 골랐습니다.
  고친 결과 예: 공기는 순수한 물질 범주에 속하지 않는다.

  대상 문항 (28개):
    E-021 E-052 E-058 E-088 E-089 E-106 E-107 E-119 E-132 E-133 E-134
    E-140 E-141 E-144 E-153 E-162 E-192 E-193 E-214 E-228 E-231 E-235
    E-271 E-272 E-273 E-275 E-286 E-300

  주의: 이 목록은 기계 검사 25개와 사람 검수 9개의 합집합입니다.
        일부는 실제로는 정상일 수 있습니다. 문항을 읽고 판단하되,
        정상이라고 판단한 문항은 번호와 이유를 보고서에 적어 주세요.

[결함 B] 문항 E-020 에서 오답 후보 하나가 정답 문장과 같은 뜻이 되었습니다.
         (양치류 -> 양치식물 로 고치면서 생긴 문제입니다.)
         정답이 둘이 되지 않도록 그 오답을 다른 것으로 바꿔 주세요.

== 3. 절대 바꾸지 말 것 ==

  1) prompt 와 answer. 이 둘은 검수에서 대체로 옳다고 확인되었습니다.
  2) 후보 4개가 같은 문장 틀을 쓰는 구조.
     이것은 의도된 설계입니다. 후보 길이가 다르면 모델이 내용이 아니라
     길이를 보고 고르기 때문에, 일부러 틀을 맞춰 놓았습니다.
     실제로 이 설계가 '가장 긴 것 고르기' 정확도를 39.0% 에서 25.0% 로 낮췄습니다.
  3) 위 목록에 없는 문항.
  4) 문항 수(300개)와 id 체계.
  5) correct_index 자체. 후보 문장을 고치되 정답 위치는 그대로 둡니다.

== 4. 함께 확인만 하고 보고할 것 (이번에 고치지 마세요) ==

  후보 4개에 질문의 내용어가 하나도 없는 문항이 132개(44%)입니다.
  예: 질문이 "두 물건의 크기가 비슷하다. 같은 범주라고 할 수 있는가?" 인데
      후보는 모두 "해당 속성만으로 대상의 범주를 확정할 수 없다는 관계다." 꼴이라
      '크기' 라는 낱말이 후보에 없습니다.

  이러면 개념 지식이 아니라 대명사 결합을 재게 됩니다.
  이 문제와 위 3-2)(틀을 맞춘 설계)는 다른 문제입니다. 섞지 마세요.
  이번 작업 범위 밖이니 의견만 적어 주세요.

== 5. 산출물 ==

  1) 새 버전 폴더에 수정본을 저장 (기존 버전은 그대로 두세요)
  2) 문항별 수정 표: id / 고치기 전 / 고친 후 / 왜 고쳤는지
  3) 정상이라고 판단해 안 고친 문항이 있으면 그 목록과 이유
  4) 4번 항목에 대한 의견

== 6. 자기 점검 (제출 전에 직접 확인) ==

  체크1. 오답 후보 중에 정답 후보와 글자 그대로 같은 것이 있는가? (있으면 안 됨)
         부분 문자열로 비교하지 마세요. '식물' 은 '양치식물' 안에 들어 있어서
         부분 문자열로 세면 0건이 나옵니다. 문장 전체로 비교하세요.
  체크2. 정답 후보가 answer 와 의미가 반대인 문항이 남아 있는가? (있으면 안 됨)
  체크3. prompt 와 answer 를 하나도 안 바꿨는가?
  체크4. 후보 4개의 문장 틀이 여전히 서로 같은가?
```

## 10.4 ★★신규 축 — **부정 지름길(D4)** 을 처음 쟀다

우리 문형은 대개 *"X 는 A 범주에 **속한다**"* 셋 + *"X 는 A 범주에 **속하지 않는다**"* 하나다.
→ ★**후보만 보고 "부정형" 을 고르면** 모델이 X 도 A 도 몰라도 맞힌다.

| 판 | 부정 후보가 **정확히 1개**인 문항 | 그중 정답 | ★**부정 선택기 정답률** | z |
|---|---:|---:|---:|---:|
| v2.1 · v2.2 | 105 / 300 | 94 | **32.3%** | +2.9 |
| ★**v2.3** | **80 / 300** | 75 | ★**29.5%** | **+1.8** |
| v2.4 | 90 / 300 | 85 | 31.3% | +2.5 |
| ★**v2.5** | **90 / 300** | 85 | **31.3%** | **+2.5** |

- ★**부정 후보가 하나뿐인 90문항에서는 그것이 정답일 확률이 94.4%** 다.
- 🚫**길이 축(v2.3 토큰 최단 30.3%, z +2.1)보다 강한 지름길**인데 **지금까지 아무도 안 쟀다.**
- ⚠️**규약상 아직 "결함" 은 아니다** — 결과 068 의 기준은 `|z| ≤ 3` 이고 **+2.5 는 통과**다.
- 🚫★**그런데 개정이 이 축을 악화시켰다**: v2.3(+1.8) → v2.4·v2.5(+2.5).
  ★**개정마다 한 축을 고치고 다른 축을 나쁘게 만들고 있다** — v2.4 는 문자 폭을 고치면서
  이 축을 잃었다. → ★**v2.6 은 두 축을 함께 봐야 한다.**
- ✅**게이트 신설**: `check_heldout_defects.py` 의 **D4** 가 매번 인쇄한다.
