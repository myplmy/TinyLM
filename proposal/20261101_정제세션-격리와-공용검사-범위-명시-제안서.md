# 제안 — 같은 검사 규칙과 다른 입력 범위를 명시한다

> **작성** 2026-11-01 · **상태** 판단 대기 · **분류** 작업방식·검증 하네스

## 1. 배경 — 왜 지금 이 제안을 하나

사용자105는 정제 세션을 제외한 연구·커밋을 허가했다. 소유 어댑터를 사용한 오후 정적 실행은69 PASS/2 ERROR/6 NOT_RUN이었고, 원형 check_attrs가 scripts 전체를 읽는 경로를 놓쳤다. check_call_kwargs/check_imports/check_flag_used/check_flag_whitelist에도 넓은 본문 수집 경로가 있다. 따라서 일부 목록만 제한한 실행을 타 세션 비접근 증거로 주장할 수 없다. 원로그와 이 실패는 보존한다.

두 ERROR 중 직접 import 경로는 수리됐다. 나머지 check_smoke_diag는 현재 새 라이브러리·변경 소스에 대응하는 전체 smoke가 없어서 발생하는 신선도 오류다. 옛 전체 smoke의 성공을 현재 소스의 성공으로 복사하지 않는다. Codex00 R58은 작업흐름 생성기·검사기에 직접 지시 또는 승인된 구현안을 요구하므로 공용 계약을 지금 무단 수정하지 않았다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

사용자 전역 검사와 Codex의 승인된 소유 입력 검사를 구별하면서, 같은 규칙·모델 실행 조건을 유지하고 타 세션 전용 본문 접근을 차단한다. 결과의 범위가 좁아지는 사실을 보고서가 숨기지 못하게 한다.

## 3. 성과물 — 승인하면 무엇이 생기나

| 산출물 | 형태 |
|---|---|
| 검사 명령별 입력 명세 | 검사기·판독 경로·소유/공유 입력·제외·고정 SHA |
| 명시 범위 collector | 기본 인수는 기존 USER_GLOBAL 유지, 별도 승인 manifest에서만 OWN_SCOPED |
| 판독 거부 회귀 | 소유 결함은 계속 검출, 제외 canary의 파일 본문 open은 실패, 자식 실행도 별도 확인 |
| 새 정적·smoke 영수증 | 검사 규칙/수·모델 팔/인수·collector 차이·실제 read-set·NOT_RUN을 함께 기록 |

후속 구현 대상 후보는 scripts/check_static_all.py의 명령 전달, 각 검사기의 실제 본문 collector, scripts/codex_smoke.py의 허용된 치환과 영수증 계약이다. 정확 변경 허용목록을 먼저 고정한다. .agents/.codex 변경이나 정제 코드 수정은 이 제안의 범위가 아니다.

## 4. 비용

| 항목 | 양 |

| 구현·CPU 회귀 | 약2~4시간 추정. 모든 자식 판독 경로가 단순한지 아직 미확정 |
| GPU | collector 변경 자체는0. 이후 승인된 새 전체 smoke의 기존 합성 모델 팔을 실제 수행 |
| 사용자 행동 | 권장 A의 구현 범위 승인. 실행 권한은 해당 회차의 별도 CPU/GPU 범위와 대조 |
| 디스크 | 새 manifest/원로그/영수증, 합성 smoke checkpoint가 생기면 별도 목록에 보존 |

## 5. 원리·근거

**우리 실측:** [PRODUCT_BOUNDARY_STATIC_AUDIT.json](../handoff/audit/nov01_afternoon/PRODUCT_BOUNDARY_STATIC_AUDIT.json), [SCOPED_ATTRS_v2.json](../handoff/audit/nov01_afternoon/SCOPED_ATTRS_v2.json)이 정본이다. 원형 attrs의 TARGETS만 메모리에서 명시48입력으로 바꾸고 본문 open guard를 붙인 개별 시험은 소유 결함1개를 검출하고 제외 canary를 거부했으며 실제 종료0이었다. 이는 전수 정적/전체 smoke 증명이 아니다.

첫 개별 시험은 파일 검사는0이었지만 tempfile 정리용 디렉터리 handle까지 막아 프로세스가1로 종료했다. v1을 최종 PASS로 삼지 않고 v2는 디렉터리 메타데이터와 파일 본문을 구별했다. 이 guard도 전체 OS 격리는 아니다.

**외부 근거:** 새 웹 문헌을 인용하지 않는다. 현재 저장소의 collector와 실제 실행만을 근거로 한다.

## 6. 방법

| 단계 | 무엇 | 다음으로 가는 조건 |
|---|---|---|
| 1 | 모든 부모/자식 명령의 판독·import·경로 순회를 조사 | 제외 경로와 shared 입력을 실행 전에 명시 |
| 2 | explicit manifest를 collector에 전달 | 원형 판정식/허용오차/ERROR 처리 변화0, 결과 후 필터링0 |
| 3 | 결함 주입·canary·자식 접근 거부 회귀 | 누락되면 해당 검사는 ERROR/NOT_RUN, 조용한 skip 금지 |
| 4 | 소유 범위 정적을 실제 실행 | 입력 범위·근거와 결과를 고정, USER_GLOBAL PASS 주장 금지 |
| 5 | 새로운 isolated 전체 smoke | 원형106행동·모델 인수·판정은 유지하고 collector/환경 치환을 영수증에 명시 |

일반 사용자 실행에서 manifest를 주지 않으면 기존 전역 입력을 그대로 쓴다. 소유 모드는 같은 검사식이라도 다른 파일 집합을 다루므로 결과가 달라질 수 있다. 모델 smoke 인수와 수치 판정이 바뀌는 것은 별도 변경이며 이 승인에 포함하지 않는다. 이전 두 치환만 허용하던 Codex smoke 계약에 collector 치환을 추가하면 차이를 명시하고 새 회귀를 통과해야 한다.

## 7. 거절하면 못 하는 것

현재 소유 범위의 개별 CPU/GPU 기술 결과와 커밋·결과 기록은 계속할 수 있다. 타 세션 비접근을 보장하는 현재 소스 전체 smoke·전역 정적 PASS는 주장하지 못한다. 정제 해결이나 본학습 권한은 어느 안에서도 자동으로 생기지 않는다.

## 8. 위험 — 실행하면 무엇이 잘못될 수 있나

| 위험 | 어떻게 드러나나 | 완화 |
|---|---|---|
| 범위 축소를 전수 PASS로 오인 | 제외 파일 오류가 보고서에 사라짐 | OWN_SCOPED/USER_GLOBAL·파일수·제외·SHA를 필수 출력 |
| 자식이 guard를 벗어남 | 부모 기록과 실제 판독이 다름 | 자식별 경계/회귀, 미관찰 자식은 비접근 확정 금지 |
| 미래 source에 옛 smoke 재사용 | source pin 불일치 | 새 immutable namespace, 기존 신선도 실패 유지 |
| 동시 세션 입력 변경 | 실행 전후 SHA 차이 | 해당 결과를 유효 증거로 채택하지 않고 재승인 범위 확인 |

## 9. 대안

| 안 | 무엇 | 장점 | 단점 |
|---|---|---|---|
| **A 권장** | 명시 입력 collector와 read 거부, 사용자 전역 기본은 유지 | 같은 규칙을 공유하고 동시 세션 판독을 통제 | 검증 범위 표기·자식 전달의 구현이 필요 |
| B | 소유 파일만 담은 별도 검증 복사본에서 원형 검사 | 입력 트리 구분이 눈에 보임 | 상대 경로·캐시·동일 소스 증명·복사본 유지 비용이 큼 |
| C | 개별 검사만 하고 새 전체 smoke는 보류 | 공용 변경0, 현재 경계를 지킬 수 있음 | 현재 소스의 전체 smoke 증거는 계속 미완 |

권장안은 A다. 검사 기준을 바꾸어 통과시키는 방식이 아니라 판독 대상과 결과 범위를 정본에 드러낼 수 있기 때문이다. 승인 전 현재 운용은 C이며, 개별 입력 시험을 A의 전체 구현 완료로 부르지 않는다.
