# 제안 — 제안서 경로 오배치와 미해결 FAIL 보고 누락 재발 방지

> **작성** 2026-09-12 · **상태** ⏳판단 대기 · **분류** 작업방식
> 양식: [`proposal/README.md`](README.md) §3. 이 문서는 개선안의 승인 여부를 묻는 제안이며,
> 스크립트·훅·규약 구현은 아직 변경하지 않았다.

---

## 1. 배경 — 왜 지금 이 제안을 하나

2026-09-12 통합 작업에서 서로 다른 두 오류가 연속으로 발생했고 사용자가 직접 지적했다.

1. 오류원장 A19: 사용자가 출력 경로를 지정하지 않은 제안서 **2개**를 기본
   `proposal/`이 아니라 `ai_dev_tool/temp_*.md`에 작성했다. 그 결과 두 문서가
   `proposal/*.md` 기반 판단 대기 목록에서 빠졌고, 파일 이관·접두사 제거·역참조 갱신이
   추가로 필요했다.
2. 오류원장 A20: 전역 계획번호 검사에서 남은 `P091` FAIL **1건**을 한 문장으로만 보고했다.
   정확한 원문 1개와 검출 위치 6곳, 현재 실험에 미치는 영향, 권장 조치와 사용자 승인 필요 여부를
   생략해 사용자가 무엇을 결정해야 하는지 알 수 없었다.

상세 보고 뒤 재검사에서는 누락 번호 자체는 1개로 같았지만, 검사 출처가 최초 원문과 진단 문서
3개를 합친 **4파일**로 늘었다. 현재 검사기는 미승인 선점과 그 오류를 정확히 기록하는 문장을 구분하지
않는다. 즉, “정확한 FAIL 보고”를 강화하면 “미작성 번호 참조 금지” 검사가 다시 실패하는 계약 충돌도
이번 재발방지 범위에서 함께 다뤄야 한다.

두 오류의 직접 원인은 다르다. A19는 **파일을 만들기 전 산출물 종류와 기본 소유 폴더를 확정하는
게이트가 없었던 것**, A20은 **최종 보고 전에 미해결 FAIL의 결정 정보가 모두 있는지 확인하는
게이트가 없었던 것**이다. 공통적으로는 규칙이 문서에만 있고 실제 작성 흐름에서 강제되지 않았다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

사용자가 정확한 경로를 지정한 산출물에는 그 지시를 해당 파일에만 적용하고, 경로 미지정 산출물은
종류별 정본 폴더로 보내며, 남은 FAIL은 사용자가 조치·승인 여부를 바로 결정할 수 있는 완결된 형식으로
보고하게 하는 **좁은 생성·검사 계약**을 만든다.

## 3. 성과물 — 승인하면 무엇이 생기나

| 산출물 | 형태 |
|---|---|
| 문서 종류별 경로 계약 | `.agents/project.json`의 단일 기계 판독 맵과 각 README의 설명 링크 |
| 제안서 생성 도우미 | 정본 템플릿·기본 폴더·파일명 규칙을 적용하는 `scripts/new_proposal.py` |
| 경로 구조 검사 | 새로 만들거나 이동한 문서가 명시 경로 또는 기본 라우팅에 맞는지 확인하는 검사기 |
| 미해결 검사 보고 계약 | 정확한 대상·검출 근거·운영 영향·권장 조치·대안·승인 주체를 가진 공통 표 |
| 핸드오프 검증 보강 | 미해결 FAIL이 있을 때 위 필드 누락을 잡는 `scripts/check_handoff.py` 규칙 |
| 회귀 테스트 | 명시 경로 예외, 기본 제안서 경로, 과거 문서, 완전·불완전 FAIL 보고 fixture |

승인 후에는 “어디에 쓸지”와 “무엇을 보고해야 하는지”가 사람의 기억이 아니라 생성 시점과
최종 검증 시점의 두 게이트에서 확인된다. 이로써 폴더 이관·역참조 수리와 사용자 재질문 비용을 줄인다.

새 파일 생성 전에 이를 확인하는 기계적 관문이 없다는 점이다.

**영향도 분석**

| 축 | 영향과 경계 |
|---|---|
| 코드·도구 | 승인 시 문서 생성 도우미와 정적 검사기만 바뀐다. 모델·학습 코드는 바뀌지 않는다. |
| 데이터·체크포인트 | 접근·열거·수정할 필요가 없다. 보호 경로는 검사 대상에서 제외한다. |
| 검증 | 문서 경로와 보고 형식의 구조적 PASS만 판정한다. 내용의 진실성이나 실험 성공을 대신하지 않는다. |
| 문서 단일 소스 | 기계 판독 라우팅은 한 곳만 소유하고 README는 설명·링크만 둬 경로표 중복을 피한다. |
| 운영 부채 | 도우미를 쓰지 않은 수동 작성도 최종 검사에서 잡되, 과거 문서는 기준선으로 동결한다. |

**외부 근거**

- OpenAI의 [Hooks 문서](https://learn.chatgpt.com/docs/hooks)는 `PreToolUse`가 도구 실행 전에
  차단할 수 있고, 프로젝트 훅은 검토·신뢰 및 정확한 구성 hash와 연결된다고 설명한다. 동시에 훅 도구의
  오류나 부재 자체는 전체 작업을 막지 않도록 처리된다. 따라서 문서 경로처럼 예외가 많은 정책을 훅 하나에
  맡기기보다 저장소 내부 생성 도우미와 정적 검사기를 정본으로 두는 편이 판정 근거를 보존하기 쉽다.

세부 계약은 다음과 같다.

- 사용자가 `ai_dev_tool/특정파일.md`처럼 출력 경로를 직접 지정하면 **그 파일 하나만** 예외다.
  같은 요청 묶음의 다른 산출물로 예외를 전파하지 않는다.
- 경로가 없고 문서의 목적이 승인 전 제안이면 `proposal/`을 사용한다. 승인 후 실험계획은
  `test_plan/`, 결과는 `test_result/`, 핸드오프는 `handoff/` 등 기존 전용 정본을 따른다.
- 검사기는 내용에 `FAIL`이라는 문자열이 있다는 이유만으로 실패시키지 않는다. 이번 세션에서 새로 생긴
  **미해결 검사 항목**만 구조화된 절에 등록하고 그 절의 필드 완결성을 본다.
- 계획번호 진단 예외는 번호 전체를 면제하거나 디렉터리를 통째로 제외하지 않는다. 정확한 파일·번호·사유를
  선언한 진단 기록만 허용하고, 원래 검토용 문서의 사전 번호 선점은 계속 FAIL이어야 한다.
- 구조 PASS는 위치·필드 존재만 뜻한다. 근거가 사실인지, 조치가 적절한지는 별도 리뷰 대상이다.

## 7. 거절하면 못 하는 것

현재 A19·A20의 개별 수리는 이미 완료됐으므로 저장소 사용이 막히지는 않는다. 다만 다음 문서 작성에서도
작성자가 README와 최종 보고 체크리스트를 기억해야 하며, 경로 이관·역참조 수리 또는 사용자의 추가 질문이
다시 발생할 가능성을 기계적으로 낮출 수 없다. 제안 거절이 GPU 실험이나 현재 P088 Stage10을 막지는 않는다.

## 8. 위험 — 실행하면 무엇이 잘못될 수 있나

| 위험 | 어떻게 드러나나 | 완화 |
|---|---|---|
| 명시 경로를 오탐으로 차단 | 사용자가 정확히 지정한 출력 파일을 생성하지 못함 | `--exact-path`가 아니라 현재 사용자 지시의 정확한 경로 증거를 기록하고 파일 단위 예외로 제한 |
| 과거 문서가 대량 FAIL | 레거시 `temp_`와 이전 폴더 배치가 한꺼번에 검출됨 | 승인 시점의 기준선을 동결하고 새 변경분부터 적용 |
| 라우팅 정본 중복 | README와 JSON의 폴더 값이 다시 어긋남 | 기계 값은 `.agents/project.json` 한 곳만 소유하고 README는 링크·설명만 유지 |
| 형식만 채운 빈 보고 | 필드는 존재하지만 영향·권고가 실질적으로 없음 | `없음`도 근거와 함께 쓰게 하고 사람 리뷰를 최종 게이트로 유지 |
| `FAIL` 문자열 기반 오탐 | 역사 기록·해결된 실패까지 미해결로 판정 | 전용 ‘미해결 검사’ 절과 상태 enum만 파싱 |
| 훅 오작동 또는 fail-open | 파일 작성 전 차단이 불안정하거나 정상 작업을 막음 | 권장안은 훅에 의존하지 않고 생성 도우미·저장소 정적 검사로 판정 |
| 계측 과대해석 | 구조 검사 PASS를 보고 품질·사실성까지 검증됐다고 주장 | 출력에 항상 `STRUCTURAL_ONLY`를 표시하고 증거 수준을 별도 기록 |

### ★권장안과 근거

**B안을 권장한다.** A안은 이번 오류 당시에도 이미 있던 문서 규칙과 본질적으로 같아 재발 방지력이
약하다. C안은 차단 시점은 빠르지만 문서 종류와 사용자 예외를 훅 입력만으로 판정해야 해 Git Bash 오탐과
유사한 인프라·분류 오류를 만들 수 있다. B안은 저장소 안에서 재현 가능한 fixture와 정적 결과를 남기면서,
사용자가 지정한 정확한 경로를 파일 단위로 허용한다. 승인 전에는 B안의 스크립트·설정·검사기를 구현하지 않는다.
