# 제안 — 유사도는 후행 검토 후보를 찾고 의미 판정을 대신하지 않는다

> **작성** 2026-10-01 · **상태** ⏳판단 대기 · **분류** 실험검증
> 양식: [제안서 규약](README.md) §3.
> [조건부 승인안](20261001_P106B-온라인-계약검사와-후행-품질검증-분리-제안서-approved-on-going.md) §6.4의 재제안. **유사도 구현과 임계값 적용은 승인 전 보류**다.

## 1. 배경 — 왜 지금 이 제안을 하나

[결과101 §37](../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)의 12요청은 원답18행이며 내용 화면4/4·3/4·3/4는 문자열 탐지에 불과했다. 앞 제안의 문자0.90은 검증된 문턱이 아니다. 비슷한 틀의 “A는X/A는Y”가 높게 겹쳐도 뜻은 다르므로 보편 문턱으로 재생성/격리하는 방식은 철회한다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

동결된 생성자료에서 복제 가능성이 높은 **후행 검토 후보**를 저렴하게 찾고 질문·답·수치·조건을 함께 읽어, 정상 공용표현을 불량으로 단정하지 않는다.

## 3. 성과물 — 승인하면 무엇이 생기나

| 산출물 | 형태 |
|---|---|
| 후보 검색기 | 원형 SHA에 연결한 n-gram/Jaccard·필요시 MinHash 후보쌍 |
| 검증 표본 | 길이/언어/고정답/코드/인용을 포함한 동결 calibration·별도 확인셋 |
| 검사 보고 | 경고 적중·정상 경고·검토 누락·시간/메모리, 원답과 사유 |
| 후행 계보 | 사람이/GPT가 문맥 판독한 라벨·교정본·보존 원형 연결 |

## 4. 비용

| 항목 | 양 |
|---|---:|
| GPU | ⚙0h 권장A; B 임베딩은 별도 승인 |
| AI 작업 | ⚙4~6h 구현/표본 판독 |
| 사용자가 직접 해야 하는 일 | 방법 승인1회·애매한 표본10~20쌍 확인 |
| 디스크 | ⚙50MB 이하 소형 후보/인덱스 |

## 5. 원리·근거

**우리 실측:** 현재4원천6쌍만으로 오탐률/미탐률을 추정할 수 없다. 고정 잘못된 문구 리스트를 만들지 않는다.

**외부 근거:** [Broder1997](https://www.cs.princeton.edu/courses/archive/spring13/cos598C/broder97resemblance.pdf) §2~4를 읽었다. shingle 집합의 교집합/합집합과 sketch로 어휘적 유사·포함을 근사하지만 shingle 길이·해시/표본 오차가 영향을 준다. **정답이나 의미 동치 지표가 아니다.**

[PAWS](https://aclanthology.org/N19-1131.pdf) §1~3을 읽었다. 단어가 크게 겹쳐도 어순/관계가 바뀌면 의미가 달라진다. 따라서 임베딩을 더하거나 문자 threshold를 올리는 것만으로 문맥 검증을 대체할 수 없다.

## 6. 방법

온라인 생성/학습에는 연결하지 않는다. 동일 요청 안 **원문 전체 동일** 계약은 별도 §6.3 설계가 소유하고 이 유사도 기능과 분리한다.

1. 불변 생성자료·출처·질문·답·계보를 고정한다. 제약 있는 유일답, 한국어/영어, 짧은/긴 답, 코드/수식/인용을 포함해 후보와 무작위 비후보를 함께 판독한다.
2. 권장A는 문자3/5-gram Jaccard·포함률을 비교하는 탐색이다. 문구·부정·숫자·코드 대소문자를 제거하지 않는다. 매우 짧은 답은 검색 결과와 별도 유형으로 취급한다. 전역N² 대신 같은 source/concept·동결블록 후보부터 제한한다.
3. 대규모 archive일 때만 MinHash/인덱싱을 추가한다. 샘플 근사 오류·메모리·해시 설정을 공개하고 후보의 최종 겹침은 정확 계산한다.
4. calibration은 **복제 경고**의 precision/놓침에 대해 길이·언어별로 잡는다. 임계값은 사전 고정한 별도 확인셋에서 검사하며 현재4질문에 맞추지 않는다. 목표 오류율은 승인 시 결정한다. 의미/정답 threshold는 없다.
5. 검토자는 질문 맥락에서 차이가 사실·수치·주체·부정인지 확인한다. 공용 문장·정답 공유는 정상일 수 있다. 원형은 보존하고 교정/격리 결정은 버전드 후행 자료에만 기록한다.

| 단계 | 무엇 | 비용 | 다음으로 가는 조건 |
|---|---|---:|---|
|0|후행 범위/라벨/비용 승인|⚙0GPUh|방법·검토 대상 확정|
|1|동결 후보·비후보 표본 판독|⚙2h|정상 공용표현과 실제 복제를 구분한 근거|
|2|방법/설정 calibration|⚙2h|개별유형 오탐·누락·지연 보고|
|3|별도 확인셋/자료 적용|⚙1~2h|문턱 재조정 없이 한계 보고; 자동 의미판정 금지|

## 7. 거절하면 못 하는 것

온라인 교사 생성/교육은 계속 가능하다. 후행 검토 후보 자동 검색의 비용 절감만 얻지 못하며 원답 수동 판독으로 대체할 수 있다.

## 8. 위험 — 실행하면 무엇이 잘못될 수 있나

| 위험 | 어떻게 드러나나 | 완화 |
|---|---|---|
| 공용표현 오탐 | 정상 X/Y·수식·인용에 경고 | 경고 전용·문항 유형·문맥 판독 |
| 검색 누락 | 다른 표현의 의미 복제를 못 찾음 | 비후보 무작위 표본·누락 공개 |
| 계측 위험 | Jaccard0.9를 정답/같은뜻으로 표시 | lexical 명칭·분모·설정 명시·의미판정 분리 |
| 과대 일반화 |4질문이 모든주제를 대표 | 길이/언어/내용층 구분·별도 확인셋 |

## 9. 대안

| 안 | 무엇 | 장점 | 단점 |
|---|---|---|---|
| A | 후행 lexical 후보+문맥 판독·calibration | CPU 비용·투명한 근거·온라인 지연0 | 다른 표현의 의미 복제 누락 |
| B | 후행 임베딩/NLI 후보+교차/문맥 판독 | 표현 차이 큰 후보 보강 가능 | 모델/추론 비용·주체/부정 오탐·별도 승인 |
| C | 같은 요청2/4답만 단순 문자 경고 | 좁고 저렴·원답과 함께 보기 쉬움 | 전역 후보 못찾음·온라인 경고도 재승인 필요 |

### 권장안과 근거

**A를 권장한다.** 온라인 병목 없이 검사 근거를 보여줄 수 있고, 후행 품질 검증이라는 사용자 정책에 맞는다. B는 누락 실측 후 추가하며 원문 전체 동일 외의 유사도는 자동 재생성/격리 사유가 되지 않는다.
