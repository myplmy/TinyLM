# 제안 — 유사도는 후행 검토 후보를 찾고 의미 판정을 대신하지 않는다

> **작성** 2026-10-01 · **상태** 🔄조건부 승인 후 진행 중 · **분류** 실험검증
> 양식: [제안서 규약](README.md) §3.
> [조건부 승인안](20261001_P106B-온라인-계약검사와-후행-품질검증-분리-제안서-approved-on-going.md) §6.4의 재제안. 원래 후행 전체검색 설계는 보존한다. 사용자 추가 승인 범위는 **온라인 문자A(동일요청)와 B(최근답큐) 게이트**이며 아래 §6.6이 현재 범위다. 의미 임베딩/NLI·전역검색·자동 격리·품질 threshold는 미승인이다.

## 1. 배경 — 왜 지금 이 제안을 하나

[결과101 §37](../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)의 12요청은 원답18행이며 내용 화면4/4·3/4·3/4는 문자열 탐지에 불과했다. 앞 제안의 문자0.90은 검증된 문턱이 아니다. 비슷한 틀의 “A는X/A는Y”가 높게 겹쳐도 뜻은 다르므로 보편 문턱으로 재생성/격리하는 방식은 철회한다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

동결된 생성자료에서 복제 가능성이 높은 **후행 검토 후보**를 저렴하게 찾고 질문·답·수치·조건을 함께 읽어, 정상 공용표현을 불량으로 단정하지 않는다.

## 3. 성과물 — 승인하면 무엇이 생기나

| 산출물 | 형태 |
|---|---|
| 후보 검색기 | 원형 SHA에 연결한 n-gram/Jaccard·필요시 MinHash 후보쌍 |
| 검증 표본 | 길이/언어/고정답/코드/인용을 포함한 동결 calibration·별도 확인셋 |
| 검사 보고 | 경고 적중·정상 경고·검토 누락·시간/메모리, 원답과 사유 |
| 후행 계보 | 사람이/GPT가 문맥 판독한 라벨·교정본·보존 원형 연결 |

## 4. 비용

| 항목 | 양 |
|---|---:|
| GPU | ⚙0h 권장A; B 임베딩은 별도 승인 |
| AI 작업 | ⚙4~6h 구현/표본 판독 |
| 사용자가 직접 해야 하는 일 | 방법 승인1회·애매한 표본10~20쌍 확인 |
| 디스크 | ⚙50MB 이하 소형 후보/인덱스 |

## 5. 원리·근거

**우리 실측:** 현재4원천6쌍만으로 오탐률/미탐률을 추정할 수 없다. 고정 잘못된 문구 리스트를 만들지 않는다.

**외부 근거:** [Broder1997](https://www.cs.princeton.edu/courses/archive/spring13/cos598C/broder97resemblance.pdf) §2~4를 읽었다. shingle 집합의 교집합/합집합과 sketch로 어휘적 유사·포함을 근사하지만 shingle 길이·해시/표본 오차가 영향을 준다. **정답이나 의미 동치 지표가 아니다.**

[PAWS](https://aclanthology.org/N19-1131.pdf) §1~3을 읽었다. 단어가 크게 겹쳐도 어순/관계가 바뀌면 의미가 달라진다. 따라서 임베딩을 더하거나 문자 threshold를 올리는 것만으로 문맥 검증을 대체할 수 없다.

## 6. 방법

온라인 생성/학습에는 연결하지 않는다. 동일 요청 안 **원문 전체 동일** 계약은 별도 §6.3 설계가 소유하고 이 유사도 기능과 분리한다.

1. 불변 생성자료·출처·질문·답·계보를 고정한다. 제약 있는 유일답, 한국어/영어, 짧은/긴 답, 코드/수식/인용을 포함해 후보와 무작위 비후보를 함께 판독한다.
2. 권장A는 문자3/5-gram Jaccard·포함률을 비교하는 탐색이다. 문구·부정·숫자·코드 대소문자를 제거하지 않는다. 매우 짧은 답은 검색 결과와 별도 유형으로 취급한다. 전역N² 대신 같은 source/concept·동결블록 후보부터 제한한다.
3. 대규모 archive일 때만 MinHash/인덱싱을 추가한다. 샘플 근사 오류·메모리·해시 설정을 공개하고 후보의 최종 겹침은 정확 계산한다.
4. calibration은 **복제 경고**의 precision/놓침에 대해 길이·언어별로 잡는다. 임계값은 사전 고정한 별도 확인셋에서 검사하며 현재4질문에 맞추지 않는다. 목표 오류율은 승인 시 결정한다. 의미/정답 threshold는 없다.
5. 검토자는 질문 맥락에서 차이가 사실·수치·주체·부정인지 확인한다. 공용 문장·정답 공유는 정상일 수 있다. 원형은 보존하고 교정/격리 결정은 버전드 후행 자료에만 기록한다.

| 단계 | 무엇 | 비용 | 다음으로 가는 조건 |
|---|---|---:|---|
|0|후행 범위/라벨/비용 승인|⚙0GPUh|방법·검토 대상 확정|
|1|동결 후보·비후보 표본 판독|⚙2h|정상 공용표현과 실제 복제를 구분한 근거|
|2|방법/설정 calibration|⚙2h|개별유형 오탐·누락·지연 보고|
|3|별도 확인셋/자료 적용|⚙1~2h|문턱 재조정 없이 한계 보고; 자동 의미판정 금지|

### 6.1 사용자용 보완 — 세 안은 ‘언제, 어디까지, 무엇으로 찾는가’가 다르다

세 안 모두 유사도가 높다는 이유만으로 재생성하거나 격리하지 않는다. **검색 결과는 검토 후보이지 불량 판정이 아니다.**

| 안 | 검사 시점·범위 | 비교 방법 | 마지막 판단 |
|---|---|---|---|
| A | 생성이 끝난 고정 자료의 제한된 후보 블록. 다른 요청의 답도 비교 가능 | 글자/단어 조각이 얼마나 겹치는지 계산 | 실제 질문과 두 답을 사람/GPT가 읽어 정상 공용표현·복제를 구분 |
| B | A와 같은 후행 자료. 표현이 다른 후보까지 보강 | 임베딩으로 의미가 가까워 보이는 후보 검색, 필요시 NLI 관계 분석 | 모델 점수도 정답 판정이 아님. 질문·근거를 함께 읽고 확인 |
| C | 현재 한 요청의 답2~4개만 비교. 다른 요청/전체 코퍼스는 검색하지 않음 | 가벼운 문자 겹침 수치를 경고로 표시 | 경고만 남김. 맥락 판독·수정은 나중에 수행 |

### 6.2 같은 사례에 적용하면 무엇이 달라지나

**사례1 — “A는X입니다”와 “A는Y입니다.”**

A의 글자 조각은 많이 겹칠 수 있다. 그러면 비슷한 문형 후보로 보여주되 X/Y가 다른 값이라는 사실을 원문에서 확인한다. **둘 다 올바른 상황일 수도 있으므로** 높은 값만으로 중복 불량이라고 하지 않는다. B도 의미 벡터가 비슷하게 나올 수 있어 자동 해결책이 아니다. C는 두 답이 같은 요청에서 나왔을 때만 경고를 보여준다.

**사례2 — “파리는 프랑스의 수도입니다”와 “프랑스의 수도는 파리입니다.”**

표현 순서는 다르지만 같은 사실을 말한다. A는 문구 겹침으로 후보를 찾을 수 있으나 표현 변화가 커지면 놓칠 수 있다. B는 의미가 비슷한 후보를 더 잘 찾을 가능성이 있지만 실제 효과는 별도 검증해야 한다. 두 문장이 같은 개념의 의도된 한국어 표현 연습이라면 정상 변형이다. 같은 사실을 여러 번 생성했다는 이유만으로 저품질·삭제로 판정하지 않는다.

**사례3 — “파리는 프랑스의 수도입니다”와 “파리는 독일의 수도입니다.”**

문형·주제가 비슷하므로 A와 B 모두 비슷한 후보로 묶을 수 있다. 하지만 이 둘의 문제는 문자 유사도가 아니라 **사실이 다른 것**이다. 질문·근거를 확인하는 후행 단계에서 다룰 일이며, 유사도 검색기가 올바른 문장을 선택해 주지는 않는다. NLI가 서로 다른 진술을 찾아도 어느 나라의 수도가 참인지는 독립 근거가 필요하다.

**사례4 — 자료5만 행에서 여러 요청에 걸쳐 같은 설명이 복제됨**

A는 동결 자료의 원천/개념/후보 인덱스로 검토할 쌍을 찾는다. B는 표현을 크게 바꾼 복제 후보를 추가로 찾을 수 있지만 모델 추론 비용이 있다. C는 요청 하나 안의 답만 비교하므로 서로 다른 요청 사이의 복제를 찾을 수 없다. 자료5만 행 전체를 전부 서로 비교하는 N² 작업을 온라인 생성에 넣자는 안은 아니다.

### 6.3 권장 순서와 비용 차이

**A부터 권장**하는 이유는 글자 조각의 겹침이라는 관찰 근거를 보여줄 수 있고, CPU 후행 작업으로 생성 속도에 영향을 주지 않기 때문이다. 대표 후보와 무작위 비후보를 실제로 판독해 정상 표현 오탐·놓친 복제를 확인한다. 한국어 길이/공백·짧은 정답·코드/수식별로 나눠 보며 보편0.90 같은 값을 확정하지 않는다.

A가 같은 의미의 다른 표현을 많이 놓친다는 근거가 생기면 B를 추가한다. B는 별도의 모델 선택·권리·언어 적합성·처리시간 검증이 필요하다. C는 작은 비용으로 답2~4개를 함께 보는 데 적합하지만 전체 데이터셋 검증을 대신하지 못한다.

A/B에서 사람이든 GPT든 하는 일은 **검색기의 점수를 확인하는 것**이 아니라 질문과 실제 답을 문맥으로 읽는 것이다. 모든 행의 사전 승인을 온라인 교육의 선결로 만들지 않으며, 원형과 나중의 교정/격리 사유를 연결한다. 세 안은 방법 선택 전까지 구현 보류다.

### 6.4 A의 계산 방법 — 문자를 조각으로 나누어 겹치는 부분을 보여준다

**아직 구현·임계값 승인은 없다.** A는 정답 검사기가 아니라 후보 검색기다. 원형 SHA·질문 ID를 고정한 복사본에서 전송용 줄끝만 맞추고, 숫자·부정·코드 대소문자·외국어 인용은 지우지 않는다. 공백 정규화본을 탐색용으로 추가하더라도 원문 계산과 구분해 저장한다.

- 답을 연속 문자3개 또는5개 조각의 집합으로 만든다. 예를 들어 ‘파리는’의3글자 조각과 ‘프랑스의 수도’의 조각을 비교하는 방식이다. 조사/공백 차이 때문에 두 길이를 별도 실험한다. 정답 단어가 짧아 조각을 만들 수 없으면0점으로 판정하지 않고 ‘짧은 답·별도 검토’로 남긴다.
- 겹침 비율 `J(A,B)=공통 조각 수 / 전체 서로 다른 조각 수`를 계산한다. 한 답이 다른 답의 일부인지 보려면 방향별 포함률 `C(A→B)=공통 조각 수 / A의 조각 수`도 계산한다. 긴 답과 짧은 답의 Jaccard가 낮아도 포함률은 높을 수 있으므로 둘을 섞어 하나의 품질 점수로 만들지 않는다.
- 우선 같은 요청·개념 가족 안의 답부터 정확 계산한다. 다른 요청을 찾을 때는 조각→문서 ID 역색인으로 겹치는 조각이 있는 후보를 모은다. 매우 흔한 조각은 후보 폭증을 만들므로 제외/가중 여부와 누락 가능성을 공개한다. 대규모 자료에서만 MinHash/LSH 후보 검색을 추가하고, 최종 후보쌍의 겹침은 원문 조각으로 다시 정확 계산한다. MinHash는 계산량을 줄이는 근사이지 맥락 이해가 아니다.
- 후보와 무작위 비후보를 한국어/영어·길이·수식/코드·고정답별로 판독한다. 설정용 표본에서 검색 문턱을 고정한 뒤 별도 확인셋에서 정상 후보 비율·놓친 복제를 확인한다. 단일 보편 threshold는 지금 확정하지 않는다. 검토 목록 수를 제한하는 상위 k개 선택도 비용 제어일 뿐 불량 기준이 아니다.

결과 화면은 **질문 전문, 답 두 개, 겹친 실제 구간, 다른 숫자/주체/부정, 검색 수치**를 함께 보여준다. “A는X/A는Y”의 높은 겹침은 문형이 비슷하다는 관찰일 뿐 같은 뜻·잘못된 답이라는 판정이 아니다. [Broder의 조각 집합·근사 검색](https://www.cs.princeton.edu/courses/archive/spring13/cos598C/broder97resemblance.pdf)을 이 용도로만 차용한다.

### 6.5 B의 계산 방법 — 의미 벡터로 후보를 찾고 관계를 추가 검토한다

B는 A에 **다른 표현의 후보 검색**을 보강한다. [Sentence-BERT](https://arxiv.org/pdf/1908.10084)의 문장 벡터/코사인 비교 원리를 참고하지만 그 영어 실험 성능을 한국어 자료에 그대로 적용하지 않는다. 언어·권리·자원에 맞는 모델 선정과 소형 확인이 선결이며 모델 실행·다운로드는 별도 승인 사항이다.

1. 질문과 답을 별도 필드로 유지하고, 답 전체 또는 긴 답의 의미 단락을 임베딩 벡터로 만든다. 모델 토큰 창을 넘는 답은 무단 절단하지 않고 단락과 원문 위치를 연결한다. 질문을 함께 넣은 벡터는 질문 유사성만으로 후보가 묶일 수 있어 답 벡터와 구분해 비교한다.
2. 코사인 값으로 가까운 상위 k개 답을 찾는다. 먼저 같은 언어/관련 개념 블록을 쓰고, 번역 복제가 검토 목적일 때만 한영 교차 검색을 추가한다. 벡터가 가깝다고 동치나 정답으로 표시하지 않는다. ‘복용한다/복용하지 않는다’처럼 핵심 부정이 달라도 가까울 수 있다.
3. 후보쌍에 필요시 NLI 모델을 붙여 A가 B를 함의하는지, B가 A를 함의하는지, 상충하거나 판단 불가인지 각각 조사한다. 양방향 함의 추정은 동치 후보의 보조 근거이며 세계 사실의 진위 판정이 아니다. 모델의 어순·수치·부정 실패는 [PAWS](https://aclanthology.org/N19-1131/) 같은 어려운 관계 사례와 자체 한영 표본으로 확인한다.
4. 사람이/GPT가 실제 질문·조건·근거를 읽고 정상 변형인지 복제인지 판독한다. A가 놓치고 B가 찾은 후보, B의 정상 표현 오탐, 무작위 비후보의 누락을 함께 측정한다. 임베딩/NLI 모델명·버전·입력 길이·시간·메모리와 설정을 보고한다.

**선택 차이:** A는 겹친 문구를 직접 보여줘 CPU 비용과 해석이 단순하지만 ‘표현은 다르고 뜻은 비슷한 답’을 놓칠 수 있다. B는 그 누락을 보강할 수 있지만 별도 모델 비용·오류가 추가된다. C는 동일 요청2~4답의 문자 겹침만 표시하는 좁은 도구다. A/B 모두 생성 이후의 검토 후보 검색이며 온라인 재생성·자동 격리에는 연결하지 않는다.

### 6.6 현재 승인 — 온라인 문자 A/B 비교, 문제 시 A로 되돌릴 수 있게 한다

앞 §6.1~6.5의 **후행 B(임베딩/NLI)**와 여기의 **온라인 문자 B(최근답큐)**는 다른 기능이다. 사용자는 온라인 문자 A/B를 모두 게이트로 시험하고, B의 속도 저하가 작을 때 채택을 고려하되 후행 경고 판독에서 문제가 많으면 A로 전환하도록 승인했다.

- A는 현재 요청2~4답의3/5-gram Jaccard·방향별 포함률·겹친 실제 조각을 기록한다. ‘1’ 같은 짧은 답은 점수null/짧은답으로 표시한다.
- B는 A에 최근32답(상한64)·텍스트256KiB 제한 큐를 더한다. 과거 답과 계산한 후보는 높은 겹침 상위3쌍만 보여준다. 상위3은 화면 비용 제한이지 불량 threshold가 아니다. 원질문·두 답을 함께 저장한다.
- 점수나 경고는 재시도/수락/학생 손실 마스크에 영향0이다. 전역 잘못된 문구 목록은 없다. 코드의 `mode=within/recent`로 변경 가능하며 현재 교육 기본은 A다.
- [CPU 비교 게이트](../scripts/diag_p106b_lexical_modes.py)는 정확 동결 교사 답12요청/18행을 두 모드에서 동일하게 재생하고 요청당 median/p95·CPUpeak·표시쌍과 실문구를 남긴다. 새 모델 추론이나 온라인 GPU 속도 검증으로 부르지 않는다. 사전 비용선 p95≤200ms/요청·CPUpeak≤32MiB는 이 소형 비용 시험의 기준이며 품질선이 아니다.
- 실물 교사 연결은 [소형 계약 게이트](../scripts/diag_p106b_contract_gate.py)와 새 v33의 raw 문자 관찰에서 확인한다. B 기본 채택은 처리 비용 결과와 원질문/후보를 후행 판독한 뒤 별도 결정한다. CPU 게이트만 통과해 오탐이 적다거나 실제 전체wall 손익이 확인됐다고 하지 않는다.

종료조건은 A/B 비용 관측·모드 전환·수락 불변 회귀와 후행 후보 판독 결과의 분리다. 임베딩/NLI 검증은 추후 같은 자료 SHA·ID를 사용하는 별도 후행 작업으로 남는다.

## 7. 거절하면 못 하는 것

온라인 교사 생성/교육은 계속 가능하다. 후행 검토 후보 자동 검색의 비용 절감만 얻지 못하며 원답 수동 판독으로 대체할 수 있다.

## 9. 대안

| 안 | 무엇 | 장점 | 단점 |
|---|---|---|---|
| A | 후행 lexical 후보+문맥 판독·calibration | CPU 비용·투명한 근거·온라인 지연0 | 다른 표현의 의미 복제 누락 |
| B | 후행 임베딩/NLI 후보+교차/문맥 판독 | 표현 차이 큰 후보 보강 가능 | 모델/추론 비용·주체/부정 오탐·별도 승인 |
| C | 같은 요청2/4답만 단순 문자 경고 | 좁고 저렴·원답과 함께 보기 쉬움 | 전역 후보 못찾음·온라인 경고도 재승인 필요 |

### 권장안과 근거

**A를 권장한다.** 온라인 병목 없이 검사 근거를 보여줄 수 있고, 후행 품질 검증이라는 사용자 정책에 맞는다. B는 누락 실측 후 추가하며 원문 전체 동일 외의 유사도는 자동 재생성/격리 사유가 되지 않는다.
