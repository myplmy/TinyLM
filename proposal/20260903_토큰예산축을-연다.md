## 1. 배경 — 왜 지금 이 제안을 하나

### 1.1 승자가 심하게 미학습이다

| 모델 | 파라미터 | 학습 토큰 | ★**토큰/파라미터** |
|---|---:|---:|---:|
| `d12_cla2_r20`(32 MiB 승자) | **81.17M** | 300M | ★**3.70** |
| `d16_cla2_r20`(40 MiB 승자) | **105.37M** | 300M | ★**2.85** |
| Chinchilla 최적 | — | — | 20 |
| **SmolLM2-1.7B** | 1.7B | **11T** | ★**약 6,470** |

→ ★★**우리는 SmolLM2 의 약 1/1,750 이다.** 초록이 스스로 *overtrain* 이라고 밝힌 모델이지만,
**1,750배는 그 말로 설명되지 않는다.**

### 1.2 ★★그리고 이 축은 **배포 상주를 1바이트도 안 늘린다**

지금까지 잰 모든 레버는 상주를 사고팔았다(§3 의 표). 토큰은 다르다 —
**학습만 길어지고 배포되는 것은 같은 텐서**다.

### 1.3 ★깊이 곡선이 이미 신호를 보내고 있었다

d8/d12/d16/d20 = **3.6776 / 3.6130 / 3.5757 / 3.5418**. 층당 이득이 줄지만
**평평해지지 않는다**(−0.0162 → −0.0093 → −0.0085). 🚫**예측 E2 가 16.1배 빗나갔다.**
⚠️★**깊은 팔일수록 토큰/파라미터가 더 낮다**(3.70 → 2.85) — *"깊이가 좋다"* 로 읽은 것의
일부가 실은 *"덜 굶었다"* 일 수 있다. **이건 예측이지 측정이 아니다.**

★**독립변수 = 학습 토큰 수(300M vs 600M), 나머지 전부 고정.**
*"상주를 안 늘리는 이 축이 우리 구간에서 살아 있는가"* 를 **2런에 답한다.**

## 3. 성과물

| 산출물 | 형태 |
|---|---|
| ★**토큰 축의 기울기 1점** | `d12_cla2_r20` 의 300M → 600M Δfull-val (재귀 자 0.0018 대비) |
| **깊이 축과의 교환비** | Δ / GPU-h 를 깊이(d12→d16, −0.0412 @ +1.6h)와 나란히 |

| ⚠️**부수** | ★**풀 1.2B 의 val 이 한국어 0% 라는 사실의 실운영 확인**(§5.3) |

★**"~ 를 알게 된다" 가 바꾸는 것**: 이득이 크면 **REVIEW3 의 배포 후보 선정 기준 자체가
바뀐다** — 같은 상주에서 더 좋은 모델을 **아키텍처가 아니라 학습으로** 얻는다.

## 5. 원리·근거

### 5.1 우리 실측

| 근거 | 값 | 출처 |
|---|---|---|
| **풀만 2배로 dense 가 −0.12** | 시간 0 | 결과 006 |
| 깊이 d12→d16 | −0.0412 @ +1.6h | 결과 067 §11 |
| 재귀 자(cla2) | **0.0018** | 결과 039 §12 |
| ★**승자 시드 재현** | Δ −0.0004(t −0.24) | 결과 067 §12.1 |

★**마지막 줄이 이 실험을 가능하게 한다** — 시드 노이즈가 자의 1/5 이므로
**1시드 2팔로도 0.01 급 차이를 읽을 수 있다.**

### 5.2 외부 근거

| 자료 | 무엇 | 조회 |
|---|---|---|
| **SmolLM2**(HF `HuggingFaceTB/SmolLM2-1.7B`) | 11T 토큰 / 1.7B, 초록이 **overtrain 명시** | ✅서지·초록 확인. 🚫**전문 미독** |
| **arXiv:2305.16264**(Muennighoff 외) | 데이터 제약 스케일링 — **4 epoch 까지 거의 무손실** | ✅초록·요약 확인. 🚫**전문 미독**. ⚠️**고정 compute 가정이라 우리에 직접 적용 아님** |

### 5.3 🚫★★★**진짜 선결은 풀이 아니었다 — 그것이 이 제안의 핵심이다**

40MB 문서는 선결을 *"풀 1.2B 준비"* 라고 적었다. **그 풀은 이미 있다**
(`data_cache/ko-en_1200000000`, 1,194,000,000 토큰, 2026-08-06 빌드).
🚫**막고 있던 것은 다른 것이었다.**

`scripts/diag_val_lang.py` 를 돌려 실측했다(학습 0 · torch 0):

| 캐시 | val 토큰 | ★**val 한글 비율** | train 90% 지점 |
|---|---:|---:|---:|
| `ko-en_300000000` | 1.5M | **14.8%** | 10.2% |
| `ko-en_600000000` | 3.0M | **5.8%** | 3.3% |
| ★**`ko-en_1200000000`** | 6.0M | 🚫★**0.0%** | 0.0% |

★**val 은 스트림 말미 0.5% 인데, 한국어 소스(위키피디아)가 먼저 고갈된다.**
1.2B 풀의 소스 비율은 **위키 25.0% / fineweb-edu 75.0%**(요청은 50/50 이었다) —
한국어 위키에 **300M 토큰밖에 없다.**

→ 🚫★★**풀을 바꾸면 시험지가 바뀐다.** 도구가 스스로 판정한다:
*"풀이 다른 런끼리 val_loss·bpb 를 비교하면 안 된다."*

★★**해결은 설계로 한다 — 두 팔을 같은 풀에 둔다.**

| 종전 설계(40MB 문서) | ★**이 제안** |
|---|---|
| 기존 300M 런(풀 600M) **vs** 새 600M 런(풀 1.2B) | ★**둘 다 풀 1.2B** — 300M 팔을 **새로 돌린다** |
| 🚫**토큰·풀·시험지 세 축이 동시에** 움직인다 | ✅**토큰 하나만** 움직인다 |
| ⚙6.4h(2모델 × 1팔) | ⚙**5.1h**(1모델 × 2팔) |

⚠️★**대가 하나**: 이 두 팔의 값은 **기존 300M 수치와 비교할 수 없다.**
**축의 기울기만** 얻는다. 🚫**그것으로 충분하다** — 우리가 묻는 것이 기울기다.

⚠️★★**그리고 남는 구멍 하나**: 풀 1.2B 의 val 은 **한국어를 하나도 안 잰다.**
학습 스트림에는 한국어가 25% 있는데 **시험지에는 0%** 다.
→ 🚫**이 실험은 "한국어 품질이 어떻게 되는가" 를 답하지 않는다.** §8 위험표에 넣었다.

## 6. 방법

| 단계 | 무엇 | 비용 | ★**다음으로 가는 조건** |
|---|---|---:|---|
| **0** | 풀 1.2B 무결 확인(`meta.json` · `diag_val_lang`) | ✅**완료**(2026-09-03) | — |
| ★**1** | `d12_cla2_r20_p12` — **300M 토큰 / 풀 1.2B**(대조) | ⚙1.7h | `skip 0` · `grad_max < 10` · `val−train_ce < 0.3` |
| ★**2** | `d12_cla2_r20_p12_t600` — **600M 토큰 / 풀 1.2B** | ⚙3.4h | 같음 |
| **3** | `paired_eval` 로 두 팔 비교(같은 val) | ⚙2분 | ★**Δ가 재귀 자 0.0018 의 몇 배인가** |
| **4** | 다운스트림 3종(hellaswag·piqa·arc_easy) + `--wandb` | ⚙6분 | ⚠️**n=400 은 0.04 nats 급을 못 읽는다**(067 §12.5) |

```
--tokens 1200M --pool-tokens 1200M --exact-cache --steps 4578 --micro-bs 8 --accum 16 --seq 1024
```

⚠️`--no-ckpt` 예산: `M x 방문 = 8192 x 20 = 163,840 <= 294,912` ✅
⚠️**단계 1 은 `--steps 2289`**, 나머지는 문자 그대로 동일하게 둔다.

## 7. 거절하면 못 하는 것

- 🚫**"상주를 안 늘리는 레버가 남아 있는가" 를 모른 채** 아키텍처 축을 계속 판다.
- ⚠️**정직하게**: 거절해도 **당장 막히는 것은 없다.** REVIEW3 배포안도, P083 도 진행된다.
  이 축은 **상한을 올리는 것**이지 현재 후보를 막는 것이 아니다.
- ★**다만 미루는 비용이 비대칭이다** — 5.1h 로 *"열린다/닫힌다"* 를 아는 축인데,
  **닫혀 있으면 그것도 결과**이고(가설 기각도 결과다) **열려 있으면 판을 바꾼다.**

### ★권장안 — **A**

**근거 셋**:

1. ★**유일하게 교락이 없다.** B 는 3축이 동시에 움직이고, C 는 결과 006 을 위반한다.
2. ★**가장 싸다**(5.1h). 원안보다 **1.3h 싸면서** 판정이 선다.
3. ★**선결이 0 이다.** 풀은 이미 있고(§4), 게이트 넷은 기존 것을 그대로 쓴다.

⚠️**D 는 기각이 아니라 별건**이다 — 공통 val 고정은 **P007 계열 풀 비교 전체**를 여는

> ★**승인하면**: `test_plan/` 에 계획서를 쓰고(번호는 신규), 배치 하나를 만든다.

## 10. ★★사용자 조건부 승인에 대한 답 — **풀 실사 결과** (2026-09-03)

> 사용자 지시: *"600M학습토큰 1200M학습토큰 확보가 가능한지 검토하고 검토결과에 따라 조건부승인."*

### 10.1 디스크 실사

| 캐시 | 존재 | `train` 토큰 | 구성 |
|---|---|---:|---|
| `ko-en_600000000` | ✅ | 597,000,000 | (meta 에 mix 기록 없음 — 구형) |
| ★`ko-en_1200000000` | ✅ | **1,194,000,000** | ko 위키 **300,186,620** + fineweb-edu **899,813,544** = **ko 25.1%** |

### 10.2 판정 — **600M 은 가능, 1200M 은 불가**

규칙(결과 006): ★**풀 ≥ 학습토큰의 2배.**

| 학습토큰 | 필요 풀 | 있는가 | 판정 |
|---:|---:|---|---|
| 300M(현재) | 600M | ✅ 1.2B | ✅ |
| ★**600M** | **1.2B** | ✅ **정확히 2.0배** | ★**가능. 지금 바로 돌 수 있다** |
| 🚫**1200M** | **2.4B** | 🚫 **없다**(최대 1.2B = **1.0 epoch**) | 🚫**결과 006 정면 위반** |

### 10.3 ★★2.4B 풀을 만들 수 있나 — **한국어가 병목이다**

1.2B 풀의 한국어는 **`wikimedia/wikipedia` 한국어 전량 300,186,620 토큰**이다.
★**더 뽑을 것이 없다** — 같은 소스로는 **이미 바닥**이다.

→ 2.4B 를 만들면 영어(fineweb-edu)만 늘어나 **한국어 비율이 25.1% → 약 12.5%** 로 반토막난다.
🚫**그러면 "토큰만 늘렸다" 가 아니라 "언어 혼합비까지 바꿨다" 가 된다**(함정 2).

⚠️★**게다가 1.2B 풀의 val 은 한국어 0.0%** 다(`diag_val_lang.py` 실측).
**이 풀 위의 결론은 처음부터 영어에 관한 것**이고, 2.4B 로 가면 그 편향이 더 커진다.

### 10.4 ★조건부 승인의 이행 — **안 A 를 600M 팔로 확정한다**

| 항목 | 값 |
|---|---|
| 풀 | `ko-en_1200000000`(있다. 새로 만들 것 없다) |
| 팔 | **300M**(대조) vs ★**600M**(처치) — 같은 풀·같은 시험지 |
| ⚙비용 | 300M 약 1.7h + 600M 약 3.4h = ★**약 5.1h** |
| 🚫제외 | **1200M 팔** — 풀 2.4B 가 없고, 만들면 혼합비가 바뀐다 |
