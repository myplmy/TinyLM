# 제안 — 핸드오프 실험 큐와 스모크 상태의 무손실 계승

> **작성** 2026-09-12 · **상태** ⏳판단 대기 · **분류** 핸드오프 / 실험 운영
> 양식: [`proposal/README.md`](README.md) §3. **승인 전 구현하지 않는다.**

---

## 1. 배경

[`handoff/202609120551_HANDOFF.md`](../handoff/202609120551_HANDOFF.md) §7은 후속 실험 8개,
24개 학습 팔, 최대 48.4h를 순서·큐 id·파일명·시간·선결·근거와 함께 기록했다. 그런데
[`handoff/202609121610_HANDOFF.md`](../handoff/202609121610_HANDOFF.md) §7은 “이번 세션에서
로그·계획·큐를 재감사하지 않았다”는 이유로 첫 행만 남기고 나머지 7개를 직전 문서 링크로 대체했다.

2026-09-12 재감사에서 다음을 확인했다.

| 항목 | 실측 |
|---|---|
| 후속 배치 파일 | 8/8개 루트에 존재 |
| `python scripts/queue_menu.py --audit` | 문제 0건 |
| `queue_menu.py --ids` | id 3~10 |
| TSV 시간 합 | 48.4h |
| 현재 실행 판정 | 첫 배치도 P088 Stage10 종료 확인·GPU 유휴·스모크 PASS 전에는 대기; 2~8은 앞 단계 결과 게이트 추가 |

또한 직전 핸드오프 이후 `.codex/check_environment.py`라는 코드 파일을 변경했지만 최신 핸드오프의
사용자 요청에는 `run_smoke_check.bat`가 없었다. Codex 작업규약 R21은 코드 변경 뒤 스모크를
사용자에게 요청하도록 하고, Codex 06은 동적 스모크를 장시간 큐보다 먼저 두며 AI가 직접 실행하지
않는다고 정한다. **목록 존재**, **즉시 실행 가능**, **사용자 실행 필요**를 한 상태로 압축한 것이 두
누락의 공통 원인이다.

## 2. 목적

새 핸드오프가 직전 핸드오프의 미완료 실험 큐와 동적 검증 의무를 행 단위로 계승하고, 각 항목의
현재 실행 가능 여부와 재검증 필요성을 별도 상태로 표시하게 한다.

## 3. 성과물

승인하면 다음 산출물이 생긴다.

| 산출물 | 내용 |
|---|---|
| 핸드오프 큐 계승 계약 | 직전 §7의 미완료 배치를 새 §7에 전수 기입하거나 제외 사유를 행별 기입 |
| 실행상태 열 | `READY`, `GATED`, `HOLD`, `DONE`, `REVALIDATE` 중 하나와 근거 시각·출처 |
| 스모크 disposition | `REQUIRED_USER_RUN`, `NOT_REQUIRED(근거)`, `NOT_RUN_PENDING` 중 하나 |
| 사용자 요청 동기화 | 스모크·큐·삭제·기타 요청을 §6b와 최종 대화에 동일하게 기입 |
| 기계 검사 | 이전/현재 핸드오프의 배치 집합 차이, 제외 사유, 스모크 명시 여부를 검사하는 fixture |

기존 핸드오프는 역사 기록으로 소급 수정하지 않는다. 이번에 사용자가 명시한 최신 핸드오프만 보강한다.

| AI 작업 | ⚙2~3 engineer-h |

| 디스크 | ⚙100 KiB 미만 |

## 5. 원리·근거

**저장소 실측 근거**

- Codex 02 §4·§8.3a·§9는 권장 실험의 번호·배치명·시간·선결·근거와 사용자 요청의
  실행·삭제·기타 세 갈래를 요구한다.
- Codex 작업규약 R21은 코드 변경 뒤 사용자에게 `run_smoke_check.bat`를 요청하며 정적 검사가
  동적 검증을 대신하지 않는다고 정한다.
- Codex 06 §2.2·§4는 동적 스모크를 사용자 실행 증거로 분리하고 장시간 큐보다 먼저 두도록 한다.
- 2026-09-12 현재 큐 도구 실측은 8개 모두 존재, id 3~10, 합계 48.4h, 표↔파일 문제 0건이다.

**판단 원리**

재감사하지 않았다는 사실은 기존 행을 `READY`로 새로 인증하지 못하게 할 뿐, 존재가 확인된 행을
핸드오프에서 삭제할 근거가 아니다. 안전한 계승은 행을 남기고 `REVALIDATE` 또는 `GATED`로 낮추는
것이다. 마찬가지로 스모크를 AI가 실행하지 않았다는 사실은 `NOT_RUN_PENDING`으로 적을 근거이지,
사용자 요청에서 생략할 근거가 아니다.

외부 논문 근거는 필요 없다. 이 제안은 저장소 운영 계약과 실제 파일·TSV의 정합 문제다.

## 6. 방법

| 단계 | 작업 | 다음 단계 게이트 |
|---|---|---|
| 0 | 사용자가 Codex 02·스킬·검사기 변경 범위를 별도 승인 | 파일 allowlist 확정 |
| 1 | 이전·현재 핸드오프에서 §7 배치 파일명을 구조적으로 추출 | 중복·누락 없이 파싱 |
| 2 | 이전 미완료 배치마다 새 행 또는 `제외/완료 이관` 행을 강제 | 집합 차이가 전부 설명됨 |
| 3 | `인벤토리 상태`와 `즉시 실행 상태`를 분리 | `REVALIDATE`가 누락으로 변환되지 않음 |
| 4 | 이번 diff의 코드·배치·모델 경로를 보고 스모크 disposition을 산출 | 필수인데 §6b에 없으면 FAIL |
| 5 | §7, §6b, compact·시작 프롬프트, 최종 보고를 상호 대조 | 같은 실행 요청 집합 |
| 6 | 과거 정상·누락 사례로 회귀 검사 | 8→1 축소와 스모크 침묵 fixture가 FAIL |

권장 검사 규칙은 다음과 같다.

1. 직전 핸드오프의 `-done`이 아닌 배치 중 새 핸드오프에 없는 파일은 정확한 완료·취소·대체 근거가
   없으면 오류다.
2. 로그·계획·큐를 재감사하지 않았으면 행을 없애지 않고 상태를 `REVALIDATE`로 둔다.
3. 코드 diff가 있거나 장시간 큐를 권장하면 `run_smoke_check.bat`의 `REQUIRED_USER_RUN`,
   `NOT_REQUIRED(정확한 근거)`, `NOT_RUN_PENDING` 중 하나가 반드시 있어야 한다.
4. `REQUIRED_USER_RUN`이면 §6b에 정확한 명령과 PASS 기준, 큐보다 먼저라는 선결을 적는다.

## 7. 거절하면 못 하는 것

이번 최신 핸드오프를 수동으로 바로잡는 것은 이 제안을 거절해도 가능하다. 다만 다음 핸드오프에서도
“재검증하지 않았으니 목록에서 뺀다”거나 “AI가 실행하지 않으니 사용자 요청에도 쓰지 않는다”는 같은
압축 오류를 기계적으로 차단할 수 없다.

## 8. 위험

| 위험 | 영향 | 완화 |
|---|---|---|
| 낡은 큐를 무조건 복사 | 끝난 배치가 재권장됨 | `DONE/제외` 근거와 현재 파일·TSV 존재 감사 |
| 모든 행을 `READY`로 오해 | 선결 미충족 GPU 실행 | 실행상태 열과 선결 열을 분리, 기본값 `REVALIDATE` |
| 스모크를 환경 코드 검증으로 과대 주장 | `.codex` 변경이 모델 스모크로 검증됐다고 오보고 | 스모크 적용 범위와 환경 검사 범위를 별도 판정 |
| 검사기가 문구만 요구 | 근거 없는 `NOT_REQUIRED` 남발 | 변경 경로·직전 상태와 disposition 이유를 대조하는 fixture |
| 핸드오프가 지나치게 길어짐 | 가독성 저하 | 표는 전수 유지하고 상세 근거는 계획·결과 정본 링크로 연결 |
| 사용자 실행과 AI 실행 경계 혼동 | AI가 GPU/모델 로딩 | `REQUIRED_USER_RUN`은 사용자 전용임을 고정 |

## 9. 대안

| 안 | 내용 | 장점 | 단점 | 영향도 |
|---|---|---|---|---|
| A | 직전 §7을 그대로 복사 | 누락은 적음 | 끝난 상태와 id 변화가 반영되지 않음 | 문서 낮음, 오실행 위험 중간 |
| **B** | 전수 계승 후 각 행을 현재 파일·TSV와 대조하고 실행상태를 별도 표시 | 정보 무손실과 안전한 보류를 함께 달성 | 표가 길고 상태 갱신 절차가 필요 | 문서·검사 중간 |
| C | 매 세션 전체 로그·계획·큐를 재감사하지 않으면 §7을 비움 | 새 오판 가능성은 낮음 | 다음 세션이 큐 자체를 잃고 이번 사고를 반복 | 운영 위험 높음 |
| D | `queue_menu.py` 출력만 자동 삽입 | 파일·id·시간은 정확 | 과학적 순서·선결·스모크 의무를 설명하지 못함 | 자동화 중간 |

### 권장안

**B를 정본으로 하고 D를 보조 입력으로 사용한다.** 파일·id·시간은 큐 도구에서 가져오되, 이전 행의
과학적 선결과 현재 실행상태는 무손실 계승 계약으로 검증한다. 스모크는 별도 disposition으로 강제한다.

| 영향 축 | 판정 | 내용 |
|---|---|---|
| GPU·사용자 실행 | 있음 | AI 실행은 0건, 사용자 스모크가 장시간 큐 선결 |
| 데이터셋·체크포인트 | 없음 | 읽기·변경하지 않음 |
| 실험 비교 가능성 | 개선 | 단계별 게이트와 보류 상태를 보존 |
| 문서 정본 | 있음 | Codex 02·session-handoff·검사기 동시 정합 필요 |
| 테스트 | 있음 | 8→1 누락, stale id, 스모크 침묵 회귀 fixture |
| 증거 수준 | 개선 | 존재·정적 감사·동적 PASS를 분리 |
| 기술부채 | 감소 | 링크만 남기는 손실성 계승을 차단 |

이 문서는 제안이며 `ai_dev_tool/Codex/02_핸드오프_규약.md`, `.agents/skills/**`, 검사기,
`run_smoke_check.bat`을 수정하거나 실행하는 승인이 아니다.
