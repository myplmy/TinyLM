# 제안 — 유일 출력은 재생성하지 않고 명시된 변형 계약만 회복한다

> **2026-10-17 현재 상태:** 문서 끝의 새 회수 절을 우선한다. 아래 날짜별 실행0·NOT_RUN은 당시 범위이며, 새 학생/원답의 존재와 이 제안의 고유 종료조건은 구별한다.

> **작성** 2026-10-01 · **상태** 🔄승인 후 진행 중 · **분류** 작업방식 / 실험검증
> 사용자 A 승인·추후 B 연결 준비. A의 코드계약/질문 SHA·UNKNOWN·정상 슬롯 보존·총3시도와 검수주석 어댑터를 구현했다. CPU 회귀와 사용자 소형 기능 게이트를 분리하며 실제 교사 게이트는 NOT_RUN이다. B 자동 판독은 미승인이다.

## 1. 배경 — 왜 지금 이 제안을 하나

[결과101 §37](../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)에서 교정96그룹/99요청이 작동했다. 기존 최대3시도는 HTTP·파싱·옛 내용검사에 공통 사용됐지만 새 중복 회복에 별도2회를 더 붙이면 총5회가 된다. 또한 “1이라고 말해봐”의 답1/답2는 모두1이 정상이다. 기존 `parse_multi()`의 공백 접기·casefold 중복 거부는 이를 분류하지 않는다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

내용의 진실이나 모든 질문의 의미를 실시간 판독하지 않고, **출력 제약을 소유한 명시 계약**으로 재생성 허용 여부를 정하며 모든 회복이 기존3시도 한도를 공유하도록 한다.

## 3. 성과물 — 승인하면 무엇이 생기나

| 산출물 | 형태 |
|---|---|
| 출력 계약 | 생산자가 선언한 유형·근거·버전·변형 정책을 가진 job metadata |
| 공유 예산 | 최초+HTTP+parse+변형 회복을 한 곳에서 차감하는 요청 원장 |
| 제한 회복 | 정상 슬롯 불변·전체 문자열 동일 슬롯만 회복·원형/시도 계보 |
| 검증 | 유일값·숫자·JSON·대소문자 코드·공통문장·UNKNOWN의 CPU 회귀와 사용자 소형 게이트 |

## 4. 비용

| 항목 | 양 |
|---|---:|
| GPU | ⚙0.5h 이하 소형 사용자 게이트; 본학습0 |
| AI 작업 | ⚙4~6h 구현/회귀/문서 |
| 사용자가 직접 해야 하는 일 | 출력 계약 승인1회·새 smoke1회·소형 게이트1회 |
| 디스크 | ⚙20MB 이하 추가 원형; 기존20MB 분할 유지 |

## 5. 원리·근거

**우리 실측:** 최대3회 내 PEG/parse 회복 후 전체128행. 원형·raw99를 유지한다. 내용검사와 형식 복구를 혼합한 과거 판정은 소급 변경하지 않는다.

**외부 근거:** [IFEval](https://arxiv.org/html/2311.07911v1) §2.1~2.2를 읽었다. 명시적으로 검증 가능한 출력 지시도 서로 충돌할 수 있고 strict/loose 검사에는 오탐·미탐이 있다. 이를 차용해 질문 문자열에서 임의 의미를 추정하기보다 생산자가 선언한 출력 제약을 사용한다. 논문의 지시준수 평가는 정답성이나 질문 자동 분류의 증명이 아니다.

## 6. 방법

### 6.1 분류는 정답 개수보다 허용 출력 형식이다

| 유형 | 예 | 동일 답의 처리 |
|---|---|---|
| `EXACT_LITERAL` | “1만 출력”·비밀문구 그대로·지정 JSON만 | 재생성 금지. 같은 정답을 억지로 바꾸지 않음 |
| `CONSTRAINED_UNKNOWN` | 숫자만·yes/no·짧은 고유명사/번역·불명확한 제약 | 보수적으로 중복 재생성 금지. 선택지 수와 정답 수 혼동 금지 |
| `VARIANT_ALLOWED` | 같은 사실을 간단답/설명답으로, 두 표현을 명시 요청 | 같은 응답 내 **본문 전체 동일**일 때만 남은 예산으로 변형 요청 |
| `UNKNOWN` | 일반 자유 질문에 계약 metadata 없음 | 자동 재생성 금지·원형 관찰. 실시간 교사/GPT 분류 호출 없음 |

“2+2는4”라는 정답 의미는 하나지만 설명 방식은 여러 개다. 반대로 “숫자4만”은 허용 표현이 하나다. yes/no의 허용집합 크기2가 두 올바른 답을 뜻하지 않는다. 정답이나 논리를 알아서 분류하는 기능이 아니다.

### 6.2 계약 작성과 회복

생성/번역/교정 job 생산자가 원천에 실제 명시된 출력 제약을 선언한다. 선언 근거가 없으면 UNKNOWN. 원천 문구가 불신 데이터이므로 본문 속 “무조건 변형가능”이 metadata를 변경할 수 없게 한다. 정책과 답 의미를 바꾸지 않고, 계약 충돌 시 자동회복 없이 기록한다.

같은 논리 job의 최초 응답 포함 총3회다. 예: 최초 HTTP500→두번째 parse 실패→세번째 중복이면 남은0회. 중복 전용 예산을 새로 만들지 않는다. 정상 슬롯·질문을 보존하고 차이만 요청하는 것은 추가 승인 구현이며, 같은 원답 내 부분 문장 일치·X/Y·부정어 차이는 재생성 사유가 아니다.

유일 출력 중복은 전송 raw에는 모두 보존하되 학습자료에는 같은 행을 자동 증량하지 않는다. 고유 슬롯1개만 남았을 때 원천별 최소량을 별도로 기록한다. 이 부분 수락은 품질 PASS가 아니다.

| 단계 | 무엇 | 비용 | 다음으로 가는 조건 |
|---|---|---:|---|
|0|계약 enum/원천 선언/예산 설계 승인|⚙0GPUh|사용자 범위 확정|
|1|유형·공유 예산 CPU fixtures|⚙3h|유일 출력·UNKNOWN 추가호출0, 기술 실패 포함 총3회 이하|
|2|작은 사용자 교사 게이트|⚙0.5GPUh 이하|정상 슬롯·원형 보존, 오류 분류·호출수 일치|
|3|새 온라인 job 연결|⚙2h|단계2 통과. 의미 품질은 후행 검토|

### 6.3 사용자 질문에 대한 보완 — ‘생산자’는 누구인가

여기서 생산자는 **교사에게 보낼 작업을 구성하는 관리 코드와 요청 템플릿**이다. 교사가 자기 질문에 유형을 붙였다는 이유만으로 그 유형을 신뢰한다는 뜻이 아니다. 기존 제안의 “원천에 명시된 계약을 선언한다”는 설명만으로는 이 차이를 알기 어려웠다.

A안에서 코드가 실제로 아는 경우는 다음처럼 제한한다.

| 자료를 만드는 방법 | 코드가 아는 근거 | 온라인 처리 |
|---|---|---|
| 코드가 `literal=1`을 받아 “1만 출력하세요”라는 질문을 직접 작성 | 질문과 허용 출력이 같은 템플릿의 매개변수에서 생김 | 답1=1, 답2=1도 정상. 중복 때문에 재생성하지 않음 |
| 코드가 질문을 고정하고 “같은 결론을 간단답과 설명답으로”라는 작업을 명시 | 질문은 고정되고 설명 방식의 변형을 허용한 요청 계약이 있음 | 답 전체가 같은 경우에만 남은 공용 예산으로 다른 설명을 요청 |
| 기존 공개 질문에 검수된 출력 제약 metadata가 있음 | 해당 질문 SHA·주석 근거·버전이 일치 | 확인된 제약만 사용. 질문을 바꾸면 그 계약도 재확인 |
| 교사가 자유롭게 새 질문을 생성하거나 기존 질문을 의미 수준에서 다시 작성 | 코드가 생성된 질문의 실제 허용 답 형태를 미리 안다고 보장할 수 없음 | 기본 UNKNOWN. 교사의 자기 유형 신고는 힌트일 뿐 자동 재생성 권한이 아님 |
| OASST2 등의 일반 질문을 가져왔지만 유형 주석이 없음 | 계약을 뒷받침할 metadata가 없음 | 기본 UNKNOWN. 모든 질문을 문자열 규칙으로 분류하지 않음 |

**중요한 제한:** 교사에게 “자유롭게 설명 문제를 만들어라”라고 요청했다고 해서 실제 생성된 질문도 설명을 허용한다고 확신할 수는 없다. 교사가 “숫자만 답하라” 같은 제약을 덧붙일 수 있다. 따라서 자유 생성 질문에 코드가 임의로 VARIANT_ALLOWED를 붙이지 않는다. A는 질문을 코드가 고정한 경우나 확인된 원천 계약만 다룬다. 그 밖의 문제까지 유형을 넓히려면 B의 별도 판독이 필요하다.

교사가 질문과 함께 “이 질문은 유일답입니다”라는 항목을 출력하게 만드는 방법도 가능하지만, 그것은 **교사의 추정**이다. 잘못 분류하면 엉뚱한 답을 만들도록 재요청할 수 있으므로 이번 권장 A의 신뢰 원천으로 사용하지 않는다.

### 6.4 세 안을 같은 질문으로 비교하면

**사례1 — “1만 출력하세요.”**

- A: 코드 템플릿에서 이 질문을 만들었다면 생성 전에 유일 출력임을 안다. 두 답이 모두1이면 그대로 보존한다. 동일 답을 두 개의 새 지식으로 세거나, 다른 답을 강요하지 않는다.
- B: 기존 데이터셋에서 이 질문을 가져왔다면 생성 후 별도 판독자가 실제 질문의 제약을 확인하고 유일 출력 주석을 붙인다. 다음 요청부터 이 주석을 사용한다. 교사가 혼자 붙인 주석을 그대로 확정하지 않는다.
- C: 유형 판독 없이 모든 중복 재생성을 끈다. 이 질문에서도 추가 호출0으로 안전하지만, 다른 자유 설명 문제의 변형 부족도 자동 회복하지 않는다.

**사례2 — “2+2를 간단히 답한 뒤 같은 결론을 설명하세요.”**

“정답4”라는 결론은 하나지만 “4입니다”와 “2에2를 더하면4입니다”처럼 표현은 여러 개일 수 있다.

- A: 코드가 이 고정 질문과 두 서술 역할을 만들었다면 두 답 전체가 우연히 똑같을 때만 설명 슬롯을 회복한다. 답의 숫자를5로 바꾸어 차이를 만들게 하지 않는다.
- B: 교사가 만든 질문을 사후 검토해 설명 변형이 가능한 문제로 주석 처리한 뒤, 그 주석을 다음 회복에 사용한다. 더 넓은 질문을 다루지만 판독 비용과 오분류 위험이 있다.
- C: 두 답이 모두 “4입니다”여도 다시 부르지 않는다. 원형은 보존하고 고유 답 하나만 있다는 사실을 기록한다.

**사례3 — 교사가 새로 만든 질문, 또는 일반 공개 QA**

- A는 “유형을 알아서 판별”하는 안이 아니다. 근거가 없으면 UNKNOWN으로 놓고 중복 재생성을 하지 않는다.
- B는 이 UNKNOWN 자료를 별도 검증 단계에서 읽고 유형을 보강하는 안이다. 먼저 생성한 뒤 판독해도 되고, 기존 원천을 먼저 판독해 작업표에 넣어도 된다. 판독이 끝나기 전에는 온라인 자동 회복에 사용하지 않는다.
- C는 유형 보강 자체를 하지 않고 추가 호출을 없애는 안이다.

### 6.5 A를 권장하는 이유와 약점

A의 장점은 **확실히 아는 작은 범위부터 처리**하고 나머지는 재생성하지 않는 데 있다. 매 요청마다 GPT나 교사를 추가 호출해 질문 의미를 판독하지 않고도 “유일답을 억지로 바꾸는 사고”를 피한다. 최초+HTTP+파싱+중복 회복 총3회라는 기존 한도도 유지한다.

약점은 자유 생성/OASST2 질문 대부분이 UNKNOWN으로 남을 수 있다는 것이다. A가 모든 자료에 자동 유형을 부여하는 안이라고 설명한 것은 아니다. 유형 적용률이 낮으면 A에 B를 **후행 보강**할 수 있다. 다만 처음부터 모든 질문을 사전 판독하는 B를 필수로 만들면 교육 준비가 늦고 판독 비용도 커진다. 가장 적은 호출과 구현만 원한다면 C도 합리적이다.

위 보완 설명 뒤 사용자 A를 승인했다. 구현은 [출력계약/조정기](../scripts/p106b_output_contract.py), [파서](../scripts/p106b_multi_answer.py), [저장기](../scripts/p106b_pipeline.py), [CPU 회귀](../scripts/test_p106b_output_contract.py), [사용자 기능 게이트](../scripts/diag_p106b_contract_gate.py)에 연결했다. 자유 질문의 자동 의미분류는 구현하지 않았다. 종료조건은 CPU 회귀와 새 사용자 게이트의 정상 슬롯·유일답/UNKNOWN 무재생성·최대3회 관측이다.

## 7. 거절하면 못 하는 것

자동 다중답 변형 회복은 열지 않는다. 교사 생성·원형 저장·학생 pseudo 교육 자체는 계속 가능하다. 알 수 없는 질문을 재생성하지 않는 안전 정책으로도 운영할 수 있다.

## 8. 위험 — 실행하면 무엇이 잘못될 수 있나

| 위험 | 어떻게 드러나나 | 완화 |
|---|---|---|
| 잘못된 metadata | 유일 정답을 바꾸도록 요청 | UNKNOWN 기본·선언 근거 보존·유일 출력 우선 |
| 예산 중첩 | HTTP3+중복2로 총5요청 | 동일 budget 객체·CPU 혼합 실패 회귀 |
| 정규화 오탐 | X/x·코드 들여쓰기 삭제 | 파서가 제거하는 필드 경계 공백을 제외한 본문 전체 비교·casefold/내부공백 접기 없음 |

## 9. 대안
