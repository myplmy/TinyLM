# 제안 — P106B 하위 단계 성공과 전체 실험 판정의 혼동을 막는다

> **작성** 2026-10-05 · **상태** ✅승인 · **분류** 작업방식
> 사용자 회신: **A: P106B 단계·최종판정 보강**. 공용 runlog/queue 확장 B와 문서만 보강 C는 이번 구현 범위가 아니다.
> 근거: [결과101 §47](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md). 아홉 절은 [표준 양식](../README.md)을 따른다.
> **종결 범위:** A의 P106B 전용 구현·CPU/mock 및 native tee fixture 검증을 완료해 done으로 이관했다. 사용자 새 smoke/실제 모델 판정은 별도 NOT_RUN이며 전역 확대 B의 승인이 아니다.

## 1. 배경 — 왜 지금 이 제안을 하나

사용자 화면에는 Stage5d의 회귀17건 PASS·하위 종료0·파일987B까지만 보였다. 그러나 최종 원본은35행·2,446B이며, 뒤의 check-only0과 review execute8까지 누적됐다. **이번에는 로그가 유실되지 않았다.** 문제는 매 명령의 성공/누적 파일크기가 전체 실험의 종료처럼 읽히고, 호출부가 최종 판정을 따로 쓰지 않는 것이다.

Stage4cWb/5c/5d의 세 종료8은 각각 영어35,649,183토큰 부족·실제 교육질문 거부 증거 부재·상류 LoRA 자료 부재다. 반면 자산과 MTP16요청은 정상 완료했다. 성공/오류라는 두 단어만으로 이들을 요약하면 실제 계산 오류와 의도된 선결 중단을 혼동한다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

하위 회귀 통과를 전체 교육/교사 실험 성공으로 오인하지 않도록, P106B의 단계·미실행·최종 반환값을 같은 로그에서 한 번에 읽게 한다. 비교할 모델의 성능이나 원배치를 바꾸는 제안이 아니다.

## 6. 방법

| 단계 | 무엇 | 비용 | 다음으로 가는 조건 |
|---|---|---:|---|
|0|원본5/smoke1·정확 MTP JSON/선언샤드 대조|CPU|유실 여부와 실행 범위 확정|
|1|P106B check-only를 실행과 같은 선결 계약으로 수리|CPU|C 부재와 후행 자료 부재가0으로 통과하지 않음|
|2|caller BEGIN/END·FINAL 기록|CPU|회귀0·선결8이면 본실험 NOT_RUN, 최종 HOLD8|
|3|오류/중단/로깅 실패 및 원형 hash 회귀|CPU|오류를8로 위장하지 않음; 중단한 본실험을 미호출로 쓰지 않음|
|4|새 SH·원본/재현 보존·정적|CPU|원배치/교사 설정 불변, stdin 대기0|
|5|사용자 새 smoke/CPU 계약|⚙0.05h+smoke|새 실행에서는 FINAL과 phase 목록을 읽음|

출력 예:

```text
[PHASE_END] 1/3 REGRESSION; rc=0; status=PASS
[PHASE_END] 2/3 PREFLIGHT; rc=8; status=HOLD
[EXPERIMENT_FINAL] status=HOLD, returncode=8,
  REGRESSION=PASS / PREFLIGHT=HOLD / EXECUTE=NOT_RUN
```

실제 로그의 FINAL은 JSON 한 줄이다. COMPLETE는 세 단계 호출이 끝났다는 뜻이며 지능·한국어·속도 채택 PASS가 아니다. 예상된 선결은8, 무결성/도구 오류는9, 사용자 중단은130으로 구분한다. 회귀시험 자체의8은 선결 음성이 아니므로 전체9로 보고하고 원 child8도 기록한다. FINAL 기록에 실패하면 LOG_ERROR9이며 콘솔의 비상 판정에 그 사실을 남긴다.

이 상태를 기록하지 못하는 강제 프로세스 종료/정전은 성공으로 추정하지 않는다. 기존 append 로그에 새 단계명을 사용하고 과거 파일은 조용히 덮지 않는다.

## 7. 거절하면 못 하는 것

기존 runlog의 누적·flush 기능은 그대로 쓸 수 있으므로 실험이 불가능해지는 것은 아니다. 다만 하위 성공과 전체 판정을 사람이 매번 구별해야 하며, 선결이 없는 review check-only가0을 내는 운영 혼동도 남는다.

## 8. 위험 — 실행하면 무엇이 잘못될 수 있나

| 위험 | 어떻게 드러나나 | 완화 |
|---|---|---|
| 계측: 회귀 PASS를 모델 PASS로 읽음 |FINAL scope 없이0만 인용|단계/상태/미실행/품질 비주장을 함께 기록|
| 모든 오류를 HOLD8로 숨김 |잘못된 SHA/JSON도 음성으로 보임|예상된 선결만 typed HOLD, 무결성 오류9|
| Ctrl+C를 미호출로 오기 |본실험에 들어갔는데 NOT_RUN|호출 시작을 별도 latch, INTERRUPTED130 회귀|

문구 품질 검사는 이번 범위가 아니다. 원답의 언어 혼입·어법은 후행 판독에 남기며 금칙문구 목록이나 자동 정답 판정기를 만들지 않는다.

### 권장안과 근거

**A 권장·사용자 선택 회수.** 이번은 tee 유실이 아니라 caller의 의미 경계와 check-only 선결 누락이므로 공용 저장체계를 다시 만드는 B는 필요하지 않다. 승인 범위 구현·CPU 회귀를 마친 뒤 상태를 종결하되, 사용자 새 smoke와 모델 실물은 별도 미실행으로 기록한다. 전역 훅/스킬/린터 확대는 이번 승인이 아니다.
