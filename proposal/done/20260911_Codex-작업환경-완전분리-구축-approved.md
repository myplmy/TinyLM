따라서 “파일이 Codex 경로에 존재한다”와 “Codex에 맞게 이식되어 독립적으로 작동한다”를 구분해야 한다. 현재는 전자만 일부 충족하며, 후자는 아직 검증되지 않았다.

### 1.2 공식 Codex 구성 모델과의 정합성

공식 Codex 구성은 역할이 다른 층을 조합한다.

- `AGENTS.md`: 항상 적용되는 저장소 지침. 작고 안정적인 진입점이어야 한다.
- `.agents/skills/<skill>/SKILL.md`: 특정 요청에서만 불러오는 재사용 절차와 참고자료.
- `.codex/config.toml`: 신뢰된 프로젝트에서 로드되는 Codex 네이티브 프로젝트 설정.
- `.codex/hooks.json` 또는 동일 설정층의 `[hooks]`: 도구 생명주기 훅. 한 표현만 선택해야 중복 로드와 경고를 피할 수 있다.
- 프로젝트별 보조 메타데이터: 스킬이 읽는 저장소 고유 경로·영향축·제외경로. 이는 Codex 네이티브 설정과 별개다.

근거: [Codex customization overview](https://learn.chatgpt.com/docs/customization/overview), [AGENTS.md guidance](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [advanced configuration](https://learn.chatgpt.com/docs/config-file/config-advanced), [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference), [hooks](https://learn.chatgpt.com/docs/hooks).

공식 기본값상 `AGENTS.md` 계층의 결합 크기에는 32 KiB 한도가 있으므로, 현재 100,960바이트 문서는 “매 프롬프트에 필요한 최소 규범”이라는 목적과도 맞지 않는다. 이 제안은 최종 `AGENTS.md`를 12~16 KiB 범위로 줄이는 것을 목표로 하며, 16 KiB를 상한 목표로 삼는다. 정확한 내용이 우선이므로 실제 승인 단계에서 문장 단위 계측 후 확정한다.

## 2. 목적

Claude 자료는 승인된 **일회성 이식 입력**으로만 읽고, 전환 완료 뒤 Codex가 `.claude/**`, `CLAUDE.md`, 루트 `ai_dev_tool/00~08`을 전혀 참조하지 않아도 동일한 안전 규범·작업절차·프로젝트 맥락을 얻는 **자기완결형 Codex 작업환경**을 구축한다.

완료 판정은 다음을 모두 만족할 때만 내린다.

1. Codex의 활성 지침·스킬·훅·설정에 `.claude` 또는 `CLAUDE.md` 런타임 의존성이 0건이다.
2. `AGENTS.md`는 매 프롬프트 필수 규범과 라우팅만 담고, 변동 정보·긴 역사·도구 목록은 적절한 Codex 문서로 분리된다.
3. `ai_dev_tool/Codex/00~08`은 단순 복사본이 아니라 Codex 도구·권한·경로에 맞춘 독립 정본이다.
4. 17개 스킬은 `.agents/skills` 안에서 독립적으로 작동하며 `.claude` 파일을 import·링크·복사 실행하지 않는다.
5. Codex 훅은 Codex가 실제 제공하는 이벤트·입력 스키마에 맞게 이식되고, 안전한 모의 입력과 별도 승인된 새 세션 E2E로 검증된다.
6. `ai_dev_tool/09_구현검증_필요목록.md`는 수정·복제·이관하지 않고 현 위치의 공유 정본으로만 참조한다.
7. GPU·학습·모델 로딩·스모크·삭제·커밋·푸시 없이 정적 구축 검증이 가능해야 한다.

### 4.2 컴퓨팅·저장·외부 의존 비용

- GPU/학습/모델 로딩: **0회, 0 GPU 시간**.
- 다운로드·패키지 설치·외부 서비스 호출: 기본 계획에는 없음.

- 커밋·푸시·PR: 구축 범위에 포함하지 않으며 별도 사용자 지시가 필요하다.
- 동적 스모크: 프로젝트 학습 스모크와 분리한다. Codex 환경 자체의 새 세션 E2E도 별도 승인 게이트 뒤에만 수행한다.

승인된 이식 단계에서는 Claude 전용 파일을 **입력 자료로 한 번 읽는 것**만 허용한다. 그 뒤에는 심볼릭 링크·하드링크·상대경로 import·래퍼 실행·fallback 참조도 허용하지 않는다. 향후 Claude 쪽 변경을 Codex에 반영하려면 별도의 비교·승인·수동 이식 절차를 거친다.

역사 원장인 01·04·05·08에 과거 Claude 작업 사실이 기록되어 있을 수는 있다. 이는 “과거 사실” 표지를 붙인 보존 기록으로 허용하되, 현재 명령·경로·정본 링크로 해석될 수 있는 문장은 Codex 기준으로 바꾼다.

### 5.2 설정 파일의 역할 분리

`.codex/config.toml`과 `.agents/project.json`을 하나로 합치지 않는다.

- `.codex/config.toml`: Codex가 공식적으로 해석하는 네이티브 옵션만 둔다. 프로젝트 상대경로는 `.codex` 기준으로 검토한다.
- `.agents/project.json`: 저장소 스킬이 읽는 TinyLM 고유 메타데이터다. OpenAI 네이티브 설정이라고 부르지 않는다.
- `.codex/hooks.json`: 훅 정의의 단일 정본으로 삼는다. 같은 설정층의 `config.toml`에 훅을 중복 선언하지 않는다.
- 프로젝트 신뢰 여부: 프로젝트 안의 설정이 스스로 신뢰를 부여할 수 없으므로, 사용자/호스트의 신뢰 설정을 선행조건으로 점검한다.

현재 일부 스킬의 `../../project.json`은 `.agents/skills/<skill>/SKILL.md`에서 계산하면 `.agents/project.json`을 가리킨다. 따라서 `.Codex/project.json`이라는 혼합 경로를 새 정본으로 만들기보다, 링크 의미에 맞는 `.agents/project.json`을 스킬 메타데이터 정본으로 제안한다. Windows에서 `.Codex`와 `.codex`의 대소문자 구분을 기대하지 않고 공식 표기인 소문자 `.codex`만 쓴다.

### 5.3 단일 소스 원칙

- 안전 정책과 매번 필요한 작업 경계: `AGENTS.md`에 1회, 세부 절차는 Codex 00에 둔다.
- 최신 프로젝트 상태: Codex 06은 짧은 색인·기억으로 유지하고, 수치 정본은 `docs/EXPERIMENT_BASELINES.md`, 최신 핸드오프, COMPASS, 결과 문서를 직접 가리킨다.
- 작업지시 템플릿·호출법: Codex 07과 각 스킬에 둔다.
- 폐기된 규범: Codex 05에 “무엇이 왜 폐기되었고 현재 무엇이 정본인지”만 둔다.
- 누락·사고 이력: Codex 08에 둔다.
- 구현검증 후보 작업: 루트 09에만 둔다.
- 스크립트 전체 목록·고정 게이트 개수·최신 핸드오프 파일명처럼 자주 변하는 값은 `AGENTS.md`에 박아 넣지 않는다.

## 6. 수행 방법

아래 단계는 **제안 승인만으로 자동 실행되지 않는다**. 승인 뒤 사용자가 구축 착수를 명시하면, 각 단계의 변경 허용목록을 다시 고정하고 진행한다.

### 6.2 `AGENTS.md` 축약 전략

최종 `AGENTS.md`에는 다음만 남긴다.

1. 저장소 목적 한 단락.
2. 명령 우선순위와 충돌 해결 순서.
3. 세션 시작 시 읽을 Codex 전용 파일과 최신 공유 핸드오프/COMPASS의 동적 선택 규칙.
4. AI가 직접 수행하면 안 되는 GPU·학습·삭제·보호 데이터·Git 외부 상태 변경 경계.
5. 정적 검증과 실제 실행을 구분하는 증거 수준.
6. 작업 유형별 스킬 라우팅과 장기기억/단기기억 경로.
7. 루트 09는 현 위치 공유 정본이며 복제 금지라는 예외.

다음은 `AGENTS.md`에서 제거하되 삭제하지 않고 적절한 정본으로 옮긴다.

- 날짜별 장문 연구 연혁과 수백 개 수치.
- 고정된 최신 핸드오프 파일명.
- 전체 스크립트 목록과 변동 가능한 게이트 개수.
- 특정 실험의 세부 결과·기각 근거.
- 배치 작성의 세부 규칙과 예시.
- 도구별 긴 호출법.

항목별 목적지는 별도 임시 이식표에 기록했다. 실제 이식 때는 문단 단위 복사보다 “규범·사실·역사·폐기·도구 절차”를 분해해 중복 없이 재작성한다.

### 6.4 스킬 이식 계획

모든 스킬은 `.agents/skills` 아래의 Codex 소유 파일로 유지한다. `.claude/skills`를 직접 호출하거나 상대경로로 재사용하지 않는다.

| 위험도 | 스킬 | 주된 이식 작업 |

특수 처리 원칙은 다음과 같다.

- `session-handoff`: 범용 7절 템플릿을 그대로 쓰지 않고 TinyLM의 Codex 02 및 기존 `scripts/new_handoff.py` 정책에 연결되는 어댑터로 재설계한다. 실제 핸드오프 생성·갱신은 별도 요청일 때만 한다.
- `wip-ledger`: 일반 세션 WIP 원장과 `ai_dev_tool/09_구현검증_필요목록.md`를 구분한다. 이 스킬 때문에 Codex판 09를 만들거나 루트 09를 복사해서는 안 된다. 사용자의 명시 범위가 스킬 기본 동작보다 우선한다.
- `pr-workflow`: `git add .`/`-A` 금지, 명시 경로 staging, 제외경로, base/head 검증을 유지하되 Codex 도구와 Windows 실행환경으로 검증한다. PR 생성·커밋·푸시는 구축 검증에서 수행하지 않는다.
- `impact-analysis`, `plan-doc`: `.agents/project.json`을 읽도록 경로를 한 종류로 통일한다.
- 셸 스크립트가 꼭 필요한 경우에도 “파일이 존재한다”를 호환성 증거로 보지 않는다. Windows에서 호출 가능한 대안과 실패 경로를 별도로 검증한다.

### 6.5 훅 이식 계획

현재 훅은 Claude판과 동일하므로 다음 순서로 새로 검증한다.

1. 차단하려는 사고 계약을 먼저 명문화한다: 긴 백슬래시 포함 편집, 제어문자 유입, 우회 경로, 허용목록의 범위.
2. Codex가 훅에 넘기는 실제 이벤트명·도구명·입력 구조를 공식 문서와 로컬 기능으로 확인한다.
3. `.codex/hooks/**`에 독립 구현하고 오류 메시지의 `Write`/`Edit`, `.claude` 경로, Claude 전용 도구명을 제거한다.
4. 저장소 절대경로를 하드코딩하지 않고 프로젝트 기준 상대경로 또는 검증된 런타임 루트를 쓴다.
5. `.codex/hooks.json`만 훅 설정 정본으로 사용하고 `config.toml` 인라인 훅은 비운다.
6. 정상 입력, 차단 입력, 경계 입력, 잘못된 입력, 훅 자체 오류를 모의 실행한다.
7. 프로젝트가 신뢰되지 않아 로컬 설정이 무시되는 경우를 실패로 보고 사용자에게 신뢰 설정 확인을 요청한다.
8. 새 세션 E2E 전에는 “훅 활성화 완료”라고 보고하지 않는다.

### 6.6 검증 기준

정적 검증은 프로젝트 학습/스모크와 분리하며 다음만 수행하도록 제안한다.

- 허용 경로 외 변경 0건.
- `ai_dev_tool/09_구현검증_필요목록.md` 내용·해시·Git 상태 불변.
- 활성 파일의 `.claude`, `CLAUDE.md`, Claude 전용 도구명, 잘못된 `.Codex/project.json` 참조 0건.
- `.agents/skills`에서 `.claude`로 향하는 심볼릭 링크·하드링크·import·subprocess 호출 0건.
- 모든 Markdown 상대링크 해석 가능.
- `AGENTS.md` 목표 크기와 필수 안전 항목 체크리스트 통과.
- TOML/JSON/Python/PowerShell 또는 셸 파일의 구문 검사 통과.
- 스킬마다 이름·설명·트리거·입력·권한·산출물·금지행동이 Codex 도구와 일치.
- 훅 모의 테스트 통과. 단, 새 세션에서 실제 발화하지 않았다면 `STATIC_ONLY`로 표시.
- GPU·학습·모델 로딩·실험 배치·`run_smoke_check.bat`·삭제·커밋·푸시 실행 0건.

정적 통과는 실제 새 세션 품질의 증명이 아니다. P8의 사용자 승인형 E2E 전까지 최종 상태는 `IMPLEMENTED_STATIC_ONLY` 또는 `E2E_NOT_RUN`으로 남긴다.

## 7. 제안이 기각될 경우 막히는 것

제안을 기각해도 현재 코드·데이터·Claude 환경에는 새 손상이 생기지 않는다. 다만 다음은 해결되지 않는다.

- Codex가 100 KiB 규모의 `AGENTS.md`를 매번 온전히 읽는다는 보장이 없음.
- Codex 00~08이 파일명만 바뀐 Claude 원본인 상태가 유지됨.
- `.agents/skills`의 도구명·경로·셸·권한 불일치가 남음.
- `.codex` 훅이 실제 Codex에서 차단 기능을 수행하는지 증명되지 않음.
- Codex 네이티브 설정과 스킬 프로젝트 메타데이터의 정본이 없음.
- Claude 파일을 보지 않는 완전분리 운영을 선언할 근거가 없음.

즉, 기각은 “현재 상태 유지”이며 기능 퇴행은 아니지만, Codex 환경의 안전성과 동등성을 확인했다는 판정도 할 수 없다.

## 9. 대안 비교와 권고

| 안 | 설명 | 분리 수준 | 초기 비용 | 장기 드리프트 | 주요 단점 |
|---|---|---:|---:|---:|---|
| **A. Codex 완전분리 이식** | Codex 전용 AGENTS·00~08·스킬·훅·설정을 독립 유지하고 Claude는 일회성 입력으로만 사용 | **최고** | 높음 | 중간 | 변경을 양쪽에 각각 수동 이식해야 함 |
| B. 중립 공통 코어 + Claude/Codex 어댑터 | 공통 규범을 한곳에 두고 양 환경이 참조 | 중간 | 중간 | 낮음 | 사용자가 요구한 “Codex는 Codex 환경만 본다”는 경계와 충돌 |
| C. 문서만 분리하고 스킬·훅은 보류 | AGENTS와 00~08만 먼저 Codex화 | 부분 | 낮음 | 높음 | 작업절차·안전 훅의 동등성 미확보, 완전 구축이 아님 |
| D. 현 상태 유지 | 현재의 복사본과 대형 AGENTS를 그대로 사용 | 낮음 | 없음 | 매우 높음 | 파일 존재와 실제 호환성을 혼동하며 안전성 검증 불가 |

**권고안은 A안이다.** 사용자가 이미 완전분리를 목표로 지정했고, B안은 관리 효율은 좋지만 런타임 교차참조를 허용하게 되어 요구사항을 훼손한다. A안의 비용은 더 크지만 정본·권한·실패 책임이 명확하다.

승인 시에도 다음 문구처럼 범위를 분리해 착수하는 것이 안전하다.

> “A안의 P0~P1만 착수하라” 또는 “A안 전체의 정적 구축(P0~P7)을 착수하라. P8 새 세션 E2E는 수행하지 말라.”

P0~P7은 후속 승인 범위까지 이행했다. P8은 [P7 검증 보고의 사용자 테스트 방법](../../ai_dev_tool/Codex/P7_정적종합검증_보고.md#6-p8-사용자-테스트-방법)에 따라 새 세션에서 별도 수행한다.
