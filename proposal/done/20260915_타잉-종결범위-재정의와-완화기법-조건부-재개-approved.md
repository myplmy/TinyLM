# 제안 — 기존 직접 타잉은 닫고 구조조건부 직접공유·완화 타잉을 단계적으로 연다

> **작성** 2026-09-15 · **승인** 2026-09-15 · **상태** ✅권장 C안 승인 및 직접공유 구조 확장 계획 승인 · **분류** 아키텍처 / 실험계획
>
> 양식: [`proposal/README.md`](../README.md) §3. 후속 정본은 [`P093`](../../test_plan/P093_구조조건부-직접공유와-완화타잉.md)이며 구현·모델 로딩·배치·GPU는 `NOT_RUN`이다.

---

## 1. 배경 — 왜 지금 이 제안을 하나

현재 `COMPASS`는 MLP 타잉과 어텐션 타잉을 각각 “현 조건 기각”으로 정확히 적고 있지만,
짧게 읽으면 **타잉 방법론 전체가 끝난 것**처럼 보일 수 있다.

P045B Stage1은 같은 Muon·d12·CLA2·무재귀 조건에서 다음을 직접 측정했다.

| 팔 | paired full-val | dense 대비 |
|---|---:|---:|
| dense | **3.5745** | — |
| attention `ag2` | 3.5818 | **+0.0073** |
| MLP `g2` | 3.6084 | **+0.0340** |
| MLP `g4` | 3.6324 | **+0.0579** |

따라서 **현재 구현의 직접 공유를 같은 작은-g 격자로 반복할 이유는 없다**. 그러나 이 결과가
실제로 배제한 것은 “여러 층이 정확히 같은 가중치 객체를 사용한다”는 형태다. 층별 저랭크 잔차로
공유 제약을 풀거나, 어텐션 head를 정렬한 뒤 공유하는 방법은 우리 표준조건에서 0런이다.

또한 CLA는 이름에 “cross-layer”가 들어가지만 MLP/attention 가중치 타잉과 화폐가 다르다.
CLA는 인접 층의 K/V를 재사용해 **KV 캐시 엔트리**를 줄이는 축이고, 현재 세 축 중 유일하게
깊이보다 싼 승격 후보이다. 이를 직접 타잉 기각에 묶어 닫으면 안 된다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

**직접 가중치 공유의 종결 범위는 보존**하면서, 층별 차이를 작은 저랭크 보정으로 되사는
“완화 타잉”이 저장 이득을 유지한 채 P045B의 품질 대가를 유의미하게 줄일 수 있는지만 값싼
게이트부터 검증한다.

## 3. 성과물 — 승인하면 무엇이 생기나

| 산출물 | 형태 |
|---|---|
| 타잉 분류 계약 | 직접 MLP 공유, 직접 attention 공유, 완화 MLP 공유, 정렬/완화 attention 공유, CLA/KV를 별도 축으로 정의 |
| 무학습 타당성 표 | rank별 유니크 파라미터·packed/상주 추정·추가 FLOPs·fold 가능성·부모 초기화 오차 |
| 최소 구현 계약 | default-off, dense 기준 bit-identical, 층별 adapter 소유권, checkpoint/optimizer state 규약 |
| 사전등록 판정 | 직접 공유 대비 회복량, dense 대비 남은 대가, 순메모리 이득을 동시에 보는 gate |
| 후속 계획서 | ✅`P093` — 기존 exact 직접공유, 구조조건부 direct-core 공유, 완화 공유를 분리해 Stage0부터 게이트 |

이 제안서가 승인돼도 즉시 타잉을 승자로 되돌리지 않는다. “완화 형태를 시험할 자격”만 연다.

## 4. 비용

| 항목 | 양 |
|---|---:|
| GPU | T0~T1 **0 GPU-h**; 승인 뒤 T2 tiny 계약 ⚙0.1h; T3 최소 학습 ⚙2.5~5 GPU-h |
| AI 작업 | 정적 회계·설계 ⚙4~7h, 최소 구현·fixture ⚙6~12h |
| ★**사용자가 직접 해야 하는 일** | 별도 구현 승인, 스모크, T2/T3 GPU 실행, 결과 뒤 계속/종결 결정 |
| 디스크 | T0~T2 미미; T3 체크포인트 ⚙2~5 GiB |

사용자는 2026-09-15에 계획 범위를 구조조건부 직접공유까지 넓히는 것을 승인했다. 위 비용은
후속 후보 단계의 추정치이며, 현재는 P093 계획만 작성하고 배치·모델 코드·GPU 실행은 만들거나 하지 않는다.

## 5. 원리·근거

**우리 실측**

| 근거 | 값 | 출처 |
|---|---|---|
| 직접 작은-g MLP/attention | g2 +0.0340, g4 +0.0579, ag2 +0.0073 | [결과 079](../../test_result/079_20260911_P045B-작은-g와-어텐션타잉은-모두-기준선에-졌다.md) |
| MLP g4 저장 | d16 유니크 삼진 −43.9%, packed 21.56→12.91 MiB | [타잉 재평가](../../docs/20260908_타잉-세-축의-역할과-가격-재평가.md) |
| 기존 FiLM | +0.0003, 비용은 존재 | 결과 063; 범용 per-layer 변조를 다시 붙이는 길은 기각 |
| dense vector LRM | full-val +0.0001, wall +7.2%, VRAM +0.41 GiB | 결과 072; dense 몸통에서의 무효이지 tied low-rank residual 검증은 아님 |
| CLA2 | 가중치 직접 타잉과 달리 KV 캐시 축이며 현재 교환비 후보 1순위 | `COMPASS` 및 결과 059 |

**외부 근거 — 이번 조사에서 원문 초록·공개 본문을 확인한 범위**

- Bae et al., [Relaxed Recursive Transformers](https://arxiv.org/abs/2410.20672)는 반복되는 공유
  블록에 **depth-wise LoRA**를 붙여 정확한 공유 제약을 완화하고 compactness를 유지하는 방법을
  제시한다. 이는 TinyLM의 직접 g2/g4와 독립변수가 다르다.
- Mu et al., [LiSA](https://arxiv.org/abs/2408.01890)는 직접 attention weight 공유가 잘 되지 않는
  원인을 head 정렬과 층별 차이로 보고, 작은 정렬 FFN과 저랭크 차이 행렬을 사용한다. 다만
  pretrained 대형 모델 압축 결과이므로 TinyLM scratch pretraining에 그대로 전이된다는 근거는 아니다.
- Brandon et al., [Cross-Layer Attention](https://arxiv.org/abs/2405.12981)은 인접 층의 K/V를
  공유해 KV cache를 줄인다. 이 근거는 CLA를 직접 attention weight sharing과 분리해야 함을 뒷받침한다.
- Pires et al., [One Wide Feedforward is All You Need](https://arxiv.org/abs/2309.01826)은 단일
  공유 FFN을 넓히는 구조가 encoder-decoder MT에서 정확도·latency를 개선할 수 있음을 보였다.
  이는 **같은 폭의 g2/g4 반복**과 다른 가설이지만 TinyLM causal scratch 조건의 직접 증거는 아니다.
- Takase and Kiyono, [Lessons on Parameter Sharing across Layers in Transformers](https://arxiv.org/abs/2104.06022)는
  sequence/cycle/cycle-rev 배치를 분리했고, Lin et al.,
  [Understanding Parameter Sharing in Transformers](https://arxiv.org/abs/2306.09380)는 반복 사용된
  공유 weight의 gradient 범위와 수렴 규약 차이를 지적했다. 따라서 배치와 update-scale은 E0의
  고정 조건과 독립 후보지만 기존 P061/P074와 겹치면 새 런을 만들지 않는다.
- Xue et al., [Go Wider Instead of Deeper](https://arxiv.org/abs/2107.11817)는 shared-depth에
  MoE FFN과 층별 norm을 결합했다. TinyLM은 이미 층별 norm·gate와 독립 edge를 갖기 때문에 그
  요소만 다시 붙이는 것은 새 후보가 아니며, expert/width의 순비용만 별도 회계할 수 있다.

외부 논문은 “우리에서도 이긴다”는 증거가 아니라, **P045B가 시험하지 않은 독립 방법이 실재한다**는
재개 근거다.

### 5.1 승인 뒤 직접공유 확장 판단

기존 `g2/g4`의 같은 폭·연속 배치 exact sharing은 닫힌다. 반면 **공유 MLP 코어는 정확히 같은
weight로 유지하면서 코어를 넓히는 방식**, 공유 사용횟수에 맞춘 update 규약, cycle 배치는
P045B가 바꾸지 않은 독립변수라 P093에서 조건부로 연다. 층별 low-rank matrix를 붙이는 순간에는
직접공유라고 부르지 않고 완화 공유로 재분류한다. 자세한 후보·중복·중단선은 P093 §4~§7이 소유한다.

## 6. 방법

| 단계 | 무엇 | 비용 | ★**다음으로 가는 조건** |
|---|---|---:|---|
| **T0 범위 고정** | 정확 공유와 완화 공유, CLA를 용어·회계에서 분리 | GPU 0 | COMPASS·계획·결과가 같은 종결 범위를 가리킴 |
| **T1 정적 회계** | MLP rank 4/8/16 및 attention 후보의 유니크 weight, adapter, packed/상주, FLOPs, fold 가능성을 계산 | GPU 0, ⚙2~4h | adapter 포함 순저장 절감 ≥15%, 추가 FLOPs ≤10%; 둘 중 하나라도 미달이면 해당 후보 종결 |
| **T1b 부모 타당성** | dense→shared base 평균과 층별 residual 저랭크 근사의 weight/logit 오차를 학습 없이 측정 | 모델 로딩은 사용자 실행, ⚙0.2h | 같은 rank에서 오차가 단조 감소하고 직접 공유보다 명확히 작음 |
| **T2 계약 구현** | default-off, unique module 수, optimizer state, save/load, adapter fold 또는 배포 처리 fixture | ⚙6~12h, tiny GPU ≤0.1h | 기본 경로 동일·계약 오류 0·사용자 스모크 PASS |
| **T3 한 쌍** | 같은 부모·풀·토큰·시드에서 직접 공유와 완화 공유 비교; dense는 기존 짝을 조건 서명으로 재사용 가능할 때만 | ⚙2.5~5 GPU-h | 직접 공유 품질 대가의 ≥50% 회복, dense 대비 남은 대가가 계열 자/사전선 이내, 순메모리 절감 유지 |
| **T4 전이** | T3 통과 시에만 다른 seed 또는 길이 한 축 | 별도 승인 | 부호 유지 시에만 프리셋 검토 |

판정은 loss 하나가 아니라 다음 세 값을 함께 쓴다.

```text
회복률 = (L_direct - L_relaxed) / (L_direct - L_dense)
남은 대가 = L_relaxed - L_dense
순절감 = dense 배포 bytes - (shared base + adapter + metadata bytes)
```

직접 공유와 완화 공유가 다른 부모·풀·시드를 쓰면 T3가 아니다. 기존 checkpoint를 재사용할 때도
조건 서명 불일치가 하나라도 있으면 dense 팔을 새로 짜야 하며, 그때는 별도 승인한다.

## 7. 거절하면 못 하는 것

직접 g2/g4/ag2 기각, CLA 후보 유지, 현재 dense·재귀·Muon/RMS 연구에는 영향이 없다. 다만
**정확 공유보다 표현력을 조금 되사는 중간점**이 TinyLM에서 메모리-품질 Pareto를 만들 수 있는지는
계속 미확인으로 남는다. 그러므로 거절 비용은 즉시 성능 손실이 아니라 하나의 압축 가족을 조사하지
않는 기회비용이다.

## 8. 위험 — 실행하면 무엇이 잘못될 수 있나

| 위험 | 어떻게 드러나나 | 완화 |
|---|---|---|
| adapter가 절감을 되먹음 | rank·층 수가 늘수록 packed/상주가 dense에 접근 | T1에서 metadata·scale·runtime tensor까지 포함해 회계 |
| LoRA라는 이름으로 P008을 중복 | 학습 뒤 제거하는 annealed LoRA와 영구 층별 residual을 혼동 | 수명·소유권·배포 fold 가능성을 별도 필드로 고정 |
| pretrained 압축 연구를 scratch 학습에 오용 | 초기화는 좋아도 장기 loss가 개선되지 않음 | T3를 작은 한 쌍으로 제한, 논문 효과 크기 복사 금지 |
| attention 후보가 KV/CLA와 교락 | ag·cla가 동시에 바뀜 | CLA 고정, 직접 attention와 정렬/완화 attention을 별도 태그로 기록 |
| 속도 회귀 | weight는 줄지만 adapter GEMM/dispatch가 증가 | FLOPs뿐 아니라 user-run wall/VRAM을 별도 판정 |
| 기존 종결을 지워 반복실험 | COMPASS가 다시 단순 “열림”으로 바뀜 | “직접 공유 기각” 문구와 P045B 수치를 영구 보존 |
| 정적 근사 PASS를 품질 PASS로 승격 | weight/logit 오차만 보고 채택 | T1/T2는 `STATIC_ONLY`, T3 전 품질 `NOT_RUN` 명시 |

## 9. 대안

| 안 | 무엇 | 장점 | 단점 |
|---|---|---|---|
| **A** | 모든 타잉을 현재처럼 넓게 닫음 | 비용 0, 중복실험 방지 | P045B가 시험하지 않은 완화 가족까지 과잉 기각 |
| **B** | g/ag 격자를 다시 전면 실행 | 구현 0 | 같은 가설 반복, 이미 큰 열세를 뒤집을 근거 없음 |
| **C** | **직접 공유는 닫고 완화 공유만 T1 정적 게이트부터 조건부 개방** | 종결 근거 보존, GPU 낭비 최소, 외부 연구와 질문 정합 | 새 구현·회계 필요, 성공 보장 없음 |
| **D** | 타잉 완화는 보류하고 CLA LR 대조만 우선 | 현재 교환비가 가장 좋은 축에 집중 | 가중치 압축의 중간점은 계속 미확인 |
| **C+ 승인 확장** | C를 보존하면서 구조조건부 direct-core 후보도 GPU 0 회계부터 분리 개방 | 사용자의 “직접공유도 구조를 바꾸면 뒤집히나”를 기존 E0 재실행 없이 답함 | 더 엄격한 가족명·비용·중복 게이트 필요 |

### ★권장안과 근거

**C안을 권장하되 실행 우선순위는 D보다 뒤에 둔다.** 의미상으로는 지금 범위를 바로잡아야 하지만,
GPU 우선순위는 이미 실측 교환비가 좋은 CLA와 RMS4 전이가 더 높다. 따라서 승인 후에도 T0·T1의
GPU 0 게이트만 먼저 하고, 그 결과가 정량 문턱을 넘을 때에만 T2/T3 구현·계획을 별도 승인받는다.
이렇게 하면 P045B의 강한 기각을 존중하면서도 “직접 타잉 실패 = 모든 완화법 실패”라는 과잉 종결을
피할 수 있다.

### 승인 기록

- 2026-09-15: 사용자가 C안을 승인하고 공유 MLP 구조 변경을 포함한 직접공유 가능성 조사와
  확장 실험계획 작성을 허가했다.
- 판정: P093 계획 작성까지 승인. exact E0 종결은 유지하고 구조조건부 D와 완화 R만 단계적으로
  연다. 모델 코드·배치·GPU·품질 실험은 `NOT_RUN`이며 Stage0 회계 뒤 별도 범위 고정이 필요하다.
