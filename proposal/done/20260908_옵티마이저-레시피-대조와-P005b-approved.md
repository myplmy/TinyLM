## 1. ★★★가장 중요한 것 — **`--muon-lr-mult 15` 는 빠진 스케일을 손으로 메운 것일 수 있다**

두 논문이 **독립적으로 같은 식**을 쓴다:

| 출처 | Muon 업데이트 스케일 |
|---|---|
| arXiv:2505.02222 §2.1 식(1) | `W ← W − η·( (0.2·√n)·O_t + λ·W )`  (**n = max 차원**) |
| Kimi K2 Algorithm 1 | `O_t = NewtonSchulz(M_t) · √max(n,m) · 0.2`  — 주석 *"Match Adam RMS"* |
| ★**우리 `muon.py:87`** | `scale = max(1.0, out/in) ** 0.5` |

★★**논문 각주 2 가 그 0.2 를 설명한다**:
> *"0.2 is the empirically observed RMS of a typical AdamW update. 1/√n is the RMS of a
> perfectly normalized O_t … This ensures that **the same learning rate schedule and weight decay
> work well for both Muon and AdamW**, which is useful especially since AdamW is used to update
> embedding and normalization parameters."*

★★★**즉 `0.2·√n` 은 "Muon 업데이트의 RMS 를 AdamW 업데이트의 RMS 에 맞추는" 상수**이고,
**그것이 있으면 같은 lr 을 두 옵티마이저에 그대로 쓸 수 있다.**
🚫**우리는 그것이 없어서 `--muon-lr-mult` 라는 손잡이를 만들었고, 최적값이 15 로 나왔다.**

### 1.1 ★우리 형상에서 두 규칙이 얼마나 다른가 (dim 768 · ffn 2048 · kv_dim 192)

| 행렬 | shape | 우리 `max(1,out/in)^0.5` | 논문 `0.2·√max(n,m)` | 비 |
|---|---|---:|---:|---:|
| q·o proj | 768×768 | **1.000** | **5.543** | 5.54 |
| k·v proj | 192×768 | **1.000** | **5.543** | 5.54 |
| gate·up | 2048×768 | **1.633** | **9.051** | 5.54 |
| ★**down** | 768×2048 | **1.000** | **9.051** | ★**9.05** |

★★**두 가지가 다르다**:

1. **크기** — 논문 규칙이 **5.5~9.1배 크다**. 우리 최적 ×15 와 **자릿수가 같다.**
2. ★★**모양** — 우리는 **비율**(out/in), 논문은 **절대 크기**(max(n,m)).
   → 🚫**행렬 종류 사이의 상대 가중이 다르고, `down_proj` 가 나머지 대비 1.63배 가볍다.**
   ★★**스칼라 배수 하나로는 이 모양 차이를 못 메운다.**

⚠️**정직하게**: 논문의 η 와 우리 lr 1e-3 이 같다는 보장이 없다. 🚫**"우리가 절대적으로 작다" 고
단정하지 않는다.** ✅**확실한 것은 모양이 다르다는 것**이고, 그것은 배수로 못 고친다.

## 2. ★★★두 번째 발견 — **Muon 팔의 행렬에는 weight decay 가 0 이다**

`trainer.py:462`:

    opt_muon = Muon(_mats, lr=lr * muon_lr_mult)      # ← weight_decay 기본 0.0

그런데 AdamW 경로에서는 같은 행렬들이 `param_groups()` 를 통해 **wd 0.1** 을 받는다.

★★**즉 우리 "Muon vs AdamW" 비교는 사실 "Muon + 행렬 wd 0" vs "AdamW + 행렬 wd 0.1"** 이다.
🚫**우리 파라미터 81.2M 중 삼진 72.5M(89%)이 그 차이를 받는다.**

⚠️★**얼마나 나쁜가는 모른다** — 결과 072 §8 이 `ternary.py` 가 **1차 동차**임을 증명했으므로
가중치의 **균일 축소는 양자화 출력을 안 바꾼다.** 그러나 **학습 동역학은 바꾼다**
(‖W‖ 가 줄면 STE 그래디언트 대비 상대 스텝이 커진다).

★**논문 식(1)에는 `+ λ·W_t` 가 명시**돼 있고 Kimi 도 같다. **둘 다 Muon 에 weight decay 를 준다.**
→ ★**우리 `Muon(..., weight_decay=0.0)` 은 두 참조 구현 모두와 다르다.**

## 3. ★AdamW 레시피 대조 — **우리 수치 전수**

| 항목 | ★**우리 실측**(코드) | 참조 | 판정 |
|---|---|---|---|
| `betas` | **(0.9, 0.95)** | ✅논문 §2.2 는 임베딩·norm 에 **β1=β2=0.95** | ✅**표준**. ⚠️β1 도 0.95 로 두는 변형이 있다 |
| `eps` | **1e-8** | ⚠️미조회(LLaMA 계열은 1e-5 로 알려져 있다) | ⏸**확인 필요** |
| `weight_decay` | **0.1**(dense·타잉) · 0(norm/bias) · **0.01**(lrm) | ✅논문·관행과 같다 | ✅ |
| grad clip | **1.0**(global norm) | ✅관행 | ✅ |
| ★**peak lr** | **1e-3** | ⚠️미조회 | ⏸**100M 급에서 1e-3 은 보수적일 수 있다** |
| min lr | **0.1 × peak** | ✅논문 §2.2 *"cosine decay to 0.1 of the max"* | ✅**정확히 같다** |
| warmup | **100 step = 4.4%** | ✅논문 *"linear warmup"*(길이 미명시) | ✅ |
| 스케줄 | **wsd**(80% 평탄 + 20% cosine) | ⚠️논문은 cosine | ⏸다른 축(P026 이 이미 결정) |
| ★**유효 배치** | ★**131,072 토큰** | ⚠️논문 실험 범위 **128K ~ 16M** | ★**우리는 최하단** |
| ★**타잉 그룹 lr** | ★**lr / √g** | 🚫참조 없음 | ★**우리 고유** |

### 3.1 ★★배치 크기 — **논문의 핵심 결론이 우리에게 불리하다**

논문 초록·§2.4: *"Muon is more effective than AdamW in **retaining data efficiency at large
batch sizes**, far beyond the critical batch size."* 그리고 FLOP 오버헤드는 **Θ(n/B)** 다.

★★**즉 Muon 의 이점은 대배치에 집중**되고 **우리 131K 는 그들 실험 범위의 바닥**이다.
🚫**그런데 우리는 그 바닥에서도 −0.044 를 얻었다** — ★**이것은 좋은 소식**이다
(배치를 키우면 더 벌 개연성). ⚠️**단 대배치는 유효배치를 바꾸므로 기존 비교가 전부 끊긴다.**

### 3.2 ⚠️★토큰 예산 — **우리가 33배 적다**

| | 논문 §2.2 | ★**우리** |
|---|---|---|
| 100M 모델 | ★**10B 토큰**(Chinchilla 최적의 **5배**) | ★**300M**(⚙0.15배) |

★**논문이 "수렴했다" 고 부르는 지점의 1/33** 이다. 🚫**우리 옵티마이저 판정이 "수렴 전" 판정**임을
결과문서에 적어야 한다. ⚠️**그리고 옵티마이저 우열은 학습 길이에 의존할 수 있다.**

### 3.3 ✅우리가 이미 맞춘 것 셋

| 무엇 | 근거 |
|---|---|
| **Muon 을 임베딩·norm 에 안 쓴다** | 논문 §2.2 *"applying (1) to all layers except embedding and normalization"* = 우리 `split_params` |
| **Newton-Schulz 5차 · Jordan 계수** | 논문 §2.1 *"Jordan et al. provide well-tuned hyperparameters … flatten all singular values to (0.7, 1.3)"* |
| ★**QK-norm** | 논문 §2.2 는 **Gemma 3**(soft-capping → QK-norm)를 쓴다. 우리 v5 도 QK-norm |

### 4.1 ★사전등록 예측

| # | 예측 | 반증되면 |
|---|---|---|

1. ★★**b-3 이 P4 를 반증하면 결과 076·B.22 를 고쳐야 한다.** 🚫**그 가능성을 알고도 안 재는 것이
   더 나쁘다** — 지금 −0.04406 을 "Muon 의 효과" 로 문서 다섯 곳에 적어 두었다.
2. ⚠️**b-4 는 유효배치를 바꾸므로 기존 런과 비교가 끊긴다**(함정 2). **b-4 안에서만 비교**한다.
3. ⚠️**`--muon-scale` 은 기본 `jordan`(= 현행 = 비트 동일)이어야 한다.** 기본을 바꾸면
   진행 중인 큐의 Muon 팔이 전부 다른 모델이 된다.

## 5. 🚫제안하지 않는 것 — **이유를 적는다**

| 무엇 | 왜 안 하나 |
|---|---|
| ★**QK-Clip**(Kimi) | 🚫**불필요.** 우리 QK-norm 이 로짓을 **√head_dim = 8** 로 구조적 상한한다. Kimi 의 τ=100 보다 **12.5배 세다** |
| **muP** | ⏸b-2 뒤로. muP 는 **스케일 규약**이라 스케일이 안 맞은 상태에서 얹으면 두 축이 교락된다 |
| **Lion** | ⏸**GSQ 를 채택할 때만** — Gumbel 포화가 AdamW 를 멈추게 하는 문제의 대응이고, 우리는 아직 Gumbel 이 없다 |
| **β1 = 0.95** | ⏸논문은 **임베딩·norm 에만** 그렇게 쓴다. 우리 (0.9, 0.95) 는 표준이고 **바꿀 근거가 약하다** |
| **eps 1e-5** | ⏸**원문 미조회.** 🚫조회 전에 안 바꾼다 |
| **peak lr 상향** | ⏸**P005 본편이 lr 축을 이미 소유**한다. 두 곳에서 정하지 않는다(함정 18) |

⚠️**단 Kimi 도 "각 코퍼스를 최대 두 번까지만 리라이팅" 이라고 적었다.**
