## 1. 배경 — 무엇을 검토했는가

원문은 깨끗한 짧은 답변 자료를 만들고, 같은 학습 상태에서 후보 자료의 기여를 켜고 끈 두 업데이트를 실행해 실제 답변 점수의 차이로 자료를 선택하자고 제안한다. 이후 일부 가중치 블록의 변화를 되돌리거나 이식해 기능적 기여를 확인한다. 원문은 이미 역사적 기여와 현재 추가학습 효과, 단순 검색과 인과 개입, 실효 삼진 가중치와 latent 가중치를 구별한다. 이를 무시하고 단순한 gradient 유사도 제안이라고 요약하면 부정확하다.

다만 원문 문단026의 기준 커밋은 `40ba4a2`이고 문단044~047은 교정 학생 교육을 NOT_RUN으로 적는다. 현재 [결과101](../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md) §39~44와 이번 Stage4 원본에는 두 계보 각4업데이트 및 새 공개자료의2업데이트가 실제 실행됐다. 제안의 과학적 아이디어와 낡은 프로젝트 상태를 분리해야 한다.

이번 Stage4a는 한국어37,500,033·영어1,847,356 train 토큰을 준비했지만 영어35,652,644가 부족하다. 한국어의 Wiki-split19,298,463와 wiki-lingua12,066,596 합계31,365,059토큰은 약83.64%다. 파일 앞부분부터 quota를 채우는 구현 때문에 뒤쪽 출처가 선택되지 않았다. 사용자 승인으로 순서 독립 해시 선별·출처별25% 상한을 수리 중이며, 이 작업은 새 attribution 알고리즘의 승인과 무관하다.

Stage4c0는 같은 B 부모에서2업데이트·87,280 대화토큰·42,732 지도토큰을 처리했다. 작은 SFT validation CE는3.418480→3.366737이고 native CE는3.590418→3.594584다. 고정8질문의 첫답/최대3시도는 전후0/8이다. 자료 준비·업데이트는 작동했지만 지시·종료·실제 답변 개선의 증거가 부족하다.

## 2. 목적 — 먼저 답해야 할 질문

현재 부모가 명확한 질문·답·종료 신호를 학습하는지 확인한 뒤, 같은 자료와 optimizer 조건에서 실제 업데이트 기반 선택이 값싼 균형 무작위보다 추가 이득을 주는지 검증한다. 원문 전체를 곧바로 기본 학습법으로 채택하지 않는다.

### 4.1 사용자 비용 문의 — B의12~24시간은 무엇인가

이는 이번 코드 상태에서 **구현·검증 작업량**을 추정한 값이며 GPU 실행시간이나 확정 납기가 아니다. 기존 학습 함수는 재사용하지만 상태 복원·기여 유무 대조를 완성한 것으로 가정하지 않는다.

### 5.2 타당해서 적용할 부분

1. **출처 검색·추가학습 효과·내부 기여를 서로 구분한다.** 비슷한 문장을 찾았다는 것과 그 문장 때문에 답변이 만들어졌다는 것은 다른 주장이다. 현재 상태에서+와0을 비교하는 실험은 잘 정의할 수 있다. 과거300M trajectory의 문장별 원인을 소급 복구하는 기능은 현재 없다.
2. **실제 optimizer를 사용한다.** [Muon](../tinylm/train/muon.py)은 momentum·Newton–Schulz·형상별 RMS배율을 사용한다. 예제별 업데이트의 단순합은 batch 업데이트가 아니다. clipping과 AdamW의 moment도 영향을 주므로 실제 finite update를 기준으로 대리 gradient 점수를 검증하자는 방향이 타당하다.
3. **정답·질문 의존·종료·망각을 따로 본다.** 지금의 손실 감소와 실제0/8이 보여 주듯 단일 CE만으로 교육 성공을 정하면 안 된다. 질문만 바꾼 쌍이 모두 맞는지, 올바른 답 뒤에 멈추는지, 답하기 전에 멈추는지를 분리하는 설계는 적용 가치가 높다.
4. **선택·개발·최종 시험을 분리한다.** 원문의 최종 봉인 질문은 교사 프롬프트/자료 교정/선택에 노출하지 않는다. 기존 공개8문항은 계속 회귀용으로 쓰되 최종 일반화 시험으로 재명명하지 않는다.
5. **값싼 대조군을 먼저 둔다.** 같은 정답/원천/길이 자료에서 균형 무작위와 선택만 다르게 하고, 추가 선택비용을 포함해 비교해야 한다. 일반 생성자료의 전수 사실검증을 요구하는 대신, 작고 통제된 인과 진단셋에서만 코드로 정답을 확인한다.

**수학적 보완:** 원문의 고정 분모 zero-weight는 실제 행 삭제·재정규화와 다르며, zero gradient와 None gradient가 optimizer에서 달리 동작할 수 있다는 지적은 정확하다. 그러나 token 손실 기여를 없애도 clipping·moment 상호작용으로 rehearsal 쪽 효과까지 변한다. 이는 정의한 개입의 총 조건부 효과이지 후보의 고유한 독립 공헌량이 아니다.

`ΔQ=α0ΔC+ΔαC0+ΔαΔC`는 완전 삼진화의 곱 전개로 맞다. 현재α는별도독립학습parameter가 아니라 group의latent 절댓값과mask에서계산된다. code/scale을각각독립인과레버처럼이식하면실제양자화함수가만들수없는상태가될수있다. 실제endpoint의전체물리group을이식하고cache를새로만드는후속으로제한한다. 부분anneal,connectivity,arena,mode경로가켜진경우추가항과buffer를함께기록한다.

## 6. 방법 — 권장 수정 순서

현재 승인된 공개 C+B의75M/300M 목표는 유지한다. 새 연구는 그 교육을 영구 중단시키는 전제가 아니라, 반복/단답 실패를 좁히는 별도 진단으로 둔다.

| 단계 | 무엇 | 비용 | 다음 단계 조건 |
|---|---|---:|---|
| 0 | 현재마스크/시프트/정지·source/배치·실제노출수 근거대조 | CPU·기존원본,이번수행 | 코드오류와작은표본/분포문제구별 |
| 1 |32개코드정답 QA 암기·질문교체/정상반복대조,greedy/EOS 관측 | ⚙0.5~1.5GPUh |29/32+정상종료는진단제안선. 실패하면원인축하나만수리 |
| 2 |512candidate·256rehearsal·별도select/dev/test의자료와완전상태계약 | ⚙6~10engineer-h 추가 | 전체상태/alias/RNG/quantcache복원·같은입력A/A 확인 |
| 3 | 후보16묶음의K=2 실제+/0·공통tail·균형무작위와선택 비교 | ⚙2~4GPUh 후보,먼저실측갱신 | 고정dev 신호와봉인실답·망각/비용을함께만족 |

단계1은자료32개를최대128update 반복하는 **암기진단**이며 정상4epoch SFT와다르다. 승인하면micro8×accum4로32개가한update에들어가게하는별도진단recipe를기록한다. 본학습micro8×accum16은변경하지않는다. 이예외승인없이기존4epoch cap을우회하지않는다. CPU준비와사용자GPU실행을구분한다.

단계2이후는기존부모optimizer의완전역사재개가아니라같은부모에서동일fresh AdamW/Muon으로만든새S0를쓴다. model/optimizer state 외에train/eval·anneal·quantcache·CPU/CUDA/loader RNG·microbatch계획·loss분모·clipping/skip을고정한다. 현재의checkpoint보존기능만으로이조건이완성됐다고표시하지않는다.

## 7. 거절하면 못 하는 것

기존 공개 C+B 교육·실답검토·자료재가공은 계속할 수 있다. 거절하면 지금은 “어떤 자료 묶음의 실제 업데이트가 더 유익한가”와 가중치 블록 기여에 대한 별도 인과 증거를 얻지 못한다. 교육 자체가 불가능해지는 것은 아니다.

### 권장안과 근거

당초 A를 권장했으나, **사용자가 정량 비용을 확인한 뒤 B를 선택했다.** 이를 반영해 비용/A-A40 → tiny최대128 → 실제+/0와tail144 → 정책256의 전체 구현을 준비했다. 각 선결이 음성이면 후속은 자동 중단하며 최종까지 최대568업데이트/기본 누적4h를 넘기지 않는다. micro8×accum4의 작은 반복 진단은 정상 micro8×accum16·4epoch 교육과 분리한다.

현재 산출물은 P106C의 자료·캡슐·실제 AdamW/Muon 개입·동일 길이/언어/지도량 정책·봉인 답안/망각/비용 코드와 사용자 SH5개다. CPU 회귀의 상태복원/고정 분모 성공을 실제 CUDA 복원이나 학생 품질로 승격하지 않는다. 제안서가 진행 중인 이유는 구현 미착수가 아니라 **비용/A-A, tiny 학습, 선택 효과의 사용자 실물 증거가 아직 없기 때문**이다. 이 후속 증거는 다음 작업에서 회수하며 현재 구현 WIP의 미완료 사유로 남기지 않는다. 실행 단계·문턱·전체 비용의 최신 정본은 P106C 계획을 따른다.

## 10. 2026-10-04 갱신 — 실제 비용은 작았지만 선택 효용은 음성

[결과102](../test_result/102_20261003_P106C-암기는-통과했지만-선택은-일반화를-해쳤다.md)에 사용자 Stage0~4와 추가 승인 A의 원본을 연결했다. 실제472업데이트 phase wall610.19초였고, 비용40회/A-A복원·32문항암기는 통과했다. 따라서 “기초 답변 학습이 아예 안 된다”는 우려는 이 폐쇄형 과제에서 기각됐다.

그러나 원래의선택 팔은 같은학습량에서도실답15/128 대무작위91/128,문항쌍0/64 대27/64였다. 양팔native CE도부모보다각+0.5105/+0.5329로악화했다. 실제optimizer를사용한다는설계는타당하지만그점수로고른자료가항상더좋다는것은아니다. tiny성공과선택의일반화실패를분리한다.

사용자가A/B모두준비하고 A만직접GPU진단하는1안을승인했다. A의동일사실/순서반전은두학생정방향32/32·역순25/32 대9/32를보였고학생cache차이0,부모BF16차이는FP32에서일치했다. 원선택정책은비채택,어순민감성은관측으로기록한다. 보완B는원자료의언어·정답색·질문쌍/token을맞춰최대32회와8/16/32중간결과를잰다. B의GPU는NOT_RUN이며이결과전에는제안서전체를done으로옮기지않는다. 원형모델/자료·정식300M레시피는변경하지않았다.

## 11. 2026-10-04 후속 회수 — 업데이트 부족과 언어 보존을 구별

위 §10의 B미실행은 당시 상태다. 현재는 [결과102 §6~8](../test_result/102_20261003_P106C-암기는-통과했지만-선택은-일반화를-해쳤다.md)에 균형32·어순32·부모제거32·어순128·친숙이름32까지 완료했다. 균형과이름/초기화변경만의32회효과는없었으나,부모유지·양순서128회는128/128·두대상쌍64/64·형식/어순64조합전부정답이었다.

이에 따라 **학습 배선이 아예 작동하지 않는다는 가설은 이 폐쇄형 과제에서 지지되지 않는다.**32회음성을근거로부모나TinyLM구조를교체하기보다실제업데이트/지도token/조건다양성을확인해야한다. 그러나양순서128회native+0.476504·control0/64여서일반언어보존과실용SFT는입증되지않았다. 원래실제업데이트자료선택 알고리즘의비채택도유지한다. 이는선택기효과가아니라선택기를제외한후속학습대조다.

승인된 최초 구현·비용/A-A·tiny·선택 비교와 이번 진단의 **실행 증거는 모두 회수 완료**다. 더 이상 “B 사용자 실행 대기”를 미완료 이유로 쓰지 않는다. 제안의 광범위 효용·언어 보존은 음성/미측정 범위를 명시하고 후속 실교육/보존 설계 선택으로 분리한다. 제안서의 자동채택이나 물리 가중치 블록이식 승인은 없으며, 추후 종결/후속 분리 이관은 이 실제 상태를 기준으로 한다.
