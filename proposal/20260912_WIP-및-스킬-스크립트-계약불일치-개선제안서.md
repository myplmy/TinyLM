# WIP 및 스킬-스크립트 계약 불일치 개선제안서

> 작성일: 2026-09-12  
> 범위: `.agents/skills/**/SKILL.md` 17개와 그 문서가 명시적으로 호출하는 저장소·번들 스크립트  
> 상태: **제안만 작성**. 이 문서 작성 시 스킬·스크립트 구현은 변경하지 않았다.

## 1. 결론

우선 고칠 것은 **`wip.py`의 현재 열 의미가 아니라 `wip-ledger/SKILL.md`의 표 템플릿**이다.
현재 `scripts/wip.py`는 다음 5개 열을 계약으로 삼는다.

```text
# | 지시 | 상태 | 작업 내용 | 산출물
```

반면 스킬은 다음 열을 만들라고 지시한다.

```text
# | 지시 | 상태 | 산출물 | 이어받을 지점
```

두 표는 열 개수가 같아서 도구가 오류를 내지 않는다. 그 대신 스킬식 `산출물`을 도구가
`작업 내용`으로, `이어받을 지점`을 `산출물`로 해석한다. 따라서 **조용한 의미 뒤바뀜**이다.

즉시 조치는 다음 조합을 권장한다.

1. `SKILL.md`의 생성 템플릿과 설명을 `작업 내용 | 산출물`로 고친다.
2. `wip.py`의 현행 쓰기 스키마는 유지하되, 헤더 문구를 검사하여 잘못된 스키마의 상태 변경을
   거부하게 한다.
3. 과거 `산출물 | 이어받을 지점` 원장은 **읽기 전용 레거시**로 취급한다. 일괄 재작성하지 않는다.

쉽게 말하면, 지금 도구가 지키려는 핵심은 “상태를 바꿀 때 무엇을 했는지 반드시 쓴다”이다.
그 핵심과 맞는 쪽은 현재 스크립트다. 다만 도구가 잘못된 표를 눈치채지 못하는 문제도 함께
막아야 한다.

## 2. 재현 근거

### 2.1 주 불일치

| 근거 | 관측 |
|---|---|
| `.agents/skills/wip-ledger/SKILL.md` 템플릿 | `# / 지시 / 상태 / 산출물 / 이어받을 지점` |
| `scripts/wip.py:77,110` | `# / 지시 / 상태 / 작업 내용 / 산출물`로 해석 |
| `scripts/wip.py:123~136` | `--note`는 4번째 업무 열에 누적하고 `--artifact`는 5번째 업무 열을 덮어씀 |
| 현행 열린 원장 | `handoff/WIP_20260912b_작업원장.md`는 스크립트형 헤더를 사용 |
| 레거시 재현 | `python -X utf8 scripts/wip.py --list --file handoff/WIP_20260911c_작업원장-done.md`가 실제 산출물 경로를 작업 노트처럼 인쇄 |

핵심 원인은 `wip.py`가 **열 개수만 검사하고 헤더 의미는 검사하지 않는 것**이다. 두 스키마가
모두 5열이므로 파싱은 성공하지만 의미가 틀린다. 이는 단순 표시 문제가 아니다. 레거시 원장에
`--done --note ... --artifact ...`를 실행하면 두 열을 원래 뜻과 다르게 갱신한다.

### 2.2 저장소 안의 혼재

`handoff/WIP_*_작업원장*.md` 헤더를 전수 검색한 결과 세 형태가 공존한다.

- 구형: `상태 | 산출물 | 이어받을 지점`
- 신형: `상태 | 작업 내용 | 산출물`
- 더 오래된 최소형: `상태`까지만 존재

따라서 과거 파일을 한꺼번에 새 스키마로 바꾸는 것은 기록 보존 원칙과 맞지 않는다. 도구가
스키마를 식별하여 읽기와 쓰기 권한을 달리하는 편이 안전하다.

## 3. 선택지 비교

| 안 | 내용 | 장점 | 위험 | 판정 |
|---|---|---|---|---|
| A | `wip.py`를 구형 스킬 표에 맞춤 | 문서 한 곳을 안 고쳐도 됨 | 상태 변경 때 필수 작업 설명을 누적하는 사용자 요구와 충돌하고 최근 원장을 다시 깨뜨림 | **기각** |
| B | 스킬을 현행 스크립트 표에 맞추고 스크립트에 헤더 검증·레거시 읽기 전용을 추가 | 현재 강제 규칙 보존, 조용한 오해 차단, 과거 기록 불변 | 두 파일을 함께 손봐야 함 | **권장** |
| C | `작업 내용 | 산출물 | 이어받을 지점`의 6열 v2 스키마로 둘 다 확장 | 재개 지점을 별도 구조화 가능 | 파서·테스트·과거 호환·생성기까지 큰 변경, 당장 필요한 범위를 넘음 | **후속 선택안** |

권장안 B에서 `wip.py`를 고친다는 뜻은 **열 의미를 바꾸는 것**이 아니라 **잘못된 헤더를
거부하도록 방어를 추가하는 것**이다.

## 4. 권장 상세 변경

### 4.1 `wip-ledger/SKILL.md` — P0

- 템플릿 헤더를 `| # | 지시 | 상태 | 작업 내용 | 산출물 |`로 변경한다.
- `작업 내용`에는 `wip.py --note`가 착수·완료 이력을 append-only로 누적한다고 명시한다.
- `산출물`에는 `--artifact`가 최종 경로를 기록한다고 명시한다.
- 상태 변경 예시는 항상 선택한 원장을 `--file`로 명시한다. 현재 기본 동작은 열린 원장이
  여러 개면 사전순 마지막 파일을 고르므로, 동시 작업에서 엉뚱한 원장을 바꿀 수 있다.
- 같은 날짜의 두 번째 원장을 수동 고정명으로 덮어쓰지 않도록 고유 접미사 규칙 또는
  `wip.py --new` 생성 기능을 후속 도입한다.

### 4.2 `scripts/wip.py` — P0 방어 보강

- 상황판 헤더를 찾아 `작업 내용`, `산출물`의 정확한 위치를 검증한다.
- 구형 헤더는 `--list`만 허용하고 출력 첫 줄에 `LEGACY_READ_ONLY`를 표시한다.
- 구형·최소형 원장에 대한 `--start/--done/--block/--wait/--close`는 명시적 오류로 중단한다.
- 열 개수뿐 아니라 헤더 스키마 버전도 검사하는 단위 테스트를 추가한다.
- 여러 열린 원장이 있으면 기본 선택을 하지 말고 `--file`을 요구하는 편이 안전하다.

### 4.3 과거 원장 — 수정하지 않음

과거 완료 원장은 당시 기록이다. 헤더를 소급 변환하면 해시·감사 이력이 달라지고, 열 내용이
어느 의미로 작성됐는지 자동 판정하기도 어렵다. 새 도구가 레거시를 읽기만 하도록 한다.

## 6. 구현 순서와 수용 기준

### 단계 1 — 문서-현행 코드 정합

1. `wip-ledger/SKILL.md` 템플릿·예시 수정
2. `session-handoff/SKILL.md` 잘못된 리소스 경로 수정
3. `run-batch/SKILL.md` 검증 체인 보강
4. UTF-8 명령 표기 통일

수용 기준: 스킬에 나온 모든 명시 경로가 존재하고, 새 WIP 템플릿으로 만든 표에서
`--start`, `--done --artifact`, `--list`, `--close`가 의도한 열만 바꾼다.

### 단계 2 — 도구 방어

1. `wip.py` 헤더 검증과 레거시 읽기 전용 모드
2. 복수 열린 원장일 때 `--file` 강제
3. `--help` 일관성 보강

수용 기준:

- 신형 표: 상태 변경 성공
- 구형 표: 목록 조회 성공 + 상태 변경 거부
- 최소형 표: 명시적 스키마 오류
- 이스케이프 파이프, `2A` 같은 번호, 상황판 밖 유사 표에 대한 기존 회귀 테스트 유지
- 열린 항목이 있으면 `--close` 거부

### 단계 3 — 선택 사항

실제 재개 품질을 높일 필요가 확인되면 6열 v2와 `wip.py --new`를 별도 제안·테스트한다.
기존 완료 원장의 소급 변환은 하지 않는다.

## 8. 최종 판정

- **주 질문:** `SKILL.md`를 현행 `wip.py` 스키마에 맞춰 먼저 갱신한다.
- **동시 필수 방어:** `wip.py`에는 헤더 검증과 레거시 쓰기 거부를 추가한다.
- **하지 않을 것:** 과거 완료 WIP 일괄 변환, 상태 의미를 구형 템플릿에 맞추는 역행,
  정적 통과만으로 Codex 환경 E2E 완료 선언.
