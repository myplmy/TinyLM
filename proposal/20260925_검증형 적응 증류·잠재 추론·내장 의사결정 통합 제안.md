## 1. 결론·목표·범위

A는 대규모 수작업 QA 데이터 없이 수행하는 **외부 교사 기반 온라인 합성 데이터 증류**로 정립한다. 교사가 학생의 답에 점수를 매기는 것과 학생 가중치를 갱신하는 것은 별개다. 검증된 교정답과 짧은 풀이를 지도학습 목표로 공급하고, 만족도는 학습과정 제어에 사용한다. 교사의 가중치는 초기에는 고정한다. 적응하는 것은 출제 분포와 교육 전략이다.

B는 gzip 같은 파일 압축이 아니라 **과제에 필요한 정보를 보존하도록 학습한 잠재표현**으로 정립한다. 먼저 연속 표현의 효과를 확인하고, 이후 FSQ 또는 VQ를 비교한다. 잠재 추론을 작은 모듈로만 수행하는 안과 전체 Transformer를 통과시키는 문헌 재현형을 구별한다.

C는 Jev의 비공개 내부 구조를 추측하여 복제하는 대신, **TinyLM의 문맥 표현을 공유하면서 선택·검증·추론 예산을 출력하는 소형 결정 헤드**로 정립한다. 결정의 형식 보장, 정답률, 확률 보정은 별도 평가 대상이다.

목표는 교사 만족도나 훈련 손실의 개선 자체가 아니다. 외부 교사와 정답 힌트 없이 실행되는 최종 학생에서 다음을 확인한다.

- 미관측 문제 가족·조합에 대한 정확도와 지시 준수 향상.
- 기존 한국어·영어 및 언어모델링 능력 보존.
- 같은 품질에서 CPU 지연시간 감소, 또는 같은 계산·메모리 예산에서 품질 향상.

이 제안의 범위는 사전학습된 TinyLM의 후속 학습이다. 무작위 초기화에서 지식·언어능력까지 무자료로 획득한다는 주장은 하지 않는다. 사람이 개별 QA를 만들지 않는 운영은 검증 가능한 영역에서 가능하지만, 검증 규칙·능력 명세·예산·시험 설계까지 없어지는 것은 아니다.

### 2.2 구현 경계

CPU 배포 메모리 목표와 학습 GPU 메모리는 따로 회계한다. 32/40 MiB 등의 기존 예산은 저장 파일·가중치 payload·작업 메모리·RSS·KV 중 무엇을 의미하는지 기존 측정 도구의 정의와 맞춘다. 새 모듈 가중치가 1 MiB 미만이라는 계산이 전체 런타임의 1 MiB 미만 증가를 보장하지 않는다.

기존 체크포인트, `datasets/TinyDataset/**`, 사용자 로그는 이 제안의 조사·생성 데이터 경로로 사용하지 않았다. 새 데이터와 원장은 승인된 별도 scratch 경로에 둔다. 원본 데이터의 대용량 blob을 Git에 추가하지 않는다.

### 4.1 기본 흐름과 학습 신호

```text
능력 명세 + 래퍼가 계산한 상태
  -> 교사의 문제·독립 정답·짧은 풀이 생성
  -> 문제 유효성/정답 검증
  -> 학생의 무힌트 답변 생성 (이 단계는 보통 no_grad)
  -> 실행 검증기 또는 별도 평가 문맥에서 답변 평가
  -> 검증된 교정답과 풀이로 gradient update
  -> 새 형제 문제 및 지연 복습에서 전이 진단
  -> 래퍼가 다음 출제 분포를 갱신
```

실제 지도 손실의 중심은 `CE(student(q), verified_target)`이다. 틀린 학생 답변을 그대로 정답으로 CE 학습시키지 않는다. -1 점수로 CE 부호를 뒤집는 것도 기본안이 아니다. 오답은 교정답 생성과 선호쌍·오류 분류에 사용한다. 정답 텍스트 없이도 REINFORCE/PPO류 보상 최적화로 학습하는 경로는 가능하다. 다만 이는 별도 policy-gradient 목적함수가 필요한 강화학습이며, 작은 학생의 초기 정답률과 보상 신뢰성이 낮을 때의 비용·분산 때문에 첫 실험에서는 채택하지 않는다. SFT가 안정된 뒤 검증된 선호쌍의 DPO 또는 실행 보상의 RL을 별도 비교한다.

외부 teacher의 텍스트는 학생 tokenizer로 다시 tokenize한다. 이 경로는 기존 HF 로짓 KD와 다르며 teacher와 student vocab를 맞출 필요가 없다. GKD의 token 분포까지 도입하려면 별도 어휘 정렬/동일 tokenizer 검증 및 메모리 실험이 필요하다.

### 4.2 만족도의 분해

```text
validity: valid | invalid | uncertain
correctness: true | false | unknown
instruction_compliance: 0..1
reasoning_step_validity: null 또는 단계별 값
judge_confidence: 0..1
error_type: 산술/관계반전/조건누락/부정처리/형식/근거부족/기타
```

`display_score = 2 * verified_quality - 1`는 사용자가 원하는 -1..1 인터페이스를 유지하는 방법이다. `unknown`은 0점이나 오답으로 변환하지 않는다. 점수와 confidence는 별개다. 정답 판정 우선순위는 실행·정형 규칙, 신뢰 근거, 교사 판정 순서다. 교사의 자가 확신은 그 자체로 검증이 아니다.

### 4.3 최소한 유지할 내용

대규모 고정 QA 대신 능력별 prerequisite와 생성 규칙을 유지한다. 초기 과제는 다음 네 계열로 제안한다.

| 계열 | 생성·검증 방식 | 전이 시험 |
|---|---|---|
| 관계·조건 논리 | 객체·관계·조건을 먼저 생성하고 정답을 코드로 계산한 뒤 언어화 | 객체명, 관계 방향, 표현 순서, 새 관계 조합 |
| 산술·단위 | 정형 표현에서 문제와 계산 정답 생성 | 숫자 범위, 단위, 역산, 불필요 정보 |
| 정보 추출·지시 준수 | 입력 내 근거와 출력 schema/조건 검사 | 한국어 변형, 순서 변경, 다중 제약, nonce 이름 |
| 짧은 문맥 이해 | 근거 범위가 주어진 문장/문서에서 QA 생성 | 부정, 예외, 근거 없는 질문, 참조 해석 |

역사·과학·상식처럼 외부 사실이 필요한 내용은 근거 문서나 검증 가능한 지식원을 허용하는 별도 트랙으로 둔다. 교사 단독 폐회로의 합의만으로 사실성을 확정하지 않는다. 임의의 생성 코드를 실행할 때는 네트워크·호스트 파일 접근을 막고 시간·메모리를 제한한다.

### 4.4 적응 정책과 과적합 판정

교사에는 최근 전체 대화가 아니라 topic별 노출 수, template family별 노출 수, 새 문제 정확도, 지연 복습 정확도, 오류 분포, 남은 비용을 전달한다. train loss는 참고 신호이며 난이도가 다른 배치 간 raw loss 비교로 숙달을 판정하지 않는다.

첫 기본 정책은 규칙형이다. 충분한 표본이 있는 능력에 대해 성공률 0.3~0.8 범위를 탐색하고, 숙달한 가족은 복습으로 이동하며 전혀 해결하지 못하는 과제는 하위 능력으로 분해한다. 이 범위는 제안 초기값이지 선행연구의 보편 최적값이 아니다. CE 학습에서는 어려운 문제라도 검증된 좋은 설명이 있으면 학습 가치가 있으므로 일괄 폐기하지 않는다.

LLM 적응 정책은 이 규칙형 대조군보다, 같은 비용에서 **새 문제의 지연 성능 증가**를 더 크게 만드는지 검증한다. 출제 내용 변화와 순서 효과를 구분할 필요가 있으면, 적응 과정에서 확보한 동일 QA 풀을 정적 순서로 다시 학습하는 후속 대조군을 둔다. 같은 문제 즉시 재응답의 성공은 숙달로 집계하지 않는다. 동일 표현 반복과 의미상 동형 문제 반복을 각각 제한한다.

### 4.5 데이터 분리·보존

- `train`: 신규 학습과 검증된 replay. 반복 노출은 모두 기록한다.
- `curriculum_probe`: 교육 정책에 실제 영향을 주는 진단 문제. 최종 검증셋이라고 부르지 않는다.
- `dev`: 모델 선택용 및 분리된 calibration 부분집합. 교사에게 원문·정답을 노출하지 않는다.
- `sealed_test`: 생성 가족·규칙 조합을 사전에 분리한 최종 시험. 개발 종료 전 사용하지 않는다.

문장 단위 무작위 분할만 사용하지 않는다. family/논리 템플릿/원본 근거/변형 묶음 기준으로 분리한다. 생성 시 split을 먼저 정한다. 검증기가 모든 split에 같은 의미 정의를 적용하는 것은 가능하지만, test의 문항과 구체적 정답을 teacher에게 알려 주지 않는다.

초기 샘플 혼합 후보는 신규 60%, replay 20%, anchor 20%다. 모두 공학적 초기값이다. 엄격한 최소자료 트랙의 anchor는 초기 검증 합성 과제이고, 현실적인 보존 트랙에서는 승인된 소량의 원문도 별도 실험으로 허용한다. 합성 replay를 원본 데이터 보존과 같은 것으로 과장하지 않는다.

### 4.6 reasoning/hint 및 메모리

학생이 직접 생성해야 하는 thinking은 정답 target으로 학습한다. teacher가 외부 힌트로 미리 주입한 thinking은 입력으로 취급하여 해당 토큰의 loss를 마스킹한다. 두 경우의 provenance를 구별한다. 최종 성능은 항상 외부 힌트가 없는 자유 생성으로 평가한다.

독립 문제 사이와 가중치 갱신 뒤에는 KV를 재사용하지 않는다. 가중치가 바뀌기 전 KV는 새 모델의 유효 캐시가 아니다. 교사 문맥 유지, 학생 KV, 학습된 가중치, replay 원장은 서로 다른 상태다.

## 5. B: 압축된 잠재 추론

### 5.1 비교할 표현

| 후보 | 초기 위치 | 비용·한계 |
|---|---|---|
| 짧은 자연어 풀이 | 필수 대조군 | 단순히 풀이를 짧게 쓰는 것보다 복잡한 방법이 실제로 나은지 확인 |
| 압축된 symbolic plan/연산 코드 | 저비용 보조 대조군 | 제약·단위·부정을 명시할 수 있지만 범용 의미를 모두 표현하지는 못함 |
| 연속 잠재표현 | 1순위 연구 후보 | 학습은 추가 비용. 반복 forward와 KV를 실제로 회계 |
| FSQ | 연속 후보가 성공한 뒤 | 고정 유한 값의 조합. vision 선행결과를 언어 추론으로 직접 일반화 금지 |
| VQ | FSQ와 나란히 비교할 후속 후보 | codebook 사용률·dead code·commitment loss·encoder/decoder 비용 |
| gzip/zstd 등 lossless byte stream | 본 추론 경로로는 우선 제외 | 저장 크기와 학습 가능한 의미구조, 토큰 수, 연산량은 서로 다름 |

단일 K종류 코드의 index가 추가하는 구별 정보량은 최대 log2(K) bit다. 문맥과 decoder가 같은 코드를 풍부하게 해석할 수는 있지만, 무제한의 새 정보를 공짜로 넣는 것은 아니다. BF16 연속 벡터 한 개도 자연어 토큰 한 개와 정보량·계산량이 같지 않다.

### 5.2 서로 다른 두 구조

**B1: 문헌 근접 연속 잠재 경로**

```text
q를 한 번 prefill -> h_q
h_q를 projection -> 가상 입력 embedding z_1 -> Transformer -> h_1
h_1를 projection -> 가상 입력 embedding z_2 -> Transformer -> h_2
... K회 -> 답변 또는 짧은 thinking + 답변
```

K는 처음 2/4만 비교한다. 각 잠재 위치는 Transformer를 한 번 통과한다. 사용자가 보지 않는다고 계산이 사라지는 것은 아니다. 우선 이미 학습된 explicit 경로와 joint alignment로 배운다.

**B2: TinyLM용 좁은 보조 모듈 — 별도 미검증 가설**

```text
q prefill -> h_q [d=768]
        -> down projection [r=64 또는 128]
        -> 작은 residual MLP의 잠재 갱신 2/4회
        -> up projection [d=768]
        -> 가상 입력 embedding 1개를 Transformer에 전달
        -> 답변 또는 짧은 thinking + 답변
```

B2는 보조 모듈의 반복 횟수만큼 전체 Transformer를 반복하지 않는다. 그러나 마지막 가상 위치의 Transformer 1회는 여전히 필요하다. q는 처음 한 번 처리하며, z는 오직 현재 causal 문맥에서 예측한다. 이 변형의 성능은 Coconut/CODI 논문이 직접 검증한 것이 아니다.

### 5.3 학습 단계

1. 외부 교사가 만든 **검증된 짧은 풀이**로 학생의 explicit 경로를 먼저 학습한다.
2. 같은 학생의 explicit 경로와 latent 경로를 함께 학습한다. explicit 경로의 정답 직전 표현을 stop-gradient target으로 사용하고, latent 경로의 대응 표현을 정렬한다. 정답 토큰 이후의 표현을 타깃으로 사용하지 않는다.
3. 보조 decoder가 잠재 단계에서 해당 풀이의 관계·연산·제약 또는 짧은 단계 텍스트를 예측하도록 감독한다. teacher의 원래 거대 모델 hidden 좌표를 학생과 직접 맞추지 않는다.
4. 점진적으로 짧은 풀이를 내부화하고 explicit 경로도 유지한다. 실제 추론에서는 정답·teacher 풀이 없이 q에서 z를 만든다.
5. 효과가 확인된 연속 z에 대해서만 FSQ/VQ를 도입한다. 배포에서는 학습용 decoder를 제거한다.

정렬만으로 정답 보존이 보장되지 않는다. 답변 CE와 조건 반전·부정·숫자·단위 보존 검사를 함께 사용한다. decoder로 원문을 복원할 수 있다는 사실만으로 z가 답변에 사용된다고 결론내리지 않는다.

### 5.4 필수 대조군과 메모리

동일 수의 pause/dummy embedding, 동일 추가 파라미터의 단순 MLP, z=0, 다른 문제의 z로 교환, z 순서 혼합을 비교한다. 무의미 z에서도 같은 결과라면 ‘압축된 의미 추론’보다는 추가 계산 또는 모듈 정규화 효과일 수 있다.

B2의 down/up 2행렬과 r×r MLP 2행렬만 계산하면 r=64에서 106,496개 파라미터·BF16 0.203125 MiB, r=128에서 229,376개·0.4375 MiB다. bias/norm/gate/양자화 metadata/가상 위치 KV/allocator/RSS는 별도다. 이는 실제 측정치가 아니다.

처음부터 긴 텍스트 thinking을 생성한 뒤 압축해서는 생성 비용이 줄지 않는다. teacher 풀이 압축은 **학습 단계의 목표 구성**이며, 배포 latent는 q에서 직접 예측해야 한다.

## 6. C: 공유 표현 기반 결정·검증 헤드

### 6.1 역할

C는 단순한 ‘더 생각할지’ 라우터에만 한정하지 않는다.

| 시점 | 입력 | 출력 | 정답 라벨 |
|---|---|---|---|
| 질문 종료 | 질문의 causal hidden | 응답 가능성, 모순/추가정보 필요, direct/latent/text 모드별 성공 가능성 | 실제 각 모드의 검증된 결과 |
| 선택 과제 | 질문·후보 또는 후보별 표현 | 후보별 점수/확률 | 정답 또는 검증된 선호쌍 |
| 답변 종료 | 질문·자기 답의 causal hidden | 정답 가능성, 조건 준수, 재검토/유보 | 외부 검증 및 오류 라벨 |

고정 클래스 head만으로 임의의 새로운 후보 문장의 의미까지 알 수 있다고 가정하지 않는다. 임의 후보는 문맥에 포함하거나 후보별 표현을 계산해야 하며 그 비용을 포함한다.

예시 단일 head는 768→128→6이다. bias 포함 99,206개 파라미터, BF16 가중치만 약 0.1892 MiB다. 질문 전/후 head를 독립적으로 두면 약 두 배다. 작은 head가 전면 Transformer를 대체하는 것은 아니다. 문맥을 읽는 prefill 계산은 남는다.

### 6.2 감독과 확률 보정

교사의 -1..1 만족도를 C의 유일한 진실 라벨로 삼지 않는다. A에서 생성된 검증 정답, 오류 유형, 모드별 실행 결과를 사용한다. backbone을 먼저 고정하여 head의 정보 이용 능력을 측정하고, 이득이 있으면 낮은 학습률의 공동학습을 후속 비교한다.

모드 선택은 예를 들어 다음 효용을 최대화한다.

`utility(a|q) = predicted_success(q,a) - λ * measured_cost(a) - μ * error_risk(q,a)`

선택된 모드의 데이터만으로 모든 모드의 가치를 추정하지 않는다. 학습용 일부 문제는 direct/latent/text를 모두 실행하여 대응 라벨을 수집한다. 여기서 발생한 추가 rollout 비용도 기록한다.

최종 backbone이 고정된 후 calibration 전용 dev에서 temperature scaling 등으로 보정한다 [S19]. Brier/NLL, ECE, 정답/오답 구별 능력, 위험-응답률 곡선, 고확신 오답률을 함께 본다. 항상 평균 확률을 내는 무능한 head도 일부 보정 지표가 좋아질 수 있다. OOD와 교사 변경, backbone 갱신 뒤의 보정 저하를 별도 검사한다.

C가 자신을 좋다고 평가했다는 이유만으로 A의 학습 정답을 승인하는 순환은 금지한다. 초기에는 C를 학습 효율·배포 의사결정에만 사용하고 독립 검증기를 대체하지 않는다.

## 7. 통합 실험 계획

### 7.1 순서와 비교군

| 단계 | 실험 | 바꾸는 항목 | 선결 |
|---|---|---|---|
| G0 | 기준 checkpoint + 교사/검증기 진단 | 학습 없음 | 평가 가족 분리, tokenizer/실행 계약 확인 |
| A0 | 정적 교사 텍스트 SFT | 검증 QA 및 짧은 풀이 | G0 |
| A1 | 규칙형 적응 SFT | 샘플링 정책 | A0와 같은 교사·검증·손실 |
| A2 | LLM 적응 SFT | 샘플링/변형 정책 | A1과 비용 통제 |
| C0 | 선택된 A + 결정 head | head만 | A의 유효 비교 완료 |
| B0 | 선택된 A + 짧은 CoT/pause 대조 | 추론 예산 | A |
| B1 | 선택된 A + 연속 latent | latent 학습 | B0 및 API 테스트 |
| B2 | 선택된 A + 작은 sidecar | latent 계산 위치 | B1과 별도 가설로 취급 |
| BC | 선택된 A + 통과한 B + C | 적응 모드 선택 | B와 C 각각의 순이득 |
| Q | 통과한 latent의 FSQ/VQ | 양자화만 | 연속 latent의 이득 확인 |

세 아이디어를 동시에 켠 결과 한 개로 원인을 설명하지 않는다. A2와 A1의 차이가 없다면 규칙형 A1을 선택한다. B가 단순 짧은 풀이보다 못하면 latent를 빼고 A+C로 종료할 수 있다.

### 7.2 제안 초기 예산

아래는 기존 저장소의 승인된 실행값이 아니라 신규 실험을 위한 초기 제안이다.

- G0: 최소 4 능력 계열의 자동 검증 가능 문제로 학생·교사·검증기 진단. 무학습 pilot부터 실시한다.
- A pilot: 팔별 약 **2M student processed tokens 상한**, accepted token 수도 따로 집계. 효과·안전 신호가 없으면 확대하지 않는다.
- A 확인: 통과한 비교쌍만 **20M tokens 상한**, 3 seeds. 효과가 작고 CI가 넓으면 결론 보류 또는 검정력 재설계.
- B/C pilot: 동일한 검증 QA와 시작 checkpoint를 사용. 새 모듈/정렬에 드는 추가 training FLOPs를 별도 기록.
- teacher 호출: 문제 단위가 아니라 128~512문항 등의 batch 운영 후보. 단일 16GB GPU에서는 교사와 학생 학습을 교대로 배치한다. 구체 batch는 실행 프로브 후 확정한다.

사전학습의 131,072 tokens/step과 LR를 소규모 SFT에 그대로 복사하지 않는다. loss가 걸린 token 수, padded/processed token 수, rollout token 수, teacher token 수, FLOPs·wall time을 모두 구분한다. 고정 학습 token 비교와 고정 총 비용 비교를 둘 다 보고한다.

교사 8B/27B 등의 이름·크기만으로 채택하지 않는다. 실제 양자화된 교사·chat template·temperature 조합에서 문제 정확성, 풀이 오류, 학생 오류 식별률, accepted sample당 비용을 먼저 잰다. 모델 가중치·생성물 이용 조건도 확인한다. 이 검토에서는 특정 teacher checkpoint를 실행하거나 채택하지 않았다.

### 7.3 평가 계약

**주 지표:** 무힌트·교사 없는 최종 학생의 미관측 가족 pass@1/정확도. 국문/영문, 수치 변화/관계 반전/새 조합/문맥 근거 과제를 분리한다.

**보존 지표:** 고정 원문의 언어모델링 손실과 공통 byte-bpb, 지시 준수, 길이·반복, 기존 과제 성능. 다른 tokenizer의 자체 val CE를 직접 비교하지 않는다.

**B/C 지표:** direct/latent/text별 성공률, 전 과제 기준 정확도, 유보율, 응답한 문제의 정확도, Brier/NLL, 선택 정책의 비용 대비 효용. 유보한 문제를 버리고 남은 정답률만 올려 ‘지능 향상’으로 보고하지 않는다.

**실행 지표:** CPU 단일 스레드 우선, 동일 context 길이·출력 길이·backend의 end-to-end p50/p95, prefill, decode, RSS, runtime payload, KV, 학습 peak VRAM, teacher+student 총 비용. latent 비용은 출력 토큰 수에 숨기지 않는다.

family 단위 clustered bootstrap과 3 seeds의 변동을 함께 본다. seed 수만 늘리고 의미적으로 같은 template을 수천 번 복제해 검정력을 부풀리지 않는다.

### 8.1 제안 파일 배치 — 아직 존재하거나 구현됐다는 뜻이 아님

| 제안 위치 | 책임 |
|---|---|
| `tinylm/tutor/schema.py` | typed sample/feedback/state, provenance, schema version |
| `tinylm/tutor/controller.py` | 예산·주제·중복·숙달 정책; LLM 제안에 대한 최종 제약 적용 |
| `tinylm/tutor/teacher_client.py` | 교사 backend 인터페이스, 출력 검증, retry/비용 제한 |
| `tinylm/tutor/verifiers.py` | 정형 과제 검증, uncertain 처리, 실행 sandbox 경계 |
| `tinylm/tutor/replay.py` | family-aware replay/anchor, snapshot, bounded buffer |
| `tinylm/model/latent_reasoner.py` | B1/B2의 분리된 경로 및 선택적 FSQ/VQ |
| `tinylm/model/decision_heads.py` | C pre/post/choice 출력 |
| `tinylm/train/tutor_trainer.py` | 기존 optimizer·checkpoint 유틸리티와 연결하는 후속학습 루프 |
| `scripts/eval_tutor_transfer.py` | 잠긴 평가, 가족별 CI, 비용 회계 |

실제 이름·분리는 구현 전 현재 트리와 기존 SFT 경로를 대조해 중복을 제거한다. 기존 `trainer.py`의 모든 로직을 복제한 별도 학습기를 만드는 것은 피한다.

### 8.2 기존 코드 수정 경계

- `transformer.py`: token embedding 이후 d차원 입력을 받는 내부 함수로 분리; 새 opt-in embedding 입력 API; 선택 위치만 hidden 반환. 기존 호출·반환형은 불변.
- input_embeddings는 factorized embedding의 E차원이 아니라 emb_up 이후 d차원이라는 계약을 고정한다.
- latent 위치를 max_seq_len, RoPE, CLA KV owner, 반복 pass에 반영한다. batch 내 K가 다르면 bucket 또는 올바른 mask를 사용한다.
- `chat` canonical/serialize: 기존 text/thinking을 재사용. teacher-provided hint와 student-target thinking의 loss-mask provenance를 학습 어댑터가 명시한다.
- `config`/checkpoint/export/accounting: 새 모듈 default-off. 구 checkpoint 로딩, 추가 파라미터 optimizer 등록, CPU export, dtype 회계를 테스트한다.
- C는 전체 시퀀스 hidden을 보관하지 않고 질문/답변 종료 위치만 취한다. 기존 `logits_last_only` 최적화를 보존한다.

### 8.3 필수 테스트

| 테스트 | 통과 조건 |
|---|---|
| default-off 회귀 | 기존 경로의 동일 입력 출력이 선언한 수치 허용오차 안 |
| 생성/학습 분리 | 학생 rollout 자체로 optimizer step이 일어나지 않음 |
| loss mask | system/user/external hint/grade가 target에 누설되지 않음 |
| 미검증 정답 | unknown/invalid가 CE 정답으로 들어가지 않음 |
| 데이터 분리 | 변형 원본/family가 sealed_test와 train에 교차하지 않음 |
| 캐시 인과성 | 독립 문제/weight update 사이 캐시 미공유, prefill/decode 일치 |
| 잠재 인과성 | inference z가 정답·teacher 풀이·미래 token에 접근하지 않음 |
| B1/B2 구별 | 잠재 반복별 전체 backbone 호출 수·가상 위치 수를 기록 |
| 파라미터 등록 | 새 head/projector가 실제 optimizer에 있고 checkpoint에 보존됨 |
| C 라벨 시점 | 답변 전 head에 답변 hidden/정답이 들어가지 않음 |
| 확률 | 각 head의 normalized distribution, 보정 dataset 분리 |
| 예산 | 재시도·invalid 생성까지 teacher 비용 상한에 반영 |

이 문서에 기존 CLI처럼 보이는 미구현 명령을 제공하지 않는다. 실제 실행 명령·예상 소요시간은 위 구현·단위 검사 후 해당 하드웨어 throughput 측정에 근거해 계획서에 추가한다.

## 9. 채택·중단 기준과 산출물

**권장안(판단 대기):** 공개 SFT 적격성과 독립 verifier·split 격리 선결을 확인한 뒤 **A0 정적 검증 텍스트 SFT의 작은 기능 pilot**부터 열고, A1/A2 적응 정책·B 잠재·C 결정 head는 각자의 순이득이 확인될 때만 추가한다. §10.3의 A/B/C 대안 비교가 이번 검토의 구체 근거다. 이는 사용자 승인이나 구현·모델 실행을 뜻하지 않는다.

아래 수치는 **제안된 실무 채택선**이며 기존 레포의 nats 변동폭 기준을 전용한 것이 아니다.

- 품질 우선 경로: 주요 transfer 점수 +2 percentage points 이상을 목표로 하고, 가족별 CI 및 seed 변동이 개선을 지지하며 보존 과제의 손해를 별도로 승인할 수 있을 것.
- 효율 우선 경로: 주요 품질 저하 허용폭 1 percentage point 안에서 end-to-end CPU latency 20% 이상 감소를 목표로 할 것. 비열등성은 점추정만이 아니라 불확실성을 포함해 판단한다.
- C: 더 높은 유보율만으로 정확도가 오른 경우 성공으로 처리하지 않는다. 같은 응답률 또는 같은 비용에서 비교한다.
- B: 짧은 CoT/pause/동일 파라미터 MLP보다 낫지 않거나, latent 교환에도 영향이 없으면 의미 추론 주장 기각/보류.
- A: 교사 만족도만 오르고 sealed transfer가 오르지 않으면 순환 편향/암기 가능성을 우선 진단.
- 모든 단계: 데이터 누설, verifier 오류, 급격한 망각, 예산 초과 또는 정합성 실패 시 진행을 멈추고 해당 결과를 음성/무효/미검증으로 구분한다.

산출물은 teacher manifest, student checkpoint hash, tokenizer hash, split manifest, accepted/rejected ledger, loss-mask 통계, 배치별 비용, 라운드별 지연 전이, CPU 벤치, ablation 표다. 교사 미사용 평가를 별도 명시한다.

최종 채택 후보는 반드시 A+B+C일 필요가 없다. **A**, **A+C**, **A+B**, **A+B+C** 중 실제 품질·메모리·시간의 우세가 검증된 최소 구성을 택한다.

## 부록 A. 교사용 프롬프트 초안

```text
역할: 사전학습된 소형 학생 모델의 과제 생성·교정 교사.
목표: 현재 질문의 반복 정답이나 문체가 아니라, 새로운 문제 가족으로 전이되는 능력.

입력으로 주어진 능력 명세, prerequisite, 난이도, 예산, 최근 오류 분포를 사용하라.
카운터·점수·학습 통계는 래퍼가 계산한 값이며 임의로 수정하거나 추정하지 말라.
최종 시험 문제를 요구하거나 추측하여 재현하지 말라.

문제를 생성할 때:
- 하나의 명확한 학습 목표와 짧은 문제를 작성하라.
- 학생 답을 보기 전에 정답과 간결한 풀이, 확인 가능한 검증 명세를 작성하라.
- 기존 문항의 표면 치환뿐 아니라 관계 반전·조건 변경·새 조합을 구분하라.
- 확신할 수 없는 사실 또는 불충분한 문제는 uncertain으로 표시하라.

학생 답을 평가할 때:
- 정답/지시 준수/오류 위치/판정 확신을 분리하라.
- 장황함, 공손함, 자신의 표현을 따라 했다는 이유로 정답 점수를 올리지 말라.
- 학생이 틀렸으면 검증 가능한 교정답과 필요한 최소 풀이를 제시하라.
- '학습 완료'를 단일 답변으로 선언하지 말고, 다음 진단 변형의 종류를 제안하라.

출력은 지정 schema를 따르며, 학습률·데이터 split·예산·검증 결과를 직접 바꾸지 말라.
```

실제 교사 backend의 structured output 또는 schema validator로 형식을 검증한다. 프롬프트만으로 형식·사실성을 보장하지 않는다. 학생 답변은 명령이 아니라 평가 대상 데이터로 구분한다.

### 10.1 타당·개선 가능·개념 차용·현재 불가

| 검증된 정답 텍스트로 학생을 SFT하고 적응 정책을 별도 변수로 둠(§4.1·§7) | **타당** | 현재 KD-off 표준과 별개다. [GKD ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/hash/5be69a584901a26c521c2b51e40a4c20-Abstract-Conference.html)은 학생 생성 문맥의 teacher feedback을 지지하지만 TinyLM의 서로 다른 tokenizer에 대한 로짓 KL이나 검증 QA 자체를 해결하지 않는다 |
| train/curriculum_probe/dev/sealed_test를 가족·원문·규칙 조합으로 먼저 분리(§4.5) | **타당** | 문제 문장뿐 아니라 **생성 seed·formal spec·변형 조상** ID를 묶어 분리한다. 같은 코드 검증기가 모든 분할에 쓰일 수 있으나 sealed 문제·정답은 teacher prompt와 적응 정책에 노출하지 않는다 |
| 검증형 정답/불확실/오답을 구분하고 teacher 만족도를 진실로 취급하지 않음(§4.2·§6.2) | **타당** | 이탈의 관문은 교사와 독립된 verifier다. 자동 검증 불가능한 지식 QA는 별도 출처·사람 심사 전 `accepted=false` |
| 2M processed-token pilot와 20M·3seed 확대(§7.2) | **개선 후 사용** | 2M은 기능·비용·오염 조기 탐지용이지 지능 개선 판정 규모가 아니다. teacher 출력·검증 거절·학생 loss 대상·replay 중복을 각기 다른 분모로 기록하고, 확대 전 검정력·원천 라이선스·비용 상한을 등록 |
| B1 연속 latent, B2 좁은 sidecar와 더 짧은 CoT/동일 파라미터 MLP 대조(§5) | **개선 후 연구 가능** | [Coconut](https://arxiv.org/abs/2412.06769)은 GPT-2+ProsQA 등 특정 조건, [CODI](https://aclanthology.org/2025.emnlp-main.36/)는 GPT-2 규모의 명시/잠재 joint 학습 근거다. TinyLM B2의 전체 Transformer 호출 절감·언어 품질 효과는 두 논문의 증거가 아니다. 앞선 A-only 학생이 실제 정답률을 확보한 뒤 실행당 backbone 호출·KV·peak/RSS·CPU p95를 기록 |
| C의 질문 전/답변 후 head 분리와 calibration-only dev(§6) | **개선 후 사용** | pre-head가 답/미래 token을 보면 누설이다. 모든 모드의 counterfactual label 수집 일부를 고정하고 risk-coverage와 고확신 오답을 함께 재며, verifier를 C 점수로 대체하지 않는다 |

| 미검증 teacher 답을 보상±1로 바로 CE 부호 반전·자체 점수로 자기 정답 승인 | **사용불가** | 문서도 거부한 경로다. `unknown`을 오답으로 바꾸거나 학생 오답을 정답 target으로 쓰면 자기오류 강화. 검증된 정답 CE, 선호학습, RL은 서로 다른 목적함수 |
| 압축 latent 한 칸=자연어 사고 K토큰 무료 대체, 작은 결정 head=범용 답안 의미검사 | **사용불가** | latent에도 전/후 projection·Transformer pass·KV·학습비용이 있고, 임의 후보의 의미는 후보별 표현 없이 고정 head가 알 수 없다 |
| 논문/백서 효과를 TinyLM 40MiB·한국어 멀티턴·단일 CPU 성능으로 복사 | **사용불가** | 규모·교사·벤치·언어·메모리/속도 분모가 다르다. 구조/데이터/후속학습의 원인을 분해하는 대조군이 먼저다 |

**현재 코드 정정:** §2.1의 ‘hidden 반환 새로 필요’는 부분적으로 낡았다. `TiedMLPTransformer.forward(..., return_hidden=True)`가 이미 있고, 정규화 후 **전체 시퀀스 hidden**을 학습 전용으로 돌려준다(`return_aux/use_cache/logits_last_only`와 동시 사용 불가). B/C에는 선택 위치 hidden·연속 embedding 입력·KV/RoPE 인과 계약이 여전히 필요하지만 기존 API를 무시한 중복 구현은 불가하다. P090B 공개 SFT는 구조 후보일 뿐 `TRAIN_READY=false`이므로 A0 학습을 현재 실행 가능하다고 쓰지 않는다.

### 10.2 사용자 제시 Bonsai 교사 세 갈래 — 파일 크기와 교사 자질은 별개

| 후보 | 확인한 공급자 범위 | 사용 가능한 역할·위험 |
|---|---|---|
| **Bonsai 2 27B** | [제공 PDF](../article/prismML/bonsai-2-27b-whitepaper.pdf) §2~4는 언어 파일 PTQ1_0 5.93GB/PQ2_0 7.25GB(10진)와 thinking xhigh 20벤치 평균83.9를 보고한다. [공식 데모](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/README.md)는 Hadamard-aware PrismML llama.cpp fork가 필요하다고 한다 | 상대적으로 강한 정답·풀이 **후보**. 로컬 16GB GPU에서 가중치만 들어간다고 KV·context·runtime workspace와 학생 동시학습까지 들어간다는 뜻은 아니다. 교사 오프라인 생성→학생 별도 학습. 16k 근처 출력 상한에서 사고만 하다 답을 못 끝낼 수 있어 xhigh/medium·완료율·token 비용을 같이 평가 |
| **Ternary Bonsai 8B** | [공식 Ternary 발표](https://prismml.com/news/prismml-introduces-ternary-bonsai-model-family)와 [공식 데모 계보표](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/README.md): 이전 세대 8B, 약1.75GB 언어 가중치 표기 | 비용이 낮은 문제 생성·사전 스크리닝 후보. 27B의 동일 품질·같은 한국어 성능을 추정하지 않는다. 이전 세대 Q2_0/PQ2_0 파일·backend 지원을 정확히 매칭 |
| **1-bit Bonsai 8B** | [공식 1-bit 발표](https://prismml.com/news/bonsai-8b)와 [공식 데모](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/README.md): 1-bit 8B, 약1.15GB 언어 파일·Q1_0 경로 | 최소 비용 대조 교사. 낮은 bit폭만으로 잘못된 한국어 답/형식·풀이 오류가 줄었다고 추정하지 않는다 |

Bonsai 2는 **신규 27B 계보**, 뒤 두 8B는 **서로 다른 이전 계보**다. 동일 계열의 크기 스윕이나 같은 checkpoint의 bit폭 ablation으로 취급하면 무효다. 모델카드의 Apache-2.0 표시는 출발점일 뿐 선택한 GGUF revision·NOTICE·원 모델 계보/출력 재이용 조건을 사용자가 확인해야 한다. 현재 어떤 후보도 내려받거나 실행·채택하지 않았다.

**런타임 충돌 주의:** Hugging Face가 자동 표시하는 `llama ...:F16` 및 stock llama.cpp 예시는 53GB급 FP16과 fork 없는 경로라 위 16GB 저비트 teacher pilot의 실행 명령이 아니다. [PrismML 데모](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/README.md)의 tested fork/정확 GGUF pack을 기준으로 artifact SHA·chat template·reasoning effort·출력 상한을 pin해야 한다. [공식 known issues](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf/blob/main/KNOWN_ISSUES.md)는 `xhigh` 장문/미완료, `medium` 비용·정확도 교환, `high` API 오류와 일부 샘플링 메타데이터 누락을 알린다. 이는 사용자 GPU/다운로드 없이 정적 조사만 한 사실이며 로컬 teacher 기능 PASS가 아니다.

### 10.3 권장 검증 순서와 승격 금지선

| 안 | 내용 | 장점 | 단점·비용 | 이번 선택 |
|---|---|---|---|---|
| A | 공개 SFT 원천 사람 적격성 뒤 검증된 교사 텍스트의 정적 SFT pilot | 기존 chat mask/trainer 재사용, 독립변수 적음 | 한국어·정답 검증 비용과 원천 권리 확인 필요 | **1순위**. A0부터; 적응 A1/A2를 같은 교사·검증/토큰 예산에서 비교 |
| B | 적응 teacher 문제 생성부터 루프 전체 착수 | 어려운 학생 오류에 맞출 수 있음 | verifier 오판·누설·teacher 호출/반복 비용·인과 귀속 위험 높음 | A0와 생성/선택 정책을 분리한 뒤에만 |
| C | latent B+C를 첫 런부터 합친다 | 성공 시 압축/유보 연구 가치 | 현재 학생 문답 기준선 미확립·연속 호출/KV 구현/학습 부담 최대 | **현재 보류**. A-only의 transfer가 확인된 후 B1/B2·C를 분리 |

G0는 모든 teacher 후보에 같은 **사전 고정** 한국어·영어, 논리/산술/문맥/형식 문제 가족을 주되 개발용 문제와 sealed 최종 시험을 분리한다. 모델·pack·template·effort별 정답/불확실/완료율, 짧은 검증풀이 오류, 교사 자기판정 대비 독립 검증 불일치, accepted sample당 출력 토큰·wall·VRAM을 기록한다. 가족별 중복·원문 오염·사람 표본 심사를 실시하고 **비교 통과 기준과 예산은 데이터를 보기 전에** 등록한다. 가장 큰 27B가 모든 항목을 이긴다고 가정하지 않는다. P100/P090B의 정성 실패와 P097 dataset bundle 교락을 teacher 효과로 오인하지 않는다.

첫 기능 산출물은 model 다운로드나 20M 학습이 아니라 **불확실/오답 배제·loss-mask provenance·서로 다른 tokenizer의 문자열 target·split 격리** 계약이다. 실제 teacher+student 품질/비용 판단은 사용자 E2E 뒤의 별도 실험계획·권한이다. B/C를 채택하지 않아도 A-only가 최종안일 수 있다. 이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 한다.
