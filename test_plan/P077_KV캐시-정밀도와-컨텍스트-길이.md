## 0. ★왜 — **KV 가 예산의 절반 이상인데 dtype 을 한 번도 안 내려 봤다**

결과 016 §24 가 KV 를 상주 회계에 넣었다. 그 결과:

| 모델 | 안 B 가중치 | KV@1024 fp32 | 합계 | 36 MiB |

| `mC_cla2_ag4` | 16.8 | 15.0 | ✅**31.8** | ✅ |
| `mC_initonly_nc` | 19.8 | 15.0 | ✅34.8 | ✅ |

| `mC_cla1_ag4_r20` | 16.9 | **54.0** | 🚫**70.9** | 🚫 |

🚫★**KV 를 fp32 로 드는 근거가 없다.** 학습 산술이 이미 bf16 autocast 인데
**캐시만 fp32 로 승격해 저장**하고 있다 — **없는 정밀도를 담는 그릇**일 수 있다.

★**그리고 컨텍스트가 1급 설계 변수가 됐다** — KV 는 seq 에 **정확히 선형**임이 확인됐다(016 §24.2).

## 3. 단계0 — ★**`--repeat-kv-reuse` 프로브** (⚙10분, 학습 0, **지금 된다**)

### 3.1 무엇

이미 학습된 `mC_cla1_ag4_r20nc` 를 **두 가지로 평가**한다:

```
paired_eval --models mC_cla1_ag4_r20nc --match-train-repeat                    # 기준
paired_eval --models mC_cla1_ag4_r20nc --match-train-repeat --repeat-kv-reuse  # 재사용
```

`mem_runtime` 으로 **엔트리 수가 실제로 주는지** 함께 본다(함정 37 — 필드가 있다 ≠ 경로가 돈다).

### 3.2 ⚙예측

| # | 예측 | 근거 |
|---|---|---|
| **K1** | 엔트리 **36 → 20**, KV **54.0 → 30.0 MiB** | `kv_report` 가 `(own, pas>0) → (own, 0)` 으로 접는다 |
| ★**K2** | 품질 대가 **+0.005 ~ +0.02** | ⚠️**근거가 약하다.** `--reuse-attn-on-dup` 은 +0.0079+이득손실 이었는데 **그건 Q 까지 낡은 것** |
| **K3** | 속도는 **약간 빨라진다**(K/V 사영 절반) | 결과 014 §13.1 이 방문수 법칙을 확인했으나 **KV 계산은 방문의 일부** |

### 3.3 ★판정 규칙 — **미리 정한다**

★**쓸 자 = 타잉 2σ 0.0010**(결과 039 §8). ⚠️**재귀 계열의 자는 아직 없다** —
`run_P052_stage3_recursion_seed.bat` 이 그것을 잰다. **그 전까지는 타잉 자를 빌리고 그렇게 적는다.**

| 관측 | 판정 |
|---|---|
| 대가 **< 0.0010** | ✅★**즉시 채택.** 재귀 라인이 −24.0 MiB 를 공짜로 얻는다 |
| 0.0010 ~ **0.0107** | ⚠️**부분 채택** — 재귀 이득(−0.0107)보다 작으면 **여전히 순이득**이다 |
| ★**> 0.0107** | 🚫**기각.** 재귀 이득을 다 잃는다 — `--reuse-attn-on-dup` 과 같은 운명 |
| 엔트리가 **안 줄면** | 🚫★**결과가 아니라 결함**이다(함정 37). 코드를 먼저 본다 |

## 4. 단계1 — bf16 KV 구현 (⚙1h, 큐가 빈 뒤)

### 4.1 설계

```
--kv-dtype {fp32,bf16,int8}      기본 fp32 = ★비트 동일(R28)
```

`kv_bank[key] = (k.to(dt), v.to(dt))` 저장, 조회 시 `.to(q.dtype)`.
🚫**RoPE 는 그대로 fp32 로 적용**하고 **회전 뒤**를 저장한다(KIVI 와 같은 위치).

### 4.2 ★게이트 — **로짓 동등성이 0 이 아니다**

`diag_kvcache.py` 는 지금 **teacher-forced 로짓 동등성 0** 을 요구한다.
🚫**bf16 KV 는 0 이 안 나온다.** → ★**허용 오차를 미리 정한다**:

| dtype | ⚙기대 `max\|dlogit\|` | 근거 |
|---|---|---|
| fp32 | **0.000e+00** | 비트 동일 |
| bf16 | ⚙**1e-2 ~ 1e-1** | bf16 유효자릿수 ~3 |
| int8 | ⚙**1e-1 ~ 1e0** | — |

⚠️★**이 기대값은 근거가 약하다**(함정 34 — 기준값을 먼저 의심한다).
★**게이트가 실패하면 모델보다 기준값을 먼저 본다.**

## 5. 단계2 — bf16 KV 품질 (⚙0.5h, 학습 0)

`paired_eval --kv-dtype bf16` 로 **네 모델 전부**. ★**학습이 필요 없다** — 추론 경로만 바뀐다.

⚙**예측**: 품질 대가 **< 0.001**(자 미만). 근거 — 학습 산술이 이미 bf16 이다.
🚫**빗나가면 그것이 더 중요한 결과다** — *"학습은 bf16 인데 추론 캐시는 fp32 여야 한다"* 는
**우리가 모르던 비대칭**을 뜻한다.

## 6. 단계3 — 컨텍스트 2048 (3.2h 학습)

| 팔 | 조건 | 목적 |
|---|---|---|
| **C1** | `mC_cla2_ag4` 를 `--seq 2048 --micro-bs 4`(M=8192 유지) | ⚙**KV 31.8 MiB(bf16)** 가 실제로 되는가 |

⚠️★**M 을 8192 로 유지해야 결과 007 의 무릎에 머문다.** `micro_bs` 를 8→4 로 내린다.
🚫**seq 가 다르면 val 을 직접 비교 못 한다**(크롭 길이가 다르다) → **`common_bpb.py` 로만**.

## 7. 단계4 — int8 KV, KIVI 축 분리 (⚙2h)

📄[arXiv:2402.02750](https://arxiv.org/abs/2402.02750). ★**K 는 채널별, V 는 토큰별.**
🚫**대칭 양자화로 먼저 해 보고 "int8 은 안 된다" 고 결론내지 않는다** — 그것이 문헌이 경고하는 실패다.

## 8. ⚠️한계

- 🚫**단계1~4 는 전부 구현 선결**이다. **배치를 만들지 않는다**(R22).
- ⚠️**단계0 의 자를 빌려 쓴다**(타잉 0.0010). 재귀 자가 나오면 **재판정**한다.
- ⚠️**KV 회계는 "동시에 살아 있는 쌍" 이고 할당자 실측이 아니다**.
- 🚫**배치 1 기준**이다. 서버 배포는 다른 계산이다.
- ⚠️**CPU 경로는 fp32 로 돈다** — bf16 KV 의 품질 대가가 **GPU 와 CPU 에서 다를 수 있다.**
