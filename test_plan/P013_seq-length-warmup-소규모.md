# 실험계획 P013 (S2) — seq-length warmup 초기 스텝 절감 (소규모)

> 2026-10-27 현재 상태: 아래 옛 소규모 품질 판정 제안은 현재 실행 기준이 아니다. 사용자는 본학습 전 작은 학습으로 지능/벤치 성과를 판단하지 않도록 정정했고, 데이터 정제가 끝나기 전 추가300M 학습을 금지했다. 현재 후속은 독립 회계·수치·비용 선결만이다. 종전의16배는 고정시퀀스수에서attention의L제곱항 비율이며, 같은token/update나전체시간의16배 가속이 아니다.

## 목적
어텐션 O(L²) — 초반 seq를 짧게(256→1024) 성장시키면 **초기 스텝이 얼마나 싸지는지** 소규모로 측정.
절대 학습시간 절감 여부와 최종 품질 영향을 본다.

## 방법
- seq 스케줄: 전체의 0~20% 구간 256, 20~40% 512, 이후 1024(예). Loader/train에 seq 스케줄 추가(구현 필요).

## 조건 (소규모)
- m100 짧은 런(예: --steps 400) 또는 tiny 에서 **seq-warmup on/off**의 (a) 초기 구간 ms/step, (b) 전체 wall time, (c) 최종 val 비교.

## 판정
- 초기 스텝 시간 절감%(이론상 (1024/256)²=16배 싼 구간이나 다른 오버헤드로 실제는 작을 수 있음).
- 커리큘럼이라 **결과가 바뀌므로** 최종 val 영향도 확인. 이득이 초기 구간에 한정되는지.

## 비고
- 소규모 검증 후 이득이 유의하면 본 실행 옵션으로 승격. 아니면 폐기.

### Stage7Wf — 같은 단계의 `latest`와 `best`를 한 번 직렬화 ✅ 완료(결과106 §14.7, 채택 보류)

먼저 CPU에서 한 번만 직렬화되는지, 두 파일의 지문·형식·독립성, 복사 실패와 마지막 게시 실패를 검증한다. 저장 함수가 두 파일을 모두 준비하고 `best`, `latest` 순으로 교체한다. `latest` 교체 실패의 허용 상태는 이전 `latest`와 읽을 수 있는 새 `best`다. 그 뒤 결과106 §14.6의 실제 16층·약 755 MB 최종 상태 하나를 고정한다. `p013_g4_packed_checkpoint_pair_v1_20261119`에서 두 번 직렬화(A)와 한 번 직렬화 후 복사(B)를 A–B–B–A 순서로 대조한다. 학습·평가·신규 토큰은 0이다. GPU는 원 체크포인트의 CPU/CUDA 위치대로 복원하고 같은 상태로 두 방식을 실행한다.

파일별 바이트, 두 경로의 독립 파일 식별자, 입력 보존, 직렬화 횟수 및 같은 단계에서 각 장치 두 쌍의 벽시간을 기록한다. 합격은 형식·독립성·실패 복구가 일치하고, 측정 장치에서 복사 방식이 두 인접 비교 모두 최소 5% 빠른 경우다. 한 장치의 결과로 다른 장치에 적용을 확대하지 않는다. 예상 CPU 30~80초, WSL GPU 40~90초(상한 240초), 해당 프로세스 점유 3 GiB 이하 예상이다. 결과는 로컬 파일시스템의 체크포인트 두 파일에 한한다. 실제 학습의 전체 향상과 장문 품질은 별도로 본다.

### Stage7Wg — 독립 작성 단일 문서의 1,024토큰 검증과 생성 ✅ 완료(결과106 §14.8)

원장 57의 최종 문맥 검증을 보강한다. Stage7W의 최장 학습 원문은 38토큰이고 기존 평가는 1,024칸에 여러 문서를 담았다. 동일 G4 28방문, 32K 토크나이저, 초기화, 8회 갱신, 31,770 유효 타깃을 보존하고 고정 1,024와 단계형 너비의 최종 가중치 지문을 재현한다. 이전 두 팔은 가중치를 저장하지 않아 다시 R2 경로에서 복원한다. 기존 평가는 재실행하지 않는다. 원본 소스 지문과 달라진 제품 파일을 명시하고 최종 지문이 어긋난 팔에서는 새 평가를 시작하지 않는다.

새 태그 `p013_g4_single_document_held_v1_20261119`에 출처를 별도로 남긴 영어 및 한국어 작성 문서 각 한 편을 쓴다. 원 768개 학습 문서와 같은 16토큰 연속열이 없는지 CPU에서 확인한다. 한 문서의 연속 1,024입력에서 마지막 64개 타깃의 NLL·top-1과 정확히 1,024개를 본 다음 토큰의 예측을 측정한다. 동일 타깃을 마지막 128입력으로도 평가한다. 앞쪽에 소개한 이름을 992토큰 프롬프트의 마지막에서 묻고 탐욕 생성 32개를 수집한다. 원래 부모도 같은 입력에서 한 번 측정한다. 생성 텍스트를 실제로 확인하고 사전 지정 이름이 앞에 나오며 뒤가 문장인지 기록한다. 생성 종료는 정해진 길이 또는 등록 EOS다.

사용자177의 같은 WSL 환경을 쓰며 실제 GPU 목표는 6 GiB 내외, 예상 45~120초와 상한 240초다. 새 학습 자료 입장·체크포인트 쓰기는 없다. 이 진단의 결과로 두 문서의 긴 입력과 답변은 판정할 수 있다. 모집단 품질·시간 대비 수렴과 기본 채택은 정식 독립 장문과 교차 순서 대조까지 보류한다.
