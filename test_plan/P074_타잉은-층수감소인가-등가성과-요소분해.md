# 1. ★★단계0 — **사용자 질문에 대한 답 (코드 근거, 학습 0)**

## 1.1 먼저 산술을 맞춘다

`m100R1c` = **prelude 2 + middle 16 + coda 2 = 20층**, `mlp_group 8`.

| 조건 | 유니크 중간 MLP | 유니크 중간 어텐션 | **실행되는 층 수** |
|---|---:|---:|---:|
| 기준(`ag1`, `g8`) | **2** | **16** | **20** |
| `ag2` | 2 | **8** | **20** |
| `ag4` | 2 | **4** | **20** |
| `ag16` | 2 | **1** | **20** |

⚠️★**사용자 계산의 산술 정정 1건**: *"1개의 shared-MLP당 shared-attention 2개 × 4개 MLP = 8개"* 는
**MLP 가 4개**라는 전제인데, `m100R1c` 는 `mlp_group 8` 이라 **중간 MLP 가 2개**다
(4개는 `mlp_group 4` 인 `m100` 기준). 어텐션 개수 8개는 `ag2` 에서 맞다(16/2).

## 1.2 ★★★**핵심 답: 층수는 줄지 않는다. 그리고 그것이 이 아키텍처의 전부다**

🚫**타잉은 "층을 없애는 것" 이 아니라 "층이 쓰는 가중치를 공유하는 것"** 이다.
`transformer.py` 를 그대로 읽으면:

```python
layers.append(Layer(cfg, owns, mlp, mlp_lora=..., mlp_film=..., attn=shared_attn))
```

★**`Layer` 는 매번 새로 만들어진다.** 공유되는 것은 **`mlp` 참조와 `attn` 참조뿐**이다.

### ★층이 타잉돼도 **자기 것으로 갖는 파라미터** (`modules.py` `Layer.__init__`)

| 파라미터 | 크기 | 공유되나 |
|---|---:|---|
| `ln1`, `ln2` (RMSNorm) | 2 × `dim` = 1,536 | 🚫**층 소유** |
| `a_scale`, `a_shift` | 2 × `dim` = 1,536 | 🚫**층 소유** |
| `m_scale`, `m_shift` | 2 × `dim` = 1,536 | 🚫**층 소유** |
| `gates` | 2 | 🚫**층 소유** |
| (`--mlp-film`) `film_scale·shift` | 2 × `ffn_dim` | 🚫층 소유 |
| (`--lora-rank`) LoRA 3종 | rank 의존 | 🚫층 소유 |
| **MLP**(gate/up/down) | 4,718,592 | ✅**공유** |
| **어텐션**(q/k/v/o) | 1,474,560 | ✅`ag>1` 이면 공유 |

★**완전 타잉(ag16 + g16)에서도 층마다 `6 × 768 + 2 = 4,610` 개가 남는다.**
→ 🚫**두 층이 같은 함수가 아니다.**

### ★그리고 **입력이 다르다** — 이것이 더 근본적이다

잔차 스트림은 층을 지나며 누적된다. 결과 057(P072) U3 실측:

```
  ||x|| (잔차 노름)         L0 0.153 -> L5 1.944 -> L10 2.747 -> L19 8.416
```

★**같은 가중치라도 55배 다른 크기의 입력을 받는다.** 그리고 U4 실측이
*"같은 입력·다른 일 158쌍 vs 같은 입력·같은 일 3쌍"* 이라고 말한다 —
**공유 가중치를 쓰는 층들조차 서로 다른 일을 하고 있다.**

## 1.3 ★그러면 사용자의 직관은 어디가 맞나 — **두 군데가 정확히 맞다**

| # | 맞는 부분 |
|---|---|
| ★**1** | **"메모리 관점에서는" 층수가 줄어든 것과 같다.** 상주는 **유니크 파라미터 × 4B × 2벌 + 기타** 이고 **실행 층 수가 식에 없다.** `ag4`+`g16` 36층의 상주(379.7)가 `ag1`+`g8` 20층(451.5)보다 **작다** — 결과 044 가 *"36층인데 20층보다 작다"* 라고 쓴 것이 정확히 그 뜻이다 |
| ★★**2** | **극단에서는 재귀와 같아진다.** `ag=g=n_middle` 이고 층별 norm·gate 가 없다면, 중간 블록은 **같은 함수를 n 번 통과**하는 것 = `--train-repeat` 이다. ★**우리 구조는 층별 norm·gate 때문에 거기 도달하지 않지만, 방향은 같다** — 타잉을 밀면 **재귀에 수렴**한다 |

★★**그래서 사용자의 다음 질문이 정확히 옳다**: *"동일한 층수의 dense 와 비교하는 실험이 필요한가"*
→ ✅**필요하다. 그리고 우리는 한 번도 한 적이 없다.**

## 1.4 🚫★★**우리가 한 번도 물어보지 않은 반사실**

우리 논지는 *"타잉으로 상주를 줄인다"* 인데, **비교 대상이 언제나 같은 깊이의 자기 자신**이었다.

> 🚫**같은 상주를 그냥 "얕은 dense" 로 쓰면 어떤가?**

| 모델 | 유니크 삼진 | fp32 상주 |
|---|---:|---:|
| `p6d`(dense **20층**) | 123.86M | ⚙**977.9** |
| `mC_initonly`(tied 20층, g8) | 54.85M | **451.5** |
| ⚙**dense 9층**(추정) | ⚙55.7M | ⚙**458.0** |

★**dense 9층이 tied 20층과 상주가 거의 같다.** 🚫**그 둘 중 어느 쪽이 나은지 우리는 모른다.**
→ **이것이 P074 단계1 이다.**

# 2. ★★단계1 — **요소 분해: 깊이·타잉·확장·재귀를 같은 그림 위에**

## 2.1 무엇을 분해하나 (사용자 지시)

| # | 요소 | 대표 모델 | 상태 |
|---|---|---|---|
| **A** | ★**층수를 줄인 dense** | `d6`·`d8`·`d10`·`d12` | 🆕**이 단계** |
| **B** | **어텐션 타잉 + MLP 타잉** | `mC_initonly`(g8·ag1) · `mC_d36_ag4_nokd` | ✅있다 |
| **C** | **타잉 후 레이어 추가** | `mC_d36_ag4_nokd`(36층) | ✅있다 |
| **D** | **타잉 후 재귀 학습+추론** | `mC_r20_nokd` · `mC_d36_ag4_r20_nokd` | ✅있다 |

★**A 만 없다.** A 를 넣으면 **네 요소가 (상주, 품질) 평면 위의 한 그림**이 된다.

## 2.2 팔 설계 — **깊이 곡선 4점**

| 팔 | preset | 층 | ⚙유니크삼진 | ⚙fp32 상주 |
|---|---|---:|---:|---:|
| `d6_dense` | `m100s2` | **6**(2+2+2) | ⚙37.2M | ⚙**317** |
| `d8_dense` | `m100s4` | **8**(2+4+2) | ⚙49.5M | ⚙**411** |
| `d10_dense` | `m100s6` | **10**(2+6+2) | ⚙61.9M | ⚙**505** |
| `d12_dense` | `m100s8` | **12**(2+8+2) | ⚙74.3M | ⚙**600** |

★**이 네 점이 "dense 깊이-상주-품질" 곡선을 만든다.** 기존 tied 점들을 같은 그림에 얹으면
**같은 상주에서 누가 이기는가**를 **보간으로** 읽을 수 있다 — 정확히 맞추려고 층수를 억지로
고르지 않는다(정수 제약).

## 2.3 ⚠️★조건 정합 — **부모를 어떻게 맞추나**

| | |
|---|---|
| 문제 | tied 모델은 전부 **`--init-from`(20층 dense 부모)** 이다. 얕은 dense 는 **부모가 자기보다 깊다** |
| ✅**해법** | `_depth_map` 이 **양방향을 지원**한다. ⚠️**얕은 쪽은 `--depth-init role` 을 명시해야 한다**(`init_utils.py` §116) |
| 🚫**위험** | ★**`role` 은 한 번도 실측된 적이 없다.** 결과 041 §13 은 `prop`·`gate_scale`·`identity` 만 쟀다 |
| ★**게이트** | 배치 [1] 이 **step0 CE 대역 검사**(5.0 ~ 9.3972)를 먼저 인쇄한다. 대역 밖이면 **이식 실패**이고 그 팔의 Δ 는 깊이가 아니라 이식을 잰 것이다 |

## 2.4 ★예측 (결과 전에 못 박는다)

| # | 예측 |
|---|---|
| ★**N1** | **dense 곡선은 상주에 대해 볼록**하다 — 얕아질수록 손해가 가속된다 |
| ★★**N2** | **같은 상주에서 tied 20층이 dense 9층을 이긴다.** 이기지 못하면 🚫**타잉 프로그램 전체의 근거가 약해진다** |
| **N3** | 이득은 **0.02 ~ 0.10 nats** 사이. 그보다 작으면 *"타잉은 얕음과 실무상 같다"* 가 된다 |
| ★**N4** | ⚠️**`mC_d36_ag4_nokd`(379.7)는 `d8_dense`(⚙411)보다 상주가 작으면서 품질도 좋을 것이다** — 그것이 REVIEW3 안 B 의 전제다 |
| **N5** | ms/step 은 **dense 가 훨씬 빠르다**(층이 적다). ★**타잉의 대가는 메모리가 아니라 시간**이라는 것이 이 표에서 처음 보인다 |

## 2.5 ⚠️한계 — **이 단계가 답하지 못하는 것**

| # | 무엇 |
|---|---|
| ★**1** | **`--depth-init role` 이 미측정**이다. 이식이 나쁘면 dense 팔이 부당하게 진다 → 게이트(2.3)로 본다 |
| **2** | dense 는 `cla_group=1` 이고 tied 는 `2` 다(`dense_baseline` 이 그렇게 만든다). 🚫**교락**이고, 결과 058 이 그 크기를 **−0.0268(20층)/−0.0136(36층)** 으로 쟀다 → **보정해서 읽는다** |

| ★**4** | **네 요소가 서로 곱해진다.** 이 단계는 **A 를 좌표평면에 올릴 뿐**이고, A×B 상호작용은 안 잰다 |

# 3. ★단계2 (설계만) — **요소 상호작용**

단계1 이 A 를 좌표에 올리면, 다음 질문은 **A×C**(얕은 dense 에 층을 더하면?)와
**A×D**(얕은 dense 에 재귀를 걸면?)다. ⚠️**재귀는 dense 에도 걸린다** — `train_repeat` 은
`n_middle` 만 보고 타잉 여부를 안 본다.

★**dense 6층 + 재귀 R3** 은 상주 317 MiB 로 **18층 유효 깊이**를 만든다.
🚫**그것이 타잉보다 나으면 우리 아키텍처의 존재 이유가 바뀐다.**
⏸**단계1 결과를 보고 착수한다** — 지금 배치를 만들지 않는다(D1: 선결과 시간을 숫자로).
