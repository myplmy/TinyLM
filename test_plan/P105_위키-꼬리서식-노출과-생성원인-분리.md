# P105 — 한국어 Wikipedia 꼬리 서식·URL 노출과 생성 원인 분리

> 제안 계기: 사용자 승인 [위키 서식·URL 제안서 B안](../proposal/20260923_위키-서식-URL-반복생성-원인분리와-정제-제안서-approved-on-going.md). [P029 결과013](../test_result/013_20260730190000_P029-정성프로브-1차.md)의 작은 정성 표본과 [P090B 결과096 §9](../test_result/096_20260925_P090B-공개원천-구조후보-SFT-보류.md)의 실제 ko-en Wikipedia token34.35%가 계기다. 현재 모델의 `http://` 반복률·source 꼬리 token율은 아직 `NOT_RUN`.

## 1. 왜 — 원인을 확정하지 않은 문자열 억제는 품질을 훼손한다

원 P029는 wiki 표제와 반복을 정성적으로 관찰했으나 역사적 EOS 미정지 도구 조건이다. 현재 생성기는 기본 EOS 정지를 지원하고 P100/P090B에는 다른 tokenizer·데이터·모델이 섞인다. 원본을 먼저 계측하지 않고 `같이 보기`·URL을 전역 삭제하면 필요한 인용·링크까지 지운다. 현 `ko-en`은 한국어 Wikipedia+영어 FineWeb-Edu이지 영어 WikiText-103 한국어 corpus가 아니다.

## 2. 질문

| # | 질문 | 왜 중요한가 |
|---|---|---|
| Q1 | 일반/위키/링크요청/제공문단 프롬프트에서 원치 않는 표제·URL 반복이 현재 checkpoint에도 재현되는가 | 생성·디코딩 원인을 먼저 분리 |
| Q2 | 고정 원천의 표제·URL이 문서 본문보다 말미 독립 절에 편중되는가 | 꼬리만 정제할 실익과 오탐 규모 |
| Q3 | 같은 부모·풀·토크나이저·draw에서 꼬리 정제가 반복을 줄이면서 지식·형식을 보존하는가 | 실제 데이터 변경 승인 근거 |

## 3. 예측 — 양성·음성 모두 정보

위키 말미 표제는 source에 존재할 수 있으나 현재 생성에서 원하지 않은 맥락으로 반복될지는 미측정이다. 낮은 온도 반복과 SFT 부재만으로도 같은 증상이 생길 수 있어 source 꼬리 빈도가 낮다면 정제 축은 중단하고 디코딩/후속학습을 우선한다. source 양성이라도 정제 후 지식 손실이 가능하다.

## 4. 단계 설계 — 싼 것부터

### Stage0W — source/generation 계측 계약 합성 PASS, 실제 W0/W1 NOT_RUN

독립 [진단기](../scripts/diag_p105_wiki_format.py)는 standalone 제목의 말미 후보와 본문 언급을 구분하는 fixture, URL·요청 분모, 빈 입력/잘못된 JSONL 거부, 원문 비출력을 검사한다. [사용자 SH](../run_P105_Stage0W_wiki_format_contract.sh)는 이 self-test만 별도 로그에 남긴다. 모델·HF·GPU·기존 cache를 열지 않는다. 이 PASS는 현 모델 현상 재현이 아니다.

### Stage1W — 사용자 지정 현재 실물 7모델 W0 패널, chat32 SFT 팔은 별도 후속

사용자 지정 8개 개념 팔 중 현재 문서화된 실물 7개를 먼저 고정한다: (1) 6차 리뷰 A~C의 **같은 300M RMS4 full-val 범위** 품질-edge d18, (2) P090B chat32 새 사전학습 부모, (3) P097 seed1337(가용 시드 중 숫자 최소를 사전 선택) control/FineWeb2 쌍, (4) P100의 d14 300M·d14 600M·d16 1.2B 세 부모다. 여덟째 chat32 SFT 학습 완료 모델은 아직 없으므로 `NOT_RUN`으로 두고 뒤에 별도 suffix로 연다. 체크포인트 SHA 중복은 제거하며 서로 다른 풀/토크나이저·토큰 규모의 품질을 같은 눈금으로 순위화하지 않는다. [평가기](../scripts/eval_p105_wiki_panel.py)는 4 strata×5고정 prompt×2 decoding=40행/모델, 7모델 280행을 write-once JSONL로 기록한다. user-run [Stage1W SH](../run_P105_Stage1W_wiki_panel_7model.sh)는 먼저 metadata-only check-only로 계보를 확인한다. URL 요청층은 URL 생성 자체를 결함으로 세지 않고 실제 EOS 종료 이유는 `NOT_MEASURED`로 둔다. 모델/GPU 실행은 사용자 소유다.

### Stage1bW — 같은 계보 원천 W1 감사, 별도 파일/스냅샷

사용자가 접근 권한을 확인한 Wikipedia와 FineWeb-Edu **원천 JSONL 사본**을 `--source-jsonl`로 읽기 전용 감사한다. 제목·URL의 문서율/byte율과 선택한 tokenizer가 있을 때 token율, 꼬리 위치·검토용 해시 ID를 기록한다. `HF/` 다운로드·원본 cache 변경은 하지 않는다. 사람 20~50개가 진단 후보의 오탐과 유용한 링크를 확인하기 전에는 정제 코드를 기본 경로에 넣지 않는다.

### Stage2W — 조건부 꼬리 정제 fixture와 별도 cache

Stage1W에서 원치 않는 출력이 실제 재현되고 Stage1bW에서 말미 source 노출이 충분하며 사람 오탐 검토가 통과한 경우에만 독립 정제 파서/manifest를 설계한다. 기존 cache는 불변. 정제율·오탐과 정보 손실을 먼저 비교하고 matched 300M 학습은 별도 preflight/사용자 승인 뒤에만 연다.

## 5. 판정 기준

| 결과 | 판정 |
|---|---|
| Stage0W fixture 실패 또는 원문 누출 | 계측 도구 FAIL; 실제 모델/원천 결론 금지 |
| Stage1W 원치 않는 맥락의 표제/URL 재현0 | 이번 표본에서는 W2 정제 보류, 디코딩·SFT 등 타 가설 우선 |
| Stage1bW 말미 후보의 오탐·정보 손실이 사람검토에서 높음 | 전역 삭제 금지, 파서 수정 또는 축 중단 |
| P097/신규 raw–정제 쌍의 pool/tokenizer/draw/parent 중 하나 다름 | `PARTIAL_CONFOUNDED`/`DESCRIPTIVE_ONLY`, 정제 단독 효과 주장 금지 |
| matched 대조에서 원치 않는 출력 감소·지식/영어/한국어 형식 비퇴행 | 현 모델·계열에 한정한 채택 후보, 기본 데이터셋 변경은 별도 승인 |

## 6. 비용

| 단계 | 비용 | GPU |
|---|---:|---|
| Stage0W 계약 | ⚙0.1h | 없음 |
| Stage1W 현재 실물 7모델×40생성 | ⚙1~3h + 사람 판독(가속기/출력길이 환경 의존) | 사용자 단독 GPU 또는 CPU |

## 7. 실행 파일

Stage0W 계약 SH와 현재 7실물용 Stage1W 평가 SH를 분리한다. Stage1W는 checkpoint/JSON/tokenizer metadata-only gate를 먼저 통과해야 하며 사용자 모델/GPU 전용이다. chat32 SFT 팔은 실물이 생긴 뒤 별도 suffix로 연다. Stage1bW은 정확한 공개 JSONL 사본·tokenizer·snapshot 확인 뒤, Stage2W는 생성/source 양성+사람검토 뒤 작성한다. 파일 없는 단계를 현재 큐 실물로 적지 않는다.

## 8. 한계

문서 말미 후보 탐지는 휴리스틱이며 Wikipedia 원문 전수 의미판정이 아니다. 합성 fixture PASS는 실제 source의 제목·URL token율이 아니다. 생성표본의 URL 요청층과 일반층을 섞지 않으며, 몇십 출력은 전체 결함률 추정이 아니다. 보호 `datasets/TinyDataset/**`, 기존 checkpoint/원본 cache, Codex 모델 실행은 범위 밖이다.
