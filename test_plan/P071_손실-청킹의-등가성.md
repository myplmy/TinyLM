## 0. ★왜 이 계획이 생겼나 — **사용자가 옳은 것을 물었다**

> **사용자(2026-08-22)**: *"`_ce_chunked` 와 `_kd_kl` 은 **모든 학습이 지나는 길**이라고 했는데
> **아무런 실험 없이 바로 도입해도 문제 없는지** 검토바람."*

★**검토했더니 문제가 있었다. 그리고 내가 예상한 곳이 아니었다.**

| 내가 걱정한 것 | 실제 위험 |
|---|---|
| `--ce-chunk` 를 켰을 때 합산 순서가 바뀐다 | ⚠️맞지만 **명시적으로 켤 때만**이고 문서화했다 |
| — | 🚫★★**`_kd_kl` 의 `.float()` 가 학생 측 정밀도까지 바꿨다** — **기본 경로에서** |

### 0.1 🚫★★내가 만든 진짜 위험 — **1차 수정이 과거를 깼다**

1차 수정에서 `_kd_kl` 청크 안에 **무조건** `.float()` 를 넣었다:

```python
s = slog[i:i + chunk].float()      # ← 학생. 종전에는 bf16 이었다
t = tlog[i:i + chunk].float()      # ← 교사. 이건 의도한 것
```

★**종전 경로는 `torch.autocast(bf16)` 아래라 학생·교사 로짓이 둘 다 bf16** 이었다.
🚫**무조건 승격은 `--kd-chunk` 를 쓴 기존 런(P053 계열)의 수치를 바꾼다.**
★★**그리고 결과 042 가 실효 α = 0.288 을 그 정밀도에서 쟀다** — 흔들면 안 되는 수다.

✅**2차 정정**: `fp32` 를 **opt-in** 으로 만들고 **외부 HF 교사 경로에서만** 켠다.
그 경로는 **아직 발표된 결과가 없으므로** 바꿔도 과거를 깨지 않는다.

### 0.2 🚫★두 번째로 찾은 것 — **`mean` 의 분모**

`F.cross_entropy(reduction="mean")` 의 분모는 **N 이 아니라 "무시되지 않은 타깃 수"** 다.
`ignore_index`(기본 −100)가 하나라도 있으면 `sum/N ≠ mean` 이고, 그 차이는
**손실이 조금 작아지는 형태로 조용히** 나타난다.

✅우리 로더는 패딩을 안 쓰므로 지금은 전부 유효하다. **그러나 가정을 단언으로 박았다** —
나중에 패딩이 들어오면 **여기서 죽는 것이 조용히 틀리는 것보다 낫다.**

## 4. ★★판정 기준 — **사전 고정**

| # | 게이트 | 기준 | 근거 |
|---|---|---|---|
| ★**E1** | `ce_c0` 의 `final.val_loss` == `sm_base` | ★**완전 일치**(부동소수 비교 아님, **같은 값**) | `chunk<=0` 이면 **같은 함수 호출**이다. 다르면 코드가 갈라진 것 |
| ★**E2** | `ce_c64` vs `ce_c0` 손실 상대차 | ★**< 1e-5** | bf16 누적의 합산 순서 차이. **1e-3 을 넘으면 구현 결함** |
| **E3** | `ce_c16` vs `ce_c64` | < 1e-5 | 청크를 잘게 해도 발산하지 않아야 |
| ★**E4** | `kd_c64` vs `kd_c0` | ★**< 1e-5** | **2차 정정이 되돌린 것을 확인**한다 |
| **E5** | 어느 팔도 NaN/Inf 없음 | grad_max 유한 | |

> ★**E1 을 "완전 일치" 로 잡는 이유**: `chunk<=0` 분기는 **종전과 문자 그대로 같은 호출**이다.
> **근사적으로 같으면 안 되고 같아야 한다.** 다르면 내가 분기를 잘못 짰다는 뜻이다.
> ⚠️**단 스모크는 시드·데이터가 같아야 이 비교가 성립**한다 — 배치가 그것을 보장한다.
