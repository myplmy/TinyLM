## 1. 왜 — 같은 답 복제와 규칙/조건 학습의 차이

산수·Boolean·표·known JSON은 조건과 답을 함께 계산할 수 있다. C1의 이전 답은 당시 맞고 C3는 원답의 형식만 바꾼다. 자유 QA 숫자/이름을 바꾸거나 C2 오답을 현재 mask로 학습하지 않는다. C2+C3는 별도 문맥 판독/turnwise mask가 선결이다.

## 3. ★예측 — 정직하게

정답 재계산·명시 계약은 일관성을 높일 수 있지만256root/4epoch로 약100M 학생의 계산능력이 충분히 올라갈지는 불확실하다. AST/문맥 과제가 더 어려울 수도 있다. QA2쌍은 prompt/사고 공유 여지가 있지만 절단/복제/의미변경 위험이 늘며 완결은 정답성 보장이 아니다.

## 4. 단계 설계 (싼 것 → 비싼 것)

### Stage0W — 규칙·split·QA2쌍 파서 CPU 계약 (완료: 기술0)

기존20회귀와 새 source/view/token/teacher 파서 회귀를 수행한다. 원천/토크나이저/모델/GPU를 실행하지 않고 fixed literal·원형/root·LF/인용·unknown/protected 차단을 검증한다.

### Stage1W — 새 corpus/view manifest·chat32 길이 (완료: 기술0)

코드 소유 source만 새 HF namespace에 생성한다. root 분할을 먼저 고정하고 한영 자식/뷰도 같은 split로 둔다. first user를 유지한다. arithmetic/Boolean/table C1과 format C3를 균형 있게 넣는다. train128중립root×한영2자식=256canonical row×4view/epoch, val32중립root/64row를 목표로 한다.4개 절차 가족의 파라미터 인스턴스이며256개 새 지식이라고 세지 않는다.

fixed/view 각 slot의 actual x길이·assistant target mass를 같게 제한된 seed 후보를 계측한다. 부족 root는 제외/공개하고256이 안 되면 readiness8이다. padding으로 token을 부풀리지 않는다. 동일 chat32 SHA·20MB row-shard/SHA/concat·source/원형/view를 보존한다.

### Stage2Wa — fixed4epoch 학생 (완료: 기술0·조건갱신 음성)

같은 dense_chat32_p090b_s1337 부모·micro8×accum16·seq≤1024·ckptON·compile default·LR1e-4/Muon RMS4 LR4e-4다.256row는epoch2update,4epoch8update다. 8×8×16×1024=1,048,576은 padding 상한이고 실제x는 manifest를 합산한다. 정상75M/300M 대체가 아니다.

### Stage2Wb — 규칙뷰4epoch 학생 (완료: 기술0·조건갱신 음성)

부모·optimizer·batch·root order·epoch·x/target mass를 고정하고 view만 변경한다. fixed의 성공 여부와 독립이며 같은 자료/CPU 선결을 사용한다. 부모/두학생의 같은 새root 실제 첫답과 종료를 보존한다. teacher는 함께 올리지 않는다.

### Stage3W — 대응 답/망각/량 검산 (완료: 기술0)

각8update·actualx/target·root/exposure·지문 equality를 검산한다. 닫힌 과제는 계산/JSON gold로 문항·유형·언어별 보고하고 실제 Q/A를 표시한다. 같은 native subset의 CE는 망각 관측이며 새계열 σ 없이 서열을 확정하지 않는다.

### Stage4W — Gemma 한요청 QA2쌍 (종료: inline 라벨 구현결함8)

Gemma4/llama-b11396·MTPoff·card sampler1/.95/64/min_p0/중립penalty·사고1024/출력3072/ctx8192를 유지한다. source8개에서1쌍 요청2회와2쌍 요청1회를 대조한다. 교사1서버1슬롯, 학생 상주 없음이다.

QUESTION_1:/ANSWER_1:/QUESTION_2:/ANSWER_2:/NOTE: 시작라벨로 내용만 쓰고 코드는 canonical/ChatML을 만든다. source·thinking/final·usage·finish_reason·총3구조시도·오류/재시도 trace를 보존한다. 의미오류 문자열 목록이나 온라인 전수심사 없이 actual x/target/초와 실제 답을 보고하며 semantic truth는 NOT_REVIEWED다.

### Stage0bW — inline·근거context·balanced4096 CPU 계약 / 완료0

원형Stage4W의72완결응답이한줄라벨로거부된후속이다. 번호형라벨은기존Gemma시작라벨과같이inline/multiline·fence리터럴을지원하되누락/중복/순서/빈답/length-stop/literal질문검사는유지한다. 새로운 의미문구목록은없다.

### Stage4Wa — 저장72응답 CPU 후행 구조재판독 / 완료0

원형manifest/원답SHA를읽기전용확인하고원답별옛판정·새파싱/Q/A를별도새report로남긴다. 교사나tokenizer를실행하지않으며oldGPU negative를PASS로고치지않는다.

### Stage4Wb — 교사 단일/2QA 새 실물 / 완료0

8source/24논리요청·최초포함총3구조시도와원형sampler/budgets를유지한다. NOTE등라벨을닫을필요는없다. paraphrase-view2 피드백과literal-view1 피드백을구분하고학생에게SOURCE의근거문맥을전달한다. thinking은sidecar이며canonical/ChatML은코드소유다. 모든실제최종답을콘솔/원형에보존하며구조실패때에도빈pairs만보이지않게한다.

### Stage1Wb — matched4096 균형 자료 / 실제3074행·자료음성8

사용자A선택대로4,096train canonical row/2,048중립root를목표로한다. arithmetic/Boolean/table의양팔모두답변변경·답변유지각50%이며format팔은known키answer/value/result/reply를균형있게노출한다. 이전fixed의sham-only와view의변경교육교락을보완한다.
Boolean원형80개만으로목표를채울수없어20개의bounded AST형태×5연산/16할당의코드소유계열을확장했다. 숫자/이름/형식인스턴스를새지식으로세지않는다.
fixed는root별선택한하나의예제를4pass반복하고view는같은변경/유지종류에서동일actualx/target의대안최소2개를순환한다. 매epoch서로다른4개를보장하지않으며baseline예제가view에다시나올수있다.
기존val32root/64첫질문은train/새val에서모두제외한다. 새로운64닫힌probe와그대로재사용하는old64를분리저장해128개의실제첫답을평가한다. old64는알려진실패진단의재사용이지새blind일반화시험이아니다. val/test 증강·train투입은없다.
후보선별이4096행과slot길이/target을못맞추면자료gate8이며padding/복제로고유량을채우지않는다.

### Stage2Wc / Stage2Wd — 양팔각4epoch128updates / 종료·모델전보류8

기존chat32부모·micro8×accum16·ckptON·compile default·LR1e-4/Muon4e-4를유지한다.4096/128=32updates/pass,4pass=128updates다.128×8×16×1024=16,777,216은padding상한이며actualx/targets는실제로합산한다.
기존8update와의차이는양·구성/AST/변경노출도함께바뀌므로순수업데이트횟수인과로부르지않는다. 새fixed/view간에는같은root·x/target·curriculum을고정한다. 한팔의정답성음성이다른팔을막지않는다.

### Stage3Wb — 실제노출·첫답·망각 대응 / 종료·선결보류8

128updates/실제x/targets/원형SHA를검산하고old64/new64 및변경필요/변경불필요·유형/언어를나눠원답을판독한다. 먼저128회로회복되지않으면조건완전명시B를후속검토하며현재B를자동활성화하지않는다.75M/300M목표는유지한다.

새namespace `p106d_ruleviews_v2_4096_s1337`; `--samples4096`은토큰/root가아닌canonical train행수다. 정상배치/LR·교사기본·기존HFruns/원형은불변이다. teacher/dataGPU는모두사용자소유다.

## 8. 한계 (반드시 함께 기록)

작은 합성 source/과제/한 부모이며 교사2QA는 semantic 오류를 낼 수 있다. C3는 원답 형식만 바꾸고 C2를 교정하지 않는다. token match로 제외된root와 선택편향을 공개한다. 변형의 과적합 방지 보장은 없다. 기존75M/300M·보호자료·teacher 생산·학습기본은 변경하지 않는다.
