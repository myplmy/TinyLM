# P008 (C1) — 점진적 타잉 : LoRA 스케일 어닐 (untied → tied)

> **⚠️ 전면 재작성 2026-08-07.** 초판(2026-07 작성)은 *"KD 없이 격차를 줄인다"* 를 목적으로 삼았는데,
> **그 사이에 KD 가 격차를 이미 닫아 버렸다**(결과 021: `mC` 3.7393 **<** `p6d` 3.7608).
> 목적이 무효가 된 것이 아니라 **바뀌었다** — §2 가 그 재정의다.
> 사용자 질문("LoRA·FiLM 을 mA·mC 에서 켜서 재학습해야 하나? P008 과 무슨 관련인가")에 대한
> 답이 §1·§3 이다.
>
> **✅ 선결 구현 완료(2026-08-07)**: `--lora-decay`. 배치는 §8 판단 후에 만든다.

---

## 1. ★먼저 용어 정리 — LoRA·FiLM·P008 은 **서로 다른 세 가지**다

사용자 질문의 핵심이 여기다. 셋은 이름이 비슷하지만 **배포 메모리에서 완전히 다르게 행동**한다.

| | 무엇을 하나 | **추론 시 남나** | 배포 메모리 | 구현 |
|---|---|---|---|---|
| **① 고정 LoRA**(`--lora-rank 32`) | 공유 MLP 위에 **층별 저랭크 보정** `W + U·D` 를 얹는다 | **남는다** | 1.82× → **1.71×** (손해) | ✅ 있음 |
| **② FiLM**(`--mlp-film`) | 공유 MLP **은닉을 층별 scale/shift 로 변조** `h·(1+γ)+β` | **남는다** | 1.82× → **1.81×** (거의 공짜, 65K = 0.13MB) | ✅ 있음 |
| **③ P008 = 어닐 LoRA**(`--lora-rank 32 --lora-decay 0.6`) | ①과 같은 LoRA 인데 **출력 스케일 s(t) 를 1 → 0 으로 감쇠** | **사라진다**(s=0) | **1.82× 그대로** | ✅ **2026-08-07 구현** |

### 1.1 ③이 ①과 결정적으로 다른 이유

```
학습 초반  s=1.0  →  각 층이 자기 LoRA 로 특화  ≈ untied 에 가깝다
학습 중반  s=0.5  →  특화가 서서히 약해진다
학습 후반  s=0.0  →  LoRA 가 완전히 사라진다   = 순수 타잉
```

**끝에서 s=0 이므로 배포되는 가중치에 LoRA 가 없다.**
즉 **LoRA 를 "배포 부품" 이 아니라 "학습용 비계(scaffold)"** 로 쓴다.

이건 우리가 이미 쓰는 **삼진 어닐과 정확히 같은 원리**다:
제약(타잉/삼진)을 **처음부터 걸지 않고** 학습이 진행되며 점진적으로 조인다.
그래서 계획 이름이 "**점진적** 타잉" 이다.

### 1.2 그래서 P008 과 LoRA·FiLM 의 관계는

> **P008 은 LoRA 를 쓰는 하나의 방식이다.** LoRA 자체가 P008 이 아니다.
> **FiLM 은 P008 과 별개 축**이다 — 층별 조건화라는 목적은 같지만 어닐 대상이 아니고
> 어차피 거의 공짜라 끝까지 켜 두면 된다.
>
> 세 가지를 **조합**할 수도 있다(구 실험 `t_all` 이 ①+②+KD 였다).

## 2. ★목적 재정의 — 격차는 이미 닫혔다. 그럼 왜 하나

### 2.1 현재 상태 (2026-08 기준)

| 조건 | dense 대비 | 출처 |
|---|---|---|
| **plain tied g8**(KD 없음) | **+0.149~+0.168**, 토큰 6배에도 **안 닫힘** | 결과 006 |
| **tied g8 + KD k4 + 부모초기화** | **−0.0215 (dense 를 이긴다)** | 결과 021 paired |

**KD 가 격차를 닫았다.** 그러므로 초판의 목적("격차를 줄인다")은 **이미 달성돼 있다.**

### 2.2 ★그런데 KD 는 비싸다 — 이게 새 목적이다

| 경로 | 필요한 런 | 벽시계 |
|---|---|---|
| **KD 경로(현재 표준)** | ① dense 교사 학습 **117.4분** → ② 학생 KD 학습 **141.0분** | **258.4분** |
| plain tied g8 | 학생만 | **89.9분** |
| **P008(어닐 LoRA, KD 없음)** | 학생만 (LoRA 연산 추가) | **약 95분(추정)** |

> **★P008 이 KD 와 분해능(0.024) 안에서 붙으면 파이프라인이 258 → 95분 = 2.7배 싸진다.**
> 그리고 그 절감은 **모든 후속 실험에 곱해진다** — P041 단계2(약 28 GPU시간)·P033 처럼
> 여러 조건을 도는 캠페인에서 특히 크다.

### 2.3 두 번째 목적 — **더 공격적 타잉**

| g | 유니크 MLP | 감축 | plain 격차 |
|---|---|---|---|
| 4 (mA) | 8 | 1.82× | +0.132 |
| **8 (mC)** | **6** | **2.07×** | +0.168 |
| 16 | 5 | 2.26× | +0.018 (KD 후) |

**격차는 g 에 따라 커진다.** KD 가 g8 을 닫았지만 **g16·g32 도 닫는지는 미지**다.
P008 이 작동하면 **KD 와 합쳐** 더 공격적인 g 를 감당할 수 있다 = **메모리 추가 확보**.

## 3. ★사용자 질문에 대한 직접 답: "mA·mC 에서 켜서 재학습해야 하나?"

### 3.1 구 데이터가 이미 힌트를 준다 — **KD 가 켜지면 이득이 사라진다**

| 조건(300M 풀, g4) | val | `t_base` 대비 |
|---|---|---|
| `t_base` (plain) | 3.9558 | — |
| `t_lora32` (①고정 LoRA) | 3.9220 | **−0.0338** ✅ |
| `t_film` (②FiLM) | 3.9420 | **−0.0138** ⚠️ 분해능 미만 |
| | | |
| `t_kdinit` (KD + 부모초기화) | 3.8253 | — |
| **`t_all`** (KD + 부모초기화 + **①LoRA + ②FiLM**) | 3.8188 | **−0.0065** 🚫 **분해능 미만** |

> **★KD 없이는 LoRA 가 −0.0338 로 도움이 되는데, KD 를 켜면 LoRA+FiLM 을 둘 다 얹어도
> −0.0065 = 구분 불가다.** 두 기법이 **같은 자리를 채우고 있다**는 뜻으로 읽힌다.

### 3.2 판정

| 질문 | 답 |
|---|---|
| **mA·mC(=KD k4)에 ①고정 LoRA 를 켜서 재학습?** | 🚫 **권장하지 않는다.** 구 데이터가 −0.0065(분해능 미만)를 시사하고, **메모리는 확실히 손해**(2.07× → 1.94×). 이득 불확실 + 비용 확실 |
| **mA·mC 에 ②FiLM 을 켜서 재학습?** | ⚠️ **해 볼 값어치는 있다.** 메모리 대가가 **0.13MB(0.6%)** 로 사실상 없다. 단 기대 이득도 분해능 이하라 **`paired_eval.py`(SE 0.0005)로만 판정 가능** |
| **③P008(어닐 LoRA)은?** | ✅ **이게 진짜 실험이다.** 메모리 대가 **0**, 그리고 **KD 를 대체할 수 있는지**를 묻는다 |

> **★우선순위: ③ > ② > ①.**
> ①은 하지 않는다. ②는 값싸니 ③과 **같은 배치에 대조 조건으로** 넣는다.

## 6. 선결 구현 — ✅ 완료 (2026-08-07)

| # | 무엇 | 어디 | 상태 |
|---|---|---|---|
| 1 | `LoRA._scale` 버퍼 + forward 에 곱 | `ternary.py::LoRA` | ✅ |
| 2 | `set_lora_scale(v)` — **모든 LoRA 모듈 하나의 집합**으로만 정의 | `transformer.py` | ✅ |
| 3 | 스텝별 스케줄(선형 1→0, `lora_decay` 지점에서 0 고정) | `trainer.py` | ✅ |
| 4 | `--lora-decay FRAC`(기본 **0.0 = 끔**) + json 기록 | `cli.py`·`trainer.py` | ✅ |

**버퍼로 둔 이유**: 파이썬 float 면 값이 바뀔 때마다 `torch.compile` 이 재컴파일한다
(`set_anneal` 이 같은 이유로 버퍼다).

**적용 대상 집합을 한 곳(`set_lora_scale`)에서만 정한 이유**: 결과 016 §14 의 교훈 —
언팩 캐시가 **무장 목록과 세대 심는 목록을 따로 순회**해서 한쪽만 고쳤다가 두 번 실패했다.

⚠️ **`--lora-rank 0`(기본)이면 `LoRA` 모듈 자체가 없다 → 종전 경로와 비트 동일.**
`--lora-rank 32 --lora-decay 0` 이면 s=1 고정 = 종전 고정 LoRA 와 **값 동일**
(부동소수점 `×1.0` 이라 연산은 하나 늘지만 값은 안 바뀐다).

## 7. 단계 설계

### 단계 0 — **게이트: s=0 이 정말 0 인가** ⏸ · GPU 소 · 수 분

`--tiny` 스모크로 `--lora-rank 32 --lora-decay 0.5` 를 돌려 **후반 스텝의 손실이
`--lora-rank 0` 과 수렴하는지** 본다. 그리고 `report()` 의 감축비를 확인.

⚠️ **주의 — 체크포인트에는 LoRA 파라미터가 남는다.** s=0 이면 **계산에 기여하지 않지만**
`state_dict` 에는 들어 있다. **배포 시 제거하는 경로가 필요**하다:

- `mem_breakdown()` 이 `lora` 항을 세므로 **감축비가 s=0 인데도 1.71× 로 보일 수 있다**
- → **단계 0 에서 이걸 확인하고, 필요하면 `lora_rank=0` 으로 재로드하는 배포 경로를 만든다**

**게이트 G0**: s=0 이후 손실이 안정적이고, 배포 메모리 계산이 **1.82×** 로 나오는가
(안 나오면 회계 수정이 선결이다 — 결과 016 §13 이 정확히 이 종류의 사고였다).

### 단계 1 — **본 실험 4조건** ⏸ G0 통과 후 · GPU **약 6h**

`m100R1c`(g8) 기준. **KD 없음 · 부모초기화 없음**(P008 의 주장은 "KD 없이" 다):

| 태그 | 구성 | 목적 |
|---|---|---|
| `p8_base` | plain tied g8 | **대조군**(≈ 결과 006 의 p6t) |
| **`p8_anneal`** | `--lora-rank 32 --lora-decay 0.6` | **주 조건** |
| `p8_fixed` | `--lora-rank 32`(어닐 없음) | ①과 ③의 분리 |
| `p8_film` | `--mlp-film` | ②단독, 거의 공짜 |

**조건**: 600M 풀 · 300M 학습(2289 steps) · `--sched wsd` · lr 1e-3 · seed 1337 · 약 1.5h/런

### 단계 2 — **KD 와의 대결** ⏸ 단계1 에서 P1 성립 시 · GPU 0(재사용)

`paired_eval.py` 로 `p8_anneal` vs `mC_wsd`(결과 024, 3.6442) 를 짝비교.
**SE 0.0005 라 분해능 이하 차이도 본다.**

⚠️ 두 런의 **스케줄·anneal_end 가 다르면 무효**다 — 단계1 을 `mC_wsd` 와 같은 조건
(`--sched wsd --anneal-end 0.80`)으로 맞춘다.

### 단계 3 — **FiLM 을 KD 조건에서** ⏸ 조건부 · GPU 약 3.5h

P4 를 직접 검정: `mC_wsd` 구성 + `--mlp-film` 한 런. `paired_eval` 로 판정.
**단계1 의 `p8_film` 이 강한 신호를 보일 때만** 한다.

LoRA 는 gradient 를 키우는 경향이 있고, **어닐이 그걸 완화할지 악화할지 미지**다.

## 10. 한계

- **시드 1개.** σ=0.012 이므로 0.024 미만 차이는 `paired_eval` 없이는 못 읽는다.
- 단계1 은 **KD 없는 조건**이다. "KD 와 조합하면 더 좋은가" 는 **별개 질문**이고 단계3 일부만 답한다.
- `--lora-decay` 는 **선형 감쇠 하나**만 구현했다. 형태(코사인·계단) 스윕은 안 한다 —
  **P035 가 삼진 어닐 형태에서 검출 실패**(결과 022)했으므로 여기서도 둔감할 것으로 본다(P5).
- ★**체크포인트에 LoRA 파라미터가 남는 문제**(§7 단계0)가 미해결이면 **배포 메모리 주장이 성립하지 않는다.**
  이게 이 계획의 가장 구체적인 리스크다.
- g8 하나만 본다. §2.3 의 "g16 을 감당하는가" 는 **이 계획이 답하지 않는다**(성공 시 후속).
