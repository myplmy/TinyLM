# P016 — 3:4 희소 삼진 (Sherry 1.25-bit) 메모리 레버

근거 논문: *Sherry: Hardware-Efficient 1.25-Bit Ternary Quantization via Fine-grained
Sparsification* (Huang et al., arXiv:2601.07892, Tencent/AngelSlim).

## 왜 (우리 목표와 정렬)
TinyLM의 1순위는 **메모리**다. 현재 삼진 배포 밀도 BPW≈1.95. Sherry의 **3:4 희소 삼진**은
4개 가중치를 **5비트**로 패킹(= **1.25 bpw**) → 가중치 메모리 **약 1.56× 추가 절감**.
타잉과 **곱셈적으로 누적**: t_kd_g8(2.09×) 위에 얹으면 **~2.8–3.1×** 기대. 정확히 우리 지향점.

## 핵심 아이디어 (논문)
- **3:4 sparsity**: 4개 블록마다 **정확히 1개를 0**으로 강제(3개만 ±1). 조합수
  `C(4,3)·2^3 = 32 = 2^5` → 5비트를 낭비 없이 포화 → 1.25 bpw. 2비트(낭비) vs 1.67비트(불규칙)의
  절충 해소, **AVX2 vpshufb 16-byte LUT** 에 정합(CPU 추론 친화 — 우리 배포 타깃과 일치).
- **Arenas(Annealing Residual Synapse)**: 3:4 강제 시 gradient homogenization → 표현 붕괴
  (binary-like). 이를 막으려 학습 중 `Y = X·Tα + λt·XW`(λt→0) 로 full-precision 우회를 감쇠 주입.
  → **우리 기존 삼진 어닐 `eff = wq + (1-anneal)(w-wq)` 이 사실상 Arenas의 특수형.** 이미 보유.

## 우리 구현 방향 (최소 변경)
1. `ternary_g` 에 **3:4 마스크 옵션** 추가: group(128) 내부를 4개 단위로 쪼개, 각 4-블록에서
   |w| 최소값을 0으로 강제(나머지 3개만 TWN 삼진). alpha는 non-zero 3개로 재계산.
   (config 플래그 `sparse34=False` 기본; 켜면 코딩만 바뀌고 파이프라인 무영향.)
2. 어닐: 기존 `quant_anneal` 재사용(=Arenas). 별도 λ 스케줄 불필요, 필요 시 residual을
   `w`(full latent)로 두는 변형만 실험.
3. compare 메모리 계산: 3:4 경로는 `MB` 를 **1.25 bpw** 로(현재 1.95 하드코딩 → 분기 필요).

## 실험 매트릭스 (m100, ko-en, 300M, KD+parent-init 고정)
| 태그 | 구성 | 확인 |
|---|---|---|
| dense | 기준선(재사용) | 품질 기준 |
| t_kd_g8 (기존) | 삼진 1.95bpw, g8 | 2.09× 기준 |
| **t_kd_g8_s34** | **3:4 삼진 1.25bpw, g8** | 격차 유지되며 메모리 **~2.8–3.1×?** |
| t_kd_g4_s34 | 3:4 삼진, g4(보수적 타잉) | 희소×타잉 손실 분해 |

판정: `compare` 손실격차 ≤ +0.07 유지하면서 메모리비 상승이 목표. 격차가 커지면
(a) g 낮추기 (b) coda/prelude full-precision 유지 (c) Arenas residual을 full-w 로.

## 리스크 / 비판
- 3:4는 **25% 강제 0** → 삼진 위에 용량 추가 손실. Sherry는 1B+Arenas+QAT로 무손실 주장하나
  **우리 100M + 공격적 타잉(g8/g16) + KD 조합에서는 미검증** — 희소 손실과 타잉 손실이 **복합**될 수 있음.
- 배포 이득(10% 속도, 1.25bpw)은 **CPU 추론** 개념 — 우리 최종 목표엔 부합하나 학습속도와 무관.
- BPW 1.95 는 GGUF 오버헤드 포함 역산치. 1.25bpw 가 **GGUF 포맷에서 그대로 유지되는지**는
  배포 통합 시 별도 확인(순수 packing 이득과 실제 파일 크기는 다를 수 있음).

## 우선순위
메모리 1순위 목표에 가장 직접적. **P003(KD-g스윕) 결과 확정 후 착수** 권장(같은 KD 인프라 재사용).
