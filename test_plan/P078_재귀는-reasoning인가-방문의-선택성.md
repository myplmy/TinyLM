## 0. ★왜 — **우리는 재귀가 *무엇을* 개선하는지 모른다**

아는 것: 재귀 R=2 가 `val_loss` 를 **−0.0107** 내린다(결과 047 §14.3).
🚫**모르는 것: 그 −0.0107 이 어디서 왔는가.**

★★**문헌이 이 질문을 값어치 있게 만든다.** looped transformer 연구
(Ouro 📄[arXiv:2510.25741](https://arxiv.org/abs/2510.25741) · Geiping 📄[arXiv:2502.05171](https://arxiv.org/abs/2502.05171))는
*"반복이 latent reasoning 을 유도한다"* 고 주장하고, Ouro 저자들은
*"이점이 **지식 용량이 아니라 지식 조작** 에서 온다"* 고 적었다.

★**그 주장이 우리에게 참이면**: 재귀는 **메모리 레버가 아니라 능력 레버**이고,
**reasoning 라인 전체가 이미 열려 있다**(구현 0).
🚫**거짓이면**: 재귀는 그냥 **연산으로 용량을 사는 것**이고, reasoning 이야기는 접는다.

## 1. 질문

| # | 질문 |
|---|---|
| ★★**Q1** | 재귀의 이득이 **모든 토큰에 고르게** 오는가, **어려운 토큰에 몰리는가** |
| ★**Q2** | `--infer-repeat` 을 **학습 R 보다 높이면** 계속 좋아지는가(테스트타임 스케일링) |
| **Q3** | 이득이 **어느 층 통과**에서 오는가 |

## 2. ★가설과 무엇이 그것을 구분하는가

| 가설 | 예상 관측 | 함의 |
|---|---|---|
| **H1 용량설** | 크롭별 이득 분포가 **대칭·단봉**, 고손실 크롭과 저손실 크롭에 **비슷하게** | 🚫**reasoning 이 아니다.** 재귀 = 값싼 파라미터 |
| ★**H2 선택설** | 이득이 **고손실 크롭에 집중**(상관 유의) | ✅★**reasoning 의 서명** |

★**`paired_eval` 이 이미 크롭별 손실을 저장한다** — 그 자료로 바로 답한다.

⚠️★**H2 가 나와도 "reasoning" 이라고 부르는 것은 해석이다.**
관측되는 것은 *"어려운 곳에서 더 돕는다"* 뿐이다. **그 이상을 주장하지 않는다.**

## 2026-10-21 신규 Stage2W — 방문 정책을 학습에도 적용하는 별도 본대조

### 1. 목적과 기존 음성의 보존

기존 Stage0/1의 낮은 입력별 이득 설명력과 종결 판정은 유지한다. 사용자 현재 지시의 방문 순서·방문 횟수 무작위화 본실험은, 기존 모델의 추론 횟수만 바꾸던 시험과 달리 **그 경로로 본체를 학습**하는 새 질문이다. 보호 TinyDataset을 사용하지 않는다.

### 2. 질문

동일 부모·자료·assistant 지도량·평균 R2에서 순차 방문, 고정 셔플, 매 업데이트 셔플, 무작위 방문 횟수가 실제 첫 답·검증 손실·시간에 어떤 영향을 주는가? 실제 방문 수가 같아도 wall time과 peak 메모리가 같은지는 별도로 측정한다.

### 3. 사전 예측

추론 때만 경로를 바꾸는 불일치를 줄일 가능성은 있지만, 어순을 읽는 능력이나 정답성을 자동으로 확보하지 않는다. 옛 P078의 예측 불가능성이 새 코퍼스에서도 재현될 수 있다. 이번 조건의 다중 seed 분해능은 없으므로 단일 seed 관측을 구조의 일반 승자로 승격하지 않는다.

### 4. 네 팔과 통제 조건

| 팔 | 학습 중 정책 | 주평가 경로 |
|---|---|---|
| uniform_r2 | 매번 같은 순차 R2 | 같은 순차 R2 |
| fixed_shuffle_r2 | 하나의 고정 셔플 R2 | 같은 셔플 |
| update_shuffle_r2 | 업데이트마다 CLA 원자 그룹 셔플 | 고정 평가 seed로 선택한 같은 정책 |
| balanced_count | 4업데이트당 R1/R2/R2/R3를 무작위 배치 | 같은 균형 횟수 정책 |

원자 CLA 그룹 내부는 KV 소유자부터 방문한다. 한 업데이트의 micro8×accum16 전체와 checkpoint backward 재계산 동안 경로는 고정한다. 한 생성 세션 중에도 경로를 바꾸지 않고, 다른 모델·세션·경로의 KV는 거부한다. 공통 순차 R2로 바꾸는 부평가는 **경로 불일치 진단**일 뿐 주평가가 아니다.

고정 P090B chat32 부모(14층·dim768·SHA `12E18658…`)와 새 `p101a_sft_mtp_cleanbilingual_v3_s1337`의 TRAIN22,528/VAL512를 사용한다. 새 세대 595M 부모가 아니다. 잘못된 과거 assistant는 입력으로만 남기고 실제 target 마스크는 기존 `masked_record`를 재사용한다. Adam5e-5/Muon2e-4, m8×a16, seq1024, checkpoint ON, MTP OFF, eager/compile OFF, 4pass704업데이트다. 원 P101A compile·부분 micro shape와는 달라 옛 학습 수치를 완전 대응 인과 비교하지 않는다.

### 5. 단계와 선결

1. `Stage2Wa` CPU 정책/마스크/세션/권한 회귀와 정확 코퍼스 바인딩.
2. `Stage2Wb --mode cost --arm <팔>` 네 팔 각각 32업데이트 비용·FP32 VAL64행·첫 답 2개를 측정한다. 비용 모델의 가중치는 폐기하고 체크포인트는 저장하지 않는다.
3. `--mode budget`에서 같은 소스의 네 비용 영수증과 실제 사용 시간, 현재 UTC 권한, 보수적 남은 예산을 검산한다.
4. `--mode train --arm <팔>`로 각각 새 부모에서 704업데이트한다. 비용 모델에서 이어 학습하지 않는다.
5. `--mode readback`으로 원형·실제 방문·분모·모델/optimizer 연속성·완결 영수증을 다시 센다.

### 6. 판정과 비용

기술 실패·만료·미완료는 모델 품질 음성과 분리한다. 실제 첫 답은 의미 판독 전 `null`이며 CE 감소나 종료만으로 정답이라고 하지 않는다. 새로운 데이터와 실제 파라미터에 대한 resource 측정은 아직 필요하다. 네 본팔의 계산 slot 상한은 각 92,274,688이며 실제 입력·assistant 지도량과 다르다. 가족 40시간은 **상한**이지 현재 권한이 40시간이라는 뜻이 아니다. 현재 실행은 사용자 연장 승인에 따라 23시까지이며 매 worker가 별도 권한 snapshot과 UTC를 확인한다.

### 7. 실행 진입점

`run_P078_Stage2Wa_route_training_cpu.sh`, `run_P078_Stage2Wb_route_training.sh`.

두 번째 SH에는 `--mode cost|budget|train|readback`, `--arm`, 정확 `--corpus-sha256`, `--authorization`, `--authorization-sha256`, `--max-wall-sec`가 필요하다. 기본/임의 권한으로 시작하지 않는다. GPT 주도 실행도 사용자가 지정한 새 기한의 snapshot이 있어야 한다.

### 8. 학습형 라우터와 범위 제한

네 팔은 학습형 라우터가 아니다. 후속 Stage3는 미리 정한 balanced_count704 체크포인트를 동결하고 TRAIN-only R1/R2/R3 손실로 작은 prefix 라우터를 지도하는 별도 준비다. 검증·평가 정답은 라벨이나 추론 선택에 넣지 않는다. 새 DEV/TEST 연결성분 분할과 해당 부모가 없으면 HOLD이며, 기존 재귀 음성을 PASS로 바꾸지 않는다.

### 9. 증거 수준

root가 소스를 전수 읽고 구현 리뷰 gate를 열었지만, 이것은 runtime 또는 지능 PASS가 아니다. CPU 소형/기존 CLA 회귀와 실제 비용·학습·평가를 결과066의 새 절로 분리한다. 제품 코드·옛 helper·원본 로그·기존 체크포인트는 수정하지 않는다.

이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.

## Stage3W — 질문 prefix만 읽는 방문수 head의 별도 본실험 준비

1. 목적/이유: 옛crop 난이도특징의 낮은설명력 음성을 보존하고 명시문맥 SFT에서 입력별R1/R2/R3 상대 CE를 배울 수 있는지 묻는다. 정답 판별기나 reasoning 향상으로 미리 채택하지 않는다.
