## 0. ★무엇을 모르는가

우리는 **KD 가 300M 에서 해롭다는 것을 안다.** 두 시드에서 재현됐다:

| 측정 | 값 |
|---|---:|
| `mC_wsd`(KD) − `mC_initonly`(무KD), 시드 1337 | **+0.0208** |
| 같은 쌍, 시드 2024 | **+0.0219** |
| 무KD 조건의 시드 노이즈 | **+0.0017** |
| → KD 효과 / 노이즈 | ★**12~13배** |
| KD 단독 몫(부모초기화 없이) | **−0.0032** = 사실상 0 |

**모르는 것은 "왜" 다.** 그리고 그건 세 가지 중 하나다:

| # | 가설 | 함의 |
|---|---|---|
| **H1** | **교사가 학생보다 나쁘다** — soft target 이 학생을 끌어내린다 | **더 좋은 교사면 해결**된다 |
| **H2** | **KD 구현에 결함이 있다** | ★**고치면 KD 가 되살아난다** |
| **H3** | **이 예산에서 KD 라는 기법 자체가 안 맞는다** | **KD 를 버린다** |

> ★**세 가설의 처방이 정반대**다. **모르는 채로 REVIEW2 가 KD 를 버리면,
> H2 였을 경우 버그 때문에 기법을 버린 것이 된다.**

## 1. H1 의 근거와 구멍

결과 037 §1: **교사 `dense` full-val 3.8080 vs 학생 `mC_wsd` 3.6984 = 교사가 +0.1096 나쁘다.**

★**교사가 학생보다 나쁘면 KD 는 정의상 해롭다** — soft target 이 학생을 자기보다
나쁜 분포로 끌어당긴다. **가장 단순하고 설득력 있는 설명이다.**

### 1.1 ⚠️ 그런데 구멍이 둘 있다

| # | 구멍 |
|---|---|
| **①** | ⚠️**풀 핸디캡이 섞여 있다.** 교사 `dense` 는 **300M 풀**(2026-07-23), 학생은 **600M 풀**. 결과 006: 풀만 2×로 dense 가 **−0.12**. → **교사의 +0.1096 중 대부분이 풀 때문일 수 있다** |
| **②** | ⚠️**"교사가 나쁘면 KD 가 해롭다" 는 자동이 아니다.** KD 는 **dark knowledge**(오답 간 상대 확률)를 전달하고, 그건 교사의 절대 품질과 별개일 수 있다. 실제로 결과 006 은 **100M 예산에서 KD 가 −0.110 으로 이득**이었다 — **같은 교사로** |

★**②가 결정적이다.** 같은 교사가 100M 에선 도움이 되고 300M 에선 해롭다면
**"교사가 나쁘다" 만으로는 설명이 안 된다.** 예산 의존성이 있다.

## 2. H2 — **KD 구현을 감사한다. 이게 가장 값싸다**

```python
kl = F.kl_div(F.log_softmax(logits.reshape(-1, V) / T, -1),
              F.softmax(tlog.reshape(-1, V) / T, -1),
              reduction="batchmean") * (T * T)
loss = ((1 - kd_alpha) * ce + kd_alpha * kl) / accum
```

### 2.1 ★감사 항목 — **의심스러운 것 다섯**

| # | 항목 | 왜 의심하나 | 확인 방법 |
|---|---|---|---|
| **A1** | ★**`batchmean` 의 분모** | `kl_div(reduction="batchmean")` 는 **첫 차원**으로 나눈다. 우리는 `(B·T, V)` 로 reshape 했으므로 분모가 **8192**(토큰 수)다. **표준 KD 는 토큰당 평균이 맞다** → ✅ 아마 정상. **단 확인해야 한다** | 손실 스케일을 손으로 계산해 대조 |
| **A2** | ★★**`T²` 곱과 `kd_alpha` 의 상호작용** | `T=2` 면 `T²=4`. `kd_alpha=0.5` 라서 **KL 항의 실효 가중치가 CE 의 4배**다. Hinton 식은 T² 를 곱해 **gradient 크기를 맞추는 것**이 목적인데, **α 를 곱한 뒤에도 스케일이 맞는지는 별개**다 | α 를 0.1/0.3/0.5 로 스윕 |
| **A3** | ★**KD 스텝과 비KD 스텝의 손실 스케일 불연속** | `kd_every=4` 라 **4스텝 중 1스텝만** 혼합손실이다. 그 스텝의 손실 크기가 다르면 **optimizer 가 그 스텝에서 다른 크기의 업데이트**를 한다 | json 의 `train_loss` vs `train_ce` 를 스텝별로 비교 |
| **A4** | **autocast dtype** | 학생 로짓은 bf16, 교사도 bf16. `log_softmax(/T)` 가 **bf16 에서 계산**되면 tail 확률이 뭉개진다 | `.float()` 를 넣은 변형과 비교 |
| **A5** | **교사 어닐 상태** | 교사는 `freeze_quant` 없이 로드되면 **매 forward 재양자화**된다. `quant_anneal` 값이 학생과 다르면? | 교사 cfg 의 `quant_anneal` 확인 |

> ★★**A2 와 A4 가 가장 의심스럽다.** 둘 다 **학습 0 또는 소**로 확인 가능하다.

### 2.2 ⚠️ 사전 판단 — **아마 버그는 없을 것이다**

결과 006 이 **같은 코드로 100M 에서 −0.110 이득**을 쟀다.
**버그가 있으면 그 예산에서도 해로웠어야 한다.** → **H2 의 사전 확률은 낮다.**

> **그래도 감사한다.** 이유: **비용이 거의 0** 이고, **틀렸을 때의 대가가 크다**
> (기법을 버그 때문에 버리는 것). 그리고 **A2·A4 는 "버그" 가 아니라 "하이퍼파라미터 미탐색"**
> 일 수 있다 — 그건 실재할 가능성이 훨씬 높다.

---

## 3. H3 — **예산 의존성이 진짜 설명일 가능성**

결과 006 의 KD 이득: **−0.110(100M) → +0.062(300M) → +0.098(600M)**.
**단조 증가**(= 예산이 커질수록 KD 가 나빠진다). 이건 **잘 알려진 현상**과 일치한다:

> 학생이 데이터로부터 직접 배울 수 있는 양이 늘어나면, **교사의 근사를 따라가는 것이
> 오히려 제약**이 된다. `kd_alpha=0.5` 는 **손실의 절반을 교사에게 준다** — 예산이 크면
> 그 절반이 낭비다.

★**그러면 처방은 "KD 를 버린다" 가 아니라 "α 를 예산에 따라 낮춘다" 일 수 있다.**
그리고 **α 스윕은 한 번도 안 했다**(`kd_alpha=0.5` 고정).

## 4. ★예측

| # | 예측 | 근거 | 틀리면 |
|---|---|---|---|
| **P1** | **H2(구현 결함)는 없다** | 같은 코드가 100M 에서 이득 | 있으면 **KD 판정 전체를 다시 해야 한다** |
| **P2** | ★**`kd_alpha` 를 낮추면 KD 의 해로움이 줄어든다.** α=0.1 에서 Δ가 **+0.0208 → +0.005 이하** | H3. 손실 배분 문제 | 안 줄면 **α 가 아니라 교사 자체** = H1 |
| **P3** | ⚠️**그래도 α=0 (=KD 없음)보다 낫지는 않을 것이다** | 결과 038: KD 몫이 −0.0032 = 0 | 나으면 ★**최적 α 가 (0, 0.5) 안에 있다** = KD 를 살릴 수 있다 |
| **P4** | **공정 풀 교사(600M)로 바꾸면 Δ가 줄지만 부호는 안 바뀐다** | 교사 −0.12 개선 vs KD 해로움 +0.0208 | 부호가 바뀌면 **H1 이 주범** |
| **P5** | `kd_temp` 는 영향이 작다 | — | 크면 T 도 축이다 |

> ★**P3 가 이 계획의 핵심**이다. **"KD 를 버린다" 와 "α 를 낮춘다" 사이에 답이 있는가.**

## 5. 단계 설계

### ✅ 단계 0 — **KD 구현 감사** ⏸ GPU **0~소** · 수 분

`scripts/diag_kd_loss.py`(신설 필요):

1. **A1** — 고정 로짓 쌍에서 우리 `kl` 값을 **손 계산과 대조**
2. **A2** — `T²·α` 가중치 하에서 **CE gradient 대 KL gradient 의 실제 크기 비**를 잰다
   ★*"α=0.5 인데 실효 비가 1:4 면 그건 α=0.8 과 같다"* 를 수치로 본다
3. **A4** — `log_softmax` 를 bf16 vs fp32 로 계산해 **KL 값 차이**를 잰다
4. **A5** — 교사 cfg 의 `quant_anneal`·`micro_group` 이 학생과 같은지
5. **A3** — 기존 json 에서 KD 스텝 / 비KD 스텝의 `train_loss` 분포를 비교(**로그만 읽는다**)

**게이트 G0**: 1·3·4 가 전부 **예상값과 일치**해야 단계1 로 간다.
**불일치가 하나라도 있으면 그게 답이고, 단계1 은 불필요하다.**

### 단계 1 — **`kd_alpha` 스윕** ⏸ GPU **약 3 × 2.2h**

| 팔 | `--kd-alpha` | 태그 | 대조 |
|---|---:|---|---|
| (재사용) | 0.5 | `mC_wsd` | 기존 |
| **A** | **0.3** | `mC_kda03` | |
| **B** | **0.1** | `mC_kda01` | |
| (재사용) | 0(=무KD) | `mC_initonly` | 결과 038 |

나머지 표준 조건 동일. **paired_eval 로 네 점의 곡선**을 본다.

★**이 스윕이 P2·P3 를 동시에 답한다.** 그리고 **곡선이 단조인지**가 H3 의 직접 증거다.

### 단계 2 — **공정 풀 교사** ⏸ 조건부(단계1 이 α 만으로 설명 못 할 때) · GPU **약 2h + 2.2h**

600M 풀·wsd 로 dense 를 재학습(`--tag dense600`)하고 그 교사로 KD.
⚠️ **P054 단계4 와 같은 런**이다 → **중복 실행 금지, 하나로 합친다.**

### 단계 3 — **중간 표현 KD**(TinyBERT 식) ⏸ 조건부 · 구현 중

로짓만이 아니라 **은닉 상태**를 맞춘다. 근거: TinyBERT
([`1909.10351`](https://arxiv.org/abs/1909.10351), ✅조회) — *"Transformer distillation"* 으로
4층이 교사의 **96.8%**.

> ⚠️★**단계3 은 "KD 를 살리는" 것이 아니라 "다른 KD 를 시험하는" 것**이다.
> 그리고 **P049B(재귀 구조)와 결합할 때 값어치가 가장 크다**(문서 E §6: 공유 재귀 블록은
> 깊이별 기능 분화를 배우기 어려우므로 중간 KD 가 직접 감독을 준다).
> **P049B 가 살아남을 때만 착수한다.**
