> 상태: Stage0Wa CPUtoy12와Wb 비identity5 완료([105](../test_result/105_20261016_P070B-CLA방문-기능계약은-학습효과가-아니다.md)). Wa의identity기록은보존하며제품기본/실제checkpoint/재귀학습/GPU품질은NOT_RUN이다.

## 1. 왜 — 기존 결과와 문헌

[P062 결과047 §11](../test_result/047_20260814_P062-단계0-스케줄을-맞추니-0.2427이-돌아왔다.md)에서 같은 조건의 inplace R2는 uniform R2보다 paired full-val +0.0116 나빴다. §19의 d14/d16 block 이득 −0.00157/−0.00188은 시드 차와 비슷하고, progressive의 방문당 이득도 uniform보다 작았다. 같은 방문수의 무재귀 깊이 후보가 재귀를 지배한 조건까지 있다. [P072 결과057](../test_result/057_20260823_P072-같은-입력에-다른-일-묶으면-안-되는-쌍이-대부분이다.md)은 재귀 모델에서 입력이 닮고 델타가 다른 쌍 105, 델타도 닮은 쌍 0을 관찰했다. 그러므로 무작위 순서가 층 역할을 깨뜨릴 위험을 우선 본다.

[P087 결과073](../test_result/073_20260904_P087-두-번째-epoch은-과적합-없이-0.1155를-준다.md)의 동일 pool 1/2/4 노출 LM loss 개선은 **데이터 draw 반복**이지 층 재귀 또는 대화능력 증거가 아니다. [P098 결과091](../test_result/091_20260923_P098-R2-초기임베딩-재주입은-3시드-실무-동급.md)의 embedding 재주입도 3시드 실무 동급이다. 세 축을 한 런에서 섞지 않는다.

[Takase·Kiyono의 층공유 순서](https://aclanthology.org/2023.sustainlp-1.5.pdf)는 Pre-LN WikiText-103에서 Sequence valid PPL18.97, Cycle19.00, Cycle(Rev)19.60을 보고해 역순의 자동 이득을 뒷받침하지 않는다. [Universal Transformer](https://arxiv.org/abs/1807.03819)는 반복과 동적 중단의 가능성만 준다. [Mixture-of-Recursions](https://arxiv.org/pdf/2507.10524)는 토큰별 깊이 라우터와 KV 정책을 함께 학습하며 expert-choice의 미래 토큰 누출, token-choice의 불균형·KV 정합을 구분한다. [MACRO](https://arxiv.org/abs/2608.05872)의 frozen route 탐색은 개념만 차용할 수 있다. [LayerShuffle](https://arxiv.org/abs/2407.04513)는 ViT에서 순서 강건성과 약20% 정확도 손실이 공존한 사례여서 언어모델 효능으로 전이할 수 없다.

## 3. 예측 — 음성도 결과

기본 예측은 보수적이다. frozen 부모의 즉석 shuffle은 P062 학습/추론 mismatch와 P072 층 역할 차이 때문에 악화할 수 있다. 학습부터 고정 순서를 쓰면 낫더라도 Pre-LN 문헌은 reverse를 우선하지 않는다. 반복노출의 loss 개선을 route 효과라 해석하지 않는다. 토큰 라우터는 현재 [P060B 결과088](../test_result/088_20260919_P060B-forced-GQA는-문턱을-못-넘었지만-default는-살았다.md)의 GQA decode cache 미통과와 [P077 결과062](../test_result/062_20260830_P077-KV재사용은-재귀이득의-5.4배를-먹는다-기각.md)의 KV 재사용 음성을 먼저 넘어야 한다.

## 4. 단계 설계 — 싼 검증부터

### Stage0W — 스케줄·인과·회계 계약, 0 GPU-h

제품 기본 uniform은 비트 동일하게 둔다. prelude/coda 고정, middle만 변형한다. **순열**은 같은 층 방문 multiset·횟수에서 순서만 변경한다. **선택**은 총 방문수만 같고 반복할 층을 변경한다. 둘은 다른 독립변수다. seed·방문 목록 해시를 저장하고 누락·범위 밖 방문0, owner×방문차수 KV 키 충돌0, causal mask·gradient·기본 logits 불변을 fixture로 검사한다. 실패하면 모델 SH 금지.

### Stage1W — 같은 R2 checkpoint의 frozen 경로 안전 진단

사용자 모델 실행에서 uniform/reverse/고정 random 경로의 동일 prompt·seed로 유한 logits, cache on/off 정합, 방문/KV 엔트리, CPU p50/p95만 본다. 재학습하지 않은 새 경로의 손실은 **학습 함수 mismatch**라 채택·기각 점수가 아니다. 평가마다 난수를 다시 뽑지 않는다.

### Stage2W — 조건부 같은 부모 100M 진입 팔

Stage0·1 기능 PASS와 별도 사용자 실행 결정 후 새 uniform 대조군, fixed reverse, fixed random을 같은 parent·ko-en 600M nominal pool·tokenizer·seed·Muon RMS4·KD off·WSD anneal0.60·grad checkpoint 조건에 묶는다. micro8×accum16×seq1024에서 763step은 100,007,936 draw다. 유일 변경축은 순서다. 옛 mC_r20_nokd의 AdamW/anneal0.80 손실을 새 팔에서 직접 빼지 않는다. 100M은 grad/skip/퇴화 게이트지 최적 순열 품질 판정이 아니다.

### Stage3W — 긍정 뒤에만 층 선택과 라우터

먼저 P072 기반 사전 고정 선택과 random 선택을 같은 방문수로 비교한다. 그 뒤에만 학습 라우터를 별도 팔로 설계한다. 첫 라우터는 전체 시퀀스가 같은 경로를 선택해 prefill/decode KV 일치를 쉽게 만든다. 토큰별 token-choice는 GQA cache parity, causal mask, 부하분산·route collapse 검사를 통과할 때만 연다. expert-choice의 미래 토큰 top-k는 기본안에서 제외한다. P077의 첫 통과 KV 재사용을 자동 적용하지 않는다. packed·runtime·KV·실제 CPU p95와 router overhead를 모두 센다.

### Stage4W — chat32 멀티턴 반복노출(정식 SFT 적격 후)

[P090B](P090B_chat32-기존-최선부모-SFT-3계보-검증.md)의 chat32 부모와 canonical→ChatML→assistant-only mask(종료 토큰 포함)를 사용한다. 한국어/영어 대화권리·PII·오염·tree/첫질문 그룹 split·사람품질 gate가 필요하며 현재 TRAIN_READY=false다. 같은 유니크 대화 집합에서 실제 trainer 순회/셔플·target token 수를 기록해 1/2 노출 × 고정 route만 먼저 본다. 4노출·라우터는 지식/형식/단기기억 비퇴행 뒤 조건부다. 같은 질문을 train/val에 나눠 넣지 않고 600M+ 한국어 평가 결손·1.2B 6차리뷰 SH는 열지 않는다.

## 5. 판정 기준

| 관측 | 판정 |
|---|---|
| 기본 uniform 불변 실패, 방문/KV/인과/seed 누출 | IMPLEMENTATION_FAIL, 다음 gate 금지 |
| frozen route 우열 | 탐색 신호만, 학습 후 품질 추정 금지 |
| 100M skip·퇴화 또는 풀/부모/평가 불일치 | STOP/INVALID, 기존 음성 유지 |
| 100M 작은 차이 | 300M 자동 승격 금지, 계열별 현재 ruler와 다중 시드 필요 |
| matched 300M 다중 시드에서 품질·한영 능력 비퇴행 및 같은 계산 예산의 실제 CPU wall·runtime Pareto 개선 | 그 계보에 한해 후보 |
| router 비용 포함 순이득 없음, cache 불일치·route collapse | router HOLD/기각, 다른 축 판정과 분리 |

판정자는 실행 시 [현재 기준표](../docs/EXPERIMENT_BASELINES.md)와 scripts/_rulers.py에서 계열·optimizer·풀·평가 경로에 맞게 다시 조회한다. 맞는 자가 없으면 UNDETERMINED다. P070 옛 ±0.010이나 다른 가족 0.024를 복사하지 않는다.
