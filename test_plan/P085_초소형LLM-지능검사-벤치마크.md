## 제안 트리거

> 사용자 지시(2026-09-04): *"모델의 실제 지능을 loss나 bpb만으로 볼 수 없다면 모델의 좋고 나쁨을
> 비교하기 위해서는 **반드시 벤치마크도 함께 비교해야 하는 것이 아닌지** 검토바라며,
> 우리 모델의 성능을 비교할 수 있는 **적절한 벤치마크도 조사**할 것."*

---

## 1. 왜 이 계획이 필요한가

### 1.1 ★full-val 서열이 다운스트림에서 재현되지 않았다

결과 067 §12.5 실측 — `d16_cla2_r20` 이 full-val 을 **−0.0412**(재귀 자의 **23배**)로 이기면서
hellaswag 는 **27.5 vs 29.8 로 진다**. ★**정답 CE 는 방향이 맞고 어긋나는 것은 argmax** 다.

### 1.2 ★그리고 bpb 도 지문에 따라 부호가 뒤집혔다

결과 053 §12 — 같은 두 체크포인트에서 **우리 val 은 무KD 승(−0.00766)**,
**외부 영문 bpb 는 KD 승(+0.0367 nats)**. **바뀐 것은 채점 지문뿐**이다.

→ ★★**압축률 지표(loss·bpb) 하나로는 "어느 모델이 더 나은가" 를 못 답한다.**
그 답을 내려면 **다운스트림을 함께 봐야 하고**, 그러려면 **그 다운스트림이 판정력을 가져야 한다.**

### 3.0b ★★Stage2 의 *"외부 HF 어댑터"* 는 **왜 필요한가** — 2026-09-04 사용자 지시 5

> *"외부 HF 어댑터는 왜 필요한지에 대한 설명이 없음. 만약 사용자에게 다운로드 요청하여
> HF폴더에 다운로드만 하면 되는 것이라면 사용자에게 다운로드 요청할 것"*

★**답: 다운로드는 이미 끝나 있다. 막고 있는 것은 코드다.**

**`HF/` 실사(2026-09-04)** — 여섯 모델이 **가중치까지** 있다:

| 모델 | 가중치 | | 모델 | 가중치 |
|---|---|---|---|---|
| `HuggingFaceTB/SmolLM2-135M` | 257 MB | | `LiquidAI/LFM2.5-230M-Base` | 439 MB |
| `tiiuae/Falcon-H1-Tiny-90M-Base` | 174 MB | | `Qwen3-0.6B-Base` | 1.2 GB |
| `facebook/MobileLLM-125M`(+`-layer-share`) | 238 MB | | `google/gemma-3-270m` | 512 MB |

→ 🚫**사용자에게 요청할 다운로드가 없다.** (⚠️예외 하나 = **KoBEST**, §3.3)

**그러면 무엇이 막고 있나** — `eval_bench_suite` 의 모델 진입점이 하나뿐이다:

```python
model, cfg, _ = load_model(arch=_arch_of(tag), ckpt_path=str(ck), device=dev)   # :443
#   -> tinylm/infer/generate.py:41   cfg = TMTConfig(**st["cfg"])
#                                    model = TiedMLPTransformer(cfg)
```

★**우리 체크포인트(`.pt` + `TMTConfig`)만 안다.** HF 모델은 `AutoModelForCausalLM` +
자기 `AutoTokenizer` 이므로 **세 가지가 어긋난다**:

| # | 어긋나는 것 | 크기 | 어댑터가 할 일 |
|---|---|---|---|
| **1** | 로더 — `.pt/TMTConfig` vs `from_pretrained` | ⚙0.3h | `--hf-models` 분기 + 공통 인터페이스 `(model, tok)` |
| **2** | 토크나이저 — 우리 32,768 vs 외부 49,152~151,936 | ⚙0.2h | 문항 텍스트를 **모델마다** 다시 토큰화 |
| ★**3** | ★**정답CE 의 단위** | ⚙0.5h | **nats/토큰 -> nats/바이트** 로 정규화 |

★★**3 이 진짜 이유다.** 우리 정본 지표는 **정답CE(nats/토큰)** 인데
🚫**토크나이저가 다르면 토큰당 값은 비교 불가**다(R09 — 큰 어휘가 언제나 유리하다).
→ 외부 대조에서는 **`bits/byte` 로 바꿔야** 하고, 그것이 `common_bpb.py` 가 이미 하는 일이다.
⚠️**그런데 `common_bpb` 는 자유 지문용**이라 **선다형 정답CE 를 안 잰다** —
**둘을 합치는 것이 이 어댑터**다.

★**대조군 정확도(argmax)는 어댑터 없이도 비교 가능**하다 — 선택지 중 최대 우도를 고르는 것은
**토크나이저 무관**이다. 🚫**단 결과 074 가 정확도의 검정력을 닫았으므로**
*"정확도만 비교" 는 지금 쓸모가 적다.*

⚙**합계 1.0h** — 우선순위는 §3.3 의 한국어 축보다 **낮다**(그쪽은 축 자체가 0 이다).

### 3.1 Stage1 상세

- **모델 3종**: `d12_cla2_r20`(32 MiB 승자) · `d16_cla2_r20`(40 MiB 승자) · `mC_cla2_ag4_r20`(타잉 계열)
- **과제 3종**: 초판 §0.0 의 ✅ 중 **판정력이 상대적으로 좋은 것**
- 🚫**`boolq` 제외** — 기준선이 50 이 아니라 **다수결 62** 라 같은 표에 두면 오독한다
- ★**판정**: n=400 서열과 **순서가 뒤집히면** 종전 다운스트림 표는 **잡음이었다**

| 결과 | 뜻 |

| 질문 | 답 |
|---|---|

**예측 대조**: hellaswag 역전이 *"사라진다"* → ⚠️**절반**(−2.3pp → −0.6pp 로 줄었으나 부호 유지) ·

★★**판정 규약이 바뀌었다** — 판정 3층의 ②는 **정답CE** 다. `argmax` 는 우리 크기에서
**필요 n 이 45,000~254,000** 이라 **세 과제 모두 도달 불가**다(기준표 B.16.5).
