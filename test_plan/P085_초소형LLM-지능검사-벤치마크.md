## 1. 왜 이 계획이 필요한가

### 1.1 ★full-val 서열이 다운스트림에서 재현되지 않았다

결과 067 §12.5 실측 — `d16_cla2_r20` 이 full-val 을 **−0.0412**(재귀 자의 **23배**)로 이기면서
hellaswag 는 **27.5 vs 29.8 로 진다**. ★**정답 CE 는 방향이 맞고 어긋나는 것은 argmax** 다.

### 1.2 ★그리고 bpb 도 지문에 따라 부호가 뒤집혔다

결과 053 §12 — 같은 두 체크포인트에서 **우리 val 은 무KD 승(−0.00766)**,
**외부 영문 bpb 는 KD 승(+0.0367 nats)**. **바뀐 것은 채점 지문뿐**이다.

→ ★★**압축률 지표(loss·bpb) 하나로는 "어느 모델이 더 나은가" 를 못 답한다.**
그 답을 내려면 **다운스트림을 함께 봐야 하고**, 그러려면 **그 다운스트림이 판정력을 가져야 한다.**

### 3.0b ★★Stage2 의 *"외부 HF 어댑터"* 는 **왜 필요한가** — 2026-09-04 사용자 지시 5

> *"외부 HF 어댑터는 왜 필요한지에 대한 설명이 없음. 만약 사용자에게 다운로드 요청하여
> HF폴더에 다운로드만 하면 되는 것이라면 사용자에게 다운로드 요청할 것"*

★**답: 다운로드는 이미 끝나 있다. 막고 있는 것은 코드다.**

**`HF/` 실사(2026-09-04)** — 여섯 모델이 **가중치까지** 있다:

| 모델 | 가중치 | | 모델 | 가중치 |
|---|---|---|---|---|
| `HuggingFaceTB/SmolLM2-135M` | 257 MB | | `LiquidAI/LFM2.5-230M-Base` | 439 MB |
| `tiiuae/Falcon-H1-Tiny-90M-Base` | 174 MB | | `Qwen3-0.6B-Base` | 1.2 GB |
| `facebook/MobileLLM-125M`(+`-layer-share`) | 238 MB | | `google/gemma-3-270m` | 512 MB |

→ 🚫**사용자에게 요청할 다운로드가 없다.** (⚠️예외 하나 = **KoBEST**, §3.3)

**그러면 무엇이 막고 있나** — `eval_bench_suite` 의 모델 진입점이 하나뿐이다:

```python
model, cfg, _ = load_model(arch=_arch_of(tag), ckpt_path=str(ck), device=dev)   # :443
#   -> tinylm/infer/generate.py:41   cfg = TMTConfig(**st["cfg"])
#                                    model = TiedMLPTransformer(cfg)
```

★**우리 체크포인트(`.pt` + `TMTConfig`)만 안다.** HF 모델은 `AutoModelForCausalLM` +
자기 `AutoTokenizer` 이므로 **세 가지가 어긋난다**:

| # | 어긋나는 것 | 크기 | 어댑터가 할 일 |
|---|---|---|---|
| **1** | 로더 — `.pt/TMTConfig` vs `from_pretrained` | ⚙0.3h | `--hf-models` 분기 + 공통 인터페이스 `(model, tok)` |
| **2** | 토크나이저 — 우리 32,768 vs 외부 49,152~151,936 | ⚙0.2h | 문항 텍스트를 **모델마다** 다시 토큰화 |
| ★**3** | ★**정답CE 의 단위** | ⚙0.5h | **nats/토큰 -> nats/바이트** 로 정규화 |

★★**3 이 진짜 이유다.** 우리 정본 지표는 **정답CE(nats/토큰)** 인데
🚫**토크나이저가 다르면 토큰당 값은 비교 불가**다(R09 — 큰 어휘가 언제나 유리하다).
→ 외부 대조에서는 **`bits/byte` 로 바꿔야** 하고, 그것이 `common_bpb.py` 가 이미 하는 일이다.
⚠️**그런데 `common_bpb` 는 자유 지문용**이라 **선다형 정답CE 를 안 잰다** —
**둘을 합치는 것이 이 어댑터**다.

★**대조군 정확도(argmax)는 어댑터 없이도 비교 가능**하다 — 선택지 중 최대 우도를 고르는 것은
**토크나이저 무관**이다. 🚫**단 결과 074 가 정확도의 검정력을 닫았으므로**
*"정확도만 비교" 는 지금 쓸모가 적다.*

⚙**합계 1.0h** — 우선순위는 §3.3 의 한국어 축보다 **낮다**(그쪽은 축 자체가 0 이다).

### 3.3b ★★KoBEST — **논문·데이터 실사 완료** (2026-09-05 지시 (3)·(6))

> 사용자 (3): *"`article/KOBEST Korean Balanced Evaluation of Significant Tasks.pdf` 에 KOBEST 논문
> 저장했으므로 벤치마크 및 관련 실험계획 등에 참고할 것."*
> 사용자 (6): *"KoBest 다운로드 완료. `HF\datasets--skt--kobest_v1` 에 저장되어있음."*

★**논문 = arXiv:2204.04541**(Kim·Jang·Kwon·Davis, SK Telecom + Oxford, 2022-04-09).
★**초록만 읽지 않았다**(R31) — 본문 §2·§3·§4 와 Table 1·4·5 를 열어 아래 수치를 옮겼다.

#### 3.3b.1 다섯 과제 — **디스크 실사와 논문 Table 1 이 정확히 일치한다**

| 과제 | 형태 | 우연 | train | dev | **test** | 원문 출처 | 우리 MC 기계로 되나 |
|---|---|---:|---:|---:|---:|---|---|
| **KB-COPA** | 전제 + 원인/결과 + 후보 2 | 50% | 3,076 | 1,000 | **1,000** | 주석자 작성 | ✅**그대로 된다** |
| **KB-HellaSwag** | 문맥 + 후보 4 | 25% | 2,029 | 500 | **500** | 위키·유튜브 | ✅**그대로 된다** |
| KB-BoolQ | 문단 + 예/아니오 | 50% | 3,665 | 700 | 1,404 | 한국어 위키 | ⚠️verbalizer 필요 |
| KB-WiC | 동형이의어 + 문맥 2 | 50% | 3,318 | 1,260 | 1,260 | 국어사전 | ⚠️verbalizer 필요 |
| KB-SentiNeg | 문장 + 긍/부정 | 50% | 3,649 | 400 | 397 | 상품평 | ⚠️verbalizer 필요 |

#### 3.3b.2 ★★논문이 우리 대신 답해 준 것 — **어느 과제가 zero-shot 에서 살아 있나**

논문 Table 4 의 **KoGPT3-39B zero-shot(k=0)** 열이 정확히 우리 상황(SFT 없는 base LM)이다:

| 과제 | 우연 | ★**39B zero-shot F1** | 사람 | 판정 |
|---|---:|---:|---:|---|
| **KB-COPA** | 50 | ★**76.8** | 98.1 | ✅**신호가 크다** |
| **KB-HellaSwag** | 25 | ★**59.8** | 92.4 | ✅**신호가 있다** |
| KB-SentiNeg | 50 | 57.7 | 99.0 | ⚠️약하다 |
| KB-WiC | 50 | 🚫**34.7** | 96.6 | 🚫**우연 아래** |
| KB-BoolQ | 50 | 🚫**33.1** | 95.1 | 🚫**우연 아래** |

🚫★★**39B 모델이 BoolQ·WiC 에서 우연 아래로 떨어진다.** 우리 81M 이 그것을 넘을 이유가 없다 —
**두 과제는 애초에 편성하지 않는다.** ★영어 쪽에서 우리가 `boolq` 를 뺀 것과 **같은 이유이고
이번에는 논문이 근거를 준다**(종전 근거는 *"다수결 62"* 였다).

★★**그리고 우리가 살릴 두 과제가 정확히 "우리 기계가 그대로 도는 두 과제" 다** —
논문 §4.2.1: *"For multiple-choice problems like KB-COPA and KB-HellaSwag, we selected the
candidate having the lowest perplexity."* 이것이 우리 `우도acc` 와 **같은 절차**다.

#### 3.3b.3 ⚠️지표 이름 — **F1 이지 정확도가 아니다**

논문 §2.7: *"we use the F1 score as a base criterion."* 🚫**우리 인쇄에 `F1` 이라고 쓰지 않는다**
(규약 2 — 공식 metric 이름을 우리 지표에 쓰지 않는다). 우리는 `우도acc` · `길이정규acc` ·
**`정답CE`** 를 그대로 쓰고, 표의 *공식* 열에만 `F1` 을 참고로 적는다.
⚠️**2지선다에서 macro-F1 과 정확도는 다른 수다** — 논문 수와 우리 수를 **한 칸에 나란히 쓰지 않는다.**

#### 3.3b.4 ★★이 논문이 **held-out 결함 작업에 그대로 쓰인다**

우리 held-out v2.x 가 겪은 결함과 **같은 것을 논문이 먼저 겪고 고쳤다**:

| 우리 결함 | 논문의 대응 | 어디 |
|---|---|---|
| ★**D4 부정 지름길**(부정 후보가 정답일 확률 94.4%) | *"'덥다/춥다', '했다/하지 않았다' 같은 특정 표현이 **False 라벨로 크게 치우쳐** 있었다 — 전부 제거·수정"* | §3.4 model-driven review |
| ★**전제·정답을 뒤집어 만든 쌍둥이 문항** | *"COPA 에서 전제와 정답을 맞바꿔 질문만 원인↔결과로 바꾼 사례가 많았다 — **near-duplicate 라 제거**"* | §3.4 Table 3 |
| **후보가 질문 범주 밖**(E-272) | *"모든 후보는 문맥과 **주제적으로 관련**되어야 하고, 정답은 **시간 흐름을 분석해야만** 찾을 수 있어야 한다"* | §2.5 지침 3 |

★**그리고 방법론이 우리와 같다** — *ad-hoc 모델을 학습시켜 예측을 뽑고, 특정 표현이 라벨과
