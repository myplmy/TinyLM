| | **P022B** | ★**P068**(이것) |

| 포맷 | **FP8**(E4M3) | ★**BF16 / FP16** |

## 2. ★문헌이 말하는 것 — **확인한 것만**

### 2.1 DeepSeek-V3 (arXiv:2412.19437 §3.3.1·§3.3.3)

우리 문서 `20260807_DeepSeekV3-...md` §1.1·§1.3 이 **원문을 인용해** 정리해 뒀다:

| 항목 | 논문 | 인용 근거 |
|---|---|---|
| **AdamW 1·2차 모멘트** | ★**BF16** | *"without incurring observable performance degradation"* |
| ★**master weight · 누적 gradient** | ★**FP32 유지** | *"To further guarantee numerical stability"* |
| 임베딩 모듈 · 출력 헤드 | BF16/FP32 | *"sensitivity to low-precision computations"* |
| 정규화 연산 | BF16/FP32 | *"low-cost operators ... higher precision with negligible overhead"* |
| 어텐션 연산 | BF16/FP32 | 〃 |

> ★★**즉 문헌이 허락한 것은 우리가 이미 다 했다**(모멘트 bf16 = P022B 단계2).
> **master 와 gradient 는 논문이 명시적으로 지키라고 한 것**이다.
> → ★**이 계획은 "문헌을 넘어서는" 부분을 재는 것이고, 그래서 예측이 부정적이다.**

⚠️★**미조회**: Mixed Precision Training (Micikevicius et al.) — **arXiv id 를 확인하지 않았다.**
*"fp32 master + loss scaling"* 이 그 논문의 결론으로 알려져 있으나 **원문 대조를 안 했으므로
이 계획서에서 근거로 인용하지 않는다**(CLAUDE.md: 참고문헌은 인용 전에 실제로 조회한다).

### 2.2 ★우리에게만 있는 두 가지 — **문헌에 답이 없다**

| # | 우리 특수 조건 | 왜 문헌이 답을 못 주나 |
|---|---|---|
| ★**S-1** | **`w` 는 삼진 latent 다.** `mask = (\|w\| ≥ thr·mean\|w\|)` 가 **어느 가중치를 0 으로 만들지**를 정한다 | ★**문턱 비교**다. bf16 가수 7비트면 **문턱 근처에서 비교가 뒤집힌다.** 일반 master weight 논의에 이 항이 없다 |
| ★**S-2** | **`_wq` 는 매 스텝 재생성되는 중간 텐서**다(파라미터도 버퍼도 아니다) | 문헌에 이런 텐서가 없다. **우리 구조 고유** |

## 3. ★★핵심 가설 — **언더플로는 스케줄 끝에서 온다**

bf16 의 ulp(unit in last place)를 계산한다. 가수 = 1(암묵) + 7(저장) = **8비트**.

```
x ≈ 0.02  (emb std=0.02, TLinear 초기값도 같은 자릿수)
exp = floor(log2(0.02)) = -6
ulp(bf16) = 2^(-6-7)  = 2^-13 = 1.22e-4     -> 반올림 소실 문턱 ≈ 6.1e-5
ulp(fp16) = 2^(-6-10) = 2^-16 = 1.53e-5     -> 문턱 ≈ 7.6e-6
ulp(fp32) = 2^(-6-23) = 1.19e-8             -> 사실상 없다
```

AdamW 의 스텝 크기는 `lr × m/(√v+eps) ≈ lr × O(1)`.

| 학습 구간 | ⚙유효 lr | ⚙스텝 크기 | **bf16 에서** | **fp16 에서** |
|---|---:|---:|---|---|
| 초반(lr 1e-3) | 1e-3 | ~1e-3 | ✅ ulp 의 8배 — 안전 | ✅ |
| 타잉 그룹(lr/√8) | 3.5e-4 | ~3.5e-4 | ✅ ulp 의 2.9배 | ✅ |
| ★**감쇠 꼬리**(`decay_frac 0.2`) | ⚙**1e-5 이하** | ~1e-5 | 🚫★**ulp 의 1/12 — 사라진다** | ⚠️ ulp 와 비슷 |

> ★★★**가설 H-A: bf16 master 는 학습 전체가 아니라 *감쇠 구간에서* 무너진다.**
> **`--sched wsd --decay-frac 0.2`** 는 **마지막 20% 에서 lr 을 0 으로 끌어내린다.**
> 그 구간의 업데이트가 통째로 반올림으로 사라지면 **EMA·best 선택까지 왜곡**된다.
>
> ★**이건 우리 스케줄에 특정된 예측이고, 문헌에는 없다.**
> ★**그리고 검정이 값싸다** — 250스텝이 아니라 **감쇠 구간을 포함한 전체 런**이어야 하지만,
> **`--anneal-end` 를 앞당겨 감쇠를 일찍 오게 하면 짧은 런으로도 볼 수 있다**(§5 단계1b).

### 3.1 ★완화책 — **stochastic rounding**

`adamw_bf16.py` 는 *"결정론적 반올림, stochastic 아님"* 이라고 명시한다.
**확률적 반올림을 쓰면 기댓값이 보존**되어 언더플로가 상쇄된다(bf16 master 가 작동하는 표준 조건).

⚠️**구현 부담이 있고**(⚙약 30줄) **속도 대가가 있다.** ★**H-A 가 확인된 뒤에만** 손댄다.

## 7. 🚫이 계획이 결정하지 못하는 것

- ★**FP8** — P022B 의 축이다. **K축 그룹 스케일 커널이 없다**(P022B §1.3).

- ⚠️**`--compile` 상호작용** — 컴파일된 그래프에서 dtype 이 어떻게 융합되는지 모른다.
