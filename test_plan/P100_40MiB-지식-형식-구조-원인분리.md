# P100 — 40 MiB 모델의 지식·문답 형식·학습방법 원인분리

> 제안 계기: [승인된 다축 로드맵](../proposal/20260923_40MiB-실질지능-다축-검증-로드맵-제안서-approved-on-going.md), [P090 SFT](P090_SFT-경로.md), [P097 데이터](P097_한영-코퍼스-조합-300M-품질-대조.md), [P087 반복](P087_반복노출-1-2-4epoch.md). 2026-09-25 Stage0W 원답안 36건 저장·실행 PASS, 중복 재시도는 출력 충돌 FAIL. 답안의 지식/형식/구조 원인분리는 심층 검수 전 미확정이다.

## 1. 왜 — 낮은 생성 품질의 원인을 하나로 뭉치지 않는다

4차 리뷰의 외부 모델 격차는 모델 규모, 데이터, 사전학습 노출량,
instruct 여부와 평가 경로가 함께 달라 토큰 부족만의 인과효과가 아니다.
P087은 같은 300M pool의 반복 draw에서 LM loss가 감소했지만
한국어 문답·멀티턴 개선을 증명하지 않았다. P097 공통평가는 corpus별
장단점이 갈렸고 전면 승자를 내지 않았다. P090의 공개 v3는
한국어 train 175/val 9, **한국어 다회전 train 0/val 0**이라
한국어 SFT 효과를 판정하기 부족하다. 2026-09-24 큐는 종료됐고
Stage0W 원답안과 P097 Stage4 관측은 각각 결과092·090에 별도 귀속한다.

이 계획은 **P090의 데이터·trainer 구현을 복제하지 않고**
동일 부모·동일 평가의 비교 설계와 원인 판정만 소유한다.
P097의 진행 중 seed와 P087의 종결된 역사 결과도 재개명하지 않는다.

## 2. 질문

| # | 질문 | 원인을 가르는 관찰 |
|---|---|---|
| Q1 | 선택지 gold margin은 존재하는데 자유 생성 답이 틀리나 | 보유 정보의 인출/형식 문제를 지식 부재와 분리 |
| Q2 | 같은 질문에 근거 문단을 주면 답하나 | 제공 정보 활용과 폐쇄형 지식 회상을 분리 |
| Q3 | format-only SFT가 형식·역할 전환만 올리나 | SFT가 지식이 아니라 출력 정책을 교정하는지 분리 |
| Q4 | 검증된 지식 QA SFT 또는 유니크 사전학습 원천이 닫힌 책 정확도를 올리나 | 신규 정보 습득과 단순 반복 효과를 분리 |
| Q5 | 실제 한국어 다회전 SFT가 임시정보 회상·후속 지시를 올리나 | 단일턴 내용 증가와 역사 이용을 분리 |
| Q6 | 데이터·SFT를 고정해도 구조/optimizer 대조가 개선되나 | 구조·학습방법 가설은 잔여 오차만으로 채택하지 않음 |

## 3. ★예측 — 성공·실패 양쪽을 등록한다

- format-only SFT는 JSON 형식과 assistant 턴 개시는 개선할 수 있다.
  외부 지식 정답이나 폐쇄형 gold margin은 거의 안 바뀔 가능성이 높다.
  반대라면 훈련 예제의 사실 오염 또는 평가 누출부터 조사한다.
- Aya Collection 추가 단일턴 QA는 한국어 표본을 늘리지만, 번역·템플릿의
  답변 오류와 중복 때문에 자연 다회전이나 세계지식 점수가 오히려
  악화할 수 있다. **416만 행은 적격 레코드 수가 아니다.**
- 동일 pool 재노출은 loss를 낮출 수 있지만 새 고유 지식과 다회전
  능력까지 주지는 않을 수 있다. P087의 단일 seed 판정을 재사용하지 않는다.
- 구조/optimizer 대조에서 matched 조건이 불가능하면 Q6은
  `UNIDENTIFIABLE`로 남긴다. 음성/불능도 결과다.

## 4. 단계 설계 (싼 것 → 비싼 것)

### 단계 0 — 증거 봉인과 평가 계약, 현재 큐 비간섭

- 큐 종료 전에는 현재 로그·실험 런처 .sh를 **읽거나 수정하지 않는다**.
  완료라고 사용자가 보고한 P014D/P098/P092도 과학적 PASS로 바꾸지 않는다.
- 기준 parent checkpoint·tokenizer SHA, 구조·optimizer·pool·draw·seq·
  WSD horizon, 평가 코드 commit, prompt/shot/decoding seed와
  원문·gold를 봉인한다. 보호 held-out은 별도 허가 전 접근 금지다.
- 최소 한국어·영어 각각 닫힌책 사실/제공문단/형식/멀티턴 임시키/논리
  패널을 사전등록한다. 다회전 임시키는 학습 지식과 무관한 새 문자열로
  교체 가능한 family여야 한다. 생성 전체 텍스트, log-likelihood
  gold margin, 예상 답·오류유형, 모델·tokenizer hash를 같이 보존한다.
- 동일 parent를 base continuation과 chat prompt로 각각 돌리되
  평가 모드 자체의 차이를 SFT 효과로 계산하지 않는다.
  현재는 모델 실행 0회이고 실제 평가 자산 구축도 NOT_RUN.

### 단계 0bW — 저장된 36답안의 보수적 직접답·형식 신호 분류(런처 준비; 원본 재실행 없음)

기존 Stage0W의 control/FineWeb2 각 9문항×base/QA 36행을 정확 경로에서 읽기만 한다. 새 진단기는 case/form/prompt·체크포인트와 tokenizer 해시·중복을 검사하고 7개 짧은 답 사례는 이어쓰기 맨 앞의 기대 문자열, JSON 사례는 정확한 두 키·값만 엄격 신호로 센다. 논리 문항은 MANUAL_REQUIRED로 남긴다. NOT_DIRECT를 지식 부재나 오답 점수로 해석하지 않으며 log-likelihood gold margin, 제공문단 활용의 인과, SFT 효과는 여전히 NOT_RUN이다. 새 학습 tag·pool·token budget은 없으므로 학습 preflight 항목은 비해당이다.

### 단계 1 — P090 한국어 SFT 데이터 적격성

- [Aya Collection 한국어 분할](https://huggingface.co/datasets/CohereLabs/aya_collection_language_split)은
  카드상 Apache-2.0, `kor` 4,161,353행이다. 약 974 MB의 train shard
  두 개를 pinned revision으로 별도 `HF/sft_sources`에만 받는다.
  후속 사용자 지시로 별도 HF 다운로드는 허용됐다. 초안 당시에는 미취득이었으나
  2026-09-23 pinned train 두 조각을 취득·출처 집계했다. 학습 채택은 여전히 미승인이다.
  원천별 근거와 작은 대체 원천 3종은 [공개 원천 감사](../docs/20260923_한영일-SFT-멀티턴-공개원천-선별과-확보-감사.md)가 소유한다.
- `dataset_name/sub_dataset_name/task_type/template_id/split`별 수량·
  중복·언어·길이·출처별 라이선스를 감사하고, `test/validation`
  split을 학습에 섞지 않는다. Aya Dataset 인간주석 원천과
  자동 템플릿·번역 원천을 따로 판정한다. 20~50건/원천의
  사람 검토, PII·평가 오염, 첫 질문 그룹 분할, mask/길이 gate가 선결이다.
- 이 원천의 행은 단일 prompt-completion이며 **진짜 한국어 다회전이
  아님**. 다회전 train·val을 별도 공개 원천에서 확보하고 동일
  사용자 질문의 대화 tree·원천 간 누출 0, 역할/시간 순서,
  assistant-only mask를 검사한다. `train>0`만으로 성능 gate를 열지
  않고 분리된 `val>0`과 품질·다양성 검토가 필요하다.
  부족하면 한국어 다회전 팔은 `BLOCKED_DATA`, 단일턴 pilot만 가능.
- 기존 32k tokenizer 호환 SFT와 chat32 신규 사전학습 계보는 섞지 않는다.

### 단계 2 — 동일 부모의 SFT 분해, 조건부 GPU

| 팔 | 유일한 차이 | 해석 가능 조건 |
|---|---|---|
| A0 | SFT 없음, base parent | 동일 prompt/decoding의 직접 대조 |
| A1 | format·역할·문맥 내 답변만 지도, 새 세계지식은 넣지 않음 | 총 assistant target token·언어·epoch·optimizer·LR 동일 |
| A2 | 품질 검증한 한/영 사실 QA SFT | A1과 목표 토큰·언어 비율·parent·schedule 일치, 답안 누출 0 |
| A3 | 실제 한국어 다회전 대화로 지도 | 같은 소재를 단일턴으로 재구성한 대조와 목표 토큰 일치 |

A1의 합성/문맥 내 정답은 **형식용 양성대조**일 뿐 대화 지능 데이터가
아니다. A3의 단일턴 재구성은 history 차이만 보되 문장 중복이
train/val을 가로지르지 않게 그룹화한다. 데이터 적격성·contamination
gate가 미완이면 A2/A3의 공식 품질 비교는 실행하지 않는다.
SFT 부모 전체 val/byte-bpb와 한국어·영어 다운스트림 비퇴행을 따로 본다.

### 단계 3 — 지식 원천 대 반복 노출, 단계 2와 별도 계보

동일 구조·tokenizer·최종 draw·유효 step·schedule·optimizer·평가를
고정한 사전학습 대조를 별도로 설계한다. 유니크 원천 추가 팔과 기존
pool 재노출 팔은 **풀 fingerprint와 중복률**을 함께 기록하고
한 런에서 동시에 바꾸지 않는다. P087의 300M pool 역사 결과와
P097의 600M nominal pool 결과는 직접 차감하지 않는다.
현재 큐의 P097 seed 결과 회수와 source-stratified 한국어 val gate가
선결이다. 한국어 검증에 문제가 있는 600M 초과 노출이나 1.2B
6차리뷰 런처는 자동 편성하지 않는다. 반복 노출 2→4 draw는
각 단계의 한국어·영어 능력/망각 확인 뒤 별도 승인한다.

### 단계 4 — 구조·학습방법 가설, 단계 2·3 음성일 때만

A0~A3와 단계 3에서 지식·형식·다회전 실패가 분리된 뒤
동일 데이터·tokenizer·학습토큰·SFT 원천·평가의 구조 대조를
설계한다. 파라미터 수, 저장 MiB, 상주 peak, token/s,
실제 유효 FLOPs와 총 GPU-h를 함께 맞추거나 차이를 명시한다.
optimizer는 Muon RMS4 기본을 유지하고 대체 optimizer는 **별도**
팔로 하여 구조 효과와 섞지 않는다. matched 대조가 없으면
“구조적 한계”라고 결론짓지 않는다.

## 5. 판정 기준

| 관측 조합 | 허용되는 해석 | 추가 확인 |
|---|---|---|
| A1 형식↑, closed-book/gold margin≈, provided-context↑ | 형식·문맥 활용 부족이 일부 원인 | 원답안 블라인드 검토, 훈련 사실 오염 |
| A2 또는 유니크 원천에서 closed-book·margin↑, A1 변화 작음 | 지식/원천 부족 지지 | 언어별·과제별 비퇴행, 중복·라이선스 |
| 같은 pool 반복만 LM loss↓, 능력≈ | 노출은 loss에 유효, 실질 능력 해법 미입증 | 단계별 full-val·문항 난도 |
| A3만 임시키·후속 지시↑ | 한국어 멀티턴 학습 효과 후보 | 단일턴 재구성·표본·사람 채점 |
| matched 구조/optimizer 팔만 일관되게↑ | 방법론 병목 후보 | 시드 반복, 비용/40 MiB 대가 |
| 지표 혼재·누출·불완전 matching | `UNIDENTIFIABLE` 또는 `INVALID` | 원인 단정 금지 |

`↑`는 계획용 방향 기호다. 정식 PASS는 평가 문항 수·계열별
ruler/분해능을 [기준표](../docs/EXPERIMENT_BASELINES.md)와
`scripts/_rulers.py`에서 실행 직전 재조회하고 paired seed/CI를
계산한 뒤에만 부여한다. 사람이 읽는 답안은 자동 점수를 대체하지 않는다.

## 7. 실행

- **초안 당시 실험용 .sh 미작성.** 당시 큐 결과 로그는 읽기 금지,
  실험 런처는 읽기만 허용·수정 금지다. 새 tag·registry
  실물 중복검사 `NOT_RUN`, 데이터 적격성 미완이다. 시간 총합이나
  GPU 실행 약속을 이 문서에서 만들지 않는다.
- `exp-preflight`의 정본 조건은 대조했으나 `check_run_registry.py`는
  큐가 쓰는 `runs/logs`를 읽으므로 실행하지 않았다. 따라서 사전비행
  판정은 **PARTIAL/NOT_RUN**, 실제 GPU 품질도 `NOT_RUN`이다.
- 큐 종료·읽기 해제 뒤 fingerprint, 태그, token 산식,
  pool/draw, tokenizer, parent와 GPU/메모리 예산을 재검토한다.

- Stage0bW의 실물 [run_P100_Stage0bW_saved_answer_triage.sh](../run_P100_Stage0bW_saved_answer_triage.sh)는 원본 runs/bench/p100_stage0w_capability_baseline.jsonl을 읽기만 하며 결과번호 092 runlog에 기록한다. 새 모델 실행·출력 덮어쓰기 없이 사용자 실행을 기다린다. 합성 fixture PASS를 36행 실측 PASS로 승격하지 않는다.

## 8. 한계

같은 부모의 A1/A2도 완전히 같은 정보량의 문장으로 만들 수 없어
지식 증가와 instruction 다양성의 잔여 교락이 있다. 단일턴 재구성은
실제 자연 다회전의 맥락 길이·대명사·수정 요구를 완벽히 재현하지
못한다. Aya Collection의 많은 행이 템플릿·번역이며 416만을
고품질 한국어 대화 416만 건으로 볼 수 없다. 외부 instruct 모델과
TinyLM의 과거 점수는 공통 harness 재평가 전까지 직접 비교 불가다.
한 번의 생성 샘플이나 단일 시드 개선은 지능 승격 근거가 아니다.

## 9.1 2026-09-23 Stage0W 원답안 패널 착수

사용자 승인 범위에서 [Stage0W 런처](../run_P100_Stage0W_capability_baseline.sh)를 작성했다. 기존 P097 control-v2/FineWeb2 checkpoint 두 개로 한국어·영어 지식, 제공문맥, JSON 형식, 단기기억, 논리·부정의 9개 공개/합성 문항을 각각 base와 QA 형식으로 생성한다. checkpoint·tokenizer SHA, final val 메타데이터, 전체 prompt와 원답안을 별도 JSONL에 기록한다. GPU 추론·원답안 사람 검토는 사용자 실행 전 `NOT_RUN`이다.

이 두 checkpoint는 원천·tokenizer·자기 validation이 서로 달라 **모델 간 결과 차이를 데이터 유형의 인과효과로 계산하지 않는다**. 동일 모델 안에서 두 prompt 형식의 기술적 비교만 우선 한다. gold log-likelihood margin, SFT A1~A3, 보호 held-out 검사는 아직 구현·실행되지 않았으므로 Stage0W를 P100 전체 증명으로 승격하지 않는다. 새 런처의 역할은 P029 역사 5문항보다 넓은 실패 유형의 원답안을 남기는 것이다.
