## 1. 왜 — **삼진의 48.4% 를 한 번도 안 묶었다**

| `mC_wsd` 삼진 54.85M | |
|---|---:|
| MLP | 28.31M (51.6%) |
| ★**어텐션** | ★**26.54M (48.4%)** |

**MLP 축은 소진됐다** — P045 가 g16 에서 종결(−4.7M, +0.0161), P048 이 prelude/coda 로 −12.1M.
**둘 다 MLP 쪽이다.** 어텐션은 `mlp_group` 을 아무리 키워도 **안 줄어든다** — 층마다 독립이기 때문이다.

### 1.1 문헌 근거

**MobileLLM**([`2402.14905`](https://arxiv.org/abs/2402.14905), ✅조회):
*"immediate **block-wise weight-sharing**, **no increase in model size** and only marginal
latency overhead"* → **125M/350M 에서 +0.7%/+0.8%**. ★**우리 규모와 같다.**

**ALBERT**([`1909.11942`](https://arxiv.org/abs/1909.11942), ✅조회): cross-layer parameter
sharing. ★우리는 그 논문의 **두 기법 중 factorized embedding 만** 쓰고 있다.

**외부 검토문서 E §9** 도 *"Full-block sharing 전에 **Attention-only sharing ablation 을
반드시 권장**"* 이라 적었다 — **우리 REVIEW2 와 독립적으로 같은 지점을 지목**했다.

## 2. 절감 (계산)

`attn_group = g` 면 중간 16층이 어텐션 `16/g` 개를 공유한다. prelude·coda(4층)는 그대로.

| g | 유니크 어텐션 | 어텐션 삼진 | **총 삼진** | 대비 |
|---:|---:|---:|---:|---:|
| **1**(현재) | 20 | 26.54M | **54.85M** | — |
| **2** | 12 | ⚙15.92M | ⚙**44.23M** | ⚙**−19.4%** |
| **4** | 8 | ⚙10.62M | ⚙**38.93M** | ⚙**−29.0%** |

⚙ = 계산값. **`report()` 로 확인해야 한다**(단계0).
비교: `mC_g16`(MLP g16)이 **−8.6%** 였다 → **g2 만으로 그 2배.**

## 3. ★예측 — 결과 전에 고정

| # | 예측 | 근거 | 틀리면 |
|---|---|---|---|
| **P1** | **g2 의 대가가 MLP g16(+0.0161)보다 크다.** Δ = **+0.03 ~ +0.08** | ★**어텐션은 위치 의존이 강하다** — 초기 층은 국소, 후기는 전역 패턴을 본다. MLP 는 채널 변환이라 층 간 유사도가 높다 | 작으면 **어텐션도 MLP 만큼 중복** = 큰 발견 |
| **P2** | **효율선(nats/M)이 MLP 축보다 나쁘다** | P1 의 따름. `mC_g16` 0.00341 nats/M 대비 **더 큰 값** | 같으면 **모든 축이 한 선 위** = 결과 032 의 일반화 |
| **P3** | ⚠️**`cla_group` 과 교락한다** | `cla_group=2` 가 이미 K/V 를 공유한다. 공유 어텐션이 **소유층·재사용층 양쪽**에 선다 | ★**그래서 `cla_group=1` 대조가 필수**다 |
| **P4** | `grad_max` 가 오른다 | 같은 파라미터가 여러 위치에서 gradient 를 받는다 | — |
| **P5** | **부모초기화가 평균 이식**으로 간다 | 교사는 층마다 독립 → `mid_mlps` 그룹 평균과 같은 형태 필요 | ★**미구현이면 결과 041 이 재발**한다 |

> ★**P1 을 "나쁘다" 로 예측하는 이유**: 이 축은 **크기가 커서** 하는 것이지 **싸서** 하는 것이 아니다.
> 대가가 크더라도 **−19.4% 라는 크기**가 그것을 상쇄할 수 있는지가 질문이다.
> **채택 임계**: 결과 032 의 효율선(**0.0037 nats / 유니크삼진 100만**)을 적용하면
> g2 의 예상 대가는 **10.62M × 0.0037/M ≈ +0.039**. → **+0.039 보다 나쁘면 이 축은 비효율**이다.

## 4. ✅ 구현 완료 (2026-08-13)

| 구현 | 어디 | 기본 |
|---|---|---|
| `cfg.attn_group` | `config.py` (+`__post_init__` 검사) | **1 = 층마다 독립 = 비트 동일** |
| 공유 어텐션 풀 `mid_attns` | `transformer.py` — `mid_mlps` 와 **같은 형태** | g=1 이면 생성 자체를 안 한다 |
| 참조 방식 | `Layer._attn_ref = [attn]` — **모듈 등록 회피**(파라미터 이중계수 방지) | MLP 와 같은 수법 |
| `Layer.attn_mod` 프로퍼티 | 공유면 참조, 아니면 자기 것 | ★**밖에서 `layer.attn` 을 쓰던 곳(`compute_kv`·이식)을 전부 이걸로 바꿨다** |
| CLI | `--attn-group` | 미지정 = 프리셋 = 비트 동일 |
| json | `attn_group` | |

⚠️★**공유 어텐션은 `owns_kv=True` 로 만든다** — 어느 위치에 서든 K/V projection 이 있어야 한다.
**소유 여부는 층이 정하고**(`i % cla_group == 0`), 어텐션 객체는 호출에서 `kv` 를 받는다.

### 4.1 🚫 아직 안 한 것 — **부모초기화 평균 이식**

`init_from_dense` 는 **층마다 독립 어텐션**을 가정하고 `ls.attn_mod ← lt.attn_mod` 로 복사한다.
공유면 **마지막에 복사한 교사 층의 값이 남는다**(앞것이 덮인다).

> ★★**이건 결과 041 과 정확히 같은 함정**이다 — "이식했다고 믿는데 사실은 안 됐다".
> **`mid_mlps` 처럼 그룹 평균으로 이식**해야 한다. **단계0 게이트가 먼저 이걸 잰다.**

## 5. 단계 설계

### 단계 0 — **형상·이식 게이트** ⏸ GPU 소 · 수 분 · **선결**

1. `report()` 가 **삼진 44.23M(g2) / 38.93M(g4)** 를 찍는가 — §2 의 계산 검증
2. 파라미터가 **이중 계수되지 않는가**(`_attn_ref` 수법이 동작하는가)
3. ★**부모초기화 후 step0 CE** — `ln(V) − 1.0` 아래인가. **결과 041 의 재발 확인**
4. `cla_group=1` 조합에서도 죽지 않는가

**하나라도 실패하면 단계1 을 안 한다.**

### 단계 1 — **g2** ⏸ GPU 약 3.2h · 태그 `mC_a2`

표준 조건(`mC_wsd` 와 동일) + `--attn-group 2`.

### 단계 2 — **g4** ⏸ 단계1 이 임계 안일 때만 · 3.2h · `mC_a4`

### 단계 3 — ★**`cla_group=1` 대조** ⏸ 단계1 후 · 3.2h · `mC_a2_cla1`

**P3 의 교락을 푼다.** ⚠️`cla_group=1` 은 **KV 캐시가 2배**가 되므로
**메모리 비교는 이 팔을 빼고** 한다.
