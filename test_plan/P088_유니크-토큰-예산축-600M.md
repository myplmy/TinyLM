# 실험계획 P088 — **유니크 토큰 예산 축** (풀 1.2B · 300M → 600M)

> **작성 2026-09-04** · 제안서 [`done/20260903_토큰예산축을-연다-conditional.md`](../proposal/done/20260903_토큰예산축을-연다-conditional.md)
> ★**조건부 승인**(2026-09-03) → **조건 충족 확인 완료**(제안서 §10): 풀 `ko-en_1200000000`
> 이 실재하고 train **1,194,000,000 토큰** = 600M 학습의 **정확히 2.0배**.
> 🚫**1200M 팔은 제외**한다 — 풀 2.4B 가 없고, 만들면 한국어 비율이 **25.1% → 약 12.5%** 로 반토막난다.

## 1. 왜

우리 승자는 **파라미터당 학습 토큰 약 3.7** 이다. 외부는 **8,026~121,739**(**2,169~32,902배**).
★**토큰을 늘려도 배포 상주는 0 증가**다 — 우리 1순위 목표에 정면으로 맞는 유일한 종류의 레버다.

🚫**그런데 한 번도 안 쟀다.** *"작아서 못한다"* 와 *"덜 먹어서 못한다"* 를 아직 못 가른다.

## 2. 질문

★**Q1**: 학습 토큰을 **2배**로 하면 품질이 **dense 계열 자(0.0021)를 넘게** 좋아지나?

## 3. 설계 — ★**한 모델 두 팔, 같은 풀**

| 팔 | 풀 | 학습토큰 | steps | 태그 |
|---|---|---:|---:|---|
| 대조 | `ko-en_1200000000` | 300M | 2,289 | `d12_cla2_r20_p12_t300` |
| ★처치 | **같은 풀** | ★**600M** | **4,578** | `d12_cla2_r20_p12_t600` |

★**풀이 같으므로 시험지(val)가 같다.** 🚫**기존 300M 런(풀 600M)을 대조군으로 쓰지 않는다** —
풀이 달라 무효다(함정 2). **그래서 대조 팔을 새로 돌린다.**

## Stage7 — **공통 원문 bpb 의 자를 실측한다** (⚙0.6h · 학습 0)

> ✅**완료 2026-09-06 — 결과 [075 §15](../test_result/075_20260905_P088-토큰은-스텝이었고-full-val-은-학습데이터였다.md).** 계열 7 · 시드 2~3 → 2σ **0.00014 ~ 0.00378**, 채택 **0.0038**. 🚫★**예측이 빗나갔다** — *'0.008 은 11.6배 과대'* 가 아니라 **2.1배 보수적**이었다. 환산치(0.00069)는 실측의 **1/5.5** 다: **자는 코퍼스마다 따로 잰다**. 정본 `_rulers.BPB_BY_SHAPE`.

### 왜 — 🚫**지금 쓰는 0.008 은 빌린 자다**

`common_bpb.py` 가 인쇄하는 *"0.024 nats ≈ 0.008 bpb"* 는 **폐기된 fallback 0.024** 에서 왔다.
계열 자(dense 0.0021 · 재귀 0.0018 · 타잉 0.0006)를 환산하면 **0.00069 bpb** — **11.6배 차이**다.
🚫**어느 쪽이 맞는지 우리는 모른다.** 공통 원문은 결정적 채점이라 표집잡음이 0 이고,
남는 것은 **학습 시드 잡음**인데 **그것을 공통 원문에서 잰 적이 없다.**

★**그래서 결과 075 §14.2 에서 검정력 0 인 시험을 돌렸다** — 찾으려던 교호작용이 자의 1/5 이었다.

### 어떻게 — 시드 복제가 이미 **14개** 있다

| 계열 | 태그 |
|---|---|
| dense | `d8_dense`/`_s2`/`_s3` · `d12_dense`/`_s2` · `d16_dense`/`_s2` |
| 재귀 | `d12_cla2_r20`/`_s2` · `d16_cla2_r20`/`_s2` |
| 타잉 | `mC_initonly`/`_s2`/`_s3` · `mC_cla2_ag4_r20`/`_s2`/`_s3` |

🚫**한 호출에 전부 넣는다** — `common_bpb` 는 한 호출에 모델이 둘 이상일 때만 비교표를 만든다.
팔 2 로 **Muon ×30·×45** 를 763스텝 표에 마저 넣는다(단계6 이 넷만 넣었다).

### 예측

시드 쌍의 |Δbpb| 가 **0.0007~0.003** 대역이면 계열 자 환산이 맞고 **0.008 은 11배 과대**다.
★**그러면 결과 075 §14.2 의 교호작용 +0.0047 이 유의해진다** — 판정이 바뀐다.
🚫**반대로 0.008 근처가 나오면** 공통 자는 **거친 자**이고, 그것을 아는 것만으로도 값어치가 있다.

### 한계

⚠️시드 **2~3개**라 자 자체의 분산이 크다(n=2 상대 sd 약 52%). **계열별로 가장 큰 값을 쓴다.**
🚫공통 원문은 **영문 전용**이고 **8.7% 오염**돼 있다 — 우리 모델끼리만 유효하다.

## Stage11 — ★★**300M 가족과 600M 가족을 잇는다** (⚙0.3h · 학습 0)

> ★**신설 2026-09-10(2차)** — 열린 질문 **Q2**(*"두 가족을 이으면 토큰의 값어치가 얼마인가"*).
> 🚫**지난 핸드오프가 이 명령을 못 적었다** — 그 이유가 아래 §선결이다.

### 왜

2026-09-09~10 에 **600M 토큰(풀 1200M) 가족**이 넷으로 늘었다
(`d12_r20` · `d14_norecur` · `d16_norecur` · `d18_norecur`, 전부 Muon ×15).
그런데 300M 가족과는 **val 셋이 다르다**(`ko-en_300M/val.bin` vs `ko-en_600M/val.bin`) —
🚫**학습로그 val 로는 절대 못 잇는다**(함정 2 · 결과 047 §19 의 "두 가족" 경고).

★**`common_bpb` 가 유일한 유효 경로**다: 같은 SQuAD 원문 · 같은 바이트 · `bpb = loss/ln2/(bytes/token)`.

### 🚫★선결이 **구조적으로 막혀 있었다** — 그리고 고쳤다

| 선결 | 상태 |
|---|---|
| 두 가족의 체크포인트 8개가 실재하는가 | ✅**전부 해석된다**(2026-09-10(2차) 예행) |
| 🚫★**`--tokens` 가 스칼라였다** | 파일명이 `..._300M_...` / `..._600M_...` 로 갈리는데 **한 값만** 받았다. `resolve_ckpt` 의 전역 검색은 **프리셋만** 넘고 **토큰 칸은 안 넘는다** → 🚫**한 호출에 두 가족을 못 넣는다.** 그리고 `common_bpb` 는 **한 호출에 둘 이상일 때만** 비교표를 만든다 |
| ✅**조치** | ★**`--tokens` 를 모델별로 받게 했다**(`--data` 와 같은 규약). 하나만 주면 **종전과 동일**. ★함정 28 의 같은 수리를 **세 번째**로 한 것이다(`paired_eval --ckpt-tokens` 2026-09-06 · `train --ckpt-tokens` 2026-09-07) |
| ⚠️**함정 28(`--tokenizer-hf TAG=`)** | ✅**해당 없음** — 여덟 모델 전부 우리 native `ko-en` 토크나이저다. **그 플래그를 안 준다** |
| `--ce-chunk` | ✅**기본 0 으로 둔다** — 어휘 32,768 · mb8 · seq1024 = **1.07 GiB 단일 할당**이라 16GB 에서 안전하다. 🚫**바꾸면 과거 bpb 와의 비교가 흔들린다**(E22 는 어휘 262,144 의 문제였다) |

### 무엇을 재나 — **8모델 한 호출**

| 가족 | 모델 |
|---|---|
| 300M(풀 600M) | `d12_cla2_r20_muon15` · `d14_cla2_norecur_muon15` · `d16_cla2_norecur_muon15` · `d18_cla2_norecur_muon15` |
| ★**600M(풀 1200M)** | `d12_cla2_r20_muon15_t600` · `d14_cla2_norecur_muon15_t600` · `d16_cla2_norecur_muon15_t600` · `d18_cla2_norecur_muon15_t600` |

### 사전등록 판정

자 = 공통 bpb **0.0038**(실측, `_rulers.BPB_BY_SHAPE` 에 형상이 있으면 그것).

| 결과 | 판정 |
|---|---|
| 같은 깊이의 300M→600M 차가 **네 쌍 모두 자를 넘는다** | ★**토큰 배증의 값어치를 독립 자에서 확정**한다. 그 값이 정본이 된다 |
| 네 쌍의 차가 **서로 자 안**(고른 이득) | ★**토큰 이득이 깊이와 직교**다 — 047 §19 의 로그 val 판정을 확증 |
| 🚫**서열이 뒤집힌다** | ★**그 자체가 발견**이다 — 결과 075 §11.1 에 전례가 있다(풀이 다르면 뒤집혔다) |
