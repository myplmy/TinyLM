> 관련해서 별도 실험계획 작성바람. P049B 로 하여 학습할때부터 특정 레이어만 반복, 전체
> 레이어를 반복, 레이어 깊어짐에 따라 점진적으로 반복 수 조절 등 반복 조건을 다양화."*

## 0. ★이 계획이 여는 문 — **결과 020 이 닫은 문의 반대편**

결과 020(P031)이 **"추론 시 층 반복(깊이 외삽)"** 을 종결했다: 이득이 없었다.
그 종결 사유가 정확히 이것이다:

> **학습 분포와 추론 분포의 mismatch.** 모델은 *"이 층을 한 번 통과한다"* 로 학습됐는데
> 추론에서 두 번 통과시키면 **본 적 없는 상태**가 들어온다.

★**그러면 학습 때부터 반복시키면 어떻게 되는가.** 그건 **한 번도 안 재 봤다.**
그리고 `infer_repeat`·`repeat_where`·`repeat_kv_reuse` 가 **이미 config 에 있다** —
없는 것은 **학습 경로의 반복**뿐이다.

## 1. 왜 — **파라미터와 계산 깊이를 분리한다**

### 1.1 문헌 근거 (**전부 실제 조회함**)

| 문헌 | arXiv | 무엇을 말하나 |
|---|---|---|
| **Universal Transformers**(Dehghani et al., ICLR 2019) | [`1807.03819`](https://arxiv.org/abs/1807.03819) ✅ | *"parallel-in-time self-attentive **recurrent** sequence model"*. Transformer 를 **재귀적으로 반복**해 parameter count 와 computational depth 를 분리. **dynamic per-position halting** 이 정확도를 올렸다고 보고 |
| **ALBERT**(Lan et al., ICLR 2020) | [`1909.11942`](https://arxiv.org/abs/1909.11942) ✅ | 두 parameter-reduction 기법 = **cross-layer parameter sharing** + **factorized embedding**. ★**우리는 후자만 쓰고 있다**(E=256) |
| **MobileLLM**(Liu et al., ICML 2024) | [`2402.14905`](https://arxiv.org/abs/2402.14905) ✅ | *"**immediate block-wise weight-sharing**, no increase in model size, marginal latency overhead"* — **125M/350M 에서 +0.7%/+0.8%**. ★**우리 규모와 같다** |
| **Mixture-of-Depths**(Raposo et al., 2024) | [`2404.02258`](https://arxiv.org/abs/2404.02258) ✅ | token 별 동적 계산. ★**중요**: *"k is defined a priori... **static computation graph with known tensor sizes**"* — **동적 shape 이 없다** → CPU 불리 판정은 재검토 대상 |
| PoLar / Skip a Layer or Loop It? | [`2606.06574`](https://arxiv.org/abs/2606.06574) ✅ | layer skip/loop 의 입력 의존 프로그램화 |
| ★**Hyper Experts**(Deriy & Cetin, Sakana AI, ICLR 2026 TTU Workshop) | OpenReview `cGD7Nzuihz` ✅ **2026-08-13 전문 읽음** | ★★**"higher-activation"(χ=1, φ>1): 모델 크기를 안 늘리고 각 expert 를 forward 당 여러 번 활성화하는 것만으로 "expanded-pool"(χ>1)의 이득을 따라잡는다.** ★**이것이 정확히 이 계획의 가설**이다. small 규모 = backbone **82M**, LR **1e-3** — **우리 규모·우리 LR 과 일치**. ⚠️단 **이득이 모델이 클수록 커진다**(medium 이 30% 적은 활성화 증가로 같은 이득) → **우리 규모에서는 작을 수 있다.** 판정: `docs/methods/08_paper_review_202608.md` §10 |

### 1.2 ★P049 와 무엇이 다른가 — **혼동하면 두 실험이 같은 것이 된다**

| | **P049**(깊이를 산다) | **P049B**(같은 층을 다시 통과) |
|---|---|---|

## 2. 질문

1. **학습 때부터 반복하면 결과 020 의 mismatch 가 사라지는가**
2. **어떤 반복 조건이 최선인가** — 사용자가 지목한 셋:
   - **(a) 특정 층만 반복**(중간 블록만)
   - **(b) 전체 층 반복**
   - **(c) 깊이에 따라 반복 수를 점진 조절**
3. **반복으로 얻는 품질이 그 계산 비용을 정당화하는가**
4. ★**같은 벽시계에서 "반복 없이 더 오래 학습" 을 이기는가** — §5 의 진짜 게이트

## 3. ★예측 — 결과 전에 고정한다

기준선 `mC_wsd`: full-val **3.6984**, 20층, 약 132분(mC_wsd_s2 기준).

| # | 예측 | 근거 | 틀리면 |
|---|---|---|---|
| **P1** | **중간 블록 2회 반복(계산 깊이 20→36)이 `mC_wsd` 를 이긴다.** Δ = **−0.02 ~ −0.06** | UT·MobileLLM 이 같은 규모에서 이득 보고. 그리고 **결과 038 이 부모초기화(=좋은 출발점)의 몫을 +0.1386 으로** 쟀으므로 표현력이 병목일 여지가 있다 | 못 이기면 **재귀 축이 이 규모에서 죽었다** — 큰 정보 |
| **P2** | ⚠️★**그런데 같은 벽시계의 "더 긴 학습" 에는 진다** | 반복 2회 = 학습 시간 1.8배. **같은 1.8배를 토큰에 쓰면** 결과 006 이 300M→600M 에서 **−0.185**(dense) 를 쟀다. **−0.06 은 그보다 훨씬 작다** | 이기면 **재귀가 토큰보다 효율적** = 설계 방향이 바뀐다 |
| **P3** | **(c) 점진 조절이 (b) 균일 반복을 이긴다** | 후기 층일수록 추상적 = 반복 이득이 클 것 | 안 이기면 스케줄이 무의미 = **(b)로 단순화** |
| **P4** | `grad_max` 가 **오른다** | 잔차 사슬이 길어진다. 결과 032 에서 층 구성 변경이 1.48배 올렸다 | 안 오르면 QK-norm·adaLN 이 잘 잡는 것 |
| **P5** | ⚠️**부모초기화가 반복 구조와 안 맞는다** | 교사는 층마다 독립. 반복 구조에 이식하면 **같은 가중치가 두 역할**을 한다 | ★**이게 P1 을 위협한다** — §4.3 |

> ★★**P2 를 미리 못 박는 이유**: *"깊이를 늘리면 좋아진다"* 는 거의 확실히 맞다.

> **"같은 시간을 토큰에 쓰기"** 다. **채택 임계를 그것으로 잡는다**(§5).

## 4. 설계

### 4.1 선결 구현 C1 — `train_repeat` (config + transformer)

`infer_repeat` 는 **추론 전용**이고 `torch.no_grad()` 하에서만 의미가 있다.
학습 반복은 **backward 를 통과**해야 하므로 별개 구현이다.

```python
# config.py (신규, 전부 기본값 = 종전 = 비트 동일)
train_repeat: float = 1.0        # 중간 블록 통과 배수. 1.0 이면 종전
repeat_mode: str = "uniform"     # uniform | block | progressive
repeat_block: int = 0            # block 모드에서 반복할 그룹 인덱스
```

| 모드 | 동작 | 사용자 지시 대응 |
|---|---|---|
| **`block`** | **특정 MLP 그룹이 담당하는 층만** N회 반복 | (a) 특정 층만 반복 |
| **`uniform`** | 중간 16층 전체를 N회 반복 | (b) 전체 층 반복 |
| **`progressive`** | 층 인덱스가 깊어질수록 반복 수 증가(1,1,2,2,3,3,…) | (c) 점진 조절 |

⚠️★**KV 캐시 소유 규약을 반드시 정해야 한다.** 같은 층을 두 번 통과하면
`cla_group` 의 owner/재사용 스케줄이 **두 번 발화**한다. 두 선택지:

| | 동작 | 위험 |
|---|---|---|
| **재계산**(기본 권고) | 반복마다 K/V 를 다시 만든다 | 계산 ↑, **의미는 명확** |
| 재사용 | 첫 통과의 K/V 를 재사용 | 계산 ↓, ⚠️**두 번째 통과가 낡은 K/V 를 본다** |

**기본은 재계산.** `repeat_kv_reuse` 가 이미 config 에 있으므로 **학습 경로에도 같은 이름**으로 잇는다.

### 4.2 ⚠️ 잔차 크기 문제 — **P049 와 같은 함정**

같은 층을 2회 통과하면 잔차 기여가 2배다. P049 의 `--depth-init gate_scale` 과
**같은 문제·같은 해법**이다. → **P049 단계0 게이트 결과를 그대로 쓴다**(중복 측정 금지).

### 4.3 ⚠️★부모초기화 — **이 실험의 최대 위험**

교사 dense 는 **층마다 독립 어텐션**이다. 반복 구조 학생은 **같은 어텐션이 여러 위치**에 선다.
`init_from_dense` 의 `_depth_map`(2026-08-14)은 **학생 층 수 기준**이라 반복을 모른다.

**선택지 셋** — 단계0 이 고른다:

| # | 방법 | 비고 |
|---|---|---|
| **①** | 반복을 무시하고 **물리 층 수**로 이식(현행) | 가장 단순. 반복 위치는 같은 값을 받는다 |
| ② | 반복이 커버하는 교사 층들을 **평균** 이식 | `mid_mlps` 그룹 평균과 같은 형태 |
| ③ | **부모초기화를 쓰지 않는다**(`mC_solo` 조건) | ⚠️결과 038: 부모초기화 몫이 **+0.1386** → **−0.06 예측을 통째로 삼킨다.** 🚫**비권장** |

★**③을 배제하는 것이 중요하다** — 결과 038 §9 가 부모초기화의 몫을 쟀기 때문에
**부모 없이 재면 재귀 축의 이득이 부모초기화 부재에 묻힌다.**

## 5. 단계 설계

### 단계 0 — **초기화·형상 게이트** ⏸ GPU 소 · 수 분 · **선결**

`scripts/diag_depth_init.py` 를 확장하거나 신규 진단으로:

1. `train_repeat=2.0` 에서 **죽지 않고**

4. 이식 방법 ①②를 **둘 다 재서** 나은 쪽을 고른다

**하나라도 실패하면 단계1 을 안 한다.**

## ★10. 결과 041 이 이 계획에 주는 경고 (2026-08-13)

P049 단계0 게이트가 **깊이 복제 이식이 난수보다 나쁘다**는 것을 쟀다
(step0 CE 난수 10.41 vs prop 12.72). **기전은 합성 불일치** — 교사가 배운 `f` 에
`f` 자신의 출력을 먹인다.

> ★★**P049B 는 그 상황을 학습 전체에 걸쳐 만든다.** 다만 **초기화가 아니라 학습**이므로
> 모델이 적응할 기회가 있다. 그것이 이 계획의 존재 이유이기도 하다.
>
> ⚠️ **그래도 출발점은 같은 문제를 겪는다.** 부모초기화(`--init-from`)를 켠 채 `train_repeat > 1`
> 을 하면 **결과 041 과 같은 상태에서 학습을 시작**한다.
> → **단계0 이 `--depth-init identity` 와 결합해 step0 CE 를 먼저 봐야 한다.**

⚠️ **uniform 모드는 R 을 정수로 반올림한다**(`int(round(R))`). `R=1.5` 는 2 와 같다.
분수 배수가 필요하면 `progressive` 를 쓴다. **이것을 결과문서에 반드시 적는다.**
