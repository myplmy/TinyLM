## 0. ★이 계획이 여는 문 — **결과 020 이 닫은 문의 반대편**

결과 020(P031)이 **"추론 시 층 반복(깊이 외삽)"** 을 종결했다: 이득이 없었다.
그 종결 사유가 정확히 이것이다:

> **학습 분포와 추론 분포의 mismatch.** 모델은 *"이 층을 한 번 통과한다"* 로 학습됐는데
> 추론에서 두 번 통과시키면 **본 적 없는 상태**가 들어온다.

★**그러면 학습 때부터 반복시키면 어떻게 되는가.** 그건 **한 번도 안 재 봤다.**
그리고 `infer_repeat`·`repeat_where`·`repeat_kv_reuse` 가 **이미 config 에 있다** —
없는 것은 **학습 경로의 반복**뿐이다.

### 1.1 문헌 근거 (**전부 실제 조회함**)

|---|---|---|

## 4. 설계

### 4.1 선결 구현 C1 — `train_repeat` (config + transformer)

`infer_repeat` 는 **추론 전용**이고 `torch.no_grad()` 하에서만 의미가 있다.
학습 반복은 **backward 를 통과**해야 하므로 별개 구현이다.

```python
# config.py (신규, 전부 기본값 = 종전 = 비트 동일)
train_repeat: float = 1.0        # 중간 블록 통과 배수. 1.0 이면 종전
repeat_mode: str = "uniform"     # uniform | block | progressive
repeat_block: int = 0            # block 모드에서 반복할 그룹 인덱스
```

| 모드 | 동작 | 사용자 지시 대응 |
|---|---|---|
| **`block`** | **특정 MLP 그룹이 담당하는 층만** N회 반복 | (a) 특정 층만 반복 |
| **`uniform`** | 중간 16층 전체를 N회 반복 | (b) 전체 층 반복 |
| **`progressive`** | 층 인덱스가 깊어질수록 반복 수 증가(1,1,2,2,3,3,…) | (c) 점진 조절 |

⚠️★**KV 캐시 소유 규약을 반드시 정해야 한다.** 같은 층을 두 번 통과하면
`cla_group` 의 owner/재사용 스케줄이 **두 번 발화**한다. 두 선택지:

| | 동작 | 위험 |
|---|---|---|
| **재계산**(기본 권고) | 반복마다 K/V 를 다시 만든다 | 계산 ↑, **의미는 명확** |
| 재사용 | 첫 통과의 K/V 를 재사용 | 계산 ↓, ⚠️**두 번째 통과가 낡은 K/V 를 본다** |

**기본은 재계산.** `repeat_kv_reuse` 가 이미 config 에 있으므로 **학습 경로에도 같은 이름**으로 잇는다.

### 4.2 ⚠️ 잔차 크기 문제 — **P049 와 같은 함정**

같은 층을 2회 통과하면 잔차 기여가 2배다. P049 의 `--depth-init gate_scale` 과
**같은 문제·같은 해법**이다. → **P049 단계0 게이트 결과를 그대로 쓴다**(중복 측정 금지).

### 4.3 ⚠️★부모초기화 — **이 실험의 최대 위험**

교사 dense 는 **층마다 독립 어텐션**이다. 반복 구조 학생은 **같은 어텐션이 여러 위치**에 선다.
`init_from_dense` 의 `_depth_map`(2026-08-14)은 **학생 층 수 기준**이라 반복을 모른다.

**선택지 셋** — 단계0 이 고른다:

| # | 방법 | 비고 |
|---|---|---|
| **①** | 반복을 무시하고 **물리 층 수**로 이식(현행) | 가장 단순. 반복 위치는 같은 값을 받는다 |
| ② | 반복이 커버하는 교사 층들을 **평균** 이식 | `mid_mlps` 그룹 평균과 같은 형태 |
| ③ | **부모초기화를 쓰지 않는다**(`mC_solo` 조건) | ⚠️결과 038: 부모초기화 몫이 **+0.1386** → **−0.06 예측을 통째로 삼킨다.** 🚫**비권장** |

★**③을 배제하는 것이 중요하다** — 결과 038 §9 가 부모초기화의 몫을 쟀기 때문에
**부모 없이 재면 재귀 축의 이득이 부모초기화 부재에 묻힌다.**

## 12.6 ★단계1 의 성공 기준을 **지금** 적는다 (함정 34 규칙 1)

> **R=2 가 `mC_wsd` 보다 `paired_eval` full-val 로 −0.024 이상 좋으면 축이 살아 있다.**
