- **상태**: 🔜**계획**. 단계0 은 **선결 없음**(학습 0 · 구현 ⚙1.5h)
- **제안**: 사용자 지시 2026-08-31
- **근거 논문**: [arXiv:2309.17453](https://arxiv.org/abs/2309.17453) *Efficient Streaming Language Models with Attention Sinks* (ICLR 2024)
- **선행**: [`docs/methods/04_context_length.md`](../docs/methods/04_context_length.md) §4.2.2·§4.4 ·

## 0. ★왜 지금인가 — **KV 를 줄이는 축이 하나 닫혔다**

| 축 | 무엇을 줄이나 | 상태 |
|---|---|---|
| `--repeat-kv-reuse` | **엔트리 수** | 🚫**기각**(결과 062: 대가가 재귀 이득의 5.4배) |
| ★**bf16 KV**(P077 단계1) | **엔트리당 바이트** | ✅**2026-08-30 구현.** 대가 미측정 |
| **KIVI 2bit**(P077 단계2) | 같음, 더 공격적 | ⏸bf16 결과 대기 |
| ★★**StreamingLLM**(이 계획) | ★**엔트리당 토큰 수** | 🚫**계획서가 없었다** |

★★**셋은 곱해진다**: `KV = 엔트리 × 토큰 × 바이트`.
결과 062 가 **엔트리** 항을 닫았으므로 남은 것은 **토큰**과 **바이트**다.
→ ★**StreamingLLM 은 "토큰" 항을 다루는 유일한 후보**이고, `04_context_length` §4.4 가
**#4 로 순위만 매겨 놓고 계획서를 안 만들었다.**

### 0.1 ★KIVI 와 무엇이 다른가 (사용자 질문)

| | KIVI (P077) | ★**StreamingLLM (P081)** |
|---|---|---|
| 무엇을 바꾸나 | K/V 값의 **정밀도** | ★**보관할 K/V 의 개수** |
| 컨텍스트 의존 | KV 가 **여전히 seq 에 선형** | ★**seq 와 무관한 상수가 된다** |
| 재학습 | 불필요 | 불필요 |
| 구현 | 커널 필요(⚙6h) | ★**마스크·슬라이싱만**(⚙1.5h) |

🚫★**둘은 대체재가 아니라 곱셈 관계**다. 같은 계획에 넣으면 교락된다 — 그래서 분리한다.

## 2. 단계0 — **싱크가 있는가** (⚙**0.4h**, 학습 0 · 구현 포함)

### 2.1 무엇을 재나

신규 `scripts/diag_attention_sink.py`:

| 지표 | 뜻 | 싱크가 있다면 |
|---|---|---|
| 위치 0~3 토큰이 받는 **어텐션 질량 비중**(층·헤드 평균) | 싱크의 크기 | ★**10% 이상** |
| 그 비중의 **층별 분포** | 어느 층이 싱크를 쓰는가 | 깊은 층일수록 크다(논문) |
| ★**재귀 2회차 통과에서도 같은가** | S3 | — |

### 2.2 판정 (사전 확정)

| 관측 | 결론 |
|---|---|
| 위치 0~3 질량 ^> **10%** | ✅**싱크 있음. 단계1 로 간다** |
| 3~10% | ⚠️경계 — 창 크기를 크게 잡고 단계1 |
| ^< **3%** | 🚫**싱크 없음. 이 축을 닫는다** — 우리 모델은 논문과 다르게 동작한다(그것도 결과다) |

⚠️★**우리 모델은 RoPE + QK-norm + CLA 다.** 논문 관측 대상(LLaMA·MPT·Falcon)과
**위치 인코딩·KV 공유가 다르다.** 🚫**싱크가 없어도 이상하지 않다.**

## 3. 단계1 — 잘라도 되는가 (⚙**0.3h**, 학습 0)

`--kv-window W --kv-sink S` 를 붙이고 `paired_eval` 로 재단.

| 팔 | S | W | KV@seq1024 |
|---|---:|---:|---|
| 기준 | — | 전체 | 15.0 MiB |
| **A** | 4 | 512 | ⚙7.6 |
| **B** | 4 | 256 | ⚙3.8 |
| **C** | 4 | 128 | ⚙1.9 |
| ★**D** | 0 | 512 | ⚙7.5 — ★**싱크의 몫을 분리하는 대조** |

★★**D 가 이 단계의 핵심 대조다.** 논문의 주장은 *"창만으로는 무너지고 싱크를 더하면 회복된다"*
이므로, **A 와 D 의 차이가 곧 싱크의 기여**다. 🚫**D 없이 A 만 재면 "창이 통했다" 와
"싱크가 통했다" 를 못 가른다**(함정 2 계열).

⚠️★**`paired_eval` 은 teacher-forced 라 KV 캐시를 안 쓴다.** → 🚫**그 도구로는 못 잰다.**
★**필요한 것**: 캐시를 쓰는 평가 경로. `diag_kvcache.py` 가 **teacher-forced 로짓 동등성**을
이미 재므로 그것을 확장한다(⚙0.3h). ★**이 항목을 단계1 의 선결로 명시한다.**

### 3.1 판정

| 무엇 | 자 | 결론 |
|---|---|---|
| A 대 기준 | **0.0006**(타잉) | 창 512 로 잘라도 되는가 |
| A 대 D | 같음 | ★**싱크의 몫** |
| ★**대가가 0.0107 을 넘으면** | — | 🚫**기각**(결과 062 와 같은 문턱 — 재귀 이득 한 걸음) |

## 4. 단계2 — 긴 컨텍스트 (⚙**0.5h**) ⏸**단계1 통과 후**

seq 2048·4096 에서 KV 가 **상수로 유지되는지** 확인하고 `mem_runtime` 으로 회계.

★**기대**: `04_context_length` §4.4 의 *"seq 4096 + int8 = 37.4 MiB(초과 1.4)"* 가
**StreamingLLM 을 붙이면 창 크기로 고정**된다 → ⚙**W=512 에서 seq 무관 ~19 MiB**.

## 6. ⚠️한계

- 🚫**우리 val 은 seq 1024 크롭**이다. StreamingLLM 의 이득은 **긴 문맥**에서 나오는데
  **그 조건을 우리 평가가 안 만든다** → ★**단계2 가 없으면 이 기법의 값어치를 과소평가**한다.
