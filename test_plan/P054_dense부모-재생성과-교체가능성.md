## 0. ★이 계획은 "복구" 가 아니라 **"교체 가능성 판정"** 이다

재생성은 끝났다. 남은 질문은 하나다:

> **`denseb` 를 `dense` 라는 이름으로 설치해도 되는가.**

### 단계 2 — **격차 0.017 의 출처** ⏸ GPU **0** · 수 분

**학습 없이** 할 수 있는 것부터:

```
python scripts\runlog.py --name P054_stage2 --note "[P054 stage 2] where does the 0.017 gap come from"
python scripts\runlog.py --name P054_stage2 -- python scripts\paired_eval.py --preset m100 --arch dense --data ko-en --tokens 300M --models dense denseb
python scripts\runlog.py --name P054_stage2 -- python scripts\diag_cache.py --data ko-en --tokens 300M
```

★**`paired_eval` 이 핵심**이다. 두 체크포인트를 **같은 크롭 위에서** 비교하면
**eval 샘플링 노이즈가 0** 이 되고, 남는 차이가 **진짜 학습 차이**다.
(결과 015 의 교훈: `final` 로만 비교한다.)

**판정**:

| paired Δ | 해석 |
|---|---|
| **< 0.011**(dense σ) | ②비결정성으로 설명 — **정상**. 저장소 재현성에 문제 없다 |
| 0.011 ~ 0.024 | 경계. ①③을 더 봐야 한다 |
| **> 0.024** | ⚠️★**저장소 재현성 문제.** 같은 명령이 다른 모델을 만든다는 뜻 → **모든 과거 판정의 전제가 흔들린다.** 최우선 조사 |

### 단계 3 — **교체 판정** ⏸ 단계2 후 · GPU 0

단계2 결과에 따라:

| 단계2 | 조치 |
|---|---|
| Δ < 0.011 | ✅ `denseb_best` → `dense_best` 설치 **허용**. 단 **레지스트리에 "다른 런에서 왔다" 를 명시**하고, `--kd-best` 를 쓰는 런은 **그 사실을 조건에 적는다** |
| Δ ≥ 0.011 | 🚫 설치 **금지**. `denseb` 를 **독립 런**으로 레지스트리에 올리고 `--kd-best` 는 **당분간 쓰지 않는다** |

⚠️ **어느 쪽이든 `dense.pt`(final)는 건드리지 않는다.**

### 단계 4 — ⏸ **조건부·낮은 우선순위**: 600M 풀·wsd 로 부모 재학습

오늘의 표준 조건으로 부모를 다시 만들면 **교사가 −0.12 만큼 좋아질 수 있다**(결과 006).
그러면 결과 037 §1 의 *"교사가 학생보다 나쁘다"* 가 해소될지도 모른다.

> ⚠️★**그런데 이건 REVIEW2 의 KD 결정에 종속된다.** KD 를 빼기로 하면 **교사가 필요 없다.**
> 결과 038 이 KD 제거로 **−7.41 GiB + 품질 −0.0208** 을 보였으므로,
> **"교사를 좋게 만든다" 보다 "교사를 없앤다" 가 먼저 검토돼야 한다.**
> → **REVIEW2 전에는 이 단계를 만들지 않는다.**
