# P102A — T1/S1/S2/S3 학습시간 기능 계약과 수정된 MTP 표본 추정

> 제안 계기: [승인된 B안](../proposal/20260923_TinyLM-학습시간-T0-T1-S1-S3-최적화-제안서-approved-on-going.md) 10절. **2026-09-25 현재 S1/S2 작은 모델 기능 PASS, T1/T0 100M 두 팔 사용자 GPU 실행 완료·단일순서 whole-wall 1.01897× 관측; 역순 반복·고정 crop 품질·S3 효과는 NOT_RUN, 기본 채택 보류.**

## 1. 왜

기존 trainer는 전체 logits를 만들고 나중에 CE를 chunk한다. S1은 factorized head의 hidden/up/embedding gradient를 보존해야 한다. S2는 STE 유효가중치의 VJP를 update당 한 번으로 모으되 clipping·mask·anneal을 바꾸면 안 된다. 원안 S3의 선택 분모 식은 보조 loss를 2배로 만드는 결함이 있어 수정된 HT 추정식만 연구한다.

## 2. 질문

| # | 질문 | 증거 |
|---|---|---|
| Q1 | factorized CE row chunk가 full logits reference와 loss·모든 gradient가 같은가 | hidden/up/emb 비교 |
| Q2 | 고정 surrogate의 micro gradient 합에 VJP를 한 번 적용해도 같은가 | toy VJP 등가 |
| Q3 | 선택확률1/2의 MTP 손실이 전체 타깃 수 분모에서 불편추정인가 | 가능한 2/4 선택 전수 |
| Q4 | T1 eval/save cadence만 바꿀 때 실제 host wall에서 무엇이 절약되는가 | 같은 seed·부모·600M pool의 T0/T1 phase-wall JSON |

## 3. 예측

T1은 eval/save 횟수와 그 host wall을 줄일 수 있으나 compile cache 재사용·고정 측정 순서가 전체 wall 차이를 교란한다. 한 시드 한 순서로 채택하지 않는다. 순수 FP32 작은 텐서는 동일해야 한다. 기존 `factorized_ce_chunks` reference는 chunk autograd graph를 backward까지 보존해 메모리 절감이 아닐 수 있으므로, S1 opt-in은 row-chunk 재계산 backward를 별도 사용한다. 실제 GPU peak/whole-wall 이득은 아직 예측일 뿐이다. S2 실제 ternary STE·bf16·mask 버전에서 차이가 날 수 있고 S3 preclip 기대값이 같아도 clipping·Muon update 이후 궤적은 달라진다.

## 4. 단계 설계

### Stage0W — reference 기능 gate

[tensor module](../tinylm/train/p102a_contract.py), [수학 진단](../scripts/diag_p102a_contract.py), [T1 JSON 계약 진단](../scripts/diag_p102a_t1_wall_contract.py)의 self-test를 [SH](../run_P102A_Stage0W_speed_math_contract.sh)로 검사한다. CPU fixture는 모델·GPU 0이며 첫 실패를 뒤 호출의 성공으로 덮지 않는다.

### Stage0bW — S1 TinyLM 소형 모델 기능 gate

[사용자 실행 SH](../run_P102A_Stage0bW_loss_first_model_gate.sh)는 작은 dense 모델의 동일 초기 상태·동일 x/y에서 기존 full CE와 `--loss-first`가 사용하는 hidden→row-recompute CE의 손실, **모든 이름 있는 parameter gradient**, SGD 한 업데이트를 각각 `max_abs≤1e-5`로 대조한다. 이 gate는 CPU·학습 corpus 0·약0.1h이고 불일치는 exit1의 기능 FAIL이다. Codex는 모델을 로딩하지 않으므로 실제 결과는 `NOT_RUN`; 통과해도 CUDA BF16 수치·peak·whole-wall 또는 채택은 증명하지 않는다.

### Stage0cW — S2 실제 STE update cache의 작은 모델 기능 gate

[별도 진단](../scripts/diag_p102a_ste_update_cache.py)과 [사용자 SH](../run_P102A_Stage0cW_ste_update_cache_model_gate.sh)는 세 micro의 동일 TinyLM 소형 모델에서 기존 매-forward `_TernarySTE` 재생성과 opt-in update당 1회 재생성+누적 surrogate VJP를 비교한다. 손실, 이름 있는 전 parameter gradient, clip norm, SGD 한 update의 `max_abs≤5e-5`가 기능 문턱이다. 모델은 미실행이며 `--check-only`만 PASS했다. CPU 정합 통과도 CUDA BF16·whole-wall·peak 개선을 증명하지 않는다.

### Stage1W — T1 eval/save cadence만 다른 100M paired wall screen

[paired SH](../run_P102A_Stage1W_t1_evalsave_pair.sh)는 기존 m100 dense 300M 부모·m100s12 dense CLA2·ko-en 동일 600M exact pool·seed1337·Muon RMS4·compile/default·no-ckpt·WSD/anneal0.80·763step×8×16×1024=100,007,936 논리 학습토큰을 두 팔에서 고정한다. 독립변수는 T0 `eval_every=100, save_every=0` 대 T1 `eval_every=500, save_every=1000` 두 운영 cadence의 결합이다. 각각 태그는 `dense_p102a_t0_s1337`·`dense_p102a_t1_s1337`이고 기존 로그 충돌이 없음을 preflight했다. 사용자 실행 전에는 출력 충돌을 다시 거부한다.

trainer의 `t1_phase_wall`은 step/eval/save/snapshot/final-eval host seconds와 호출 수를 분리하되 추가 CUDA synchronize는 넣지 않는다. [paired 판독기](../scripts/diag_p102a_t1_wall_contract.py)는 다른 조건·누락 필드·잘못된 cadence를 거절하고 whole wall과 eval/save wall을 같이 인쇄한다. T0→T1 고정 순서 한 번은 compile cache·clock·열 영향을 통제하지 못하므로 **원인 스크린**이지 속도 채택 증거가 아니다. eval 횟수가 달라 in-run val 크롭이 달라질 수 있으므로 품질은 같은 checkpoint를 별도 고정 크롭에서 판정한다.

### Stage2W — S1/S2 기본 off trainer 경로 STATIC_ONLY

S1은 `--loss-first`를 명시한 dense·비KD·비compile 별도 태그에서만 정규화 hidden→FP32 row-recompute CE를 쓴다. S2는 `--ste-update-cache`와 별도 `p102a_s2` 태그를 요구하며 dense·비KD·비compile·FP32 STE로 좁혔다. update 시작에 유효 양자화 가중치 그래프를 한 번 만들고, 각 micro는 detached leaf에 gradient를 모은 뒤 clipping 직전 원래 그래프에 VJP를 한 번 전파한다. 기본 logits/KD 경로는 두 옵션 off로 보존한다. CPU 순수 수학은 PASS지만 S1/S2 실제 모델·BF16·peak/whole-wall은 NOT_RUN이다. skip·mask 변경·anneal 변동은 별도 모델 gate에서 확인해야 한다. S3는 P101A 전량 MTP trainer에 `--mtp-sample-half`로만 연결했다. 16 micro 중 각 horizon별 균형8개를 전역 RNG를 건드리지 않는 독립 시드로 뽑고, 전체 update 유효타깃 분모에 포함확률 `p=1/2`의 역수를 곱한다. 이는 고정 batch의 clipping 전 기대값만 보존한다. P006 전량 MTP 모델 기능·품질 기준선 PASS 전에는 S3 사용자 학습 SH나 속도 채택을 열지 않는다. 미검증 코드를 기본 경로로 승격하지 않는다.

이번 재감사에서 S2의 `begin`이 중간 실패하면 이미 만든 `_wq`를 모두 버리고, `finish`는 모든 leaf 동일성을 확인한 **뒤에만** 지운다. fake-module 합성 fixture에서 부분 초기화·치환·abort·한 번의 VJP를 검증했다. trainer는 한 update의 anneal 값을 micro 동안 고정하고, connectivity mask·custom kernel·compile 병용을 guard로 금지하며, non-finite skip은 VJP/clip 뒤 optimizer를 건너뛰고 cache를 지운다. 이 정적·합성 계약은 CUDA BF16 AMP에서의 전 gradient·메모리·속도 검증을 대체하지 않는다.

S3의 HT 보정은 **clipping 전** gradient 기대값에만 적용된다. 예를 들어 전량 gradient가 `2`, 균형 표본 gradient가 동확률 `20` 또는 `-16`이면 기대값은 `2`지만 norm 1 clipping 후 전량은 `1`, 표본 기대값은 `0`이다. Muon의 모멘텀·직교화도 비선형이므로 업데이트·학습 궤적의 동등성은 주장할 수 없다. 전량 MTP 대비 실제 사용자 GPU 품질·목표품질까지 wall을 별도 판정한다.

## 10. 2026-09-26 Stage1Wb — 사용자 선택 C분석 후 동일코드 ABBA 4팔

### 10.1 왜 기존 로그만으로 T1을 채택하지 않는가

[결과093 §9](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#9-2026-09-25-t0t1-훈련-json-직접-검산)의 원 T0→T1 순서는 whole-wall 1836.554→1802.371초, 절감 34.183초(1.01897×)다. 평가·저장은 32.703→7.189초로 25.514초 감소했으므로 **그 부분은 호출 수 8→2·파일 쓰기16→3으로 귀속 가능**하다. 나머지 8.669초 중 step 시간 차이가 7.116초, 그 외 약1.463초는 clock/compile/순서와 분리되지 않는다. 과거 같은 명령의 세션 간 ms/step 드리프트가 최대 7.5%였으므로 이 한 순서의 1.9% whole-wall 차이는 기본값 승격 근거가 아니다. 반대로 평가·저장 절감 자체를 없던 것으로 만들 필요도 없다. 이 C분석으로 새 동일코드 ABBA가 필요한 이유를 확정했다.

### 10.2 체크포인트·디스크 선결 완료, 파일 삭제는 0건

## 2026-10-23 최신 사용자 정정 — 본학습까지의 전체 시간 단축이 목적

이 절은 아래 과거 계획·작은 실행 기록을 삭제하지 않고 **앞으로의 판정 범위**를 정정한다.
소규모 학습으로 지능·벤치마크 성과나 새 방법/구조의 채택을 판정하지 않는다.
가속의 목표는 더 적은 시간에 여러 개선안을 **본학습까지 완료**하여 같은 공식 평가에서
지능·대화 효과를 비교할 수 있게 하는 것이다. 커널 한 구간만 빨라졌다는 이유로 채택하지 않는다.

### 목적·질문·예측

선택된 1안은 수치 정합 원인을 먼저 분리하는 기술 작업이다. 기존 Stage2bW의 FP32
gradient 허용차 통과와 updated weight85개 실패가 동시에 가능했던 경로를 찾는다.
기존 Muon의 BF16 Newton–Schulz가 미세 차이를 크게 만들 수 있다는 가설과,
head의 축약 순서·역전파 정밀도 자체가 다르다는 가설을 분리한다. 어느 쪽도 확정하지 않는다.

### 기술 단계와 본학습 단계의 분리

1. **CPU 준비**: 기존 Muon을 관찰하는 합성 행렬 trace를 추가한다. 동일 입력 대조와
   반올림 경계 대조에서 gradient/NS입력/BF16입력/NS출력/buffer/update를 남긴다.
   모델·학습·GPU·체크포인트 접근은 없다. 이는 실제 TinyLM 원인의 증명이 아니다.
2. **새 승인 뒤 실물 기술 진단**: 같은 부모·자료·batch·loss 분모·fresh optimizer의
   reference/후보를 재사용해 실제 gradient를 한 번 수집하고, 동일한 gradient를 각
   optimizer에 넣는 대조와 head가 만든 서로 다른 gradient의 대조를 분리한다.
   raw/clipped gradient, Muon 이전/이후, tied embedding/projection 합산과 state를 비교한다.
   FP32 연산 진단을 추가할 경우 reference/후보 양쪽에만 같은 정밀도를 적용하고
   기존 BF16 기준선도 남긴다. 제품 optimizer 기본값과 기존 문턱을 조용히 바꾸지 않는다.
3. **본학습**: 기술 정합·메모리·안전 선결을 충족한 후보만 같은 고유 원천·분할·부모·
   실제 입력/assistant 감독량·총 노출·LR/일정으로 계획한 전체 본학습을 완료한다.
   현재 SFT 목표75M 고유 train×4epoch를 작은128/704회 진단으로 대체하지 않는다.
   자료가 아직 부족하면 부족량을 공개하고 전체 준비 전 품질 승자를 고르지 않는다.
4. **최종 평가**: 본학습 완료 모델에서 동일 공식 벤치마크·고정 실제 대화·언어 보존을
   평가한다. 평가 질문/오답을 다음 학습 배치나 교사 생성에 재사용하지 않는다.

### 비용·판정·현재 상태

비용은 자료 준비·tokenization/cache·교사 생성(필요시)·학습·optimizer·평가·저장·재개를
포함한 전체 wall clock으로 기록한다. 기술 정합만으로 지능이 같거나 좋아졌다고 하지 않는다.
작은 시간 관측을 전체 본학습 가속률로 단순 외삽하지 않는다. 동일 노출과 동일 시간 두 축을
혼동하지 않고, 본학습 비용은 실제 정상상태 계측 후 산정한다.

현재23일17시 CPU/GPU 허가는 만료했다. CPU 도구/시험만 준비·실행하며 실물 재진단과
새 본학습·벤치마크는 NOT_RUN이다. 기존 Stage2bW 원형과 문턱은 그대로 보존한다.
새 GPU 런처는 정확 승인창·실물 gradient 회수 경로·명령 동작이 닫힌 뒤 만들며,
이미 만료한 옛 런처를 이름만 바꿔 재실행 가능하다고 안내하지 않는다.

### Preflight

독립변수는 head 계산 경로 및 별도 진단의 NS 정밀도이며 같은 팔에 섞지 않는다.
CPU는 수렴 학습이 아니므로 학습토큰·풀2배 규칙은 해당하지 않는다. 실제 학습에는

## Stage2bW — chat32 위치별 어휘타일 NLL의 제한 동등성·비용 진단

### 1. 왜

첨부 §2.1 우선 요청은 미완이다. 기존 scalar FP32 P102A와 유효 위치 gather/chunk/
checkpoint는 있지만 chat32/BF16 tied head의 위치별 비선형 상류 gradient·전체 update
어휘타일 대조는 없다. 기존 PAD crop의85개 weight 허용차 초과를 숨기지 않고 fixed1024를 유지한다.

### 2. 질문

같은 위치 NLL·입력/tied table/projection 합산 gradient인가? 같은 fresh optimizer
한 update가 기존 허용차 안인가? 시간과 allocator peak는 어떤가?
공식 CCE/Liger kernel 설치/재현이나 일반 지능 향상과 다른 질문이다.

### 3. 예측

행64×어휘32768 logits를 어휘4096 타일로 나누면 동시 logits 버퍼는 작아질 수 있다.
이미 유효 위치 checkpoint를 쓰므로 전체 peak 이득이 작거나, 여러 matmul/LSE/FP32
gradient 재계산 때문에 느릴 수 있다. BF16 오차가 Muon에서 증폭될 수도 있다.

### 4. 단계

CPU: 작은 FP32/float64·CPU BF16, 위치 loss·임의 양/음 상류 gradient·비선형 loss,

diag_p101a_padding_gpu의 로더/update/비교기를 재사용하며 padding은 바꾸지 않는다.
FP32 MATH와 BF16 eager 각각 reference/후보를 같은 초기화·빈 optimizer에서 한 update,
전157 gradient/updated weight/state·loss/preclip norm/row 순서/RNG를 검산한다.
CP 저장0, 모델은 한 번에 하나이며 교사 종료 후에만 입장한다. 기존 next-token shift/
전체-update CE 분모와 reference 64행 chunk/checkpoint를 유지한다.
