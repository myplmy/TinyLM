# P102A — T1/S1/S2/S3 학습시간 기능 계약과 수정된 MTP 표본 추정

> 제안 계기: [승인된 B안](../proposal/20260923_TinyLM-학습시간-T0-T1-S1-S3-최적화-제안서-approved-on-going.md) 10절. 기존 계획 본문을 복제하지 않는 별도 suffix 계획. **현재 순수 CPU reference만 구현·PASS; fused kernel·trainer integration·GPU wall은 NOT_RUN.**

## 1. 왜

기존 trainer는 전체 logits를 만들고 나중에 CE를 chunk한다. S1은 factorized head의 hidden/up/embedding gradient를 보존해야 한다. S2는 STE 유효가중치의 VJP를 update당 한 번으로 모으되 clipping·mask·anneal을 바꾸면 안 된다. 원안 S3의 선택 분모 식은 보조 loss를 2배로 만드는 결함이 있어 수정된 HT 추정식만 연구한다.

## 2. 질문

| # | 질문 | 증거 |
|---|---|---|
| Q1 | factorized CE row chunk가 full logits reference와 loss·모든 gradient가 같은가 | hidden/up/emb 비교 |
| Q2 | 고정 surrogate의 micro gradient 합에 VJP를 한 번 적용해도 같은가 | toy VJP 등가 |
| Q3 | 선택확률1/2의 MTP 손실이 전체 타깃 수 분모에서 불편추정인가 | 가능한 2/4 선택 전수 |

## 3. 예측

순수 FP32 작은 텐서는 동일하지만, S1의 각 chunk autograd graph는 backward까지 저장돼 실제 memory 절약이 아닐 수 있다. S2 실제 ternary STE·bf16·mask 버전에서 차이가 날 수 있다. S3 preclip 기대값이 같아도 clipping·Muon update 이후 학습 궤적은 다르다.

## 4. 단계 설계

### Stage0W — reference 기능 gate

[tensor module](../tinylm/train/p102a_contract.py)과 [진단](../scripts/diag_p102a_contract.py)을 [SH](../run_P102A_Stage0W_speed_math_contract.sh)로 검사한다. CPU fixture는 모델·GPU 0이다.

### Stage1W — 실제 trainer opt-in, 미완

S1은 fused/two-pass CE에서 whole-head logits 미생성을 profiler로 증명해야 한다. S2는 실제 `_TernarySTE`의 그래프 재사용/gradient·skip·mask 무효화를 포함한다. S3는 P006 MTP full head가 작동한 뒤에만 열고 전량 MTP와 동일 입력·목표품질까지의 whole-wall로 비교한다. 미검증 코드를 기본 trainer에 선제 연결하지 않는다.

## 5. 판정 기준

| 결과 | 판정 |
