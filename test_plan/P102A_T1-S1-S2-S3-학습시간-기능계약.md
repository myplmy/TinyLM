# P102A — T1/S1/S2/S3 학습시간 기능 계약과 수정된 MTP 표본 추정

> 제안 계기: [승인된 B안](../proposal/20260923_TinyLM-학습시간-T0-T1-S1-S3-최적화-제안서-approved-on-going.md) 10절. **2026-09-25 현재 S1/S2 작은 모델 기능 PASS, T1/T0 100M 두 팔 사용자 GPU 실행 완료·단일순서 whole-wall 1.01897× 관측; 역순 반복·고정 crop 품질·S3 효과는 NOT_RUN, 기본 채택 보류.**

## 1. 왜

기존 trainer는 전체 logits를 만들고 나중에 CE를 chunk한다. S1은 factorized head의 hidden/up/embedding gradient를 보존해야 한다. S2는 STE 유효가중치의 VJP를 update당 한 번으로 모으되 clipping·mask·anneal을 바꾸면 안 된다. 원안 S3의 선택 분모 식은 보조 loss를 2배로 만드는 결함이 있어 수정된 HT 추정식만 연구한다.

## 2. 질문

| # | 질문 | 증거 |
|---|---|---|
| Q1 | factorized CE row chunk가 full logits reference와 loss·모든 gradient가 같은가 | hidden/up/emb 비교 |
| Q2 | 고정 surrogate의 micro gradient 합에 VJP를 한 번 적용해도 같은가 | toy VJP 등가 |
| Q3 | 선택확률1/2의 MTP 손실이 전체 타깃 수 분모에서 불편추정인가 | 가능한 2/4 선택 전수 |
| Q4 | T1 eval/save cadence만 바꿀 때 실제 host wall에서 무엇이 절약되는가 | 같은 seed·부모·600M pool의 T0/T1 phase-wall JSON |

## 3. 예측

T1은 eval/save 횟수와 그 host wall을 줄일 수 있으나 compile cache 재사용·고정 측정 순서가 전체 wall 차이를 교란한다. 한 시드 한 순서로 채택하지 않는다. 순수 FP32 작은 텐서는 동일해야 한다. 기존 `factorized_ce_chunks` reference는 chunk autograd graph를 backward까지 보존해 메모리 절감이 아닐 수 있으므로, S1 opt-in은 row-chunk 재계산 backward를 별도 사용한다. 실제 GPU peak/whole-wall 이득은 아직 예측일 뿐이다. S2 실제 ternary STE·bf16·mask 버전에서 차이가 날 수 있고 S3 preclip 기대값이 같아도 clipping·Muon update 이후 궤적은 달라진다.

## 4. 단계 설계

### Stage0W — reference 기능 gate

[tensor module](../tinylm/train/p102a_contract.py), [수학 진단](../scripts/diag_p102a_contract.py), [T1 JSON 계약 진단](../scripts/diag_p102a_t1_wall_contract.py)의 self-test를 [SH](../run_P102A_Stage0W_speed_math_contract.sh)로 검사한다. CPU fixture는 모델·GPU 0이며 첫 실패를 뒤 호출의 성공으로 덮지 않는다.

### Stage0bW — S1 TinyLM 소형 모델 기능 gate

[사용자 실행 SH](../run_P102A_Stage0bW_loss_first_model_gate.sh)는 작은 dense 모델의 동일 초기 상태·동일 x/y에서 기존 full CE와 `--loss-first`가 사용하는 hidden→row-recompute CE의 손실, **모든 이름 있는 parameter gradient**, SGD 한 업데이트를 각각 `max_abs≤1e-5`로 대조한다. 이 gate는 CPU·학습 corpus 0·약0.1h이고 불일치는 exit1의 기능 FAIL이다. Codex는 모델을 로딩하지 않으므로 실제 결과는 `NOT_RUN`; 통과해도 CUDA BF16 수치·peak·whole-wall 또는 채택은 증명하지 않는다.

### Stage0cW — S2 실제 STE update cache의 작은 모델 기능 gate

[별도 진단](../scripts/diag_p102a_ste_update_cache.py)과 [사용자 SH](../run_P102A_Stage0cW_ste_update_cache_model_gate.sh)는 세 micro의 동일 TinyLM 소형 모델에서 기존 매-forward `_TernarySTE` 재생성과 opt-in update당 1회 재생성+누적 surrogate VJP를 비교한다. 손실, 이름 있는 전 parameter gradient, clip norm, SGD 한 update의 `max_abs≤5e-5`가 기능 문턱이다. 모델은 미실행이며 `--check-only`만 PASS했다. CPU 정합 통과도 CUDA BF16·whole-wall·peak 개선을 증명하지 않는다.

### Stage1W — T1 eval/save cadence만 다른 100M paired wall screen

[paired SH](../run_P102A_Stage1W_t1_evalsave_pair.sh)는 기존 m100 dense 300M 부모·m100s12 dense CLA2·ko-en 동일 600M exact pool·seed1337·Muon RMS4·compile/default·no-ckpt·WSD/anneal0.80·763step×8×16×1024=100,007,936 논리 학습토큰을 두 팔에서 고정한다. 독립변수는 T0 `eval_every=100, save_every=0` 대 T1 `eval_every=500, save_every=1000` 두 운영 cadence의 결합이다. 각각 태그는 `dense_p102a_t0_s1337`·`dense_p102a_t1_s1337`이고 기존 로그 충돌이 없음을 preflight했다. 사용자 실행 전에는 출력 충돌을 다시 거부한다.

trainer의 `t1_phase_wall`은 step/eval/save/snapshot/final-eval host seconds와 호출 수를 분리하되 추가 CUDA synchronize는 넣지 않는다. [paired 판독기](../scripts/diag_p102a_t1_wall_contract.py)는 다른 조건·누락 필드·잘못된 cadence를 거절하고 whole wall과 eval/save wall을 같이 인쇄한다. T0→T1 고정 순서 한 번은 compile cache·clock·열 영향을 통제하지 못하므로 **원인 스크린**이지 속도 채택 증거가 아니다. eval 횟수가 달라 in-run val 크롭이 달라질 수 있으므로 품질은 같은 checkpoint를 별도 고정 크롭에서 판정한다.

### Stage2W — S1/S2 기본 off trainer 경로 STATIC_ONLY

S1은 `--loss-first`를 명시한 dense·비KD·비compile 별도 태그에서만 정규화 hidden→FP32 row-recompute CE를 쓴다. S2는 `--ste-update-cache`와 별도 `p102a_s2` 태그를 요구하며 dense·비KD·비compile·FP32 STE로 좁혔다. update 시작에 유효 양자화 가중치 그래프를 한 번 만들고, 각 micro는 detached leaf에 gradient를 모은 뒤 clipping 직전 원래 그래프에 VJP를 한 번 전파한다. 기본 logits/KD 경로는 두 옵션 off로 보존한다. CPU 순수 수학은 PASS지만 S1/S2 실제 모델·BF16·peak/whole-wall은 NOT_RUN이다. skip·mask 변경·anneal 변동은 별도 모델 gate에서 확인해야 한다. S3는 P101A 전량 MTP trainer에 `--mtp-sample-half`로만 연결했다. 16 micro 중 각 horizon별 균형8개를 전역 RNG를 건드리지 않는 독립 시드로 뽑고, 전체 update 유효타깃 분모에 포함확률 `p=1/2`의 역수를 곱한다. 이는 고정 batch의 clipping 전 기대값만 보존한다. P006 전량 MTP 모델 기능·품질 기준선 PASS 전에는 S3 사용자 학습 SH나 속도 채택을 열지 않는다. 미검증 코드를 기본 경로로 승격하지 않는다.

이번 재감사에서 S2의 `begin`이 중간 실패하면 이미 만든 `_wq`를 모두 버리고, `finish`는 모든 leaf 동일성을 확인한 **뒤에만** 지운다. fake-module 합성 fixture에서 부분 초기화·치환·abort·한 번의 VJP를 검증했다. trainer는 한 update의 anneal 값을 micro 동안 고정하고, connectivity mask·custom kernel·compile 병용을 guard로 금지하며, non-finite skip은 VJP/clip 뒤 optimizer를 건너뛰고 cache를 지운다. 이 정적·합성 계약은 CUDA BF16 AMP에서의 전 gradient·메모리·속도 검증을 대체하지 않는다.

S3의 HT 보정은 **clipping 전** gradient 기대값에만 적용된다. 예를 들어 전량 gradient가 `2`, 균형 표본 gradient가 동확률 `20` 또는 `-16`이면 기대값은 `2`지만 norm 1 clipping 후 전량은 `1`, 표본 기대값은 `0`이다. Muon의 모멘텀·직교화도 비선형이므로 업데이트·학습 궤적의 동등성은 주장할 수 없다. 전량 MTP 대비 실제 사용자 GPU 품질·목표품질까지 wall을 별도 판정한다.

## 10. 2026-09-26 Stage1Wb — 사용자 선택 C분석 후 동일코드 ABBA 4팔

### 10.1 왜 기존 로그만으로 T1을 채택하지 않는가

[결과093 §9](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#9-2026-09-25-t0t1-훈련-json-직접-검산)의 원 T0→T1 순서는 whole-wall 1836.554→1802.371초, 절감 34.183초(1.01897×)다. 평가·저장은 32.703→7.189초로 25.514초 감소했으므로 **그 부분은 호출 수 8→2·파일 쓰기16→3으로 귀속 가능**하다. 나머지 8.669초 중 step 시간 차이가 7.116초, 그 외 약1.463초는 clock/compile/순서와 분리되지 않는다. 과거 같은 명령의 세션 간 ms/step 드리프트가 최대 7.5%였으므로 이 한 순서의 1.9% whole-wall 차이는 기본값 승격 근거가 아니다. 반대로 평가·저장 절감 자체를 없던 것으로 만들 필요도 없다. 이 C분석으로 새 동일코드 ABBA가 필요한 이유를 확정했다.

### 10.2 체크포인트·디스크 선결 완료, 파일 삭제는 0건

사용자 지시대로 [checkpoints.tsv](../checkpoints.tsv)의 미등록 6건(약4.7GiB)을 먼저 등록했다. chat32 부모 final/best와 P102A T0/T1 final 4건은 keep, T0/T1 best 2건은 ABBA fixed-crop 판독 전 hold다. 현재 디스크 실물 delete 62건·2.737GiB, keep 221건·171.599GiB, hold 2건·1.633GiB이고 보호 참조 또는 hold 본체/delete-best 충돌은 0이다. 저장소 디스크 여유는 확인 시점 721GiB라 신규 네 팔의 final/best 약6.5GiB와 여유 게이트 20GiB를 충분히 덮는다. **AI는 cleanup을 실행하지 않았고** 사용자 ABBA 실행 전에 공간 확보를 위한 실제 삭제는 필수가 아니다. 향후 공간이 부족해지면 사용자 소유의 frozen preview/YES 절차를 별도로 따른다.

### 10.3 사전등록 조건과 사용자 SH

## Stage2dW / Stage2eW — 공식 Liger·CCE 선택형 연결과 다음 수치 게이트

### 1. 왜·질문

사용자가 C 다음 A 다음 B의 선결 구현과 필요한 패키지 설치·CPU 테스트를 승인했다.
가속 목표는 같은 본학습·평가·저장까지의 전체 wall clock 단축이다. 종전 PyTorch 어휘타일의
실제 음성을 공식 Liger/CCE의 실패로 취급하지 않고 이미 끝난85개 재생을 중복 학습하지 않는다.
새 독립변수는 출력 head+CE backend(reference/Liger0.8.5/CCE 고정3de376c exact)뿐이다.

### 2. GPU 실행 전 예측

Liger는 기존 선형+CE 접점이 단순하고 CCE는 작은 rank256 대비 큰 어휘의 메모리 절약에
가치가 있을 수 있다. 그러나 작은 chunk·FP32 계산·checkpoint 재계산·원 Muon의 저정밀
NS 증폭 때문에 이득이 없거나 원 수치 문턱을 넘을 수도 있다. 설치나 CPU 모의 디스패치를
실제 GPU 커널·가속·지능 성과로 해석하지 않는다. CPU 구현 회수 뒤 동기화한 절이며 이를
이미 수행한 단위검사의 사전 등록이라고 주장하지 않는다.

### 4. 구현·비교 계약

tinylm/train/fused_ce.py는 원 hidden→projection→같은 embedding만 넘긴다. packed head는
거부하며 원본 파라미터 복제·detach·추가 shift·자동 fallback은 없다. sum은 기존 전체-update
분모로 정규화하고 none은 per-target 경로를 유지한다. full KL/top-k/ALM 분포가 scalar CE로
대체된 것은 아니다. mtp_sft.components의 ce_backend 기본값은 reference이며 생성 logits는 불변이다.
Liger0.8.5의 frozen-feature/table-only sum dW 반례는 명시 거부한다.

새 진단기는 원 old.one_update와 NS 관찰/재생/원 허용차를 재사용한다. FP32는 autocast와
TF32를 끄고 BF16은 기존 eager 경로를 보존한다. CPU 캡처는 원8GiB 한도·두 팔 동시 보유만
허용한다. checkpoint/teacher/본학습 품질 판정은0이다. phase cap과 aware deadline·새 tag·
source/의존성 SHA를 필수로 받고 보고서 저장·재읽기·출력 뒤 시간검사와 실패 veto를 요구한다.
예상 소요는 미실측이며 최대1200초는 예상시간이나 실행허가가 아니다.

### Stage2iW — 32K·248,320 tied head의 가중 토큰 손실과 실제 옵티마이저 비용

**완료·첫 NS 갱신 음성.** FP32 raw는 통과했고 BF16 raw 및 기본 NS의 첫 update는 음성이었다. 32K·248K의 조건을 고정했다. [결과 093](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-weighted-gpu-tied-head-vocab)

**목적·질문**  원장54의 대어휘 손익과 per-token loss 보존을 실제 GPU에서 검증한다. 이전 실제 FP32 세 경로는 작은 Native 부모의 scalar CE였고 원 연산 편차 가설을 보존한다. 이번에는 각 어휘 폭 및 정밀도 내에서 head 구현만 바꾼다. 전체 정식 학생은 사용하지 않는다.

**예측**  넓은 어휘에서는 materialized FP32 logit이 큰 peak를 만들고 fused 또는 vocab tile에서 감소할 수 있다. per-token 가중치 backward, BF16 양자화, 입력/출력 table의 공유 gradient와 Muon 경로는 비트 또는 허용차를 벗어날 수 있다.

**설계·판정**  FP32 32K/248320, BF16 32K/248320 네 자식마다 같은 고정 seed의 합성 token/가중치 및 동일 초기 tied table·projection을 쓴다. rank 256, hidden 768, 512행 중 매 아홉 번째에 ignore=-100을 사용하고 shift는 한 번만 한다. Reference, Liger, CCE exact, PyTorch vocab tile 8,192를 각각 3스텝 실행한다. embedding/table·projection은 입력/출력에서 각각 같은 파라미터다. AdamW와 Muon은 실제 적용하며 첫 스텝 per-token NLL, raw gradient 및 두 값의 update를 대조한다. 수치는 이전 `atol=2e-6 rtol=1e-5`(gradient/update), `atol=1e-5 rtol=1e-4`(loss), 마스크 위반 0, 전체 실행 오류를 그대로 기록한다. 피크 allocated/reserved와 시간은 전체 작은 학습 그래프의 관측이다.

**비용·실행**  고유 태그 `p102a_tied_head_fused_weighted_vocab_v1_20261118`. 이미 확보한 P102A의 fused CE 실행 환경에서 설치나 다운로드 없이 네 자식을 단일 GPU에 직렬로 미리 등록한다. 각 210초 상한과 가용 VRAM 12GiB를 적용한다. 선행 기술 실패는 기록하고 독립 다음 조건을 확인한다. [런처](../scripts/diag_p102a_weighted_head_vocab.py)

**한계**  합성 tied head의 비용·업데이트 진단이다. 어휘 폭 사이를 같은 데이터에 대한 품질 비교로 해석하지 않는다. full-distribution KD·하이브리드 마스킹과 운영 품질을 입증하지 않는다.

### Stage2iaW — FP32 가중 CE에서 Muon의 Newton–Schulz 정밀도를 분리한다

**완료·첫 갱신 허용차 통과.** FP32 NS 진단에서 첫 시점의 모든 검사 대상이 허용차 안이다. 전체 본학습과 기본 채택은 별도다. [결과 093](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-weighted-gpu-fp32-ns)

Stage2iW FP32에서는 32K·248K 모두 첫 raw gradient가 원 허용차 내였지만 projection의 갱신 이후 차이가 남았다. 기존 optimizer 재생 도구의 FP32 cast 치환을 이번 가중 토큰 경로에 사용한다. fused CE의 원 방식·shape·seed·가중치와 AdamW를 고정하고 기존 Muon의 Newton–Schulz 내부만 FP32로 계산한다. 32K/248K에서 각 네 팔×3스텝, 첫 NLL 및 gradient/갱신과 기존 허용차를 유지한다. BF16 loss 경로의 raw 차이는 별도다. 최초 참조의 학습 가중치를 바꾸었을 때의 차이와 같은 optimizer 내 커널 대조를 구분한다. [직렬 큐](../scripts/run_p102a_prism_followups_20261118.py)

### Stage2ibW — 두 어휘 크기에서 top-k와 균등 잔여 질량을 포함한 KL 학습

**완료·메모리 양성 및 시간·update 음성.** 균등 잔여분 KD에서 peak는 줄었다. CPU FP64와 GPU 원미분은 양성, 첫 GPU 업데이트에 허용차 위반이 남았다. [결과 093](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-tiled-kd-topk-uniform-tail)

기존 fused CE 비교는 CE만 사용했다. 32,768과 248,320 어휘에서 FP32 공유 입력·출력 표(폭 256) 및 projection(폭 768)의 dense와 8,192 vocab tile을 대조한다. 합성 top-8 질량 .75와 나머지 토큰에 균등 분배한 .25로 정의한 분포에서 실제 KL을 구하고, 마스크 후 341개/step의 가중 CE+0.3 KL로 양팔에 같은 AdamW를 6회 적용한다. CPU FP64에서는 dense 분포를 직접 구성해 CE·KL 및 양쪽 미분을 대조한다. GPU 첫 갱신의 행별 손실·원gradient·갱신 텐서, 전체 peak allocator와 6개 목적 궤적을 회수한다. 균등 잔여 질량 설계와 실제 교사 및 기본 trainer 채택을 구분한다. 태그는 `p102a_tiled_topk_uniform_tail_v1_20261118`이다.

### Stage2icW — 실제 비균등 분포와 같은 KL을 계산하는 tied head 대조

원장 54의 비균등 잔여분 검증이다. 기존 [Bonsai 원로짓 검산](../handoff/audit/research_20261118_01a1e647/PRISM_NATIVE_RAW_CLOSED_READBACK_v1.json)에서 얻은 짧은 원형 검증용 두 분포를 사용한다. 두 팔 모두 전체 248,320개 확률을 사용한다. 같은 분포를 공유하는 위치들의 logits 기댓값은 확률과 공유 출력 행렬을 곱한 두 rank 벡터에서 계산한다. 독립변수는 전체 logits를 만드는 구현과 8,192 토큰 타일로 정규화하는 구현이다.

같은 합성 토큰·마스크·가중치·초기값에서 각 6회 AdamW, 341개 target/회와 CE+0.3 KL을 적용한다. CPU FP64 loss·gradient를 먼저 대조하고, GPU의 첫 loss·gradient·갱신 허용차는 Stage2ibW와 같다. 후속 전체 시간·할당·예약을 기록한다. 최대 할당 절감이 예상되며 타일 반복으로 시간이 늘 수 있다. 이 두 교사 확률 벡터를 공유하는 조건의 수치·자원 진단이다. 문항마다 다른 교사 확률이나 본체를 포함하는 학습의 비용은 후속 조건이다.

태그는 `p102a_tiled_bonsai_exact_kd_v1_20261118`이다. 단일 GPU 가용 12GiB와 실제 실행 180초 상한을 둔다. Bonsai 전체가 저장되고 GPU를 반환하면 등록한 직렬 큐가 준비된 프로필을 대조해 이어서 실행한다. [진단 런처](../scripts/diag_p102a_tiled_bonsai_exact_kd.py) · [직렬 큐](../scripts/run_wip54_after_bonsai_core6.py)

**소형 CPU 준비 완료.** 메타데이터 표기 판정을 고쳐 FP64 소형 대조를 닫았다. [결과093 §27](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-tiled-bonsai-exact-kd-prepare)

### Stage2icWb — 전 어휘 CPU 검증으로 KL의 공통 기대값 계산을 고정

248,320개 확률에서 최초 FP32 dense 행렬곱으로 구한 KL의 FP64 기준 최대 오차는 0.002251이었다. 타일 쪽 최대 오차는 0.000003156이었다. `v1`의 대기 큐를 중지하고 소스와 준비 프로필을 보존했다. `p102a_tiled_bonsai_exact_kd_v2_20261118`에서는 CE에 dense와 tile을 적용하고, 두 팔의 KL은 같은 분포별 logits 기댓값과 엔트로피를 이용한다. 전체 확률을 직접 곱해 합산한 별도 FP64 기준과 7개 타일 경계 target에서 loss와 미분을 비교한다. 기존 평가가 전량 완료해 GPU를 반환하면 `v2`를 실행한다.

**CPU 준비 완료.** 전 어휘 수치 계약을 검산했고 교정된 GPU 작업을 대기열에 등록했다. [결과093 §28](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-tiled-bonsai-full-vocab-cpu)

### Stage2icWc — 갱신 수치 저장과 장치 반환을 분리한 재시도

첫 GPU 실행은 자원 종료 검사에서 종료 1이었고, 최종 수치 파일이 없었다. `p102a_tiled_bonsai_exact_kd_v3_20261119`는 원 샘플과 12갱신을 유지한다. 현재 프로세스의 저장 직전 allocated/reserved와 소스 일치를 기록하고, 장치 반환은 프로세스가 끝난 뒤 GPU compute 조회로 확인한다. 첫 GPU 원로그·프로필과 동일 샘플을 보존한다.

**실행 완료.** 최대 할당 24.83% 절감과 후속 갱신 시간 2.28배를 확인했다. 첫 projection 갱신의 허용차 위반 2개 때문에 본체 기본 경로 승격은 보류한다. [결과093 §29](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-tiled-bonsai-full-vocab-gpu)

### Stage2idW — 실제 G4 32K 어휘 타일 CE 대조 완료, 갱신 문턱 미달

#### 목적과 영향

원장 54와 P109 4단계에서 기존 optimizer의 실제 G4·BF16 전체 그래프를 확인한다. 똑같은 248,320 어휘 head-only CE+KD를 반복하지 않는다. `trainer.py`와 `cli.py`에 명시적 `--ce-vocab-tile`을 연결하고 기존 위치별 NLL을 재사용한다. 새 값은 실험 로그 및 해당 체크포인트의 재개 조건에 남긴다. 기존 기본·row chunk·dense loss-first의 호출과 기록, 기존 context binding의 기본 해시를 보존한다. CE 전용 팔로 범위를 고정하므로 KD나 학생 MTP와 함께 지정하면 일찍 거절한다. 환경·모델 구조·기존 체크포인트·실제 데이터는 그대로 사용한다.

| 방법 | 비교 목적 |
|---|---|
| 기존 전체 로짓 CE | 이번 G4 본체의 기준이다. |
| 기존 위치 청크·dense loss-first | 위치 청크는 전체 로짓이 이미 생성된 뒤 적용된다. dense loss-first의 범위를 넓히면 기존 연구 경로가 달라진다. |
| 먼저 본체 hidden을 얻고 어휘별 타일 CE | 기존 연구 함수를 사용한다. 같은 임베딩·projection에 입력/출력 양쪽 미분이 더해지는 지점과 실제 메모리 차이를 확인한다. |

#### 설계와 판정

CPU에서는 기존 타깃 shift·`-100` 분모·공유 표/입출력 투영 및 일반 CLI 선택을 확인한다. GPU는 같은 `m100s12_g4`·tied R2·CLA2·G128·seed 1337·WSD·Muon RMS4/AdamW·BF16 AMP·ckpt ON으로 기준과 tile 2,048을 대조한다. 무부모 합성 진단으로 팔당 6×8×2×1,024 = 98,304개 target, 동일 262,144개 생성 토큰에서 추출한다. 같은 원 `train`과 optimizer를 호출한다. 진단의 평가는 같은 두 배치로 제한하며, 체크포인트 함수에는 파일 대신 메타데이터·첫/마지막 수치 비교를 연결한다. 첫 원미분 전체와 첫 optimizer 갱신, 학습 구간 allocated·reserved, 첫 스텝 제외 갱신 시간을 기록한다. `2e-6 + 1e-5×|ref|` 원미분·갱신 기준과 loss 기준 `1e-5 + 1e-4×|ref|`을 별도로 적용한다. BF16 타일 GEMM과 합산 차이가 Muon에서 증폭될 수 있어 수치 불합격도 보존한다. 합성이므로 배포 품질과 정식 P109 속도는 나중에 판정한다.

#### 비용과 실행 조건

태그 `p102a_g4_native_vocab_tile_v1_20261119`의 기존 로그 충돌은 없었다. 과거 G4 계열은 방문 정책 또는 다른 코퍼스다. 표준 비교 학습 토큰을 별도로 검산했다. 진단 두 팔 합계 196,608개 target, WSL CPU1과 단일 GPU, 최대 300초다. 정식 학습·실제 교사·외부 설치·새 체크포인트 파일은 범위 밖이다. P108 장치 반환, 같은 초기값·합성 배치, 정확한 증거 경로를 확인한 뒤 실행한다.

첫 CPU CLI 확인은 단위 없는 토큰 값을 백만 단위로 읽고, 검사 대역이 호출부의 package 진입점을 막지 못해 합성 생성에 들어갔다. 60초 상한의 종료 124로 멈췄고 모델·GPU·저장된 입력은 0이다. `p102a_g4_native_vocab_tile_v2_20261119`는 `0.262144M`을 사용하고 CLI와 실제 학습 사이에서 정확한 262,144와 배치 조건을 확인한다. CPU 인수 대조는 데이터 준비 이전을 검증한다. | 8×2, 활성값 체크포인팅 사용 | 같은 배치에서 어휘 타일 자체의 메모리와 시간 비용을 확인한다. |
| 8×2, 활성값 체크포인팅 해제 | 확보한 VRAM으로 활성값을 더 저장할 때 재계산 시간과 메모리가 얼마나 바뀌는지 확인한다. 일반 CE의 해제 팔도 둔다. |
| 16×1, 활성값 체크포인팅 사용 | 유효 배치와 갱신당 입력 순서를 유지한 채 한 번에 처리하는 행을 두 배로 늘릴 때의 시간과 메모리를 확인한다. |

팔당 12×16,384=196,608 target과 합성 524,288개 시드 고정 cache, 같은 독립 합성 VAL 배치 및 Muon RMS4/AdamW·WSD·삼진 전이를 고정한다. 8×2와 16×1이 매 갱신에서 같은 순서의 실제 크롭을 소비하는지 CPU로 확인한다. 옵티마이저 완료를 동기화해 스텝 시간을 저장 및 평가 전에 잡는다. 첫 micro가 아닌 실제 옵티마이저 상태를 포함한 allocated·reserved를 비교한다. 팔을 별도 프로세스로 최대 90초 처리하고 단일 GPU 앞 팔이 반환될 때 뒤 팔로 간다. 파일 체크포인트 기록은 대체해 0으로 둔다. 정식 자료 소비와 추가 300M은 미실행이다. [실행 코드](../scripts/diag_p102a_g4_tile_training_capacity.py)

첫 CPU 준비는 정상 CLI가 체크포인팅 설정을 위치 인자로 넘기는 부분의 검사 오류로 종료 1이었다. `v2`는 기존 위치 인자와 공개 키워드를 모두 그대로 대조한다. 첫 실행은 합성 캐시 생성과 실제 모델·GPU 진입 전에 끝났다. [첫 CPU 원로그](../test_result/093_log_20261119_P102A_Stage2ijW0_G4_tile_capacity_CPU.txt)

**기술 평가 회수.** CPU 준비에서 12개 갱신의 입력이 두 배치 분할에서 일치했다. CUDA 6조건 중 5조건이 합계 60회 갱신을 완료했다. 일반 CE의 활성값 체크포인팅 해제는 같은 첫 역전파 드라이버 오류로 재시도까지 종료 1이었다. 타일 `8×2`에서 활성값을 저장한 팔이 가장 빨랐고 예약 최대값은 12,852MiB였다. 같은 체크포인팅의 `8×2` 타일은 가장 적은 메모리를 썼다. `16×1` 타일은 배치를 수용했고 후반 갱신 중앙 시간은 늘었다. 정식 비교는 메모리 제약에 맞춰 두 `8×2` 후보를 우선하며 자연어 품질은 여러 seed에서 판정한다. ### Stage2ikW — 위치별 로짓을 재계산하고 전체 로짓 미분의 곱을 유지

별도 미분 재현 연구의 Stage2iiW는 같은 로짓 미분을 주었을 때 전체 BF16 행렬곱 두 개가 기준과 정확히 일치했다고 관측했다. 독립변수는 backward에서 위치 블록별 행렬곱을 사용할지, 위치별로 얻은 BF16 로짓 미분을 전체 배열에 담고 원형의 행렬곱을 수행할지다. `8,192×32,768` BF16 미분 버퍼는 512MiB다. 로짓과 로그확률은 1,024위치씩 만들며, 메모리 측정 중에 전체 로짓이나 전체 로그확률을 보존할 필요가 없다.

전과 동일한 G4 초기값·합성 첫 8,192타깃·누적 분모 1/2·결정론을 사용한다. 프로파일을 봉인하고 CPU의 작은 마스크 예제로 위치별 손실과 세 미분을 대조한다. CUDA는 단일 장치 가용 12GiB, 중단 상한 120초, 예상 10~25초다. 기존 수치 허용차와 전체 parameter gradient의 실제 바이트 일치를 둘 다 측정한다. 같은 전체 행렬곱을 사용하면 그 단계에서 생긴 차이는 제거할 수 있다. 위치별 forward가 로짓 또는 로그정규화를 바꾸면 차이가 남을 수 있어 별도 추적으로 8,192개 NLL과 전체 logits·로짓 미분도 확인한다. 이 추적의 메모리는 F+B 계측에 합치지 않는다. 전체 F+B가 재현돼도 이 결과의 범위는 한 초기 합성 micro다. 연속 optimizer 갱신·실제 마스크 구성·기본 채택·품질과 속도는 별도 검증이다. [실험 코드](../scripts/diag_p102a_g4_full_delta.py)

### Stage2ilW — 조립 미분의 동일 갱신을 정상 G4 학습에서 확인

직전 대조에서 8,192개 위치의 로짓·NLL·로짓 미분과 전체 모델 미분이 일치했다. 일반 CE와 위치별 로짓 재계산·전체 미분 곱의 두 팔을 정상 학습기로 각 6회 실행한다. 기존 P102A의 합성 262,144 ID 캐시와 초기화·결정론을 재사용한다. 유효 학습 배치는 `8×2×1,024=16,384`이며 팔당 실제 98,304타깃이다. 두 팔에 G4 R2·BF16 AMP·활성값 체크포인팅·Muon RMS4/AdamW·WSD의 같은 수치와 학습 전이 조건을 사용한다.

진단에서만 기존 CE 선택 분기에 새 손실을 연결한다. 각 적용 이후 정상 save 호출에서 모델·AdamW·Muon 상태의 텐서 바이트와 스칼라를 비교하고 파일 저장은 0으로 둔다. 같은 입력과 모든 갱신의 상태 재현, 기존 CE 허용차와 학습 구간 최대 할당을 판정한다. 기록된 실제 학습 스텝 시간에는 평가와 지문 생성이 포함되지 않는다. 위치별 GEMM 모양의 차이가 다른 어닐·배치에서 생기면 재현성이 깨질 수 있다. 별도 학습 타일의 자원 결과와 함께 보되, 이 대조는 단일 시드와 고정 크기의 무마스크 합성 CE다. 가용 12GiB 단일 GPU 예상 30~50초, 상한 180초이며 자연어·정식 학습·제품 기본 채택에는 별도 검증이 필요하다. [진단 코드](../scripts/diag_p102a_g4_full_delta_train.py)

**미분 재현 결과.** Stage2iiW의 전체 BF16 행렬곱은 고정 입력에서 기준 미분을 정확히 재현했고 분할 곱의 전체 본체 미분은 허용차를 넘었다. Stage2ikW의 조립 미분은 같은 배치의 전체 미분에서 바이트가 다른 파라미터 0개, F+B 최대 할당 46.61% 감소였다. Stage2ilW는 두 팔의 여섯 갱신 모두 모델·AdamW·Muon 상태가 일치하고 학습 할당이 47.81% 줄었다. 검증 범위는 고정 `8×2` 합성 CE다. 교체 후보의 다음 검증은 사용하는 형상·무시 타깃·손실 분기별 수치와 반복 순서의 성능이다. 별도 타일 방식의 실험은 Stage2ijW에 기록했다. [결과093 §§37~39](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-fixed-logit-vjp)

### Stage2imW — 무시 타깃의 행을 보존하고 더 큰 마이크로배치를 확인

앞서 통과한 무마스크 `8×2`는 재실행하지 않는다. 이 대조는 무시 타깃을 계산 행렬에 0으로 남겨 native의 역전파 행렬 모양을 유지할 때 같은 갱신을 얻는지 확인한다. 새 진단에서 로짓과 로그확률은 1,024위치씩 재계산한다. 위치별 NLL은 원래 타깃 위치로 돌려주고 무시 위치를 0으로 둔다. 전체 BF16 미분을 조립해 두 행렬곱을 수행한다. 마스크의 일부는 위치 블록 전체를 가린다. 기존 로더가 정한 입력과 다음 토큰을 재사용한다.

| 합성 학습 대조 | 유효 배치 및 노출 | 일반 CE와의 판정 |
|---|---|---|
| 마스크 `8×2` | 문맥 1,024·6회·98,304 토큰 위치. 지도 타깃은 CPU에서 별도 집계 | 모든 갱신의 모델·AdamW·Muon 상태, 마스크별 NLL과 실제 지도 타깃 수 |
| 무마스크 `16×1` | 문맥 1,024·6회·98,304 타깃. 같은 순서의 입력을 한 마이크로배치에 묶음 | 더 큰 GEMM에서 각 갱신의 동일 상태와 학습 최대 할당 |

기존 합성 262,144 ID와 G4 R2·seed 1337·BF16 AMP·활성값 체크포인팅·결정론·AdamW/Muon RMS4·WSD를 고정한다. CPU에서 두 layout이 갱신별 같은 원본 입력을 소비하는지, 작은 마스크에서 위치별 NLL과 세 미분이 맞는지, 실제 CLI의 형상을 검산한다. 각 대조에서 양팔의 유일하게 바뀐 계산은 손실 경로다. 0 행을 보존하면 작은 마스크에서 나타난 행 삭제의 교란을 피할 수 있지만, 다른 CUDA GEMM 형상이나 NLL 분모 구현에서 차이가 남을 수 있다. 모든 상태 지문과 기존 CE 허용차를 판정한다. 단일 GPU 가용 12GiB, 팔당 45초·전체 210초 상한이며 네 조건은 별도 프로세스에서 순차 실행한다. 학습 자료와 체크포인트 파일 쓰기는 0이고 모델 파일이나 제품 플래그에는 연결하지 않는다. 정식 품질과 장기 속도는 별도다. [진단 코드](../scripts/diag_p102a_g4_recompute_shapes.py)

**결과 회수.** 마스크 `8×2`와 무마스크 `16×1`은 비교마다 모델·AdamW·Muon 지문 18개가 일치하고 학습 최대 할당을 각각 46.41%, 57.93% 낮췄다. 네 팔은 총 24회 실제 갱신을 완료했다. 위치별 NLL을 기존 ALM 소비 함수에 넣은 CPU 대조에서 같은 BF16 참조와 손실과 미분이 일치했다. 기존 FP32 ALM의 수치는 달랐다. 일반 CE 재현 후보의 공개 선택 경로를 검증한 뒤 실제 사용하는 손실과 형상에서 적용 범위를 정한다. ### Stage2inW — 공개 학습 옵션과 체크포인트로 CE 재계산을 검증

`train --ce-recompute-rows 1024`로 이전 진단의 위치별 로짓과 전체 미분 행렬곱을 선택한다. 기본값 0의 일반 CE, 별도 어휘 타일, 기존 FP32 손실 경로는 각각의 계약을 따른다. 새로운 선택값은 활성일 때만 결과와 학습 체크포인트에 기록한다. 저장된 값과 재개 인자가 다르면 학습 전에 거절한다. 문맥 커서 재개는 소스 무결성 묶음에 활성 손실 코드를 포함한다.

| 변경 경로 | 권한과 영향 |
|---|---|
| `tinylm/train/recomputed_ce.py`, CLI와 trainer | 원장 54와 사용자176의 구현 범위. 기존 tied 표와 projection 접근자를 재사용하고 일반 CE에 명시 선택을 제공한다. |
| 문맥 재개 계약과 플래그·런 레지스트리 | 실제 소스와 선택값을 재검사한다. 기존 엄격 소스 지문은 같은 버전의 재개를 요구한다. |
| 집중 CPU 검사와 GPU 결과 | 작은 합성 모델의 실제 파일 저장·이어학습, 기존 옵션 충돌, 마스크 NLL과 미분을 확인한다. G4에서는 이전 마스크 기준 상태를 재사용해 공개 경로의 여섯 실제 갱신을 검증한다. |

GPU 독립변수는 진단의 임시 손실 연결을 공개 CE 옵션으로 바꾼 것이다. 이전 마스크 `8×2`의 합성 TRAIN 260,834, seed 1337, G4 R2·1024·활성값 체크포인팅·결정론·WSD·AdamW/Muon을 그대로 사용한다. 팔당 98,304 토큰 위치와 지도 65,424개다. 이전 모델과 두 optimizer 지문, 타깃 수, 각 손실 수치가 일치하고 정상 저장 지점에서 선택값이 관측되면 구현 통과다. GPU 단일 장치 가용 12GiB, 예상 25초 이내·상한 120초다. GPU에서 체크포인트를 실제 파일로 저장하는 대신 데이터·상태를 관측한다. 실제 작은 CPU 체크포인트는 격리해 검증한다. 정식 학습 품질과 장기 속도는 범위 밖이다. 공개 옵션을 추가할 때 제품 파일 형태와 dtype이 달라지는 경우에 대한 검사를 같이 수행한다.

**결과 회수.** 공개 옵션으로 GPU 6갱신을 완료하고 기준 모델·AdamW·Muon 지문 18개가 모두 일치했다. 학습 최대 할당은 2,704.77MiB였으며 같은 이전 기준보다 45.38% 낮았다. 작은 CPU 모델에서 실제 체크포인트를 만들고 같은 옵션의 2+2회 재개를 연속 4회와 대조했다. 저장한 옵션이 없는 기본 경로와 일치하지 않는 재개 설정의 처리도 확인했다. 공개 옵션의 더 긴 G4 파일 재개 및 정식 규모의 속도는 검증 대기다. [결과093 §41](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-native-recomputed-ce)

### Stage2ioW — 운영 배치 8×16의 일반 CE 대조와 실제 파일 재개

원장 54의 공개 재계산 CE가 P109 규모의 갱신당 입력을 처리하는지 확인한다. 기준 일반 CE와 공개 `--ce-recompute-rows 1024`는 G4 R2 BF16 AMP, 활성값 체크포인팅, seed 1337, Muon RMS4와 AdamW, WSD, 합성 5,000,000 ID의 동일 캐시를 사용한다. 8×16×1,024로 갱신당 131,072개 위치이며 각 궤적 6갱신에 786,432개다. 명시 `--context-curriculum 6:1024`는 같은 문맥과 소스 소비 순서를 유지하면서 재개 상태를 저장한다. 운영 배치 크기 검증이며 공식 본학습 토큰 수와 별개다.

기준과 후보를 각각 연속 6회 실행한다. 후보는 별도 이름으로 3회 실행하여 정상 학습 체크포인트 한 개를 실제로 저장하고 새 프로세스에서 3회 재개한다. 양쪽 3·6회 경계의 모델, 두 optimizer, 입력과 Torch RNG 및 검증 손실을 비교한다. 같은 수치와 상태를 예상하나, 큰 누적이나 새 프로세스 CUDA 선택의 미세 차이는 실제 시험에서 확인한다. 학습 구간 할당·예약과 첫 갱신을 제외한 중앙 시간, 재개 파일 크기를 기록한다. CPU에서 캐시 SHA·로더의 shift 및 옵티마이저 인수부터 확인한다.

네 단계를 가용 12GiB 이상 단일 CUDA에 순서대로 올린다. 개별 상한 100초, 큐 상한 430초, 예상 2~3분이다. 저장은 이 진단의 고유 경로에 만든 경계 파일만 실제로 수행하며 1GiB를 상한으로 한다. 기존 체크포인트와 정제 경로를 그대로 둔다. 갱신 정합과 운영 배치의 기술 비용을 판정한다. 긴 학습의 실제 품질과 반복 순서의 속도는 별도 대조다. [진단 코드](../scripts/diag_p102a_g4_recompute_operating.py)

### Stage2ipW — 248,320개 어휘에서 전체 G4의 CE 재현과 마이크로배치 확대

원장 54에서 32K의 전체 G4 결과와 248K의 출력부 단독 결과를 이어받는다. 새 실험은 16층 G4 R2의 일반 CE와 공개 재계산 CE가 248,320개 행의 공유 표에서 같은 갱신을 내는지 확인한다. 큰 어휘의 임시 텐서가 줄어들 것으로 예상한다. CUDA의 행렬곱·정규화 선택은 달라질 수 있으므로 상태 일치는 직접 확인한다. 마이크로배치 확대에서는 누산 순서가 달라져 상태 차이를 예상하며, 처리 가능 크기와 시간을 판정한다.

|---|---:|---|
| 기준 | 4×4 | 일반 CE |
| 재계산 | 4×4 | `--ce-recompute-rows 1024` |
| 넓은 재계산 | 8×2 | `--ce-recompute-rows 1024` |

모두 `seq=1024`, 활성값 체크포인팅, 초기 시드 1337, 결정론 BF16 AMP, WSD, AdamW·Muon RMS4로 고정한다. 각 팔 6갱신, 98,304 토큰 위치다. 새 격리 1,000,000개 합성 ID의 `uint32` TRAIN 995,000개와 VAL 5,000개를 독립 시드로 생성한다. 정상 Loader를 사용해 각 팔의 매 갱신 같은 입력과 타깃의 순서 및 65,535를 넘는 ID의 보존을 CPU에서 확인한다. 검증은 팔마다 같은 VAL 배치 2×1,024에서 수행한다. 전수 어휘의 모양만 대조하며 실제 교사 토크나이저·분포와 언어 품질은 별도다.

진단 코드가 격리 캐시와 어휘 수를 주입한다. 공개 CLI와 트레이너의 손실·본체·옵티마이저는 재사용하고 제품 소스·데이터 스키마는 변경하지 않는다. 갱신별 모델·AdamW·Muon과 손실, 원생 JSON의 스텝 시간, 평가와 분리한 학습 최대 할당·예약을 보존한다. 기준과 재계산의 상태 일치 및 할당 개선을 판정한다. 넓은 팔은 같은 데이터 예산에서 실제로 완료한 크기와 비용으로 기록한다. 체크포인트 실파일은 생성하지 않는다.

가용 14GiB 이상 단일 GPU에서 기준, 재계산, 넓은 재계산을 격리 프로세스로 직렬 실행한다. 예상 1~3분, 팔당 100초와 큐 330초를 상한으로 둔다. 8×2의 BF16 전체 로짓 미분 약 3.79GiB를 포함해 예산을 잡는다. 사용 가능 GPU와 런처 소스, V·batch·캐시 SHA·태그를 준비 CPU에서 먼저 대조한다. 실험 태그 `p102a_g4_recompute_248k_v1_20261119`는 기존 32K나 출력부 단독 실험과 구분된다. ### Stage2ipWb — 248K 일반 CE와 재계산 CE의 동형 비교를 복구한다

첫 시험에서 일반 CE `4×4`는 첫 갱신 뒤 역전파의 GPU `device not ready`로 종료 1이었다. 재계산 CE의 `4×4`와 `8×2`는 각각 6갱신을 종료 0으로 마쳤다. 일반 CE 오류의 원인은 미확인이다. 이번 후속은 완료한 두 팔을 재사용한다. 같은 합성 캐시, 갱신당 16,384개 위치의 순서, 6갱신, 검증 형상과 소스를 유지하고 `2×8`의 일반 CE와 재계산 CE만 비교한다. CPU에서 마이크로배치 분할 뒤 각 갱신의 입력·타깃 SHA가 최초 실험과 같은지 확인한다.

새 팔 둘의 초기 모델, 매 갱신 모델·두 optimizer·손실이 일치하면 248K `2×8`에서 재현을 확인한다. 첫 4×4 기준의 전체 궤적은 별도 증거가 필요하다. 같은 형상의 학습 할당·예약과 후반 중앙값을 비교해 규모의 이득을 기록한다. 한 GPU 예상 30~55초, 팔당 100초가 상한이며 기존 `4×4`와 `8×2` 조건의 GPU 실행은 이미 회수했다. [복구 런처](../scripts/diag_p102a_g4_recompute_vocab_pair.py)

**결과 회수.** 격리 폴더 생성 순서를 고친 Stage2ipWc의 `2×8`은 두 팔이 각각 6갱신을 완료했다. 모델·두 optimizer 지문과 손실이 일치했고 최대 할당이 29.65% 줄었다. 재계산 `8×2`는 9,125.14MiB에서 같은 입력 순서를 완료했고 이번 중앙 갱신 시간은 재계산 `4×4`보다 13.48% 짧았다. [결과093 §43](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-248k-recompute)

**Stage2ipWd·We 원인 확인.** 일반 `4×4`의 동일 재시도에서 확장 할당기 `setAccess` 오류와 최소 GPU 가용 177MiB를 재현했다. 프로세스에서 해당 옵션을 끈 대조는 여섯 갱신을 마쳤다. 같은 재계산 `4×4`와 갱신 지문은 일치했고 allocator가 달라진 시간 대조는 제한된다. 재계산 실측에 근거해 248K의 배치 예산을 사용한다. [결과093 §44](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-248k-wsl-map)

### Stage2iqW — 적응 마스킹이 사용하는 FP32 CE와 예측 ID를 재계산에서 보존

원장 54의 적응 마스킹 소비자는 P107의 FP32 `cross_entropy(sum)/count`와 마스크 위치의 argmax를 함께 사용한다. 첫 관측 차이가 다음 마스크의 확률과 학습 입력까지 바꿀 수 있다. 같은 BF16 로짓에서 FP32 로그정규화를 수행하고, 정답 로그확률 한 열을 원 NLL 합산 규칙으로 줄인다. 전체 BF16 로짓 미분을 조립해 두 행렬곱의 원형을 유지한다. 각 행의 최상위 ID도 같은 로짓에서 계산한다. 출력부 재계산이 메모리를 줄일 것으로 예상하지만 행렬곱 shape와 FP32 합산 때문에 미분·상태 일치는 실제로 검증한다.

CPU에서 공유 표·projection 및 입력 미분, 무시 레이블, 동점 argmax와 직접 FP32 참조를 먼저 대조한다. 쿠다에서 P079 16층 G4를 읽어 명시 마스크가 지원하는 R1과 동일 BF16 AMP·math SDPA·AdamW/Muon 및 P107 스케일러를 쓴다. 모델의 명시 마스크 여닫기 및 실제 적응 학습기는 그대로 사용한다. 테스트 프로세스의 출력부만 바꾸며 일반 CE와 재계산을 고정 입력·초기 상태로 비교한다. 각 팔은 마이크로배치 8×512, 그룹당 4micro, 6갱신으로 98,304 입력 위치다. 분리 시드의 합성 원문 256×1,025개와 검증 8×1,025개를 생성한다. 마스크 선택·예측·통계, 두 목적의 분모, 모델·두 optimizer·RNG·스케일러, 학습 최대 할당·갱신 시간을 대조한다. 단계는 P102A의 기술 검증이며 실제 언어 품질이나 P109의 R2 명시 가시성 채택은 별도다.

시험 `p102a_adaptive_fp32_recompute_v1_20261119`의 태그 중복을 확인했다. 두 팔을 단일 GPU에 직렬로 실행한다. 예상 총 1분 이내, 팔당 상한 90초다. 각 팔의 초기 조건이 다르거나 CPU 숫자 게이트가 미달하면 해당 비교를 보류한다. 원본 모델과 보호 자료는 읽기 범위를 지키고, 이 단계에서 모델 파일을 저장하지 않는다. [시험 런처](../scripts/diag_p102a_adaptive_fp32_recompute.py)

**결과 회수.** CPU 두 정밀도에서 참조 미분·예측이 일치했다. GPU 27초에 12회 실제 갱신과 12개씩의 적응 관측을 회수했다. FP32 손실·마스크·예측 ID 및 최종 학습 상태가 일치했고 학습 최대 할당은 37.17% 줄었다. 이 결과는 G4 R1과 해당 합성 조건의 출력부 교체 시험이다. ### Stage2irW — ALM·ACTD 정규화의 계산 행을 줄여 같은 학습을 재현한다

원장 54의 위치별 ALM 출력과 ACTD의 대응 토큰·잔여 확률을 검증한다. 독립변수는 기존 64행 헤드 안에서 손실 정규화의 어휘 중간값을 한 번에 계산하는지 8행씩 재계산하는지다. 행렬곱, CE, 원래의 토큰·교사 희소 지원, ACTD 중복 대응과 고유 잔여 범위, 합산 순서, ALM FP64 로그 꼬리는 유지한다. ALM과 ACTD는 서로 다른 목적이며 목적마다 기준과 재계산만 비교한다.

P079의 기존 16층 G4 R2·CLA2·32,768 어휘 체크포인트를 읽는다. BF16 AMP, 활성값과 헤드 체크포인팅, math SDPA, 결정론, AdamW·Muon, 스케일러 및 갱신 순서를 고정한다. 네 팔이 같은 합성 숫자 ID 풀 128×257에서 문맥 256 입력을 마이크로배치 4·누산 2로 세 번 갱신한다. 팔마다 6,144 입력 위치와 5,376 CE 타깃을 사용한다. ALM은 정렬한 4위치 구간 총 168개, ACTD는 지원 타깃 네 개마다 한 위치씩 총 1,344개에 계산한다. 스크립트는 교사 점수와 이동 타깃을 함께 봉인한다. 이 비교는 학습과 자원 교체 검증이며 자연어 품질 평가를 포함하지 않는다.

CPU에서 각 목적의 원 손실·hidden/공유표/projection 미분을 FP32·BF16으로 대조한다. ALM의 목표 확률 경계와 ACTD 중복·전체 지원을 별도 입력으로 조사한다. GPU에서는 각 목적 안에서 초기·최종 모델·두 옵티마이저·스케일러 및 갱신별 손실·목표 수가 일치해야 같은 학습으로 판정한다. 같은 학습을 재현한 뒤 최대 할당·예약과 첫 갱신을 뺀 중앙시간을 기록한다. 기존 헤드가 이미 64행으로 체크포인팅하므로 절감이 미미할 수 있다. 이번 짧은 순서의 시간은 반복 성능 판정에 사용하지 않는다.

기존 ALM·ACTD 학습이나 P107의 CE 시험은 정규화 재계산을 비교하지 않았다. 새 태그는 `p102a_g4_distill_row_recompute_v1_20261119`이며 사용자 176의 GPU 허가 범위에서 단일 GPU에 네 팔을 격리 프로세스로 올린다. 가용 7GiB 이상, 팔당 상한 70초, 정상 실행 예상 45~75초다. 기존 및 보호 입력의 변경과 새 체크포인트 저장은 0건이다. [실험 코드](../scripts/diag_p102a_g4_distill_normalizers.py)

**결과 회수.** 네 팔의 실제 12갱신이 완료됐다. ALM은 손실과 학습 상태를 재현했고, ACTD는 첫 클리핑 전 미분 노름과 최종 상태가 달랐다. 두 목적의 학습 최대 할당은 1,549.36MiB로 같았고 관측 시간은 늘었다. 두 재계산 후보는 미채택이다. [결과093 §46](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-distill-normalizers)

### Stage2isW — 248K 전체 분포 KL에서 기준 합산과 학습 상태를 재현한다

원장 54의 전체 G4 분포 KD를 검증한다. 독립변수는 같은 248,320개 어휘 학생·교사 로짓으로 계산하는 FP32 KL 구현이다. 정상 전체 KL과 이미 있는 128행 KL 청크를 기준으로 둔다. 후보는 128행씩 정규화한 손실 항을 전체 모양 하나에 채워 원래의 한 번 합산을 유지한다. 역전파에는 원 BF16 학생 로짓과 동결 교사 로짓에서 해당 행의 정규화를 재계산한다. CE, BF16 헤드 행렬곱과 두 목적의 결합은 공통이다.

기존 P079 16층 G4 R2·CLA2의 본체와 32K 공유표 앞부분을 계승하고, 248K로 확장한 나머지 215,552행은 고정 시드로 초기화한다. 원본은 변경하지 않는다. 기존 보호 영역 밖의 995,000개 합성 TRAIN을 재사용한다. 팔마다 마이크로배치 2와 누산 4, 문맥 512, 6갱신으로 24,576개 학습 타깃을 소비한다. 저장한 실제 Bonsai 분포 두 개의 전 로짓을 마이크로배치 안에서 번갈아 주입한다. 동일한 `T=2`, KL 가중치 0.3, BF16 AMP, 활성값 체크포인팅, AdamW·Muon, 결정론, 소스 순서를 적용한다. 합성 학생 ID와 교사 분포의 언어 정렬 및 교사 추론 비용은 별도다.

CPU에서 실제 248K 교사와 7행의 FP32/BF16 학생에 대한 전체 KL 손실과 CE를 결합한 미분을 먼저 대조한다. GPU에서는 초기 상태, 첫 모형 전체 미분, 갱신별 KL·CE·기울기 노름, 마지막 모델·두 옵티마이저를 비교한다. 동일 학습 판단에는 후보의 손실·미분·상태가 모두 일치해야 한다. 기존 청크의 합산 차이는 따로 기록한다. 메모리는 전체 학습 allocated·reserved, 시간은 첫 갱신 뒤 중앙값을 계측한다. 공식 언어 품질과 반복 성능은 별도다.

새 태그 `p102a_g4_full_kl_recompute_v1_20261119`에는 같은 조건의 기존 결과가 없다. 기존 G4 일반 CE의 248K 형상과 출력부 단독 KL 결과는 참고로 재사용한다. 가용 14GiB 이상의 단일 GPU에서 같은 프로세스 한정 allocator 설정으로 세 팔을 직렬 실행한다. 예상 45~90초, 팔당 상한 100초다. 원본 모델 쓰기, 보호 데이터 접근과 새 체크포인트 쓰기는 0건이다. [실험 코드](../scripts/diag_p102a_g4_full_kl_recompute.py)

**결과 회수.** 세 팔 18갱신을 완료했다. 재계산은 기존 전체 KL의 손실·첫 전체 미분·최종 상태를 재현하고 최대 할당을 38.37% 줄였다. 기존 128행 청크의 상태도 일치했으며 해당 경로보다 최대 할당이 11.89% 낮았다. 이번 순서의 후반 중앙시간은 전체 대비 11.34% 길었다. 전체 BF16 로짓과 FP32 합산 배열을 만드는 방식이므로 이를 피하는 헤드까지 검증한 것은 아니다. [결과093 §47](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-full-kl-recompute)

### Stage2itW — 248K 결합 CE·KL 헤드에서 전체 학생 로짓을 생성하지 않는다

원장 54의 factorized tied head에서 한 번에 생성하는 학생 로짓을 128행으로 제한한다. 동일 블록의 FP32 정답 로그확률과 전체 어휘 KL을 계산한다. 전체 합산 팔은 기존의 FP32 합산 배열을 유지하고, 청크 합산 팔은 기존 `--kd-chunk 128`과 같은 순서로 블록 합만 누적한다. 각각 결과093 §47의 전체·청크 기준을 재사용한다. 역전파에는 원 CE 분모와 KL 온도를 보존하고 조립한 BF16 로짓 미분으로 같은 모양의 공유표·입력 행렬곱을 호출한다. 두 팔의 전체 미분과 입력 FP32 교사 로짓은 남는다.

시작 P079, 어휘 확장 시드, 토큰 풀·위치별 두 교사 분포, CE:KL 0.7:0.3, T=2, BF16 AMP, 스케줄·옵티마이저·확장 allocator 설정을 §47과 동일하게 봉인한다. 각 팔 2×4·문맥 512에서 6갱신과 24,576타깃을 소비한다. 첫 CPU 검사는 실제 248K 교사와 타깃 무시 위치를 포함한다. FP32 소비자 미분은 절대 5e-8·상대 1e-5, BF16은 정확 일치를 사용하고 CE와 KL 스칼라는 두 정밀도 모두 일치를 요구한다. GPU는 전부 로짓 함수의 호출을 금지한 채 실제 G4를 갱신한다. 대응 기준마다 손실·첫 전체 파라미터 미분·최종 모델과 두 옵티마이저를 대조한다. 할당·예약과 후반 중앙시간은 이전과의 서로 다른 큐 시점을 밝히고 비교한다.

새 태그 `p102a_g4_joint_ce_kl_v1_20261119`의 두 팔은 같은 실험의 재실행을 피하고 §47 세 기준의 원수치와 소스 지문을 불러온다. 가용 14GiB 이상의 CUDA 한 대에서 예상 35~55초, 팔당 상한 75초다. 사전 CPU 게이트가 통과해야 시작하며 정식 언어 학습·품질 평가·체크포인트 쓰기는 포함하지 않는다. [런처](../scripts/diag_p102a_g4_joint_ce_kl.py)

**Stage2itWb 수정 대조.** v1의 두 팔은 실제 12갱신을 완료했으나 첫 갱신의 KL과 달리 CE가 기준에서 벗어났고 전체 미분도 달랐다. 기존 §33에서 확인한 동일 CUDA 일반 CE의 BF16 로그확률 반올림을 v2의 순방향과 역방향 모두에 적용한다. CPU의 FP32 정규화와 KL은 유지한다. v1 소스와 결과를 보존하고 동일한 기준의 수치와 상태로 두 팔을 다시 판정한다. 태그는 `p102a_g4_joint_ce_kl_v2_20261119`다.

**결과 회수.** v2의 두 팔은 여섯 갱신의 손실과 첫 전체 미분, 최종 모델·두 optimizer를 각각 재현했다. 전체 학생 로짓 없이 기존 전체 합산 대비 최대 할당이 55.38%, 기존 청크 합산 대비 39.25% 줄었다. 이번 청크 합산 후보는 전체 KL 항 배열도 저장하지 않는다. FP32 교사 로짓 입력과 BF16 전체 로짓 미분은 유지된다. [결과093 §48](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-joint-ce-kl)

### Stage2iuW — 전체 교사 입력을 CPU에 두고 128행씩 전송한다

원장 54의 248K 결합 CE·KL에서 1,024×248,320 FP32 교사 원로짓은 970MiB다. 이전 `chunk_sum`의 학생 계산·청크 합·전체 BF16 미분을 보존하고 교사 행의 상주 위치만 바꾼다. 이전의 GPU 상주 행렬은 결과093 §48에서 재사용한다. 신규 두 팔은 CPU 일반 메모리와 페이지 고정 메모리다. 전자는 일반 할당으로 동기 전송하고 후자는 같은 CUDA 스트림에서 비동기 전송한다. 두 팔 모두 128행 최대 121.25MiB를 한 번에 복사한다. 원래 두 교사 분포를 사용하되 밀집 배치 전체를 호스트에 실제 할당한다. 교사 순전파와 실제 토큰 정렬은 별도다.

정규화와 온도뿐 아니라 상류 미분과 합산 순서를 고정하므로 같은 학습 상태를 예상한다. 970MiB의 전체 GPU 입력 대신 128행 버퍼가 필요하다. 순방향·역방향의 재전송은 팔당 논리적 45.47GiB이고, 반복 배치의 호스트 할당과 PCIe 전송으로 전체 학습은 느려질 수 있다. 페이지 고정은 전송 배치를 기다리는 시간을 줄일 수 있으나 호스트 여유가 필요하다.

원 G4 R2·CLA2·동일 248K 확장, 기존 합성 995,000토큰 풀, 두 교사 로짓, `2×4×512×6=24,576` 타깃/팔, CE:KL 0.7:0.3, BF16 AMP, 온도 2, 동일 시드 및 AdamW·Muon을 재사용한다. CPU에서 기존 결합 함수의 FP32·BF16 미분을 먼저 확인한다. GPU는 여섯 갱신의 모든 손실·그라디언트 노름과 첫 전체 미분, 마지막 모델·두 optimizer의 지문을 선행 `chunk_sum`과 정확 대조한다. 같은 상태 및 512MiB 이상 최대 할당 절감을 재현 가능한 교체 후보의 조건으로 둔다. GPU allocated/reserved, 호스트 최고 RSS, 전송 바이트와 후반 중앙시간을 회수한다. 다른 큐 시점의 기준 시간은 관측 비교다.

새 태그는 `p102a_g4_joint_ce_kl_host_v1_20261119`이다. 유효입력 24,576타깃의 2배 이상 풀과 중복·태그를 확인했다. 기존 기준의 두 소스 파일을 원 지문으로 보존하고 새 경로의 소스·조건을 실행 전에 봉인한다. GPU 가용 14GiB 이상·호스트 가용 4GiB 이상을 확인한다. 예상 1분 이내, 팔당 상한 65초다. 출력은 독립 결과 경로에 남긴다. [런처](../scripts/diag_p102a_g4_joint_ce_kl_host.py)

**결과 회수.** CPU 준비와 GPU 두 팔이 종료 0이었다. 각각 여섯 갱신에서 기존 GPU 상주의 손실·첫 미분·최종 모델과 두 optimizer를 정확히 재현했다. 최대 할당이 853.01MiB(18.17%) 줄어 사전 512MiB 기준을 통과했다. 페이지 고정은 일반 메모리보다 전송을 포함한 후반 중앙시간이 짧았다. [결과093 §49](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-joint-ce-kl-host)

### Stage2ivW — 같은 4,096타깃 갱신을 4×2로 묶는다

Stage2iuW에서 재현한 페이지 고정 호스트를 다음에 사용한다. 기존 `2×4×512`의 연속 두 마이크로배치를 배치 차원에서 합쳐 `4×2×512`로 만든다. 샘플·타깃 순서와 업데이트당 4,096타깃 및 여섯 갱신을 보존한다. 새 4×2는 교사 GPU 전체 상주와 페이지 고정 CPU 청크를 각각 사용한다. 옛 2×4는 메모리 변화의 비교 기준이다.

4×2의 두 팔은 저장 위치 외에 같은 학습 상태여야 한다. 마이크로배치 묶음이 바뀐 2×4와는 부동소수점 합산 순서 및 실행 모양이 다르다. 같은 4×2의 대응 손실·첫 전체 미분·최종 모델·두 optimizer가 일치하며 여섯 갱신을 끝내면 실제 확대 대조가 성립한다. 옛 2×4 예약량 4,772MiB는 당시에 정한 연구용 비교선이다. 할당·예약·후반 시간과 호스트 비용을 비교한다. 장치 운영 목표는 후속 단계에 따로 기록한다.

태그 `p102a_g4_joint_ce_kl_host_capacity_v1_20261119`의 중복·토큰 식을 확인했다. 초기화·풀·교사·128행 블록과 승인·가용 자원 조건은 Stage2iuW와 동일하다. CPU에서 갱신마다 펼친 토큰의 완전 일치를 확인한 뒤 4×2 두 팔을 직렬 실행한다. 예상 1분 이내, 팔당 65초 상한을 유지한다. [런처](../scripts/diag_p102a_g4_joint_ce_kl_host_capacity.py)

**결과 회수.** 같은 4×2의 두 팔이 손실·첫 미분·최종 모델과 두 optimizer를 재현하고 모두 종료 0이었다. CPU 페이지 고정의 최대 할당 4,390.45MiB는 종전 2×4 GPU보다 303.49MiB 낮았고 예약 5,054MiB는 282MiB 높았다. 4×2 GPU 상주는 해당 형상에서 더 빨랐다. [결과093 §50](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-joint-ce-kl-host-capacity)

### Stage2iwW — 사용자 운영 목표에서 같은 갱신을 8×1로 처리한다

사용자는 실제 GPU 사용 메모리 약 12~13GB에서 OOM 없이 처리량을 높이는 조건을 요청했다. 같은 4,096타깃 갱신에서 누산 1이 되는 마지막 묶음은 8×1이다. 이전 4×2 GPU 상주를 그대로 재사용하고, 기존 네 마이크로배치를 8샘플로 결합한다. 128행 CE·KL 블록과 전체 FP32 교사 상주, P079 시작 가중치·248,320행 어휘·기존 합성 995,000토큰 풀·동일 배치 순서·여섯 갱신·BF16/AdamW·Muon을 고정한다. 소스와 입력 지문을 봉인한다.

PyTorch의 allocated·reserved와 약 100ms 간격의 `nvidia-smi` 장치 전체 메모리를 모두 기록한다. 카드에서 독립적으로 14GiB 이상 가용한 상태에서 실행한다. 예약 4,772MiB는 역사적 관측치다. 부동소수점 합산 묶음이 다른 기존 4×2와는 상태 동일성이 아니라 완료·처리량·메모리를 비교한다. 실행 시점이 달라 시간 비교는 관측값이다. 새 태그 `p102a_g4_joint_ce_kl_batch8_v1_20261119`, 대상 24,576개, 단일 신규 GPU 팔 예상 1분 이내다. ### Stage2ixW — P109 32K 실제 부모에서 갱신당 131,072타깃의 배치를 비교한다

원장 54에서 248K의 8×1을 확인했다. 본 단계는 P109의 32K 경로에서 P079 G4 R2·CLA2 2,289회 가중치와 공개 `--ce-recompute-rows 1024`를 사용한다. 기존 §42의 초기값은 이번 부모와 달라 속도는 참고한다. 새 8×16과 32×4, 실측에서 허용할 때 64×2에서 각 여섯 갱신을 수행한다. 문맥 1,024·동일 131,072타깃/갱신과 소비 순서, 합성 TRAIN 4,975,000 ID, BF16 AMP와 완전 삼진, fresh AdamW·Muon RMS4, 동일 일정이 공통이다. CPU의 원 `Loader` 세 호출 형상에서 갱신별 펼친 X·Y 지문과 최종 RNG를 대조한다.

일반 `train` 경로에서 생성한 모델에 승인한 부모를 처음부터 strict 로드한다. 학습용 데이터를 읽는 경로와 출력 디렉터리는 실험 범위에 고정한다. 합성 검증은 고정 micro8·2배치로 각 종료 상태마다 한 번 실행한다. 종료 가중치·두 optimizer 지문과 장치 전체 100ms 표본, PyTorch allocated·reserved, OOM 여부와 측정 중앙속도를 기록한다. 마이크로배치 변경 간에는 부동소수점 합산 순서를 포함한 학습 경로가 다르다.

첫 두 배치의 장치 실측으로 64×2의 전체 사용을 선형 추정한다. 12~13GB 요청 범위에 들어갈 것으로 예상되고 손실 없이 남은 실제 VRAM이 충분할 때 다음 팔을 실행한다. 소요 예상 약 2분 내외, 각 팔 상한 100초. GPU 감시는 종료·오류·반환만 담당한다. 태그 `p102a_p109_warm32k_device_batch_v1_20261119`. 6×131,072=786,432 타깃/팔이며 자료 풀은 2배 이상이다. [런처](../scripts/diag_p102a_p109_warm32k_device_batch.py)

**Stage2ixWc 후속.** 8×16과 32×4는 종료 0이었다. 32×4 실측에서 예측한 64×2 장치 16.92GB는 목표를 벗어나 실행하지 않았다. 양쪽 사이의 16×8을 추가해 같은 학습기·토큰 순서·부모와 6갱신에서 메모리·처리량을 확인한다. 태그 `p102a_p109_warm32k_micro16_v1_20261119`에 같은 형상의 결과가 없다. GPU 한 팔 예상 1분 이내, 이전 두 결과를 재사용한다. [런처](../scripts/diag_p102a_p109_warm32k_mid_batch.py)

**결과 회수.** 세 형상에서 18회 실제 학습과 같은 종료 합성 평가를 회수했다. 8×16의 4.94GB·20,077타깃/초가 관측상 가장 효율적이었다. 배치 확대에 따른 메모리·속도 차이와 실제로 시행하지 않은 64×2를 기록했다. [결과093 §52](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-p109-warm32k-device-batch)

**실제 교사 후속.** 248K의 할당 행과 FP32 CE 옵션은 P109의 실제 교사·작성 한영 조건에서 사용했다. 기존 결합 손실의 기본 조건은 유지한다. 실제 88갱신의 품질·시간·장치 비용과 첫 미분 차이는 해당 결과를 참조한다. [결과109 §25](../test_result/109_20261119004016_P109-기존G4-방문-세정책-실제갱신.md#p109-qwen35-real-248k-kl)

### Stage2iyW — 248K 결합 CE·KL의 역전파 미분을 위치 묶음으로 누적한다 ✅ 완료(결과093 §53)

원장 54의 [8×1 기준](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-joint-ce-kl-batch8)은 전체 학생 로짓을 만들지 않지만 역전파에서 4,096×248,320 BF16 미분을 구성한다. 새 팔은 같은 128행 CE·KL 미분을 만들고 최대 512위치씩 입력 쪽 미분과 공유표 미분을 계산한다. 공유표 부분합은 FP32로 누적하고 기존 BF16 출력 반올림을 한 번 적용한다. 두 전방 손실과 CE·KL의 유효 분모를 유지한다. 입력 및 공유표 행렬곱의 합산 모양이 달라 최종 학습 상태가 달라질 수 있다.

같은 P079 부모·어휘 확장 시드·두 저장 FP32 교사 벡터·995,000토큰 합성 풀·재현 입력 순서에서 8×1×512의 6갱신과 24,576타깃을 사용한다. 기존 AdamW/Muon·BF16·128행 청크 합산·교사 GPU 상주·T=2를 고정한다. 기존 완결 8×1 팔은 재사용한다. CPU·CUDA 출력부에서 무시 타깃, 마지막 부분 묶음, CE·KL 각각과 결합 역전파를 점검한다. 순방향은 같아야 하며 미분 상대 L2는 기술 입장 문턱으로 FP32 0.001%, BF16 1%를 사용한다. 전체 첫 미분과 최종 모델·두 optimizer 지문이 일치하면 교체 후보이고, 지문이 다르면 자원과 수치에 근거해 별도 학습 후보 여부를 판단한다.

새 태그 `p102a_g4_joint_ce_kl_bounded_delta_v1_20261119`. 시도 비용은 기존 12.48 GB 이내 예상, 단독 GPU 1분 이내와 120초 상한이다. 기존 할당기 설정을 사용한다. 학습 최대 할당이 512 MiB 이상 줄고 후반 갱신 중앙시간이 30% 이내에서 늘면 별도 품질 비교 후보로 유지한다. 품질 개선은 정식 독립 교과에서 확인한다. 새 학습 체크포인트는 저장하지 않는다.

**결과.** CPU·CUDA 출력부의 순방향 및 미분 기술 입장 통과 후 실제 GPU 6갱신 종료 0이었다. 최대 할당 −1,513 MiB, 장치 최고 12.48→9.81 GB, 후반 갱신 중앙시간 +11.33%다. 첫 손실은 일치했고 첫 전체 미분과 최종 모델·옵티마이저는 달랐다. 사전 조건에 따라 메모리 우선의 별도 학습 후보로 유지한다. [결과093 §53](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-joint-ce-kl-bounded-backward)

### Stage2izW — 한·영 작성 교과와 실제 Qwen 교사에서 512위치 역전파를 비교한다 ✅ 완료(결과093 §54)

원장 54에서 합성 8×512로 확인한 절감이 고정 P109 G4 R2와 짧은 실문장에도 남는지 확인한다. 원장 109의 Qwen3.5 248K BF16 교사와 P079 부모, 기존 할당 어휘 248,066개를 사용한다. [기존 P109 교사 특징 캐시](../test_result/109_20261119004016_P109-기존G4-방문-세정책-실제갱신.md#p109-qwen35-248k-cache-shapes)에서 검증한 4×96 모양으로 교사 특징을 한 번 계산한다. 같은 특징과 같은 크기의 교사 출력부를 두 팔에서 사용한다.

두 팔의 독립변수는 학생 출력부 역전파 작업영역의 최대 위치 수다. 기준은 배치의 유효 위치 전부, 후보는 최대 512개다. `64×96`, 누적 1, G4 R2, BF16, 64행 손실 타일과 FP32 CE, `CE + 0.3 × KL(T=2)`를 고정한다. 기존 352개 학습 행을 원 순서로 네 바퀴 이어 총 22회 갱신한다. 각 팔의 입력 슬롯은 135,168개, 유효 타깃 노출은 49,668개다. 원래의 유일 학습 타깃은 12,417개이며 같은 문장 재노출을 포함하는 기술 진단이다. 기존 4×96의 88갱신은 재사용하되 배치·갱신수가 달라 직접 품질 대조에는 쓰지 않는다.

메모리는 줄어들 것으로 예상하나 후보의 반복 표 미분 누적이 속도를 떨어뜨릴 수 있다. 첫 CE·KL이 일치하고 학습 최고 할당이 512 MiB 이상 줄며 첫 회 제외 갱신 시간 중앙값이 30% 이내로 늘 때 자원 조건을 충족한다. 양 팔 최종 작성 홀드아웃(영어 660, 한국어 888 타깃)에서 각 언어 NLL 증가 0.015 이내, 합계 top-1 감소 2개 이내를 기존 P109 소교과 진단 문턱으로 적용한다. 이는 공식 품질 자가 아니다. 첫 미분·최종 모델·두 optimizer 지문은 등가 교체에 별도로 필요하다. 한 쌍과 이 작성 홀드아웃으로 장기 수렴이나 독립 교과 우세를 판정하지 않는다.

태그 `p102a_g4_joint_ce_kl_authored64_v1_20261119`. WIP177의 WSL CUDA 단독 승인 창에서 실제 두 팔을 순서대로 실행한다. 전체 예상 2~3분, 240초 상한, 카드 점유 13 GB 목표다. CPU에서 입력·부모·교사·계획과 기존 결과를 봉인하고, GPU 샘플과 종료·반환을 기록한다. 체크포인트를 저장하지 않는다.

**실행 이력.** 11월 19일 CPU 준비와 WSL CUDA 68초가 종료 0이었다. 22회씩 갱신해 최대 할당 610.52 MiB 감소를 확인했다. 후반 갱신 중앙값은 0.800초씩으로 한 순서에서는 눈에 띄게 느려지지 않았다. 작성 홀드아웃도 사전 문턱을 충족했다. 모델과 optimizer 상태는 달라 메모리 우선 별도 학습 후보로 유지한다. 후속은 정식 독립 교과, 장기 수렴·반복 순서·정식 예산 비교다. [결과093 §54](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-joint-ce-kl-authored64)

### Stage2izX — 512위치 역전파에서 한 번의 문서 배치를 128로 늘린다 ✅ 완료(결과093 §55)

원장 54의 배치 확대를 확인한다. Stage2izW에서 검증한 352개 작성 행·한영 검증 48개·P079 2,289단계 초기화·Qwen3.5 0.8B BF16의 4×96 특징을 사용한다. 새 태그 `p102a_g4_joint_ce_kl_authored128_v1_20261119`에서 64문서×2회 누적(A)과 128문서×1회(B)를 대조한다. 각 팔은 순서가 같은 유효 배치, 11회 갱신, 135,168개 입력 슬롯과 49,668개 유효 타깃이다. 각 논리 배치의 CE·KL에 유효 타깃 수를 가중해 모든 타깃을 한 번씩 센다.

512위치 미분·BF16·고정 재귀 28방문과 64행 CE·KL 타일, `CE + 0.3 × KL(T=2)`, 같은 AdamW/Muon 학습률(3e-5, 행렬 0.5배), warmup 4와 11회 cosine을 고정한다. 첫 묶음은 원 문서 묶음 순서에서 A→B, 둘째는 2039 시드로 교사 4문서 묶음을 섞어 B→A다. 두 문서 순서 안에서 각각 같은 원 토큰과 표본을 씀을 CPU에서 확인한다. 문서 마스크를 선택적으로 지원하게 된 현재 `transformer.py`를 다시 봉인하며 두 팔은 기존 표준 마스크 경로를 사용한다. 이전 22회 갱신은 배치와 용량의 근거로 재사용한다.

큰 배치는 모델 호출을 줄일 가능성이 있지만, 한꺼번에 더 많은 교사 로짓과 활성값을 올린다. 양 묶음에서 카드 점유 13,000,000,000 B 이하, 영어·한국어 검증 NLL의 상승이 각각 0.015 이하, 합계 top-1 감소가 2개 이하여야 배치 확대 후보다. 첫 갱신 제외 유효 타깃/초가 두 묶음 모두 5% 이상 늘면 속도 우세도 기록한다. 현 용량 문턱에 부딪히면 실제 실패 팔과 성공 팔을 보존한다. 4팔 합계 44회, WSL GPU 약 80~140초와 프로세스 상한 300초, 체크포인트 쓰기 0이다. 작성 교과의 제한된 적응에서 확인하며, 정식 장문 품질·장기 수렴·128문서 전체 위치 미분은 별도 시험이 필요하다.

**실행 이력.** 11월 19일 GPU 113초·44갱신, CPU와 GPU 종료 0 및 반환을 확인했다. 128문서 양 팔이 최고 10,761 MiB 이하에서 한영 검증 문턱을 통과했다. 처리량은 원 순서에서 1.00%, 셔플에서 0.04% 낮았다. 장치 용량 가능성을 확인했고 속도 상향 후보의 기준은 충족하지 못했다. [결과093 §55](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-g4-joint-ce-kl-authored128)

원장 54의 §2.1 공개 코드와 실측 근거를 회수했다. CPU 회귀 83개, 32K·248K의 재계산 상태, 토큰별 소비자와 전체 분포 KL을 확인했다. 512위치 미분은 별도 학습 후보로 기록했다. [결과093 §56](../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md#p102a-wip54-head-contract)
