# P103A — X1 접두부·X2 FFN tile·X3 INT8 활성캐시 기능 계약

> 제안 계기: [승인된 C안](../proposal/20260923_TinyLM-계산량-재설계-X1-X3-추가가속-제안서-approved-on-going.md) 10절. 기존 P024/P091의 역사 계획을 바꾸지 않는 suffix 계획. **toy tensor contract는 PASS; X2/X3 실제 모델 기능 gate 코드는 STATIC_ONLY, 모델/whole-step은 NOT_RUN.**

## 1. 왜

X1은 동일 prefix의 gradient를 모으는 것이 필요하고, 단순 inference KV/no-grad cache는 훈련 정합을 깨뜨린다. X2는 실제 FFN 행/열 slicing이 필요하며 큰 GEMM에 mask만 곱해선 계산이 안 준다. X3의 20M×768 FP32 boundary는61.44GB로 수용 불가하므로 INT8 값+64채널 FP32 scale의 **16.32GB 계산상** 후보를 별개 근사 실험으로 검증한다.

## 2. 질문

| # | 질문 | 증거 |
|---|---|---|
| Q1 | toy shared prefix gradient와 독립 branch gradient가 같은가 | 전 parameter toy VJP |
| Q2 | 네 FFN tile을 모두 선택하면 full SwiGLU 출력이 같은가, 하나만 선택하면 물리 폭이 줄어드는가 | output·GEMM shape |
| Q3 | INT8 per64 cache가16.32GB 산술과 작은 tensor 수치·shape를 만족하나 | q/deq·NRMS·bytes |

## 3. 예측

toy X1과 full tile X2는 같아야 하지만 실제 CLA/SDPA branching과 Muon state는 미구현이다. 작은 난수 X3 NRMS가 낮아도 언어 품질이나 RAM-resident whole-wall이 개선될 것이라는 근거는 아니다.

## 4. 단계 설계

### Stage0W — CPU 기능 gate

[계약 모듈](../tinylm/train/p103a_contract.py)과 [진단](../scripts/diag_p103a_contract.py)을 [SH](../run_P103A_Stage0W_compute_math_contract.sh)로 실행한다. 20GB 실제 할당은 하지 않고 bytes만 계산한다.

### Stage0bW — 비보호 공개 SFT v3의 정확 토큰 접두부 실사

[read-only 진단](../scripts/diag_p103a_prefix_census.py)은 canonical JSONL·manifest SHA·legacy tokenizer SHA를 대조하고, 직렬화된 토큰 ID가 정확히 같은 prefix만 세며 원문을 출력하지 않는다. [재현 SH](../run_P103A_Stage0bW_public_sft_prefix_census.sh)는 최소 공유 길이 32/64/128과 자연 분기 최대4를 같은 로그로 기록한다. Codex가 비보호 공개 v3 train을 직접 읽은 2026-09-24 선결 관측은 2,996행·857,679 직렬화 토큰 중 32토큰 기준 공유 951토큰(0.1109%, 21그룹/43행), 64토큰 기준 83토큰(0.00968%, 1그룹/2행), 128토큰 기준 0이다. 입력 SHA는 `96A3507344FEFCA5072887AB4664DBB9BEDBD37BCD0D01A564220C1008D4F836`, tokenizer SHA는 `3A69001ECC28A5BDF1E951A1036B234C9BDCB847B310252C6D72CFC6C52C48E3`이다. 이 수는 **공개 v3를 가상으로 같은 update에 묶었을 때의 구조적 token occurrence**이고 실제 batch sampler·GPU attention·wall 이득은 아니다. 보호 KnowledgePack은 접근하지 않았으므로 원안 X1 대상의 중복률은 `NOT_RUN`이다.

### Stage0cW — X2 소형 모델의 실제 물리 FFN tile 기능 gate

[모델 진단](../scripts/diag_p103a_model_ffn_tile.py)과 [사용자 SH](../run_P103A_Stage0cW_model_ffn_tile.sh)는 기본 off MLP와 4개 물리 tile 전체 선택의 작은 실제 모델 loss·전 parameter gradient·SGD 한 update를 비교한다. 한 tile만 고르면 gate/up의 행과 down의 열을 실제 64채널로 잘라 `ffn_tiles` reference와 대조한다. 이 opt-in 경로는 정상 forward의 STE 유효가중치를 잘라 계산하므로 full tile 등가는 검증 대상이다. **현재 check-only/구문 PASS, 모델 E2E NOT_RUN.** optimizer 상태는 full-width로 남으므로 이 코드를 곧바로 전체 학습 가속으로 해석하지 않는다.

### X3 고정 윈도우 인덱스 선결 — 실제 모델 경계 전 단계

Transformer의 한 token ID는 왼쪽 문맥·RoPE 절대위치가 다르면 다른 activation이다. 기존 무작위 crop Loader의 token ID만으로 boundary를 재사용하면 **잘못된 학습**이 된다. 순수 CPU [`WindowBoundaryTable`](../tinylm/train/p103a_contract.py)은 고정 전체 윈도우 `[W,S,D]`, 원 token window SHA, parent checkpoint SHA, split layer, `fixed_window_causal_start0_v1` 정책을 묶고, 다른 윈도우·순서·부모·길이의 조회를 거절한다. exact/INT8 조회 fixture PASS는 인덱스 계약일 뿐 실제 lower 모델이 그 hidden을 만들었다는 증명이 아니다. Stage1에서는 무작위 crop을 쓰지 않는 고정 윈도우 sampler와 CLA group 경계·segment/position을 먼저 고정하고 실제 frozen lower→tail 함수/gradient를 사용자 모델 gate에서 확인해야 한다.

### Stage0dW — X3 작은 CLA2 모델 frozen lower/tail exact window gate

[제한된 모델 함수](../tinylm/train/p103a_model_boundary.py)와 [사용자 진단](../scripts/diag_p103a_model_boundary.py), [SH](../run_P103A_Stage0dW_model_boundary.sh)는 4층 CLA2의 완결된 2/2 split에서 embedding/head·하부를 freeze한다. 같은 고정 window의 전체 forward와 detached exact boundary→상부 재개에서 logits·loss·모든 이름 있는 trainable gradient·SGD 한 update를 `max_abs≤5e-5`로 비교한다. INT8 boundary NRMS는 보고만 하며 품질 문턱이 아니다. 코드/`--check-only`는 정적 PASS, **실제 소형 모델은 사용자 실행 전 `NOT_RUN`**이다. 승인안의 실제 M0 16층 12/4, 2M/20M cache·fixed-window sampler·whole-wall·RAM은 아직 검증하지 않았다.

### Stage1aW — 고정 M0 실제16층 CLA2 12/4 CPU 함수 게이트, 사용자 실행

[별도 진단](../scripts/diag_p103a_m0_boundary.py)과 [사용자 SH](../run_P103A_Stage1aW_m0_boundary.sh)는 P101A와 같은 M0 final·tokenizer·cache SHA/조건을 먼저 확인한 뒤 실제16층 모델의 앞12/뒤4 CLA 완결 경계에서 전체 forward와 exact 고정 S+1 window 재개를 비교한다. logits·loss·모든 trainable gradient·한 SGD update가 `max_abs≤5e-5`이면 작은 **실제 부모 함수** 게이트만 PASS다. CPU host RAM 수 GiB, 약0.4h를 예상한다. INT8 NRMS는 보고만 한다. **Codex의 `--check-only`는 체크포인트/메타데이터 접근 경계로 자동 안전 검토가 거절했으므로 미실행**이며 본 모델·2M/20M 캐시·GPU wall·품질도 `NOT_RUN`이다. 거절을 우회해 재검사하지 않는다.

### Stage1W — 실제 모델에서 분리된 계측, 미완

X1은 실제 KnowledgePack/SFT 동일 token prefix 중복률과 trainable prefix VJP, X2는 Stage0cW 모델 gate 뒤 실제 GPU의 4개 tile 작은 GEMM/backward 및 full-width optimizer 상태 비용, X3는2M-token exact 원 dtype frozen-prefix 대 INT8 cache의 hidden/logit/gradient/품질·RSS를 별도로 구현·측정한다. protected 데이터·20M 전량은 사용자 승인과 선결 전 접근하지 않는다.

### Stage2W — 조건부 20M RAM·반복 학습

Stage1의 수치·능력 비퇴행, host RAM 여유, swap0, cache 생성+읽기+마지막 full epoch의 whole-wall gate 뒤에만 연다. X1/X2/X3 이득을 합산하지 않는다.

## 5. 판정 기준

| 결과 | 판정 |
|---|---|
| Stage0 toy VJP, full-tile 출력, q/deq 유한·bytes 일치 | 기능 fixture PASS만 |
| Stage0cW 실제 모델 full-tile loss/전 gradient/update 또는 one-tile 물리폭 불일치 | 기능 FAIL, GPU 속도 평가 금지 |
| Stage0dW frozen lower/tail exact window logits·gradient/update 불일치 | 기능 FAIL, 2M/INT8 확대 금지 |
| Stage1aW 실제 M0 12/4 exact window 함수/gradient/update 불일치 | 기능 FAIL, 2M 확대 금지 |
| X3 16.32GB 계산만 PASS | RAM 적합·품질 PASS 아님 |
| Stage1 frozen exact 대비 quantized tail 성능·능력 악화 | X3 근사 후보 HOLD |
| 공개 v3 128토큰 이상 정확 prefix 0건 | 공개 v3에서 X1 확대 보류; 보호 KnowledgePack이나 다른 corpus로 일반화 금지 |
| X1 실제 대상 prefix 공유율 부족 또는 X2 small GEMM wall 회귀 | 해당 축 확대 중단 |

## 7. 실행 파일

`run_P103A_Stage0W_compute_math_contract.sh`와 `run_P103A_Stage0bW_public_sft_prefix_census.sh`와 `run_P103A_Stage0cW_model_ffn_tile.sh`와 `run_P103A_Stage0dW_model_boundary.sh`와 `run_P103A_Stage1aW_m0_boundary.sh`를 작성, 결과번호094의 서로 다른 단계 로그를 사용한다. Stage0bW는 새 20GB 캐시 파일을 생성하지 않고 공개 v3만 읽는다.

## 8. 한계

X1은 실제 Transformer attention/gradient restoration, X2는 optimizer·compile, X3는 pinned H2D·전체 RAM/품질이 미측정이다. `TRAIN_READY` 공개 SFT 원천도 아직 없다.

## 9. 실행 이력 / 갱신

- 2026-09-24: opt-in toy tensor 모듈과 CPU fixture 구현·PASS. 공개 v3 SHA-pinned prefix 직접 계수는 32/64/128 기준 951/83/0 공유 토큰이며 실제 KnowledgePack·Stage1/2 모델·GPU·20GB allocation은 `NOT_RUN`.

- 2026-09-24 막힘 재감사: 보호 KnowledgePack의 X1 중복률은 별도 권한이 필요한 실제 대상 선결이고 공개 v3의 0.1109%로 외삽하지 않는다. X2 optimizer/물리 tile과 X3 synthetic exact/INT8 boundary 코드 작성은 사용자 실험 로그가 없어도 GPT가 계속할 수 있다. 현재의 toy PASS를 모델 통합·20GB 실제 RAM·품질 PASS로 승격하지 않는다.

- 2026-09-24 막힘 재감사 후속: `BoundaryTable`의 비보호 합성 exact/INT8 CPU 인덱스 gather와 작은 frozen boundary의 tail loss·전 tail gradient exact 기준 일치 PASS, INT8 q/deq NRMS 0.0059282(난수 fixture)·20M 원시16.32GB 산술은 종전과 분리해 기록한다. 이는 원 dtype 실제 frozen lower 모델, 2M cache 파일·sampler/position/CLA, 한 update, 4epoch 품질, 20M RAM RSS·wall을 검증하지 않는다.

- 2026-09-24 후속: X2 기본 off config와 실제 MLP의 gate/up 행·down 열 물리 slice를 코드로 연결했다. Stage0cW의 full 4-tile 동일 함수·전 gradient·SGD update, one-tile 폭/수치 모델 진단기·SH를 TSV에 등록했다. 정적/`--check-only`는 PASS, 실제 모델·GPU/optimizer state 절감·품질은 `NOT_RUN`이며 상태는 full-width다.

- 2026-09-24 후속: X3에서 token ID만 boundary key로 쓰면 임의 crop의 문맥·RoPE 위치가 달라 오염된 activation을 재사용한다는 설계 결함을 명시했다. `WindowBoundaryTable`은 고정 전체 window token SHA/parent SHA/split/policy를 묶어 다른 문맥을 거부하며 합성 CPU fixture PASS. 실제 frozen lower·고정 window sampler·CLA 경계·2M cache·RAM/품질은 여전히 미구현/`NOT_RUN`.

- 2026-09-24 후속: 승인안의 앞12/뒤4 CLA 완결 split을 소형 4층/2층 경계로 축소한 기본 off frozen lower/tail 함수와 Stage0dW 사용자 모델 SH를 추가했다. 전체 forward 대비 exact 고정 window logits·loss·gradient·한 update가 기능 판정 대상이다. `--check-only`·shell 정적 PASS이며 실제 모델, M0 12/4, INT8 품질·2M/20M RAM·GPU wall은 `NOT_RUN`.
