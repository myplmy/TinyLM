## 2. ★단계0 — 토큰 실사 (⚙**0.4h**, 학습 0 · GPU 0)

### 2.1 무엇을 재나

| 지표 | 도구 | 판정 |
|---|---|---|
| 후보 4개의 **토큰 길이** 분포 | 신규 `diag_bench_tokens.py` | ★**정답이 체계적으로 길거나 짧으면 채점기가 그것을 잰다** |
| 벤치마크 토큰의 **학습 빈도** | 같은 도구(`ko-en` 600M 캐시 스캔) | ★**빈도 0 또는 하위 0.1% 토큰이 정답에 몰려 있는가** |
| 문항별 **미학습 토큰 수** | 같은 도구 | 그 문항을 슬라이스로 분리 |
| 원문 겹침(13-gram) | 기존 `diag_common_text.py` | Q3 |

### 2.2 ★★**과소학습 토큰 판정 — 노름을 쓰지 않는다**

🚫★**Magikarp 의 "임베딩 노름이 작으면 미학습" 휴리스틱은 우리 구조에서 부호가 뒤집힌다.**
결과 025 §2 실측:

| 집합 | 개수 | 노름 중위 |
|---|---:|---:|
| 사용됨(freq^>0) | 32,715 | **0.5201** |
| 🚫**미사용(freq=0)** | 53 | ★**0.8315** |
| 비 | | ★**1.599 — 반대다** |

★**원인**(결과 025 가 제시한 메커니즘): 출력 헤드가 임베딩과 **tie** 돼 있어
**정답이 된 적 없는 토큰도 매 스텝 softmax 분모에서 *"이것이 아니다"* gradient 를 받는다.**
그 방향이 일관되므로 **노름이 단조 증가**한다.

→ ★★**그래서 이 계획은 노름을 쓰지 않고 *빈도를 직접 센다*.**
🚫**"노름이 크면 미학습" 이라는 역방향 지표도 쓰지 않는다** — 표본 53개로 유도한 것이고
**이 계획이 그것을 검증할 기회이지 전제로 삼을 것이 아니다.**

⚠️★**부수 소득**: 벤치마크 토큰의 빈도를 세면 **노름-빈도 관계를 32,768 토큰 전부에서
다시 볼 수 있다**(025 는 미사용 53개만 봤다). ★**결과 025 의 역전이 표본 문제였는지
구조적인지 여기서 갈린다** — 그것만으로도 단계0 의 값어치가 있다.

### 2.3 판정 (사전 확정)

| 관측 | 결론 |
|---|---|
| 정답/오답 **토큰 길이 비 중위** 0.95~1.05 | ✅토크나이저 편향 없음 |
| 그 밖 | ⚠️**슬라이스로 분리해 보고**, 🚫전체 점수를 단일 수로 인용하지 않는다 |
| 빈도 하위 0.1% 토큰을 포함한 문항 ^< 5% | ✅Q2 통과 |
| ^> 15% | 🚫**그 문항들을 별도 슬라이스로 뺀다** |
| 13-gram 겹침 ^> 10% | 🚫**학습 스트림에서 그 원문을 빼거나 벤치마크를 못 쓴다**(결과 060 규칙) |

## 3. 단계1 — 검정력 계산 (⚙**0.1h**, 계산만)

★**300 문항 forced-choice 의 표준오차**는 정확도 p 에서 `sqrt(p(1-p)/300)`.
p=0.5 면 **2.9%p**. 두 모델을 비교하면 paired 라도 **⚙2~4%p** 급이다.

⚠️★**우리 자는 val CE 기준 0.0006~0.0021 nats 다.** 그것이 정확도 몇 %p 에 해당하는가는
**변환식이 없다** — 다른 지표다. → ★**단계1 은 *"이 벤치마크로 무엇을 가를 수 있는가"* 를
%p 로 명시**하고, 🚫**CE 자와 섞어 쓰지 않는다**(함정 28: 한 이름이 두 양을 가리킨다).

★**산출물**: *"이 벤치마크는 정확도 차 X%p 이상만 판정한다"* 한 줄. 그 X 를 계산한다.

## 4. 단계2 — 실제 채점 (⚙**0.3h**, 학습 0, 모델 로드만)

기존 체크포인트 4~6개에 v2.3 300문항을 forced-choice 로 돌린다.

| 팔 | 왜 |
|---|---|
| `mC_initonly_nc` | 표준 대조군 |
| `mC_cla2_ag4` | 36 MiB 후보 |
| `mC_cla1_ag4_r20` | 최고 품질 |
| `d8_dense` | 얕은 dense |
| ★**난수 초기화 모델** | ★**바닥 확인** — 자명 27.0% 근처가 나와야 한다 |

★★**난수 팔이 이 단계의 게이트다.** 그것이 27% 를 크게 넘으면 **채점기나 데이터에
누출이 있다**(결과 031·032 계열의 대조군 규약).

⚠️**정답률 서열이 val CE 서열과 다르면 그것이 결과다** — 어느 쪽이 옳은지는
이 단계가 답하지 않는다. **두 지표가 다른 것을 잰다는 사실**을 기록한다.

## 5. ★예측

| # | 예측 | 신뢰 |
|---|---|---|
| **E1** | 13-gram 겹침 **< 5%** — 이 데이터는 LLM 이 새로 쓴 것이라 위키 원문이 아니다 | ⚙중간 |
| ★**E2** | 빈도 하위 0.1% 토큰 포함 문항이 **5~20%** — 개념어가 많아 희귀 토큰이 섞인다 | ⚙낮음 |
| ★**E3** | 난수 팔이 **25~30%** | ⚙높음 |
| ★★**E4** | 학습된 모델 넷이 **전부 30~45%** 이고 **서로 자 안에서 구분 안 된다** | ⚙중간 — **그러면 이 벤치마크는 현 단계에서 못 쓴다** |
| **E5** | 결과 025 의 노름 역전이 **전체 어휘에서도 성립**한다 | ⚙낮음 |

🚫★**E4 가 이 계획의 진짜 위험이다.** 100M 급 모델이 300문항 4지선다에서 서로 안 갈리면
**벤치마크가 나쁜 것이 아니라 모델이 아직 그 능력 구간에 없는 것**이다.
→ ★**그 경우의 결론은 "폐기" 가 아니라 "보류하고 언제 다시 볼지 정한다"** 다.

## 6. ⚠️한계

- ★**이 데이터셋은 우리 학습 스트림에 안 들어 있다.** 그래서 held-out 이지만,
  **모델이 이 문체·형식을 한 번도 안 봤다** — 낮은 점수가 능력 부족인지 형식 낯섦인지 못 가른다.
  ⏸**train 900 을 추가 학습한 뒤 다시 재는 것**이 그 통제이고, 그건 TinyDataset 단계0 이다.
- 300 문항은 **작다**. 단계1 이 그 한계를 %p 로 명시한다.
- 🚫**정답률을 val CE 와 같은 표에 나란히 적지 않는다** — 단위도 자도 다르다.
