## 1. 왜 이 실험을 하는가

이 저장소의 **모든 판정이 지표 하나 위에 서 있다** — 우리가 만든 `ko-en` val 크롭의 손실.
P037 이 *"val 셋 자체가 판정을 왜곡하는가"* 를 물어 놓고 **답이 없다.**
그리고 지금 **0.008 짜리 차이로 모델을 고르려 한다**(결과 044 §9).

> ★**다른 자로 한 번 재 본다.** 순위가 같으면 val_loss 에 대한 신뢰가 올라가고,
> **다르면 그것이 P037 의 첫 증거**다. **어느 쪽이든 정보다.**

## 2. ★기준 모델을 무엇으로 정했고 왜 그것인가

> **규약**(P062 §11): 기준 모델 선정 이유 · 대조군별 조건 차이 · 플래그 정의 3절 필수.

**기준 모델 = `mC_wsd`**(현 표준조건, KD, full-val 3.6984)

| # | 왜 `mC_wsd` 인가 |
|---|---|
| 1 | ★**모든 레버표의 공용 대조군**(기준표 §2.2c). 이 도구의 첫 측정이므로 **가장 많이 인용된 점**에 걸어 둔다 |
| 2 | ★**REVIEW2 가 아직 표준을 안 바꿨다.** 지금 시점의 정본은 여전히 이것이다 |
| 3 | ⚠️**단 REVIEW2 가 무KD 로 확정되면 기준선이 `mC_initonly` 로 옮겨간다** — 그래서 **둘 다 넣는다** |

## 3. ★대조군별 조건 차이

| 태그 | 프리셋 | 구조 | KD | full-val | **왜 넣는가** |
|---|---|---|---|---:|---|
| `mC_wsd` | m100R1c | g8, 20층 | ✅ | 3.6984 | 현 표준·공용 대조군 |
| `mC_initonly` | m100R1c | g8, 20층 | 🚫 | **3.6776** | ★**무KD 최선**. REVIEW2 후보 |
| `mC_d36_ag4` | m100R1d | g16, **36층**, `attn_group 4` | ✅ | 3.7062 | ★**최선 상주**(379.7 MB). 모델안 1순위 |
| `p6d` | m100 | **dense**, 타잉 0 | 🚫 | 3.7608 | ★**타잉 없는 참조.** *"타잉이 과제 능력을 깎는가"* 를 본다 |

★**네 모델의 full-val 순위는 `mC_initonly` < `mC_wsd` < `mC_d36_ag4` < `p6d`** 다.
**이 순서가 재현되는지가 P2 다.**

## 4. ★★무엇을 재고 무엇을 안 재는가

### 4.1 🚫**EM / F1 은 명시적으로 기각한다**

| 왜 | 근거 |
|---|---|
| 우리 모델은 **100M base LM 이고 SFT 를 한 적이 없다** | 지시를 안 따른다 |
| **0 은 서열을 못 만든다** | 재려는 차이가 **0.008** 이다 |
| ★**KorQuAD 2.0 논문 자체가 방증** | **BERT-multilingual F1 46.0%** vs 사람 85.7%(2019). 우리는 그 아래 |

### 4.2 ✅**우도 채점(likelihood scoring)**

| 과제 | 방식 | 지표 | 우연 |
|---|---|---|---|
| **YNAT** | 라벨 7개의 **평균 로그우도 argmax** | 정확도 | **14.3%** |
| **NLI** | 라벨 3개 동일 | 정확도 | **33.3%** |
| ★**KorQuAD 1.0** | `지문 … 질문 … 답:` 뒤 **정답 문자열 CE** | ★**nats + paired Δ** | — |

★**길이 정규화 필수** — "사회"(2자) vs "생활문화"(4자). **합으로 비교하면 짧은 라벨이 항상 이긴다.**

### 4.3 ★표본 크기 — **과제마다 다르다**

| 과제 | 표본 | 근거 |
|---|---|---|
| KorQuAD CE | ⚠️★**100문항 = pilot** | 🚫**2026-08-21 정정.** ~~049 유추~~ — **049 의 SE 는 1464 val 크롭의 것이고 모집단이 다르다**(외부 검토문서 §7). ★**도구가 관측 SD 로 `필요 N = (SD/0.002)²` 를 계산**해 스스로 판정한다 |
| YNAT / NLI | **500문항** | 정확도 0.3 부근에서 100문항은 **SE 4.6%p** — 서열이 안 나온다. 500 이면 2.0%p |

> ★★**이것이 이 계획의 핵심 설계다: paired 로 재라.**
> 결과 049 가 증명했다 — 1464 크롭 결정적 full-val + per-crop paired 로 **SE 0.0011~0.0014**.
> **100문항 unpaired 로는 아무것도 안 보이지만 paired 면 보인다.**

## 5. ★예측 — **결과 전에 못 박는다**

| # | 예측 | 실패하면 |
|---|---|---|
| **P1** | YNAT·NLI 가 **네 모델 모두 우연 근처** | 그러면 **그 과제는 이 스케일에서 못 쓴다.** ★**프롬프트를 튜닝하지 않는다** — 튜닝하면 그건 다른 실험이다 |
| **P2** | KorQuAD CE 순위가 **full-val 순위와 같다** | ★**그것이 P037 의 첫 증거다.** 도구 버그가 아니다 |
| **P3** | `p6d`(dense)가 CE 에서 **꼴찌가 아닐 수 있다** | full-val 은 꼴찌인데 과제에서 다르면 **타잉이 무엇을 깎는지**의 단서 |
| **P4** | 건너뛴 문항(seq 초과)이 **10% 미만** | 넘으면 표본이 설계와 다르다 → **재설계** |

## 6. 🚫이 실험이 결정하지 못하는 것

- **어느 모델이 "더 낫다"** 를 정하지 않는다. QA 프롬프트 위의 CE 도 **우도지 능력이 아니다.**
- **체크포인트 간 비교**다(paired_eval 과 같은 한계). *"이 아키텍처가 낫다"* 가 아니다.
- 🚫★**KorQuAD CE 를 val_loss 와 숫자로 비교하지 않는다** — 다른 분포·다른 자(함정 1).

## 7. ⚠️예상되는 함정 — **먼저 적어 둔다**

| # | 함정 | 대비 |
|---|---|---|
| 1 | 우리 어휘 32,768 · `ko-en` 코퍼스라 **KLUE 고유명사가 파편화**될 수 있다 | 토큰 길이 분포를 **먼저 인쇄** |
| 2 | 라벨 문자열 길이 불균등 | **평균 로그우도**(길이 정규화) |
| 3 | 지문 480자 + 질문이 **seq 1024 초과** 가능 | ★**자르지 않고 그 문항을 버린다**(자르면 정답이 사라진다). **버린 수 인쇄** |
| 4 | 우연 이하가 나올 수 있다 | **프롬프트 문제일 수 있다.** `p6d` 대조군으로 판별 |
| 5 | 과제 점수와 val_loss 가 **무상관**일 수 있다 | ★**그 자체가 결과다**(P2) |
| 6 | ★**모델마다 다른 문항을 쓰면 paired 가 무효** | **고정 시드 99 + guid 로그 + 공통 문항만** ✅**구현됨.** ⚠️네 모델이 **같은 토크나이저**라 제외 집합이 자동으로 같다 — **P067(외부 토크나이저)에서는 문다** |
| 7 | ★★**어휘 사전지식 교락** — 지문을 안 읽고도 `대한민국↔서울` 로 정답에 높은 확률을 줄 수 있다 | ★**NC 대조군 신설**: `CE(ans|q) − CE(ans|ctx,q)` = **문맥 이용도**. 0 근처면 이 지표는 QA 가 아니다 |
| 8 | 🚫**공식 metric 과 이름을 섞는 것** | ★**공식 YNAT = macro F1**(KLUE §3.1.2) · **공식 NLI = accuracy**(§3.3.2) · 공식 KorQuAD = EM/F1. 우리 것은 **auxiliary** 로만 부른다. 도구가 첫 줄에 인쇄한다 |
