# P061 — **불균등 타잉**: 초기 층과 후기 층을 같은 `g` 로 묶고 있다

> **신설 2026-08-13**(사용자 승인). 발단: **Hyper Experts** 논문의 expert diversity 분석
> (`docs/methods/08_paper_review.md` §10.6).

---

## 1. 왜 — **우리는 층의 역할 차이를 무시하고 있다**

현행 `mlp_group` 은 중간 16층을 **균등하게** g 개씩 묶는다. `g=8` 이면
`[0..7] → MLP0`, `[8..15] → MLP1`. **초기 층과 후기 층을 똑같이 취급**한다.

### 1.1 그런데 문헌은 층이 다르다고 한다

| 근거 | 내용 |
|---|---|
| ★**Hyper Experts**(OpenReview `cGD7Nzuihz`, ✅전문 읽음) | expert diversity 분석: *"**초기 층에는 expert 부분집합 간 상당한 중복**이 있고, **후기 층에서는 expert 선호가 거의 직교**한다"* |
| 그 논문이 인용하는 근거 | *"초기 층은 단순한 구문·어휘 분석에, 후기 층은 풍부한 문맥·의미 처리에 특화된다"*(Jawahar et al. 2019) ⚠️**원 논문 미조회 — 인용하지 않는다** |
| 우리 결과 038 §2 | 부모초기화가 아키텍처 델타의 주 성분(+0.1386) — **층별 역할이 중요하다는 간접 증거** |

> ★**중복이 많은 곳은 세게 묶고, 직교한 곳은 느슨하게 묶는다** — 그게 자연스러운 귀결이다.
> 우리는 그 반대도 아니고 균등이다. **한 번도 안 재 봤다.**

### 1.2 왜 지금인가 — **MLP 축이 "종결" 됐다고 했는데**

P045 가 **g16 에서 축을 종결**했다(결과 029). 그런데 그 종결은 **균등 타잉 안에서**다.

| | 균등 | **불균등** |
|---|---|---|
| 탐색한 것 | g4 · g8 · g16 | 🚫 **없음** |
| 자유도 | 1개(g) | **2개**(앞 g, 뒤 g) |

★**같은 유니크 MLP 개수에서 배치를 바꾸는 것**이므로 **메모리가 완전히 동일**하다.
→ **공짜로 품질만 움직이는 축**일 가능성이 있다.

## 2. 설계 — **유니크 MLP 개수를 고정한다**

`mC_wsd`(g8)는 중간 16층에 유니크 MLP **2개**다. 그것을 유지하면서 배치만 바꾼다:

| 안 | 배치 | 유니크 | 메모리 |
|---|---|---:|---|
| **기준** `mC_wsd` | `[0-7] [8-15]` | 2 | 기준 |
| ★**A(앞 무겁게)** | `[0-11] [12-15]` | **2** | ★**완전 동일** |
| ★**B(뒤 무겁게)** | `[0-3] [4-15]` | **2** | ★**완전 동일** |

**A** = 초기 12층이 하나를 공유(중복 많으니 세게), 후기 4층이 하나(직교하니 느슨하게)
→ **문헌이 예측하는 방향**.
**B** = 그 반대. **대조군으로 반드시 필요하다** — A 만 재면 "층 위치가 중요하다" 를 못 가른다.

### 2.1 구현 — `mlp_split`

`mlp_group`(스칼라) 대신 **경계 목록**을 받는다:

```python
mlp_split: tuple = ()      # 비어 있으면 종전 균등 = 비트 동일
                           # (12,) 면 [0..11] [12..15]
                           # (4,)  면 [0..3]  [4..15]
```

`transformer.py` 의 `mid_mlps[j // cfg.mlp_group]` 를
`mid_mlps[bisect(split, j)]` 로 바꾼다. **`split` 이 비면 종전 식 그대로.**

⚠️ **부모초기화 그룹 평균도 같이 바뀐다** — `init_from_dense` 가 `j*g+k` 로 멤버를 고르는데
불균등이면 **그룹마다 크기가 다르다.** `_depth_map` 과 같은 방식으로 **경계에서 나눠야** 한다.
★**이걸 빠뜨리면 결과 041·P057 과 같은 함정**이다(이식했다고 믿는데 안 됐다).

## 3. ★예측 — 결과 전에 고정

| # | 예측 | 근거 | 틀리면 |
|---|---|---|---|
| **P1** | **A(앞 무겁게)가 기준선보다 낫다.** Δ = **−0.005 ~ −0.02** | HX 의 diversity 관측 | 안 나으면 **층 역할 차이가 이 규모에서 안 나타난다** |
| **P2** | ★**B(뒤 무겁게)는 기준선보다 나쁘다.** Δ = **+0.01 ~ +0.04** | P1 의 대칭 | ★**A·B 가 둘 다 기준선과 같으면 "배치는 무관" 이 결론** — 그것도 정보다 |
| **P3** | \|A − B\| 가 **분해능(0.024)을 넘는다** | 두 극단이므로 | 못 넘으면 **이 축의 전체 폭이 노이즈 수준** = 종결 |
| **P4** | 메모리·속도는 **완전히 동일** | 유니크 MLP 개수·FLOPs 불변 | 다르면 구현 오류 |

> ★★**P3 가 이 계획의 진짜 게이트**다. **A 와 B 의 차이**가 축의 전체 폭이고,
> 그게 분해능 미만이면 **어떤 배치를 골라도 상관없다**는 뜻이다.
> **기준선과의 비교가 아니라 A vs B 로 판정한다** — 대조군이 서로다.

## N.2 ★★설계 핵심 — **그룹 규약을 한 곳에서만 정한다**

계획 §2.1 이 경고한 것:

> *"부모초기화 그룹 평균도 같이 바뀐다 — 불균등이면 **그룹마다 크기가 다르다.**
> ★**이걸 빠뜨리면 결과 041·P057 과 같은 함정**이다(이식했다고 믿는데 안 됐다)"*

**그래서 `j // g` 를 두 곳에서 쓰는 구조 자체를 없앴다.**

```python
# config.py — ★단일 소스
def mlp_group_index(cfg, j):   return bisect_right(split, j) if split else j // cfg.mlp_group
def mlp_group_members(cfg, gi): return [j for j in range(cfg.n_middle) if mlp_group_index(cfg,j)==gi]
```

`transformer.py` 와 `init_utils.py` 가 **둘 다 이 함수를 부른다.**
→ **함정 18**(적용 대상 집합을 두 곳에서 정의)의 구조적 예방이다.

## N.3 ✅ 비트 동일 검산 (torch 없이)

```
종전 g8(균등)   split=()      유니크 2개  크기 [8, 8]
A 앞무겁게      split=(12,)   유니크 2개  크기 [12, 4]
B 뒤무겁게      split=(4,)    유니크 2개  크기 [4, 12]

✅ split 이 비면 `j // g` 와 **완전히 동일** (16층 전수 대조)
✅ A·B 둘 다 유니크 **2개** = 기준선 g8 과 **메모리 동일**
```

★**P4 예측**(*"메모리·속도는 완전히 동일"*)의 **전제가 코드로 확인**됐다.

## N.4 ⚠️ G0 기준값 정정 (함정 34)

계획 §5 의 G0 이 *"step0 CE 교사(3.8080) 근처"* 라고 썼는데 **틀렸다.**
`init_from_dense` 가 중간 MLP 를 **그룹 평균**하므로 타잉 학생은 교사가 될 수 없다.

→ **대역 검사로 정정**: `5.0 ^< CE ^< 9.3972`, 앵커 **7.7742**(결과 030 §2).

⚠️**불균등이면 앵커가 더 흔들릴 수 있다** — 12층을 하나로 평균하면 8층 평균보다
정보 손실이 크다. **대역 검사가 그래서 옳다**(점 검사면 오탐한다).
