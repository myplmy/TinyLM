# 실험계획 P086 — **타잉된 층에 층별 스케일을 준다** (Learnable Multipliers)

> **작성 2026-09-04** · 제안서 [`done/20260903_타잉-스케일-해제-approved.md`](../proposal/done/20260903_타잉-스케일-해제-approved.md)
> ✅**사용자 승인 2026-09-04** · 논문 [08 §14](../docs/methods/08_paper_review.md)(arXiv:2601.04890)

## 1. 왜

MLP 타잉의 품질 대가는 **잰 전 구간에서 지배당했고 깊을수록 커진다**(d8 **+0.0637** → d16 **+0.1049**).
🚫**그 대가가 *무엇 때문인지* 를 한 번도 안 갈랐다** — *"가중치를 공유해서"* 라고 가정했을 뿐이다.

★**가설**: **대가의 일부는 가중치가 아니라 *스케일까지* 공유한 탓이다.**
논문은 WD 가 걸린 행렬층의 노름이 **`√(η/λ)` 가 정한다**(데이터가 아니라)는 것을 보이고,
스칼라 승수를 붙이면 **블록 출력 노름이 깊이에 따라 증가하는 추세**가 나타남을 보인다(그림 2).
🚫**타잉된 스택은 정의상 그 추세를 표현할 수 없다.**

## 5.1 ★★2026-09-04 범위 정정 — **우리 승자는 dense 몸통이다**

🚫**설계 오류를 스모크 커버리지 게이트가 잡았다.** 초판은 승수를 **타잉된 중간층에만** 붙였는데,
우리 32 MiB 승자 `d12_cla2_r20` 은 **`--arch dense`**(`tie_mlp=False`)다.
→ ★**플래그가 조용히 아무 일도 안 할 뻔했다**(함정 37 의 정확한 형태).

**고친 것**: 타잉 여부와 무관하게 **중간층 전부**에 붙인다. 논문도 대상은 *모든 행렬층*이다.

⚠️★**그래서 이 팔이 재는 것이 바뀐다** — 정직하게 적는다:

| 몸통 | 이 팔이 묻는 것 |
|---|---|
| **타잉** | *"가중치를 공유해서인가, **스케일까지** 공유해서인가"* |
| ★**dense**(우리 승자) | *"**WD 가 노름을 묶는 것** 자체가 손해인가"* — 층마다 이미 자기 W 가 있다 |

★**둘 다 논문이 주장하는 것**이지만 **같은 질문이 아니다.** 결과를 쓸 때 **몸통을 함께 적는다.**

★**재귀와의 관계가 더 큰 기회다**: 우리 승자는 `--train-repeat 2.0` 으로 **같은 층을 두 번 지난다.**
**방문마다 다른 스칼라**를 주면 1회차와 2회차가 다른 스케일을 쓸 수 있고 비용은 스칼라 몇 개다.
🚫**이번 구현은 방문을 구분하지 않는다** — **Stage3 후보**로 남긴다.

## 5.2 ★★실험군 모델 명세 — **`--mlp-lrm` 이 정확히 무엇을 하는가**

> **2026-09-04 사용자 지시 3**: *"lrm 옵션이 어떤 레이어에 어떤 기능을 추가하며, dense일때와
> tying일때에는 어떻게 다르게 할 것인지, tying 대상 mlp 레이어에만 적용하는 것인지 prelude와
> coda에도 적용하는 것인지, mlp와 어텐션이 둘다 타잉일 경우엔 어떻게 하는 것인지 등 세부사항이 누락됨."*
>
> ★**코드가 정본이다.** 아래는 `transformer.py:94` · `modules.py:152-172, 202-204, 253-254` ·
> `transformer.py:806-825` 를 그대로 옮긴 것이고, **한 줄마다 파일:행을 붙였다.**

### 5.2.1 파라미터가 **어디에 사는가**

```python
# modules.py:202-204  —  Layer.__init__
self.has_lrm = mlp_lrm and getattr(cfg, "mlp_lrm", False)
if self.has_lrm:
    self.lrm = nn.Parameter(torch.ones(3))     # gate · up · down
```

★★**`Layer` 에 산다. `MLP` 에 살지 않는다.** 이것이 설계의 핵심이다 —
타잉이면 **MLP 객체는 여러 층이 공유**하지만 **`Layer` 는 층마다 하나**이므로,
**공유 가중치를 건드리지 않고도 층마다 다른 스케일**을 줄 수 있다.

### 5.2.2 어느 층에 붙는가 — ★**중간층 전부. 머리·꼬리에는 안 붙는다**

```python
# transformer.py:94
mlp_lrm=(cfg.n_prelude <= i < cfg.n_prelude + cfg.n_middle)
```

| 역할 | 층(`m100s8` 기준) | LRM | 왜 |
|---|---|:---:|---|
| **prelude** | 0·1 | 🚫**안 붙는다** | 설계상 완전 독립 — 층마다 자기 W 가 이미 있고 **공유가 없다** |
| ★**middle** | 2~9 | ✅**붙는다** | 타잉이면 공유 대상, dense 여도 **WD 가 노름을 묶는 대상** |
| **coda** | 10·11 | 🚫**안 붙는다** | prelude 와 같은 이유 |

✅**실측 확인**: `params` 81,171,224 → **81,171,248 = +24 = 8층 × 3.**
🚫**+36(12층 × 3)이 아니다** → 머리·꼬리에 안 붙었다는 **산술 증거**다(결과 072 §3.1).

⚠️★**이것은 설계 선택이고, 논문과는 다르다.** 논문(arXiv:2601.04890)의 대상은 *모든 행렬층*이다.
**머리·꼬리를 뺀 이유는 "이 저장소의 다른 모든 레버가 그 둘을 안 건드린다" 는 일관성**뿐이고,
🚫**머리·꼬리에 붙였을 때의 값은 안 쟀다.** → **Stage4 후보**(⚙3.2h).

### 5.2.3 무엇을 곱하는가 — **셋을 따로 건다**

```python
# modules.py:159-170  —  MLP.forward
if lrm is not None:  g = g * lrm[0]; u = u * lrm[1]      # gate_proj·up_proj 출력
h = F.silu(g) * u
if lrm is not None:  d = d * lrm[2]                       # down_proj 출력
```

- ★**출력 쪽에 건다.** `TLinear` 는 선형이라 `s·(Wx) = (sW)x` 와 **동치**이고,
  이렇게 하면 **공유 W 를 안 건드린다**(5.2.1 의 이유).
- 🚫★**gate 와 up 을 하나로 묶지 않는다.** `silu(s·g)·(s·u)` 는 **비선형이라 `s²` 로 안 빠진다** —
  묶으면 두 축이 교락된다.
- 초기값 **1.0** → ★**켠 직후는 비트 동일**이다.

### 5.2.4 ★dense 일 때와 tying 일 때 — **부착은 같고, 재는 질문이 다르다**

| | 부착 조건 | 파라미터 수 | ★**이 팔이 묻는 것** |
|---|---|---|---|
| `--arch dense`(`tie_mlp=False`) | ★**같다**(중간층 전부) | 3 × `n_middle` | *"**WD 가 노름을 `√(η/λ)` 로 묶는 것** 자체가 손해인가"* |
| `--arch tied`(`tie_mlp=True`) | ★**같다** | 3 × `n_middle` | *"가중치 공유가 문제인가, **스케일까지** 공유한 것이 문제인가"* |

★★**코드에 `tie_mlp` 분기가 없다** — 일부러 없앴다(초판은 `is_mid_tied` 로 걸었다가
**우리 32 MiB 승자가 dense 라 아무 일도 안 할 뻔했다**, §5.1).
🚫**그러므로 "dense 에서 안 됐다" 를 "타잉에서도 안 된다" 로 옮기지 않는다.**

### 5.2.5 MLP 와 어텐션이 **둘 다 타잉**일 때

```python
# modules.py:253-254
lrm = self.lrm if self.has_lrm else None
x = x + self.gates[1] * self.mlp[0](self.ln2(x)*m + self.m_shift, mode_p, lora, film, lrm)
```

★**`lrm` 은 MLP 호출에만 들어간다.** 어텐션 경로(`self.attn_mod(...)`, `attn_group` 이 공유하는
`mid_attns[j // ag]`)에는 **아무 곱도 안 붙는다.**

| 조건 | MLP 스케일 | 어텐션 스케일 |
|---|---|---|
| `mlp_group>1` 만 | ✅층마다 자유 | — |
| ★`mlp_group>1` **그리고** `attn_group>1` | ✅층마다 자유 | 🚫★**여전히 묶여 있다** |

⚠️★**그래서 둘 다 타잉인 형상에서는 이 팔이 대가의 절반만 푼다.**
🚫**"타잉 대가를 LRM 이 얼마나 되사는가" 를 그 형상에서 물으면 답이 과소평가**된다.
→ 어텐션용 승수(`Layer.lrm_attn`)는 **미구현**이고 **Stage5 후보**다(⚙구현 0.5h + 런 3.2h).
✅**우리 승자는 `attn_group=1`** 이라 이번 결론에는 영향이 없다.

### 5.2.6 재귀(`--train-repeat`)와의 관계

`Layer.lrm` 은 **층 소유**이고 재귀는 **같은 `Layer` 를 다시 지난다** →
★**1회차와 2회차가 같은 스칼라를 쓴다.** 🚫**방문을 구분하지 않는다**(§5.1 의 Stage3 후보).

### 5.2.7 옵티마이저 — ★**승수만 다른 그룹**

```python
# transformer.py:813-825
if n.endswith(".lrm"): lrm.append(p)
...
{"params": lrm, "lr": lr, "weight_decay": 0.01}      # ★약한 WD(P086)
```

**네 번째 param group** 이다(삼진 `gt` · dense · `nodecay`(norm·gate) · **`lrm`**).
★**WD 0.01 이 같은 커밋에 들어갔다** — 나중에 붙이면 그때까지의 런이 무효가 된다(논문 §4.1 대칭성 표류).
⚠️**LR 은 본체와 같다** — 논문 부록 C 가 다른 값을 권할 수 있는데 **아직 안 읽었다**(§6).

### 5.2.8 배포 상주

`TLinear` 가 선형이므로 **원리상 per-row α 에 흡수**되어 0 이다.
🚫★**그 접기(fold)는 아직 구현 안 됐다** — `to_lut()`·`to_int8()` 어디에도 `lrm` 이 없다.
✅**그래도 상주 증가는 실측 +96 B**(24 × fp32)이므로 **접든 안 접든 반올림 밖**이다.
⚠️**행 승수(Stage3)로 키우면 그때는 접기가 선결**이다 — `dim`·`ffn_dim` 크기의 벡터가 3개 붙는다.

## 5.10 ✅**Stage6 확정 — 승수는 움직였고, 축은 산술로 닫힌다**(2026-09-05 기록)

**정본 = [결과 072 §8](../test_result/072_20260904_P086-층별-스케일은-dense-몸통에서-아무것도-사지-못한다.md).**

| | 값 |
|---|---:|
| 본런 max\|s−1\| | **0.2718** |
| 프로브(250스텝) | 0.0692 |
| ★순수 WD 바닥 `Π(1−lr_t·0.01)` | **0.0202** / 0.0022 |
| ★기울기 몫 / WD 몫 | ★**12.7배** / 30.8배 |

🚫★**§5.2.7 의 문장을 정정한다** — *"WD 0.01 이 1.0 으로 당긴다"* 는 **거짓**이다.
AdamW 의 decoupled WD 는 **0 으로** 당긴다. 귀무값은 1.0 이 아니라 **`s_wd` = 0.9798** 이다.

★★**그리고 축이 닫히는 이유가 측정이 아니라 산술이다**: `ternary.py` 가 **1차 동차**라
`s·ternary(W) = ternary(s·W)` 이고, dense 는 층이 MLP 를 독점하므로 **`W'=s·W` 로 흡수**된다.
→ **dense 에서 LRM 의 표현력 증가는 0.** Δ −0.0005 는 구조적으로 보장된 값이었다.

★**Stage5(타잉 몸통) 판정**: ⏸**후순위 유지.** 흡수가 불가능해 **진짜 자유도가 되는 것은 맞지만**,
`mlp_group` 축 자체가 잰 전 구간에서 지배당했다(결과 067). **재개 조건 = REVIEW3 이 타잉 몸통을
다시 채택하는 경우**이고 그 결정은 이 계획이 하지 않는다.

## 6. ⚠️한계·위험

- ★**대칭성 표류**: `(a,b) → (sa, s⁻¹b)` 가 출력을 안 바꿔 노름이 무한 성장. → **WD 0.01 로 대응**했다.
- ★**RMSNorm 이 이미 열 승수**다(논문 §2) — 🚫**열 승수는 안 붙인다.** 겹치면 NaN 위험.
- ⚠️**논문 부록 C(권장 배치)를 안 읽었다.** Stage3 전 정독이 선결.
- 🚫**우리 스케일(100M·300M 토큰·삼진)에서의 검증은 세계 최초다** — 외부 근거는 대형 모델이다.

## 단계1 — **`mlp_lrm` 의 품질 효과** (⚙3.0h · 학습 2)

★**2026-09-07 사용자 지시 4A 가 우선순위를 올렸다.** `mlp_group` 축이 다시 열렸고,
`mlp_lrm` 은 **타잉 대가를 직접 겨냥하는 유일한 구현 완료 레버**다.

구현·스모크는 2026-09-05 에 끝났다(스모크 팔 [23] · `check_smoke` EXPECT `mlp_lrm: True`).
🚫**품질을 한 번도 안 쟀다.**

| 태그 | 프리셋 | arch | `mlp_group` | `mlp_lrm` |
|---|---|---|---:|:--:|
| `d16_g4_base` | m100s12 | tied | 4 | 🚫 |
| `d16_g4_lrm` | m100s12 | tied | 4 | ✅ |

★**짝을 새로 돌리는 이유**: 기존 `d16_g4`(결과 067)는 **다른 세션·다른 코드**다.
자 0.0006(타잉)이 작아 **세션 드리프트가 자를 넘을 수 있다**.

### 예측

논문(arXiv:2601.04890) 주장대로면 타잉 대가(+0.1049)의 **일부**를 되찾는다.
⚙**−0.005 ~ −0.030**. 🚫**자(타잉 0.0006)는 아주 작으므로 −0.002 만 넘어도 유의**하다 —
⚠️**그래서 "유의" 와 "값어치 있다" 를 갈라 적는다**: 값어치의 기준은 **깊이 한 칸(−0.0115)** 이다.

### 한계

⚠️`mlp_lrm` 은 **타잉된 몸통에서만** 뜻이 있다. dense 에는 공유 MLP 가 없다.
🚫이 단계는 **`mlp_group` 축을 되살리지 않는다** — 되살릴지는 폭 축 결과와 함께 본다.

## 단계2 — ★**타잉 × Muon** (⚙1.4h · 학습 1)

> ★**신설 2026-09-08** — [5차 리뷰 §7 X5](../docs/review/202609080325_5차리뷰_초안_새-기준-프리셋과-네-승격후보.md) ·
> [타잉 재평가 §9](../docs/20260908_타잉-세-축의-역할과-가격-재평가.md) 실험 2.

### 왜 — 🚫**타잉 161런이 전부 AdamW 다**

전수로 셌다: `mlp_group > 1` 인 full-train 런 **98개 · 전부 AdamW**.
그리고 Muon 은 다른 축 넷에서 **−0.036 ~ −0.044** 를 줬다(전이 4/4).

★**기전이 구체적이다**: 타잉된 행렬의 그래디언트는 **g 개 층 그래디언트의 합**이다.
Muon 은 그 **합을 직교화**한다 — dense 층 하나의 그래디언트를 직교화하는 것과
**다른 연산**이고, 어느 쪽에 유리한지 **선험적으로 모른다**.

⚠️★**그리고 이것이 승격의 선결이다** — Muon 을 기본값으로 올리면 **타잉 판정 전체가
그 위에서 다시 매겨진다.** 🚫**먼저 한 점을 재고 승격한다.**

### 무엇

| 팔 | 태그 | 조건 |
|---|---|---|
| 대조(있음) | `d16_g4` | L16 · g4 · cla2 · **AdamW** · 3.63063 |
| ★처치 | ★**`d16_g4_muon15`** | 같은 것 + `--optimizer muon --muon-lr-mult 15` |

★**같은 예산의 dense 대조도 이미 있다**: `d16_cla2_norecur_muon15` **3.51391**.

### 사전등록 예측

| # | 예측 | 무엇을 뜻하나 |
|---|---|---|
| **P1** | Muon 이득이 **−0.036 ~ −0.044**(dense 와 같은 대역) | ★**타잉 판정 불변** — 가격표를 그대로 쓴다 |
| **P2** | 이득이 **−0.06 이상**(더 크다) | ★★**타잉이 Muon 에서 되살아난다** — 격자를 다시 판다 |
| **P3** | 이득이 **−0.02 이하**(더 작다) | ★**Muon 이 타잉과 안 맞는다** — 승격이 타잉 축을 더 불리하게 만든다. 그것도 정보다 |

### 판정

Muon 후 격차 `d16_g4_muon15 − d16_cla2_norecur_muon15` 를 **AdamW 격차(+0.07954)** 와 견준다.
★**자는 계열 교차** √(0.0006² + 0.0024²) = **0.0025**.

🚫**이 단계는 `mlp_group` 축을 채택하지 않는다** — **가격표가 옵티마이저에 의존하는지**만 본다.
