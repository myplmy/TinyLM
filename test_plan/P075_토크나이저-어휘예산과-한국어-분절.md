# P075 — 토크나이저: **어휘 예산과 한국어 분절**

- **작성** 2026-08-28 · **상태** ✅**사용자 승인**(2026-08-28) · **선행 문헌** [방법론 11](../docs/methods/11_tokenizer.md)
- **원안**: 방법론 11 §10 의 3안(T1·T2·T3)에 **단계 0(공통 원문 검증)** 과 **gemma 비교군**을 더했다

---

## 0. 한 줄

> **임베딩이 남은 최대 비삼진 항이다.** LUT 이후 상주 42.1 MiB 중 **33.2 가 임베딩·기타**이고
> 그 대부분이 **어휘 표**다. 어휘를 절반으로 줄이면 int8 임베딩이 **9.1 → 4.2 MiB** 가 된다.
> 🚫**그러나 품질 대가를 우리는 모르고, 그것을 잴 자(공통 원문)조차 오염 검증이 안 돼 있다.**

---

## 1. 왜 지금인가

| 근거 | 수 |
|---|---|
| 임베딩이 상주에서 차지하는 몫 | LUT 이후 **33.2 / 42.1 = 79%**(REVIEW3 §1) |
| 어휘를 절반으로 줄일 때 int8 임베딩 | **9.1 → 4.2 MiB** → 안 B 합계 **18.4 → 13.5** |
| 100M 한국어 모델이 성립한 최소 어휘(문헌) | ★**KR-BERT 12,367** — NSMC 에서 어휘 119,547 mBERT 를 **90.10 vs 87.08** 로 이긴다 |
| 우리 어휘 32,768 의 근거 | 🚫**없다.** SentencePiece 논문에 32k 는 **한 번도 나오지 않는다**(방법론 11 §9.5) |

---

## 2. 🚫**단계 0 이 선결이다 — 잴 자가 없다**

어휘가 다른 모델은 **`common_bpb` 로만** 비교할 수 있다(토큰 손실은 큰 어휘가 자동으로 유리).
그런데 지금 그 도구는:

1. **영문 전용**이다(SQuAD v2 context 2.97 MB). 한국어 결론이 안 나온다.
2. ★**그 영문 원문의 학습 데이터 오염 여부가 미검증**이다 — 방법론 11 §13.3.
3. **SE 를 계산한 적이 없다.** *"분해능 0.008 bpb"* 가 이 원문에서 성립하는지 아무도 안 봤다.

### 2.1 단계 0 — **공통 원문 검증** (학습 0 · GPU 0 · ⚙0.5h)

| # | 무엇 | 방법 | 판정선 |
|---|---|---|---|
| ★**O1** | **겹침 측정** | 후보 원문을 문서 단위로 자르고 **문자 13-gram 해시**를 `data_cache/ko-en_600000000` 스트림과 대조 | **13-gram 히트율 ≥ 1% 인 문서는 제외**(GPT-3 계열 관행) |
| **O2** | **대조군** | 학습 풀에서 뽑은 문서로 같은 측정 | 🚫**대조군이 100% 근처가 안 나오면 도구가 고장난 것**이다. 이것 없이 O1 을 믿지 않는다 |
| **O3** | **SE** | 원문을 10등분해 bpb 를 따로 재고 표준오차 | **0.008 이 이 원문에서 성립하는가** |

**후보 원문**

| 언어 | 1순위 | 2순위 | 비고 |
|---|---|---|---|
| 한국어 | **KLUE-YNAT/뉴스 계열**(위키가 아니다) | KorQuAD 1.0 context 중 **O1 통과분** | ⚠️KorQuAD 는 **한국어 위키** = 우리 학습 풀의 24.3%. 겹칠 가능성이 매우 높다 |
| 영어 | **SQuAD v2 context 중 O1 통과분** | fineweb-edu 밖의 공개 산문 | ⚠️fineweb-edu 는 교육 텍스트 분류기라 **위키를 선호**한다 |

**구현 필요**: `scripts/diag_common_text.py`(신규). torch 불필요, 해시 집합만 쓴다.

> 🚫★**O1·O3 가 끝나기 전에는 결과 053 의 bpb 네 수로 토크나이저 서열을 확정하지 않는다.**
> 그 수들은 **"오염 미검증" 표시를 유지**한다.

## 3. 단계 1 — **T1: 어휘 반감**(사용자 승인)

| | |
|---|---|
| **무엇** | 자체 SentencePiece 를 **16,384** 로 재학습 → 그 토크나이저로 **처음부터** 학습 |
| **왜 이것부터** | 상주에서 가장 큰 항을 **직접** 절반으로. 문헌 넷(§1)과 KR-BERT 실측이 **12K 가 성립한다**고 말한다 |
| **비용** | 토크나이저 학습 ⚙20분 + 본 학습 ⚙1.7h |
| **선결** | ★**단계 0**(잴 자가 없다) |

### 3.1 팔

| 팔 | 어휘 | preset | 비고 |
|---|---:|---|---|
| **A0** 기준선 | 32,768(현재) | `m100R1c` | `mC_initonly_nc` 재사용 — **재학습 안 한다** |
| ★**A1** | **16,384** | `m100R1c` + `--vocab 16384` | ⚠️**구현 확인 필요** — 어휘를 바꾸면 캐시 디렉터리가 갈라져야 한다 |
| ⏸**A2** | 8,192 | 〃 | A1 이 분해능 안이면 착수. 아니면 안 한다 |

### 3.2 예측

| # | 예측 | 틀리면 |
|---|---|---|
| **U1** | int8 임베딩 **9.1 → 4.2 MiB**(계산값) | 회계가 틀렸다. **가장 먼저 본다** |
| **U2** | 한국어 bpb 가 **나빠진다**(어휘가 줄면 한국어가 먼저 손해) | 한국어가 32k 에서 이미 포화였다는 뜻 |
| **U3** | 영어 bpb 는 **거의 안 변한다** | — |
| ★**U4** | 두 언어 합쳐 **+0.008 bpb 이내면 채택** | 그 이상이면 12,288 을 다시 보거나 T2 로 간다 |

⚠️★**U2·U3 는 한국어·영어 원문을 따로 재야 나온다** — 단계 0 이 선결인 두 번째 이유다.

## 4. 단계 2 — **T2: 자모(sub-character) pre-tokenization**(구현 선결)

| | |
|---|---|
| **무엇** | 한글을 **68 자모**로 분해한 뒤 BPE. 어휘 **8,192** |
| **근거** | Lee 2025(LoResMT): 소어휘 제약에서 **positional jamo 20.77 BLEU vs 음절 16.78** · \|V\|=1000–1500 자모가 \|V\|=2000 음절보다 **시퀀스 25–40% 짧다**. KR-BERT 서브문자 12,367 이 문자 16,424 와 **동급**(89.86 vs 90.10) |
| ★**왜 우리 조건인가** | 우리는 **메모리 때문에 강제로 소어휘 레짐**에 있다 — 그 논문이 이득을 보고한 바로 그 조건 |
| 🚫**선결** | **구현**: `prepare` 에 자모 정규화 + **역변환 round-trip 검증**. 🚫**round-trip 이 100% 가 아니면 착수하지 않는다**(무손실이 아니면 bpb 가 무의미하다) |
| **한계** | 근거가 **NMT·인코더**이고 인과 LM 이 아니다. 시퀀스가 길어지면 **어텐션 비용이 오른다** — 우리 배포는 CPU 12.5 tok/s(결과 014 §12)다 |

## 5. 단계 3 — **T3: `emb_rank 128` 무KD 재확인**

| | |
|---|---|
| **무엇** | `--emb-rank 128` 을 **무KD 표준조건**에서 |
| **왜** | Lan 2020(ALBERT) Table 3 이 **E=128(12M/79.6)이 E=256(16M/80.1)보다 파라미터 25% 적고 점수 0.5 높다**고 보고했는데, 우리 구 측정(결과 030)은 **KD 조건**이었고 `grad_max 19.32` 로 **판정 불가**였다 |
| **비용** | ⚙1.7h |
| **선결** | 없음 |
| **예측** | int8 임베딩 **9.1 → 4.9**. 품질은 ⚙+0.01~+0.03(로짓 랭크가 절반이 된다) |

## 6. ★★단계 4 — **gemma 비교군**(사용자 지시 2026-08-28)

방법론 11 §12 참조.

> 🚫★**2026-08-29 정정.** 종전 이 자리에 *"gemma 를 학생 어휘 후보로 넣지 않는다 — 예산 밖"* 이라고
> 적었다. **P075 의 제약을 P067 에 적용한 잘못**이다(P067 §6 X5 는 상주를 판정에서 명시적으로 뺀다).
> ★**바를 숫자로 놓는다**(방법론 11 §12.4): 임베딩 int8 기준 Qwen 은 **−0.0130 nats**,
> gemma 는 **−0.0250 nats** 를 넘으면 **상주 증가를 정당화한다.**
> 그 크기는 우리가 재 온 효과들(재귀 −0.0202 · CLA1 −0.0268)과 **같은 범위**다 — **재 보면 된다.**

| 팔 | 무엇 | 왜 |
|---|---|---|
| ★**G1** | `gemma-3-270m` 을 **공통 원문 bpb 비교군**에 추가 | 어휘 축의 **세 번째 점**(32,768 / 151,936 / **262,144**). 두 점으로는 곡선을 못 그린다 |
| ★**G2** | `gemma-3-270m` 을 **교사**로 KD | ★**270M 은 Qwen3-0.6B 보다 우리 100M 에 가깝다.** §7 문헌이 말하는 *"교사–학생 격차가 작을수록 정렬이 쉽다"* 를 시험하는 **유일한 로컬 교사** |
| ⏸**G3** | `gemma-3-1b-pt` 교사 | G2 가 Qwen 을 이기면 격차 축을 넓혀 본다 |

⚠️**선결**: `docs/20260820_Qwen-Gemma-...` §2 가 지목한 **하드 블로커 3건**(uint16 어휘 상한 65,535 ·
KD 손실 VRAM 이 어휘에 선형 · 외부 HF 교사 경로)이 P067 에서 어디까지 풀렸는지 **먼저 확인**한다.
🚫**확인 전에는 배치를 만들지 않는다**(규칙 R22).

## 8. 🚫이 계획이 답하지 못하는 것

- **다운스트림 정확도.** 전부 bpb 판정이다. Park 2020 이 한국어에서 **64K 가 최고**라고 한 것은
  **파인튜닝 후 다운스트림** 기준이고 우리 자와 다르다 — 방법론 11 §1 의 불일치.
- **토크나이저 학습 코퍼스.** 어휘를 다시 학습할 때 **어떤 텍스트로** 할 것인지는 별도 결정이다.
- **KV 캐시.** 어휘는 KV 캐시와 무관하지만, 시퀀스 길이를 바꾸는 T2 는 KV 를 바꾼다.
  🚫**상주 회계에 KV 항이 없다**(REVIEW3 §13 미지 8).
