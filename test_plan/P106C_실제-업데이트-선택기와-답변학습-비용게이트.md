# P106C — 실제 업데이트 기반 자료 선택: 비용과 복원부터 검증하는 폐쇄형 대조

> 제안 계기: [외부 제안 비판검토](../proposal/20261002_데이터-가중치-학습개선-외부제안-비판검토-approved-on-going.md)와 사용자 **B: 비용계측부터 여는 전체 선택기** 승인. 기존 [P106B](P106B_Bonsai-자동번역-pseudo-SFT-온라인-교사학생-검증.md)의 75M 고유 train ×4pass/300M 목표와 분리한다.
> 상태: 구현·CPU 계약 검증, 사용자 모델/GPU **NOT_RUN**. 결과번호102 예약(결과문서는 실제 로그 회수 후 생성).

## 1. 왜 — 손실 감소와 답변 실패를 구별한다

[결과101 §45](../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)의 B 학생은 공개 자료로 실제2업데이트를 수행했지만 고정 질문의 첫 답/3시도는 전후0/8이었다. 기존94행은 실험용 prototype이지 최대 생성량이 아니다. 큰 자료 확대와 별개로 **코드로 정답을 아는 작은 문맥조회 과제도 학습 가능한가**, 가능하면 실제 optimizer 업데이트로 고른 자료가 같은 비용의 무작위보다 나은가를 묻는다. 현재 부모의 모든 지식 원인을 추적하거나 교사 자료를 전수 사전 검수하는 실험은 아니다.

## 2. 질문

|---|---|---|
| Q1 | 같은 모델·optimizer·RNG·입력을 복원한 A/A가 같은가? | 복원이 틀리면 후보별 차이는 무효 |
| Q2 | 32개 문맥조회 QA를 정답 후 정상 종료하도록 암기할 수 있는가? | 실패 시 고급 선택기보다 학습·종료 경로를 먼저 좁힘 |
| Q3 | 후보 묶음의 손실 기여를 켠 +와 0인 branch의 차이가 공통 tail 뒤에도 남는가? | 짧은 score를 장기 교육효과로 바로 확대하지 않음 |
| Q4 | 길이·언어·지도 token·노출 상한을 맞춘 두 정책에서 봉인 질문쌍·망각·비용이 개선되는가? | 선택 점수와 실제 유용성을 구분 |

## 3. ★예측 — 정직하게

같은 새 S0의 AdamW/Muon과 고정 분모·alias·RNG를 복원하면 CPU fixture처럼 A/A가 일치할 것으로 예상한다. 그러나 실제 CUDA/compile의 비결정성이나 누락된 runtime 상태가 있으면 **40회 단계에서 중단**한다.

32문항 암기는 복잡한 일반 지식보다 쉬워 성공 가능성이 있지만, 부모의 종료/문맥 학습 실패가 남으면 최대128회에도 실패할 수 있다. 이는 이 구현·과제·부모·LR의 음성이지 SFT 자체의 불가능 증명이 아니다. 16묶음의 단기 우위가 128회 교육이나 봉인 템플릿에 유지되지 않는 결과도 충분히 예상한다. 선택기가 무작위보다 못하면 선택 알고리즘을 채택하지 않는다.

## 4. 단계 설계 (싼 것 → 비싼 것)

구현은 [p106c_data.py](../scripts/p106c_data.py), [p106c_replay.py](../scripts/p106c_replay.py), [CPU 회귀](../scripts/test_p106c_replay.py)다. 원본 부모/자료는 불변이고 새 `HF/sft_ready/p106c_replay_v1/<phase>/`에만 write-once 저장한다. 기존 파일·중단 출력이 있으면 덮지 않고 새 단계/버전에서 재시험한다. 모든 SH는 입력 대기 없이 선결 음성8·도구 오류9를 분리한다.

### 단계 0 — Stage0W CPU 자료 계약

교사 호출0. 코드가 색상 대응표·묻는 대상·정답을 함께 생성한다. train512행(16묶음), rehearsal256행, select32, dev32, retention128, sealed128행(64질문쌍), 정상 반복/산술 대조64행을 분리한다. 역할별 entity와 템플릿이 다르고 첫 질문 중복을 거부한다. gold·두 오답·질문만 바뀐 쌍은 코드로 검산한다. chat32 실제 encode/mask/길이, 20MB 이하 샤드·SHA와 동일 길이/지도량 정책 feasibility를 검사한다. **선택·프롬프트 개선 과정에서는 sealed 내용을 읽지 않는다.** 준비 도구의 생성/마스크 검증은 답변능력 평가가 아니다.

### 단계 1 — Stage1W 비용·A/A 40업데이트

20 warmup +16 timed +2쌍 A/A4 =40. 기존 chat32 d14 B 부모(`ARMS["b"]`의 정확 SHA·tokenizer)에서 fresh AdamW/Muon으로 새 S0를 만든다. 역사적 부모 optimizer 재개가 아니다. model/비영속 buffer/optimizer moments·물리 alias/CPU·CUDA·Python RNG/train-eval/config/math backend를 캡슐화하고 quant cache는 update 경계에서 지워 재생성한다. 자료는 고정되어 별도 loader RNG가 없다.

S0 SHA가 후속 phase에서도 같아야 한다. A/A의 model·moments·buffer 해시가 두 쌍 모두 같아야 다음 단계로 간다. 변동의3배/최소1e-6은 코드 재현성 경계일 뿐 통계적 sigma가 아니다.

업데이트·복원·select/retention/dev 점수평가·8개 greedy 생성·native full-val·CPU 물리 가중치 delta를 따로 잰다. 전체568회/복원50회/904최대 생성/각 역할 평가/4phase compile·로딩으로 외삽한다. 기본 **누적 wall 예산14,400초(4h)** 이내 추정이어야 다음 단계가 열린다. 실제 남은 예산은 후속 phase마다 차감하며 timeout이면 partial/음성 종료한다.

### 단계 2 — Stage2W tiny 암기, 최대128업데이트

같은 S0에서32행을 반복, 매8회 실제 greedy 최대32token·정답+정상EOS를 검사한다. **29/32 이상**이면 조기 종료하고 아니면128회에서 음성 종료한다. 진단 결과를4epoch 교육·봉인 일반화로 부르지 않는다. 이 branch는 버리고 다음 단계는 S0에서 다시 시작한다.

### 단계 3 — Stage3W 후보16묶음·공통 tail, 144업데이트

각 후보의32행을 두 업데이트로 나눠16candidate+16공통rehearsal을 넣는다. +는32행 모두 가중치1, 0은candidate16행만0이고 **전체 원래 target token 분모를 유지**한다. 단순 행 삭제/분모 재정규화와 다르다. 16×2branch×2step=64회. 물리 parameter는 alias 중복 없이 ΔW를 세고, 미리 정한 첫3 TLinear의 전체group에서 유효 Q/code/scale 변화만 기술한다(블록 이식은 이번 범위 밖).

select의 정답-오답 log-prob margin, 정답 뒤 EOS margin, 답 전 조기EOS margin과 retention NLL을 기록한다. 후보선은 Δcontrast>A/A경계, retention Δ≤0.01nats, 조기EOS margin Δ≥−0.02이다. 상위/중간/하위/고정seed무작위4묶음에 같은8step tail을 붙인다: 4×2×(2+8)=80회. 후보가 있고 상위 tail의 dev 신호가 유지될 때만 두 정책을 연다. 작은 후보순위가 일반 자료의 인과 기여라는 주장은 금지한다.

### 단계 4 — Stage4W 두 정책 각128업데이트, 256회

정책·batch ID 계획을 먼저 동결한 뒤 sealed를 연다. 무작위와 선택 정책은 각각 같은 S0·seed·LR·배치·clipping에서 시작한다. 매32행 중16은 공통 rehearsal,16은candidate다. 선택 팔은 그중 최대8을 유효 상위4묶음에서 고르되 언어·실제 x길이·assistant target 수가 무작위 팔의 각 slot과 같은 행으로 치환한다. 안 맞으면 같은 strata의 무작위를 쓰고 그 계획을 남긴다. 각 ID/팔 최대16노출; 이를 넘겨 자료를 복제하지 않는다.

두 팔 각각 sealed128답과 정상 반복/산술64답, retention/dev·약3M native full-val, 전체 wall·실제 token·peak VRAM·새 endpoint checkpoint를 남긴다. 첫 정책은 baseline, 다음 selected로 고정한 한 seed 진단이므로 시간의 인과 가속이나 다중 seed 개선을 주장하지 않는다.

## 8. 한계

색상표 lookup은 광범위 지식·추론·한국어 회화의 대표 벤치가 아니다. 정답이 있는 작은 과제에서 학습·종료·선택 메커니즘이 작동하는지를 묻는다. 실제로 쓰인 자료는 각각 역할과 x/target/노출을 기록한다. 짧은2step 영향은 역사적 데이터 삭제가 아니며, clipping/Muon 때문에 후보와 rehearsal 상호작용이 포함된다. Q/code/scale 차이는 설명 지표이지 독립 인과효과의 합이 아니다. 같은 총시간 대조·다중 seed·역순 실행·물리 블록 개입은 후속 결정 전 미실행이다. 실패해도 승인된 대량 공개C+B 자료 준비는 취소하지 않는다.
