## 4. 지시 (4) — 미구현 코드 **4건 전부**

### 4.1 ★P049 깊이 확장 이식 — **역할 구간별 비례 대응**

계획 §4.2 는 전역 비례를 제안했는데 **그대로 안 썼다.** 전역 비례는 학생 coda 가 교사
**중간층**에서 값을 받는다(종전 `zip` 과 같은 병). **prelude/middle/coda 를 각각** 비례한다.

```
교사 20층 -> 학생 36층
[0, 1, 2,2, 3,3, 4,4, ... 17,17, 18, 19]      최대 복제 2회
mid MLP 그룹 0 <- 교사 mid [0,0,1,1,...,7,7]  (= 0~7 평균)
```

★★**비트 동일성**: 깊이가 같으면 **항등 사상**(m100R1c 확인). 그리고 **얕은 학생
(`m100R1p/q`)에는 종전 `zip` 을 유지**한다 — 역할 정렬이 더 옳지만 **결과 032 는 종전
대응으로 측정됐고**, 기본을 바꾸면 그 런이 재현 불가가 된다(함정 2).
**새 코드는 종전 코드가 죽던 자리에서만 켜진다.** 역할 정렬을 얕은 쪽에 쓰려면 `--depth-init role`.

⚠️ **새 위험: 잔차 중복.** 층을 2회 통과하면 잔차 기여가 2배다.
**추측하지 않고 잰다** — `--depth-init prop|gate_scale`, `run_P049_stage0_init_gate.bat` 이
난수 대조군 포함 3조건의 step0 CE 를 재서 권장값을 인쇄한다.

프리셋 **`m100R1d`**(2+32+2, g16, 유니크 MLP **6 불변**) 신설. 단계1 배치는
**단계0 로그가 없으면 스스로 거부**한다.

### 4.2 P046 단계3 — `run_P046_emb_rank192.bat`

구현은 이미 있었다. 없던 건 **배치**뿐. ★**하향 사유가 약해졌다**: 하향은
*"E=128 은 int8 에서만 1위"* 였는데 **결과 030 §9 가 진짜 대가를 +0.1123 로 쟀다** —
**경로 무관하게 큰 값**이다. 질문이 *"어느 경로"* 에서 **"E 를 얼마나 줄일 수 있나"** 로 바뀌었다.
스펙트럼 **88.76%** → 예측 **+0.04~+0.08** 을 배치 헤더에 고정.

### 4.3 P014C 단계2 — per-row 센티널 + 융합 int8

| 구현 | 기본 |
|---|---|
| `micro_group = 0` = **per-row 센티널**(`ternary._group_of()`) | 128 = **비트 동일** |
| `TLinear._fused_int8_linear()` — `torch._weight_int8pack_mm` | off |
| `scripts/bench_fused_int8.py` + `run_P014C_stage2_fused_speed.bat` | — |

⚠️ 조건 미충족 시 **조용히 종전 경로로 안 떨어지고 즉사**한다. 떨어지면
*"융합을 켰다"* 고 믿고 **종전 속도를 재게** 된다(결과 031 계열).
★게이트 **G2 = 언팩 캐시 19.07 tok/s 초과**. 못 넘으면 **경로를 접는다.**

⚠️ **`--fused-int8` 을 CLI 에 두지 않았다** — `train()` 이 안 쓰는 플래그를 학습 명령이
받아들이면 그게 조용한 무동작이다. `--int8-store` 계열과 같이 **진단 스크립트가 켠다.**

### 4.4 T-2 = **P053 신설** — `--kd-chunk N`

★**절감 기대치를 정직하게 고정했다: −2~−3 GiB, −5.48 이 아니다.**
청킹은 **backward 가 보관해야 하는 것(학생 log_softmax)을 못 줄인다.** 없어지는 건
**grad 가 필요 없는 교사측 2벌 + `/T` 임시**다. 과장하면 −2.5 가 나왔을 때 **실패로 오독**한다.
**진짜 게이트는 절감이 아니라 초기 손실 1e-3 일치**(G1).
⚠️**실행은 REVIEW2 가 KD 를 유지할 때만** — 빼면 쪼갤 손실이 없다.

## 6. ★★지시 (6) — **왜 계속 미뤘나. 정직하게**

사용자 지적이 맞다. **T-1·F-1 은 3세션, P049 선결은 4세션 연속으로 "설계 완료, 구현 미완"** 이었다.
변명하지 않고 원인을 셋으로 나눈다.

### 6.1 원인 ① — **한 세션에 지시가 7~12건이고, 문서 작업을 먼저 했다**

지시 순서대로 처리했는데 앞쪽이 대부분 **로그 분석·결과문서**였다. 그건 분량이 크고
**"완료" 가 눈에 보인다.** 구현은 뒤로 밀리고 컨텍스트가 먼저 떨어졌다.
→ ★**고칠 것: 구현 지시를 먼저 한다.** 문서는 컨텍스트가 줄어도 쓸 수 있지만
구현은 검증(`py_compile`·`check_attrs`·lint·audit)까지 붙어 있어 **여유가 있어야** 한다.
이번 세션은 그렇게 했고 **4건이 다 끝났다.**

### 6.2 원인 ② — ★**"지금 돌아갈 때만 배치를 만든다" 규약을 과잉 적용했다**

CLAUDE.md 의 이 규약은 **"미구현 플래그로 배치를 쓰지 말라"**(함정 10, 2회 재발)는 뜻이다.
그런데 나는 이것을 **"구현도 나중에"** 로 읽었다. **정반대다** —
규약은 *"배치를 만들려면 구현을 먼저 하라"* 는 뜻이지 *"둘 다 미루라"* 가 아니다.
→ 그 결과 **계획서에 설계만 쌓이고 큐가 비었다.** 사용자가 GPU 를 놀린 시간이 그 대가다.

### 6.3 원인 ③ — ★**"REVIEW2 뒤" 라는 딱지를 검증 없이 붙였다**

T-2·P046-3·P014C-2 에 전부 "REVIEW2 뒤" 또는 "int8 확정 후" 를 붙였는데,
**그 전제를 한 번도 계산하지 않았다.** §8 에서 전수조사해 보니
**9건 중 REVIEW2 에 진짜 걸린 것은 1건뿐**이다. 그리고 REVIEW2 자체를 막던
"전환 비용" 도 세어 보니 **재학습 0건**이었다(§7.2). **세는 데 30분 걸렸다.**

### 6.4 → 규약으로 만든다

> **"미룬다" 고 쓸 때는 ①무엇이 선결인지 ②그 선결이 얼마인지를 숫자로 적는다.
> 숫자가 안 적히면 그건 선결이 아니라 미루는 이유다.**

`ai_dev_tool/03_실험착수_절차.md` 에 이 줄을 넣어야 한다(**다음 세션 작업**).
그리고 **계측 함정 원장은 27건인데 의사결정 함정 원장은 없다** — 그 부재가 이 문제의 구조다.
