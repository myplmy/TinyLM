## 1. 가장 중요한 것 셋

1. **P097 네 300M 학습은 실제 완료됐다.** 전 팔 exit0·skip0·`grad_max≤1.1343`이지만
   tokenizer와 val이 서로 달라 final 3.5133/3.8828/3.9858/4.0261을 품질 순위로 쓰지 않는다.
2. **새 성능 개선은 아직 주장하지 않는다.** P025B We/Wf, P022C Wc, P060B Wd는 코드·CPU
   계약만 PASS한 `STATIC_ONLY / E2E_NOT_RUN`이다. 과거 P025B/P022C 음성은 보존한다.
3. **W&B는 전송되지 않았다.** local payload는 구성되지만 완료 SH가 push를 호출하지 않고,
   config allowlist에도 optimizer/Muon/WD/CLA 핵심 5필드가 빠져 있다.

### 2.2 P025B/P022C 병목 귀속

- P025B We는 `wall_sync_ms`, `event_batch_ms`, `host_enqueue_us`, profiler, M1→8 padding,
  explicit pad+slice, pack wall, CUDA Graph를 분리한다.
- P025B Wf는 `_cslt_sparse_mm` alg-id/Split-K 탐색값과 fresh confirmation을 분리한다.
  cuSPARSELt 0.8.0의 max alg 조회는 `None`; 0~4는 지원 집합 주장이 아닌 예외 허용 probe다.
- PyTorch public Python API가 plan handle을 노출하지 않아 descriptor/plan reuse C++ 확장은
  We가 host/setup 병목을 실제로 보인 뒤 별도 승인으로 연다.
- P022C Wc는 BF16/prepared FP8/weight cache/delayed/current를 같은 측정 함수로 비교하고,
  speed·working memory·NRMS/cosine을 독립 판정한다. actual TLinear cache/backward는 `NOT_RUN`이다.

### 2.3 제안서·SDPA·W&B

- frontier 감사기는 active message sender가 아니라 전 정본을 한 행으로 합치는 inventory compiler다.
  물리 계획 집합=frontier 집합, 비종결 전 행 disposition, READY 미포함 0을 checker가 검증한다.
- 정적 부채 제안은 새 checker 묶음 대신 기존 `check_static_all` profile+JSON evidence와
  `wip --close` evidence 소비로 축소했다. 과거에는 검출된 FAIL을 GPT가 승인 없이 “기존 부채”로
  넘긴 경우와 checker 미탐/오탐이 모두 있었다.
- Wc grouped EFFICIENT는 5-D 형상 결함이었다. batch×KV-head 4-D zero-stride로 교정한 Wd는
  CPU math/shape/storage 계약 PASS, GPU `NOT_RUN`이다.
- W&B dry-run은 각 P097 tag에서 config40/summary30/history23을 만들지만 remote push 증거가 없다.
