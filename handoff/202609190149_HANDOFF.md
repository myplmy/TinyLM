## 1. 가장 중요한 것 셋

1. **P025B의 이전 WSL 실패는 backend 미지원 판정이 아니라 `INVALID_DIAGNOSTIC`이다.** 일반
   `to_sparse_semi_structured(W)`의 한쪽 패킹만으로 dgrad까지 묶어 검사해 transpose 객체의
   `packed=None` 경로에 들어갔다. 새 Stage0bWb는 양방향 training pack과 dense forward/dgrad
   대조를 요구한다. 실제 RTX 4070 Ti SUPER 실행은 아직 `NOT_RUN`이다.
2. **권장 실행 큐에는 지금 디스크에 있고 `runlog`를 거치는 5개 SH만 있다.** 큐 id는
   `1 2 3 5 6`이며 사용자는 개별 파일을 직접 실행할 필요가 없다. 미작성 연구 항목은 번호 없는
   backlog로 격리했다.
3. **기존 정적 부채는 해소했지만 WSL 이관은 완료가 아니다.** 날짜·제안서 상태·문서귀속·제어문자·
   LR 검사기·pending의 `.sh` 인식 부채는 0 오류·0 조치 경고가 됐다. 반면 M4의 FP8·SDPA/cuDNN·Triton·외부
   flash-attn 완결 gate와 현 트리 smoke는 남아 있어 WSL 제안서는 `approved-on-going`이다.

## 6. ★열린 질문

1. 현 트리 smoke를 같은 queue에 넣을 경우 실패 정책을 `stop`, `collect`, `warn` 중 무엇으로 할지
   사용자가 정해야 한다. smoke가 장시간일 수 있으므로 AI가 전체 큐 실패 의미를 대신 결정하지 않는다.
2. P025B Stage0bWb가 PASS해도 Stage0c 학습 진입은 자동 승인되지 않는다. 정확도·dgrad·속도·peak-memory
   결과를 회수한 뒤 계획서 gate에 맞춰 별도 판정한다.
3. WSL M4의 FP8·SDPA/cuDNN·Triton·외부 flash-attn 중 어떤 gate를 다음 구현 우선순위로 둘지
   미정이다. 외부 flash-attn 설치는 별도 승인 없이는 하지 않는다.
4. 옛 `-done.sh` 4개는 새 단계의 durable 로그가 생기기 전에는 삭제 조건을 충족하지 않는다.
   사용자가 예고한 다음 작업에서도 로그 존재와 재현 명령 보존을 다시 확인해야 한다.
5. 정적검사 부채 재발방지 제안서 B안은 미승인이다. 이번 즉시 교정만 완료됐고 pre-close 자동화는 없다.
