## 1. 가장 중요한 것 셋

1. 완료 런처14개 중 누락13개의 정확한 학습/평가 명령을 결과083·090·091의 **기존 역사 아래에만** 추가했다. 이관 재실행 추가0/건너뜀14, 문자열 삭제 계약①② 14/14. **삭제 가능 주장과 실제 삭제는 다르다**: 원칙상 후보13, 역사 핸드오프가 직접 링크한 P014D 1건은 링크 정리 선결로 HOLD다.
2. P092 `-cancel.sh`는 실행한 실험이 아니라 100M gate가 막은 옛 300M 3시드 설계다. 12개 미실행 학습 명령과 여러 문서 링크의 유일한 파일 정본이므로 지금은 삭제 부적합이다. 14 `-done`의 크기 합16,565B, 이 취소본8,899B라 디스크 확보 실익도 없다.
3. 제안서 A/B/C의 원안은 미승인 상태로 유지하고 검토 절만 덧붙였다. **A: 신규 C0 1.2B 금지·MTP는 P006 후속**, **B: S3 현재 추정식은 2배 오류**, **C: X3 저정밀 활성 캐시와 master 분리, INT8+FP32 scale 약16.32GB 조건부 RAM 후보**. 계산은 PASS지만 새로운 훈련 품질·속도는 NOT_RUN이다.

### 2.1 재현 명령 보존과 삭제 판정

[기존 이관 도구](../scripts/append_repro.py)의 dry-run은 13결손/1기존, 적용 뒤 0결손/14기존이었다. 대상 결과의 diff는 [083](../test_result/083_20260913_P092-import-실패로-DST-계약은-미실행이다.md) +28/−0, [090](../test_result/090_20260919_P097-세-cache는-완성됐지만-학습은-0step이다.md) +44/−0, [091](../test_result/091_20260923_P098-R2-초기임베딩-재주입은-3시드-실무-동급.md) +79/−0줄이다. 신규 관측 결과나 학습 수치를 추가한 것이 아니라 launcher 원문 명령만 이관했다. 결과 조건서명 10건 PASS.

[삭제 감사](audit/WIP_20260924_REPRO_DELETE_REVIEW.md)는 14개 exact 파일과 -cancel 1개를 분리했다. 원칙 ①사용자 완료, ②해당 결과문서 명령, ③동일 SH 재실행 계획 없음을 대조하면 P092 2·P097 4·P098 7은 후보13이다. Stage4W는 P097 checkpoint **평가**이지 Stage3 네 학습 SH의 예정 재실행이 아니다. P014D도 ①②③ 자체는 만족하지만 [직전 메모](202609232309_HANDOFF.md)가 SH로 직접 링크한다. 이전 메모를 소급 재작성하지 않으므로 링크 처리 승인 전 보존한다. 실제 파일 삭제, TSV `--apply`, staging·commit은 0건이다.

### 2.2 이전 누락의 원인과 제안서 분석

[근거 감사](audit/WIP_20260924_REPRO_DELETE_REVIEW.md)처럼 `ea363b3`의 14로그 closure는 raw-log basename↔결과 절의 1:1 대응을 검사했지 런처 명령은 검사하지 않았다. `append_repro.py`는 이미 있었으나 호출하지 않았다. `sync_experiments_tsv.py`가 결손을 보고해도 종료0으로 처리하므로 전체 정적 PASS가 이를 막지 않았다. 직전 `c4a05b7` 작업은 감사·보고만 요청받은 범위라 13보류를 기록하고 결과문서 쓰기는 하지 않았다. 따라서 **첫 결과 회수의 절차 누락**과 **후속 감사의 권한 경계**를 구분한다. 재발방지용 exact SH→해당 결과문서 실패 게이트는 제안만 했고 이번에는 작업흐름 코드를 구현하지 않았다.

[A](../proposal/20260923_TinyLM-M0-C0-E384-QK-MTP-지능향상-제안서.md)에서 E384의 실수 산술상 함수 보존과 QK/MTP 분리 가설은 유지했다. 그러나 신규 C0 1.2B는 [기준표](../docs/EXPERIMENT_BASELINES.md)의 600M 한국어 gate HOLD·1.2B SH 금지와 충돌하고, 1.194B 실제 pool/1.200B draw는 약0.995배로 표준≥2배 미달이다. [P006](../test_plan/P006_MTP-학습aux-및-FastMTP추론.md)이 학습용 MTP를 이미 소유한다. 기존 M0 역사 숫자는 보존하되 새 C0 권장을 열지 않았다.

[B](../proposal/20260923_TinyLM-학습시간-T0-T1-S1-S3-최적화-제안서.md)에서 S1 loss-first의 `8192×32768×2B=512MiB` full-logits 제거 방향은 유효하지만 factorized·tied head에 외부 커널을 바로 꽂을 수 있다는 증거가 없다. S3 원안의 선택확률 역수2를 **선택된 target 평균**에 곱하면 target 수가 같아도 원래 평균의 2배다. 문서10절에 전체 update의 유효 target 총수로 나누는 수정 추정식을 적었다. 이는 clipping 전 기대값만 보존하고 Muon/AdamW 학습 궤적을 보존하지 않는다. 새 1.2B G5도 HOLD다.

[C](../proposal/20260923_TinyLM-계산량-재설계-X1-X3-추가가속-제안서.md)에서 X1의 공유 prefix와 X2의 물리 FFN 폭 축소는 조건부로 타당하지만 실제 중복률·kernel profile·회복 학습이 없으므로 39%/29.5%는 가정이다. X3의 20M×768 활성 캐시는 FP32 61.44GB, BF16 30.72GB, INT8+64채널 FP32 scale **16.32GB**, packed INT4+scale 8.16GB다. M0 약105.4M parameter의 FP32 master 자체는 약0.422GB이므로 master 저정밀화는 이 캐시 문제의 해법이 아니다. 이번 WSL의 `free -h`는 RAM 총30GiB·가용28GiB였으나 실제 학습 때의 RSS·중복 copy·swap·품질은 NOT_RUN이다. 조건부 권장은 **원 master checkpoint 보존 + INT8 경계 활성 캐시**, FP8/INT4는 대조 또는 후순위다.
