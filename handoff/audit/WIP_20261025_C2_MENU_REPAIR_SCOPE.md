# 원장71의 실제 메뉴 번호와 인계 소비자 정합 수리

권한 근거는 사용자10월22일 필요한 하네스 조정과10월25일13시까지 원장 미완료 착수
지시다. 현재 WIP 머리말은 정상 override API와 구체 승인 참조로 이 좁은 범위를 기록했다.
새 사용자 권한이나 과학적 기준을 만드는 작업은 아니다.

실측 `WIP_20261025_C2_MENU_READBACK.json`에서 실제 Linux 메뉴9행과 C2의29행이
다르며 완료20개가 혼입됐다. 현재 실행은 실제 메뉴4, C2에서는24다. 원형과 현재
동결된 C·v12·FP32·교사 코드에 수리 대상이 포함되지 않음을 재귀 의존성으로 검산했고
원 소스6개의 사본을 `source_20261025_c2_menu_v1/`에 보존했다.

| 안 | 내용 | 이점 | 한계·비용 |
|---|---|---|---|
|A 권장|실제 Linux 메뉴의 기존 필터를 소비자가 재사용하고 물리적 존재/완료/실행대상을 분리|규칙 중복을 줄이고 실제 메뉴 id를 보존|세 소비자와 격리 회귀 필요,20~40분 예상이며 실측 아님|
|B|소비자마다 같은 접미사 제외 조건을 복제|변경 위치는 단순|이후 메뉴 규칙이 바뀌면 다시 갈라질 수 있으며 비슷한 검증 비용|
|C|현재 기록만 하고 C2/C3를 미완으로 인계|새 코드 변경 없음|검사와 실제 메뉴 번호 차이가 계속 남고 원장71을 닫지 못함|

A로 진행한다. 수정 허용 소스는 `scripts/frontier_audit.py`,
`scripts/frontier_queue_gate.py`, `scripts/handoff_queue.py`, 회귀는
`scripts/test_frontier_audit.py`, `scripts/test_frontier_queue_gate.py`,
`scripts/test_handoff_queue_locked.py`뿐이다. 추가 파일이나 실제 메뉴·실행기·훅·
WIP 도구·모델/학습 코드·원로그·이전 핸드오프는 수정하지 않는다.

물리적으로 남아 있는 완료 런처를 삭제하지 않고 완료 재고로 보존한다. HOLD의 존재와
실행 가능 여부를 구분하며 실제 선결을 자동 해제하지 않는다. Windows/BAT·Linux
SH·동일 우선순위·완료/보류/취소·원래 이름이 없고 done만 있는 경우·큐 잠금의 읽기
금지 계약을 격리된 CPU 반례로 검산한다. 전체 C2/C3의 과학적 수동 판정 완료를
이 수리의 통과로 대체하지 않는다. root가 실제 현재 메뉴의 번호 일치와 동결 의존성
불변을 다시 확인한 뒤 문서와 원장에 결과를 연결한다.
