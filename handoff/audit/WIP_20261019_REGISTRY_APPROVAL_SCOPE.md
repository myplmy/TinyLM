# 승인 후 레지스트리 경로 수리 범위

- 근거: 현재 사용자의 레지스트리 권장안 수정 및 이번 작업 CPU/GPU 승인.
- 기존 WIP 5번을 재개하고, 런처 계보 보고와 실제 지능 설명은 8·9번으로 추가했다.
- 이번 범위는 경로 격리·회귀·실물 스모크·보고다. 새 학생 학습이나 외부 취득을 열지 않는다.

| 대상 | 동작과 권한 | 제외 |
|---|---|---|
| `scripts/registry.py` | 승인한 `TINYLM_DIR` 런타임 경로 수리 | 스키마·등록 조건·기존 등록 데이터 변경 없음 |
| `scripts/test_registry_runtime_paths.py` | 전용 CPU 회귀 신설 | 실제 모델·기존 등록 자료 열람 없이 임시 자료 사용 |
| `scripts/codex_smoke.py` | 경로 회귀 통과 후 의존성 보류 해제 | 사용자 기본 스모크·학습 명령·합격 문턱 변경 없음 |
| 감사·WIP·새 인계 | 실제 검증과 계보·설명 기록 | 타 WIP와 무관한 인터랙티브 변경 보존 |
| 새 격리 런타임·원로그 | 현재 CPU/GPU 승인에 따른 제한 스모크 | 기존 JSON·체크포인트·레지스트리 덮어쓰기 없음 |

## 착수 전 영향도

| 축 | 영향과 대응 |
|---|---|
| 코드 | `runlog._register`가 `registry.record`를 호출한다. 호출·반환값은 유지하고 import 시 루트만 기존 `tinylm.paths`와 같은 환경 선택식을 따른다. |
| 데이터 | LOGS/RESULTS/TSV/MD/DB/MANUAL 여섯 경로가 같은 선택 루트에 묶인다. 열 형식과 자료 이동·소급 등록은 바꾸지 않는다. |
| 회귀 | 기본 환경의 경로 동일성, 두 독립 루트, 등록·조회·렌더·DB·수동 연결·runlog 호출을 임시 자료로 검증한다. 기존 스모크 회귀도 다시 수행한다. |
| 정본 | 모델·실험 수치는 바꾸지 않는다. 실행 안전과 실제 스모크 상태만 인계·현재 맥락에 연결한다. |
| 부채·우선순위 | 임시 보류를 실제 검증 후 해제한다. 일반 지능 보고를 위해 새 학습을 추가하지 않는다. |
| GPU 권한 | 이번 사용자 승인으로만 제한 실물 스모크를 수행한다. 정적 통과를 동적 통과로 대신하지 않는다. |
| 소유권 | 원래 레지스트리 파일의 전후 해시를 대조한다. 기존 원본을 재생성·삭제하지 않는다. |
| 비교 조건 | 스모크 명령·옵션은 정본에서 얻으며, 이미 승인된 인계/필드 검사 경로 대체만 유지한다. |
| 증거 수준 | CPU 재현, 실제 스모크, 학생 답변 품질을 별도로 보고한다. |
| 문서 연쇄 | 새 과학적 학습이 없으므로 기존 실험 수치를 중복 기록하지 않는다. 기술 검증 근거는 감사·인계에 둔다. |
