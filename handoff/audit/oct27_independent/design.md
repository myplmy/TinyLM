## 원장56 AdaMuon의 구현 범위

문헌 보조는 읽기 전용으로 논문v3 Algorithm1/3절과 공식 두 소스를 확인했다. 총괄도 같은 원문을 직접 읽었다. v1의 별도beta2/bias correction과 최신 sign-before-NS 방법을 섞지 않는다. 공식 main의 commit SHA는 웹에서 확인하지 못했으므로 고정 원본 재현이라고 주장하지 않는다.

세 경로는 (A) FP32 V·기존 NS 재사용의 독립 적응판, (B) 공식 BF16 V와 분산 통신 구조까지 재현, (C) 논문 Algorithm1의 비Nesterov판이다. A를 먼저 선택한다. 현재 FP32 master와 상태 검증에 맞고 분산 버퍼를 복제하지 않지만 공식 BF16 정밀도와는 다른 후보임을 명시한다. Nesterov는 별도 명시 인자로 두고 논문/공식 기본의 차이를 회귀에서 검증한다.

- 쓰기: `tinylm/train/adamuon.py`, `scripts/test_adamuon.py`, 별도 `scripts/diag_p005b_adamuon.py`와 대응 test, P005b의 새 Stage16 및 결과078 새 절, 이번 audit/새 런처/필요 등록행. 권한은 현재96 및 원장56의 미완 구현·기술 시험이다.
- 제외: 기존 Muon/NorMuon/NS 함수·trainer/CLI 기본값/CE/KL·모든 실행 중 자원 측정 소스, 정제 자료/코드·원형/checkpoint 저장·추가300M.
- 구현: 실제 모멘텀 방향의 sign→NS5→동일beta의 원소별 제곱 EMA→RMS0.2, FP32 V, 명시2D 행렬/비행렬 그룹. 기존 `split_params`와 NS는 재사용한다. 큰 임시 전체 rollback 저장을 넣지 않는다.
- 검증: 독립 다단계 수식, 행렬 방향·0/None·비유한/중복·gradient 불변·state 재개·STE 접점, 실제 행렬/상태 바이트 및 GPU 시간. 작은 실행에서 지능/벤치 우위를 판정하지 않는다.
- 비용: 실제 측정 전에는 상태의 추가4B/행렬원소만 계산값이다. 속도는 추가연산과 동기화·입력검사를 포함한 실제 구현 시간으로 보고한다. 본학습 시간/품질은 추가300M 금지가 풀린 뒤의 별도 실험이다.

## 실제 자원 측정의 첫 정리 오류

## 원장68 후속 — 외부 HF 실행본 자원

현재 TinyLM5개의10행은 회수했다. 나머지 선택지는 A: 완료된 공식 비교의 Falcon90M/Gemma270M/Qwen0.6B/Gemma1B를 같은 로컬 HF 자원행으로 측정, B: GPT2 GGUF부터 새 resident 생성 worker를 구현, C: 자원 작업을 멈추고 라우터 계보 교량부터 구현하는 것이다. A를 우선한다. 기존 엄격 로더/자산 해시를 재사용할 수 있고 새 설치 없이 일반 모델과의 자원 범위를 채운다. B는 native worker가 현재 likelihood만 지원해 별도 C++ 생성 프로토콜/빌드/회귀가 필요하며, C는 실제 자원 판정 이전에 과거 실행과 현재 소스의 연결 선결이 남는다.

권한은 사용자96의 독립 미완 작업과97의 tmp 조율이다. 새 파일은 `scripts/diag_p106b_hf_resources.py`, 대응시험, 새 Stage11cW 런처·프로필·독립 evidence다. 기존 `diag_p106b_external_core6.model_runtime`와 `diag_p106b_official_core6.model_runtime`는 고치지 않고 현재 로컬 자산/엄격 로딩/최종 가중치 검증을 재사용한다. 이전 평가의 만료된 CLI를 실행하거나 원 영수증을 바꾸지 않는다.

생성은 기존 Transformers `generate`를 사용한다. TinyLM의 전용 dict KV 루프에 외부 Cache를 억지로 끼우거나 새 샘플링 루프를 복제하지 않는다. 모든 모델은 Base/PT로 추가 chat template 없이 plain 질문이다. FP32/eager·TF32 off·MTP/assistant off·KV on을 명시하고 무관찰 생성속도와 streamer 관찰 TTFT를 구분한다. 후자는 CPU 토큰 복사와 cache 관찰 비용을 포함한다. 두 경로의 ID/종료가 같아야 하며 HF와 TinyLM 엔진 차이는 보고서에 남긴다.

기존 엄격 HF 로더는 CUDA에서 검증하므로 CPU행도 최초 검증 로드는 CUDA를 사용한 뒤 본체를 CPU로 옮겨 실제1스레드 생성만 측정한다. 이 제한 때문에 CPU 전용 장치의 시작/최대 메모리·CUDA 없이 로딩 성공이라고 주장하지 않는다. 현재 실행 기기의 모델 저장소와 반환 cache, CUDA 할당/예약, RSS, 점조회는 분리한다. 행별 새 프로세스로 이전 모델/캐시를 이어받지 않는다.

cache는 기존 Transformers의 full/sliding attention 및 Falcon의 convolution/recurrent 상태를 실제 물리 storage로 수집한다. 같은 storage는 중복 합산하지 않으며 알 수 없는 cache 객체나 빈 측정은 기술 오류다. generation의 실제 logits 정밀도/길이·cache 사용 여부를 관찰하고, 모델 원본과 config는 바꾸지 않는다. 고정 token 길이는 토크나이저마다 다른 텍스트가 되므로 tok/s만으로 언어/모델 효율 순위를 정하지 않고 동일한 질문 원문·문자/바이트 속도를 함께 남긴다.

CPU 회귀는 prompt/첫 토큰 구분·cache alias와 recurrent 상태·실패 정리·완결/빈 측정 거부를 검사한다. 실제 CPU/GPU 실행은 각1800초/외부1860초·27일17시 마감·GPU 단독입장·현재 여유10GiB와 추가1GiB 여유를 확인한다. 새8행은 작은 학습·지능 판정이 아니며 외부 원학습량/정밀도/engine 차이를 통제한 인과시험도 아니다. 정제 코드/자료·기존 본체·공용 검사기·환경 패키지는 변경하지 않는다.
