# 향후 출생 독립 판독의 입력 전달 검증

지침만 반복해도 판독 전 추정 리뷰가 다시 작성됐다. 잘못된 단계의 입력을 읽은 사례도 있었다. 원문 의미 판독을 생략하지 않으면서, 앞으로 시작하는 TASK의 공식 리뷰에 실제 입력 전달 선결을 추가한다.

| 안 | 비용과 한계 | 판단 |
|---|---|---|
| A. 실제 판독 후 저장 지침만 유지 | 구현 비용은 작으나 이미 반복 오류를 막지 못했다. | 기존 의미 원칙으로 유지하되 단독 수단으로 쓰지 않는다. |
| B. 초안 접두사와 수동 시각 점검 | 작성 실수를 줄일 수 있으나 전달된 입력의 정확 버전·패킷 누락을 확인하지 못한다. | 초안 규약은 유지한다. |
| C. 고정 판독기의 성공 출력 기록과 리뷰 시각을 대조 | 메타데이터와 작은 CPU 검사가 추가된다. 출력 성공은 이해의 증거가 아니고 동일 UID 환경의 인증 장치도 아니다. | 앞으로 시작하는 정확 TASK 경계에 적용한다. |

F4 수준으로 기존 읽기·리뷰 채택 경로에 영향을 준다. GPU·학습·모델은 실행하지 않는다. 기존 원형·후보·고정 v1 도구·과거 리뷰는 바꾸지 않는다. 새 코드·역할 고정 v2 진입점·설정·전달 로그·별도 검증 뷰만 만든다. 보호 ID와 원문 SHA는 자식 판독기 실행 및 본문 열기 전에 메타데이터로 거부한다. 새 로그는 원문을 저장하지 않고 역할·버전·패킷 SHA·성공 출력 시각만 기록하며 각 파일은 1MB 이하로 나눈다.

원래 공식 원장의 캐시 수치나 의미 검토 상태를 이 도구가 올리지 않는다. 새 활성화 경계 이전 리뷰에는 없던 기록을 소급 요구하거나 생성하지 않는다. ROOT 시험 출력은 별도 목적값으로 기록하고 역할 판독 증거에서 제외한다. 새 경계 이후에는 모든 정확 패킷의 일치하는 전달 기록이 리뷰 저장보다 먼저 있어야 검증 뷰에 들어간다. 원래 리뷰 바이트가 스냅샷과 일치할 때만 그 파일의 저장 시각을 쓴다. 이 선결을 통과해도 원문 전체 판독·의미 검토·독립 판독·총괄 채택이 자동 완료되지는 않는다.

시험은 누락/뒤늦은 전달, 틀린 역할·레지스트리·원문·후보·패킷·도구 버전, ROOT 시험 이벤트, 보호 메타데이터 선차단, 본문 출력 무결성, 로그 분할을 다룬다. 구현 전 문서이며 실제 구현·시험·활성화 결과는 별도 영수증으로 남긴다. 보호 데이터, 타세션 자료, 학습 풀·토크나이저·학습 토큰·실험 조건, 공유 실험 정본은 변경하지 않는다.
