# v17 — 값 보존형 경계와 정보상자

현재 goal의 CPU 전처리·코드·시험·새 파생물 허가를 적용한다. 총괄은 규칙/판정만 구현하고 실제 개별 TXT 정제는 지정 Luna 다섯 역할이 수행한다. 기존 v1–v16, 원문·중간캐시·실패 기록을 보존한다.

| 경로 | 예정 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| scripts/p106b_hold_resolution_policy_v17.py 및 revision_v17.py | 새 버전 신설 | 첨부 목표1절의 CPU 전처리·관련 코드 구현 | 기존34생산파일 변경 없음 |
| scripts/test_p106b_hold_resolution_policy_v17.py | CPU 의미 회귀 신설·실행 | 같은 목표의 관련 시험 허가 | 모델·GPU·스모크 없음 |
| own 감사와 BASE의 새 namespace | 문맥 계약·목적 탐색·전량 초안 | 새 파생 데이터와 분석 허가 | 기존캐시 채택 아님 |

| 안 | 내용 | 이점 | 한계 | 영향 | 비용 |
|---|---|---|---|---|---|
| A | 19,653개 APPENDIX 사유를 모두 개별 새 본문으로 처리 | 사례별 판단 가능 | 이미 채워진 정상 말미도 반복 수작업 필요 | 코드 낮음, 텍스트 작업 큼 | 높음 |
| B | 별도 말미의 복수 명시 표지로 경계만 증명하고 모든 값을 유지; 확인된 명사 서술과 단층 정보상자 문법을 재사용 | 값 삭제/배열 결합 없이 정상 구조 복구 | 실제 결손·모순·미증명 경계는 남음 | 새 정책·시험·초안만 | 중간 |
| C | 분류 단어의 허용목록만 계속 추가 | 작은 패치로 일부 복구 | 관측한 직업/기관/가문을 끝없이 열거하며 경계 근거가 약함 | 코드 부채와 재판정 증가 | 반복 비용 높음 |

선택: B. 후보 전량 프로파일에서 생사 표지 두 개와 알 수 없는 분류명이 함께 있는 별도 마지막 문단을 확인했다. 미확인 단어를 삭제하거나 뜻을 부여하지 않는다. 예: `1900년 출생 / 살아있는 사람 / 김해 김씨`를 전부 원래 순서로 보존한다. 경계 증명은 바로 앞 문단 전체가 빈 각주/외부 링크 등의 표제뿐인 경우의 그 표제 제거에만 사용한다. 출생 모순, 실제 빈 값, 수식/조건 소실과 자동 부분문단 삭제는 독립적으로 보류한다.

말미 근거는 생년+몰년/생존의 짝 또는 명시 연도와 복수의 이미 인식한 분류형이다. 한 연도와 아무 명사 한 개, 문장/책 제목/코드 예시는 근거가 아니다. 인식하지 못한 명목 행을 모두 보존하며 새 분류 판정을 적지 않는다.

정보상자는 기존 v14 flat_football의 단층 `| 항목 = 값` 문법·이름-서두 일치·배열 결합 금지·코드/수식 보호를 그대로 재사용한다. 새 버전만 템플릿명이 정보로 끝나고 모든 라벨이 명시된 단층 기록인 경우로 일반화한다. 원래 이름이 독립 서두와 일치해야 하고, 채워진 각 라벨과 값/순서/단위는 그대로 유지한다. 중첩·링크 구문·여러 셀·잃은 표 구조·불균형·서술값과 내부 생년 모순은 종전처럼 보류한다.

명사 서두는 기존 ENTITY 문법의 `으로`와 이미 채워진 `정당` 등의 명시 서술만 확장한다. 일반 자연어 전체를 정상으로 간주하지 않는다. 함수 호출·기호·수량과 미확정 날짜/이름을 빈 별칭으로 지우지 않는다.
