# 교차 검토가 닫힌 첫 묶음의 ROOT·원장 연결

사용자의 전체 정제 goal에서 총괄의 채택 판단·CPU 전처리·별도 캐시 생성과 검증을 허용한 범위다. 학습 실행이나 새 의미 기준 승인이 아니다.

| 안 | 장점 | 비용·한계 |
|---|---|---|
| 교차 후보 3,688건 전부 끝난 뒤 통합 | 한 번에 큰 묶음 처리 | 이미 닫힌 결과도 미결과 대기 |
| 고정 snapshot에서 1차·교차 판독과 기존 guard가 모두 닫힌 ID만 지금 통합 | 실제 채택 선결과 다음 캐시 경로가 전진 | 작은 최초 묶음의 전체 캐시 재생성 비용 |
| 리뷰만 더 저장하고 통합은 마지막으로 미룸 | 당장 준비 작업이 적음 | 공식 HOLD 정체를 계속 유지 |

두 번째 안을 수행한다. 현재 snapshot은 재개 가능한 중간 묶음이며 작업량 한도가 아니다. 이후 같은 유형의 결과를 계속 누적하고, 매 TASK마다 전체 캐시를 재생성하지 않는다. 일부 guard 미결은 그 ID만 분리하며 다른 닫힌 ID를 막지 않는다.

새 ROOT 선택은 기존 ROOT11의 모든 선택을 그대로 보존하고, 자기 작성자가 아닌 역할의 명시 교차 리뷰가 있는 새 source/body 쌍만 추가한다. 원문 ID/SHA·두 리뷰·선택본문 SHA·입력 snapshot·모든 guard를 고정한다. 자동 guard 통과만으로 승인하지 않는다. 메모·빈 본문·과제 불일치·원형 또는 리뷰 변경은 차단한다. source/code/Unicode/style/숫자/순서에 미결이 생기면 정확 ID와 이유를 남기고 추가 승인을 만들지 않는다.

쓰기 경로는 이 감사 폴더의 새 ROOT12/closure/roster producer, data_cache의 새 원장/별도 캐시뿐이다. 원형·기존 캐시·로그·보호 데이터·타 세션·GPU/모델·외부 Git은 불변이다. 초기 전체 원장은 roster3에서 이어받아 설명 없는 누락을 막는다. 새 원장 분모는 297,539고유/460,695위치이고, 기존 38개 검토 후 HOLD는 미검토와 분리한다. 보호 28876 두 위치는 V3 metadata guard로 유지한다.

실제 cache/consumer 전에는 ROOT·원장 승인과 실제 cache 반영을 구분한다. 새 cache 생성/독립 검증이 끝나면 관련 정본과 WIP에 실제 수치를 연결한다. 전체 정제 A–E와 학습 재개 선결은 계속 미완이다.
