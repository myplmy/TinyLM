# 실제 저장 본문 선택 계약 v5

v4의 일본어 제목과 안내문은 총괄의 작성 오류였다. 이미 선택6에 해시로 고정된 v4와 그 오류는 보존하고, 이 한국어 새 계약으로 이어간다. v4의 의미 보존·원문 연결·낮은 옛 후보로 우회하지 않는 규칙을 유지한다.

새 선택7은 캐시 채택이 아닌 실제 저장 본문의 선택 의도다. 기존 새239쌍, 정책 반례14쌍, 추가 미배정 유형233쌍의 정확 source/candidate/본문/review SHA와 배정 TASK를 대조한다. 리뷰가 저장되지 않은 배정도 계획의 결손행으로 남긴다. 최신 리뷰가 문법 오류·복수 출력·다른 TASK의 ID·부분 읽기뷰 복사이면 이를 결손으로 연결하고 과거 본문으로 우회하지 않는다. 서로 다른 새 목적의 본문이 다르거나 기존 exact root 결정과 달라지면 총괄의 명시 중재 전에는 미결이다.

대안은 이전 선택6 유지, 실제 저장 검토와 배정 결손을 연결하는 새 선택, 파일명 버전 숫자로 본문 추측이다. 두 번째를 채택한다. 이는 새 검토가 발견한 실제 오삭제·잘림·결손 의존부를 드러내며, 비용은 추가 중재다. 영향 범위는 자기 감사 폴더의 새 collector/plan/selection과 파생 JSON뿐이다. 원문·기존 캐시·이전 기록을 바꾸지 않는다.

작업 중 보조 파일은 정확 경로·SHA·동일 ID를 포함하는 최종 review 경로/SHA를 등록한 경우에만 결정행에서 제외한다. 원형과 보조 파일 해시는 감사 이력에 남긴다. 알려지지 않은 review 파일명을 일반적으로 무시하지 않는다. review012_work의 존재를 숨기거나 가장 최신 파일을 추측해서 해결하지 않는다.

출력 열은 최종 본문 TXT 한 개와 해당 hold만 지목한다. 과거 실패본은 사유 또는 hold에 기록한다. 실제 읽기뷰의 일부 SHA와 완성본문이 같으면 거부하며 임의 길이감소 비율을 합격선으로 삼지 않는다. 306600은 실제 v3의 명시 검토를 사용한다. 1278318의 원문은 내부6·외부2의 총8개 literal 관계이고, v4에서 손실된 실제3관계를 복구한 v5를 명시 대조한다. 기존 검토자의 잘못된 관계 수와 총괄의 그에 따른 최초 판단·실패 테스트도 보존한다.

기존 exact root 선택과 명시 supersession, 제한 parent metadata-only와 승인된 안전뷰, source 개수 및 SHA 보존, 메모·숫자·코드·Unicode·스타일·원문 링크관계·어휘·조건·인용·잘림 검산을 유지한다. source/candidate가 같아도 실제 결손이 있으면 자동 수용하지 않는다. 원문에 없는 사실·수식·날짜를 생성하지 않으며 모든 독립 유효 내용을 보존한다.

선택 후 실제 본문 검산·미결 중재·전량 캐시와 재계측·정본·로컬 커밋은 별도 미완 작업이다. PENDING 일괄 제외 또는 zeroH 계약 완화는 하지 않는다. 추가300M 학습은 계속 미허가다.
