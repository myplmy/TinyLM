# 네 과거 리뷰의 입력 계보 연결 방식

변경 대상은30538/3902/8699/17705의 저장 근거를 읽는 새 감사 코드와 새 JSON뿐이다. 본문·과거 리뷰·생산 바인더·ROOT선택·캐시는 수정하지 않는다. 먼저 ID와 원형SHA 양쪽을 보호계약과 대조한다.

| 대안 | 범위와 비용 | 한계 |
|---|---|---|
| 현재 미연결 상태 유지 | 코드 변경이 없고 기존 근거를 그대로 둔다 | 복구 가능한 과거 입력과 정정행을 활용하지 못한다 |
| 정확 입력·명시 정정행으로 새 감사 연결 | 원래 manifest의 candidate/recipe base SHA와 실제 재생성, 정확 리뷰행·명시 상대경로를 검산한다 | 과거 전달시각·이해·그 당시 recipe바이트를 새로 증명하지 못한다 |
| 새 역할 전문 재판독 | 현재 입력에 대한 새 독립 판독 근거를 만든다 | 전량 큐를 지연시키고 과거 계보의 형식 문제는 별도 남는다 |

두 번째 방법으로 진행한다. 기존 v3 실패는 보존하며 새 연결을 자동 의미통과·flag면제·ROOT/캐시 채택으로 쓰지 않는다. 확인되지 않은 세 건의 과거리뷰SHA를 현재 해시로 소급하지 않는다.

30538은 명시 ACCEPT_CANDIDATE와 정확 출력 `없음`의 결합을 원래 배정 후보로 연결하는 특정 역사 계약만 검산한다. 17705의 출력은 자기 새 복사본이 아니라 `legacy_rendered_v3/...txt`라는 BASE기준 상대경로다. 총괄의 이전 상태 요약에서 이를 자기 복사본으로 해석한 설명을 정정한다. BASE에 고정해 실제 배정 후보 전체경로와 같은지 확인하며 임의 suffix/부분문자열 매칭을 허용하지 않는다.

3902는 출력 후보가 아닌 과거 legacy manifest의 candidate SHA B242C9C7…를 recipe 기준입력으로 사용한다. 8699는 같은 리뷰의 NEEDS_ROOT 원형행과 명시 `root 결정 후 정정` EDIT_TEXT행을 모두 보존하고, 정확 한 정정행과 실제 출력 SHA만 연결한다. 임의 마지막행 우선순위를 도입하지 않는다.

영향 축은 GPU/학습/모델0, 본문·보호/타세션자료 변경0, tokenizer/학습풀 비교조건 변경0, 증거수준은 CPU 계보검산이며 의미·품질·시간 증명과 분리, 문서연쇄는 새 감사·진행보고·WIP만이다. 기준표/METHODS/COMPASS의 학습 재개 판정은 바꾸지 않는다. 실제 바이트/ID/기준입력 반례와 거부검사를 수행하고, 독립 검산 뒤에만 연결 수를 갱신한다.
