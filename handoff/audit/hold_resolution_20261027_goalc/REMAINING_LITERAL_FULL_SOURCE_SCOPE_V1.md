# 빈 괄호의 프로그램 문맥 유형 전량 판독

대상은 전체 연결계획 v4의 HOLD 중 GLOBAL_PROGRAM_WORD_DOES_NOT_PROVE_EACH_EMPTY_PAREN_LITERAL 사유 1,793고유 원문이다. 프로그램 관련 단어가 있다는 사실만으로 각 빈 괄호가 코드 리터럴이라고 판단할 수 없다. 이 수는 미결 사유 계수이며 새 처리량이나 채택량이 아니다.

| 안 | 처리 | 한계 |
|---|---|---|
| A | 프로그램 단어가 있으면 빈 괄호를 모두 보존 | 실제 소실된 수식·변수·표적을 정상으로 오인할 수 있음 |
| B | 빈 괄호를 모두 제거하거나 전체 문서를 제외 | 함수 호출·튜플·인용·설명 관계와 독립 본문을 훼손할 수 있음 |
| C | 이 사유 전량을 원문·동결 후보·전체 diff로 판독 | 실제 코드와 표적 결손을 문맥별로 구별하고 좁은 HOLD 근거를 남김 |

선택은 C다. 기존 반복 732와 출생 충돌 2,743의 소유 원문은 SHA로 분리하며, 보호 ID·동일 SHA는 본문을 읽거나 배정하지 않고 메타데이터 계수만 남긴다. 원래 유형 전체 = 기존 소유 + 보호 + 새 판독 대기열의 합을 검산한다. 총괄은 코드·CPU 원문 연결 검증·좁은 판정을 담당하고, 실제 정제 TXT는 기존 다섯 Luna가 자기 역할에 지정된 원문만 판독해 작성한다. 현재 배정과 재검토를 마친 역할부터 새 유형을 이어간다.

빈 괄호의 함수 호출, 빈 튜플, 시그니처, 코드 문자열, 인용과 실제 결손 설명을 구별한다. 설명에서 수식·변수·독립 표적이 빠졌으면 의존 구간만 원형 HOLD하며 완결된 코드·정의·역사·예시를 보존한다. 값을 생성하거나 이름·단위·조건·숫자·부정을 임의 수정하지 않는다. 출생 유형에서 확인한 나이·기간 보존 경계도 그대로 적용한다.

모든 지정 원문·후보·전체 diff를 순서대로 읽는다. 새 패킷은 2,000문자의 연속 조각이며 개별 파일 끝이 논리 문장 끝은 아니다. 실제 출력 잘림과 정상 분할을 구별한다. 경로를 추측하거나 경로 없는 검색을 하지 않는다. controls 역할은 별도 고정 입력 reader가 준비된 뒤에만 새 원문을 읽는다. 다른 역할도 지정 START/TASK/READING_VIEWS와 정확 배정 입력 및 승인 MD만 읽는다. 코딩·시험·통계·해시·Python·Git·웹·GPU·모델·다른 역할·다른 세션 자료 접근은 Luna에게 허용하지 않는다.

영향 축은 프로젝트 메타데이터와 기존 영향도 검토를 따른다. 새 버전 메타데이터·증명·패킷·리뷰만 생성하고 원형과 기존 캐시를 보존한다. CPU 재생성 일치는 의미 판독이나 사실 검증의 대체가 아니다. 새 자료는 개별 20,000,000바이트 미만으로 나누며 원문 ID/SHA와 순서를 연결한다. 본 유형 대기열 준비나 일부 마감을 전체 목표 완료·일시중지·학습 승인으로 바꾸지 않는다.
