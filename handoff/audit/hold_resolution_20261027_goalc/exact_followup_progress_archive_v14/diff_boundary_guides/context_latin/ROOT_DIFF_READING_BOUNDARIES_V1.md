# 순서 패킷 경계와 개행 없는 diff를 읽는 방법

기존 자기TASK·고정 reader·ID/SHA/역할·출력 한도와 모든 논리 END/EOF 규칙을 그대로 따른다. 이 안내는 원형 직접 읽기·임의 코드·다른 역할·시험·Git 권한을 추가하지 않는다.

패킷은 고정 문자 수로 나뉘므로 원문 단어·diff 행 또는 부호도 경계에서 나뉠 수 있다. 현재 조각 첫머리 파편을 독립된 후보 문장으로 해석하지 말고 이미 지정한 앞뒤 패킷을 순서대로 이어 읽는다. 이전 조각의 마지막 삭제 부호와 다음 조각의 글자가 같은 diff 행일 수 있다. 일부 조각만으로 입력 변경·문장 삭제·동시 작성자를 추정하지 않는다.

원형이나 후보의 마지막 줄에 개행이 없으면 unified_diff가 마지막 삭제와 추가를 같은 표시 줄로 붙일 수 있다. 붙어 보이는 줄만으로 실제 후보 내용을 판단하지 말고, 같은 지정 입력에서 실제 original/candidate 전문과 EOF를 대조한다. 후보에 실제 정보가 온전히 있으면 표시 현상 자체를 정보 손실이나 NEEDS_ROOT로 세지 않는다. 실제 전체 후보를 못 읽었거나 핀이 불일치하면 그 범위는 미완으로 두고 총괄에 알린다.

표시 혼동 때문에 완료한 전체 입력을 재독하거나 원형/candidate를 수정하지 않는다. 실제 단어·수치·조건·반복의 삭제/이동/변질은 별도로 문맥 판정하며, 모든 diff 차이를 무해한 표시 현상이라고 일반화하지 않는다. 이 안내는 새 본문 채택이나 의미 검증 완료가 아니다.
