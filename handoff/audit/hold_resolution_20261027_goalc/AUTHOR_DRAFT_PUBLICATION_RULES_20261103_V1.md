# 새 작업 초안과 확정 기록의 구분

현재 사용자 목표의 새 TXT/MD 작성 범위에서 총괄이 정하는 작업 절차다. 원문·후보·기존캐시·로그·체크포인트·이미 확정한 본문/리뷰를 수정하는 허가는 아니다. 기존 다섯 역할은 이 MD를 읽을 수 있다.

| 안 | 동작 | 비용과 한계 |
|---|---|---|
| A | 작은 초안 수정도 매번 다른 이름에 저장 | 모든 시도 파일이 늘고 연결 정정과 반복 판독이 발생 |
| B | 새 draft_만 편집하고 최종본은 새 버전으로 고정 | 초안의 모든 중간 바이트가 보존되는 것은 아니며 최종 게시 경계가 필요 |
| C | 확정 본문·리뷰도 같은 경로에서 수정 | 이미 연결한 SHA와 실제 판독 버전이 달라질 수 있음 |

B를 적용한다. 아래 허용은 지금부터 작성하는 자기 지정 출력 폴더의 `draft_*.txt`와 `draft_*.md`에만 추가한다.

1. 자기 새 draft_ 파일은 좁은 패치로 여러 번 편집할 수 있다. 정확한 지정 후보에서 아직 없는 draft_로 초기 복사할 수 있다. 다른 역할·원문·공유후보·기존 working/initial 사본을 수정하지 않는다.
2. 아직 읽지 않은 ID의 판단·판독범위·근거를 실제 판독인 것처럼 작성하지 않는다. 준비 중 내용은 draft_에 남기며 공식 review_NNN은 TASK의 실제 전량 판독 후에만 작성한다.
3. 검토한 결과는 아직 없는 정식 TXT 버전으로 고정하고, 공식 리뷰는 그 정식 파일만 가리킨다. `draft_`는 공식 출력으로 연결하지 않는다. 뒤의 정정은 정식 새 버전과 리뷰 새 버전으로 남긴다.
4. 새 정식 파일은 전체 차이와 필요한 문맥·끝을 확인하고 실제 검토 범위를 기록한다. 전문 재출력 생략 조건은 `EDITED_BODY_READING_SCOPE_IMPACT_20261103_V1.md`를 따른다.
5. 이전에 존재하는 초안·버전은 삭제하지 않는다. 초안을 편집했다면 모든 수정 전 바이트를 보관했다고 주장하지 않는다. 남은 파일과 최종 버전의 보존, 확인하지 못한 중간 이력을 구분한다. 이 지시는 이전 범위 밖 동작을 소급 승인하는 기록이 아니다.
6. progress log는 append-only로 유지한다. 공식 리뷰·원형 보류 근거·고정 버전은 조용히 덮지 않는다. 코드·시험·해시·통계·웹·Git·모델/GPU는 계속 총괄/사용자의 기존 권한 경계를 따른다.

프로젝트 영향: GPU·학습·비교조건은 바꾸지 않는다. 데이터 변경 범위는 이미 허용된 자기 새 작업 초안뿐이다. 확정 증거는 버전과 SHA로 구분하며 중간 초안 이력을 전량 보존한 것으로 취급하지 않는다. 현재 WIP·감사 자료에 기록하고 필요한 최종 정본 연쇄는 실제 전체 결과에 맞춘다.
