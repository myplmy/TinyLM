# 실제 차단 자료의 정확한 metadata HOLD 연결

사용자 goal의 CPU 정제·코드·시험·새 파생물 권한 안에서 처리한다. G가
`expanded_train:360211` 편집 중 실제 내용 필터 차단을 보고했다. 원형·후보·작성 중
본문을 재열람하거나 해시하지 않는다. 주제에 따른 추가 차단은 만들지 않는다.

| 안 | 내용 | 영향 | 비용 |
|---|---|---|---|
| A | 기존 guard5만 사용 | 새 차단 자료와 별칭을 보호하지 못함 | 낮음 |
| B | 새 ID만 제외 | 다른 ID와 content-addressed 경로의 같은 원형을 놓침 | 낮음 |
| C | ID·원형/패킷 SHA·metadata 별칭을 누적 | 기존 판독과 보존 검사를 유지하며 새 자료만 차단 | 중간 |

C를 적용한다. 새 guard는 기존 guard5를 먼저 검증하고 정확한 metadata 확장만 허용한다.
과거 고정 코드·스코프·계약은 수정하지 않는다. 향후 판독은 새 guard를 먼저 적용한
동일 프레임 판독 경로로 연결한다. 수집·캐시에도 같은 metadata 확장을 적용해야 한다.

| 경로 | 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| 이 audit 폴더의 새 guard·계약·검사·판독 어댑터 | 신설 | goal 1·6 CPU 전처리/관련 코드 시험 | 차단 본문 읽기·해시·변경 |
| `tmp/hold-{c,l,h,j,g}-field-lossless-batch-v1` | 고정 어댑터 SHA만 갱신 | 동일 지정 원문 판독의 보호 강화 | 배정 확대 |
| page15 manifest, opaque HOLD metadata shards | 읽기 | 원문 연결/처리 근거 | payload 읽기 |

코드 영향은 공통 guard와 새 판독·수집·캐시 진입부다. 데이터 영향은 정확한 두 원형
위치의 metadata HOLD이며 다른 문서는 바꾸지 않는다. 검사는 가상 payload 접근 차단,
SHA 별칭·ID 별칭 거부, 정상 배정·기존 프레임 일치를 확인한다. 모델/학습/GPU와
보호 TinyDataset, 타세션, 기존 캐시·원로그에는 영향이 없다. 기준표·METHODS·COMPASS의
최종 정제 상태는 실제 새 캐시 뒤 묶어서 갱신한다. 이 문서와 검사만으로 정제나 goal
완료를 주장하지 않는다. 기술부채는 고정 guard를 하나 더 계승하는 것이며, 전체 대기열을
이 자료 때문에 반복 스캔하거나 payload 사본을 만들지 않는다.
