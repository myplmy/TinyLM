# 계속 정제 중 확인한 추가 실패와 조치

이 문서는 [이전 V8](RESUME_PREPARATION_FAILURES_V8.md)에 추가한다. 과거 실패·초안·캐시를 교체하거나 삭제하지 않는다. 전체 정제는 진행 중이다.

- 1323187의 최초 LTER 표 복구 본문에 Harvard Forest 이름의 LTER가 누락됐다. 실제 원문 27행과 대조해 발견했으며 Luna가 새 v2 본문과 review_020_v4를 작성했다. 정확 이름·좌표 문자열·순서·부호의 검증, 원형 R 코드의 sidecar 보존 및 잘못된 이전 본문 거부를 확인했다. 새 cache adapter v4의 실제 초기화와 네 가지 정확 쌍 결합 검사를 통과했으나 캐시 생성 증거는 아니다.
- ROOT11 preview3의 guard V7은 이전 LTER 본문 한 건을 거부했다. snapshot16/preview4와 guard V8에서는 그 문제가 해소됐고 다른 literal 본문 두 건(1022680, 1228201)이 거부됐다. 새 표시를 자동으로 면제하지 않는다. 원문·선택 본문·사유를 추가 검토하고 정확 교정 또는 입증 전에는 채택하지 않는다.
- controls의 앞선 세 UTF-8 손상 본문은 새 버전으로 복구됐고 guard V7/V8에 invalid UTF-8 실패가 남지 않았다. 앞선 손상본과 실패 증거는 그대로 보존한다.
- 총괄이 메타데이터 상태 확인에 `python`을 사용해 command not found를 받았다. 실제 환경의 고정 tlm_torch Python 경로로 재실행했다. 데이터 변경은 없었다.
- 총괄의 스냅샷 출력에서 review history와 sidecar 목록까지 포함해 도구 출력이 잘렸다. 뒤이어 필요한 키와 계수만 제한해 다시 읽었다. 잘린 출력으로 문서 전문 판독이나 전체 이력 검증을 주장하지 않는다.
- Luna의 잘못된 packet 경로 호출은 내용 없이 No such file 결과였다. 각 담당자가 지정 TASK의 실제 경로로 돌아가 전문과 END를 확인하고 자기 오류 메모/리뷰를 보존했다. 보호 입력이나 다른 역할 입력 접근을 허용하는 근거로 쓰지 않는다.
- 채워진 Java 제목 목록을 위치만으로 추천 UI라고 본 224013은 총괄이 원문을 읽고 보존하도록 정정했다. 실제 CTA와 저자 정보·채워진 참고 제목을 구분한다. 향후 새 버전의 실제 저장과 선택 연결이 필요하다.

공식 cache_reviewed_partial_v2는 변경하지 않았다. 새 ROOT11 승인·새 roster·새 캐시 생성·독립 consumer·전체 재계측은 별도 미완료다. 원문을 읽지 않고 reviewed HOLD로 개명하는 작업은 하지 않는다.
