# 실제 프로그램과 외형 기호의 정확 본문별 판정

이 문서는 기존 코드 보호를 전역 완화하지 않는다. 아래 일곱 원문/수정본의 정확 SHA 쌍에 대해서만, 실제 프로그램이 아닌 장식/인용/키보드 잡음이 코드로 잘못 분류됐다는 판독 근거를 연결한다. Unicode 예제 보존은 그대로 검사한다. 본문 변경, 다른 원문, 다른 수정 버전에는 이 판정이 적용되지 않는다.

| 안 | 처리 | 장점 | 한계 |
|---|---|---|---|
| A | 알려진 오탐도 모두 계속 HOLD | 기존 자동 보호를 그대로 사용 | 실제 보존·수정이 끝난 역사/조리/글쓰기 본문까지 풀지 못함 |
| B | 정확 원문SHA와수정본문SHA, root 판독 근거, 실제 코드 조각의 문자 보존을 함께 고정 | 근거가 확인된 해당 바이트 쌍만 처리하며 새 본문은 다시 거부 | 버전이 바뀌면 새 실제 대조가 필요 |
| C | tilde/backtick/fence 보호를 전체 끄기 | 빠른 형식 통과 | 실제 코드와 Unicode·정보 손실을 놓칠 수 있어 채택 불가 |

B를 적용한다. 이전 생산 코드와 최종 zero-HOLD 조건은 바꾸지 않고 별도 새 보호 함수/어댑터에서만 연결한다. 현재 중간 캐시의 생성·독립검증에는 이 예외를 사용하지 않았다. 새 예외의 실제 적용·캐시 생성·검증은 별도 영수증이 필요하다.

관련 입력은 curated snapshot_v5와 literal_guard_recheck_v1의 정확한 본문/판독 파일이며 다음 승인 JSON이 각 실제 SHA를 소유한다. 이 판정은 외부 사실/권리 확인이나 모델 품질·실행 성공이 아니다. 일곱 건 밖의 코드 보호를 면제하지 않는다.
