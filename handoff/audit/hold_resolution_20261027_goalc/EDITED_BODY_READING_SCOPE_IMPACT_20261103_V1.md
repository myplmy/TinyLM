# 이미 판독한 입력의 수정본 검토 범위

46845는 원문109206자와 실제 변경 공란 네 구간을 가진 사례다. 문서 건수와 판독 분량이 같은 작업량 단위가 아님을 보여준다. 이 사례 하나로 전체 지연 기여율이나 개선율을 추정하지 않는다. `impact-analysis`의 방법 비교와 영향 축을 적용한다.

| 안 | 확인 범위 | 비용 | 남는 판단 |
|---|---|---|---|
| A | 수정할 때마다 새 본문 전량 재열람 | 변경 없는 긴 부분도 다시 읽음 | 전문 안의 의미·조건 판단은 여전히 필요 |
| B | 서식 변경은 차이, 의미 변경은 전문 재열람 | 수정 종류에 따라 달라짐 | 서식처럼 보이는 조건·소유관계 변화의 분류가 필요 |
| C | 실제 입력 판독을 유지하고, 수정본은 전체 차이·변경 문맥·끝을 읽고 총괄이 나머지 바이트 보존을 검산 | 변경하지 않은 구간의 반복 출력을 줄임 | 소유 범위나 순서가 불명확하면 해당 범위 또는 전문 재열람 필요 |

C를 적용한다. 아직 읽지 않은 원문이나 첫 독립 검토의 입력 전문을 생략하지 않는다. 원문과 후보가 같다는 기존 고정 증명이 있는 경우에만 이미 허용한 중복 입력 생략을 유지한다. 다른 역할이 수행하는 독립 검토를 같은 역할의 재읽기로 대체하지 않는다.

역할이 새 수정본 전량을 다시 출력하지 않는 경우, 다음 조건을 모두 지킨다.

- 해당 정확 입력의 실제 판독 기록과 ID·원문SHA·후보 버전이 있어야 한다.
- 새 파일에 저장하고 이전판을 보존한다. 모든 차이 hunk와 변경 전후 문맥·문서 끝을 실제로 확인한다. 잘린 출력의 END나 EOF만 보고 전체 차이를 읽었다고 하지 않는다.
- 조건·부정·화자·단위·표의 소유자 및 절 경계를 함께 확인한다. 문맥이나 순서가 불명확하면 필요한 더 넓은 범위 또는 새 본문 전문을 읽는다.
- 총괄은 보호 ID와 원문SHA를 먼저 확인한 다음, 입력·출력 버전과 SHA 및 전체 차이를 대조한다. 변경 밖의 보존은 바이트 대조로 검산하고, 기계검사만으로 의미 보존을 승인하지 않는다.
- 리뷰에는 ‘이전 입력 전문 판독 + 새 전체 차이/변경 문맥/끝 확인’이라고 실제 범위를 쓴다. 새 전문을 읽지 않았으면 읽었다고 쓰지 않는다. 같은 읽기를 독립 판독 두 건으로 세지 않는다.

| 프로젝트 영향 축 | 처리 |
|---|---|
| GPU·학습·모델 권한 | 변경 없음. CPU 정제·파일 검산만 하며 추가300M은 계속 금지 |
| 데이터·로그·동시 소유권 | 자기 지정 입력과 새 TXT/MD만. 원형·이전판·기존캐시·보호자료·타세션자료를 덮거나 삭제하지 않음 |
| 학습 비교 조건 | 풀·토크나이저·학습토큰·초기화·평가 경로를 바꾸지 않음. 채택과 캐시 검증은 별도 |
| 증거 수준 | 원문 전문, 독립 검토, 수정 차이, 바이트 검산, 의미 판단과 실제 채택을 분리해 기록 |
| 정본 연쇄 | 현재 WIP·감사 기록에 반영하고 최종 결과·계획·기준표·METHODS·COMPASS는 전체 처리와 검증 근거로 갱신 |

기존 다섯 역할은 이 MD 하나를 읽을 수 있다. 기존 정확 입력 경로와 controls의 birth 고정 reader는 유지한다. 코드·시험·해시·통계·웹·Git 권한을 역할에 추가하지 않는다. 개선 뒤의 실제 처리율은 아직 측정하지 않았다.
