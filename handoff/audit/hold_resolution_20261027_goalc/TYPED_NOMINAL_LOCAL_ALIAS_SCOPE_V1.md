# 실제 대상과 역할이 명시된 첫 문단의 빈 별칭 검사

전체 잔여19,123개 필드 후보를 대상으로 새 진단을 수행한다. 대표 판독은 규칙 검증이며 처리량 상한이 아니다. 현재 v26과 생산66개는 동결하고 새 audit 도구·새 data_cache 버전만 작성한다. 개별 본문 수정은 계속 Luna 역할이 맡는다. 새 일반 규칙의 기계 후보는 실제 원문 재생성과 독립 의미 판독·총괄 채택 전에는 캐시에 넣지 않는다.

| 안 | 내용 | 장점 | 한계·비용 |
|---|---|---|---|
| A | 모든 빈 괄호를 제거 | 처리량이 큼 | 함수 호출·빠진 수식·문헌 전사와 선택적인 별칭을 구별하지 못함 |
| B | 모든 빈 괄호 자료를 계속 보류 | 새 변질이 없음 | 실제 주체와 정보가 완결된 문서도 복구하지 못함 |
| C | 문단 처음의 명명된 대상, 실제 서술된 인물·지리·작품·기관 역할, 완결 문장, 유일한 빈 별칭을 함께 확인 | 범위가 좁고 남은 모든 정보를 보존하며 전량 증명 가능 | 다른 위치와 수식·기호 교육 문서는 적용하지 못함 |

선택 C. 이름과 서술 역할의 단순 동시 출현만으로 증명하지 않는다. 빈 괄호가 실제 첫 주어에 붙어 있고 바로 뒤에 한국어 주제 조사가 있어야 한다. 따옴표·전사·코드·수식·기호 문맥과 추가 빈 필드는 제외한다. 삭제는 해당 빈 괄호 두 기호 및 내부 공백뿐이며 순서·학술 용어·숫자·날짜·조건·채워진 별칭을 바꾸지 않는다. 나머지 기존 사유가 남으면 계속 미결이다.

| 경로 | 권한·동작 | 제외 |
|---|---|---|
| 이 audit의 새 helper·시험·전량 진단기 | goal의 관련 CPU 코드·시험 허가로 신설 | 동결 코드 수정 |
| 소유 data_cache의 새 파생 버전 | goal의 원문 연결·전량 분석 허가 | 원본·기존 캐시 덮기·삭제 |
| 지정 Luna 새 TXT/MD | 원문 전문과 새 기계 후보의 독립 판독 | 코드·시험·해시·Git·웹·모델 |

코드 영향은 새 audit helper와 이를 호출하는 새 진단기뿐이다. 기존 v26은 그대로 재현하며 기존 판정과 새 진단을 함께 기록한다. 데이터 계보·토크나이저·EOS·분할·원문 SHA는 동일해야 한다. 시험은 호출 괄호·수학 정의·명명되지 않은 역할·두 번째 빈 슬롯·인용·글리프·주체 뒤의 별개 괄호·숫자/날짜 보존을 반례로 확인한다. 정본 수치는 실제 캐시 편입 뒤에만 갱신한다. 유지보수 부담은 좁은 어휘 역할 목록이며 미확인 유형으로 넓히지 않는다.

GPU·모델·학습·추가300M·설치·다운로드·유료서비스는 실행하지 않는다. 보호TinyDataset, 타 세션 전용 자료, 보호7 원문 부모는 접근하지 않는다. 형식 복구는 사실검증이나 모델 품질 증거가 아니다. 고유 원문 수·캐시 위치·토큰을 구분하고 실제 총괄 채택 전의 감축량을 보고하지 않는다.
