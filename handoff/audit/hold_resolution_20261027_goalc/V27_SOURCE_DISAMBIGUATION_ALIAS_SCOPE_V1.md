# 대량 처리 방법 복귀: 명시 동음이의 목록의 빈 병기

사용자 질문으로 실제 이전 방법을 재확인했다. cache3의350522 처리 위치는 EDIT195071/KEEP32187/EXCLUDE123264다. 이는 전량 수작업 판독 수가 아니다. v26 draft는 기존297512행을 그대로 검산하고 영향27원문만 새로 처리했다. 당시 흐름인 실제 사례·반례 → 좁은 규칙 보완 → 회귀 → 전량/변경범위 적용 → 독립 문맥·캐시 검산을 이어간다. 현재 field/other reader는 유형 전량을 각 문서 판독으로 넘기는 절차로 바뀌었고 새 일반화 규칙은26에서 멈춰 있었다.

## 확인한 원문

총괄이 원형 전문과 후보 전체 diff를 읽은 마이어377815, 페랭319241, 상호713313은 명시적으로 다음 뜻/사람/대상을 가리키는 목록이다. 채워진 이름·연대·직업·작품을 보존하면서 빈 병기만 다룰 수 있다. 현재26은 모두 `UNRESOLVED_FIELD_OR_TITLE` 하나로 PENDING이다. 377815의 `(, 1904~2005)`에서 연대는 실제 값이며 비어 있는 앞 병기 칸만 제거 대상이다. 원문 밖 이름·번역을 채우지 않는다. 쓰다주쿠31567·샤나군293559·플랜츠1067899 등은 이번 첫 확장의 명시 목록 범위를 벗어나므로 자동 포함하지 않는다.

| 안 | 내용 | 영향·비용 |
|---|---|---|
| A | 목록의 모든 인명·빈 병기를 계속 개별 작성 | 구현 변화가 작지만 동일 문법의 반복 판독 비용이 크다 |
| B | 완결된 첫 동음이의 선언과 실제 이름이 있는 행만 기존 명칭 변환으로 처리하고, 연대 앞 빈 병기 구분자를 별도 증명 | 원문 값·순서·수학/코드 보호를 재사용하며 새 인식 범위를 명시적으로 검사한다 |
| C | EOF 빈 표제 제거 모양만 별도 묶음 검산 | 범위가 더 작고 접미부 보존을 쉽게 입증하지만 본문에 남은 빈 병기 판단은 해결하지 못한다 |

수행은 B다. C의 접미부 검산도 그대로 쓰되 원문 전체를 무검토 통과하는 근거로 쓰지 않는다. 새 규칙 후보는 즉시 캐시 채택이 아니며 독립 판독·반례 및 전량 delta 검증이 필요하다.

| 경로 | 동작·권한 | 제외 |
|---|---|---|
| `scripts/p106b_hold_resolution_disambiguation_v1.py`, `scripts/p106b_hold_resolution_policy_v27.py`, 해당 CPU 시험 | 사용자 objective1·6과 원래 대량 방법 재개 범위의 새 파일 | 기존1~26/캐시/원문 덮기 없음 |
| 현재 세션 audit·새 metadata delta | 규칙 근거/계수/독립 검토 | 원형/후보 사본·전체 ledger 재복사 없음 |

영향: 코드 호출은 새27→기존26 한 곳이며 기존6의 명칭 병기/수학·값 보호와9의 구조를 재사용한다. 데이터는 새 초안만 생기며 원문 이름·숫자·단위·불확실성·코드·순서가 유지돼야 한다. 새 처리에는 완결된 첫 목록 선언, 실제 한글 명칭, 보호 구간/문법·수식·값 이름 배제, 닫힌 괄호가 필요하다. 불명 주체나 비어 있는 연대값은 채우지 않는다. 실제 부분 HOLD와 개별 제한 원형을 일반 규칙으로 해제하지 않는다.

시험은 원래 정책 회귀를 재사용하고 선언 없는 목록, 수식/함수/튜플/인구값, 불완전 괄호, 앞뒤 값이 없는 연대, 채워진 한자/외국어 병기, 코드·인용, 실제 개별 HOLD를 반례로 추가한다. 숫자/code/Unicode/style/순서의 일반 gate는 바꾸지 않는다. CPU 도구만 실행하며 모델/GPU/학습/설치/다운로드/TinyDataset/타 세션 자료는 제외한다. 모델·실험 조건 변경이 없어 기준표/METHODS/COMPASS는 최종 정제 결과 때 갱신하고 지금은 WIP와 이 audit가 진행을 기록한다.
