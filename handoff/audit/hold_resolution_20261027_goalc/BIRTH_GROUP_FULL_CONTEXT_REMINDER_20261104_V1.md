# 출생 묶음은 입력 분류이며 검토 범위를 날짜만으로 줄이지 않는다

현재 `birth_root11_independent_v1`의 출생이라는 이름은 입력을 묶은 유형이다. 승인된 의미 보존 정제 원칙 전체가 적용된다. 원문·후보·전체 차이를 실제 읽은 뒤 판정하며, 후보와 원문에 같은 오류가 있거나 기존 diff가 빈 각주 제거뿐이라는 이유로 나머지 형식 손상을 허용하지 않는다.

공식 행을 마감할 때 같은 입력 안의 다음 경계도 확인한다.

- 실제 내용이 전혀 없는 절·목록·표 예고와 그 빈 목록에만 붙은 범례는 원형·위치·사유와 함께 분리한다. 채워진 하위절이 있는 상위 표제와 유효 목록은 보존한다.
- 빈 병기·고립된 서식·명확히 닫히지 않은 괄호는 채워진 이름·값·관계를 보존하며 최소 정리한다. 같은 최소 편집을 ID마다 허가받을 필요는 없다.
- 연도·날짜·숫자는 실제 주체와 역할을 확인한다. 출생 대 사망, 실제 생일 대 호적상 날짜, 재위 대 즉위식, 전투일 대 사망일을 임의로 합치지 않는다. 출처가 분명한 인용은 그 귀속과 한정어를 유지한다.
- 범위 한쪽을 분리한 뒤 남은 날짜가 다른 역할로 읽히면 원문이 명시한 역할만 보존한다. 소실된 값·주체·역법이나 사실은 생성하지 않는다.
- 없는 표·발화·수식·제목을 직접 가리키는 결손 단위는 분리하고, 독립적으로 완결된 정의·설명·인명·조건·유보는 보존한다. 살아 있는 병기 제목·서지·인용을 빈 원제와 함께 지우지 않는다.

새로운 외부 사실검증·날짜 환산·나이 역산·전량 역사 사실교정을 수행하라는 지시가 아니다. 이미 읽은 전문을 도구 전환이나 이 알림만으로 다시 읽을 필요도 없다. 같은 확정 경계는 바로 적용하고, 새 주체·출처·조건 귀속이 실제 모호한 경우만 묶어 중재를 요청한다. 다음 미착수 TASK를 자동으로 계속하고 매번 번호 승인을 기다리지 않는다.

확정 본문과 리뷰는 새 버전으로 보존하며 원형·기존 캐시·로그를 덮거나 삭제하지 않는다. 새 `draft_`만 작성 중 편집 가능하다. 현재 읽기/새 TXT·MD 범위와 고정 reader 외의 코드·해시·통계·Git·웹·모델 권한을 추가하지 않는다.
