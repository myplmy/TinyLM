# 재개·판독 경로 명확화 V3

현재 사용자 전체 정제 재개 지시와 기존 지정 경로/금지 경계를 유지한다. 이 안내는 내용 판독·채택·독립2차 완료 증거가 아니다.

- 현재 정확 TASK의 native original/candidate 각각 전문+직접 full diff, 또는 이 세 프레임을 담은 연속 패킷 전부는 대안이다. 한 경로의 실제 EOF를 온전히 확인했다면 같은 세 내용을 다른 경로로 다시 읽을 필요 없다. controls는 기존 고정 reader 경로만 사용한다.
- literal의 동일성 계획은 ROOT_IDENTITY_TASK_NNN_V2.md, field/other의 기존 계획은 ROOT_IDENTITY_TASK_NNN_V1.md다. field/other 계획과 identity_reading_proofs_v1.json은 native 준비 때 이미 실제 바이트/순서 frame 검산으로 생성됐다. JSON은 Luna가 직접 열지 않고 자기 현재 역할 폴더의 해당 MD만 사용한다. 해당 ID에 명시된 원문+최종diff 구간은 실제 읽고, 증명된 candidate 중복 구간만 생략한다. 원문/후보 두 독립 판독으로 세지 않는다.
- 같은 역할의 현재 지정 TASK/페이지 안에서 자기 TXT/MD 이름은 rg --files로 찾을 수 있다. 다른 역할·미지정 cohort·보호경로로 넓히지 않는다. 다음 TASK/페이지는 자기 완료 review/append-only PROGRESS_LOG/전체 TASK 색인의 정확 커서를 사용하며 매번 새 허가를 기다리지 않는다.
- No-such-file 또는 실행파일 중복 입력 같은 호출 오타는 권한 거부가 아니다. 이미 TASK/ROOT가 지정한 정확 명령·경로로 바로 고쳐 이어갈 수 있다. 실패 호출은 미판독이고 내용을 반환한 적 없으면 판독했다고 세지 않는다. 바깥 경로를 추측 검색하지 않는다.
- 같은 최소 경계 규칙으로 닫히는 빈 슬롯/직접 지시/고아 접속은 재승인 질문 없이 새 TXT/sidecar/리뷰로 마감할 수 있다. 실제 새로운 의미 충돌이나 소유가 정해지지 않는 사례만 원문 행과 앞뒤 실제 인용·제안 경계를 묶어 총괄에 질의하고 독립 항목을 계속한다.
- 표시식/예시가 없어도 원문에 주체·조건·값·명명 API/기능이 실제 채워진 독립 설명은 보존한다. 빈 값과 그 값이 있어야만 뜻이 정해지는 직접 절만 원형 보류한다. 비교 기준/연도가 빠졌는데 접속어만 지워 무조건 현재 주장으로 만들지 않는다.
- 구조가 소실된 코드의 값에만 의존하는 후속 실행 단위/결과는 함께 보류한다. 그 코드 안에만 있는 이름을 추출해 새로운 API 설명/실행 예제를 만들지 않는다. 실제 원저자 오류/질문/의사코드/TODO 자체를 추출손상이나 편집메모로 확정하지 않는다.
- 실제 채워진 인용/이름/제목/저자/URL/날짜/조건/불확실성은 보존한다. 빈 괄호 일부가 있다고 같은 괄호 안 채워진 이름 전체를 삭제하지 않는다. 자료가 없다는 지시만 분리하고 채워진 서지는 원래 자료 범위를 유지한다.
- 새 수정 TXT 전문과 전체 diff는 반드시 실제 확인한다. 입력의 동일성 생략 증명이 새 수정본문까지 적용되는 것은 아니다. 기존 원문·후보·확정/미확정 초안은 덮거나 삭제하지 않고 새 버전만 쓴다.
- 코드/시험/통계/해시/웹/Git/모델/GPU는 Luna에게 여전히 금지다. 고정 reader와 허용된 도구 호출 묶음은 그 기존 범위 안에서만 사용한다.
