# 전량 처리표의 새 부분 캐시 편입 범위

전체 goal은 진행 중이다. 확정한 최초 HOLD297,539고유 원문SHA·460,695위치·462,874,291입력ID를 전량 처리표로 연결했다. v26의 실제 생산·독립 검산, 원문별4,381개 정확 선택과 후속 독립49 판독, 실제 캐시 가드·보호 메타데이터·코드 예제 검산을 근거로 새 부분 캐시만 만든다. 공식 이전 캐시H160,219는 새 실제 캐시와 독립 소비자가 통과할 때까지 유지한다.

새 처리표의 미처리73,668고유/115,526위치는 여전히 `UNRESOLVED_NOT_ADMITTED`다. 원형 부재·모호함을 개별 검토해 확정한 종결HOLD라고 부르지 않고, 이름만 바꿔 전체 goal을 완료하지 않는다. 이 단계의 root 승인·캐시 생성·검산은 추가300M 학습 재개 승인이 아니다.

새로운 기계 규칙을 이 승인으로 만들지 않는다. 동결v26의 terminal219,490개와 source/body/review를 특정한 개별4,381개를 연결한다. 기존 실제 부분v1은 옛 제한적 안정 집합이고, 원래 v5가 보존하는 baseline1,145,290본문과는 다르다. 앞서 발견한v1의3,421재비교도 최신 전량 규칙·개별 선택에 따라 새 버전에서 다시 처리하며 기존v1을 덮거나 삭제하지 않는다.

| 결정 경로 | 승인하는 근거·제한 |
|---|---|
| 동결v26 규칙의 KEEP/EDIT | verified25 원형·전체 보존 및 좁은delta26의 실제/독립 검산·native원문27쌍, 기존 언어/위험/유형별 판독과 반례 조치. KEEP은 원문SHA 불변, EDIT는 고정된 본문SHA·비공백 순서/코드/Unicode/의미스타일 가드를 통과한 규칙 결과다. 전량 사실검증이 아니다. |
| 개별4,381 선택 | ROOT_AUTHORED_SELECTIONS_V10의 정확 원문/본문/리뷰와 실제 전체 가드 검산. 의미 있는 반복·부록·인용·API·서식은 판독 근거와 함께 보존한다. |

| HOLD73,668 | 후보 본문·해시를 채택에 넣지 않고 `root_approved=False`·`UNRESOLVED_NOT_ADMITTED`로 유지한다. 후속 전체 복구가 남는다. |

9개 코드 가드 예외는 정확 SHA쌍과 리뷰에 한정하며 실제 코드 단위/비어 있지 않은 Unicode 예제는 보존한다. 동결v22의 첫 명명 정의 빈 병기 증명은 그 한 쌍에만 적용하고 다른 함수 호출을 보호한다. baseline에는 적용하지 않는다. 메타데이터 보호7건과 같은SHA11위치는 본문을 디코딩하지 않는다. 이 중3개 이미 승인한 안전 뷰는 정확 EDIT로만 인코딩하고 KEEP/SOURCE_SLICE를 금지한다. 초안v26의1250821 KEEP은 이 안전뷰 EDIT가 대체하며 원형으로 자동편입하지 않는다.

원문 전체·기존캐시·원로그·실패 초안은 불변이다. 새캐시는EOS2·문서경계·토크나이저·UTF8·직렬화·train/val·정확중복·256ID구간겹침·기존baseline보존을 동결된 생성기와 독립소비자로 검사한다. 원문서URL/ID가 없어 확인하지 못한 원문서 단위 누설은 계속 미확인이다. 새 산출물은 개별20,000,000바이트 미만이다.

현재 여유 공간은약519GB이며 기존 실제 부분캐시 생성은약1,781초였다. 새시간은 보장하지 않으며 CPU·디스크 입출력만 사용한다. GPU·모델·교사·학생·스모크·추가학습·설치·다운로드·유료/외부서비스·push/PR은0으로 유지한다. 보호TinyDataset·타세션 전용 경로는 접근하지 않는다. 새캐시 뒤 전량 재계측·잔여 유형 처리·정본 연쇄·한국어 로컬 커밋을 계속한다.
