# 검증 진입 실패와 판독 연결 반려의 보존

이전 V3와 원형 실패 파일은 유지한다. 이번 추가 기록은 전체 goal 완료/일시중지 근거가 아니다.

| 실행/자료 | 관측과 조치 |
|---|---|
| 새 부분 캐시 독립 소비자 첫 실행 | 실제 종료1, 검증 파일0. CLI가 이전 모듈의 verify를 자기 자신으로 바인딩해 재귀 진입했다. 생성된 캐시와130개 동결 입력을 보존하고 별도 직접 라이브러리 진입점을 만들었다. 실제3개 반례 시험 뒤 두 번째 전량 소비자가 종료0으로 네 증거를 생성했다. 첫 실패 로그/영수증은 그대로 남긴다. |
| 수집61의 새732 중간 회수 | 270행 저장,462행 대기,1행 중재,9행 정확 출력 결합 반려. 9행은 출력 셀에 TXT와 sidecar MD가 함께 들어 있어 단일 TXT 계약과 맞지 않았다. 역할은 새009/010/011 교정 리뷰를 저장했다고 보고했으며 새 수집으로 검증하기 전에는 반려 해소로 승격하지 않는다. 과거26개 오류와 이 실패를 보존한다. |
| 공개 조정 메모를 붙이려던 셸 호출 | Codex PreToolUse 역슬래시 보호 훅이 쓰기 명령 안의 역슬래시 n 표기를 실행 전에 거부했다. 같은 호출의 읽기 부분도 실행 증거로 세지 않았다. 실제 별도 읽기와 리터럴 heredoc 추가는 이후 종료0으로 수행했다. 자동 승인 심사 거절이나 상대 데이터 조사 결과로 표현하지 않는다. |

후속 역할의 잘못된 경로 호출과 내용 미수신은 각 자기 MD의 관측 보고로 보존한다. 해당 잘못된 경로를 총괄이 다시 열어 확인하거나 OS 보호 성공으로 해석하지 않는다. 실제 지정 입력·출력·리뷰는 별도의 TASK/SHA 결합으로 검증한다.

새 검증 수량은 REVIEWED_PARTIAL_V2_VERIFIED_METRICS_V1.json이 소유한다. 잔여115,526위치/73,668고유는 아직 미처리/미결이며 새732 및 다음2,743 원문 판독의 준비·대기열 생성은 처리 완료가 아니다.
