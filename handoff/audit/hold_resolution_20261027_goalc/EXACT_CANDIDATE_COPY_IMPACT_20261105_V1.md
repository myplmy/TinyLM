# 담당 후보 복제의 경계와 영향

사용자 목표의 CPU 도구 구현 범위에서 총괄이 코드만 작성한다. 실제 학습 TXT 복제·편집은 해당 역할 에이전트가 수행한다.

| 방안 | 이점 | 비용·위험 | 선택 |
|---|---|---|---|
| TASK를 보고 수동 cp 유지 | 새 도구 불필요 | 지난 ID·다른 폴더·예전 후보를 재사용한 실제 오류가 반복됨 | 미선택 |
| 역할·TASK·ID·고정 후보 SHA 대조 후 새 버전만 복제 | 후보 경로를 추측하는 단계가 없어지고 원형 및 기존 초안을 보호함 | 도구 경계 시험 필요, 문맥 검수는 별도로 필요 | 적용 |
| 후보를 다시 입력 | 복제 경로 자체는 불필요 | 재입력 비용과 전사 오류, 숫자·코드 누락 위험 증가 | 미선택 |

호환성은 기존 root12 manifest와 TASK 및 역할별 TXT 이름에 한정한다. 파일 복제 도구는 선택 후보를 바꾸거나 채택하지 않는다. 후속 작업본 복제에는 사용하지 않는다. 기존 작업본의 수정 내용을 잃지 않도록 후속 보완은 총괄이 특정한 현재 입력 경로·SHA를 따른다.

보호 ID·해시는 본문을 열기 전에 거부한다. 메타데이터 전용 검사는 원문·후보 TXT를 열지 않으며 파일을 생성하지 않는다. 실제 복제는 후보 bytes와 SHA·UTF-8·20 MB 미만을 대조하고 해당 역할 폴더의 새 파일만 배타적으로 생성한다. 원형·기존 파일 덮어쓰기, symlink, 임의 입력 경로와 출력 경로는 허용하지 않는다. 애플리케이션 검사이며 운영체제 권한을 새로 부여하는 기능은 아니다.

검증은 실제 고정 TASK의 유효 메타데이터와 잘못된 역할·TASK·보호 ID·기존 출력·경로 이탈을 사용한다. 총괄 검증은 `--check-only`만 실행하므로 학습 TXT를 만들지 않는다. 실제 에이전트 복제는 이후 별도 관찰 근거로 남긴다.
