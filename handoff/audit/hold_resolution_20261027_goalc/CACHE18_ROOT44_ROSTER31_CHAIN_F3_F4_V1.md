# 캐시18의 통합 선택44·원장31·opaque·참조 census 연결

현재 사용자 승인 범위는 CPU 정제/검증/파생캐시/한국어 로컬 저장이다. GPU/모델/추가300M 학습은 포함되지 않는다.
공식cache17(ROOT39)의 H101721과 마지막 물화roster30(ROOT40)의 H101343을 구분한다.
ROOT41/42/43/44는 각각112/20/53/26고유를 추가했으며 이전 선택 prefix를 그대로 보존했다.
roster30→31은 이4선택을 한 번에 합쳐211고유411위치를 반영한다. ROOT39→44의 cache delta는400고유789위치다.

대안 A는 작은 선택마다 전체2154912위치 캐시를 다시 생성하는 것으로64분가량의 build/consumer와 대량파일이 반복된다.
B는 닫힌 source/body/review 증명과 prefix를 모아 한 roster/opaque/참조census/실제delta검사 후 전체캐시를 한 번 생성·검증하는 것이다.
C는 새본문의 검사를 생략하고 기존 캐시 검증으로 대신하는 것으로 잘못된 완료 주장이 된다. B를 적용한다.

기존 guard6 등록 roster builder/verifier, native metadata prefix reader, prepare opaque2/verify opaque3,
참조census4, cache10/runner7을 그대로 재사용한다. 새 full legacy census 원문사본이나 model/index preflight는 만들지 않는다.
원장297539 canonical rows와 원래460695위치/462874291 inputIDs를 보존하고 각새선택/원형SHA/최종SHA/리뷰를 대조한다.
원장31과 선택44가 일치하는 opaque를 새로 만들어 참조 parent census의 top-level source id/SHA로만 대응한다.
source/candidate로 들어가기 전 guard6의13제한ID/25hash/21alias를 적용하고 실제필터360211의 원형/후보/packet은 열지 않는다.
세 과거 승인 안전파생본문은 정확 CAS만 사용하고 원형/compare-source를 열지 않는다.12122의 정확 Unicode 예외도 기존 입력쌍만 적용한다.

전량 cache worker는 하나만 CPU1로 실행한다. config와 모든 runtime pin은 build/consumer 종료 이후에도 재현 기록으로 불변이다.
참조census의 부모 열거는 원형/후보 payload사본0이며, adapter가 명시 승인한 일반 evidence pin을 해시할 수 있음은 별도로 기록한다.
실제delta code guard는 matching 선택44/원장31/opaque44 아래에서 모든400개 새고유를 검사한다. 전체인덱스나 모델을 만들지 않는다.
그 성공은 전체build/consumer 성공과 별개다. consumer6core+2companion·누설/문서경계/EOS/tokenizer/직렬화·전량본문증명이 끝나야 cache18을 공식으로 쓴다.
원문서ID 부재에 따른 article-level leakage 미확인은 계속 명시한다.

실패cache16의 exit1/검증없음과 원로그는 보존한다. cache17/과거기준본·원형/타세션자료를 새 삭제 승인 없이 삭제하지 않는다.
중간metadata와CAS본문은 동일hash재사용하고 수집/분석은 마지막마감분까지만 동결한다. 이후 저자결과는 별도 후속선택/저장분이다.
정제 rule processing, Luna모델저자 최초전문판독, ROOT승인, cache채택, 모델품질, 사용자사실검증은 서로 다른 증거수준이다.
이 실행만으로 전체goal의 A–E 충족이나 추가학습 승인을 주장하지 않는다.
