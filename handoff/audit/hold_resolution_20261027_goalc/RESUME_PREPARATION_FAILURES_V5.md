# 후속 회수·재판독 중 실패 및 정정 V5

전체 goal과 WIP 1번은 계속 진행 중이다. 아래 사건을 성공 기록으로 치환하지 않는다.

1. `prepare_exact_rechecks_and_meridian139_v1.py`는 1006080을 hangul 역할로 잘못 묶은 총괄의 지정 실수를 소유권 검사에서 잡아 종료 1이었다. 그 전에 생성된 반복 역할 허용서 4개는 보존했다. 실제 manifest 소유자는 legacy이며, V2 준비기는 기존 허용서 바이트 일치를 확인하고 그대로 유지한 뒤 올바른 역할의 출생 허용서를 생성해 종료 0이었다. 총괄의 잘못된 메시지도 취소했다. 이를 잘못된 역할의 원문 읽기가 실행됐다는 증거로 보지 않으며, 보호 기능 전반이 검증됐다고 확대하지 않는다.
2. V2 준비기를 만드는 첫 셸 쓰기 요청은 리터럴 역슬래시 n 때문에 Codex 전용 PreToolUse 훅이 차단했다. 해당 도구 요청은 실행되지 않았고, 줄바꿈을 `chr(10)`으로 구성한 후속 요청이 성공했다. 이는 자동 승인 심사 거절이 아니다.
3. Latin 역할의 832056 잘못 조합한 경로에서 내용이 반환됐다는 자기 보고는 `path_error_note_v4.md`에 보존했다. 총괄은 보고된 잘못된 경로 6개를 lstat만 했으며 현재 모두 부재였다. 과거 실제 내용 반환이나 비공개 접근 여부는 독립 확인되지 않았다. 잘못된 경로를 다시 열거나 해시하지 않았다. 정확 원문·후보·공유 15패킷의 해시를 확인해 새 1,500자 읽기 조각 60개와 정확 명령 허용서를 만들었다. 이후 전량 판독 보고와 review_028_v2를 회수했지만 아직 새 캐시에 채택하지 않았다.
4. Latin 역할의 `path_error_note_v2.md`는 수집61의 핀 `92E42DDD26F1B7704CF58C6E359286E66630E51D9216585EC5C28FE897AAD3A1`과 현재 `20FA9CF5969E5E7ED089D158428EE07DD9F4F987370D6F97034875B410D2420C`가 다르다. 현재 내용은 reviewed_308758_v2.txt 부재 호출 기록이다. 이전 바이트의 별도 보존본은 확인하지 못했다. 역할은 새 v5에 변경 시점·도구 기억 없음/별도 보존 경로 미상을 구분해 기록했다. 과거 핀 무결성을 계속 통과한다고 주장하지 않으며 원형 보존 미확인 한계로 남긴다. 현재 버전 및 새 v5/v6는 별도로 보존한다.
5. 1116686의 중간 패킷 EOF를 입력 누락으로 오인한 보고가 있었다. 실제 manifest와 TASK에는 두 조각이 모두 명시되어 있고, 두 번째를 순서대로 읽어 마지막 END까지 확인한 뒤 새 sidecar에서 정정했다. 추가 검사에서 반복732/1,838패킷 및 출생2,743/3,501패킷 전량의 TASK 참조·순서 예외는 0이었다.
6. 첫 별도 수집은 실제 종료 0이지만 반복 판독 10건 누락, 미결8건, 실제 TXT 부재/출력칸 혼합 11건을 드러냈다. 출생은 575건 저장 중 미결10건이며 나머지2,168건은 미판독이다. 이 수집 상태를 정제 완료나 캐시 채택으로 바꾸지 않는다. 실제703+565본문을 전량 CPU 재확인해 code/Unicode/style/no_memo 검사는 통과했지만, 순서삭제107표시·미상주장자8발생·미상소유자3발생·무명도입8건은 문맥 재검토 대상이다. 새 수정 보고만으로 이를 모두 해결됐다고 세지 않는다.
