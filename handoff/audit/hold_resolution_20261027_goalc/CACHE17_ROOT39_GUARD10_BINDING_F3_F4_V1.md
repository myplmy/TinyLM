# ROOT39·roster29·cache10 실제 가드 선검사와 cache17

현재 공식 소비 검증 완료본은 cache15 HOLD 105824다. cache16은 전체 2154912위치 생성 후 원문 12122의 두 중복 위치에서 기존 Unicode 예시 가드가 빈 괄호 제거를 거절해 실제 exit 1로 끝났다. consumer는 실행하지 않았다. 실패를 완료나 정제 내용 오류로 바꾸지 않는다.

F3 대안은 (A) cache15 유지, (B) 기존 ROOT39·roster29를 유지하며 원문/본문 SHA가 고정된 12122 하나만 검증한 cache10으로 새 cache17 생성·소비 검증, (C) 승인 선택을 다시 변경하고 새 roster·reference 계약을 만드는 방법이다. B는 내용 재저술이나 전역 Unicode 검사 완화 없이 승인된 32개 코드포인트 표기와 실제 특수 문자 5개의 순서를 보존한다. A는 채택 4103위치가 소비본에 반영되지 않고 C는 이미 적법하게 정제한 문장을 다시 HOLD로 되돌리는 비용이 있다.

F4 독립 문맥 증거와 EXACT_UNICODE_EMPTY_ANNOTATION_12122_APPROVAL_V1.json의 정확한 두 쌍만 예외다. 기존 실제 코드, 채워진 Unicode 예시, 다른 ID·상태·본문 SHA·코드포인트 변경은 기존 가드를 그대로 따른다. source 및 candidate를 열기 전에 guard6를 적용하고 기존 세 승인 파생 본문의 원형·비교 뷰를 다시 열지 않는다.

전체 재생성 전 CACHE17_ROOT39_ACTUAL_DELTA_GUARDS_PREFLIGHT_V1.json이 실제 캐시 클래스와 partial.revision 정책을 사용해 ROOT29→39 변경 2551원문 전체를 검사했다. 구 가드는 12122만 거절하고 cache10은 0거절이다. 15.58초 범위 검사이며 전체 캐시 검증 또는 새 전문 판독 실적으로 세지 않는다.

cache17은 기존 원형과 cache15·16을 덮어쓰지 않는 새 파생 공간이다. 제안 census는 부모 HOLD 460695위치를 재계수한 metadata 참조만 생성하며 본문 복사 0이다. 전체 CPU worker는 하나만 실행하고 실제 build exit 0 뒤 consumer를 실행한다. 실행 중 고정 입력은 불변이며 저자 후속 결과는 다음 묶음이다. 실패한 cache16은 비교 근거로 보존한다. 이 문서는 신규 삭제 승인이 아니다. 목표 완료와 학습 승인은 모두 false다.
