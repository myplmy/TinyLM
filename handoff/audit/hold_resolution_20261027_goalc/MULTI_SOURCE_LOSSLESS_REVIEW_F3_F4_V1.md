# 같은 배정의 여러 ID를 한 번에 전달하는 판독

사용자 지시의 구간마다 반복하는 판독·기록 축소와 목표 CPU 도구·시험 허가를 적용한다.
기존 v3는 같은 ID의 최대3조각을 묶지만 짧은 각 ID는 별도 호출한다. H의20 ID에서
27조각/21호출이 실제 보고됐다. 새 기능은 같은 role/page의 최대5 ID가 metadata 준비를
한 번 공유하는 전달이며 원문 내용 판정·정제·리뷰 자동화가 아니다.

| 안 | 내용 | 장점 | 부담·영향 | 비용 |
|---|---|---|---|---|
| A |기존 ID별 호출 유지|변경 없음|짧은 문서도 setup·도구 왕복 반복|낮음|
| B |같은5개 배정 ID를 byte 제한 안에서 순서대로 전달|기존 core/scope/guard 재사용|일부만 반환되면 명시 커서로 계속 읽어야 함|중간|
| C |원형을 새 묶음 파일·상주 서비스로 변환|장기 캐시 가능|사본·수명·재개 관리 증가|높음|

B를 적용한다. 고정 새 shortcut만 사용하고 기존 v3도 유지한다. 새 CLI는 PAGE와
1–5개 ID를 받는다. role은 shortcut에 고정되며 기존 scope6의 같은 role/cohort 배정만
허용한다. 요청 ID 전부의 배정·원형/후보 SHA·guard6를 본문 I/O 전에 점검한다.
metadata pin은 호출 안에서 한 번 검증해 재사용한다. 각 pair는 기존 core3에서 그대로
준비하며 실제 EOF·UTF8 byte range를 바꾸지 않는다. 새 원형/후보/pair 사본은 쓰지 않는다.

출력 본문은 합계12000바이트 이하, 한 ID 최대3조각이다. 다음4KB 조각의 여유가 없으면
아직 반환하지 않은 ID를 목록에 남긴다. 긴 마지막 ID는 next_part를 명시한다. 해당 ID의
연속 조각은 기존 v3로 읽고, 미반환 ID는 별도 호출한다. 출력 전체가18000바이트를 넘으면
본문을 일부 인쇄하지 않고 거절한다. 호출의 max_output_tokens는16000 이상을 사용한다.
실제 tool 출력이 잘리면 EOF를 주장하지 않고 그 ID의 필요한 조각만 다시 확인한다.

공통 header는 반환한 ID들에 실제로 같은 metadata 값만 공유하고 per-ID header를 합치면
기존 v3 header와 모든 필드가 같다. 각 frame에 ID·part·범위·다음조각·실제 EOF를 유지한다.
5 ID가 반환됐다는 사실은 다섯 본문을 완독했다는 뜻이 아니며 각 ID의 EOF를 따로 확인한다.
여러 ID를 하나의 학습 본문으로 합치지 않고 기존5행 리뷰를 유지한다.

| 경로 | 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| audit의 새 entry·fixture·실측 증거 |신설|현재 효율화/CPU 시험 지시|기존 frozen 코드·계약 수정 없음|
| tmp의 다섯 새 role별 shortcut |신설|기존5역할의 같은 배정 판독|새 자료·역할 확대 없음|
| 기존 scope·manifest·원형/후보 |읽기|지정 HOLD 정제|보호자료는 본문 I/O 전 거절|

코드 영향은 새 전달 entry와 shortcut뿐이다. 같은 core3의 배정·SHA·diff 재구성·UTF8를
사용하며 상주 서비스/데이터 포맷 이관은 없다. 회귀는 잘못된 세 번째 배정/제한 SHA가
첫 정상 본문보다 먼저 거절됨, 중복 ID, 경계·EOF·UTF8·위조 marker·출력 한도와 header
독립 재구성을 검증한다. 실제 짧은5 ID 전달을 다섯 역할에서 기존 header/frame과 대조한다.
단순 호출 수·출력 비교를 전체 업무 속도 배율로 과장하지 않고 새 최초 판독으로 세지 않는다.

현재 cache16의206개 runtime pin은 바꾸지 않는다. 새 도구는 그 입력·학습 집합·ROOT
판정을 바꾸지 않고 새 원형 사본도 만들지 않는다. GPU·모델·TinyDataset·타세션·원형
삭제/덮기·Git 외부 상태는 제외한다. 결과·METHODS·COMPASS는 최종 실제 정제 수치의
묶음 동기화 대상으로 두며 이 전달 시험만으로 수치·학습 승인을 갱신하지 않는다.
