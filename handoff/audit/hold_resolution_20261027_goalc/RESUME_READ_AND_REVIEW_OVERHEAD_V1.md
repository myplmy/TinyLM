# 전량 판독을 유지한 호출·기록 비용 조정

권한·고정 V5 별칭·지정 ID·원문/후보 전량·SHA/EOF·새 본문 전체diff 확인은 그대로다. 새 패키지나 코드 실행 권한을 추가하지 않는다.

| 방식 | 효과 | 한계 |
|---|---|---|
| 매 part 한 호출 | 출력 작음 | 긴 문서에서 호출 왕복 반복 |
| 총 part 수 확인 후 같은 ID의 다음2~3 part를 한 functions.exec에서 독립 고정별칭 호출로 묶음 | 전량 바이트·순서를 유지하며 왕복 감소 | 합산 출력 예산을 충분히 잡고 각 결과를 모두 확인해야 함 |
| 거대한 문서 전체를 무제한 연결 | 호출 감소 | 출력 잘림·일부 미판독 위험 |

일반 문서는 두번째 방식을 사용할 수 있다. 첫 part의 역할/ID/양 SHA/총 part 수를 확인한 뒤 알려진 다음2~3개만 Promise.allSettled로 호출한다. 각 exec_command의 max_output_tokens와 바깥 exec의 max_output_tokens를 합산 크기보다 크게 잡는다. 번호순으로 모든 결과를 읽고 출력이 잘렸으면 해당 미노출 part를 다시 읽는다. 전문을 안 읽은 상태를 EOF 완료로 기록하지 않는다. 경계 판단이 새로 필요한 문서는 한 part씩 유지한다. packet 파일·원문/후보 사본은 만들지 않는다.

판정·본문·SHA·정확출력·보류범위가 바뀌면 새 정식 리뷰 버전을 만든다. 실제5개 판정행은 모두 정확하고 맨 끝 진행요약의 '세/네' 등 건수만 틀렸으면 기존 리뷰를 보존하고 PROGRESS에 정확한 정정 한 줄을 추가한다. 그 요약 오기만으로 전체 리뷰 사본을 또 만들 필요는 없다. 사용자에게 보고할 수량은 저장된 실제 ID 행과 수집 receipt가 소유한다.

이 조정은 전체 판독량을 줄이거나 byte-identical을 내용 품질로 승격하지 않는다. 실제 판독 속도 향상률은 아직 측정하지 않았다.
