# v24 별칭과 본문 정상성 분리

v23의955 목적 검산에서 새 종결9쌍은 전량 독립 판독됐다. 별도로 전수 계수의 구조후보33쌍을 정확 원문에서 재생성한 결과15쌍이 자동 종결됐으나, 독립 판독은827·47955·183488·268392 등에서 실제 수식/변수 결손을 확인했다. v23의 회귀351/재생43/목적955 통과는 이 의미 반례를 해소하지 않는다. 전량v22와v23은 실행하지 않는다.

대안은 새 별칭 처리를 전부 버리기, 한 완결된 명명 정의만 있는 경우로 자동 종결의 범위를 제한하고 나머지는 개별 복구하기, 종전의 넓은 자동 종결을 유지하기다. 두 번째를 선택한다. 첫 빈 괄호를 지워도 나머지 본문의 식/증명/조건이 완전하다는 근거는 생기지 않는다.

새 v24는 실제 typed alias 규칙이 적용되는 원문에 첫 완결 문장 이외 내용이 있으면 그 본문을 자동 종결하지 않는다. 이는 길이 상한이나 삭제 비율 기준이 아니며, 뒤 내용이 잘못됐다고 확정하는 것도 아니다. 별칭만 있는 완결 명명 정의, 실제 전체 프로그램, 축과 항목이 있는 희소표의 기존 검사는 유지한다. 개별 검토가 실제 독립 문장과 결손 직접 의존부를 구분해 새 본문을 저장할 수 있다.

기존 실제 선택 본문529487에서도 points with 뒤의 데이터와 where 쉼표 뒤의 계수가 빠진 영어 반례를 확인했다. 보호 코드/인용 문맥은 구분하면서 이 실제 역할 결손을 새 진단으로 추가하고, 동결된 과거 종결도 다시 검사한다. 상위 근거가 PENDING이었다는 이유로 잘못된 개별 ACCEPT를 자동 수용하지 않는다.

기존59 생산 파일과 모든 잘못된 후보·검토·테스트·반례는 보존한다. 새61 생산 파일로 회귀/목적/독립 대조와 전량 재생을 별도 수행한다. 원문이나 기존 캐시를 바꾸지 않으며 PENDING 일괄 제외, zeroH 계약 완화, 원문에 없는 식·변수·단위 생성은 하지 않는다. 현재 캐시H160219/goal미완/추가300M 미허가를 유지한다.
