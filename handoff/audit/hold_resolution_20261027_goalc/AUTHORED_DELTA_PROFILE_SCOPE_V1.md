# 이미 작성한 결과의 미채택 원인 묶음 분석

현재 전체 HOLD 정제·효율 개선 지시와 목표 §1·4·5·6의 CPU 분석 범위다.
기존 literal 후보 분석은 단어 변경2670건·불확실 사유636건 등을 한데 보류했다.
새 분석은 현재 ROOT37 미채택 자료와 오류0 stage17 스냅샷만 SHA로 연결한다.

| 안 | 내용 | 장점 | 한계·영향 | 비용 |
|---|---|---|---|---|
| A | 모든 미채택 결과를 다시 개별 판독 | 직접 문맥 증거 | 기존 전문 작업 반복 | 높음 |
| B | 기존 결과의 실제 단어 변화·삭제 줄 역할·남은 결손을 전량 계수 | 재사용할 큰 유형을 먼저 선택 | 계수만으로 채택하지 않음 | 낮음 |
| C | 모든 저자 결과를 일괄 채택 | 빠름 | 실제 오삭제·깨진 문맥을 놓침 | 낮음이나 부적합 |

선택 B. 코드·원문·본문은 변경하지 않고 작은 metadata shard와 집계 보고만 새로 쓴다.
보호 ID·hash·alias와 개별 NEEDS_ROOT는 payload 전에 제외한다. 검토/보류 의견을 PASS로 바꾸지 않는다.
기존 숫자 검사는 부분 숫자 변경을 찾는 검사이며 숫자 전체 삭제의 의미를 증명하지 않으므로,
삭제된 숫자 전체를 별도 다중집합으로 계수한다. 학습/검증 풀·모델·GPU·캐시는 변경하지 않는다.
프로파일은 선택 우선순위 근거이지 규칙 승인·인간 추가 완독·캐시 채택이 아니다.
후속 채택은 별도 독립 보존/문맥 검증이 필요하다. 현 WIP와 결과 정본은 실제 채택 묶음에서만 갱신한다.
