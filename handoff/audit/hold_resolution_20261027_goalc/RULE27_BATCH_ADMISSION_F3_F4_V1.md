# 선언된 동음이의 목록의 좁은 규칙 일괄 반영

사용자는 목표 파일 §1에서 CPU 전처리·코드 시험·별도 파생 자료·관련 로컬 커밋을,
§5에서 사례 검증 후 전체 적용을 승인했다. 원래 대량 처리 방법을 이어가라는 현재 지시를 따른다.
총괄은 규칙과 채택 근거를 구현·검산하며 새 수동 정제 TXT를 저술하지 않는다.
프로그램으로 생성되는 정책 결과와 Luna가 직접 전문 판독한 TXT/MD를 명시적으로 구분한다.

| 안 | 내용 | 장점 | 한계 | 영향·비용 |
|---|---|---|---|---|
| A | 후보478개를 전부 다시 두 사람이 수동 편집 | 개별 판독 증거 추가 | 이미 검증한 동일 편집을 반복하며 대량 규칙 방법의 병목 재발 | 수동 시간 높음, 정책 그대로 |
| B | 좁은 규칙·독립 문자 보존·반례·독립 문맥 리뷰를 결합해 변경분 반영 | 원문 값과 순서를 전량 검증하고 같은 사례를 일괄 처리 | 개별 사실 검증이나 모든 문서의 인간 전문 판독 증거는 아님 | 새 채택 메타데이터·필요한 본문만 생성, CPU 비용 낮음 |
| C | 기존 가드 PASS인 모든 HOLD를 일괄 해제 | 구현량 적음 | 실제 문맥 결손과 개별 보류를 해제할 수 있음 | 의미 손실 위험 높음 |

현재 승인 범위 안에서 B를 적용한다. 범위는 첫 문장이 실제로 `다음 사람을 가리킨다`,
`다음 뜻으로 쓰인다` 등 목록임을 선언하는 문서의 빈 별칭이다. `우미(于糜, 于麋, ?~?)`처럼
차 있는 외국어·미상 날짜는 그대로 유지한다. 빈 수식·함수 인수·코드·인용 및 개별 HOLD는
같은 규칙으로 해제하지 않는다. 끝 표제도 실제 내용이 없는 EOF 표제만 문자 보존 증명에서 허용한다.

| 파일·경로 | 예정 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| `handoff/audit/hold_resolution_20261027_goalc/`의 새 버전 도구·작은 근거 | 신설 | 목표 §1·5·6 및 현재 대량 방법 재개 지시 | 기존 기록 덮기·원문 복사 |
| `data_cache/p106b_hold_resolution_v1_20261027_goalc/`의 새 정책 결과 | 해시가 다른 새 정제본문을 한 번 생성, 기존 동일 결과 재사용 | 목표 §1·6 CPU 전처리·별도 파생 데이터 | 원형·고정 후보·기존 캐시 수정/삭제 |
| 새 선택 manifest·내용주소 행 조각 | 기존 행 그대로 보존, 승인된 변경분 추가 | 목표 §5·6 전체 상태 추적 | 제한 원형 접근·기존 개별 HOLD 무효화 |
| 후속 roster/검증·단계계수 | 전체 정본 비교 및 인간 전문판독/규칙처리 분리 | 목표 §6 | GPU·모델·추가 학습·타세션 정본 수정 |

코드는 기존 policy27, 검산기, `SelectionStore`, roster 빌더와 가드를 재사용한다. 새 기능은
규칙 결과를 기존 선택 스키마에 연결하는 부분이다. 이전 선택 행과 이미 승인한 세 안전 파생본은
동일성을 검증한다. 최신 개별 NEEDS_ROOT를 다시 확인하고 그런 원문은 자동 채택하지 않는다.
규칙 결과의 본문 SHA와 원문 SHA·규칙 핀·독립 증거를 소스별로 연결한다.

시험 근거는382회귀, 독립 오삭제 반례10개, 후보478개 전부의 순서/차 있는 문자·숫자·코드·Unicode·문체
보존 검사다. 최신 독립 전문 리뷰24개와 본문은15개 완전히 같고9개는 끝 줄바꿈만 다르다.
319241의 차 있는 `acques Perrin`을 수동본에서 없앤 오류는 원문/diff와 저자 확인 뒤 복원했다.
나머지454개를 개별 인간 전문판독으로 표시하지 않는다.

총괄은 사람목록 여부·빈 날짜 전 별칭 여부·차 있는 Latin 이름 여부로 생긴 여섯 실제 유형의
원문과 정책 결과를 추가로 전문 판독했다:668957 대극원역,739268 스웨덴의 호칸,
875462 올센,297380 우미,1259491 티나 찰스,1065688 잭 힐.
이름·지명 구분·미상 `?~?`·살아 있는 사람의 열린 연도 범위·외국어 철자가 남아 있음을 확인했다.
이는 위험 유형 검토이며478개 각각에 대한 인간 전량 판독·사실 검증 주장이 아니다.

데이터 스키마의 기존 필드는 유지하고 새 행에 `approval_mode=SOURCE_CLASS_RULE_WITH_ALL_ROW_LITERAL_PROOFS`와
`individual_human_full_text_read_claimed=false`를 추가한다. 일반 코드 가드가 보호하는 빈 튜플 같은
예제는 대상에서 제외된다. 개별 본문 파일은20MB 미만, 행 조각은4MB/512행 이하로 유지한다.

프로젝트 도메인 축은 CPU/사용자 실행 분리, 원문·동시 작업 소유권, 풀·토크나이저 계보,
정적/실제 캐시/모델 품질 구분, 정본 문서 연쇄다. 이번 반영은 CPU 파생 정제와 검증에만 영향을 준다.
공식 캐시 수치는 실제 새 build/consumer 후에만 바꾸며 전체 A–E·훈련 허가를 선언하지 않는다.
현재 공유 문서에 다른 세션 변경이 있으므로 WIP와 이 감사 근거를 먼저 갱신하고 최종 정본 통합 시
현재 파일·소유권을 대조한다. 정책 결과를 인간 최초 판독으로 합산하지 않는 단계계수 보완이 필요하다.
