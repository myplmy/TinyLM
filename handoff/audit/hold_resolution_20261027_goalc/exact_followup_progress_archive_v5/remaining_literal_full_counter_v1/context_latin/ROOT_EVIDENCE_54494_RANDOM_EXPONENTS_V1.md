# 54494 난수 명세의 소실된 지수

총괄이 지정 원문 전문을 읽었다. 원문 SHA-256은16B185E872B4C0CB88DC8B61BB7232AEB505A5C18822BAE27DB7678135F1195A다. [Oracle의 같은 random 명세](https://docs.oracle.com/cd/E19683-01/816-0213/6m6ne388k/index.html)에서31-long 상태 배열·기본 범위·주기 및256바이트 조건을 직접 대조해 지수 표기가 소실됐음을 확인했다.

세 정확 복원은 범위의231-1→2^31-1,주기의16 x (231-1)→16 x (2^31-1),256바이트 조건의269→2^69다. 밑2/지수31·69/기존 곱16/조건256바이트를 그대로 보존한다. 일반 상식으로 숫자를 고른 것이 아니라 같은 함수·상태 조건·같은 인접 설명의 직접 일치 근거다.

이 숫자 표기 세 곳만 복원한다. Oracle 판과 원 IEEE 명세의 다른 initstate 조건/스레드 권고/선언 차이는 가져오지 않는다. 없는 random 선언·현재 보안 권장·새 결과를 추가하지 않는다. 코드 실행/독자적 웹·해시 계산은 하지 않는다.

원래 손상 표기는 sidecar에 남기고 실제 새 전체 TXT와 TASK045의 다른 네 행을 보존한 새 리뷰로 연결한다. 다른2n/231 문자열에도 같은 복원을 일반 적용하지 않는다.
