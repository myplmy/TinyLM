# 본문 재작성 없이 명확한 리뷰 셀 두 형식 수용

최신 field12v15/13v10/14v10의34건 수집 거절을 실제 리뷰 셀과 대조했다.
L의19건은 REVISE_TEXT_PARTIAL이 기존 REVISE_TEXT 별칭표에 없어서 편집 출력으로
정규화되지 않은 경우다. G의15건은 상대 TXT basename 뒤 같은 ID의 HOLD MD를
세미콜론으로 함께 적어 단일 basename 검사가 거절한 경우다. 경로가 실제 다른 폴더를
가리켰다는 의미로 단정하지 않는다. 현재 거절은 그대로 보존하고 새 수집 버전에서 검산한다.

| 안 | 동작 | 이점 | 영향·부담 | 비용 |
|---|---|---|---|---|
| A | 작성자가 모든 리뷰를 새 버전으로 재작성 | 기존 parser 유지 | 본문과 무관한 반복 리뷰/버전 증가 | 중간 |
| B | 정확 상태 별칭 하나와 단일 TXT+같은ID MD 메모 문법만 정규화 | 원문/본문 수정 없이 실제 지정 파일을 연결 | 작은 parser 어댑터와 음성시험 필요 | 낮음 |
| C | 새 구조화 리뷰 형식으로 전환 | 장기 스키마 명확화 | 전체 작성기/기존 자료 이관 필요 | 높음 |

선택 B. 현재 사용자의 반복 작업 축소와 전체 정제/CPU 코드·검증 승인 안에서
이 감사 폴더의 작은 정규화 helper·시험·collector11을 신설한다. scripts·기존 collector와
원래 TXT/MD는 변경하지 않는다. 원문·GPU·모델·학습·외부 상태·타세션은 제외한다.

REVISE_TEXT_PARTIAL만 REVISE_TEXT로 해석하고 실제 EDIT_TEXT 변환은 기존 parser를 쓴다.
출력 셀은 하나의 TXT와 세미콜론 뒤 같은ID의 로컬 MD 메모가 명확할 때만 TXT를 분리한다.
복수 TXT/다른ID/다른 역할·폴더/원형의 편집출력 지정/의미 불명 셀은 기존 검사를 통과해야 한다.
모호한 후보를 추정하거나 새 본문을 만들지 않는다. 원래 review_text/파일 SHA는 그대로 남고
정규화 전후 토큰·행·원래 MD SHA를 별도 작은 receipt로 연결한다.

기존 header/rank/ID/role/guard5/바이트 검사·본문 검산·채택 기준은 유지한다.
이 수집 성공을 내용 품질·ROOT 채택·캐시 편입으로 승격하지 않는다. 새 후기 문서에
원래 리뷰를 조용히 덮지 않고 원형/실제 후속 선택을 구분한다.
