# 누적 선택 메타데이터 분할 착수 근거

현재 ROOT31은 10,596행, 18,319,321바이트다. 행 이외 메타데이터는 JSON 공백 포함 32,380바이트다. `advance_counter_selection_v1.py`는 이미 들여쓰기 제거를 사용하며, 그래도 20,000,000바이트 이상이면 쓰기 전에 거절한다. 파일 제한은 사용자 objective 6절의 실제 제약이다.

| 안 | 내용 | 장점 | 단점 | 영향도 | 수행비용 |
|---|---|---|---|---|---|
| A | 현재 단일 JSON을 더 압축하거나 이력을 생략 | 호출부 변경이 적다 | 이미 최소 공백이며, 이력을 생략하면 출처 연결이 손상된다 | provenance 손실 또는 다음 크기 한계 | 낮지만 지속 불가 |
| B | 전체 JSON의 고정 바이트 조각과 manifest | 원래 JSON 바이트를 재조립한다 | 선두 메타데이터의 길이만 바뀌어도 뒤 조각의 경계가 바뀌어 중복 저장이 증가한다 | 저장·읽기 도구 | 중간 |
| C | 순서가 고정된 행 배열 조각과 작은 manifest | 동일한 앞 행을 버전 간 재사용하고, 조립한 기존 dict/list를 그대로 소비한다 | manifest를 이해하는 명시 로더가 필요하다 | 저장·읽기 도구와 CPU 회귀 | 중간 |

권장·수행: C. 최대 512행/4MB의 내용 주소 조각, 원래 최상위 키 순서, rows 이외 메타데이터, 논리 JSON의 전체 길이·SHA를 manifest에 연결한다. 이미 존재하는 단일 JSON은 그대로 읽는다. 논리적 선택 행·본문·판정·출처·개별 guard를 바꾸지 않는다. 새 선택 버전에서만 새 저장 형식을 사용하고 기존 ROOT 파일을 다시 쓰지 않는다.

| 파일·경로 | 예정 동작 | 권한 근거 | NOT_RUN·제외 |
|---|---|---|---|
| 이 audit의 selection metadata helper, 새 버전 selector/roster/checkpoint/stage/cache wrapper | 신설·CPU 시험·명시 결합 | 사용자 objective 1·6절의 관련 코드·시험·파생 자료 승인, 현재 중간 생성물 관리 지시 | 모델·GPU·외부 취득·기존 파일 덮기 없음 |
| 이 audit의 새 ROOT와 `selection_metadata_row_shards_v1/` | manifest·메타데이터 조각 신설 | 사용자 objective의 20MB 미만 분할 및 manifest | 원문 TXT·기존 ROOT·원본 캐시 수정 없음 |
| 현재 세션 WIP와 작은 감사 근거 | 검증 후 현재 상태 연결 | 장기 작업 재개·기록 승인 | 다른 WIP·루트09·환경 파일 변경 없음 |

| 축 | 영향 | 직접 추적 근거와 처리 |
|---|---|---|
| 코드 | 있음 | selector는 `inv.cache.read`로 prior를 읽고 직접 payload를 쓴다. roster v1은 `json.loads(selection_path.read_bytes())`, checkpoint v5는 현재·prior를 같은 방식으로 읽는다. stage v1의 read도 `json.loads`이며 cache v6/v7은 inventory/cache reader를 사용한다. 새로운 wrapper에서 정확한 선택 파일 SHA에만 결합하는 로더를 설치한다. SHA 계산용 원본 파일 읽기는 바꾸지 않는다. |
| 데이터 | 있음 | 디스크 저장 형식만 분할한다. 로더의 결과는 기존 native dict/list와 같아야 한다. source_ids, 행 순서·중복, 조각별 길이·SHA, 논리 전체 SHA를 검사한다. 기존 inline 형식은 보존한다. |
| 시험 | 있음 | 한글·CRLF·경계, inline 호환, 전체 재조립 동등성, 행 중복, 누락·변조·순서 변경·경로 이탈·심볼릭 링크 거절, 버전 간 앞 조각 재사용을 CPU로 검사한다. 실제 native ROOT31과도 같은 내용인지 검산한다. |
| 정본 문서 | 제한적 | `.agents/project.json`의 기준표·METHODS·COMPASS·실험목록·플래그는 새 실험/모델 조건이 없어 즉시 변경하지 않는다. 현재 데이터 작업 WIP와 이 감사 문서가 저장 도구 변경을 소유한다. 최종 A–E 갱신은 별도 전체 완료 단계다. |
| 기술부채·순서 | 있음 | 큰 선택 파일 생성이 막히기 전에 도구를 검증한다. 한시 wrapper는 해시로 동결된 이전 구현을 재사용한다. 본문 검토 다섯 역할은 병행해 계속한다. |
| GPU·모델 권한 | 없음 | CPU 메타데이터만 처리한다. |
| 데이터·로그·동시 소유권 | 제한적 | 현재 세션 audit만 쓰고 원본/후보/보호 본문을 열지 않는다. |
| 학습 비교 조건 | 없음 | 풀 구성의 판정 의미·토크나이저·모델 실행은 바꾸지 않는다. |
| 메모리·속도·품질 증거 | 있음 | 조각 재사용·크기를 실제 계수한다. 속도 개선률이나 의미 품질을 이 도구 시험으로 주장하지 않는다. |
| 문서 연쇄 | 제한적 | WIP와 새 wrapper pins를 실제 검증 후 연결한다. |

핵심 위험은 분할 파일을 기존 reader가 원래 선택 dict로 오인하는 것이다. 전용 schema와 고정 SHA의 명시 결합을 사용하고, 미결합 manifest는 거절한다. 조각의 실제 파일 SHA와 논리 전체 SHA를 분리한다. 기존 파일·현재 공식 cache15는 변경하지 않는다.
