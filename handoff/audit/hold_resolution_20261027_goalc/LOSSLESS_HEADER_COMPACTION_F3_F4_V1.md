# 본문 프레임을 바꾸지 않고 반복 metadata 출력 줄이기

| 안 | 방식 | 영향 | 비용 |
|---|---|---|---|
| A | 매4KB 프레임마다 전체 경로·해시·범위 context 반복 | 현행 그대로, 긴 문서에서 같은 metadata가 누적 | 낮음 |
| B | 묶음마다 같은 context를 한 번, 프레임별 범위/EOF는 각각 | 동일 본문·동일 배정·동일 검증을 유지하면서 출력 감소 | 낮음 |
| C | metadata를 모두 생략 | 원문 연결/EOF 확인 근거 부족 | 채택 불가 |

B를 적용한다. 사용자의 반복 판독/리뷰/원장 비용 감소 지시와 goal의 관련 CPU 도구·시험
권한 안이다. 변경은 이 감사 폴더의 새 entry3/검사 및 기존 다섯 tmp shortcut의 고정 entry
경로/해시에 한정한다. 고정 entry2/core3/scope6/guard6, 실제 원형·후보·수정본은 바꾸지 않는다.

새 context와 프레임별 metadata를 합치면 이전 V2 헤더와 같은 정보를 복원해야 한다.
프레임 본문 바이트·순서·범위·후보 diff·EOF는 완전히 같아야 한다. 실제 다섯 역할의
15프레임을 메모리에서 비교하고 보호 ID/배정 밖/잘못된 개수는 계속 거부한다.
원문·패킷 사본은0이고 이 검사는 새로운 인간 전문판독이나 정제 채택으로 세지 않는다.
원장과 기준표·METHODS·COMPASS의 전체 정제 수량은 이 transport 변경으로 달라지지 않는다.
모델/GPU/학습·보호자료·타세션·외부 상태에는 영향이 없다. 새 포맷은 1..3프레임마다
context 한 번과 기존 EOF 표지를 제공하므로 판독 범위/신뢰 경계를 잃지 않는다.
