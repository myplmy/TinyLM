# 생년 구간의 공통 보존 경계 4

기존 V1–V3, 개별 날짜 근거와 정확 재검토 허가를 유지한다. 아래는 반복해서 중재한 같은 형식의 처리 기준이다. 자기 지정 TASK 안에서는 매번 추가 허가를 기다리지 않고 적용하며 원형·이전 초안·리뷰를 보존한다.

1. 같은 사람의 같은 출생 필드를 조건 없이 단정한 연도들이 충돌하면 어느 쪽도 선택하지 않고 실제 상충 연도만 별도 sidecar에 둔다. 도입·본문·출생 분류에 같은 값이 반복돼도 독립 증거의 수로 세지 않는다. 생년 외 경력·작품·재위·사망 연도를 출생으로 혼동하지 않는다.
2. 월일이 충돌하지 않으면 실제 월일을 보존한다. 1995년2월5일과1989년 출생이 충돌할 때 2월5일은 남길 수 있다. 1927년12월26일과1926년12월25일처럼 월일도 다르면 상충 월일도 보류한다. 없는 값을 다른 문장에서 가져와 채우지 않는다.
3. 명시 이설·추정·등록일·공식일·음력/양력 병기와 그 근거·조건은 보존한다. 달력 표기가 있다는 사실만으로 서로 다른 두 날짜가 같다고 환산하지 않는다. 이미 제공된 개별 공개 근거의 범위만 적용한다. 서로 다른 인물의 날짜나 단순 범위와 그 안의 연도는 자동 충돌이 아니다.
4. 다른 사망일·친족·신분 등 실제 알려진 충돌도 확인한다. 같은 사망일의 조건 없는 두 일값은 선택하지 않는다. 공통 연도·공통 월은 유지한다. 명시된 달력·이설·사망 원인의 비배타성은 그대로 보존한다. 다른 시기의 역할을 충돌로 만들지 않는다.
5. 9세·10세·69세 등 실제 독립 나이, 향년, 최연소 기록은 생년 산술로 지우지 않는다. 같은 문장의 왕후10세와 세손11세는 다른 사람의 나이다. 원문 수치·조건·주체를 유지한다. 세기 분류도 생년을 계산해 고치지 않는다.
6. 참고문헌·책·자료의 실제 제목 안 숫자와 연도는 서지 원문으로 보존한다. 제목의 연도를 전기의 무조건 단정형 생년과 혼동해 지우거나 정정하지 않는다. 유효한 책 제목·작성자·발행년을 빈 참고문헌 표제로 취급하지 않는다.
7. 전체 원문을 읽어도 인명이 없고 무명 선수 한 문장과 팀/학교 분류만 남으면 이름을 추정하지 않는다. 그런 문서의 연도만 지운 익명 소개나 분류 목록은 독립 학습 본문이 아니다. NEEDS_ROOT·본문 출력 없음으로 전체 판독과 신원 소실 근거를 기록한다. 총괄이 개별 2차 판독 후 검토 완료 HOLD 원장에 연결한다. 실제 이름이나 독립 사건이 남은 다른 문서는 별도로 판단한다.
8. 스승·소속·친족 대상이 빠진 관계만 원형 보류하고 독립 이름·예명·경력까지 지우지 않는다. 앞 문장을 분리하며 ‘이후’의 연결 대상이 사라졌다면 그 연결어만 좁게 정리할 수 있다. 조건을 지워 일반적인 사실로 바꾸지 않는다.
9. 실제 값이 남아 있고 빈 다른 표기만 소실된 `이름(: 날짜…)`, `본명: ; 실제 이름`의 값 없는 콜론·쉼표·세미콜론 포장은 좁게 정리할 수 있다. 실제 이름·작위·월일·원래 한자 등은 유지하며 새로운 글자를 채우지 않는다.
10. 완결 문장/URL 뒤 짝 없는 위키 닫기 `]`, 내용 없는 `|-`, 실제 빈 각주·참고문헌 표제만 좁게 분리할 수 있다. 코드·전사·인용·교육 문제의 문자나 의도된 빈칸이면 보존한다. 표에 유효한 값이 남았다는 이유로 표 전체를 지우지 않는다.
11. 출력은 자기 역할의 새 TXT/MD만 만들고 noclobber를 유지한다. 실제 선택 본문의 전체 diff와 EOF를 확인한다. 본문이 exact candidate와 같고 sidecar만 추가한 경우 ACCEPT_CANDIDATE로 지정 후보를 선택한다. 같은 내용을 복사한 TXT를 수정량으로 세지 않는다.
12. 리뷰 표 헤더는 `ID / 판정 / 실제 판독 범위 / 출력 / 구체 근거`이며 출력 열에는 정확 TXT basename 또는 절대경로 하나를 쓴다. 파일명은 review_NNN_vN.md처럼 단일 버전만 쓴다. 각 TASK의 모든 원래 ID가 저장됐는지가 완료 기준이다. 미결·미저장을 완료로 보고하지 않는다.

입력은 자기 START/TASK/ROOT_CAT_COMMANDS에 있는 literal 경로만 사용한다. agents 접두사를 공유 입력에 덧붙이거나 파일명을 조합하지 않는다. 정상 6000문자 패킷 끝과 실제 도구 출력 잘림은 다르다. 실제 잘림은 같은 허용 파일의 좁은 범위로 이어 읽고 마지막 논리 END까지 확인한다. 코드·시험·계수·모델·GPU·Git·웹·타 역할·보호 자료 접근 금지는 그대로다.
