# 출력 TXT 머리글 회수 교정의 착수 전 영향도

현재 사용자 재개 지시와 objective의 CPU 분석·관련 구현/시험·새 파생 산출물 허가가 근거다. 실제 리뷰/본문은 그대로 보존한다.

| 경로 | 동작 | 권한·제외 |
|---|---|---|
| 이 audit의 exact_review_header_alias_v1.py, collect_exact_cohort_reviews_v6.py, test_exact_review_header_alias_v1.py | 신설 | 관련 구현/시험 허가; 기존 v5/v63/환경 파일 수정 없음 |
| 자기 literal snapshots/v13 | 새 회수본 생성 | 파생 데이터 허가; 과거 v12/원문/캐시 덮기 없음 |
| 자기 WIP | 후속 CAS 갱신 | 기존 정상 wip.py API만; 상태 임의 완료 없음 |

| 안 | 내용 | 장점 | 단점 | 영향도 | 비용 |
|---|---|---|---|---|---|
| A | 저자가 25행 리뷰의 머리글을 새 버전으로 바꿈 | 집계기 유지 | 유효한 원저자 리뷰를 중복 작성·회수해야 함 | 리뷰 이력 증가 | 중간 |
| B | 정확한 출력 TXT 별칭만 파서에 추가 | 원문/리뷰 보존, 명시 열만 사용 | 새 파서의 회귀 검증 필요 | 새 회수본만 | 낮음 |
| C | 전체 행에서 TXT 이름을 추측 | 머리글 의존 감소 | 근거 열의 옛 TXT/다른 버전을 잘못 고를 수 있음 | 실제 본문 오연결 위험 | 높음 |

B를 적용한다. 25건 모두 같은 명시 머리글과 실제 파일명 열을 갖고 있다. 원인이 본문 소실이 아니며 전체 행을 출력 열로 쓰는 fallback이 잘못 적용됐다.

| 축 | 영향과 검증 |
|---|---|
| 코드 | v5의 정의 로더·v63 review_entries/decisions 재사용. 새 래퍼는 header 배열의 정확 별칭만 정규화한다. raw 행/셀/바이트/ID/상태/본문 이름을 바꾸지 않는다. |
| 데이터 | 새 snapshot만 생성. 원본 리뷰 SHA와 25개 정확 출력 셀/파일 연결을 전후 대조한다. 모호한 출력 열 둘은 거부한다. |
| 시험 | 실제 리뷰25행 회귀, 원래 출력 열 보존, 중복 출력 머리글 거부, 미등록 이름 유지, 근거 속 파일명으로 승격 금지. 이후 실제 새 회수본으로 검산한다. |
| 정본 | WIP와 audit의 회수 근거만 현재 갱신. 본문 선택·실험·METHODS/BASELINES/COMPASS 판정은 변하지 않는다. 최종 goal 정본 연쇄는 계속 미완이다. |
| 기술부채 | 데이터/캐시의 frozen 생산 코드는 그대로 두고 새 collector만 opt-in한다. 실제 텍스트 정제보다 새 집계기 확장에 범위를 넓히지 않는다. |
| GPU·모델 | 실행·로딩 없음. CPU 문서 회수만 한다. |
| 보호·동시 작업 | 자기 audit와 새 snapshot만 사용. 보호 TinyDataset/타 세션/원형/캐시 변경 없음. |
| 비교 조건 | 같은 입력·원저자 리뷰·토크나이저/평가 조건 유지. 새 본문 생성·채택 없음. |
| 증거 수준 | 명시 파일 연결 통과만 판정. 의미 보존·모델 품질·전체 완료로 승격하지 않는다. |

현재 실제 외부 승인 대기는 없다. 관리 goal의 blocked 표시는 관측했으나 현재 사용자 재개 지시 아래 실무는 계속하며 변경 원인을 추측하지 않는다.
