# ROOT50 실제 수정본과 닫는 괄호 보정 묶음

902개 secondary 배정은 모두 불변 canonical MD에 연결했다. 기존 SHA 오기 두 건은 담당자의 메타데이터 정정 근거로만 보완했고, 원래 오류 행도 보존했다. 판독 기록 형식이나 해시 정정은 신규 본문 채택 실적이 아니다.

두 검사 기준의 적용 범위를 바로잡았다. 첫째, 전각과 일반 괄호를 혼용한 실제 가수·성우 이름은 짝이 맞으므로 진단 표현에서만 너비를 맞춘다. 원문·본문·코드·Unicode 비교에는 실제 바이트를 그대로 쓴다. 진짜 미폐쇄·교차 괄호와 깨진 위키 표기는 7개 회귀 검사에서 계속 보류된다.

둘째, 자동 추출의 `ordered_deletion`은 공백 이외의 문자를 추가하면 실패한다. 따라서 사람이 누락된 닫는 괄호를 복구한 본문에 이를 그대로 적용하면 올바른 수정도 탈락한다. 기존 False 관측을 True로 덮지 않고 별도 보존 근거를 만들었다. 채워진 문자·목록값·수치·코드·Unicode·스타일·메타데이터 검사는 모두 통과해야 한다. 추가 문자는 닫는 소괄호뿐이고, 원문에는 실제 미폐쇄 괄호가 있으며, 최종 본문의 괄호는 완결되어야 한다. 원문별 secondary 의견과 ROOT의 실제 삽입 맥락 판단도 필요하다. 새 사실·숫자·부정·순서·코드를 바꾸거나 미폐쇄가 남는 경우는 8개 회귀 검사에서 거절했다.

902행 재검사에서 아직 미채택인 25고유50위치가 준비 후보가 됐다. 빈 각주가 남은 184413과 구현 예고가 끊긴 기존 488152는 제외하여 기존 본문 23고유46위치만 이번 묶음에 넣는다. H의 명사형 목록은 J/L/G와 마찬가지로 정확한 ID·본문 SHA·실제 판독 기록에 한해 판단했다. ROOT가 실제 전문 대조한 201466의 배우–배역·연도·분류 목록은 유지돼 있다.

새 수작업 출력은 원형과 이전 본문의 식별을 동결된 workset에서 확인하고, 새 본문은 지정 출력 경로와 COMPLETE 판독 기록에 별도로 연결했다. 이전 본문과 새 본문이 같다는 거짓 주장을 만들지 않는다. 24개 새 출력 검증 중 20고유40위치가 기존 문자·수치·코드·Unicode·순서 검사를 모두 통과했다. 그러나 ROOT가 117441의 말미에서 실제 관직 목록이 없는 `관직 역임 약력`과 음력 날짜 범례를 발견했다. 분류 복구 성공을 본문 전체 완결성으로 바꾸지 않고 이 1건을 추가 보류하여 19고유38위치만 채택한다. 304440의 2008년 9월 도서 행은 제목과 날짜가 있는 서지 항목이며 원문에 없는 출판사를 생성하지 않았다. 269255/300968/304440의 열린 생몰 범위 기호는 복구됐고 종료일은 만들지 않았다.

이번 추가는 42고유84위치다. 독립검산 성공 후 B안 누적 신규는 537고유1,029위치, 기대 HOLD99,903, 공식 cache18 HOLD100,932, 캐시 반영 대기1,029, 처리 후 미채택7,673, 미처리92,192, 기존 검토 HOLD38이다. 새 캐시 생성·소비 검증, 전체 원문 사실검증, 모델 품질 및 goal 완료는 주장하지 않는다.

ROOT의 후속 수리 배정에서 171691과 validation:453의 문맥을 혼동한 오류도 기록한다. 담당자가 실제 Edda 본문을 보고 중단했고, ROOT가 각각의 실제 ID·SHA·내용을 대조해 잘못된 지시를 철회했다. 171691 prefill은 그대로 보존했고 채택하지 않는다. governor 문맥의 쉼표 수리는 검증된 validation:453 별도 scope로 재배정했다. 이 후속 수리들은 이번 42건에 합산하지 않는다.
