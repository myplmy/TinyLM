## 분리한 조각과 이유

- Relation의 `Given sets A relation is a subset of . It is set of n-tuples where`는 집합·원소 수식과 문장 목적어가 소실되어 완결된 정의가 아니다. 제목 `Relation (AKA table or entity set)`와 뒤의 독립된 열/행 설명은 본문에 남겼다. 비어 있는 수식은 생성하지 않았다.
- Select의 `in this example p is called the selection predicate.`는 실제 예제에 p의 표기/식이 없고 이어지는 SQL에도 p 식별자가 없어 해당 문장만 보류한다. `R is the relation...` 설명, 완결된 부분집합 정의, SQL 원형과 그 결과는 보존한다. `Formally, select is defined as`에는 정의식이 뒤따르지 않아 그 예고 문장도 보류한다.
- Project 앞 `are attribute names and`는 문두 주어가 빠진 조각이므로 보류한다. 본문에는 실제 채워진 `R is the relation.`과 K columns의 일반 정의, SQL 및 결과를 남긴다. 누락 주어를 K로 추정하지 않았다.
- `The shaded areas represent respectively`는 대상 그림/값이 없는 포인터라 보류한다.
- 원문 disjoint 문장 중 `that is .`는 실제 등식/조건이 비어 있어 그 빈 수식 조각만 보류했다. 채워진 R/S disjoint 관계와 disjoint하지 않을 때 renaming을 써야 한다는 문장은 남겼다.
- Rename의 `Similarly if an expression E has an arity n, then`과 `And this will return ... renamed to`는 이어지는 식/대상 속성 목록이 없어 보류한다. 앞의 명명된 rename 역할과 E를 X라는 이름 아래 반환한다는 문장은 보존한다.
- `Top comments (0)`은 본문이 아니라 댓글 UI여서 해당 한 줄만 분리한다.
- 빈 `( )` 선택 연산자 포장과 subset 괄호의 빈 `( )`는 값 없이 남은 껍데기라 본문에서 제거했으며 새 기호를 넣지 않았다.

새로운 표제 `Union`, `Set Difference`, `Cartesian Product`는 원문 앞의 여섯 기본 연산 목록에 실제로 있는 명칭만 각 해당 단락 앞에 재사용했다. 원문 SQL `SELECT * EMPLOYEES WHERE firstName='John';`는 FROM을 추가하거나 고치지 않고 그대로 유지했다. arity 링크는 원래 `[arity]` 앵커와 URL을 그대로 두고 누락된 Markdown 괄호만 복구했다.
