# 긴 저장 본문 판독 영향

| 방법 | 효과·비용 | 선택 |
|---|---|---|
| 긴 전체 원문/본문/차이를 한 번에 출력 | 도구 추가가 적으나 출력 잘림 때문에 전문 판독 증거를 잃을 수 있음 | 미선택 |
| 논문별 전용 판독기를 계속 복제 | 특정 핀은 명확하나 보호·분할 로직이 중복되고 이전 버전 이름이 남기 쉬움 | 미선택 |
| 기존 보호 검사와 저장 메타데이터를 재사용하고 6000자씩 판독 | 기존 짧은 판독기의 SHA/ID 보호를 그대로 사용하며 범위·전체길이·EOF를 명시함 | 적용 |

새 도구는 총괄 전용이다. 기존 다섯 역할의 허용 경로나 명령을 확대하지 않는다. 고정 짧은 판독기의 메타데이터 준비 부분만 실행하고 원래 본문 출력 루프는 실행하지 않는다. 같은 V3 보호 ID/SHA와 오류 없는 저장 스냅샷만 통과시킨다. 원문·본문 경로는 해당 목표 BASE 내부에 한정하고 원문·본문·기존 JSON은 덮어쓰지 않는다. 미저장 행은 거부한다.

원문/본문 출력은 수정이나 채택이 아니다. 차이 모드는 새 감사 JSON만 배타적으로 생성하며 최초 `root_full_diff_read`는 false다. 실제 모든 차이를 읽은 뒤 별도 채택 증거에서 그 범위를 명시한다. 개별 새 파일 20 MB 미만을 강제하며 학습 TXT 작성·모델 실행·GPU·설치·다운로드·Git 동작은 하지 않는다.
