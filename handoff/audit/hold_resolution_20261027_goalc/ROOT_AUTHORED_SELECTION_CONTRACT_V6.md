# 실제 저장 본문 선택 계약 v6

v5의 원문 연결·전체 배정 결손·정확 TASK/뷰 핀·모든 과거 실패 보존을 유지한다. 새 선택8은 snapshot35와 plan12의 새239·14·233·48·1 검토를 모두 대조한다. 실제 서로 다른 새 본문18건은 ROOT_LITERAL_MEDIATION_RATIONALE_V1.md의 원문 문맥과 전체 diff 판단 및 ROOT_LITERAL_MEDIATIONS_V1.json의 정확 핀으로만 중재한다.

대안은 미결18건을 그대로 둔 이전 선택, 원문 및 모든 충돌 검토를 고정한 개별 명시 중재, 새 코호트를 일괄 우선하는 방식이다. 두 번째를 선택한다. 일반적인 코호트 순위 변경만으로 서로 다른 새 본문을 승인하지 않는다.

각 중재는 해당 원문SHA와 모든 새 목적의 결정·본문·review SHA 집합이 일치해야 한다. 새 검토가 하나라도 없거나 실패 또는 NEEDS_ROOT이면 과거 본문으로 우회하지 않는다. 다른 ID나 새 코호트에는 이 중재를 전파하지 않는다. 종전 정확 root 선택을 바꿀 때는 이전 선택 파일·파일SHA·원문SHA·결정·본문SHA를 특정하며 원형을 보존한다.

940988은 복구된 잘못된 지수 등식 때문에 최신48 검토 본문을 선택하지 않는다. 이전의 정확 반례 본문을 선택해 질문·원문 최종식·조건·귀속은 보존하고 유도 직접 의존부는 분리한다. 59479는 실제 편집 기반 v3에 있던 단위 결손을 좁게 분리한 v5를 선택한다. 총괄의 잘못된 버전명 안내와 이전 실패·검토는 보존한다.

선택 후 실제 본문 검산과 캐시 검증을 별도로 수행한다. source 수량, 제한 parent metadata-only와 안전뷰, 원문 링크·코드·Unicode·스타일·수치·조건·인용·문맥·메모 검사를 유지한다. 이 선택은 캐시 채택이나 goal 완료가 아니다. 신규9·33 구조 반례 검토는 별도의 배정이며 저장 결과를 대조하기 전 이번 선택의 근거로 세지 않는다. PENDING 일괄 제외·계약 완화·원문에 없는 사실 생성은 하지 않으며 추가300M 학습은 계속 미허가다.
