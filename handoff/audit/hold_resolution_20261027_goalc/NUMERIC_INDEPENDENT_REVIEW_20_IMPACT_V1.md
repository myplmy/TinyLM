# 기존 역할을 통한 숫자 문맥 독립 검토

숫자의 존재·개수 보존만으로는 빠진 방정식에 의존하는 결론을 검증할 수 없었다. 207에서 실제 숫자0이 남아 있어도 계산 전제가 빠진 사례를 발견해 해당 두 문장만 보류했다. 기존13원자 국소 증명/412원자 문맥 필요 결과는 그대로 유지한다.

| 방법 | 이점 | 비용·한계 | 판단 |
|---|---|---|---|
| 총괄이79문서를 모두 직렬 판독 | 기존 작업 배정을 유지한다 | 새 산출물 중재·검산과 숫자 판독이 한 역할에 몰린다 | 나머지 범위는 계속 수행 |
| 기존 C 역할이 현재 묶음 뒤 어려운20문서를 독립 판독 | 새 에이전트 없이273개 미결 원자의 문맥을 분담한다 | 그동안 첫 판독 큐는 다른 네 역할이 진행한다 | 선택 |
| 전역 값·단위 개수나 자동 정렬만으로 면제 | 처리 시간은 짧다 | 원문의 값 재배정·빠진 조건을 검증하지 못한다 | 사용하지 않음 |

선택은 현재 목표가 허용한 최대 다섯 Luna의 지정 원문 판독 범위에서 수행한다. C가 처음 작성한 문서는 제외하고, 다른 역할이 작성한 정확 원문/현재 선택본문 쌍20개만 새 고정 패킷으로 제공한다. 기존 두 reader를 해시 고정해 재사용하며 일반 숫자 증명기나 생산 게이트를 변경하지 않는다. C는 새 검토 MD만 작성하고 다른 작성자의 TXT를 수정하지 않는다. 총괄이 결과를 검토하고 필요한 보완은 기존 작성 역할에 지시한다.

| 프로젝트 영향 축 | 경계 |
|---|---|
| GPU·학습·모델 | 기존 CPU 텍스트 패킷과 읽기 도구만 사용한다 |
| 데이터·소유권 | ID/원문 SHA 이중 가드 후 읽으며 원형/선택본문을 변경하지 않는다. 새 C 독립 검토 폴더의 패킷·MD만 사용한다 |
| 비교 조건 | source/split/토크나이저/채택 집합은 그대로다. 독립 검토를 새 고유 문서 수에 더하지 않는다 |
| 증거 수준 | 읽기 도구 경계 검산과 실제 C 판독·총괄 채택을 구분한다. 원자 계수나 helper 통과를 의미 통과로 바꾸지 않는다 |
| 기록 연쇄 | 정확 배정·입출력·재개 위치는 새 START/TASK/manifest와 WIP에 기록한다. 최종 정본 연쇄는 실제 최종 근거에 맞춰 갱신한다 |

첫20개는 전체 목표의 상한이 아니다. C는 지정 독립 큐 뒤 자신의 기록한 필드 큐 다음 위치로 복귀하며, 총괄과 다른 네 역할은 나머지 문맥·전량 큐를 계속한다. 효과는 아직 계측하지 않았다. 완료·일시중지·학습 승인으로 바꾸지 않는다.
