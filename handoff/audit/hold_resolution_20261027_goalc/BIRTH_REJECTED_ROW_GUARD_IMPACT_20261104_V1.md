# 거부된 리뷰 행의 전달 검증 경계

사용자 전체 정제 재개 및 objective의 CPU 도구 구현·시험 허가 안에서 수행한다. 새 검증 도구만 만들고 기존 입력·캐시·독립 리뷰·실행된 도구는 바꾸지 않는다.

| 경로 | 예정 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| 현재 감사 폴더의 quarantine_rejected_birth_row_v1.py 및 CPU 회귀 시험 | 신설·실행 | objective 1·6의 CPU 구현·시험 | 모델·GPU·설치·외부 통신 |
| validate_birth_delivery_snapshot_v3.py | 기존 v2/v1을 재사용하는 새 검증 진입점 | 같은 허가 | 실행된 v1/v2 수정 없음 |
| birth_root11_independent_v1_snapshots/v18 및 전달 이벤트 | 읽기 | 지정 원문 연결·검증 허가 | 원형 수정 없음 |
| birth_root11_input_delivery_gated_v1의 새 버전 | 별도 파생 뷰 생성 | 별도 파생 데이터 허가 | 캐시·학습 채택 없음 |

## 실제 문제와 선택

v18의 320336/321048은 ACCEPT 출력 경로가 지정 입력과 달라 수집기에서 거부됐다. 거부는 materialize 이전에 일어나 원형 핀이 그 행에 아직 부착되지 않았다. v2 검증기는 모든 행에 original이 있다고 가정하여 `KeyError: original`로 종료했다. v8 불완전 출력 디렉터리는 보존한다. 종료 증거는 도구 chunk 736b01이며 원형 누락을 원문 부재로 해석하지 않는다.

| 안 | 내용 | 장점 | 단점·영향 | 비용 |
|---|---|---|---|---|
| A | 작성자가 경로를 고친 다음 v2 재실행 | 코드 변경 없음 | 다음 거부 행에도 같은 종료가 반복됨 | 낮음 |
| B | 새 검증 버전에서 정확 거부 행을 격리 | 원래 거부를 유지하고 음성 사례도 뷰에 보존 | 새 작은 격리 함수와 회귀 시험 필요 | 낮음 |
| C | 수집기 모든 행의 생성 순서를 변경 | 공통 스키마를 먼저 채울 수 있음 | 여러 cohort와 실행된 수집 경로에 영향 | 중간 |

권장·수행: B. raw 오류 목록의 정확 ID/리뷰 SHA/사유와 일치한 거부만 허용하고, 후보 본문·SHA·출력 참조를 격리 뷰에서 제거한다. 정상 행의 original 누락이나 불일치는 계속 명시적으로 실패한다. 소스 manifest의 원형 핀을 격리 행에 연결하되 읽기 성공·작성자 리뷰 성공·채택으로 승격하지 않는다.

## 영향도

- 코드: 기존 v2가 v1을 재사용하는 20행 진입점과 v1의 행 루프를 직접 확인했다. 새 버전은 그 경로를 그대로 재사용하고 정확 루프 지점에 격리 처리를 더한다. 실행된 도구는 수정하지 않는다.
- 데이터: 새 전달 뷰만 추가한다. 원형/후보/리뷰/실시간 이벤트를 변경하지 않는다. 거부된 행에는 학습용 본문 참조가 남지 않는다.
- 시험: 정상 행, 원형 핀이 없는 실제 형태의 거부 행, 원형이 이미 있는 거부 행, 잘못된 ID/역할/리뷰 SHA/사유, 원형 불일치를 CPU 단위 시험으로 검증한다. 기존 전달·이벤트 접두 보존 시험을 함께 실행한다.
- 정본: 캐시와 학습 조건이 바뀌지 않는다. 이번 중간 상태는 감사·WIP에 반영하며 BASELINES/METHODS/COMPASS의 최종 전체 수량 갱신은 새 roster·캐시의 실제 검증 뒤에 수행한다. 타 세션 소유 flag_whitelist는 건드리지 않는다.
- 부채·우선순위: 실패 사례를 조용히 생략하지 않도록 작은 독립 함수를 재사용한다. 새 뷰의 실패 수와 raw 오류 수를 함께 기록하며 오류가 있는 스냅샷을 채택하지 않는다.
- 도메인: GPU/학습/모델 실행 없음. 보호 ID와 SHA 검사는 기존 expected_event 경계 뒤에서 계속 적용한다. 원형/캐시/타 세션 불변. 코퍼스나 토크나이저 변경 없음. 전달 증거와 의미 판정·품질을 분리한다. 최종 정본 연쇄의 미완료 상태를 유지한다.
