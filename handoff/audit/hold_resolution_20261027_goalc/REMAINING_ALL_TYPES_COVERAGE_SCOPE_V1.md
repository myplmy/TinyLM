# 아직 배정하지 않은 모든 잔여 유형의 추적 범위

전체 goal은 중간 캐시 생성과 무관하게 계속 active다. 새 roster3의 미처리70192고유/110135위치와 개별 검토 비채택38고유/38위치를 구분한다. 이미 배정한 literal1793 중 비채택 검토1을 제외한1792고유는 계속 판독 중이다. 나머지 모든 미배정 유형을 metadata로 먼저 대조한다.

| 방식 | 장점 | 한계 |
|---|---|---|
| 대표 몇 건만 추가 처리 | 규칙 실험이 빠름 | 전량 잔여를 닫지 못함 |
| 모든 원문을 즉시 다시 추출해 새 담당자에게 일괄 배정 | 큰 큐를 한 번에 준비 | 기존 소유권 중복과 불필요한 대량 I/O가 생김 |
| 전체 metadata를 먼저 분할하고 가용 역할에 유형별 전량을 순차 배정 | 전체 누락을 막고 현재 판독을 방해하지 않음 | 순차 원문 판독과 교정은 여전히 필요함 |

세 번째 방식을 적용한다. 현재 열린 세 코호트의 source SHA 소유권을 대조하고 미판독·기존 배정·보호 metadata를 분리한다. metadata census는 판독·정제·캐시 채택 완료가 아니다. source ID와 SHA 두 보호 경계를 raw 본문 열기보다 먼저 적용한다.

각 유형의 전량이 작업 범위이며 TASK 크기는 페이지 단위일 뿐 작업량 한도가 아니다. 기존 다섯 Luna만 사용하고 지정 원문/후보/순서 packet/자기 새TXT·MD 경계를 유지한다. 실제 글 생성은 Luna만 맡는다. 원문·기존 캐시·타 세션 자료·TinyDataset을 덮거나 검색하지 않으며 GPU·모델·학습·push·PR은 수행하지 않는다.
