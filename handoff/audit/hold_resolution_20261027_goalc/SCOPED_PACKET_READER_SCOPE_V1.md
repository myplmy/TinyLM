# 경로 없는 검색 이후의 입력 제한

controls 역할이 저장소 루트를 workdir로 지정해 경로 인수 없는 rg를 호출했다고 자기 MD에 기록했다. 출력은 비었고 정확 종료 코드와 검색된 파일 집합은 확인하지 못했다. 빈 출력으로 비접근을 주장하지 않는다. 총괄은 private 로그를 읽지 않고 해당 역할만 중단했으며 다른 네 역할은 계속했다.

대안은 기존 긴 경로 재입력 지침만 반복하기, 기존 잘못된 경로에 원문 복사본을 새로 만들기, ID와 패킷 번호만 받는 고정 읽기 수단을 제공하기다. 세 번째를 선택한다. 잘못된 과거 경로를 실제 경로로 바꾸지 않고, root가 만든 controls 전용 registry의 정확 파일·SHA만 읽게 한다.

읽기 수단은 경로·역할·cohort를 CLI로 받지 않는다. 현재 역할에 배정된 source ID·패킷·부분 번호만 받으며 다른 ID, 상위 경로, SHA 변화, symlink와 파일 범위 이탈은 거부한다. 출력은 지정 패킷의 순서 보존 부분과 전체 길이/END 정보뿐이다. 코드 작성·시험·탐색·계수 업무를 역할에 위임하는 것이 아니다.

이 프로그램은 OS sandbox가 아니며 다른 도구 호출을 기술적으로 봉쇄하지는 않는다. 따라서 역할에 허용된 읽기 호출을 이 수단으로 한정하고 실패 시 임의 검색·경로 재구성을 금지한다. 새로운 범위 이탈이 생기면 해당 역할을 다시 제한하고 실제 관측을 기록한다. 과거 rg 접근 범위의 미확인은 그대로 남는다.
