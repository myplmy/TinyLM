# 재개 후 선택 연결과 저장 영향 검토

선택지는 세 가지다. 첫째, 검토 다섯 건마다 전체 캐시를 만들면 반영 지연은 짧지만 10GB 안팎의 payload와 전체 원장이 반복된다. 둘째, 닫힌 독립 대조를 모아 선택·전체 원장·캐시를 순서대로 만들면 중간 복제와 CPU 재작업을 줄이면서 공식 수치와 미반영 분량을 구별할 수 있다. 셋째, 즉시 delta 전용 캐시 스키마로 바꾸면 저장은 작아지지만 현재 consumer·EOS·경계·누설 검증 계약을 새로 검증해야 한다. 현 단계에서는 둘째를 적용하고 기존 생성기와 검증기를 재사용한다.

현재 오류가 있던 counter31은 채택 입력으로 쓰지 않는다. 단일 출력 경로를 새 리뷰로 정정한 뒤 counter32를 고정하고, 누적 보호 V4를 활성화한 선택 adapter에서 닫힌 행만 채택한다. 기존 순서 문맥 closure와 숫자74의 정확 두 범위 근거를 연결하되, 기존 일반 검사는 유지한다. 실패하거나 변경된 개별 본문은 보류한다.

GPU·학습·모델 실행은 없고 CPU 자료 작업만 한다. TinyDataset·체크포인트·타 세션 전용자료는 접근하지 않는다. 원형·기존 TXT와 원로그를 보존한다. 선택·원장·캐시 검증과 모델 품질을 구분한다. 최종 전량 정제 단계에서 METHODS·기준표·COMPASS 등의 필요한 정본을 갱신하며 현재 부분 진행을 연구 결과로 승격하지 않는다.

숫자 closure의 음성 검증은 숫자·범위·문맥·ID·SHA 변경을 거절하는지 확인한다. 실제 채택 후에는 이전 행 불변, 새 ID 수와 중복 위치 수, 현재 V4 보호 대상 접근0을 별도로 검산한다. 전체 캐시는 현재 검증본과 기준본을 보존하며 새 namespace 하나에서만 생성한다.

실제 counter32는 본문 수집 오류0이지만 review207 v2/v3의888524 사유 칸에 등장하는98341을 누락 판정 행으로 오인한 이력2건이 있었다. 선택 단계는 이를 거절했으며 ROOT29나 전체 캐시를 만들지 않았다. 원인은 기존 선언 검사에서 표의 모든 칸에 있는 ID를 모은 것이다. 새 safeguards V4는 표 첫 칸에서 선언한 ID만 검사하며 명시 제목·ID 라벨의 누락 검사와 실제 누락 행 거절은 유지한다. 기존 snapshot과 실패 로그를 보존하고 새 counter33에서 오류·미해석 이력·잘못된 과거 본문 fallback이 모두 없는지 확인한다. 이는 원문 변경이나 과거 작업 재판독이 아니다.

실행 결과 counter33의2345행·미해석0을 확인했고 ROOT29는245고유/412위치를 추가했다. roster21 전체297539행의 독립 검산에서 나머지297294행이 불변이었다. 새 roster 생성기의 최초 사전검사에서는 종전에 승인된 세 안전 부분본까지 원형의 보호 ID라는 이유로 거절했다. payload 생성 전 실패 로그를 보존했으며, 세 부분본은 이전 선택과 완전히 동일할 때만 보존하고 신규 보호 자료는 계속 거절하도록 바로잡았다. 원형 파일 접근은0이다.

전량 목록 저장 방식은 기존 사본 반복, 파일 연결, 불변 부모 manifest 참조의 세 가지를 비교했다. 반복 사본은266MB씩 누적되고, 파일 연결은 inode 공유·보존 책임이 불명확해진다. 불변 부모 HOLD 목록의 정확 경로·built SHA·manifest를 참조하는 방식을 적용한다. 실제460695위치/462874291입력ID를 매번 metadata로 재계수하고, 캐시 생성기에서 그 census ledger 검사 한 곳만 같은 부모 목록 검사로 연결한다. 다른 cache/text/토큰/원장 검사는 원래 경로에서 실행한다. 새 runtime7은 adapter 자체를 코드 핀에 포함한다. 부모 변경·잘못된 참조·manifest 변경·사본 혼입은 거절하며 원형·부모 파일을 수정하거나 연결 파일을 만들지 않는다. 실제 전체 캐시/consumer 검증은 별도다.

새 census 최초 핀 구성에서는 수집기용 ID 파일명 observer가 종전에 승인된 safe-view 원형 비교용 부분본까지 읽기 전에 차단했다. 원형 접근이나 새 census 출력은 없었고 실패 로그를 보존한다. 전량 캐시용 census는 기존 runtime6/7의 정확 V4 계약 검사와 세 safe-view SHA·명시 원문/본문 조건을 사용한다. 임의 ID 파일을 여는 수집기 진입점의 observer는 변경하지 않았다. 새267902/historical267904 등의 원형 차단과 HOLD 전량 opaque 투영은 유지한다. 수집기 observer의 접근0 결과를 전량 runtime 실행 증거로 복사하지 않는다.
