# 서수 마침표가 있는 실제 분류명 경계 검토

전량v25 미결 후보 분석에서336348·450493 등의 끝 문단은 출생/생존 표지와 축구 선수 분류가 함께 있으나 `1. FC ...의 축구 선수`, `2. 분데스리가의 축구 선수`, `3. 리가의 축구 선수`의 마침표 때문에 v17의 일반 명사형 꼬리 증명이 중단된다. 원문과 값은 그대로 둔 채 기존 증명의 이 부분만 좁게 확장한다.

| 안 | 장점 | 단점·영향 | 비용 |
|---|---|---|---|
| 전부 개별 판독 | 각 문맥 확인 가능 | 동일한 정상 분류명도 전체 수작업 대기 | 높음 |
| 꼬리의 일반 마침표 허용 | 많은 후보를 빠르게 처리 | 서지/문장을 분류로 잘못 묶을 수 있음 | 낮지만 의미 위험 큼 |
| 기존 분류 패턴에도 맞는 서수+축구선수 값만 증명 | 실제 값/순서 보존과 명시 표지 필요 | 다른 구두점·새 유형은 여전히 미결 | 중간 |

세 번째 안을 적용한다. 일반 구두점 허용이나 PENDING의 일괄 채택은 하지 않는다.

| 경로 | 동작·권한 | 제외 |
|---|---|---|
| scripts/p106b_hold_resolution_metadata_v2.py, policy_v26.py, 관련 시험 | 현재 goal의 CPU 전처리·관련 코드/시험 승인에 따른 신설 | 기존63생산파일 수정 |
| 자기 audit 및 새 파생 profile | 원문/SHA 연결과 목적 검산 | 기존 캐시·원형 덮기/삭제 |

코드 영향은 기존v17/v25 경계 증명의 재사용과 새 두 모듈이다. 데이터 값·숫자·날짜·분류 순서는 바꾸지 않고 고립된 빈 표제만 제거 가능하다. 실제 코드·수식·인용·개별 HOLD와 partial-quarantine 보호는 유지한다. 기존 회귀와 새 반례를 실행하고 모든 새 증명 매치를 계수한 뒤 원문을 별도 대조한다. 초안 캐시 채택과 정본 수치를 바꾸는 단계는 아니다.

GPU/모델/학습은0이며 보호TinyDataset·타세션 경로에 접근하지 않는다. 원문/토크나이저/분할은 바뀌지 않는다. 속도·품질 실험으로 해석하지 않고 최종 캐시 뒤 필요한 결과/계획/기준표/METHODS/COMPASS 연쇄는 별도 수행한다.
