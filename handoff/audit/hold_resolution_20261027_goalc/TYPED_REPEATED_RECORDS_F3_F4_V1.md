# 반복 문맥의 두 가지 좁은 처리

목표 §1·4·5·6과 현재 대량 규칙 처리·중간 파일 축소 지시로 진행한다.
실제 원문 전문을 읽은 근거: 344665는 서로 다른 1·7번 문항의 같은 선택지를 보존해야 한다.
457072·472081은 별도 분류 블록에 같은 비수치 태그가 반복되며, 첫 태그와 모든 다른 값은 남길 수 있다.
484877의 반복 설립 연도는 이번 비수치 규칙에서 제외한다. 71648의 결손 수식,
1048549의 구별 불가능한 동명이인, 515382의 빈 방송일자, 690742의 노선 표제 없는 역 목록은
반복 줄이 있다는 이유로 채택하지 않는다.

| 안 | 내용 | 장점 | 위험·영향 | 비용 |
|---|---|---|---|---|
| A | 짧은 반복이면 모두 삭제/해제 | 범위 큼 | 문항 선택지·인물·노선 관계 손실 | 낮음 |
| B | 완결된 번호 문항의 선택지는 보존하고, 이미 별도 입증된 분류 블록의 비수치 동일 태그만 중복 제거 | 모든 반복 출현의 역할을 추적 가능 | 다른 구조는 보수적으로 계속 보류 | 중간 |
| C | 반복 19472개를 전부 개별 재판독 | 넓은 사람 문맥 판단 | 긴 지연·기록 반복 | 높음 |

선택 B. 문항은 1부터 순서대로, 각 문항 서로 다름, 각 4개 비어 있지 않은 서로 다른 선택지,
모든 문항의 원래 답안 키가 실제 있고 일치할 때만 판독 역할을 부여한다. 답안의 사실성 검증은 아니다.
분류는 기존 metadata4의 이름 있는 도입·복수 typed anchor proof를 재사용한다. 모든 탐지 반복이
그 마지막 블록 안에만 있어야 하며, 숫자 포함 반복 태그는 처리하지 않는다. 값을 조용히 합치거나
다른 인물/작품/시기 기록을 중복으로 취급하지 않는다.

현재 ROOT37의 실제 미채택 HOLD만 대상으로 한다. 그 안에는 이전 CPU 정책이 이미 KEEP/EDIT라고
판정했어도 ROOT에서 아직 채택하지 않은 자료가 있으므로 PENDING→terminal 외의 전이도 별도 표시한다.
이를 공식 캐시 처리 완료나 새 인간 판독으로 세지 않는다. 새 정책32는 기존 terminal의 같은 분류
중복도 이 좁은 proof로 정리할 수 있으나, 부분 quarantine·개별 HOLD는 자동 해제하지 않는다.

| 경로 | 예정 동작·권한 | 제외 |
|---|---|---|
| scripts/p106b_hold_resolution_repeat_context_v2.py, policy_v32.py, test_policy_v32.py | 신설, 목표의 CPU 전처리·코드·시험 허가 | 기존1–31 변경 없음 |
| 이 audit의 census config·독립 문자/중복 proof·보고 | 신설 | 전량 인간 판독·자동 ROOT 승인 주장 없음 |
| manifest의 정확 원문 | guard6·ID/SHA 확인 후 읽기 | 제한 ID·hash·alias, 개별 NEEDS_ROOT는 제외 |

코드: 기존 repeat_context1은 완결 산문 직후의 표제/기명만 처리하므로 두 새 문맥을 추가한다.
데이터: 원형·고정후보는 불변, census는 metadata만 저장하며 학습/검증 분할을 바꾸지 않는다.
검증: 이전 회귀 전체와 문항 중복·빈 선택지·미일치 답안·수식·연도·본문 반복 반례를 추가한다.
중복 태그 삭제는 독립 line parser가 첫 동일 태그를 남긴 결과와 원래 수치·순서·코드·문체를 검산한다.
정본: 실제 채택 시에만 roster·캐시·단계/WIP·결과·METHODS·COMPASS에 계수 연결한다.
기술부채: config 기반 census/채택기 재사용. 숫자·코드 가드 포괄 면제는 없다.
도메인: CPU 정제뿐, GPU/모델/학습/평가 자료 추가·분할 이동 없음, 타 세션과 원형 소유권 유지,
규칙 처리·개별 최초 전문 판독·공식 캐시 검증·모델 품질은 별개다.
