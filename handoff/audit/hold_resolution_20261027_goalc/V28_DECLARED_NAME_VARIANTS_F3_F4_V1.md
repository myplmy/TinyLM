# 명시된 이름 목록의 선언 문법 확장

현재 사용자 지시의 기존 대량 정제 방법을 이어간다. 총괄이 원문을 직접 읽은309329 실비오,
304771 코바치,307632 후안 베론,1053703 아웅 투,186152 버밍햄,761947 퐁퐁은
이름/대상 목록임을 명시하지만27의 첫 문장 문법과 다른 형태여서 빈 별칭이 미처리된다.
수치·차 있는 이름·열린 연대·부정·기존 철자는 바꾸지 않는다.

| 안 | 내용 | 장점 | 한계·비용 |
|---|---|---|---|
| A | 기존478개 문법에서 멈추고 나머지는 전부 개별 편집 | 새 코드가 없음 | 동일 이름 목록의 반복 수작업이 계속됨 |
| B | 실제 관찰한 선언 변형만 기존 별칭 도구에 연결 | 이미 검증한 편집·가드를 재사용하고 반례로 범위 고정 | 새 회귀·전체 대기열 census·독립 문맥 대조 필요 |
| C | 모든 빈 괄호와 쉼표를 제거 | 넓은 적용 | 수식·튜플·누락된 값과 이름을 손상시킬 수 있음 |

승인된 전처리 범위에서 B를 적용한다. `어권에서 쓰이는 이름이다`, `라는 이름을 가진 사람은 다음과 같다`,
`이름이 ...인 사람으로는 다음이 있다`, `의 다른 뜻은 다음과 같다`, `다음 등을 가리킨다`처럼
목록이라는 원문 근거가 있는 첫 문장만 인식한다. 콜론이나 사람이름 주어로 실제 후속 서술이 붙은 행만
기존 명칭 변환을 이용한다. 단순 이름 목록을 완성된 외부 사실로 보충하지 않는다.

반례로131596의 이름 없는`(, He River)`,516973의 닫는 괄호가 과다한 연대,
1272749의 빈 작품명,192356의 이름 없는 인물,1046254의 이름 없는 여러 인물을 실제로 읽었다.
이들은 일반 규칙으로 해제하지 않는다.1104651의 연대만 있는 영화 괄호도 이번 생몰범위 확장의
근거로 삼지 않는다. 새 선언에 비대칭 괄호가 남으면 기존 PENDING을 유지한다.

| 경로 | 예정 동작·권한 근거 | 제외 |
|---|---|---|
| `scripts/p106b_hold_resolution_disambiguation_v2.py`, `policy_v28.py`, 해당 시험 | 목표 §1·5·6의 CPU 전처리·검증으로 신설 | 기존1~27/캐시/원문 덮기 없음 |
| 현재 세션 audit·새 작은 후보 metadata | 입력SHA·규칙·독립 보존 증거를 연결 | 원문/후보 사본·대량ledger 중복 |

코드는 기존27→26과6의 수식/값/호출 보호·명칭 변환을 재사용하고 새 선언 인식만 추가한다.
실제 새 텍스트가 필요한 경우만 파생본을 생성한다. 시험은382개 기존 회귀와 선언 변형,
빈 이름/작품명/숫자튜플/코드/기호/비대칭괄호/이전 개별HOLD 반례를 합친다.
초안 후보는 즉시 채택하지 않고 소스별 문자/숫자/순서·코드·Unicode 가드와 독립 판독을 확인한다.
개별 인간 전문판독과 규칙 처리는 단계계수6에서 구분한다.
데이터 조건·모델/토크나이저·GPU 실행은 바꾸지 않으며 현재 공식cache15 수치와 최종 캐시/학습 승인은
독립이다. 정본 문서 연쇄는 최종 전량 정제·캐시 검산 후 갱신한다.
