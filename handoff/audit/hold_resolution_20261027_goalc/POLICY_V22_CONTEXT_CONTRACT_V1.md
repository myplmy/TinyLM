# v22 문맥 규칙의 영향도와 검증 계약

기존 52개 생산 파일과 v21 전량 근거는 보존한다. 새 규칙은 초안이며 실제 캐시 채택이 아니다.

대안은 개별 판독만 계속하는 방식, 기존 검증기를 재사용해 정확 구조가 증명되는 유형을 추가하고 독립 대조 후 전량 적용하는 방식, 모든 반복·빈 괄호·빈 칸을 일괄 삭제하거나 기존 보류 조건을 없애는 방식이다. 두 번째를 선택한다. 첫 번째는 실제 발견된 예외의 판독에 필요하지만 전체 유형 처리를 대신할 수 없고, 세 번째는 코드·의미·조건을 손실시킨다.

새 자동 증명 범위는 다음으로 제한한다.

- 전문이 구문 분석되는 Python 코드 또는 기존의 완결 코드펜스, 실제 타입·함수 선언과 균형 괄호가 원문 전체를 덮는 제한된 C 계열 함수 묶음이다. 실제 소스 코드 문맥 안의 반복과 빈 인수는 삭제하지 않고 보존한다. 전역 프로그래밍 단어 하나로 산문을 면제하지 않는다. 구문은 실행·컴파일·알고리즘 정답의 증거가 아니다.
- 원문에 닫힌 위키 표, 고유한 채워진 열 제목, 채워진 행 식별자와 적어도 하나의 실제 데이터 칸이 있는 행이다. 일부 빈 칸이 있어도 행/열 관계와 모든 원문 칸을 그대로 보존할 수 있는지 검사한다. 빈 칸을 채우거나 완전한 사실 기록으로 주장하지 않는다. 전체 값이 빈 행, 사라진 헤더·닫힘, 합쳐진 셀, 모호한 여러 행은 이 추가 증명으로 풀지 않는다.
- 명칭 자체와 같은 종류가 첫 완결 정의에 명시된 한국어 정리·공간·가산기·알고리즘 등의 초기 빈 선택 병기다. 실제 함수명·값·매개변수·괄호 교육은 제외하며 빈 괄호 외의 명칭·값·조건을 바꾸지 않는다.

일반 정보상자의 평탄한 label=value 처리는 v17의 기존 구현이 이미 소유하므로 새로 만들지 않는다. 정의식·실제 함수 호출 손실·출생/사망 충돌·소속 없는 범례·UI와 불완전 의존부는 기존 보류 및 개별 중재를 유지한다. 유효한 반복을 남기는 것은 반복 제거 성과가 아니다.

영향은 자기 새 코드·시험·목적 검산·파생 초안에 한정한다. 원문·기존 캐시·52개 생산 파일·타 세션 소유 자료·GPU·모델·Git/index를 변경하지 않는다. 원문/code/Unicode/스타일/순서/메모와 source/body SHA 검사를 유지한다. 실제 새 종결은 독립 원문 대조 전까지 채택하지 않는다. PENDING 일괄 제외, zeroH 계약 완화, 대표 묶음만으로 전량 완료 선언은 금지한다.
