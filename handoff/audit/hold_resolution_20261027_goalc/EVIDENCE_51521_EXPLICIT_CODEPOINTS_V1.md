# 51521 명시 코드포인트의 문자 복구 근거

대상은 기존 배정 `expanded_train:51521` 한 건이다. 원문이 이미 적은 U+ 식별자를 해당 문자로 표기하는 복구이며 비어 있는 기호를 형태나 인접 순서로 추정하는 규칙이 아니다. 실제 본문 편집은 지정 Luna가 수행한다.

| 원문 명시 식별자 | 정확한 문자 | 원문에서 정해진 역할 |
| --- | --- | --- |
| U+3046 | う | 현재 사용되는 히라가나 |
| U+3045 | ぅ | 작은 히라가나 |
| U+1B11F | 𛄟 | 해당 문장의 히라가나 |
| U+1B122 | 𛄢 | 해당 문장의 가타카나 |
| U+4E8E | 于 | 해당 문장의 한자 |

정수 코드포인트를 Unicode 문자로 부호화한 뒤 다시 같은 정수로 돌아오는 것은 CPU로 독립 확인한다. Unicode 공식 [히라가나 코드표](https://www.unicode.org/charts/PDF/U3040.pdf) 및 [Kana Extended-A 코드표](https://www.unicode.org/charts/PDF/U1B100.pdf)도 해당 코드와 문자 이름을 명시한다. 후자의 1B11F/1B122 이름은 각각 HIRAGANA LETTER ARCHAIC WU 및 KATAKANA LETTER ARCHAIC WU다. 총괄 조회일은 2026-11-01이며 조회된 최신 코드표의 표제는 18.0이다. 이것을 14.0의 당시 표라고 기록하지 않는다. 원문의 2021년/Unicode14.0 추가 서술은 원문에 실제로 있는 연혁의 보존이며 이 최신 표만으로 해당 발표 연혁을 새 검증했다고 주장하지 않는다.

각 식별자가 직접 붙은 '컴퓨터 코딩' 문장 안의 정확한 문자 슬롯과 원문 `각각` 대응만 복구할 수 있다. 추가 발음·유래·빈 첫 표제·다른 작은 가나의 쌍·행 위치는 이 표를 근거로 추정하여 채우지 않는다. 마지막의 실제 `𛀁` 문자는 보존 가능하지만 그 문자와 `Yi(가나)` 또는 다른 빈 항목의 연결은 명시 근거가 없으므로 새 귀속하지 않는다. 불명확한 연결/빈 슬롯은 원형 hold에 남긴다. 공식 표의 추가 역사 주석과 새 문자들을 학습 본문에 가져오지 않는다.

이 문서는 새로운 문자 허용의 전역 예외가 아니다. 원문 ID/SHA, 선택 본문/SHA와 해당 판독표/SHA를 고정한 개별 채택에서만 사용한다.
