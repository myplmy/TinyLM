# 검토본 적체를 다음 채택 묶음으로 연결하는 선결

사용자의 전체 정제·CPU 전처리·관련 구현과 시험·별도 캐시 생성 승인을 적용한다. 총괄은 판단·계보·검산·명령을 담당하고 학습 TXT는 작성하지 않는다. 현재 원인분석 보고의 세 진행 방식 중, 닫힌 묶음을 먼저 통합하고 미결 ID만 분리하는 방식을 수행한다.

| 경로 | 동작 | 근거와 제외 |
|---|---|---|
| 이 감사 폴더의 새 preflight/metadata producer와 보고 | 신설 | goal 1·5·6 허용. 기존 원장·코드·기록 불변 |
| 고정 field/literal 진단과 최신 snapshot, 정확 지정 본문 | 읽기·SHA 대조 | V2 ID·original/candidate/body SHA 선검사. 보호 원형 재독 없음 |
| data_cache/root12_guard_clear_preflight_v1 | metadata 후보만 신설 | 채택·원장·캐시 변경과 구별 |
| 부모 cache5의 text-free ledger | metadata로만 스캔 | 새 보호 원문의 alias 위치 확인. 원형·후보·초기사본·패킷·토큰 디코드 없음 |

코드는 고정된 기존 진단 결과와 동일 source/body 쌍만 재사용한다. source/body 또는 현재 선택이 다르거나 guard 하나라도 미결이면 이번 선결 후보에서 분리한다. 전 guard 통과는 의미 검토나 채택 승인이 아니므로 독립 문맥 검토와 명시 ROOT 선택이 추가로 필요하다. 중재가 끝난 예외도 이번 단순 묶음에 자동 편입하지 않는다.

데이터 영향은 새 metadata 후보와 alias 계약뿐이다. 기존 본문과 캐시를 덮지 않으며, 알 수 없는 새 보호 alias는 payload 디코드 없이 실패한다. 후보와 보호 목록의 교집합 0, 본문/원형 SHA 일치, 이전 ROOT와 새 ID/원형 SHA 교집합 0, 수량 합을 검산한다. 새 캐시는 아직 생성하지 않는다. 전량 모델 실행·학습·스모크와 다른 세션 자료는 제외한다.

대조한 도메인 축: GPU/모델 없음; 데이터/타 세션 소유권 침범 없음; 실제 학습 비교 수치 변경 없음; 정적 선결과 의미·캐시 검증을 분리; 중간 상태는 WIP에 갱신하고 최종 결과/기준표/METHODS/COMPASS 연쇄는 A–E 종결 때 수행한다. docImpactTargets의 flag_whitelist 등 타 세션 변경을 만지지 않는다.

부채는 고정 snapshot·진단 버전 의존이다. 새 본문은 새 검산 뒤에만 포함한다. metadata alias 확인은 전체 원문을 다시 읽는 작업을 대체하며, 원형 해시를 새로 계산하지 않는다. 전체 metadata 원장의 해시는 허용된 계보 검증이고 보호 원문 자체 해시와 다르다.
