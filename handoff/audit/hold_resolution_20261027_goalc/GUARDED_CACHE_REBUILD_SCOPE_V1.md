# 원문 보호 경계를 지키는 새 캐시 생성 준비

전체 goal의 실제 별도 캐시 생성·독립 검산을 이어간다. 현재 공식 부분 캐시H160219와 새 초안을 구분하며 이 준비나 부분 캐시 생성으로 전체 목표를 완료하지 않는다. 기존 v5가 보존하는1145290개 채택 본문과 기존 제외는 그대로 유지한다. 부분 캐시 v1의 나머지196115개는 앞선 대조에서 확인한3421개 재검토를 포함하여 새 원문 판독·규칙 결과와 대조한다. 기존 캐시·원본은 덮거나 삭제하지 않는다.

| 안 | 내용 | 장점 | 한계·비용 |
|---|---|---|---|
| A | 동결 생성기를 그대로 호출 | 구현 추가가 적음 | 기존 scan iterator가 보호7 원문 본문까지 JSON으로 다시 디코딩함 |
| B | 독립 전체 생성기를 새로 작성 | 경계를 자유롭게 구현 | EOS·누설·기존본문보존·중복 검사를 대규모 중복 구현해야 함 |
| C | 동결 생성기·소비자를 재사용하고 입력 iterator에서 보호 원문은 메타데이터만 투영 | 기존 검증 경로를 보존하며 보호 본문 디코딩을 차단 | 투영과 정확 안전 본문 예외를 별도 반례 시험해야 함 |

선택 C. 보호 원문ID 및 같은 원문SHA의 다른 위치도 원형 본문을 디코딩하지 않는다. 전체 원시 토큰 파일의 기존 SHA·구간 SHA·EOS는 동결된 계보를 확인하는 데 쓰되 보호 원문 TXT를 다시 열거나 해석하지 않는다. JSON 원형 줄은 바이트로 경계를 확인하고, 보호 대상은 본문 필드를 건너뛰어 검증된 메타데이터만 읽는다. 보호 대상에 KEEP이나 원문 슬라이스 채택을 허용하지 않는다. 이미 명시 승인된 안전 뷰의 정확 EDIT만 별도 계약으로 검증하고 나머지는 명시 제외·보류다.

| 경로 | 예정 동작·권한 | 제외 |
|---|---|---|
| 이 audit의 새 투영 helper·반례시험·adapter | goal의 관련 CPU 코드·시험·캐시 허가로 신설 | 동결 생산66개 변경 |
| 동결 corpus/recovery/resolution 엔진 | 읽기·동일 기능 재사용 | 원형 파일 패치 |
| 실제 원문별 선택·메타데이터·안전 뷰 계약 | 정확 핀 대조 | 보호7 부모 TXT·원문 본문 디코딩 |
| 새 data_cache 캐시·roster·manifest | 새 버전만 실제 생성·독립 소비자 검증 | 기존 캐시 덮기·삭제·훈련 실행 |

코드 영향은 기존 iter_scan 호출부와 캐시 adapter 연결이다. 입력·출력 schema는 원문 SHA·구간·결정·분할·EOS를 유지하고 본문을 읽지 않은 보호 경계를 명시한다. 테스트는 문자열 속 위조 ID, 중복 ID, 보호 원문 SHA의 다른 위치, 변경된 메타데이터, 누락된 메타데이터, 본문 UTF-8 디코딩 차단, 일반 자료의 동일 본문, 허가되지 않은 KEEP/안전 뷰 예외를 검사한다. 기존 생성기·소비자의 문서경계·직렬화·train/val·정확중복·256토큰 부분 겹침·baseline보존 검사는 계속 적용한다.

정본 문서의 수량·판정은 실제 캐시와 독립 검산 뒤 갱신한다. 새로운 부분 캐시는 잔여 미결과 수량을 그대로 보고하며 최종 zero-HOLD 계약을 우회하거나 미결을 종결 HOLD로 개명하지 않는다. 명시 처리 불가능 구간의 최종 보류 계약과 미처리 상태는 별도 근거가 필요하다.

비용 참고: 기존 실제 부분 캐시 생성1781.196초와 v5 생성1760.134초가 저장돼 있다. 새 생성 시간의 보장은 아니며 추가 입출력·인코딩·검산을 예상한다. GPU·모델·교사·학생·학습·스모크·추가300M·다운로드·설치·외부서비스·push/PR은 실행하지 않는다. 보호TinyDataset·타 세션 전용 경로에도 접근하지 않는다. CPU·토큰/문서·기술검산·모델품질 증거를 구분한다.
