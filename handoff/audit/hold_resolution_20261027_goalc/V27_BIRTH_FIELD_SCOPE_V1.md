# 상충 생년 필드의 좁은 부분 복구

전량 계수에서 생년 충돌 사유는 3,541개 고유 원문에 나타났다. 그중 3,006개는 하나의 완전한 리드 날짜와 하나의 출생 분류가 있고, 리드의 명시적 불확실성 및 다른 미결 사유가 없는 **진단 후보 형태**다. 이 형태만으로 복구 가능이나 채택을 확정하지 않는다.

| 안 | 내용 | 장점 | 한계 | 영향·비용 |
|---|---|---|---|---|
| A | 각 사람의 생년을 원래 일차 자료와 대조 | 사실 정정의 강한 근거 | 수천 명의 원천 접근과 동명이인 검증 필요, 대량 취득 별도 승인 | 높음: 외부 사실 확인과 이력 |
| B | 충돌한 문서 전체를 계속 HOLD | 어느 연도도 임의 선택하지 않음 | 독립된 이름·월일·경력도 후보에서 빠짐 | 낮은 구현비, 큰 회수 손실 |
| C | 정확한 두 출생 역할이 증명되는 경우에만 두 상충 연도 필드를 원형 보류 | 생년을 정하지 않고 남은 실제 월일·경력을 보존 | 다른 출생 주장·달력·재임 날짜·불확실성은 별도 판독 필요 | 중간: 술어·반례·전량 계수·독립 판독 |

**선택 C.** 자동 판정은 이름이 있는 사람의 첫 생애 괄호, 실제 월일, 분리된 마지막 출생 분류, 다른 출생 주장 부재가 모두 증명될 때만 가능하다. 어느 생년이 맞는지 선택하거나 나이를 다시 계산하지 않는다. 해당 연도들에 의존한 나이/생애 산술이 있으면 적용하지 않는다. 실제 원문과 기존 진단 후보의 역할 증명이 서로 일치해야 한다.

| 경로 | 동작·권한 | 보호선 |
|---|---|---|
| 새 `scripts/p106b_hold_resolution_birth_conflicts_v1.py`와 해당 시험 | 첨부의 CPU 정제 도구·시험 허가로 정확 삭제 증명 구현 | 기존 생산 66개 파일 불변, 전역 가드 완화 없음 |
| 본 audit의 새 계수 도구와 새 data_cache 네임스페이스 | 기존 v26의 전량 미결 후보를 읽고 일치/불일치·원형 구간을 추적 | 개별/제한 parent는 메타데이터만, 캐시 채택0 |
| 이후 지정 Luna 원문 묶음 | 실제 원문·출력·보류 경계를 독립 판독 | 코드·시험·통계·해시·모델·GPU·Git 권한 없음 |

코드 영향은 새 증명 함수와 후속 정책 어댑터뿐이며 기존 원문 디코더·분류 경계·문자/코드/스타일/순서 가드를 재사용한다. 삭제 구간은 함수 입력 기준 좌표와 SHA를 기록하고, native 원문 구간과 별도로 구분한다. 값 복원·새 숫자 생성은 없다. 실제 날짜가 아닌 재임/활동 기간, 생년만 있는 왼쪽과 사망일이 있는 오른쪽, 같은 연도, 복수 출생 분류, 인용/예문/코드, 출생 논쟁·다른 출생 주장·생애 산술은 적용하지 않는다.

테스트는 이런 반례에서 원형을 보존하는지와 월일·사망일·경력 수치가 삭제되지 않는지를 확인한다. 작은 시험 뒤 전량 후보 계수와 실제 원문 대조 및 독립 판독을 수행한다. 아직 정책27 전량 실행이나 캐시 채택은 아니다. 정본 연쇄는 실제 새 전량 결과·최종 캐시 검산 이후 갱신한다. CPU1·새 파일 20MB 미만·GPU/모델/추가300M/설치/대량 다운로드0 경계를 유지한다.
