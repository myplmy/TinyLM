# 동일 후보의 중간 packet 생략과 실제 파일 불일치 구분

V2 판독 계획은 원문 프레임의 처음부터 끝까지와 마지막 full_diff 프레임을 읽는다. 원문/후보 전체 바이트가 같다는 증명에 따라 **후보 프레임만 담은 중간 packet**은 생략한다.

따라서 원문 마지막 packet에 후보의 앞부분이 보이고 마지막 diff packet 앞에 후보의 뒷부분이 보일 수 있다. 이 두 후보 조각 사이의 번호가 생략됐다면 두 조각을 연속된 후보 전문처럼 이어 붙여 비교해서는 안 된다. 후보 헤더의 character 수는 실제 후보 전체 길이이며, 선택 packet에 보이는 조각의 합계가 아니다.

required_packets와 duplicate_only_packets가 이 차이를 명시한다. source의 실제 전체 프레임은 생략하지 않는다. 원문이 첫 문자부터 END까지 실제 확인되지 않았거나 **한 packet 자체의 출력이** 도구에서 잘렸다면 같은 정확 파일을 좁게 나누어 읽어야 한다. 이것은 후보 전용 중간 packet을 계획대로 생략하는 경우와 다르다.

총괄은1014459/1017734/501839의 원문/후보 실제 바이트와 모든 순서 packet을 다시 대조했고 완전히 일치했다. 후보 발췌가 서로 달라 보였다는 관측은 남기되 파일 자체의 변경/손상이라고 단정한 메모는 새 버전으로 정정한다. 실제 도구 표시 문제를 재구성해 확인했다고 주장하지 않는다.

본인 TASK에 명시된 original/candidate 경로를 직접 읽고 diff -u로 확인할 필요가 생기면 그 정확 두 경로에서 수행해도 된다. controls 역할은 기존 고정 reader 경계를 유지하며 총괄이 별도 허용하지 않은 raw 파일 직접 접근은 하지 않는다. 동일 후보 증명은 내용 수용이나 독립 두 번 판독의 증거가 아니다. 내용은 원문 문맥으로 판단한다.
