# 1105949 병합 오염과 RTF 본문 경계

총괄이 지정 original 5,716바이트 전문을 읽었다. 서로 다른 Doxygen 강좌, RTF/AIML 편집 글, ConfigParser/Java/batch 검색 단편, Dreamweaver/GCC/Makefile 단편이 연결돼 있다. RTF 글의 필자나 출처를 다른 단편에 귀속시키지 않는다.

새 본문의 중심은 실제 반복된 주제인 RTF/RichTextBox/AIML의 독립적으로 완결된 서술이다. 처음 Doxygen 강좌 문단, 중간 ConfigParser부터 batch 복사까지의 병합 문단, Summary 뒤 다른 프로그램 설명·Dreamweaver·GCC·Makefile 단편은 다른 문서가 섞인 원형 구간으로 sidecar에 보존한다. 이것은 각 단편의 모든 사실이 거짓이라는 판정이 아니며, 현재 발췌에서 독립 문서의 계보·경계를 회복하지 못한 데 따른 비채택이다.

Background의 실제 작업 목적과 첫 RichTextBox 문장은 보존한다. 여기/여기를 지시하는 링크 소실 문장은 분리한다. RTF 색상표의 개념과 index 관계, header 역할, 기존 색상표 탐색과 rtf 태그 위치의 완결 설명은 보존한다. 방법 1/2의 지시가 실제 나열 순서와 엇갈린 비교 문장은 통째로 원형 분리하고 번호를 추정해 교환하지 않는다.

실제 없는 3색 색상표 예고, 중단된 IndexOf 코드, `From this index`의 미완 삽입 방법과 그 직접 보장 문장, 없는 sample code의 실제 동작 주장, 누락된 사양 링크에 의존한 미완 Further Work/History는 각각 원형 분리한다. 완결된 RTF header/colortbl 설명과 실제 Summary 문장은 보존한다. iterator 증가 문장이 빠진 실제 코드의 Note라서 독립 설명으로 남기기 어려우면 그 직접 의존 문장도 분리하고 루프 코드를 생성하지 않는다.

말미 반복 abstract 중 첫 완결 문장은 앞선 중심 주제와 같다. 처음 본문에 없는 실질 정보를 제공하는지 Luna가 문맥으로 판단하고, 단순 반복이면 삭제 이유와 원형을 남긴다. 새 저자/출처/코드/단락 연결문은 쓰지 않는다.
