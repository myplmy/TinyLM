# 전량 연결과 독립 판독의 실패 원형

앞 한국어 실패기록V2에 더해 이번에 실제로 반려·정정한 경위를 보존한다. 원형 코드·파일·실패 수집본은 삭제하거나 덮지 않았다. 아래는 데이터 품질 자체의 실패와 구분하며 전체goal 완료·일시중지의 근거가 아니다.

| 원형 | 실제 실패와 조치 |
|---|---|
| 전량 연결 계획v2 | 원문SHA 필드가 중첩된 proof 객체에도 나타날 수 있는데 전역 byte regex 일치1개를 가정했다. validation4의메타데이터에서2개를 확인하고 top-level 투영으로식별한v3를준비했다. 실패폴더v2는완료manifest가없다. |
| 전량 연결 계획v3 | 보호7개모두 초안PENDING일것으로가정했으나1250821이초안KEEP이었다. 본문은디코딩하지않고메타데이터만읽은상태에서반려했다. v4는이를정확한안전뷰EDIT/명시EXCLUDE로대체할때만통과하게해전체연결했다. 실패폴더v3도보존한다. |
| 정확 코드쌍 준비v1 | xs 호출이원문에서`nhlDF.`뒤줄바꿈으로분할돼있어연속한줄패턴이일치하지않았다. 실제109–110행을확인하고v2에서공백분할을허용했다. 코드비공백토큰은추가하지않았고정확5블록AST·xs단위검사가통과했다. 원형v1은보존한다. |
| 수집57 | 276550 ACCEPT출력이이번TASK의최신후보가아닌과거semantic후보를가리켰다. 정확후보를전문재판독해새리뷰로정정했다. |
| 수집59 | 689736 출력의내용주소파일명에서749가빠졌다. 작성자가v4수정중sed실패로손상파일을만들었고별도corrected리뷰를명시했다. 손상v4는auxiliary이력으로고정하고corrected리뷰는SHA·TASK배치로명시결합했다. 수집60은새49행미저장0·기계반려0이다. |

보조 역할이 보고한 지정 밖 경로3회씩의실패는 각각원형메모에남아있다. 내용이반환되지않았다는것은역할의보고이며총괄이그잘못된경로를재열람하거나OS차단성공으로확대하지않았다. 지정입력·실제본문·리뷰의경로와SHA일치는별도검산했다.

현재새부분로스터의115,526미결위치는단순HOLD개명으로종결한것이아니라미처리로유지한다. 새실제캐시생성·독립검산과큰잔여유형처리는계속한다.
