# 저장공간 정리 후 정제 재개 계약

현재 사용자는 전체 잔여 HOLD 정제 재개와 불필요한 새 중간 생성물 누적 방지를 지시했다. 기존의 정확 46개 하위 폴더 삭제는 완료됐으며 그 삭제 명령을 다른 대상으로 확대하지 않는다.

## 새 생성물의 수명

- 원문, 기존 후보, 역할이 작성한 모든 TXT 버전, 원로그와 판정 근거, 불변 manifest를 보존한다. 기준 캐시11과 현재 검증 캐시를 보존한다.
- 후보를 그대로 채택할 때에는 고정 reader의 `accept_output_absolute`를 사용한다. 동일 본문을 역할 폴더에 다시 복사하지 않는다. 수정이 필요한 경우에만 새 TXT 버전을 만든다.
- 판독 packet은 stdout으로 전달한다. 검토표 다섯 행마다 전체 캐시나 전체 원장을 만들지 않는다. 독립 대조가 닫힌 분량을 모아 다음 선택에 연결한다.
- 전체 캐시는 동시에 하나만 생성한다. 시작 전에 정확한 새 namespace, 입력 핀, 생성할 하위 경로, 보존 캐시와 진행 중인 자체 작업을 확인한다. 중단된12/14 namespace를 재사용하지 않는다.
- 새로운 중간물의 폐기는 정확 manifest와 현재 참조 여부, 대체 검증본을 먼저 확인한다. 과거 원본 보존 경계를 일반 정리 권한으로 해제하지 않는다. 이번 계약 자체는 추가 삭제 실행 기록이 아니다.
- 전체 원장과 census가 실제로 필요한 경우 기존 생성기를 재사용하되 작은 묶음마다 재생성하지 않는다. metadata 재사용은 기존 consumer의 입력·계보 계약이 성립할 때만 한다.

## 다섯 역할의 일반 텍스트 작업

각 역할은 RESUME_AFTER_STORAGE_ROLE_BINDINGS_20261105_V1.json의 정확 입력·출력과 V4 보호 경계 안에서 작업한다. V2 고정 reader로 해당 ID의 original/candidate pair를 전 파트 끝까지 확인하고 두 SHA와 EOF를 확인한 뒤에만 다음 일반 작업을 수행한다.

- reader가 명시한 exact original 또는 candidate를 본인의 존재하지 않는 새 TXT 경로로 복사할 수 있다. 원형과 기존 TXT를 덮지 않는다.
- 해당 원문·후보와 본인의 새 TXT에 대해 일반 `diff -u -- ORIGINAL NEW_TXT`를 사용할 수 있다. diff 종료1은 차이가 있다는 뜻이다.
- 새 본문, 전체 diff, EOF를 실제로 확인한다. 출력이 잘리면 빠진 부분을 다시 읽는다. 새 파일 해시는 정확한 해당 경로에 한한다.
- 코드 작성·실행, 전처리 프로그램, 모델, GPU, Git, 삭제, scope 밖 원문이나 아직 전체 판독하지 않은 원문에 대한 권한은 없다. 민감 자료로 새로 판별하면 추가 판독·해시를 멈추고 ID와 상위 사유만 보고한다.

통상적인 빈 필드 제거와 독립 본문 보존은 매번 총괄의 재승인을 기다리지 않고 수행한다. 판단 불가능한 한 건만 보고하고 나머지 건을 계속한다. 실제 학습 실행 승인은 없다.
