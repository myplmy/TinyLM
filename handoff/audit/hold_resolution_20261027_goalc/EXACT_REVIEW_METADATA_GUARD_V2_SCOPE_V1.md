# 새 비채택 원문을 다시 열지 않는 수집 경계

2026-11-04. 사용자 전체 정제 목표의 CPU 전처리·관련 코드 시험·별도 산출물 작성 승인 안에서 수행한다. 총괄은 학습 TXT를 작성하지 않는다.

| 경로 | 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| 이 감사 폴더의 새 guard·collector·시험·receipt | 신설 | goal 1·5·6의 코드·시험·총괄 검산 허용 | 기존 코드/기록 덮기 없음 |
| 지정 cohort manifest, 리뷰와 최소 사유 MD | 읽기·새 버전 수집 | 원문 연결 및 전체 처리 상태 확인 | 보호 ID의 원형·후보·초기사본·패킷 재독 없음 |
| data_cache의 새 cohort snapshot | 신설 | 별도 파생 산출물 허용 | ROOT·roster·공식 cache 채택 없음 |

| 안 | 내용 | 장점 | 단점 | 영향·비용 |
|---|---|---|---|---|
| A | 기존 V1 guard 수집기 실행 | 추가 구현 없음 | 새 보호 ID를 모른 채 원형을 해시·재독함 | 경계 위반이므로 실행하지 않음 |
| B | 고정 V5 수집 로직을 재사용하고 V2 guard 및 정확한 한 건의 metadata-only 분기 추가 | 기존 파서·버전 우선순위를 유지하고 새 보호 원형을 열지 않음 | tuple·리뷰·사유를 고정하고 분기를 검증해야 함 | 국소 코드·새 snapshot, 중간 비용 |
| C | 해당 페이지 전체 수집을 보류 | 보호 원형 재독 없음 | 나머지 정상 원문의 진척과 채택 선결까지 지연 | 구현 비용 낮음, 후속 처리 비용 높음 |

권장·선택: B. 실제 문제는 기존 수집기가 NEEDS_ROOT인 행도 원형·후보를 먼저 해시한다는 점이다. 원형을 전혀 열지 않는 별도 행 경로를 추가하고, 나머지는 고정 파서와 본문 바인딩을 그대로 사용한다. 알 수 없는 보호 ID·SHA나 보호 원문의 EDIT/ACCEPT는 읽기 전에 실패시킨다. 기존 V1·V5·페이지 V2 파일은 보존한다.

| 영향 축 | 판단 |
|---|---|
| 코드 | V5 collect의 계약 경로·사전 차단·view 생성·materialize 호출만 고정 marker로 감싼다. 기존 named 함수와 header/rank alias를 재사용한다. |
| 데이터 | 새 snapshot만 생성한다. 보호 한 건은 기존 ID·SHA·위치·사유·리뷰 연결만 저장하며 본문·새 원문 해시를 만들지 않는다. |
| 시험 | 가상 metadata로 정확한 HOLD 허용, EDIT/ACCEPT 거부, 잘못된 tuple·역할·SHA 거부, 다른 보호 ID 거부, 비보호 원문 경로 보존을 검사한다. 실제 수집에서 보호 TXT open 시도 0을 별도 확인한다. |
| 정본 | 중간 증거는 WIP와 이 감사 폴더에 기록한다. 모델/학습 결과 변화가 없어 현재 기준표·METHODS의 수치를 바꾸지 않는다. 최종 A–E 갱신은 별도 미완이다. |
| 기술부채·우선순위 | 한 건의 예외는 범용 허용목록으로 확대하지 않는다. 새 보호 ID가 나오면 새 계약·receipt·버전이 필요하다. |
| GPU·모델 실행 | 없음. CPU 수집·검산만 수행한다. |
| 데이터·타 세션 소유권 | 원형·기존 캐시·다른 세션·TinyDataset에 쓰거나 새로 접근하지 않는다. |
| 비교 조건·증거 수준 | 새 검토 수집은 cache 채택·학습·품질 증명이 아니다. Python open 관찰은 OS sandbox 증명이 아니다. |
| 문서 연쇄 | WIP에 V2 의무와 기존 수집기 재실행 금지를 기록하고 후속 최종 정본 갱신을 남긴다. |
