# L의 기존 전량 field 큐 편집용 초기 사본

L이 생년 TASK271까지 마친 뒤 이미 승인된 field001–036/other001–098 전량 큐로 이동한다. 편집 시작 때 원형/후보 직접 복사 권한을 다시 묻는 지연을 줄이도록 C에서 검산한 초기 사본 생성기를 역할만 바꿔 재사용한다. 새 정제문을 총괄이 작성하지 않는다.

| 방법 | 이점 | 한계 |
|---|---|---|
| 검증한 C 생성기를 같은 보호 검사로 L에 재사용 | 고정 candidate와 동일한 작업 바이트를 미리 준비하고 역할 경계를 유지 | 초기 사본 파일은 로컬에 추가됨 |
| 매 문서마다 총괄이 사본 생성 | 처음 쓰는 파일만 생성 | 수천 번 중재와 호출이 추가됨 |
| raw 원형/candidate 읽기·복사 권한을 확대 | 명령이 짧음 | 보호ID/SHA와 고정 입력·역할 경계가 약해져 채택하지 않음 |

첫 안을 적용한다. 36페이지/3,749 자기 배정에만 원문ID와 원형SHA의 보호 검사를 바이트 해시보다 먼저 적용한다. 원형/candidate/기존 파일 덮기0, 각 파일20MB미만, 복사 뒤SHA동일성을 검산한다. 초기 사본은 정제·새 판독·채택0이며 원문 판독은 계속 고정 reader를 쓴다. L은 자기 초기사본→아직 없는 자기 새TXT의noclobber복사와 자기TXT/MD읽기·비교만 허용한다. 원형·초기사본을 덮지 않는다.

영향축: CPU 로컬 사본과 작은 감사자료만 생성; GPU/모델/학습0; 타세션/보호자료접근0; 비교조건·품질결론·학습승인변경0; 원장과 역할 안내만 후속 연결한다. 생년 미완 작업을 이 사본 준비 때문에 중단하지 않는다.
