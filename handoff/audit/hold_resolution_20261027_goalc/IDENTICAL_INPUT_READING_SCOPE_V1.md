# 동일 입력의 판독 재사용 범위

사용자 전체 정제 지시와 첨부 objective의 CPU 분석·코드·시험·역할별 판독 허가 안에서 수행한다. 실제 정제 TXT는 기존 Luna 다섯 역할만 작성한다. impact-analysis의 착수 검토를 적용했다.

| 안 | 내용 | 장점 | 한계 | 영향도·비용 |
|---|---|---|---|---|
| A | 원문·동일 후보·프레임을 각각 반복 판독 | 기존 절차 그대로 | 동일 내용의 반복 읽기가 누적됨 | 없음·실행 비용 높음 |
| B | 원문 대신 짧은 차이만 판독 | 빠름 | 원문 맥락 손실과 가짜 END 위험 | 의미 검토 위험 높음·구현 낮음 |
| C | 실제 바이트·SHA·순서 패킷이 모두 일치한 쌍만 원문 전체 판독을 후보에 연결 | 원문 전문과 변경 없음의 증거를 유지 | 별도 증명·정확 범위 안내가 필요 | 판독 계획만 추가·구현 중간 |

권장·수행 C. 예를 들어 50,000자 원문과 동일 후보가 한 프레임에 각각 들어 있어도 원문 첫 문자부터 실제 END까지 읽는다. 후보는 실제 바이트 동일성으로 연결하고 최종 full_diff 프레임까지 읽는다. 서로 다른 후보에는 적용하지 않는다. 이것을 두 번의 독립 판독으로 세지 않는다.

| 경로 | 동작·권한 | 제외 |
|---|---|---|
| 본 audit의 새 helper/test/producer/증명 | objective의 CPU 구현·시험 허가로 신설 | 동결 코드·이전 증명 수정 없음 |
| remaining_literal_full_counter_v1의 정확 manifest·입력·패킷 | 지정 유형의 전체 CPU 검증 | 보호 ID 및 SHA는 본문 읽기 전에 거절 |
| 각 역할의 ROOT_IDENTITY_TASK_NNN_V1.md | 자기 TASK의 증명과 정확 읽기 목록 신설 | START/TASK/기존 TXT 덮기 없음 |

코드: 독립 helper를 추가하며 기존 정제·캐시 함수의 의미를 바꾸지 않는다. 데이터: 원문/후보/패킷 바이트와 스키마는 보존한다. 시험: 가짜 END, 다른 후보, SHA 변조, 누락·재정렬·오프셋·UTF-8 오류를 거절하는 회귀를 수행한다. 문서: 각 TASK 증명과 WIP에 연결하며 기준표·METHODS·COMPASS의 연구 판정은 바꾸지 않는다. 기술부채: 프로토콜 버전을 증명에 고정한다.

GPU/학습/모델 로딩과 무관하다. TinyDataset·타 세션·보호 부모는 접근하지 않는다. 같은 풀/원문/토크나이저·평가 경로는 변경하지 않는다. 동일성 증명은 의미·사실·품질·독립 검토나 캐시 채택 증거가 아니다. 새 수정 TXT는 전체 읽기와 전체 diff를 계속 요구한다.
