# 다섯 기존 작성 역할의 단일 최종 작업파일 준비

권한은 사용자의 전체 정제 및 구간별 반복 작업 축소 지시와 기존 Luna 새 TXT/MD 작성 위임이다.
전문을 이미 읽은 장문의 좁은 수정에서 총괄의 복사 작업을 기다리거나 전부 수기 재전사하지 않는다.

적용 역할은 현재 C/context_controls, L/context_latin, H/context_hangul,
J/historical_review, G/legacy_review 다섯뿐이다. 입력은 고정 V6 또는 검증된 batch-v1의
자기 배정 헤더에 나온 정확한 keep_output_absolute/accept_output_absolute TXT다.
출력은 기존 자기 역할·같은 page cohort 폴더의 새 `expanded_train_ID_...txt` 하나뿐이다.

원문/후보 전문 또는 lossless pair를 EOF까지 실제 읽고 REVISE_TEXT가 필요한 경우에만:

1. 고정 헤더의 원형 또는 후보 중 수정 출발본 하나를 고른다. 헤더의 정확 경로와 SHA를
   사용하고 같은 TASK 안에서도 다른 ID의 값/경로를 재사용하지 않는다.
2. 자기 새 최종 출력의 정확 경로에 `test ! -e`와 `test ! -L`로 기존 파일/심볼릭 링크가
   없는지 확인한다. 기존 원형·후보·완료본문·리뷰는 덮지 않는다.
3. Bash의 `cp -- 정확입력 정확새출력`으로 한 번 준비하고, **수정 전에**
   `cmp --silent -- 정확입력 정확새출력`의 종료0으로 초기 바이트 일치를 확인한다.
   광범위 복사, glob, 디렉터리 복사, 중간 source/packet 사본은 허용하지 않는다.
4. 이 아직 완료하지 않은 최종 파일에서만 실제 정제 편집한다. 최종 전문·전체 diff·EOF를
   확인하고 기존 5행/TASK 리뷰에 최종 출력 경로 하나와 원래 준비 입력·SHA·경계 사유를 기록한다.
   수정 후 최종 SHA는 총괄 수집기가 계산한다. 작성자가 해시/전처리 코드를 만들지 않는다.
5. 정상 KEEP/ACCEPT는 기존 경로를 선택하며 복사하지 않는다. 완료 후 추가 교정은 기존처럼
   새 버전으로 보존한다. 준비 전 상태는 불변 원형/후보에서 그대로 복구 가능하다.

이는 정해진 파일 복사·비교의 좁은 허용이며 코드·시험·임의 스크립트·모델·GPU·Git·삭제·
다운로드 권한을 늘리지 않는다. 보호 guard5·정확 배정은 그대로다. 거절된 ID/SHA의 원형·후보를
이 절차로 열거나 우회하지 않는다. Sidecar는 원문 경로/SHA/앵커를 참조하며 전문 복사하지 않는다.

총괄은 기존 source-linked 수집·변경구간/수치/코드/문체 검증과 독립 문맥 대조 후 채택한다.
복사 성공·전문 판독·새 본문 저장·ROOT 채택·실제 캐시 검증은 각각 다른 상태다.
일반 진행 기록은25ID/5TASK 또는 페이지·오류·실제 중재 경계에 묶는다.
