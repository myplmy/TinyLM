# 무손실 검토 전달 V2의 한정 변경

V1의 전체 원문과 손실 없는 후보 표현 원칙을 유지하며 실제 배포 전에 현재 누적 보호 V4를 강제한다. 사용자 전체 정제·CPU 도구 구현 허가 범위이고 실제 학습 TXT는 기존 다섯 역할만 작성한다.

| 안 | 내용 | 장점 | 단점 | 영향도 | 수행비용 |
|---|---|---|---|---|---|
| A | 기존 고정 reader와 동일 SHA 중복 읽기 생략 유지 | 현재 절차 재사용 | 원문/후보/diff 분리 호출과 경로 오기가 계속 발생 | 없음 | 낮음 |
| B | 전체 원문+모든 후보 변경을 하나의 pair view로 전달, UTF8 4000바이트 이하 분할 | 짧은 자료의 호출 통합, 삭제/추가 문자열 모두 확인 | 새 전송 범위·독립 복원·실제 역할 확인 필요 | 새 V2 entry/core/scope/별칭만 | 중간 |
| C | 기존 reader 출력 폭만 확대 | 구현 단순 | 한글·특수문자의 토큰 상한과 도구 출력 잘림 문제가 남음 | 기존 출력 계약 | 낮음이나 재독 위험 |

권장 B. V1의4000코드포인트 대신 UTF8 4000바이트 이하로 잘라 넓은 Unicode에서도 출력 상한 여유를 확보한다. 변경이 적으면 지운 문자열과 새 문자열을 모두 보여주고, 그 표현이 더 길면 후보 전문을 제공한다. 동일 SHA이면 그 사실을 확인하고 원문을 한 번 읽는다. 이 변경은 최초 검토 생략·의미 기준 완화·모델 품질 주장으로 해석하지 않는다.

| 파일·경로 | 동작 | 권한 | 제외 |
|---|---|---|---|
| audit의 새 core2/entry2/scope2/시험·측정 근거 | 기존 core1·고정 metadata reader 재사용, 새 전송 계약 시험 | 목표1·5·6의 CPU 구현·검증 | 기존 파일 덮기, 새 역할/모델0 |
| tmp의 다섯 새 고정 별칭2 | 정확 역할·기존 cohort·현재 V4를 고정 | 같은 허가와 지정 다섯 역할 | 기존 별칭 변경0 |
| 기존 역할의 시험 판독과 새 리뷰 MD | 모든 파트·바이트 복원·실제 읽기 범위 기록 | 원문 판독·TXT/MD 작성 위임 | 권한 확대·총괄 TXT 작성0 |

| 축 | 영향 | 내용 |
|---|---|---|
| 코드 | 있음 | core1의 역할/경로/양쪽 SHA guard와 diff·복원을 그대로 재사용한다. 전송 표현·UTF8 경계·pair 조합만 새 코드다. |
| 데이터 | 제한 | 입력 원형·후보는 변경하지 않는다. 원문/후보 SHA와 정확 출력 경로를 헤더에 제공한다. |
| 테스트 | 있음 | 독립 decoder로 byte 복원, 가짜 EOF, CRLF, Unicode 경계, 삭제/삽입, 역할·양쪽 SHA·V4 제한을 확인하고 실제 소규모 전달을 측정한다. |
| 정본 문서 | 제한 | 새 계약과 실제 적용 여부를 audit/WIP에 기록한다. 정본 최종 갱신은 목표E에 남는다. |
| 기술부채·순서 | 있음 | V1은 보존한다. 실제 원문/후보를 받은 검증 전에는 다섯 역할에 적용하지 않는다. 측정한 출력량·호출수와 사람의 처리시간을 구분한다. |
| GPU·학습 소유권 | 없음 | 모델·학습·GPU0, CPU만 사용한다. |
| 데이터 범위·비교·증거 | 있음 | 기존 다섯 역할과7개 cohort-role 조합만 허용하며 보호9 ID/10 SHA는 payload 전에 거절한다. trial을 전역 속도 개선 증명으로 쓰지 않는다. |
