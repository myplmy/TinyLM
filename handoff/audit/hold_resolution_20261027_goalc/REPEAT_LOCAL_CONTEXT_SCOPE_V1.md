# 반복 줄의 문맥 증명 범위

전량 v26의 반복 진단21,891고유 원문·32,802위치를 새 census로 모두 분류했다. 짧은 비문장 반복14,494, 작성자 모양184,160자 이하 나머지6,738,긴 반복475다. 이 수는 진단 분류이며 채택이나 복구량이 아니다. `By car`도 작성자 모양 정규식에 맞으므로 모양만으로 역할을 증명하지 않는다.

## 접근 비교

| 안 | 내용 | 장점 | 한계·비용 |
|---|---|---|---|
| A | 반복 줄을 하나만 남긴다 | 반복 신호를 크게 줄임 | 표제·역할·코드·인용·반복이 필요한 구조를 손실 |
| B | 전부 기존 PENDING 유지 | 새 오삭제가 없음 | 독립 표제·작성자 등 정상 반복을 계속 보류 |
| C | 텍스트를 그대로 두고 명시 역할과 서로 다른 완결 본문 문맥을 증명하는 반복만 분리 검증 | 실제 값·순서·반복을 보존하고 탐지 오경보를 좁게 해소 | 엄격한 이름/표제·문단 증명, 반례와 원문 독립 판독 필요 |

선택 C. 우선 자동 채택하지 않는 순수 증명 함수·반례 시험·전량 적용 후보 계수를 만든다. 후보가 된 모든 원문의 실제 native 역할을 다시 확인하고 기존 다른 가드는 유지한다. 위험도·언어·구조별 독립 판독과 발견 반례 조치를 거쳐서만 전체 정책/캐시에 연결한다.

## 영향과 허용 경로

| 경로 | 동작·근거 | 제외 |
|---|---|---|
| scripts/p106b_hold_resolution_repeat_context_v1.py 및 해당 시험 | 전체 목표의 관련 CPU 전처리 코드·시험 허가에 따른 신설 | 생산66 동결 파일 수정 |
| 이 audit의 새 계수·검증 도구와 새 repeat_* 파생 경로 | 원문SHA·위치·판정 연결 및 CPU 계수 허가 | 원형 덮기·삭제·보호7 원문·타 세션 |
| 지정 Luna TXT/MD | 앞215건 뒤 별도 정확 입력 계약으로 독립 판독 | 코드·시험·Git·웹·모델·GPU |

코드는 기존 policy_v26의 보호 코드 구간 마스킹·표제 정규화·원문 및 보존 가드를 재사용한다. 증명 함수는 본문을 편집하지 않으며 반복이 없는 텍스트를 다른 사유 해제 근거로 쓰지 않는다. 본문에 이미 있는 숫자·조건·부정·인용과 원문 순서는 그대로다. 새 패키지·외부 취득·GPU·학습·추가300M·push/PR는0이다.

완결 문장·빈 줄 배치는 의미 검토를 대체하지 않는 보수적 후보 필터다. 역할을 추정할 수 없는 짧은 문구, 동일한 주변 문단, 빈 표/수식, 메뉴·광고, 실제 코드/인용의 반례는 해제하지 않는다. 글자 수 하나만으로 정상 반복을 확정하지 않는다. 기존 계수·공식H160219는 실제 새 캐시 검증 전까지 유지한다.

테스트는 작성자와 `By car`의 구별, 인접 복사와 다른 문맥, 실제 코드/인용과 제목, 한 줄이라도 역할 미입증이면 실패하는 전체 반복 집합 보존을 확인한다. 최종 정책·캐시·정본 영향은 후속 실제 검증 시 반영한다.
