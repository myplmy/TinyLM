# ROOT11 중간 캐시 반영 범위

전체 잔여 정제는 계속 active다. snapshot16에서는 출생2743과 반복732의 전량 리뷰가 저장됐고, literal1793은 재판독·수정·중재가 진행 중이다. 기존 잘못된 채택1255247 철회와 수량 복구는 빠르게 실제 캐시에 반영할 필요가 있다.

| 선택 | 장점 | 한계 |
|---|---|---|
| 모든 literal 판독이 끝날 때까지 새 캐시를 기다림 | 한 번에 큰 범위를 반영 | 이미 확인한 오채택 철회와 수량 복구의 실제 검증도 늦어짐 |
| 현재 guard를 통과한 literal만 즉시 포함 | 새 본문을 일찍 반영 | 초반 부실 ACCEPT 재감사와 남은 문맥 중재가 끝나지 않음 |
| 완료된 출생·반복과 기존 수량 교정부터 반영 | 닫힌 판독 범위와 검증 범위를 명확히 연결 | literal 본문 및 나머지 유형은 다음 버전에서 반영해야 함 |

세 번째 방식을 적용한다. ROOT10의 변함없는 정확 쌍 승인 근거를 재사용하고, 완성된 출생·반복·수량 재판독만 이번 새 선택에 포함한다. 개별 원문 전문을 검토한1046282 HOLD는 비채택 근거로만 포함할 수 있다. 현재 literal 본문을 이번 캐시에서 미처리로 남기는 것은 불량 확정이나 영구 제외가 아니다.

선택 문서의 `unresolved_sources=0`은 **이번에 선택한 정확 ID 집합 안의 미종결0**이라는 기존 로더 계약에만 사용한다. 현재 배정 미선택 및 전체 코퍼스 미처리 계수와 목록은 별도 명시한다. 코퍼스 전체 HOLD가0이거나 goal이 완료됐다는 의미로 쓰지 않는다.

보호: 원본·이전 캐시·동결 코드130pin·TinyDataset·타 세션 전용자료를 변경하지 않는다. 새 audit 코드와 새 roster/cache 경로만 사용한다. 숫자·단위·주체·조건·순서·코드/Unicode 표시가 정확히 종결되지 않은 쌍은 이번에도 채택하지 않는다. 원문 생성·수정은 Luna만 수행한다.

새 roster는 미판독과 개별 검토 비채택을 분리하고 전체 위치/고유 원문/토큰 합을 맞춘다. 실제 cache build·독립 consumer·전체 재계측을 실행한 뒤 결과를 보고한다. 중간 저장·부분 캐시 검증은 전체 goal 정지나 완료의 사유가 아니다.
