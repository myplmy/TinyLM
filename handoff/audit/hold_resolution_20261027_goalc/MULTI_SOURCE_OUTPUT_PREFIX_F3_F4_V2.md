# 실제 큰 묶음의 출력 한도 대응

v1의 다섯 역할25개 짧은 source 대조는 통과했지만, J의 실제 page017 TASK008에서
metadata와 본문을 합친18000바이트 한도가 초과됐다. 본문을 인쇄하기 전에 거절해
잘린 내용을 완료로 세지는 않았으나 ID별 fallback 때문에 호출 비용이 생겼다.

| 안 | 영향·비용 |
|---|---|
| A |한도 초과 때 기존처럼 전부 실패·개별 재호출|안전하지만 준비한 프레임을 낭비함|
| B |이미 준비한 프레임의 접두 묶음을 메모리에서 줄여 한도 안에 반환|원형 재읽기 없이 같은 byte/range/EOF 보존|
| C |출력 한도를 없앰|tool 자체 잘림 위험이 커짐|

B를 새 v2에 적용한다. 기존 v1은 불변이다. 본문을 재가공하거나 조각 중간을 자르지 않고
마지막 frame 또는 source packet 전체만 미반환으로 돌린다. 이전 조각의 실제 next_part와
not_returned_ids를 다시 계산한다. 실제로 준비한 source 수와 반환 source 수를 분리하며
준비만 하고 반환하지 않은 ID를 읽기 완료로 세지 않는다. 재조립한 header·frame 자체는
기존 v1과 같다. 단일 frame조차 한도 안에 들어가지 않으면 여전히 아무 본문도 인쇄하지 않는다.

새 adapter·반례 시험과 다섯 새 고정 shortcut만 신설한다. 기존 core/scope/guard/원형/
cache16의206개 입력 pin은 불변이다. 실제 J 실패 묶음과 metadata가 큰 fixture에서
추가 payload read 없이 접두 frame이 그대로 반환되고 커서·미반환 ID가 맞는지 검증한다.
짧은 묶음은 v1과 출력 bytes도 같아야 한다. 과거 실패 원로그와 v1의25개 검증을 보존한다.
이 수정은 전송의 크기 대응이며 의미 판독·ROOT·캐시/학습 판정을 바꾸지 않는다.
