# 새 필드 선택본문의 기존 진단기 재사용

field001v17/002v8/003v6/004v12/005v9/006v13/007v8/008v6의 동결 리뷰2224개 중 실제 선택본문을 가진 행만 검사한다. 보호 ID와 원형SHA 양쪽을 본문 읽기·해시 전에 대조한다. 원형·리뷰·본문·캐시와 기존 진단기를 수정하지 않는다.

| 방법 | 장점 | 비용과 한계 |
|---|---|---|
| 기존 연결/SHA 검사만 유지 | 추가 계산이 적다 | 숫자 일부 손상·코드/인용변형·검수메모 혼입을 별도로 찾지 못한다 |
| 기존 본문 진단기를 새 동결에 적용 | 숫자 atom·코드·Unicode·style·순서·메모의 기존 기준을 재사용한다 | 신호는 개별 문맥 판단이 필요하며 의미통과가 아니다 |
| 곧바로 ROOT/캐시 재생성 | 캐시 소비 경로의 실제 결과를 얻는다 | 미검토 신호를 먼저 해결해야 하며 긴 재생성/소비를 반복하게 된다 |

두 번째 방법을 진행한다. audit_exact_cohort_bodies_v6.py의 순수 CPU 검사를 AST로 그대로 재사용하고 명시된 cohort/version 목록만 바꾼다. 원본의 단일 큰 JSON 쓰기는 기존 shard_records/write_json_new를 사용해 새5MB미만 메타데이터 shard와 complete로 나눈다. 실제 바이트의 끝LF 여부·길이·말미 hex를 추가 계수하며 이를 원형EOF 불변이라고 뭉뚱그리지 않는다.

의미 검토·학습 품질·전량 사실검증·캐시채택·학습승인으로 승격하지 않는다. 기계 신호를 자동면제하거나 정제본을 자동수정하지 않는다. 기존22/개별후속과 독립 생년2707본문은 이 보고를 위해 다시 전량 판독하지 않는다. GPU/모델/학습/설치/다운로드0, 보호/타세션자료 변경0, tokenizer/학습풀 조건 변경0이며 문서연쇄는 진단 근거·WIP·진행보고에 한정한다.
