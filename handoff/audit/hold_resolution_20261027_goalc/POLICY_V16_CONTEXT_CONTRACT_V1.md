# v16 문맥 보존과 새 반례 보호

사용자 목표의 CPU 관련 코드·시험·별도 파생물 허가 안에서 수행한다. 이전 v1–v15 정책과 기록은 덮지 않는다. v15는 목적 탐색만 했고 전량 실행하지 않았다. 전량 후속은 동결 v14를 기준으로 새 v16 namespace를 사용한다.

| 안 | 처리 | 이점 | 한계 | 영향·비용 |
|---|---|---|---|---|
| A | 분류처럼 보이는 모든 말미를 삭제 | 탐지 수치 감소 | 참고자료·직업·출생 정보까지 소실 | 의미 영향 큼, 구현 낮음 |
| B | 별도 문단의 명시 연도/상태와 알려진 분류 구문으로 끝 경계를 증명하고 모든 값을 보존 | 자료가 채워진 앞 목록과 분류를 모두 유지 | 미확인 말미는 계속 개별 판독 필요 | 새 정책·시험·초안에 국한, 검증 중간 |
| C | APPENDIX 신호를 일괄 면제 | 구현 쉬움 | 실제 빈 절·깨진 문맥도 통과 | 데이터 위험 큼, 구현 낮음 |

수행: B. 기존 원문 판독에서 확인한 `같이 보기`의 실제 항목은 그대로 두고, 그 뒤 별도 문단의 연도·생존 상태·분류 표기만 끝 경계 근거로 사용한다. 삭제는 바로 앞의 독립 문단 전체가 빈 각주/외부링크 등의 표제들뿐인 경우로 제한한다. 분류 단어·연도·실제 출처·인용·문장·순서는 삭제하거나 새로 만들지 않는다. 경계 증명만으로 다른 결손/중복 사유는 면제하지 않는다.

새 v15 반례에서는 명칭 뒤 콜론의 실제 빈 값, 빈 발급 이름, 주어를 잃은 빈 따옴표, 닫는 대괄호 잔재가 남았다. v16은 본문 밖 코드/리터럴을 보호한 채 이런 실제 결손을 추가 보류한다. 이전 종결 초안도 이 새 결손이 있으면 재사용을 거부하고 새 정책으로 판정한다. 해당 개별 문서의 실제 복구 TXT는 별도 root 선택으로만 사용한다.

| 영향 축 | 범위 |
|---|---|
| 파일 권한 | `scripts/p106b_hold_resolution_policy_v16.py`, 새 refinement/revision 및 해당 시험, own 감사 producer/receipt만 신설한다. 환경 규약·원형·타 세션·GPU·모델은 제외한다. |
| 호출부 | 기존 policy v15와 original reader·draft engine·refinement v3를 재사용한다. 새 revision만 새 refinement로 진입한다. 기존 실행 경로를 변경하지 않는다. |
| 데이터 | source-linked 초안만 새 namespace로 쓴다. 기존 1,145,290 채택 본문과 검증 중간 캐시를 변경하지 않는다. 새 파일은 20,000,000바이트 미만이다. |
| 시험 | 기존 184회귀와 명시 경계/이름/코드/리터럴/반복 반례, 과거 종결의 새 결손 재판정을 검사한다. 달라진 목적 후보는 별도 전문 대조한다. |
| 의미·학습 비교 | 값이나 사실·조건을 선택하지 않는다. 출생 모순과 소실 수식은 보류한다. 초안 건수를 실제 캐시 수치로 쓰지 않는다. |
| 부채·정본 | 이전 실패를 보존하고 단일 source/본문/검토 SHA를 연결한다. 실제 캐시 재생성·전체 재계측 뒤 정본 연쇄를 갱신하며 root09는 수정하지 않는다. |
| 실행 | CPU1/계산 스레드1, 전량 시작 전 own tmp로 부하 구간을 알린다. 모델·학습·추가300M 승인을 만들지 않는다. |
