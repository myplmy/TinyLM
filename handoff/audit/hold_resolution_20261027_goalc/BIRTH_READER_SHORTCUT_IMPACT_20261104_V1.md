# 고정 판독기의 짧은 호출 경로

사용자 전체 정제 재개 및 objective의 CPU 도구 구현·시험 허가로 수행한다. 원문 판독은 Luna가 하고 총괄은 기존 도구의 호출 경로만 보완한다.

| 경로 | 예정 동작 | 권한 | 제외 |
|---|---|---|---|
| 현재 감사 폴더의 준비기·CPU 시험·실행 근거 | 신설/실행 | CPU 분석·관련 구현/시험 | GPU·모델·설치·네트워크 |
| tmp/hold-c-v1, tmp/hold-l-v1 | 새 실행 진입 파일 | 지정 원문 판독 지원 | 기존 파일 덮기 없음 |
| controls/Latin의 ROOT_SHORT_READER_ENTRY_V1.md | 새 안내문 | root의 위임 경로 고정 | Luna 본문/기존TASK/리뷰 수정 없음 |

## 선택

| 안 | 이점 | 비용·한계 |
|---|---|---|
| A. 긴 기존 명령을 그대로 복사 | 구현 없음 | 공백·audit 누락 등 실제 경로 오기가 반복됨 |
| B. 역할별 짧은 진입점에서 기존 v2 그대로 실행 | 기존 ID/SHA/순서/전달기록을 재사용 | 두 짧은 파일과 경계 시험 필요 |
| C. 모든 phase에 새 통합 판독기 도입 | 필드 경로도 통합 가능 | 역할·registry·분할 계약의 영향이 커짐 |

수행: B. 기존 v2의 바이트를 매 실행 전에 검사하고, 원문ID/패킷번호와 선택적인 root `--probe`만 그대로 전달한다. 실제 판독은 같은 v2가 담당한다. 원문·후보·패킷·registry·guard·journal을 변경하지 않는다. 완료한 원문을 도구 변경 때문에 재판독하지 않는다. 필드3역할은 아직 이 새 진입점의 범위가 아니며 기존 scoped helper의 추가 재사용을 별도로 검토한다.

## 영향도

- 코드: 실제 read_context_controls/latin_birth_root11_packet_v2.py와 scoped_packet_reader_v1.py를 읽었다. 새 진입점은 v2를 그대로 실행하며 argparse·분할·보호 계약은 기존 코드가 소유한다. v2·guard·config 파일을 수정하지 않는다.
- 데이터: 역할 입력/출력과 리뷰 경로가 같다. 실제 역할 실행은 기존 review_inputs, root 시험은 기존 root_probes로 분리된다. 과거 리뷰에 전달시각을 소급하지 않는다.
- 시험: 합성 reader로 출력/오류코드/리터럴 인자 전달, 잘못된 인자수, 변경·심볼릭 링크 reader 선거부를 확인한다. 실제 root probe로 원래 메타데이터와 END를 확인하되 정식 리뷰 입력으로 기록하지 않는다.
- 정본: 학습 풀·캐시·기준표·METHODS의 수치/판정은 바뀌지 않는다. 근거·위임문서·WIP에 새 호출 경계만 연결한다.
- 부채/우선순위: 새 reader를 중복 구현하지 않는다. 짧은 진입 파일이 사라져도 고정 준비기로 재생성 가능하다. 보호 경계와 실패 기록을 유지한다.
- 도메인: GPU/모델/학습 없음. 보호ID와 SHA는 기존 v2에서 본문보다 먼저 검사한다. 타 세션 전용 경로 접근 없음. 비용·전달 증거와 의미/품질을 구분하며 완료·학습 승인으로 승격하지 않는다.
