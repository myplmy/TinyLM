# 긴 문서의 중복 전달 개선 영향 검토

| 파일·경로 | 예정 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| audit의 lossless_review_packet_v3.py와 시험 | 새 버전 작성·CPU 검증 | 전체 정제 목표의 관련 코드 구현·시험 승인 및 현재 재개 지시 | 원형·기존 core 수정 없음 |
| audit의 새 고정 entry/scope와 tmp의 새 역할 별칭 | 새 버전 연결 | 기존 다섯 역할의 명시 입력·출력 위임 | 역할·원문·판정 범위 확대 없음 |
| 기존 원문/후보 | 현재 보호 계약과 지정 manifest로 읽기 | 전체 잔여 HOLD 정제 CPU 범위 | 쓰기·모델·GPU·보호 원형 접근 없음 |

확인 사례는 G의278626이다. 원문44187자, 후보44171자이며 V2의80000자 합계 경계에서 긴 구간을 하나의 변경으로 표현해 INDEX_AND_FULL_CANDIDATE와50파트가 전달됐다. 두 길이의 차이가 전체 수정량이라는 주장은 하지 않는다. 기존 코드를 추적하면 짧은 문서의 줄/문자 비교와 긴 문서의 공통 접두·접미 비교는 이미 구현돼 있다. 새 구현은 긴 문서의 반복 후보 전달을 줄이는 부분에만 둔다.

| 안 | 내용 | 장점 | 단점 | 영향도 | 수행비용 |
|---|---|---|---|---|---|
| A | 현재의 긴 구간 통째 표현 유지 | 기존 검증 그대로 | 원문과 거의 같은 후보를 반복 전달 | 없음 | 낮음 |
| B | 긴 문서도 제한 없는 SequenceMatcher | 상세 변경 가능 | 반복 문서에서 계산량이 커질 수 있음 | 계산 경로 | 중간 |
| C | 유일한 동일 줄의 순서 anchor와 제한된 구간 비교, 기존 표현과 크기 비교 | 원문 전문과 모든 OLD/NEW를 유지하면서 반복 감소 가능 | 새 차이 계산 검증 필요 | 전달 전용 새 core | 중간 |

권장·적용은 C다. 동일한 줄의 순서를 보존하는 anchor 사이 구간만 비교하고, 작은 구간에 기존 문자 비교를 재사용한다. 큰 구간은 기존 제한 비교를 유지한다. 최종 표현이 기존보다 작을 때만 선택하며 source/candidate의 UTF-8 바이트가 정확히 재구성돼야 한다. 큰 입력의 최적화 작업량을 제한하고 실패하거나 이득이 없으면 기존 표현을 사용한다. 원문은 언제나 전부 전달한다.

코드 영향은 prepare_views의 새 구현과 이를 명시하는 고정 entry/scope다. 기존 V1/V2, 이미 생성·검증한 cache15와166 runtime 핀은 바꾸지 않는다. 데이터 스키마·코퍼스 본문·채택 기준·문맥 검토·모델 실행에는 영향이 없다. 기존 독립 표시 decoder, UTF-8/CRLF/가짜 끝 표식/보호계약 시험을 재사용하고 긴 반복문·앞뒤 소수 변경·순서 변경·단일 긴 줄을 추가 검증한다. 실제 corpus의 양쪽 SHA와 전 파트 재결합을 별도로 검사한다. 성공해도 새 최초 판독이나 전량 의미 검토로 세지 않는다.

기술부채는 버전 연결과 고정 별칭의 추가이며 기존 재현 경로는 보존한다. 기존 캐시·학습 풀·토크나이저·모델·GPU·타 세션 소유권을 변경하지 않는다. 속도 향상은 실제 전달 바이트/파트에 한해 보고하고 인간 검토 처리율이나 학습 품질 향상으로 해석하지 않는다. METHODS·기준표·COMPASS의 실험 결과를 바꾸는 작업은 아니며 최종 데이터 정제 정본에 실제 적용 범위를 연결한다.
