# v23 원문 결손과 빈 구조 처리 계약

v22의 회귀 통과와955쌍 목적 검산은 실제 수식 결손을 놓친146452의 의미 종결을 증명하지 못했다. 기존55개 생산 소스와 실패·반례를 보존하고 전량v22는 실행하지 않는다. 새 전량의 기준은 실제 검산된v21이다.

대안은 개별 판독만 계속하는 방식, 실제 비어 있는 구조를 좁게 처리하면서 새 결손을 과거 종결에도 다시 검사하는 방식, 미결 이유를 일괄 없애는 방식이다. 두 번째를 선택한다. 원문에 없는 계수·수식·날짜를 만들지 않으며 기존 코드·Unicode·스타일·순서 검사를 유지한다.

새 결손 검사는 ‘여기서 은 주어진 계수들이다’ 및 ‘여기서 에 따라 미분방정식…’처럼 실제 기호 역할이 빈 구간이다. 이를 일반적인 수학 문장이나 기술 용어가 있다는 이유로 확대하지 않는다. 보호된 코드/인용 예문과 원문 전체가 실제 코드인 경우는 구분한다.

새 구조 처리는 알려진 명명 소개가 있는 원문의 빈 줄거리→배역/출연진, 빈 수록소프트→기타, 값 없는 단일 가족 필드, 실제 Staff/Musicians 출처문 뒤 목록 없이 증명된 메타데이터가 오는 경우로 제한한다. 실제 사이 내용이 공백뿐이어야 하며 코드·예문·목차 안의 표시는 처리하지 않는다. 부모/자녀/형제/자매 그룹 표제를 빈 단일 인물 값으로 취급하지 않는다. 실제 참고문헌·목록 항목·인용·숫자·순서·인과·조건은 보존한다.

분리한 정확 원문과 문자 구간, 좁은 이유를 각 변경 근거에 남긴다. 이 분리는 알려진 빈 구조의 처리이며 일반 문단 격리를 허용하지 않는다. 과거의 내용 결손 격리가 메타데이터 경계 판정을 빌려 자동 종결할 수 없다는 기존 금지는 유지한다. 모든 새로운 종결은 정확 원문과 실제 저장 본문의 독립 대조 후에만 채택한다.

원문·기존 캐시·원로그·체크포인트·보호TinyDataset·다른 세션 소유 경로·GPU·모델·Git/index를 변경하지 않는다. PENDING 일괄 제외나 zeroH 계약 완화는 금지하며 추가300M 학습은 미허가다.
