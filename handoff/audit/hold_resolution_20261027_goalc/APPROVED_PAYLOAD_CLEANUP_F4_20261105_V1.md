# 승인된 파생 생성물 삭제 범위

현재 사용자 지시는 `삭제 가능한 생성물 삭제`다. 바로 앞 보고의46개 하위 폴더·5177파일·101526917120할당바이트가 승인 범위다. 기본 삭제 금지의 예외는 이 명시 범위뿐이다. 별도 승인을 다시 요구하지 않고 실행한다.

| 파일·경로 | 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| BASE의 cache_partial_v1 및 cache_reviewed_partial_v2~v10 아래 tokens·text | 명시 파일 제거와 빈 대상 하위 폴더 제거 | 현재 삭제 지시와 직전 후보 표 | 부모 폴더·built/verified·ledger/hold 보존 |
| BASE의 cache_reviewed_partial_v12/v14 아래 tokens·text·ledger·hold | 같은 방식으로 중단 부분본 제거 | 같은 승인 | started.json·외부 로그·오류 기록 보존 |
| BASE의 guarded_partial_proposals_v2~v17/v19/v20 아래 ledger | 부모 원장과 지문이 같은 중복 원장 제거 | 같은 승인 | 각 complete.json, v18, 현재 opaque census 보존 |
| 이 audit의 삭제 실행기·시험·manifest·진행 저널·결과 | 작은 감사 근거 신설 | 삭제의 정확 범위·실제 결과 기록에 필요한 작업 | source TXT 본문 읽기·해시0 |
| 현재 세션 WIP의6번 및1번 재개 지점 | 공식 wip.py로 진행·결과·현재 상태 기록 | 현재 지시와 원래 전량 정제 지시 | 전체 정제 완료/일시중지로 처리하지 않음 |

BASE는 `/home/uranus/tinyLM/data_cache/p106b_hold_resolution_v1_20261027_goalc`다. 저장 장치 여유나 Windows 가상디스크 축소는 이번 실행 범위가 아니다.

| 축 | 영향 | 내용 |
|---|---|---|
| 코드 | 제한 | 기존 모델·캐시 생성기는 변경하지 않는다. 삭제 실행기는 고정46개 대상과 manifest inode/mtime를 확인하고 os.unlink/os.rmdir만 사용한다. 재귀 전체 삭제와 링크 추적을 사용하지 않는다. |
| 데이터 | 있음 | 승인된 과거/중단 파생 payload만 제거된다. 최신 cache11·roster20·원문·수작업 TXT·현재 census·과거 판정/로그를 보존한다. |
| 테스트 | 있음 | fixture의 허용 밖 경로·symlink·hardlink·변경된 파일 거절과 명시 범위 삭제를 확인한다. 실제 실행 전 현재 참조와 열린 핸들을 검사한다. |
| 정본 문서 | 제한 | 저장 위치와 오래된 캐시의 payload 퇴역 상태를 audit/WIP에 기록한다. 실험 수치·모델·학습 풀 판정은 변경하지 않아 기준표/METHODS/COMPASS의 과학 판정 갱신은 없다. |
| 기술부채·재개 | 있음 | 옛 캐시의 본문/토큰 자체를 다시 검사하려면 재생성이 필요하다. 중단 cache14는 삭제 후 재실행하지 않고 원래 코드 계약대로 새15이상 namespace가 필요하다. |
| GPU·학습 권한 | 없음 | GPU·모델·학습·설치 실행0이다. |
| 데이터/동시 소유권 | 있음 | 명시 대상만 제거하고 나머지 BASE 파일의 metadata 지문을 전후 대조한다. 타 세션 경로·원본 로그·TinyDataset에는 접근하지 않는다. |
| 비교·증거 수준 | 제한 | 삭제 완료와 파일 사용량만 주장한다. 정제·캐시 검증·모델 품질 완료를 뜻하지 않는다. |

사용자가 확정한 방식은 명시 파일의 직접 삭제다. 동일 파일을 먼저 같은 디스크로 이동하는 방식은 최종 삭제 전 공간을 돌려주지 않고, 외부 보관 후 삭제하는 방식은 별도 경로와 복사 공간이 필요하다. 이번에는 이미 승인된 명시 삭제를 수행하고 원문 대신 감사 metadata를 보존한다.
