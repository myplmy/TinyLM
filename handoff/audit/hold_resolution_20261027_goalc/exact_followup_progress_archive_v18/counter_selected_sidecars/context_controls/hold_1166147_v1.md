# 1166147 원형 보류·독립검토 근거

TASK에 지정된 original/candidate/full_diff를 4 packet 모두 END까지 읽었다. 원형과 선택본문은 byte-identical이고 full_diff도 차이 없음을 나타냈다. 독립적으로 확인한 본문 손상 때문에 동일 candidate를 그대로 ACCEPT하지 않았다.

아래 코드는 원형의 한 줄 안에서 `//` 주석과 실행 코드가 separator 없이 이어진 상태이므로, 그 코드를 살려 실행 예제로 보이게 하려고 개행이나 세미콜론을 새로 만들지 않았다. 인접 문장의 일부만 떼어 예제의 결론인 것처럼 일반화하지 않도록 직접 의존 도입/설명도 함께 분리했다.

```text
// name our organization after our project (both are SettingKey[String]) organization := name.value
```

```text
Or, set the name to the name of the project's directory:
// name is a Key[String], baseDirectory is a Key[File] // name the project after the directory it's inside name := baseDirectory.value.getName
This transforms the value of baseDirectory using the standard getName method of java.io.File.
```

두 번째 코드 예시의 `Or, set the name...:` 도입문은 바로 뒤 코드가 없어지는 직접 포인터이므로 함께 분리했다. 앞의 `As a first example...` 문장은 조직 이름과 프로젝트 이름의 관계를 자연어로 완결해 보존했다. `This transforms...` 문장도 결손 코드에 직접 의존해 분리했다.

```text
Take these two keys (from Keys):
val scalacOptions = taskKey[Seq[String]]("Options for the Scala compiler.") val checksums = settingKey[Seq[String]]("The list of checksums to generate and to verify for dependencies.")
// The scalacOptions task may be defined in terms of the checksums setting scalacOptions := checksums.value
```

```text
// The checksums setting may not be defined in terms of the scalacOptions task checksums := scalacOptions.value
```

한 줄에 붙은 두 `val` 선언은 새 경계를 만들지 않고 그 한 줄로 보류했다. `//`로 시작해 같은 물리 줄에 붙은 `scalacOptions := ...` 및 `checksums := ...`도 코드로 되살리지 않았다. 반면 `:=`, `+=`, `++=`의 실제 정의·조건·완결 예시, 나머지 명명 키와 설정/태스크 관계를 설명하는 독립 산문은 원문대로 유지했다.
