# expanded_train:96 원형 및 보류 범위

- reader 입력: TASK136에 지정된 `expanded_train:96` original/candidate 전체, 2개 packet 및 전체 diff를 확인했다.
- c4 직접 의존 블록 원형:
  - `c4(n) - n을 음수가 아닌 정수로 표현하는 방법의 가지수. 덧셈의 순서도 구분한다. 예를 들어 다음과 같다.`
  - `1 = 12+02+02+02 = 02+12+02+02 = 02+02+12+02 = 02+02+02+12,`
  - `그러므로 c4(1)=4.`
- 이 정의·순서 문장·예시는 한 단위로 원형 보류한다. 함수 관계와 성분/항 수가 닫히지 않았고 예시 표기의 빠진 지수나 관계를 추정하지 않는다.
- 별도 원형 예시 `a0(20) = a0(22 · 5) = 2 + 2+ 5 = 9.`도 수식 표기 결손을 추정 복원하지 않고 분리한다.
- 실제 수론적 함수 일반 설명 및 P(n), π(n), a0(n), a1(n)의 채워진 정의·조건·예시는 candidate 본문에 유지됐다. 새 수학 명제나 값은 추가하지 않았다.
- 앞선 `expanded_train_96_reviewed_task136_v1.txt`는 c4 블록을 복구한 비선택 작업본으로 남긴다. `expanded_train_96_reviewed_task136_v2.txt`는 exact candidate 바이트 사본이지만 최종 출력으로 연결하지 않는다. 최종 판정은 지정 exact candidate 경로를 가리킨다.
