# 잔여 출생연도 충돌 유형의 전량 원문 판독 범위

새 검증 캐시의 미처리73,668고유/115,526위치 중 출생연도 충돌 사유는2,743고유다. 이 수는 전체 연결계획v4의 미결 사유 계수이며 개별 정제나 사실 정정 증거가 아니다. 이미ROOT10에서 처리한753개 출생 필드 판독과 다른 선택은 다시 배정하지 않는다. 지금 판독 중인732와 겹치는 원문은 그 역할의 소유권을 유지하고 새 대기열에서 제외해 수량을 따로 남긴다.

| 안 | 처리 | 근거와 한계 |
|---|---|---|
| A | 모든 충돌의 실제 출생연도를 웹으로 하나씩 결정 | 명확한 1차 근거가 있으면 복원할 수 있으나 대량 외부 취득·추정 사실 정정으로 범위가 바뀔 수 있음 |
| B | 한쪽 연도/분류를 일괄 우선하거나 전부 복구불가로 종결 | 빠르지만 연도 선택·불확실성 삭제와 미처리의 HOLD 개명이 발생할 수 있음 |
| C | 같은 미결 유형 전량의 실제 원문/동결 후보를 마련해 월일·별도 날짜·생애·직함·조건·불확실성을 문맥 판독 | 실제 남길 수 있는 독립 본문과 충돌 구간을 구분하며, 애매한 귀속은 총괄 중재/근거 있는 최종 HOLD로 남김 |

선택C다. 이는 추가 GPU/모델 실험이나 학습 승인이 아니다. 총괄은 원문 연결과 CPU 재생성·코드·판정·좁은 중재를 담당하고 실제 새 TXT는 최대 다섯 기존 Luna가 쓴다. 현재732를 끝낸 역할부터 자기 새 START/TASK 전체를 이어받으며 임의 건수로 종료하지 않는다.

동결66개 생산 코드·토크나이저·EOS·원문 ID/SHA·구간을 확인하고 새 명명 경로에만 파생 자료를 만든다. 보호7개 ID와 동일SHA, 타 세션 전용자료, 보호TinyDataset은 배정/본문 디코딩에서 제외한다. 원형/기존 캐시/원로그를 덮거나 삭제하지 않는다. CPU 구조/의미 판독과 모델 품질을 구별하며 새 대기열 생성은 처리·채택이 아니다.

연도 충돌을 월일이나 나이에서 역산하거나 한쪽 값을 사실로 선택하지 않는다. 실제 다른 사람의 날짜·인용·재임/재위 기간·사망일·음양력·추정/논쟁·부정·조건을 유지한다. 충돌 필드와 직접 의존 구간을 분리해도 나머지 본문이 독립적으로 이해되는지를 본다. 독립성이 없으면 정확 원형 구간과 이유를 남겨 총괄에 질문한다. 이전 단순 문법 증명이 맞지 않는다고 곧바로 전체 문서를 제외하지 않는다.

영향 축은 .agents/project.json을 따른다. 사용자 실행 GPU/모델 경계는 불변, 기존 데이터/동시 소유권은 보호, 원천/토크나이저 비교는 고정, 문법·정적 검증과 사실/품질은 분리한다. 새 근거·실패·소유 범위는 WIP에 연결하고 계획·결과·기준표·METHODS·COMPASS의 최종 연쇄는 전체 정제 근거를 기준으로 갱신한다. 중간 계수·검증을 전체 완료/일시중지로 바꾸지 않는다.
