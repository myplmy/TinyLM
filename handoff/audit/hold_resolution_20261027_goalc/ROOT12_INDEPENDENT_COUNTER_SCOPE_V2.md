# 완료 후보의 독립 판독을 채택 흐름으로 연결하는 범위

2026-11-04. 총괄의 실제 독립 판독에서 자동 guard 전부 통과와 byte-identical 본문에도 주체·조건 소실, 미존재 그림, 불완전 코드, 상품 홍보가 남은 것을 확인했다. 선결 후보 3,692건을 승인으로 승격하지 않는다. 네 건은 최초 작성 역할의 후속 보완에 두고 나머지 3,688건을 자기 작성 건과 겹치지 않는 두 기존 Luna 역할의 교차 판독에 연결한다. 새 고유 원문 판독 수에 더하지 않는다.

| 안 | 장점 | 비용·한계 |
|---|---|---|
| 총괄이 모든 후속을 직렬 판독 | 판단이 한 곳에 모임 | 총괄 통합 작업이 계속 밀림 |
| 기존 두 역할이 교차 판독, 세 역할은 신규 판독, 총괄은 중재·선택·캐시 통합 | 신규와 채택 선결이 함께 전진 | 신규 1차 판독 담당이 일시적으로 세 역할로 줄어듦 |
| 다섯 역할 신규 판독 뒤 후속을 한꺼번에 수행 | 당장 신규 행 수는 빨리 증가 | 닫히지 않은 후보와 수정 미결이 계속 쌓임 |

두 번째 안으로 진행한다. 후보가 모두 승인되거나 정제 완료라는 뜻은 아니다. 한 TASK는 5건의 재개 단위이며 작업량 한도가 아니다. 기존 source/candidate를 덮지 않고 정확 원문과 이전 선택본문을 새 판독 입력으로 연결한다.

| 경로 | 허용 동작 | 권한 근거·제외 |
|---|---|---|
| data_cache/root12_independent_admission_counter_v1 | 원문 판독용 packet/manifest 신설 | goal의 CPU·독립 의미 검토 허용. 학습본문 생성은 보조 역할 소유 |
| agents/context_controls 또는 context_latin의 같은 새 cohort | 지정 원문/선택본문 읽기와 자기 TXT/MD 작성 | 정확 START/TASK만. 다른 역할 파일 수정 불가 |
| 이 감사 폴더와 tmp의 정확 reader | 기존 scoped reader를 고정 재사용 | 코드/시험/JSON/Git/모델은 총괄 소유; 역할은 제공된 읽기 명령만 호출 |

소유 경계를 바꾸기 전에 각 START/TASK와 manifest를 저장하고, 역할 이동은 현재 승인 과제를 마친 시점에 알린다. V3 guard가 source ID와 원형/이전선택 SHA를 먼저 차단한다. 보호 원형·후보·초기사본·패킷을 다시 열지 않는다. 전체 input 관계와 같은 작성자 재판독 0을 검산한다.

코드 영향은 새 입력·과제·두 reader wrapper뿐이며 고정 save 함수와 scoped_packet_reader_v1을 재사용한다. 데이터는 새 파생 packet/metadata이며 원형이나 cache3은 불변이다. 2,000자 packet 순서와 전체 원문/본문/diff를 재구성 검증한다. byte-identical인 경우 실제 원문은 전부 읽고 본문은 정확 byte 동일성 근거로 중복 출력만 생략한다. 변경 있는 본문은 전문과 모든 diff를 읽는다. 변경 후보의 판독 생략 규칙을 새로 적용하지 않는다.

드래프트 운영을 구별한다. 이 새 범위에서 아직 review로 선택하지 않은 자기 counter_working_v1.txt 한 건은 좁은 패치로 편집할 수 있다. 최초 사본은 정확 TASK candidate에서 cp --no-clobber로만 만든다. 원문·초기 후보·이미 선택된 본문·review·역사 기록 덮기는 계속 금지한다. 최종 전체 diff/EOF를 확인하고 리뷰에 선택한 뒤에는 그 파일도 고정하며 후속은 새 버전이다. 이 구분으로 몇 조각을 찾을 때마다 큰 새 사본을 반복 생성하지 않는다.

실제 실행 증거는 CPU 준비·packet 대조·후속 리뷰로 한정한다. 자동검사나 교차 리뷰를 모델 품질·학습 승인으로 해석하지 않는다. 아직 ROOT12·전체 원장·cache4와 consumer는 미완료다. 중간 상태는 WIP에 연결하고 최종 정본 연쇄는 전체 goal의 별도 미완 항목이다.
