# 159921 원형 보류

original/candidate는 지정 동일성 계획에서 바이트 동일성이 연결되었다. 아래 문구는 붙은/불완전 코드, 그 코드 예제에 직접 연결된 소개·결과 포인터다. 이름·경로·인수·메서드 및 완결된 설명/조건은 본문에 보존했고 누락된 코드 줄은 만들지 않았다.

## 쓰기 예제: 손상된 핸들러와 직접 포인터

> |// Don’t forget to import System.IO namespaceprivate void Button1_Click(object sender, System.EventArgs e)

> As you can see the code is really simple. Lets examine the code and see what’s going on.

첫 줄은 위키 파이프/주석/namespace와 메서드 선언 경계가 붙어 있으며 메서드 본문도 완결되지 않았다. `As you can see...`는 이 손상된 listing을 직접 지시한다. 다음 실제 완결 코드 줄은 본문에 그대로 남겼다.

## 읽기 예제: 손상된 핸들러/while 조건과 직접 포인터

> Lets look at the reading code below:
> |private void Button1_Click(object sender, System.EventArgs e)
> while(sr.Peek() > -1)
> Lets see what the code does:

핸들러 줄은 pipe와 선언 경계가 붙어 있으며, while 조건 뒤에는 반복 본문이 없다. 코드를 직접 가리키는 소개/결과 분석 예고도 함께 분리했다. `File.OpenRead(Server.MapPath(“test.txt”))` 호출과 완결된 `StreamReader sr = new StreamReader(fs);` 선언은 본문에 보존했다. 이어지는 `sr.Peek()`가 EOF에서 -1을 반환한다는 설명과 close/파일/스트림 역할은 실제 이름과 조건이 채워져 있어 본문에 남겼다.
