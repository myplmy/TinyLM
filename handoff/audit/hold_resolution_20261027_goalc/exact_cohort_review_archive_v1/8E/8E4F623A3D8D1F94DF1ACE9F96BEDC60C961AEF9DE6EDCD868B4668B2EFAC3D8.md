# 637681: 실제 정의에 대응하는 식별자 복원

총괄이 지정 원문을 전문 읽고 [Oracle의 같은 API 매뉴얼](https://docs.oracle.com/cd/E36784_01/html/E36886/ddi-umem-lock-9f.html)과 대조했다. 원문 SHA-256은 8984DCBEA1C17DF8B719DAC985595E00B787A425DBCB23E1FEC848E93E515AEB다.

원문에 이미 있는 정의 앞의 식별자만 복원할 근거가 있다. 원래 줄번호 기준3의 가상주소 정의는 addr,4의 바이트 길이는 len,5의 읽기 용도는 DDI_UMEMLOCK_READ,6의 쓰기 용도는 DDI_UMEMLOCK_WRITE,7의 커널 cookie 포인터는 cookiep다. 두 DDI 정의는 flags의 값이다. 이 식별자들은 원문 선언/뒤 설명에도 실제 존재한다.

반환 설명 뒤 다섯 원래 오류 정의는 순서 추측만이 아니라 발행처의 각 정의를 직접 대조했다. 매핑 없음은 EFAULT,권한 부족은 EACCES,메모리 자원 부족은 ENOMEM,나중 재시도 가능 자원 할당 실패는 EAGAIN,페이지 정렬 불일치는 EINVAL에 각각 대응한다. 이 다섯 label만 기존 정의 앞에 붙일 수 있다.

확인 페이지는2014판이다. ENOMEM에는 원문에 없는 추가 limit 설명이 있으므로 그 새 절은 넣지 않는다. 원문에 없는 unlock 선언·fork/exec 문단·cookie 항목·기타 매뉴얼 내용도 추가하지 않는다. 원문의 addr+size 표기와 Notes의 함수명을 외부판과 다르다는 이유로 조용히 바꾸지 않는다. 다른 버전의 내용으로 문서 전체를 최신화한 증거가 아니다.

원문 첫 줄의 실제 두 #include와 int 선언은 이미 존재하는 토큰 경계에 개행만 둘 수 있다. 빠진 선언/명령은 만들지 않는다. 기존 실제 설명과 주체·조건·0 반환값을 보존하고 새 전체 TXT/sidecar 및 실제 해당 TASK의 다섯 행을 유지한 새 리뷰로 연결한다. 코드 실행/자체 해시/웹 접근 권한은 없다.
