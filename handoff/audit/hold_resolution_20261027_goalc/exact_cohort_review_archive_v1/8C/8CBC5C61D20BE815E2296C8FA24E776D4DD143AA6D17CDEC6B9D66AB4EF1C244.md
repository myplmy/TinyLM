# expanded_train:865970 원형 보류

원문은 regular query 결과 도입 뒤 실제 `or Column List`와 `or Single List of Values` 두 항목만 남기며, 그 앞 결과 항목은 없다. 두 표제와 본래 `or`를 본문에 그대로 두었고 빠진 유형을 추측하거나 이 둘만이 완전한 전체 목록이라고 선언하지 않았다.

`Here’s a quick summary ... applicable:`는 이어질 summary가 실제로 없는 빈 요약 예고라 해당 문장만 분리했다. Scalar/Result A 설명, 완결된 SELECT/FROM/WHERE/HAVING/ORDER 예제, Chinook database 이름은 유지했다.

보류 원형:
- `Here’s a quick summary of where you can place these subqueries. You might find some weird corner cases, but for the most part, this is where subqueries are applicable:`
- 결과 유형 앞의 누락 선행 항목은 원문에 문구가 없어 생성하지 않음. 실제 두 항목은 위처럼 본문에 원형 보존.
