## Narrow automatic checks and counterexamples

- A field-aware checker can confirm that populated titles, names, bibliography values, article text, and code signatures survive the recorded edits, while allowing removal only of explicitly empty alias/field slots or isolated unmatched delimiters.
- Punctuation checks must be token/context aware: the `):` after an alias in 515925 separates the alias from its description and must remain; `←` in an element/symbol name (review 004) is meaningful; a colon can introduce a real list, but 844721 ends at EOF with the condition and example already present. A global rule to delete colons, brackets, parentheses, or punctuation-only lines would be unsafe.
- For code and technical prose, compare token streams around signatures, units, operators, ranges, and examples. Balanced delimiters or matching words alone cannot establish semantic preservation.
