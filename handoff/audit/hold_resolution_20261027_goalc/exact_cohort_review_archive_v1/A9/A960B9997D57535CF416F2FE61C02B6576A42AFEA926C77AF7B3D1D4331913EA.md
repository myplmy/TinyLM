# expanded_train:644837 — 원형 보류

## 판독 범위
지정 original/candidate 21행과 3개 연속 패킷의 original/candidate/full_diff END까지 읽었다. original과 candidate는 줄 차이가 없다. Cypher/APOC 이름과 완결된 접근 설명·제약을 보존하고, 없는 query에 직접 기대는 결과/참조만 분리했다.

## 없는 query에 직접 의존하는 조각

> A common first (and wrong) approach is something like this:
> The above query returns movies featuring at least one of the given actors, not movies with all the given actors.

query 본문이 없으므로 그 query가 어떤 배우/관계를 매칭했는지 특정하지 않고, 이에 대한 결과 주장을 함께 보류했다. “We need alternate approaches...”와 이후의 완결된 접근 설명은 유지했다.

> We can make some changes to the above query to get the relevant set of :Movie nodes.

직접 참조하는 “above query”가 없다. 뒤에 명시된 distinct count 조건·중복 관계 처리·입력 고유성 제약은 완결 설명으로 본문에 남겼다.

## 유지한 의미
`WHERE ALL()`과 `reduce()` 및 APOC intersection 함수명은 실제로 적혀 있어 보존했다. Neo4j 3.0.x 이상 조건, Movie/actor 조건, 복수 관계 시의 distinct 처리, 입력 목록의 distinct 전제와 성능 비교, query complexity 조건을 원문 그대로 유지했다. 누락된 query 코드나 APOC 함수명을 추정해 추가하지 않았다.
