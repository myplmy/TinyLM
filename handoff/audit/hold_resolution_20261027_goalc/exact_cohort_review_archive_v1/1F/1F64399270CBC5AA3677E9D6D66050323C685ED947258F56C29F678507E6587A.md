# 1241782 원형 보류 기록

## 판독 범위

지정 original/candidate 전문, 0001–0008 연속 패킷 및 전체 diff를 논리 END/EOF까지 대조했다. candidate는 original과 동일하다. 출력 본문은 revise_1241782_v1.txt이며, 코드 예제를 실행하거나 오류 설명을 외부 지식으로 보충하지 않았다.

## 본문에서 분리한 미완 구간

- `That line provides you with the following information:`은 설명이 뒤따르지 않는 예고다. 바로 앞 파일/행/함수 형식은 보존했다.
- `This line provides you with two pieces of information:` 및 `TypeError). These are usually descriptive enough ...`는 오류형식이 가리키는 두 정보와 그 설명의 연결이 깨져 있어 함께 보류했다. 실제 `<error type>: <error message>` 형식과 앞 traceback의 TypeError 정보는 본문에 남겼다.
- `I personally find that information unnecessary, so I usually leave`는 끝이 없는 문장이다. 바로 앞의 verbose 설명은 보존했다.
- `much like the` 뒤에 이름이 빠진 Project 1 함수 참조는 보류하고, 자기 함수를 작성할 수 있다는 독립 문장만 남겼다.
- `One common practice is to add` 및 `foo keeps returning the`는 실제로 무엇을 더하는지/무엇을 반환하는지 빠진 예고다. 바로 뒤의 채워진 foo 코드와 print 예제는 그대로 유지했다.
- `If it turns out ... we would go / some_function ... Otherwise, we might have to add a print statement before the return to check`는 방문 대상과 끝의 확인 대상이 빠진 연결 문장이다. 뒤의 두 완결된 코드 예제는 그대로 남겼다.
- `whileloop to view the state ...`는 실행 가능한 반복문 코드를 예고하지만 그 문장이 온전하지 않아 예고 문장만 보류했다. 반복문 코드는 그대로 보존했다.
- `One way to avoid this is to use a global`은 global 무엇인지 빠진 꼬리다. debug 코드와 True/False 제어 설명은 보존했다.
- `False (such a variable is called`는 분류명이 빠진 문장 꼬리다. 앞의 global debug True/False 설명은 보존했다.
- `seq[x], make sure the variable is assigned to a proper index.`는 도입부와 관계가 빠져 있어 그대로 보류했다. 그 앞의 IndexError 예시는 보존했다.
- `whileloop or recursive function might stop ...`는 실제로 채워진 반복/재귀 범위 설명이지만 추출된 문장 시작이 결손된 형태다. 본문에서는 문법 경계만 복구해 `A while loop or recursive function ...`로 보존했다. 새 알고리즘이나 수치는 넣지 않았다.

## 유지한 원문 결손/표기

- `SyntaxErrors`는 바로 뒤의 `before executing any code`와 결합해 공백만 복구했다. `raiased`, `helo`, traceback, 예제 함수, 에러 문구와 값은 원문 그대로 두었다.
- `==: the single equal sign`, `=is used for assignment; the double equal sign`, `==is used for testing equivalence. The most common error of this form is something like:`, `if x = 3:`는 수식 기호와 설명의 결합이 손상되어 있다. 비교 연산 기호의 의미를 추론해 고치지 않고 해당 단락 전체를 보류했다.
- `SyntaxError. Consider the following code:`는 앞에서 설명한 에러 예시와 같은 항목으로 읽히며, 그 뒤 실제 코드가 있다. 코드는 원문 그대로 유지했다.

보류 구간은 이 문서의 원문에 있던 그대로 기록했다. 빠진 설명, 함수명, 예제 결과, 변수 또는 연산자 의미는 만들지 않았다.
