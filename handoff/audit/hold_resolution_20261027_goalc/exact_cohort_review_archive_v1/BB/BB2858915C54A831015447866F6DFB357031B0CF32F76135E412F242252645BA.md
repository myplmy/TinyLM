# 1116298 원형 보류 v2 — 직접 미상 대상 의존부

v1은 보존한다. v1에서 `구체 exploit 작업`이라는 주제 이유로 함께 보류한 완결된 설명을 과삭제로 판단해 v2 본문에 복구했다. 이 sidecar는 발췌에 실제 없는 스크립트·gist·실행 대상·표적 바이너리/입력 변수에 직접 의존하는 조각과 끊긴 절만 구분해 보존한다. exploit 코드를 생성·실행하거나 원문에 없는 값을 채우지 않았다.

## 원형 보류 구간

- `According to man access(), there’s a race condition with this usage of the function:`부터 뒤의 반복 스크립트/리스너/VM 안내, `Description (full): Execute getflag with the given source code.`, 실제 첨부되지 않은 gist 지시: 필요한 코드·실행 대상이 지정 본문에 없다.
- `- The solution path must end with the`와 `- There are two ways to reach process()via the if-else branch in`: 두 불완전 bullet의 목적어/두 번째 경로가 소실됐다. 인접한 별도 완결 `else branch` 관찰과 mmap/getrand/XOR 설명은 본문에 보존했다.
- ASCII 결과 문자가 비어 있는 설명, `- Add an executable named`/`bto the path` 구간: 실제 이름·목표 입력이 빠진 구체 실행 지시다.
- `This turns out to be the case. We execute arbitrary code via this line, where our input is the variable`: 가리키는 원 코드 행과 변수명이 없다.
- `- The preprocessor macro for` 및 `FAKEUID: can we redefine`: 문장이 끊겨 직접 질문의 대상/목적어 연결이 완결되지 않는다. 완결된 getuid 질문 및 다음 고수준 설명은 본문에 남겼다.
- `Unfortunately, it turns out ... debug flags from`: 뒤 대상이 누락된 절.
- `We can take a look at the assembly using`, `Our magic number is represented by`, `3d e8 ... Our goal is to change`, `0x3f6, which is 1014 in binary`, 그리고 `We change 3df6 in the binary`: 명령/대상/변경 연결이 끊긴 바이너리 수정 설명이다. 이들에 나온 숫자를 별도 관계나 새 목표로 재구성하지 않았다.

## 복구/보존 경계

v2 본문은 완결된 `fread(buf, length, 1, stdin)` 제시와 세 번째 인수·반환값 설명, `length must be 1`, `process()`/XOR 문장과 `key = 1 & 0xff` 서술을 남겼다. 또한 명명된 `getuid()` 및 `LD_PRELOAD`에 관한 저자의 설명, suid 조건, 실제 인용 출처와 독립적인 Lua/SHA1·flag14 서술을 원문 범위에서 보존했다. 이 선택은 누락된 구체 스크립트·입력·바이너리 단계를 복원하거나 실행했다는 뜻이 아니다.
