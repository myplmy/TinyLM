## 판독 범위

지정 TASK_011의 original/candidate가 동일한 입력임을 연속 패킷 0001–0004와 0007에서 확인했고 full diff의 종료도 확인했다. 원문은 빈 별칭 포장 외에도 수식·표 결과가 빠진 직접 의존 문장을 포함한다. 아래 조각은 원형과 위치를 보존하며, 새 숫자·기호·지수·계수식을 보충하지 않았다.

### 증가 차수의 빈 상한식과 평탄화 표기

```text
만약 입력 크기가 n이고 함수 f(n)와 양의 상수의 곱으로 알고리즘 실행 시간의 상한선(upper bound)을 제공한다면, 수학 함수의 차수로 알고리즘의 성장 비율을 보일 수 있다.
다시 말해서, 주어진 입력 크기 n이 0와 상수 c보다 클 경우, 알고리즘의 실행시간은 보다 결코 크지 않다.
예를 들어 퀵 정렬의 최악의 경우 시나리오는 O(n2)이지만 평균 경우 실행 시간은 이다.
```

빈 상한식·상수 결합과 `O(n2)` 표기를 정정하거나 지수 표기로 해석하지 않고 그 직접 정의/결론을 보류했다. 퀵 정렬의 빠진 평균 경우 값과 함께 해당 문장을 보류했다. 원문에 실제 적힌 삽입 정렬의 이차식 증가 설명은 본문에 유지했다.

### 평탄화된 차수/크기 값

```text
이는 O(2n) 차수이다.
32-bit 장치는 232 = 4 GiB 그리고 64-bit 장치는 264 = 16 EiB.
(log*)는 모든 실제 데이터 (265536 bits)에서 5보다 작다; (log log n)은 거의 모든 실제 데이터 (264 bits)에서 6보다 작다; 그리고 (log n)은 거의 모든 실제 데이터 (264 bits)에서 64보다 작다.
```

기존 입력에 실제 적힌 표기와 값을 초거듭제곱/밑 표기로 새로 해석하지 않았다. `O(2n)` 차수 주장, 장치 용량 수치, 로그 상한과 직접 연결된 조건/단위를 sidecar에 보존했다. 파일 크기 증가 시 메모리 사용이 지수적으로 늘어난다는 자연어 설명, 100,000 kilobytes마다 예약 메모리를 두 배로 한다는 의사코드, 제한된 크기·상수 인자에 관한 독립 조건은 본문에 남겼다.
