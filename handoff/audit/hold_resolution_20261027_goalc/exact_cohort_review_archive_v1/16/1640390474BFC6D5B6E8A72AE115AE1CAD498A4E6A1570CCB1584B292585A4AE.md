# validation:2305 원형 보류 — 평탄화된 목록과 미상 key 연결

새 본문은 `/home/uranus/tinyLM/data_cache/p106b_hold_resolution_v1_20261027_goalc/remaining_literal_full_counter_v1/inputs/validation_2305_original.txt`에서 직접 정제했다. 아래 조각은 실제 원문과 같은 텍스트이며, 값/기능을 임의 key나 파일에 연결하지 않도록 본문에서 분리했다. 문서 전체나 `/proc` 일반 설명을 보류한 것은 아니다.

## 행·열 대응을 읽을 수 없는 flattened 출력

- 원문 3행의 `/proc` 최상위 `ls` 목록은 다수 권한·소유자·크기·시각·파일명이 한 줄로 이어져 개별 행 대응을 잃었다.
- 원문 7행의 `/proc/460` 파일 목록은 서로 다른 파일과 symlink를 나타내는 행 경계를 잃었다.
- 원문 281행의 `/proc/tty/drivers` 출력은 장치 행이 한 줄로 합쳐져 경계가 보이지 않는다.

## 사라진 파일/설정 이름을 직접 요구하는 최소 관계

- 원문 130행의 `shows the number of allocated disk quota entries...` 설명은 앞의 `dquot-max`와 별도 파일을 가리키지만 그 key가 보이지 않는다. 누락 key를 만들어 연결하지 않았다.
- 원문 146, 147, 149, 158, 160행은 각각 `The file`, `this file`, `this parameter`, `This is the number`를 설명 주체로 삼는데 그 파일/key 이름이 빠져 있다. 해당 문장만 보류했다.
- 원문 163–167행은 파일의 세 buffer-memory 값과 각 설명을 함께 요구하지만 parameter 이름/대응이 없다. 해당 다섯 행만 보류했다.
- 원문 173–175행은 이름 없는 세 값과 “this number” 결과 설명을 대응시킬 수 없어 분리했다. 176행의 명명된 `swap_cluster` 설명은 본문에 남겼다.
- 원문 178행은 `This file`이 가리키는 memory-mapping/generic-caching 설정 이름이 없다.
- 원문 206행은 `This file`을 주어로 하는 RARP/BOOTP/DHCP IP 구성 여부 설명인데 filename/key가 없다.
- 원문 231행의 `This switch`와 240행의 `If it is not set`은 둘 다 어떤 interface 설정을 가리키는지 누락됐다.
- 원문 244행의 “Writing to this file”은 routing-cache flush 대상 filename이 없다.

## 직접 연결만 제거한 문맥

- `Each of the numbered directories...`와 `/proc/460` 일반 설명은 유지했다. `The purpose and contents of each of these files is explained below:`도 설명 목록의 존재를 소개하므로 남기되, 어떠한 파일명도 각 설명에 새로 붙이지 않았다.
- binfmt_misc 일반 역할·register/status 설명은 유지했다. 원문 142행 끝의 “An example ... follows” 예고, 143행의 합쳐진 command sequence, 144행 첫 문장 “These four lines add support...”만 그 없는 예제에 직접 의존해 분리했다. 144행의 독립 JDK·스크립트 경로·파일명 설명은 유지했다.
- `printk`의 네 명시 필드명·순서와 바로 뒤 설명은 원문 순서대로 보존했다. `min/low/high`, `Ndirty`, inode-state, `message_cost`/`message_burst`, `tcp_retries1`, `CONFIG_SYNCOOKIES`, IPX 및 그 밖의 실제 이름·조건이 자립하는 설명은 보존했다.

원문 값·조건·일반 설명을 새 filename/key와 결합하지 않았고 command를 실행하거나 결과를 만들지 않았다.
