# 81945 원형 보류 및 후보 정정

| 원문 위치 | 원형 | 처리/이유 |
|---|---|---|
| 5행 | `그러므로 다음과 같은 결과가 된다.` | 직접 예고하는 정렬 결과가 뒤따르지 않아 이 지시 문장만 분리했다. 앞의 삽입 동작 설명은 보존했다. |
| 65–78행 | `C++` 및 `#include <iterator>`부터 닫는 `}`까지의 `insertion_sort` 함수 | 함수 괄호는 닫히지만 `key`, `ins`, `pre` 선언 뒤 요소를 이동·삽입하는 본문이 없다. 원저자의 미완/오류일 수도, 추출 손상일 수도 있어 판단하지 않고 C++ 예제 단위로 원형 보류했다. 함수 구현이나 새 `skeleton` 표제를 만들지 않았다. |
| 101행 | `개의 데이터가 있을 때, 최악의 경우는 번의 비교를 하게 되므로, 시간복잡도는` | 데이터 수·비교 횟수와 결론 값이 빠진 채 문장이 끝나 직접 결손 절 전체를 분리했다. |
| 103행 | `각주` | 내용이 없는 각주 표제만 분리했다. 다음 네 개 분류 라벨은 원래 순서대로 보존했다. |

후보가 원문 48행의 `memcpy()는`을 `memcpy는`으로 바꾼 것은 원문 괄호를 복구했다. 나머지 Java/C/OCaml/Python 코드와 실제 수치·설명, `정렬 알고리즘`/`안정 정렬`/`비교 정렬`/`온라인 정렬` 분류는 보존했다.
