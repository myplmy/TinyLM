# 1438328 원형 보류

original과 candidate는 지정 동일성 계획에서 바이트 동일성이 연결되었다. 아래는 미상 문장 주어, 줄바꿈/블록 경계가 손실된 Visual Basic 코드, 그 코드에 직접 의존하는 예고·결과 참조, 페이지 편집/이동 UI만 원형으로 남긴다. 실제 변수·조건·호출·예시를 재작성하지 않는다.

## 미완 주어 및 코드 예고

> The condition can be anything from
> If X = 1 Then MsgBox "X = 1" End If
> If InStr(1, sName, " ") > 0 Then sName = """" & sName & """" End If

위의 “anything from”은 아래 예시로 이어지는 문장 조각이다. 두 조건 예시는 블록 종료표식과 문장 경계가 한 줄에 붙어 있으므로 실행 가능한 VB 코드처럼 다시 줄 나누지 않는다. 완결된 단일 조건 예시 `If Y + 3 = 7 Then MsgBox "Y + 3 DOES = 7"`는 본문에 남겼다.

## 다중 조건 블록 및 직접 예고

> The concept of an If-Else-If structure is easier to understand with the aid of an example:
> Dim Temperature As Double ... If Temperature >= 40.0 Then Debug.Print "It's extremely hot" ElseIf 30.0 <= Temperature And Temperature<=39.0 Then Debug.Print "It's hot" ElseIf 20.0 <= Temperature And Temperature <= 29.0 Then Debug.Print "It's warm" ElseIf 10.0 <= Temperature And temperature <= 19.0 Then Debug.Print "It's cool" ElseIf 0.0 <= Temperature And Temperature <= 9.0 Then Debug.Print "It's cold" Else Debug.Print "It's freezing" End If

조건/결과가 채워진 분기 예지만 ElseIf 블록의 여러 줄 경계가 사라져 원형 보류한다. 뒤의 컴퓨터가 조건을 순서대로 살피고 첫 참 조건 후 나머지는 검사하지 않는다는 설명, 우선순위 정렬 및 최적화 주의는 독립 서술로 본문에 보존했다.

> The above example is such a case and could also be written like this:
> Select Case Temperature Case Is >= 40# Debug.Print "It's extremely hot" Case 30# To 39# Debug.Print "It's hot" Case 20# To 29# Debug.Print "It's warm" Case 10# To 19# Debug.Print "It's cool" Case 0# To 9# Debug.Print "It's cold" Case Else Debug.Print "It's freezing" End Select

위 Select Case 블록도 분기 경계가 한 줄에 붙어 있다. 독립적인 Select Case 사용 설명은 본문에 남겼다.

> use ElseIf as described in the example above.

앞의 손상된 분기 예를 직접 가리키는 참조라 그 조각만 분리했다. Visual Basic Classic의 short-circuit 조건 설명과 ElseIf라는 완결된 개념/관계는 본문에 남겼다.

## 빠진 명령 주체 및 종속 결과/코드

> End a function, subroutine or property and return to the calling procedure or function. Note that in Visual Basic returning from a function and assigning a return value requires two separate statements.
> This simple command ends the execution of the program
> Private Sub cmd1_Click() End End Sub
> In this example, when the button cmd1 is clicked, the program will terminate.

첫 문장은 명령 주체가 없다. 다음은 프로그램 종료 호출의 실제 줄 경계가 손상됐고 마지막 문장은 그 블록 실행 결과에 직접 붙어 있으므로 함께 보류했다. 뒤의 `The End command ...`로 시작하는 독립적인 End 동작/종료 방식 설명은 본문에 보존했다.

> Transfer control to the statement after the label (or line number).
> Goto Label Dont_Do_Something Label: ...

첫 문장은 주체가 없고 다음 label 예시는 토큰이 손상/압축되어 있어 복원하지 않는다. 뒤의 same-procedure 제약 설명은 `Goto`가 명시되어 있으므로 본문에 남겼다.

## 비교/반복 코드 예시와 직접 포인터

> When it comes down to readability the following two samples are almost the same:
> Sub Use_Exit Do_Something If Test Then Exit Sub End If Do_Something_Else End Sub Sub Use_Goto is Do_Something If Test Then Goto Exit_Use_Goto End If Do_Something_Else Exit_Use_Goto: End Sub

> Sub Use_If is Do_Something If Not Test Then Do_Something_Else End If End Sub

세 procedure 예시는 줄 경계/블록 구조가 손상되었다. `goto`와 여러 exit의 일반 서술, 구조적 방식에서 둘 다 필요하지 않다는 독립 명제는 본문에 남기고, 누락된 예시 결과로 취급하지 않는다.

> Sub Use_PseudoLoop Do 'Start the pseudo loop. Exists only so that you can use Exit Do Try_Something If Test Then Exit Do End If Try_Again If Test Then Exit Do End If Try_Try_Again Loop While False ' will never loop Do_One_Last_Thing End Sub
> Of course this example can be recast using If..Then..Else..End If without the need for any Exit statements at all so it is a little artificial:
> Sub Use_IfThen Try_Something If Not Test Then Try_Again If Not Test Then Try_Try_Again End If End If Do_One_Last_Thing End Sub

두 예제의 블록 경계와 직접 비교 설명은 원형 보류했다. pseudo loop의 목적에 대한 앞 문장은 그 자체로 완결되어 본문에 유지했다.
