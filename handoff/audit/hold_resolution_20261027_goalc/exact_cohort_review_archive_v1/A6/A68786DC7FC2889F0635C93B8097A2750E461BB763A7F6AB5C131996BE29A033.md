# 91906 원형 보류 구간과 경계

지정 original/candidate 전문과 packet 0001–0007을 전부 순서대로 읽었다. candidate의 두 `|Least significant bits|` 줄은 각각 완결 산문 뒤에 단독으로 있고 대응 도식/비트 표값은 없다. 두 발생만 분리한다.

1. `RADIX 50 was not normally used in 36-bit systems for encoding ordinary character strings; file names were normally encoded as six six-bit characters, and full ASCII strings as five seven-bit characters and one unused bit per 36-bit word.` 뒤의 원형 `|Least significant bits|`
2. `RADIX 50 was also commonly used in the symbol tables of the various PDP-11 programming languages.` 뒤의 원형 `|Least significant bits|`

다음 계산 예시에서 표시된 거듭제곱 서식·등식의 역할이 불명확하다. 아래 예시의 원형을 보존하며 402/401/400을 거듭제곱 표기로 고치거나 계산값을 검증하지 않는다.

`For example, using the PDP-11 encoding, the string "ABCDEF", with character values 1, 2, 3, 4, 5, and 6, would be encoded as a word containing the value 1×402 + 2×401 + 3×400 = 1683, followed by a second word containing the value 4×402 + 5×401 + 6×400 = 6606.`

RT-11 예시는 값 표기가 끊겨 그 값 및 같은 값을 받는 치환 설명을 특정할 수 없다. 그 직접 의존 구간은 원형 그대로 보존한다.

`For example, the RT-11 operating system considered the character corresponding to value
%) to be undefined, and some utility programs used that value to represent the
* character instead.`

본문에는 실제 ABCDEF와 문자값 1–6의 대응, 16-bit 값 범위 0–63999, 짧은 문자열의 공백 채움, RADIX 50의 사용·기호 테이블·이름 관례 설명, 다른 채워진 서지 정보를 유지한다. 위 hold는 없는 값/기호/서식을 만들지 않기 위한 것이며, 다른 파이프나 명명 인코딩 설명으로 넓히지 않는다.
