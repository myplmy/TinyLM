# 사용자103 격리 체크포인트 정리기 구현·검증

사용자 지시: 기존 정리기처럼 격리폴더용 체크포인트 정리기를 만들어 이후 주도적 학습 뒤
정리에 활용한다. 이 작업에서는 **도구 구현·CPU 임시 시험·실제 경로 조회**만 수행한다.
직전 사용자102의 exact 삭제·로컬커밋 승인을 현재 작업으로 연장하지 않는다.

## 착수 영향과 쓰기 범위

| 경로 | 동작·권한 | 제외 |
|---|---|---|
| `scripts/cleanup_isolated_ckpt.py` | 현재 정리기 구현 지시로 신설 | 모델·GPU·설치 없음 |
| `scripts/test_cleanup_isolated_ckpt.py` | CPU 임시 fixture 검증 | 실제 체크포인트 삭제 없음 |
| `run_cleanup_isolated_checkpoints.sh` | 유지보수 실행기 신설 | 큐 기본 호출은 후보 조회만 수행 |
| `experiments.tsv` | 기존 정리기와 동일한 `plan=-` 유지보수 행 한 개 추가 | 실험 번호·GPU 실행·자동 삭제 없음 |
| `docs/ISOLATED_CHECKPOINT_CLEANUP.md` | 사용법·보호·한계 기록 | 일반 정리기 판정 변경 없음 |
| 이 감사 및 이쪽 WIP103 | 절차·검증·재개 증거 갱신 | 타세션 WIP·코드·TSV 수정 없음 |

| 영향 축 | 확인 결과 |
|---|---|
| 코드·중복 | 기존 `cleanup_ckpt.py`는 일반 root/TSV만 처리한다. 새 도구는 별도 격리 경로의 완료 영수증을 소비한다. 기존 함수·호출부를 바꾸지 않는다. |
| 데이터 | 텐서·데이터셋을 열지 않는다. 미래의 삭제는 정확한 격리 합성 출력에 한정한다. 새 감사 JSON 계약만 신설한다. |
| 테스트 | 임시폴더에서 실제 unlink와 보류·경합·변경·부분 오류·SHA 고정을 검증하고 기존 일반 정리기 회귀도 확인한다. |
| 정본 문서 | 별도 유지보수 도구이다. 실험 조건·방법론·기준표·결과·COMPASS 판정을 바꾸지 않는다. 기존 공용 정리기도 등록된 실행 레지스트리에는 `plan=-` 행만 추가한다. CLI는 이미 등록된 플래그만 사용하므로 타세션 dirty `flag_whitelist.tsv`도 수정하지 않는다. |
| 기술부채·우선순위 | 명시된 격리 스모크 V1만 지원한다. 미지원·실패 기록은 추정해서 삭제하지 않는다. 사용자99의 연구 중단을 유지한다. |
| GPU/모델 권한 | CPU 시험과 읽기 전용 preview만 수행하며 모델·GPU·전체 스모크는 NOT_RUN이다. |
| 소유권 | 일반 모델·연구9개·원로그·판정·캐시·보호 데이터와 타세션 변경을 보존한다. |
| 비교 조건 | 학습·평가 실험을 하지 않아 풀·토크나이저·초기화 비교 변경이 없다. |
| 증거 수준 | 임시 CPU 동작과 실제 경로 읽기를 구분한다. 실제 대용량 삭제 검증이나 품질 개선으로 승격하지 않는다. |
| 문서 연쇄 | 사용법·WIP103·이 감사로 유지보수 범위를 기록한다. 실험계획·결과 레지스트리는 대상이 아니다. |

## 구현 선택

경로 접두사만 보고 지우거나 원본 스모크를 재실행하는 방식은 사용하지 않는다. 과거 성공
영수증·원로그·학습 JSON에서 출력을 도출하고, 확인한 목록의 identity·해시·참조가 유지될
때만 미래 실행이 가능하도록 했다. 실패·미완료는 보류하는 보수적 정책이다.

사용법은 [정리 안내](../../../docs/ISOLATED_CHECKPOINT_CLEANUP.md)가 소유한다.
`CPU_TEST_v1.log`의 CLI 임시 root/도구 소스 경로 혼동 3실패는 보존한다. 이를 분리한
`CPU_TEST_v2.log`는 27시험 통과이다. 이후 실행시각·파일 수정시각 대응과 추가 경합 시험을
더한 30시험은 `CPU_TEST_v3.log`에 보존한다. 이후 같은 이름을 쓰는 다른 격리폴더의 내부
참조와 실제 교차폴더 참조를 구분하는 시험을 추가했다. 첫 정적 검사 68PASS/2ERROR/6NOT_RUN의
2오류는 새 SH의 공용 실행 레지스트리 미등록이었다. 검사 기준은 바꾸지 않고 기존 정리기와
동일한 유지보수 행으로 연결해 `STATIC_AUDIT_v2.json`에서 70PASS/0ERROR/6NOT_RUN을 확인했다.
마지막으로 불명확한 부모 경로를 보수적으로 보호하는 시험을 추가해 `CPU_TEST_v6.log`의
34시험이 통과했다. 현재 코드의 실제 읽기 전용 조회는 `READ_ONLY_FINAL_v1.json`이 소유한다.
최종 재검증과 파일 해시는 후속 정적 감사 및 `VALIDATION_v1.json`에 기록한다. 시험 로그의
`실제 삭제` 문구는 TemporaryDirectory fixture의 unlink이며 저장소 모델 삭제가 아니다.

Git staging·commit은 이 지시의 범위가 아니므로 수행하지 않는다. 현재 타세션 변경은
`scripts/flag_whitelist.tsv`이며 그대로 보존한다. 이전102의 커밋은 별도 감사가 소유한다.
