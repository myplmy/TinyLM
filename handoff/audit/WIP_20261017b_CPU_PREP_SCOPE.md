# CPU 전용 후속 준비의 범위와 착수 영향도

현재 권한은 사용자 2026-10-17의 ‘오늘 23시59분까지 CPU만 활용하여 다음 주도적 실험 전 준비’다. 기존 질문·답 관계 대조 A 선택을 구현 준비의 근거로 사용한다. 실제 모델/가중치 로딩·학습·GPU·전체 스모크는 실행하지 않는다. 원래 dirty 파일과 이미 동결된 실행 코드는 보존한다. 이번 지시에는 staging/commit/삭제 권한이 없어 수행하지 않는다.

## 실질적 세 구현안 비교

| 안 | 구체 시나리오 | 장점 | 단점·비용 |
|---|---|---|---|
| 1 권장 | 기존 자연 QA·보존자료는 양팔 동일하게 유지하고, 코드가 사실 관계를 정의한 두 질문 묶음에서만 CE 대 CE+행별 대조 | 부정확한 자연문항 오답을 강요하지 않고 질문별 정답 선택을 직접 검증 | 통제 관계 자료를 추가하므로 자연 QA 전체에 곧바로 일반화할 수 없음. 새 손실·일정·평가 필요 |
| 2 | 기존 자연 TRAIN 두 질문의 교차답을 사람이 전량 판독해 대조 | 자연 질문에 직접 적용 | 서로 다른 문자열이어도 둘 다 맞을 수 있음. 대량 판독 없이 자동 승격 불가 |

## 착수 전 영향도

| 축 | 영향 | 구체 내용 |
|---|---|---|
| 코드 | 있음 | 기존 `natural_sums`는 동일 정답 두 표현용이고, `question_scores`는 no_grad 판독용이다. 다른 정답 두 개의 학습 손실은 별도 구현한다. 모델/생성 기본 경로는 바꾸지 않는다. |
| 데이터 | 있음 | 같은 사실 묶음·두 질문·검증 가능한 두 답·교차답의 부적합 근거를 저장한다. TRAIN/DEV/TEST는 사실 묶음 단위로 분리하고 질문 유형·정답 역할·순서를 균형화한다. |
| 테스트 | 있음 | 동일 정답 보호·무효 음성·shift/EOT/패딩·기울기·행/열 반례·전체 업데이트 분모·누락/중복·파일 크기·입력 대기 없는 진입을 CPU로 검사한다. |
| 정본 | 있음 | 실행한 새 모델은 없으므로 성능표는 갱신하지 않는다. 새로운 계약·단계·태그·문헌 차이와 사용자 실행 선결만 기록한다. |
| 기술부채 | 있음 | 로컬 연구 컨트롤러 하나가 늘어난다. 범용 trainer 변경이나 별도 추론 헤드는 피하며 실행 코드 동결 후 수정은 새 버전으로 구분한다. |
| GPU/권한 | 분리 | 실제 모델 로딩·CUDA 접근·학습·스모크는 0회로 유지한다. CPU 합성 텐서/토크나이저/자료 계약만 검증한다. |
| 소유권 | 분리 | 기존 dirty·보호 데이터·이전 산출물은 그대로 둔다. 새 파일은 무덮어쓰기이며 삭제·Git 변경을 하지 않는다. |
| 비교 유효성 | 있음 | 부모·토크나이저·자연 QA/보존 입력·정답 노출·배치·LR·순서는 동일하다. 두 팔 모두 같은 교차 후보를 계산하며 CE는 맞는 답에만 적용한다. 추가 후보 계산량과 정답 학습량은 별도 집계한다. |
| 증거 수준 | 분리 | 문헌·수식·합성 gradient·실제 토크나이저 검산은 실제 모델 효과·VRAM 안전·품질 통과가 아니다. |
| 문서 연쇄 | 있음 | 계획→CPU 결과→목록→기준표의 예약 태그→방법론→COMPASS의 다음 준비를 동기화한다. 기준표의 기존 실측/표준과 root09는 바꾸지 않는다. |

핵심 위험은 무효 오답쌍과 ‘질문을 구별한 점수’를 실제 자유 답 정답률로 오해하는 것이다. 같은 질문 안의 두 답 순위를 필수로 보고, 최종적으로 실제 첫 답·두 질문 모두 정답·어순/미학습 표현 전이·일반 능력 보존을 분리해 평가한다. 대조 강도는 이 실험에 한정한 탐색값이며 전역 기본값이나 정답 판정 정책이 아니다.

## 실제 변경·검증 중간 기록

- CPU81/실제 자료2048/128/128·재소비0을 확인했다. 실제 모델/학습가중치 로딩·GPU·새 체크포인트0이다. source code 지문에 결합된 새 파일은 동결 뒤 바꾸지 않는다.
- 첫 codex-safe는66PASS/2ERROR/6NOT_RUN이었다. 새 플래그 등급·신규 helper import bootstrap을 수리했고 기존 검사기를 면제하거나 변경하지 않았다. 실패 감사는 보존하며 마감 전 새 전체 검사를 수행한다.
- CPU shell1은 -done으로 개명하고 명령을 결과101§272에 실제 추출 보존했다. 삭제는0이며 기존 done1·hold/다른 연구는 그대로다. 새 GPU/후행6개는 작성·등록만 했다.
- 기존 UI dirty의 실제 코드/사용법/원답/감사와 기존 데이터 원장 둘은 변경하지 않는다. 방법론03/계획/결과·목록의 이전 UI 기록은 보존하고 새 절만 추가했다.
- 새 자료는 기존 ignored local의 연구 fixture이고 작은 계약·원로그·코드·문서만 추후 Git 검토 후보다. 이번에는 staging/commit/push를 하지 않는다.
- 새 문구의 언어 혼입은 저장 전 추가행 검사와 저장 뒤 diff 검사로 확인한다. 영구 언어 훅/문자열 품질 검사기를 설치하지 않는다.
- 마감 직전 정확한 기존 부모 파일/토크나이저의 SHA를 읽기 전용으로 확인해 준비된 기대값과 일치했다. 가중치 역직렬화·본체 재계산·실제 모델 실행은0이다. 파일 식별과 모델 검증을 혼동하지 않는다.
