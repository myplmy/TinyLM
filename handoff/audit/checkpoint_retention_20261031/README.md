## 4. 보존과 확인의 한계

현재 열린 체크포인트가 없다는 관측을 참조 부재의 증명으로 취급하지 않는다. 정확 파일명과 완결 stem 검색에 더해 가족 태그·동적 epoch 함수·runs/logs의 부모/교사·수동 메뉴를 확인했지만, 다른 세션이나 외부 경로까지 전역 참조가 없다고 보증하지 않는다. 보호 TinyDataset과 다른 세션의 전용 원문·캐시·원장은 조사하지 않았다. 다만 넓은 `scripts` 참조 검색에 공유 정제 코드82개가 포함됐으므로 코드까지 미조사였다는 초안 문구는 정정한다. 해당 코드의 실행·수정은0이며 검색 범위와 원인·후속 제한은 [범위 정정](REFERENCE_SCOPE_DISCLOSURE_v1.json)에 남겼다. 이후에는 생산자·소비자의 명시 목록과 제외 접두부를 먼저 고정한다.

논리 용량과 호스트의 실제 여유는 구분한다. 이번에는 파일을 삭제하지 않았고 Windows 호스트 여유나 VHDX 축소를 측정·실행하지 않았다. 이후 WSL 안의 파일을 지워도 같은 양이 곧바로 Windows 여유로 반환된다고 보장할 수 없다. 후보56.24GiB를 호스트 즉시 회수 실적으로 읽지 않는다.
