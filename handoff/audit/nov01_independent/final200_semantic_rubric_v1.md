# FINAL200 응답 판독 기준 — 모델 실행 전 고정

아직 두 모델의 v1/v2 첫 답을 실행/관측하지 않은 시점에 기록한다. 자료 v1은 조사 오류로
준비까지만 회수했고, 수정 v2의 FINAL/DEV·정답·조건은 별도 동결했다. 새 학습/교사 전달0이다.

- stable: 비어 있지 않고, 파손/역할 토큰/불필요 반복·질문 나열/종료 실패가 없어야 한다.
  이 프로토콜에서는 MAX_NEW가 자기 종료를 못한 것이므로 stable=false다. 정상 EOT/EOS
  자체는 나머지 두 축의 통과가 아니다. 요구된 세 번 반복은 반복 실패가 아니다.
- responsive: 요청한 행동·언어·형식에 대응하는 답이어야 한다. 틀린 정수만 답하면 숫자
  계산 요청에 대응은 했으나 correct=false일 수 있다. 맞는 값이 있어도 JSON-only 요청에
  설명/코드펜스를 덧붙이면 형식 대응은 false다. 단어 뒤 마침표 같은 통상 문장부호만으로
  대응을 탈락시키지 않는다. exact 문자열 검산과 이 의미 판독은 다를 수 있다.
- correct: 지문/규칙/일상 요청의 핵심을 빠뜨리거나 모순 없이 만족해야 한다. 정답 단어가
  긴 나열 속에 한 번 포함된 것을 정답으로 세지 않는다. 명확한 맞는 핵심에 불필요한 문체만
  붙은 경우 correct=true/response=false로 분리할 수 있다. 부분 지식·유창성만으로는 통과하지 않는다.
- usable: 위 세 축의 교집합이다. 열린 일상 답은 미리 적힌 rubric을 사용한 총괄 GPT의
  판독이며 외부 독립 인간 판정이나 정답 모델의 자동 보증이 아니다.
- 자동 reference_match/빈답/반복/role/MAX_NEW 신호는 판독 보조다. 각 실제 답을 읽어
  질문 복사·중복·무관 주제·내용 오류를 기록한다. 정답과 종료만으로 나머지 축을 일괄 통과시키지 않는다.
- 불확실 사례는 숨기지 않고 보류/근거를 남긴다. 사용자 검수가 필요하면 WSL의
  `review_request/`에 사람이 읽을 수 있는 질문/답 쌍과 요청을 별도로 작성한다.

모델/입력/상한/선정은 판독 결과로 변경하지 않는다. 이 문항/정답/오답은 후속 TRAIN·교사 교정·
증강에 사용하지 않는다. 문항군이 제한된 총괄 작성200평가이며 공식 KoBEST/Core6와 동등한
공개 benchmark나 일반지능 향상 증거로 이름을 바꾸지 않는다.
