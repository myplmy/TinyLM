### 1.3 ⚠️★★**좋은 교사는 KD 를 살렸다. 분해능 경계 바로 아래에서** (결과 053 단계1)

같은 641,795 토큰 스트림의 common_bpb:

```
  mC_initonly  1.3075     (V=32,768, 교사 없음)
  Q256T        1.3362     (Qwen 교사)          <- QT0 대비 -0.0078
  QT0          1.3440     (Qwen, 교사 없음)

★**`Q256T` − `QT0` = −0.0078 bpb** — **0.008 바로 아래**다.
🚫**규약대로면 서열을 매기지 않는다.** 우리 dense 교사(학생보다 나쁨)는 −0.0032 nats 였다.

*"교사가 나빠서"* 에서 ★**"교사를 고쳐도 우리 자를 못 넘는다"** 로 바뀐다.
🚫**Gemma 4조건은 착수하지 않는다**(§3 이 *"Qwen 결과를 보고 정한다"* 고 했다).

### 1.4 🚫★★★**사용자 질문 (4) — 타잉은 층수 감소가 아니다. 그런데 질문의 다음 절반이 정확히 옳았다**

**산술 정정 1건**: `m100R1c` 는 `mlp_group 8` 이라 중간 MLP 가 **2개**다(4개는 `m100` 기준).
어텐션 8개는 `ag2` 에서 맞다.

★**핵심 답 — 층수는 줄지 않는다**:

| 근거 | |
|---|---|
| 코드 | `layers.append(Layer(...))` — **`Layer` 는 매번 새로 만들어진다.** 공유되는 것은 **참조뿐** |
| 층 소유 파라미터 | 완전 타잉에서도 `ln1·ln2·a_scale·a_shift·m_scale·m_shift·gates` = ★**6×768+2 = 4,610개** |
| 입력이 다르다 | 잔차 노름 **L0 0.153 → L19 8.416 = 55배**(결과 057 U3) |

★★**그러나 사용자 직관 두 가지가 정확히 맞다**:
① **메모리 식에 실행 층 수가 없다** — 36층이 20층보다 작다는 044 의 결과가 그 뜻이다.
② **극단에서는 재귀에 수렴한다** — 타잉을 밀면 같은 함수를 n 번 통과하는 것에 가까워진다.

★★★**그래서 그다음 질문이 옳다**: 🚫**"같은 상주를 그냥 얕은 dense 로 쓰면?" 을 우리는 한 번도 안 물었다.**

| 모델 | fp32 상주 |
|---|---:|
| `mC_initonly`(tied 20층) | **451.5** |
| ⚙**dense 9층**(추정) | ⚙**458.0** |

→ ★**P074 신설**: dense 깊이 곡선 4점(6/8/10/12층) + 프리셋 `m100s2/s4/s6/s8`.
⚠️★**지면 REVIEW3 네 안 전부를 다시 읽어야 한다.**

### 1.5 🚫★★**U2 가 층의 중요도를 재고 있지 않았다** (결과 057 §11.2)

### 1.6 🚫★★**P034 bf16 은 세 번째 실패였다 — 원인은 "네 곳에서 소비되는 두 텐서"** (결과 016 §21)

| # | 고친 것 | 죽은 곳 |
|---|---|---|
| 1 | `emb` 만 | `emb_up` |
| 2 | `emb_up` 도 | **어텐션 블록**(`ternary.py`) |
| ★**3** | `forward` 가 `x.float()` | 🚫★**출력 헤드**(`_head_logits`) |

★**1·2차는 `BFloat16 != float`, 3차는 `float != BFloat16` — 방향이 반대**다. **증상만 쫓은 증거**.
★**진짜 원인**: 가중치 타잉 때문에 `emb.weight`·`emb_up.weight` 가 **모델 양 끝 네 곳**에서 소비된다.
✅**조치**: 접근자 `_emb_w()`·`_emb_up_w()` 단일화 + ★**`quantize_embedding` 이 직후 1토큰 forward 자체 시험**.
🚫★**네 번째로 죽으면 고치지 말고 bf16 경로를 지운다** 고 배치에 적었다.

```
큐 여덟 실험이 끝났다. 결과문서 여섯을 이어 썼고 REVIEW3 를 두 번째로 개정했다.

재귀가 36층 위에서도 무료임을 확인했다. paired 로 0.0157 좋고 deploy_mb 와
상주가 기준 모델과 소수점 열다섯 자리까지 같다. 20층에서 벌던 0.0202 의
77퍼센트를 유지한다. 깊이와 재귀가 같은 것을 산다면 36층에서 0 이 나왔어야
하는데 안 나왔으므로, 둘은 겹치지만 상쇄되지 않는다. 예측 넷이 모두 맞았고
REVIEW3 안 B 의 마지막 미검증이 닫혔다. 안 B 를 확정으로 올린다.

볼록성 모델이 틀렸다. mlp_group 을 16 에서 32 로 밀었더니 유니크 삼진 백만당
0.00312 로, 앞칸인 g8 에서 g16 의 0.00342 보다 오히려 싸다. 임베딩은 2.18배,
어텐션은 4.6배와 6.0배로 볼록한데 MLP 축만 반대다. 배치 헤더에 미리 적어 둔
예측 B4 가 이것을 정확히 겨냥하고 있었다 - 0.03 미만이면 볼록성 모델이 틀린
것이고 그게 이 레버보다 큰 발견이라고. 앞으로 볼록성을 근거로 안 잰 점을
예측하지 않는다. 부수적으로 g32 는 채택 가능하다. 상주를 36 MiB 줄이고 품질
대가는 실무 분해능 미만이다. 다만 상주 이득이 예측의 4분의 1인데, 유니크
중간 MLP 가 이미 두 개뿐이라는 것을 계산했으면 알 수 있었다.

외부 교사 KD 의 답이 나왔다. Qwen3-0.6B 를 교사로 쓴 Q256T 가 교사 없는 QT0
보다 0.0078 bpb 좋다. 실무 분해능이 0.008 이므로 바로 아래다. 규약대로면
서열을 매기지 않는다. 우리 dense 교사는 학생보다 나빴고 그때 KD 의 몫이
0.0032 nats 였다. 교사를 진짜로 고쳐도 우리 자를 못 넘는다는 뜻이므로,
REVIEW2 의 KD 제거는 뒤집히지 않고 근거가 오히려 강해진다. 교사 탓이 아니라
교사를 고쳐도 안 된다. Gemma 네 조건은 착수하지 않는다.

그런데 그 판정이 세 번 다 OOM 으로 죽었다. common_bpb 가 4.64 GiB 를 한 번에
잡는데 그것은 micro_bs 8 곱하기 seq 1024 곱하기 어휘 151,936 곱하기 4바이트다.
결과 053 에 M 무릎은 어휘 32,768 기준의 수이지 상수가 아니라고 우리가 써
놓고, 학습 배치에는 적용하고 판정 도구에는 적용하지 않았다. common_bpb 에
ce-chunk 를 넣고 재판정 배치를 만들었다. 21.5시간짜리 학습 셋의 판정을
0.3시간에 회수한다.

사용자가 아키텍처에 대해 물은 것이 이번 세션에서 가장 큰 것을 열었다.
어텐션과 MLP 를 둘 다 타이면 층수가 줄어드는 것 아니냐는 질문이다. 답은
아니오다. Layer 는 매번 새로 만들어지고 공유되는 것은 참조뿐이며, 완전
타잉에서도 층마다 norm 과 게이트 4,610개가 남고, 잔차 노름이 L0 에서 L19
까지 55배 커지므로 같은 가중치라도 다른 입력을 받는다. 그러나 질문의 다음
절반이 정확히 옳다. 메모리 식에 실행 층 수가 없으므로 메모리 관점에서는
층수가 준 것과 같고, 타잉을 극단으로 밀면 재귀에 수렴한다. 그래서 같은
층수의 dense 와 비교해야 하지 않느냐는 것이 옳은 질문인데, 우리는 그것을 한
번도 물어본 적이 없다. 타잉 20층이 451.5 MiB 이고 dense 9층이 458 MiB 로
같은데 어느 쪽이 나은지 모른다. P074 를 신설하고 얕은 dense 프리셋 네 개와
깊이 곡선 배치를 만들었다. 이것이 지면 REVIEW3 네 안을 전부 다시 읽어야 한다.

층 지도의 json 을 받고 나서 U2 해석에 결함이 있는 것을 찾았다. mC_initonly
에서 층별 기여도 상위 여섯 개가 전부 K/V 소유층이고 소유와 비소유의 중앙값
비가 7.9배다. cla_group 2 는 짝수 층이 K/V 를 소유하므로 그 게이트를 0 으로
하면 다음 층의 어텐션까지 죽는다. dense 는 1.37배, attn_group 4 인 36층
모델은 1.1배여서 이 해석이 검증된다. 어텐션 타잉이 그 효과를 지운다.
층별 불균등 압축에 U2 를 쓰려면 attn_group 이 4 이상이어야 한다는 조건을
결과 057 에 붙였다. 나는 이 근거를 검증하기 전에 결과문서와 REVIEW3 와
기준표 세 곳에 복사했었다.

bf16 임베딩이 세 번째로 죽었다. 이번에는 출력 헤드다. 앞의 두 번은
BFloat16 이 float 이 아니라고 했는데 이번엔 float 이 BFloat16 이 아니라고
한다. 방향이 반대인 것이 증상만 쫓았다는 증거다. 진짜 원인은 가중치 타잉
때문에 emb 와 emb_up 이 모델 양 끝 네 곳에서 소비된다는 것이다. 접근자

실패를 변이 지점에서 드러내게 했다. 네 번째로 죽으면 고치지 말고 bf16
경로를 지운다고 배치에 적었다.

paired_eval 이 드디어 조건별 분해능을 쓴다. 네 세션 미구현이었다. 두 모델이
둘 다 무KD 이고 부모초기화면 0.0034 를, 아니면 0.024 를 고르고, 쌍마다 어느
자를 썼는지 인쇄한다. 조건이 섞이면 경고한다.

체크포인트 판정표에 84행을 넣었다. 디스크에 153개가 있는데 표에는 84개만
있었고, 표에 없으면 기본이 hold 라 지워지진 않지만 why 가 없어 다음 세션이
판단할 근거가 없다. 가장 위험했던 것은 표준모델 mC_d36_ag4_nokd 가 표에
없었다는 것이다. keep 열다섯 개는 지금 대기 중인 실험이 읽는 것들이고,
특히 QT0 와 Q256T 와 Q64T 를 지우면 21.5시간이 사라진다. 회수 가능량은
약 20.4 GB 다.

W&B 곡선이 거의 같아 보이는 것은 정상이다. 모델 열 개의 val 오르내림 부호
일치율이 99.1퍼센트이고, 올라가는 구간이 1200, 1800, 2000, 2289 로 전 모델
같다. 같은 시드와 같은 풀과 exact-cache 를 쓰므로 어려운 배치가 같은 스텝에
도착한다. 모델 간 스프레드는 곡선 진폭의 9.8퍼센트라 W&B 축에서는 선

평가 스케줄이다.

마지막으로 자백 원장을 만들었다. 이번 협업에서 보고하지 않고 넘어간 것
열세 건을 적었다. 정적 게이트를 13종 통과라고 두 번 보고했는데 12종만
