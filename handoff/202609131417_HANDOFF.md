## 1. 가장 중요한 것 셋

1. 09:23 스모크는 **41팔 중 실패 1, exit-0 오류표지 0, 계측 계약 오류 0**이었다. 실패는 모델이 아니라 옛 핸드오프가 사용자가 이미 삭제한 P005 Stage3b·3c 완료 배치를 현재 `-done` 파일처럼 적은 두 줄이었다. 이 판은 현재 상태로 고쳤지만 코드·훅·새 CLA 회귀가 추가됐으므로 **사용자 새 스모크 전에는 큐를 실행하지 않는다**.
2. 승인 연구 4종은 모두 Stage0에서 fail-fast하도록 열었다. 추가 예산은 정확히 **72.0h 조건부 hard cap**이지만 지금 실행 가능한 새 배치는 **0.4h**뿐이다. gate PASS 없이 나머지 71.6h의 배치를 미리 만들지 않는다.
3. P089 Stage2의 실제 결함은 폭 자체가 아니라 CLA=2 교사의 reuse 층에 물리 K/V가 없는데 역할 깊이 매핑이 그 층을 직접 읽은 것이다. K/V·K-norm만 `teacher.owner`를 따르고 Q/O·Q-norm은 층 로컬로 유지했다. 순수 매핑 회귀 3/3은 PASS지만 실제 모델 조합은 새 스모크에서만 판정된다.

## 2. 무엇을 했나

- 병렬 원장 지원은 기본 동작을 풀지 않았다. 동시 생성에는 사용자 승인 사유와 Codex session id가 필요하고, 다중 원장 mutation은 `--file`을 요구한다. compact 훅도 같은 `session_id` 원장 하나만 선택하고 0개·2개 이상이면 중단한다.
- 핸드오프 작성 중 `apply_patch` 본문에 완료 WIP 링크가 있다는 이유만으로 직접 WIP 수정으로 오인해 차단되는 실제 훅 오탐을 관찰했다. 우회하지 않고 패치 전체 문자열이 아니라 `Add/Update/Delete/Move` 대상 헤더만 검사하도록 고쳤으며, 비-WIP 본문의 WIP 링크 허용과 WIP 직접 대상·이동 차단을 함께 회귀화했다.
- 종료 직전 재감사에서 열린 원장이 하나로 줄면 compact가 session id를 대조하지 않는 결함도 찾았다. 이제 원장 수와 무관하게 정확히 한 개가 결합돼야 하며, 결합되지 않은 병렬 SFT 원장을 현재 세션에 주입하지 않는다. 또한 WIP 이름 생성기가 동일 stem의 완료 원장을 점유 슬롯으로 세지 않아 open/`-done` 충돌을 만든 결함을 고치고, 이미 생긴 충돌은 감사형 `--repair-name-collision`로 `c` 원장에 이관했다.
- exact binding 도입 전에 만들어진 미결합 원장은 자동 추정하지 않는다. 소유 세션과 사용자가 확인된 경우에만 정확한 파일·session id·사유·승인을 요구하는 일회성 `--bind-session`을 추가했다. 완료 원장과 재결합은 거부하며, 현재 병렬 SFT 원장에는 이 명령을 실행하지 않았다.
- 스모크 원로그를 판독해 실패가 `check_handoff.py`의 두 존재성 오류뿐임을 확인했다. 옛 핸드오프는 역사 기록이라 수정하지 않고, 최신 판에서 “사용자 삭제 완료·현행 큐 아님”으로 계승했다.
- P089 부모 이식에서 Q/O와 K/V의 물리 소유 규칙을 분리하고, 합성 임시 체크포인트로 실제 모델 조합을 확인하는 `diag_init_cla_owner.py`를 사용자 스모크에 추가했다. 새 Stage2b는 실패 이력 태그를 재사용하지 않고 `_b` 태그 두 개와 결정적 paired eval을 쓴다.
- P091은 unique physical block·default-off·`W+sBA` fold 계약, P092/P025B는 세 희소도·birth/death·exact N:M·dense-regrowth-gradient 계약을 공통화했다. P022C/P025B는 실제 CUDA backend 호출 실패를 성공으로 삼지 않는 엄격 진단을 별도 작성했다.
- 승인 제안서 4종은 원문 절을 지우지 않고 마지막 승인 절이 과거 조건부/미승인 문구보다 우선하도록 이관했다. 계획·계획목록·방법론 3종·COMPASS·TSV를 연쇄 갱신했고, 실측이 없으므로 기준표 수치는 바꾸지 않았다.
- B2는 전체 경로 manifest를 두지 않는다. `check_doc_metadata.py`가 55개 Markdown을 직접 발견하고 live/draft/snapshot 자기선언, Git 내용일, dirty `--as-of`, 영한 pair, 선택 mtime을 검사한다. 루트 Claude 문서는 바이트 메타데이터만 파싱하며 환경 지침으로 사용하지 않았다.
- `PNone`은 구현하지 않았다. 현행 W2의 임의 문구 포함 면제보다 정확한 두 필드 결합이 안전하며, 해당 변경은 별도 사용자 승인 대상이다.
- `sync_experiments_tsv.py`의 판정은 P085 두 건을 올바르게 삭제 후보로 냈지만, 마지막 안내의 인자 없는 `queue_menu.py --ids`는 실제 parser에서 실패했다. 삭제 후 `--apply`→`--audit`을 먼저 수행하고, id가 필요한 배치명을 `--ids <배치명...>` 뒤에 넘기도록 출력과 회귀를 교정했다.
