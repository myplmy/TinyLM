## 1. ★가장 중요한 것 여섯

### 1.1 Stage0와 smoke 판정

- 원 Stage0 로그: 종료코드 0, `PM000 CONTRACT PASS`.
- 계약 수치: params `36,136`, state keys `47`, R1 exact, R3 delta `6.521e-03`, cached/full max abs `3.539e-08`, KV entries `4`, finite backward loss `0.000030`, grad tensors `47`.
- PM synthetic smoke arm: 종료코드 0, schedule `latin`, order `[0,1]`, R3, CLA2, skip 0.
- 전체 smoke: runlog arm 34개 중 2 nonzero. `check_links.py` exit 6과 `diag_sparse34_pack.py` exit 1이다.
- 따라서 **PM wiring PASS / 전체 smoke FAIL / 품질 효과 미측정**이다.

### 1.2 provenance 한계

smoke는 `e0330e3 +dirty 27개`, Stage0는 `e0330e3 +dirty 28개`에서 실행됐다. 커밋 단독
증거가 아니다. 결과 뒤 코드를 리팩터링했으므로 원 Stage0를 현재 소스의 동적 증거로 재사용하지 않는다.

### 1.3 선택 이식 구조

- 알고리즘 정본: [`pm000_latin_gqa.py`](../tinylm/moonshot/pm000_latin_gqa.py)
- 이식·제거 manifest: [`tinylm/moonshot/README.md`](../tinylm/moonshot/README.md)
- 정본은 torch import 없이 schedule, validation, 실제 layer visit counter, shift 선택을 소유한다.
- core에는 config 필드/검증, CLI 전달, trainer 계측, transformer pass ID, attention의 `torch.roll` hook만 남겼다.
- 기본 `fixed`는 order `None`이라 rotation helper와 `torch.roll` 경로를 타지 않는다.

### 1.4 변경 후 검증 상태

py_compile, pure-core, PM namespace, import, attribute, call kwargs, flag, smoke field/coverage,
batch name/lint/dry-run이 PASS했다. 전체 torch-free suite는 **29/32**다.

1. 기존 held-out D6: `E-157`, `E-205`.
2. 로컬 gitignored 링크 5건.
3. 사용자 smoke가 만든 일반 `tiny_synthetic_2M_dense.json`의 일반 registry 미등재 1건.

첫 전수 시도의 다수 실패는 `-X utf8`이 자식 Python에 상속되지 않은 CP949 출력 예외였다.
프로세스 환경에 UTF-8을 명시해 재실행했고 위 3건만 남았다. 모델 코드는 실행하지 않았다.

### 1.5 Stage1 preflight와 HOLD

세 tag는 모두 미사용이다. 각 arm은 `763 × 8 × 16 × 1024 = 100,007,936` tokens,
20 visits, CLA2, grad checkpoint on이며 schedule/seed만 `fixed/0`, `latin/0`, `random/17`이다.
`--no-ckpt` 미사용은 R2/R3 안전 조건을 맞추기 위한 사전등록 선택이다.

그러나 Stage1은 아직 실행하지 않는다. 최신 공통 smoke의 PM arm과 새
`run_PM000__MOONSHOT__Stage0B_postrefactor.bat` PASS가 필요하며, unrelated sparse34 실패를
전체 gate로 유지할지 PM gate에서 분리할지는 사용자가 정해야 한다.

### 1.6 namespace와 사용자 변경 보존

첫 smoke는 격리 보강 전 tag `sm_gqapass`여서 로컬 일반 registry에 역사적 smoke 행이 생겼다.
삭제하지 않았다. 이후 tag는 `dense_pm000__sm_gqapass`이고 `runlog.py`가 일반 registry에서 제외한다.

착수 전부터 루트 배치 15건이 사용자 변경으로 삭제돼 있었다. 되돌리거나 추가 삭제하지 않았다.
`sync_experiments_tsv.py`는 TSV 고아 행 15건을 보고하지만 `--apply`하지 않았다.
