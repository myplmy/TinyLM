## 1. 가장 중요한 것 셋

1. **재귀는 전부 미실행이 아니다.** P062의 고정/동일층/블록/점진 반복은 과거 실제 학습됐다. 방문 셔플·방문층 선택 라우터·최대 횟수 랜덤화는 현재 미구현/실행 증거 없음이다.
2. **복원층에는 학습 목적을 직접 줄 수 있지만 효과는 미측정이다.** P093의0.75% 개선은 Gaussian 입력의 근사 음성이지 복원층 학습 실패가 아니다. GSQ는 배정, LittleBit는 인자/잔차 구조, RCO는 후보 예산을 다룬다.
3. **증강 A·C1·C3는 작은 CPU 적용까지 끝났고 대량 경로는 불변이다.** 정수 계산·Boolean·표조회·JSON 필드 선택을 규칙으로 변형하고 고정답은 보호한다. C3는 원답 형식만 변경한다. 기존75M 부족·원배치300M 선결은 그대로다.

우선 A/CPU 계약을 권장하되 이번 요청은 검토이므로 해당 계획·런처·모델 코드는0이다.
n_mid10/prelude2/coda2 형상이라면 방문은 R1의14→R2의24이며 전체14층을 두 번 방문한28과 다르다.
현재 부모의 실제 cfg를 새로 열지 않았으므로 이 산술을 특정 checkpoint의 실측으로 쓰지 않는다.

CLA consumer를 owner보다 먼저 방문하면 현재 코드의 fallback KV가 consumer hidden에서 만들어진다.
순열의 owner 의존·visit/pass cache key·prefill/decode 정합, backward checkpoint 재계산의 동일 RNG,
resume seed·실제 방문 수·VRAM·추론의 고정 route를 먼저 검증해야 한다.

## 4. ⚠️조심할 것 — 다음 세션이 밟을 자리

- d16 dense는 tying하지 않았다는 뜻이다. 그 native TLinear 함수는 삼진이다. raw FP32 master가 더 좋은 teacher라고 가정하지 않는다.
- 기존 P093 Gaussian/rank16 근사 음성은 그대로다. 새 loss를 정해도 rank 한계가 사라지지는 않는다.
- GSQ/LittleBit의 학습 logits/master/optimizer와 배포 패킹을 구분한다. RCO의 연속 예산만으로 실제 이산 byte가 맞는 것은 아니다.
- A 변형기의 source SHA는 선언된 계보다. 원천 파일을 직접 검증했다고 주장하지 않는다. 코드 계산 정합은 세계 지식 정답성과 다르다.
- 첫 원형 QA와 새 규칙 QA의 답은 각각 맞다. 이 기능은 C의 옛 오답을 context-only로 만드는 turnwise mask가 아니다.
- 새 QA view의 길이는 달라진다. 기존 epoch_tokens==report train sum 검사를 끄지 말고 새 view manifest/실제 처리량/재개를 설계한다.
- source/root split을 먼저 고정하고 변형은 train만 쓴다. 최종 val/test의 실패를 다음 train에 그대로 넣지 않는다.
- DeepSeek V3의 FIM/token-boundary/random split을 질문 재표현 매 epoch로 오인하지 않는다. 해당 귀속은 채팅과 리뷰에서 정정했다.
- current 교사 train 공급3.95x/s로 새3M은 약8.8일의 조건부 외삽이다. 완료74tok/s는 학생 유효 공급속도가 아니다.
- 제공 LittleBit PDF는 읽기 입력으로 보존하고 이번 final staging allowlist에는 포함하지 않는다. 문서·코드만 새 작업 변경으로 커밋한다.
- 과거 telemetry와 현재 CPU PASS가 실제 peak/OOM·교사 품질·75M완성·300M교육을 증명하지 않는다.
