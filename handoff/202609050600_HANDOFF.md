## 1. 가장 중요한 세 가지

### 1.1 🚫★★★**어텐션 재사용(6.5-1)은 기각이다 — 재귀 이득을 전부 까먹는다**

| 모델 | full-val | `mC_initonly`(3.6776) 대비 |
|---|---:|---:|
| `mC_r20_nokd`(재귀) | **3.6573** | ★**−0.0203**(이득) |
| 🚫**`mC_r20ra_nokd`**(재귀+재사용) | **3.6855** | 🚫★**+0.0079**(손해) |

paired **+0.0281**(SE 0.0006, t 50.46, 승률 9.8%) = **무KD 2σ 의 8.3배.**
★**속도는 벌었다**: ms/step **4,729 → 3,976 = −15.9%**(V1 적중).
🚫**그러나 재귀를 안 하느니만 못하다** — 기준선보다도 나쁘다.

★**추론만 켜면 3.7899 = +0.1326**(학습해서 켠 것의 4.7배) → **무료 배포 레버도 아니다.**

★★**교훈 — `cos 0.9882` 를 오독했다**:

| | |
|---|---|
| 측정된 것 | 복제 통과 어텐션 **출력의 방향**이 첫 통과와 거의 같다 |
| 🚫내가 읽은 것 | *"그러니 건너뛰어도 손실이 작다"* |
| ★실제 | **잔차에 더해지는 것은 방향이 아니라 벡터**다. cos 는 **크기 차이를 안 담고**, 그것이 **36회 통과 동안 누적**된다 |

→ **계측함정 후보: *"유사도가 높다 ≠ 대체 가능하다."***

### 1.2 🚫★★**`_kd_kl` 1차 수정이 과거를 깰 뻔했다 — 사용자 지적이 맞았다**

내가 넣은 무조건 `.float()`:

```python
s = slog[i:i + chunk].float()      # ← 학생. 종전에는 bf16 이었다
```

★**종전 경로는 `autocast(bf16)` 아래라 학생·교사가 둘 다 bf16** 이었다.
🚫**무조건 승격은 `--kd-chunk` 를 쓴 기존 런(P053 계열)의 수치를 바꾼다.**
★★**결과 042 가 실효 α = 0.288 을 그 정밀도에서 쟀다** — 흔들면 안 되는 수다.

✅**2차 정정**: `fp32` 를 **opt-in** 으로. **외부 HF 교사 경로만** 켠다(발표된 결과 없음).

★**두 번째로 찾은 것**: `F.cross_entropy(reduction="mean")` 의 분모는 **N 이 아니라
무시되지 않은 타깃 수**다. `ignore_index` 가 있으면 `sum/N ≠ mean` 이고
**손실이 작아지는 형태로 조용히** 틀린다. → **단언으로 박았다.**

✅**P071 신설** — E1 은 **완전 일치** 기준(같은 호출이므로 근사면 안 된다), **E4 가 2차 정정을 증명**한다.

### 1.3 🚫★★**결과문서 번호를 잘못 붙였다 — 사용자 지적이 맞았다**

## 6. 커밋 메시지 제안

**제목**

```
어텐션 재사용 기각과 손실 청킹 정밀도 정정, 결과문서 번호 오배정 수정
```

**본문**

```
어텐션 재사용(--reuse-attn-on-dup)을 기각한다. mC_r20ra_nokd 의 full-val 은
3.6855 로 mC_r20_nokd 의 3.6573 보다 0.0281 나쁘다. SE 0.0006, t 50.46,
승률 9.8 퍼센트로 무KD 2 시그마의 8.3배다. 속도는 예측대로 벌었다 -
ms/step 이 4,729 에서 3,976 으로 15.9 퍼센트 줄었고 deploy_mb 는 동일하며
reserved 는 0.56 GiB 낮다. 그러나 재귀가 벌어 준 0.0203 을 전부 잃고
0.0079 를 더 잃어서 mC_initonly 기준선보다도 나쁘다. 학습 없이 추론에서만
켜면 3.7899 로 0.1326 나빠지므로 무료 배포 레버도 아니다.

결과 041 의 cos 0.9882 를 내가 오독했다. 측정된 것은 복제 통과 어텐션
출력의 방향이 첫 통과와 거의 같다는 것이고, 잔차에 더해지는 것은 방향이
아니라 벡터다. 코사인 유사도는 크기 차이를 담지 않으며 그 차이가 36회 통과
동안 누적된다. 유사도가 높다는 것은 대체 가능하다는 뜻이 아니다.

P054 안 C 가 부모의 중요성을 뒤집었다. dense2 에서 초기화한 mC_init2 가
mC_initonly 보다 0.0109 좋다. SE 0.0008, t -13.61 로 무KD 2 시그마의 3.2배다.
부모는 중요하지 않다는 가설이 기각됐고, 방향은 결과 049 와 반대다 - dense 가
재생성본 넷보다 좋았는데 그 나쁜 부모의 자식이 더 좋다. 표본이 한 쌍이므로
재생성이 낫다고 말할 수는 없고, 부모를 바꾸면 분해능 이상으로 움직인다는
것만 말할 수 있다. 안 A 의 값어치가 달라졌으므로 REVIEW3 안건으로 올린다.
부수적으로 dense 와 --no-ckpt 조합이 12.69 GiB 로 실측됐고, tied 쪽 10.31 은
결과 051 을 그대로 재현했다.

P062 단계2 는 학습이 끝난 뒤 로더에서 죽었다. config.py 의 __post_init__ 이
repeat_mode 를 세 가지로만 단언하고 있었고 inplace 를 몰랐다. 유효 모드
목록이 cli choices, transformer._repeat_schedule, config assert 세 곳에
있었는데 둘만 고쳤다. 함정 18 이다. 학습이 통과한 이유는 build_config 가
만든 뒤 trainer 가 필드를 대입해서 __post_init__ 이 다시 돌지 않기
때문이고, 죽은 것은 TMTConfig(**cfg) 로 재구성하는 load_model 이었다.
config.REPEAT_MODES 를 단일 소스로 만들고 세 경로가 전부 그것을 import 하게
했다. _repeat_schedule 진입에도 단언을 넣어 모르는 모드가 조용히 uniform 으로
떨어지는 것까지 막는다. 체크포인트는 정상이므로 재학습은 필요 없다.

손실 청킹의 정밀도를 되돌렸다. 사용자가 이 두 함수는 모든 학습이 지나는
길인데 실험 없이 도입해도 되느냐고 물었고, 검토해 보니 문제가 있었으며
내가 예상한 곳이 아니었다. 1차 수정에서 _kd_kl 청크 안에 무조건 .float() 를
넣었는데, 종전 경로는 autocast(bf16) 아래라 학생과 교사 로짓이 둘 다
bf16 이었다. 무조건 승격은 --kd-chunk 를 쓴 기존 런의 수치를 바꾸고,
결과 042 가 실효 알파 0.288 을 그 정밀도에서 쟀다. fp32 를 opt-in 으로
바꾸고 외부 HF 교사 경로에서만 켠다 - 그 경로는 아직 발표된 결과가 없다.
그리고 F.cross_entropy 의 mean 분모는 N 이 아니라 무시되지 않은 타깃 수라는
것도 찾았다. 우리는 패딩을 쓰지 않으므로 지금은 무해하지만 단언으로 박았다.
P071 계획서와 배치, check_chunk_equiv.py 게이트를 만들었다. E1 은 완전
일치가 기준이다 - chunk 0 은 종전과 같은 호출이므로 근사면 안 된다.

결과문서 번호를 잘못 붙인 것을 고쳤다. 번호는 실험군이지 세션이 아니고,
사용자가 준 로그 파일명이 이미 번호를 말하고 있었다. 054 하나에 P014,
P065, P067 세 실험군을 뭉쳤는데 세 로그가 같은 배치 실행에서 나와 내
머릿속에 하나의 사건이 됐기 때문이다. 문서 번호는 사건이 아니라 실험군을
센다. 내용을 003, 051, 053 으로 분할 이관하고 054 를 비웠으며,
check_result_numbers.py 를 신설해 NNN_log 가 있는데 같은 번호의 결과문서가
없으면 정적으로 잡게 했다. 정적 게이트가 13종이 됐다.

핸드오프에 쓴 "로그는 정본이 아니다" 는 용어 오용이다. 뜻한 것은 로그를
받은 것과 결과문서에 반영한 것이 다른 일이라는 것이었는데, 이 저장소에서
정본은 반대 뜻으로 쓰인다 - 함정 4 는 인쇄값이 정본이 아니고 runs/logs 의
json 이 정본이라고 한다. 콘솔 인쇄와 json 을 로그라는 한 단어로 뭉뚱그렸다.
함정 28 이 같은 단어가 다른 규약을 가리키는 것을 경고하는데 그것을 문서에서
밟았다.
```
