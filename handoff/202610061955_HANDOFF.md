### 2.3 원장 ID 결함·승인 후 복구와 재발 방지

정상 `wip.py --add 3AB`가 행을 추가했지만 `--start 3AB`는 found=0으로 끝났었다.
정확히는 새 원장 생성에는 ID 검증이 있었고 **add에는 없었다**. reader는 숫자+최대 한 ASCII
letter만 읽고 다른 행을 건너뛰어 실제8/CLI7과 잘못된 compact 완료 설명을 만들었다.
지원하지 않는 ID를 고른 제 실수와 도구의 쓰기·읽기 계약 불일치를 함께 인정한다.

사용자가 2026-10-06 일반 채팅에서 `scripts/wip.py`와 `scripts/test_wip.py`의 수리를 승인했다.
생성·추가·파싱에 같은 ID 검증을 사용하고, 불명 ID·열 결손·구분선 결손·행 구문 결손은 조회,
상태전이, capsule, close에서 오류로 중단한다. 오류 때 실제 원장 바이트는 변경하지 않는다.
새 CLI 플래그나 느슨한 파서를 만들지 않고 기존 `--override --field #`로 **지원하지 않는 ID만**
교정한다. 수정 전 값·승인·사유가 필수이며 정상 ID의 임의 개명, 중복 목표, 다른 불명 행,
완료 원장, 복수 대상은 거부한다. 교정 후 전체 표를 다시 엄격히 파싱해야만 원자쓰기한다.

현재 원장에서는3AB→3B만 교정하여 나머지 다섯 셀과 기존 작업/override 이력을 보존했다.

정상 start로 해제하고3B를 정상 start→done 처리했다. 현재 실제8/metadata8/CLI8이 일치한다.
모든8항목 완료 뒤 exact static-audit·동일 handoff·result-closure를 전달한 정상 close가 성공했다.
완료 원장은 개명 전 바이트를 그대로 보존하고 첫 미완료는 없다. 새 후속 E2E는 새 사용자 지시로 회수한다.
