## 3. ★결과 요약 — 3건의 로그가 말한 것

### 014 §10 — P030 단계2B (첫 유효 CPU 추론 측정)

- **헤드라인: CPU 1스레드 31~35 tok/s**(132M 삼진). 프로젝트 정체성에 대한 최초 실측.
- **메모리→속도 전이 거의 없음**: 상주 기준 전이율 mC **9.4%** / mA **3.4%**.
  → dequant 후 fp32 GEMM 이므로 당연하며, **R8(5비트 패킹)의 실측 근거**다.
- **단 순위는 상주를 따라간다**(mC ^> mA ^> p6d) — 결과 016 예측이 방향으로는 적중.
- **KV 캐시 이득의 부호가 디바이스마다 다르다**: CPU t1 **6.4~6.9×** / **CUDA 0.88~0.95×(손해)**.
- **스레드는 디코드를 가속하지 않는다**: 1→8 에서 tok/s **−4%**, TTFT **−42%**(prefill 만 병렬).
- mA 가 mC 보다 −7.4% = 유니크 파라미터 17% 차이와 정합 → **014 §1 의 −26% 인공물 소멸 확인**.

### 018 — P037 단계1 (경계 신뢰도)

- **경계는 정상**(eos 684 → 문서 685, 16토큰 미만 **0개**). 단계0.5 형 도구 결함 **재발 없음**.
- **원인은 길이가 아니라 SEO 스팸**: 7개 전부 자격증 덤프 판매글 + 무관한 소설 + **단어 중간 키워드 삽입**.
  서명 = **줄바꿈 0.0% + 줄 고유율 100%**(한 줄짜리 초대형 문서).
- → **단계2 설계 변경: 길이 상한 → 내용 필터.**
- `ko-en` 은 건강. ⚠️ 단 도구가 출력한 "**무작위 분할 필요**"는 −0.001 에서 발화한 **근거 없는 판정문**.

### 019 — P036 단계1 (trapping) — **판정 불가, 재실행 필요**

- **dense 대조군이 `torch.quantile` 2²⁴ 한계로 크래시** → 혼란요인 제거 장치가 사라진 채 비교됨.
- **모델마다 다른 shape 의 층을 뽑아 놓고 평균 ER 비교** → 아키텍처가 아니라 뽑기 결과를 쟀다.
- **`0 비율` 25.00% 는 3:4 의 구조가 정한 값**이지 관측이 아니다(순환논증).
- 방향만: mA 골짜기 40.87% vs mC 48.09%, ER/차원 37.34% vs 47.17% — **가설과 일치하나 귀속 불가**.
- ER 추정 자체는 안정(4배치 vs 12배치 +0.7~1.5%) → 재실행에서 배치를 늘릴 이유 없음.
