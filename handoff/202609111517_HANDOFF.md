## 4. ⚠️조심할 것 — 다음 세션이 밟을 자리

- 프로젝트를 신뢰하지 않았거나 `/hooks`에서 변경된 hash를 승인하지 않으면 훅 파일이
  있어도 활성되지 않는다. P8 전 “훅 활성 완료”를 쓰지 않는다.
- 이 guard는 백슬래시로 인한 텍스트 쓰기 사고만 막는 좁은 보조 장치다. Codex 권한,
  샌드박스, 사용자 승인, 데이터 보호를 대신하지 않으며 일부 특수 도구 경로는 훅을 우회할 수 있다.
- 손상 JSON은 무출력 fail-open, allowlist/내부 오류는 사용자 경고형 fail-open이다.
  경고가 보이면 보호가 통과한 것이 아니라 검사가 건너뛰어진 것이다.
- `ALLOW_BACKSLASH_WRITE`는 의도적 literal escape 때만 쓴다. 편의를 위한 상시 우회가 아니다.
- Codex 런타임에서는 공유 `scripts/check_handoff.py`를 실행하지 않는다. 이 파일은 다른
  에이전트 환경 진입 파일을 직접 읽는다. Codex 소유 `check_handoff_codex.py`를 쓴다.
- P7의 Git Bash 권한 확장은 5개 `.sh` 파일에 대한 `bash -n` 구문 분석만 수행했다.
  스크립트 본문, 프로젝트 스모크, 실험은 실행하지 않았다.
- `scripts/check_static_all.py`는 보호 데이터 검사를 포함하므로 이번 P7에서 실행하지 않았다.
  이전 공유 핸드오프의 프로젝트 35/35와 이번 환경 20/20을 합치지 않는다.
- 루트 `ai_dev_tool/09_구현검증_필요목록.md`는 해시만 대조했고 수정·복제·이관하지 않았다.
- 데이터셋 팀 작업 경로는 계속 접근 금지다. 불필요한 저장소 전체 검색·status도 피한다.
- 삭제·staging·commit·push·PR은 하지 않았다. §8은 제안문일 뿐 실행 증거가 아니다.
