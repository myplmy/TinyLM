## 1. 가장 중요한 것 셋

1. **P025B cuSPARSELt는 WSL에서 실제 동작했다.** inference forward와 bidirectional
   training-pack forward/input-gradient는 PASS다. 다만 M8192 training-pack forward는 dense 대비
   **0.759×/0.820×**로 느렸다. 이는 유효한 음성 결과이지 설치 실패가 아니며, inference
   pack·decode/prefill·whole-step·학습 후 실제 모델 추론은 아직 닫히지 않았다.
2. **다섯 로그는 보존됐지만 네 작은 계약 로그의 감사 상세도는 서로 다르다.** P093은 후보별
   수치를 충분히 남겼고 P025B도 pack·속도를 남겼다. P091/P095/P096은 assert 결과 요약만 남겨
   계약 PASS에는 충분하나 개별 identity·분포·gradient 수치를 독립 재구성하기에는 부족하다.
   `runlog.py` 자체나 WSL 경로는 정상이며 문제는 개별 diagnostic 출력 설계다.
3. **현재 실제 runnable 연구 gate는 두 개뿐이다.** P025B Stage0bWc와 P060B Stage0aW가
   존재하고 정적 검사를 통과했다. 둘 다 학습 0의 GPU 진단이며 사용자 실제 실행 전까지
   `E2E_NOT_RUN`이다. P022C/P092/P095 S0b는 여전히 구현되지 않았고 P094는 P022C 의존성 HOLD다.

## 4. ⚠️조심할 것 — 다음 세션이 밟을 자리

- P025B Stage0bWb 속도 저하는 **측정 사실**이지만 원인이 cuSPARSELt 자체, bidirectional
  pruning/layout, PyTorch prototype overhead, dense cuBLAS 우세 중 무엇인지는 아직 분해되지 않았다.
  Stage0bWc가 inference pack과 M 의존성을 먼저 가른다.
- Stage0bWc는 합성 kernel attribution이다. 통과해도 실제 TLinear 통합·weight-gradient·optimizer·
  checkpoint 추론 속도를 증명하지 않는다. 계획의 Stage2i가 실제 학습 checkpoint 비교를 소유한다.
- P060B는 torch `2.10.0+cu130`, Triton `3.6.0`, RTX 4070 Ti SUPER `sm_89`의 플랫폼 선결만
  확인했다. 외부 `flash-attn`은 설치되지 않았고 설치·다운로드 승인도 없다. native SDPA부터 잰다.
- P014 계열은 “Triton이 없어서” 닫힌 것이 아니다. Triton 정확성 실행 뒤 weight-only FLOPs·
  launch/커널 경제성으로 GPU 학습축을 닫았으므로 WSL 설치 사실만으로 P014 새 접미사를 만들지 않는다.
- 일반 `generate()`는 `sample(... logits_last_only=False)`를 그대로 써 prefill 전 위치 head를
  계산한다. 의미 오류는 아니지만 생성이 실제 사용하는 것은 마지막 위치뿐이다. forward 기본값은
  학습/평가 계약 때문에 false로 유지하고, generation 전환은 별도 캐시/비캐시·greedy/stochastic
  회귀 뒤 결정한다.

## 6. ★열린 질문

1. 현 트리 smoke를 gate 둘과 같은 queue에 넣을 때 `stop`, `collect`, `warn` 중 어떤 정책을
   쓸지는 사용자가 실행 시 선택한다. AI가 장시간 smoke의 실패 의미를 대신 고정하지 않았다.
2. P025B Stage0bWc가 속도 음성이어도 sparse-master 메모리 연구를 계속할지, 실제 checkpoint가
   생긴 뒤 Stage2i만 다시 볼지는 결과 회수 뒤 별도 결정이다.
3. P060B native backend가 음성이면 외부 `flash-attn` 설치를 검토할지 계속 보류할지 별도 승인이
   필요하다. 현재는 설치하지 않는다.
4. P022C/P092/P095 S0b의 직전 승인 범위를 다시 이어서 구현할지는 사용자 우선순위 결정이 필요하다.
5. generation 전용 호출에서 `logits_last_only=True`를 기본화할지는 별도 회귀 후 결정한다.
