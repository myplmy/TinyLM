실험이 멈춘 뒤 사용자 Windows PowerShell에서 아래 명령은 읽기 전용이다.
실제 복귀시각을 알면 앞뒤10~15분으로 좁힌다. 아래는 구 로그 종료를 포함한 참고창이다.

```powershell
Get-WinEvent -FilterHashtable @{
    LogName='System'
    StartTime=[datetime]'2026-10-09 10:30:00'
    EndTime=[datetime]'2026-10-09 13:40:00'
} | Where-Object {
    $_.ProviderName -match 'Display|nvlddmkm|Kernel-Power|Power-Troubleshooter'
} | Select-Object TimeCreated,ProviderName,Id,LevelDisplayName,Message | Format-List
```

같은 시각의 display driver 복구는 TDR 가설의 근거, 절전/복귀 사건은 전원상태 가설의 근거다.
사건이 없더라도 reset 없음/안전 보증은 아니며 시각·provider 필터·로그 보존의 한계가 있다.

회신에는 관련행만 남기고 계정명·개인경로는 가린다.
실제 GPU reset/CUDA/llama 오류가 있으면 무한 재시작하지 않고 확정 조각과 원본을 보존해 멈춘다.

공식 본문을 읽은 근거:
[Microsoft 전원 설정](https://support.microsoft.com/en-us/windows/experience/power-battery/power-settings-in-windows-11),
[화면·절전 타이머 분리](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/display--sleep--and-hibernate-idle-timers),
[WDDM TDR와 사건 기록](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/timeout-detection-and-recovery).
TdrDelay/TdrLevel 조정·TDR 비활성은 권장하지 않는다.
Microsoft는 이 키가 end-user 조작이 아니라 driver 개발/디버깅용이라고 명시한다:
[TDR registry keys](https://learn.microsoft.com/en-us/windows-hardware/drivers/display/tdr-registry-keys).
WSL의 nvidia-smi/NVML에는 기능 제한이 있고 GPU driver는 Windows 쪽에서 제공된다:
[NVIDIA WSL guide](https://docs.nvidia.com/cuda/wsl-user-guide/index.html).
