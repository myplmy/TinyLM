## 1. 가장 중요한 것 셋

1. `tomllib` 오류는 데이터나 Codex 훅 실패가 아니라 **사용자 기본 Python과 검사기의 3.11 전용 import가 맞지 않은 것**이다. fallback과 실제 import 회귀를 넣었지만, 사용자가 같은 명령을 같은 Python으로 다시 실행하기 전까지 E2E는 PASS가 아니다.
2. 직전 상위 지시 5 누락은 compact가 만든 문제가 아니다. WIP를 만들 때 GPT가 상위 번호를 제목으로 오판해 이미 버렸고, 훅은 HANDOFF의 compact 문구를 읽지 않는다. 이번에는 상위·하위 행 보존 규칙과 비대체 문구를 추가했다.
3. SFT revision1은 정확 마스크 계약은 통과했지만 구조 템플릿 중복 때문에 계속 HOLD다. held-out D9 저장 계약은 정적으로 구현됐으나 실제 6체크포인트 census는 사용자 소유 `NOT_RUN`이다.

## 2. 무엇을 했나

### 2.1 Python 진입점과 반복 오류

- `.codex/check_environment.py`가 `tomllib`을 무조건 import하던 경로를 선택 import로 바꿨다. `tomllib`이 없을 때는 현재 `.codex/config.toml`이 사용하는 flat·JSON-compatible 값만 엄격히 읽고, table·중복 키·지원하지 않는 값은 조용히 오독하지 않고 중단한다.
- 현재 Codex 셸은 Python 3.11.4라 원래 오류가 재현되지 않는다. 대신 테스트에서 `tomllib` import를 강제로 차단해 모듈 진입과 현재 config 파싱을 검증했다. 사용자 기본 Python 실물 재실행은 §6b에 남겼다.
- 세션별 원인은 다음처럼 달랐다.
  - P091·CLA와 P025B·P092: `scripts/` 직접 실행의 `sys.path[0]`이 저장소 루트를 포함하지 않는 문제였다.
  - 이번 `audit_sft_corpus.py`: 같은 루트 bootstrap 누락이었다.
  - 이번 환경 검사: 저장소 경로가 아니라 표준 라이브러리 지원 버전 문제였다.
- 공통 재발 원인은 `py_compile`·AST 검사를 실제 사용자 명령의 인터프리터·작업 디렉터리·격리 옵션과 동일시한 것이다. `check_hf_redirect.py`가 앞선 위험을 찾고도 당시 범위 밖 경고로 남았으며, 변경 후 최종 필수 게이트로 다시 실행하지 않은 절차 오류도 있었다.
- 최종 핸드오프 생성 전 `python -I scripts/new_handoff.py --help`도 형제 모듈 `handoff_queue`를 못 찾는 사각지대를 발견했다. 스크립트 자신의 디렉터리를 먼저 넣도록 고치고 별도 subprocess 회귀를 `check_static_all.py`에 연결했다.
- 오류원장에는 A33, 규약에는 R61을 추가했다. 앞으로 직접 실행 도구는 최소한 사용자 문서 명령 그대로의 진입 회귀, 지원 Python 하한/대체 경로, 도구별 기존 import 검사를 모두 거친다.

### 2.2 compact와 지시 누락

- 직전 WIP 원문부터 상위 `(5) 확인요청사항`이 없고 5A~5F만 있었다. 따라서 compact가 삭제한 것이 아니라 GPT가 WIP를 수동 분해할 때 누락한 것이다.
- `.codex/hooks/compact_state.py`는 세션 ID가 정확히 맞는 열린 WIP의 상태 캡슐만 읽으며 `*_HANDOFF.md`나 그 안의 compact 프롬프트를 읽지 않는다.
- `SessionStart(source=compact)`의 `additionalContext`가 기본 압축 요약에 **추가되는** 정보임을 훅 출력에 명시했다. 이번 자동 압축에서도 기본 요약과 상태 캡슐이 함께 들어왔지만, 이것을 모든 manual/0-match 경로의 종합 PASS로 확대하지 않는다.
- Codex 02에 상위 번호와 A/B 하위 항목을 각각 독립 행으로 보존하는 규칙을 추가했고, HANDOFF compact 문구를 반복 삽입하지 않는 회귀를 넣었다. 훅 제거는 권장하지 않으며 승인되지 않은 M6 양식 전환도 하지 않았다.

### 2.3 held-out D9

- `census_heldout_discrimination.py`가 기존 요약값 외에 `per_pick`과 모든 모델쌍의 a-only/b-only/discordant 수, 관계 family 수·95% CI·판정을 JSON에 저장하도록 했다.
- 모델별 결과 길이가 다르거나 항목을 건너뛰면 통계를 내지 않고 중단한다. 기존 키는 유지했다.
- 합성 CPU 계약 회귀 2/2는 PASS다. 데이터 원본과 체크포인트를 쓰는 실제 D9는 실행하지 않았다.

### 2.4 SFT와 fetch

- 사용자가 제공한 `diag_sft_mask.py` 실측은 총 10,025,284토큰, assistant 지도 4,012,983토큰, 지도 비율 40.0%, empty/M3/M4/M5 모두 0으로 PASS다.
- `audit_sft_corpus.py`의 `No module named 'tinylm'`은 데이터 실패가 아니라 도구 bootstrap 실패다. 해당 출력의 7,196,990은 문자/2.2 추정값이므로 정확 토큰값으로 채택하지 않았다.
