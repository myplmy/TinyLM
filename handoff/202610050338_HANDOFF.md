## 1. 가장 중요한 것 셋

1. **MTP는 실제 속도를 비교할 준비까지 끝났습니다.** 같은 Bonsai MTP 파일을 사용해 off→on→on→off 순서로16요청을 측정합니다. 과거60tok/s와 서로 다른 파일을 비교해 MTP 효과라고 부르지 않습니다.
2. **LoRA는 파일이 작아도 품질·속도 대가가 미측정입니다.** 9.23MiB 파일의129쌍은 구조상 맞지만 CUDA 작동·VRAM 증가·거부 감소는 아직 모릅니다. 사용자가 선택한 C에 따라 실제 허용 교육질문의 거부 관측 전에는 HOLD입니다.
3. **Qwen IQ2_XS-mtp는 유망한 비교 후보이지 채택 확정은 아닙니다.** 일반 GGUF와 MTP가 제공되며 교사 단독16GB 구동은 가능성이 있습니다. 한국어 평가·학생 동시 상주·현재 Prism 바이너리의 이 양자화 실행은 모두 미측정입니다.

### 2.1 준비한 비교와 출력

[프로파일](../scripts/p106b_mtp_teacher.py), [진단기](../scripts/diag_p106b_mtp_teacher.py), [회귀](../scripts/test_p106b_mtp_teacher.py)는 기존 교사 기본 경로를 바꾸지 않습니다. 한영·단답/다중답4문항을 고정하고 같은 prompt SHA·입력토큰·seed·xhigh를 사용합니다. 권장 Bonsai 샘플링은 temperature1.0/top_p0.95/top_k20/min_p0.05/presence0/repeat_penalty1.0입니다. 사고8,192·사고+최종답16,384·context32,768을 구분합니다.

MTP는16요청, LoRA는 base/mtp/lora/mtp_lora 네조건×두순서×4문항=32요청입니다. 완료문구가 확률적으로 달라질 수 있으므로 출력 길이와 두 실행순서의 속도비를 함께 보고합니다. backend decode tok/s, 전체 요청 tok/s, 최종문구 공급량, 첫요청/후속요청, 시작 시간, GPU 표본peak·여유·RSS를 분리합니다. MTP 카운터가 응답에 없으면 null이고 가짜 수락률을 만들지 않습니다.

사용자 실행 결과는 새 `HF/sft_ready/p106b_mtp_teacher_v1/mtp/` 또는 `lora/`에만 저장합니다. raw JSONL은20,000,000byte 이하 샤드와 SHA로 보존하며 사고와 최종답을 구분합니다. 실제 질문/최종답을 화면과 `review_packet.md`에 함께 보여주고, stdin 입력 대기는 없습니다. 이번 GPT가 그 HF 폴더를 생성하거나 모델을 실행한 것은 아닙니다.

### 2.2 사용자 C 선택 — LoRA를 여는 조건

LoRA는 일단 준비만 합니다. 허용 가능한 교육 질문에 교사가 실제로 거부한 경우, 질문/최종답/정확 원형 JSONL의 SHA·행·field path·판독자·근거를 `HF/sft_ready/p106b_mtp_teacher_v1/lora_trigger.json`에 남긴 뒤 Stage5c를 엽니다. 파일이 없으면 execute는 **서버 시작 전 HOLD8**입니다. 이 음성 선결을 모의 회귀와 실제 모델 없는 경로로 확인했습니다.

‘할 수 없습니다’라는 문자열이 인용돼도 자동 거부로 분류하지 않습니다. 후행 판독은 ANSWER/REFUSAL/PARTIAL/INVALID/UNSURE를 구분하고 모든 원답 SHA를 확인합니다. 기본 교사가 전부 답한 표본이면 LoRA의 거부 감소는 입증할 수 없습니다. LoRA의 안전·정답성 향상을 주장하거나 거부 감소를 지능 개선으로 바꾸지 않습니다.

### 2.3 Qwen IQ2_XS-mtp 읽기 전용 검토

**결론:** 한국어 교사 후보로 비교할 가치가 있습니다. 다만 현 단계에서 Bonsai보다 한국어가 낫다고 확인한 것은 아니며, 사용자 요청은 검토이므로 Qwen 파일 다운로드·교사 교체·새 Qwen SH 작성은 하지 않았습니다.

공식 [ISTA 모델카드](https://huggingface.co/ISTA-DASLab/Qwen3.8-27B-GSQ-RCO-GGUF)는 tensor별 GSQ/RCO 혼합 정밀도와 표준 GGUF를 설명합니다. IQ2_XS-mtp는8.77GB이며 MTP head로 약0.35GB가 추가됩니다. MTP가 언어 지식을 늘리는 기능은 아닙니다. IQ2_XS에서 BF16 대비 GPQA는89.90→84.85, LiveCodeBench는85.71→76.57이므로 모든 품질이 보존됐다고 말할 수 없습니다. 한국어 벤치는 이 카드에 없습니다. Apache-2.0 표시는 모델카드의 공개 상태이며 이번 파일을 로컬 검산·실행하지 않았습니다.

정확 후보는 [Qwen3.8-27B-GSQ-RCO-IQ2_XS-mtp.gguf](https://huggingface.co/ISTA-DASLab/Qwen3.8-27B-GSQ-RCO-GGUF/blob/main/Qwen3.8-27B-GSQ-RCO-IQ2_XS-mtp.gguf)입니다. 공개 파일 SHA-256 `F3369F8D36968AB7DD12F5FF11452680AEF9371AA19C9922D22CCD5E58C2D9C8`는 취득 후 검산할 후보값이며, 로컬 파일 MATCH 주장이 아닙니다.

**메모리 계산과 제한:**8.77decimalGB≈8.17GiB로 현재 Bonsai MTP 파일보다 약2.21GiB 큽니다. [Qwen config](https://huggingface.co/Qwen/Qwen3.8-27B/raw/main/config.json)의16 full-attention층·KV4head·dim256에 F16 K/V를 가정한 backbone KV는 context8K/16K/32K에서 약0.5/1/2GiB입니다. MTP 상태, 선형-attention 상태, workspace·GPU 화면 점유는 이 계산 밖입니다. 파일 크기는 VRAM 실측이 아니므로 단독16GB에서 작동 가능성은 있지만 OOM 안전을 보장하지 않습니다. 먼저8K~16K의 제한된 문항으로 비교하는 것이 타당합니다. 오래된 학생8,846MiB와 파일 전량GPU상주를 가정하면 합계가16GiB를 넘지만, 이 오래된 조건을 현재 학생에 그대로 적용하면 안 됩니다.

더 직접적인 [P106 결과098 §8](../test_result/098_20260925_P106-검증형-교사-레코드-계약만-통과했다.md)의 같은 micro8×accum16·ckpt-on·실물 부모/compile 두 합성 update는 학생 reserved4,122MiB, full Bonsai와 전역 표본peak11,640MiB·보수여유4,422MiB였습니다. [P106B 결과101 §30.1](../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)의 실제 online1은 교사ctx3,072·학생reserved2,322MiB·전역표본peak10,632MiB입니다. 이는 동시 구동 가능성을 완전히 배제할 근거가 없음을 뜻합니다. 그러나 Qwen은 다른 파일/연산·MTP·KV 예산이고 legacy 학생과 chat32 dense 부모도 다르므로, 이 여유에서 파일차만 빼고 안전을 보증할 수는 없습니다. **Qwen 교사+원배치 학생의 제한된 실제 동시peak가 필요한 조건부 후보**로 판정하며 이번 검토에서 그 실행을 하지는 않았습니다.

[Qwen 공식 모델카드](https://huggingface.co/Qwen/Qwen3.8-27B)는 low/medium/xhigh를 공식 지원하고 thinking에서 temperature1.0/top_p0.95/top_k20/**min_p0.0**/presence0/repetition1.0을 권장합니다. Bonsai의 min_p0.05와 다르므로 별도 프로파일이 필요합니다. GGUF qwen35와 MTP 방식이 같아 재사용할 수 있는 것은 HTTP/샤드/계측 구조이지, 기존 모델 SHA·sampler·LoRA가 아닙니다. 이번 Bonsai용 adapter는 Qwen에 자동 적용하지 않습니다. 현재 Prism의 옵션 존재는 확인했지만 이 IQ 포맷의 CUDA 작동과 MTP 수락·가속까지 확인한 것은 아닙니다.

후속 후보는 세 가지입니다. **A(권장):** 같은 한국어 질문·번역·다중턴 문맥 표본에서 Bonsai/Qwen 최종답과 유효자료 속도·peak를 먼저 대응 비교합니다. 실제 결함을 줄이는지 직접 보며, 채택을 가정하지 않습니다. **B:** Qwen 단독에서 MTP off/on부터 비교하면 속도 효과를 좁힐 수 있으나 한국어 교체 근거는 남습니다. **C:** 기존 Bonsai를 유지하면 추가 모델 비용은 없지만 한국어 한계는 해결되지 않습니다. 이 선택은 새 요청에서 결정할 범위이며 현재 WIP를 대기/막힘으로 남기는 사유가 아닙니다.
