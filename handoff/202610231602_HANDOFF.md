## 1. 가장 중요한 것 셋

1. **제한 규칙 추론은 크게 좋아졌지만 일반 대화는 아직 불안정하다.** 같은 질문의 검산 중간상태 지도는424/1024→1003/1024였으나 지도 토큰이6.44배다. 일반 사용자8질문은 두 팔0/8이었다. 공식Core6의 최신 Broad는41.91→42.40%로 소폭 상승했지만 유의한 전면 개선은 아니며 문법은72.16→70.98%로 하락했다. Falcon90M의48.36%에는 못 미친다.
2. **실제 방법 대조와 음성을 숨기지 않았다.** MTP704 네팔, 검산풀이128 두팔, 재귀704 네정책, ALM32 네팔, 내부 어휘타일 실제4update와 공식 평가를 회수했다. ALM은 대응 CE보다 좋아지지 않았고 어휘타일은 FP32에서도85개 업데이트가 문턱에 미달해 기본 경로에 채택하지 않았다. 학습 라우터·공식 CCE/Liger·추가 KD 등은 실제 미완이다.
3. **자료량과 품질을 섞지 않는다.** 고유 원문3427·SFT5529 초안·비SFT284 텍스트는 미채택이다. 교사 신규199555 train-x를 두 창으로 보존했고 누적29,221,731/잔여45,778,269다. 75M 완료가 아니며 현재source82의106동작 전체스모크 실패0도 정답성 PASS가 아니다.

### 2.5 첨부에서 실제 끝내지 못한 것

공식CCE/Liger 접합, NorMuon/AdaMuon, progressive context, causal MNTP/adaptive masking,
ACTD/DSKDv2/DWA-KD/DVLM 최소학습, ALM+GSQ 배정, 새KO100+EN100 finalholdout,

## 3. 무엇이 바뀌었나 — 코드·도구

주요 구현은 TinyLM용 공식우도 adapter/공식평가 최소환경, Gemma byte확률 수집과 엄격한
목표구간 정렬·ALM F/Q profile, 원문/작성/보류의 명시 패킷과 copy-only 게시/수입,
출력-head 수치진단의 opt-in 모듈이다. Luna는 처리코드를 수정하지 않았다.
추론loader는 Gemma tokenizer의 추가특수토큰1개를 **명시 옵션에서만** 허용하고 base어휘/
입력ID경계를 검사하도록 수리했다. 원체크포인트/원tokenizer는 resize/변경하지 않았다.

사용자가 제시한 Gemma270M 증류 TinyLM 체크포인트는 baseV262144인데 tokenizer에 `<image_soft_token>`이
ID262144로 하나 더 있어 엄격검사에서 거부됐다. `--allow-extra-special-tokens`로 텍스트범위를
명시 허용했지만 원학습 tokenizer SHA가 없어 역사적 일치까지 인증하지 않았다.
한영 네 실제답은 여전히 MAX128/오답·반복이어서 loader복구가 지능복구라는 뜻은 아니다.

사용자가 같은 텍스트 범위 진단을 다시 열 경우의 명령은 다음과 같다. 현재 새모델 실행을
요청하는 것이 아니며 base completion이 chat instruction 능력을 보증하지 않는다.

```bash
./interactive_infer.sh \
  --model m100R1c_ko-en_300M_G270Tfull.pt \
  --tokenizer ./HF/models--google--gemma-3-1b-pt/snapshots/fcf18a2a879aab110ca39f8bffbccd5d49d8eb29/tokenizer.json \
  --mode plain --device cuda --max-new 128 --allow-extra-special-tokens
```

## 6. 열린 질문

다음 우선순위는 세 갈래를 제시한다. 선택은 방향이며17시 이후 실행권한을 자동 연장하지 않는다.

1. **권장: 수치정합을 갖춘 학습가속+내용 증류를 먼저 좁힌다.** 기존 정상1024 경로를 보존하고
   tied embedding/head 전체gradient·optimizer정밀도·실제update를 맞춘 뒤 작동하는 경로에서만
   같은 교사신호/같은자료의 작은 대조를 준비한다. 출력head가 첨부최우선이었던 누락을 바로잡는
   방향이다. CPU2~4h/GPU0.5~1h부터 계측하는 추정이며 통과/가속을 보장하지 않는다.
2. **학습된 prefix router를 먼저 연다.** 완료balanced704를재사용하고 body재학습없이
   TRAIN라벨→DEV head선택→새TEST를 네고정정책과 비교한다. 기존 약1.5h 표기는미측정이다.
   cost8을 먼저재서 실제8448forward/880CPU/768DEV/1024TEST가 새허가창에 들어갈때만 진행한다.
   경로선택의 추가이득을직접보나 현재잘못된감독/일반대화문제까지자동해결하지는않는다.
3. **자료 품질과 실제 지시능력 보완을 먼저 한다.** 현재5529초안·교사674의 주체/조건/용어·턴감독을
   후행판독하고 검수된 자료만 정상SFT/replay와비교한다. 사용자목표에직접가깝지만전량1.44M
   의미정제는새창안완료를보장할수없고알고리즘/아키텍처미완이또뒤로밀릴위험이있다.

Luna 원문/번역 정리는 어느 방향에서도 같은원형보존/텍스트전용으로 이어갈 수 있다.
원문품질 우려가 남은 교사8h를 무조건 실행하라고 요청하지 않는다. 별도 확정된blind200 질문은
평가용으로만 만들고 train/teacher에는 넣지 않아야 한다.
