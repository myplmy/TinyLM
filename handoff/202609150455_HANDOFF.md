## 1. 가장 중요한 것 셋

1. 사용자 스모크의 두 실패는 **제품/GPU 팔이 아니라 문서 게이트 둘**이었다. 깨진 SFT 링크는
   새 `SFT/v1` 경로로 교정했고, 28.3h 큐는 이번 요청의 배치 작성 금지 때문에 늘리지 못한 사유를
   이 핸드오프에 명시했다. AI는 스모크를 재실행하지 않았으므로 최종 상태는 `REQUIRED_USER_RUN`이다.
2. P025B 전체가 실패한 것이 아니다. Windows의 **native cuSPARSELt 가속 분기**만 현재 환경에서
   막혔다. WSL 환경 교량을 통과하면 Stage0b를 다시 열 수 있고, 비native mask/gradient 및
   sparse-master 질문은 별도 증거·승인이 필요하다.
3. 현재 연구에서 직접 MLP/attention 공유는 실제로 닫혔지만 타잉 가족 전체는 아니다. CLA/KV는
   별도 열린 축이고, 저랭크 잔차·head 정렬 완화는 0런이다. 다만 GPU 우선순위는 토큰·RMS4·CLA가
   더 높으므로 완화 타잉은 승인 뒤에도 GPU 0 회계부터 시작한다.

### 2.2 WSL2 이관 제안

- 현재 Windows와 WSL 후보의 PyTorch/CUDA/cuDNN/cuSPARSELt/Triton 차이를 환경축으로 고정했다.
- Windows agent가 `wsl.exe`로 명령을 호출하는 것과 Desktop의 agent environment를 WSL로
  전환하는 것을 분리했다. 후자는 설정 변경·앱 재시작·Linux sandbox·새 E2E가 필요하다.
- `/mnt/z/TinyLM`은 호환성 탐색에는 쓸 수 있지만 Linux 도구의 장기 빌드·학습 정본으로는
  교차 파일시스템 비용이 있다. 권장 C안은 Windows 정본 동결 → Linux ext4 clean clone →
  정적/E2E/backend/교량 gate → 사용자 최종 cutover다.
- 기존 실험을 삭제하거나 “버리지” 않는다. 품질은 교량이 자 안일 때 재사용하고, tok/s·VRAM·RSS와
  backend 종속 수치는 WSL 층에서 다시 잰다. 데이터·체크포인트 이관은 별도 승인 전 0건이다.

### 2.3 anneal 조사

- WSD LR cooldown, ternary FP→quant 전이, Arenas/LoRA 보조경로 제거를 서로 다른 계약으로 분리했다.
- WSD는 cosine 대비 −0.0755 nats(6.3σ)로 강하지만, quant anneal 0.60↔0.80 및 linear↔step은
  P026/P035에서 채택 이득을 검출하지 못했다. step은 grad peak가 더 컸다.
- 코드·기준표의 0.60과 최근 배치 명시값 0.80이 갈린다. 새 기본값을 추측해 바꾸지 않고 code flip,
  quant distance, occupancy, grid margin, grad/update를 먼저 계측하는 C안을 제안했다.

### 2.4 P025B 실행 가능 범위

| 분기 | 현 상태 | 지금 주장 가능한 것 | 다시 여는 조건 |
|---|---|---|---|
| Windows native 2:4 | `cuSPARSELt not supported` | 현재 Windows/torch 환경의 native 가속 팔은 중단 | 지원 backend가 있는 환경에서 동일 Stage0b를 다시 수행 |
| WSL native 2:4 | 라이브러리 메타데이터상 cuSPARSELt ON | **지원 가능성**만 있음 | WSL Codex/환경 교량 뒤 실제 첫 호출·정확성·grad·속도 gate |
| mask/topology/gradient | backend 비의존 검사가 가능 | 2:4 구조와 mask 의미론 | native 속도·메모리 주장과 분리한 계약으로 실행 승인 |
| sparse-master | native kernel과 독립적인 저장·optimizer 질문 | 별도 연구 분기로 남아 있음 | temporary dense·optimizer state·checkpoint bytes 회계와 별도 승인 |
| mask-only 품질 | 실행 자체는 가능 | 고정 희소 패턴의 품질 대가 | native 가속 성과로 오인하지 않는 별도 계획·판정 |

결론은 **P025B 전체 수행 불가가 아니라 Windows native 가속만 현재 불가**다. WSL에서 Stage0b가
통과해도 전체 P025B가 자동 PASS가 되지 않으며 각 후속 단계는 다시 승인받는다.

### 2.5 연구현황과 타잉 범위

- 연구현황 보고서는 완료한 결과를 1~4등급으로 분류하되 P번호 전체가 아니라 **판정된 단계**를
  등급 단위로 삼았다. 같은 P번호 안의 계약 PASS와 품질 성과를 섞지 않기 위해서다.
- 가장 큰 내부 품질 레버는 토큰/노출, WSD, Muon/RMS이며 배포 후보 d18은 37.1 MiB·15.84 tok/s다.
  그러나 외부 기준 P059와 신뢰 가능한 held-out이 미완료여서 외부 지능 수준은 미확인이다.
- P045B의 dense 3.5745 대비 ag2 +0.0073, g2 +0.0340, g4 +0.0579는 직접 공유를 닫기에 충분하다.
  반면 Relaxed Recursive Transformer식 depth-wise LoRA, LiSA식 attention 정렬/저랭크 차이,
  CLA/KV는 독립 방법이다. COMPASS는 이 범위를 명시하도록 갱신했다.
