2. 그 task 소유의 새 open WIP를 `scripts/wip.py`로 만들고 결합한 뒤 `sha256sum`을 기록한다. 완료된 `-done` 원장을 다시 열거나 다른 세션 WIP를 probe 대상으로 쓰지 않는다.
3. 허용 경로를 먼저 실행한다.
   ```bash
   /home/uranus/miniforge3/envs/tlm_torch/bin/python -B -X utf8 scripts/wip.py --file handoff/<현재-open-WIP>.md --capsule-check
   ```
   기대값은 `CAPSULE_OK`, exit 0, fail-open/`systemMessage` 0건이다.
4. Bash matcher는 실제로 쓰지 않는 false branch로 probe한다.
   ```bash
   if false; then printf 'm3-probe\n' >> handoff/<현재-open-WIP>.md; fi
   ```
   기대값은 **shell 시작 전 deny**라서 shell exit code 자체가 없어야 한다. exit code 0이 보이면 hook fail-open이다. 전후 WIP hash는 같아야 한다.
5. apply_patch matcher는 존재할 수 없는 context를 WIP에 겨냥한다.
   ```diff
   *** Begin Patch
   *** Update File: /home/uranus/tinyLM/handoff/<현재-open-WIP>.md
   @@
   -__TINYLM_M3_CONTEXT_MUST_NOT_EXIST__
   +__TINYLM_M3_CONTEXT_MUST_NOT_EXIST_CHANGED__
   *** End Patch
   ```
   기대값은 apply_patch 실행 전 deny다. `verification failed`가 나온다면 hook은 fail-open했지만 불가능 context 덕분에 파일은 그대로여야 한다. 전후 hash를 다시 대조한다.
6. 합법적인 갱신 한 건을 `scripts/wip.py`로 수행하고 hash·capsule-check를 다시 기록한 뒤 **manual compact**를 실행한다. 재개 직후 모델이 현재 사용자 allowlist, NOT_RUN 경계, 정확한 open WIP/미완료, 수행 변경·검증, 막힘, 사용자 소유 실행, 폐기 주장, 다음 행동의 **8필드**를 현재 값으로 보고해야 한다. stale WIP·0/multi-match·fail-open 경고가 없어야 한다.
7. 최소 M3 종료 조건은 `허용 wip.py 1건 PASS + Bash deny + apply_patch deny + manual compact 최신 capsule + 경고 0 + 두 deny 전후 hash 불변`이다. 이번 task의 auto compact 정상 주입은 auto route 재시험을 대체할 수 있지만 hook hash/project identity가 바뀌면 다시 본다. 0-match/multi-match/stale capsule 같은 파괴적 음성 경로는 production WIP를 훼손하지 말고 별도 fixture/new task에서 검증한다.
