## 2. 사용자 질문 (10) — **KD 코드 검토**

REVIEW2 가 KD 를 뺄지 정하기 전에 *"KD 가 제대로 구현됐는가"* 를 봤다. `trainer.py` 375~390줄:

```python
with torch.no_grad():
    tlog = teacher(x)
T = kd_temp                                     # 2.0
kl = F.kl_div(F.log_softmax(logits.reshape(-1, V) / T, -1),
              F.softmax(tlog.reshape(-1, V) / T, -1),
              reduction="batchmean") * (T * T)
loss = ((1 - kd_alpha) * ce + kd_alpha * kl) / accum
```

| 항목 | 판정 |
|---|---|
| 교사 no_grad | ✅ 맞다 |
| `log_softmax(student)` / `softmax(teacher)` 배치 | ✅ **`F.kl_div` 규약대로**(input=log-prob, target=prob) |
| `T²` 보정 | ✅ Hinton 관행대로 |
| `reduction="batchmean"` | ⚠️ **주의**: 입력이 `(-1, V)` 로 **평탄화**돼 있어 batchmean 이 **토큰 수(8192)로 나눈다**. 이건 **KL/토큰**이라 CE 와 같은 스케일이다 → **✅ 맞다.** (평탄화 없이 `(B,T,V)` 였다면 B 로만 나눠 T배 커졌을 것) |
| `kd_alpha=0.5` 혼합 | ✅ |
| **어닐과의 상호작용** | ⚠️ **교사는 `set_anneal(1.0)`**(완전 삼진), 학생은 어닐 중이다. **의도된 설계**지만 초반에 학생·교사의 표현 공간이 다르다 |

> ✅ **KD 구현 자체에 결함은 없다.** 결과 038 의 *"KD 몫 −0.0032"* 는 **구현 버그가 아니라
> 300M 예산에서 KD 가 실제로 무익하다는 뜻**이다. 기준표 §7 의 예산 의존성과도 일관.
>
> ⚠️ **다만 한 가지 미검토가 남는다**: `kd_every=4` 로 **KD 스텝과 비KD 스텝의 손실 스케일이 다르다**
> (KD 스텝만 `(1-α)ce + α·kl`). gradient 크기가 스텝마다 뛰는데 **그 영향은 잰 적이 없다.**
> → **REVIEW2 전에 값싸게 볼 수 있다**(로그의 `|g|` 를 KD/비KD 스텝으로 갈라 보기, GPU 0).

### 4.1 오염 위험 판정 — **둘 다 "분리 구현 + 동일성 검증" 이 필요하다**

| | T-1 (eval 타이밍 분리) | F-1 (GQA `enable_gqa`) |
|---|---|---|
| 학습 수치 변경 | **없음**(측정 전용) | ⚠️ **있을 수 있다**(SDPA 커널 경로가 바뀐다) |
| 기존 로그 비교 | ⚠️ **ms/step 정의가 바뀐다** → 과거 값과 **비교 불가** | 없음 |
| 오염 방지 | **새 필드를 추가**하고 기존 `ms/step` 은 **그대로 둔다** | **플래그 기본 off** |
| 검증 | 같은 런에서 두 값이 함께 찍히는지 | **로짓 동등성 게이트**(`diag_kvcache.py` 방식) |

### 4.2 T-1 설계 (구현 소)

**기존 `ms/step` 인쇄를 건드리지 않는다.** json 에 **두 필드만 추가**:

... (accum 루프 + opt.step) ...
step_ms.append((time.time() - t_step0) * 1000)   # eval·ckpt 저장 제외
# json 에:  "ms_step_median": median(step_ms[warm:]),
#           "ms_step_p90_p10": p90/p10 - 1

★**`check_spill.py` 가 오프라인으로 하던 계산을 런타임이 직접 한다** → 스필 판정이 **자동**이 된다.
**게이트**: 같은 런에서 `ms_step_median` 이 `check_spill.py` 의 중앙값과 **5% 안**.

### 4.3 F-1 설계 (구현 소, 검증 필수)

```python
# modules.py Attention.forward — 플래그 기본 off
if cfg.sdpa_gqa and n_rep > 1:            # 신규 --sdpa-gqa
    o = F.scaled_dot_product_attention(q, k, v, is_causal=True, enable_gqa=True)
else:                                      # 종전 경로 = 비트 동일
    k = k.repeat_interleave(n_rep, dim=1); v = v.repeat_interleave(n_rep, dim=1)
    o = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

⚠️ **`attn_mask` 경로(KV 캐시 추론)에도 같이 넣어야 하나 그쪽은 Flash 가 아니다** — **1단계는 학습만.**

**검증 배치 `run_F1_gqa_equivalence.bat`(수 분, 학습 0)**:
1. **로짓 동등성** — 같은 입력에 두 경로 로짓 차. **`0.000e+00` 을 기대하지 않는다**(커널이 다르다).
   기준: **최대 절대차 < 1e-3**(bf16 누산 자릿수, 결과 028 §11 의 `1.7e-3` 과 같은 계열)
2. **Flash backend 유지 확인** — `torch.nn.attention.sdpa_kernel` 컨텍스트로 강제하고
   `enable_gqa=True` 가 **거부되지 않는지**
3. **VRAM** — 250스텝 × 2(off/on), 같은 배치. 기대 **−0.4~0.5 GiB**

> ⚠️ **F-1 은 "3줄" 이라고 지난 세션에 썼는데 검증까지 넣으면 그렇지 않다.** 정정한다.

## 5. 사용자 지시 (4) — T-2 분리 판단: **분리한다**

| 기준 | 판정 |
|---|---|
| 목적이 다른가 | ✅ T-1·F-1 은 **계측/활성**, T-2 는 **손실 계산 구조** |
| 위험이 다른가 | ✅ T-2 는 **gradient 누적 순서가 바뀐다** — 비트 동일 불가 |
| 크기가 다른가 | ✅ T-2 는 **−2~3 GiB** 로 한 자릿수 크다 |
| **선행 조건이 있는가** | ★✅ **KD 를 유지하기로 REVIEW2 가 정해야 의미가 있다.** KD 를 빼면 **손실 청크의 대상이 사라진다**(CE 만 남아 −1 GiB 급) |

> **→ T-2 는 별도 실험계획(가칭 P053)으로 분리한다. 단 착수는 REVIEW2 뒤.**
> **지금 계획서를 쓰지 않는다**(사용자 허가 대기 + 선행 조건 미충족).

## 6. 사용자 지시 (7) — 미구현 코드, **언제까지 미루나**

| 계획 | 선결 구현 | 지금 가능한가 | 판단 |
|---|---|---|---|
| **P049**(깊이 g16×2) | `init_from_dense` **깊이 확장 이식** | ✅ **가능** | ★**지금 해야 한다.** 결과 038 이 격하 조건을 **부정**했고(부모초기화가 43배), 결과 030 이 **이식 결손 = 0.1123** 을 쟀다. **더 미루면 P049 델타가 또 초기화 핸디캡에 오염된다** |
| **P046 단계3**(E=192) | 없음(`--emb-rank` 존재) | ✅ **즉시 가능** | ⏸ **int8 배포 확정 후.** packed 기준 최악 레버(0.0737 nats/MB) |
| **P014C 단계2** | `TLinear` **per-row 융합 경로**(기본 off) | ✅ 가능 | ⏸ **P014 축 전체가 배포 경로 확정 대기** |
| **T-2 / L5** | KD 손실 청크 | ✅ 가능 | ⏸ **REVIEW2 뒤**(§5) |

★**결론: P049 선결 이식만 "지금" 이다.** 나머지 셋은 **배포 경로(int8 vs fp32)와 KD 유지 여부**라는

⚠️ **P049 이식은 이번 세션에 구현하지 못했다.** 설계는 명확하다 —
`init_from_dense` 에서 학생 `n_middle` > 교사 `n_middle` 일 때 **교사 층을 순환 반복하거나 균등 보간**하고,
**어느 쪽인지 로그에 크게 찍는다**(결과 030 의 교훈: 조용한 부분 이식이 사고를 만든다).
