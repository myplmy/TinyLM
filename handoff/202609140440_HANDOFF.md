## 1. 가장 중요한 것 셋

1. **승인된 B안의 G0/G1 정적 경로가 구현됐다.** 다음 census JSON은 조건 서명·문항 라벨·관계/난이도/하위가족 집계를 보존하고, 새 비교기는 모델·ID·평가 조건을 강제한다. 회귀는 census 7/7 + 비교기 6/6이다.
2. **최소 통제셀은 v2.9×seed2다.** seed2는 v3.0 독립 판정에는 옳았지만 v2.9 통제가 빠져 판본/패널이 교락했다. `v3.0×Muon15`는 이미 설계에 사용한 패널이라 최종 통제로 쓰지 않는다.
3. **품질 향상은 별도 승인 대기다.** 정보 0 제거·bit/모델쌍 coverage·실측 난이도·하위 가족 선별을 제안했지만, G2 canary와 데이터 원본 변경은 Stage10c 결과 전에는 시작하지 않는다.

### 2.4 JSON 단독 판독과 자동 로그

JSON만으로 B1/B2/D9/bit, 정오·선택 벡터, 모델쌍 CI는 다시 계산할 수 있다. 그러나 현 JSON은
relation·difficulty 라벨, 실제 argv 전체 조건, 시작·종료시각, process exit code, JSON 저장 전
traceback을 보존하지 않는다. 따라서 JSON 단독으로 콘솔 판정과 실패 원인을 완전 감사할 수 없다.

`scripts/census_heldout_discrimination.py`는 이제 실제 run이면 `--out`의 같은 폴더에
`YYYYMMDDhhmmss_<out-stem>.log`를 자동 생성한다. stdout/stderr는 콘솔에도 유지하고,
같은 초의 기존 파일은 `_2` suffix로 보존한다. `--help`는 실행이 아니므로 로그를 만들지 않는다.
이번 기존 v3.0은 완결 JSON과 콘솔 사본이 있어 새 로그만 얻기 위한 GPU 재실행은 권하지 않는다.

### 2.8 왜 seed2였고 어떤 통제셀을 골랐나

Muon15 여섯 모델은 v2.9 `per_item_rate`를 통해 v3.0 교체 방향을 정하는 설계 패널이었다.
같은 패널로 v3.0을 최종 합격시키면 선택 편향이므로 요청서 §8.3·§8.4·§9.4가 다른 seed 또는
독립 체크포인트를 요구했다. 같은 아키텍처 격자의 seed2 여섯 개를 v3.0에 쓴 것은 타당하다.
누락은 같은 seed2로 v2.9를 재지 않은 것이다. 따라서 최소 통제셀은 **v2.9×seed2**다.
`v3.0×Muon15`는 설계 패널 진단이라 낙관 편향을 제거하지 못하므로 편성하지 않았다.

Stage10c와 v3.0 응답을 v3.1 생성에 사용하면 seed2도 설계 패널로 강등된다. 다음 판의 최종

### 4.3 사용자 실행 절차 — 순서를 바꾸지 않는다

1. GPU를 사용하는 다른 작업이 없는지 확인한 뒤 저장소 루트에서 다음을 실행한다.

   ```bat
   run_smoke_check.bat
   ```

2. 새 `smoketest_logs/YYYYMMDDHHMM_smoke_<sha7>.txt` 파일명을 AI에 회신한다. AI가
   **실패 팔 0, exit-0 오류 표지 0, 계측 계약 오류 0**을 실제 로그에서 확인하기 전에는
   Stage10c나 뒤 큐를 실행하지 않는다.
3. AI가 스모크 PASS를 확인한 뒤에는 §7의 첫 행인 다음 배치 **한 건만** 실행한다.

   ```bat
   run_P085_Stage10c_heldout_v29_seed2_control.bat
   ```

   메뉴를 쓰려면 실행 직전에 ID를 다시 계산한다. 현재 정적 스냅샷의 ID는 `1`이지만 TSV가
   바뀌면 이동하므로 숫자를 기억해서 재사용하지 않는다.

   ```bat
   python scripts\queue_menu.py --ids run_P085_Stage10c_heldout_v29_seed2_control.bat
   run_queue.bat
   ```

4. 배치는 v2.9를 benchmark cache의 활성판으로 가져온 뒤 seed2 여섯 체크포인트를 읽는다.
   따라서 종료 뒤 활성 held-out cache는 **v2.9**다. 이후 held-out 작업은 판본을 명시하고
   필요한 판을 다시 fetch해야 한다.
5. 완료 뒤 다음 파일을 회신한다. 이름에 날짜·번호가 자동 붙는 runlog는 실제 생성명을
   그대로 알려준다.

   - `test_result/*_log_*_P085_stage10c_heldout_v29_seed2_control.txt`
   - `runs/census/P085_stage10c_v29_fetch.log`
   - `runs/census/YYYYMMDDhhmmss_stage1_heldout.v2.9_independent_s2_stage10c_census.log`
   - `runs/census/stage1_heldout.v2.9_independent_s2_stage10c_census.json`
   - `runs/census/stage1_heldout.v2.9_vs_v3.0_independent_s2_stage10c_compare.json`
