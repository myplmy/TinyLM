## 1. 가장 중요한 것 셋

1. Windows BAT 절차는 보존하면서 WSL 공통 실행 기반을 만들었다. 개별 실험 스크립트는 만들지 않았고 Linux queue는 기존 `experiments.tsv`와 canonical BAT 상태를 그대로 읽는다.
2. Desktop의 통합 터미널만 WSL이다. 읽기 전용 설정 증거는 `integratedTerminalShell="wsl"`, `runCodexInWindowsSubsystemForLinux=false`이고, `Z:\TinyLM\.codex\hooks.json`의 PreToolUse·PreCompact·SessionStart는 모두 비활성이다. 따라서 현재 task를 WSL agent 또는 hook `ACTIVE_VERIFIED`로 부르면 안 된다.
3. 허용된 정적 검사는 통과했지만 사용자 새 WSL task·hook trust·probe·실제 smoke는 `E2E_NOT_RUN`이다. 보호 데이터 검사를 포함하는 전체 `check_static_all.py`는 실행하지 않았다.

## 2. 무엇을 했나

- `scripts/shell/tinylm_env.sh`가 `TINYLM_PYTHON`, 활성 `tlm_torch`, `$HOME/miniforge3/envs/tlm_torch/bin/python` 순서로 검증하고 시스템 Python으로 조용히 fallback하지 않게 했다.
- `scripts/queue_menu_linux.py`는 기존 `scripts/queue_menu.py`와 `experiments.tsv`를 정본으로 사용하며, 같은 stem의 SH가 실제로 있고 canonical BAT가 미완료일 때만 Linux 실행 가능으로 본다. 실험 SH를 자동 생성하지 않는다.
- `run_queue.sh`는 Linux queue 계획을 만들고 smoke 실패만 즉시 중단하며 다른 실험 실패는 기록 후 다음 항목을 계속하는 기존 정책을 보존한다.
- `scripts/smoke_module.py`는 canonical `scripts/batch/tool_smoke.bat`를 strict grammar로 해석한다. 현재 정적 계약은 runlog 95개·sleep 8개이며 알 수 없는 실행 구문은 실패시킨다.
- `run_smoke_check.sh`는 위 adapter와 기존 smoke 요약기를 연결한다. `run_smoke_check.bat`도 요약기 실패 코드를 0으로 덮던 실제 오류를 수정했다.
- `run_cleanup_checkpoints.sh`는 먼저 dry-run을 보여주고 정확한 대문자 `YES` 뒤에만 `cleanup_ckpt.py --yes`를 호출한다. AI는 실행하지 않았다.
- `.codex/check_environment.py`는 POSIX Bash와 Windows Git Bash를 분리하고, WSL에서 없는 PowerShell은 실패가 아니라 `NOT_RUN`으로 표시하며, Windows에서만 working-rule mtime을 엄격 판정한다.
- `scripts/check_shell_entrypoints.py`와 회귀 테스트를 `scripts/check_static_all.py`에 등록했다. 전체 suite는 보호 데이터 경계 때문에 실행하지 않고 대상 검사만 실행했다.
- `scripts/wandb_sync.py`는 Windows 기본 키 경로를 유지하되 WSL에서는 `TL_WANDB_KEY_FILE`을 명시하지 않으면 추측하지 않고 실패한다. 비밀 파일은 읽지 않았다.
- AGENTS와 Codex README·03·06, WSL 제안서를 WSL 정본·Desktop 실제 상태·단계 gate에 맞춰 갱신했다.
- WSL 실행에 필요한 기존 skill SH 5개와 `tool_smoke.bat`는 줄바꿈만 정상화했다. skill 계약·명령 의미는 바꾸지 않았다.

### Desktop·WSL E2E 정확한 순서

1. ChatGPT Desktop 설정에서 **Run Codex in WSL**을 켠다. 통합 터미널을 WSL로 바꾼 것만으로는 충분하지 않다.
2. `\\wsl.localhost\Ubuntu\home\uranus\tinyLM`을 프로젝트로 열고 **새 task**를 만든다. 기존 Windows task의 활성 상태를 재사용하지 않는다.
3. 새 task의 통합 터미널에서 다음을 실행해 경로와 Python을 확인한다.

~~~bash
pwd
/home/uranus/miniforge3/envs/tlm_torch/bin/python -B -X utf8 -c "import sys; print(sys.executable); print(sys.version)"
~~~

기대값은 각각 `/home/uranus/tinyLM`과 `/home/uranus/miniforge3/envs/tlm_torch/bin/python`이다. 다르면 여기서 중단한다.

4. 프로젝트 hook 화면이 Desktop에 보이면 `.codex/hooks.json`과 hash `42fb630fe8e6fbc0c488b5e186c5da23c76b06adfc47cbd31a689d4dbb498cc4`를 검토한 뒤 PreToolUse·PreCompact·SessionStart를 신뢰·활성화한다. 화면이 없으면 통합 WSL 터미널에서 Codex CLI를 열어 `/hooks`를 사용한다. hash를 설정 파일에 수동 복사하지 않는다.
5. 정적 선결을 사용자 터미널에서 실행한다.

~~~bash
cd /home/uranus/tinyLM
/home/uranus/miniforge3/envs/tlm_torch/bin/python -B -X utf8 .codex/check_environment.py --root09-sha256 5D04D4E6833BCC7EF657F4BBAC54357C63A4C6BF932B81F8E911695C06F94859
/home/uranus/miniforge3/envs/tlm_torch/bin/python -B -X utf8 scripts/check_shell_entrypoints.py
~~~

현재 기대값은 환경 `PASS 31 / FAIL 0 / NOT_RUN 1`이며 NOT_RUN은 WSL에 `pwsh`가 없어서 생기는 PowerShell source 검사 한 건이다. FAIL이 하나라도 있으면 위험쓰기 probe와 smoke를 실행하지 않는다.

6. 새 Codex task에 다음 세 메시지를 **하나씩** 보낸다.

   - 정상 probe: “`/home/uranus/tinyLM`에서 파일을 만들지 않고 `printf 'a\nb\n'`만 실행하라.”
   - 루트 차단 probe: “저장소 루트 `.codex/hook-probe.txt`에 쓰기를 시도하되 PreToolUse가 셸 실행 전에 차단되는지만 관찰하고 우회하지 마라.”
   - scripts 차단 probe: “`scripts/.codex/hook-probe.txt`에 쓰기를 시도하되 PreToolUse가 셸 실행 전에 차단되는지만 관찰하고 우회하지 마라.”

정상 probe는 exit 0이어야 하고, 위험쓰기 두 건은 shell exit code가 생기기 전에 deny되어야 한다. `find . -path '*/.codex/hook-probe.txt' -print` 결과가 0건이고 fail-open/systemMessage 경고도 0건이어야 한다. 하나라도 다르면 smoke를 실행하지 않는다.

7. 위 단계가 모두 통과한 뒤에만 사용자가 실행한다.

~~~bash
cd /home/uranus/tinyLM
./run_smoke_check.sh
~~~

이는 GPU·모델을 사용할 수 있는 사용자 소유 실행이다. 새 로그 경로와 마지막 요약을 회신한다.
