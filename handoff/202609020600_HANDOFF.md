## 1. 가장 중요한 세 가지

### 1.1 ★★★**`repeat_where` 는 학습 경로에 한 번도 들어간 적이 없다** — 함정 39 의 재발

사용자가 물었고, 코드를 펼쳐 보니 맞았다.

```
_repeat_schedule (학습)  ->  repeat_mode 만 읽는다
visit_schedule (추론)    ->  R != 1.0 분기에서만 repeat_where 를 읽는다
```

m=16, R=2 에서 스케줄을 펼치면:

| 경로 | 방문 리스트 | |
|---|---|---|
| 학습 `uniform` | `mid + mid` | |
| 추론 `front` | `mid + mid` | ✅**extra==m 이라 정확히 같다** — 그래서 짝이 맞았다 |
| 추론 `back` | `mid + mid` | ✅ 동 |
| ★**추론 `even`** | ★**각 층 제자리 2회** | 🚫★**학습된 적이 없다** |

> ★★**즉 결과 047 단계0 의 `even +0.0992` 는 "even 이 나쁘다" 가 아니라
> "학습 안 한 함수라 나쁘다" 였다.** 판정을 **철회**하고 P062 단계2 가 다시 잰다.
> ✅**`--repeat-mode inplace`** 를 만들었다(추론 `even` 의 학습 짝).

### 1.2 ★★**표준이 확정됐다 — 그리고 052 의 18.3 MiB 를 표준모델에 옮기면 틀린다**

| | 확정 |
|---|---|
| 표준조건 | ★**안 A**(`m100R1c` + `--init-from` + KD 제거, 추가 플래그 없음) |
| 표준 대조군 | **`mC_initonly` 3.6776** |
| ★**표준모델** | ★★**`mC_d36_ag4_nokd`** 3.6848 / fp32 상주 **379.7 MiB** |

🚫★**그런데 결과 052 §3.1 의 "LUT + emb int8 = 18.3 MiB" 는 `m100R1q` 행**이고
그 모델은 **임베딩이 인수분해**돼 있다. **표준모델은 임베딩이 통짜 32,768×768** 이라
같은 계산이 ⚙**약 36 MiB** 가 된다. **여유가 21.7 이 아니라 약 4 MiB** 다.

## 6. 커밋 메시지 제안

**제목**

```
표준조건 A 확정과 재귀 where 축 정정, LUT 참조 구현 착수
```

**본문**

```
REVIEW2 표준을 확정했다. 표준조건은 안 A(m100R1c + --init-from + KD 제거,
추가 플래그 없음), 표준 대조군은 mC_initonly(3.6776), 표준모델은
mC_d36_ag4_nokd(3.6848 / fp32 상주 379.7 MiB)다. B2 안은 폐기한다 —
결과 051 이 무KD 조건에서 opt bf16 의 reserved 이득을 -0.016 GiB 로 쟀고,
KD 조건의 -1.02 는 대부분 할당자 파편화였다.

재귀 where 축을 정정한다. repeat_where 는 학습 경로에 한 번도 들어간 적이
없다. _repeat_schedule 은 repeat_mode 만 읽고 repeat_where 는 visit_schedule
의 추론 분기에만 있다. m=16, R=2 에서 학습 uniform 과 추론 front/back 은
extra==m 이라 우연히 같은 리스트였고, even 만 다르며 그것은 학습된 적이
없다. 따라서 결과 047 단계0 의 even +0.0992 는 even 이 나쁘다는 뜻이 아니라
학습하지 않은 함수를 평가했다는 뜻이다. 추론 even 의 학습 짝으로
--repeat-mode inplace 를 신설하고 P062 단계2 가 다시 잰다.

어텐션 재사용(--reuse-attn-on-dup)을 구현했다. 결과 041 §17 이 복제층 어텐션
출력의 cos 를 0.9882 로 쟀으므로 재귀 두 번째 이후 통과에서 어텐션을 건너뛰고
첫 통과 출력을 재사용한다. 그 층이 KV 의 유일한 소비자면 KV 계산도 건너뛴다.
기본 off 이고 재귀가 아니면 죽은 코드라 비트 동일하다. 학습과 추론 양쪽에
같은 값을 줘야 하므로 paired_eval 에 --match-train-repeat 를 넣어
체크포인트가 학습된 스케줄과 재사용 여부를 그대로 승계하게 했다.

LUT 커널 단계0 을 착수했다. tinylm/model/lut.py 는 5트릿/바이트(1.600 bpw)
패킹과 T-MAC 구조의 참조 matmul 을 담는다. 표를 활성값으로 만들고 가중치로
인덱싱하므로 가중치가 곱셈에 들어가지 않는다. numpy 대조로 패킹 왕복 무손실,
LUT 대 dense 상대오차 1.2e-15, 그룹 스케일 수용을 확인했다. P014B 의 게이트
U2 가 긍정으로 닫혔다. 속도는 일부러 재지 않는다 — 참조 구현은 느리고 그것을
재면 LUT 가 느리다는 틀린 결론이 남는다. 다만 결과 052 의 18.3 MiB 는
m100R1q 행이고 표준모델은 임베딩이 통짜라 약 36 MiB 가 된다.

벤치마크를 전수 구현했다. eval_bench_suite.py 가 13종을 우도·클로즈·생성·
생성저장 네 방식으로 채점하고 fetch_bench_data.py 가 15종을 내려받는다.
docs/methods/11_benchmarks.md §3.2 의 기각을 §6.5 에서 철회했다 — 기각 사유가
전부 "점수가 0일 것" 이었고 그것은 예측이지 기각 사유가 아니다. 원문 조회로
두 가지를 정정했다. BoolQ 의 성공 기준값은 50%가 아니라 다수결 62%이고,
MuSR 지문은 약 1000단어라 seq 1024 에서 대부분 길이 초과로 제외된다.

게이트를 두 층으로 나눴다. check_static_all.py 는 torch·GPU 를 쓰지 않는
검사 11종을 묶어 AI 가 매 갱신 직후 스스로 돌린다. run_smoke_check.bat 은
실제 학습 경로를 도는 동적 게이트로 남고 사용자가 돌린다. 정적은 이름이
있는가를, 동적은 그 경로가 실제로 도는가를 본다.

lint_bat 규칙 셋을 추가했다. 20 은 check_smoke 뒤에 학습 런이 오는 것을
막는다(sm_wqbf16 이 이것으로 오탐됐다). 21 은 무KD 학습에 --no-ckpt 가
없으면 알린다. 22 는 학습 배치에 wandb push 호출이 없으면 알린다.

외부 모델 실사(결과 053)에서 종전 보고를 정정한다. Qwen3.5-0.8B-Base 의
어휘는 248,320 이고 사용자가 말한 248K 가 맞았다 — 내가 인용한 151,936 은
Qwen3 값이었다. Gemma-4-E2B 는 35층 중 20층이 KV 를 공유하고 28층이
sliding 512 이며 KV 헤드가 1개다. Qwen3.5 는 24층 중 18층이 선형 어텐션이다.
둘 다 전역 어텐션을 20~25%로 줄였고 이것은 우리 P057·CLA 축의 외부 증거다.
다만 그들은 KV 캐시를 줄이고 우리는 가중치 상주를 줄이므로 seq 1024 에서
sliding·linear 의 이득은 작다. 어휘를 248K 로 갈아타면 임베딩 상주가
763 MiB 가 되어 표준모델 전체의 두 배가 되므로 외부 토크나이저 가지는
기각을 권고한다.
```
