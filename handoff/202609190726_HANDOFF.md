## 1. 가장 중요한 것 셋

1. **P025B Wc는 방법론 실패로 끝난 로그가 아니다.** 측정 행은 모두 sparse가 느렸지만,
   둘째 형상 M128의 elementwise tolerance가 실패하면서 뒤 형상을 버렸다. 출력 규모에 무관한
   절대오차 단독·fail-fast를 설계결함으로 고쳐 Stage0bWd를 만들었다.
2. **P060B forced 가설은 음성이지만 실용 경로는 살아 있다.** CUDNN/FLASH는 +7.9%/+5.8%로
   문턱 미달이지만 `on_default`는 +0.3%·working memory −37.2%다. default를 후보에서 뺀
   Stage0aW selector를 고쳤고 actual d14 checkpoint gate도 작성했다.
3. **현재 실행 가능 연구 queue는 약 13.3h다.** 승인 목록의 다음 즉시 gate 11개와 P097
   300M 학습 4팔이 존재한다. 48h를 채우지 않은 것은 나머지 본런이 직전 gate에 조건부이기
   때문이며 중복·placeholder SH로 채우지 않았다.

### 2.2 설계결함 교정

- P025B: `rtol/atol`은 near-zero 원소와 출력 규모에 민감하다. 새 gate는 normalized RMS≤0.001,
  max-abs/reference-RMS≤0.01, cosine≥0.999999를 쓰고 legacy assert는 경고로 보존한다. 실패 행이
  있어도 나머지 형상을 끝까지 기록한다.
- P060B: forced backend 이름과 제품 목표를 분리했다. default 또는 forced 중 어느 쪽이든
  속도 +5% 이내·memory ≥10% 절감이면 practical candidate다.
- 로컬 CPU 회귀는 P025 scale-aware 사례와 P060 default-only 후보를 모두 재현했다. 새 GPU
  결과는 사용자 실행 전까지 `NOT_RUN`이다.

### 2.3 `logits_last_only`

생성·TTFT·tok/s·배포 메모리 측정은 마지막 위치 logits만 소비하므로 `true`가 정상이다.
학습과 teacher-forced target NLL은 모든 위치가 필요하므로 `Transformer.forward` 기본 false를
유지한다. `bench_infer`는 last-only가 기본이며 `--full-logits`는 과거 결과 재현용이다.

### 2.4 데이터셋 판단

현재 base model의 대화 불능은 데이터만의 문제가 아니다. SFT가 없으므로 P097은 chat 성공이
아니라 continuation·주제 관련성·한영 gold-margin/accuracy·공통 byte-bpb를 본다. 네 recipe는
기존 cache를 덮지 않고 source token과 val을 50:50으로 고정한다. HF cache runtime gate는
`/home/uranus/tinyLM/HF/{hub,datasets}`를 실제 확인했다.

  이어서 각 보존 로그의 선언된 exit 계약과 실제 수치를 판독한다. P025B Wd와 P060B Wb는
  기존 Wc/Wa 결과를 소급 덮지 않는다.
- **승인 전 금지**: 보호 데이터 접근, GPU·모델·smoke·queue·cleanup 대리 실행, 외부 데이터
  다운로드, `-done.sh` 두 개 삭제, 조건부 full trainer/통합 SH 선제 작성, 루트 09,
  staging·commit·push·PR.
- **상태 언어**: 회수 로그 082·088의 실제 관측, 신규 구현의 `STATIC_ONLY`, 사용자 실행 전
  `E2E_NOT_RUN`을 분리한다. exit 8은 registry에 선언된 경우에만 과학적 음성/HOLD다.
