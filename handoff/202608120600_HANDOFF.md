## 1. ★가장 중요한 것 세 가지

### ① ★★★KD 를 빼는 것이 이 저장소 최대 VRAM 레버다 (결과 038)

P050 네 팔:

| 팔 | 구성 | full-val | reserved | 벽시계 |

| B `mC_kdonly` | KD only | 3.8194 | 12.47 | 123.3분 |

```
부모초기화 몫 = +0.1386      KD 몫 = −0.0032      상호작용 = +0.0176
```

**①이 ②의 43배.** `mC_kdonly` vs `mC_solo` = **+0.0032**(승률 44%) →
**부모초기화 없이 KD 만 하면 아무것도 안 한 것과 같다.**

★★**KD 제거 = reserved −7.41 GiB(−59%) + 품질 −0.0208(더 좋다).**
이 세션의 교사 레버 3개 합(압축교사 −1.88 + 추론모드 −1.03 + bf16옵티 −1.02 = −3.93)의 **1.9배**.

⚠️ **새 사실이 아니다.** 기준표 §7 이 이미 *"KD 이득은 예산↑에서 감소 −0.110 → +0.062 → +0.098"*
이라 했고 **300M 에서 이미 +0.062 = 해로웠다.** **알면서 거의 모든 실험을 KD 로 돌렸다.**

⚠️ **유보 3건**: `--init-from` 은 부모 97.5분 선행(**파이프라인 전체로는 −10.6%**) /
예산이 작으면 KD 가 이긴다(100M 에서 −0.110) / 시드 1개 → **`run_P050_kd_removal_confirm.bat`** 신설.

```python
if q_len == kv_len:                      # 학습·prefill
    o = F.scaled_dot_product_attention(q, k, v, is_causal=True)
else:                                    # KV 캐시 추론
    o = F.scaled_dot_product_attention(q, k, v, attn_mask=mask)
```

| 조건 | 상태 |
|---|---|
| SDPA 사용 | ✅ (Level 1) |
| dtype | ✅ **bf16**(autocast + `apply_rope`/`RMSNorm` 이 `.to(x.dtype)`) |
| `head_dim` | ✅ **64**(768/12) — Flash 지원 |
| 마스크 | ✅ **학습은 `is_causal=True`**(Flash 적격). `attn_mask` 경로는 **KV 캐시 추론 전용** |
| 학습 시 Flash 사용 | **거의 확실히 예** — 다만 **로그로 확인한 적은 없다** |

> ★**문서의 Level 2/3 검증(backend 강제·profiler)은 값싸므로 해 볼 만하다**(1분).
> 하지만 **기대 답은 "이미 켜져 있다"** 이고, 그러면 문서 §21 Case C 로 **속도 이득은 0** 이다.

### 6.2 ★★그런데 문서가 놓친 진짜 문제가 있다 — **GQA `repeat_interleave`**

```python
n_rep = c.n_q_heads // c.n_kv_heads      # 12 / 3 = 4
if n_rep > 1:
    k = k.repeat_interleave(n_rep, dim=1)   # (B,3,T,64) -> (B,12,T,64)
    v = v.repeat_interleave(n_rep, dim=1)
```

**K·V 를 4배로 물리적으로 복제해서 SDPA 에 넘긴다.** torch 2.5+ 는
`scaled_dot_product_attention(..., enable_gqa=True)` 로 **복제 없이** 처리한다(우리는 **torch 2.10**).

**회계**: 복제 후 k = `8×12×1024×64×2B` = **12.6 MB**, k+v = 25.2 MB, **× 20층 = 약 0.5 GB**
(+ backward 를 위해 살아 있다). **GQA 의 존재 이유가 KV 를 3배로 줄이는 것인데
어텐션 직전에 되돌리고 있다.**

| | 기대 |
|---|---|
| VRAM | **약 −0.4 ~ −0.5 GiB** |
| 속도 | 대역폭 절감분(미지, 아마 작다) |
| 코드 | **3줄** |
| 위험 | ⚠️ `enable_gqa=True` 가 **Flash backend 를 유지하는지** 확인 필요. 수치는 비트 동일 아닐 수 있다 |

> ★**이것이 (5)에서 나온 유일한 실행 가치가 있는 항목**이고 **문서에는 없다.**
> **F-1 로 허가를 구한다**(§9).

### 6.3 문서 자체의 문제 3건

| # | 무엇 |
|---|---|
| 1 | **`attn_mask` 경로를 학습 경로로 오해할 위험.** 문서 §8 이 "GQA/CLA 때문에 Flash 가 거부되는지" 를 걱정하는데, 우리 학습은 `is_causal=True` 라 무관하다. **거부되는 것은 추론 경로**다 |
| 2 | **QK-norm·RoPE 가 `.float()` 를 거친다는 점을 안 봤다.** `apply_rope` 가 fp32 로 계산하고 되돌린다 — dtype 확인 시 여기를 봐야 한다 |
| 3 | **분량 대비 산출이 낮다**(23KB, 24절). *"먼저 확인 → 그다음 측정"* 인데 §1 확인은 **코드 5줄로 끝난다.** 실제 발견(§6.2)은 문서에 없다 |
