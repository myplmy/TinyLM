## 1. 가장 중요한 것 셋

1. **정적 명명 차단은 해소됐다.** 사용자 승인으로 P104A Windows BAT를 Stage1B로 개명하고 계획·TSV·runlog·WSL 안내를 맞췄다. BAT 명명·CRLF·큐 감사와 codex-safe 정적 검사는 PASS다. 이는 현재 코드의 smoke나 Windows/WSL 모델 E2E PASS가 아니다.
2. **A/B/C는 승인·착수됐으나 실제 학습 가속/품질 기능 완료가 아니다.** 수학 fixture와 opt-in QK gain은 구현했고, fused S1·실제 MTP aux/trainer·Transformer X1/X2/X3 RAM 경로는 남았다. 기능 gate SH는 사용자가 나중에 돌릴 파일이지 실행 증거가 아니다.
3. **SFT 세 계보의 비교는 설계됐지만 학습 0건이다.** A는 기존 32k 부모, B는 chat32 신규 어휘/신규 사전학습 부모 필요, C는 공통 한영 원답안으로 기존 최선 부모를 먼저 정해야 한다. 파일 존재나 영어 full-val만으로 C를 확정하지 않는다.

### 2.1 handoff/audit 최초 34건 전수 판정과 현재 35건

[audit/README.md](audit/README.md)의 직접 계약은 세션 결산의 TINYLM_STATIC_AUDIT_V1 JSON과 진행 중 큐 잠금의 PARTIAL JSON이다. 그 밖에 사용자 승인된 frontier/결과 closure의 기계 증거와 그 설명 MD는 실험 계획·결과 흐름의 소유 문서다. 34건(23 JSON, 11 MD) 중 **명시된 정적 감사 양식이 아닌 임의 수동 서술 4건**은 CHECKPOINT_REVIEW, ORIGINAL6_REAUDIT, DONE_SH_REVIEW, REPRO_DELETE_REVIEW(모두 audit/의 WIP_20260923 또는 WIP_20260924 접두사)다. 이들은 각각 닫힌 WIP/핸드오프의 근거로 참조되어 있어 사용자 승인 없는 삭제는 부적절하다. 이미 정본 결과/핸드오프에 중복 없는 판단이 옮겨졌는지 확인한 후 정확한 파일별 삭제 승인을 받아야 한다. 이번에는 삭제·이동0, 새 임의 audit MD0. CONTINUATION_FRONTIER와 R1의 MD 본문은 byte 동일하나 JSON은 timestamp/TSV hash가 달라서 두 세트의 안전 삭제를 추론하지 않는다.

최초 전수감사 뒤 이 세션의 정적 감사 JSON 1건이 추가돼 현재 폴더는 **35건(JSON24·MD11)**이다. 최초 34건 중 임의 수동 MD4건의 보존 판정은 변하지 않았고 새 임의 설명 MD는 만들지 않았다.

| [WIP_20260923_CHECKPOINT_REVIEW.md](audit/WIP_20260923_CHECKPOINT_REVIEW.md) | 닫힌 원장의 checkpoint 판단 근거 | 현 상태 보존, 정확한 중복/인용 대조 뒤 별도 삭제 승인 |

앞으로 audit/에는 **기계 생성 증거의 schema·WIP/session·검사 범위·보존 이유가 있는 기록만** 자동 추가한다. 일반 분석·사용자 설명은 핸드오프 §2나 실제 결과/계획 정본이 소유하고, 중복 snapshot은 참조 사슬과 hash를 확인한 뒤에만 정리한다.

### 2.2 제안서·코드·논문

- [A](../proposal/20260923_TinyLM-M0-C0-E384-QK-MTP-지능향상-제안서-approved-on-going.md), [B](../proposal/20260923_TinyLM-학습시간-T0-T1-S1-S3-최적화-제안서-approved-on-going.md), [C](../proposal/20260923_TinyLM-계산량-재설계-X1-X3-추가가속-제안서-approved-on-going.md)를 사용자 승인에 따라 진행 중으로 이관했다. 원안과 앞선 타당성 분석은 보존하고 §11에 이번 실제 구현·남은 조건을 누적했다. 이전 핸드오프의 옛 파일명 링크는 당시 기록으로 보존하며 링크 검사에서 INFO로 분리된다.
- A: 기존 emb_rank와 연결된 새 QK gain은 기본 off이며 per-layer/head τ=1 초기값, WD0, LR×0.1 그룹을 구현했다. E384 함수 보존과 MTP horizon/EOS 계산은 CPU reference다. 실제 checkpoint E384 migration, MTP 보조 head/주 학습 loss 결합은 아직 없다.
- B: factorized CE 청크, update-local VJP, S3의 전체 valid-token 분모 HT 추정량은 CPU reference이며 기존 trainer 속도 경로를 바꾸지 않았다. S1 fused kernel·S2 STE 캐시·S3 trainer 통합은 미구현이다.
- C: X1 동일 prefix gradient의 작은 reference, X2 FFN 물리 tile 연산, X3 INT8 per64 scale quantizer를 분리했다. 20M×768 기준 16.32GB는 산술값이며 실제 RAM 단일 사본·RSS·whole-wall·품질은 NOT_RUN이다.
- TTPO 원문은 Qwen3 1.7B/4B/8B, test-time 적응, 다수 rollout/교사 점수, 4×H20 등의 조건이다. 수치와 재현 전제는 리뷰08-2 §6에 기록했다. TinyLM 100M급·단일 GPU·기초 SFT 미확립 조건에 즉시 높은 효과가 입증된 모듈은 없어 조건부 신규 제안서는 만들지 않았다.
