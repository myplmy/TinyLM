## 1. 가장 중요한 것 셋

1. **1차 원인은 저장소의 Windows handler였다.** Python guard는 같은 이벤트를 deny했지만,
   기존 `powershell ... -Command "..."`를 Codex식 `cmd /C "<handler>"`로 실행하면
   exit 1로 guard에 도달하지 않았다. OpenAI Codex
   [#38168](https://github.com/openai/codex/issues/38168)의 embedded-quote 무동작과 일치한다.
2. **저장소측 교정과 로컬 회귀는 끝났다.** quote-free 중첩 `cmd`, Git 루트 해석,
   PowerShell wrapper를 적용했고 루트·`scripts` cwd의 실제 outer-quote 프로세스가
   모두 deny했다. 훅 테스트 16/16, Codex 환경 전용 P7 20/20이다.
3. **P8 완료는 아니다.** 1차 새 세션에서 `AGENTS.md`와 17개 스킬 발견만 확인됐고
   차단 probe는 0/2였다. 변경 hash를 다시 신뢰한 새 세션 재검증 전 상태는
   `STATIC_ONLY / E2E_NOT_RUN`이며, 보호 데이터·GPU·학습·모델·프로젝트 스모크는 `NOT_RUN`이다.

## 4. ⚠️조심할 것 — 다음 세션이 밟을 자리

- `.codex/hooks.json`이 바뀌었으므로 이전 신뢰 hash로는 충분하지 않다. Codex를 완전히
  재시작하고 `/hooks`에서 새 내용을 직접 검토·신뢰한 뒤 P8을 다시 수행한다.
- 로컬 프로세스 테스트는 handler가 실행되면 올바르게 deny함을 보인 것이지, Codex 런타임이
  실제 `PreToolUse`를 dispatch했다는 증거가 아니다. Code Mode 경로에는 별도 공개 이슈
  [#23411](https://github.com/openai/codex/issues/23411)가 남아 있다.
- 재검증에서도 deny가 없으면 matcher를 임의로 넓히거나 `ACTIVE_VERIFIED`로 승격하지 않는다.
  실제 사용 도구 경로, Codex Desktop/CLI 버전, `/hooks` 상태를 기록해 런타임 결함으로 분리한다.
- Windows handler는 훅 명령이 세션 cwd에서 실행되는 계약 때문에 Git 루트에서 wrapper를 찾는다.
  단순 `.codex/hooks/...` 상대경로로 되돌리지 않는다.
- 환경 P7 첫 샌드박스 실행의 19/20은 5개 셸 파일의 Git Bash 신호 파이프 `Win32 error 5`
  때문이며 소스 구문 실패가 아니다. 같은 검사를 제한 해제 후 재실행한 최종값은 20/20이다.
- `scripts/check_static_all.py`는 보호 데이터 검사를 포함하므로 실행하지 않았다.
  환경 20/20을 프로젝트·모델·데이터 검증으로 승격하지 않는다.
- 루트 09는 기준선 해시만 확인했고 수정·복제하지 않았다. 데이터셋 팀 경로는 접근 0건이다.
- 삭제·staging·commit·push·PR은 수행하지 않았다. §8은 제안문일 뿐 실행 증거가 아니다.
