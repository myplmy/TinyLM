## 1. 지시 (0) — 로그에 안 남는 `echo`

### 1.1 원인

`runlog.py` 는 **자기가 실행한 것**만 기록한다. 배치가 `echo` 로 찍는 헤더·경고·판정 안내는
**cmd 창에만 뜨고 로그에는 한 줄도 안 남는다.**

★`run_recover_dense_best.bat`(P054)이 정확히 그랬다 — 콘솔에는 *"정본을 덮어쓰지 않는다 /
best 를 3.7797 과 비교하라 / 설치는 이 copy 명령"* 이 다 떴는데 **로그 309줄 어디에도 없다.**
→ 로그를 나중에 읽는 사람(**대개 다음 세션의 AI**)은 **판정 기준을 못 본다.**

### 1.2 조치 — **중복이 아니라 1:1 치환**

`runlog.py --note` 는 파일에 쓴 뒤 `sys.stdout.write(body)` 로 **콘솔에도 흘린다.**
즉 `echo X` → `--note "X"` 는 **같은 말을 두 번 적는 것이 아니다**(그러면 함정 18 이 된다).

| 조치 | 내용 |
|---|---|
| **`lint_bat.py` 규칙 13** | 실험 배치의 정보성 `echo` 를 경고. 허용 = `echo.` · 구분선 · **실패 라벨 블록 안** |
| **전 배치 전환** | 9개 배치 **31개 echo 블록** → `--note`. 남은 경고 **0** |
| **`run-batch` 스킬 R13** | 규칙·사례·허용 범위 |

## 2. 지시 (1) — `YES` 를 눌러도 취소되던 버그

```
if not "!TL_OK!"=="YES" goto CANCEL      ← setlocal enabledelayedexpansion 이 없었다
```

cmd 가 **문자열 `"!TL_OK!"` 와 `"YES"` 를 비교**했다. 항상 불일치 → **YES 를 입력해도 CANCEL.**

→ **`lint_bat.py` 규칙 14**(에러) + `run-batch` 스킬 R14. **린터가 실제로 이 버그를 잡았다.**

## 5. 지시 (9) — 5비트 패킹과 3:4 희소의 가치

### 5.1 ✅ **사용자 지적이 맞다**

★**상주 메모리는 bpw 를 보지 않는다**(결과 016 §7.2). 상주 = 유니크삼진 × 4B × 2벌.
**3:4 희소는 저장만 줄인다.** 그리고 **우리는 저장 포맷으로 배포한 적이 없다** —
`to_int8()`(단계3)은 파라미터당 **8비트**로 이론값 1.25bpw 의 **6.4배**다.

> **→ 5비트 패킹(단계4)이 없으면 3:4 의 이득이 실물로 나타나는 지점이 아예 없다.**

### 5.2 ⚠️ **그런데 "그러므로 단계4 를 먼저" 는 자동으로 따라오지 않는다**

단계4 는 **커널을 요구**한다(`code*alpha` 를 fp32 로 되돌리면 이론값의 7.6배에서 멈춘다).
그리고 `custom_ternary_kernel.md` §4 가 *"현재 상주 최대항은 임베딩·어텐션이라 우선순위 낮음"*
으로 판정한 상태다.

### 5.3 ★권고 — **커널 전에 "패킹 회계 시뮬레이터"(GPU 0)**

커널 없이 **① 실제 비트 패킹 파일 크기 ② numpy/torch 만으로 언팩 비용** 을 재면
**"단계4 가 얼마를 벌고 얼마를 내는지" 를 학습 0 으로 확정**할 수 있다.
→ **P034 단계3.5** 신설 제안. **그 결과가 좋으면 커널을 만든다.**

### 5.4 결과 028 제목 — ✅ 갱신
