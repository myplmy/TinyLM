## 1. 한 줄

★★**이번 실행은 `tinylm` 패키지 import 실패로 mask/gradient 연산 전에 종료됐다.** 따라서 STE, inactive regrowth score, birth/death 보존은 실패가 아니라 `NOT_RUN`이며, 진입 경로를 고친 새 Stage0c 재실행이 필요하다.

## 2. 실패 지점과 원인

```text
File "z:\TinyLM\scripts\diag_dynamic_sparse_contract.py", line 15, in main
  from tinylm.model.sparse_connectivity import connectivity_weight
ModuleNotFoundError: No module named 'tinylm'
```

직접 실행된 `scripts/*.py`가 형제 디렉터리 `tinylm/`을 import하려면 저장소 루트 bootstrap이 필요하지만 이 진단 파일에 빠져 있었다. 따라서 CUDA나 dynamic sparse 수학을 평가하기 전에 Python module 탐색에서 끝났다.

## 3. 조치와 현재 증거

- `scripts/diag_dynamic_sparse_contract.py`가 import 전에 저장소 루트를 `sys.path`에 넣도록 수정했다.
- `scripts/check_hf_redirect.py`, `python -m py_compile`, `git diff --check`는 통과했다.
- Codex는 CUDA 진단을 실행하지 않았다. 수정 후 과학적 게이트는 새 Stage0c 사용자 실행 전까지 `NOT_RUN`이다.

나왔지만, 그 뒤 loss와 `weight.grad`의 finite 검사 및 모든 계약값이 정상 출력돼 이번 판정을
무효화하지 않는다. 향후 진단 정리 시 `float(loss.detach())`로 경고를 없앨 수 있으나, 이번
결과 회수 범위에서는 코드를 바꾸거나 동일 진단을 재실행하지 않는다.
