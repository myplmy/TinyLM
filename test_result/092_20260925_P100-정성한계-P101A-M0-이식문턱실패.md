## 1. P100 Stage0W 정성 능력 패널 — 첫 실행 PASS, 같은 출력 재시도만 FAIL

- 원본: `092_log_20260924_P100_Stage0W_capability_baseline.txt`에는 **두 번의 실행**이 시간순으로 있다. 21:26 첫 실행은 종료코드0으로 control-v2/FineWeb2 × 9개 한영 문항 × base/Q&A = 36개 원답안을 저장했고, 22:31 같은 출력 경로 재시도는 `FileExistsError` 종료코드1이다. 두 번째 실패는 이미 저장한 첫 결과를 지키는 write-once 동작으로, 모델 품질 실패나 첫 출력 손상을 뜻하지 않는다. 이미 첫 실행이 성공했으므로 별도 동일조건 재실행은 필요하지 않다.
- 로그 인쇄 답안에서 control-v2의 한국어 질문은 `같이 보기`·`각주`·`외부 링크` 등 위키 표제와 반복이 빈번했다. FineWeb2는 일부 파란 상자 `417` 맥락을 되짚었으나 답변을 반복하거나 지시한 JSON 형식을 지키지 못했다. 영문·한국어 모두 사실/형식/논리/멀티턴을 **안정적으로** 수행한다는 근거가 없다. 정성 표본 36개를 자동 정확도 점수나 데이터셋 단독 인과효과로 변환하지 않는다.
- 출력 JSONL 원답안 36행은 §6에서 직접 판독했다. 자동 정확도 채점과 일반화 판정은 `NOT_RUN`이다.

## 7. 2026-09-25 P101A Stage1Wb 독립 팔 — E384만 원 문턱 실패

원본: `092_log_20260925_P101A_Stage1Wb_m0_arm_attribution.txt`. 사용자가 고정 M0 SHA 검사를 통과한 뒤 같은 9-token 입력과 기존 `1e-5` 문턱에서 E384·QK gain·MTP를 각각 독립 이식해 CPU로 실행했다. 종료코드 1은 아래 E384 주 로짓 기능 문턱의 실패이며, 다른 두 팔이나 GPU 학습의 실패를 뜻하지 않는다.

| 독립 팔 | 주 logits 최대 절댓차 | NRMS | top-1 변경 | 이 로그의 기능 판정 |
|---|---:|---:|---:|---|
| E384 | 1.23977661e-5 | 4.01000563e-7 | 0 | **FAIL**: 1e-5 초과 |
| QK gain | 0 | 0 | 0 | 이 입력의 주 로짓 정합 PASS |
| MTP | 0 | 0 | 0 | 이 입력의 주 로짓 정합 PASS; 배포용 aux 제거 차0 |

진단기는 각 팔의 신규 파라미터 gradient 존재도 검사하고 실패 항목에 넣는다. 마지막 실패 목록은 `e384:main_logits` 하나였으므로 gradient 존재 검사는 통과했지만, 크기·학습 효과는 출력되지 않았다. E384의 기존 열을 복사하고 새 `emb_up` 열을 0으로 시작하는 이식은 실수 산술상 같은 함수를 목표로 한다. 그러나 rank 256→384의 FP32 GEMM에서 감소 순서가 바뀌었는지, 다른 실제 경로가 다른지는 **이 로그만으로 확정할 수 없다**. 작은 NRMS·top-1 동일을 근거로 사전 문턱을 1.3e-5로 올리지 않는다.

후속 `run_P101A_Stage1Wc_e384_roundoff_attribution.sh`는 고정 부모의 old-block/zero-new-U, 입력 embedding·body hidden·공통 hidden 헤드의 FP32 차이와 FP64 수학적 지도 차이를 나눠 기록하는 **별도 사용자 CPU 모델 진단**이다. 작성 및 tensor-only self-test만 PASS, 실제 M0 측정은 `NOT_RUN`이다. 그 진단의 exit0은 측정 완료일 뿐 Stage1Wb 실패를 소급 PASS로 바꾸지 않는다. E384 학습은 HOLD; QK/MTP도 이 한 입력의 함수 확인만으로 100M 품질·속도를 주장하거나 자동 학습하지 않는다.

## 8. 2026-09-25 P101A Stage1Wc — E384 오차 위치 분해, 기존 기능 FAIL 유지

원본 `092_log_20260925_P101A_Stage1Wc_e384_roundoff_attribution.txt`는 사용자 CPU 고정 M0 진단이며 학습·GPU·정식 품질 평가가 아니다. 이전 §7의 E384 `1e-5` 문턱을 변경하지 않았다. 구 E256 블록은 bit-identical이고 새 E384 projection 열은 0으로 확인됐다.

| seed | FP32 입력 | FP32 body | 공통 hidden에서 FP32 head | 전체 FP32 logits | FP64 입력 / 공통 hidden head | top-1 변경 |
|---:|---:|---:|---:|---:|---|---:|
| 7 | 2.5331974e-7 | 1.90734863e-6 | 9.53674316e-6 | **1.23977661e-5** | 0 / 2.66453526e-15 | 0 |
