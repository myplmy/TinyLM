## 1. P100 Stage0W 정성 능력 패널 — 첫 실행 PASS, 같은 출력 재시도만 FAIL

- 원본: `092_log_20260924_P100_Stage0W_capability_baseline.txt`에는 **두 번의 실행**이 시간순으로 있다. 21:26 첫 실행은 종료코드0으로 control-v2/FineWeb2 × 9개 한영 문항 × base/Q&A = 36개 원답안을 저장했고, 22:31 같은 출력 경로 재시도는 `FileExistsError` 종료코드1이다. 두 번째 실패는 이미 저장한 첫 결과를 지키는 write-once 동작으로, 모델 품질 실패나 첫 출력 손상을 뜻하지 않는다. 이미 첫 실행이 성공했으므로 별도 동일조건 재실행은 필요하지 않다.
- 로그 인쇄 답안에서 control-v2의 한국어 질문은 `같이 보기`·`각주`·`외부 링크` 등 위키 표제와 반복이 빈번했다. FineWeb2는 일부 파란 상자 `417` 맥락을 되짚었으나 답변을 반복하거나 지시한 JSON 형식을 지키지 못했다. 영문·한국어 모두 사실/형식/논리/멀티턴을 **안정적으로** 수행한다는 근거가 없다. 정성 표본 36개를 자동 정확도 점수나 데이터셋 단독 인과효과로 변환하지 않는다.
- 출력 JSONL 원답안 36행은 §6에서 직접 판독했다. 자동 정확도 채점과 일반화 판정은 `NOT_RUN`이다.

## 3. P101A Stage1W 고정 M0 결합 이식 — 기능 FAIL

- 원본: `092_log_20260924_P101A_Stage1W_m0_migration_gate.txt` · 종료코드1. 부모·토크나이저·cache 검사를 지난 뒤 결합 E384+QK+MTP 대상의 주 logits `max_abs=1.2397766e-05`가 사전등록 `1e-5`를 초과했다. 그 이후 aux/export/gradient 단계는 실행되지 않았다.
- 기존 게이트가 **승인된 독립 E384/QK/MTP 팔이 아니라 세 축 결합 모델을 먼저 검사**한 설계 공백도 확인했다. 1.24e-5가 형상 변경의 FP32 누적 반올림인지 각 팔 함수 오류인지는 원본 로그 하나로 분리할 수 없다. 문턱을 사후 완화하거나 기능 PASS라고 쓰지 않는다.
- 같은 고정 M0에서 독립 팔별 `max_abs`·NRMS·top1 변화·신규 gradient를 분해하는 [Stage1Wb](../test_result/092_20260925_P100-정성한계-P101A-M0-이식문턱실패.md) 진단기/런처를 준비했다. 사용자의 새 모델 로그는 `NOT_RUN`; 어느 팔이든 기존 1e-5를 넘으면 그 팔의 Stage2 학습은 보류한다.

## 7. 2026-09-25 P101A Stage1Wb 독립 팔 — E384만 원 문턱 실패

원본: `092_log_20260925_P101A_Stage1Wb_m0_arm_attribution.txt`. 사용자가 고정 M0 SHA 검사를 통과한 뒤 같은 9-token 입력과 기존 `1e-5` 문턱에서 E384·QK gain·MTP를 각각 독립 이식해 CPU로 실행했다. 종료코드 1은 아래 E384 주 로짓 기능 문턱의 실패이며, 다른 두 팔이나 GPU 학습의 실패를 뜻하지 않는다.

| 독립 팔 | 주 logits 최대 절댓차 | NRMS | top-1 변경 | 이 로그의 기능 판정 |
|---|---:|---:|---:|---|
| E384 | 1.23977661e-5 | 4.01000563e-7 | 0 | **FAIL**: 1e-5 초과 |
| QK gain | 0 | 0 | 0 | 이 입력의 주 로짓 정합 PASS |
| MTP | 0 | 0 | 0 | 이 입력의 주 로짓 정합 PASS; 배포용 aux 제거 차0 |

진단기는 각 팔의 신규 파라미터 gradient 존재도 검사하고 실패 항목에 넣는다. 마지막 실패 목록은 `e384:main_logits` 하나였으므로 gradient 존재 검사는 통과했지만, 크기·학습 효과는 출력되지 않았다. E384의 기존 열을 복사하고 새 `emb_up` 열을 0으로 시작하는 이식은 실수 산술상 같은 함수를 목표로 한다. 그러나 rank 256→384의 FP32 GEMM에서 감소 순서가 바뀌었는지, 다른 실제 경로가 다른지는 **이 로그만으로 확정할 수 없다**. 작은 NRMS·top-1 동일을 근거로 사전 문턱을 1.3e-5로 올리지 않는다.

후속 `run_P101A_Stage1Wc_e384_roundoff_attribution.sh`는 고정 부모의 old-block/zero-new-U, 입력 embedding·body hidden·공통 hidden 헤드의 FP32 차이와 FP64 수학적 지도 차이를 나눠 기록하는 **별도 사용자 CPU 모델 진단**이다. 작성 및 tensor-only self-test만 PASS, 실제 M0 측정은 `NOT_RUN`이다. 그 진단의 exit0은 측정 완료일 뿐 Stage1Wb 실패를 소급 PASS로 바꾸지 않는다. E384 학습은 HOLD; QK/MTP도 이 한 입력의 함수 확인만으로 100M 품질·속도를 주장하거나 자동 학습하지 않는다.

## 8. 2026-09-25 P101A Stage1Wc — E384 오차 위치 분해, 기존 기능 FAIL 유지

원본 `092_log_20260925_P101A_Stage1Wc_e384_roundoff_attribution.txt`는 사용자 CPU 고정 M0 진단이며 학습·GPU·정식 품질 평가가 아니다. 이전 §7의 E384 `1e-5` 문턱을 변경하지 않았다. 구 E256 블록은 bit-identical이고 새 E384 projection 열은 0으로 확인됐다.

| seed | FP32 입력 | FP32 body | 공통 hidden에서 FP32 head | 전체 FP32 logits | FP64 입력 / 공통 hidden head | top-1 변경 |
|---:|---:|---:|---:|---:|---|---:|

## 10. 2026-10-12 SFT MTP·선택형 추론 구현 — CPU 계약, 실제 학습효과는 미실행

## 15. 2026-10-21 Stage3i — 문맥 교과 MTP와 검산풀이의 준비 분모를 실제 확인했다

### 15.1 목적과 이전 실험의 차이

과거 동결8M×4epoch의 scratch/parent×NTP/MTP 네 팔은 이미 실제 완료했다(§11). 이번 준비를 MTP를 처음 실험하는 것처럼 설명하지 않는다. 새 네 팔은 **기존 Broad22,528행의 명시문맥 교과를 재사용**하되 MTP 엔진의 assistant 턴 마스크를 적용하고 보조 MTP 목적을 비교한다. 검산풀이는 별도4096 코드 소유 root에서 직접답 대 짧은 중간 상태 지도를 비교한다. 그128회 본학습은 과거 fixture/기한 문제로 실행하지 못했으므로 이번에도 미실행을 품질 음성으로 재표시하지 않는다.

### 15.2 실제 준비 설정과 측정

원형은 `092_log_20261021_P101A_Stage3jW0b_parent_mtp_native_path_cost.txt`, `092_log_20261021_P101A_Stage3kW0_direct_cost.txt`, `092_log_20261021_P101A_Stage3kW0b_trace_cost.txt`다. 수치 정본은 각각 `test_result/evidence/p101a_sft_mtp_cleanbilingual_v3_s1337/calibrate_parent_mtp/report.json`, `p101a_sft_mtp_verified_direct_v3_s1337/calibrate_parent_ntp/report.json`, `p101a_sft_mtp_verified_trace_v3_s1337/calibrate_parent_ntp/report.json`이다. 여기서 전체초에는 실제 인코딩·모델·compile·업데이트가 포함되지만 선결 해시 검산·최종 report 직렬화는 제외된다. 외삽은 **본 업데이트만**이며 전체 평가·시작·저장까지 완료하는 시간의 보증이 아니다.

부모 MTP의 horizon2/3/4는 각각32/32회 nonzero gradient, 보조 목적 전체도32/32회였다. 실제 추가 head tensor는2,359,296bytes(2.25MiB)이며 세 head 각0.75MiB다. 따라서 보조 head가 손실과 gradient에 연결되어 업데이트되는 것은 확인했다. 그러나 NTP 대응팔·본704회·실제 첫답 평가는 이번 추가 실측에서 실행하지 않았으므로 **MTP가 지능을 높였다는 판정은 NOT_RUN**이다. 직접답/풀이의 grad max는 각각15.947/4.081이므로 비용 통과를 학습 안정성 보증으로 해석하지 않는다. 풀이의 더 많은 target량도 그대로 남는다.

### 16.3 이미 성공한 비용을 다시 덮어쓰려는 런처 경로를 보완했다

기존 SH는 매번 calibrate를 먼저 호출했다. 성공한 report가 존재하면 write-once 방지가 동작해 FileExists/HOLD가 되고, 그 팔의 본학습까지 skip할 수 있었다. `scripts/check_p101a_clean_cost.py`는 기존 report만 읽어 현재 전체 code SHA·코퍼스 SHA·팔·학습률·배치·32회 시간/분모·CP 미저장·기대 본업데이트를 검산한다. **없으면 최초 비용 실행, 같으면 재사용, 불일치면 본학습 금지**다. 원래 train 엔진의 same-code/corpus 검사와 학습 수식은 그대로다.

실제 검증은 `092_log_20261021_P101A_Stage3jW1_cost_reuse_cpu.txt`의8회귀와 `092_log_20261021_P101A_Stage3jW2_cost_reuse_mtp.txt`, `092_log_20261021_P101A_Stage3jW2_cost_reuse_direct.txt`, `092_log_20261021_P101A_Stage3jW2_cost_reuse_trace.txt`의 세 실물 report 읽기 검산이다. 모델·GPU·report 쓰기0으로 모두 통과했다. main SH 두 개는 아직 본실행하지 않았으므로 `-done` 처리하지 않는다. 새 학생의 실제 일반대화·벤치마크·부모 대비 개선은 여기서 보고할 수 없다.
