## 4. 조치 — SVD 절단 이식 (구현 완료)

난수 대신 **부모의 실효 임베딩을 최적 저랭크 근사**로 이식한다.

factorized embedding 의 실효 가중치는 두 행렬의 곱이다:

```
W = emb(V × E) @ emb_up(E × dim)          shape (32768, 768), 랭크 ≤ E
```

학생의 `E' < E` 가 표현할 수 있는 **최선**은 `W` 의 랭크 `E'` 최적 근사이고,
Eckart–Young 정리로 그것은 **상위 `E'` 특이값**이다:

```
W ≈ U_k S_k V_k^T   →   emb' = U_k √S_k ,  emb_up' = √S_k V_k^T
```

- `√S` 로 나눠 갖는 것은 두 인자의 스케일을 맞춰 초기 gradient 를 고르게 하려는 것이다
- **`emb` 만 절단하면 안 된다** — 헤드가 tie 돼 있어 출력 쪽이 깨진다. **곱 `W` 를 근사**해야 한다
- 로그에 **보존된 스펙트럼 에너지 %** 와 σ₁/σ_k/σ_E 를 찍는다 → **E=128 이 얼마나 잃는지가
  학습 전에 보인다.** 에너지가 예컨대 99% 면 E=128 은 애초에 값싼 선택이다

★ **검산 완료**(numpy, torch 없이): 재구성이 **최적 랭크-k 근사와 정확히 일치**하고
상대오차가 **Eckart–Young 하한과 소수점까지 같다**(0.405722 = 0.405722).
난수 초기화의 상대오차는 **1.0136**(= 정보 0) — **이 이식이 걷어내는 핸디캡의 크기가 그것이다.**

⚠️ **이 함수가 E=128 을 공짜로 만들지는 않는다.** 로짓 랭크가 `E'` 로 제한되는 **구조적** 한계는
그대로 남는다. 하는 일은 **P046 을 "판정 불가" 에서 "판정 가능" 으로 옮기는 것**뿐이다.

## 9.1 ⚠️ 먼저 — 1차 시도가 shape 오류로 죽었다 (사용자 수정)

`log_20260808_P046_mC_e128svd-error.txt` (⚠️**파일은 남아 있지 않다** — 오류 로그라 삭제됐다. 아래 발췌가 유일한 기록이다):

```
RuntimeError: mat1 and mat2 shapes cannot be multiplied (32768x256 and 768x256)
  at  W = (te.float() @ teacher.emb_up.weight.float())
```

**내(AI) 구현 오류다.** `nn.Linear(E, dim)` 의 `weight` shape 은 **`(out, in) = (dim, E) = (768, 256)`** 인데
`(V, E) @ (dim, E)` 로 곱하려 했다. **전치가 빠졌다.**

**사용자 수정 2건을 검증했다 — 둘 다 옳다:**

| # | 수정 | 검산 |
|---|---|---|
| 1 | `W = te.float() @ teacher.emb_up.weight.float()**.T**` | `(32768,256) @ (256,768) = (32768,768)` ✅ 실효 임베딩 `W` 의 정의(`emb_up(x) = x @ weight.T`)와 일치 |
| 2 | `emb_up' ← (r[:,None] * Vh[:k])**.T**` | `Vh[:k]` = `(128,768)` → `.T` = `(768,128)` = `nn.Linear(128,768).weight` 의 shape ✅ |

**검산 근거**: `full_matrices=False` 이면 `W (32768,768)` → `U (32768,768)`, `S (768)`, `Vh (768,768)`.
`emb' = U[:,:128] * r` → `(32768,128)` = `student.emb.weight` ✅ / `emb_up'` → `(768,128)` ✅.
**두 수정 없이는 어떤 조합으로도 shape 이 맞지 않는다.** 사용자 수정이 유일한 정답이다.

> ⚠️ **내가 놓친 이유**: 함수 docstring 에 `emb_up(E × dim)` 이라 적어 두고 코드에서는
> `nn.Linear` 의 `(out, in)` 규약을 따랐다. **문서의 표기와 코드의 규약이 어긋난 상태로 썼다.**
> 그리고 **`check_attrs`·`check_call_kwargs` 는 shape 을 안 본다** — 이건 **스모크만 잡을 수 있었고,
> `_svd_emb_init` 은 `--emb-rank` 를 바꾼 런에서만 발화하므로 `run_smoke_check.bat` 에도 안 걸린다.**
> → **함정 후보: "조건부로만 실행되는 경로는 스모크가 못 잡는다"**(§9.6).

⚠️ **잔여 표기 결함 1건(무해)**: 인쇄가 `σ_{k_t}` 를 `S[-1]`(= σ_768 ≈ 0)로 찍는다.
로그의 `σ_256 0.000` 은 **σ_256 이 아니라 σ_768** 이다(랭크 ≤ 256 이라 257 이후는 0).
**수치 판정에는 영향 없다**(`kept` 는 제곱합 비라 0 항이 무해). 표기만 정정 대상.

**★그런데 결과 039(P052)가 판정을 더 날카롭게 만든다.** 이 조건의 시드 노이즈가 **+0.0006** 이므로
**+0.0645 는 노이즈의 108배** 다 — *"분해능 근처라 애매하다"* 가 아니라 **명확한 대가**다.

## 9.6 판정 — **판정 가능해졌고, 결론은 "비싼 거래"**

| 배포 경로 | 얻는 것 | 내는 것 | 효율 |
|---|---:|---:|---|
| **⚙int8 상주** | **−18.8%**(86.94 → 70.56 MB) | +0.0645 nats | **0.00394 nats/MB** |
| fp32 상주 | −3.6%(451.5 → 435.1) | 〃 | 0.00394 nats/MB |
| **packed** | **−6.7%**(13.050 → 12.175) | 〃 | ★**0.0737 nats/MB** |

**다른 레버와 비교**(결과 032 §4 · 036):

| 레버 | nats/MB(packed) | 판정 |
|---|---:|---|
| `mC_g16` | **0.0167** | 채택 가능 |
| `mC_p1c1` | **0.0199** | 같은 효율선 |
| **`mC_e128svd`** | ★**0.0737** | **4.4배 비싸다** |
| `mC_g256a` | **≈ 0**(Δ 구분 불가) | ★**채택** |

> ★**packed 기준으로 E=128 은 우리가 가진 가장 비싼 레버다**(g16 의 4.4배).
> **그러나 int8 배포를 확정하면 이야기가 달라진다** — int8 상주에서는 **−18.8% 로 1위**이고
> 그건 g16(−5.3%)의 3.5배다(함정 24: 레버 순위가 배포 경로에 따라 뒤집힌다).
>
> **판정: `int8` 배포가 확정될 때까지 보류. 그 전에는 채택하지 않는다.**
> **결과 016 §10 이 *"int8 은 RAM 부족 시 마지막 수단이지 기본 배포 경로가 아니다"* 라고 적어 두었다.**
