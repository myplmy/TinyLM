## 2. 회전 뒤 삼진 오차는 보고값 — 효과 판정 아님

동일 합성 입력·가중치를 두 회전으로 변환한 뒤 `x_rot @ ternary_g128(w_rot).T`를 원래 FP 출력과 비교한 NRMS다. 아래는 FP64 값이며 같은 조건 FP32의 차이는 이 표시 자릿수보다 작다.

| seed | 3×256 NRMS | 1024-pad NRMS | 읽을 수 있는 것 |
|---:|---:|---:|---|
| 1337 | 0.422557 | 0.373503 | 이 합성 가중치에서는 padding 방식의 오차가 작음 |
| 2024 | 0.515284 | 0.354398 | 같은 방향 |
| 31415 | 0.383468 | 0.408520 | **반대 방향** |

모드 사이 독립변수는 회전 block과 768→1024 padding을 함께 바꾼 것이다. 무회전 삼진 대조가 로그에 없으므로 “회전이 삼진 오차를 개선했다”고 말할 수 없다. 세 seed 중 2개에서 pad가 작은 NRMS였더라도 seed 선택·패딩 비용·실제 층 분포·출력 품질은 미해결이다. 이 표는 `DESCRIPTIVE_ONLY`이고 실제 모델 채택 문턱이 아니다.

## 3. 판정·예측 대조

계획 §3의 FP64 직교 동치와 FP32 소오차 예측은 합성 12행에서 맞았다. 그러나 계획이 우려한 1024-pad의 byte 대가도 이론 회계에서 +33.3%다. 코드에는 FP32/FP64 출력 동치에만 assert가 있고 삼진 NRMS의 개선 문턱은 없다. 따라서 G0는 **수학/회계 계약 통과**, 실제 checkpoint 민감도·packed byte·runtime/RSS·CPU wall·GPU whole-step·full-val·한영 품질·learnable rotation은 모두 `NOT_RUN`이다. 기존 [P014D 결과069](069_20260902_P014D-디코드-프로파일이-경로이름을-양자화형식으로-넘겨-두-팔-다-죽었다.md)와 [P025B 결과082](082_20260913_P025B-import-실패로-2대4-게이트는-미실행이다.md)의 실제 wall 음성은 바뀌지 않았다.

## 4. 후속·재현 경계

G1의 같은 checkpoint·같은 형상 CPU/GPU 병목 재계측을 설계할 수 있는 수학 선결만 열렸다. 사용자가 정확한 checkpoint·SHA와 대상 tensor를 고른 뒤, G2 품질 비교 전에는 **무회전 g128 대조·padding/seed별 층 민감도·온라인 회전 비용**을 별도로 고정해야 한다. 현재 G1/G2 SH는 없고 기본 TLinear 경로를 바꾸지 않는다. 사용자 실행 명령은 완료 SH의 재현 부록으로 이 문서 아래에 보존한다.

## 5. 2026-09-26 Stage1Wa — 세 실물 체크포인트의 부분 가중치 민감도

사용자 원본 `099_log_20260926_P014E_Stage1Wa_{A_d14_rms4,B_mc_initonly_s2,C_d12_r20}_rotation_weights.txt`는 각 0종료다. 세 체크포인트에서 pre/mid/coda `gate_proj` 하나씩을 뽑고 **합성 활성값** batch8에 적용했다. 아래 각 셀은 pre/mid/coda 순서의 `ternary_vs_float_nrms`이며 낮을수록 해당 투영에 가까울 뿐 모델 언어 품질은 아니다.

정확한 원본 세 건: `099_log_20260926_P014E_Stage1Wa_A_d14_rms4_rotation_weights.txt`, `099_log_20260926_P014E_Stage1Wa_B_mc_initonly_s2_rotation_weights.txt`, `099_log_20260926_P014E_Stage1Wa_C_d12_r20_rotation_weights.txt`.

| 체크포인트 | 무회전 | 3×256 회전 | 1024 padding 회전 |
|---|---|---|---|
| A d14 CLA2 RMS4 | .412/.440/.466 | .441/.430/.431 | .387/.389/.387 |
| B mC initonly s2 | .475/.467/.515 | .429/.404/.424 | .388/.366/.385 |
| C d12 CLA2 r20 | .468/.480/.505 | .430/.429/.426 | .388/.385/.381 |

A의 pre에서는 3×256이 **악화**되고, B/C의 세 선택 투영에서는 개선됐다. 1024 padding은 모든 선택 투영에서 NRMS가 낮지만 code+scale 이론 byte가 442,368→589,824B(+33.3%)이고 FP32 작업 가중치도 12,582,912→16,777,216B다. `projection_plus_online_rotation_p50_ms`도 예를 들어 A pre 0.491→0.657→0.945ms, B coda 0.729→0.852→1.390ms다. C pre의 3×256은 0.699→0.685ms로 근소한 예외가 있어 **모든 층에서 느리다**고 일반화하지 않는다. 패킹 시간은 일반적으로 회전 시 증가한다. 이는 Python/CPU 부분 투영 계측이며 가중치 선택·캐시·스레드/클럭 영향을 통제한 전체 모델 배포 시간이 아니다.

회전 동치는 세 가중치에서 수치상 유지됐다(`identity_nrms` 약 5e-7). 그러나 3개 선택 텐서·합성 활성값만으로 아키텍처 기본값을 바꾸지 않는다. 실제 텍스트 입력의 full-val·한영 품질, 물리적 2-bit 패킹과 모델 RSS, 전체 prefill/decode 속도, 학습 backward는 `NOT_RUN`이다. 후속 G1은 무회전 대조·동일 checkpoint·동일 실제 텍스트 입력으로 end-to-end wall/RSS와 양자화 오차를 함께 측정해야 한다. 기존 §4의 'G1 SH 없음'은 당시 기록이며 이번 G1a 세 SH가 실행된 뒤의 최신 판정은 이 절이 소유한다.
