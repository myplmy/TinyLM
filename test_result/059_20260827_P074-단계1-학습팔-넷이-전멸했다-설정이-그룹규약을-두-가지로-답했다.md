## 2. ★★근본원인 — **한 개념, 두 정의**(계측함정 18)

`tinylm/config.py`:

```python
@property
def n_mlp_groups(self):
    if not self.tie_mlp:          # ★ tie_mlp 를 본다
        return self.n_middle
    ...
    return self.n_middle // self.mlp_group

def mlp_group_index(cfg, j):      # ★ 바로 아래. tie_mlp 를 **안 본다**
    return j // cfg.mlp_group
```

모델은 위를 쓴다 — `mid_mlps = ModuleList([MLP(cfg) for _ in range(cfg.n_mlp_groups)])`.
이식 코드는 아래를 쓴다 — `members = mlp_group_members(sc, j)`.

`m100s2` dense(`n_middle=2`, `mlp_group=2`, `tie_mlp=False`) 에서:

| | 답 |
|---|---|
| 모델이 만든 `mid_mlps` | **2 개** (j = 0, 1) |
| `mlp_group_members(cfg, 0)` | `[0, 1]` |
| ★`mlp_group_members(cfg, 1)` | ★**`[]`** → `sum(...) / 0` |

> ⚠️**아이러니**: `mlp_group_index` 의 docstring 이 *"⚠️여기서만 정한다. 종전에
> `transformer.py` 와 `init_utils.py` 가 각자 `j // g` 를 쓰고 있었는데 … 계측함정 18"*
> 이라고 적혀 있다. **단일 소스로 만들면서 `tie_mlp` 분기를 옮겨오지 않았다.**
> 단일 소스는 만들었는데 **소스가 불완전했다.**

### 2.1 왜 `mlp_group=2` 인 얕은 dense 프리셋이 생겼나

`m100s2/s4/s6/s8` 은 **내가 이번 세션에 만든 프리셋**이다. 부모 `m100` 은 `mlp_group=4`
인데 `__post_init__` 이 `n_middle % mlp_group == 0` 을 요구하므로 `n_middle=2` 에서는
성립하지 않는다. 그래서 `mlp_group=2` 로 낮췄다. **tied 로 쓸 일이 없으니 무해하다고 봤다** —
그런데 `mlp_group_index` 가 dense 에서도 그 값을 읽고 있었다.

★**그러나 원인을 새 프리셋에 돌리면 안 된다.** 정적 게이트를 옛 구현으로 되돌려 돌리면
**`m100`·`m100R1c`·`m100R1d`·`tiny` 를 포함한 12개 프리셋 전부가 dense 에서 불일치**다.
새 프리셋은 **이미 있던 결함을 처음 밟았을 뿐**이다.

## 3. 🚫왜 스모크가 못 잡았나 — **새 기능이 아니라 새 조합이었다**

**"dense 학생이 dense 부모를 이식받는다"** 를 요구했다.

> 이것이 최근 코드 사고의 **공통 구조**다 — §7.

## 6. ⚠️★세 번째 결함 — **게이트가 자기가 재지 않은 대응표를 인쇄했다**

[1] 의 머리말:

```
대응표 [0, 1, 2, 6, 10, 14, 18, 19]        <- 역할 구간 비례(role)
```

같은 로그 20줄 아래, 실제 이식:

```
[init] ★종전 인덱스 zip 으로 앞 8층만 이식한다
[init] ★대응표 student->teacher: [0, 1, 2, 3, 4, 5, 6, 7]        <- zip
```

`init_from_dense` 는 **학생이 더 얕으면 `depth_init == "role"` 일 때만** 역할 대응표를 쓴다.
게이트는 `prop`/`gate_scale`/`identity` 세 모드만 돌았으므로 **전부 zip 을 쟀다.**
그런데 배치의 학습 팔은 **`--depth-init role`** 로 돌았다.

> 🚫★**게이트가 배치가 쓰는 구성을 한 번도 재지 않았다.** 통과는 무의미했다.
> 계측함정 4(인쇄값 ≠ 정본)이고, 함정 37(필드가 실려도 경로는 안 돈다)의 사촌이다.

✅**조치**: `diag_depth_init.py` 가 (a) **두 대응표를 함께 인쇄하고 어느 모드가 어느 것을
쓰는지 이름으로 말한다**, (b) 학생이 더 얕으면 **`role` 을 기본 모드에 넣는다**.

⚠️**그래서 §1 의 "이식이 걷어낸 핸디캡 +4.3745" 는 zip 대응표의 수**다.
**role 대응표의 수는 아직 없다.** 재실행 때 다시 읽는다.
