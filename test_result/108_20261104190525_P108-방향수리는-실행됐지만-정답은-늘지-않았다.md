## 2. 핵심 발견

1. **직접 수정은 실제 수행됐다.** 관찰만 한 P093B의 임시 활성 교체와 달리 실제 계산 행렬을 바꾸고 캐시·가중치 원복까지 확인했다.
2. **현재 방향 수리는 정답을 회복하지 못했다.** dev의 추가1건은 test로 이어지지 않았고 무작위보다 우수하지 않았다. 반복1건 감소를 지능 향상으로 보고하지 않는다.
3. **삼진 잠재 공간의 희소 편집이 계산 공간의 희소 편집을 보장하지 않는다.** group scale의 연쇄 변화가 커서 저자 실수 모델의 일부 열 수정을 그대로 옮길 수 없다.
4. **일상 답을 실제로 읽었다.** [원본·수리 전체 대응 원문](evidence/p108w_v2_20261104/new595-broad-q/readback/original_target_pairs.md)의 일상16쌍을 총괄이 확인했다. 원본과 수리 모두 농구 질문을 재출력하고, 사과 개수에 두통을 반복했다. 사과 설명의 각주·같이 보기와 깨진 JSON, 영어의 문장 반복도 남았다. 프랑스 수도 답은 수리 뒤 오히려 길이 상한에 닿았다. 일반 한국어·영어 대화가 개선됐다고 판단하지 않는다.
5. **다른 원인을 기각한 것은 아니다.** 이 완료 모델은 비공유·R1에서 반복하므로 공유 MLP·재귀만이 반복의 필요 원인은 아니다. 그렇다고 모든 데이터/학습/아키텍처 원인을 이번 실험이 분해한 것은 아니다. 타 세션의 정제 원문에는 접근하지 않았다.

## 3. 판정

- 기술 실행: CPU50·무변경 byte·실제 수정·원복·원답 샤드 검산은 범위 내 완료.
- 과학 판정: **GATE_NEGATIVE**, 현재 선정 수리 비채택. 기존 기본 모델·제품 기본 추론은 바꾸지 않는다.
- 새 학습·일반 지능·공식 벤치마크·배포 가속/압축: 이 결과로 승격하지 않는다.
- 현재 명시 정적 감사는 [OWNED_STATIC_v3](../handoff/audit/nov04_weight_space/OWNED_STATIC_v3.json)의193입력, 6PASS·0ERROR·71NOT_RUN이다. 전역 전수 정적이나 새 전체 스모크 PASS가 아니다.
- 앞선 정적 호출2회는 exact WIP 인자가 부족해 검사 전 거부됐고, v2는 재사용 시험 모듈1개가 입력 목록에 없어 읽기 경계가 차단했다. 알려진 경로의 SHA로 확인해 명시 입력에 추가한 v3에서 통과했다. 공유 검사기의 보호 정책을 완화하지 않았다.

## 4. 후속

- [완료, 비채택] 완료 실수 모델의 같은 방향 수리는 §6의 독립5팔에서 모두5/128이었다. 비영점 float 잠재/캐시 편집이 bit-identical하다는 CPU 계약으로 중복 팔은 생략했다. Q/F는 따로 학습됐으므로 둘의 차이는 서술 비교다.
- [중, 조건부] 그룹 단위 상한 또는 원래 ternary scale을 유지하는 과제별 편집을 검토한다. 현재 방향의 부적합 가능성도 남기며, 같은 test 답을 다음 편집 선택에 사용하지 않는다.
- [필수] 현재 소스의 허가 범위 검증과 문서 연쇄·원문 로그·인계를 마감한다. 정제 해결 전 추가300M은 수행하지 않는다.
- 공식 자료의 [블로그](https://rikiyat.github.io/blog/weight-space-programming/)와 [저자 기록](https://github.com/RikiyaT/lm_understand-logs/tree/main/exp8_math)은 연구 근거다. 일부 Qwen의 성공을 모든 작은 모델의 기대 성능으로 복사하지 않는다.
