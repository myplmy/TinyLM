## 2. 핵심 발견

1. 원래 x/y의 마지막 target까지 보존하면서 길이를 바꾸는 회계는 구현됐다. 짧게 자른 뒤 앞부분만 학습한 가속과 구분된다.
2. **이번 micro8 분할 방식은 속도 음성**이다. 짧은 attention의 이점보다 증가한 micro 호출·GEMM/재계산 등 비용이 클 수 있다는 가설과 부합한다. 원인별 시간을 직접 분해한 실험은 아니므로 호출 비용만을 유일 원인으로 확정하지 않는다.
3. allocated peak는 줄었지만 속도가 느렸다. 메모리 절감과 본학습 가속을 서로 대신할 수 없다.
4. 독립 모듈·가상 회계의 준비와 제품 trainer 통합·완료 본학습의 품질 효과는 다르다. 현재 정제 미완과 추가300M 금지를 그대로 유지한다.

원장 55·56의 합성 실험에 이어, P079 2,289갱신 부모를 같은 16층 G4 R2로 불러왔다. 이전에 작성한 768개 한영 학습 문서와 다른 틀의 검증 문서 48개를 재사용했다. 학습 풀 24,342타깃, 각 추출 시드의 실제 손실 위치 11,169·11,121개, 배치 4·누산 1·폭 96·88갱신, 같은 AdamW 그룹·명목 LR과 초기 모델을 확인했다. 각 시드 안에서 GPU에 전달한 입력·출력 위치와 갱신 순서가 같았다. ### 14.6 실제 규모 G4 문서 CLI는 재개 상태가 일치했고 저장 비용이 컸다

P079의 2,289단계 가중치를 16층·62.9M·32K의 같은 G4에 사용했다. 먼저 일반 `--init-from`을 확인했다. 조밀 교사용 집약 코드가 이미 공유된 MLP를 개별 층처럼 인덱싱해 CPU에서 종료 1이었다. 기존 쿨다운의 `--decay-from` 가중치 직접 복사를 명시 문서 프로필에 연결했다. 새 학습은 모델 키를 엄격히 대조해 복사했고, 재개는 부모의 바이트 지문을 확인한 뒤 학습 체크포인트를 읽었다. CPU 회귀 83개와 부모·입력 준비는 종료 0이었다. [초기 로드 오류](106_log_20261119_P013_Stage7We_ParentProbe_CPU.txt) · [CPU 회귀](106_log_20261119_P013_Stage7We_PackedCooldownTests_CPU.txt) · [CPU 준비](106_log_20261119_P013_Stage7We_FullPackedPrep_CPU.txt) · [봉인 프로필](evidence/p013_g4_packed_cli_resume_v1_20261119/profile.json)

기술 확인용 한영 768문서(25,110토큰)와 분리한 검증 48문서(1,464토큰)를 사용했다. 학습은 28방문, 평가는 16방문이었다. 원 윈도 8×2×1,024에서 활성 너비 256→512→1,024→1,024를 적용했다. 연속 4갱신의 2단계 저장본을 같은 파일시스템에 링크했고, 새 프로세스는 후반 2갱신만 다시 실행했다. 한 궤적은 65,536슬롯·유효 타깃 노출 63,525개였고, 두 프로세스에서 실제로 계산한 갱신은 6회·유효 타깃 노출 95,292개였다. 고정 검증은 세 번 실행했고 각 15,844개 유효 타깃으로 계산했다.

최종 모델·AdamW·문서 진행 상태(표본 커서, 검증 이력, CPU/CUDA 난수)가 비트 단위로 일치했다. 두 실행의 최종 검증 손실은 5.2153220462였다. 체크포인트 6파일은 개당 약 755 MB, 고유 할당 디스크 크기는 합계 4,530,036,736 B였다. 저장 경계를 비교용으로 보존한 용량이다. 저장 경계와 두 팔의 각 최종 상태에서 `latest`와 `best`를 읽어 전체 SHA-256을 비교했다. 세 쌍 모두 파일 식별자는 달랐고 내용은 일치했다. 장기 실행에서는 이 중복 직렬화 비용을 함께 계산해야 한다.
