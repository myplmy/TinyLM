## 1. Stage0 계약

HF_HOME·hub·datasets cache가 모두 `/home/uranus/tinyLM/HF` 아래이고, 네 recipe의 독립 이름,
exact quota, text schema 계약이 exit 0으로 통과했다.

## 2. cache 준비 결과

| 팔 | cache | train/val | source token | 상태 |
|---|---|---:|---:|---|
| control v2 | `ko-en-control-v2_600000000` | 597M / 3M | 300M / 300M | ✅완성; prepare 종료 시 CPython abort |
| FineWeb2 | `ko-en-fw2_600000000` | 597M / 3M | 300M / 300M | ✅완성 |
| edu v2 filtered | `ko-en-edu-v2_600000000_filtered` | 597M / 3M | 300M / 300M | ✅완성; 487 docs 제외; prepare 종료 시 abort |
| MADLAD | 없음 | — | — | 🚫datasets 5가 remote builder script 거부 |

control과 edu는 cache·meta를 완전히 쓴 뒤 HF background request가 interpreter finalization
시점에도 남은 정황과 함께 `Bad file descriptor`·`PyGILState_Release` abort(exit −6)를 냈다.
명시적 iterator close 전파가 없었던 것은 확인된 구현 공백이지만 **abort의 단일 원인이라는 판정은
추정**이다. close 보강 뒤 사용자 재실행 전에는 해결됐다고 주장하지 않는다. cache 파일 크기와
meta 계약은 별도 검증에서 정상이다.

FineWeb2는 prepare 뒤 학습에 진입했지만 첫 compile에서 PyTorch 2.10이 CUDA system-info용
`nvcc`를 찾았다. WSL PATH에 접근할 수 없는 Windows mount 항목이 있어 `FileNotFoundError` 대신
`PermissionError`가 발생했고 PyTorch가 처리하지 못했다. 실제 CUDA compiler 오류나 GPU OOM이
아니며 step 0 전에 종료됐다.

MADLAD는 현재 datasets 5.0.0이 Hub Python builder를 실행하지 않기 때문에
`Dataset scripts are no longer supported`로 종료됐다. 공식 고정 revision의 clean ko/en JSONL
shard를 `huggingface_hub`로 repo `HF/hub`에 받는 direct adapter로 교체했다.

## 3. 수정과 재실행

- HF iterator와 buffer shuffle이 quota 도달 시 하위 iterator까지 `close()`를 전달한다. 실제
  remote finalizer 재현 여부는 사용자 재실행 전까지 `STATIC_ONLY`다.
- WSL 공통 실험 환경에서 `/mnt/<drive>/...` Windows PATH만 제거해 `nvcc` 부재가 정상
  `FileNotFoundError`로 처리되게 한다. `--compile` 비교조건은 유지한다.
- exact-token cache 재사용 전에 `train.bin/val.bin` byte 수, train+val, requested token,
  `mix_tokens`와 `val_mix_tokens` 합계를 검사한다. control/FineWeb2/filtered-Edu 세 실물 cache는
  이 검사를 통과했다.
- MADLAD는 공식 repository의 고정 revision과 clean JSONL.gz shard를 `HF/hub`에서 직접 읽는다.
  최초 adapter 분기가 recipe의 소문자 ID와 대소문자 불일치해 선택되지 않는 추가 결함도
  network-off 단위검사에서 발견해 case-insensitive 비교로 교정했다. tokenizer 표본과 본 cache가
  모두 direct adapter를 사용한다.
- 새 Stage1aB~dB launcher는 기존 tag를 재사용한다. 기존 JSON/checkpoint가 0건임을 확인했으므로
  덮어쓰지 않는다. 실제 download·학습·품질 검증은 `NOT_RUN`이다.

## 4. 판정

데이터 recipe 품질 비교는 전부 `NOT_RUN`이다. cache 준비 성공을 모델 품질이나 다운로드 전체
성공으로 승격하지 않는다. 재실행 뒤 JSON과 checkpoint가 생긴 팔만 결과 비교에 들어간다.
