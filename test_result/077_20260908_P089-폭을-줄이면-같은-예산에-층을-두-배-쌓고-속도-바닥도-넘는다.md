## 3. ★★사전등록 확인 셋 — **둘 통과, 하나는 "가정은 맞고 숫자가 틀렸다"**

계획서 §4.1 이 *"셋 중 하나라도 벗어나면 단계1 을 돌리지 않고 **계획을 다시 쓴다**"* 라고
못 박아 두었다. 결과는 아래와 같고, ★**"축을 접는다" 가 아니라 "⚙수치를 갈아 끼운다"** 가 답이다.

| # | 확인 | 예측 | 실측 | 판정 |
|---|---|---:|---:|---|
| **1** | 상주식 `9.0 + 0.788·L`(512) 이 실측과 ±5% | **31.06** MiB | ★**31.1** MiB | ✅**+0.1%** |
| **2** | `ms/방문` 이 ⚙1.40 ±15% | 1.40 | ★**2.054** | 🚫**+47% — 대역 밖** |
| **3** | 층당 삼진이 `dim²` 에 비례(⚙2.69M) | 2.689M | **2.752M** | ✅**+2.3%**(사유 있음) |

### 3.1 ★확인 2 를 어떻게 읽나 — **산문과 숫자가 서로 달랐다**

계획서 §4.1 의 산문은 *"디코드가 대역폭 바운드라 시간이 **`dim` 에 선형**"* 이라고 적었는데,
그 옆의 ⚙**1.40** 은 **`dim²`** 에서 나온 수다(3.138 × (512/768)² = 1.394).
**선형 가정대로 계산하면 3.138 × (512/768) = 2.09** 이고 ★**실측 2.054 는 그것과 2% 안**이다.

> ★★**그러므로 틀린 것은 가정이 아니라 숫자다.** 계획서 안에서 **두 값이 갈라져 있었고**
> 게이트가 그중 낙관적인 쪽을 기준으로 잡았다. **함정 28 의 또 한 얼굴**(같은 문장 안에서
> 한 양이 두 규약으로 적혔다).

★**같은 날 두 점으로 잰 폭의 시간 지수**:

| 폭 | 총 ms/token | 방문당(절편 6.79 가정) |
|---:|---:|---:|
| 512 | **64.31** | **2.054** |
| 384 | **42.57** | **1.278** |

- 총 시간비 **1.511배**(폭비 1.333) → **지수 1.44**
- 방문당으로 보면 지수 **1.65**
→ ★**폭의 시간 지수는 1.4~1.7 = 선형(1)과 제곱(2) 사이**다.
⚠️**`dim 768` 의 3.138 은 다른 날 값**이라 세션 간 드리프트 7.5% 를 안고 있다 —
**같은 날 두 점**(512·384)만 인용할 때가 가장 안전하다.

### 3.2 ★확인 3 의 +2.3% 는 잡음이 아니라 구조다

층당 삼진 실측 **2.752M**(512) · **1.5236M**(384) vs `dim²` 예측 2.689M · 1.5125M.
초과분이 **512 에서 +2.3%, 384 에서 +0.7%** 인데, 원인은 계획서 §4.3 이 **일부러 넣은 규약**이다:
★**`n_kv_heads` 를 올림 나눗셈으로 고정**해 두 폭이 **둘 다 `kv_dim=128`** 이다.
K/V 투영은 `dim × 128` 이라 **폭에 선형**으로만 준다 → `dim²` 항보다 천천히 준다.
✅**의도한 설계이고, 그래서 팔 B↔C 비교에서 KV 항이 상수다.**

### 4.1 🚫★★**폭 축에는 바닥이 있다 — 임베딩이다**

`w384` 에서 **삼진 8.51 MiB 보다 기타 8.7 MiB 가 크다.**
"기타" 의 대부분은 **int8 임베딩**(factorized 8.5M 파라미터)이고 ★**폭과 무관**하다

> 🚫★**그래서 계획서의 ⚙21.4(384) 는 2.8 MiB 낙관이었다**(실측 24.2).
> ★**폭을 더 줄여도 24 MiB 아래로는 잘 안 내려간다** — 16 MiB 목표는
> **어휘 축**(P075 단계1, 어휘 32,768 → 16,384)이 함께 와야 한다.
> ✅이것은 계획서 §6 이 이미 경고한 것이고, **이제 숫자가 붙었다**: `w384` 상주의 **36%가 임베딩**이다.

## 9. ★★단계1 (2026-09-08) — **좁은 부모가 생겼다. 그리고 그것은 측정이 아니다**

> **로그**: `test_result/077_log_20260908_P089_stage1_narrow_parent.txt`(1팔, exit 0, 69.4분).
> ★**이 단계의 산출물은 수가 아니라 체크포인트**다 — 단계2 가 `--init-from-tag w512_d20_parent`
> 로 쓸 **같은 폭의 부모**를 만드는 것이 목적이었다.

### 9.1 무엇이 나왔나

| 항목 | 값 |
|---|---|
| tag / 프리셋 | `w512_d20_parent` / `m100w512s16`(**dim 512 · 20층** = 2+16+2) |
| 조건 | `--arch dense --cla-group 2` · **`--init-from` 없음(from scratch)** · 300M 토큰 · 풀 600M · 시드 1337 |
| **final val** | ★**3.79094**  (best 3.86719@2200) |
| 파라미터 | 63.6M (삼진 55.1M · 임베딩 8.5M) |
| 벽시계 / ms/step | **69.3분** / **1,755**(중앙값) |
| VRAM(reserved) | **8.08 GB** |
| `grad_max` / `n_skip` | **1.366** / **0** — 기준선 대역 안(0.53~1.56) |
| 상주(fp32, 현 구현) / 저장(packed) | 452.7 MiB / 13.0 MiB |

★**부수 관측 — 좁히면 학습도 빨라진다**: `d14_cla2_norecur`(dim 768·14층)가 2,085 ms/step 인데
**dim 512·20층이 1,755** 다 = **−15.8%**. 층이 6개 더 많은데 더 빠르다.
VRAM 도 8.72 → 8.08 GB(−7.3%). → ★**폭 축은 추론뿐 아니라 학습 예산도 산다.**

### 9.2 🚫★★**그런데 이 값으로 폭의 대가를 잴 수 없다**

배치가 마지막에 *"Do not rank this val against dim 768"* 를 찍는다. 실사해 보니 정확했다 —
**깊이 20 · dim 768 점 셋이 전부 조건이 하나씩 다르다.**

| dim 768 · 20층 후보 | final | w512_d20_parent 와 다른 것 |
|---|---:|---|
| `dense`(정본 부모) | 3.82406 | 🚫**풀 300M**(함정 2) |
| `d20_dense` | 3.49703 | 🚫**부모초기화 있음** + `cla_group 1` |
| ★`dense2` | **3.62859** | ⚠️`--anneal-end 0.60`(우리는 0.80) + `cla_group 1` |

★**가장 가까운 것은 `dense2`** 이고 남는 차이가 둘이다. 그중 하나는 크기를 안다:

| 보정 | 근거 | 크기 |
|---|---|---:|
| `anneal-end` 0.60 → 0.80 | 기준표 §스케줄 — **두 예산에서 검출 실패**(1.07σ / 0.05σ) | ⚙**≲0.005** |
| `cla_group` 1 → 2 | `d12_dense`↔`d12_cla2` **+0.02641** · `d16_dense`↔`d16_cla2` **+0.02187** | ⚙**+0.024** |

→ ⚙**폭 대가(dim 768 → 512, 깊이 20 고정, from scratch)** = (3.79094 − 0.024) − 3.62859 = ⚙**+0.138**.
🚫★**이것은 실측이 아니라 두 보정을 얹은 추정**이다. **⚙표시를 떼지 않는다.**

### 9.3 ★★그래서 단계2 를 **사전등록**한다

깊이 곡선(dim 768, AdamW, 무재귀, 300M 토큰)은 12→14 −0.01718 · 14→16 −0.02297 ·
16→18 −0.01047 로 **16층 뒤에 층당 ⚙0.005 로 꺾인다**. 그 기울기를 그대로 쓰면
**20→28(+8층)이 사는 것은 ⚙−0.04** 이고 **폭이 파는 것은 ⚙+0.138** 이다.

| # | 사전등록 예측 | 통과 기준 | 반증되면 |
|---|---|---|---|
| ★**P12** | `w512_d28`(31.1 MiB)이 같은 프로토콜의 **`d14_cla2_norecur`(30.8 MiB)보다 나쁘다**. 격차 ⚙**+0.09 ± 0.05** | 실측이 대역 안 | — |
| ★**P13** | 격차가 **자(0.0024) 안이거나 음수** | — | ★**폭이 진짜 레버다.** 32 예산에서 층을 두 배로 쌓는 길이 열린다 |
| **P14** | dim 512 의 깊이 곡선이 dim 768 보다 **가파르다**(작은 모델일수록 층이 더 산다) | 20→28 이 ⚙−0.04 보다 크다 | 폭 대가를 깊이로 갚는 계산이 낙관 |

> ★**왜 사전등록을 적나** — 단계2 가 나온 뒤 *"⚙표를 갈아 끼우면 맞는다"* 로 사후 해석하는 것을
> 막는다(§3 에서 ⚙1.40 ms/방문이 47% 낙관이었던 것과 같은 종류의 사고).

### 9.4 ⚠️한계

1. 🚫★**품질 대가는 여전히 0런이다.** 이 절은 **추정 하나(⚙+0.138)** 를 더했을 뿐이다.
2. **부모가 `cla_group 2`** 다 — 단계2 가 cla2 이므로 **부모·자식이 맞다**. 🚫단 dim 768 계보의
   부모(`m100_ko-en_300M_dense`)는 **cla1** 이라 **두 계보의 부모 조건이 다르다.**
   ⚠️이 비대칭이 단계2 의 폭 비교에 **잔여 교락**으로 남는다.
3. **250스텝 프로브(§2)와 본런의 val 을 섞지 않는다** — `w512_d28_probe` 5.98 은 **속도·메모리 전용**이다.
4. **시드 1개.**
