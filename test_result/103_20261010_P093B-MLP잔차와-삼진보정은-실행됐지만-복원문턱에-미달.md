## 3. 핵심 발견과 negative의 정확한 이유

1. 사전 문턱은 **NRMS≤0.90 그리고 shared 대비 오류감소≥10%**다. shared0.996645에서는 두 조건을 함께 만족하려면 약0.896980 이하가 필요하다. A r8/r16은 둘 다 오히려 오류가 늘어 각각−0.337%/−1.780%이고, B의+1.406%는10%에 미달한다. 그래서 두 실행은 정상 종료된 **과학적 음성8**이다. 문턱을 사후 낮추지 않는다.
2. A의 보정 입력 손실은 step1→250에서 r8 0.947969→0.554068, r16 0.883065→0.378626으로 낮아졌지만 별도 입력의 NRMS는 초기보다 악화했다. 과적합·LR/종료시점·낮은rank 표현력은 **경쟁 가설**이며 아직 한 원인으로 확정하지 않는다. history 마지막loss는 해당 업데이트 직전 계산값이다.
3. B의 입력 손실도 0.992576→0.633579으로 줄었다. 공유 삼진 배정만으로 네 층 역할 차이를 복원하기에는 현 조건에서 부족했다. 이 관측으로 GSQ 전체나 모든 타잉 방법을 기각하지 않는다.
4. 세 후보의 whole forward CE는 원부모보다 약+0.14~0.16 높았다. shared-only wholeCE는 없어 ‘보정이 mean보다 언어손실을 개선했다’는 비교는 하지 않는다. 이는 같은source8창 관측이며 새 calibration 계열 σ·다중seed·언어 일반화 근거가 아니다.
5. Stage3W는 r16 A viability가 없어서 **모델을 올리기 전** `rank16_A_viability_missing`으로 막혔다. 실제 삼진 factor 품질 실패나 OOM이 아니다. 전체적으로 종료8이3개여도 실제 함수 음성은2개이고 나머지1개는 선결보류다.

## 4. 후속과 양자화 해석

사용자는 A(분할/LR/종료시점)와 B(rank32/64 표현력)를 모두 선택했다. 기존r8/16/mean/정상학습기본은 보존하고 새 stage/tag에서 train/dev/test·dev선택·독립test, r8/16/32/64, LR1e-3/1e-4,20/50/100/250회 곡선 및 보정 전후 실제 추론 답을 준비한다. **새 모델 실행/답안 판독은 NOT_RUN**이며 실제 원문을 회수한 뒤 GPT가 판독한다.

현재4층·3투영의 인자는 r16 FP32 약2.0625MiB, r32 4.125MiB, r64 8.25MiB다. r64의 FP16 **저장**은4.125MiB, 이상적2bit는0.515625MiB이나 scale/metadata는 별도다. 기존 LoRA16 forward는FP32 입력/Parameter이므로 저장half를 읽고FP32로 복원하면 **상주는 줄지 않는다**. 실제FP16 resident/mixed forward와 native 삼진은 dtype/커널·함수·추론 정합 및 실제RSS/속도를 별도로 검증해야 한다.
가정상 원래4 MLP의2bit 본체는4.5MiB, shared1 본체1.125MiB다. r64 FP16을 붙이면5.25MiB로 **그 그룹의 원래2bit저장보다도 클 수 있다**. 전모델32/40MiB 목표 달성을 선언하지 않는다. LittleBit binary kernel·전층 RCO는 이번 준비 범위 밖이다.

### GPT 실제 원답 판독 — 표현력과 함수 복원은 별도

A/B 원형에 총64답이 있으나 parent/shared가 두 팔에 중복 저장되어 서로 다른 조건/질문은48개다. 부모·shared·r8/16/32/64의8질문씩 원답을 직접 읽었다. 이는 후행 정성 판독이지 새 정답률 자동 판정은 아니다.

- 부모에도 ‘나의 색은 무엇입니까? 답:’ 질문 반복과 숫자 나열이 있다. shared/r64에만 처음 생긴 현상이라고 할 수 없다.
- r8/16의 한국어 산수는 ‘2.5.5.5…’, 영어 산수는 질문을 바꿔 말한 ‘What is the difference between 2 and 3?’를 반복했다.
- r32/64의 한국어 산수는 ‘2 더하기3는 무엇이든,2 더하기4는 무엇이든…’으로 다른 계산을 나열했고 문맥 질문도 반복했다. 지식조회 답에 파랑을 포함했다고 ‘값만 답하기’ 성공으로 세지 않았다.
- 숫자1만 요구한 답은1,2,3… 목록으로 확장되고 이유 질문에는 위키 문서의 ‘같이 보기/각주/외부 링크’가 이어졌다.
- parent/rank 각7 MAX_NEW·1 EOS, shared8 MAX_NEW다. 종료1건과 요구 정답/형식 성공을 같게 보지 않는다.

즉 보정이 CE/local NRMS를 조금 회복해도 부모의 일반 문서 이어쓰기 성향을 지시응답으로 바꾸지 못했다. 이번 품질 저하를 구조/구현 결함으로 확정하지도, 일반 연구에 반복이 있으니 구현이 옳다고 선언하지도 않는다. [논문 검토08 §10](../docs/methods/08_paper_review2.md)이 원인 가설·학술 대안·비용을 구분한다.

### factor 저장·선결과 정확 재현

r8/16/32/64 FP32 인자만1.03125/2.0625/4.125/8.25MiB다. r64 FP16 저장 payload4.125MiB, 이상적인2bit는.515625MiB지만 추가 scale/metadata/master/KV/실제 RSS 제외다. r64 half+shared ternary core1.125MiB=5.25MiB로 원래4MLP 이상적2bit4.5MiB보다 크므로 압축 목표 달성을 선언하지 않는다. 실제 half/native ternary roundtrip은 선결 보류였으며 코드상 native half 실행 dtype 경로도 별도 검증 대상이다.

## 9. 다음 A 원인진단 준비와 C 학술검토

사용자 A 선택으로 Stage6aW CPU 계약→Stage6bW 무학습 진단을 작성했다. 정확 old parent/shared/r64를 유지하고 plain/few-shot × greedy/nucleus(p.95,t1,seed3개) 대응 원답을 보존한다. 기존 plain-greedy24답은 재사용하고 새192생성 중24는 cache-off 대응이다. text/finish/count 일치는 전체 logit/토큰 ID의 bitwise 증명을 대신하지 않는다. 사고·자유의미 문자열 검사를 넣지 않으며 GPU는 사용자 실행이다.

후행 C의 최우선 후보는 정상 QA·종료 SFT 기준선과 reference-free ORPO 대조다. ScaleGrad·SimCTG·contrastive decoding·DPO/SimPO·출력분포 복원까지 primary 원문을 검토했다. 정상 반복/유일답/숫자/코드를 보호하고 실제 A 뒤에 C 범위·자료·학습 승인을 다시 정해야 한다. 새 C 손실·GPT 모델 실행·학습은0이다.
