# 094 — P103A X3 하부 MLP 동결 복구 뒤 소형·M0 정확 경계 통과

> 로그 날짜 2026-09-24 · [계획 P103A](../test_plan/P103A_X1-X2-X3-계산량-기능계약.md). 2026-09-24 실패 이력 5로그와 2026-09-25 복구 2로그를 시간순으로 기록한다. 첫 X3 실패는 코드 오류였고 최신 exact 경계는 통과했다.

## 1. Stage0W CPU 수학 계약 — PASS

- 원본: `094_log_20260924_P103A_Stage0W_compute_math_contract.txt` · 종료코드 0.
- X1 toy VJP, X2 full/tile, X3 고정창 키와 INT8 q/deq fixture PASS. X2 한 tile GEMM 피연산 비율 0.25이나 Muon 전폭 버퍼 301,989,888B 그대로다. 2M source의 고정 seq1024 창 1,953개, FP32 exact 원시 6,143,606,784B, INT8 per64 원시 1,631,895,552B는 **산술 하한**이다. 20M INT8 16,320,000,000B 계산 역시 실제 RAM/RSS 아님.

## 2. Stage0bW 공개 SFT 접두부 — 구조 관측만 PASS

- 원본: `094_log_20260924_P103A_Stage0bW_public_sft_prefix_census.txt` · 세 진단 호출 모두 종료코드 0.
- SHA 고정 공개 v3 train 2,996행·직렬화 857,679 token에서 최소 32/64/128 token 공유 가능 출현은 951/83/0이었다. 32 token의 가상 작업절감 0.11088%, 64 token 0.009677%, 128 token 0%. 이것은 corpus 구조적 상한이며 보호 KnowledgePack의 중복률·Transformer VJP·학습 wall이 아니다. 공개 v3 `TRAIN_READY=false`를 유지한다.

## 3. Stage0cW 실제 소형 X2 물리 tile — 기능 PASS

- 원본: `094_log_20260924_P103A_Stage0cW_model_ffn_tile.txt` · 종료코드 0.
- 네 tile 전부 선택 대 원래 FFN의 loss/전 gradient/한 SGD update 차이는 로그 인쇄상 모두 0, 한 tile reference 차이 0, 물리 선택폭 `[64,64,64,64]`였다. 이전 `float(requires_grad tensor)` UserWarning은 판정 수치가 아니라 계측 출력 변환 경고다. 후속 코드에서 지표를 detach 후 변환하도록 수정했다.
- 범위는 CPU FP32 소형 모델이다. 선택되지 않은 master·Muon 상태는 남고 GPU step·RSS·품질은 `NOT_RUN`이다.

## 4. Stage0dW 소형 X3 경계 — 구현 FAIL

- 원본: `094_log_20260924_P103A_Stage0dW_model_boundary.txt` · 종료코드 1.
- `pre_mlps.0.gate_proj.weight` gradient 존재가 full forward와 detached boundary→tail에서 달라졌다. `Layer.mlp`가 등록 모듈이 아닌 리스트 참조인데 진단기는 등록된 `model.layers[:split]`만 동결했다. 원래 게이트의 비교 대상부터 어긋난 것이므로 INT8 근사·캐시 품질의 과학적 실패로 해석하면 안 된다.
- 공통 하부 의존성 freeze와 상·하부 MLP 공유 거부를 코드로 추가했고 **모델 없는** 소유권 fixture만 PASS했다. Stage0dWb 사용자 재실행은 `NOT_RUN`; 기존 5e-5 문턱은 유지한다.

## 5. Stage1aW 고정 M0 12/4 경계 — 같은 구현 FAIL

- 원본: `094_log_20260924_P103A_Stage1aW_m0_boundary.txt` · 종료코드 1. 고정 M0 SHA 검사 뒤 동일한 `pre_mlps.0.gate_proj.weight` gradient 존재 오류가 발생했다.
- checkpoint 계보 불일치나 cuSPARSELt 미지원의 증거가 아니다. Stage0dWb가 먼저 통과한 뒤 Stage1aWb에서 같은 M0·입력·5e-5 문턱으로 재실행한다. 두 결과 전까지 2M builder·20M RAM·INT8 언어 품질은 `NOT_RUN`이다.

## 8. 2026-09-25 X3 동결 복구 재실행 — 소형과 고정 M0의 정확 경계 PASS

사용자 원본은 `094_log_20260925_P103A_Stage0dWb_model_boundary_freeze.txt` 다음 `094_log_20260925_P103A_Stage1aWb_m0_boundary_freeze.txt` 순서다. 두 로그 모두 종료코드0이다. §4~§5의 `pre_mlps.0.gate_proj.weight` gradient 존재 불일치는 **이전 코드의 실제 실패 이력**으로 유지하며, 새 suffix 재실행만 아래 기능 범위에서 통과했다.

| 모델·단계 | logits 최대차 | loss 차 | 전 gradient 차 | 한 SGD update 차 | INT8 boundary NRMS | 판정 |
|---|---:|---:|---:|---:|---:|---|
| 작은 CLA2 Stage0dWb | 0 | 0 | 0 | 0 | 0.0057803518 | exact 경계 `5e-5` PASS |
| 고정 M0 12/4 Stage1aWb | 0 | 0 | 0 | 7.4505806e-9 | 0.005923023 | exact 경계 `5e-5` PASS |

같은 고정 창 입력의 full forward 대 동결 하부 경계→tail 경로를 확인한 것이며, M0 검사는 랜덤 8-token 창에 한정된다. `INT8 boundary NRMS`는 보고값이지 정합/품질 채택 문턱이 아니다. 2M/20M 실제 cache, RAM·GPU wall, 배포 RSS, 언어 품질은 실행되지 않았다. 따라서 X3 **정확 함수 연결 오류는 복구**됐지만 X3 가속/압축/학습축 전체를 완료로 승격하지 않는다.
