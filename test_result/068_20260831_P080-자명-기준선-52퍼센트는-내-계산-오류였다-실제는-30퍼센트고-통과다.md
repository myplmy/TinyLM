## 9. 🚫★★★**정정 — 52.0% 는 내 계산 오류였다. 실제는 30.3% 이고 게이트를 통과한다** (단계0b, 2026-09-02)

### 9.1 실측 — **동점을 반영하니 22%p 가 사라졌다**

| 자명 선택기 | v2.2 | v2.3 | 우연 | 판정 |

🚫★**§1~§7 이 쓴 "52.0%(+10.8σ)" 는 틀렸다.**

### 9.2 ★왜 틀렸나 — **순위표를 정답률로 읽었다**

로그의 `정답의 토큰 길이 순위 1/2/3/4 = 156/41/73/30` 에서 `156/300 = 52.0%` 를 계산했다.
그런데 그 순위는 **경쟁 순위**다:

```python
rank_of_correct[sum(1 for x in L if x < L[ci]) + 1] += 1
```

★**정답이 최솟값과 *같기만* 해도 rank 1 이다.** 동점이 있으면 동점자 전원이 1위다.
후보 4개의 토큰 길이가 **중위 21 · 폭 11~37 의 작은 정수**라 **동점이 흔하다.**
길이만 보는 선택기는 동점에서 **1/k 확률로만** 맞는다:

```python
if L[ci] == min(L):
    trivial_short += 1.0 / L.count(min(L))
```

→ **156건 중 상당수가 2~4중 동점** → 기대 정답률 **30.3%**.

★**156/300 은 "정답이 최단과 동점 이상인 문항의 비율" 이지 "최단 선택기의 정답률" 이 아니다.**
🚫**한 표가 두 양을 가리켰다**(함정 28) — 그리고 내가 그 둘을 바꿔 읽었다.

⚠️★**§7.6 에 이미 이렇게 적어 뒀다**: *"52.0% 는 동점이 없다고 보고 계산한 값이고
정확한 수는 큐 4번이 인쇄한다."* ✅**유보를 적은 것은 잘했다.**
🚫**그런데 그 유보를 달고도 §1 제목·§6 결론·핸드오프·기준표 B.13.7·`CLAUDE.md` 에
52.0% 를 그대로 옮겨 적었다** — 자백 원장에 올린다.

### 9.3 ★★그래서 v2.3 은 **쓸 수 있다**

★**§7 의 안 A(채점 정규화)는 여전히 유효한 개선**이지만 **선결이 아니다.**
