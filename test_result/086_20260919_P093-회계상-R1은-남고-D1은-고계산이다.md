## 3. 후속

R1 r4/8/16의 Stage0c 부모 근사 오차를 먼저 측정한다. D2는 P091 selector/local
update 의존성을 해소한 뒤에만 재판단하고, D1은 속도 가치를 별도로 증명하지
못하면 기본 후보로 승격하지 않는다.

## 4. Stage0c actual parent approximation(2026-09-19) — **과학적 음성으로 정정**

> **로그**: `086_log_20260919_P093_Stage0c_parent_approximation.txt` · 기록 exit 0

| rank | weight NRMS | MLP output NRMS |
|---:|---:|---:|
| 0(shared mean) | 0.86499 | 0.98139 |
| 4 | 0.85716 | 0.97912 |
| 8 | 0.85070 | 0.97735 |
| 16 | **0.83956** | **0.97400** |

오차는 rank에 따라 단조 감소했지만 rank16의 output error는 baseline 대비 **0.75%만 감소**했고
NRMS가 0.974라 원 출력을 사실상 복원하지 못했다. 기존 진단기는 “단조 감소”만 확인해 이를
`PASS`로 인쇄한 설계결함이 있었다. Stage0c의 목적은 Stage1 구현 가치 선별이므로 단조성만으로는
불충분하다. 최소 10% error reduction과 output NRMS≤0.90 viability floor를 추가했고, 기존
수치에 적용하면 **exit 8 과학적 음성**이다.

따라서 R1 r4/8/16의 save/load·optimizer·학습 통합은 열지 않는다. D1 고계산 트랙과 P091
의존 D2는 별도 질문으로 남지만 이 결과를 R1 품질 가능성으로 인용하면 안 된다. 같은 수치가
이미 충분하므로 판정 코드 확인만을 위한 GPU 재실행은 권하지 않는다.
