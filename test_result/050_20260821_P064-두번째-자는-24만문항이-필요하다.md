## 2. YNAT — label-likelihood accuracy (500문항)

| 모델 | **정확도** | full-val |
|---|---:|---:|
| **`p6d`**(dense) | ★**39.4%** | 3.7608(**최악**) |
| `mC_wsd_s2` | 39.2% | — |
| `mC_initonly_s2` | 39.0% | — |
| `mC_initonly` | 36.0% | ★**3.6776**(최선) |
| `mC_wsd` | 34.2% | 3.6984 |
| **`mC_d36_ag4`** | ★**30.4%** | 3.7062 |

**우연 = 14.3%.** ✅**전부 우연의 2.1~2.8배** → ★**P1(우연 근처) 기각. 과제가 이 스케일에서 작동한다.**

### 2.1 ★★★순위가 full-val 과 **정반대다** — P2 실패

```
full-val 순위(좋은 순):  initonly < wsd < d36_ag4 < p6d
YNAT 순위(좋은 순):      p6d > initonly > wsd > d36_ag4
```

★**`p6d` 는 full-val 꼴찌인데 YNAT 1위**이고, **`mC_d36_ag4` 는 그 반대**다.

> ★★**P2 실패는 이 실험의 목적이었다** — 계획서가 *"다르면 그것이 P037 의 첫 증거"* 라고 적었다.
> 🚫**그런데 아직 "증거" 라고 부를 수 없다** — §2.2.

### 2.2 ⚠️★★시드 노이즈가 3~5%p 다

| 쌍 | 차 |
|---|---:|
| `mC_initonly` 36.0% vs `_s2` 39.0% | ★**3.0%p** |
| `mC_wsd` 34.2% vs `_s2` 39.2% | ★★**5.0%p** |

★**모델 간 최대 차이가 9.0%p**(30.4 ~ 39.4)인데 **시드쌍이 5.0%p** 다.
→ ★**신호 대 잡음이 1.8:1.** **순위 역전을 주장하기에는 표본이 부족하다.**

⚠️★**500문항의 정확도 SE ≈ 2.2%p** 이므로 **시드쌍 5.0%p 는 SE 의 2.3배** = **진짜 시드 효과**다.
→ ★**필요한 것은 문항 수가 아니라 시드 수**다. **모델당 2시드 이상**이어야 순위를 말할 수 있다.

## 4. ★★★원인 규명 — **모든 모델이 항상 "알 수 없다" 를 고른다**

우리가 뽑은 500문항의 **라벨 분포**(고정 시드 99, 사전 확인값):

| 라벨 | 개수 | 비율 |
|---|---:|---:|
| entailment(맞다) | 182 | 36.4% |
| contradiction(틀리다) | 157 | 31.4% |
| ★**neutral(알 수 없다)** | **161** | ★**32.2%** |

★★★**32.2% = neutral 비율과 소수점까지 일치한다.**
→ ★**모든 모델이 모든 문항에서 "알 수 없다" 를 고른다.** 그래서 정확도가 그 비율과 같고
문항별 결과가 모델 간 **완전히 동일**해 Δ 가 전부 0 이 된다.

### 4.1 ★★왜 그런가 — **길이 정규화가 반대 방향으로 편향됐다**

라벨 문자열: `" 맞다"`(2자) · `" 틀리다"`(3자) · **`" 알 수 없다"`(6자, 공백 포함)**.

우리는 **평균 로그우도**로 비교한다. 그런데 **긴 어구는 뒤 토큰이 매우 예측 가능**하다 —
`"알 수"` 뒤에 `"없다"` 가 오는 것은 거의 확실하므로 **그 토큰들의 CE 가 0 에 가깝고
평균을 끌어내린다.**

> ★★**외부 검토문서 §2 는 *"합으로 하면 짧은 라벨이 이긴다"* 고 경고했고 우리는 평균으로 갔다.**
> 🚫**그런데 평균은 반대편으로 편향된다** — **긴 라벨이 항상 이긴다.**
> ★**함정 28 계열**(*"같은 단어가 다른 규약"*)의 새 얼굴: **한 처방이 두 방향의 편향을 만든다.**
>
> ⚠️★**YNAT 이 안 걸린 이유**: 라벨이 전부 2~4자로 비슷하고 대부분 1~2토큰이라 **편향이 작았다.**

### 4.2 ★수정안 — **PMI 정규화. 그리고 재료가 이미 있다**

```
현재:  argmin  CE(label | ctx)                       -> 긴 라벨이 이긴다
수정:  argmin [ CE(label | ctx) − CE(label | 무맥락) ]  -> 라벨 자체의 사전확률을 뺀다
```

★★**`CE(label | 무맥락)` 은 우리가 KorQuAD 용으로 만든 NC 대조군과 같은 계산**이다.
**이미 구현돼 있고 라벨 과제에도 붙이면 된다**(⚙약 15줄).

⚠️★**"PMI 정규화" 라는 이름은 통용되는 용어이나 원 논문을 조회하지 않았다** —
**문서에서 근거로 인용하지 않는다**(CLAUDE.md 규약).

### 4.3 ★★도구가 **스스로 잡았어야** 했다

**여섯 모델이 전부 같은 값**인데 도구가 **경고 한 줄 없이 표를 찍었다.**

> ★**계측 규약 추가**: *"라벨 과제에서 **한 라벨이 90% 이상 선택**되면 **퇴화**로 표시하고
> 정확도를 읽지 말라고 인쇄한다."*
> **결과 042 §4 에서 `diag_kd_loss.py` 에 넣은 퇴화 감지(총변동거리)와 같은 장치**다.
> ✅**그 장치는 그때 작동했다.** **이번 도구에는 안 넣었다.**
