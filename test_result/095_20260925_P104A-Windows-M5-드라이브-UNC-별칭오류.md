## 1. Stage1B Windows 원본 실행

- 원본: `095_log_20260924_P104A_Stage1B_m5_dense_bridge.txt` · 23:18:09 시작, 종료코드 1, 약 0.1분.
- Windows `z:\TinyLM`에서 Windows Python(`W:\miniforge3\envs\collatz_torch`)이 `scripts/diag_m5_dense_bridge.py`를 실행했다. 코드 SHA 딕셔너리 생성 중 `Path(__file__)`는 `z:\TinyLM\scripts\...`, `ROOT=Path(__file__).resolve().parents[1]`는 `\\wsl.localhost\Ubuntu\home\uranus\tinyLM`이었다. 서로 다른 별칭에 `relative_to(ROOT)`를 적용해 `ValueError`가 났다.
- 오류는 CUDA/체크포인트 존재 검사 **뒤**, 실제 `torch.load`·forward·한 업데이트 **전**이다. 따라서 tiny 모델의 Windows 호환성, 동일 SHA, CE·gradient·메모리와 WSL 대조는 `NOT_RUN`이다. 원본 로그를 성공으로 바꾸지 않는다.

## 2. 원인과 이전 검사 공백

진단기는 대부분의 CODE 항목을 ROOT에서 구성했으나 자기 파일 하나만 미해결 `Path(__file__)`로 넣었다. 기존 Linux 정적 검사와 `--check-only`는 코드 SHA 생성 전 반환하므로 이 Windows Z/UNC 혼용 분기를 밟지 않았다. BAT 형식 린트 PASS를 OS 독립 런타임 PASS로 오인한 검증 공백이다.

수정은 코드 SHA 키를 `scripts/diag_m5_dense_bridge.py` 등 **고정 저장소 상대 이름**으로 두고, 모든 경로를 같은 ROOT에서 조립하는 것이다. Windows 드라이브·UNC·POSIX 순수 경로 자기시험은 PASS했다. 이 시험은 Windows 실제 파일·CUDA·모델 로딩을 검증하지 않는다.

## 3. 재실행과 판정

- 원본 Stage1B BAT는 실패 이력과 명령을 아래 부록에 보존하고 파일 자체는 사용자 승인으로 삭제했다. 새 [Stage1Bb BAT](../run_P104A_Stage1Bb_m5_dense_bridge-done.bat)는 경로 자기시험 뒤 같은 tiny checkpoint·seed104·write-once JSON을 수집하도록 작성했다. 현재 사용자 Windows E2E는 `NOT_RUN`이다.
- Stage1Bb가 성공해 Windows JSON이 존재하고 같은 code/checkpoint/input SHA를 갖춘 뒤에만 기존 WSL Stage1W를 진행한다. 이미 Windows 출력이 있으면 자동 덮어쓰지 않고 원인 판독이 먼저다. M5의 **실제 모델 품질 교량은 소형 합성 PASS여도 별도**다.

### 6.2 Stage1Bb — Windows tiny dense 교량 수집 PASS, 양 OS 비교 NOT_RUN

원본 `095_log_20260925_P104A_Stage1Bb_m5_dense_bridge.txt`에서 사전 comparator fixture와 Windows CUDA tiny model 수집이 모두 종료코드0이다. 사용자 승인 아래 정확한 `runs/bench/p104a_m5_windows.json` 한 파일만 직접 열어 아래를 검산했다. 저장된 schema는 `TINYLM_M5_SMALL_DENSE_V2`, Python 3.10.19, Torch 2.10.0/CUDA 13.0, GPU RTX 4070 Ti SUPER다.

| Windows JSON 필드 | 원본값 | 의미 |
|---|---:|---|
| eval CE / train one-step CE / post-step eval CE | 10.42415047 / 10.42415047 / 10.42401314 | 동일 synthetic 32-token 입력, 품질벤치 아님 |
| one-step gradient norm / 갱신된 좌표 변화 | 1.18074405 / 1.1920929e-7 | 비영 update 확인 |
| peak allocated / reserved | 107,737,600B / 140,509,184B | Windows 이 실행의 CUDA 지표 |
| checkpoint·input SHA | JSON에 각각 기록 | 다른 경로의 재계산은 아직 안 함 |
| code SHA 5개 | 현 WSL 작업트리의 다섯 코드 파일과 모두 일치 | 지금 코드 수정 전의 양 OS 비교 선결 |

경고는 `scripts/diag_m5_dense_bridge.py`의 `float(loss)`가 `requires_grad=True` scalar를 JSON에 옮길 때 발생했다. 해당 변환은 `loss.backward()`·`optimizer.step()` 뒤에 있고 기존 텐서를 제자리 변경하지 않는다. 이 경고만으로 정합·gradient·저장 수치를 무효화할 근거는 없다. 지금 `float(loss.detach())`로 소스를 바꾸면 Windows JSON이 기록한 진단기 코드 SHA와 WSL 코드 SHA가 달라져 비교기가 선행 단계에서 종료한다. **따라서 이번에는 코드를 고치지 않는다.** 우선 같은 코드로 사용자 WSL `run_P104A_Stage1W_m5_dense_bridge.sh`를 실행해 checkpoint/code/input SHA와 CE·gradient 차이를 대조한다. 그 후 별도 유지보수 변경으로 경고를 없앨 수 있다. WSL JSON과 양 OS functional bridge 판정·전체 M5 품질은 현재 `NOT_RUN`이다.
