## 1. 한 줄

★★**이번 실행은 `tinylm` 패키지 import 실패로 첫 2:4 연산 전에 종료됐다.** 따라서 native 2:4 지원·정확성·input-gradient·속도는 실패가 아니라 모두 `NOT_RUN`이며, 진입 경로를 고친 새 Stage0b 재실행이 필요하다.

## 2. 실패 지점과 원인

```text
File "z:\TinyLM\scripts\diag_sparse24_backend.py", line 32, in main
  from tinylm.model.sparse_connectivity import exact_nm_mask
ModuleNotFoundError: No module named 'tinylm'
```

`python scripts\diag_sparse24_backend.py`로 실행하면 Python의 첫 module 검색 경로가 `scripts/`가 된다. 이 스크립트에는 저장소 루트를 `sys.path`에 넣는 bootstrap이 없어 형제 디렉터리 `tinylm/`을 찾지 못했다. 데이터·GPU 지원·희소 kernel과 무관한 실행 진입 결함이다.

## 3. 조치와 현재 증거

- `scripts/diag_sparse24_backend.py`가 자기 위치에서 저장소 루트를 계산해 import 전에 `sys.path`에 넣도록 수정했다.
- `scripts/check_hf_redirect.py`, `python -m py_compile`, `git diff --check`는 통과했다.
- Codex는 GPU 진단을 실행하지 않았다. 수정 후 실제 2:4 게이트는 새 Stage0b 사용자 실행 전까지 `NOT_RUN`이다.
