# P108 — 직접 가중치 방향 수리와 학습 개입: 반복 감소와 정답 회복을 구분한다

> 계기: 사용자107과 [착수 근거·영향도](../docs/research/20261104_P108_직접가중치수리_착수분석.md). 허가 종료 2026-11-05 02:00 KST. 타 세션 정제·추가300M·원본 변경은 제외한다.

## 1. 왜

기존 P093B의 활성·캐시 진단은 원인 관찰이고 저랭크 복원은 MLP 함수 재구성이다. 새 질문은 완료한 모델의 가중치 일부가 쓰는 방향을 직접 바꿨을 때 반복과 정답이 함께 바뀌는가다. 외부 Qwen 사례는 성공 근거이지만 Gemma270M의 음성은 TinyLM의 지식 부족을 방향 수리만으로 해결하기 어렵다는 반례다.

## 2. 질문

| 번호 | 질문 | 이유 |
|---|---|---|
| Q1 | 편집·원복과 no-op가 실제 등록 가중치/계산 캐시에서 정확한가 | 조용한 stale cache와 가짜 편집 방지 |
| Q2 | 반복 이력에서 얻은 방향이 무작위 방향보다 독립 반복을 줄이는가 | 위치 관찰을 직접 개입과 구분 |
| Q3 | 정답·종료·일반 복사/명시 반복은 보존되는가 | 빠른 오답·빈 답을 개선으로 오인하지 않음 |
| Q4 | 연속 계산 보정이 삼진 재양자화에서도 실현되는가 | 새 FP 인자를 삼진 배포로 오인하지 않음 |
| Q5 | 학습 중 제약에 연결할 근거와 비용이 생겼는가 | Muon의 실제 갱신과 gradient 투영 구분 |

## 3. 예측

반복과 특정 down 쓰기 방향에 인과관계가 있으면 targeted 편집이 같은 크기 random보다 반복을 줄일 수 있다. 그러나 정상 문장/복사와 방향이 겹치거나 모델이 지식을 배우지 못했다면 정답 개선은 없거나 손상이 더 클 수 있다. 삼진 잠재 편집은 재양자화에서 사라지거나 scale을 통해 다른 열까지 영향을 줄 수 있다. 성공 수치·층·배율을 외부 모델에서 복사하지 않는다.

예측 대조: Q/F 독립 확인은 정확12→12와5→5로 무작위 범위 안이었다. 현재 순서 대비 방향의 수리 이득 예측은 지지되지 않았다. 삼진 scale의 선택 밖 전파 위험은 실제1,310,745개로 확인됐다. Stage5는 다른 가설이며 앞 음성을 성공으로 정정하지 않는다.

## 4. 단계 설계

### Stage0W — CPU 계약, 설계 봉인: 보완 완료·원실패 보존

수식·0편집·희소 열·예외 원복·연속/삼진 계산 차이·안전한 경로·수치/스키마를 검증한다. 소스 SHA와 profile·규칙형 repair/dev/test를 동결한다. GPU0. 오류이면 다음 단계 미실행이다.

### Stage1W — 원본 생성과 방향 수집: v1 관측·v2 완료

완료6종 중 new595-broad-q부터 strict loader로 읽는다. 같은 모델 FP32 MATH·chat32·greedy·R1·cache ON·MTP OFF로 repair 질문의 원답을 보존한다. 반복 이력과 정답 또는 순서 대조 이력에서 각 down 입력/출력을 모은다. 새 모델 학습0, 원본 변경0. 최대30분 예상. 수리 선택에는 repair/dev만 사용한다.

### Stage2W — 직접 수리와 무작위 대조: Stage2bW 완료

원본·targeted 계산 캐시 보정·targeted 잠재 편집 후 재양자화·norm-matched random을 비교한다. down 층 후보는 원본 repair 활성 대비로 순위를 매기고 상위2층을 사용한다. 열 수32, 배율0.25/0.5/1/2를 dev에서 비교한다. 무작위는 같은 층·열 수·실제 계산 delta Frobenius norm으로 맞춘다. 무작위 seed3개를 보존한다. dev 기준은 정확도 우선, 동률이면 반복/공백 손상과 보정 크기 순서이며 test는 선정에 쓰지 않는다. dev 양성이 없어도 최선 후보와 무작위 대조를 test에서 기록하되 채택 근거로 과장하지 않는다.

### Stage3W — 동결 후보 독립 확인·실제 답 판독: Stage3cW 완료·수리 비채택

선정 설정을 봉인한 뒤 별도 test·명시 복사/정상 반복·일상 질문에 원본/targeted/random을 대응 실행한다. source-family 단위 paired bootstrap은 탐색 불확실성으로만 기록한다. 공식 벤치마크는 설정 동결 뒤 시간 안에서만 기존 공식 경로/동일 protocol로 실행한다. 없으면 NOT_RUN이다. 최종 정답표와 질문/답 원문을 총괄 GPT가 읽는다.

### Stage0bW/Stage0cW/Stage0dW/Stage0eW — 계약 보완 이력

Stage0b는 이름 연결 수리 뒤 CPU46통과, Stage0c는 음수0 fixture에서 영열을 비영열로 오인한 시험1실패, Stage0d는 fixture의 실제 비영열 대조와 음수0 비트 보존을 함께 통과했다. Stage0e는 아래 실제 지지집합 대응 대조를 CPU에서 추가 검증한 뒤 별도 profile을 봉인한다. 실패 원형을 지우지 않는다.

### Stage1bW/Stage2bW/Stage3bW/Stage3cW — v2 직접 편집과 강화 확인

Stage1b는 비트동일 no-op와 원본 core·같은64원답을 확인했다. Stage2b dev64에서 원본4정답/반복21, 최선 latent gain1은5정답/반복20이었다. 작은 개선은 선정용 관측이며 아직 test 양성이 아니다. 잠재49,152개 변경이 삼진 계산에서 요청 밖1,310,745개로 번져, 좁은 열만 바꾸는 무작위 대조 Stage3b는 실행하지 않는다.

Stage3c는 test를 보기 전에 실제 유효 delta에 행별 무작위 부호를 곱하는3seed 대조를 고정한다. 이는 구성상 정확한 지지집합·절댓값·Frobenius·특이값을 보존하며 출력 방향을 바꾼다. 실제 행렬 덧셈의 차이는 FP32 roundoff 상한2epsilon으로 검산한다. 반대 방향 -delta도 고정 진단으로 추가한다. 원본144·동결target144·부호대조3×144·역방향144를 모두 보존한다. test128의 기대답은 코드로 고정했고 일상16은 자동 정답 점수에서 제외한다. 무작위/역방향의 연속 캐시 경로는 삼진 배포 효과로 확대하지 않는다.

### Stage4W — 연속 모델·학습 개입 연결: 조건부

시간이 남으면 완료 float 모델에 같은 수리를 독립 실시하거나 기존 옵트인 학습 adapter에 가중치 방향 penalty/실제 갱신 제약의 기술 계약을 검토한다. Q/F는 각각 독립 학습된 모델이므로 Q와 F 간 격차를 순수 양자화 효과라고 주장하지 않는다. 새로운 소규모 학습으로 일반 지능 성과를 판정하지 않는다. 정제 미완 때문에 추가300M은 열지 않는다.

### Stage4aW/Stage4bW/Stage4cW/Stage4dW — 완료 실수 모델 대조: 완료·수리 비채택

권장1의 준비를 현재 CPU·GPU 주도 허가 범위에서 진행한다. 같은 new595-broad-f 완료 체크포인트와 동일272문항/정밀도/생성기/선정 정책을 쓴다. Stage4a는 float에서 잠재와 캐시의 비영점 편집이 실제 bit-identical함을 CPU로 확인하고 별도 v3 profile을 봉인한다. Stage4b에서 자연 반복4개 미만이면 강제 반복을 근거로 품질 수리하지 않고 후속은 보류한다. 그 이상일 때 Stage4c는 동일한 두 realization을 중복 실행하지 않고 effective 배율4개만 dev에서 비교한다. Stage4d는 원본·동결후보·같은열/실제norm 대응 random3seed를 test에서 확인한다. 실수 경로에는 삼진 scale 전파가 없어 좁은열 대조가 성립하며, 실제 delta 원복을 검산한다. Q test 결과를 F의 설정 선택에 사용하지 않는다.

### Stage5aW/Stage5bW/Stage5cW/Stage5dW — 정답 민감도 기반 사후 보정: 완료·수리 비채택

Q/F 순서 대비 방향은 독립 확인에서 정답12→12/5→5로 모두 비채택이다. [후속 설계·세 안·영향도](../docs/research/20261104_P108_정답민감도_보정설계.md)에 따라 다른 목표를 사용한다. 정답과 activation gradient를 사용한 사후 보정 학습임을 명시하며 새 작은 학습으로 일반 지능을 판정하지 않는다. 같은 완료 Q checkpoint의 마지막 down 한 곳에서 key·정답 대 경쟁 토큰의 margin gradient·EOT를 수집해 ridge/SVD nominal rank16 보정을 구한다. 원래 parameter.grad/optimizer/원CP 저장은0, 실제 계산 캐시는 바뀐다.

Stage5a는 새 균형 calib128/dev128/test256·strict scoring·독립 선형/gradient oracle을 CPU로 검산하고 태그·소스·profile을 봉인한다. Stage5b는 실제 gradient의 유한차분·동일 위치 연결·원본 불변을 확인하고 key/목표를 수집한다. Stage5c는 FP64 ridge lambda.01, rank16, weight-norm 상한0.25%/1%/4%의 서로 다른 실제 delta만 dev에서 비교한다. Stage5d는 동결 후보와 원본·실제 delta row-sign3팔을 새 test와 기존 일상 회귀16에서 비교한다. 옛 test나 공식 benchmark를 보정 선택에 사용하지 않는다. 시간 상한과 원복이 실패하면 오류/보류로 기록하며 뒤 단계를 닫는다.

예측: 정답 margin의 국소 개선은 가능해도 자유 생성의 자기 오류 경로와 미학습 지식은 남을 수 있다. 교사강제 CE만 좋아지고 실제 정답이 늘지 않으면 수리 채택하지 않는다. 이 새로운 예측을 앞 음성 결과의 정정으로 쓰지 않는다.

### Stage6aW/Stage6bW/Stage6cW — 보정 신호 감쇠와 국소 실제 개입: 기술 완료·수리 비채택 유지

Stage5의 동결 보정과 test 음성을 바꾸지 않고 [세 안·영향도·제외 범위](../docs/research/20261104_P108_보정신호_감쇠진단.md)를 따른다. Stage6aW는 이미 저장한 calibration580위치만 CPU에서 읽어 이상적인 목표·full ridge·rank16·기존 세 상한의 1차 margin을 비교한다. 압축과 norm cap의 감쇠를 분리하되 선형 근사로 실제 정답 증가를 주장하지 않는다. 모든 기존 값과 원형 SHA는 보존한다.

필요한 경우 Stage6bW는 첫4개 calibration 문항을 사전 고정해 원본·동결 보정·상한 없는 rank16·정답별 활성값 주입의 실제 teacher-forced margin을 비교한다. 마지막 조건은 정답 oracle이며 배포 기능이 아니다. 실제 비선형 최대 경쟁토큰과 원래 고정 경쟁토큰을 나눠 기록한다. test/공식 benchmark·새 생성평가·상한 재선택은0이다. 예측은 rank16/상한이 목표 신호를 줄이거나 입력별 oracle과 공유 행렬의 차이가 드러날 수 있다는 것이며 어느 결과도 사전 정답으로 가정하지 않는다. 모델/생성기/기존 solver는 수정하지 않는다.

Stage6aW는 CPU6/0·0.275초로580위치의 선형 감쇠를 확인했다. Stage6b0W의 CPU hook6 뒤 실제6bW에서 네 문항의 원 core/logit 원복은 확인했으나 종료 allocator 검사1로 중단됐다. 원형과 실패 로그를 보존했다. Stage6c0W는 실패 후 독립 최종 검사가 모두 실행되는 CPU7을 추가했다. Stage6cW는 기존 close_owned_cuda/cuBLAS 작업공간 정리 helper만 재사용하고 같은 질문/행렬/정밀도로 별도 gpu_v2에서 수행한다. 이 재실행은 모델 수리 방식 재탐색이 아니라 실패한 종료 증거를 닫는 단계이며 과거 성공으로 소급하지 않는다.

## 5. 판정 기준

| 결과 | 판정 |
|---|---|
| no-op/원복/원본 SHA 불일치·캐시 부정합 | ERROR, 품질 대조 무효 |
| 반복만 감소, 정답/보호 과제 악화 | GATE_NEGATIVE, 수리 비채택 |
| dev만 양성 또는 test에서 random과 구분 미확인 | 탐색 관측, 채택 보류 |
| 독립 test의 정답·반복·보호 과제에서 일관된 이득 | 해당 완료 모델·고정 조건의 후보. 일반 지능/다른 모델로 확대 금지 |
| 시간/자원 만료 | HOLD와 NOT_RUN을 오류와 분리 |

현재 기준표의 학습 val σ/NRMS 문턱은 이 편집 행동 비교에 적용하지 않는다. 새로운 전역 수치 문턱을 사후 설정하지 않는다. Stage0~4는 업데이트0·학습토큰0의 같은 CP 직접 대조다. Stage5는 정답을 사용한 사후 보정 학습이며 지도 토큰 노출을 따로 계측한다.

## 8. 한계

## 12. Stage10 — Attention 후보 선정의 순전파 검증 (설계 2026-11-05 15:40)

Stage9의 dev에서는 반복 방향 기여 상위3헤드가 모두 원본 정답5/64보다 낮았다.
