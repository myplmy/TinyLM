# 실험 근거의 역할·저장 위치·Git 보관 기준

이 폴더는 학습 데이터셋이나 모델 창고가 아니라, `test_result` 결과문서의 판정을 다시 확인하는 **실험 근거**를 둔다. 모든 파일을 스테이징하는 폴더는 아니다. 2026-10-12 사용자 승인 A안에 따라 필요한 근거만 명시 경로로 선별한다.

## 1. 무엇이 저장되어 있고 왜 필요한가

| 자료 | 실제 예 | 보존 이유 |
|---|---|---|
| 구조화된 측정·판정 JSON | `report.json`, 원형 입력 SHA, 분모, 종료사유, 비용·메모리 | Markdown의 요약이나 콘솔 인쇄값과 독립적으로 수치·조건을 재검산한다 |
| 제한된 원답·실패 시도 JSONL | Gemma MTP 6답·원천·과거 답·사고·구조 재시도 | 형식 성공을 내용 정답으로 오인하지 않고, 실패 원인과 실제 답을 후행 판독한다 |
| 상세 진단 JSONL | 반복 시작 전후 로짓·KV·층별 관찰 | 평균 수치만으로 알 수 없는 시간순 변화와 국소 개입을 확인한다 |
| 샤드 명세 | 파일별 SHA-256·바이트·행 수·연결 해시 | 20MB 분할 뒤에도 누락·변조·순서 변경 여부를 확인한다 |
| 실행 코드 사본 | `executed_gate_snapshot.py.txt` | 실행 뒤 코드가 수리됐더라도 실패 당시 구현을 보존한다. 모든 실행에서 코드 전체를 중복 보관해야 한다는 뜻은 아니다 |
| 로컬 복원 인자 | P093B의 rank별 `.pt` | 실제 재평가에 필요한 수치 가중치다. 이미 전역 `*.pt` 규칙으로 Git에서 제외되어 있다 |

이 폴더를 쓰는 기술적 필수 조건은 없다. 다만 현재 [MTP driver](../../scripts/diag_p101a_sft_mtp.py)와 [Gemma 비교기](../../scripts/diag_p106b_gemma_mtp_production.py), 결과문서·manifest가 정확한 상대경로와 해시로 소비한다. 예를 들어 [결과103 §12](../103_20261010_P093B-MLP잔차와-삼진보정은-실행됐지만-복원문턱에-미달.md)의 두 trace 샤드를 옮기면 원답·관찰 판독 연결이 깨진다. **위치 변경은 생산자·소비자·명세·문서의 함께 수정 및 별도 검증이 선결**이다.

## 2. 역할별 올바른 위치

| 역할 | 기존 또는 권장 위치 | Git 원칙 |
|---|---|---|
| 사람이 읽는 실험 결론 | `test_result/NNN_*.md` | 추적한다 |
| 같은 결론을 재확인하는 작은 측정·판정·제한 원답 | `test_result/evidence/<tag>/` | 출처·민감정보·용량·실제 소비 필요성을 확인한 파일만 선별 추적한다 |
| 완전한 장문 원답·대량 per-token trace·임시 분석/캐시·비공개 자료 | 새 실험의 `test_result/evidence/local/<tag>/` 또는 `runs/diagnostics/<tag>/` | 로컬 전용. 필요한 판정 요약·SHA·선별 창만 추적한다. 단순 해시만 남기고 원본을 지우지 않는다 |
| 교사 생성 학습 코퍼스·학생 직렬화 코퍼스 | 현재 코드의 `HF/sft_ready/<version>/` | 기본 제외. 학습·교정 데이터셋 공개는 별도 출처·권리·개인정보 검토와 사용자 지시가 필요하다 |
| 실제 모델 체크포인트 | `runs/ckpt/` | 제외한다 |
| 새 진단의 복원 인자·활성값 배열 | `runs/diagnostics/<tag>/` 권장 | 제외한다. 기존 `evidence`의 인자는 이동하지 않고 현재 제외 규칙을 유지한다 |
| 토큰화/파생 캐시 | `data_cache/` 또는 위 로컬 진단 경로 | 제외한다 |
| WIP 종료·전수 정적·큐/커밋 보관 감사 | `handoff/audit/` | 실험 수치 근거와 구별해 필요한 감사기록을 보존한다 |

`local/`은 신규 대량/비공개 산출물의 권장 구획이지 기존 코드가 자동으로 이곳에 출력하도록 바뀌었다는 뜻이 아니다. 기존 런처·입력 계약·원형 결과 경로는 이번에 바꾸지 않았다. 앞으로 생산 경로를 정할 때 이 표를 적용한다. 이미 Git에 들어간 파일은 `.gitignore`를 추가해도 추적에서 빠지지 않는다.

## 3. 스테이징 기준과 예외

1. 결과의 조건·분모·음성 판정 또는 후행 원답 판독을 실제로 소비하는 파일인가를 확인한다. 모든 실험의 전체 trace를 무조건 Git에 넣지 않는다.
2. `.pt/.bin`, 모델·배열·데이터셋·캐시·압축 아카이브·`local/`은 제외한다. `.gitignore`는 실수 방지선이며 `git add -f`로 우회하지 않는다.
3. 비밀키·인증정보·개인 대화·보호 데이터 원문을 넣지 않는다. 공개 원천 인용도 원천 ID·revision·권리 상태를 보존한다. `CARD_ONLY`는 해당 카드 정보를 기록했다는 뜻이지 전체 재배포 권리가 검증됐다는 뜻이 아니다. 로컬 커밋은 공개 배포 승인이 아니다.
4. 증거 파일 하나는 **20,000,000 bytes 이하**다. JSONL은 행·UTF-8 문자를 깨지 않고 [샤드 계약](../../scripts/p106b_shards.py)을 사용한다. 모든 샤드의 전체 바이트·행수·연결 SHA도 보존한다. 파일당20MB를 지켰다고 총 저장소 증가가 작아지거나 Git 추적이 자동 허용되는 것은 아니다.
5. 생성 원형은 판독/요약과 별도 보존하고 조용히 덮어쓰지 않는다. 과거 음성·실패를 최신 코드의 성공으로 바꾸지 않는다. 보관 정책 변경만으로 기존 원본을 삭제·압축·개명하지 않는다.
6. 명시한 파일 경로만 `git add -- <paths>`로 스테이징한다. `git add .`, `git add -A`, evidence 폴더 전체를 무검토로 추가하는 방식은 사용하지 않는다. stage된 blob의 크기·원형 SHA와 제외 경로·LFS filter를 마지막에 대조한다.
7. 작은 원답/사고도 데이터이므로 재사용·공개 범위를 따로 검토한다. 이 폴더의 기술 PASS는 `TRAIN_READY`·정답성·안전성 인증이 아니다.

## 4. 2026-10-12 현재 조치

읽기 전용 재고에서143파일/318.7MiB 중107파일/46.9MiB가 기존 Git 추적분이었다. `.pt`21개/270.6MiB는 이미 제외되어 있다. 이는 그 시점의 재고이며 영구 상수가 아니다.

기존 추적분에는 사용자 승인 아래 판정을 기록한 반복 trace 약33.6MiB와 국소 개입 약8.6MiB가 있다. 해당 원형은 결과문서가 직접 인용하므로 이번에 추적 해제·이동·삭제하지 않는다. 향후 새 대량 진단까지 동일하게 전수추적하라는 선례로 사용하지 않는다.

이번 MTP의 신규15파일은 약1.13MiB이고, 보고서·샤드 명세·한정 원답·후행 판독·실행 코드 사본·CPU 토크나이저 계약으로 판정에 직접 연결된다. 이번 로컬 커밋에 선별 포함한다. 학습 코퍼스·모델·보호 원천은 포함하지 않는다. 상세 파일별 분류와 Git 제외 확인은 `handoff/audit/WIP_20261012b_EVIDENCE_STORAGE_REVIEW.json`이 소유한다.
