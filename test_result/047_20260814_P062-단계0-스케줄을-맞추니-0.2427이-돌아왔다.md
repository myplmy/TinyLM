## 2. ★★핵심 발견

### (1) 스케줄 불일치가 **+0.2427** 이었다

`mC_r20` 을 20회로 평가 **3.89219** → 36회로 평가 **3.64953**.
**같은 체크포인트, 같은 크롭, 같은 도구.** 차이는 **평가 스케줄뿐**이다.

결과 043 §13 이 보고한 `paired +0.2275`(vs `mC_wsd`)는 **이 0.2427 위에서 잰 값**이다.
→ **반복의 대가가 아니라 계측 결함의 크기였다.**

### (2) ★★재귀 모델이 기준선을 이겼다

| | val_loss |
|---|---:|
| `mC_wsd` (R=1 학습, R=1 추론) — **표준 기준선** | 3.66609 |
| ★**`mC_r20` (R=2 학습, R=2 추론)** | ★**3.64953** |
| **차** | ★**−0.01656** |

⚠️**분해능(0.024) 미만이므로 "실무상 동급"** 이고, **시드 노이즈(0.0006)의 27배라 통계적으로는 유의**하다
(단 이 도구는 `paired_eval` 이 아니다 — §5).

> ★★★**핵심은 순위가 아니라 이것이다**: **`mC_r20` 은 유니크 삼진·packed·상주가
> `mC_wsd` 와 완전히 같다**(54.85M / 13.05MB / 451.5MB).
> **메모리를 1바이트도 더 쓰지 않고 동급 이상**이 됐다.
> 프로젝트 1순위 목표가 배포 메모리이므로 **이것이 정확히 우리가 찾던 형태의 축**이다.
> ⚠️**대가는 연산·지연이다**(통과 36회 = 약 1.8배).

### (3) ✅ P031 이 재현됐다 — **(b)와 (d)는 다른 조합이다**

| 조합 | 학습 R | 추론 R | val_loss | 해석 |
|---|---|---|---:|---|
| (a) | 1 | 1 | 3.66609 | 기준선 |
| **(b)** | **1** | **2** | **3.96891** | ★**+0.3028 = 나쁘다.** 결과 020 재현 ✅ |
| (c) | 2 | 1 | 3.89219 | **우리가 "반복의 대가" 로 잘못 읽은 값** |
| ★**(d)** | **2** | **2** | ★**3.64953** | ★**가장 좋다** |

★**(b)와 (d)의 차이가 0.3194 다.** *"추론 반복은 학습 분포 mismatch 로 죽는다"* 는
**mismatch 가 있을 때만 참**이고, **학습으로 맞춰 주면 반대가 된다.**
→ **P031(결과 020)의 결론은 (b)에 한정된다. 축은 다시 열린다.**

### (4) 스케줄의 **형태**가 중요하다

| where | val_loss | vs front |
|---|---:|---:|
| **front** | **3.64953** | — |
| back | 3.64953 | **0.00000** |
| even | 3.74875 | **+0.09922** |

✅**front == back 은 정합성 확인이다** — `extra(16) == m(16)` 이면 `mid+mid[:16]` 과
`mid+mid[-16:]` 이 **같은 스케줄**이다. **도구가 옳게 동작한다는 증거.**
🚫**even 은 +0.0992 나쁘다** — `even` 은 층을 **제자리에서 두 번**(`…,7,7,8,8,…`) 돌고
학습은 **블록 전체를 두 번**(`…,7,8,…,7,8,…`) 돌았다. **학습과 다른 형태는 대가를 낸다.**

### (5) `repeat_kv_reuse` 는 예측대로 나쁘다

front + kv-reuse **3.74281** vs front **3.64953** = **+0.09328**.
학습은 매 통과 KV 를 **재계산**했으므로 재사용은 학습과 다른 함수다. ✅**대조군이 의도대로 작동.**

## 4. ⚠️🚫**설명되지 않는 관측 1건 — arm3(R=1.5)이 arm1(R=1.0)과 소수점까지 같다**

```
arm1  R=1.0            층 통과 20회      val_loss 3.8921875
arm3  R=1.5 front      층 통과 28회      val_loss 3.8921875   ← 같다
```

- `[P031]` 줄은 **28회를 인쇄했다** → `visit_schedule()` 은 옳게 계산했다
- 28회 스케줄(`mid + mid[:8]`)은 20회와 **명백히 다른 함수**다
- 그런데 손실이 **최종 자리까지 동일**하다 — 우연일 확률은 사실상 0

> ⚠️**원인 미상.** 이 결과문서는 **관측만 기록하고 해석하지 않는다.**
> ★**판정에는 영향이 없다** — 헤드라인은 arm2 이고, arm4·5·6·7·8 은 전부 서로 다른 값을
> 합리적인 방향으로 냈다(front==back 정합성 포함). **arm3 만 이상하다.**
>
> **후속(§7-2)**: `--infer-repeat 1.25 / 1.75` 를 추가해 **R 곡선을 다시 그린다**(수 분).
> 그때도 정수 아닌 R 이 R=1.0 과 같으면 **`visit_schedule` 의 분수 경로에 결함**이 있는 것이고,
> 그건 P031 의 분수 R 결과 전체(결과 020)를 다시 봐야 한다는 뜻이다.

## 10.4 🚫★★**그런데 무KD 기준선한테는 진다** — 단계0 이 못 본 것

| | full-val | `mC_r20`@R2 대비 |

**단계0 은 `mC_initonly` 를 팔에 안 넣었다.** 그래서 *"기준선을 이겼다"* 로 읽혔는데,

> 🚫**정정: `mC_r20` 은 KD 기준선과 동급이고 무KD 기준선보다 근소하게 나쁘다.**

### 10.4.1 ⚠️**단 공정 비교가 아니다**

`mC_r20` 은 **KD 로 학습**됐고 `mC_initonly` 는 **무KD** 다.
결과 038 이 **KD 제거만으로 −0.0208** 을 쟀다. 그 크기를 그대로 가정하면:

```
⚙무KD + 재귀 R=2  ≈  3.6811 − 0.0208 = 약 3.660     (계산값, 미측정)
                    vs  mC_initonly 3.6776          →  약 −0.018
```
