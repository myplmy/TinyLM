## 3. ★★로더에는 epoch 이 없다 — *"1 epoch"* 은 이름일 뿐이다

`tinylm/data/loader.py:26` 이 전부다:

```python
ix = self.rng.integers(0, len(self.d) - self.seq - 1, self.bs)
```

**균일 랜덤 시작점 · 복원추출**이다. 🚫**에폭 경계도, 셔플도, 미방문 보장도 없다.**
→ ★*"epoch"* 은 `학습토큰 / 풀크기` 라는 **이름**이지 데이터 구조가 아니다.

★**그러면 유니크 토큰은 몇 개인가**: 크롭 `seq`=1024 를 `T/1024` 번 뽑을 때
어떤 토큰이 **한 번도 안 덮일 확률**은 `(1 − 1024/P)^(T/1024) ≈ e^(−T/P)` 다.

| 런 | 풀 P | 토큰 T | 커버리지 `1−e^(−T/P)` | ★**유니크 토큰** |
|---|---:|---:|---:|---:|
| 표준 300M 런(`d12_cla2_r20` 등) | 600M | 300M | **39.35%** | ★**236.1M** |
| `e1` | 300M | 300M | 63.21% | 189.6M |
| `e2` | 300M | 600M | **86.47%** | **259.4M** |

★★**우리가 *"300M 토큰 학습"* 이라고 불러 온 것의 유니크 토큰은 236M 이다.**
→ **파라미터당 토큰 3.7 은 유니크 기준으로 2.9** 다(81.2M 파라미터).
외부(SmolLM2 약 6,470)와의 배수가 **1,749 → 2,231배**로 커진다.

⚠️★**이것은 유도값이다**(⚙). 실측하려면 `diag_cache.py` 급 도구가 크롭 시작점을 세야 한다 —
🚫**아직 안 쟀다.** 다만 **로더 코드 한 줄이 근거**라 모형 자체는 튼튼하다.

### 3.1 그래서 §2.1 의 세 줄을 유니크 토큰으로 다시 읽으면

| 비교 | Δ유니크 | Δ nats | nats / 유니크 100M |
|---|---:|---:|---:|

| `e1` → `e2`(토큰만 2배) | +69.8M | −0.1155 | 0.165 |

★**셋이 0.126~0.185 로 같은 자릿수**다 → ⚙**"이득의 대부분은 유니크 토큰이 설명하고,
반복 노출 자체의 값은 작다"** 는 읽기와 모순되지 않는다.
🚫**단 세 점으로 함수를 세우지 않는다** — **P088(풀 1.2B · 토큰 600M · 유니크 472M)이

| ★**이번 직접 실측** | 풀 600M, 300M→1,200M | ★**−0.20078125** |
| ★**잔차(실측−예측)** | | ★**−0.01968750** |

잔차는 dense 자의 **9.4배**다. → 🚫**두 레버가 겹쳐 이득을 먹어 버린다는 가설은 기각**되고,
이번 600M 풀·12층·AdamW 조합에서는 **가법보다 10.9% 더 개선**됐다. 리뷰3 안 B의 *“약 −0.18”*은
낙관이 아니라 **보수적 예측**이었다.

⚠️단, 두 구성항의 시험지는 각각 풀 1,200M와 300M다. 이 잔차를 풀 크기 전반의 보편적인
“교호작용 상수”로 쓰지 않는다. 이번 실험이 직접 확정한 것은 **두 축을 실제로 쌓았을 때 총 이득이
사라지지 않았다는 것**이다.

### 10.3 과적합·커버리지·안정성

- `val−train_ce` 마지막 10회 평균 **+0.02237**(범위 −0.0392~+0.1153) — 문턱 0.3의 **7.5%**.
  ★**2.0 풀 노출에서도 과적합 징후가 없다.** 마지막 한 점(+0.1153)이 아니라 꼬리 평균을 읽었다.
- 복원추출 모형의 유니크 커버리지 `1−exp(−T/P)` = **86.47%**, 약 **518.8M 토큰**(⚙)이다.
- `n_skip=0`, warmup 이후 `grad_max=0.9320`(warmup peak 9.7453)으로 안정성 이상이 없다.
- 정상구간 JSON 중앙값은 **2,537.2 ms/step**이다. 다른 날 런과 속도 서열을 만들지는 않는다.

### 10.4 ⚠️남은 확인 — 배치 꼬리말은 요구했지만 명령이 없었다

배치 꼬리말은 대조군과 `paired_eval --tokens 600M`을 요구하지만 **실제 배치에는 그 호출이 없다.**
따라서 −0.20078은 **학습로그 눈금의 직접 비교**이며 full-val 값으로 바꾸거나 오프셋을 보정하지 않는다
(규칙 52). 차이가 자의 95.6배라 *“이득이 사라지지 않았다”*는 판정은 강하지만, 엄격한 짝 비교 수치와
크롭별 t·승률은 **미측정**이다.

또한 JSON의 `best_val=3.3684375@8900`은 마지막 별도 final 평가 3.35640625를 best 추적기에 다시 넣지
않는 구현 특성이다. 🚫**best가 final보다 나쁘다는 것을 성능 역전으로 읽지 않는다.**
