# 실험 003 — P014①: 커스텀 삼진 커널 레퍼런스 정확성

- 실험계획: P014 (커스텀 삼진 커널 검증)

## 결과 (수정 전)
- k_off(기존 경로) vs k_ref(커널 레퍼런스): **step0부터 loss 불일치** (10.4017 vs 10.3978, 최종 9.318 vs 9.371).

## 원인
- 커널이 **삼진 어닐링을 미구현**. 기존 경로는 `_wq = wq + (1-anneal)·(w-wq).detach()` 로
  anneal<1 구간에서 **full-precision↔삼진 블렌드**(step0은 anneal=0이라 사실상 full-precision)를 쓰는데,
  커널은 **항상 순수 삼진** → 어닐 구간(=이 40스텝 대부분) 내내 달라짐. anneal=1에서만 일치.
- **P014가 의도대로 버그를 사전 포착**(실사용 전 검증 게이트).

## 수정
- 커널 forward가 동일 어닐 값(eff = wq + (1-anneal)(w-wq))을 쓰고, **anneal>=1(완전 삼진)에서만 저비트 경로**
  사용하도록 재작성. backward는 STE window(어닐 무관) 유지 → 기존 경로와 값·gradient 모두 동일.
- (별건) backward dtype 충돌(bf16 @ float32)도 수정.

## 다음
- P014① 재실행 → k_off와 k_ref loss가 **정확히 일치**해야 정상. 이후 ② Triton 정확성, ③ 속도.

## 재검증 (어닐 수정 후)
- k_off vs k_ref: **step0 정확히 동일(10.4017=10.4017)** → forward bit-exact. 최종 9.3181 vs 9.3169(차 ~0.001).
- 잔차 원인: backward의 **가중치 grad를 커널은 float32, 기존 경로는 autocast(bf16)로 계산** → bf16 누적 정밀도 차이.
  **로직 버그 아님, 커널이 오히려 더 정밀.** → **수학적 등가 확인, 수정 불필요.** P014① 사실상 통과.
- (원하면 backward를 bf16로 맞춰 완전 일치 가능하나 float32가 정확도상 유리.)
