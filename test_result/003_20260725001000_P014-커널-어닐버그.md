# 실험 003 — P014①: 커스텀 삼진 커널 레퍼런스 정확성

- 실험계획: P014 (커스텀 삼진 커널 검증)

## 결과 (수정 전)
- k_off(기존 경로) vs k_ref(커널 레퍼런스): **step0부터 loss 불일치** (10.4017 vs 10.3978, 최종 9.318 vs 9.371).

## 원인
- 커널이 **삼진 어닐링을 미구현**. 기존 경로는 `_wq = wq + (1-anneal)·(w-wq).detach()` 로
  anneal<1 구간에서 **full-precision↔삼진 블렌드**(step0은 anneal=0이라 사실상 full-precision)를 쓰는데,
  커널은 **항상 순수 삼진** → 어닐 구간(=이 40스텝 대부분) 내내 달라짐. anneal=1에서만 일치.
- **P014가 의도대로 버그를 사전 포착**(실사용 전 검증 게이트).

## 수정
- 커널 forward가 동일 어닐 값(eff = wq + (1-anneal)(w-wq))을 쓰고, **anneal>=1(완전 삼진)에서만 저비트 경로**
  사용하도록 재작성. backward는 STE window(어닐 무관) 유지 → 기존 경로와 값·gradient 모두 동일.
- (별건) backward dtype 충돌(bf16 @ float32)도 수정.

## 다음
- P014① 재실행 → k_off와 k_ref loss가 **정확히 일치**해야 정상. 이후 ② Triton 정확성, ③ 속도.

## 재검증 (어닐 수정 후)
- k_off vs k_ref: **step0 정확히 동일(10.4017=10.4017)** → forward bit-exact. 최종 9.3181 vs 9.3169(차 ~0.001).
- 잔차 원인: backward의 **가중치 grad를 커널은 float32, 기존 경로는 autocast(bf16)로 계산** → bf16 누적 정밀도 차이.
  **로직 버그 아님, 커널이 오히려 더 정밀.** → **수학적 등가 확인, 수정 불필요.** P014① 사실상 통과.
- (원하면 backward를 bf16로 맞춰 완전 일치 가능하나 float32가 정확도상 유리.)

## P014② — Triton forward 정확성 테스트 (2026-07-25)

- 실험계획: P014 (커스텀 삼진 커널 검증) — ② Triton 경로.
- 증상: `--ternary-kernel-triton` 로 t_kd_g16 진행 중, **약 10스텝 이후** Triton 실패 →
  레퍼런스 폴백 메시지가 **매 forward마다** 출력되어 cmd 버퍼를 초과, 로그 확인 불가.

### 원인 (확정, 디버그 로그 불필요)
1. **Triton 컴파일 에러 = `arange's arguments must be of type tl.constexpr`.**
   커널 `_tern_mm_kernel` 의 `offs_g = tl.arange(0, G)` 에서 `G`(=micro_group=128)를
   **런타임 커널 인자**로 넘겼다. `tl.arange` 의 상한은 반드시 **컴파일타임 상수(constexpr)** 여야 한다.
   → JIT 컴파일 단계에서 실패.
2. **왜 "10스텝 이후"에 터졌나 = 정상 동작.** Triton 저비트 경로는 `anneal>=1.0`(완전 삼진)에서만
   활성. 어닐이 1.0에 도달하기 전(초기 ~10스텝)은 full-precision 블렌드(`F.linear`)라 커널 미호출 →
   조용. 어닐=1 도달 순간 모든 TLinear가 Triton 시도 → 전부 컴파일 실패 → 폴백.
3. **로그 폭주 = 폴백 print 가 forward마다 실행.** TLinear 다수(q/o/k/v/gate/up/down×층) × 스텝 ×
   accum → 수천 회. (결과는 오염 안 됨: 폴백이 레퍼런스=기존 경로와 수학적 동일이므로 **학습은 정상**.)

### 수정
- `ternary_kernel.py`: 커널 시그니처에서 `G` 를 **`tl.constexpr`** 로 이동, 런치 시 `G=group`(키워드
  constexpr)로 전달. 루프 내 alpha 그룹 인덱스는 수동 카운터(`g_idx`) 대신 **`kb // G`**(constexpr 나눗셈)로.
- **폴백 경고 1회화**: 모듈 전역 `_KERNEL_WARNED` 플래그 → 최초 1회만 출력(`...(이후 조용히)`), 이후 침묵.
  에러 메시지도 120자로 절단. → 폭주 원천 차단(향후 다른 커널 오류가 나도 로그는 1줄).

### 상태
- 컴파일 에러 원인 **확정 → 별도 디버그 로그 추가 불필요**. constexpr 수정으로 해소 예상.
- 안전성: 설령 Triton이 또 실패해도 폴백=레퍼런스(정확)라 **학습 오염 없음**, 로그도 1줄. 재실행 안전.
- 다음: `--ternary-kernel-triton` 재실행 → (a) 폴백 경고가 최대 1줄인지, (b) Triton이 실제로 도는지
  (경고 없으면 성공), (c) k_ref vs k_triton loss 일치(bit-exact 또는 bf16 잔차 ~0.001) 확인. 그 뒤 ③ 속도.
