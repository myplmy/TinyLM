종결 소비자도 대조하니 기존 WIP는 V1 schema와 오류 수만으로 정적 증거를 수락했다. 초기 소유 영수증 v1/v2에 같은 schema를 쓰는 것은 부분 결과를 전역 종결로 오인할 위험이 있었다. 원형은 보존하고 최종 생산자는 별도 TINYLM_SCOPED_STATIC_AUDIT_V1을 출력하도록 수정했다. 기존 종결기가 이 schema를 거부하는 CPU 반례도 추가했다. 전역 schema와 WIP 도구는 변경하지 않았다.

마감 중에는 진행 행에 --start를 다시 주어 상태 전이2가 발생했고, 이후 정확 수정 전 값을 읽어 세 셀 CAS로 갱신했다. capsule-check의 로그 리다이렉션은 직접 WIP 수정으로 훅이 거부해 실행되지 않았고, 리다이렉션 없이 정식 API를 실행해0을 확인했다. 쓰기 전 문자 검사 정규식의 오타 한 건도 JS 파싱 단계에서 중단돼 중첩 실행0이었다.

인계의 정적 링크 label/suffix와 아직 생성 전인 결과 링크 때문에 첫 구조 검사3오류가 났다. 원래 전역 감사의 명시 링크를 복원하고 이미 존재하는 소유 증거를 연결해 v2 구조0을 얻었다. v4 소유 검사의 링크1오류 역시 생성 중인 자기 결과를 문서가 미리 참조한 것이었으며, 기준을 바꾸지 않고 존재하는 증거를 연결한 v5의6/0/71을 회수했다. 제안서의 기존 양식 anchor5누락도 전용 lint로 검출해 양식·비용 label·계측위험·A 셀을 복원하고0을 확인했다. 실패 원형은 삭제하거나 성공으로 덮지 않았다.
