> 상태: **Codex 독립 이식본 / P7 통과(`STATIC_ONLY / E2E_NOT_RUN`)**
> 환경 경계: [`README.md`](README.md)  
> 작업규약: [`00_WORKING_RULES.md`](00_WORKING_RULES.md) · [한글 대조본](00_작업규약_한글판.md)
> 환경 검증: [`P7_정적종합검증_보고.md`](P7_정적종합검증_보고.md)

이 문서는 TinyLM에서 일하는 Codex가 필요한 **프로젝트 맥락과 현재 상태의 색인**이다. 실험 수치의 정본을 복제하지 않으며, 최신 핸드오프·COMPASS·기준표·결과 문서를 어디서 읽을지 알려준다.

## 0. 세션 시작과 정본 우선순위

### 0.1 읽는 순서

1. `AGENTS.md` — P6에서 축약·전환된 매 프롬프트 영구 경계.
2. [`00_WORKING_RULES.md`](00_WORKING_RULES.md) — 현재 유효 작업규약.
3. 이 문서 — 프로젝트 목적, 보호선, 현재 상태.
4. [`handoff/COMPASS.md`](../../handoff/COMPASS.md) — 연구축별 현재 위치와 다음 증거.
5. `handoff/`의 최신 유효 `*_HANDOFF.md` — 직전 작업의 실제 완료·미실행·사용자 요청.
6. 작업 유형에 맞는 Codex 01~08과 `.agents/skills/**` — P7 정적 계약은 통과했지만 P8 전에는 새 세션 발견·라우팅을 가정하지 않는다.

최신 공유 핸드오프는 파일명·`이전` 체인·존재 증거를 동적으로 대조해 고르며, 이 문서에 특정 파일명을 최신값으로 고정하지 않는다.

### 0.2 충돌 시 우선순위

1. 사용자의 현재 지시와 승인 범위
2. 삭제·GPU·데이터·Git·동시 작업 보호 경계
3. `AGENTS.md`의 Codex 영구 규범과 이 폴더의 분리 계약
4. 최신 유효 핸드오프, COMPASS, `docs/EXPERIMENT_BASELINES.md`
5. Codex 00~08
6. 실제 코드·로그·결과 문서의 해당 정본

실험 수치가 충돌하면 더 최신처럼 보이는 요약을 택하지 않는다. 결과 문서와 기준표의 측정 조건을 직접 대조한다. 환경 경로가 충돌하면 공유 문서 안의 레거시 에이전트 포인터를 따르지 않고 Codex 경로를 쓴다.

### 0.3 완전분리 경계

Codex의 활성 환경 원천은 `AGENTS.md`, `.agents/**`, `.codex/**`, `ai_dev_tool/Codex/00~08`이다. 공유 프로젝트 문서·코드·결과는 직접 읽을 수 있다.

Codex는 다른 에이전트 전용 지침·스킬·훅을 런타임 fallback으로 사용하지 않는다. 과거 핸드오프나 원장에 다른 환경의 경로가 보여도 현재 명령으로 따라가지 않는다. 루트 `ai_dev_tool/09_구현검증_필요목록.md`만 사용자가 정한 공유 원장 예외이며, 복사하지 않고 현 위치를 링크로 참조한다.

## 1. 프로젝트 목적과 환경

TinyLM은 저사양 CPU·엣지·모바일 배포를 위한 초경량 LLM 아키텍처 연구 프로젝트다. 사전학습 모델을 단순 변환하는 작업이 아니라 PyTorch에서 from-scratch 학습하며, 연산 절감보다 **배포 상주 메모리 절감**을 우선한다.

| 항목 | 현재 지침 |
|---|---|
| 작업 루트 | `Z:\TinyLM` |
| 사용자 하드웨어 | Windows, RTX 4070 Ti Super 16GB 단일 GPU |
| 배포 목표 | 상주 ≤16 MiB(엔트리), 32 MiB(메인스트림), 40 MiB(데스크톱 상한). 현 연구 의사결정은 주로 32·40 MiB |
| 속도 기준 | 단일 CPU·단일 코어 ≥15 tok/s. 속도는 현재 우선순위 ③이며 단독 종결 게이트가 아님 |
| 목표 우선순위 | ① 상주 메모리 ② 지능/품질 ③ 속도 |
| 코드 계보 | 코드 v6(`tinylm/`), 아키텍처 v5. 정확한 현재 구조는 코드와 최신 핸드오프가 정본 |

메모리 단위는 MiB다. 숫자를 인용할 때 저장(`packed`)과 상주(`runtime`), 모델/KV dtype/컨텍스트, 실측인지 식(⚙)인지를 함께 적는다.

## 2. Codex 작업 보호선

### 2.1 절대 금지와 승인 경계

- Codex는 학습·GPU 코드·모델 로딩 진단·실험 배치·`run_smoke_check.bat`을 직접 실행하지 않는다. 배치와 절차를 준비하고 사용자가 실행한다.
- 파일을 삭제하지 않고 삭제 권한도 요청하지 않는다. 삭제 후보는 핸드오프의 사용자 요청 표에 적는다.
- commit·push·PR·광범위 staging은 사용자의 명시 지시 없이는 하지 않는다. `git add .`와 `git add -A`는 사용하지 않는다.
- `datasets/TinyDataset/**`는 2026-09-11 현재 데이터셋 팀이 생성 작업 중이다. P0~P4·P6 수행 중 열람·열거·해시·검색·검사·수정·staging을 모두 하지 않는다.
- 사용자 또는 다른 작업자의 dirty/untracked 파일은 해당 작업자의 소유다. 변경 허용목록 밖 파일을 정리하거나 되돌리지 않는다.
- 설치·다운로드·외부 획득, 장시간 계산, 보호 데이터 변경은 별도 승인을 받는다.

세부 규약과 증거는 Codex 00, 반복 사고는 01·04·08을 따른다.

### 2.2 정적 검사와 실제 실행을 분리한다

| 수준 | 의미 | 완료 표현 |
|---|---|---|
| 제안/계획 | 무엇을 할지 정함 | `PLANNED`, 구현 아님 |
| 정적 검사 | 구문·링크·정본·계약 확인 | `STATIC_ONLY`, 동작 증명 아님 |
| 모의 검증 | 합성 입력에서 도구 계약 확인 | 실제 프로젝트 E2E 아님 |
| 동적 스모크 | 실제 경로·모델 로딩 확인 | 사용자 실행 증거가 있어야 함 |
| 학습/벤치 | GPU·장시간 실제 실행 | 사용자 로그와 JSON이 있어야 함 |
| 배포 | 목표 환경에서 상주·속도·기능 확인 | 별도 배포 증거가 있어야 함 |

정적 통과를 학습·품질·훅 활성화 증거로 승격하지 않는다. 실행하지 않은 항목은 `NOT_RUN`으로 남긴다.

### 2.3 Windows와 문서 편집

- 긴 문서와 백슬래시가 많은 본문은 셸 문자열 조립으로 쓰지 않고 전용 패치/편집 수단을 쓴다.
- PowerShell에서 UTF-8이 필요한 사용자 명령은 `$env:PYTHONIOENCODING='utf-8'`을 먼저 설정한다. `cmd.exe` 예시는 `set PYTHONIOENCODING=utf-8`을 쓴다.
- `.bat`은 ASCII·CRLF 규약을 따르며 전용 `run-batch` 절차를 사용한다.
- 경로 대소문자에 의존하지 않는다. Codex 네이티브 설정 폴더 표기는 `.codex`, 저장소 스킬은 `.agents/skills`다.

### 3.2 연구축의 현재 입구

세부 수치와 판정은 [`handoff/COMPASS.md`](../../handoff/COMPASS.md)를 직접 읽는다. 이 문서는 방향만 요약한다.

| 축 | 현재 요약 | 다음 증거의 성격 |
|---|---|---|
| 깊이 | 열림. 18층에서도 포화하지 않았고 일부 상주·속도는 식 | d18 상주·단일코어 속도 실측 |
| 폭 | 열림. 메모리·속도 이점은 있으나 품질 대가가 미측정 | P089 품질 격자 |
| 재귀 | 상주 축의 부품이나 같은 방문 수에서는 깊이가 유리. 일부 방식 종결 | 공통 bpb와 승인된 후속 구현 |
| MLP/attention 타잉 | 작은 group 격자가 비어 있어 열림 | P045B |
| CLA/KV | 깊이보다 싼 후보 부품 | 컨텍스트·LR 조건을 붙인 검증 |
| 양자화 | 상주 회계는 진전, LUT 커널 속도는 열림 | 실제 커널/속도 증거 |
| 토큰·코퍼스 | 현재 가장 큰 실측 레버 | 공통눈금과 추가 토큰 런 |
| 옵티마이저 | Muon 전이가 관측됐지만 최적 배수와 몸통 의존성은 열림 | 본런 길이·이웃 배수·무재귀 몸통 |
| 토크나이저/어휘 | 보류 | 16 MiB 목표가 실제 우선순위가 될 때 |
| 속도 | 열림, 단독 종결 게이트 아님 | 후보별 실측과 커널/멀티코어 |
| 지능/벤치 | held-out 판정 단위와 시드 변동 문제가 남음 | 여섯 체크포인트 census와 가족 재표집 |

이 표가 COMPASS와 다르면 COMPASS가 이긴다. 이 표에 새 실측값을 추가하지 말고 결과 문서→기준표→COMPASS를 먼저 갱신한다.

### 3.3 다음 실행 큐

실제 실행 순서·현재 배치명·예상 시간은 최신 공유 핸드오프 §6b·§7이 정본이다. 이름과 시간이 변하므로 이 문서에 복제하지 않는다.

현재 안전한 요약은 다음뿐이다.

- 동적 스모크가 장시간 큐보다 먼저다.
- 스모크와 모든 GPU/모델 로딩 실행은 사용자가 한다.
- 큐 id는 변하므로 이름으로 안내하고 필요할 때 `queue_menu.py --ids`가 계산한다.
- 현재 Codex 환경 구축은 연구 큐를 실행하거나 재편성하는 권한이 아니다.

### 4.2 반복해서 지킬 판정 원칙

- 학습로그 val, 결정적 full-val, common bpb, downstream 정확도/CE/margin을 같은 눈금으로 취급하지 않는다.
- “동급”과 “통계적으로 유의”를 분리하고 계열별 자를 `scripts/_rulers.py`에서 읽는다.
- 상주와 저장, 실측과 식, 모델과 KV, dtype과 컨텍스트를 구분한다.
- 짧은 런은 축 탐색·속도·VRAM에 쓰고 본런 품질 최적 결론으로 승격하지 않는다.
- 새 지표가 예상보다 깨끗하면 모델보다 계측 경로와 유효 표본 단위를 먼저 의심한다.
- 논문 기법은 실제로 읽은 절과 구현 차이를 기록하고 루트 09의 검증 상태를 확인한다.
- 후보의 목적함수는 상주·지능·속도다. 품질 한 지표로 파레토 후보를 삭제하지 않는다.

| 논문 기반 구현 | Codex 00 R50/R55, 04 D21, 루트 09 | 사본·읽은 절·차이를 확인하기 전 구현 일치 주장 금지 |
| Codex 환경 자체 변경 | 이 README, 승인 제안서, 현재 WIP | 승인된 단계만 수행. 현재 남은 P8 무단 선행 금지 |

`.agents/skills/**`는 P4에서 Codex 독립 이식본으로 전환되고 P7 정적 종합검증을 통과했다.
내용이 이 문서와 충돌하면 스킬을 억지로 따르지 말고 사용자 지시와 Codex 00을 우선한다.
`session-handoff`와 프로젝트 메타데이터 경로도 이식했으나 실제 새 세션 발견·라우팅은 P8 전까지 `E2E_NOT_RUN`이다.

## 7. 이 문서의 갱신 조건

다음 중 하나가 발생한 세션이 이 문서를 갱신한다.

1. 사용자 확정 표준조건·배포 목표·우선순위가 바뀜.
2. 프로젝트의 대표 후보 또는 연구축 상태가 크게 바뀜.
3. 반복 도구 사고가 새 보호선·라우팅 변경을 요구함.
4. Codex 환경 단계(P0~P8)의 상태가 바뀜.
5. 시작 순서·정본 위치·공유/금지 경로가 바뀜.

다음 변화만으로는 갱신하지 않는다.

- 개별 실험 수치 한 줄 추가.
- 게이트 개수만 변함.
- 스크립트 하나가 생김.
- 큐 id나 배치 순서가 바뀜.

그 정보는 각 정본이 소유한다. 이 문서는 링크와 현재 의사결정에 영향을 주는 요약만 고친다.
