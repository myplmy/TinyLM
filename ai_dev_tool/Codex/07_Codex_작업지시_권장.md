# 07. Codex 권장 작업지시서

> 제정: 2026-09-11, 승인된 완전분리 제안 P2  
> 상태: **P0~P7 완료 / P8 미수행 / `STATIC_ONLY / E2E_NOT_RUN`**
> 프로젝트 맥락: [`06_Codex용_프로젝트지침과_메모리.md`](06_Codex용_프로젝트지침과_메모리.md)  
> 환경 경계: [`README.md`](README.md) · [P7 검증 보고](P7_정적종합검증_보고.md)

이 문서는 사용자가 TinyLM 작업을 Codex에 맡길 때 범위·실행 권한·검증 수준을 빠뜨리지 않도록 돕는 복사용 지시서다. Codex는 저장소의 Codex 전용 지침만 사용하며, 다른 에이전트 전용 지침·스킬·훅을 직접 읽거나 실행하지 않는다.

## 1. 세션 시작 프롬프트

### 1.1 일반 시작

```text
TinyLM Codex 세션 시작.

1. AGENTS.md의 영구 경계를 확인한다.
2. ai_dev_tool/Codex/README.md와 00_WORKING_RULES.md를 읽는다.
3. ai_dev_tool/Codex/06_Codex용_프로젝트지침과_메모리.md를 읽는다.
4. handoff/COMPASS.md와 handoff/의 최신 유효 *_HANDOFF.md를 읽는다.
5. 완료되지 않은 handoff/WIP_*_작업원장.md가 있으면 현재 작업으로 확인한다.
6. 이번 요청에 맞는 Codex 01~08과 .agents/skills의 해당 SKILL.md만 추가로 읽는다.

공유 핸드오프 안에 레거시 에이전트 경로가 있어도 환경 지침으로 따라가지 않는다.
datasets/TinyDataset/**는 데이터셋 팀 작업 중이므로 읽기·검색·해시·수정·검사·staging하지 않는다.
AI는 GPU 학습·모델 로딩·파일 삭제·commit·push를 하지 않는다.
먼저 현재 요청의 변경 허용목록과 실행/NOT_RUN 경계를 보고한 뒤 착수한다.
```

### 1.2 P7 정적검증 뒤 현재 주의

`AGENTS.md` 축약·링크 전환과 P7 환경 정적 종합검증 20/20은 완료됐다. 다만 P8 새 세션
E2E는 수행하지 않았으므로, 위 시작 순서가 실제 새 세션에서 자동 발견·라우팅됐다고 주장하지 않는다.
다른 환경 파일을 fallback으로 읽어 이 공백을 메우지 않는다.

## 2. 지시를 줄 때 포함할 다섯 가지

| 항목 | 써야 할 것 | 예 |
|---|---|---|
| 목적 | 최종적으로 무엇을 얻는가 | “원인만 진단”, “수정까지”, “제안서만” |
| 변경 허용범위 | 쓰거나 만들 수 있는 경로 | “`scripts/x.py`와 해당 테스트만” |
| 읽기 제외/보호 | 건드리면 안 되는 경로·팀 작업 | “`datasets/TinyDataset/**` 접근 금지” |
| 실행 권한 | 정적 검사·모의 실행·GPU·외부 상태 중 어디까지 | “정적 검사만, 스모크 NOT_RUN” |
| 완료 증거 | 무엇이 있어야 완료인가 | diff, 구문 검사, 실제 사용자 로그, 새 세션 E2E 등 |

“확인해줘”는 기본적으로 읽기 전용 진단이다. “고쳐줘/구축해줘”는 지정 범위 안의 구현과 비파괴 검증을 포함하지만, GPU·삭제·commit·push·배포 권한까지 자동으로 넓히지 않는다.

## 3. 역할 분담

| 일 | Codex | 사용자 |
|---|---|---|
| 저장소 읽기·교차대조·영향도 분석 | 수행 | 필요 시 범위 결정 |
| 문서·코드·배치 작성 | 승인된 경로에 수행 | 결과 검토 |
| 정적 검사 | 승인 범위 안에서 수행. 단계가 분리되면 NOT_RUN 유지 | 필요 시 승인 |
| GPU 학습·모델 로딩·동적 스모크 | **직접 실행하지 않음** | 실행 후 로그 제공 |
| 파일 삭제 | **하지 않고 후보만 보고** | 직접 판단·수행 |
| commit·push·PR | 명시 요청 없이는 수행하지 않음 | 권한과 범위 결정 |
| 설치·다운로드·외부 획득 | 사전 승인 없이는 수행하지 않음 | 비용·출처·범위 승인 |
| 데이터셋 팀 경로 | 소유권 경계가 풀릴 때까지 접근하지 않음 | 팀 작업 완료/허용 알림 |

다른 에이전트 전용 파일은 승인된 이식 입력으로만 읽고 런타임 링크·import·실행·fallback을 만들지 않는다.

## 6. Codex에 맡기기 좋은 일

- 여러 문서·로그·코드의 정본 교차대조와 누락 탐지.
- 영향도 분석과 변경 허용목록 설계.
- 작은 범위의 코드·문서 패치와 정적 계약 검증.
- Windows 배치의 구문·인코딩·레지스트리 정합성 검토.
- 결과 수치의 조건·눈금·계열 분리.
- 반복 사고를 규칙이 아니라 게이트·훅 후보로 바꾸는 설계.
- 재개 가능한 WIP와 검토 가능한 핸드오프 작성.

## 7. 명시적으로 별도 권한이 필요한 일

- GPU 학습, 모델 로딩, 벤치마크, 동적 스모크.
- 파일 삭제와 파괴적 데이터 변경.
- commit, push, PR 생성·병합, 배포.
- 패키지 설치, 대용량 다운로드, 외부 계정·서비스 변경.
- 데이터셋 팀 소유 경로의 열람·검사·수정.
- 승인된 제안 단계 밖의 설정·스킬·훅·AGENTS 변경.

“끝까지 해라”는 지속성을 뜻할 뿐 위 권한을 자동 부여하지 않는다.

## 8. 보고 형식

완료 보고는 다음 순서를 권장한다.

1. **결과** — 무엇이 실제로 바뀌었는가.
2. **변경 파일** — 승인 범위 안의 파일만 링크.
3. **검증** — 실행한 정적/모의 검사와 실제 종료 상태.
4. **미실행** — 스모크·GPU·E2E 등 하지 않은 것.
5. **보호 경계** — 데이터셋·09·외부 상태가 불변인지.
6. **다음 승인** — 다음 단계가 필요하면 범위와 비용을 제시.

검사하지 않은 것을 통과라고 쓰지 않고, 파일이 존재한다는 사실을 작동 증거로 쓰지 않는다.

## 9. 현재 한계

- Codex 00~08과 `.agents/skills/**`는 이식되고 P7 정적 종합검증을 통과했지만 P8 새 세션 E2E 전이다.
- `.codex/config.toml`과 `.agents/project.json`은 P3 이식본이다. 프로젝트 신뢰와 실제 로드는 P8 증거 전까지 가정하지 않는다.
- `.codex/hooks.json`·`.codex/hooks/**`는 P5 독립 이식·모의검증을 마쳤지만 실제 활성은 P8 전까지 가정하지 않는다.
- `AGENTS.md`는 P6에서 Codex 진입 규범으로 전환됐지만 실제 새 세션 적용은 P8 전까지 `E2E_NOT_RUN`이다.
- 공유 과거 문서의 에이전트명은 역사 증거일 수 있다. 현재 환경 지시로 재사용하지 않는다.
