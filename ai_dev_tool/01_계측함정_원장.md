## 2. 2026-08-06 신규 항목

- **★★풀 크기가 val 셋을 바꾼다(L5 + L4, 결과 006 §5).** `prepare()` 의 val 은 **스트림
  말미 0.5%** 이고(`arr[-n_val:]`), 한국어 위키는 약 300M 토큰에서 **고갈**된다. 둘이 겹쳐
  **val 한글 비율이 300M 풀 13.5% / 600M 5.5% / 1200M 0.0%** 가 됐다.
  → **풀이 다른 런의 `val_loss`·`bpb` 비교는 무효다. 시험지가 다르다.**

> **규칙: 메모리 여유가 1GB 미만인 런에서 CUDA 오류가 나면 OOM 계열부터 의심한다.**

## 31. ★★진단 스크립트의 **테스트 데이터**가 지표의 부호를 뒤집는다 (2026-08-13, 결과 041 §11)

`diag_depth_init.py` 가 **입력과 정답을 둘 다 난수 토큰**으로 줬다:

```python
x = torch.randint(0, V, (bs, seq))    # 난수 입력
y = torch.randint(0, V, (bs, seq))    # ★x 와 무관한 난수 정답
ce = F.cross_entropy(model(x), y)
```

그러면 CE 가 재는 것이 뒤집힌다:

| 모델 | 결과 |
|---|---|
| 난수 초기화 | 균등 출력 → CE ≈ ln(V) |
| ★**학습된 가중치 이식** | 확신 있는 예측 → 난수 정답과 안 맞음 → **CE ≫ ln(V)** |

→ **이식이 성공할수록 게이트가 실패한다.**

★★**가장 위험했던 것은 대조군이 정확했다는 점**이다. 난수 모델이 `ln(32768)=10.3972` 를
소수 셋째 자리까지 재현했고(10.4082), 결과문서 §1 이 그것을 근거로
*"계측은 건강하다"* 라고 적었다. **대조군만 건강했다.**

**어떻게 잡았나**: `identity` 모드가 **수학적으로 교사와 동일한 함수**인데 13.4887 을 찍었다.
교사의 결정적 full-val 은 **3.8080**(결과 040 §2)이다. **교사가 자기 점수의 3.5배를 받을 수 없다.**

> ### 규칙
> **진단을 만들 때 "성공했을 때 나와야 하는 값" 을 대조군과 **함께** 정한다.**
> 실패 쪽 기준선(난수)만 있으면 **부호가 뒤집힌 지표를 못 알아본다.**
> 그리고 **가능하면 실제 데이터**를 쓴다 — 합성 데이터는 퇴화하기 쉽다(함정 32).

## 32. **감사 도구의 합성 데이터가 퇴화** (2026-08-13, 결과 042 §3)

`diag_kd_loss.py` 가 교사·학생 로짓을 **같은 `base` 에서** 만들고 정답 로짓만 4.0/3.2 로 달리 줬다.
→ 두 분포가 거의 같아 **KL ≈ 0**, gradient 도 0 → *"실효 α = 0.000"* 이 나왔다.
**KD 구현의 성질이 아니라 테스트 데이터의 성질**이다.

⚠️ 스크립트가 말미에 *"합성 로짓으로 했다"* 는 한계를 인쇄했는데도 **판정 줄은 단정**했다.
→ **한계를 적는 것과 결론에 반영하는 것은 별개다**(의사결정 함정 D4).

> ### 규칙
> **합성 데이터를 쓰는 감사는 "데이터가 퇴화하지 않았는지" 를 먼저 재고 인쇄한다.**
> `diag_kd_loss.py` 는 이제 **총변동거리**를 먼저 찍고 0.05 미만이면 *"읽지 말 것"* 을 인쇄한다.

## 34. ★★기준값을 **적는 것**과 **옳은 값**을 적는 것은 다르다 (2026-08-13, 결과 043)

**함정 31 계열의 세 번째 발현이다.** 31 은 *"성공 기준값을 적어라"* 였고, 32 는

`diag_train_repeat.py` 는 `check_diag_data.py` 를 **통과했다.** 실데이터를 읽었고, 성공
기준값 상수를 파일에 두었고, 그 값을 인쇄했다. **그런데 그 값이 틀렸다.**

```python
TEACHER_FULLVAL = 3.8080     # 결과 040 §2 — dense 의 결정적 full-val
...
if abs(b_ce - TEACHER_FULLVAL) > 0.5:
    print("🚫★어긋난다. **나머지를 읽지 말 것**")
```

실측 R=1.0 은 **7.2799** 였고 게이트는 `G0-c 실패` 를 찍고 단계1 을 막았다.
**막힌 이유는 모델이 아니라 내 기준값이었다.**

### 왜 틀렸나

`init_from_dense` 는 **중간 MLP 를 타잉 그룹별로 평균**한다:

```python
mid_mlps[j // g] ← mean(교사 MLP g개)
```

→ **부모초기화된 타잉 학생은 교사가 아니다.** 교사 점수를 낼 수 **없다.**
오히려 3.8 근처가 나왔다면 **타잉이 안 걸린 것**이므로 그쪽이 이상 신호다.

### ★옳은 앵커는 **이미 저장소에 있었다**

결과 030 §2, 2026-08-07 기록:

> *"step 0 `ce` **10.4051** — `ln(32768) = 10.397`, 출력이 완전 무작위.
> 같은 밤 `mC_g16` 은 **7.7742** 로 부모초기화 이득이 살아 있었다"*

| 조건 | step0 CE 앵커 | 근거 |
|---|---|---|
| dense 학생(구조 동일) | **3.8080** | 결과 040 §2 |
| ★**타잉 + 부모초기화** | **7.7742** | ★**결과 030 §2** |
| 초기화 없음(난수) | **10.3972** = `ln V` | 결과 030 §2 |

**나는 표의 첫 줄을 셋째 조건에 갖다 붙였다.** 검색 한 번이면 나왔을 값이다.

### 규칙

1. ★**기준값에는 조건을 함께 적는다.** `TEACHER_FULLVAL = 3.8080` 이 아니라
   **`PARENT_TIED_ANCHOR = 7.7742  # 타잉 학생 + 부모초기화`**. 이름에 조건이 없으면
   다른 조건에 갖다 쓰게 된다.
2. ★**점 검사 대신 대역 검사.** 앵커는 조건마다 다르지만 **대역은 안정적**이다 —
   하한 = "교사보다 좋을 수 없다", 천장 = "난수보다는 나아야 한다".
   `diag_train_repeat.py` 를 `FLOOR 5.0 ^< CE ^< ln V − 1` 로 고쳤다.
3. ★**게이트가 실패를 찍으면 모델을 의심하기 전에 기준값을 의심한다.** 이 저장소에서
   *"게이트 실패"* 는 지금까지 **3번 중 3번 다 게이트의 잘못**이었다(041 §11, 042 §3, 043).
4. **크롭 크기를 인쇄한다.** 이 진단들의 CE 는 1~4천 토큰 **단일 표본**이고 ko-en 혼합이라
   크롭이 다르면 1 nat 단위로 흔들린다. **스크립트끼리 CE 를 비교하지 않는다.**

> ⚠️**`check_diag_data.py` 는 이 함정을 못 잡는다.** "상수가 있는가" 는 정적으로 보이지만
> "그 상수가 이 조건에 맞는가" 는 안 보인다. 도구 docstring 에 그 한계를 명시했다.

## 35. ★`pathlib.Path.write_text()` 는 **먼저 지우고 나중에 인코딩한다** (2026-08-13, 실사고)

**게다가 조용했다.** 빈 배치는

   ```python
   assert len(blob) > 3000, f"복원본이 너무 작다: {len(blob)}"
   ```

2. **크기 하한을 단언한다.** 파일을 통째로 다시 쓸 때는 "이보다 작을 리 없다" 를 적는다.

## 37. ★★**필드가 기록되는 것 ≠ 그 코드 경로가 실행되는 것** (2026-08-14, 실사고)

`transformer.py` 가 `build_attention()` 을 부르는데 **import 목록에 없었다.**
그 호출은 **`attn_group > 1` 분기 안에만** 있다:

```python
ag = int(getattr(cfg, "attn_group", 1) or 1)
if ag > 1:                                   # <- 기본은 여기 안 들어온다
    self.mid_attns = nn.ModuleList([build_attention(cfg, True) ...])
```

## 41. ★**VRAM `reserved` 에도 세션 드리프트가 있다** (2026-08-21, 실측 1건)

`mC_wsd` 와 `mC_wsd_s2` 는 **같은 조건**이다 — KD·2289스텝·`grad_ckpt` ON·`micro_bs 8`·

**`--no-ckpt` 가 열리는지 아닌지를 뒤집을 수 있는 크기**다(결과 034 §10: 여유 0.62 GiB).

### 규칙

> 다른 날 런의 `reserved` 차이가 **0.8 GiB 미만이면 조건 탓으로 귀속하지 않는다.**
> ★**그리고 `reserved` 와 `alloc` 을 함께 적는다** — 둘이 반대로 움직이면 **할당자 이야기**다.

⚠️**표본 1건이다.** 자릿수 관찰이지 상수가 아니다.
⚠️**이 함정이 판정을 뒤집은 적은 아직 없다** — 결과 035 의 `−1.02 GiB` 는
**같은 조건 두 쌍에서 독립 재현**되므로 유효하다(035 §12.3 정정 참조).
**틀린 것은 그 표의 대조군 이름 하나였다.**
