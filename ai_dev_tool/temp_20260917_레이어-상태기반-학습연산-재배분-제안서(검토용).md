# 제안 — 레이어 상태 진단 기반 학습 연산 재배분

> **작성** 2026-09-17 · **상태** ⏳판단 대기 · **분류** 실험계획
> 양식: [`proposal/README.md`](README.md) §3. **아홉 절을 비우지 않는다** — 없으면 *"없다"* 라고 쓴다.
> 이 문서는 제안서이며, **승인 전에는 코드 구현·배치 생성·GPU 학습을 시작하지 않는다.**

---

## 1. 배경 — 왜 지금 이 제안을 하나

현재 TinyLM의 제약은 여러 레이어별 최적화 정책을 각각 독립된 full training run으로 비교하기에는 GPU 예산이 부족하다는 것이다. 목표는 많은 대조군을 만드는 것이 아니라, **한 번의 본 학습 과정에서 거의 무료로 얻을 수 있는 학습 통계와 소수의 one-shot 진단을 이용해 계산량을 더 유용한 레이어에 배분하는 것**이다.

저장소의 기존 300M 기준선 P002는 다음 조건을 사용했다.

| 항목                         | P002 실측/설정                                      |
| -------------------------- | ----------------------------------------------- |
| 모델 깊이                      | prelude 2 + mid 16 + coda 2 = 20 logical blocks |
| dense 파라미터                 | 132.5M                                          |
| 데이터                        | ko-en 300M tokens                               |
| 학습 step                    | 2,289                                           |
| micro batch / accumulation | 8 / 16                                          |
| sequence length            | 1,024                                           |
| 유효 batch                   | 약 131K tokens                                   |
| dense 학습시간                 | 97.5분                                           |
| tied 학습시간                  | 약 90분                                           |
| dense best val loss        | 3.7797 @ step 2200                              |
| 해석                         | 300M에서는 모델이 아직 크게 undertrained한 것으로 판정          |

출처: `test_plan/P002_300M-기준선-및-격차축소-매트릭스-done.md`, `test_result/001_20260723222103_dense-tied-300M-기준선-손실격차.md`.

이 결과는 **학습 종료까지도 개선 가능성이 남아 있으며**, 모든 레이어에 동일한 optimizer budget을 계속 배분하는 것이 계산 효율 면에서 최적이라는 근거는 없음을 뜻한다. 다만 현재 모델·optimizer·WSD 등은 P002 당시와 달라질 수 있으므로 P002 시간과 손실값은 비용의 역사적 기준으로만 사용하고 현재 성능 기준으로 직접 전용하지 않는다.

본 제안에서는 레이어 또는 공유 tensor의 학습 상태를 다음 두 개의 저비용 지표로 우선 관찰한다.

### U — normalized update activity

레이어 또는 tensor `l`의 실제 optimizer update 크기를 현재 weight norm과 learning rate에 대해 정규화한 EMA를 기록한다.

```text
U_l = EMA( ||ΔW_l,grad|| / (η_t · ||W_l|| + ε) )
```

가능하면 AdamW weight-decay에 의한 변화는 제외하고 gradient-driven update만 기록한다.

LR decay 때문에 모든 레이어의 raw `ΔW`가 동시에 작아지는 현상을 `학습 완료`로 오판하지 않기 위한 정규화이다.

### S — functional bypass sensitivity

고정된 작은 validation panel에서 특정 logical Transformer block의 residual branch를 bypass했을 때 CE가 얼마나 변하는지 측정한다.

```text
S_l = CE(block l bypass) - CE(normal)
```

따라서 다음 네 상태를 구분한다.

| 상태       | 1차 해석                               |
| -------- | ----------------------------------- |
| `S↑, U↑` | 현재 중요하고 활발하게 학습 중                   |
| `S↑, U↓` | 중요하지만 현재 update가 작음; 안정화되었을 가능성     |
| `S↓, U↑` | 현재 중요도는 낮지만 아직 representation이 변화 중 |
| `S↓, U↓` | 현재 사용도가 낮은 dormant/redundant 후보     |

특히 마지막 상태를 곧바로 제거 대상으로 보지 않는다.

`S↓ + U↓ + bypass 영향≈0`은 다음 두 경우를 아직 구분하지 못한다.

1. 실제로 없어도 되는 redundant block
2. 아직 역할을 획득하지 못한 undertrained/dormant block

따라서 D안에서는 해당 block에 짧은 **resuscitation probe**를 주어 이 둘을 구별한다.

Fresh-seed reinitialization, `-W`, `1-W`와 같은 적극적 weight 교체는 이번 제안의 1차 범위에서 제외한다. 특히 `1-W`는 0 중심 signed initialization을 1 중심으로 이동시키므로 일반적인 Transformer weight에서 의미 있는 “반대값”으로 볼 근거가 없다.

## 2. 목적 — 무엇을 알아내거나 얻으려 하나

**full training trajectory를 최대 3개로 제한한 상태에서, 레이어별 학습 상태를 저비용으로 계측하여 동일하거나 더 낮은 validation loss를 더 적은 wall-clock/FLOPs에 얻을 수 있는지 확인하고, `TRAIN / LOW-LR·FREEZE / SKIP / RESUSCITATE` 중 어떤 계산 배분 정책이 TinyLM에 유효한지 판정한다.**

독립변수 후보는 다음 네 안이다.

* A: 현행 학습 기준선
* B: Blockwise LR
* C: S/U 기반 selective layer skip
* D: S/U 기반 dormant-layer resuscitation 후 keep/skip 판정

단, 네 안을 모두 full run하지 않는다. §6의 게이트에 따라 **동시에 비교하는 full trajectory는 최대 3개**로 제한한다.

## 3. 성과물 — 승인하면 무엇이 생기나

| 산출물                             | 형태                                                  |
| ------------------------------- | --------------------------------------------------- |
| 레이어/tensor update 계측            | `U_l` EMA와 layer/module별 로그                         |
| one-shot functional sensitivity | 20 logical block의 `S_l` 표                           |
| 상태 분류                           | `ACTIVE / STABLE / DORMANT / REDUNDANT`             |
| A 기준선                           | val loss / tokens / step / wall-clock / peak VRAM   |
| B 결과                            | blockwise LR의 동일-token·동일-step 성능                   |
| C 결과 또는 보류 판정                   | selective skip의 CE/FLOPs/wall-clock 영향              |
| D 결과                            | dormant block resuscitation의 paired micro-branch 결과 |
| 최종 판정                           | 품질 우선·속도 우선 각각 채택 가능한 정책                            |
| 승인 후 실험계획                       | 실제 실행이 승인되면 `test_plan/`에 별도 P번호 계획서 작성             |

최종 판단은 단순한 `best val loss` 하나가 아니라 다음 두 축으로 기록한다.

```text
품질 효율 = validation CE @ 동일 token budget
계산 효율 = baseline CE 도달까지 wall-clock / FLOPs
```

속도 개선을 주장하려면 FLOPs 감소뿐 아니라 실제 `tokens/s` 또는 wall-clock 감소도 확인한다.

| 항목                     |                                         양 |
| ---------------------- | ----------------------------------------: |
| GPU — 기본 상한            |         ⚙ 최대 **3.0 full-run equivalents** |
| GPU — P002 역사적 시간으로 환산 |     ⚙ 약 **4.5~4.9 GPU-h** if 90~97.5분/run |
| one-shot S 진단          |                ⚙ full run의 **0.5% 미만** 목표 |
| D micro-branch         | ⚙ 50~100 step 추가 시 full run의 **2.2~4.4%** |
| AI 작업                  |                          ⚙ 4~7 engineer-h |
| 사용자 검토                 |                                  ⚙ 20~40분 |
| 디스크                    |            ⚙ 3~8GB 이내의 checkpoint/log 추가분 |
| ★사용자가 직접 해야 하는 일       | 승인 후 smoke 실행, full run 최대 3개 시작·초기 로그 확인 |

P002의 90~97.5분은 역사적 reference다. 현재 architecture·optimizer·compile 조건에서 실시간은 별도 실측한다.

D의 50~100 step probe는 원래 training step 내부의 LR 변경만 하면 추가 FLOPs가 없지만, 동일 checkpoint에서 normal과 resuscitation을 직접 비교하는 paired micro-branch를 실시할 경우 한쪽 branch만큼 추가 비용이 생긴다.

본 제안은 full seed sweep을 하지 않는다.

### 우리 실측

| 근거                 | 값                     | 출처            |
| ------------------ | --------------------- | ------------- |
| 300M 기준 depth      | 20 logical blocks     | P002          |
| dense 크기           | 132.5M params         | 결과 001        |
| 300M step 수        | 2,289                 | P002 / 결과 001 |
| dense 300M 시간      | 97.5분                 | 결과 001        |
| tied 300M 시간       | 약 90분                 | 결과 001        |
| dense best loss 위치 | step 2200 / 3.7797    | 결과 001        |
| 기존 해석              | 300M은 크게 undertrained | 결과 001        |
| 조건간 run noise 주의   | 약 ±0.02~0.03 수준으로 기록  | 결과 001        |

이 실측은 제한된 training budget에서 많은 full run을 소비하는 대신 본 학습 내부의 계측과 짧은 intervention을 우선해야 한다는 근거다.

### 외부 근거

#### 1. Blockwise Learning Rate

Jinbo Wang et al., **The Sharpness Disparity Principle in Transformers for Accelerating Language Model Pre-Training**, ICML 2025, PMLR 267.

* Transformer의 embedding, normalization, attention, FFN 등 block type 사이의 sharpness disparity가 학습 초기에 나타나고 이후에도 유지됨을 보고했다.
* 이를 이용한 Blockwise LR을 GPT-2/LLaMA 0.12B~1.1B pretraining에 적용하여 vanilla AdamW보다 낮은 terminal loss와 거의 2× 수준의 convergence acceleration을 보고했다.
* 본 프로젝트의 모델 규모와 가장 직접적으로 가까운 선행 근거다.
* 논문의 정확한 multiplier를 검증 없이 복사하지 않고, 승인 후 method를 확인하여 **한 세트만 사전 고정**한다. 별도 LR sweep은 하지 않는다.

#### 2. SlimFit

Ardakani et al., **SlimFit: Memory-Efficient Fine-Tuning of Transformer-based Models Using Training Dynamics**, NAACL 2024, ACL Anthology `2024.naacl-long.345`, DOI `10.18653/v1/2024.naacl-long.345`.

* runtime training dynamics로 기여도가 낮은 layer를 골라 freeze하는 방법을 제시했다.
* BERT/ViT fine-tuning에서 큰 비율의 layer를 freeze하고도 낮은 품질 저하를 보고했다.
* 단, scratch LLM pretraining이 아니라 fine-tuning 결과이므로 TinyLM의 직접적인 성능 보장은 아니다.
* 본 제안에서는 `U`가 낮다는 이유만으로 freeze하지 않고 `S`를 추가하는 이유가 된다.

#### 3. Layer re-initialization / robustness

Zhang, Bengio, Singer, **Are All Layers Created Equal?**, JMLR 23(67), 2022.

* 학습 뒤 layer를 initial value로 되돌리거나 re-randomize하여 layer별 functional robustness가 크게 다름을 보였다.
* 학습 중 거의 변하지 않고 reset해도 성능이 유지되는 robust layer와 reset 시 성능이 붕괴하는 critical layer를 구분했다.
* 따라서 weight movement 자체보다 **실제 intervention 뒤 성능 변화**를 같이 봐야 한다는 근거다.

#### 4. Structured layer dropout

Elhoushi et al., **Don't Drop Dropout: Optimizing Layer Sparsity for Efficient LLM Training and Inference**, arXiv:`2609.05275`, 2026-09-04 preprint.

* 271M~8.2B LLM과 최대 160B-token 조건에서 layer dropout의 위치·시간 schedule·optimizer 조건을 조사했다.
* 같은 training step에서 최대 25% training FLOPs 절감과 비슷하거나 더 낮은 validation loss를 보고했다.
* 2,400회 이상의 실험을 사용했지만 preprint이며, 최소 모델도 TinyLM 기준선보다 크고 Cerebras CS-3 기반이므로 수치를 직접 전용하지 않는다.
* C/D에서 **낮은 확률의 structured skip부터 보수적으로 시작**하는 근거로만 사용한다.

#### 5. Dormant capacity와 재활성화

Dohare et al., **Loss of plasticity in deep continual learning**, Nature 632, 768–774, 2024.

* continual learning에서 least-used unit 일부를 reinitialize하여 plasticity를 유지하는 continual backpropagation을 제시했다.
* LLM scratch pretraining에 대한 직접 근거는 아니며, 이번 D안도 reinitialization을 사용하지 않는다.
* 다만 `현재 덜 쓰이는 capacity = 반드시 영구적으로 불필요한 capacity`라고 보지 않고 재활성화 가능성을 먼저 확인해야 한다는 보조 근거다.

## 6. 방법

### 네 실험안의 정의

| 안                             | 개입                                            | full-run 목적                            |
| ----------------------------- | --------------------------------------------- | -------------------------------------- |
| **A — Baseline**              | 현행 optimizer/LR/모든 block active               | 비교 기준                                  |
| **B — Blockwise LR**          | block type별 사전 고정 LR multiplier               | 동일 FLOPs에서 수렴 가속                       |
| **C — S/U selective skip**    | `S↓ + U↓` block에만 stochastic structured skip  | 실제 FLOPs/wall-clock 절감                 |
| **D — Dormant resuscitation** | `S↓ + U↓` block을 먼저 집중 학습하고 실패한 경우에만 skip 후보화 | unused capacity와 genuine redundancy 분리 |

### 실행 원칙

**full trajectory 상한은 3개다.**

기본 권장 trajectory는:

```text
A → B → D
```

C는 네 번째 full run으로 추가하지 않는다.

D 구현이 불가능하거나 one-shot 진단에서 resuscitation 대상이 하나도 없으면 **D 대신 C**를 실행한다.

기존 baseline을 재사용할 수 있는 경우에도 자동으로 네 번째 full run을 허용하지 않는다. 추가 실험은 별도 승인 대상이다.

### 단계별 게이트

| 단계 | 무엇                                                      |              비용 | ★다음으로 가는 조건                                            |
| -- | ------------------------------------------------------- | --------------: | ------------------------------------------------------ |
| 0  | 기존 코드에서 logical block / shared tensor 구조와 compile 경로 확인 |        ⚙0 GPU-h | U와 bypass를 graph break 없이 계측 가능                        |
| 1  | `U_l` logging만 추가하고 smoke                               |             ⚙수분 | baseline output/loss가 instrumentation off와 동일          |
| 2  | A 실행 또는 정확히 동등한 기존 A 존재 확인                              |   1 full run 이하 | 비교 가능한 val/timing 정본 확보                                |
| 3  | burn-in 동안 U EMA 축적                                     |       기존 run 내부 | 최소 100-step 이상 안정된 U 순위                                |
| 4  | one-shot block bypass로 S 측정                             |      ⚙<0.5% run | block별 paired ΔCE 확보                                   |
| 5  | B full run                                              |      1 full run | NaN/grad 이상 없이 동일 token budget 완료                      |
| 6  | D 후보 선정                                                 |         계산 거의 0 | `U` 하위권 + `S` 하위권 + bypass-safe block 1~2개 존재          |
| 7  | D paired micro-branch                                   | ⚙50~100 step 추가 | resuscitation branch가 normal branch보다 held-out CE 개선   |
| 8a | D 성공                                                    |     기존 D run 내부 | 해당 block 정상 pool 복귀                                    |
| 8b | D 실패                                                    |     기존 D run 내부 | normal checkpoint 선택, 후보를 low-probability skip 대상으로 전환 |
| 9  | A/B/D 또는 A/B/C 최종 비교                                    |             평가만 | 품질·wall-clock·FLOPs 모두 기록                              |

### U 판정

단일 순간값은 사용하지 않는다.

* 최소 최근 100 step EMA 사용
* raw `ΔW`가 아니라 LR-normalized update 사용
* group tying이 있는 경우 **shared physical tensor 단위의 U**를 계산
* weight decay는 가능한 한 제거
* 전체 tensor 중 지속적으로 하위 20~25%인 경우만 `U-low` 후보로 본다

### S 판정

20개 block을 가정하면 fixed diagnostic panel에서 다음을 평가한다.

```text
normal
block 0 bypass
block 1 bypass
...
block 19 bypass
```

block마다 여러 diagnostic mini-batch의 paired CE 차이를 사용한다.

`S-low`는 단순한 절대 threshold 하나가 아니라:

1. 전체 block 중 하위권이며
2. paired CE 차이가 diagnostic sampling variation보다 작고
3. 여러 mini-batch에서 같은 방향

인 경우로 제한한다.

group tying 모델에서는 `S`는 **logical depth occurrence별**로 기록한다. 같은 shared tensor를 쓰더라도 서로 다른 depth 위치의 bypass 중요도는 다를 수 있다.

### C — selective skip

C를 실행하는 경우 처음부터 많은 block을 drop하지 않는다.

```text
대상: S-low + U-low 중 최대 1~2개
초기 skip probability: ⚙10%
상한: ⚙20%
종료부: 0% 방향으로 감소
```

품질 게이트를 통과해야 skip probability를 올린다.

compile/recompilation 때문에 FLOPs 절감이 wall-clock 절감으로 연결되지 않으면 C는 실패로 판정한다.

### D — dormant resuscitation

D는 본 제안의 핵심 추가안이다.

후보:

```text
S 낮음
+
U 낮음
+
실제 bypass해도 CE 변화가 작음
```

인 block 중 최대 1~2개만 선택한다.

첫 probe는 reinitialize하지 않고 기존 representation을 보존한 채 LR allocation만 바꾼다.

```text
candidate block : base LR × 2
other blocks    : base LR × 0.5~1.0
기간            : 50~100 steps
```

첫 시도에서 ×4 이상과 fresh random reset은 사용하지 않는다.

#### D의 paired micro-control

full 대조 run을 하나 더 만드는 대신 동일 checkpoint `t0`에서 짧게 분기한다.

```text
                    ┌─ N: normal 50~100 steps
checkpoint t0 ──────┤
                    └─ R: resuscitation 50~100 steps
```

두 branch는:

* 같은 시작 checkpoint
* 같은 token 순서
* 같은 seed
* candidate LR policy만 다르게

한다.

이 때문에 300M full run을 하나 더 만드는 대신 약 2.2~4.4% run 비용으로 직접 counterfactual을 얻는다.

#### D 채택 게이트

`U` 증가만으로 성공이라 하지 않는다. LR을 올리면 U 증가는 기계적으로 발생할 수 있다.

다음 조건을 모두 본다.

```text
1. R의 held-out CE가 N보다 개선
2. 개선량이 diagnostic sampling uncertainty보다 큼
3. NaN/gradient spike 없음
4. candidate S가 증가했더라도 전체 CE가 악화되지 않음
```

통과하면 R checkpoint를 이어 학습한다.

실패하면 N checkpoint를 정본으로 선택하고 R branch는 버린다.

이후 해당 block은 `REDUNDANT` 후보가 되어 C 방식의 10~20% stochastic skip 대상이 될 수 있다.

즉 D는 다음 controller를 구현한다.

```text
ACTIVE
  │ U 감소
  ▼
STABLE
  │ S 낮음
  ▼
DORMANT
  │
  ├─ resuscitation 성공 ─→ ACTIVE
  │
  └─ resuscitation 실패 ─→ REDUNDANT ─→ low-probability SKIP
```

### 이번 단계에서 하지 않는 것

```text
fresh-seed full-layer restart
original-init rewind
-W
1-W
여러 reinitialization seed sweep
Hessian/Fisher full measurement
매 checkpoint별 exhaustive bypass
```

이들은 D가 반복적으로 실패하고도 추가 연구 가치가 남을 때 별도 제안으로 연다.

---

## 7. 거절하면 못 하는 것

기존 TinyLM 학습 자체는 그대로 계속할 수 있으므로 **아무것도 못 하게 되지는 않는다.**

다만 다음은 알 수 없거나 이용할 수 없다.

* 현재 20개 block의 계산량이 실제로 균등하게 필요한지
* 거의 사용되지 않는 block이 genuine redundancy인지 undertraining인지
* 동일 token budget에서 blockwise LR이 수렴을 개선하는지
* 일부 block skip으로 실제 wall-clock을 줄일 수 있는지
* 별도 full seed sweep 없이 dormant capacity를 구제할 수 있는지

따라서 거절의 대가는 기능 상실이 아니라 **향후 모든 학습에서 동일한 균등 compute allocation을 계속 사용하는 기회비용**이다.

## 8. 위험 — 실행하면 무엇이 잘못될 수 있나

| 위험                           | 어떻게 드러나나                                     | 완화                                              |
| ---------------------------- | -------------------------------------------- | ----------------------------------------------- |
| **U 오측정**                    | LR decay 때문에 전 block이 `U-low`로 보임            | LR-normalization, weight-decay 제거, EMA 사용       |
| **S 오측정**                    | 작은 diagnostic panel에서 block 순위가 흔들림          | paired mini-batch 여러 개, 동일 panel 고정             |
| residual bypass 교락           | layer가 불필요한 것이 아니라 주변 block이 일시적으로 보상        | U와 S를 함께 사용, 즉시 영구 제거 금지                        |
| group tying 교락               | shared tensor U와 logical depth S를 같은 개념으로 취급 | U=physical tensor, S=logical occurrence로 별도 기록  |
| D의 자기충족                      | LR↑ 때문에 candidate가 중요해졌지만 전체 모델은 더 나빠짐       | S 증가가 아니라 paired global held-out CE를 채택 기준으로 사용 |
| D의 과도한 LR                    | gradient spike / loss 악화                     | 최초 ×2 상한, 50~100-step micro-branch, rollback    |
| C/D dynamic skip의 compile 손실 | FLOPs는 줄었는데 tokens/s가 떨어짐                    | graph-break/recompile 수 계측, wall-clock이 안 줄면 폐기 |
| B의 scale mismatch            | 논문 LR 비율이 TinyLM에서 불안정                       | multiplier 1세트만 사전 고정하되 smoke에서 발산 계약 확인        |
| 작은 모델의 낮은 redundancy         | skip 시 큰 품질 저하                               | 최대 1~2 block, 10~20% stochastic skip부터          |
| diagnostic overfitting       | controller가 작은 validation panel에만 맞춤         | controller panel과 최종 판정 panel 분리                |
| 실험 효과 교락                     | D에서 resuscitation과 skip 효과가 섞임               | paired micro-branch 로그와 상태전이 시점을 별도 기록          |
| historical runtime 오용        | P002 90~97.5분을 현재 runtime으로 간주               | P002는 비용 anchor만 사용, 현재 tokens/s 별도 실측          |

가장 중요한 계측 위험은 `S-low + U-low`를 곧바로 “쓸모없는 layer”로 해석하는 것이다. 본 제안은 이를 막기 위해 D의 resuscitation gate를 둔다.

## 9. 대안

| 안                             | 무엇                                  | 장점                                                                     | 단점                                 |
| ----------------------------- | ----------------------------------- | ---------------------------------------------------------------------- | ---------------------------------- |
| **A — Baseline**              | 모든 block을 현행 방식으로 동일하게 학습           | 가장 단순하고 비교 기준이 명확                                                      | 계산량 재배분 없음                         |
| **B — Blockwise LR**          | block type별 LR을 달리해 수렴 속도 개선        | 추가 FLOPs 거의 없음, LLM pretraining 직접 선행근거가 가장 강함                         | per-depth redundancy를 직접 이용하지 않음   |
| **C — S/U selective skip**    | `S↓ + U↓` block을 stochastic skip    | 실제 forward/backward FLOPs 감소 가능                                        | dormant와 genuine redundant를 오판할 위험 |
| **D — Resuscitate then skip** | `S↓ + U↓`를 먼저 집중학습한 뒤 실패한 경우에만 skip | unused capacity를 구제하면서 C의 오판 위험 감소, micro-branch로 full run 추가 없이 검증 가능 | controller가 복잡하고 효과 분리가 C보다 어려움    |

### ★권장안과 근거

**권장안은 `A → B → D`의 최대 3-trajectory 구성이다.**

C는 독립적인 네 번째 full run으로 추가하지 않고 **D가 불가능하거나 D 후보가 전혀 없을 때 D를 대체하는 fallback**으로 둔다.

근거는 다음과 같다.

```text
A
→ 현재 학습의 실제 기준을 확보한다.

B
→ 거의 추가 FLOPs 없이 수렴속도를 높일 가능성이 있고,
   0.12B~1.1B LLM pretraining이라는 가장 가까운 직접 근거가 있다.

D
→ S/U one-shot 진단을 이용하되,
   S↓+U↓를 곧바로 제거하지 않고 먼저 살릴 수 있는지 시험한다.
   정상 50~100-step micro-control과 직접 비교할 수 있으므로
   별도 full 대조군을 추가하지 않아도 된다.
   실패한 block만 이후 selective skip으로 보내므로 C의 기능도 일부 포함한다.
```

따라서 제한된 GPU에서 정보량은 다음과 같이 최대화한다.

```text
full run 1 : A — control
full run 2 : B — convergence acceleration
full run 3 : D — adaptive resuscitation + conditional skip

추가:
D 내부 50~100-step paired micro-branch만 허용
```

A와 완전히 동일한 architecture·data order·seed·optimizer·schedule의 기존 결과를 그대로 비교할 수 있더라도 **자동으로 C까지 네 번째 full run으로 추가하지 않는다.** 네 번째 run은 이 제안의 승인 범위 밖이다.

### 성공 기준

B 또는 D를 채택하려면 최소한 다음 중 하나를 만족해야 한다.

```text
1. 동일 token/step에서 validation CE가 A보다 낮음
또는
2. A의 최종 CE에 더 짧은 wall-clock/FLOPs로 도달
```

속도 개선안은 품질 저하도 함께 기록한다.

첫 실험에서 목표로 삼을 계산량 개선은 공격적인 25% 절감이 아니라 **품질을 사실상 유지하면서 실측 wall-clock 5~10% 수준의 개선 가능성을 확인하는 것**으로 제한한다.

D가 효과가 없더라도 `S↓ + U↓ + resuscitation 실패`가 확인되면 해당 block이 genuine redundancy 후보라는 정보가 남으며, 이후 C 또는 구조적 depth 축소를 훨씬 낮은 위험으로 제안할 수 있다.

반대로 D가 성공하여 처음에는 bypass해도 영향이 없던 block이 resuscitation 후 전체 validation CE를 개선한다면, `S/U`가 단순 pruning 지표가 아니라 **학습 자원을 재배분하는 상태 변수**로 기능한다는 직접적인 TinyLM 내부 근거가 된다.
