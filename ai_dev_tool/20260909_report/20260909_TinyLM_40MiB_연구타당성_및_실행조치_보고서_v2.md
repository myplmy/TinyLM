## 1. 판단과 가장 먼저 할 일

**현재 아키텍처를 폐기할 근거는 부족하다. 반면, 추가 구조 격자를 계속 늘리는 것보다 평가·배포의 미완성 부분을 고치고, 이미 준비된 Fresh SFT와 검증된 교사 응답의 학습으로 중심을 옮길 근거는 충분하다.** 현 프로젝트는 압축·메모리·학습 속도에 관해서는 상당한 실증을 축적했다. 그러나 “40MiB 안의 바로 그 실행 산출물이 현대 100M급 모델과 비슷한 능력을 낸다”는 결합 명제는 아직 입증되지 않았다.

현재 필요한 조치는 세 종류다. **기존 체크포인트의 재평가·진단으로 끝나는 문제**, **학습 설계와 구현을 먼저 고쳐야 하는 문제**, **아직 결과가 없는 정상적인 후속 연구**를 분리해야 한다. 과거에 실패했어도 뒤 단계에서 복구된 실험은 재실험 목록에 다시 올리지 않았다.

| 우선순위 | 지금 해야 할 일 | 필요한 실행의 종류 | 연구 결정에 미치는 영향 |
|---|---|---|---|
| P0 | A01: held-out 버전 선택·v2.8 schema 연결 수정 | 코드 수정 후 자료 로딩 확인; 승인된 버전으로 기존 모델 평가 | 새 평가를 가져오는 것부터 실패하거나 잘못된 버전을 조용히 쓰는 문제 방지 |
| P0 | A02: 공통 bpb의 실제 오염 제외와 정확한 채점 분모 구현 | 평가기 수정 + 최종 후보·KD 대조군 재평가 | 현재 품질 순위의 신뢰 범위 확정 |
| P0 | A03–A04: 문항 ID 기반 paired 비교, 점수 규약·margin·통계 수정 | 평가기/분석기 수정; 원점수 없으면 해당 평가만 재실행 | “정확도는 안 변하지만 지식은 늘었다” 등의 과도한 판정 방지 |
| P0 | A05: P090 SFT 계획·토큰 계측·assistant mask 경로 정합 | 도구·학습 입력 구현 후 소규모 SFT 비교 | 이미 생성된 1,000건 파일럿을 실제로 검증 가능한 학습으로 연결 |
| P0 | A06: P083에서 동일 packed 산출물의 품질·메모리·속도 확인 | 기존 체크포인트 변환·측정; 손상 때만 후속 QAT | 40MiB 목표의 실제 통과 여부 확정 |

| P1 | A09–A11: LRM·sink·그룹 집약 진단 수정 | 대부분 기존 체크포인트 진단만 다시 수행 | 잘못된 음성 판정 때문에 유망 경로를 닫거나 불필요한 학습을 하는 것 방지 |

P0는 “학습을 전부 중단하라”는 뜻이 아니다. 현재 사용자가 실행 중인 작업에는 개입하지 않았다. **다음 모델을 승격하거나 새 SFT/KD의 성공·실패를 판정하기 전에 해결할 항목**이라는 뜻이다.

### 1.1 v1과 달라진 점, 기존 계획과 중복되는 점

- P069의 다지표 평가, P085의 표본 확대·한국어 평가·두 시드, P050/P055/P067의 KD 대조는 **이미 수행됐다**. 이를 새 연구처럼 제안하는 것은 자료 확인 누락에 해당한다.
- P082는 교사 우위 확인, 학생 고유 tokenizer, 짧은 답/이유, 비용 및 시드 대조를 이미 제안했다. v2의 권고는 이 계획의 존재를 발견한 것이 아니라 **남은 실행 경로와 판정 기준을 구체화**한 것이다.
- v1에도 bpb 오염, pooled 검정, CE와 형식의 인과 혼동, LRM WD 불일치, 평균 margin의 한계, 메모리 계약 문제가 있었다. 이들은 v2의 새 발견으로 세지 않았다. v2에서는 고칠 함수, 다시 측정할 비교, 완료 기준으로 바꿨다.
- 이번 추가 대조에서는 **v2.8 자동 로딩의 파일명 검색 실패와 schema 비호환 경로, SFT 계측기의 미정의 변수, sink의 causal null 기준 오류**를 구체적으로 확인했다. v1의 LRM·margin 지적도 현행 구현까지 추적했다. 정적 코드 경로에서 확인한 결함과 실제 실행에서 관찰한 현상을 구분한다.
- v1의 “v2.8 감사 미실행”은 현재 상태와 맞지 않는다. 지금은 **PASS_WITH_WARNINGS 감사 보고서가 존재**한다. 또한 Fresh SFT 파일럿 1,000건과 평가 300건이 생성되어 있다. 다만 토큰 보정·학습·모델 평가는 완료되지 않았다.

## 2. 현재까지 무엇이 실제로 확인됐는가

여기서 저장소의 `dense`는 종종 **층간 타잉을 하지 않은 삼진 모델**을 뜻한다. 외부 BF16 dense 모델과 혼동하면 압축률과 부모 초기화의 의미가 달라진다. 토큰 예산, 실행 토큰, 학습 step, 원문 고유 정보량도 같은 단위가 아니다.

| 축 | 후속 단계까지 반영한 결론 | 현재 남은 질문 |
|---|---|---|
| 부모 초기화와 기존 KD | P050은 부모 초기화와 KD를 분리했고 P055는 실제 체크포인트 감사와 α=0/0.1/0.3/0.5/0.7까지 수행했다. 기존 표준에서 KD 제거는 근거가 있다. | 검증된 과제 응답·짧은 이유·학생 생성 분포에 대한 증류도 무효인지는 미확인 |

### 2.2 고밀도 데이터와 별도 moonshot 연구를 합산하지 않는다

Stage1 고밀도는 34,000행 규모지만 P090의 1.0–1.7M token은 추정치이며 SFT의 실제 assistant 손실 token과 다르다. Stage2의 README도 최신 완료 상태보다 늦다. [A03 최종 통합 감사](Z:/TinyLM/datasets/TinyDataset/stage2_highdensity_dataset/audit_reports/TinyLM_Stage2_A03_TemporalOrder_Train_Consolidated_Audit_2026-09-09.md)를 전체 읽은 결과, **A01 train 87 + A02 train 86 + A03 train 69개 checkpoint entry**가 기록되어 있다. A03만 10,350행/396,177 token(+EOS), source/corpus 69쌍, 정본 포장·최종 재감사 PASS다. “A03 pilot 하나만 완료”라는 README 수치를 현재 상태로 인용하면 안 된다.

이 감사는 생성 자료의 무결성·중복·길이·예약 규약에 대한 증거다. **학생이 그 자료에서 추론 능력을 배웠다는 실험 결과는 아니다.** 현존 validation과의 충돌 0도 아직 만들지 않은 validation 전체의 무누설 증명이 아니다. 감사기의 TF-IDF/조사 판별 오류는 교정 후 재검증되어 있으므로 옛 오류만 보고 source를 다시 생성하라고 제안하지 않는다.

[Stage10](Z:/TinyLM/datasets/TinyDataset/stage10_highdensity_dataset/README.md)은 3,017,910 token 계획, 600행 pilot, 추가 corpus 생성 승인 대기 상태를 적고 있다. Stage2의 진전으로 Stage2–10 전체 약 30M이 이미 포장·감사·학습됐다고 합산하지 않는다. 길이 하한 충족은 작업 규약이며, 정보 밀도나 효율 개선은 동일 token/시간의 학습 대조로 확인해야 한다. **정제된 고밀도 CPT 자료와 Fresh assistant-only SFT는 학습 목적이 다르므로 서로 대체 완료로 표시하지 않는다.**

[moonshot 나침반](Z:/TinyLM_moonshot/handoff/COMPASS__MOONSHOT.md)에는 PM002 CPU v2 decode 신호, PM003 단일 seed 신호, PM004 준비, PM005 동적 미실행, update dynamics의 HOLD-NEURAL/GO-DIAGNOSTIC이 구분되어 있다. PM002 v3와 PM005의 구현/정적 계약을 main의 배포 성능으로 더하지 않는다. 별도 branch의 kernel·재귀 신호는 해당 동적 대조와 품질 검증을 통과한 뒤에만 main 후보에 반영하는 것이 적절하다.

## 3. 지금 수정하거나 다시 측정해야 할 실험

### A01 — P085/held-out v2.8: 새 자료를 읽는 경로 자체가 호환되지 않는다

**판정: 정적 코드 결함 확인. 재학습 불필요. v2.8 평가 전에 로더·버전 계약 수정이 필요하다.**

### A02 — P067/P088 common bpb: 오염 제외 옵션과 분모를 실제로 구현해야 한다

**판정: 평가 구현 수정과 선별 재평가 필요. 과거 142런 전량 재학습은 근거 없다.**

또한 구현은 원문을 합친 뒤 완전한 seq 청크를 평가하고, bpb 변환에 전체 바이트/전체 토큰 비율을 사용한다. 끝부분과 실제 채점하지 않은 위치·특수 토큰의 회계가 일치하지 않아 **실제로 채점한 바이트에 대한 정확한 NLL 총합**과 다르다. 현재 수치 차이의 몇 %가 이 편향인지는 실행 없이 알 수 없다. 같은 tokenizer·같은 절단 조건의 내부 비교가 전부 무효라는 뜻도 아니다.

**조치**
1. 이미 확인된 중복 ID/해시를 입력으로 받아 실질적으로 제외한다. 제외 전/후 수와 목록 해시를 출력하고, clean 세트를 평가 전에 고정한다.
2. 문서 경계, BOS/EOS, scorer가 사용한 실제 대상 token/byte 수, 꼬리 처리 규칙을 명시한다. 문서별 NLL 또는 정확히 대응하는 원문 구간으로 바이트 분모를 계산한다.
3. 언어·출처별 bpb를 함께 제시한다. 다른 tokenizer 간 비교는 동일 원문과 명시된 context 절단 규약을 쓰되 “모든 모델에 같은 토큰 수”를 같은 정보량으로 간주하지 않는다.
4. 현재 승격 후보, no-KD 기준, Qwen/Gemma KD 대조를 먼저 재평가한다. clean 평가에서 결론이 뒤집히거나 효과가 결정 기준을 넘나드는 비교만 재검토한다.

**완료 기준:** clean 집합의 실질 제외 증거, 정확한 채점 분모, 문서 ID 기반 paired 결과가 남는다. 데이터 변경이 필요한 학습은 그 다음 별도 결정한다. [P067/053](Z:/TinyLM/test_result/053_20260822_P067-단계0a-두-최신-소형모델은-KV를-버리고-있다.md), [P088/075](Z:/TinyLM/test_result/075_20260905_P088-토큰은-스텝이었고-full-val-은-학습데이터였다.md).

### A03 — P069/P085: 점수의 이름, paired 연결, margin을 고쳐야 한다

**판정: 평가기 보완 필요. 기존 13종 시험과 확대 평가를 폐기할 필요는 없다.**

[eval_bench_suite.py](Z:/TinyLM/scripts/eval_bench_suite.py)의 현재 MC는 선택지 token 평균 CE를 기본 비용으로 쓰고, 기본 PMI 보정은 무조건부 평균 CE를 뺀다. `acc_norm`은 다시 token 길이 정규화한 무보정 점수다. 이는 자체 진단으로 사용할 수 있지만 **공식 harness의 모든 과제별 acc/acc_norm과 같지 않다**. 공식 구현의 버전·task·prompt·정규화 단위를 고정해야 공개 점수와 비교할 수 있다.

동일 파일 392행 부근은 모델별 문항을 건너뛰고, paired 구간은 `min` 길이로 배열을 잘라 위치대로 대응한다. 서로 다른 문항이 skip되면 **다른 문제의 정오답을 한 쌍으로 비교**할 수 있다. skip이 0으로 확인된 기존 쌍은 이 결함 때문에 무효가 되지 않는다.

407행 부근의 `gold_margin`은 **오답 비용 평균 − 정답 비용**이다. 가장 강한 오답과의 차이가 아니다. 예를 들어 정답 비용 0, 오답 비용 −1/2/2이면 이 margin은 +1이지만 모델은 오답을 고른다. 기존 평균 margin을 삭제하기보다 정확한 이름으로 남기고, 결정 경계를 나타내는 `min(wrong_cost)-gold_cost`를 추가해야 한다.

**조치**
1. 문항마다 ID, gold/pred, 선택지별 sum/mean NLL, token/byte 길이, 보정값, 평균 margin와 최강 오답 margin, skip 사유를 저장한다.
2. paired 비교는 ID의 교집합으로 join하고, 모델별/공통 coverage와 누락 원인을 출력한다. 단순 positional zip은 제거한다.
3. checkpoint별 tokenizer와 모델 adapter를 갖춘 외부 모델 경로를 추가한다. 현재 공통 bpb의 HF 경로가 MC 벤치 전체의 HF 지원을 대신하지 않는다.
4. 기존 내부 규약 점수와 공식 규약 재현 점수를 별도 열로 표시한다. HumanEval parse 성공은 pass@k가 아니고, 일부 규칙만 처리하는 IFEval도 공식 전체 IFEval이 아니다.

**완료 기준:** 결과 한 행에서 어떤 문항·규약·모델이 점수를 만들었는지 복원할 수 있고, 잘못된 paired 대응이 불가능하다. 공식 규약 확인에는 [lm-evaluation-harness task guide](https://github.com/EleutherAI/lm-evaluation-harness/blob/main/docs/task_guide.md)를 사용하되 실제 실행에는 commit/task 버전을 고정한다.

### A04 — P085와 v2.8: 통계와 평가 범위를 바꿔야 한다

**판정: 일부 결론의 재분석 필요. 새 평가 자료는 감사가 없는 상태가 아니다.**

P085의 동일 300문항을 여러 모델·시드에서 얻은 정오답으로 단순 합산한 pooled z를 독립 표본의 증거로 해석하면 안 된다. 여섯 구조에서의 높은 상관이나 정답 CE의 일관된 개선도 외부 지능의 대리 지표를 검증한 것으로 보기 어렵다. 문항 변동과 학습 seed 변동은 다른 오차원이다. crop 단위 SE가 작아도 학습 재현성까지 높다는 뜻은 아니다.

[v2.8 감사](Z:/TinyLM/datasets/TinyDataset/stage1_dataset/held-out_v2.8/v2.8_design_generation_audit_report.md)는 4,500문항/18,000선택지의 모든 13-token window를 600M/1,200M 스트림에 대조한 기록을 포함한다. 따라서 “금지집합/중복 대조를 전혀 안 했다”고 지적해서는 안 된다. 반면 8-token 검사는 400 prompt의 첫 window 표본이고, 모든 의미 오류를 독립적으로 검증한 것은 아니다.

감사에는 context 근접쌍 2,757, 전체 문항 근접쌍 1,920, 문장 반복률 context 28.1%/전체 61.83%, 사용 어휘 token 771개, 선택지 길이 중앙값 58 token이 나타난다. 균형과 길이 통제는 장점이지만 **긴 padding과 좁은 어휘·생성 가족을 일반 지식·언어 능력의 대표로 삼을 수 없다.**

**조치**
- 이미 완료된 13-token 전수 대조는 재작업 목록에서 제외한다. 경고 중 미검증 의미·동일 규칙 변형·가족 상관을 다룬다. 문항 전문을 새 학습 자료로 복제하지 않는다.
- 가능한 유형은 독립 규칙 solver로 정답 유일성을 검증하고, 불가능한 유형은 별도 독립 검증 절차와 검증 범위를 표시한다. 원 생성기의 정답 함수를 재호출한 것만으로 독립 감사를 주장하지 않는다.
- 모델/seed 반복을 문항 수로 늘려 세지 않는다. ID 단위 paired 분석과 가족 단위 bootstrap을 사용하고, seed별 효과도 별도로 제시한다. 최종 한두 비교에서만 추가 seed를 쓴다.
- CE는 정답 문자열 likelihood, 최강 오답 margin은 선택 경계, 정확도는 결정 결과, choice NLL/Brier는 명시한 선택확률의 지표로 분리한다. 정답 문자열 CE만으로 calibration을 주장하지 않는다.
- v2.8은 문맥 규칙 추론의 진단으로 위치시킨다. padding 제거/선택지 순서 변경은 별도 진단 세트로 운영하며, 고정 최종 평가와 뒤섞지 않는다.
- 중간 난도 문항만 남기면 모델 간 차이는 보기 쉬워도 전체 능력 추정 대상이 바뀐다. 쉬운/어려운 문항의 정확도가 “정보 0”이라고 폐기하지 않는다.

**완료 기준:** P085의 현재 결론을 문항·가족·seed 단위로 재보고하고, v2.8의 4,500행을 4,500개의 완전 독립 문제로 취급하지 않는다. v2.7은 누적 진단으로 유지하되 외부 최종 주장에는 별도 잠금 평가를 둔다.

### A05 — P090/Fresh SFT: 인과 가정, 데이터 크기 기준, 계측·학습 경로를 고쳐야 한다

**판정: 다음 학습 전에 설계·코드 보완이 필요하다. SFT가 이미 실패한 것이 아니라 아직 유효한 본 실험 결과가 없다.**

[P090](Z:/TinyLM/test_plan/P090_SFT-경로.md)은 CE 개선과 정답률 정체에서 “지식은 있지만 출력 형식이 없다”를 추론하고, SFT 실패를 지식 부족 확인으로 연결한다. 둘 다 단정할 수 없다. 정답 likelihood는 개선되었지만 가장 강한 오답의 likelihood가 더 개선됐을 수 있고, 난도·표본·길이·점수 보정·학습 과제 불일치도 가능하다. SFT는 형식만 바꾸는 기법이 아니며 사실·절차·계산을 학습할 수도 있다. 반대로 작은 학생에게 맞지 않는 SFT가 실패해도 지식 학습 능력 자체의 부재를 입증하지 않는다.

P090의 “6,000건/300M” 비교는 문항 수와 token 수를 나눈 단위 오류다. 후속 [생성 요청서](Z:/TinyLM/review_request/20260908_SFT용-데이터셋-생성-요청-프롬프트.md)는 총/assistant token과 자동 생성 평가로 발전했다. 특히 **후속 부록 B는 생성 평가를 이미 포함하므로, 현재 프로젝트가 생성 평가를 전면 배제한다고 비판하면 잘못**이다. 다만 원 P090의 생성 평가 제외·실패 해석과 최신 요청서가 어긋나므로 정합성이 필요하다.

후속 요청의 최소 300 step, 5M/10M token, 사전학습의 3% 경계는 이 학생에서 검증된 성공 임계값이 아니다. **SFT와 CPT를 가르는 것은 3%라는 비율이 아니라 데이터/목적함수/마스킹/학습 목적**이다. 수십 M token을 먼저 만드는 것이 효과적인 소량 학습보다 우월하다는 근거도 아직 없다.

1. P090의 가설을 “SFT로 과제 적합성·출력·지식 중 무엇이 개선되는가”로 바꾸고, 실패를 단일 원인으로 환원하는 문구와 임의의 성공 최소 token/step 규칙을 제거한다.
2. 토큰 도구의 미정의 변수를 수정한다. 단일 chat serializer를 학습·계측·평가에서 공유하고 tokenizer 경로/해시, role 경계, EOS, packing, truncation, 총/assistant/잘린 token을 출력한다.
3. assistant-only label mask를 구현한다. prompt 위치의 직접 CE는 0이어야 하지만 attention을 통해 prompt 표현에 gradient가 전달되는 것은 정상이다. “prompt 관련 모든 gradient가 0”을 등가성 검사로 요구하지 않는다.
4. label shift, assistant 시작/끝, padding, multi-turn, 길이 초과, 빈 assistant, packing 경계의 작은 수작업 사례로 손실 위치를 검증한다. 단순히 같은 최종 CE가 나왔다고 mask 정확성을 증명하지 않는다.
5. 1,000건 파일럿으로 §5의 최소 비교를 먼저 설계한다. 결과에 따라 6,000건/더 큰 Fresh 자료로 확대한다. 이미 사용자 방향이 Fresh로 정해진 상황에서 옛 Bridge-vs-Fresh 제안을 다시 필수 gate로 만들지 않는다.
6. 자동 채점 생성 평가를 실제로 연결한다. final answer exact match/선택지 파싱/형식 제약과 짧은 이유의 검증 범위를 분리하고, 출력 불능·잘림도 집계한다. 자유 서술을 임의의 “그럴듯함” 점수로 승격 기준에 넣지 않는다.

**완료 기준:** 동일 데이터에 대해 실제 학습에 쓰이는 assistant token 수를 재현할 수 있고, 기존 모델 B0와 SFT 모델을 동일한 객관적 생성·선택 평가로 비교한다. SFT의 실패는 “그 용량·자료·목적함수 조건에서 이득 미입증”으로 보고한다.

### A06 — P030/P034/P083: 작은 모델의 메모리와 빠른 모델의 속도를 합쳐 주장하면 안 된다

**판정: 배포 측정과 변환 후 품질 검증 필요. 기본 학습 전량 재실행은 필요 없다.**

P030/P034 뒤쪽에는 latent 제거, 임베딩·버퍼 포함 회계, 여러 형상의 텐서+KV 계산이 있다. 따라서 초기 `--lut` 무동작이나 임베딩 누락을 여전히 미수정으로 지적하면 안 된다. P034C의 새 프로세스 실행과 긴 생성도 이미 수행됐다. 남은 문제는 **실제로 채점하는 변환 산출물과 메모리/속도를 재는 산출물이 같은가**, **생성 전후 RSS 차이가 최고점이 아닌가**이다.

현재 `mem_runtime`의 KV 항목에는 구조에서 계산한 값이 포함된다. 추론 구현의 KV 형변환·연결은 구/신 cache와 임시 FP32 사본이 동시에 살아 있을 수 있다. 모든 위치의 FP32 logits를 한꺼번에 만들면 vocab 32,768 × seq 1,024만으로 128MiB이고, 마지막 한 위치만 계산하면 약 0.125MiB다. 이는 구조 가중치가 작아도 prefill 구현이 중요하다는 예이지, 현재 모든 실행에서 128MiB를 추가 사용한다는 측정 주장은 아니다.

**조치**
- P083에 모델 고유 상주량, KV/context 조건, 추가 workspace 최고점, 전체 프로세스 사용량을 구분해 기록한다. **3차 리뷰 v2의 엔진 제외 예산 계약을 존중하며 전체 Python/PyTorch RSS ≤40MiB를 새로 강제하지 않는다.**
- 후보 한두 개의 packed weight/scale/int8 embedding/버퍼를 합산하고, 같은 파일·같은 실행 모드로 clean bpb, 선택·생성 품질, prefill/decode latency를 측정한다.
- 변환 전→per-row→embedding int8→실제 배포 경로를 비교해 손상 원인을 분리한다. autocast의 작은 차이가 embedding int8의 무해함을 대신 증명하지 않는다.
- shape, batch, prompt/context, 생성 길이, KV dtype, materialization 사본 생존 기간을 명시한다. 마지막 위치 head와 tiled prefill/임시 버퍼 재사용은 workspace 문제가 실제 확인될 때 구현 후보로 삼는다.
- int8 cache 방식에서 얻은 높은 tok/s와 20–30MiB LUT 회계를 결합하지 않는다. 최근 폭 실험의 int8 cache 역시 74.5/108.5MiB 수준 회계가 있으므로 별도 실행 모드다.

**완료 기준:** 같은 산출물의 능력·계약상 상주량·추가 workspace·속도를 한 행에 제시한다. 40MiB 통과 여부와 엔진 제외 보조 메모리의 부담을 함께 공개한다. [P083](Z:/TinyLM/test_plan/P083_구동기-설계-초기실험-및-플랫폼-검증.md).

### A07 — P007/P012/P037/P087/P088: 데이터 양과 효율의 인과 해석을 좁혀야 한다

**판정: 대부분 기존 결과 재분석부터 진행. 데이터 효율을 주장할 최종 비교에만 대조 학습이 필요하다.**

P037의 잘못된 캐시 평가·토큰 부족은 후속 교정 기록이 있고, P088은 훈련 자료가 full-val에 들어간 문제를 이미 발견해 공통 bpb와 여러 구조의 자를 만들었다. 반복 1/2/4회도 수행됐다. 이것들을 미실행으로 취급할 이유가 없다.

그러나 600M→1,200M pool 확대에는 한국어 비중 50%→25% 같은 변화가 함께 들어간 기록이 있다. tokenizer가 다른 큐레이션 실험이나 고유 pool·노출·update 수·schedule이 함께 바뀐 실험에서 하나의 원인만 추정하면 안 된다. P088의 높은 R²와 “유니크 2.34배에서 한계”도 소수 조건의 외삽이며 지식 학습의 물리적 상한이 아니다.

**조치**
1. 결정에 사용할 checkpoint별 실제 학습 token, assistant token, update, 원문/문서 고유량, 반복 노출, 언어 비율, tokenizer, 부모, schedule을 기존 로그에서 복원한다. 설정명 `tokens`만 믿지 않는다.
2. “같은 노출 token에서 고유 자료 증가”와 “같은 자료에서 반복 증가”를 구분한다. 언어/출처 비율을 맞추고 동일 clean 평가를 쓴다.
3. 기존 행으로 대조가 성립하면 새 학습을 생략한다. 누락된 팔이 실제 승격 결정에 중요할 때만 추가한다.
4. 다양성은 임의 crop 위치 수가 아니라 문서/정보/문제 가족과 중복을 함께 본다. 고정 step에서 gradient accumulation만 바꾼 효율과 token 효율도 구분한다.

**완료 기준:** “이 데이터로 같은 비용에서 더 배웠다”와 “더 오래 학습해서 좋아졌다”를 표에서 분리할 수 있다. 142런 모두를 무효 처리하거나 다시 돌리는 조치는 권하지 않는다.

### A08 — P005/P005b: Muon의 실용적 승리는 유효하지만 단독 원인은 아직 분리되지 않았다

**판정: 계획된 후속 대조를 정교화할 필요. Muon 구현 자체가 틀렸다고 확인된 것은 아니다.**

현재 trainer의 Muon 행렬 그룹은 기본 WD 0, AdamW 비교는 WD 0.1인 조건이 있다. 따라서 관측 개선은 그 **레시피 전체의 실용적 효과**이며 optimizer 수학만의 인과 효과는 아니다. lr 15배 선택과 업데이트 규모도 포함된다. [P005b](Z:/TinyLM/test_plan/P005b_Muon-레시피-정렬과-QK-norm-상한.md)는 이미 WD·RMS·QK-norm을 다룬다. 이를 새 아이디어로 중복 제안할 필요는 없다.

**조치**
- 기존 AdamW/WD .1, Muon/WD 0의 두 팔과 다른 조건이 정확히 같다면 AdamW/WD 0과 Muon/WD .1만 추가해 optimizer×WD를 분리한다. 같지 않으면 동일 비교 가능한 작은 설계부터 만든다.
- 그 뒤 동일 WD에서 실제 parameter update RMS를 관찰해 LR 정렬 여부를 판단한다. raw gradient norm만 같게 만드는 것은 Adam/Muon 업데이트의 정렬이 아니다.
- batch 4배 팔은 같은 token에서 update가 1/4이므로 순수 batch 효과와 step/schedule 효과를 나눠 설명한다.
- 고정 QK gain 8→학습 가능 20을 한 번에 바꾸면 초기값과 학습 가능성 두 요인이 섞인다. 우선 fixed 8 대 learnable 8로 비교하고 초기값 20은 조건부 후속으로 둔다.
- 마지막 QK logit 범위가 5 미만이라는 이유만으로 학습 가능 gain의 이득이 없다고 판정하지 않는다. SGD 가정의 1/W² 잡음식도 Muon의 일반 상한으로 쓰지 않는다.

**완료 기준:** 최종 표에 실용 레시피 승자와 요인별 해석을 따로 제시한다. 이미 진행한 LR 1/5/15/30/45 격자는 반복하지 않는다.

### A09 — P086 vector LRM: WD=0 학습을 WD=.01로 역보정한 진단을 수정해야 한다

### A10 — P081 attention sink: causal attention의 비교 기준이 잘못됐다

**판정: 진단 기준식 수정 필요. StreamingLLM을 채택해야 한다는 결론은 아니다.**

[diag_attention_sink.py](Z:/TinyLM/scripts/diag_attention_sink.py)는 모든 causal query 위치의 attention을 평균내면서 uniform 기준을 S/T로 제시한다. S/T는 마지막 query에서 T개 과거 위치를 볼 때의 비율이다. 전체 query 평균의 올바른 균등 causal 기준은 다음이다.

`null(T,S) = (1/T) × Σ[t=1..T] min(S,t)/t`

T=1,024, S=4이면 약 **2.5101%**다. 보고된 2.01–2.73%는 이 기준의 약 0.80–1.09배이며, S/T=0.3906% 대비 5–7배라는 해석은 성립하지 않는다. 시작 query 자체가 첫 네 위치만 볼 수 있어 평균이 올라간다. 후속의 union 중복 계산 수정은 이미 반영되어 있으므로 그 옛 결함을 다시 지적하지 않는다.

**조치**
- query별 causal null 및 마지막 구간 query의 sink mass를 따로 계산한다. 재귀 module을 재사용하면 마지막 방문 값으로 덮어쓰지 않도록 visit ID를 기록한다.
- attention mass가 작다는 이유만으로 기능적 기여가 작거나 안전하게 버릴 수 있다고 단정하지 않는다.
- 긴 context가 실제 요구될 때만 동일 checkpoint의 full KV와 sink+window를 비교하고, 처음/중간/끝 정보 회수 및 생성 품질로 판정한다. 임의의 mass 5%/10%만으로 채택/기각하지 않는다.

**완료 기준:** 균등 causal attention 입력에서 진단의 과대 enrichment가 사라진다. 현재의 KV 절감 연구 우선순위를 바꿀지는 수정 진단과 기능 평가가 정한다.

### A11 — P076 그룹 집약: 종료코드 수정 이후에도 유효한 MLP 분석 결과가 없다

**판정: 도구 수정·기존 부모 checkpoint 진단이 필요하다. 그룹 타잉 본학습은 그 다음 선택 사항이다.**

### A12 — P072/P049: residual gate 제거를 KV source 제거로 해석하면 안 된다

**판정: 해석 수정. pruning/공유를 실제 선택할 때만 별도 개입 실험이 필요하다.**

### A13 — P082: 같은 KD 격자를 반복하지 말고 가설·예산을 맞춰 새 경로를 검증한다

**판정: P082의 기본 방향은 타당. 현재 증거를 반영한 계획 정정과 새 목적의 학습 필요.**

[P082](Z:/TinyLM/test_plan/P082_Qwen-Gemma-교사-지능향상-KD-후속실험.md)의 “100M token에서 −0.110”은 데이터 pool/초기화/구조 등이 함께 다른 비교를 KD 단독 효과로 사용할 수 없다. P050의 부모 초기화 효과와 구분해야 한다. Qwen/Gemma full 대조는 완료됐으므로 “외부 교사를 한 번도 검증하지 않았다”는 전제로 시작하지 않는다.

현행 skip KD에서 active step은 `(1−α)CE+αKL`, inactive step은 CE다. α=.5, 매 4 step KD이면 단순 평균 계수는 CE .875/KD .125다. 이는 전 step에 .5/.5를 적용하는 것과 다르다. P055의 gradient norm 비 r≈.404도 측정한 조건의 값이며 전체 훈련 궤적·새 teacher·mask에 그대로 적용할 수 없다.

**조치**
1. 교사의 한국어·해당 문제군 정답률, 짧고 정확한 답을 생성하는 능력부터 확인한다. 낮은 raw CE가 모든 과제에서 좋은 교사를 뜻하지 않는다.
2. Fresh SFT 기준 팔과 연결해 **정답만** 대 **정답+검증된 짧은 이유**를 우선 비교한다. 기존 학생 tokenizer를 유지하는 text KD가 첫 선택이다.
3. 교사 생성 비용, 검증 탈락률, 최종 채택 token, student forward/backward, KD 주기와 T², mask를 명시한다. 동일 student token 비교와 동일 총 GPU 시간 비교를 따로 보고한다.
4. 더 큰 교사나 teacher assistant는 교사 적합성/학생 수용성 문제를 실제로 확인한 뒤 검증한다. 단순 크기 증가를 기본 해결책으로 쓰지 않는다.
5. supervised 기준이 생긴 뒤 학생이 틀린 풀이/응답을 생성하고, 정답 검증을 통과한 교사 교정을 학습하는 on-policy 단계를 소량 추가한다. generation 실패가 많은 무훈련 학생에게 처음부터 긴 on-policy rollout을 강제하지 않는다.
6. 다른 tokenizer의 logit KD는 단순 위치 KL로 붙이지 않는다. alignment를 구현한 별도 팔로 두고, 더 싼 text KD를 넘는 이득이 있을 때 확대한다.

**P082에서 보존할 대조:** 기존 `P82_N_REF`처럼 교사가 없어도 얻을 수 있는 정본 정답/reference를 같은 accepted intersection에서 학습하는 팔을 유지한다. 교사 출력만 선별한 자료와 전체 gold 자료를 비교하면 선별 효과와 교사 효과가 섞인다. §5의 S1/S2를 실행할 때도 이 규약을 약화시키지 않는다.

**비용표 수정:** P082 상단의 약 52 GPU-hour, 본문의 full core 139–160시간 및 전체 191–280시간은 서로 다른 실행 가지를 혼용한다. C0 screen으로 조기 탈락할 때 절약되는 시간과 모든 gate를 통과해 전체 팔·seed를 실행할 때의 합계를 분리한다. 팔별 생성/검증/학습/평가 시간과 실행 확률을 구분해 조건부 누적 비용을 다시 계산한다. 이미 그 시간을 잘못 소비했다는 뜻은 아니다. 부록이 본문 §3.4를 val 하나만의 판정으로 요약하는 부분도 downstream 조건을 반영해 정정한다.

**완료 기준:** 교사 비용을 포함해 CE/SFT 기준보다 개선되고, 한국어·영어·기초 지식 유지 비용을 공개한다. 이미 완료된 기존 α 스윕, 부모 초기화 대조, 청킹 비교를 새 본 실험으로 반복하지 않는다.

### A14 — P062/P074/P089: 진행 중인 구조 연구는 결과를 완성하되 비교 단위를 맞춘다

**판정: 정상적인 미완료 후속 연구와 인과 교락을 구분해야 한다.**

### A15 — P042/P063/P065/P071 및 preset: 숫자가 같다는 것과 연산이 같다는 것을 분리한다

**판정: 새 최적화/학습 경로의 검증 기준 보완. 기존 모델 전량 재학습 사유는 아니다.**

여러 결과의 반올림된 최종 손실 일치는 실용적으로 고무적이지만 bitwise equality 증명이 아니다. P071의 기존 청킹 일치 검증도 새 assistant mask·다른 teacher·새 dtype 경로 전체의 보증이 아니다. 최종값 차이가 나타난 재생성 사건을 증거 없이 특정 CUDA/환경 원인으로 확정하는 것도 피한다.

**조치:** 새 preset·청킹·SFT path를 도입할 때 canonical cfg, 부모/tokenizer/data hash, seed, 실제 optimizer group을 저장하고, 같은 작은 batch에서 forward/target 위치/gradient/한 update를 비교한다. 허용 오차는 dtype과 목적에 맞춘다. 문서 번호만으로 상태를 추정하지 말고 해당 stage의 run/종료 결과를 연결한다.

**완료 기준:** 값이 달랐을 때 어느 설정·입력·연산이 달랐는지 추적할 수 있다. 이미 있는 WIP·로그·실험목록을 확장하면 되며 별도 거대한 관리 도구를 새로 만드는 것이 우선과제는 아니다.

### 5.1 실제로 실행할 가치가 있는 가장 작은 SFT 비교

새 10M 자료 전체를 먼저 만드는 것보다 **현재 1,000건으로 경로와 방향을 확인**하는 편이 낫다. 이것은 최종 품질의 표본 크기를 1,000으로 고정하자는 뜻이 아니다.

| 팔 | 시작점과 학습 | 무엇을 알아내는가 |
|---|---|---|
| B0 | 선정된 현재 checkpoint, 추가 학습 없음 | 현재 모델이 이미 할 수 있는 것 |
| C0 | 같은 checkpoint에서 기존 clean CE 자료로 추가 학습 | 단순 추가 학습으로 얻는 이득 |
| S1 | Fresh 정답 응답, assistant-only CE | 새로운 지식/과제·형식 학습의 실용적 이득 |
| S2 | 같은 source/문제의 정답 + 짧고 검증된 이유 | 이유 token이 정답만 학습할 때보다 도움이 되는지 |

첫 단계는 B0/S1의 기능·효과 검증으로 좁힐 수 있다. 능력 개선을 주장할 때는 C0를 포함하고, S1이 성립하면 S2를 추가한다. **한 비교에서 총 token·손실 token·update·벽시계를 모두 완전히 같게 만들기는 어렵다.** 주 비교의 예산을 사전에 선택하고 나머지는 관측량으로 기록한다. 정답+이유는 손실 위치가 늘어나므로 같은 epoch 수만 맞추면 이유의 질과 추가 학습량이 섞인다.

평가는 다음처럼 분리한다.

- **자료 내 일반화:** source family가 분리된 300건 파일럿 eval. 직접 학습 문항을 외워 맞힌 비율과 구분한다.
- **생성 실행 능력:** 정답 필드 생성, 형식 제약 준수, EOS/반복/잘림, 자동 검증 가능한 계산·규칙 적용.
- **선택 능력:** 승인된 held-out 및 기존 벤치, 최강 오답 margin과 정답률을 함께 확인한다.
- **기초 능력 보존:** clean 한국어/영어 bpb와 기존 상식·추론 과제. 일괄 “val +0.05”보다 목적별 허용 손상과 효과 구간을 정한다.

S1이 틀린 형식만 줄이고 새 source 정답률이 오르지 않으면 “형식 개선”으로 보고한다. 정답률이 오르고 clean 언어 지표가 나빠지면 효용의 교환을 평가한다. 성능이 그대로이면 token·mask·실제 학습량·자료 난도·정답 모호성을 확인한 뒤 확대/수정을 결정한다. **첫 음성 결과만으로 SFT나 지식 전수 전체를 기각하지 않는다.**

### 5.2 학생에게 맞는 교사 신호를 만드는 방법

가장 큰 교사가 가장 좋은 교사는 아니다. 작은 학생이 학습하기 어려운 긴 풀이, 과도한 전문어, 검증되지 않은 그럴듯한 설명은 감독 신호의 양만 늘린다. 반대로 정답만 반복하면 이유·전이의 학습 기회를 잃는다.

권장 절차는 **정답 검증 → 짧은 응답 후보 생성 → 학생 난도에 따른 선택 → 학습 → 미해결 오류 재수집**이다. 여러 후보 중 학생 likelihood가 높은 응답을 고르는 방법은 반드시 정답 검증을 먼저 거쳐야 한다. 그렇지 않으면 학생이 이미 선호하는 쉬운 오답을 강화한다. 가장 쉬운 답만 남기면 새 지식을 배우지 못하므로 난도·과제 가족별 최소 다양성도 유지한다.

긴 사고 과정을 그대로 모사하기보다 “필요한 사실/규칙 한두 개 → 결론” 같은 짧은 과정부터 비교한다. reasoning token을 줄였다는 이유만으로 지능이 감소했다고 보지 않고 실제 정답·전이로 판단한다. 틀린 교사 이유와 정답을 한 응답에 섞지 않는다.

on-policy는 학생의 실제 생성 분포를 다룬다는 장점이 있지만, 충분한 SFT 없이 낮은 품질 rollout만 쌓으면 비싸고 편향된 자료가 된다. P082의 track C는 초기 본류보다 S1/S2를 이긴 다음 단계에 두는 것이 적절하다. [GKD](https://arxiv.org/abs/2306.13649), [MobileLLM-R1.5-140M](https://huggingface.co/facebook/MobileLLM-R1.5-140M), [SmartAD](https://aclanthology.org/2026.findings-acl.1349/)가 이 판단을 뒷받침하지만 TinyLM에서의 성공을 보장하지는 않는다.

### 5.3 적은 데이터와 적은 step을 구별한다

- **자료 효율:** 같은 고유 정보량에서 성능이 높아지는가. 교사 정답/이유, 중복 제어, 난도 조절을 평가한다.
- **token 효율:** 같은 실제 학습 token에서 높아지는가. 총 token과 assistant 손실 token을 모두 기록한다.
- **update 효율:** 같은 optimizer update에서 높아지는가. batch를 크게 하면 token 비용이 늘어날 수 있다.
- **시간 효율:** 교사 생성·검증·cache 구축·학생 학습을 합친 벽시계/GPU 시간에서 높은가.

사전학습에 이미 있는 정보를 다른 템플릿으로 바꿔 쓰는 것은 언제나 무효가 아니다. 적절한 재구성은 과제 수행을 가르칠 수 있다. 다만 이것을 새 외부 지식의 주입으로 부르면 안 된다. Fresh 자료와 출처 분리 평가는 이 둘을 구별할 좋은 출발점이다.

반복은 초소형 모델의 undertraining을 줄이는 현실적 방법이다. [Data-Constrained Language Models](https://arxiv.org/abs/2305.16264)는 제한 자료의 반복이 일정 범위에서 유용할 수 있음을 보인다. 프로젝트의 1/2/4회 결과가 직접 근거이며, 해당 논문의 반복 수를 모든 corpus의 최적값으로 옮기지 않는다.

최신 연구가 공통으로 지지하는 방향은 **학생 용량에 맞는 감독, 실제 학생 오류 분포, 학습된 지식을 보존하는 압축, 정확한 시스템 비용 측정**이다. 전형적인 KL을 더 세게 걸거나 긴 CoT를 더 많이 넣으면 된다는 결론은 지지하지 않는다.

## 7. 아키텍처를 유지할지 바꿀지

### 7.1 40MiB의 수학과 현재 목표의 의미

아래는 가중치만의 단순 산술이다. scale/zero-point, embedding의 다른 dtype, norm, KV, 실행 버퍼는 포함하지 않았다.

| 형식 | 100M 파라미터 원시 크기 | 40MiB 목표에서의 의미 |
|---|---:|---|
| FP16/BF16 | 190.73MiB | 그대로는 불가능 |
| int8 | 95.37MiB | 그대로는 불가능 |
| 4bit | 47.68MiB | **가중치만으로 이미 초과** |
| 3bit | 35.76MiB | 다른 항목을 넣을 공간이 매우 좁음 |
| 2bit packed | 23.84MiB | 혼합 정밀도·KV를 포함할 여지가 있음 |
| 이상적인 삼진 정보량 log₂3 | 18.89MiB | 정보량 하한이며 실제 2bit packing/커널 회계와 다름 |

예를 들어 vocab 32,768, embedding rank 256이면 해당 행렬 하나가 FP16 16MiB, int8 8MiB다. 초소형 모델에서는 embedding이 차지하는 몫이 커서 몸통 bit만 낮춰서는 충분하지 않다. tied output 여부와 projection도 합산해야 한다.

9700X의 L2 총 8MB와 L3 32MB는 하나의 자유로운 40MiB 저장소가 아니다. core별 L2, 공유 cache, 코드와 다른 데이터의 점유가 있으며 MB와 MiB도 다르다. **40MiB 목표는 사용자 제약으로 유효하지만, L2+L3 산술만으로 전부 cache hit 또는 일정 tok/s를 보장할 수 없다.** 최신 리뷰는 이미 예산·cache·속도를 분리하므로 이를 새로운 프로젝트 결함으로 반복하지 않는다. [AMD 공식 사양](https://www.amd.com/en/products/processors/desktops/ryzen/9000-series/amd-ryzen-7-9700x.html).

### 7.2 세 가지 설계안

| 안 | 구조·학습 설계 | 장점 | 위험/채택 조건 |
|---|---|---|---|
| A — 현재 모델을 완성 | 현재 untied 삼진 12–18층 후보, CLA2, 필요할 때 R2, 기존 tokenizer·부모·Muon. w512 좁고 깊은 후보는 P089 결과로 선택 | 기존 성과 활용, 낮은 추가 비용, SFT/KD로 가중치 수 증가 없이 개선 | clean 능력과 같은 packed 산출물 검증 필요. 가장 우선 |
| B — 작은 pretrained 모델의 지식 보존 | 약 90–135M 원모델 → native tokenizer 유지 → 선택적 2/3bit/mixed QAT → 필요한 소량 KD/SFT. pruning은 압축만으로 부족할 때 | 수천억~수조 token 사전학습을 재현하지 않고 지식 활용 | 저비트 손상·embedding/KV·한국어 부족. 4bit 100M은 목표 초과. 제한된 독립 후보로 검증 |
| C — 장기 상태 구조로 전환 | local attention+소수 global layer 또는 SSM/hybrid, 고정 상태 예산, teacher text KD | 긴 context의 KV가 지배적일 때 이점 가능 | pretrained 생태계·CPU kernel·한국어 학습 비용. 현재 실패만으로 전면 전환할 근거 부족 |

**안 A의 세부 선택.** 먼저 모델 하나로 SFT/KD 효과를 확인하고, 좋은 학습법을 32MiB/40MiB 각 대표 후보로 옮긴다. 모든 구조에서 동시에 SFT×교사×α×seed 격자를 시작하지 않는다. E128·과도한 타잉·즉석 KV 재사용은 지금까지 관측된 손상이 커서 기본값으로 복귀시키지 않는다. per-row/int8 embedding은 품질 손상 확인 후 채택한다. R2는 독립 고유 가중치 수를 늘리지 않지만 계산·visit별 KV·latency의 비용을 낸다.

**안 B의 단계.** (1) 원모델이 동일 과제에서 실제 우위인지 측정, (2) 배포 예산의 embedding/KV floor 계산, (3) 소량 calibration/QAT로 2/3bit 손상 측정, (4) 손상이 작을 때 한국어·과제 SFT/KD를 적용한다. 큰 모델을 무리하게 잘라 완전히 다른 100M 구조에 이식하기보다 **원래부터 작은 pretrained 모델을 덜 바꾸는 것**이 초기 성공 가능성이 높다. 다른 vocab 가중치를 학생 embedding에 직접 복사하는 것보다 native vocab 유지 또는 text KD가 단순하다.

**안 C의 채택 조건.** A/B에서 능력은 만족하지만 필요한 context의 KV/workspace 때문에 예산을 지키지 못하고, 저비용 cache/window 방법도 품질을 잃을 때 비교한다. 수천만 parameter SSM을 scratch로 다시 학습한다고 지식 학습량 격차가 저절로 사라지지 않는다. 일부 attention layer 유지, state dtype, kernel 지원, prefill/decode 품질을 동일 조건으로 비교해야 한다.

### 7.3 본류로 권하지 않는 방법과 그 이유

- **100M 4bit 모델의 작은 파일을 근거로 40MiB 통과 주장:** 가중치 산술과 실행 회계가 맞지 않는다.
- **TinyLoRA/LoRA의 trainable parameter 수를 총 상주 크기로 사용:** frozen 기반 모델이 남는다. TinyLM 자체 위의 작은 adapter는 적응 기법으로 별도 평가할 수 있다.
- **무작정 긴 CoT·RL·tree search:** 100M급 생성 실패와 검증 비용이 먼저 문제다. 제한된 계산/규칙 과제에는 나중에 적용할 수 있다.
- **SSM·TRM·MoE로 전면 교체:** 특수 과제 또는 큰 모델에서의 장점을 일반 한국어 40MiB의 직접 증거로 삼을 수 없다. MoE의 활성 parameter 수와 전체 상주 parameter도 다르다.
- **외부 검색/RAG/도구를 결합한 점수를 순수 모델의 지능으로 사용:** 제품 효용을 높일 수 있으나 외부 지식·메모리·도구 비용을 별도 계약으로 표시해야 한다.
- **FP8·커널·MTP·새 optimizer 격자를 최우선화:** 시간 절약 후보지만 현재 여러 kernel probe와 음성 결과가 있다. forward microbenchmark 성공이 전체 학습·능력 효율의 성공은 아니다.

## 8. 현 장비에서의 비용과 평가 계약

### 8.1 실험 자원

사용자 제약은 RAM 32–40GB 정도 사용 가능, VRAM 13–14GB 정도 사용 가능하며 15GB 부근 OOM이다. 로그의 GiB와 사용자 표기의 GB를 섞지 말고 프로세스 전체 상황을 기록한다. 과거 14.77GiB reserved의 교사 학습이 종료됐다는 사실만으로 **지금도 안정적으로 가능하다**고 계획하지 않는다.

| 작업 | 권장 운영 |
|---|---|
| 현재 TinyLM 학습 | 한 번에 하나, 알려진 안정 설정 재사용. 최근 여러 로컬 run은 약 1–2시간대지만 구조·token·온도에 따라 다름 |
| 교사 생성 | 학생 학습과 순차 실행, 검증된 응답을 저장한 text KD 우선. 본 보고서에서는 생성/저장을 실행하지 않음 |
| online logit KD | checkpointing/chunking을 활용하되 실제 peak 여유가 있는 작은 batch부터 별도 검증 |
| 데이터 작업 | 32–40GB 가용 RAM을 고려한 streaming/작은 shard. 무조건 대규모 전처리를 RAM에 올리지 않음 |
| 외부 모델 평가 | 작은 원모델 우선, 동일 scoring adapter. 모델 공개 BF16 점수와 TinyLM packed 점수를 혼합하지 않음 |
| CPU 배포 | 현재 Windows/9700X에서 측정. Linux/GPU의 논문 속도를 그대로 대입하지 않음 |

교사 cache도 비용이다. FP16 full logits는 1M 위치×32,768 vocab만으로 약 61GiB다. top-64에 FP16 값+int32 ID를 저장하면 같은 위치 수에서 약 366MiB지만, 누락 확률 질량·tokenizer 정렬·temperature 정보는 별도다. top-k라는 이유만으로 full KL과 같은 학습이 되지 않는다. **text KD의 낮은 저장·정렬 비용이 우선순위의 실질적 근거**다.

현재 수억 token 학습과 공개 작은 모델의 수천억~수조 token 학습 사이에는 수천 배 차이가 있다. 이 장비에서 공개 사전학습량을 전부 재현하는 것이 주 전략이어서는 안 된다. 고유 지식의 확보, 검증된 감독 신호, pretrained 지식 보존의 가치가 크다. 다만 교사 생성·검증 비용을 숨긴 “학생 학습 step 절약”도 총 효율로 오인하지 않는다.

### 8.2 “100M급 지능”의 비교 계약

파라미터 수를 정답률 목표로 바꿀 수 없다. 다음 두 기준을 함께 둔다.

1. **구조 기준:** 비슷한 학습 조건의 내부 100M급 untied/비압축 대조. 압축·타잉·학습 레시피의 손상을 판단한다.
2. **능력 기준:** SmolLM2-135M, MobileLLM-R1.5-140M, 적합한 90M급 등 실제 현대 외부 모델. native tokenizer, 동일 문제/split, 동일 shot/prompt/채점으로 비교한다. 공개 card는 기준 선택의 근거이고 로컬 결과의 대체재가 아니다.

한국어 관계 이해, 영어 상식/언어, 자동 채점 가능한 지식·계산/규칙, instruction 생성, 긴 context 요구가 있으면 정보 회수를 각각 보고한다. 하나의 평균 점수로 심각한 한국어 실패를 감추지 않는다. 특정 영역만 목표로 줄이면 40MiB의 성공 가능성이 높아질 수 있지만 **범용 목표를 달성했다고 이름만 바꾸면 안 된다.**

성공 계약은 “같은 packed 산출물”, “32/40MiB 포함 항목”, “대표 context”, “외부 기준 대비 과제별 허용 격차”, “한국어 최소 성능”, “추가 workspace”, “속도 우선순위”를 명시한다. 최신 리뷰에서 속도는 세 번째 우선순위이므로 15 tok/s 같은 수치를 새 절대 gate로 임의 승격하지 않는다.

### 8.3 권장 진행 순서

1. **다음 승격 전:** A01–A04 평가 연결·통계를 수정하고, 현재 최종 후보·KD 대조만 clean 규약으로 재평가한다.
2. **배포 계약:** 기존 사용자 순서대로 P083을 P082 본 실행보다 먼저 구체화하여 같은 산출물의 메모리·품질·속도를 확인한다.
3. **그 사이 준비 가능한 것:** A05의 serializer/mask/token meter와 자동 생성 평가를 구현·검증한다. 파일럿 1,000건을 근거 없이 대규모로 먼저 늘리지 않는다.
4. **학습 중심 이동:** B0/S1 → C0와 S2 → 좋은 팔만 확대/추가 seed. P082의 검증된 교사 신호를 연결한다.
5. **기존 구조 실험 마무리:** 진행 중 Stage19, 완료된 block 및 narrow parent 결과를 활용한다. P005b의 필요한 대조를 수행하고 최종 후보 수를 줄인다.
6. **독립 대안:** 안 A의 능력 격차가 크면 안 B의 원모델 평가·메모리 하한·저비트 손상부터 작은 비용으로 판단한다.
7. **조건부 확대:** SFT 이후 on-policy, cross-tokenizer alignment, 긴 context hybrid를 순서대로 검토한다.

어느 단계든 **계획 승인, 구현 완료, 정적 검증 통과, 학습 완료, 독립 평가 통과, 최종 승격**은 서로 다른 상태다. 이 보고서는 그중 문서 분석과 제안까지만 수행했다.

## 부록 C. 판정의 한계와 후속 작업의 산출물

이번 보고서의 확실성은 다음과 같다.

| 증거 수준 | 이 보고서에서의 사용 |
|---|---|
| 문서화된 실제 실행 | 001–077의 full 결과와 후속, 선별 최신 로그의 종료·평가 수치 |
| 정적 구현 확인 | 로더/schema, 미정의 변수, WD 상수, sink 기준식, scoring/paired/margin, gate와 KV 순서 |
| 아직 실행하지 않은 검증 | 수정된 도구, clean 재평가, SFT mask 학습, 동일 packed 산출물 검증 |
| 외부 실증의 유추 | 최신 KD/QAT/소형 모델 연구를 TinyLM으로 옮기는 권고. 성공 수치 보장 아님 |

정적 확인만으로 당시 모든 run의 정확한 실행 경로를 복원할 수 없는 경우는 “모든 결과 무효”로 판정하지 않았다. 반대로 문서에 PASS가 있더라도 현재 코드가 검사하지 않는 속성까지 통과했다고 해석하지 않았다. **현재 raw 로그 전체·모델 tensor 전체를 독립 재현한 감사는 아니며, 실제 코드 실행 없이 판단할 수 없는 효과 크기는 미확인으로 남겼다.**

후속 작업에서 가장 유용한 산출물은 다음 네 개다.

1. **평가 결과 묶음:** version/hash와 문항 ID를 포함하는 clean bpb·MC·자동 생성 결과. 기존 최종 후보와 외부 기준의 동일 규약 비교.
2. **배포 후보 표:** 같은 packed 산출물의 능력, 계약상 상주량, KV/context, 추가 workspace, 속도.
3. **작은 학습 대조 표:** B0/C0/S1/S2 또는 P082 N_REF/교사 팔, 실제 손실 token·시간·forgetting 포함.
4. **진단 정정 결과:** LRM 실제 WD, causal sink null, 유효 MLP 집약. 재학습이 아니라 기존 checkpoint 진단으로 닫을 수 있는 문제를 먼저 종료.

이 네 산출물로 “작게 만든 모델이 왜 아직 원하는 일을 못 하는가”를 좁힌 뒤, 좋은 학습 경로를 확장하거나 pretrained 압축 대안을 선택하는 것이 현재 실험 격자의 단순 확대보다 의사결정 가치가 높다.
