# A14 — 기존 폭·깊이·재귀 결과의 비교 완성

우선순위: **조건부** · 산출물 상태: **실험개선안 문서, 코드 생성 대상 아님**

근거: [보고서 v2의 A14](../20260909_TinyLM_40MiB_연구타당성_및_실행조치_보고서_v2.md). 원본 코드·데이터·checkpoint 및 기존 보고서는 이 작업에서 수정하지 않았다.

이 폴더에는 실험개선안만 둔다. 지금 필요한 조치가 코드 변경이 아니므로 replacement/original 폴더를 생성하지 않는다.

이 항목은 **실험개선안만** 제공한다. 현재 목적은 정상 완료된 모델을 올바르게 비교하는 것이며, 새 아키텍처나 새로운 전체 sweep을 강제로 구현하는 것이 아니다.

### 보존할 완료 결과

보고서 v2에서 확인한 P062 Stage13 block/progressive 세 학습, P089 narrow parent, 복구된 train/eval 방문 schedule·CLA default·빈 그룹 후속은 재실험 목록에서 제외한다. “진행 중”으로 적힌 나머지 stage는 실제 최신 종료 로그와 checkpoint를 확인한 뒤 상태를 갱신한다. 이 코드 패키지는 추가 실행의 완료를 추정하지 않는다.

### 후보 선정 순서

1. 같은 parent/init 규약·tokenizer·실제 데이터/노출·optimizer/schedule을 기록한다.
2. A02 clean bpb와 A03 능력 지표로 기존 후보를 비교한다. 원하는 좁은 자식이 미완료이면 그 자식만 기존 계획 범위에서 완성한다.
3. A06의 동일 배포 artifact 조건에서 32/40MiB 비용점을 만든다. 큰 int8-cache 속도를 작은 LUT 메모리와 결합하지 않는다.
4. 품질·추론 상주·workspace·지연을 함께 보고 Pareto 후보 한두 개만 남긴다.

### 인과와 실용 선정의 구분

AdamW block 대 Muon cyclic 비교는 방문 순서만의 효과가 아니다. 폭을 줄이며 깊이·부모·파라미터도 바꾼 비교는 폭 단독 효과가 아니다. 그러나 제한된 메모리 예산의 좋은 실제 구조를 고르는 데는 이 복합 비교를 사용할 수 있다.

방문 순서 단독 원인을 알아야 하는 경우에만 optimizer/초기화/norm/gate를 맞춘 최소 대조를 추가한다. 모든 축의 원인 규명을 위해 전 격자를 확장하지 않는다. 학습된 cfg의 visit_schedule을 사용하며 train_repeat를 infer_repeat에 또 대입해 새 불일치를 만들지 않는다.

**종결 기준:** 기존 완료 산출물을 사용한 후보 표와, 남은 자식/평가의 실제 종료 증거. 새 방법론 전면 교체 여부는 이 비교와 A05/A13의 능력 향상 가능성을 본 뒤 판단한다.
