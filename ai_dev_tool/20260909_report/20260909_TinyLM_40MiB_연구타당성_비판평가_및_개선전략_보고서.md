# TinyLM 40MiB 연구 타당성 비판 평가 및 개선 전략

작성일: 2026-09-09, Asia/Seoul  
상태: **REVIEW_ONLY — 조사·설계 제안. 실험 실행·구현·승격을 의미하지 않음.**  
대상: Ryzen 7 9700X, RAM 64GB 중 가용 약 32~40GB, RTX 4070 Ti SUPER 16GB 중 가용 약 13~14GB. 사용자가 보고한 약 15GB OOM 경계를 우선한다.

**2026-09-09 재검토·증보:** 초판은 P069·P082와 methods/review/실험 목록의 연결 확인이 불충분했다. 그 결과 **이미 수행된 다지표 평가를 과소서술하고, 이미 설계된 교사 검증·비용 통제·증류 경로를 새로운 제안처럼 제시했다. 이는 초판의 자료 확인 누락이다.** 해당 본문을 정정했으며, §13에서 기수행·기계획·복구된 실험 오류·남은 해석 문제를 분리한다. P069·P082 전체가 잘못된 실험이어서 초판에서 제외한 것은 아니다. 특히 P082는 후속 실험 **계획**으로, 설계의 타당성과 실제 수행 증거를 구분한다.

## 0. 판단 요약

**40MiB 이하에서 현대적인 100M급 모델의 일부 또는 상당한 능력을 구현한다는 목표는 연구할 가치가 있다. 현재 기록만으로 목표 달성을 판정할 수는 없지만, 연구 방향 자체는 P069→P085의 평가 확장, P082의 증류 설계, P083의 구동기 검증으로 이미 상당 부분 적절하게 보완되어 있다. 아키텍처 전체 폐기보다, 이 기존 계획의 남은 증거를 완성하고 국소 결과의 과대해석을 줄이는 것이 먼저다.**

현재 프로젝트는 삼진 가중치, 저랭크 임베딩, GQA·CLA, 재귀를 조합해 메모리 비용을 낮추는 데 상당한 성과를 냈다. 반면 다음 세 가지가 아직 연결되지 않았다.

1. **같은 배포 실행 경로에서 현행 40MiB 모델 예산과 품질을 동시에 입증하는 것.** 현재 작은 메모리 수치는 주로 압축 텐서 합계와 KV 회계다. 속도·품질 측정이 항상 그 압축 경로와 동일한 조건이라는 보장은 없다. 엔진 제외 계약은 유지하며, 별도 workspace·피크의 공개 범위는 §3.2처럼 구분한다.
2. **현대적인 외부 100M급 모델과의 능력 차이를 같은 평가 규약으로 측정하는 것.** P069의 13종 벤치 실측과 P085의 표본 확대·KoBEST·held-out v2.7·두 시드·margin 분석은 이미 있다. 남은 문제는 평가의 부재가 아니라, 공식 scoring과 다른 로컬 지표의 구분, 현대 외부 체크포인트와의 일치된 비교, 오염·시드 불확실성의 처리다.
3. **좋은 학습 신호를 실제 학생 학습으로 연결하는 것.** 고밀도 자료 생성과 SFT 계획은 진행 중이지만, 문서에 적힌 교육 단계가 학생의 능력 향상을 입증하지는 않는다.

권장 순서는 **기존 평가 결과 재사용 및 남은 계약 정리 → P083 배포 검증 → P082/P090의 검증된 응답 학습 → 성공한 팔의 오류 교정·조건부 KD → 필요 시 사전학습 모델 계승 또는 구조 전환**이다. 이는 이미 기록된 P083 선행 및 P082의 단계별 확대 원칙을 존중한 보완안이다. 순서를 실제로 바꾸거나 실행을 승인하는 문서가 아니다. 속도는 최신 사용자 우선순위대로 메모리·지능 다음에 둔다.

| 질문 | 판단 | 확신의 범위 |
|---|---|---|
| 현재 구조가 근본적으로 잘못됐는가? | **그렇게 단정할 근거는 없다.** 저비트·GQA·CLA·좁고 깊은 구조는 관련 연구와 정합적이다. | 설계 타당성은 높음. TinyLM의 최종 품질은 미확정 |

| 가장 성공 가능성이 높은 작은 투자부터 고르면? | **기존 모델에 검증된 단답·짧은 설명 SFT와 학생 오류 교정을 연결하는 것.** | 지시이행·해당 과제 개선 가능성에 대한 판단. 일반지능 전체의 성공률 수치는 없음 |

본 보고서는 성공 확률을 임의의 백분율로 만들지 않는다. 아래의 높음·중간·낮음은 **현 환경에서 제한된 목적의 개선을 관측할 가능성에 대한 정성적 판단**이며, 40MiB·100M급 종합 능력의 달성 확률과 다르다.

## 2. 현재 프로젝트 진행 상황

### 2.1 아키텍처와 기준 모델

기본 설정은 어휘 32,768, 폭 768, FFN 2,048, query head 12개·KV head 3개, 저랭크 임베딩 rank 256이다. 앞·뒤의 독립층과 중간층을 구분하고, MLP 공유·CLA·반복 방문을 실험한다. 실제 유망 후보는 초기의 강한 MLP 타잉 계열에서 **독립 MLP를 가진 12~18층 몸통 + CLA2 + 선택적인 재귀** 쪽으로 이동했다. 여기서 저장소가 말하는 `dense`는 주로 **층 간 가중치를 공유하지 않는 구조**를 뜻하며, 배포 가중치가 모두 FP32라는 뜻은 아니다. [설정 코드](Z:/TinyLM/tinylm/config.py), [5차 리뷰 초안](Z:/TinyLM/docs/review/202609080325_5차리뷰_초안_새-기준-프리셋과-네-승격후보.md)

공식 표준 `m100R1c + 부모초기화 + KD 제거`와 실제 실험 선두의 구조·Muon 조건은 아직 다르다. `m100R5` 승격은 리뷰와 사용자 최종 승인 전이다. “후보 성과”를 “표준 변경 완료”로 읽으면 안 된다.

### 2.3 인수인계 이후 새 로그를 반영한 정정

**좁은 부모 학습은 더 이상 미실행이 아니다.** `w512_d20_parent`는 2,289 step, 약 69.3분, 63.6M 파라미터, 로그 최종 val 3.7909, reserved 8.08GB·allocated 6.85GB, 종료코드 0으로 기록됐다. 이는 좁은 학생의 부모가 준비되었다는 뜻이다. 폭 768의 다른 부모·학생과 그 val을 바로 비교하거나 w512_d28의 최종 품질로 대체하면 안 된다. [P089 부모 로그](Z:/TinyLM/test_result/077_log_20260908_P089_stage1_narrow_parent.txt)

**벡터 LRM은 작동했지만 이득이 확인되지 않았다.** 대조군과 실험군의 full-val은 반올림 표시로 3.5402/3.5400이고, paired 출력은 평균차 +0.0001, t=0.29로 구분 불가다. 학습 시간은 약 102.7/110.1분, reserved는 9.22/9.63GB다. 따라서 현 조건에서는 추가 비용에 비해 품질 이득의 근거가 없다. 첫 판정 호출의 종료코드 130 뒤 재호출 성공 기록도 있어, 배치의 마지막 `DONE`만으로 모든 호출이 성공했다고 요약하지 않았다. 또한 이 로그의 학습 인자는 `--mlp-lrm-wd 0`인데 승수 진단은 `wd=0.01`로 보정한다. **승수가 움직였다는 raw 관측은 남지만, WD 보정값과 “기울기 몫 13.1배”는 설정 일치 확인 전 그대로 채택하면 안 된다.** 이는 읽기에서 발견한 검증 과제이며 이번에 수정하지 않았다.

## 3. 40MiB 목표의 물리적 가능성과 회계 문제

### 3.1 100M 파라미터를 담을 수 있는가

**40MiB = 41,943,040바이트**다. 아래는 파라미터 정확히 100,000,000개를 균일 저장할 때의 가중치 payload 산술이며, 스케일·인덱스·임베딩 예외·KV·작업공간을 포함하지 않는다.

| 가중치 표현 | payload | 40MiB에 대한 의미 |
|---|---:|---|
| FP32 | 381.47MiB | 불가 |
| FP16/BF16 | 190.73MiB | 불가 |
| INT8 | 95.37MiB | 불가 |
| 4bit | 47.68MiB | 가중치만으로 초과 |
| 3bit | 35.76MiB | 나머지 전부에 약 4.24MiB. 매우 좁음 |
| 2bit | 23.84MiB | mixed precision·KV·작업공간 설계에 따라 가능 |
| 5-trit/byte, 1.6bit | 19.07MiB | 유망하나 실제 모델 모든 항목이 삼진인 것은 아님 |

**즉 목표는 정보량 계산만으로 불가능하지 않다.** 다만 100M개의 삼진 계수가 100M개의 충분히 학습된 고정밀 계수와 같은 능력을 갖는다는 보장은 없다. 실제 목표는 파라미터 수 보존이 아니라 과제 능력 보존이다. BitNet은 native 저비트 학습의 가능성을 보였지만 대표 공개 모델은 2B·4T 학습 규모이므로 그 성공을 100M·단일 GPU의 성공률로 환산하지 않는다. [BitNet b1.58 2B4T](https://arxiv.org/abs/2504.12285)

### 3.2 현재 메모리 수치의 정확한 의미

| 후보 | 기록된 압축 텐서+KV, seq1024 | 40MiB까지 산술 여유 | 현재 주장 가능한 것 |
|---|---:|---:|---|
| d12 CLA2 무재귀 | 27.7MiB | 12.3MiB | 변환 후 텐서 회계가 작음 |
| d12 CLA2 R2 | 30.7MiB | 9.3MiB | 반복 방문의 KV 증가 포함 |
| d14 CLA2 무재귀 | 30.8MiB | 9.2MiB | 자원·품질 비교의 유력한 기준 후보 |
| d16 CLA2 무재귀 | 34.0MiB | 6.0MiB | workspace를 포함하면 여유가 좁음 |
| w512 d28 | 31.1MiB | 8.9MiB | 250-step 자원 프로브 기반, 품질 미확정 |
| w384 d28 | 24.2MiB | 15.8MiB | 폭 축소 대가를 포함한 품질 검증 필요 |

근거: [P030 §18](Z:/TinyLM/test_result/014_20260731003000_P030-CPU추론실측-양자화오버헤드.md), [P089 결과](Z:/TinyLM/test_result/077_20260908_P089-폭을-줄이면-같은-예산에-층을-두-배-쌓고-속도-바닥도-넘는다.md)

`mem_runtime.py`를 읽으면 압축 후 실제 텐서 크기를 합산하지만, `kv_report(seq_len=...)`는 설정 기반 회계다. 일반 생성 측정과 압축 변환 후의 짧은 forward도 구분되어 있다. 따라서 위 표는 **실제 압축 텐서를 확인한 유용한 하한 성격의 회계**이지, 지정된 긴 입력·출력을 생성하는 전체 런타임의 peak 증명은 아니다. 도구 자체도 임시버퍼 제외로 텐서합산이 과소평가될 수 있다고 명시한다. [메모리 측정 구현](Z:/TinyLM/scripts/mem_runtime.py)

권장 계약은 세 수를 함께 보고하는 것이다.

- **상시 모델 상태:** packed weights·scales·임베딩·norm·고정 메타데이터.
- **모델 실행 작업집합 최대치:** 위 상태 + 실제 KV/SSM state + 동시 생존 activation·logits·scratch·변환 사본.
- **프로세스 전체 메모리:** 위 항목 + 런타임·토크나이저·allocator·라이브러리 등의 실제 점유. 모델 증분과 분리해 원값도 보존한다.

**기존 사용자 결정은 먼저 존중해야 한다.** 3차 리뷰 v2의 9월 개정 기록은 32/40MiB 예산과 엔진 제외를 명시한다. 따라서 초판이 두 번째 항목을 곧바로 “이번 목표의 최소 엄격 해석”으로 바꾼 것은 과도했다. 현행 모델 예산의 포함 항목을 보존하면서 scratch·activation·변환 사본의 실제 부담을 별도 공개하고, 이들을 40MiB 통과 조건에 포함할지는 계약에서 명시하는 것이 맞다. 전체 프로세스 RSS까지 40MiB여야 한다고 사용자 목표를 임의로 확대하지 않는다. P083의 측정 설계와 최신 리뷰의 예산 정의를 정합시키는 것이 남은 과제다. [3차 리뷰 v2](Z:/TinyLM/docs/review/202609051900_3차리뷰_v2_초안_32와40MiB-예산-네안-재작성.md)

### 3.3 구현에서 확인한 구체적 peak 위험

현재 LUT 참조 구현에는 `codes.to(int64)`, 활성값 LUT 생성, gather 임시 텐서가 있다. 폭 768, FFN 출력 2,048, g=5, FP32를 가정하면 다음은 **코드 형상에 따른 산술 추정**이다.

- J=ceil(768/5)=154. 정수 인덱스 사본은 2,048×154×8바이트 ≈ **2.41MiB**다.
- 1,024 입력 토큰을 한꺼번에 처리하는 LUT는 1,024×154×243×4바이트 ≈ **146.18MiB**다.
- 출력 채널 청킹은 gather 크기를 줄이지만, 위 LUT의 입력 토큰 축 전체 생성을 자동으로 줄이지 않는다.
- 어휘 32,768에 대해 seq1024 전체 FP32 logits를 만들면 **128MiB**다. 최종 토큰 logits만 만들면 같은 어휘에서 **0.125MiB**다.

실제 모든 호출이 위 최악 형상을 사용한다고 주장하는 것은 아니다. **현재 작은 텐서 회계만으로 40MiB peak를 증명할 수 없다는 구체적 이유**다. prefill 입력 타일링, 출력 타일링, 재사용 scratch, 마지막 토큰용 head, full-weight 복원 방지 등이 메모리 목표를 완성하는 설계 요구다. 빠른 native LUT의 타당성은 T-MAC이 뒷받침하지만 해당 기기의 배수 성능을 Ryzen에 그대로 대입할 수 없다. [LUT 구현](Z:/TinyLM/tinylm/model/lut.py), [T-MAC](https://arxiv.org/abs/2407.00088)

또한 현재 5-trit LUT 변환은 per-row alpha 재추정을 사용한다. 학습의 group-scale 표현과 배포 표현이 달라지므로 **압축 뒤 동일 평가를 다시 통과해야 한다**. packed 파일이 작다는 이유로 학습 체크포인트의 점수를 그대로 배포 모델 점수로 부여하지 않는다. [삼진 구현](Z:/TinyLM/tinylm/model/ternary.py)

### 3.4 9700X의 캐시를 목표 근거로 삼을 때

AMD 공식 사양은 L2 총 8MB와 L3 32MB다. 그러나 L2는 코어별 캐시이고 L3와 하나의 자유로운 40MB 풀을 구성하지 않는다. 단일 코어가 전체 코어의 L2를 자신의 가중치 저장소처럼 사용할 수 없으며, 코드·다른 데이터·캐시 충돌도 공간을 차지한다. 따라서 “40MiB 이하면 L2+L3에 전부 들어가므로 빨라진다”는 일반식은 성립하지 않는다. **다만 최신 3차 리뷰 v2는 이미 예산·캐시·속도를 구분하도록 발전했다. 이것을 현재도 수정되지 않은 프로젝트 전반의 전제로 지적한 초판 표현은 정정한다.** 40MiB는 사용자 제약으로 유지하고, 캐시 효과는 P083의 별도 검증 대상으로 둔다. [AMD Ryzen 7 9700X 사양](https://www.amd.com/en/products/processors/desktops/ryzen/9000-series/amd-ryzen-7-9700x.html), [3차 리뷰 v2](Z:/TinyLM/docs/review/202609051900_3차리뷰_v2_초안_32와40MiB-예산-네안-재작성.md)

## 4. 연구 판단을 왜곡할 수 있는 문제

### 4.1 누설된 검증과 언어 구성 변화

이 문제는 본 보고서의 최초 발견이 아니다. **P088/결과 075가 캐시 누설과 토큰·step 해석 문제를 이미 진단하고 후속 공통 평가를 진행했다.** 아래 비판은 해당 교정의 부재를 지적하는 것이 아니라, 영향받은 과거 주장과 교정 후 주장을 분리하자는 뜻이다. 추가로 SQuAD 공통 bpb의 오염 제외 옵션이 현재 코드에서 적용되지 않는 문제는 결과 053에 이미 보고되어 있으며, §13.4에서 남은 한계로 다룬다.

기준표 B.17은 작은 캐시의 val 구간이 더 큰 캐시의 train 구간과 바이트 단위로 같았다고 기록한다. 당시 600M pool 실런 142개에 영향을 줄 가능성이 있었고, 큰 캐시의 validation은 한국어 비율도 달랐다. 이후 새 P062 paired 로그는 600M 캐시·약 3M val 토큰을 명시하므로 모든 최근 수치가 과거 결함을 그대로 갖는다고 단정해서도 안 된다. **비교마다 실제 pool·val provenance를 확인하는 것이 올바른 범위다.** [기준표 B.17·B.21](Z:/TinyLM/docs/EXPERIMENT_BASELINES.md), [새 paired 로그](Z:/TinyLM/test_result/047_log_20260908_P062_stage14b_paired_d18.txt)

개선 제안은 전 과거 런 재학습이 아니다. 원본·가족 단위로 분리한 고정 dev/test를 먼저 만들고, **결정에 사용하는 상위 후보와 대조군만** 깨끗한 공통 평가로 재판정한다. “차이가 작을 때만 오염을 다시 본다”는 규칙은 일반지능·외부 모델 비교의 최종 증거에는 충분하지 않다. 큰 효과도 용량과 암기에 따라 편향될 수 있기 때문이다.

### 4.2 CE와 정답률의 분리를 ‘지식은 있고 형식만 없다’로 단정할 수 없다

**이 구분은 P069 및 결과 056이 이미 실험으로 다뤘고, P085/결과 074가 더 큰 표본과 margin으로 후속 검증했다.** 초판은 이를 충분히 인정하지 않았다. 새로 필요한 것은 다지표 체계의 재발명이 아니라, 기존 결과에서 “정답 CE 개선=calibration 개선=지식 보유”로 넘어가는 해석의 제한이다. 정답 문자열 CE만으로 선택지 확률의 calibration을 입증할 수는 없다.

정답 CE는 정답 문자열 확률을 보고, 객관식 정답률은 **오답과의 상대 순위**를 본다. 정답 확률이 올라도 오답 확률이 더 오를 수 있다. 따라서 CE 개선과 정확도 하락은 교정 가능한 출력 문제일 수도 있지만, 오답 관계의 혼동·언어 편향·길이 효과·지식 부족일 수도 있다.

`gold_margin`이 6개 체크포인트에서 정확도와 ρ=+0.943으로 맞았다는 것은 유용한 진단 신호다. 하지만 두 지표는 같은 후보 점수에서 만들어지므로 상관 자체가 독립적인 지능 타당성 증거는 아니다. **margin으로 선별하되 실제 생성·독립 과제·새 시드에서 확인**해야 한다. [P085 결과 §23](Z:/TinyLM/test_result/074_20260904_P085-정답CE는-9쌍-전부-맞고-정확도는-끝까지-못-가른다.md)

### 4.3 시드 변동과 평가 문항 변동을 분리해야 한다

같은 구조의 d12 두 시드가 held-out 37.7%/31.0%로 다른 것은 계기가 고장났다는 증거만은 아니다. 실제 학습 변동도 원인이 될 수 있다. 반대로 두 시드의 같은 300문항을 합쳐 600개의 독립 표본처럼 계산하면 불확실성을 과소평가할 수 있다. 기존 pooled z=3.30은 탐색 신호로 남기되 확정적인 아키텍처 판정으로 승격하지 않는다.

최종 비교는 최소 3개 시드를 권장하되, 3개만으로 충분한 검정력이 보장되지는 않는다. 시드와 문항/문항 가족을 구분한 계층적 불확실성 추정, 원본 문서 단위 bootstrap, paired 차이·실용적 효과 크기를 함께 본다. 다수 후보를 반복 비교한 후 선택했다면 최종 잠금 평가가 필요하다.

**이 역시 P082 §8 등에 이미 설계된 내용이다.** P052의 아키텍처별 시드 실측과 P088의 bpb 분해능 재측정도 수행됐다. 미완료인 것은 이를 최종 교사/SFT 비교에 적용한 결과이며, 모든 축에 대해 처음부터 시드 실험을 반복하자는 권고가 아니다.

### 4.4 기존 SFT 계획에서 수정해야 할 설명

| 기존 설명 | 문제 | 권장 수정 |
|---|---|---|
| “SFT는 모르는 사실을 가르치지 않는다” | SFT도 파라미터를 갱신하므로 새 사실·절차를 학습할 수 있음 | 작은 SFT로 광범위한 지식이 안정적으로 늘어난다는 보장이 없다고 표현 |
| “6,000 레코드 = 300M 토큰의 0.002%” | 레코드 수와 토큰 수를 나눈 단위 오류 | 예컨대 6,000×평균 300토큰이면 1.8M, 300M의 0.6%. 실제 토큰화로 확인 |
| “CE/argmax 분리는 지식이 아니라 형식 문제” | 가능한 원인 중 하나만 확정 | 질문·정답·오답을 통제한 반례와 생성 시험으로 원인 분리 |
| “100M이므로 생성 과제는 0이 정상” | 모델·학습·난이도마다 다름 | 어려운 GSM8K만 쓰지 말고 쉬운 생성·수치·조건준수부터 평가 |
| “4지선다는 생성이 없으므로 타당성이 높다” | 자동화는 쉽지만 shortcut·정답 오류가 가능 | 의미 정답성·길이·위치·표현·출처 편향을 함께 검사 |
| 고검정력 문항만 최종 평가에 집중 | 현 후보를 가르는 문항에 과적합·대표성 상실 가능 | 진단용 판별 세트와 대표성 있는 잠금 테스트를 분리 |

근거 문서: [P090](Z:/TinyLM/test_plan/P090_SFT-경로.md), [SFT 요청 부록 B](Z:/TinyLM/review_request/20260908_SFT용-데이터셋-생성-요청-프롬프트.md). 위 표는 설명의 수정 제안이며 원문 파일을 바꾸지 않았다.

**적용 범위 정정:** 위 설명 문제를 프로젝트 전체의 현행 방침으로 확대하면 안 된다. `methods/10_benchmarks.md`는 생성 평가의 “측정 금지”를 이미 철회했고, 낮은 예상 점수·낮은 검정력과 실행 불가능을 구분한다. P069의 옛 계획 상태보다 결과 056 및 이후 개정을 우선해야 한다. 일부 설명이 P090 등에 남은 것과, 프로젝트가 생성 평가를 전혀 하지 않았다는 주장은 다르다.

## 5. 무엇을 ‘100M급 지능’으로 비교할 것인가

### 5.1 파라미터 수를 목표 점수로 사용하지 않는다

외부 기준선 대조는 **P059 및 4차 리뷰에서 이미 제안된 방향**이다. 아래 후보는 그 계획을 최신 공개 모델과 연결하는 보완이며 새로운 연구축의 발명으로 제시하지 않는다. 남은 공백은 비교 제안의 존재가 아니라, 같은 평가 규약과 실제 양자화 산출물로 얻은 대조 결과다.

**100M급은 하나의 지능 수준이 아니다.** 오래된 100M 모델, 교육 데이터로 충분히 학습한 135M 모델, 추론 중심의 140M 모델은 다르다. 특정 모델 하나를 이긴 뒤 전체 100M급을 대체한다고 쓰는 것도 부적절하다.

| 비교 대상 | 역할 | 주의점 |
|---|---|---|
| 현재 TinyLM 부모와 표준 학생 | 내부 개선·압축 대가의 대조군 | 프로젝트 내부 동급이지 외부 현대 모델과의 동급이 아님 |
| MobileLLM-125M | 좁고 깊은 구조·GQA·공유 접근의 기준 | 기존 tokenizer·checkpoint를 그대로 쓰는 기준과 구조만 닮은 모델을 구분 |
| SmolLM2-135M Base / Instruct | 일반 언어 이해와 지시이행의 공개 기준 | 주로 영어. 135M은 2T 토큰 사전학습으로 TinyLM의 현재 예산과 크게 다름 |
| MobileLLM-R1-140M | 최신 소형 추론 지향 대조군 | 어휘 128k·다른 학습 분포. 총 파라미터 수만으로 메모리 적합성을 추정하면 안 됨 |
| Falcon-H1-Tiny-90M-Instruct | 90M의 실제 생성·지시이행 및 hybrid 대안 | 영어 모델이며 모델 카드의 능력과 임의 GGUF 양자화의 능력은 다름 |
| 동일 한국어 과제를 푸는 검증된 교사 | 학생이 학습할 수 있는 목표의 질 확인 | 교사도 틀리면 증류 대상으로 부적절. 크기나 브랜드로 대체 불가 |

자료: [MobileLLM](https://arxiv.org/abs/2402.14905), [SmolLM2-135M 공식 카드](https://huggingface.co/HuggingFaceTB/SmolLM2-135M), [MobileLLM-R1 공식 코드·평가](https://github.com/facebookresearch/MobileLLM-R1), [Falcon-H1-Tiny 공식 카드](https://huggingface.co/tiiuae/Falcon-H1-Tiny-90M-Instruct)

외부 자료상 SmolLM2-135M-Instruct는 IFEval을 0이 아닌 수준으로 수행하고, MobileLLM-R1-140M은 공식 표에서 GSM8K·HumanEval의 비영점 성과를 보고한다. 이는 **“이 규모의 생성·추론은 평가할 필요가 없다”는 일반론을 반박**한다. 서로 다른 shot·prompt·scoring 설정의 공개 숫자를 TinyLM의 로컬 숫자와 직접 빼지는 않는다.

평가는 두 장부로 나눈다. **능력 장부**는 외부의 강한 100M급 모델과 같은 과제를 비교하고, **연구 효율 장부**는 데이터·학생 연산·교사 비용까지 맞춘 실험에서 개선을 비교한다. 외부 모델의 수조 토큰 사전학습은 전자의 비교를 무효화하지 않지만, 후자의 학습효율 우위를 주장할 때는 반드시 비용으로 설명해야 한다.

### 5.2 최소 능력 묶음

| 능력 | 권장 시험 | 결과를 읽는 기준 |
|---|---|---|
| 한국어 의미·관계 이해 | 감사된 v2.7 진단 + 승인·감사 후 v2.8 + 별도 가족 분리 테스트 | 관계별·길이별·seen/unseen 구분. 새 v2.8은 닫힌 문맥 규칙 추론이므로 사실 지식 전체를 대표하지 않음 |
| 영어 상식·언어 이해 | ARC-Easy, HellaSwag, PIQA 등의 동일 harness 비교 | tokenizer가 달라도 동일 문제·표준 scoring으로 비교 가능. 토큰 CE를 직접 비교하는 것은 별개 |
| 지시이행 | 쉬운 길이·형식·포함조건과 표준 IFEval 일부/전체 | 규칙 만족과 답의 의미 정답성을 분리 |
| 근거 기반 답변 | 짧은 제공 문서에서 단답·추출·1단계 요약 | 사실 암기 없이 문맥 이용 능력을 확인 |
| 계산·절차 | 정확한 oracle이 있는 한두 단계 산술·조건·시간순서 | 새 수·새 템플릿·새 조합에서 일반화 평가 |
| 생성 건전성 | EOS 정지, 반복률, 질문 관련성, 잘못된 전제에 대한 대응 | 원시 출력과 규칙 점수를 함께 보존 |
| 언어모델 능력 | 고정 독립 한국어/영어 문서 bpb | 동일 원문 바이트, 경계, context 규칙. tokenizer 간 비교에 적합한 보조 지표 |

객관식만으로 사전 선별할 수는 있지만, 최종 LLM 판정에는 **실제 생성**을 포함해야 한다. 긴 수학 문제를 못 푸는 것과 단문 지시도 못 따르는 것은 다른 실패다. 정확한 프로그램 oracle을 쓸 수 있는 과제부터 시작하면 사용자의 수작업 채점 부담을 줄일 수 있다. 프로그램 채점기 또한 별도의 알려진 정답·오답 사례로 검증해야 한다.

### 5.3 최종 성공 계약 제안

1. 배포 모델·tokenizer·양자화 방식·scale granularity·KV dtype·context·batch=1·decode 규칙을 고정한다. **seq1024가 prompt+생성의 총 길이인지**도 명시한다.
2. 모델 작업집합 peak≤40MiB와 실제 변환 후 품질을 같은 artifact에서 확인한다. 프로세스 전체 peak는 별도 병기한다.
3. 우선 비교할 외부 모델과 핵심 과제 묶음을 결과 보기 전에 고른다. Base끼리, Instruct끼리의 비교를 우선한다.
4. 동급 판정은 “유의차가 안 남”이 아니라 **사전등록한 비열등성 허용폭과 신뢰구간**으로 한다. 예를 들어 핵심 정확도 과제의 허용 손실 2pp를 검토할 수 있으나, 필요한 표본수와 사용 목적에 맞춰 확정해야 한다.
5. 무작위·길이·위치 같은 자명 기준선보다 충분히 나아야 한다. 모두 우연 수준인데 서로 비슷하다는 것은 목표 달성이 아니다.
6. 특정 영역의 우위를 다른 언어·능력의 심한 퇴보와 평균해 숨기지 않는다. 한국어 능력은 영어 소형 모델과의 비교만으로 확정하지 않는다.

## 6. 최신 연구를 TinyLM에 적용할 때의 판단

### 6.1 2024~2026 연구의 공통 방향

공개 근거가 반복해서 지지하는 것은 **적합한 데이터·사전학습 계승·저비트 학습·추론 상태 절감·학생 오류에 맞춘 감독**의 결합이다. “새로운 아키텍처 하나가 적은 데이터의 모든 부족을 상쇄한다”는 근거는 약하다.

| 연구 | 확인한 요지 | TinyLM에 적용할 판단 |
|---|---|---|
| MobileLLM, 2024 | sub-billion에서 깊고 얇은 구조, 임베딩 공유, GQA, block 공유의 효율을 연구 | 폭 512 후보를 시험할 근거. 폭 축의 승리를 보장하지 않음 |
| Cross-Layer Attention, 2024 | 인접층의 KV 공유로 추가 캐시 절감 | 현재 CLA 연구 유지. 문맥 길이에 따라 메모리·품질 교환비를 재평가 |
| FineWeb/FineWeb-Edu, 2024 | 데이터 정제·교육적 품질 선택이 학습 결과를 바꿈 | 고밀도라는 이름보다 검증된 학습 효용·다양성·출처가 중요 |
| Scaling Data-Constrained LMs, 2023~2025 | 제한된 데이터의 반복 학습이 일정 구간에서 효율적일 수 있음 | 반복 노출을 일률적으로 과적합이라 버리지 않음. 한국어·TinyLM에서 최적 횟수는 별도 |
| BitNet 2B4T, 2025 | native 저비트 모델의 실제 학습·공개 배포 사례 | 삼진 방향 유지 근거. 작은 학생에서 고정밀과의 차이를 재야 함 |
| Low-Bit Quantization Favors Undertrained LLMs, 2025 | 충분히 학습된 작은 모델에서 저비트 손상이 커질 수 있음 | 초기 저토큰 비교의 작은 양자화 손실을 장기 학습까지 고정값으로 보지 않음 |
| MobileLLM-R1, 2025 / ICLR 2026 | 데이터 큐레이션·재샘플링·후학습을 결합한 sub-billion 추론 모델 | 작은 모델의 추론을 포기할 이유는 없음. 논문의 수조 토큰 예산은 현재 장비와 큰 차이 |
| Falcon-H1-Tiny, 2026 | hybrid 소형 모델과 SFT 데이터를 사전학습 혼합에 넣는 접근을 보고 | 순차 SFT 외에 중간학습 혼합을 후보로 추가. 보고된 혼합률을 그대로 채택하지 않음 |
| Learnable Multipliers, 2026 | 행·열 scale의 자유도를 학습하고 Adam/Muon과 비교 | 원 논문을 검토할 가치. 현재 TinyLM 벡터 LRM 무효 결과를 우선하고 대규모 추가 투자 보류 |
| Self-Distilled Reasoner, 2026 | 정답 등 추가 정보를 가진 teacher 경로와 student 경로의 on-policy 학습 | 단순 자기 복제와 다름. 초기 학생에게 없는 일반 지식을 저절로 만드는 방법으로 해석하지 않음 |
| DWA-KD, 2026 | tokenizer 간 공간·시퀀스 정렬과 정보성에 따른 가중 | 이종 tokenizer 증류 후보. 작은 실험에서 정렬 비용을 먼저 확인 |

각 행의 1차 자료: [MobileLLM](https://arxiv.org/abs/2402.14905), [CLA](https://arxiv.org/abs/2405.12981), [FineWeb](https://arxiv.org/abs/2406.17557), [Data-constrained scaling](https://arxiv.org/abs/2305.16264), [BitNet](https://arxiv.org/abs/2504.12285), [저비트 손상 연구](https://arxiv.org/abs/2411.17691), [MobileLLM-R1](https://arxiv.org/abs/2509.24945), [Falcon 기술 보고](https://tiiuae-tiny-h1-blogpost.hf.space/), [Learnable Multipliers](https://arxiv.org/abs/2601.04890), [Self-Distilled Reasoner](https://arxiv.org/abs/2601.18734), [DWA-KD](https://arxiv.org/abs/2602.21669).

Falcon의 SFT-pretraining 결과는 특히 관련이 있다. 공식 보고는 기존 순차 SFT와 사전학습 중 SFT 혼합을 비교한다. 이것은 **후학습 예제를 늦게 한 번만 주어야 한다는 가정**을 흔든다. 그러나 그 모델의 memorization window 추정과 25% 혼합률은 TinyLM의 최적값이 아니며, 해당 표가 40MiB 양자화 이후의 결과라는 뜻도 아니다. 이 보고서는 소규모 통제 실험의 동기로만 사용한다. [Falcon 기술 보고](https://tiiuae-tiny-h1-blogpost.hf.space/)

### 6.2 가장 유망한 증류 순서

다음은 P082 트랙 B→조건부 C 및 학생 분포 기반 증류와 겹치는 **기존 경로의 우선순위 권고**다. 초판이 이를 새로운 방법 목록처럼 제시한 점을 정정한다. P082의 승인된 실행 순서를 자동으로 변경하지 않는다.

**1순위 — 교사 응답을 검증하고 학생 tokenizer로 학습하는 sequence-level 증류.** 교사는 정답·짧은 설명·근거를 제공하고 학생은 자신의 어휘로 assistant-only SFT를 한다. 어휘 매핑과 동시 teacher forward가 필요 없어 현재 장비에서 위험이 낮다. 가장 큰 기대 효과는 질문 응답 방식, 관계 구분, 짧은 절차, 실제 출력의 개선이다. TinyStories와 Distilling Step-by-Step은 각각 제한된 언어 분포와 과제별 이유 감독의 가능성을 뒷받침하지만, 범용 지능 전체로 확장한 보장은 아니다. [TinyStories](https://arxiv.org/abs/2305.07759), [Distilling Step-by-Step](https://arxiv.org/abs/2305.02301)

**2순위 — 학생이 실제로 틀리는 응답을 교사가 고치는 데이터 반복.** 학생의 train/dev 전용 질문에 대한 실패를 모으고, oracle로 확인한 교정 답과 짧은 이유를 추가한다. 정답·오답이 동시에 맞는 애매한 사례는 제외한다. 학생 샘플이 자기실수를 포함한다는 점은 GKD의 동기와 맞지만, 텍스트를 오프라인으로 고쳐 SFT하는 방식 자체를 GKD의 정확한 구현이라고 부르지는 않는다. [GKD](https://arxiv.org/abs/2306.13649)

**3순위 — 동일 tokenizer·동일 공간의 soft-target KD를 제한적으로 재개.** CE 단독, forward-KL, 학생 생성 분포를 사용하는 reverse/skew-KL 계열을 작은 예산에서 비교한다. MiniLLM은 reverse-KL 계열의 on-policy 접근을, DistiLLM-2는 교사·학생 응답을 다르게 다루는 대비 접근을 제안한다. reverse-KL은 불필요하게 넓은 분포 모방을 줄일 가능성이 있지만 mode 축소 위험도 있다. 단순히 KL 방향만 바꿔 논문의 알고리즘을 재현했다고 하면 안 된다. [MiniLLM](https://arxiv.org/abs/2306.08543), [DistiLLM-2](https://arxiv.org/abs/2503.07067)

**4순위 — cross-tokenizer·hidden-state KD.** DSKD와 DWA-KD는 서로 다른 어휘·시퀀스 공간을 정렬한다. 임의로 같은 위치의 logits나 hidden vector를 맞추는 것은 잘못이다. 특히 한국어의 분절 차이, 폭·층 대응, projection의 비용을 따져야 한다. 성공하면 training-only projection은 배포에서 제거할 수 있으나, 학생에 남는 adapter는 메모리에 포함한다. [DSKD](https://arxiv.org/abs/2406.17328), [DWA-KD](https://arxiv.org/abs/2602.21669)

큰 교사를 먼저 새로 학습하는 것은 권장하지 않는다. Distillation Scaling Laws는 교사가 이미 있거나 여러 학생에 비용을 나눌 수 있을 때와, 한 학생을 위해 교사까지 새로 만드는 경우의 경제성이 다름을 보인다. 따라서 **사용 가능한 사전학습 교사를 활용하고, 학생에 맞는 교사를 선택**한다. 가장 큰 교사의 benchmark 순위가 가장 좋은 교사라는 보장은 없다. [Distillation Scaling Laws](https://arxiv.org/abs/2502.08606), [Capacity gap 연구](https://aclanthology.org/2025.acl-long.1097/)

### 6.3 현재 KD의 실패를 정확히 해석하기

현재 trainer는 문서 토큰 `x,y`에서 CE를 계산하고, 교사의 동일 입력 logits를 이용한 forward-KL을 가중합한다. 기본 인자에는 KD alpha=0.5, temperature=2.0이 있으며, 실제 실험별 값·skip 주기·정밀도는 로그로 확인해야 한다. 이 구조는 **학생의 생성 실수를 교정하는 on-policy instruction 증류와 다른 문제**다. [현재 trainer](Z:/TinyLM/tinylm/train/trainer.py)

외부 HF 교사를 쓰는 경로는 교사의 어휘 설정을 학생 구성에 반영한다. 따라서 “서로 다른 tokenizer logits를 무조건 같은 인덱스로 비교해서 기존 KD가 실패했다”는 진단도 이 코드에 대해 확인 없이 적용하면 안 된다. 교사의 큰 어휘를 학생에게 물려주어 생기는 임베딩·head·손실 텐서 비용과, 서로 다른 교사 계열의 tokenizer 교락을 구분해 보아야 한다. [HF 교사 규약](Z:/TinyLM/tinylm/hf_spec.py), [trainer 설정 경로](Z:/TinyLM/tinylm/train/trainer.py)

기존 검증과 새로 남은 질문을 구분해야 한다.

| 쟁점 | 이미 확인·설계된 것 | 남은 범위 |
|---|---|---|
| 부모초기화와 KD 분리 | P050이 비교했고 P055가 α=0/0.1/0.3/0.5/0.7을 비교 | 100M 토큰의 −0.110 인용은 별도 실험의 복합 개입이므로 KD 단독 이득으로 쓸 수 없음 |
| KD 구현·실효 강도 | P055 Stage0c의 실제 체크포인트 감사와 P071 청킹 등가성 검사 | 검사한 조건 밖의 SFT mask·새 교사·on-policy 경로까지 보증하지 않음 |
| 외부 교사 | P067의 Qwen 및 Gemma full run과 각 no-KD 대조군이 존재 | 도메인·tokenizer·교사 우위가 섞인 차이를 보편적 KD 실패로 확대할 수 없음 |
| 교사 우위·native 32k·짧은 응답 | P082가 선결 gate와 트랙 B/C로 이미 설계 | 계획대로 얻은 학생 학습 결과는 미확인 |
| 토큰·GPU 비용·3시드 | P082에 별도 CE/비교 팔과 통계 계약이 있음 | 비용 요약의 내부 불일치 정리 및 실제 비용 장부 필요 |

따라서 현재 no-KD 기본은 유지할 근거가 충분하며, **동일한 α 스윕이나 부모 분리 실험의 무조건 재실행은 권장하지 않는다.** P082가 이미 열어 둔 새로운 목적·데이터·손실의 증류를, 기존 대조군과 실패 기록을 활용해 검증하는 것이 타당하다. 자세한 수치·오류 범위는 §13.3~13.4에 정리한다.

### 6.4 ‘지능이식’으로 오해하기 쉬운 방법

| 방법 | 실제로 옮기는 것 | 40MiB 관점의 판정 |
|---|---|---|
| 부모 가중치 초기화 | 이미 학습한 표현과 파라미터 | 강한 근거가 있는 자산. 형상·tokenizer가 맞아야 직접 복사 가능 |
| 구조적 pruning + 복구 KD | 큰 모델의 일부 구조와 학습 표현 | 가능한 계승 경로. 2~4배 압축의 문헌 성과를 10~100배로 외삽 금지 |
| LoRA·TinyLoRA | 큰 기반 모델에 대한 작은 업데이트 | 업데이트가 작아도 기반 모델은 배포에 필요 |
| task vector·가중치 평균 | 같은 좌표계를 전제로 한 변화량 | 다른 폭·층·tokenizer 모델에 직접 덧셈해 일반지능을 이식할 수 없음 |
| hidden-feature distillation | 정렬된 내부 표현 | 보조 loss 후보. 학습·배포 모듈 경계와 비용 확인 필요 |
| 외부 검색·도구 | 모델 밖 지식과 계산 결과 | 제품 능력 개선 가능. 모델 자체의 내재 지능 향상과 별도 평가 |

Minitron 계열은 사전학습 모델에서 pruning·증류로 학습비를 줄인 근거다. 다만 논문은 15B에서 8B/4B 등을 다루므로 100M 삼진 학생의 성공을 직접 입증하지 않는다. [Compact Language Models via Pruning and KD](https://arxiv.org/abs/2407.14679)

2026년 **Learning to Reason in 13 Parameters**는 대형 기반 모델의 극소수 조정 파라미터에 관한 연구다. 26바이트만으로 그 지능을 독립 실행하는 모델을 만들었다는 뜻이 아니다. 마찬가지로 TRM의 7M 퍼즐 추론 성과는 작은 재귀망의 유망한 사례지만, 일반 한국어·영어 생성 LLM의 대체 증거가 아니다. [TinyLoRA 연구](https://arxiv.org/abs/2602.04118), [Tiny Recursive Model](https://arxiv.org/abs/2510.04871)

### 7.2 가장 권장하는 학습 경로의 구체적 설계

**권장안 A: 현재 TinyLM의 유력한 메모리 후보를 유지한 상태에서, 짧고 검증 가능한 응답을 학습하고 오류 중심으로 개선한다.**

1. **동일 부모의 후보를 1~2개로 좁힌다.** d14 CLA2 무재귀 또는 d12 CLA2 R2를 기준 후보로 두고, w512 계열을 별도 후보로 비교한다. 이는 현 단계의 실험 선택 제안이며 공식 승격이 아니다. 모델 작업집합 예산상 여유가 작은 후보부터 더 많은 workspace 검증이 필요하다.
2. **교사는 짧은 답과 검증 가능한 근거를 생성한다.** 우선 한두 단계 관계·수치·문서 근거 문제에 집중한다. 모든 학생에게 긴 CoT를 강제하지 않는다. 최종 답만 학습하는 팔과 한두 문장 이유를 포함하는 팔을 비교한다.
3. **학생 tokenizer로 직렬화하고 assistant target만 학습한다.** EOS, prompt mask, 길이 초과·truncation, packed 경계, 실제 target token 수를 확인한다. `rejected`는 positive CE에 그대로 섞지 않는다.
4. **작은 예산에서 확대 여부를 결정한다.** 예시로 0.5M→2M→10M 총 입력 토큰 구간을 두되, unique target·반복 target·update·teacher 생성량을 따로 기록한다. 10M은 요청서의 목표량이며 성능이 발생하는 과학적으로 확정된 최소량은 아니다.
5. **성공 후 train/dev 오류만 수집한다.** 새로운 인물·수·조건·순서·표현을 만들고, 확인된 오류와 그 수정 이유를 학습한다. 평가 문항이나 그 풀이를 이 데이터에 넣지 않는다.
6. **망각을 억제한다.** 별도 CLM 유지 데이터나 작은 혼합 비율을 검토하되, pure SFT와 구분되는 팔로 평가한다. 최종 양자화 표현과 다른 학습 표현을 쓰면 배포 복구 단계를 추가한다.

과제별 성공 가능성이 높다는 판단은 “P082/P090에 설계된 출력 학습 경로를 실제 학생 효과까지 연결한다”는 점에 근거한다. **현재의 약한 base가 작은 SFT만으로 광범위한 사실 지식과 장기 추론을 확보한다는 기대는 두지 않는다.**

### 7.3 적은 데이터·적은 step에서의 효율을 높이는 방법

- **정답 밀도:** 배경문만 길게 반복하는 대신, 문맥→질문→정답·짧은 이유의 조건부 학습 신호를 만든다. 관계 라벨 수가 많다는 것과 유효 정보량이 많다는 것은 다르다.
- **다양성과 난이도:** 쉬운 사례로 형식을 익히고, 중간 난도의 구분·조합을 늘린다. 가장 큰 loss 사례만 선택하면 오류·이상치를 과대표집할 수 있다.
- **작은 데이터 재사용:** 동일 원문 재노출은 금지할 대상이 아니라 비교할 변수다. fresh와 bridge는 동일 토큰·update·난이도로 비교하고, source 노출이 불명확하면 `unverified`로 남긴다.
- **교사의 역할 분리:** 큰 교사는 오프라인 생성·검증에 쓰고, 학생과 동시 학습하는 teacher는 작고 검증된 모델로 제한할 수 있다. 이 중간 교사를 새로 학습하는 추가 비용이 이득을 넘는지도 계산한다.
- **배치와 step의 분리:** 같은 10M 토큰을 batch 16,384로 처리하면 약 611 updates다. batch를 줄여 step만 늘린 뒤 “적은 데이터에서 성능 향상”이라고 보고할 때는 FLOPs·벽시계도 함께 본다.
- **배포 형식과 일치하는 복구:** 최종 per-row scale·임베딩 quant·KV dtype를 미리 결정하고 해당 형식에서 짧게 복구한다. 학습 후 별도 변환의 품질 손실을 뒤늦게 발견하는 일을 줄인다.

반복과 데이터 정제는 문헌상 유망하지만, 이미 학습된 부모까지 포함한 총 노출량을 누락하면 효율을 과대평가한다. “학생 300M 토큰”과 “전체 시스템이 300M 토큰으로 배운 것”은 같지 않다. [Data-constrained scaling](https://arxiv.org/abs/2305.16264), [FineWeb](https://arxiv.org/abs/2406.17557)

## 8. 아키텍처를 유지하거나 바꿀 때의 설계 대안

### 8.1 세 가지 안의 선택 기준

| 안 | 구조·학습 출발점 | 장점 | 단점 | 권장 상황 |
|---|---|---|---|---|
| **A. 현재 구조의 정리·학습 개선** | TinyLM 삼진 Transformer, CLA2, 폭·깊이 후보, 기존 부모 | 코드·로그·자산 활용, 비교 비용 낮음, 원인 분리 쉬움 | 현재 부모의 지식량과 학습 분포 한계 | **지금의 기본 권장안** |
| **B. 강한 사전학습 소형 모델 계승** | 90~135M급 pretrained → 필요한 축만 pruning → 2bit/혼합 QAT·증류 복구 | 장기간 사전학습한 표현을 활용. 일반 능력의 잠재 이득 큼 | 어휘·임베딩·양자화 손상. 이론상 2bit와 실제 파일·runtime의 차이 | **일반 100M급 능력이 최우선이고 자체 from-scratch를 목적 자체로 고집하지 않을 때** |
| **C. 작은 SSM/attention hybrid** | recurrent state 중심 몸통 + 적은 attention층, 저비트·SFT | 긴 context에서 KV 증가를 줄일 가능성 | 학습·CPU kernel·배포·QAT를 함께 새로 검증해야 함 | context 증가가 A/B의 지배적 메모리 병목일 때 |

일단 A를 진행하면서 B의 메모리·품질 가능성을 작은 별도 비교로 확인하는 것이 권장이다. B가 분명히 앞서면 본류를 옮긴다. C는 A/B가 왜 실패했는지 확인한 뒤 선택해야 한다. 이번 보고서는 그 어떤 구조도 구현하거나 기본값으로 승격하지 않는다.

### 8.2 안 A — 현재 구조를 유지하는 구체적 설계

**기준 후보:** 폭 768의 d14 CLA2 무재귀와 d12 CLA2 R2. **도전 후보:** 폭 512, 24~28층, GQA·CLA2, 저랭크 임베딩, 삼진 몸통. 폭 512·28층의 자원 관측과 MobileLLM의 설계 방향을 근거로 선택한다. 실제 최종 깊이는 같은 학습비·독립 평가의 결과로 정한다. [MobileLLM](https://arxiv.org/abs/2402.14905), [P089](Z:/TinyLM/test_result/077_20260908_P089-폭을-줄이면-같은-예산에-층을-두-배-쌓고-속도-바닥도-넘는다.md)

| 부품 | 초기 제안 | 선택 이유·검증 |
|---|---|---|
| 몸통 | 독립 MLP를 기본으로 하고 강한 MLP 공유는 선택 팔 | 현재 성과를 기준으로, 공유 축을 보편 기각하지 않음 |
| 어텐션 | GQA + CLA2 | KV 예산에 직접 효과. 실제 캐시 소유·중복 사본을 확인 |
| 재귀 | 무재귀와 제한적 재귀를 비교 | 반복은 파라미터를 늘리지 않지만 KV·연산·학습 스케줄을 바꿈 |
| 임베딩 | 현재 32k·rank256·int8를 첫 기준으로 유지 | tokenizer까지 함께 바꾸는 교락을 피하고 기존 부모 활용 |
| 양자화 | 실제 배포와 동일한 scale granularity에서 복구 | group128→per-row 변환 대가를 품질 비교에 포함 |
| KV | 검증된 FP16/BF16, 총 context1024 우선 | 단순한 1byte 변경을 무료 개선으로 간주하지 않음 |
| 런타임 | 입력·출력 타일링, bounded scratch, 마지막 토큰 head | 전체 seq logits·전층 dequant 사본·큰 gather를 피크에서 제거 |

w512_d28의 현재 텐서+KV 약 31.1MiB를 기준으로 하면 40MiB까지 약 8.9MiB가 남는다. 예를 들어 작업공간 6MiB와 기타 여유 2MiB를 **목표 배분**할 수 있다. 이 예산은 이미 검증된 peak가 아니며, 현재 reference LUT가 자동으로 만족한다는 뜻도 아니다. CPU cache에 꼭 맞는다는 주장 없이 peak·품질부터 완성한다.

폭 512의 부모는 이미 준비됐으므로 그 부모를 명시적으로 쓰는 것이 필수다. 폭 768 부모를 자동 선택한 뒤 구조가 다르다는 이유로 일부만 조용히 복사하는 비교는 피한다. 부모 자체의 학습비를 무시한 “학생만의 효율”과 전체 개발 비용도 별도 기록한다.

### 8.3 안 B — 사전학습된 지능을 보존하는 경로

**가장 큰 전략 전환은 새 attention 공식을 만드는 것보다, 이미 충분히 학습된 작은 모델에서 시작하는 것이다.**

구체적인 절차 제안은 다음과 같다.

1. 90~135M급 후보 2개 이하를 원래 tokenizer·정밀도·chat template로 평가한다. 처음부터 student tokenizer로 갈아끼우지 않는다.
2. 가중치·임베딩/head·KV·runtime 비용을 분리한다. 135M 전체 2bit만도 약 32.19MiB이므로 metadata·KV·scratch를 더하면 40MiB에 쉽게 근접한다. “2bit면 무조건 충분”은 틀리다.
3. 처음에는 고정밀→4bit→2bit 순서의 진단으로 어느 부품에서 품질이 무너지는지 확인한다. 4bit 단계는 목표 충족 모델이 아니라 손상 원인 파악용이다.
4. 필요하면 75~100M 범위로 구조적 pruning을 검토하되, 우선 MLP 중간 폭 등 작은 변경부터 비교한다. 층·attention·어휘를 한꺼번에 자르지 않는다.
5. 블록별 복구 후 end-to-end quantization parameter 학습 또는 원모델 teacher를 이용한 복구를 비교한다. 마지막에 한국어 adaptation과 짧은 SFT를 평가한다. 한국어 능력을 새로 얻는 비용을 감추지 않는다.
6. 최종 배포 표현에서 외부 원모델 대비 비열등성과 40MiB peak를 함께 검증한다.

가상의 예산 예시는 **전체 가중치 90M, 평균 payload 2.2bit**일 때 약 23.60MiB, 별도 scales/index 1.5MiB, KV 4MiB, scratch 7MiB, 기타 1MiB로 약 **37.1MiB**다. 이는 임베딩을 포함한 평균 비트율을 실제로 달성한다는 가정이다. 큰 임베딩을 int8로 남기거나 attention state가 크면 곧바로 깨진다. **지원 포맷의 실제 byte 수를 세기 전에는 구현 가능 확정안으로 취급하지 않는다.**

BitDistiller는 QAT와 self-distillation을, EfficientQAT는 블록 학습과 end-to-end 양자화 파라미터 학습을 조합한다. 두 방법은 안 B의 방향을 뒷받침하지만 연구 모델 크기·GPU 조건이 TinyLM과 다르다. 특히 잘 학습된 작은 모델의 초저비트 손상이 커질 수 있다는 반대 근거도 함께 고려해야 한다. [BitDistiller](https://arxiv.org/abs/2402.10631), [EfficientQAT](https://arxiv.org/abs/2407.11062), [저비트 손상 연구](https://arxiv.org/abs/2411.17691)

**권고:** 완전히 새로운 모델을 처음부터 설계하는 것보다 이 경로의 작은 가능성 시험이 먼저다. 다만 이 보고서가 안 B의 삼진 변환 성공이나 특정 checkpoint의 40MiB 적합성을 확인한 것은 아니다.

### 8.4 안 C — SSM/attention hybrid로 바꿀 조건

권장 설계 가설은 **대부분의 시퀀스 처리를 recurrent state로 하고, 정확한 문맥 접근을 위해 적은 attention층을 남기는 60~100M급 hybrid**다. SSM 상태는 길이에 대해 고정될 수 있지만 각 층의 state 차원·conv buffer·dtype에 따라 실제 크기가 달라진다. hybrid에 남은 attention의 KV는 계속 길이에 비례한다.

초기 조건은 다음처럼 잡는다.

- 가중치·scale·임베딩 합계의 목표를 24~28MiB 이하로 설정한다.
- attention KV + recurrent state는 context1024에서 4MiB 안팎의 목표를 두고 **실제 아키텍처 식으로 검산**한다.
- 나머지 8~12MiB를 workspace·메타데이터·여유로 남긴다.
- 긴 문맥과 장거리 관계가 A/B 대비 실제로 개선되는지 검사한다. 정확한 복사·회상·드문 사실에서 state 압축 손실을 확인한다.
- Windows·4070 Ti SUPER의 학습 kernel과 Ryzen의 CPU inference 경로가 함께 가능한지 확인한 뒤 본 학습 규모를 정한다.

Falcon-H1-Tiny의 90M hybrid 공개 사례는 구조적 타당성의 직접적인 동기다. 그러나 그 가중치 파일을 작게 양자화할 수 있다는 사실과 40MiB의 전체 실행 peak·원품질 보존은 별개다. [Falcon-H1-Tiny 모델 카드](https://huggingface.co/tiiuae/Falcon-H1-Tiny-90M-Instruct), [공식 GGUF 자산](https://huggingface.co/tiiuae/Falcon-H1-Tiny-90M-Instruct-GGUF/tree/main)

**전환 조건:** context 길이를 늘릴 때 KV가 지배적이고, CLA·FP16/BF16·정상적인 제한 window 등으로 해결하면 능력을 크게 잃으며, 작은 hybrid 비교가 같은 메모리에서 더 나은 결과를 보이는 경우. context1024에서 아직 평가·SFT가 불완전한 지금 즉시 전면 재작성할 이유는 부족하다.

### 8.5 현재 본류로 권하지 않는 방향

- **일반 LLM을 TRM으로 즉시 교체:** 퍼즐용 구조의 성과가 언어·지식 표현의 대체 근거는 아니다. 필요하면 별도 문제 해결 모듈로 검토한다.
- **MoE를 ‘active parameter가 작으므로 40MiB’라고 평가:** 전체 expert·router·캐시가 상주하면 총량에 포함해야 한다. SSD streaming은 다른 지연·I/O 계약이다.
- **외부 RAG·계산 도구를 모델 내재 지능 점수로 합산:** 제품 요구상 유용할 수 있으나 모델 자체 능력과 시스템 능력을 나누어 보고한다.
- **Adam-mini 등 optimizer-state 절감을 곧바로 배포 축소로 주장:** training memory 개선이지 inference weight/KV 감소가 아니다.
- **trajectory 없이 미래 gradient 예측기로 step을 대체:** 독립 run·단순 예측 기준선·실제 loss 개선 검증이 선결이다. 현재 moonshot의 보류 판단을 유지한다.

## 9. 현 장비에서의 자원 설계

### 9.1 학습과 배포 예산을 분리한다

40MiB는 배포 목표다. 학습 중 FP32 master·gradient·optimizer state·activation을 쓰는 것은 목표 위반이 아니다. 반대로 학습 모델이 100M으로 작다고 해서 seq·어휘·teacher를 포함한 VRAM이 자동으로 안전한 것도 아니다.

| 상황 | 권장 자원 운영 | 근거·제약 |
|---|---|---|
| 현재 TinyLM 학습/SFT | 우선 기존 성공 형상을 사용하고 새로운 seq·batch는 작은 자원 확인 후 확대 | 최신 로그의 reserved 약 8.08~9.63GB는 특정 조건의 기록. 다른 조합에 자동 전이 금지 |
| 오프라인 텍스트 teacher | 대략 0.3~1.5B급의 실제 과제 성능을 먼저 확인하고 순차 생성 | 학생 학습과 동시에 두지 않아 VRAM·원인 분리를 단순화 |
| 0.6B BF16 teacher | 가중치 payload 약 1.12GiB라는 산술만 참고 | activations·logits·KV·runtime은 별도. 실제 총량은 미실측 |
| 1.5B BF16 teacher | 가중치 payload 약 2.79GiB. 생성 길이·batch를 제한 | 13~14GB 안에 항상 들어간다는 보장은 없음 |
| 7B BF16 teacher | 가중치 payload만 약 13.04GiB | 사용자가 보고한 가용 VRAM상 학생과 동시 실행은 부적절. 필수 teacher로 지정하지 않음 |
| 큰 어휘의 logit KD | teacher/student를 작은 microbatch·chunk로 처리 | weight보다 어휘×토큰 텐서가 OOM 원인이 될 수 있음 |
| 데이터·캐시 | 필요한 shard만 읽고 압축·memory map 방식 검토 | 가용 RAM 하한 32GB를 기준으로 하고 전체 대형 corpus를 RAM에 적재하지 않음 |

사용자 경험의 15GB 경계에 근접하도록 설정하는 대신 초기 실험은 더 낮은 peak를 겨냥하고, 시스템 여유를 관측해야 한다. 위 표의 GB는 로그의 표기를 보존했고, 계산값은 GiB로 구분했다. 모델 로드·학습·생성 피크가 서로 다르므로 `allocated`, `reserved`, 장치 전체 사용량을 같은 수로 취급하지 않는다.

### 9.2 증류 캐시의 현실적 비용

산술 예시로 10M 학습 위치마다 top-32의 token ID(int32)와 logit(fp16)를 저장하면 **약 1.92GB**, top-64이면 **약 3.84GB**다. 추가 metadata·tail mass·파일 인덱스는 별도다. 300M 위치의 top-32는 약 57.6GB이므로 가용 RAM 전체보다 크다. 전체 어휘 32,768개를 FP16으로 10M 위치에 저장하면 **약 655GB**여서 처음부터 전량 저장할 이유가 적다.

top-k는 full distribution KD와 같은 목적함수가 아니다. 누락된 확률질량·재정규화·temperature를 어떻게 처리하는지 명시하고 비교해야 한다. tokenizer가 다르면 ID 캐시는 직접 공유되지 않는다. 따라서 **초기 단계는 텍스트 응답 캐시, 필요가 증명된 후 짧고 선택된 위치의 logits 캐시**가 권장이다.

### 9.3 토큰·시간 격차를 보는 법

SmolLM2-135M의 2T 토큰과 현재 학생 단계의 300M은 단순 비율로 약 6,667배다. 이것은 모델 간 총 학습 효율 비교가 아니라 **개별 학생 단계와 공개 사전학습 규모의 차이를 보여주는 참고 산술**이다. TinyLM 부모 노출·반복·언어 구성·tokenizer가 달라 정확한 지식 격차로 해석할 수 없다. [SmolLM2-135M 카드](https://huggingface.co/HuggingFaceTB/SmolLM2-135M)

최근 300M 로그의 약 69~110분을 선형 환산하면 10B 토큰은 대략 38~61시간, 100B는 약 16~25.5일이다. **이는 동일 형상·처리율이 유지되고 교사 생성·추가 평가·오류 복구가 없다는 가정의 산술**이지 실행 시간 약속이 아니다. 수조 토큰 from-scratch 경쟁을 단일 장비의 단기 계획으로 세우기보다는, 계승·큐레이션·선택적 반복·SFT로 필요한 학습 신호를 압축하는 것이 타당하다.

‘적은 데이터’의 주장은 unique source와 token으로, ‘적은 step’의 주장은 batch와 함께, ‘학습 효율’의 주장은 교사 생성·검증·학생 학습을 합한 시간/FLOPs로 평가해야 한다. 셋 중 하나만 좋아졌는데 모두 좋아졌다고 표현하지 않는다.

## 10. 권장 연구 순서와 판정 기준

아래는 기존 P083→P082 및 P090 등에 연결할 **검토안**이다. 새 master plan으로 기존 결정을 덮어쓰지 않는다. P069/P085의 기존 결과·도구를 재사용하고, 결과가 없는 경계만 채운다. 이번에 큐·기본값·실험계획 파일을 바꾸지 않았고, 실행 중인 사용자의 작업에 개입하지 않았다.

### 10.1 단계별 의사결정

1A와 1B는 독립적으로 준비할 수 있다. 이를 이유로 GPU 병렬 실행을 전제하지 않는다. 기존 P089 부모와 P086 결과를 반영하면 **부모 재학습과 같은 벡터 LRM 팔의 단순 재실행은 우선순위가 낮다**. 새 형상·WD·평가 근거가 생기지 않는 한 이미 얻은 증거를 사용한다.

### 10.2 가장 작은 유익한 SFT 비교

**초판 설계의 한계 정정:** 아래 4팔만으로는 “SFT 효과”와 “교사가 추가한 감독의 효과”를 완전히 분리할 수 없다. P082는 이미 더 적절한 `P82_N_REF`(교사 없이 같은 정답/참조로 SFT), `P82_N_CE_TOK`/`P82_N_CE_GPU` 및 Qwen/Gemma QA·이유 팔을 설계했다. 아래 표는 파이프라인 pilot의 축약 표현이며, 교사 효과를 주장하는 정식 실험에서는 P082의 대조군을 생략하면 안 된다. 아래 CLM 대조는 초판의 `C0`를 명확하게 다시 표기한 것으로, P082의 C0 screen과 구분한다.

| 팔 | 학습 | 답하려는 질문 |
|---|---|---|
| B0 | 현재 checkpoint 그대로 | 학습 전의 능력과 생성 실패는 무엇인가? |
| CLM 대조 | 같은 추가 연산 규모의 기존 CLM 계속학습 | 추가 업데이트 자체의 효과인가? |
| S1 | 검증된 정답 중심 assistant-only SFT | 질문 응답 목적에 맞춘 감독이 이득인가? |
| S2 | 같은 질문 분포의 정답 + 짧은 검증된 이유 | 이유 감독이 동일 예산에서 추가 이득인가? |

먼저 한 시드의 작은 pilot으로 형상·학습 신호를 확인하고, 선택된 두 학습 팔을 여러 시드로 확장한다. 처음부터 교사 크기×KL×폭×데이터를 모두 조합하는 거대 격자를 만들지 않는다. S1과 S2는 이유 길이로 노출량이 달라지므로 **동일 총 입력 토큰 예산 비교**와 **동일 질문 수 비교**를 구분해 해석한다. 양쪽을 동시에 완벽히 같게 만들 수 없으면 무엇을 고정했는지 명시한다.

Fresh/Bridge 비교가 필요하면 S1의 source 축만 바꾼 별도 비교로 둔다. Bridge는 실제 train 출처만, Fresh는 정해진 Stage corpus와 분리된 출처만 사용한다. ‘외부 교사가 사전학습에서 본 적 없음’까지 보장하는 것으로 표현하지 않는다.

### 10.3 성공·중단 기준 제안

- **학습 경로 성공:** prompt·padding의 target loss가 의도대로 제외되고 EOS와 응답 토큰이 실제 loss에 들어가며, source와 target 수가 맞는다. 파일이 존재하거나 tensor가 변했다는 것만으로 완료하지 않는다.
- **품질 성공:** 독립 dev에서 효과가 나고 최종 잠금 테스트에서 방향과 실용적 크기가 유지된다. 정확도·margin·생성 결과를 함께 보고한다.
- **망각 제한:** 한국어·영어 bpb와 쉬운 생성의 퇴보 허용폭을 사전등록한다. 기존의 “CE +0.05 이내”도 분포가 다른 평가로 옮길 때 새로 정당화해야 한다.
- **양자화 성공:** float checkpoint의 품질이 아니라 실제 packed artifact의 품질로 판정한다. 최종 저장 표현이 달라지면 gate를 다시 통과해야 한다.
- **방법 확대 중단:** 합리적으로 설정한 소규모 비교 두세 번에서 계속 SFT/CE 대조군을 못 넘으면 해당 세부 방법의 우선순위를 내린다. 이 횟수는 연구 운영 제안이며 보편 통계 법칙이 아니다.
- **큰 방향 전환:** 같은 메모리 계약에서 pretrained 계승안이 현재 구조보다 일관되게 좋고, 한국어 adaptation 비용까지 감당 가능하면 안 B를 본류로 검토한다.
- **속도 해석:** 15tok/s 미만이라는 이유만으로 지능 연구축을 닫지 않는다. 최종 제품의 대기시간·사용성 요구와 연구 우선순위를 구분한다. 최신 사용자 우선순위는 ①상주 ②지능 ③속도다. [기준표 B.23.1](Z:/TinyLM/docs/EXPERIMENT_BASELINES.md)

### 10.4 평가 자산을 보호하면서 개선하는 방법

v2.7은 이미 많은 연구 결정에서 결과를 확인했으므로 반복해서 사용하면 최종 blind test 역할이 약해진다. 계속 진단용으로 쓸 수는 있지만 최종 외부 주장을 위해서는 별도 잠금 평가가 바람직하다. v2.8도 생성됐다는 이유만으로 즉시 그 역할을 부여해서는 안 된다.

v2.8은 4,500행이지만 공통 생성 틀이 많다면 유효 독립 표본수는 훨씬 작을 수 있다. 감사 시 행 수 외에 source·template·논리 구조 가족 수를 본다. 문항을 늘려도 같은 shortcut을 복제하면 검정력과 타당성이 함께 좋아지지 않는다.

`ctx/choices/gold` 등 새 schema와 기존 `prompt/candidates/correct_index` 계열의 대응도 확인 대상이다. 평가는 정답 index 범위, 후보 개수·배타성, 언어와 tokenizer 길이, 선택지 순서 재배치, 쉬운 기준선, 중복·가족 누설을 점검한다. **현재 보고서 작성은 그 감사의 실행이나 통과를 의미하지 않는다.** [v2.8 상태](Z:/TinyLM/datasets/TinyDataset/stage1_dataset/held-out_v2.8/v2.8_design_generation_audit_report.md)

## 11. 최종 권고와 남은 불확실성

**가장 권장하는 방향은 이미 계획된 ‘정의된 메모리 안에서 검증된 학습 신호로 능력을 확보하는 연구’를 끝까지 연결하는 것이다.** P069/P085는 이미 평가를 확장했고 P082/P083은 증류·배포의 핵심 통제를 설계했다. 현재 구조를 전면 폐기하거나 같은 계획을 다시 만드는 것보다, 남은 실행 증거와 해석의 정확도를 보완할 이유가 더 강하다.

현재 프로젝트는 메모리 회계 오류와 KD의 실효성을 실험으로 재검토하고, 잘못된 측정도 후속 단계에서 복구해 왔다. 일부 문서의 “RSS 축 종결”, “SFT는 새 지식을 못 가르침”, “CE가 좋으니 지식은 있음” 같은 넓은 해석에는 여전히 주의가 필요하다. **반면 생성 평가 금지처럼 이미 철회한 방침이나, 사용자 지시로 보존된 옛 리뷰의 본문을 현재의 잘못으로 재지적하면 안 된다.** 이 구분을 놓친 초판의 서술을 정정한다.

우선 투자할 세 가지는 다음과 같다.

1. **동일 실행 경로의 40MiB와 외부 능력 비교를 연결한다.** 메모리 측정 자체가 부족한 후보를 성급히 승격하지 않는다.
2. **짧고 정답이 확인된 교사 응답과 학생 오류 교정에 투자한다.** 가장 큰 교사·가장 복잡한 KD부터 시작하지 않는다.
3. **사전학습 소형 모델의 계승·저비트 복구를 진지한 대조 경로로 둔다.** 일반 100M급 능력이 목표라면, 수조 토큰의 선행 학습 자산을 활용할 기회를 배제할 이유가 없다.

아키텍처를 완전히 새로 만들 정당성은 **현재 구조가 적절한 데이터·학습·평가에서도 같은 메모리의 대안보다 지속적으로 열세**일 때 강해진다. 지금 확인한 근거는 “삼진 Transformer 전체가 틀렸다”보다 “무엇을 측정하고 어디에 학습비를 쓰는지 고쳐야 한다”를 지지한다.

남아 있는 핵심 불확실성은 실제 native/packed peak, w512 최종 품질, block 재귀 전체 결과, 독립 benchmark에서의 지능 차이, 새 SFT의 실제 효과, pretrained 90~135M 모델을 목표 예산까지 줄일 때의 손상이다. **이 중 어느 것도 이번 읽기 전용 조사로 실험적으로 해결됐다고 주장하지 않는다.**

## 13. 추가 자료 대조에 따른 정정과 실험 타당성 감사

### 13.1 사용자 지적에 대한 직접 답변: 무엇을 누락했고 무엇이 실제 문제인가

**P069·P082를 충분히 확인하지 못한 것이 초판의 주된 문제였다.** 이 두 문서의 제안이 잘못되어 의도적으로 배제한 것이 아니다. P069는 후속 실측까지 있고, P082는 초판의 여러 권고보다 더 세밀한 통제 설계를 이미 갖고 있다. 반면 문서·결과·코드까지 대조하니, 별도로 정정해야 할 인과 해석과 측정 범위의 문제도 발견됐다. 다음 표에서 책임과 상태를 분리한다.

### 13.2 목록·방법론·리뷰를 어떻게 대조했는가

#### 13.2.1 상태 판단의 기준

[실험계획 목록](Z:/TinyLM/test_plan/실험계획목록.md)과 [실험결과 목록](Z:/TinyLM/test_result/실험목록.md)은 **추적의 출발점**으로 사용했다. 제목의 “완료/실패/종결”만으로 판단하지 않고, 관련 결과문서의 뒤쪽 후속 단계와 최신 리뷰를 우선했다. 한 문서가 초기 실패와 여러 차례 복구를 함께 포함하기 때문이다. 예를 들어 결과 042의 제목은 A1만 유효했던 초기 상태지만 §11~12에는 유효한 감사와 α 실험이 있고, 결과 053의 초반은 배관 프로브지만 §11~12에는 Gemma full 품질 결과가 있다.

P069 계획의 옛 “설계” 상태, P082 앞부분의 Gemma “full 품질 미실행”, 일부 methods의 “미측정” 표현은 뒤의 결과와 시차가 있다. 이것은 **현재 결과가 없다는 증거가 아니다.** 반대로 P082의 자세한 gate와 배치 명세만으로 실행됐다고 판정하지 않았다. §15는 코드 구현·데이터 생성·시험·교사 평가·학습 실행을 수행하지 않았다고 명시한다. 실행 증거가 생기면 그 범위별로 갱신해야 한다.

### 13.4 기존 문서에 남아 있는 해석·설계 문제의 상세 근거

#### 13.4.1 P082의 “100M 토큰에서 KD −0.110”은 KD 단독 효과가 아니다

[P007 결과 006 §1](Z:/TinyLM/test_result/006_20260730114800_P007-토큰스윕-클린판.md)의 원 표는 다음과 같다. 낮을수록 좋은 val loss다.

| 학생 학습 예산 | dense `p6d` | plain tied `p6t` | 부모초기화+full KD tied `p6tk` | `p6tk−p6d` |
|---|---:|---:|---:|---:|
| 100M | 4.3650 | 4.5136 | 4.2550 | **−0.1100** |
| 300M | 3.7045 | 3.8727 | 3.7661 | +0.0616 |
| 600M | 3.5197 | 3.6853 | 3.6180 | +0.0983 |

100M의 −0.110은 **구조·초기화·KD를 함께 바꾼 학생과 dense의 차이**다. 같은 tied 구조에서 `p6tk−p6t=−0.2586`을 구해도 부모초기화와 KD가 여전히 함께 달라지므로 KD 단독 효과가 아니다. 원문에는 EMA 조건도 있어 checkpoint 선택 규약까지 확인해야 한다. 따라서 적절한 문장은 **“100M 학생 예산에서 부모초기화+KD를 포함한 압축 경로가 dense 기준보다 낮은 loss를 기록했다”**다. “100M이면 KD가 효과적임이 확인됐다”로 줄이면 인과 귀속이 바뀐다.

시간 역시 dense 40.0분과 KD 학생 56.7분이다. 부모를 새로 마련해야 하는 경로라면 선행 학습 비용이 추가되므로 같은 100M 학생 토큰만으로 총 학습효율 우위를 입증하지 못한다. 부모를 이미 보유한 증분 비용 비교는 가능하지만, 그 경우에도 비용 장부를 별도로 써야 한다.

P050/P055는 **다른 조건의 300M 비교에서** 부모초기화와 KD를 분리했다. 이것이 100M의 순수 KD 이득을 소급 입증하지는 않는다. P082의 N0 통제와 비용 대조는 옳은 방향이며, 계획 전체를 폐기할 이유가 아니다. 새로운 100M init-only 팔은 그 작은 예산 구간의 인과 질문이 실제 의사결정에 필요할 때만 검토하면 된다.

#### 13.4.2 P055는 이미 제대로 보완됐지만 “실효 α”에는 적용 범위가 있다

실제 체크포인트로 교정한 Stage0c에서 `‖∇CE‖=0.012595`, `‖∇KL‖=0.005086`, 비율 약 0.404를 보고했다. 이는 초기의 거의 균일한 합성분포 감사보다 유효한 증거다. 이어 α=0/0.1/0.3/0.5/0.7의 val은 **3.6776/3.6776/3.6856/3.6984/3.7156**으로, 이 조건에서 KD를 기본에서 뺀 판단은 뒷받침된다. “α를 안 맞춰서 KD가 실패했을 것”이라고 다시 제안할 근거가 부족하다. [P055 결과 §11~12](Z:/TinyLM/test_result/042_20260813_P055-단계0-KD감사-A1만-유효하다.md)

다만 `a·r/((1−a)+a·r)`은 두 gradient **norm을 이용한 비중 지표**다. 두 벡터의 방향·상쇄·optimizer 변환을 포함한 실제 update의 인과 기여율은 아니다. 특정 체크포인트·crop에서 구한 r을 모든 학습 step·다른 교사에 일정하게 적용할 수 없다. 또한 문서의 α=0.7 행은 같은 식과 r=0.404를 쓰면 약 **0.485**인데 0.404로 적혀 있다. 이는 파생 표의 산술 오류이며, 원 val 측정이나 KD 제거 결론을 뒤집지는 않는다. 기존 로그의 `kd_alpha` metadata 누락은 문서가 이미 지적했고 실행 인자로 적용 여부를 확인했으므로, 이를 α가 전혀 적용되지 않았다는 뜻으로 읽으면 안 된다.

#### 13.4.3 P067 Gemma full은 이미 완료됐고, KD의 서열은 도메인에 따라 바뀌었다

| 비교 조건 | Gemma KD 학생 | 같은 Gemma tokenizer의 no-KD 학생 | 허용되는 결론 |
|---|---:|---:|---|
| 학습 로그의 같은-cache val | 3.70938 | 3.70172 | 이 단일 시드·분포에서는 no-KD가 0.00766 낮음 |
| 공통 영문 SQuAD 원문 bpb | 1.3087 | 1.3199 | 이 원문 혼합에서는 KD가 0.0112 낮음 |
| full-run 최대 gradient 기록 | 1.687 | 1.179 | 250-step probe의 큰 값은 해당 full에서 재현되지 않음 |
| 학습 시간 | 553.0분 | 400.3분 | KD의 추가 학습비가 실제 발생 |

근거는 [결과 053 §11~12](Z:/TinyLM/test_result/053_20260822_P067-단계0a-두-최신-소형모델은-KV를-버리고-있다.md)다. **P082 앞부분의 “Gemma full 품질 미실행” 및 probe gate 실패를 현재 전체 상태로 읽는 것은 잘못이다.** 뒤의 결과를 우선해야 한다. 단, 이 표는 P067의 완료 증거이며 P082 신규 트랙이 수행됐다는 뜻은 아니다.

두 가지 일반화를 모두 피해야 한다. 첫째, in-domain no-KD 승리만으로 “Gemma 교사도 쓸모없다”를 확정할 수 없다. 둘째, 영문 bpb 역전만으로 “KD가 영어 일반지능을 이식했다”를 확정할 수 없다. 평가 원문·도메인·오염 및 단일 시드 조건이 남아 있고, downstream QA 개선은 이 표에서 직접 측정하지 않았다. 다른 구조에서 얻은 0.0006 또는 bpb 0.008의 자를 빌려 “12.8배 유의”, “0.0002 차이는 동급”이라고 확정하는 것도 피해야 한다. **차이를 검출하지 못한 것과 사전 허용폭 안의 동등성 입증은 다르다.** P052/P088이 아키텍처별 자를 연구한 이유와도 맞닿는다.

하드웨어 관점에서도 KD full의 reserved 14.77GB는 성공 기록이지만 현재 사용자가 제시한 가용 13~14GB를 넘을 수 있다. 과거 한 번 완주했으므로 지금 같은 형상도 안전하다고 가정하지 않는다. 이미 실행된 무거운 런을 초기 상태 오독 때문에 다시 반복할 필요는 없으며, 향후 계획은 실제 가용량과 형상을 다시 맞춰야 한다.

#### 13.4.4 공통 bpb의 오염은 자동으로 상쇄되지 않는다

결과 053 §12.3은 SQuAD 4,000문서 중 348문서의 겹침을 제외하려던 `--drop-contaminated`가 작동하지 않았음을 **이미 명시**했다. 이번에 [현재 코드](Z:/TinyLM/scripts/common_bpb.py:89)를 읽어도 인자 선언·경고만 있고, 이 옵션을 소비해 문서 집합을 거르는 경로는 확인되지 않는다. 따라서 해당 옵션을 줬다는 로그만으로 깨끗한 평가가 됐다고 인정할 수 없다.

한편 문서가 “우리 모델끼리는 공통 상수”라고 해석한 부분은 충분히 뒷받침되지 않는다. 같은 평가 문서를 써도 모델의 용량·깊이·시드·노출·KD에 따라 암기 이득이 다를 수 있기 때문이다. 손실 가중치 기준 오염 비중을 w라 하면 관측 차이는 개념적으로 `Δobs=(1−w)Δclean+wΔoverlap`이다. **두 모델이 같은 문서를 쓴다는 사실은 Δoverlap=0 또는 Δoverlap=Δclean을 보장하지 않는다.** 여기서 w는 손실 집계의 token/byte 가중치에 맞는 값이며, 문서 수 비율 348/4000을 그대로 대입하면 안 된다.

현재 bpb는 **그 고정된 원문 혼합에 대한 기술 통계**로 보존할 수 있다. 깨끗한 일반화 우위, 외부 모델 대비 능력, 작은 차이의 확정 승격 근거로 쓰려면 중복 제외 목록과 원문별 결과가 필요하다. 제외 후 점수가 얼마나 바뀔지는 이번 읽기만으로 알 수 없다. 전체 과거 학습을 다시 하자는 결론도 아니다. 우선순위는 최종 후보의 평가 원문·집계 규약을 신뢰할 수 있게 만드는 데 있다.

#### 13.4.5 P069/P085는 유효한 진전이지만 공식 점수·통계·해석을 분리해야 한다

**이미 한 일.** [P069/결과 056](Z:/TinyLM/test_result/056_20260823_P069-벤치13종-hellaswag와-piqa만-살아있다.md)은 13종 벤치와 여러 모델 블록을 실행해 무작위 수준·퇴화·지표 불일치를 실제로 확인했다. [P085/결과 074](Z:/TinyLM/test_result/074_20260904_P085-정답CE는-9쌍-전부-맞고-정확도는-끝까지-못-가른다.md)는 HellaSwag n=5,000 설정, PIQA 가용 전량 1,838, ARC 확대, KoBEST, held-out v2.7 및 두 시드까지 발전했다. 초판이 이를 “평가가 빈약하므로 시작해야 한다”는 인상으로 표현한 것은 부정확했다.

**공식 지표와의 차이.** [현재 MC 구현](Z:/TinyLM/scripts/eval_bench_suite.py:364)의 `acc`는 기본적으로 후보 **평균 token CE에서 무문맥 평균 CE를 뺀 점수**의 순위다. `acc_norm`은 합 CE/token 수로, PMI를 끄면 두 지표가 실질적으로 같은 평균 token CE 순위를 사용한다. 반면 확인한 LM Evaluation Harness 공식 정의는 일반 `acc`=후보 전체 log-likelihood 순위, `acc_norm`=문자 길이 정규화 순위이며 mutual-information 지표를 따로 구분한다. 따라서 로컬 지표의 이름만 보고 공식 `acc`/`acc_norm`과 같은 것으로 비교하면 안 된다. 이는 PMI를 쓴 내부 비교가 무효라는 뜻이 아니라 **무엇을 측정했는지 이름·규약을 정확히 붙여야 한다는 뜻**이다. [Harness 공식 metrics](https://lm-evaluation-harness.readthedocs.io/api/metrics/)

**부분 생성 평가.** 로컬 IFEval은 구현한 8개 유형만 검사하고 미구현 조건은 평가에서 빠진다. 이를 논문의 전체 prompt/instruction strict·loose 점수로 대체할 수 없다. HumanEval의 parse 비율 역시 코드의 문법적 파싱 가능성을 보는 값으로 `pass@1`이 아니다. MuSR은 거의 모든 문항이 길이 제한으로 제외된 뒤 남은 극소수의 100%를 결과문서가 이미 무효라고 표시했다. 이들을 숨겨진 성공 조작처럼 지적할 이유는 없지만, methods나 요약에서 “공식 벤치 가능/통과”로 압축하면 분모·정의가 사라진다. [로컬 구현](Z:/TinyLM/scripts/eval_bench_suite.py), [IFEval 원 논문](https://arxiv.org/abs/2311.07911)

**ARC 확대와 오염 감사 범위.** `arc_easy_full` 5,197은 train 2,251+test 2,376+validation 570을 합친 내부 진단 집합이다. 정식 test 점수와 직접 동일시할 수 없다. 기록된 오염 표본 400개 중 유효 감사는 308개이고, 짧은 92개는 해당 n-gram 감사에서 제외됐다. 따라서 “검사한 308개에서 hit 0”은 유효하지만 **전체 5,197개가 깨끗함을 증명하지 않는다.** 긴 n-gram으로 판정하지 못하는 짧은 문항은 별도 exact/짧은 문자열·출처 검사가 필요할 수 있다. 이를 이유로 ARC 결과를 전부 폐기하지 않고, 감사 범위를 명시해 진단용으로 보존하는 것이 합리적이다.

**정확도가 끝까지 못 가른다는 초기 제목은 후속 결과와 다르다.** Stage1c의 ARC full에서 d12−mC는 +1.46pp, McNemar z=2.20이고 d16−mC는 +1.44pp, z=2.09다. 특정 비교에서는 명목 유의 수준의 차이가 관측됐다. 다만 여러 모델·과제·후속 선택을 거친 경계적 수치이므로 다중비교 조정·독립 확인 없이 확정적 승자로 부르지는 않는다. d12와 d16을 못 갈랐다는 것은 두 모델이 모든 능력에서 동등하다는 뜻도 아니다.

**한국어 능력 부재라는 일반화도 제한해야 한다.** KoBEST-COPA 1,000에서 52.1%와 우연 50%를 유의하게 구분하지 못한 것은 이 과제·규약의 결론이다. 한국어 인과 능력이 전혀 없다는 증명은 아니다. KoBEST-HellaSwag의 43.6/42.4/44.0%를 다른 논문의 F1 또는 다른 설정과 나눠 “큰 모델 능력의 몇 %”로 환산하는 것도 타당하지 않다. 정확도는 선형적인 지능 단위가 아니다.

**시드 pooled 분석은 탐색 근거로 낮춰 읽는다.** Stage7에서 d12−d16은 seed1에서 +10.67pp, seed2에서 +3.33pp로 방향은 유지됐지만 크기가 달랐다. 같은 300문항을 두 시드에서 평가한 discordant 수 102/60을 단순 합친 z=3.30은 문항 반복의 의존성을 처리하지 않는다. 방향 재현은 남기되, “시드가 원인이 아님을 확정”이라고 쓰기에는 근거가 부족하다. P082가 이미 정한 시드/문항 계층적 분석과 최종 잠금 평가가 적합한 보완이다.

**margin과 calibration의 의미.** `gold_margin=평균 오답 score−정답 score`는 공통 유창성 효과를 줄이는 유용한 보조 지표다. 그러나 양수라도 정답이 1위라는 뜻은 아니다. 예를 들어 정답 score=0, 오답 score=−1과 +3이면 평균 margin은 +1이지만 −1의 오답이 선택된다. 정확도의 직접 경계는 `최선 오답 score−정답 score`의 부호다. 따라서 평균 margin을 그대로 “정오의 연속판”이라고 부르기보다 평균 오답 대비 선호도로 해석해야 한다. 6개 체크포인트의 높은 순위 상관은 탐색 근거이며 독립 타당성 입증은 아니다. 또한 정답·오답 CE가 모두 낮아졌다고 calibration이 좋아졌다고 말할 수 없다. 그 주장이 필요하다면 선택지 확률 정의를 고정하고 신뢰도-정답률 관계 또는 Brier 등 별도 지표가 필요하다. 새로운 지표를 모두 주지표로 늘리기보다, 현재 주장에 필요한 부분만 추가하는 것이 좋다.

#### 13.4.6 P082는 좋은 계획이지만 상태·비용·판정 기준의 내부 정합성을 정리해야 한다

P082에서 **그대로 살릴 부분**은 분명하다. 교사 우위 선결, native와 HF tokenizer 경로 분리, 공식 교사 template, gold/reference 대조, 동일 accepted intersection, 토큰/총 GPU-hour 장부, 검증된 짧은 이유, 조건부 cross-tokenizer, 3시드·계층적 CI·다중비교가 이미 있다. 특히 §4.3의 `P82_N_REF`는 초판의 단순 SFT pilot보다 인과 분리가 좋다. [P082 계획](Z:/TinyLM/test_plan/P082_Qwen-Gemma-교사-지능향상-KD-후속실험.md)

다만 다음은 실행 전에 문서상 정리할 가치가 있다. 이번 보고서는 원 계획을 수정하지 않는다.

1. **Gemma 상태:** §2의 probe 실패·full 미실행은 결과 053 §11~12 및 계획 뒤의 도메인 부록과 맞지 않는다. 이미 완료된 P067 full 결과를 gate 판단의 입력으로 써야 한다. 과거 불안정 수치를 현재 전체 실패 원인으로 고정하지 않는다.
2. **비용 가지별 합계:** 상단은 C0를 screen으로 옮겨 191~280→약 52 GPU-hour로 준다고 하지만 §11.1에는 full core 약 139~160 GPU-hour 및 전체 191~280이 남아 있다. **조기 탈락 시 절약**과 **모든 gate 통과 시 총비용**은 다르다. C0의 위치를 앞당기는 것만으로 전량 수행 비용이 52가 되지는 않는다. 변경 후 실제 남기는 팔·시드 수와 중단/통과 시나리오별 누적 비용이 필요하다. 이는 비용 계획의 불일치이며, 이미 280시간을 잘못 소비했다는 주장이 아니다.
3. **최종 기준:** 부록 G.2는 “§3.4가 우리 val 하나를 본다”고 적지만 §3.4는 downstream 종합 개선과 통계 조건을 이미 포함한다. 부록의 새로운 도메인 질문은 유용하나 본문의 기존 주지표를 잘못 요약한 부분은 정정해야 한다. Q6 번호도 기존 짧은 rationale 질문과 중복되므로 참조 혼선을 줄일 필요가 있다.
4. **100M 근거:** −0.110은 §13.4.1처럼 복합 경로의 효과로 표기한다. 이 값으로 낮은 예산 KD의 순수 이득이나 같은 compute의 우위를 사전 확정하지 않는다.

**결론적으로 P082는 새로 대체할 계획이 아니라, 기존 결과와 비용표를 정합시켜 활용할 계획이다.** native-tokenizer 텍스트 증류를 먼저 작게 확인하자는 본 보고서의 선호는 P082 트랙 B에 이미 포함된 경로의 우선순위 제안이다. 기존 승인된 Stage 순서를 바꾸려면 변경 범위를 별도로 명시해야 하며, 이 보고서가 이를 실행한 것은 아니다.

### 13.5 재검토 후 연구 우선순위: 중복을 줄이고 결정에 필요한 증거에 집중

| 순위 | 기존 연구와의 연결 | 추가로 필요한 최소 증거 | 반복하지 않을 것 |
|---|---|---|---|

**가장 성공 가능성이 높은 방법에 대한 권고는 유지하되 근거를 수정한다.** 검증된 답/짧은 이유의 SFT와 오류 교정은 작은 지시이행·관계 과제에서 비용 대비 유망하다. **이미 P082/P090에 구체적 설계와 데이터 준비가 있고, 아직 학생 효과를 확인하는 연결 단계가 남았기 때문**이다. 실제 성공률 수치나 광범위한 100M 지능 달성은 미확정이다. 새 감독의 효과가 `N_REF`·CLM 대조를 넘는지, 교사 추가 효과 `N_QA−N_REF`가 있는지를 구분해 주장해야 한다. 이 차이만으로 순수한 새 지식 획득과 출력 형식 적응까지 완전히 분리됐다고 주장하지 않는다.

40MiB가 가장 중요한 만큼 교사의 큰 어휘를 학생에게 복제하는 logit KD보다 native 32k 텍스트 감독이 배포 예산에 유리할 수 있다. 이는 성능 우월성의 확정이 아니라 메모리·구현·실패 원인 수가 적다는 공학적 이유다. 기존 Qwen/Gemma full 결과는 버리지 않고, 어떤 도메인·목적에서 감독이 도움이 되는지를 설계하는 근거로 활용한다. 부모초기화의 강한 이득과 KD 제거의 현재 표준도 유지한다.

새 문헌을 보더라도 기존 계획을 건너뛸 근거는 부족하다. **GSQ**는 그룹별 양자화·최적화의 최신 PTQ 근거지만, 원 논문의 대형 모델 결과가 TinyLM의 native 삼진 QAT/5-trit LUT와 같은 경로는 아니다. 이미 `08_paper_review2`에서 검토한 축이므로 “새로운 지능이식 방법”으로 다시 제안하지 않는다. **QK normalization**도 유효한 연구 후보지만 원 근거가 저자원 번역이고, TinyLM의 안정성 결함을 직접 입증하지는 않는다. P005b의 Muon 레시피 정합 이후 독립적인 후속 팔로 다루는 것이 해석에 유리하다. ### 13.6 최종 재판정과 이번 감사의 한계

**현재 아키텍처나 연구 방향 전체가 잘못됐다는 결론은 지지되지 않는다.** 평가 확대·부모초기화 분리·KD 감사·재귀 스케줄 복구·데이터 누설 진단 등은 이미 수행됐고, 증류·구동기 계획도 상당히 정교하다. 따라서 초판의 “방향 전환” 표현보다 **“이미 수정된 방향의 미완료 검증을 연결하고, 인과 귀속과 평가 범위를 엄밀하게 유지한다”**가 더 정확한 권고다.

가장 중요한 남은 문제는 (a) 일부 요약·계획 상태의 갱신 시차, (b) 100M KD 효과의 잘못된 단독 귀속, (c) 오염이 자동 상쇄된다는 해석, (d) 로컬 대리 지표와 공식 벤치 점수의 혼용 위험, (e) 시드·동등성·margin의 과대해석, (f) P082 비용표 및 P083과 최신 메모리 계약의 연결이다. 이들은 이미 복구된 실행 오류와 구별해야 한다.

이번 감사는 기존 문서·코드·로그를 읽은 결과다. 모든 데이터의 정답성, 모든 과거 명령의 실제 환경, 통계량의 원 item 재계산, packed 경로의 실제 peak를 독립 검증한 것은 아니다. 결과문서의 최신 단계까지 추적한 주요 사례는 위 표에 남겼으며, 추적하지 않은 실험까지 이상 없음으로 인증하지 않는다. 원 계획·결과·코드의 수정과 실험 재실행은 하지 않았고, **사용자가 지정한 이 Markdown 보고서 한 파일만 증보했다.**
