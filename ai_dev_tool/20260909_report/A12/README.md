# A12 — residual 차단과 실제 KV 공급자 삭제의 분리

우선순위: **조건부** · 산출물 상태: **실험개선안 문서, 코드 생성 대상 아님**

근거: [보고서 v2의 A12](../20260909_TinyLM_40MiB_연구타당성_및_실행조치_보고서_v2.md). 원본 코드·데이터·checkpoint 및 기존 보고서는 이 작업에서 수정하지 않았다.

이 폴더에는 실험개선안만 둔다. 지금 필요한 조치가 코드 변경이 아니므로 replacement/original 폴더를 생성하지 않는다.

이 항목은 **해석·실험개선안만** 제공한다. U2 residual gate 실험은 해당 잔차 중요도 진단으로 유지한다. 실제 pruning을 채택할지 결정하지 않은 상태에서 원본 구조와 KV 연결을 바꾸는 코드를 생성하지 않는다.

### 잘못된 인과 해석

현재 transformer는 layer residual gate 적용 전에 KV를 계산할 수 있다. gate=0은 잔차 기여를 막지만 owner KV의 생성/후속 소비까지 제거하지 않는다. 따라서 U2의 손실 변화로 “KV 공급자를 삭제한 영향”을 판정할 수 없다.

### 실제 삭제를 선택할 때의 최소 설계

| 개입 | 질문 | 별도로 확인할 것 |
|---|---|---|
| MLP residual=0 | 이 MLP 잔차의 현재 기여 | 기존 KV 유지 |
| Attention residual=0 | 이 attention 출력의 현재 기여 | KV owner/consumer 유지 여부 |
| 전체 block bypass | 합성 함수를 건너뛴 영향 | norm/gate/skip 연결 |
| KV owner 제거+재지정 | 후속 layer가 다른 KV를 사용할 때 비용 | consumer 전수 매핑, 방문/재귀 키, 저장·연산 실제 감소 |

완전한 owner 삭제는 잘못된 인덱스만 지우는 코드로 구현해서는 안 된다. 실제 사용할 owner 재지정 정책과 train/eval 방문 계약을 먼저 정한 후 별도 구조 분기로 구현한다. 이는 지금 원본에 수정안을 적용하는 필수 단계가 아니다.

### 종결 기준

기존 U2/cosine 결과를 잔차 진단 범위로 정정하면 현재 문서 조치는 종결할 수 있다. pruning을 실제 후보로 올릴 때만 A03/A06의 같은 품질·메모리·속도 조건으로 물리적 삭제 팔을 추가한다. “유사하다”를 “공짜로 재사용할 수 있다”로 바꾸지 않는다.
