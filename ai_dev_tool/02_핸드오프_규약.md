# 02 — 핸드오프 메모 규약 (장기기억)

> **목적**: 세션이 끊겨도 **작업 기록이 유실되지 않게** 한다.
> 새 세션이 `handoff/` 의 최신 메모 **하나만 읽고** 이어받을 수 있어야 한다.

## 1. 언제 쓰나

| 시점 | 무엇 |
|---|---|
| **세션 컨텍스트 70% 전후** | 중간 핸드오프(유실 방지). 프로젝트 지침에 명시된 규칙 |
| **작업 단위가 끝날 때마다** | 사용자 지시 1건이 끝나면 그 자리에서 갱신 |
| **세션 종료 시** | 최종 핸드오프. 다음 세션 시작 프롬프트까지 포함 |

## 2. 파일 규약

- 경로: `handoff/{YYYYMMDDHHMM}_HANDOFF.md`
- 첫 줄: `# HANDOFF {날짜 시각} — {이 세션이 남긴 것 한 줄}`
- 둘째 줄: 이전 핸드오프 링크
- **요약하지 않는다.** 신규 세션이 이것만 읽고 이어받을 수 있게 쓴다.
- `CLAUDE.md` 의 "현재 상태" 줄에서 **최신 핸드오프를 가리키게** 갱신한다.

## 3. ★고정 섹션 (이 순서로)

```markdown
# HANDOFF {시각} — {한 줄}

이전: [{이전파일}]({이전파일}).
**코드가 정본**(`tinylm/`). 영구 규범은 `CLAUDE.md`. 장기기억은 `ai_dev_tool/`.
**★AI 는 학습/GPU 코드를 직접 실행하지 않는다** — 배치·스크립트만 만들고 **실행은 사용자**.

> **이 문서는 요약하지 않는다.**

## 0. 사용자 지시사항과 그 목적

| # | 사용자가 지시한 것 | **AI 가 판단한 목적** | **그래서 필요했던 작업** | **실제로 한 것** | 결과 |
|---|---|---|---|---|---|

★"지시한 것" 과 "목적" 을 따로 적는다. 목적을 잘못 읽으면 지시를 다 지켜도 헛일이 된다.
★"필요했던 작업" 과 "실제로 한 것" 이 다르면 **그 차이를 반드시 남긴다** — 다음 세션이
  그 자리에서 이어야 할 지점이다.

## 1. ★가장 중요한 것 세 가지 (먼저 읽을 것)

## 2. ~ N. 항목별 상세 (근거·수치·판정)

## N+1. 사용자에게 부탁하는 것
(실행할 배치 / 확인할 판단 / git 명령 — **AI 가 못 하는 것만**)

## N+2. 다음에 하면 좋을 것 (권장 순서)
| 순 | 실험 | 배치 | GPU | 예상 시간 | 권장 근거 |

## N+3. 커밋 메시지 제안 (한국어 제목 + 본문)

## N+4. 신규 세션 시작 프롬프트 (제안)

## N+5. 참조 치트시트
```

## 4. ★반드시 들어가야 하는 것

- [ ] **사용자 지시사항 원문**과 **AI 가 이해한 목적**을 **분리**해서
- [ ] **하려던 것 vs 실제로 한 것**의 차이(있으면)
- [ ] **판정이 뒤집힌 것**과 그 이유 — 조용히 덮어쓰지 않는다
- [ ] **아직 답이 없는 질문**(가장 자주 유실되는 항목)
- [ ] **사용자 대기 항목**(실행·승인·git) — AI 가 못 하는 것만
- [ ] **다음 권장 실험**: 실험번호 · 단계 · **배치 파일명** · **예상 시간** · **권장 근거**
- [ ] **커밋 메시지**(한국어 제목 + 본문)
- [ ] **신규 세션 시작 프롬프트**

## 5. 쓰지 말아야 하는 것

- **"~할 예정"** 만 적고 실제 상태를 안 적는 것. 상태는 ✅/⏸/🚫 로 명시한다
- **결론만 적고 근거 수치를 뺀 것.** 다음 세션이 재검증할 수 없다
- **"조치 완료" 를 파일 diff 없이 적는 것**(결과 014 초판 사고)
- 이전 핸드오프의 **요약본**. 링크를 걸고 **새 내용만** 쓴다

## 6. 3층 기억 구조 (이 저장소의 규약)

| 층 | 위치 | 무엇 | 수명 |
|---|---|---|---|
| **영구 규범** | `CLAUDE.md` | **매 프롬프트 반드시 확인해야 하는 것만.** 컴팩트 유지 | 프로젝트 전체 |
| **장기기억** | `ai_dev_tool/*.md` | 함정 원장 · 규약 · 절차. **펼쳐 볼 때 읽는다** | 프로젝트 전체 |
| **단기기억** | `handoff/*.md` | 세션 컨텍스트. 다음 세션이 이어받는 유일한 통로 | 세션 |

> **판단 기준**: "이걸 몰라서 **매 프롬프트** 사고가 나는가?" → `CLAUDE.md`.
> "필요할 때 찾아보면 되는가?" → `ai_dev_tool/`.
> "이번 세션에서만 유효한가?" → `handoff/`.

## ★7. 2026-08-13 개정 (사용자 지적) — **빠지면 안 되는 두 절**

> *"어느순간 세션 핸드오프 메모에 사용자가 해줘야 할 것이 없어진 것 같은데 ...
>  AI가 요청할 사항이 없으면 '요청할 것이 없다'고라도 작성필요.
>  덧붙여 -done으로 완료된 실험 배치파일 중 삭제가능한 것도 항시 보고하도록"*

**진단**: §3 고정 섹션에 *"N+1. 사용자에게 부탁하는 것"* 이 이미 있는데,
**요청이 없는 세션에서 그 절을 통째로 빼 버렸다.** 그러면 다음 세션이
*"요청이 없었나, 아니면 쓰다 잊었나"* 를 구분할 수 없다. **빈 절도 정보다.**

### 규칙 (핸드오프 작성 시 **무조건**)

| # | 규칙 |
|---|---|
| **A** | **"사용자에게 부탁하는 것" 절은 언제나 쓴다.** 요청이 없으면 **"이번에는 요청할 것이 없다"** 라고 **명시**한다. 절을 지우지 않는다 |
| **B** | 그 절에 **`-done` 배치 삭제 판정을 항상 포함**한다. 삭제 가능한 것이 없으면 **"삭제 가능한 `-done` 배치 없음"** 이라고 적는다 |
| **C** | 삭제 판정은 3조건으로 한다 — ① 실험 완료 ② **재현 명령이 결과문서에 보존** ③ 재실행 예정 없음. **②를 문자열로 대조**한 뒤에 적는다(011 §0.5-7 전례) |
| **D** | 체크포인트·로그·캐시가 **10 GB 이상 쌓였으면** 정리 목록도 이 절에 넣는다 |

⚠️ **왜 규칙 A 가 필요한가**: 이 저장소의 사고 다수가 *"안 적혀 있어서 안 한 것인지,
안 해도 되는 것인지 몰랐다"* 에서 나왔다(함정 13 "조치 완료 표기", 결과 031 "조용한 무동작").
**빈 절을 명시하는 것은 그 계열의 예방이다.**

## 8.3 ★고정 섹션 — **번호까지 고정한다**

종전 §3 은 *"N+1, N+2 …"* 로 써서 **번호를 자유롭게 뒀다.** 그래서 순서가 흔들렸다.
**이제 번호를 못 박는다:**

```markdown
# HANDOFF {YYYY-MM-DD HH:MM} — {이 세션이 남긴 것 한 줄}

> 양식: `ai_dev_tool/02_핸드오프_규약.md` · **이전**: [{이전파일}]({이전파일})
> **코드가 정본**(`tinylm/`). 영구 규범 `CLAUDE.md`. 장기기억 `ai_dev_tool/`.
> **★AI 는 학습/GPU 코드를 직접 실행하지 않는다** — 배치만 만들고 실행은 사용자.
> **이 문서는 요약하지 않는다.**

## 0. 사용자 지시 N건 — 지시 ↔ 목적 ↔ 실제로 한 것     ← ★표. 5열
## 1. ★가장 중요한 것 세 가지
## 2. ~ K. 지시별 상세 (근거·수치·판정)
## K+1. ★사용자에게 부탁하는 것                        ← ★비어도 쓴다(§7-A)
## K+2. ★다음 권장 실험 순서                           ← 실험번호·배치명·시간·근거
## K+3. 커밋 메시지 제안                               ← ★제목/본문 **분리 라벨**
## K+4. 열린 질문 (아직 답이 없는 것)
## K+5. 새 세션 시작 프롬프트 (제안)
## K+6. ★compact 프롬프트 (제안)                       ← ★2026-09-02 신설
## K+7. 참조 치트시트
```

### 8.3a ★★**K+2 다음 권장 실험 순서 — 표의 열을 못 박는다** (2026-09-04 사용자 지시 6)

> 사용자: *"핸드오프 권장 실험순서 목록 표에 **id 열이 사라짐**.
> 핸드오프메모 린터에 권장실험순서 표 **형식 규정 명확히** 할 것."*

**왜 사라졌나** — 양식이 *"실험번호·배치명·시간·근거"* 라고만 적어 두고 **id 를 안 적었다.**
2026-09-04 판은 표 대신 *"큐 입력 줄 `2 3 5 4 6 7 8`"* 을 본문에 썼다. 🚫**그것은 열이 아니다** —
표를 훑어 한 줄을 고를 수 없고, 줄이 표와 어긋나도 아무도 못 본다.

★**규정 = 열 여섯. 이 순서로.**

| 열 | 무엇 | 누가 정하나 |
|---|---|---|
| `순` | 내가 매긴 **권장 우선순위**(1,2,3…) | ★AI |
| ★**`id`** | **큐 메뉴 id** | 🚫**손으로 쓰지 않는다** — `python scripts/queue_menu.py --ids <배치명들>` |
| `실험` | `P0NN Stage<N>` + 한 줄 이름 | AI |
| `배치 파일` | `run_P0NN_Stage<N>_<요약>.bat` | 디스크 |
| `⚙` | 예상 시간(h) | `experiments.tsv` |
| `근거` | **왜 그 순서인가** | AI |

🚫★**`순` 과 `id` 는 다른 번호다**(함정 36). 2026-08-14 에 둘을 섞어 권장했다가
**1순위를 건너뛰고 최하위에 3.5시간을 태울 뻔했다.** 그래서 **둘 다 적는다** —
하나만 적으면 다음 사람이 어느 쪽인지 모른다.

✅**`check_handoff` 규칙 11 이 기계로 본다**: 열 여섯이 다 있는가 + ★**`id` 가
`queue_menu` 가 계산한 값과 같은가**. `-done` 이라 큐에 없으면 `—` 로 적는다.
⚠️**최신 판에만 적용**한다(지난 핸드오프는 그때의 스냅샷이다).

### 8.3b ★**K+6 compact 프롬프트** (2026-09-02 사용자 지시)

> 유실을 방지하기 위한 적절한 compact 프롬프트도 함께 제안할 것"*

**왜 양식에 넣나** — 매 세션 요구되는 항목인데 **양식에 없어서 실제로 빠졌다**(2026-09-02).

🚫★**K+5 와 다른 것이다.** 둘을 같은 절에 쓰지 않는다:

| | 무엇 | 누가 읽나 |

| **K+5** 시작 프롬프트 | *"무엇을 읽고 시작하라"* — 경로·규범·금지 | **다음 세션**이 붙여넣는다 |

| **C** | 사고와 **재발 방지 조치** | 같은 도구 사고가 반복된다 |

★**수치는 반드시 이름과 함께** 적는다 — `3.6054` 가 아니라 `d12_cla2_r20 3.6054 @ 30.7 MiB`.

## 8.4 ★커밋 메시지 절 — **제목을 라벨링한다** (2026-08-13 지시)

> 사용자: *"커밋메시지 제안시 커밋메시지 제목을 누락하지 않도록 할 것."*

**진단**: 제목을 안 쓴 적은 없지만, **본문과 한 덩어리로 코드블록에 넣어** 어디까지가
제목인지 안 보였다. 그리고 **채팅 답변에서는 핸드오프 §를 가리키기만 하고 제목을
안 적은 적이 있다.** 지시는 *"커밋메시지 제목과 본문을 제안하라"* 였다.

### 규칙

| # | 규칙 |
|---|---|
| **A** | 핸드오프의 커밋 절은 **`### 제목`** 과 **`### 본문`** 을 **따로** 둔다. 각각 별도 코드블록 |
| **B** | 제목은 **한 줄, 50자 내외, 한국어.** 저장소 관례는 `타입: 요지` (`fix:`/`chore:`/`feat:`/`docs:`) |
| **C** | ★**채팅 답변에도 제목을 그대로 적는다.** *"핸드오프 §7 참조"* 로 대체하지 않는다 |
| **D** | 본문에 **이모지·박스문자 금지**(터미널·git log 에서 깨진다). `★`·`⚠️`·`—` 는 허용 |

## §9. ★**권장순서 표에 `선결` 열은 필수다** (2026-08-20 신설, 의사결정함정 D15)

핸드오프 `202608270600` §7 에서 **한 문장이 두 행을 덮었다**:

> *"6·7 은 배치가 없다 — 선결이 있어서 일부러 안 만들었다"*

**6 에는 선결이 있었고 7 에는 없었다.** 7 은 학습 0 · 0.1시간이고 도구도 이미 있었다.
사용자가 지적했다 — *"근거없는 미구현은 오류/게으름/환각으로 오인된다."*

### 규칙

> ★★**§7 권장순서 표에 `선결` 열을 둔다. 빈 칸을 남기지 않는다.**

| `선결` 값 | 뜻 |
|---|---|
| `없음` | 🚫★**이 값이 적히는 행은 표에 남을 수 없다 — 배치를 만든다** |
| `P0NN 단계N (Nh)` | 실험 선결. **시간도 함께** |
| `구현: <이름>` | 코드 선결. **무엇이 없는지 이름으로** |
| `결정: <무엇>` | 사람의 결정 선결 |

★**형식은 D1 을 따른다** — *"무엇이 선결이고 그것이 얼마인가"* 를 **숫자로**.
**숫자를 못 적으면 그건 선결이 아니다.**

### §9.1 ★★2026-08-27 개정 (사용자 지적) — **보류 목록에도 같은 규칙이 적용된다**

§9 는 **권장순서 표의 열**을 규정했다. 그런데 **보류(⏸) 목록은 §4 계열의 인라인 나열**이라
**빈 칸을 남기지 말라는 규칙에 걸릴 칸 자체가 없었다.** 그 틈으로 2026-09-09 판이 이렇게 나갔다:

```
⏸보류: P061B(§5, 선결 P073 2) · P070 · P014B U1 · P050B · 🚫★P030 단계2B
```

**다섯 중 하나에만 선결이 있었다.** 그리고 🚫**`P030 단계2B` 는 이미 2026-07-31 에 완료된 실험**이다 —
계획서 본문은 완료라고 적혀 있었고 **그 절의 소제목만 낡은 ⏸ 를 달고 있었다**(계측함정 18).
그것을 다섯 세션 연속으로 *"REVIEW3 를 막는 급한 것"* 이라고 옮겨 적었다.

> ★★**규칙**: **보류 항목 하나하나에 선결을 단다.** 형식은 §9 표와 같다.
> 선결이 정말로 없으면 **`선결 없음: <왜 지금이 아닌가>`** 라고 **명시**한다 —
> **선결이 없는데 미루는 것은 우선순위 결정이므로, 그 결정을 적어야 사용자가 뒤집을 수 있다.**
>
> ✅**검사**: `scripts/check_handoff.py` 가 ⏸ 줄의 항목마다 선결 표기를 요구한다(에러).
> ⚠️**그리고 보류 항목을 적기 전에 계획서를 연다** — 완료된 것을 보류로 적는 사고가 실제로 났다.
