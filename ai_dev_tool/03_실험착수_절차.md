## 1. ★배치를 만들기 전 — 구현 게이트

**최상위 `.bat` 은 문서가 아니라 실행 가능한 물건이다.** 거기 있으면 사용자는 돌려도 되는
것으로 읽는다. 실제로 두 번 그렇게 됐다.

| # | 확인 | 방법 |
|---|---|---|
| 1 | 계획이 요구하는 **플래그가 파서에 있는가** | `python scripts/check_batch_flags.py` |
| 2 | 그 플래그가 **실제로 연결돼 있는가**(파서 → 함수 → 동작) | 코드 경로를 **눈으로 따라간다**. ★1번은 이걸 못 본다 |
| 3 | 계획이 요구하는 **동작이 구현돼 있는가** | 계획서 §측정·판정 항목을 한 줄씩 대조 |
| 4 | 코드를 고쳤으면 **스모크** | `run_smoke_check.bat` (`[VERIFY]` 줄만 읽는다) |
| 5 | **린트** | `python scripts/lint_bat.py --fix` |

> **2번이 왜 따로 있나**: 2026-08-06 에 `--doc-filter` 가 `train` 파서에 **있었는데**
> `trainer.train()` → `prepare()` 로 **전달되지 않았다.** 필터 캐시를 만들 수는 있어도
> **그것으로 학습할 방법이 없었다.** 1번 검사는 통과했을 것이다.
>
> **구현이 선결이면 배치를 만들지 않는다. 계획서에만 설계를 남긴다.**
> 불가피하면 헤더 첫 줄에 선결 조건 + `:NOTIMPL` 가드를 넣는다(그러면 1번이 경고로 낮춘다).

## 2. ★실험 간 독립성 (사용자 요청, 2026-08-06)

한 실험이 다른 실험을 **막거나 오염시키지 않게** 설계한다. 이유는 두 가지다 —
① 하나가 실패해도 나머지가 살아야 하고 ② **AI 사용량이 소진된 동안 사용자가 긴 학습을
혼자 돌릴 수 있어야** 한다.

| 축 | 규칙 |
|---|---|
| **체크포인트** | 항상 `--tag` 를 붙인다. 정본 `dense`/`tied` 를 덮어쓰지 않는다 |
| **데이터 캐시** | 내용이 달라지면 **디렉터리를 분리**한다(`_filtered` 방식). 기존 캐시 무변 |
| **플래그 기본값** | 새 기능은 **기본 off**. 켜지 않으면 **비트 동일**이어야 한다 |
| **속도 측정** | 다른 실험과 **동시 실행 금지**. 직전 5분 유휴 |
| **선행 의존** | 있으면 배치 헤더에 **명시**하고 `goto ERROR` 로 막는다. 없으면 `[WARN] continuing` |

### 2.1 "무인 실행" 배치의 조건

사용자가 시작만 하고 자리를 뜰 수 있으려면:

- [ ] **중간에 판단이 필요 없다**(분기·확인 프롬프트 없음)
- [ ] **선결 조건을 헤더에서 검사하고 없으면 즉시 멈춘다**(GPU 를 태우기 전에)
- [ ] **예상 소요 시간이 헤더에 있다**
- [ ] **판정 기준이 꼬리말에 있다** — 로그만 받아도 다음 세션이 문서를 쓸 수 있게
- [ ] **다른 실험의 산출물을 건드리지 않는다**

### 2.2 우선순위를 매길 때

| 우선 | 성격 | 왜 |
|---|---|---|
| 1 | **GPU 0 · 수분** | 값싼 진단이 비싼 학습의 게이트다. 먼저 돌려서 설계를 고친다 |
| 2 | **구현 선결이 없는 긴 GPU 런** | AI 사용량과 무관하게 굴릴 수 있다 → **대기시간을 자산으로** |
| 3 | 구현이 필요한 것 | AI 가 있을 때만 진행 |

## 3. 실험 한 사이클

```
exp-preflight  (조건 정합성 — docs/EXPERIMENT_BASELINES.md 와 대조)
      +
exp-plan       (계획서 양식 — ★예측 절과 한계 절을 반드시 쓴다)
      ↓
구현 게이트 (§1)
      ↓
run-batch      (.bat 작성 → lint_bat.py + check_batch_flags.py)
      ↓
[사용자가 실행]
      ↓
log-to-result  (결과문서 → ★계획서 본문 갱신 → 연쇄 갱신)
      ↓
핸드오프 (ai_dev_tool/02)
```

**`exp-plan` 과 `exp-preflight` 는 대체 관계가 아니다.** 전자는 문서 양식·절차,
후자는 실험 조건의 정합성. 새 계획을 쓸 때는 **둘 다** 돈다.

## 4. 결과를 읽기 전에 예측을 적는다

계획서와 배치 헤더 **양쪽에** 예측을 적는다. 이유:

- 예측이 없으면 **어떤 결과든 "예상대로" 로 읽힌다**
- 예측이 있으면 **틀렸을 때 그것 자체가 결과가 된다**(가설 기각도 성과다)
- 배치 헤더에 적으면 **사용자가 로그를 볼 때 이미 기준을 갖고 본다**

그리고 결과문서에서 **예측 대조 절을 명시적으로** 쓴다. 계획서에 예측을 써 놓고
대조하지 않으면 쓴 의미가 없다.

### 4.1 대조군을 반드시 하나 넣는다

**"아무것도 안 변해야 하는 조건"** 을 같은 배치에 넣는다. 그게 계측 결함을 잡는다.

- P034 단계3C: `p6d`(공유 없음)가 **안 변해야** 한다 → 변하면 환경이 변한 것
- P037 단계2C: `ko-en` 대조군이 **완전 불변**이어야 스코핑이 맞다
- 속도 배치: 기준선 조건을 같은 로그에 넣어 **비율로 읽는다**(열·부하가 상쇄된다)

목록을 읽어 분배하는 일은 파이썬이 해야 하고, 그 대가로 **`call` 만 담긴 계획 파일을 기계가 생성**하므로
**§6 규칙 2 를 사람이 잊을 수 없게** 됐다.

## §7. ★재실행본은 **단계명을 바꾼다** — `stage0` → `stage0b` (2026-08-13 신설)

> **사용자 지시**: *"새로만든 재실행본은 `stage0b` 처럼 이전 수행실험과 구분할 수 있는
> 단계명 사용할 것. 다른 실험에서도 재실행본 작성시 구분가능한 단계명 사용하도록 규약 반영."*

### 왜

`runlog.py` 의 실험 로그 파일명은 **`{번호}_log_{YYYYMMDD}_{name}.txt`** 이고
**같은 날 같은 이름이면 이어쓴다**(설계 — 한 배치의 여러 단계를 한 파일에 모으려고).

→ ★**같은 날 재실행하면 두 측정이 한 파일에 섞인다.**
그리고 그 둘은 **다른 측정**이다 — 도구가 바뀌었으니까.

실제 사례(2026-08-13):

| | 무엇 | 결과 |
|---|---|---|
| P049 `stage0` | 난수 정답으로 잰 게이트 | 🚫**무효**(결과 041 §11) |
| P049 `stage0b` | **실제 val 데이터**로 고친 게이트 | 이제 잰다 |
| P055 `stage0` | 퇴화 합성 로짓 | 🚫**A2·A4 무효**(결과 042 §3) |
| P055 `stage0b` | **독립 분포 + 퇴화 감지** | 이제 잰다 |

**같은 이름이었다면 로그·레지스트리·결과문서에서 둘을 못 가른다.**

### 규칙

> **도구·조건·해석이 바뀐 재실행은 단계명에 `b`, `c` … 를 붙인다.**
>
> - 배치 파일명: `run_P055_stage0b_kd_audit.bat`
> - `runlog --name`: `P055_stage0b_audit`
> - 결과문서 절 제목: *"§12. 단계 0b — …"*
> - 계획서 단계 표에 **행을 추가**한다(단계 0 을 고쳐 쓰지 않는다)

**언제 `b` 를 붙이나**

| 상황 | 새 단계명? |
|---|---|
| ★**도구를 고쳤다**(계측이 바뀌었다) | ✅ **필수** |
| ★**조건을 바꿨다**(데이터·시드·하이퍼파라미터) | ✅ **필수** |
| **해석 기준을 바꿨다**(게이트 임계) | ✅ 필수 |
| 같은 코드·같은 조건에서 그냥 다시 돌린다 | 🚫 불필요 — 그건 **같은 단계의 반복**이다 |

⚠️★**"같은 단계의 반복" 이라도 시드가 다르면 조건이 다르다.** 시드 반복은
`_s2` 태그로 구분하고(결과 039 의 `mC_wsd_s2`), 그건 **단계명이 아니라 태그**의 몫이다.

### 왜 `-done` 만으로는 부족한가

`-done` 은 **배치 파일**의 상태이지 **측정**의 정체가 아니다.
배치는 지워도 **로그와 결과문서는 남는다** — 거기서 구분이 돼야 한다.

## §7.1 🚫🚫 **`-done` 을 되돌리지 않는다** (2026-08-14 신설, 사용자 지적 · 위반 2건)

> **사용자 지적**: *"`-done` 처리한 배치파일의 파일명을 동일한 파일명으로 다시 복구하면
> 어떤 실험을 완료했는지 알 수 없게 되어 기존에 실행했던 동일한 실험을 재실행하게 될 가능성이 있음."*

### 무엇을 어겼나 (2026-08-14)

`run_P057_stage0_attn_gate-done.bat` 이 **측정 0건**으로 죽어서 재실행이 필요했다.
나는 **`-done` 을 떼어 원래 이름으로 되돌렸다.** `run_P061_stage0_split_gate` 도 같이.
**§7 이 이미 "재실행은 `b` 를 붙인다" 라고 적혀 있었는데 적용하지 않았다.**

★**그 결과가 바로 관측됐다**: P061 은 되돌린 뒤 **다시 `-done` 이 됐는데 로그가 그대로였다.**
→ **재실행한 것인지 표시만 되돌린 것인지 파일만 봐서는 구분이 안 된다.** 사용자가 경고한 그대로다.

### 규칙 (§7 을 보강한다)

| # | |
|---|---|
| **A** | 🚫🚫**한 번 실행된 배치는 영구히 `-done` 이다.** 실패했어도, 데이터가 0건이어도 **실행은 실행이다** |
| **B** | ★**재실행은 새 파일**이고 이름에 단계 구분자를 올린다(`stage0` → `stage0b` → `stage0c`) |
| **C** | ★**`runlog --name` 도 같이 올린다.** 안 올리면 §7 의 이유대로 로그가 한 파일에 섞인다 |
| **D** | ★**새 배치 헤더 맨 앞에 "왜 `b` 인가" 를 적는다** — 1차가 무엇으로 실패했고 그 사이 무엇이 바뀌었는지. 이게 없으면 다음 세션이 두 파일을 보고 **어느 쪽이 최신인지** 모른다 |
| **E** | `experiments.tsv` 는 **행의 배치명을 새 이름으로 갱신**한다(행을 지우고 새로 만드는 것이 아니다 — prio·note 이력이 이어져야 한다) |

### ⚠️§7 표의 마지막 행을 오해하지 말 것

§7 표에 *"같은 코드·같은 조건에서 그냥 다시 돌린다 → `b` 불필요"* 가 있다.
**측정 0건으로 죽은 실험의 재실행은 여기 해당하지 않는다.**

> **죽었다는 것은 원인이 있었다는 뜻이고, 그 원인을 고쳤으면 "도구를 고쳤다"(표 1행) 다.**
> 배치 파일이 한 글자도 안 바뀌었어도 **그 배치가 부르는 코드가 바뀌었으면 다른 측정**이다.
> P057 이 정확히 이 경우였다 — 배치는 그대로고 `transformer.py`·`diag_depth_init.py` 가 바뀌었다.

### 기계 그물 — `lint_bat.py` 규칙 19 (2026-08-14 신설)

배치의 `--name X` 로 **이미 `test_result/` 에 로그가 있는데** 그 배치가 `-done` 이 아니면 경고:

```
[W] run_P057_stage0_attn_gate.bat: --name 'P057_stage0_attn' 으로 실행된 로그가
    이미 있다(044_log_20260814_P057_stage0_attn-error.txt).
    재실행이면 stage 구분자를 올려라(0 -> 0b). 완료면 -done 을 붙여라.
```

⚠️**경고이지 에러가 아니다** — 로그를 AI 가 개명하면(§8) 이름이 안 맞을 수 있고,
`-done` 을 사용자가 붙이기 전 상태도 정상이다. **사람이 한 번 보라는 신호**다.

## §8. ★결론이 바뀌면 **파일명도 AI 가 바꾼다** (2026-08-13 사용자 지시)

> *"다음번부터 실험결과 변경에 따른 파일명 변경은 claude 가 직접 파일명 수정바람.
>  실험결과 파일명 수정에 따른 경로 수정이나 링크 수정 필요 확인하여 진행.
>  실험목록 파일에도 반영 필요하다면 반영바람"*

### 8.1 왜 필요한가 — **낡은 제목이 중복 작업을 만든다**

결과 041 은 제목이 *"이식이 난수보다 나빴다"* 였는데 **그 주장이 철회**됐다.
그대로 두면 다음 세션이 **파일명만 보고 잘못된 결론을 사실로 취급**한다.
실제로 **의사결정 함정 D3** 가 이 방식으로 발생했다 — 낡은 제목 때문에
**이미 끝난 P028 단계1 을 다시 제안**했다.

### 8.2 ★가능해졌다 — 마운트 실측 (2026-08-13)

| 연산 | 샌드박스 | 비고 |
|---|---|---|
| `cp` 복사 | ✅ | |
| ★**`mv` 이름 변경** | ★**✅ 가능** | **종전 기록("rename 차단")은 낡았다** |
| `rm` 삭제 | 🚫 **차단** | **삭제는 여전히 사용자** |

→ **개명은 AI 가 한다. 삭제는 사용자가 한다.** (`git mv` 가 아니라 `mv` + 사용자 커밋)

### 8.3 개명 절차 (5단계, **순서 고정**)

| 단계 | 무엇 | 왜 |
|---|---|---|
| **1** | **새 이름을 정한다** — 철회된 주장을 빼고 **현재 결론**을 넣는다. 번호·날짜·P번호는 **유지** | 번호가 바뀌면 실험목록 정렬이 깨진다 |
| **2** | `mv 옛이름 새이름` | |
| **3** | ★**참조 전수 치환** — `grep -rln "옛이름" --include=*.md .` | |
| **4** | ★**`test_result/실험목록.md` 의 링크 열**을 고친다. 같은 번호의 행이 **여러 개**면(041 / 041+ / 041++) **전부** | 한 행만 고치면 나머지가 죽는다 |
| **5** | **문서 상단에 개명 이력을 남긴다** — `옛이름 → 새이름` 과 사유 | 다음 세션이 옛 이름으로 검색할 수 있다 |

### 8.4 ⚠️ **고치지 않는 것** — 과거 핸드오프

`handoff/*.md` 는 **그 시점의 기록**이다. 옛 파일명이 적혀 있어도 **고치지 않는다.**
고치면 *"그때 무엇을 알고 있었는가"* 를 알 수 없게 된다.
→ 링크 검사(`grep`)에서 `handoff/` 는 **제외**한다.

### 8.5 검산

```
grep -rln "옛이름" --include=*.md . | grep -v handoff/     # 0건이어야 한다
python scripts/check_links.py                              # 깨진 링크 0건
```

### 8.6 새 이름 짓기 — 이 저장소의 관례

```
{번호}_{YYYYMMDD}_{P번호}-{단계}-{현재 결론 한 조각}.md
```

- ✅ `041_20260813_P049-단계0-게이트가-틀렸다-이식은-4.78nats-이득.md`
- 🚫 `041_20260813_P049-단계0-이식이-난수보다-나빴다.md` (철회된 주장)
- 🚫 `041_20260813_P049-단계0-수정본.md` (**결론이 안 보인다**)
