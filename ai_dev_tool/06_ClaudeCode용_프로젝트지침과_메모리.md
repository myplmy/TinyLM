## 1. 이 프로젝트가 무엇인가 (Purpose & context)

uboy 는 PyTorch 로 **CPU·엣지 배포용 초경량 LLM 아키텍처(TinyLM)** 를
**from-scratch 학습**으로 만들고 있다(사전학습 모델 변환이 아니다).
★**1순위 목표는 연산이 아니라 배포 상주 메모리**다.

| | |
|---|---|
| 환경 | **Windows + RTX 4070 Ti Super(16GB) 단일 GPU**. 작업폴더 `Z:\TinyLM` |
| 지향점 | **dense 대비 절반 이하 상주 메모리로 유사 품질** |
| 최종 목표 | ★**상주 메모리를 CPU 의 L2+L3 안에**(REVIEW3). ⚠️그 크기는 **아직 사용자 결정 전** — 40 MiB·32 MiB 를 둘 다 표기 중 |

## 2. ★프로젝트 지침 (Cowork 지침의 Claude Code 판)

> 🚫**아래는 Claude Code 에서도 그대로 유효하다.** 특히 §2.1 은
> **Claude Code 가 실제로 그 능력을 갖고 있어서 더 위험하다.**

### 2.1 🚫🚫★**Claude Code 에서 더 위험해지는 두 가지**

| # | 규범 | Cowork 에서는 | ★**Claude Code 에서는** |
|---|---|---|---|
| ★**1** | **AI 는 학습/GPU 코드를 직접 실행하지 않는다** | 능력이 없어 자동으로 지켜졌다 | 🚫★**Bash 로 `python run100m.py train` 을 정말 돌릴 수 있다.** **GPU 시간은 사용자 자원**이고 한 런이 2~6시간이다. **배치만 만들고 실행은 사용자가 한다** |
| ★**2** | **파일 삭제 절대 금지** | 능력이 없었다 | 🚫★**`rm` 이 그냥 된다.** 이건 **능력 문제가 아니라 정책**이다(2026-08-14 위반 1회, [D11](04_의사결정함정_원장.md)). ★**삭제 권한을 요청하지도 않는다.** 지울 것은 **핸드오프의 "사용자에게 부탁하는 것" 절에 목록으로 적고 끝낸다.** ★**`mv`(개명)는 된다** — 되돌릴 수 있기 때문이다 |

★**돌려도 되는 것 / 안 되는 것**

| ✅ 돌려도 된다 | 🚫 안 된다 |
|---|---|
| `python scripts/check_static_all.py`(정적 게이트 13종, torch·GPU **0**) | `python run100m.py train …` (**어떤 형태로든**) |
| `python scripts/queue_menu.py --audit` / `--ids` | `run_smoke_check.bat`·`run_*.bat` (**GPU를 쓴다**) |
| `python scripts/lint_bat.py --fix` · `check_batch_flags.py` | `scripts/paired_eval.py`·`mem_runtime.py`·`diag_*.py` (**모델을 로드한다**) |
| `python scripts/sync_experiments_tsv.py --apply`(표만 고친다) | `git commit`·`git push` (**사용자 몫**) |
| `ls`·`grep`·`cat` 류 읽기 | `rm`·`rmdir`·`del` (**정책상 금지**) |

### 2.2 나머지 지침

- 세션 시작 시 **`handoff/` 최신 메모**를 먼저 읽는다. 영구 규범은 `CLAUDE.md`,
  장기기억은 `ai_dev_tool/` — **01** 계측함정 / **02** 핸드오프 규약 / **03** 실험착수 절차 /
  **04** 의사결정함정 / **05** 폐기된 규약.
- 문서를 고치거나 배치를 만든 **직후** `python scripts/check_static_all.py` 를 **AI 가 스스로** 돌린다.
  코드를 고쳤으면 `run_smoke_check.bat` 을 **사용자에게 요청**한다.
  🚫**정적이 동적을 대체하지 않는다** — 정적은 *"이름이 있는가"*, 동적은 *"그 경로가 도는가"*(함정 37).
- **실험용 배치는 "지금 돌아갈 때" 만 만든다.** 구현이 선결이면 **계획서에만** 설계를 남긴다.
  만든 직후 `check_batch_flags.py` + `lint_bat.py --fix`, 그리고 **파서에 있는 것과 실제로
  전달되는 것은 다르므로 코드 경로를 눈으로 따라간다.**
  ★**새 축을 뚫으면 그 축을 켠 스모크 팔을 함께 넣는다**(함정 37).
- 새 배치를 만들면 **`experiments.tsv` 에 한 줄** 추가하고 `queue_menu.py --audit` 로 확인한다.
  ★**큐 안내는 이름으로 한다** — id 는 표에 한 줄만 추가해도 밀린다(함정 36).
  id 가 필요하면 **`queue_menu.py --ids <배치명>` 이 계산하게 한다.**
- 로그를 받으면 **`log-to-result` 절차** — 결과문서뿐 아니라 **계획서 본문·실험목록·
  실험계획목록·`EXPERIMENT_BASELINES`** 까지 연쇄 갱신.
  ★**결과문서 번호는 실험군 번호다. 로그 파일명 앞 세 자리가 그것을 말한다.**
- **세션 컨텍스트 70% 전후·작업 단위 종료 시** 핸드오프를 쓴다(양식 `ai_dev_tool/02`).
  🚫`session-handoff` 스킬은 이 저장소에서 쓰지 않는다([D-03](05_폐기된_규약_원장.md)).
- 실험이 하나 끝나면 **다음 권장 순서**를 보고한다(실험번호·단계·배치 파일명·예상 시간·근거).
- 커밋할 변경이 있으면 **커밋 메시지 제목·본문을 한국어로 제안**한다(커밋은 사용자가 한다).
- ★**분해능은 조건 의존이다.** 현 표준(무KD) **2σ = 0.0034**, dense/부모없음 **0.024**.
  **어느 자를 썼는지 항상 명시**하고 `paired_eval` 이 인쇄하는 0.024 를 무KD 비교에 그대로 쓰지 않는다.
  *"동급"* 이라 쓸 때는 **"실무상 동급, 통계적으로는 유의"** 를 함께 적는다.
- 외부 AI 검토문서는 **우리 실측으로 반증을 먼저** 시도한다(코드 인용은 대개 맞고 우선순위는 자주 틀린다).
- 참고문헌은 **인용 전에 실제로 조회**한다(arXiv id·DOI). **초록만 읽고 인용하지 않는다.**
- **"조치 완료" 를 파일 diff 없이 적지 않는다**(함정 13).

## 3. ★프로젝트 메모리 (2026-08-23 기준)

### 3.1 현재 상태

| | |
|---|---|
| 코드 | **v6**(`tinylm/` 패키지), 아키텍처 v5. 학습은 안정적이다 |
| ★**표준조건** | **REVIEW2 안 A**(2026-08-22 사용자 확정) — `--preset m100R1c` + `--init-from` + ★**KD 제거**, 추가 플래그 없음 |
| ★**표준 명령** | `--data ko-en --tokens 300M --pool-tokens 600M --exact-cache --steps 2289 --micro-bs 8 --accum 16 --seq 1024 --lr 1e-3 --sched wsd --anneal-end 0.80 --decay-frac 0.2 --seed 1337 --eval-every 100 --compile` |
| ★**표준 대조군** | **`mC_initonly`** = full-val **3.6776** |
| ★**표준모델** | **`mC_d36_ag4_nokd`** = full-val **3.6848** / fp32 상주 **379.7 MiB** / int8 상주 **77.8**. ★**36층인데 20층 기준선보다 작다**(저장소 최초) |
| ★**분해능** | **무KD 2σ = 0.0034** / dense·부모없음 **0.024** |
| ★**`--no-ckpt`** | **무KD 의 기본**(사용자 지시). tied 20층 **10.31** ✅ / dense 20층 **12.69** ✅ / 🚫**36층·재귀는 OOM**(`--ce-chunk` 로도 안 열린다) |
| 아키텍처 | MLP 타잉 + **어텐션 타잉(`attn_group 4`)** + prelude/coda 2+2 독립 + **CLA2** + 임베딩 인수분해 E=256 |
| 리뷰 | REVIEW1(모델안) ✅ / REVIEW2(학습 조건) ✅ **KD 제거** / ★**REVIEW3(배포·상주, 4안) 초안 — 안 B 잠정 1순위** |

> ⚠️★**"안 A" 가 REVIEW2 와 REVIEW3 에서 다른 것을 가리킨다**(함정 28).
> **반드시 "REVIEW2 안 A" / "REVIEW3 안 A" 라고 쓴다.**

### 3.2 ★계측 — 이 저장소 사고의 대다수는 아키텍처가 아니라 계측이었다

- ★**"내가 재려던 양을 정말 재고 있는가" 를 항상 먼저 의심한다.**
  **예상 밖으로 깨끗한 패턴**이 보이면 계측을 먼저 의심한다.
- ★**함정 37**: **필드가 기록된다 ≠ 그 경로가 실행된다.** 새 축을 뚫으면 **그 축을 켠 스모크 팔**을 함께 넣는다.
- ★**함정 39**: **학습 경로 ≠ 평가 경로.** `train_repeat` 은 평가에서 무시된다.
  게이트는 **`val − train_ce`** 이고 **0.3 이 넘으면 계측을 먼저 의심**한다.
- ★**함정 38**: 인쇄와 판정이 갈라진다. 게이트가 *"거부"* 를 인쇄만 하고 실패로 안 세어
  *"전 게이트 통과"* 를 찍은 적이 있다. **34 는 오탐, 38 은 미탐 — 미탐이 더 비싸다.**
- ★**함정 40**: 지표가 조건을 잰다. `ms_step_spread` 는 스필이 아니라 **KD 스텝 교대**를 잰다.
- ★**함정 34**: 게이트가 실패를 찍으면 **모델보다 기준값을 먼저 의심**한다(**4번 중 4번** 다 게이트 잘못).
  **기준값에는 "언제 적용되는가" 를 함께 적는다.**
- ★**step0 CE 는 이진 게이트다** — *"이식이 됐는가 / 대역(5.0~9.3972) 안인가"* 만 답한다.
  🚫**크기·서열·축의 개폐를 step0 으로 정하지 않는다**([D13](04_의사결정함정_원장.md)).
  실측 배수 **1/20.6 ~ 2.22배 = 46배 범위**.
- 런 비교는 **`paired_eval`**. 학습로그 val 은 **무작위 크롭 표본**이라 `final` 끼리도 부호가 뒤집힌다.
  `best` 는 **하향 편향**이다. 안정성은 인쇄 `|g|` 가 아니라 **json `grad_max`**.
- **짧은 런(250스텝)은 VRAM·속도만** 읽는다. **세션 간 ms/step 드리프트 7.5%** — 다른 날 속도를 비교하지 않는다.
- **OOM 이 OOM 이라는 이름으로 안 온다**(`CUBLAS_STATUS_EXECUTION_FAILED`).
  **스필은 조용하다** — 종료코드 0 인데 26% 느렸다(`check_spill.py`).

### 3.3 ★메모리 (1순위 목표)

- **저장(packed) ≠ 상주(runtime).** 인용할 때 **어느 쪽인지 명시**.
  상주 = **유니크 삼진 × 4B × 2벌 + 나머지** — **bpw 가 식에 없다.**
- ★**함정 24**: **fp32 상주 ≠ int8 상주.** `E=128` 은 **int8 에서만** 1위(−18.8%)이고 fp32 는 −3.6%.
  **레버 순위가 배포 경로에 따라 뒤집힌다.**
- ★**LUT(1.6bpw) 이 삼진 항을 44.7 → 8.88 MiB(5.03배)** 로 줄였다.
  ★**남은 최대 항은 임베딩**이고 그 회계가 **2026-08-23 에 거짓으로 밝혀져 재측정 대기**다.
  🚫**int4·ternary 임베딩은 패킹이 없어 int8 과 같다.**
- ★**레버 가격은 볼록하다**(같은 g16 이 작은 기반 위에서 **1.57배**). **평균가격으로 예측 금지.**
- ★**어텐션 타잉 0.00083 nats/유니크삼진100만 = MLP 타잉(0.00342)의 1/4.1** — 가장 싼 레버.
- ★★**메모리를 안 쓰고 품질을 사는 레버가 둘 있다**: **재귀 R2**(−0.0202, 상주 0)와
  **깊이 36층+`attn_group 4`**(상주 −15.9%, 품질 +0.0072). → **감축과 품질은 제로섬이 아니다.**
- **타잉은 저장·상주를 줄이지 컴퓨트를 안 줄인다.** FLOPs 식에 `mlp_group` 도 `cla_group` 도 없다.

### 3.4 ★KD·부모

- ★**부모초기화 +0.1386 vs KD −0.0032 = 43배.** KD 단독은 아무것도 안 한다.
- ★★**KD 제거가 최대 VRAM 레버다** — reserved **12.47 → 5.07 GiB(−59%)**, 품질은 오히려 **−0.0208**.
- ★**학습 VRAM 의 최대 항목은 모델이 아니라 "어휘 전체 위의 KD 손실 계산"** 이다.
- ⚠️★**우리 KD 교사(dense 3.8080)가 그 학생(mC_wsd 3.6984)보다 나쁘다.**
  **KD 제거는 그 교사로 잰 값으로 결정됐다** → **P067 이 이것을 다시 연다.**
- ✅KD 구현 결함(H2)은 **배제**됐다. **실효 α = 0.288**(명목 0.5).

### 3.5 데이터

- **데이터 풀 ≥ 학습토큰 × 2.** 풀만 2배로 dense 가 **−0.12**(시간 0). **풀이 다른 런끼리 비교 금지.**
- **교차 데이터셋·교차 토크나이저 비교는 `common_bpb.py` 만 유효**하다.
- `ko-en` 은 **스팸 감사 통과**(0.062%). `ko-edu-en` 은 **폐기·재생성 대상**.
- 벤치는 **hellaswag · arc_easy · piqa** 만 살아 있다. MMLU 는 우연, MuSR 은 seq 초과, BoolQ 는 다수결 미만.

### 3.6 🚫기각·종결된 축 — **다시 제안하지 않는다**

`--reuse-attn-on-dup`(재귀 이득 전부 손실 +0.0079) · `--sdpa-gqa`(VRAM +27%, 시간 +96%) ·
per-row 융합 int8(6.5배 느림) · FiLM(+0.0003) · depth-delta ·
어닐 정렬 `anneal-end 0.80` 단독 · 어닐 형태 linear vs step(P035, 결과 022) ·
int4/ternary 임베딩 저장.

### 3.7 ★일하는 방식

- **값싼 진단 → 비싼 학습** 순서. 각 단계가 다음 단계의 게이트.
- 실험 전 **`exp-preflight`**(조건 정합성) + **`exp-plan`**(문서 양식) **둘 다**.
- 계획서에 **예측 절·한계 절**을 반드시 쓰고, 결과가 나오면 **예측 대조**를 명시적으로 한다.
  **빗나간 예측은 성과이지 감출 것이 아니다.**
- **가설 기각도 결과다.** 음성 결과로 라인을 종결하는 것을 성과로 친다.
- ★**실험은 서로 독립이게 설계한다** — 태그로 체크포인트 분리 / 새 플래그는 **기본 off·비트 동일** /
  선행 의존이 있으면 헤더에 명시하고 `goto ERROR`.
  **이유 둘**: 하나가 실패해도 나머지가 살아야 하고, ★**AI 사용량이 소진돼도 사용자가 혼자 돌릴 수 있어야** 한다.
- ★**[D1](04_의사결정함정_원장.md)**: *"~ 후에" 라고 미룰 때는 **무엇이 선결이고 그것이 얼마인지를 숫자로** 적는다.
  숫자가 없으면 그건 선결이 아니라 **미루는 이유**다.*

### 3.8 배치·큐 규약 (요약 — 전문은 `CLAUDE.md`·`run-batch` 스킬)

- **실험 하나 = 배치 하나.** 큐(`run_queue.bat`)는 **`call` 만** 한다.
- `.bat` 은 **순수 ASCII**. ⚠️**`%` 전면금지는 2026-08-13 해제** — 지금은 **`%VAR%` 즉시확장만 에러**,
  `%%`·`for %%a` 는 허용. 지연확장 `!VAR!` 를 쓴다. `chcp` 금지. **모든 경로가 `exit /b` 로 끝난다.**
- 무KD 학습 런에는 `--no-ckpt`, `--no-ckpt` 런 **앞에 `timeout /t 15 /nobreak`**.
- ★**`runlog.py` 에 `--note` 와 실행 명령을 한 줄에 주면 명령이 조용히 버려진다**(종료코드 0). **두 줄로 나눈다.**
- 스윕은 **한 런 실패로 중단되지 않게** — `if errorlevel 1 echo [WARN] … - continuing`.
