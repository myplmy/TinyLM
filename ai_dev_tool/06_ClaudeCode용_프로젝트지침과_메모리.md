## 1. 이 프로젝트가 무엇인가 (Purpose & context)

uboy 는 PyTorch 로 **CPU·엣지 배포용 초경량 LLM 아키텍처(TinyLM)** 를
**from-scratch 학습**으로 만들고 있다(사전학습 모델 변환이 아니다).
★**1순위 목표는 연산이 아니라 배포 상주 메모리**다.

| | |
|---|---|
| 환경 | **Windows + RTX 4070 Ti Super(16GB) 단일 GPU**. 작업폴더 `Z:\TinyLM` |
| 지향점 | **dense 대비 절반 이하 상주 메모리로 유사 품질** |
| 최종 목표 | ★**상주 메모리를 CPU 의 L2+L3 안에**(REVIEW3). ✅**2026-09-06 사용자 확정 — 3단**: **≤16 MiB**(엔트리) · **32 MiB**(메인스트림) · **40 MiB**(데스크톱 상한). ★**지금은 32·40 만 쓴다** |
| ★**속도 목표** | ✅**2026-09-06 사용자 확정** — **단일 CPU·단일 코어에서 ≥15 tok/s**. **80 tok/s 부터**는 속도를 줄여 품질을 올린다. 코어 증가 이득은 **별도 실험**. 🚫★**승자 둘이 둘 다 미달**(⚙12.5~13.2 / 9.9) — 기준표 **B.19** |

### 2.1b ★**Claude Code 에서 반복해서 발생하는 도구 사고** (2026-08-30 신설)

> **왜 이 절이 생겼나**: 아래 셋은 **이번 세션에서만 여러 번** 났고, 전부
> *"파일을 어떻게 쓰느냐"* 에서 났다. 🚫**아키텍처와 무관하고 규약으로도 못 막는다** —
> **도구 선택의 문제**라 여기 적는다.

| # | 증상 | 원인 | ★**대응** |
|---|---|---|---|
| ★★**1** | Bash heredoc 이 `unexpected EOF while looking for matching '` 로 죽는다 | 본문에 따옴표·백틱·한글이 섞이면 **셸이 먼저 파싱**한다. `<< 'EOF'` 로도 안 막힌다 | ★**긴 파일은 `Write` 툴로 쓴다.** 스크립트가 필요하면 **스크래치패드에 `Write` 로 만들고 `python` 으로 실행**한다 |
| ★★**2** | 파이썬 문자열 안의 백슬래시 이스케이프가 **실제 제어문자**가 된다 | 패치 스크립트가 **문자열 안의 문자열**을 다룰 때 이스케이프가 한 겹 벗겨진다. 이번에 **백스페이스(0x08)가 정규식에 박혀** 게이트가 60건 오탐했고, ★**이 표를 쓰다가 같은 사고가 한 번 더 났다** | ★**패치 뒤 `ast.parse` 로 끝내지 않는다** — **그 스크립트를 실제로 돌려 본다.** 제어문자는 문법 오류가 아니다. ★**본문에 백슬래시를 쓸 일이 있으면 `Write` 툴로 직접 쓴다** |
| **3** | `Path.write_text` 가 `OSError: [Errno 22]` | 경로·인코딩 조합 | ★**`encode` → 임시파일 → `os.replace`** 를 기본으로 쓴다(함정 35 와 같은 대응) |

★**2026-09-02(2차) 추가 — 4번**: 🚫**같은 플래그 이름이 도구마다 다른 규약일 수 있다.**
`run100m.py train --tokenizer-hf <폴더>` 인데 `common_bpb.py --tokenizer-hf **TAG=<폴더>**` 다.
**학습 명령을 복사해 판정 명령을 만들면 죽는다** — 이것으로 **9.2시간 런의 헤드라인이 날아갔다.**
그리고 `common_bpb` 는 **한 호출에 모델이 둘 이상**일 때만 비교표를 만든다(나누면 exit 0).
✅`lint_bat` **규칙 24** 가 이제 **돌리기 전에** 잡는다.

★**2026-09-03 추가 — 5번**: 🚫**한 도구를 부르는 법이 배치마다 따로 산다.**
`common_bpb` 는 2026-08-27 에 `--micro-bs 2 --ce-chunk 4096` 으로 큰 어휘 OOM 을 넘었는데,
**그 두 플래그가 새 배치로 안 옮겨와** 2026-09-03 에 **같은 자리에서 또 죽었다**(E22).
★**같은 수를 세 번 연속 못 쟀다**(형식 → 호출분할 → OOM). ✅`lint_bat` **규칙 24c** +
도구가 **돌기 전에 CE 메모리를 계산하고 거절**한다.
★**교훈**: *"이 도구를 이렇게 부른다" 는 지식은 배치가 아니라 **도구와 게이트**에 둔다.*

★**2026-09-03 추가 — 6번**: 🚫**린터가 주석을 명령으로 읽는 사고가 2회째**다.

### 2.2 나머지 지침

- 세션 시작 시 **`handoff/` 최신 메모**를 먼저 읽는다. 영구 규범은 `CLAUDE.md`,
  장기기억은 `ai_dev_tool/` — **01** 계측함정 / **02** 핸드오프 규약 / **03** 실험착수 절차 /
  **04** 의사결정함정 / **05** 폐기된 규약.
- 문서를 고치거나 배치를 만든 **직후** `python scripts/check_static_all.py` 를 **AI 가 스스로** 돌린다.
  코드를 고쳤으면 `run_smoke_check.bat` 을 **사용자에게 요청**한다.
  🚫**정적이 동적을 대체하지 않는다** — 정적은 *"이름이 있는가"*, 동적은 *"그 경로가 도는가"*(함정 37).
- **실험용 배치는 "지금 돌아갈 때" 만 만든다.** 구현이 선결이면 **계획서에만** 설계를 남긴다.
  만든 직후 `check_batch_flags.py` + `lint_bat.py --fix`, 그리고 **파서에 있는 것과 실제로
  전달되는 것은 다르므로 코드 경로를 눈으로 따라간다.**
  ★**새 축을 뚫으면 그 축을 켠 스모크 팔을 함께 넣는다**(함정 37).
- 새 배치를 만들면 **`experiments.tsv` 에 한 줄** 추가하고 `queue_menu.py --audit` 로 확인한다.
  ★**큐 안내는 이름으로 한다** — id 는 표에 한 줄만 추가해도 밀린다(함정 36).
  id 가 필요하면 **`queue_menu.py --ids <배치명>` 이 계산하게 한다.**
- 로그를 받으면 **`log-to-result` 절차** — 결과문서뿐 아니라 **계획서 본문·실험목록·
  실험계획목록·`EXPERIMENT_BASELINES`** 까지 연쇄 갱신.
  ★**결과문서 번호는 실험군 번호다. 로그 파일명 앞 세 자리가 그것을 말한다.**
- **세션 컨텍스트 70% 전후·작업 단위 종료 시** 핸드오프를 쓴다(양식 `ai_dev_tool/02`).
  🚫`session-handoff` 스킬은 이 저장소에서 쓰지 않는다([D-03](05_폐기된_규약_원장.md)).
- 실험이 하나 끝나면 **다음 권장 순서**를 보고한다(실험번호·단계·배치 파일명·예상 시간·근거).
- 커밋할 변경이 있으면 **커밋 메시지 제목·본문을 한국어로 제안**한다(커밋은 사용자가 한다).
- ★★**분해능은 계열 의존이고 전부 실측이다**(2026-09-02 갱신, 결과 039 §12) —
  **타잉 0.0006 / dense 0.0021 / ★재귀 0.0018**. ✅**정본은 `scripts/_rulers.py` 한 파일**이고
  `paired_eval`·`paired_join` 이 **같은 상수를 읽고 어느 자를 썼는지 인쇄한다** —
  🚫종전처럼 **손으로 적용하지 않는다**(두 도구가 각자 표를 들고 있다가 갱신을 둘 다 놓쳤다, 함정 18).
  🚫★**"시드 한 쌍은 σ 를 체계적으로 과대평가한다" 는 철회한다** — 타잉·dense 에서는 그랬지만
  재귀에서는 **반대로 과소평가**했다(0.0006 → 0.0011 / 0.0016 → 0.0024).
  ★**옳은 진술: 두 점 추정량은 편향된 것이 아니라 분산이 크다**(n=2 상대 sd 약 52%, n=3 약 36%).
  *"동급"* 이라 쓸 때는 **"실무상 동급, 통계적으로는 유의"** 를 함께 적는다.
- 외부 AI 검토문서는 **우리 실측으로 반증을 먼저** 시도한다(코드 인용은 대개 맞고 우선순위는 자주 틀린다).
- 참고문헌은 **인용 전에 실제로 조회**한다(arXiv id·DOI). **초록만 읽고 인용하지 않는다.**
- **"조치 완료" 를 파일 diff 없이 적지 않는다**(함정 13).

### 3.3 ★메모리 (1순위 목표)

★★**2026-09-03 사용자 결정 — 단위는 `MiB` 다.** **40 MiB = 41,943,040 B · 32 MiB = 33,554,432 B.**
근거 셋: ①구속 조건이 **CPU 캐시**이고 캐시 용량은 **하드웨어 정의상 이진** ②`nvidia-smi`·
`llama.cpp`·`/proc/meminfo`·PyTorch 관용구가 **전부 이진** ③★**우리가 인쇄해 온 수가 이미 전부 MiB**
였다(`transformer.py:845/877/947` · `mem_runtime.py:98` 이 `/1024**2`). 🚫**재측정 0건, 라벨만 정정.**

- **저장(packed) ≠ 상주(runtime).** 인용할 때 **어느 쪽인지 명시**.
  상주 = **유니크 삼진 × 4B × 2벌 + 나머지** — **bpw 가 식에 없다.**
- ★**함정 24**: **fp32 상주 ≠ int8 상주.** `E=128` 은 **int8 에서만** 1위(−18.8%)이고 fp32 는 −3.6%.
  **레버 순위가 배포 경로에 따라 뒤집힌다.**
- ★**LUT(1.6bpw) 이 삼진 항을 44.7 → 8.88 MiB(5.03배)** 로 줄였다.
  ★**남은 최대 항은 임베딩**이고 그 회계가 **2026-08-23 에 거짓으로 밝혀져 재측정 대기**다.
  🚫**int4·ternary 임베딩은 패킹이 없어 int8 과 같다.**
- ★**레버 가격은 볼록하다**(같은 g16 이 작은 기반 위에서 **1.57배**). **평균가격으로 예측 금지.**
- ★**어텐션 타잉 0.00083 nats/유니크삼진100만 = MLP 타잉(0.00342)의 1/4.1** — 가장 싼 레버.
- ★★**메모리를 안 쓰고 품질을 사는 레버가 둘 있다**: **재귀 R2**(−0.0202, 상주 0)와
  **깊이 36층+`attn_group 4`**(상주 −15.9%, 품질 +0.0072). → **감축과 품질은 제로섬이 아니다.**
- ★★★**2026-09-02 예산 승자가 바뀌었다**(결과 067 §11, 기준표 B.14): **32 MiB = `d12_cla2_r20`**
  (3.6054 @ 30.7) · **40 MiB = `d16_cla2_r20`**(3.5642 @ 38.5). 둘 다 **dense 몸통 + `cla_group 2`
  + 재귀 R2** 다. `d16_cla2_r20` 은 `d16_dense` 를 **품질·메모리 양쪽에서** 이긴다.
  🚫**이 조합은 REVIEW3 네 안 어디에도 없었다**(전부 20층 타잉 몸통 위에서 그렸다).
- 🚫★**`mlp_group`(MLP 타잉) 축은 잰 전 구간에서 지배당했다** — 대가가 d8 +0.0637 → d16 **+0.1049**
  로 **깊을수록 커진다**. ⚠️**"타잉 종결" 이라 쓰지 않는다**: 반증된 것은 `mlp_group` 이고
  `cla_group` 과 재귀는 **승자의 부품**이다(한 단어가 세 축을 가리켜 왔다 — 함정 28).
- ★**상주 회계가 깊이에 선형**: dense 는 **9.0 + 1.96 × 깊이**, 일반형은
  **9.0 + 1.21·L + 0.75·(방문/cla_group)** MiB (LUT + int8 임베딩 + KV bf16 @ seq 1024).
- **타잉은 저장·상주를 줄이지 컴퓨트를 안 줄인다.** FLOPs 식에 `mlp_group` 도 `cla_group` 도 없다.

### 3.4 ★KD·부모

- ★**부모초기화 +0.1386 vs KD −0.0032 = 43배.** KD 단독은 아무것도 안 한다.
- ★★**KD 제거가 최대 VRAM 레버다** — reserved **12.47 → 5.07 GiB(−59%)**, 품질은 오히려 **−0.0208**.

- ⚠️★**우리 KD 교사(dense 3.8080)가 그 학생(mC_wsd 3.6984)보다 나쁘다.**
  **KD 제거는 그 교사로 잰 값으로 결정됐다** → **P067 이 이것을 다시 연다.**
- ✅KD 구현 결함(H2)은 **배제**됐다. **실효 α = 0.288**(명목 0.5).

### 3.7 ★일하는 방식

- **값싼 진단 → 비싼 학습** 순서. 각 단계가 다음 단계의 게이트.
- 실험 전 **`exp-preflight`**(조건 정합성) + **`exp-plan`**(문서 양식) **둘 다**.
- 계획서에 **예측 절·한계 절**을 반드시 쓰고, 결과가 나오면 **예측 대조**를 명시적으로 한다.

- ★**실험은 서로 독립이게 설계한다** — 태그로 체크포인트 분리 / 새 플래그는 **기본 off·비트 동일** /
  선행 의존이 있으면 헤더에 명시하고 `goto ERROR`.
  **이유 둘**: 하나가 실패해도 나머지가 살아야 하고, ★**AI 사용량이 소진돼도 사용자가 혼자 돌릴 수 있어야** 한다.
- ★**[D1](04_의사결정함정_원장.md)**: *"~ 후에" 라고 미룰 때는 **무엇이 선결이고 그것이 얼마인지를 숫자로** 적는다.

### 5.1 ★★★가장 중요한 것 — **`paired_eval` 의 val 이 학습 데이터였다**

`prepare._stream()` 이 `default_rng(0)` 고정이라 **작은 캐시는 큰 캐시의 접두사**이고

    ko-en_600M/val.bin == ko-en_1200M/train.bin[597M:600M]    True (3,000,000)
