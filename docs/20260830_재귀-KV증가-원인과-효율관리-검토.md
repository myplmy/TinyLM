# 재귀 R 이 늘면 **왜 KV 캐시가 느는가**, 그리고 **어떻게 덜 늘릴 것인가**

> 작성 2026-08-30 (사용자 지시 7) · 근거 [결과 016 §24](../test_result/016_20260731110000_P034-실행시메모리-순위역전확인.md) · [결과 047 §14](../test_result/047_20260814_P062-단계0-스케줄을-맞추니-0.2427이-돌아왔다.md) · 코드 `tinylm/model/transformer.py`
> ★**결론 먼저**: 원인은 **캐시 키에 통과번호가 들어가기 때문**이고,
> **해법은 이미 구현돼 있다**(`--repeat-kv-reuse`). 🚫**그런데 한 번도 안 쟀다.**

---

## 0. 세 줄 결론

1. **재귀는 같은 층을 여러 번 지나고, 통과마다 그 층의 K/V 를 새로 만든다.** 그래서 엔트리가 방문 수를 따라간다 —
   `mC_cla1_ag4_r20` 은 **36 엔트리 / 54.0 MiB**(실측)로 **예산 36 MiB 의 1.5배를 KV 하나로** 쓴다.
2. ★**이것은 물리 법칙이 아니라 우리 규약이다.** `forward` 의 키가 `(owner, 통과번호)` 라서 그렇고,
   **`repeat_kv_reuse` 를 켜면 `(owner, 0)` 하나로 접힌다** — ⚙**36 → 20 엔트리**.
3. 🚫★**그 대가(품질)를 우리는 0회 쟀다.** 그리고 ★**추론 전용 플래그라 재학습이 0시간**이다
   → **⚙10분짜리 측정 하나가 이 라인의 생사를 정한다.**

## 1. ★원인 — 코드를 그대로 읽는다

### 1.1 방문 스케줄

`--train-repeat 2.0` 은 `_repeat_schedule()` 이 **중간 16층을 2회** 도는 목록을 만든다:

```
prelude(2) + [중간 16층] + [중간 16층] + coda(2) = 36 방문
```

🚫**층이 늘어난 것이 아니다.** 파라미터·상주 가중치는 **소수점까지 동일**하다(결과 047 §13 T1 확인).

### 1.2 ★그런데 캐시 키가 통과마다 갈라진다

`transformer.py` `forward()`:

```python
own = self.owner[i]
if i == own:
    pas = seen.get(own, 0); seen[own] = pas + 1
else:
    pas = seen.get(own, 1) - 1
key = own if not repeating else (own, pas)      # ★여기
```

★**`repeating` 이면 키가 `(owner, 통과번호)` 다.** 그래서 중간 16층은
`(2,0) … (17,0)` 과 `(2,1) … (17,1)` **두 벌**의 K/V 를 동시에 든다.

★**주석이 이유를 적고 있다**:
> *"그렇게 안 하면 두 번째 통과가 첫 통과의 KV 를 덮어써서 캐시가 조용히 틀려진다."*

즉 ★**정확성을 위한 선택**이었다. **두 번째 통과의 입력 `x` 가 첫 통과와 다르므로
그 층이 만드는 K/V 도 다르고, 덮어쓰면 디코딩이 학습과 다른 함수가 된다.**

### 1.3 엔트리 산술 — **실측과 일치한다**

| 모델 | 방문 | `cla_group` | 소유 층 | ★엔트리 | 실측 |
|---|---:|---:|---:|---:|---:|
| `mC_initonly_nc` | 20 | 2 | 10 | 10 | ✅**10** |
| `mC_cla1_ag4` | 20 | 1 | 20 | 20 | ✅**20** |
| `mC_d36_ag4_nokd` | 36 | 2 | 18 | 18 | ✅**18** |
| `mC_cla1_ag4_r20` | **36** | 1 | 20 | **36** | ✅**36** |

★**규칙**: `엔트리 = 스케줄에서 서로 다른 (소유층, 통과번호) 쌍의 개수`.
**재귀는 통과번호를 늘리고, `cla_group` 은 소유층을 나눈다. 두 축이 곱해진다.**

> ★**`mC_cla1_ag4_r20` 이 최악인 이유가 여기 있다** — `cla1`(소유층 최대) × `r20`(통과 최대)의 **곱**이다.

## 3. ★★해법 — **네 갈래. 하나는 이미 구현돼 있다**

### 3.1 ✅**안 1 — `--repeat-kv-reuse`(구현 완료, 미측정)**

```python
reuse = repeating and cfg.repeat_kv_reuse and pas > 0
if reuse:
    kv_bank[key] = kv_bank[(own, 0)]     # 첫 통과 KV 재사용
```

`kv_report()` 도 이미 이것을 회계에 반영한다(`key = (own, 0)` 으로 접는다).

| | 엔트리 | KV@1024 | 가중치 | **합계** |
|---|---:|---:|---:|---:|
| `mC_cla1_ag4_r20` 지금 | 36 | 54.0 | 16.9 | 🚫**70.9** |
| ⚙**+ `--repeat-kv-reuse`** | ⚙**20** | ⚙**30.0** | 16.9 | ⚙**46.9** |
| ⚙**`cla2` 몸통 + r20 + reuse** | ⚙**10** | ⚙**15.0** | ⚙16.8 | ⚙★**31.8** ✅ |

★★★**세 번째 줄이 이 문서의 전부다** — **재귀를 유지하면서 예산에 들어간다.**

| 왜 좋은가 | |
|---|---|
| ★**추론 전용 플래그다** | `cli.py:349` 가 `infer_repeat` 경로에서만 읽는다 → ★**재학습 0시간** |
| ★**이미 `paired_eval` 에 있다** | `paired_eval.py:135` → **지금 있는 체크포인트로 바로 잰다** |
| ★**⚙10분** | 학습 없음 |

🚫★**대가**: **두 번째 통과가 낡은 K/V 를 본다.**
첫 통과의 `x` 로 만든 K/V 를 두 번째 통과의 Q 가 조회한다 — **학습된 함수가 아니다.**
⚠️**그래서 이것은 함정 39 의 사촌**이다: 학습 경로와 추론 경로가 갈라진다.

★**그러나 크기를 모른다.** 관련 실측 하나가 있다 —
🚫`--reuse-attn-on-dup`(어텐션 **출력** 재사용)은 **재귀 이득을 전부 잃고 +0.0079 더 나빴다**(결과 041 §17.4).
⚠️★**그것과 이것은 다른 물건이다** — 출력 재사용은 **Q 까지 낡은 것**이고,
KV 재사용은 **Q 는 새로 계산**한다. **cos 유사도 0.9882 는 출력 쪽 수**이고 KV 쪽은 안 쟀다.
→ 🚫**041 의 기각을 이 안에 그대로 옮기지 않는다.** **재야 안다.**

### 3.2 ⚙**안 2 — 몸통을 `cla2` 로 바꾼다**(구현 0)

`cla_group=2` 면 소유층이 절반이므로 엔트리도 절반이다. **재귀와 무관하게 곱해진다.**

| 조합 | 엔트리 | KV | 가중치 | 합계 | 품질 대가 |
|---|---:|---:|---:|---:|---|
| `cla1` + r20 | 36 | 54.0 | 16.9 | 70.9 | 기준 |
| ⚙`cla2` + r20 | ⚙**18** | ⚙**27.0** | ⚙16.8 | ⚙**43.8** | ⚙**+0.0195**(결과 058 §13) |
| ⚙`cla2` + r20 + reuse | ⚙**10** | ⚙**15.0** | ⚙16.8 | ⚙**31.8** ✅ | ⚙+0.0195 + ? |

★**이 안은 학습이 필요하다**(⚙3.0h) — `run_P073_stage4_cla2_ag4_r20.bat` 이 **바로 그것**이고
**지금 큐에서 돌고 있다.** ✅**즉 안 2 의 절반은 이미 진행 중**이다.

### 3.3 ⚙**안 3 — 통과별 KV 를 "합친다"**(구현 필요 ⚙2h)

두 통과의 K/V 를 **버리지도 따로 두지도 않고 섞는다**:

| 방식 | 식 | 비고 |
|---|---|---|
| 평균 | `K = (K₀ + K₁) / 2` | 가장 단순. ⚠️두 통과의 스케일이 다르면 나쁘다 |
| ★가중평균 | `K = (1−w)K₀ + wK₁`, `w` 학습 | 파라미터 **층당 1개** |
| 마지막만 | `K = K₁` | **첫 통과를 버린다** — reuse 의 반대 |

⚠️★**"마지막만" 이 흥미롭다** — reuse 는 *"첫 통과가 옳다"* 고 가정하는데,
**깊은 통과일수록 표현이 정제됐을 것**이므로 **마지막이 더 나을 수도 있다.**
🚫**둘 다 근거가 없다.** ⚙**그리고 이것은 학습 경로를 바꾸므로 재학습이 필요하다**(⚙2.7h/팔).

### 3.4 ⏸**안 4 — 첫 통과만 K/V 를 만든다(학습 시부터)**

학습 때부터 `repeat_kv_reuse` 를 켜면 **모델이 그 함수를 학습**한다.
→ ★**함정 39 가 사라진다**(학습 경로 = 추론 경로).
⚠️**그러나 지금은 학습 경로에 안 걸린다** — `cli.py:352` 는 `infer_repeat` 분기 안이다.
⚙**구현 0.5h + 학습 2.7h.** ⏸**안 1 의 결과를 보고 정한다** — 안 1 이 싸고 먼저다.

## 5. ⚠️한계

- 🚫**§3 의 엔트리 수는 전부 ⚙유도**다. `kv_report()` 가 `repeat_kv_reuse` 를 반영하도록
  이미 짜여 있지만 **그 경로로 실행한 적이 없다**(함정 37 — 필드가 있다 ≠ 그 경로가 돈다).
- 🚫**품질 대가는 0회 측정.** §3.1 의 *"041 과 다른 물건"* 은 **논증이지 측정이 아니다.**
- ⚠️**KV 회계는 "동시에 살아 있는 쌍" 의 수**이고 할당자 실측이 아니다(결과 016 §24.7).
- ⚠️**`repeat_mode` 가 `uniform` 일 때의 분석**이다. `block`·`progressive`·`inplace` 는
  스케줄이 다르므로 **엔트리 수도 다르다.** 🚫**이 문서를 그 모드에 그대로 적용하지 않는다.**
- ⚠️**속도는 안 는다**(결과 014 §13.1 이 확인) — 이 문서는 **메모리만** 다룬다.
