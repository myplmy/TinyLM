# (a) ★**"볼록하다" · "볼록성"**

## a.1 무슨 뜻으로 쓰고 있나

**레버를 한 칸 더 밀 때 드는 값이 앞칸보다 비싸지는 것**이다. 수학의 볼록함수에서 가져온 말이지만
우리가 쓰는 뜻은 좁다 — ★**"한계비용이 증가한다"** 다.

```
  품질 손실(누적)
    ^                                       ★볼록: 갈수록 가팔라진다
    |                              ,-'
    |                        ,--'
    |                 ,---'
    |          ,----'
    |  ,-----'
    +-------------------------------> 레버를 민 정도 (g8 -> g16 -> g32)

    같은 "한 칸" 인데 뒤로 갈수록 세로로 더 많이 올라간다 = 볼록
```

## a.2 어디서 나온 말인가 — 실측 두 건

| 근거 | 무엇 |
|---|---|
| **결과 032 §8.3** | ★**같은 `g16` 이 더 작은 기반(`p1c1`) 위에서 1.57배 비쌌다** |
| **결과 041 §14.3** | 더할 때 0.00118 vs 뺄 때 0.00342~0.00443 nats/유니크삼진100만 |

## a.3 🚫★**2026-08-26 — 이 말을 좁혀야 한다** (결과 029 §11)

| 축 | 한 칸 더 밀었을 때 | 볼록한가 |
|---|---|---|
| 임베딩 랭크 E=192 → 128 | **2.18배** | ✅ |
| 어텐션 ag4 → ag8 → ag16 | **4.6 → 6.0배** | ✅ |
| ★**MLP g16 → g32** | ★**0.91배**(0.00312 vs 0.00342) | 🚫★**아니다 — 오히려 싸졌다** |

★★**네 축 중 하나가 반례다.** → 🚫**"볼록성" 을 근거로 안 잰 점을 예측하지 않는다.**
그건 **관찰된 패턴**이지 법칙이 아니다.

## a.4 실무에서 쓰는 법

| ✅ | 🚫 |
|---|---|
| *"세 점이 볼록했다"* (관찰 보고) | *"볼록하니 다음 점은 더 비쌀 것이다"* (예측) |
| *"평균가격으로 예측 금지"*(032 §8.3) | *"평균가격 × 2 = 두 칸 비용"* |

# (b) ★**"어텐션이 꺼진다" · "안 깨어났다"**

## b.1 무슨 값을 말하는가 — **게이트**

`modules.py` 의 `Layer` 는 층마다 **게이트 두 개**를 갖는다:

```python
g0 = 1.0 / math.sqrt(cfg.n_layers)
self.gates = nn.Parameter(torch.tensor([g0, g0]))   # [어텐션 게이트, MLP 게이트]
```

층의 출력은 대략 `x = x + gate_attn · attn(ln1(x))` 그리고 `x = x + gate_mlp · mlp(ln2(x))` 다.
★**게이트가 그 층의 어텐션·MLP 가 잔차에 얼마나 섞이는지를 정한다.**

★**초기값이 `1/√n_layers`** 이므로 학습 시작 시점에는 전부 같다.
→ ★**학습 후 게이트가 초기값보다 커졌으면 "깨어났다", 작아졌으면 "꺼졌다"** 고 부른다.

## b.2 어디서 나온 말인가 — 결과 041 §15

`mC_d36`(20층 → 36층 깊이 확장)에서 **복제된 층**의 게이트가 학습 뒤 어떻게 변했나:

| | 게이트 변화 | 우리가 쓴 말 |
|---|---:|---|
| ★**어텐션** | ★**×0.279** (초기값의 28%) | 🚫**"꺼졌다"** |
| ★**MLP** | ★**×1.434** (초기값의 143%) | ✅**"깨어났다"** |

★**같은 층 안에서 두 게이트가 반대로 움직였다.**

## b.3 ★그래서 무엇을 뜻했나

> **"이식이 어텐션 깊이를 못 살렸다"** (041 §15)

깊이 확장은 교사(20층)의 층을 복제해 36층을 만든다. 학습이 그것을 **어떻게 쓰기로 했는지**를
게이트가 말한다: ★**복제층의 MLP 는 쓰기로 했고(1.43배), 어텐션은 안 쓰기로 했다(0.28배).**

🚫**"어텐션이 쓸모없다" 가 아니다.** *"이 이식 방식으로 만든 복제 어텐션이 쓸모없었다"* 다.

## b.4 ⚠️혼동하기 쉬운 두 가지

| 말 | 실제 대상 |
|---|---|
| ★**"게이트가 꺼졌다"** | **학습이 정한 값**(게이트 파라미터). 관찰 |
| ★**"게이트를 0 으로 한다"**(U2, 결과 057) | **우리가 강제로** 0 을 넣어 손실 변화를 본다. 개입 |

★**둘은 다르다.** b.2 는 *"학습이 스스로 껐다"*, U2 는 *"우리가 꺼 보았다"* 다.
⚠️**그리고 결과 057 §11.2 가 U2 의 함정을 밝혔다** — `cla_group=2` 에서 게이트를 0 으로 하면
**K/V 사슬까지 끊겨** 그 층의 중요도가 아니라 사슬 효과를 재게 된다.

# (c) ★**"MLP 가 깨어난다"**

## c.1 (b)와 같은 지표의 반대편

`gates[1]`(MLP 게이트)이 **초기값보다 커진 것**이다. 결과 041 §15 에서 **×1.434**.

## c.2 ★왜 이것이 결론이 됐나

**같은 복제층**에서 어텐션은 0.279, MLP 는 1.434 로 갈렸다는 사실이 다음을 말한다:

| # | 읽은 것 |
|---|---|
| 1 | 🚫*"복제층 전체가 죽었다"* 가 **아니다** — MLP 는 오히려 더 쓰인다 |
| 2 | ★**이식의 문제는 어텐션 쪽에 있다** — 그래서 P057(어텐션 타잉)로 이어졌다 |
| 3 | ★**깊이는 값어치가 있다** — 다만 어텐션을 늘리는 형태로는 아니다 |

## c.3 ★이 말이 지금 어디에 서 있나

★**결과 044 가 그 판단을 확증했다**: `mC_d36_ag4`(36층 + 어텐션 4층 공유)가
**상주 −15.9%** 이면서 품질 **+0.0072** 였다 — ★**어텐션을 줄이고 깊이를 얻는 것이 맞았다.**

## (d) ★**"어휘로 접는다" · "접는다"**

| | |
|---|---|
| **일상어에는 없다** | 종이를 접는다는 말은 있어도 *"어휘로 접는다"* 는 없다 |
| ★**무슨 뜻인가** | **여러 개의 다른 이름을 정해진 소수의 이름으로 대응시킨다**(수학의 *사영*·*몫집합*에 가깝다) |
| ★**왜 이 말을 썼나** | *"통일한다"* 는 **원본을 덮어쓰는 느낌**이고, *"매핑한다"* 는 영어다. **접으면 원래 것이 안쪽에 남아 있다** 는 뉘앙스를 쓰고 싶었다 |

**실제 사례** — held-out 벤치마크의 관계 이름:

```
접기 전 (자유 어휘, 81종)          접은 뒤 (통제 어휘, 13종)
  concept_boundary        ─┐
  classification_boundary ─┼──>  boundary
  temporal_boundary       ─┤
  entity_boundary         ─┘
  subtype                 ─┬──>  subclass_of
  subclass_of             ─┘
  function_or_role        ───>  function  또는  role  (사람이 고른다)
  (그 밖 60여 종)          ───>  other
```

★**"접는다" 가 맞는 말인 이유**: `other` 로 간 60여 종은 **사라진 게 아니라 한 칸에 모였다.**
원본 필드를 남겨 두면 언제든 펼 수 있다. 🚫**"통일한다" 로 썼으면 원본을 덮어쓴 것처럼 읽힌다.**

★**앞으로 쓸 때**: 처음 등장 시 *"통제 어휘로 접는다(여러 이름을 정해진 13개에 대응시킨다)"* 로 푼다.

## (e) ★**"자" · "자를 잰다" · "빌린 자"**

| | |
|---|---|
| ★**무슨 뜻인가** | **자 = 분해능(2σ)**. *"이 차이가 진짜인가 노이즈인가"* 를 가르는 문턱 |
| **일상어와 다른 점** | 일상에서 *"자"* 는 도구다. 여기서는 **그 도구의 눈금 간격**을 뜻한다 |

**사례 셋**:

| 표현 | 뜻 | 실제 |
|---|---|---|
| *"자를 다시 쟀다"* | 같은 조건을 **시드만 바꿔 여러 번 학습**해서 노이즈 폭을 측정했다 | 타잉 3.6762 / 3.6768 / 3.6765 → **2σ = 0.0006** |
| ★*"빌린 자"* | **그 계열에서 안 쟀고 다른 계열의 값을 대신 쓰는 중** | 재귀 판정에 dense 자 0.0042 를 쓰던 시기 |
| *"자의 5.7배"* | 차이가 문턱의 5.7배 = **확실히 진짜** | `--repeat-kv-reuse` 대가 +0.0591 |

⚠️★**"자 아래" 는 "차이가 없다" 가 아니다** — *"이 실험 설계로는 못 가른다"* 는 뜻이다.
그래서 이 저장소는 **"실무상 동급, 통계적으로는 유의"** 라고 둘을 나눠 적는다.

## (f) ★**"교환비가 나쁘다"** vs 🚫**"기각"**

★**이 둘을 구분하는 것이 이 저장소의 규약**이다.

| 말 | 뜻 | 다시 열리는가 |
|---|---|---|
| 🚫**기각** | **효과가 없거나 해롭다.** 다시 제안하지 않는다 | ❌ |
| ⚠️**교환비가 나쁘다** | **효과는 있는데 대가가 더 크다** | ✅**대가가 싸지면 다시 연다** |

**사례**: 방문 20 → 28 은 품질 **−0.0036**(자의 6.0배 = 진짜 이득)인데 속도가 **−24.6%** 다.
🚫*"R=6 기각"* 이라고 적었더니 **LUT 커널로 속도가 싸져도 아무도 다시 안 볼 상태**가 됐다.
→ ★*"교환비가 나쁘다"* 로 고쳤다.

## (g) ★**"축" · "축을 연다/닫는다"**

| | |
|---|---|
| ★**축** | **바꿀 수 있는 설계 변수 하나**(예: 타잉 그룹 크기, 재귀 횟수, KV dtype) |
| **축을 연다** | 그 변수를 실험 대상으로 삼기 시작한다 |
| **축을 닫는다** | 더 안 건드리기로 한다(기각이든 종결이든) |

**사례**: *"어텐션 타잉은 `ag4` 에서 끝난다"* = **`attn_group` 축을 4 이상에서 닫았다.**
🚫*"모델을 바꾼다"* 가 아니라 **"그 변수 하나만 움직인다"** 는 뜻이다.

## (h) ★**"상주" vs "저장" vs "패킹"**

★**이 셋을 섞어 쓰면 이 저장소에서 가장 자주 나는 사고**(함정 1·24)다.

| 말 | 영어 | 무엇 | 이 모델의 예 |
|---|---|---|---|
| **저장(packed)** | packed | **디스크에 담기는 크기.** 비트폭이 식에 있다 | 8.2 MB |
| ★**상주(runtime)** | resident | **돌아가는 동안 램에 붙들려 있는 크기** | 16.8 MB |
| **KV** | KV cache | 문맥 길이에 **선형으로 자라는** 별도 항 | 15.0 MB @ seq 1024 |

★**"저장 8.2 인데 상주 16.8" 이 이상하지 않은 이유**: 삼진 가중치를 **계산 직전에 fp32 로
펼치기** 때문이다. 그래서 **비트폭을 줄여도 상주는 그대로**일 수 있다.
→ ★**인용할 때 반드시 어느 쪽인지 적는다.** 상주는 **(모델, KV dtype, 컨텍스트)** 셋을 함께.

## (i) ★**"~ 가 조용하다" · "조용한 실패"**

| | |
|---|---|
| ★**뜻** | **에러도 안 나고 종료코드도 0 인데 결과가 틀린 상태** |

**사례 셋**:

| 무엇 | 어떻게 조용했나 |
|---|---|
| 메모리 스필 | 종료코드 0, 손실 정상, **그런데 26% 느렸다** |
| `--mlp-film` | 학습이 정상 종료됐는데 **로그에 그 플래그가 켜졌다는 기록이 없었다** |
| HF 캐시 | 다운로드 성공, 에러 0, **그런데 작업폴더 밖에 받았다** |

★**그래서 이 저장소는 "게이트" 를 만든다** — 조용한 실패는 **소리를 내게 만들어야** 보인다.

## (j) ★**"게이트"**

| | |
|---|---|
| ★**뜻** | **통과하지 못하면 다음으로 못 가게 막는 자동 검사** |
| 일상어와 차이 | 문(gate)이 아니라 **검문소**에 가깝다 |

**두 층이 있다**:

| 층 | 무엇을 보나 | 예 |
|---|---|---|
| **정적** | *"이름이 있는가"* — torch·GPU 를 안 쓴다 | `check_static_all.py`(20종) |
| **동적** | *"그 경로가 실제로 도는가"* | `run_smoke_check.bat` |

🚫★**정적이 동적을 대체하지 않는다.** `mlp_film` 사고가 정확히 그 틈이었다.

## (k) ★**"~ 를 산다" · "메모리를 사서 품질을 판다"**

| | |
|---|---|
| ★**뜻** | **한 자원을 내주고 다른 자원을 얻는다**(경제학의 trade-off) |

**사례**: *"`mC_cla2_ag4` 는 상주 −17.3% 를 샀는데 속도를 안 잃었다"*
= 메모리를 줄였고(얻음) 속도는 그대로(대가 없음).
★**"공짜"** 라는 말은 이 저장소에서 **"대가가 자 아래"** 라는 뜻이다.

## (l) ★**"교락(交絡)된다"**

| | |
|---|---|
| ★**뜻** | 통계 용어 confounding. **두 원인이 같이 움직여서 어느 쪽 몫인지 못 가른다** |

**사례**: `attn_group` 실험을 전부 `cla_group=2` 에서 돌렸는데 **`cla_group=2` 자체가 −0.0268 의
대가**가 있었다. → *"`attn_group` 결과 전부가 교락됐다"* = **어텐션 타잉의 몫과 CLA 의 몫을
분리할 수 없다.**

## (m) ★**"~ 로 귀속한다"**

| | |
|---|---|
| ★**뜻** | **관측된 차이의 원인을 무엇으로 돌리는가** |

**사례**: *"cla1 의 t1 −20% 를 아키텍처로 귀속하지 않는다"*
= 그 −20% 를 **모델 구조 탓으로 적지 않는다**(기준 행이 외부 부하 한계를 넘었으므로).

## (n) ★**"⚙" 표시**

| 표시 | 뜻 |
|---|---|
| ⚙ | ★**추정값이다. 재지 않았다.** ⚙8.8시간 = *"환산해 보니 8.8시간일 것"* |

## (s) ★**"창 스윕" · "편향이 스윕 축을 따라 커진다"**

| 말 | 뜻 |
|---|---|
| **창(window)** | 어텐션에서 **최근 W 개 토큰만 남기는** 그 W |
| ★**창 스윕** | W 를 **여러 값으로 바꿔 가며** 같은 것을 재는 것(128·512·768…) |
| ★★**편향이 스윕 축을 따라 커진다** | **틀린 양이 일정하지 않고 W 가 커질수록 더 틀린다** |

★★**왜 마지막 것이 특별히 나쁜가** — 스윕은 **곡선의 모양**을 보려고 한다.

🚫**곡선 자체가 휜다** — 즉 **곡선을 읽으려고 만든 도구가 그 곡선을 망친다.**

**실측**(E18, 결과 065 §9.6): 인쇄된 값의 편향이 **+1.5 → +2.25pp** 로 커졌고,
창 768 에서는 **−0.3%** 라는 **불가능한 값**(질량은 음수가 될 수 없다)이 나왔다.

## (t) ★**"싱크∩창 겹침"**

| 말 | 뜻 |
|---|---|
| **싱크(sink)** | 어텐션이 **위치와 무관하게 늘 보는** 맨 앞 토큰 몇 개 |
| **창** | 최근 W 개 |
| ★**싱크∩창** | ★**둘 다에 속하는 토큰** — 짧은 문장에서는 앞 4개가 최근 W 개 안에도 있다 |

★**왜 문제였나**: 남기는 질량을 `싱크 + 창` 으로 더하면 **겹치는 토큰을 두 번 센다.**
그래서 버릴 질량 `1 − (s + w)` 가 **실제보다 작게** 나오고, 창이 커질수록 겹침도 커져
**음수까지 내려갔다**(§s).

★**옳은 식은 합집합**: `1 − both`, `both = P(싱크 ∪ 창)`.
✅표의 `중간(버릴)` 열은 **처음부터 합집합이라 옳았다** — 틀린 것은 **요약 한 줄**이었다.

> ★**한 줄 규칙**: **집합 둘을 더하기 전에 겹치는지 묻는다.**

## (x) ★★**"교호작용"**(交互作用 · interaction)

**한 줄**: 레버 **둘을 같이 쓸 때의 효과**가 **따로 쓴 효과의 합과 다른** 정도.
🚫**"둘 다 좋다" 와 다른 말이다** — 둘 다 좋으면서 교호작용이 0 일 수 있다.

**셈법**: 레버 A·B 의 on/off 네 칸을 다 채우고

```
교호작용 = (A효과 | B=on) − (A효과 | B=off)
```

**실측**(결과 075 §10, 전부 1.2B 풀 · 같은 val):

| final val | 토큰 t300 | 토큰 t600 | **깊이 효과** |
|---|---:|---:|---:|
| **d12** | 3.63172 | 3.52500 | — |
| **d16** | 3.59281 | 3.47922 | — |
| **깊이 효과** | −0.03891 | −0.04578 | ★**교호작용 −0.00687** |

깊이는 **오래 학습할수록 더 값지다**(−0.03891 → −0.04578, **+17.7%**). 뒤집어 말하면
**긴 학습이 깊이의 값어치를 6.4% 키운다**. 부호가 **음수**이므로 **상승효과(synergy)** 다.

### ⚠️★교호작용의 자는 **단일 차이의 자 × √2** 다

네 런의 조합이라 분산이 크다: `Var(교호작용) = 4σ²` vs `Var(단일 차이) = 2σ²`.
→ ★**2σ 자 = √2 × 0.0021 = 0.00297**(dense 계열). 위 값은 그 **2.31배**라 **유의하지만 작다.**

🚫**단일 차이의 자(0.0021)를 그대로 대면 2.31 이 3.27 로 부풀어 보인다.**

### 🚫왜 이 말을 조심해야 하나

**2×2 의 한 칸이 비면 교호작용을 아예 못 잰다.** 결과 075 §4.1 이 정확히 그 상태였고
(`d16 × t300` 미실행) **§10 에서 그 칸을 채우고서야** 답이 나왔다.
★**두 레버를 함께 쓰는 안을 낼 때는 네 칸을 세어 본다.**

## (y) ★★**"유니크 커버리지"**(unique coverage) · **"유니크 토큰"**

**한 줄**: 학습 중에 모델이 **적어도 한 번 본 서로 다른 토큰의 수**. 🚫**학습 토큰 수와 다르다.**

★**로더에 epoch 이 없다**(`loader.py:26` 이 **균일 랜덤 복원추출**이다). 그래서 같은 토큰을
여러 번 보고 어떤 토큰은 한 번도 안 본다. 풀 `P` 에서 `T` 토큰을 뽑으면

```
유니크 = P · (1 − e^(−T/P))          ← 결과 073 §3 이 유도
```

| 풀 | 학습 토큰 | 커버리지 | 유니크 |
|---:|---:|---:|---:|
| 300M | 300M | 63.2% | 189.6M |
| ★**600M(표준)** | **300M** | ★**39.35%** | ★**236.1M** |
| 1,200M | 300M | 22.12% | 265.4M |
| 300M | 1,200M | 98.2% | 294.5M |

★**그래서 *"1 epoch"* 은 실제로 한 바퀴가 아니라 `학습토큰 / 풀` 이라는 이름**일 뿐이다.

### ★★유니크는 **학습 토큰에 갇혀 있다** — 이것이 실무 결론을 만든다

**유니크 ≤ 학습 토큰**이다(못 본 것을 셀 수는 있어도 본 것보다 많이 셀 수는 없다).
`P → ∞` 여도 유니크는 **T** 에서 멈춘다. 그래서 표준 300M 토큰에서:

| | 값 |
|---|---:|
| 유니크 배증의 가치 | **−0.0424 bpb** (스텝 배증 −0.0181 의 **2.34배**) |
| ★**풀 축에 남은 전부**(600M → ∞) | ★**−0.0146 bpb** |
| 그것을 스텝으로 사면 | **0.81 배증**(= 학습시간 1.75배) |

→ ★**"코퍼스보다 GPU 시간이 먼저다" 의 진짜 이유**는 *"새 글이 값이 없어서"* 가 아니라
***"값은 큰데 더 넣을 자리가 없어서"*** 다(결과 075 §11.3).

## (z) ★**"WD" · "decoupled WD"**

**한 줄**: `WD` = weight decay(가중치 감쇠). `decoupled` = **손실이 아니라 갱신 단계에서** 뺀다.

| | 식 | 어디로 당기나 |
|---|---|---|
| 고전 L2 | 손실에 `+ (wd/2)·‖w‖²` 를 더한다 | 0 |
| ★**decoupled**(AdamW) | `w ← w − lr·(Adam 스텝) − lr·wd·w` | ★**0** |

🚫★★**우리 문서 세 곳이 *"WD 가 1.0 으로 당긴다"* 라고 적었었다. 거짓이다** —
**0 으로 당긴다.** 이 오류가 게이트를 미탐으로 만들었다(결과 072 §8.2·§8.3, **함정 34 의 다섯 번째**).

### ★왜 이것이 판정을 바꿨나 — **귀무값**

`mlp_lrm`(층별 스칼라 승수)은 **1.0 에서 시작**한다. *"학습이 됐는가"* 를 보려면
**학습이 안 됐을 때 어디에 있는가**(= 귀무값)를 알아야 하는데, WD 가 걸려 있으므로 **1.0 이 아니다**:

```
순수 WD 궤적 = Π(1 − lr_t · wd) = 0.979778   (2,289스텝) / 0.997820 (250스텝)
```

즉 ★**바닥이 |s−1| = 0.0202** 다. 초판 게이트의 문턱 `PASS_MIN = 1e-2` 는 **그 바닥보다 낮아**
**학습이 전혀 안 된 승수도 ✅통과**시켰다. 지금은 json 에서 스케줄을 읽어 **`r = s / s_wd`** 로 판정한다.

★**일반 규칙**: **WD 가 걸린 파라미터의 귀무값은 초기값이 아니다.** `Π(1−lr_t·wd)` 를 계산해서 쓴다.

## (aa) ★★**"헤드라인이 흔들렸다 / 안 흔들렸다"**

**한 줄**: 계측 결함을 찾았을 때 — ***"그 결함이 우리가 이미 내린 결론을 뒤집는가"*** 에 대한 답.

결함을 발견하면 두 가지를 **따로** 물어야 한다:

| 물음 | 뜻 |
|---|---|
| 1. **결함이 진짜인가** | 계측이 틀렸다는 것 자체 |
| ★**2. 헤드라인이 흔들리나** | ★**그 결함으로 만들어진 판정 중 뒤집히는 것이 있는가** |

🚫**둘은 독립이다.** 결함이 진짜여도 헤드라인은 멀쩡할 수 있고, 그 반대도 있다.

### ✅안 흔들린 예 — val 오염 (결과 075 §6.3)

`paired_eval` 의 val 이 **142개 런의 학습 데이터**였다. 결함은 **진짜**다(바이트 일치로 확인).
그런데 **깨끗한 학습로그 val 로 다시 재니 분해능 초과 두 효과가 0.0003 안에서 일치**했다:

| 효과 | 오염된 자 | 깨끗한 자 | 차 |
|---|---:|---:|---:|
| `cla2e` | +0.0072 | +0.0075 | 0.0003 |
| 깊이 12→16 | +0.0412 | +0.0414 | 0.0002 |

→ ★**"헤드라인은 안 흔들렸다"** = **소급 재측정을 안 한다**(142런 × 0.9분을 아낀다).
⚠️**단 규약과 게이트는 고친다** — 다음번에 흔들릴 수 있기 때문이다.

### 🚫흔들린 예 — 시험지가 달랐다 (결과 075 §11.4)

*"유니크 토큰을 3배 더 줘도 이득이 안 커진다"* 는 **두 다른 val 셋**에서 잰 것이었다.
같은 시험지(`common_bpb`)로 다시 재니 **총 이득의 서열이 뒤집혔다**(P087 +8.2% → P088 +24.6%).
→ ★**결과문서 §1 에 철회 배너를 달고 §11.4 에 정정본을 썼다.**

### ★쓰는 규칙

1. 🚫**"헤드라인은 안 흔들렸다" 를 근거 없이 쓰지 않는다** — **다른 자로 다시 재서** 보인다.
2. ★**흔들렸으면 원문을 고치지 말고 철회 배너 + 정정 절**을 쓴다(기록은 안 고친다).
3. ★**흔들리든 안 흔들리든 게이트는 만든다.**

## (bb) ★**"관용 lr" · "상수 lr"**

두 말이 **서로 다른 것**을 가리키는데 둘 다 학습률 이야기라 섞이기 쉽다.

### ★"관용(慣用) lr" — **그 옵티마이저에서 관례적으로 쓰는 학습률 대역**

옵티마이저마다 **잘 도는 lr 대역이 자릿수 단위로 다르다.**

| | 관용 lr | 우리 표준 |
|---|---:|---:|
| AdamW | 1e-3 급 | **1e-3** |
| ★**Muon** | ★**2e-2 급**(원 구현) | — |

🚫★**그래서 `--optimizer muon` 만 켜면 그것은 "Muon 을 20배 낮은 lr 로 돌린 것"** 이다.
실측(결과 076): 배수 ×1 은 **자의 64배로 지고**, ×15 는 **자의 13.9배로 이긴다** — **같은 옵티마이저다.**

→ ★**규칙: 새 옵티마이저를 평가할 때 lr 대역을 함께 스윕하지 않으면 그 실험은 무효다.**
`--muon-lr-mult` 가 그것을 위해 있다(기본 1.0 = 종전 동작).

### 🚫"상수 lr" — **스케줄이 안 걸려서 lr 이 안 변하는 상태**

우리 표준은 `--sched wsd`(warmup → stable → decay)라 lr 이 **스텝마다 변한다.**
🚫**옵티마이저를 새로 붙이면서 스케줄러를 안 연결하면 그 옵티마이저만 상수 lr 로 돈다.**

실제로 났다(결과 076 구현 실사): `base_lrs` 를 `opt.param_groups` 에서만 뽑아
**Muon 쪽(`opt_muon`)에 warmup·decay 가 안 걸렸다** → **AdamW 팔과 다른 스케줄을 도는 무효 비교**.
✅한 커밋에서 고쳤고 json 에 `optimizer`·`muon_lr_mult`·`muon_matrices` 를 함께 넣었다(함정 37).

★**구별**: *"관용 lr 을 안 줬다"* 는 **값**의 문제, *"상수 lr 로 돌았다"* 는 **경로**의 문제다.
**전자는 결과를 나쁘게 만들고 후자는 비교 자체를 무효로 만든다.**

## (dd) ★★**"대각선"**(diagonal)

> **뜻**: 두 축을 함께 움직여서, ★**두 축의 어떤 조합량이 상수로 고정된 선** 위에서만 잰 상태.
> 🚫**그 선 위의 점들로는 두 축을 뗄 수 없다.**

**실례**(타잉 재평가 §격자): 깊이를 12→16 으로 올릴 때 `mlp_group` 도 4→8 로 올려서
**유니크 MLP 개수 = 층수/g ≈ 2** 가 계속 유지됐다.

```
   g\깊이   8    12    16    20
     1      ·    ·     ·     ·
     2      o    ·     ·     ·      o = 잰 칸(10)
     4      ·    o     ·     ·      · = 빈 칸(17)
     8      ·    ·     o     ·      ↘ 대각선
```

→ *"깊이를 올렸더니 타잉 대가가 커졌다"* 는 관측이 **깊이 때문인지 g 때문인지 모른다.**
★**대각선은 교락(§l)의 기하학적 이름**이다.

⚠️★**대각선은 게으름이 아니다** — 예산(상주 MiB)을 고정하면 **자연히 대각선이 생긴다.**
🚫**그래서 "예산을 맞춘 비교" 는 언제나 대각선일 위험이 있고**, 축을 떼려면
**예산을 일부러 어기는 점**을 하나 넣어야 한다.

## (ee) ★★**"화폐"**(currency) · **"환율"**

> **뜻**: 서로 다른 레버를 **하나의 단위로 환산해 견주는 것**, 그리고 그 환산비.
> 우리 화폐는 ★**`nats / 배포 MiB`** 다 — *"상주 1 MiB 를 얻는 데 품질 몇 nats 를 내는가"*.

**왜 필요한가** — 레버들이 서로 다른 단위로 온다:
`mlp_group` 은 *"유니크 파라미터 개수"*, 재귀는 *"방문 수"*, CLA 는 *"KV 엔트리"*.
🚫**그대로는 못 견준다.** 화폐로 바꾸면 한 줄에 세울 수 있다.

| 레버 | 값 (nats/MiB) | 방향 |
|---|---:|---|
| 재귀 R1→R2 | 0.01094 | ★**사는 쪽**(MiB 를 내고 품질을 산다) |
| 깊이 | 0.00614 | 사는 쪽 |
| ★**CLA** | ★**0.00587** | **파는 쪽** — 유일하게 깊이보다 싸다 |
| MLP `g4`@d12 | 0.01282 | 파는 쪽 |

★**규칙 둘**

1. ★**화폐 단위를 반드시 밝힌다** — `저장(packed)` MiB 와 `상주(runtime)` MiB 는 **다른 화폐**다(§h).
2. ⚠️★**환율은 조건 의존이다** — CLA 의 값어치는 **컨텍스트에 선형**이라 `seq 2048` 이면 **0.00293** 으로 절반이 된다.
   🚫**환율을 인용할 때 `(몸통, 컨텍스트, 배포 경로)` 셋을 함께 적는다.**

★**리라이팅 제안서(2026-09-08)에서 이 말이 한 번 더 쓰였다** — 거기서는
*"리라이팅 토큰 1개 = 찾은 토큰 몇 개인가"* 라는 **다른 화폐의 환율** `η` 다.
⚠️**같은 단어가 두 화폐를 가리키므로 어느 쪽인지 적는다**(함정 28).
