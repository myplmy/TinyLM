# TinyDataset **held-out v2.2** 재생성 요청 — 데이터셋 생성 LLM 전달용 프롬프트

> 작성 2026-08-30 · 근거 [`20260829_TinyDataset-v2-활용방향-변경제안-검토.md`](20260829_TinyDataset-v2-활용방향-변경제안-검토.md) §8
> ★**v2.1 은 요청 셋을 전부 반영했다**(자명 베이스라인 91.3% → **41.5%**). **이 문서는 v2.1 을 부정하지 않는다.**
> 🚫**남은 결함은 하나뿐**이고, 그것이 **v2.1 을 그대로 쓰면 벤치마크가 못 되는 종류**여서 재생성을 요청한다.

---

## 0. 왜 다시 만드는가 — **한 가지 결함**

v2.1 의 `correct_index` 분포:

| index | 0 | 1 | 2 | 3 |
|---|---:|---:|---:|---:|
| 건수 | 27 | 73 | **110** | 90 |

**χ²(3) = 50.1** (p < 0.001). 균등이면 각 75건이어야 한다.

🚫★**결과: *"내용을 안 보고 항상 index 2 를 찍는" 전략이 36.7% 를 얻는다.**
우연(25%)보다 **11.7%p 높다.** 우리가 재려는 것은 **개념 정체성 구분 능력**인데
**위치를 외우는 것으로 그 절반을 벌 수 있으면 그 수는 능력이 아니다.**

### 🚫왜 채점기에서 안 섞고 데이터에서 고치는가

섞는 것이 더 쉬워 보이지만 **재현성을 잃는다.** 우리 판정은 **0.0010 자** 위에서 이뤄지고
(`paired_eval` 은 **결정적 full-val**), 평가마다 후보 순서가 달라지면 **같은 체크포인트가
다른 점수**를 낸다. ★**데이터가 고정이어야 비교가 성립한다.**

## 1. ★생성 LLM 에게 그대로 전달할 프롬프트

> 아래 블록을 **그대로** 복사해 데이터셋 생성 LLM 에 준다.

```
TinyDataset held-out v2.1 을 v2.2 로 재생성해 주세요.

[배경]
v2.1 은 이전 요청 세 가지를 모두 반영했고 그 부분은 그대로 유지해 주세요.
  (1) 오답 길이비 0.8~1.2 구간 준수 — 900/900 달성
  (2) forbidden_relations_canonical 을 항목마다 채움 — 빈 것 0건 달성
      + 후보별 candidate_forbidden_relation 배열 신설
  (3) concept_seen_in_train 필드로 학습 노출 여부 명시

[이번에 고칠 것 — 이것 하나입니다]
correct_index 의 분포가 균등하지 않습니다.
  현재: index 0=27건, 1=73건, 2=110건, 3=90건 (총 300건, 카이제곱 50.1)
  문제: 내용을 보지 않고 항상 2번을 고르는 전략이 36.7% 를 얻습니다.
        무작위 추측 25% 보다 높아서, 이 벤치마크로 잰 점수에
        "위치를 외운 몫" 이 섞여 들어갑니다.

[요구사항]
R1. 각 문항의 4개 후보(candidates) 순서를 무작위로 다시 배열하고,
    correct_index 를 새 위치에 맞게 갱신해 주세요.
R2. 재배열 후 correct_index 분포가 균등에 가깝게 해 주세요.
    목표: 각 index 75건 +-8건 이내 (즉 67~83건).
    카이제곱(자유도 3) 값이 7.81 미만이면 됩니다.
R3. candidate_forbidden_relation 배열도 후보와 "같이" 움직여야 합니다.
    후보 i 를 위치 j 로 옮겼으면 그 배열의 i 번째 원소도 j 번째로 갑니다.
    ★이 배열이 후보와 어긋나면 데이터가 조용히 망가집니다.
R4. 다른 필드(id, question, answer, concepts, relations,
    forbidden_relations_canonical, required_relations_canonical,
    concept_seen_in_train)는 값을 바꾸지 마세요.
R5. 후보의 "내용" 은 하나도 바꾸지 마세요. 순서만 바꾸는 작업입니다.

[추가로 확인해 주실 것 — 새로 만드는 문항이 있다면]
A1. 정답이 후보 중 가장 긴 것이 되지 않게 해 주세요.
    (길이만 보고 고르는 전략을 막기 위한 것입니다. v2.1 은 이미 만족합니다.)
A2. 정답이 후보 중 유일하게 특정 접두사/접미사를 갖지 않게 해 주세요.
    (예: 정답만 "~이다" 로 끝나고 오답은 "~한다" 로 끝나는 식)
A3. 한 문항 안에서 후보 4개의 문장 구조가 서로 비슷하게 해 주세요.

[출력 형식]
v2.1 과 동일한 JSON 스키마를 유지해 주세요.
파일명은 v2.2 로 해 주세요.
작업 후 correct_index 의 분포(0/1/2/3 각 몇 건인지)를 함께 알려 주세요.
```

## 2. ★받은 뒤 우리가 확인할 것 (검수 게이트)

| # | 검사 | 통과 기준 | 왜 |
|---|---|---|---|
| **G1** | `correct_index` 분포 | **χ²(3) < 7.81** (각 67~83건) | 이번 재생성의 목적 |
| ★**G2** | **후보 집합이 v2.1 과 동일** | 문항마다 `set(candidates)` 가 v2.1 과 **일치** | 🚫**"순서만" 이 지켜졌는지** — 내용이 바뀌면 v2.1 실사가 무효가 된다 |
| ★★**G3** | **`candidate_forbidden_relation` 정합** | 후보 i 의 라벨이 **같이 움직였는가** | ★**가장 조용히 깨지는 곳.** 어긋나도 파일은 잘 열린다 |
| **G4** | 정답 최장 비율 | **25% 근처** | A1 |
| **G5** | 자명 베이스라인 | **≤ 30%** | 위치 36.7% 가 사라지면 자연히 내려간다 |
| **G6** | 축자 누수 | train 문장과 일치 **0건** | v2.1 에서 이미 0 이었다 |

★**G2·G3 이 이번 검수의 핵심**이다. R5 가 지켜지지 않으면
**v2.1 에 대해 한 실사(길이비·금지관계·노출라벨)를 처음부터 다시 해야 한다.**

⚙**검수 도구**: `scripts/diag_dataset_quality.py` 는 중복·오염만 본다.
**G1~G6 은 held-out 전용이라 `scripts/check_heldout_v22.py` 를 새로 만들어야 한다**(⚙0.4h).
🚫**아직 안 만들었다** — v2.2 가 도착한 뒤에 만드는 것이 맞다(스키마가 확정돼야 한다).

## 3. ⚠️한계

- 🚫**이 재생성은 "위치 편향" 하나만 고친다.** v2.1 실사가 찾지 못한 다른 자명 전략
  (어휘 중복, 문체 단서)은 **여전히 미탐일 수 있다.**
- ⚠️**자명 베이스라인 41.5% 는 "우리가 시험해 본 전략들의 최대치"** 이지
  **모든 자명 전략의 상한이 아니다.**
- ⚠️**300건이다.** 이 크기에서 정확도 차이의 표준오차는 **약 2.6%p** 이므로
  **5%p 미만의 모델 간 차이를 이 벤치로 판정하지 않는다.**
