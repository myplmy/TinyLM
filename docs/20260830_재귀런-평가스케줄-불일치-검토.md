# 재귀 런의 val 은 **학습과 다른 함수를 잰다** — 추가 실험이 필요한가

> 작성 2026-08-30 (사용자 지시 8) · 근거 `runs/logs/*.json` 92개 전수 · `tinylm/train/trainer.py` · 함정 39
> ★**사용자 질문**: *"재귀런의 경우 validation 도 R=2 로 평가하는 것은 추가실험이 필요한지?
> (학습에 영향을 미칠 수 있는가?) 학습시 재귀평가 결과를 반영하는 것까지 검토"*

---

## 0. 세 줄 답

1. ★**추가 "실험" 은 필요 없다. "코드 수정" 이 필요하다.** 재는 대상이 바뀌는 것이 아니라
   **재는 자가 틀린 것**이라, 새 학습 런이 아니라 **`evaluate()` 호출 한 줄**의 문제다.
2. ★**학습에 영향은 있다 — 다만 간접적이다.** 손실·기울기에는 **전혀** 안 들어간다.
   **`best.pt` 선택**에는 들어가고, **`--early-stop`** 에도 들어간다(다만 **기본 0 = 꺼져 있다**).
3. 🚫★**가장 큰 피해는 학습이 아니라 보고다.** W&B 곡선이 재귀 런을 **최대 1.28 nats 나쁘게** 그린다.
   ★**그리고 그 편차가 학습 중 단조 감소해서 곡선의 "모양" 까지 다르다** — 상수 보정으로 못 고친다.

---

## 1. 무엇이 일어나는가

`trainer.py` 의 주기 eval:

```python
m = evaluate(model, va, 50, device, bytes_per_token=bpt)
```

`evaluate()` 는 `model.eval()` 을 부르고, `visit_schedule()` 은 **`self.training` 일 때만
`train_repeat` 을 본다.** → ★**학습은 36 방문, 평가는 20 방문.**

🚫**두 개는 다른 함수다.** 같은 가중치를 다른 깊이로 돌린 것이라
**val 은 "이 모델의 품질" 이 아니라 "이 가중치를 절반 깊이로 돌렸을 때의 품질" 이다.**

---

## 2. ★얼마나 큰가 — **런 92개 전수**

게이트는 **`val − train_ce`** 다(R12). 기준선 계열은 약 0 이어야 한다.

| `train_repeat` | `val − train_ce` | n | 판정 |
|---:|---|---:|---|
| **1.0**(재귀 아님) | 평균 **+0.063** · 최대 +0.136 | **78** | ✅**전부 0.3 게이트 안** |
| 2.0 | +0.199 ~ **+0.435** | 8 | ⚠️**3건이 게이트 초과** |
| 3.0 | +0.668 ~ +0.682 | 2 | 🚫**초과** |
| 4.0 | **+0.909** | 1 | 🚫**3.0배 초과** |
| 6.0 | ★**+1.280** | 1 | 🚫**4.3배 초과** |
| 8.0 | +1.134 | 1 | 🚫**3.8배 초과** |

★**재귀 런 14개 중 11개가 게이트를 넘는다.** 비재귀 78개는 **하나도 안 넘는다.**
→ ✅**게이트가 제대로 작동하고 있었다.** 🚫**우리가 그 경고를 안 읽었을 뿐이다.**

### 2.1 ★★그리고 **상수가 아니다** — 곡선의 모양이 다르다

| step | `mC_cla1_ag4_r20nc`(R=2) | `eq_d8_r60`(R=6) |
|---:|---:|---:|
| 100 | **+0.934** | **+1.784** |
| 500 | +0.811 | +1.793 |
| 900 | +0.639 | +1.716 |
| 1300 | +0.439 | +1.500 |
| 1700 | +0.209 | +1.227 |
| 2100 | +0.234 | +1.221 |

🚫★★**편차가 학습 중 3~4배로 줄어든다.**
→ **오프셋 하나를 빼서 고칠 수 없다.** ★**mis-eval 된 곡선은 진짜 곡선보다 가파르다** —
*"재귀 모델이 늦게까지 계속 좋아진다"* 처럼 보이는데 **그 개선의 일부는 계측 편차가 걷히는 것**이다.

★**해석**: 학습 초기에는 20방문 함수와 36방문 함수가 아주 다르고(가중치가 아직 재귀에 안 맞음),
학습이 진행되며 **층이 "반복돼도 되는" 표현을 배우면서 두 함수가 가까워진다.**
⚠️**이것은 그럴듯한 이야기이지 측정이 아니다.**

## 3. ★학습에 영향을 미치는가 — **경로별로 답한다**

| 경로 | 영향 | 근거 | 크기 |
|---|---|---|---|
| **손실 / 기울기 / 옵티마이저** | ✅**전혀 없다** | val 은 `torch.no_grad()` 이고 손실에 안 들어간다 | **0** |
| **LR 스케줄(WSD)** | ✅**없다** | `--sched wsd` 는 **스텝 기반**이고 val 을 안 본다 | 0 |
| **어닐 스케줄** | ✅**없다** | 스텝 기반 | 0 |
| ★**`best.pt` 선택** | 🚫**있다** | `is_best = m["val_loss"] < best_val - 1e-4` | ⚠️**아래 3.1** |
| ★**`--early-stop`** | 🚫**있다 — 그러나 휴면** | `since_improve` 가 같은 지표로 센다. **기본값 0 = 꺼짐**(`cli.py:116`) | **현재 0** |
| **EMA** | ✅없다 | 부가 표시일 뿐 | 0 |

### 3.1 ★`best.pt` 편향의 방향 — **늦은 스텝 쪽이다**

편차가 **단조 감소**하므로 mis-eval 된 val 은 **진짜보다 더 오래 개선되는 것처럼 보인다.**
→ `best_step` 이 **실제 최적보다 뒤로 밀린다.**

⚠️**실무 영향은 작다**: WSD 스케줄에서 **끝이 대개 최적**이고, 우리는 판정에
**`final` 을 쓰지 `best` 를 안 쓴다**(결과 015 이후 규약). ★**실측**: `mC_cla1_ag4_r20nc` 는
`best_step 2200` / `mC_cla1_ag4_r20` 은 `2289`(=끝) — **둘 다 끝 근처**다.

🚫★**그러나 `--early-stop` 을 켜는 순간 이것이 실질적 결함이 된다.**
편차가 계속 걷히므로 **`since_improve` 가 안 쌓이고 조기종료가 안 걸린다.**
→ ★**`--early-stop` 과 `--train-repeat` 를 함께 쓰지 않는다**(아래 §5 조치 3).

## 4. ★그래서 추가 실험이 필요한가 — **아니다. 두 가지 이유**

### 4.1 🚫**새 학습 런은 답을 안 준다**

이미 학습된 체크포인트를 **올바른 스케줄로 다시 평가하면** 그만이다.
그것이 `paired_eval --match-train-repeat` 이고 ✅**이미 구현돼 있고 이미 쓰고 있다.**

★**실측 대조**(결과 047 §14.5):

| | 값 |
|---|---:|
| 학습로그 `final` val (20방문) | 3.8170 |
| `paired_eval --match-train-repeat` (36방문) | **3.6760** |
| 차 | **+0.1410** |

→ ✅**판정은 이미 옳게 하고 있었다.** 🚫**틀린 것은 학습 중 인쇄값과 W&B 곡선뿐이다.**

### 4.2 ✅**대신 코드 수정이 필요하다 — ⚙0.5h**

| # | 조치 | 무엇이 좋아지나 |
|---|---|---|
| ★**1** | `_do_eval` 이 **학습된 스케줄로** 평가 | 곡선이 진짜가 된다. `best.pt` 편향 제거 |
| ★**2** | 두 값을 **함께** 인쇄 (`val@36 / val@20`) | ★**둘 다 정보다** — 20방문 값은 *"재귀 없이 배포하면"* 을 말한다 |
| **3** | `--early-stop` + `--train-repeat` 동시 사용 시 **경고** | §3.1 |

⚠️★**1 이 기존 런과의 비교를 끊는다**(함정 2). 그래서 **2 가 필수**다 —
새 필드 `val_loss_base`(20방문)를 남기면 **과거 런과 계속 비교할 수 있다.**

### 4.3 ⏸**"학습 시 재귀평가 결과를 반영" 은 지금 하지 않는다**

사용자 질문의 뒷부분(*"학습시 재귀평가 결과를 반영하는 것까지"*)에 대한 답:

| 반영 방식 | 판정 |
|---|---|
| **val 을 손실에 넣는다** | 🚫**절대 안 된다** — val 로 학습하면 val 이 val 이 아니다 |
| **val 로 R 을 조절한다**(적응 재귀) | ⏸**흥미롭지만 새 축**이다. 선결: §4.2-1 · P077 · 재귀 계열의 자(P052 단계3) |
| ★**val 을 올바른 스케줄로 재고 기록만 한다** | ✅★**이것을 한다**(§4.2) |

★**D1 규약**: *"미룬다" 고 쓸 때는 선결을 숫자로 적는다.*
**적응 재귀의 선결 = ⚙0.5h(§4.2) + 3.3h(재귀 자) + 2.6h(P077 단계1).**
🚫**그 자가 없으면 "R 을 조절해서 좋아졌다" 를 판정할 수 없다** — 지금 재귀 계열의 2σ 는 **미측정**이다.

## 6. ⚠️한계

- ⚠️**§2 의 92개 런은 `history` 마지막 점**만 봤다. 중간 점의 분포는 두 런만 봤다.
- ⚠️**§2.1 의 "왜 줄어드는가" 는 해석이지 측정이 아니다.** 층별 표현 유사도를 잰 적이 없다.
- ⚠️**`repeat_mode` 별로 다를 수 있다.** 전수의 대부분이 `uniform` 이다.
- 🚫**"편차가 0.3 을 넘으면 계측을 의심하라" 의 0.3 은 임의 값**이다(R12). 근거는 관례다.
- ★**부수 발견**(결과 047 §14.5): 학습로그 val 의 **양자화 눈금이 1/6400 = 0.00016** 이다.
  **타잉 자(0.0010)의 1/6** 이라 **자 근처 판정에 학습로그 val 을 쓸 수 없다** —
  이것은 재귀와 무관하게 **모든 런에 해당**한다.
