# 초소형 LLM 의 지능검사 — **벤치마크 검토 및 조사 결과서**

> **작성 2026-09-04**(사용자 지시) · 계획 [`P085`](../test_plan/P085_초소형LLM-지능검사-벤치마크.md)
> 물음: *"모델의 실제 지능을 loss나 bpb만으로 볼 수 없다면 모델의 좋고 나쁨을 비교하기 위해서는
> **반드시 벤치마크도 함께 비교해야 하는 것이 아닌지** 검토바라며, 우리 모델의 성능을 비교할 수
> 있는 **적절한 벤치마크도 조사**할 것."*

---

## 0. 결론 — 네 줄

1. ★★**그렇다. 벤치마크를 함께 봐야 한다.** 압축률 지표(loss·bpb)만으로 서열을 매긴 판정이
   **이 저장소에서 이미 두 번 뒤집혔다**(§1).
2. 🚫★**그러나 "벤치마크를 붙였다" 가 "답을 얻었다" 가 아니다.** 지금 우리 벤치마크는
   **검정력이 모자라** 0.04 nats 급 차이를 못 읽는다(§2).
3. ★**그래서 판정은 3층으로 나눈다** — ①압축률(서열의 후보를 만든다) ②다운스트림(그 서열을
   **반증**한다) ③배포 상주(**동률일 때 이긴다**). **셋을 한 표에 함께 적는다**(§4).
4. ★**한국어 축은 지금 비어 있다.** 외부 후보를 조사했고 **KoBEST 계열이 유일하게 우리 급**이다.
   KMMLU·HAE-RAE 는 **전문가 시험 난도**라 우리 모델이 우연에 붙는다(§3.3).

---

## 1. ★왜 loss·bpb 만으로는 안 되는가 — **우리 실측 두 건**

### 1.1 full-val 이 이겨도 다운스트림에서 진다 (결과 067 §12.5)

| | full-val | hellaswag | piqa | arc_easy |
|---|---:|---:|---:|---:|
| `d12_cla2_r20` (32 MiB) | 3.6054 | **29.8** | 56.0 | 39.0 |
| `d16_cla2_r20` (40 MiB) | ★**3.5642**(−0.0412 = 자의 23배) | 🚫**27.5** | 55.2 | **39.8** |

★**정답 CE 는 방향이 맞다.** 어긋나는 것은 **argmax 정확도**다.

### 1.2 같은 체크포인트에서 bpb 의 **부호가 뒤집힌다** (결과 053 §12)

| 채점 지문 | 무KD − KD | 승자 |
|---|---:|---|
| 우리 학습 분포(ko-en val) | −0.00766 nats | 무KD |
| 외부 영문(SQuAD context) | ★**+0.0367 nats** | 🚫**KD** |

★**바뀐 것은 채점 지문뿐**이다. **압축률은 "어느 텍스트에 대한 압축률인가" 를 빼면 무의미하다.**

### 1.3 ★그래서 무엇이 문제인가 — **한 문장으로**

> **loss·bpb 는 "이 모델이 *이 분포를* 얼마나 잘 압축하나" 를 잰다.
> 우리가 알고 싶은 것은 "이 모델이 *쓸 만한가*" 다. 둘은 같은 양이 아니다.**

⚠️**다만 압축률을 버리자는 것이 아니다.** 압축률은 **연속값이고 분산이 작아** 0.002 급을 읽는다.
다운스트림은 **이산값이고 분산이 커** 0.04 급도 못 읽는다(§2). ★**둘은 역할이 다르다.**

---

## 2. 🚫벤치마크도 만능이 아니다 — **검정력이 먼저다**

결과 050·067 §12.5 실측:

| 무엇 | 값 |
|---|---:|
| 정답 CE 의 **필요 N**(SE 0.002 기준) | **5,275 ~ 5,816** |
| 현재 다운스트림 n | **400** |
| n=400 정확도 **95% CI** | 약 **±5pp** |
| ★**보이는 경계** | **0.08 nats 급은 보이고 0.04 급은 안 보인다** |
| KorQuAD 정답 CE 필요 N(결과 050) | 🚫**244,040** — dev 는 5,774 문항뿐 |

★★**벤치마크를 고를 때 첫 질문은 *"이 과제가 무엇을 재나"* 가 아니라
*"이 과제로 0.01 짜리 차이를 몇 문항에 잴 수 있나"* 다.**

## 3. ★조사 — 우리 급에 쓸 수 있는 벤치마크

### 3.1 우리 조건 (후보를 거르는 필터)

| 조건 | 함의 |
|---|---|
| **100M 급 base LM** | 대부분의 벤치마크가 **1B+ 를 전제**한다 |
| ★**SFT 를 한 적이 없다** | **생성형·지시형은 0 에 가깝다.** 그것이 정상이다 |
| **코퍼스 ko-en 300M 토큰** | 전문 지식 과제는 **학습량 자체가 없다** |
| ★**어휘 32,768 자체 BPE** | 영어 고유명사가 **긴 subword 열**로 쪼개진다 |
| ★★**재려는 차이 0.003~0.03 nats** | **지표 분해능이 그보다 좋아야 한다** |

### 3.2 영어 — **이미 구현된 16종의 판정**(방법론 [10 §0.0](methods/10_benchmarks.md))

★**판정 축은 "수행 가능한가"** 이고, 서열 판정력은 **따로** 적는다.

| 과제 | 수행 | 서열 판정력 | 비고 |
|---|---|---|---|
| ★**hellaswag** | ✅ | ★**상대적으로 좋다**(25.8~33.7%) | **우리 주력** |
| ★**piqa** | ✅ | ★좋다(50.7~56.7%) | 우연 50 |
| ★**arc_easy** | ✅ | ★좋다(34.8~39.8%) | 우연 25 |
| arc_challenge · winogrande · mmlu · mmlu_redux | ✅ | ⚠️낮다(우연 근처) | **수행은 된다** |
| boolq | ✅ | ⚠️주의 | ★기준선이 50 이 아니라 **다수결 62** |
| lambada | ✅ | ⏳미판정 | 적재 5,153 |
| gsm8k · ifeval | ✅ | 🚫지금은 0 | **SFT 없음 — 정상이다** |
| 🚫**musr** | **수행 불가** | — | 지문 약 1,000단어 → **길이 초과로 대부분 제외**. **잘못 수행 = 수행 불가** |
| 🚫**bfcl_v3** | **수행 불가** | — | 적재 실패(우회 미구현) |
| ⏸humaneval 계열 | 대상 아님 | — | **생성 코드를 실행하지 않는다**(정책) |

### 3.3 ★★한국어 — **지금 비어 있다.** 외부 후보 조사

⚠️★**조회 표시**: 아래는 2026-09-04 웹 검색으로 **서지만 확인**했다.
🚫**데이터를 내려받아 우리 harness 로 돌려 본 것은 하나도 없다.**

| 후보 | 무엇 | ★우리에게 | 근거 |
|---|---|---|---|
| ★★**KoBEST** | 추론 중심 다지선다(BoolQ·COPA·WiC·HellaSwag·SentiNeg 계열) | ★**유일하게 우리 급**이다 — **우도 채점이 가능한 짧은 다지선다**이고 상식·인과가 대상이라 **300M 토큰으로도 우연을 넘을 여지**가 있다 | ⚠️**서지 미조회**(HRET 문서에서 이름만 확인) |
| **HAE-RAE Bench** | 한국어 **지식의 깊이**를 잰다(이해·추론이 아니라) | 🚫**우리 코퍼스에 그 지식이 없다.** 우연에 붙을 것 | ✅[arXiv:2309.02706](https://arxiv.org/html/2309.02706) |
| **KMMLU** | **전문가 수준** 4지선다 **35,030문항 · 45과목**. ★번역이 아니라 **한국 원시험**에서 수집 | 🚫**난도가 우리 급이 아니다.** ⚠️**단 문항 수 35,030 은 §2 의 필요 N 을 유일하게 넘는다** — 나중에 모델이 커지면 1순위 | ✅[HF 데이터셋](https://huggingface.co/datasets/HAERAE-HUB/KMMLU) |
| KMMLU-Pro / Redux | KMMLU 의 전문 직역 확장 | 🚫더 어렵다 | ✅[arXiv:2507.08924](https://arxiv.org/pdf/2507.08924) |
| CLIcK · HRM8K · KorMedMCQA | 문화·수학·의학 | 🚫**전부 우리 범위 밖** | ⚠️이름만 확인 |
| **HRET** | 위 벤치마크들을 묶은 **평가 툴킷**(HF 백엔드) | ⚠️**우리 harness 와 채점 규약이 다르면 수치가 안 맞는다** — 붙이려면 **규약 대조가 선결** | ✅[arXiv:2503.22968](https://arxiv.org/html/2503.22968) |

#### ★결론 — 한국어는 **KoBEST 를 1순위 후보**로 둔다

근거 셋: ①**우도 채점이 되는 짧은 다지선다** ②**상식·인과** 라 300M 토큰에서도 신호가 날 여지가
있다 ③**번역체가 아니다.** 🚫**단 문항 수가 우리 필요 N(5,275~5,816)에 미치는지 미확인**이다.

⚠️**우리 자체 held-out 은 지금 쓸 수 없다** — 정답 후보가 거짓인 문항이 **최대 28건**이고
**v2.1~v2.4 에서 고쳐진 적이 없다**(결과 068 §12, 작업지시서 발행됨).

### 3.4 🚫**우리 학습 스트림과 겹치는 것은 벤치마크가 아니다**

| 후보 | 왜 못 쓰나 |
|---|---|
| **KorQuAD** | ★**우리 학습 스트림의 94.8%**(결과 060 §7). **공통 원문·벤치마크로 쓰지 않는다** |
| SQuAD train(공통 원문) | ⚠️**8.7%(348/4,000)가 우리 스트림과 축자 겹친다.** 우리 모델끼리는 공통 상수라 유효하지만 **외부 모델과 절대 bpb 비교는 무효** |
| 우리 val | 정의상 같은 분포다 — **압축률 지표이지 벤치마크가 아니다** |

## 4. ★★권고 — **판정을 3층으로 나눈다**

| 층 | 무엇 | 역할 | 분해능 |
|---|---|---|---|
| ★**①압축률** | `paired_eval` full-val · 공통 원문 bpb | **후보 서열을 만든다.** 값이 싸고 분산이 작다 | **0.0006~0.0021**(계열별 자) |
| ★**②다운스트림** | hellaswag · piqa · arc_easy (+한국어는 KoBEST 후보) | ★**그 서열을 반증한다.** 확인이 아니라 **반증**이 역할이다 | ⚠️**0.08 nats 급까지만** |
| ★**③배포 상주** | `mem_runtime.py`(모델·KV dtype·컨텍스트 명시) | **동률일 때 이긴다.** 1순위 목표 | 산술 |

### 4.1 ★쓰는 법 — 규칙 넷

1. ★**압축률만으로 "더 낫다" 고 쓰지 않는다.** 반드시 다운스트림 열을 **함께** 적는다.
2. ★**둘이 어긋나면 그것을 적는다.** 🚫**평균내지 않는다.** 결과 053 §12 가 선례다.
3. ★**압축률을 인용할 때 "어느 텍스트에 대한 압축률인가" 를 함께 적는다**(우리 val / 외부 영문).
4. ★**다운스트림이 자기 검정력 밖이면 "판정 불가" 라고 쓴다.** 🚫*"차이 없음"* 이 아니다.

### 4.2 지금 해야 할 것 — **순서**

| 순 | 무엇 | ⚙ | 계획 |
|---:|---|---:|---|
| ★**1** | **n=5,000 재측정** — §1.1 의 역전이 진짜인지 | **0.7h** | P085 Stage1 (배치 있음) |
| **2** | held-out **28건 수정** — 한국어 축을 되살린다 | 1~2h(GPU 0) | 작업지시서 발행됨 |
| **3** | 외부 5모델 동일 채점기 대조 | 1h + 어댑터 1h | P085 Stage2 |
| **4** | **KoBEST 적재·검정력 조사** | ⚙0.5h(학습 0) | ⏳제안 전 |

## 5. ⚠️이 문서의 한계

- 🚫**KoBEST 를 내려받아 돌려 보지 않았다.** *"1순위 후보"* 는 **설계 판단이지 측정이 아니다.**
- ⚠️**§3.3 의 서지 중 KoBEST·CLIcK·HRM8K·KorMedMCQA 는 이름만 확인**했다(HRET 문서 경유).
- 🚫**HRET 툴킷의 채점 규약을 우리 것과 대조하지 않았다** — 수치가 맞을지 모른다.
- ⚠️**§4 의 3층 체계는 이 저장소의 실측에서 나온 것**이고 외부 표준이 아니다.
- 🚫**"지능" 을 정의하지 않았다.** 이 문서가 다루는 것은 **판정 가능성**이지 지능의 정의가 아니다.
