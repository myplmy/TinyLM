## 0. ★★우리 조건이 먼저다 — **왜 대부분의 벤치마크가 안 맞는가**

| 우리 조건 | 함의 |
|---|---|
| **100M 급 base LM** | 대부분의 벤치마크가 **1B+ 를 전제**한다 |
| ★**SFT·instruction tuning 을 한 적이 없다** | **생성형·지시형 과제는 전부 0 에 가깝다** |
| ★**코퍼스가 `ko-en` 300M 토큰** | 영어 지식 과제는 **학습량 자체가 없다** |
| ★**어휘 32,768 · 자체 BPE** | 영어 고유명사가 **긴 subword 열**로 쪼개진다 |
| ★★**재려는 차이가 0.003~0.03 nats** | ★**지표의 분해능이 그보다 좋아야 한다** |

> ★★★**마지막 줄이 이 문서의 핵심이다.**
> 결과 050 이 실측했다 — **KorQuAD 정답 CE 는 필요 N 이 244,040 문항**이었다.
> **KorQuAD 1.0 dev 는 5,774 문항뿐**이다. → 🚫**그 지표로는 우리 레버를 못 잰다.**
>
> **벤치마크를 고를 때 첫 질문은 *"이 과제가 뭘 재나"* 가 아니라
> *"이 과제로 0.01 짜리 차이를 몇 문항에 잴 수 있나"* 다.**

## 1. ★평가 방식 세 갈래 — **우리가 쓸 수 있는 것은 둘**

| 방식 | 무엇 | 우리에게 |
|---|---|---|
| ★**A. 우도 채점**(likelihood scoring) | 후보 문자열의 조건부 로그우도를 비교 | ✅**쓸 수 있다.** base LM 이 정당하게 할 수 있는 일 |
| ★**B. 조건부 CE** | 정답 문자열의 CE 를 잰다(연속값) | ✅**쓸 수 있다.** 단 분산이 크다(결과 050 §1.2) |
| **C. 생성 채점**(EM/F1/pass@k) | 모델이 답을 **생성**하고 채점 | 🚫**전부 0.** SFT 없이는 무의미 |

### 1.1 ★★A 의 정규화 — **우리가 두 번 틀렸다**

| 규약 | 편향 |
|---|---|
| **합 로그우도** | 🚫**짧은 라벨이 이긴다** |
| **평균 로그우도**(길이 정규화) | 🚫★**긴 라벨이 이긴다** — 뒤 토큰이 예측 가능해 평균을 끌어내린다 |
| ★**PMI 정규화** `log P(y\|x) − log P(y)` | ✅**라벨 사전확률을 뺀다** |

> ★★**결과 050 §4 가 그 사고다** — NLI 에서 **여섯 모델이 전부 32.2%** 였고
> 그 값이 **neutral 라벨 비율과 정확히 일치**했다. **모두 항상 "알 수 없다" 를 골랐다.**
> 외부 검토문서는 **합 규약의 편향만** 경고했고 우리는 **반대편으로 넘어갔다.**
> → ★**규약: 라벨 우도 과제는 PMI 정규화를 기본으로 한다.**
>
> ⚠️★**"PMI 정규화" 는 통용되는 이름이나 원 논문을 조회하지 않았다.** 근거로 인용하지 않는다.

### 1.2 ★★퇴화 감지는 **필수다**

**한 라벨이 90% 이상 선택되면 정확도를 읽지 않는다.**
결과 050 에서 도구가 **경고 한 줄 없이 표를 찍었다.**
✅**2026-08-22 부터 `eval_korean_bench.py` 가 선택 분포를 인쇄하고 90% 초과면 퇴화로 표시한다.**

## 2. ★★지표의 분해능 — **이 표가 채택 여부를 정한다**

| 지표 | 우리 실측 SD | 100문항 SE | ★**0.01 을 재는 데 필요한 N** |
|---|---:|---:|---:|
| ★**우리 val full-val**(1464 크롭, paired) | 0.46 | — | ★**이미 SE 0.0005** |
| **KorQuAD 정답 CE**(paired) | **0.41~0.96** | **0.041~0.097** | ★**최대 244,040** |
| **YNAT 정확도**(500문항) | — | 약 2.2%p | ★**시드 노이즈 3~5%p 가 더 크다** |

> ★★**우리 val 이 압도적으로 좋은 자다.** 1464 크롭에 paired 라 **SE 0.0005** 다.
> **외부 벤치마크는 그 근처도 못 간다.**
>
> → ★★**외부 벤치마크의 역할은 "서열 매기기" 가 아니라 "val 이 놓치는 축이 있는가" 다.**
> 결과 050 §2.1 이 그 예다 — **YNAT 순위가 full-val 과 정반대**였다.
> ⚠️**단 시드 노이즈 대비 1.8:1 이라 아직 증거가 아니다** → **문항이 아니라 시드를 늘린다.**

## 3. ★후보 벤치마크 — **조회한 것만**

⚠️★**아래 arXiv id 는 이 문서를 쓰며 조회하지 않았다.** 통용되는 식별자를 적어 두되

## 5. ★★★가장 중요한 설계 판단 — **문항이 아니라 시드**

결과 050 이 두 가지를 동시에 보였다:

| 관측 | 함의 |
|---|---|
| KorQuAD CE 필요 N = **244,040** | **문항을 늘려서 해결되지 않는다**(dev 가 5,774) |
| YNAT 시드쌍 차이 **3~5%p** vs 모델 간 최대 **9%p** | ★**신호대잡음 1.8:1** |

> ★★**즉 외부 벤치마크의 병목은 문항 수가 아니라 학습 시드다.**
> **모델당 2시드 이상**이 아니면 **어떤 순위 주장도 못 한다.**
> ⚠️**그리고 시드를 늘리는 비용은 문항을 늘리는 비용보다 훨씬 크다**(런당 1.8h).
>
> → ★**현실적 전략**: **외부 벤치마크로 "서열" 을 말하지 않는다.**
> **"우리 val 과 방향이 다른가" 만 본다.** 그건 시드 2개로도 볼 수 있다.

### 6.2 ⚠️0a-1 은 **미완**이다 — 숨기지 않는다

🚫**"공식과 같다" 고 주장하지 않는다** — 규약 2(공식 metric 이름을 우리 지표에 쓰지 않는다)를 지킨다.

## 8.3 ★★★가장 중요한 것 — **HF 캐시가 작업폴더 밖으로 갔다**

사용자 보고: *"작업 경로 내 HF 폴더에 다운로드되지 않고 **환경변수의 HF 캐시폴더로**

로그가 그것을 보여 준다:

```
UserWarning: ... your machine does not support them in Z:\unsloth_files\cache\datasets--Rowan--hellaswag
```

### ★원인 — **리다이렉트는 있었는데 실행되지 않았다**

`tinylm/paths.py` 는 **import 부작용**으로 HF 캐시를 작업폴더 `HF/` 로 **강제**한다:

```python
os.environ["HF_HOME"] = str(HF_DIR)
os.environ["HF_HUB_CACHE"] = str(HF_DIR / "hub")
os.environ["HF_DATASETS_CACHE"] = str(HF_DIR / "datasets")
```

🚫**그런데 `fetch_bench_data.py` 는 `sys.path` 만 건드리고 `tinylm` 을 import 하지 않았다.**
→ **그 부작용이 한 번도 일어나지 않았다.**

★★**함정 37 의 다른 얼굴**이다 — *"리다이렉트가 존재한다 ≠ 그 경로가 실행된다."*
그리고 **조용한 실패**였다: 다운로드는 성공했고 에러도 경고도 없었다.

### ✅조치 3중

| # | 무엇 | 층 |
|---|---|---|
| **1** | `fetch_bench_data.py` 상단에 ★**`import tinylm`**(datasets 보다 먼저) | 코드 |
| **2** | 실행 시 ★**`HF_HOME`·`HF_DATASETS_CACHE`·저장 위치를 먼저 인쇄**하고, 작업폴더 밖이면 **중단**(exit 3) | 런타임 |
| **3** | ★**`scripts/check_hf_redirect.py` 신설** — `scripts/*.py` 중 `datasets`·`transformers`·`huggingface_hub` 를 쓰면서 `tinylm` 을 import 안 하면 **정적 에러**. `check_static_all` 에 편입(12종) | 정적 |

🚫★**사용자 환경변수는 영구 수정하지 않는다**(사용자 지시). 위 셋 다 **프로세스 안에서만** 바꾼다.
