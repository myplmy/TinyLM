## 1. ★★GSQ — **우리 삼진 파라미터화와 같은 식을 쓰는데, 배우는 방법이 다르다**

- arXiv:2604.18556v2 (2026-05-15) · ISTA · Red Hat AI · ETH Zürich · 코드 `github.com/IST-DASLab/GSQ`
- ★**읽은 범위**: 초록 · §1 서론 · §2 관련연구 · §3 방법(3.1 삼진 · 3.2 일반 · 3.3 구현) · §4.1 실험설정.
  ⚠️**§4.2 이후 전체 결과표와 부록은 안 읽었다** — 아래 수치는 초록·§1·§4.1 에서만 인용한다.

### 1.1 무엇을 하는가

레이어별 재구성을 ***미분가능한 이산 배정 문제***로 다시 쓴다. 가중치 좌표마다
**후보 격자점 위의 학습 가능한 로짓**을 두고 **Gumbel-Softmax 로 soft 양자화값**을 얻는다.
온도를 어닐하면 soft 배정이 격자점으로 붕괴해 **완전 이산**이 된다.
그룹 스케일과 이산 배정이 **함께** 최적화된다.

### 1.2 ★★★우리와 정확히 겹치는 자리 — **§3.1 삼진 케이스**

논문의 삼진 제약(식 2):

    C_ternary = { ŵ = s · m ⊙ b ;  s ∈ ℝ,  m ∈ {0,1}^d,  b ∈ {−1,+1}^d }

★**우리 `ternary.py` 의 파라미터화와 같다** — 마스크(0 여부) · 부호 · 스케일 α.
그리고 그룹 규약도 같다: **symmetric · group-wise · 그룹 크기 128** (§4.1) =
우리 `micro_group=128` 과 **정확히 일치**.

★**그런데 배우는 방법이 다르다**:

| | 우리(현행) | GSQ |
|---|---|---|
| 이산 결정 | **STE**(hard threshold + 직통 그래디언트) | ★**Gumbel-Softmax**(로짓 2d개를 학습) |
| 시점 | ★**from-scratch QAT** | 🚫**PTQ**(이미 학습된 fp16 모델을 압축) |
| 초기화 | TWN 임계 | **GPTQ 삼진 해에서 warm-start** |
| 옵티마이저 | AdamW(또는 Muon) | ★**Lion** — Gumbel 포화에서 **AdamW 가 멈추기 때문** |

### 1.3 ★가져올 수 있는 것 넷

| # | 무엇 | 왜 우리에게 값이 있나 | ⚙비용 |
|---|---|---|---:|
| ★**1** | **STE → Gumbel-Softmax 로 이산 결정을 학습** | 우리 삼진 대가는 **아직 정면으로 안 줄여 봤다.** STE 는 1990년대 도구이고, 논문은 *"ternary GSQ 가 **2비트 스칼라 기준선 전부를 이긴다**"* 고 보고한다 | 구현 ⚙1.5h + 학습 1.4h |

| # | 무엇 | 왜 |

### 1.5 ⚠️정직한 위험 셋

1. ★★**논문의 이득은 "PTQ 가 STE-QAT 를 따라잡는다" 는 것**일 수 있다. 우리는 **이미 QAT** 다 —
   🚫**그러면 얻을 것이 없다.** 논문은 QAT(EfficientQAT)를 §2 에서 언급만 하고 **직접 비교하지 않는다.**
2. ⚠️**우리 기준선이 좋다는 것이 이미 한 번 손해였다** — Sherry 3:4 때도 *"논문의 이득 원천은
   과희소 회피인데 우리 TWN 은 이미 46.57%"* 라 이득이 없었다(2026-09-06). **같은 형태가 재발할 수 있다.**
3. ⚠️**Gumbel 포화**(§3.3 Optimizer) — AdamW 가 멈춘다고 논문이 직접 말한다.
   🚫**우리는 Muon 승격을 검토 중**이고 **Muon × Gumbel 은 아무도 안 해 봤다.**

## 2. RCO — **정확한 예산 아래 배정을 최적화한다. 그런데 우리 목적함수는 평평하다**

- arXiv:2605.00649v2 (2026-05-07) · ETH Zürich · IST Austria · 코드 `github.com/IST-DASLab/RCO`
- ★**읽은 범위**: 초록 · §1 서론 · §2 예산 다양체(명제 1~3) · Figure 1·2.
  ⚠️**§3(알고리즘 전체)·§4(실험)·부록은 안 읽었다.**

### 2.1 무엇을 하는가

N 개 그룹(예: 층) 각각에 K 개 옵션(예: 비트폭) 중 하나를 배정하되 **총비용 = 예산 B 를 정확히**
만족시킨다. 소프트맥스 확률 `p_i = softmax(α_i)` 로 배정을 완화하면 제약면
`{C(α) = B}` 이 **깨끗한 리만 다양체**가 된다:

- **닫힌 형태 법선** `(∇C)_ik = w_i·p_ik·(c_k − E[c])` → 접선 사영이 **내적 한 번**
- **단조 되돌림** — 로짓을 비용벡터 방향으로 밀면 기대비용이 **단조 증가**하므로 이분탐색이 지수 수렴
- **싼 수송** — 여차원 1 이라 모멘텀 재사영도 내적 한 번

→ 표준 Adam 스텝을 이 셋으로 감싼다. **제약 하이퍼파라미터가 없다**(페널티 λ 튜닝이 사라진다).

### 2.2 ★우리 문제와 형태가 정확히 같다

우리는 **32 / 40 MiB 예산**이 있고 층마다 선택지가 있다(타잉할지 · KV 를 소유할지 · 몇 bpw 로 저장할지).
**RCO 가 푸는 문제가 바로 그것**이고, 우리는 지금 그것을 **균일하게** 정하고 있다.

### 2.3 🚫★★그런데 우리 실측 셋이 "배정은 자유다" 라고 말한다

| 실측 | 무엇을 말하나 | 근거 |
|---|---|---|
| **불균등 타잉 종결** | `mlp_split` 경계를 12/4 · 2/14 · 4/12 로 바꿔도 **3.62375 / 3.62703 / 3.62781** = 균등 3.62672 와 **전부 자 안** | 결과 041 계열 |
| **KV 엔트리 단가가 어디서나 같다** | 머리·꼬리를 푸는 것과 몸통을 묶는 것이 **0.00440 vs 0.00375**(15% 안) | B.16.2 |
| ★**타잉 가격은 "지운 개수" 로 정해진다** | MLP 첫 걸음 0.001873 vs 어텐션 첫 걸음 0.001946 = **4% 안** | [타잉 재평가](../20260908_타잉-세-축의-역할과-가격-재평가.md) §3.3 |

★★★**셋 다 같은 말이다: 우리 손실은 "어느 그룹에 배정하느냐" 에 거의 반응하지 않고
"총량" 에만 반응한다.** 🚫**RCO 는 배정을 최적화하는 도구이고, 우리 배정은 이미 평평하다.**

### 2.4 ⚠️그리고 선결이 하나 더 있다

RCO 를 쓰려면 **층마다 다른 옵션이 실재**해야 한다. 우리는 지금:

## 3. ★★★Kimi K2 — **MuonClip · 리라이팅 · 희소도**

- Moonshot AI 기술보고서 `KIMI K2 OPEN AGENTIC INTELLIGENCE` · 1.04T MoE(활성 32.6B) · 15.5T 토큰
- ★**읽은 범위**: §2.1 끝(Algorithm 1 MuonClip · Figure 2·3) · §2.2 데이터 리라이팅(Table 1 · Figure 4) ·
  §2.3 아키텍처(Table 2 · Figure 5·6) · §2.4 학습 인프라.
  ⚠️**§3 이후(포스트트레이닝·에이전트·평가) 전체와 부록 D 는 안 읽었다.**

### 3.1 ★★MuonClip 알고리즘 (원문 Algorithm 1)

```
1. Muon step:  M_t = μ·M_{t−1} + G_t
               O_t = NewtonSchulz(M_t) · sqrt(max(n, m)) · 0.2      ← "Match Adam RMS"
               W_t = W_{t−1} − η·(O_t + λ·W_{t−1})
2. QK-Clip:    각 어텐션 헤드 h 에서 forward 가 이미 계산한 S_max^h 를 본다
               if S_max^h > τ:  γ = τ / S_max^h
                                W_qc ← W_qc·√γ ,  W_kc ← W_kc·√γ ,  W_qr ← W_qr·γ
```

**τ = 100.** Figure 2: **QK-Clip 없이는 어텐션 로짓이 학습 중반에 1000 을 넘는다.**
있으면 100 에 붙어 있다가 **학습의 약 30% 지점부터 스스로 내려온다.**
Figure 3: 15.5T 토큰 전 구간 **스파이크 0**(스무딩·서브샘플링 없이).

### 3.2 🚫★★QK-Clip 은 우리에게 **불필요하다** — 같은 문제를 이미 다르게 막았다

`modules.py:53` — *"v5: q·k 내적 전에 **파라미터 없는 RMSNorm(QK-norm)** 으로 로짓 폭주를 막는다."*
`q_norm`·`k_norm` 이 각 헤드의 q·k 를 **노름 √head_dim 으로 고정**하므로

    |logit| = |q·k| / √head_dim  ≤  (√64 · √64) / √64  =  √64  =  8

★★**우리 어텐션 로짓은 구조적으로 8 이 상한**이다. Kimi 가 τ=100 으로 막으려던 것을
**우리는 아키텍처로 막았고, 더 세게 막았다.**

★★★**그리고 그 사실이 하나를 정정한다**: 2026-09-06 에 우리는
*"Muon ×30·×45 에서 `grad_max` 가 단조 증가하는데 `n_skip` 은 0 이니 천장은 발산이 아니라 품질"*
이라고 적었다. **Kimi 의 관찰은 그 천장의 흔한 원인이 어텐션 로짓 폭주라는 것**인데
🚫**우리에게는 그 경로가 닫혀 있다** → ★**우리 천장의 원인은 아직 모른다. 다른 데를 봐야 한다.**

## 4. ★★QK-Norm 원 논문 — **우리가 반쪽만 구현했다**

- **arXiv:2010.04245** · Henry, Dachapally, Pawar, Chen (Cyndx Technologies) · EMNLP 2020 Findings
- ★**읽은 범위**: 본문 5쪽 전부(§1~§5) + 참고문헌. **식 2·3·5**, Figure 1·2, Table 2·3.

### 4.1 무엇을 하나

| 식 | 내용 |
|---|---|
| (2) | `q̂ᵢ = qᵢ / ‖qᵢ‖` — **head 차원**으로 ℓ2 정규화 |
| (5) | `softmax(g · Q̂K̂ᵀ) V` — ★**학습 가능한 스칼라 `g`** |
| (3) | `g₀ = log₂(L² − L)`, L = 학습 시퀀스 길이의 97.5 분위 |

### 4.2 ★★논문 자신이 경고한 실패 모드 — **바로 우리 상태다**

> §3: 코사인 유사도는 [−1,1] 로 묶여 **"소프트맥스와 반대의 문제"** 를 만든다 —
> 값의 차이가 너무 작아 **주의하지 말아야 할 연결을 효과적으로 무시하지 못한다.**

그래서 `1/√d` 로 **나누는** 대신 학습 가능한 `g` 로 **곱한다.**

### 4.3 ★우리와의 차이 — **숫자 하나**

| | 논문 | 우리 |
|---|---|---|
| 정규화 | ℓ2 (head 축) | RMSNorm (head 축) — **같은 방향** |
| 스케일 | ★**학습 가능한 `g`**, `g₀ = 20.0`(L=1024) | 🚫**없다.** 고정 `1/√head_dim` → **유효 `g = 8`** |
| 로짓 범위 | 학습으로 넓힐 수 있다 | **[−8, +8] 하드** |

★**우리 유효 스케일은 논문 권장 초기값의 40%** 이고 **학습되지도 않는다.**

⚠️**단 산술로 반박도 된다** — 상한 8 에서도 T=1024 의 최대 어텐션 가중치는 **0.99988** 이라
원-핫이 도달 가능하다. ★**그래서 이 물음은 실측(`cosθ` 분포) 없이는 못 닫는다.**

### 4.4 판정

⏸**측정 대기.** 정본 보고서 = [`docs/20260908_QK-norm이-과도-상한인가-QK-Clip과의-대조.md`](../20260908_QK-norm이-과도-상한인가-QK-Clip과의-대조.md).
🚫**`g` 를 지금 넣지 않는다** — 넣으면 무엇을 고쳤는지 모른다. **M1 측정이 먼저다.**

### 4.5 ★★부수 — **`W_q`·`W_k` 는 스케일 불변이고, 그것이 Muon 천장의 후보다**

`q = RMSNorm(W_q x)` 이므로 손실이 `W_q` 의 **스케일에 정확히 불변**이다
(삼진화의 α 도 `mean(|w|)` 라 함께 스케일된다 → 이중으로 불변).
→ **Muon 팔의 wd 0**(기준표 B.23.6)에서 `‖W_q‖` 가 단조 증가하면
**유효 학습률이 `1/‖W‖²` 로 감쇠**한다. ★**발산이 아니라 조기 정지**이고,
그것은 `n_skip` 이 전 배수에서 **0** 인 관측과 맞는다. → 검정은 M2(보고서 §7).

## 6. TTPO — 다수결의 오류를 비대칭 업데이트로 제한하지만 지금 TinyLM 기본 학습에 넣지 않는다

- **논문**: Wang et al., [TTPO: Test-Time Policy Optimization](https://arxiv.org/abs/2608.27448), arXiv:2608.27448v1(2026-08-27). [저자 코드](https://github.com/ZJU-REAL/TTPO).
- **검토 원본**: `article/TTPO TEST-TIME POLICY OPTIMIZATION.pdf`(로컬, SHA-256 `D67E875FFC81FE065C02C0C02808F522653BA8DDAEC5E629507A3A5EE7FA7E22`). `mutool`로 본문 1~9쪽의 방법·결과·ablation, 12~13쪽 설정, 17쪽 한계를 읽었다. 미판독 부록·코드 구현은 결과 근거로 쓰지 않는다.
- **TinyLM 상태**: 모델 약105M, 현재 대화/SFT 경로는 학습 게이트 준비 단계이고 thinking-mode 교사·검증 가능한 64-rollout 수학 과제 계약은 없다. 보호 held-out을 학습 입력으로 사용하지 않는다.

### 6.1 원리와 실제 논문 증거

각 문제에서 `K=64`개 rollout의 최종 답을 추출해 다수결 pseudo-label로 나눈다. 다수결과 **같은 답**의 trajectory에는 답을 힌트로 받은 thinking-on 고정 교사의 분포를 non-thinking 학생에 forward KL로 증류한다(OPSD). **다른 답**의 trajectory에는 집단 상대 보상의 음의 advantage로 GRPO 패널티를 적용한다. 전자는 학생 entropy와 교사/학생 KL이 높은 위치에 가중, 후자는 이상 토큰 점수의 상위 절반만 벌한다. 이 두 분기는 같은 지도신호가 아니다.

논문 Fig.1/§3.2의 “pseudo-label이 틀려도 disagreeing rollout 약79%는 실제로도 틀림”은 **Qwen3-1.7B의 어려운 수학 TTT** 관측이다. 정답이 다수결과 다르다는 사실만으로 TinyLM의 자유 대화 답변을 자동 오답 판정할 근거는 아니다. 반대로 majority가 전부 틀린 문항에서 positive 증류는 참 정답을 가르치지 않고 **자기 답의 reasoning 스타일**을 모사한다.

논문 Table 2의 Qwen3-1.7B TTT 평균은 **38.0→45.2%**(AIME26/HMMT26/BRUMO25)이고 평가 단위는 **temperature1.0의 Avg@12**다. Table 1의 OpenThoughts 비교에서 TTPO와 정답 기반 OPSD는 1.7B **40.1 대39.7%**다. 전체를 “TinyLM 단일답 정확도 +7.2%p”로 복제하지 않는다. 같은 평가 benchmark 문제로 **라벨 없이 적응**한 TTT이므로, 우리 held-out 판정지에 직접 적용하면 독립 평가가 오염된다.

### 6.3 차용·보류·기각의 분리

| 부분 | 판정 | TinyLM에 맞는 후속 조건 |
|---|---|---|
| **오답 후보에만 보수적 패널티**와 token-level confidence 필터 | **개념 차용 가능**. 정답이 확인된 오답과 P090 rejected 자료가 있는 경우의 손실 설계 힌트 | 먼저 assistant-only SFT·정답/오답 검증·동형 부모 대조를 완성. 불확실한 다수결을 정답으로 쓰지 않음 |
| 다수결로 pseudo-label을 만들고 시험 문제 자체에서 모델 업데이트 | **현 시점 부적합**. 64개 생성의 품질·비용과 benchmark leakage가 가장 큼 | 학습·평가 분리된 공개 수학 데이터, 실제 pass@K/majority 정확도와 비용 측정 뒤만 연구 후보 |
| thinking 교사 조건부 OPSD + full-vocab KL 전체 | **즉시 구현 불가**. 원 논문의 핵심 teacher mode와 검증 가능한 답이 현재 없다 | 독립 teacher/학생 capability, full-vocab KL VRAM, 같은 입력 비교 조건이 먼저 |
| 논문의 +7.2%p / 대규모 무정답 수학 성과 | **TinyLM 예상효과로 사용 불가** | 모델 규모·시험지·평가단위·rollout 예산이 일치하지 않음 |

**즉시 적용 가능하면서 효과가 뛰어날 것으로 입증된 메커니즘은 현재 0건**이다. 따라서 이 요청의 “그런 메커니즘이 있으면 제안서” 조건은 충족하지 않아 **새 제안서는 작성하지 않는다**. P090 SFT·실제 정답 추출·독립 수학 패널에서 기초 정답률과 64-rollout 대비 소형 `K`의 비용을 확인한 뒤, 원안 전체가 아닌 **검증된 오답의 selective negative learning**을 별도 제안할 수 있다. 이는 현재 승인된 A/B/C 구현·M4/M5·SFT 게이트의 선결이 아니다.

### 7.1 백서가 실제로 제시한 메커니즘과 분모

| 항목 | 백서의 증거 | TinyLM에 주는 의미 |
|---|---|---|
| 모델 구조 | §2 표1: Qwen3.8-27B 계보, 언어 backbone 24.35B+embedding/head 2.54B, 별도 vision 0.47B; 약 75% linear attention | 우리 약100M·CLA/GQA/TLinear 구조와 다르다. Bonsai 가중치/회전 계수를 TinyLM에 복사하는 처방 아님 |
| 삼진 저장 | §2.1~2.3: `{-1,0,+1}`, group128 FP16 scale; 순수 삼진 약1.71bpw, 언어 전체 이론1.72bpw, PTQ1_0 1.76bpw/5.93GB, PQ2_0 2.16bpw/7.25GB | 저장 GB(10진)이지 TinyLM runtime MiB·RSS·KV·훈련 마스터가 아니다. 실제 패킹과 배포 지표를 분리 |

| 회전 basis | §2.4: block1024 Hadamard+고정 부호, 가중치는 회전 좌표에서 저장하고 활성값은 런타임 변환 | matrix별 padding/역변환·새 커널이 필요. 백서는 TinyLM의 처음부터 학습하는 TLinear와 같은 최적화/수렴 레시피를 명시하지 않음 |

백서 §2.3의 FP16 53.80GB 대비 5.93GB는 *언어모델 저장 파일* 약9.1배의 비교다. 별도 vision 0.63/0.93GB, KV cache, 활성값, 훈련 optimizer는 이 표의 분모 밖이다. TinyLM의 40MiB 배포 목표나 단일 CPU 15tok/s 목표를 27B의 파일 크기와 같은 눈금으로 판정하지 않는다.

### 7.2 성능과 계측: 높은 평균 뒤에 남는 실패 가족

백서 §4/부록 B·C는 H100의 vLLM/EvalScope 동일 경로에서 thinking `xhigh`, 20 benchmark 평균 **83.9 대 Qwen3.8 FP16 85.4**를 보고한다. 이는 백서가 정의한 평균의 98.2%이지 문항별 오류율·한국어 정확도·교사 답변 검증률의 98.2%가 아니다. `medium`은 별도 부록 C 표11에서 **79.3 대82.6**으로 비율도 다르다. 추가 agentic 과제는 Terminal-Bench 2.1 **52.8 대69.7**, SWE-bench Verified **60.8 대80.6**으로 평균 보존율과 다르게 약 3/4 수준이다. 수치는 모두 공급자 백서의 특정 harness·추론 budget 관측이며 TinyLM 전이효과가 아니다.

§3 표5의 RTX 4090에서는 PTQ1_0이 batch1 decode 96.7tok/s 대 PQ2_0 90.9tok/s이나 prefill은 1,634 대3,134tok/s로 반대다. 4070 Ti SUPER·WSL·단일 CPU에서 동일 우열은 미측정이다. 부록 D는 세 반복과 warm-up, `tg128/pp512`, depth0·batch1·vision 제외, NVIDIA board 전력과 Apple powermetrics의 분모 차이를 밝힌다. 회전 transform은 batch1 decode의 주요 부가비용이며 §5도 최적화 과제로 남긴다.

**버전 분리:** 현재 공급자 [모델카드](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf/blob/main/README.md)는 14 benchmark 평균 **84.78**, PTQ1_0 5.95GB/PQ2_0 7.21GB라고 적는다. 로컬 2026-09-17 생성 백서의 20 benchmark 83.9, 5.93/7.25GB와 평가 집합·포장 수가 다르다. 어느 쪽이 정정인지 확인 없이 병합·평균하지 않고 각 주장에 PDF SHA 또는 모델카드 revision·벤치 목록을 결합한다. HF 페이지의 자동 `:F16`/일반 llama.cpp 사용 예시는 [공식 데모 README](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/README.md)의 ‘Bonsai 2는 Hadamard-aware PrismML fork 필요’ 계약과 충돌한다. F16은 53GB급으로 이 프로젝트 16GB GPU 교사 후보의 저비트 실행 명령이 아니다. 설치·다운로드·실행은 이번 작업에서 `NOT_RUN`이다.

### 7.3 TinyLM 차용·보류·불가 판정

| 요소 | 분류 | 이유와 최소 후속 검증 |
|---|---|---|
| packed 직접 소비, decode/prefill 분리, 저장·상주·KV·RSS 별도 회계 | **타당·기존 축 보강** | P014D/P025B의 wall/event·실제 모델 결과를 같은 형상에서 비교. 커널보다 unpack/변환이 크면 같은 패킹도 속도 음성 |
| 민감한 소수 텐서를 높은 정밀도로 보존 | **개념 차용** | TinyLM TLinear/embedding/norm의 부위별 오류·상주 증가를 먼저 계측. Qwen hybrid recurrent 경로의 0.0976%를 목표 수치로 복사하지 않음 |
| 고정 Hadamard 회전 뒤 삼진화 | **개선 후에만 연구 후보** | 이미 학습된 FP32↔삼진 TinyLM의 같은 checkpoint·같은 정합/언어 평가와 회전/역회전·padding·decode wall을 분리. 백서에는 우리 from-scratch STE/optimizer 수렴 레시피와 개별 회전 ablation이 없음 |
| Bonsai 2 27B를 외부 텍스트 교사로 평가 | **개념 차용/조건부 pilot** | Apache-2.0 표시·실제 모델 revision·출력 이용 조건, PrismML fork/quant·template·reasoning effort, 16GB VRAM/KV와 accepted sample당 비용·한국어 검증 QA 정답률을 먼저 확인. 교사와 학생은 순차 실행하고 학생 checkpoint/보호 data 접근 없음 |
| 27B 수치·98.2%를 TinyLM 직접 품질/속도 향상으로 이식 | **사용불가** | 모델 규모·아키텍처·벤치/언어·runtime·분모가 다름. 27B packed 5.93GB가 TinyLM 40MiB 안에 든다는 해석도 불가 |
| 백서를 완전한 학습·커널 구현 명세로 취급 | **사용불가** | 공개 문서는 회전 정의·출력·runtime 개요를 제공하지만 훈련 목적/데이터/optimizer·커널 소스 정합을 충분히 고정하지 않음 |

현재 이 백서만으로 TinyLM에 **즉시 적용 가능하면서 큰 효과가 확인된 새 메커니즘은 0건**이다. 따라서 새로운 구현 제안서를 이 결과만으로 만들어 곧바로 기본 경로를 바꾸지 않는다. 최우선 재사용은 기존 P014D/P025B의 전체 호출 실측 계약, 그 다음은 사용자 별도 승인 아래 외부 교사의 **무힌트·독립 검증 pilot**이다. 후자는 본 백서가 TinyLM 증류 성공을 보인 것이 아니라 교사 후보를 비교할 이유를 준다는 뜻이다.

2026-09-25 사용자 후속 요청에 따라 위 세 차용군을 **즉시 기본 구현**이 아닌 [단계별 실험제안 B안 승인 진행](../../proposal/20260925_회전-삼진-민감도와-직접패킹-단계검증-제안서-approved-on-going.md)으로 분리했다. 동시 작성한 [Hadamard·삼진화 문헌조사](../20260925_Hadamard-회전과-삼진화-선행연구-적용성-조사.md)는 PTQ·QAT·배포 커널의 시작 조건과 TinyLM g128/CLA 차이를 비교한다. [P014E](../../test_plan/P014E_회전삼진-민감도와-직접패킹-단계게이트.md) G0 독립 수학 계약만 준비했고 새 백엔드/학습 효과는 여전히 `NOT_RUN`이다.

- 프로젝트 정본: [P093 결과086 §4](../../test_result/086_20260919_P093-회계상-R1은-남고-D1은-고계산이다.md), [P093 계획](../../test_plan/P093_구조조건부-직접공유와-완화타잉.md), [실제 근사 진단기](../../scripts/diag_sharing_parent_approx.py), [TLinear](../../tinylm/model/ternary.py), [MLP 구현](../../tinylm/model/modules.py). 체크포인트 내용을 새로 열거나 모델을 실행하지 않았다.

### 8.2 LittleBit의 실제 구조와 그대로 이식할 수 없는 부분

원래 선형층 `W`를 두 경로의 합 `W_hat = W_pri + W_res`로 바꾼다. 각 경로의 유효 가중치는 다음과 같다.

```text
W_pri = diag(h) · sign(U) · diag(l) · sign(V)^T · diag(g)
U: d_out×r, V: d_in×r
h: 출력 행 스케일, g: 입력 열 스케일, l: r개 잠재축 스케일
```

이진 인자는 저장 시 ±1, 스케일은 FP16이다. 학습에는 실수 잠재 인자를 유지한다. 실행 시 전체 `W_hat`를 펼치지 않고 두 작은 행렬곱과 스케일 곱을 계산한다. **가중치당 0.1bit라는 뜻은 원래 행렬 원소 수를 분모로 한 압축 회계**이지, 한 학습 파라미터를 0.1bit로 저장한다는 뜻이 아니다.

| 부품 | 원 논문의 방법 | TinyLM 적용 판단 |
|---|---|---|
| Dual-SVID 초기화 | `W`의 truncated SVD 인자를 얻고, 각각의 절댓값을 rank1 근사하여 `h/g/l`를 초기화 | 작은 복원층의 초기화 후보. 실수 잔차·실제 활성값 목적의 대조가 먼저 필요 |
| 잔차 경로 | 처음에는 `W − W_pri,0`를 대상으로 초기화하고, 이후 두 경로를 공동 학습 | tying 오차와 양자화 오차의 합을 겨냥하는 개념이 유용. 잔차를 공짜로 추가하는 방법은 아님 |
| 고정 비트 예산 | 큰 단일 경로의 예산을 더 작은 주경로/잔차 경로로 재배분 | 총 rank·스케일·패킹·runtime을 같은 예산으로 비교해야 함 |
| QAT 증류 | 사전학습 full-precision 원모델의 logit KL와 hidden MSE를 사용 | 동형 TinyLM의 동결 기준 함수가 필요. Gemma의 hidden/vocab을 그대로 맞춰 붙일 수 없음 |
| SmoothSign | forward는 hard sign, backward는 `100·(1−tanh²(100x))` | 현 삼진의 0 구간·두 임계와 다른 함수. 현 STE의 단순 대체재 아님 |
| 이진 전용 커널 | 저랭크 binary MatMul과 스케일을 직접 소비 | CPU·4070 Ti SUPER·작은 형상에 맞춘 별도 구현/상주/지연 검증 필요 |

부록 G는 Adam·cosine·warm-up 2%·sequence2048·5epoch, epoch당 약0.2B 수준의 QAT 자료와 다수 대형 GPU를 사용한다. 본문의 hidden MSE 계수10도 TinyLM의 기본값으로 채택하지 않는다. 큰 full-precision 모델 압축 결과는 약100M from-scratch 삼진·tying 모델의 복원 성공 증거가 아니다.

**수치상의 한계:** 표1의 Llama2-7B 0.55bpw PPL은 10.47로 FP16 5.47과 차이가 크고, 표2의 해당 상식 평균은 47.26 대62.97이다. 부록 B의 OPT1.3B 0.1bpw에서는 잔차가 있을 때 PPL60.011, 없을 때48.512로 오히려 나빴다. 낮은 예산에서 잔차를 나누는 전략이 항상 이기지 않는다. 부록 H의 11.6배는 A100·큰 GEMM 형상의 커널 비교이고, 전체 7B decode는 생성길이128/256에서 2.46/2.37배였다. 이를 TinyLM CPU의 속도 예상치로 사용하지 않는다. 저장 크기는 embedding/head·KV·활성값·학습 상태를 각각 다시 회계해야 한다.

### 8.3 기존 ‘소형 복원층 실패’의 정확한 범위

P093 Stage0c는 **복원층을 실제로 학습한 실험이 아니다**. `diag_sharing_parent_approx.py`는 부모의 실수 master 행렬을 group4 평균으로 공유하고, 차이를 rank4/8/16으로 `svd_lowrank(niter=3)` 근사했다. 입력은 표준 정규분포 128개이고 raw `F.linear`/SwiGLU 출력 오차를 쟀다. 실제 문장 활성값, native 삼진 forward, optimizer, CE, 학생 학습이 들어 있지 않다.

결과086에서 출력 NRMS는 평균 공유 0.98139 → rank16 0.97400, 약0.75% 감소뿐이다. 가중치 NRMS는 0.86499 →0.83956이다. 기존 최소10% 출력오차 개선/NRMS≤0.9 조건을 통과하지 못한 **유효 근사 음성**은 유지한다. 하지만 이를 모든 저랭크 복원 학습이 실패했다거나, 실제 활성값 보정의 여지가 없다는 증거로 확대하지 않는다.

**표현력 한계도 유지한다.** 같은 총 rank의 제약 없는 최적 SVD와 비교하면 이진 인자·잔차 분할이 Frobenius 최적 오차 하한을 없애지 못한다. 기존 `svd_lowrank`가 정확 SVD와 동일하다는 뜻은 아니지만, 새로운 알고리즘만 붙이면 rank16이 임의의 층 차이를 다 복원한다는 보장은 없다. 이진화의 주된 이점은 같은 저장 예산에서 더 큰 rank를 허용할 수 있다는 점이다.

### 8.4 tying 손실 복원을 직접 겨냥하는 개선 가설

권장 순서는 **실제 활성값 기반 실수 복원층 → 양자화한 복원층 → 예산 최적화**다. 아래는 미구현 가설이며 P093 결과를 소급 PASS로 바꾸지 않는다.

1. 동형의 untied 기준 모델을 동결하고, 일반 문장·한영·SFT train에서 해당 층의 실제 활성값 `X_i`와 기준 MLP/block 출력을 수집한다. 평가 문항·val은 보정에 사용하지 않는다.
2. 공유 중심을 단순 평균만으로 정하지 않고, 층별 실제 활성값의 중요도와 공유 후 함수 오차를 반영한다. 실수 잔차의 가중 SVD 초기화는 regularized `H=X^T X`와 별도 수치안정성 검사가 필요한 후보다.
3. 보정 목적을 `Σ_i ||f_ref,i(X_i) − f_shared+delta,i(X_i)||²`로 명시한다. SwiGLU 전체 출력부터 맞추고 필요 시 block 출력·동형 logit KL·CE를 단계적으로 추가한다. 행렬 오차 감소만으로 언어 품질 복원을 선언하지 않는다.
4. `W_ref,i − Q(W_shared)`처럼 **공유와 삼진화의 합성 오차**를 대상으로 한다. 양자화 전 공유 잔차만 맞춘 뒤 마지막에 삼진화하면 양자화 오차를 다시 만들 수 있다.
5. 행/열/잠재 스케일과 두 저랭크 인자를 조절하되, 기존 MLP scale/FiLM/mode delta와 중복인 자유도는 먼저 식별한다. 초기에 공유 본체를 동결해 복원층의 기여를 가르고, 이후 제한 해제를 별도 비교한다.

여기서 **GSQ**는 이산 마스크·부호·그룹 스케일을 재구성 목적에 맞추는 보정 수단이다. **LittleBit**는 잔차 초기화·스케일·직접 인자 실행의 구조 후보다. **RCO**는 이미 성능을 잰 rank4/8/16/32, FP/삼진/이진, 공유/비공유 옵션 중 예산을 배정하는 후단이다. 원래 공유 함수를 잘 근사하는 옵션이 없으면 RCO도 좋은 해를 만들어 내지 못한다.

LittleBit-2의 잠재 회전은 `(UR)(VR)^T=UV^T`를 보존하면서 인자를 이진 격자에 맞추는 초기화 후보다. Joint-ITQ는 두 인자를 함께 회전한다. 이는 잠재 rank를 늘리지 않고, input 전체에 런타임 Hadamard를 적용하는 방법과도 다르다. 회전은 초기화 인자에 흡수할 수 있지만 TinyLM에서 QAT 수렴·정답률 개선은 미측정이다. [LittleBit-2 §4.3~4.4](https://arxiv.org/html/2603.00042v2).

### 8.5 master 가중치와 삼진 품질: 서로 다른 세 문제

| 문제 | 검토 결론 | 필요 대조 |
|---|---|---|
| FP32 master 자체가 학습/tying으로 나빠진 경우 | 양자화기를 바꾸는 것만으로 잃은 지식을 복구하지 못함. 이전 동형 기준 함수·보정 자료·증류 목적이 필요 | 동결 원부모/native 함수 → 공유 실수 경로 → 공유 native 삼진 경로 |
| FP32 master를 BF16/저비트로 보관해 수치가 바뀌는 경우 | GSQ는 quantized 함수 오차를 줄일 수 있지만 저정밀 optimizer의 누적 오차 해결책은 아님 | master dtype·optimizer state dtype·배포 dtype를 별개 요인으로 고정 |
| 같은 master를 삼진 forward로 바꾸면서 생기는 손실 | GSQ의 mask/sign/scale 및 민감층별 잔차가 직접 겨냥할 수 있음 | master-only와 native-QAT 기준을 둘 다 보존하고 실제 CE/답안·저장/상주/지연 비교 |

현재 `TLinear.weight`는 학습 시 실수 Parameter를 갖고, 기본 forward는 삼진 STE 또는 그 cache를 사용한다. **dense 모델도 ‘MLP를 안 묶었다’는 뜻이지 모든 선형층이 FP16 forward라는 뜻이 아니다.** master-only 함수가 원래 학습된 삼진 함수보다 좋다고 가정하지 않는다. 기존 alpha는 임계·비영 원소 평균에서 계산되며, GSQ의 독립 학습 scale과 같지 않다.

**과거 §1 정정:** ‘fp16 원본이 전혀 없어서 PTQ 전체를 사용할 수 없다’는 단정은 너무 넓었다. 학습된 실수 master와 동형 native 기준 함수가 있으므로 **학습 후 블록별 보정**은 조건부 연구가 가능하다. 다만 검증된 FP16 언어모델을 그대로 압축하는 논문 설정과는 다르다. GSQ가 기존 from-scratch QAT보다 유리하다는 결론도 없다. Gumbel mask/sign/scale의 보조 로짓·optimizer 상태와 Lion/Muon 정합 비용은 새로 들어가며 accum16 자체만으로 같은 분산 감소·수렴을 보장하지 않는다. [GSQ §3](https://arxiv.org/html/2604.18556v2).

**과거 §2 보완:** 기존 `mlp_split`의 평평한 결과는 그 당시 옵션 집합에 대한 관측이다. 새 rank/정밀도/잔차 집합의 층별 효용이 평평하다고 입증하지는 않는다. RCO에는 연속 기대비용의 다양체 처리뿐 아니라 **이산 선택용 knapsack DP와 straight-through 경로**도 있다. DP의 비용 `O(N·K·B')`에서 예산단위를 1byte로 두면 40MiB조차 가벼운 계산이라고 단정할 수 없다. 옵션 단위·최대공약수·희소 DP 등과 최종 실제 byte 검산이 필요하다. 공유 본체는 한 번만 회계하고, KV/활성값/scale/adapter까지 포함해야 한다. [RCO §2~§3](https://arxiv.org/html/2605.00649v2).

### 8.6 저장·훈련·추론 추가비용의 계산 예

아래는 **d=768, MLP 폭 f=2048, rank r=16, 보정할 MLP 12개**를 가정한 계산이다. 현재 특정 체크포인트의 실제 모듈 수/메모리 측정이 아니다.

- gate/up/down 각각에 저랭크 인자 두 개를 붙이면 MLP당 `3r(d+f)=135,168` 파라미터다. FP32 한 벌은 **0.515625MiB**, 12개는 **6.1875MiB**다.
- 파라미터·gradient·Adam의 두 모멘트만 FP32로 세면 총 **24.75MiB**다. 활성값, 기준 모델, 공유 본체, scale, compiler cache는 포함하지 않았다. Muon의 상태 회계와도 다르다.
- 단일 binary 잔차에 FP16 행/열/rank scale을 포함하면 같은 가정에서 MLP당 **33,888byte**를 패킹할 수 있다. 학습용 FP32 인자를 함께 상주시킨다면 이 저장 절감이 runtime 절감으로 실현되지 않는다.
- full MLP 행렬 `2048×768`에 GSQ 삼진용 FP32 로짓 두 개/원소를 붙이면 **12MiB/행렬**이고, rank16 인자 `(2048+768)×16`에만 붙이면 **0.34375MiB**다. 둘 다 로짓만의 크기이며 gradient·optimizer 상태는 추가다.
- rank16 잔차의 선형곱 수는 원래 세 MLP 행렬곱의 약 **2.865%**다. 작은 GEMM 호출·scale·dequant·메모리 이동 때문에 wall 증가가 같은 2.865%라는 뜻은 아니다.
- 두 binary 경로의 rank를 `r_p/r_r`라 하면 저장 bit는 대략 `(r_p+r_r)(d_in+d_out)+32(d_in+d_out)+16(r_p+r_r)`다. padding·format metadata는 별도다. 두 경로가 각각 r이면 `2r(d_in+d_out)+32(d_in+d_out)+32r`다.

### 8.7 구현·보정·학습 비용: 범위와 미계측을 분리

개발 시간은 **계획용 추정 범위**이며 실제 작업 실측이나 완료 약속이 아니다. GPU 시간은 아직 benchmark가 없으므로 **첫 비용 게이트에 둘 실행 예산 후보**다. 서로 의존하는 행을 무조건 더하거나 모든 방법을 동시에 적용하지 않는다.

후보 보정 비용은 `모듈 수 N × 옵션 수 K × 보정 반복 S × 실측 step 시간`에 활성값 수집·평가·DP·포맷 검증을 더한 값이다. 논문의 대형 GPU 학습시간을 RTX 4070 한 장으로 선형 환산하지 않는다. 먼저 한 모듈의 100회 내외 처리율·peak·초기/최종 오차를 재면 다음 예산을 정량화할 수 있다.

정식 학습을 두 팔 모두 같은300M 처리토큰으로 다시 한다면, 기존 학생 처리의 약5.5시간 앵커와 길이/구성 차이를 고려한 **계획 범위 5.6~12시간/팔**만으로도 두 팔은11.2~24시간, 네 팔은22.4~48시간이다. 여기에 새 기준모델 forward와 양자화/복원층의 실제 overhead가 추가된다. 현재 자료 공급 병목이 더 크므로 작은 보정 시험을 마치기도 전에 300M 전면 학습부터 잡는 것은 권장하지 않는다. **이번 실제 GPU·보정·추가학습 시간은 0**이다.

### 8.9 사용자 후속 회신: 어느 모델의 어느 부분을 어떻게 바꾸는가

사용자는 §8.8의 추상 설명만으로는 범위를 판단할 수 없다며 구체화를 요청했다. 현재 우선 후보는 **P093에서 사용했던 d16 RMS4 dense 부모의 첫 middle 4층 그룹**이다. 그 외 prelude/coda·attention·embedding·tokenizer·방문 순서는 고정한다. 부모 내용 읽기·모델 실행·아래 구현은 이번에 하지 않았다.

### 8.10 A/B 독립 실험과 ‘삼진 복원 인자’ 대안

사용자는 A와 B를 별도로 검증하고, LittleBit의 이진화·별도 커널을 강제하지 않는 방향을 요청했다. **A/B를 독립으로 검증하는 것은 의미가 있다.** A는 공유 함수 차이, B는 같은 공유 함수의 삼진 배정 오차를 겨냥한다. 처음부터 둘을 동시에 바꾸면 원인을 분리하기 어렵다.

**A의 보정 인자는 data-aware LoRA 형태다.** 각 층·각 gate/up/down에서 `W_i = Q(W_shared) + U_i V_i^T`로 두고, `U_i: out×r`, `V_i: in×r`를 별도로 학습한다. 전체 delta 행렬을 저장/실행하지 않고 두 작은 선형곱으로 계산한다. 처음에는 공유 본체를 동결하고, 동결한 원래 native 함수의 MLP 출력과 후보의 출력을 실제 활성값에서 맞춘다. residual SVD를 초기값으로 쓰는 경우에도 최종 목적은 weight Frobenius가 아닌 SwiGLU 출력이다. 저랭크 작은 층을 무작위로 추가해 ordinary CE가 알아서 역할을 복원하길 기다리는 설계와 다르다.

관련 1차 방법도 확인했다. [LoftQ §2.3·§3.1](https://arxiv.org/pdf/2310.08659)은 양자화 본체와 저랭크 초기값의 합으로 원가중치를 맞추고, [LQ-LoRA §2.1·§3.1~3.3](https://arxiv.org/html/2311.12023v2)는 이 교대 분해에 예산 배정과 Fisher 가중 목적을 추가한다. 따라서 binary 전용 표현 없이 quantized 본체+실수 잔차를 직접 최적화한다는 근거가 있다. 다만 원 논문은 각 층 본체가 별도이며 **여러 층이 같은 Q를 공유하는 tying 제약은 우리 추가 조건**이다. 성능표 전체는 여기서 검토하지 않았다. LQ-LoRA는 활성값 가중 분해가 Fisher보다 나빴던 예비 관측도 밝혔으므로 data-aware 입력만 쓴다고 최고의 언어손실 복원을 보장하지 않는다. Fisher는 기준 모델 backward·importance 저장 비용이 추가되며, 먼저 작은 함수 보정과 CE를 대조한 뒤 필요할 때 추가한다.

LittleBit에서 차용할 것은 **잔차에 맞춘 초기화, 행/열/잠재축의 scale 분리, 주경로와 잔차의 단계별 보정, frozen 함수에 대한 재구성/증류 목적**이다. 실수 인자를 쓸 때 `diag(h)·U·diag(l)·V^T·diag(g)`의 diagonal은 U/V에 흡수할 수 있어 같은 rank의 표현력이 새로 늘지는 않는다. 초기화·조건수·나중의 양자화에서 값의 범위를 다루는 아이디어로 비교해야 하며, 중복 scale을 모두 추가하면 오히려 비용만 늘 수 있다.

**GSQ→RCO 압축도 가능하다.** 실수 인자의 유효성을 확인한 뒤 U/V를 `{−1,0,+1}`와 group scale로 보정하거나, 처음부터 같은 native 삼진 본체를 B에서 보정할 수 있다. GSQ는 실제 입력에 대한 오류를 줄이는 assignment/scale 방법이고 RCO는 rank/정밀도 후보를 예산 내 고르는 방법이다. GSQ-RCO가 단독 압축 포맷·커널이 되는 것은 아니다. rank8/16/32·실수/삼진·민감층 예외의 오류/bytes를 먼저 재고, 공유 본체 비용을 고정한 뒤 추가 인자 옵션만 선택하면 서로 결합된 공유 비용을 이중 계산하지 않을 수 있다.

**현 삼진 경로 재사용은 조건부 가능하다.** V의 입력폭768은 g128에 맞지만, U의 입력폭r16은 현재 `TLinear`의 `in_f % micro_group == 0` 조건을 통과하지 못한다. 현 `_group_of`의 `micro_group=0`은 per-row sentinel이므로 factor 전용 cfg에서 r16을 한 그룹으로 쓰는 native 경로 후보는 있다. 그러나 global cfg를 바꿔 공유 본체까지 재삼진화하면 다른 실험이 된다. factor별 group을 저장/복원하고 GSQ가 정한 code/scale을 재양자화로 바꾸지 않는지 먼저 검증해야 한다. per-row LUT·int8·실험용 ternary 커널의 작은 rectangular 형상/패딩/scale·cache·wall 지원은 새 실물 gate가 필요하다.

**2026-10-09 신규 구현 착수의 추가 확인:** 위 경고는 generic TLinear에 해당한다. 실제 기존 `LoRA.forward(bits=2)`는 D의 input group과 U의 **rank-per-row group**을 `ternary_g`로 이미 처리하므로 r16에서 새 슬롯/별도 binary kernel을 만들 필요가 없다. micro_group=0 sentinel은 해당 LoRA의 modulo 경로에서 별도 처리되지 않으므로 positive parent group을 유지한다. bits=16도 현재 Parameter dtype은 FP32이며 저장 표기와 runtime을 분리한다. 기존 ordinary CE ternary-LoRA 학습은 결과001에 존재하고, P093 Gaussian 근사만이 학습 전 진단이다. 새로운 [P093B](../../test_plan/P093B_실제활성값-잔차복원과-GSQ-삼진보정-독립대조.md)는 이 기존 경로에 함수 목적·초기화·GSQ 배정/정합을 추가한다. full-model 공식 GSQ/RCO 성능이나 packed CPU 가속을 재현한 것으로 부르지 않는다.

따라서 별도 LittleBit binary 커널 없이도 **삼진 TLinear 두 개+필요한 작은 scale 곱**으로 구조를 표현하는 연구는 가능하다. 하지만 기존 커널이 해당 rank 형상에서 빠르게 동작한다거나 목표 RSS에 든다는 증거는 없다. FP32로 full delta를 펼쳐 놓으면 작은 저장 구조의 이점도 사라진다. 잠재축 회전은 인자에 흡수하는 초기화로만 차용할 수 있으나, 원 논문의 binary Joint-ITQ를 ternary에 그대로 써도 같은 최적화가 되는 것은 아니다.

후속 후보는 (1) **권장: A 실수 보정/B native GSQ 독립 대조→유효 인자만 삼진 보정**, (2) A/B 독립 대조와 factor 삼진화 비용 gate를 병행, (3) 처음부터 작은 삼진 인자·RCO 예산 후보까지 동시 구축이다. 첫 안은 복원 실패와 양자화 실패를 가장 명확히 가르며 이진화를 강제하지 않는다. 전체 A/B 구현·GPU 실행·new kernel은 이번에 하지 않았다.

| [GSM-Symbolic §3.1·§4](https://arxiv.org/html/2410.05229v2) | 변수·정수 조건·정답식을 가진 template로 이름/수를 바꿔 평가; 같은 문제의 여러 변형에서 성능 편차 | 조건을 지키며 정답을 재계산하는 변형과 미관측 수/이름 평가. **증강 학습의 효과를 이미 보장한 논문은 아님** |

앞서 대화에서 ‘DeepSeek V3의 재표현 증강’으로 묶은 설명은 위 원문 범위에서 확인되지 않아 정정한다. 이 문서 §3의 리라이팅은 **Kimi K2에 대한 과거 검토**다. DeepSeek V3/R1의 거절샘플링·정답검증도 현재 P106B 전체 자유 QA에 강제하는 새 온라인 의미 게이트로 가져오지 않는다.

### 9.2 현재 교사 자료에 적용할 증강 종류와 사례

| 종류 | 올바른 변형 사례 | 위험·보호 조건 |
|---|---|---|
| **A: 규칙 보존 변수/관계 변형** | ‘사과2개에3개를 더하면5’ → ‘4개에7개를 더하면11’; 표의 a/b 순서와 묻는 대상을 함께 변경 | 숫자만 바꾸고 답5를 남기면 오답 학습. 계산기/프로그램으로 답을 다시 산출할 수 있는 과제부터 시작 |
| B: 의미 보존 재표현 | 자유 설명 ‘물을 아끼는 방법 두 가지’의 질문·설명 방식 변형 | ‘1만 출력’, JSON key, 코드·인용문·고유명사 등의 literal 계약은 바꾸지 않음. 같은 뜻인지 후행 검토가 필요 |
| C: 조건 변경·이의제기 멀티턴 | 앞 턴의 색상/예산 조건을 다음 턴에서 바꾸고 새 조건에 답하기; 잘못된 답을 지적한 뒤 고친 답 제공 | 옛 잘못된 assistant 답은 **문맥만** 제공하고 교정한 답만 loss에 포함. 모든 assistant를 지도하는 기존 mask를 그대로 쓰면 옛 오답도 학습 |
| 문맥조회/FIM 개념 | 앞/뒤 문장이나 표를 주고 빠진 중간 내용을 복원하는 ChatML 과제 | DeepSeek의 특수 token·10%를 복사하지 않고 현재 tokenizer/ChatML 유지. 정보가 없는 빈칸을 정답 하나로 강제하지 않음 |

교사는 필요한 자연어 내용·풀이를 생성하고, 관리 코드는 명시된 과제 유형·조건·원천·변형 관계와 known output contract를 소유한다. teacher thinking은 원형에 보존하되, 현재 최종답-only SFT에 자동으로 추가하지 않는다. reasoning 목표로 바꾸는 것은 길이·마스크·평가가 달라지는 별도 실험이다.

### 9.3 epoch별 변형은 가능하지만 현재 reader를 그대로 사용할 수는 없다

가능한 설계는 root concept마다 원본과 사전 생성한 view0~view3을 보존하고, epoch마다 정해진 view를 읽는 것이다. 같은 원형을 매 노출마다 teacher에게 다시 요청할 필요가 없다. 각 view는 원천 SHA·root family·변형 규칙·seed·teacher/sampler·원질문/답·생성 이력·tokenizer SHA·실제 x/target token을 갖는다.

현재 [mixed repeat4 reader](../../scripts/diag_p106b_mixed_repeat4.py)는 epoch의 실제 처리토큰이 원래 report의 train token 합과 같은지 검사한다. 변형 길이가 달라지면 이 검사가 실패한다. **검사를 끄는 것이 수리가 아니다.** 새 자료 버전/manifest에서 각 view의 길이, epoch별 실제 처리량, padding과 지도 token, batch/accum, 재개 cursor/view seed를 사전등록해야 한다. micro8×accum16·checkpoint-on·현재 LR을 유지하면서 총 처리토큰300M에 맞출 수는 있으나, view 길이가 달라지면 원래의 ‘고유75M×정확4회’와 같은 조건인지 별도로 보고한다.

표현만 다른 네 행은 네 개의 독립 지식이 아니다. **root concept 수, 고유 직렬화 token, 실제 반복 처리token, 지도token, 노출 횟수**를 구분한다. train/val split은 변형 전에 root/source family로 고정하고, 같은 개념의 변형을 val이나 고정 평가 질문의 ‘새자료’로 넣지 않는다.

### 9.4 과적합을 줄이고 논리를 배우는지 검증하는 방법

동일자료 반복 팔과 증강 팔의 **부모·micro/accum·LR·실제 처리토큰·가능하면 업데이트 수**를 맞춘다. 변형 한 종류씩 추가해 이름/수/어순 변경, 묻는 대상 변경, 부정/조건 변경, 미관측 조합, 멀티턴 상태 갱신의 실제 답·종료·형식과 기존 언어 손실을 본다. 원래 val 답을 교사가 다음 train에 교정해 주면 해당 val은 더 이상 독립 성능지표가 아니므로, 학습용 feedback-dev와 최종 test를 따로 둔다.

변형은 우연한 문구 암기를 줄일 **가설**이지 과적합 방지 보증이 아니다. 근거 오류를 네 번 바꾸어 쓰면 같은 오류를 더 강하게 학습할 수 있다. ‘패턴/논리 학습’을 주장하려면 교사가 만든 익숙한 표현 외의 조건·수·조합에서 개선돼야 한다. 문자 n-gram은 중복 후보 경고에만 쓰고 의미 정확성·불량 판정·자동 재생성의 대용으로 사용하지 않는다.

### 9.5 생산·학습 비용과 실용적인 첫 범위

현재 확정 생성 자료의 train 공급은 [결과101 §86~§87](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)에서 약 **3.95 x-token/s**다. 약74 completion-token/s와 분모가 다르다. 이 공급률을 그대로 쓰면 새로운 유효 train3M토큰은 **약8.8일**,75M의 추가 view 세 벌225M은 **약659일**이라는 조건부 외삽이 된다. 향후 길이·과제·수락률·교사·batch가 같다는 가정일 뿐 확정 일정은 아니며 val·계측·원천 소진 비용은 별도다.

따라서 전체75M에 새 자연어 view를 세 벌 만드는 설계부터 실행하지 않는다. 비용이 적은 코드 기반 변형과 제한된 교사 view를 먼저 만든다. 계획용 개발비는 고정 규칙/답 재계산·계보 8~16시간, 자유 재표현·후행 패킷 연결 8~16시간 추가, 멀티턴 turnwise mask·재개 회귀 12~24시간 추가 정도로 잡고 실제 범위를 정한 뒤 재산정한다. 온라인 모델 생성 시간은 실측 전 보장하지 않는다. 파일은 각각20,000,000byte 이하로 분할하고 원형·교정·view를 구분한다.

### 9.6 후속 비교안과 권장 순서

| 안 | 예시와 수행 범위 | 장단점·권장 근거 |
|---|---|---|
| **A 권장: 규칙 기반 변형 + 소형 교사 보완** | 계산·표조회·known JSON 형식을 코드가 변형하고 답을 다시 계산. 자연어 설명만 교사가 보완. 동일반복/변형 대조 | 비용·정답 정합·원인 분리가 가장 명확. 자유 상식·문학 전체를 이 방식으로 증강할 수는 없음 |
| B: 교사가 뜻을 보존한 여러 view 생성 | 같은 질문의 표현·풀이를2~4개 만들고 저장, epoch별 view 선택 | 현재 교사 관리 흐름과 가깝지만 정보량은 늘지 않을 수 있고 의미변형·생성비용이 큼 |

권장은 A의 작은 범위에서 실제 일반화/망각을 확인한 뒤 필요한 가족에만 B/C를 추가하는 순서다. 현재 생산 재개와75M/300M 목표를 임의 축소·취소하는 제안이 아니다. 이번에는 조사·비교안만 기록했으며 **증강 코드, 새 데이터, 새 실험계획/런처, GPU 실행은 모두 `NOT_RUN`**이다.

### 9.7 사용자 후속 회신: A의 적용 범위와 첫 CPU 적용

§9.6 기록 후 사용자는 A를 ‘가능 유형·범위를 보고한 뒤 적용’하도록 요청했다. 이에 범위를 먼저 채팅 보고하고, **새 opt-in 결정적 변형기와 CPU 회귀**를 추가했다. 기존 생산 코드·자료·epoch reader·교사 호출에는 연결하지 않았다. 이는 모든75M에 증강을 적용했다는 뜻이 아니다.

| 유형 | 바로 가능한 규칙 | 현재 적용/미적용 |
|---|---|---|
| 정수 계산 | 코드가 소유한 `+/-/*` 과제의 선언된 정수 범위에서 피연산자를 바꾸고 답 재계산 | **구현**. 나눗셈·단위·날짜·다단계 식은 조건 체계가 필요해 아직 미구현 |
| 명시 표 조회 | 원래 entity→value 대응은 보존하고 행 순서와 묻는 대상을 바꿈 | **구현**. 실제 세계의 사람/장소/날짜를 임의 교체하는 기능 아님 |
| 입력 record의 JSON 필드 선택 | producer가 알려 준 scalar 입력·존재하는 필드 이름을 사용해 질문과 JSON 답을 함께 만듦 | **구현**. 자유 JSON 변환·의료 지식 검증·임의 복잡한 schema는 제외 |
| ‘1만 출력’ 등 유일 literal | 선언된 질문/답을 그대로 유지 | **보호 구현**, 다양화를 강제하지 않음. 같은 답은 정상일 수 있음 |
| 정렬/단위/날짜/논리 규칙 | 명시 입력·해석·답 계산기를 추가하면 가능 | 후속 후보이며 현재 구현·자료량0 |
| 자유 상식·의료·문화·문학 | 자연어 사실관계의 의미 보존을 코드가 알 수 없음 | 자동 숫자/이름 교체 **적용 불가**. B/C의 별도 생성·후행 검토 대상 |

현재 코드로 확인되는 닫힌 합성 범위는 [P106C generator](../../scripts/p106c_data.py)의 train 표조회 **256쌍/512행**, 산술 positive-control **32행**이다. legitimate repetition32행은 임의 다르게 답하게 만들면 안 된다. 이 숫자는 **코드에 선언된 진단 자료**의 범위이지 현재 대량 SFT에서 자동 변형 가능한 행/토큰 비율이 아니다. 실제 공개 원천의 typed contract 재고는 아직 계측하지 않았고, 자유 QA에 `json` profile이 붙었다고 수학/사실 변형이 가능한 것으로 분류하지 않는다.

현재 [capability 생성기](../../scripts/p106b_capability_corpus.py)의 code-owned JSON 후속은 키/정수·출력 계약만 변형할 여지가 있고, 사실 답의 의미는 별개다. 원천 내용에 대한 실제 가용토큰 계측 없이 ‘25% JSON profile이므로25%를 A로 증강 가능’이라고 계산하지 않는다.

첫 구현: [p106b_rule_views.py](../../scripts/p106b_rule_views.py), [CPU 회귀](../../scripts/test_p106b_rule_views.py). explicit `code` 또는 검수된 원천 계약·한영·train split·공개/코드 원천만 받고, 모르는 유형/보호/val/dev/sealed/test 입력은 변형하지 않는다. 원본 첫 질문/답을 그대로 두고 새 규칙 QA를 후속 턴으로 붙여 기존 first-user 기반 split identity를 유지한다. 원형·source license/SHA·root concept·seed·규칙 version·변형 payload를 보존한다. **두 assistant 턴은 각 입력에 대해 맞는 답**이므로 C의 옛 오답 문제와 다르다.

`python3 -B -X utf8 scripts/test_p106b_rule_views.py`: **14 tests PASS, 산술96개 조합 포함**, input 불변·재현·canonical/ChatML·두 지도구간·정상 동일답·unknown/protected/평가 분할 차단을 검증했다. 최초 import는 환경의 numpy 의존성을 불필요하게 끌어와 실패했고, 기존 split 함수를 복제하지 않고 **첫 user content의 완전 동일성**을 검사하도록 수리해 표준 Python CPU로 통과했다. 토크나이저·원천·모델·교사·training 호출은0, 새 데이터파일도0이다. 실자료 typed inventory/총 처리토큰/epoch reader 연결 및 학생 효과는 `NOT_RUN`이다. 현재 동일 token 검사를 해제하거나 기존 raw/HF 입력 SHA를 바꾸지 않았다.

### 9.8 B의 ‘한 요청 여러 질문/풀이’와 C의 세 시나리오

**B는 설계상 가능하지만 현재 기능과 동일하지 않다.** [기존 multi-answer](../../scripts/p106b_multi_answer.py)는 한 completion에서 **질문 하나+답2/4개**를 파싱한다. 질문 자체가 바뀐2/4쌍을 받는 계약은 없다. 새로운 B는 한 요청에 `QUESTION_1:/ANSWER_1:/QUESTION_2:/ANSWER_2:/NOTE:`처럼 시작 라벨의 QA 두 쌍을 요청하고 코드가 별도 행으로 wrapping해야 한다. 예: ‘2+3의 값은?’/‘2에3을 더하면?’의 답5 두 쌍. literal/JSON 키·숫자·단위를 임의 바꾸지 않고 같은 root/split로 묶는다. 사고/NOTE는 학생 target에 넣지 않는다.

우선2쌍 소형 시험에서 한 요청 한 쌍과 같은 원천·sampling·출력 예산 조건을 대조하고, 완결률·실제 두 질문/풀이·문맥 보존·유효 학생token/s를 확인한 뒤4쌍으로 늘리는 것이 타당하다. prompt/prefill/사고를 공유할 수 있으나 출력은 길어지고 절단·서로 베끼기 위험이 있으므로, ‘한 번에2쌍이면 생성속도도2배’라고 보장하지 않는다. **현재 모델의 실제2질문/2풀이 출력은 실행하지 않았다.** 기존2/4답 생성 성공을 이 새 계약의 PASS로 사용하지 않는다.

| C의 시나리오 | 대화 예시 | 교육할 대상과 보호 |
|---|---|---|
| C1 조건 갱신 | user ‘2+3은?’ →assistant ‘5’ →user ‘3 대신4로 바꿔 다시 계산’ →assistant ‘6’ | 두 답은 각 조건에서 모두 맞으므로 둘 다 지도 가능. 새 user 조건이 답을 바꾸는 패턴을 배움 |
| C2 실제 오답 교정 | user ‘2+3은?’ →assistant ‘6’ →user ‘다시 계산해 줘’ →assistant ‘5’ | 옛‘6’은 실패 사례 **context-only**, 마지막‘5’만 지도. 지금의 전체 assistant mask로 넣으면6도 배워 부적합 |
| C3 설명/형식 이의 | user가 자유 설명을 받은 뒤 ‘두 항목 JSON으로 다시’ 또는 ‘두 번째 근거도 설명’ 요구 | 내용·형식의 새 계약에 답하는 턴을 지도. 같은 뜻의 문장을 복제하는 B와 달리 대화 상태/요구 변경이 목표 |

재제안은 **C1부터**가 가장 작다. 다음 후보 C2는 turnwise mask 구현·검증 후에만, C3는 자유 답 의미 보존의 후행 표본 검토와 함께 진행한다. 어느 경우도 최종 validation/test의 오답을 그대로 다음 train에 넣지 않으며 별도 feedback-dev를 사용한다. B/C의 새로운 prompt/parser·turnwise mask·모델 실험은 이번 A 적용에 포함하지 않았다.

### 9.9 사용자 후속 회신: C1·C3 CPU 적용, C2+C3의 대상 검토

사용자는 C1과 C3단독의 적용을 요청했다. 같은 새 모듈에 `boolean_expression`, `make_condition_followup`, `make_format_followup`을 추가했다. 기존 production/reader는 변경하지 않았다.

- **C1:** 정수 `+/-/*`, 표조회·묻는 대상·행 순서, Boolean `NOT/AND/OR/XOR/IMPLIES/EQ`를 코드가 계산한다. Boolean은 제한된 명시 AST를 해석하고 Python `eval`을 사용하지 않는다. 예: 원래 `A=true,B=false, A AND NOT B→true`에서 값이 바뀌면 식은 이전 문맥에서 유지하고 새 답을 계산한다. 원래 질문/답과 조건변경 user·새 답을 모두 보존한다.
- **C3단독:** 원래 답 문자열 전체를 `answer` 항목의 JSON으로 다시 출력하는 명시 user 요구를 붙인다. public typed `verbatim_qa`에도 가능하지만 **원래 내용의 정답 여부는 NOT_REVIEWED**다. 이 함수는 답을 요약·재표현·교정하지 않고 형식만 바꾼다. 원문 줄바꿈·인용부호를 실제 JSON escape로 보존하고 기존 canonical/ChatML을 재사용한다.
- **C2+C3:** 아래 유형 후보를 검토했지만 아직 자동 분류·교정 생성·turnwise loss 기능은 구현하지 않았다. C3의 형식 wrapping이 오답을 정답으로 바꾸는 기능인 것처럼 사용하지 않는다.

| 적용 후보 | 예시 | 판독·학습 주의 |
|---|---|---|
| 묻는 대상/지시를 무시함 | A=빨강,B=파랑인데 B를 물어도 빨강을 답함; user가 B를 다시 지목 | 닫힌 표에서는 코드 gold로 확인 가능. 자유 QA의 ‘사용자 의도’는 문맥 판독이 필요 |
| 이전 조건에 머무름 | user가 수/예산/범위를 바꿨는데 이전 조건의 답을 반복 | 새 조건이 객관적으로 주어졌으면 새 gold 산출. 이전 답은 당시 맞았다면 C1이지 C2 오답이 아님 |
| 잘못된 형식/범위 | JSON만 요청했는데 장문 해설; 핵심2개 요청에 다른 주제 설명 | 구조 조건은 코드 검사 가능하지만 무슨 내용이 핵심인지는 별도 판독. 온라인 오답 문자열 목록 금지 |
| 대상·역할·목적·부정 오해 | 상담자의 설명을 광고문으로 받았다고 user가 교정; 제외할 내용을 포함 | 원질문·이전 대화·실제 오답·user 교정·새 답을 묶어 후행 GPT/로컬 판독 패킷으로 확인 |
| 사실 오류 주장 | user가 날짜/개념 설명을 잘못됐다고 지적 | 불만 자체가 새 정답의 증거는 아님. 원천 근거·검증 가능한 계산 또는 후행 검토로 교정내용을 점검 |

C2는 첫 잘못된 assistant를 context-only로 두고, 실제 잘못된 구간을 지도하지 않으며, 마지막 교정답만 target으로 삼는 새 mask가 선결이다. 반면 C1의 이전 답은 당시 조건에서 맞으므로 두 답 모두 지도한다. 실제 validation/test 실패를 바로 train으로 되먹이지 않고 feedback-dev를 분리한다.

최종 새 회귀는 **20 tests PASS(산술96·Boolean 변경16조합 포함)**, 표준 Python CPU0.016초였다. C1의 문맥/연산/형식 유지, C3의 원답·줄바꿈·인용 보존과 두 assistant 지도구간, 평가/보호 원천 차단을 확인했다. 현재 코드 생성에 모델·교사·tokenizer·학습·데이터파일 쓰기는0이다. current mass corpus의 적용률·actual token/view budget·새 reader 연결·학생 효과는 계속 `NOT_RUN`이다.

## 10. 반복·질문 나열 연구 — 일반 현상과 TinyLM 원인, 최저비용 처방을 구분한다

> 2026-10-11 사용자 추가 조사. 학술 원문을 읽고 현재 코드/저장 원답과 대조한 검토이며, 새 C 학습·모델/GPU 실행은 0이다. [결과103 §8](../../test_result/103_20261010_P093B-MLP잔차와-삼진보정은-실행됐지만-복원문턱에-미달.md)이 실제 관측을 소유한다.

### 10.1 먼저 확인된 것과 아직 확인되지 않은 것

현재 dense d16 CLA2 부모도 문맥 질문을 반복하고 숫자를 나열한다. shared-only와 r8/16/32/64에도 같은 가족의 문제가 있다. 따라서 ‘r64 때문에 반복이 시작됐다’, ‘TinyLM만의 현상’, ‘재귀 라우터 결함’은 현재 증거로 성립하지 않는다. 이 부모는 이름과 복구 계약상 norecur이며 이 진단은 n_modes=1이다. 복원 NRMS를 낮추는 것과 지시를 이해하고 답을 끝내는 것은 다른 목적이다.

코드 점검상 native sample은 반환된 전체 문자열에서 동일 tokenizer의 decoded prompt를 제거한다. 원답 파일의 answer에도 반복이 남아 있어 화면에 입력을 함께 보여 준 착시만은 아니다. EOS는 발견되면 정지하며, attention의 증분 mask는 past_len을 반영하고 RoPE도 절대위치를 쓴다. MLP/LoRA 패치는 finally로 원래 슬롯을 복구한다. 그렇다고 실제 체크포인트의 캐시·정밀도·마스크 정합성을 증명한 것은 아니다. 실제 24개의 cache on/off 원답 대조는 새 A 진단의 사용자 실행 항목이다.

ChatML SFT의 assistant loss span에는 im_end가 이미 포함된다. ‘종료 토큰을 학습하지 않는 코드’라고 단정하거나 무조건 EOS를 더 붙이지 않는다. legacy 부모의 문서 EOS 학습과 chat32의 대화 종료는 구분하고 각 토크나이저의 실제 mask를 확인한다. teacher thinking은 현재 자료에서 sidecar이며 학생 target이 아니다.

현재 아키텍처가 질문에 답하는 학습 자체를 못 한다는 주장에도 반례가 있다. [P106C 결과102 §6~§8](../../test_result/102_20261003_P106C-암기는-통과했지만-선택은-일반화를-해쳤다.md)의 양순서128회 학생은 폐쇄형 조회128/128·쌍64/64를 맞혔으나 일반 언어 손실은 +.476504 악화했다. 이는 특정조건에서 학습 가능함만 뜻하며 P093B 부모·r64의 지시능력, 망각 없는 일반화, 구조별 원인을 대신 증명하지 않는다.

### 10.2 원문에서 확인한 대안과 실제 적용 한계

| [SimPO, NeurIPS 2024 §2](https://arxiv.org/html/2405.14734v3) | 응답 평균 log probability의 선호 margin을 학습, reference 없음 | 비용상 후보지만 좋은 답 확률을 올리기보다 나쁜 답만 낮춰 margin을 만족할 수 있고 작은 학생의 언어 망각을 별도 확인해야 함 |

Unlikelihood의 음성 후보와 DITTO의 반복 pseudo-data는 기존 후보로 남기되 모든 반복 토큰을 부정하지 않는다. [Unlikelihood](https://arxiv.org/html/1908.04319v2)는 gold 제외·negative 설정이 중요하고, [DITTO](https://arxiv.org/html/2206.02369v2)는 반복 뒤 확률의 자기강화를 다룬다. 원문의 영어 생성/요약 성과를 한국어 소형 공유 모델의 성공률로 환산하지 않는다. 원문의 실험 조건·목적함수는 이 절에서 검토했지만 전 방법의 전체 부록/공식 코드 재현을 수행한 것은 아니다.

### 10.3 현재 최적의 준비 방향: 정답·종료 SFT 기준선 → 보수적인 ORPO 대조

이는 TinyLM에서 검증된 최적 알고리즘이라는 뜻이 아니라 현재 관측·메모리 목표를 반영한 우선순위 판단이다. 사용자 승인한 A 진단이 먼저다.

1. A에서 실제 cache/prompt/종료 결함이 보이면 이를 고친 뒤 학습한다. sampler/few-shot만으로 변화하면 greedy 원답을 보존하고 생성 정책 영향으로 보고한다.
2. 부모도 지시/종료를 못 배운 경우 정상 QA·형식·조건변경·대화 종료 SFT를 기준선으로 둔다. ‘반복하지 마세요’ 문장만 추가하거나 EOS를 무조건 조기 강제해서 정답 손실을 감추지 않는다.
3. SFT 뒤에도 불필요한 loop가 남으면 같은 질문·사실·출력 요구의 후행 판독 쌍을 만든다. 예: 요구가 ‘2+3의 값만’일 때 좋은 답은 ‘5+종료’, 나쁜 답은 ‘5.5.5…’; 반대로 ‘5를 세 번 적으세요’의 ‘5 5 5’는 보호 사례다.
4. 먼저 frozen native shared core와 층별 실수 보정 인자만 조정하는 SFT-only/ORPO 대조를 고려한다. 동일 parent·자료 split·좋은 target·실제 토큰/업데이트 예산을 맞춘다. local NRMS와 일반 언어 손실도 함께 확인한다. 능력 부족이 이 작은 인자로 해결될지는 미확인이다.
5. 미래 정상 chat32 지시 부모의 압축 복원은 별도 실험이다. legacy d16을 chat32 부모로 조용히 바꾸거나 그 결과를 현 r64 재현이라고 부르지 않는다.

권장 손실은 원문 ORPO의 형태인 `L = L_SFT(chosen) + lambda * L_OR(chosen,rejected)`이며, `log P`는 assistant 유효 위치의 평균으로 계산한다. prompt/pad/교사 사고/옛 오답 문맥은 제외하되 정상 종료 표지는 포함한다. odds 계산은 FP32 log-space의 안정한 log1mexp로 처리할 필요가 있다. chosen/rejected의 동일 입력 조건·첫 답·종료/길이·검토 근거를 보존한다. 이 구현은 아직 하지 않았다.

원래 전역 새로움 억제보다 ORPO를 권하는 이유는 이미 나온 ‘새 단어 부족’만을 벌주는 대신 좋은 답의 확률을 직접 올리고, 특정 문구의 오조어 목록 없이 질문에 맞는 답 쌍을 이용하기 때문이다. 반복이 아닌 지식 오답이 함께 다른 쌍은 ‘반복만의 효과’ 분석에서 분리한다. 단답만 선호하도록 length bias를 만들지 않도록 긴 정상 설명·목록·코드·인용·정답복사도 dev/test에 넣는다.

native r64 FP32 인자만8.25MiB, FP16 저장은4.125MiB이며 실제 half 계산/배포 상주는 별개다. 추가 학습의 optimizer 감소가 전체 활성값·backward 비용을 없애지는 않는다. GSQ/양자화 압축은 이 목적함수 대조 뒤에 별도로 시험한다. AQLM식 KL과 local 복원을 섞을 때는 제대로 지시를 수행하는 부모가 기준이어야 한다.

### 10.5 데이터·평가 보호와 후속 상태

실시간 생성 중 틀린 문구 목록을 만들거나 의미 심사를 다시 붙이지 않는다. pair는 생성이 끝난 별도 feedback-dev/검토 패킷에서 원질문·대화·정상 반복 허용 계약·오류 구간을 확인해 만든다. validation/test 실패를 즉시 train으로 되먹이지 않는다. 최종 시험 질문은 분리하고 보호 원천은 별도 승인 없이 읽거나 교사에게 보내지 않는다.

보고는 반복 관찰값, 요구 정답/형식, 종료 성공, 정상 반복 보존, 일반 언어 손실, 처리율/상주를 분리한다. ‘반복 감소’만으로 지능 향상이나 복원 문턱 통과를 선언하지 않는다. 현재 선택된 것은 무학습 A 준비이고 C의 새 손실·새 자료·학습은 조건부 연구 후보다. 다음 단계가 필요하면 세 안의 실제 변경 범위와 비용을 사용자에게 다시 제시한 뒤 구현한다.

### 10.8 관찰방법의 충분성과 실제 반복 시작점

[103 §11~§12](../../test_result/103_20261010_P093B-MLP잔차와-삼진보정은-실행됐지만-복원문턱에-미달.md)은옛48행이8문항×3조건×2입력임과짧은중심화rank의N−1상한을명시했다. 조건별저장답은7/8입력에서달라표현통계와구조인과를분리한다.
[Ethayarajh2019](https://aclanthology.org/D19-1006.pdf)의층별무작위문맥비등방성기준선이나[SimCTG](https://papers.nips.cc/paper_files/paper/2022/file/871cae8f599cb8bbfcb0f58fe1af95ad-Paper-Conference.pdf)의생성/학습개입을이작은표본이대체하지않는다.

새한정실물진단은24원답·2186native선택을재현하고같은prefix cacheOFF·실제KV·16층을측정했다. parent/r64의같은반복위상에서copy선호가강해졌고shared단일token루프의last-layer 출력은가까워졌다. 이는반복의결과일수있어SimCTG의필요성/효용을확정하지않는다. 다중token루프의인접위치cosine은단어도달라동일위상비교가아니다.

옛KVprefix불변·원답24/24일치이나BF16 cacheargmax6/2186차이로기술8이다. [PyTorch2.10 수치정확성](https://docs.pytorch.org/docs/2.10/notes/numerical_accuracy.html)에서설명하는행렬형태/precision 차이는가능원인이지이번6건의확정원인이아니다. fixedprecision/math 대조·정상응답기준선·attention확률·선택적층개입은NOT_RUN이다.
보유prefix를추가한상태의확률변화와SFT/ORPO/SimCTG 학습효과를같게보지않는다. 기본micro/accum·추론/학습손실·삼진커널은변경하지않았다.
### 10.9 반복 원인분리의 실물 개입과 readout-aware 한계

[103 §13](../../test_result/103_20261010_P093B-MLP잔차와-삼진보정은-실행됐지만-복원문턱에-미달.md)의같은길이/같은token 다중집합shuffle은반복prefix의다음선호를크게바꿨다. [DITTO](https://proceedings.neurips.cc/paper_files/paper/2022/file/148c0aeea1c5da82f4fa86a09d4190da-Paper-Conference.pdf)식입력이력피드백의국소근거이지만문법/의미변형/OOD의교락은남는다.
[활성값patch 연구](https://arxiv.org/pdf/2309.16042)의metric/donor 민감성을반영해확률과고정focus−EOS logit차를함께보고부호가반대인층도보존했다. shared/r64와R2가반복양상을바꿔도untied/R1에서이미반복하므로그들만의고유문제라고말할수없다. R2_on_R1-trained의분포mismatch는재귀학습의인과와별개다.

단일마지막위치의output-equivalent 영공간반사로cosine을약1→음수로내려도전체next-token logits가유지됐다. raw/global cosine이좋거나나쁘다는것만으로학습처방을정하는근거는부족하다. 이TinyLM의factorizedhead(768→256)에서head-visible 정보/출력분포와cosine을함께봐야한다는방법상경고이지embedding factorization이반복의원인이라는결론은아니다.
SimCTG의원목적함수효용을자동기각하지않고정답/종료SFT 양성대조·head-visible/전체출력분포 보존·normal-copy 보호와새학습대조가필요하다. 이번에는어떤손실도추가하지않았다. FP32/math에서6cache차이가사라진결과도현재반복의유일원인이나모든입력구현PASS로승격하지않는다.

## 11. 야간 QA 실측 이후 — 질문 구별, 실제 복사 분포, 근거 과제의 구분

검토일 2026-10-17. [P106B 결과101 §244~258](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)의 원문 재노출·같은 QA, 입력본문 LM, 고유32k의 실제 답안과 아래 원문을 대조했다. 논문 아이디어는 TinyLM에서 이미 효과가 난 방법이라는 뜻이 아니다. 새로운 학습/추론 기능은 아직 구현하지 않았으며 기존 보류를 완료로 올리지 않는다.

**추가 실측 §264~267:** 질문만앞으로옮긴동일지시대조는KO를악화시켰다. 같은답의질문조건부점수에는정보가있지만자유답의정확한대상선택은낮았다. 따라서‘질문을못보는head’를붙이는수리가아니라,같은답종류/최소질문차이에서질문조건과답조건을분리한CE/대조설계가우선이다. 기존8k/32k에이미같은본문의다른질문이있으므로묶음추가자체를새기여로세지않는다. 아래수식/구조는아직학습후보이며새기본이나검증된해결책이아니다.

### 11.1 기존 span 보조가 질문을 못 보고 있었다는 가설은 코드와 맞지 않음

현재 `scripts/p106b_grounded_span.py`의 `locations/new_head/auxiliary_sum`과 `diag_p106b_grounded_span.py`의 실제 train/generate를 직접 읽었다. 시작/끝 점수의 query는 **질문을 모두 읽은 뒤 assistant 답 직전 hidden**이다. 본문 위치의 key는 causal hidden이라 뒤의 질문을 보지 않지만, 질문 query와 결합하며 보조 손실의 gradient도 본체로 흐른다. 따라서 ‘질문 없는 head’나 ‘detach 때문에 본체를 못 가르침’이라는 결함은 발견하지 못했다.

다만 기존 보조 head는 학습에만 쓰이고 자유 생성은 보통 어휘 head를 쓴다. 이 경로에서 span을 잘 찾는 것과 실제 답의 문자를 정확히 복사하는 것은 다르다. 기존 첫 QA 중심의 span 보조 실험에서 약한 자유답 변화가 난 사실도 함께 보존한다. 새로운 copy decoder는 단순히 query를 붙이는 수정이 아니라 **추론 확률분포에 source 복사 경로를 연결하는 새 구조**여야 한다.

### 11.2 후보1 — 같은 답을 어느 질문에 대응시킬지 직접 학습

[Learning with Instance Bundles, EMNLP 2021](https://aclanthology.org/2021.emnlp-main.584.pdf)은 관련 QA 묶음의 질문/답 조합 점수를 대조한다. 원문은 fine-tuned T5-large에서 MLE와 대조 목표를 함께 사용했으며, 대조만 쓰는 것은 약했다. 같은 본문의 임의 질문들을 묶으면 답의 종류만으로 맞추는 지름길이 생길 수 있다는 한계도 명시한다. 저자 저장소의 실행 검증은 하지 않았다.

TinyLM 응용 후보는 같은 본문 c의 질문 q1/q2와 정답 a1/a2를 쓰되, 같은 정답 a1의 점수 s(c,q1,a1)를 s(c,q2,a1)보다 높이는 질문조건부 대조를 정상 CE에 낮은 가중치로 더하는 것이다. 동일 답을 두 질문에서 비교하면 답 길이는 같지만, 이 자체가 모든 길이/난도 교락을 제거하지는 않는다. 예시 보조항은 두 방향의 `softplus(s_other_question - s_correct_question)` 평균이다. 이는 연구용 후보식이며 현재 학습 기본값이 아니다.

이미 TRAIN32k에 문자상 구별 후보12,854묶음이 있어 **두 질문을 추가했다는 것만으로 새 기여를 주장할 수 없다**. 먼저 TRAIN의 코드로 정답을 계산하는 과제 또는 별도로 후행 확인한 자연 QA 묶음에서 교차답이 실제로 부적절한지 확인한다. 다른 문자열/겹침 없음만으로 negative를 만들지 않는다. 기존 CE만 한 팔에도 같은 두 질문·자료/업데이트를 제공하고 CE+대조와 비교해야 한다. TEST/최종평가 오답은 여기에 쓰지 않는다.

### 11.3 후보2 — 어휘 생성과 source 복사를 실제 추론에서 혼합

[Pointer-generator, ACL 2017](https://aclanthology.org/P17-1099.pdf)과 [저자 구현의 최종분포](https://github.com/abisee/pointer-generator/blob/master/model.py)는 어휘 생성 확률과 입력 token 복사 확률을 합친다. 원래 요약 연구이며 TinyLM QA 성공 증거는 아니다. [Pointer Sentinel, 2016](https://arxiv.org/pdf/1609.07843)은 작은 LSTM 언어모델에서 pointer와 어휘 분포를 혼합한 선례지만, QA의 질문대상 구별을 입증하지 않는다.

우리 응용 후보는 질문을 본 decoder query와 **명시적으로 제공된 본문 위치만** copy bank로 쓰고, 질문/관리지시/옛 오답/정답 history는 copy bank에서 제외하는 것이다. 저장된 gold span을 추론에 주지 않는다. 현재 factorized vocabulary head를 유지하면서 source token ID에 복사 질량을 더하며, 학습뿐 아니라 generate/cache 경로에서도 같은 분포를 사용해야 한다.

bias 없는 768→64 query/key 두 투영과 sentinel64라면 새 파라미터는 `2*768*64+64=98,368`, FP32 저장 약0.375MiB다. 본문1024위치의64차원 FP32 key bank는 **한 시퀀스당**0.25MiB,배치8이면2MiB이며 optimizer·역전파·기존 KV는 별도다. 이는 설계식 계산이지 실측 상주량/속도다. BPE 조각의 어긋남이나 다른 연도/사람을 복사하는 오류는 여전히 가능하므로 copy 비율/문자 보존/실제 대상 정답을 분리한다.

### 11.4 후보3 — 짧은 근거 인용을 답과 분리된 과제로 지도

[Distilling step-by-step, ACL Findings 2023 §4.4](https://aclanthology.org/2023.findings-acl.507.pdf)은 pretrained T5의 label/rationale 과제를 분리했고, 단순히 rationale+label을 이어 출력하는 방식이 항상 이롭지는 않았다. 220M 이상의 T5와 큰 교사의 결과를 현재93M causal 삼진 모델에 그대로 이전할 수 없다. [RAFT](https://arxiv.org/pdf/2403.10131)는 근거 문서/방해 문서와 인용을 활용했지만 7B 모델·교사 작성 근거를 쓴 다른 조건이다.

TinyLM에서는 답만 하는 과제를 유지하고, TRAIN의 알려진 정답 span을 포함한 짧은 원문 근거를 별도 요청에 답하는 보조 과제를 고려할 수 있다. 코드로 자른 문장은 논리 풀이/검증된 thinking이 아니며, 추론 때 gold sentence·answer_start·정답 주변 crop을 제공하면 oracle 누설이다. ‘근거 먼저→답’ 방식을 평가한다면 근거도 학생이 직접 찾아 생성한 것을 써야 한다. 긴 thinking을 무조건 늘리는 처방과 구별한다.

### 11.5 현재 우선순위와 해석 경계

| 후보 | 직접 겨냥하는 문제 | 선결·비용/위험 | 권장 |
|---|---|---|---|
| 질문조건부 CE 대조 | 같은 본문에서도 묻는 대상 대신 같은 답을 선택하는 현상 | TRAIN 묶음의 의미 확인·정상 CE 기준팔·추가 조합 forward 비용8 계측 필요. 새 파라미터는 불필요하지만 negative 오류 위험 | **현재 1순위 설계 후보.** 기존 구조를 유지하며 source 재고와 연결 |

구현 시간과 GPU 시간은 아직 해당 코드/비용8을 수행하지 않아 미측정이다. 세 방법을 한 팔에 한꺼번에 넣지 않고 같은 부모/분할/실제 입력·지도토큰/종료/보존을 기록한다. 원문 CE가 낮아졌다는 사실, DEV가 낮아졌다는 사실, 실제 질문을 맞혔다는 사실은 서로 대체하지 않는다. 이번 결과만으로 셋 중 하나를 검증된 최적안으로 선언하지 않는다.

참고로 [Lost in the Middle §5.2](https://arxiv.org/html/2307.03172v1)는 질문을 본문 전후에 두는 방식이 합성 key-value 검색에는 크게 도움됐지만 다문서 QA에는 일반적 개선이 아니었다. [ReReading, EMNLP 2024](https://aclanthology.org/2024.emnlp-main.871.pdf)의 질문 재읽기도 더 큰 모델에서 검증한 다른 개입이다. 현재 지시 고정1/3 필드순서 진단은 질문 중복이 없으므로 이를 재읽기 실험이라고 부르지 않는다. 후속 Q→C→Q는 별도 길이/반복/위치가 함께 바뀌는 설계이며 아직 구현·실행하지 않았다.

## 12. 질문을 구별하는 것과 정답을 선택하는 것 — CPU 준비와 문헌 대조

2026-10-17 사용자가 A를 선택한 후속이다. 문헌 보조·찬성 설계·반증 검토를 gpt-6.1-sol/max 세 명으로 필요할 때만 나누고 총괄이 새 수식·코드·검증 범위를 대조했다. 이번은 CPU 자료/합성 gradient 준비이며 실제 모델·학습·GPU 효과는 NOT_RUN이다. 계획은 P106B Stage4en, 수치와 원로그는 [결과101 §272](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)가 소유한다.

### 12.1 원문에서 실제 읽은 방법과 우리 적용의 차이

**권장**은 정상CE+행별 답 우도 대조다. 두 번째는 ORPO 같은 선호 odds 대조, 세 번째는 ContraCLM/SimCTG 같은 표현 대조다. 첫 안은 이미 관측한 ‘질문 신호는 있으나 같은 질문 아래 오답이 더 높음’을 가장 직접 겨냥하고 추론 계수를 늘리지 않는다. 다른 두 안은 선호쌍/표현 기하를 추가로 설계해야 하므로 이번 팔에 섞지 않는다. 이는 논문 원형의 재현 인증이 아닌, 문헌에서 착안한 독립 로컬 손실이다.

### 12.2 왜 열별 질문 우위나 대각합만으로는 부족한가

행이 질문, 열이 답 후보인 내용 평균 로그우도 표를 `S=[[-4,-1],[-12,-0.5]]`라고 하자. 각 정답 후보는 자기 질문 아래에서 더 높다(열 차이8,0.5). 올바른 배정의 합도 교차 배정보다8.5 높다. 하지만 첫 질문에서는 오답−1이 정답−4보다3 높아 여전히 틀린다. 따라서 두 질문의 개별 정답 선택을 따로 가르쳐야 한다.

새 손실은 `CE/실제 양성 target수 + 0.1*sum(softplus(교차답 내용평균우도-정답 내용평균우도))/실제 관계 질문수`다. 정답 EOT는 CE에 포함하고 대조에는 넣지 않는다. 실제 최적화 분모는 micro가 아니라 전체 optimizer update가 소유한다. `.1`도 실제 gradient에서 작다는 뜻은 아니며, `CE/W`와 `lambda*대조/E`의 상대 크기는 W/E에 달린다.

서로 다른 길이의 두 답을 평균으로 비교하면 공통 prefix의 정확한 상쇄도 보장되지 않는다. 그래서 첫 Stage4en은 실제 BPE 내용 길이가 같은 관계쌍만 사전 선별하고, source 사실표로 양방향 교차답의 부적합을 확인한다. 자연 TRAIN의 문자구별12854쌍을 자동 오답으로 바꾸지 않는다. 모든 입력/후보는 두 팔에서 같고 λ만0/.1이다. 교차 후보의 forward 비용이 없어지는 것은 아니므로 실제 시간·VRAM은 양팔 cost8에서 따로 잰다.

### 12.3 검증 수준과 남은 원인

합성 CPU는 gradient·shift/EOT·분모·행/열 반례·해시/원형 결합을 검증한다. 실제 토크나이저 검산은 완전한 답 coverage와 정답 없는 생성 prefix,1024 내 입력을 확인한다. 어느 것도 실제 자유 답·자연 QA·언어 보존·GPU OOM 안전을 증명하지 않는다. 점수는 최초 분기 token 마진까지 별도로 남기지만, 분기가 뒤에 있으면 이는 두 후보가 공유한 teacher-forced prefix의 점수다. 실제 모델이 그 prefix까지 생성했다는 뜻은 아니다.

새 TEST는 같은24개 이름·4개 역할 가족 안의 새 사실 배정이다. 한영128묶음은 독립 사실64개의 번역 두 개씩이며 새 이름·새 관계의 전이가 아니다. 실제 평가에서는 후보 없는 첫 답의 양질문 모두 정답,역순 사실표,미학습 질문 틀,자연 QA·산수 monitor와 원문32크롭 손실을 별도 기록한다. 이름/앞뒤 규칙만 맞춘 부분 성공을 범용 지능이나 Falcon 동급으로 부르지 않는다.

### 12.4 돌파구 후보 — 질문뿐 아니라 사실 배정도 바꾸기 (미구현)

[Counterfactually Augmented Data](https://arxiv.org/pdf/1909.12434)의 §3 데이터 작성·검토 방식은 최소 변경으로 라벨을 바꾸는 연구다. 원 검증은 분류/NLI이며 한국어93M 생성 QA의 성공을 보여준 것이 아니다.

후속 가설은 원래 ‘민수의 스승=지훈, 안내 담당자=수진’에서 두 역할의 사람만 맞바꾼 새 기록을 만들고, 같은 질문의 답도 함께 바꾸는 것이다. 이름 일괄 치환·문장 순서·질문 역할을 독립적으로 바꾸면 고정 인명/앞뒤 선호로는 전체를 맞히기 어려워진다. 같은 사실 배정의 모든 번역/변형/반사실은 split 가족을 공유해야 한다. 이 방법이 자연 QA까지 이전된다면 유용하지만 합성 규칙 암기에 그칠 수도 있다.

**현재 A에 섞지 않는다.** Stage4en의 질문별 답 선택과 실제 전이/보존 결과 뒤 별도 대조로 검토한다. 이번 view1의 사실 줄 역순을 이 반사실 값 교환 실험이라고 주장하지 않는다.

## 13. 2026-10-19 대상×관계 네 질문 — 실제 오류를 포함하는 대조

현재 근거는 [101 §282~284](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)다. 양팔768회 학습·각990자유답·값교환256답/모델과 원형 재집계가 완료됐다. 기존 TF 두 후보를 잘 가르면서도 CE 기본뷰107오답은 모두 **다른 대상의 같은 관계**였다. 따라서 §12의 CPU 준비 및 값교환 미구현은 당시 상태이고, 현재 실행 범위는 이 결과를 따른다. 일반 QA·산수 실패와 한국어 전이 한계는 남는다.

### 13.1 직접 가까운 선행 방법과 적용 한계

### 13.2 네 양성 질문 자체가 바꾸는 것

한 표의 두 대상×두 관계가 서로 다른 네 답을 가지면, 역할만 보거나 대상만 보는 결정적 정책은 네 질문 중 최대2개, 상수 답은 최대1개만 맞힌다. 기존처럼 한 대상의 두 질문만 내면 역할만 보는 정책도 둘 다 맞힐 수 있다. 이는 제한된 정책의 계산적 상한이지 무제한 신경망·암기·위치 규칙에 대한 증명은 아니다.

그러므로 새 Stage4er는 CE4 / 같은대상·다른관계 음성1개 / 모든 다른답 음성3개를 같은 네 양성·전체16점수·896업데이트에서 비교한다. 옛 A768→새896의 개선을 음성 추가만의 효과로 읽지 않는다. 새 CE4만으로 좋아지면 양성 질문 범위 수리가 더 싼 해결일 수 있다.

### 13.3 평균화·대안·우선순위

음성3개를 합산하지 않고 행별 평균하므로 손실이 단순3배 되지 않는다. 반대로 핵심 ‘다른대상·같은관계’ 한 음성의 계수는λ/3이므로 다른 두 음성이 쉬워졌을 때 유용한 gradient가 희석될 수 있다. 동일λ가 동일 gradient 크기를 뜻하지 않는다.

현재 세 팔을 먼저 완결한다. 추가 이득이 없으면 **같은4×4에서 다른대상·같은관계 음성1개만 선택**하는 대조, 그다음 **정상 CE+후보4 softmax**를 고려한다. 후자는 `logsumexp(네 후보 점수)−정답점수`이고 현재 pairwise softplus와 다른 목표다. 기존 실행 중 손실·온도·λ를 바꾸거나 문턱을 사후 완화하지 않는다. 더 큰 λ 전수탐색·복사 head·표현 개입을 한 팔에 섞지 않는다.

후보 길이/내용합·평균/EOT·최초분기와 실제 첫답을 분리하고, 네질문 모두정답·다른대상오류·자연QA·native 보존을 함께 판독한다. 현재의 익숙한 이름/관계·반복관측 개발 코호트·단일seed 한계도 유지한다. 조건부 문맥 연결의 개선을 일반 한국어·논리·세계지식·Falcon 동급으로 승격하지 않는다.

## 14. 질문 위치·최근성과 반복량 — 확장 문맥이나 복사 head 전에 구별할 것

[Lost in the Middle arXiv v3 §4.2·그림9](https://arxiv.org/pdf/2307.03172)는 질문을 본문 앞뒤에 배치한 경우 합성 key-value 검색은 크게 개선됐으나 자연 다문서QA는 일관되게 개선되지 않았다고 보고한다. v1은 같은 논의가§5.2다. 대상은 큰 decoder 모델/별도자료이며 93M 삼진 TinyLM의 개선 근거로 옮기지 않는다.

우리 `_user`의 자연QA view2는 지시문과 함께 질문을 본문 뒤에서 앞으로 옮긴다. 따라서 [101 §290](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)의 한국어4/256·영어6/256을 순수 재표현 실패로만 읽으면 안 된다. 하드 길이상한 미초과도 앞 질문 유지/거리 문제가 없다는 뜻은 아니다. 관계자료 view2는 질문 위치가 그대로여서 별도 축이다.

총괄은 독립 Stage4es에서 같은CP·같은지시/질문/전체지문을 CQ/QC/QCQ/CQQ로 평가하도록 준비한다. CQ 대 QC는 위치/거리, QCQ 대 CQQ는 질문두번을 맞춘 배치 대조지만 후자는 모든 기제를 완벽히 분리하지 않는다. 입력토큰 차이/거리/길이사분위·root/기사·실제 첫답·STOP/MAX_NEW를 함께 보존한다. 정답주변crop·후보/골드위치 힌트·훈련·자동prompt채택은 없다. 기존동일CQ 원답재현도 독립 확인한다.

다음 후보는 계산가능 산수/상태갱신 교과과정, 자연QA 대상·속성 대응, 작은복사경로다. 기존203오답의 최초분기부터 오답선호라는 사실은 우선 ‘잘못 고른 답’ 문제를 지지하지만 어느층이 원인인지는 증명하지 않는다. 위치/길이와 현재896세팔의 결과를 먼저 회수해 기존P106D나본문보조 실패를 그대로 반복하지 않는 설계를 고른다. 이 절은 조사/설계이며 새CPU/GPU 성공이나 일반지능 개선의 기록이 아니다.

## 15. 결정 토큰·주의 경로·짧은 실행 상태 — 현재 대조 이후의 조건부 문헌 후보

2026-10-19 문헌담당의1차3편 검토 뒤 총괄도 원문의 해당 방법/한계/표를 직접 재확인했다. 문헌·코드조회와 이절 문서화 외 새모델실험/외부코드설치/모델변경은 없으며 **아래 후보는 아직 실험 채택이 아니다.** 기존896세팔·질문위치·P106D이력 진단의 실제결과가 먼저다.

### 15.1 CRINGE와 구별되는 코드정답 최초분기 지도

[CRINGE, ACL2023 §3 식3~5·Algorithm1·§6](https://aclanthology.org/2023.acl-long.493.pdf)는 음성token과 모델 top-k에서 뽑은 대체token의 logit을 대조하며 정상CE를 유지한다. 원문은 좋은 대체token을 내는 기존모델이 필요하다는 한계와400M/3B 조건을 명시한다. 따라서93M 삼진에 그대로 옮기거나 임의top-k를 정답으로 삼을 근거가 없다.

**우리의 조건부 변형/추론**: 코드가 유일정답을 인증한 TRAIN의 같은 질문에서 정답/다른사람답이 처음 갈리는 위치를 찾고, 정확히 같은 prefix 아래 `softplus(logit_wrong−logit_gold)`를 정상CE/EOT·native보존과 함께 학습할 수 있다. 원논문 재현이 아니라 gold를 아는 닫힌과제용 변형이다. 기존sequence평균과 달리 최초결정 위치를 직접 겨냥하나 제3의 오답으로 옮겨갈 수 있다. 자연QA의 다른 문자열을 자동음성으로 바꾸지 않는다.

다른 후보는 이미 §13에서 제안한 네후보 정규화 `logsumexp(S_i0..S_i3)−S_ii`다. pairwise평균은 쉬운음성에 유효gradient가 희석될 수 있지만 listwise가 항상우월한 것은 아니다. 동일λ여도 gradient크기는 달라진다. 최초분기 손실과 listwise를 한팔에 합치지 않고 실제첫답/네질문모두정답·분기마진·새오류축·종료/native를 비교해야 한다. 기존코드검색에서는 first_divergence는 평가/재계수에 쓰였고 현재학습루프는 sequence대조다.

### 15.2 실제 attention 지도는 위치효과와 같지 않다

[Guiding Attention, Findings2020 §3.2 식2~4·§5.6/Table8](https://aclanthology.org/2020.findings-emnlp.419.pdf)는 지정한 attention패턴과의 MSE 보조목표를 사용한다. MLM 손실이 좋아져도 Table8의 개별head 상호참조 성적은 나빠질 수 있었다. 낮은언어손실/높은attention값을 대상연결 성공으로 읽지 않는다. 원문의MLM/큰모델 조건을 우리causal모델에 복사하지 않는다.

**조건부 변형/추론**은 제한된 일부head/위치에서만 질문의대상·관계 단서를 활용하도록 돕는 것이다. causal방향상 앞질문이 뒤본문을 보게 하는 지도는 불가능하다. 뒤본문이 앞질문을 보거나 마지막답 위치가 앞질문/본문을 보는 경로만 가능하다. 현재모델의CLA/KV소유·SDPA/compile과 새head계측 구현 부담이 크므로 위치대조의 효과가 뚜렷할 때만 추가검토한다. 단서attention 증가에도 다른사람답/질문속이름복사가 늘면 반증이다.

### 15.3 Scratchpads — 지도만 추가하고 추론에서 지워도 된다는 근거가 아니다

[Scratchpads, arXiv2112.00114 §3·§5.2.1·부록B/Fig7](https://arxiv.org/pdf/2112.00114)는 중간계산을 출력해 덧셈/실행을 학습한다. 덧셈은2M~1B의사전학습모델·100k예제/5k단계와별도자리수표기를썼다. 저자료MBPP에서는 직접출력보다나빴고, scratchpad학습뒤다시답만출력하도록학습한조건에선앞선이득이남지않았다. 추론중중간단계를없애도효과가유지된다는근거가아니다.

**조건부 변형/추론**은 코드로 검산한1~2단계의선택/현재상태를 실제로 생성한 뒤 답하는 별도소형대조다. 긴자유사고의진실성/teacher사고복제를보장하지않는다. 입력이같아도지도token·생성시간·오류기회가늘므로동일update만으로알고리즘효과를분리할수없다. gold중간상태를 추론에 주지 않고 스스로생성한상태/최종답·실제앞답의후속갱신·새숫자/이름을검사해야한다. 단순부호·보조분류를가르치는기존P106D/상태aux와구별한다.

### 15.4 현재 근거의 우선순위

| 관측 뒤의 조건 | 후보 | 비용·위험 |
|---|---|---|
| 같은위치에서도 최초분기 오답선호가 남음 | 정상CE+코드정답 최초분기 또는 네후보정규화 중 하나 | 별도head0; 계수/gradient·제3오답·보존 검증 필요 |
| 앞뒤질문/거리 효과가 큼 | 같은조건의 질문배치교육을 먼저, 실제attention지도는 그다음 | 원인분리는 작지만 head/커널변경은별도구현 |
| 조회는되고 계산·실제이력 갱신만 실패 | 짧은code-state 실제출력 | 출력/지도량·계산비용증가·gold상태 의존 위험 |

세후속을한팔로합치지않는다. 현재결과만으로일반지능/Falcon동급/75M준비/기본모델승격을선언하지않으며, 이미구현된동일학습목표가발견되면신규라부르지않고중복으로제외한다.

## 16. QK gain은 구현돼 있다 — 기존 기능 증거와 아직 없는 품질 증거

2026-10-19 문헌담당과 총괄은 기존 P101A 계획·[결과092 §2/§7](../../test_result/092_20260925_P100-정성한계-P101A-M0-이식문턱실패.md), `tinylm/model/modules.py`의 RMSNorm/Attention, `tinylm/train/p101a_contract.py`, 모델의 optimizer 그룹을 직접 읽었다. 이번 확인은 읽기 검토와 본절 문서화이며 새모델/가중치텐서계산/GPU실행은 없다. §4의 과거 ‘gain 미구현’은 당시 상태이며 현재 사실로 재사용하지 않는다.

현재 `qk_gain_learnable`은 기본off이고, on이면 각층 Qhead별 `tau=0.5+3.5*sigmoid(logit)`을 Q의 정규화·RoPE 뒤에 곱한다. 초기tau1이다. 작은모델 기능과 과거 고정16층M0의9token 입력에서는 QK독립팔 logits 차0·gradient존재를 확인했지만, 현재P090B/chat32의 이식·긴prompt/cache 동등성과 QK학습/품질은 **NOT_RUN**이다. 결합E384 실패를 QK 자체실패로 묶지 않는다.

[QKNorm 원문 §2~3 식2/3/5·Table1](https://aclanthology.org/2020.findings-emnlp.379.pdf)은 unit-L2 정규화에 학습scalar g를 곱한다. 초기 g의 L은 최대context가 아니라 학습 source/target 길이의97.5분위이며 Table1은72~79다. 따라서 최대1024를 넣은20이 우리최적값이라는 주장은 근거가 없다. 현재는 파라미터없는 RMSNorm 뒤 기본SDPA의1/sqrt(d)를 유지하므로 eps/반올림을 제외하면 cosine계수는 `tau*sqrt(d)`이며 head64에서 약8tau다. 정의를 변환해 비교해야 하며 bounded·head별tau도 논문의scalar와 같은 계약은 아니다.

같은head의 q/k를 고정하면 양의tau는 key순위를 바꾸지 않고 집중도만 바꾼다. 이후층 hidden/KV까지 고정된다는 뜻은 아니다. 다른대상을 더 강하게 볼 위험도 있으며, 다른logit들이0이라는 추가가정 없이 길이와8만으로 최대attention확률을 단정하지 않는다. 현재답실패를 ‘스케일8 구현오류’로 설명하지 않는다.

기존 exact-key 이식helper를 이용하면 같은E/vocab/dim의 FP32 부모에 신규gain키만 보충해 strict load할 수 있다. `strict=False`나 기존 core 수정은 필요하지 않다. 다만 과거 legacy M0용100M trainer에 현재P090B/chat32를 그대로 끼우는 것은 다른문제다. attn_group1에서만 허용되며 CLA2의 K/V공유와 층별Qgain을 구분해야 한다.

14층·12Qhead라면 계산상 신규168개·FP32672B이며 새KV텐서는 없다. 이는 실제peak메모리/임시activation/optimizer/export 크기의 실측이 아니다. 기존 optimizer는 gain을 AdamW의LR×0.1/WD0으로 나누고 Muon행렬경로에 넣지 않는다. Q projection의 양의배율에 흡수하면 뒤 RMSNorm이 그배율을 대부분 지워 대체가 되지 않는다.

향후 조건부 무학습대조에서는 같은체크포인트의off/이식tau1을 먼저 검증한 뒤 다른gain마다 prefill/KV를 새로 만들어야 한다. gain변경 전 cache를 재사용하면 뒤층 hidden/KV 조건이 섞인다. 현재896세팔·질문위치·P106D이력 진단보다 앞당기지 않으며, 아직 새gain sweep/학습 런처나 성능개선 증거는 없다.

## 17. 문맥 대비 생성과 첫 분기 학습 — 현재 결과 뒤에 검토할 후보

2026-10-19 문헌 담당의 검토 뒤 총괄이 아래 원문의 방법·실험·한계 절을 직접 확인했다. 이번 절은 문헌과 제한된 코드 검색의 기록이다. 새 생성기·loss·모델·GPU 실험은 **NOT_RUN**이며 현재 세 팔·질문 위치·실제 이력 진단의 순서를 바꾸지 않는다.

### 17.1 CAD: 같은 모델에서 문맥 유무를 대비

[Shi et al., NAACL2024 §2.2·§3·§5·Limitations](https://aclanthology.org/2024.naacl-short.69.pdf)는 다음 토큰 점수를 `(1+alpha)*z(context,question,prefix)-alpha*z(question,prefix)`로 조절한다. 문맥이 생겼을 때 확률이 더 오른 토큰을 강조하는 무학습 방식이며 alpha0은 기존 생성이다. 원문의 요약·지식충돌 결과를 현재 93M 한국어 모델의 대상 연결 성공으로 옮길 수는 없다. 이미 문맥에 정답과 다른 사람의 값이 모두 있는 경우에는 오답도 강조될 수 있다. 원문도 최적 alpha의 모델·과제 의존성을 명시한다.

총괄의 국소 유도는 같은 causal prefix에서 `mCAD=mF+alpha*(mF-mQ)`다. 여기서 m은 정답 토큰과 오답 토큰의 logit 차이다. mF<0이고 mF<=mQ라면 어떤 alpha>=0도 이 두 토큰 순서를 고치지 못한다. 이는 고정 prefix에서의 쌍 비교이지 실제 전체 생성이 언제나 실패한다는 증명이 아니다. 정답을 보며 문항마다 alpha를 고르는 용도로 사용하지 않는다.

조건부 진단은 균형 DEV에서 사전에 정한 소수 alpha를 비교하는 것이다. 생성기에는 정답·후보·정답 prefix를 주지 않는다. 같은 모델 가중치는 공유하되 문맥·위치가 다른 두 경로의 prefill/KV는 공유하지 않고, 매 단계 선택한 실제 토큰을 두 경로에 똑같이 추가해야 한다. CLA의 KV owner 관계도 경로별로 유지한다. 출력당 두 forward와 두 cache가 필요하지만 실제 속도·peak 증가량은 아직 미측정이다.

### 17.2 일반 CD: 부모를 빼면 무조건 좋아진다는 방법이 아니다

[Li et al., ACL2023 §3.1~3.4·§7.4](https://arxiv.org/html/2210.15097)는 큰 expert와 작은 amateur의 log 확률 차이를 최대화하면서 expert가 충분히 그럴듯하게 보는 어휘로 제한한다. 제한이 없으면 두 모델 모두 거의 안 쓰는 이상한 토큰이 비율 때문에 선택되거나, 둘 다 맞게 아는 정상 토큰을 벌할 수 있다. 원래 주 실험의 모델 크기 차이·beam 탐색을 같은 크기의 TinyLM 부모/학생과 greedy 대비로 바꾸면 별도 변형이다. 두 모델이 같은 오류를 공유할 때도 이득을 보장하지 않는다.

### 17.3 첫 분기 지도와 cDPO의 차이

[Critical Tokens Matter v3 §2·§3.1~3.3](https://arxiv.org/html/2411.19943v3)는 정답/오답 경로에 따로 맞춘 두 모델의 대비로 토큰 점수를 만들고 오답의 reference log-ratio에 `1-s_t`를 곱하는 cDPO다. rollout과 두 추정 모델 학습이 필요하며 단순히 정답/오답의 문자열 최초 차이만 학습하는 논문이 아니다. 인과적으로 중요한 토큰과 최초로 다른 토큰도 같은 개념이 아니다.

현재 `subject_role`의 학습은 완성 답의 content mean softplus이고 최초 분기는 평가용이다. 기존 `scripts/p106b_binding_auxiliary.py`의 첫 assistant hidden 이진 head도 이미 있는 구현이므로 새 방법으로 재제안하지 않는다. 기존 어휘 logits에서 코드로 인증한 정답·오답의 공통 prefix를 확인하고 최초 차이의 `softplus(margin-z_gold+z_wrong)`를 더하는 것은 별도 국소 변형 후보다. 이미 있는 정답 신호를 집중시키는 변경이지 새 진실을 얻는 방식이 아니다. 양성 CE·자연 QA·native replay와 제3 오답·정상 종료 보호가 필요하다.

## 18. 2026-10-19 작은 모델의 교육·질문 위치 — 세 원문의 적용 한계

현재 실제 결과는 [101 §299~301](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)이 소유한다. 문헌의 큰 모델·우도·추가 과제 재학습 결과를 TinyLM의 자유 답변 성공으로 옮기지 않는다. 이번 검토 자체로 새 교과과정·라우터·context 상한·epoch를 채택하지 않았다.

### 18.1 CLASS-IT: 크기는 가깝지만 자유 생성 검증은 아니다

[CLASS-IT v1 §3~7·Tables1~2·Limitations](https://arxiv.org/html/2510.25364v1)는100M/140M 모델에서 대화·QA의 혼합과 순차 교육을 비교했다. 추가 과제 재학습/우도 기반 평가의 국소 이득을 보고하지만, 일반 자유 대화가 된다는 증거는 아니다. 순차 교육을 검토할 가설은 얻을 수 있으나 현재4epoch·1024를 논문의10epoch·약6k로 바꿀 근거는 아니다.

본문의8.7M words 부분집합,18M words 전체 자료,10epoch/180M words 노출은 연결이 불명확하다. words를 우리 BPE tokens와 비교하지 않는다.100M과140M은 폭·깊이·vocab도 달라 크기만의 효과가 아니다. SuperGLUE 참고문헌이 동명 CV 논문을 가리키는 오류는 있지만, 그것만으로 실행 코드까지 잘못됐다고 단정하지 않는다. 그림 수치를 새로 추출하거나 z-score를 학습seed 유의성으로 읽지 않았다.

### 18.2 질문 반복: 보편 처방이 아니라 모델별 진단

[Asking Again and Again v3](https://arxiv.org/html/2412.07923v3)는 여러 큰 모델·읽기 자료에서1/3/5회 질문 반복을 비교했으며, 전체적으로 통계적으로 유의한 이득을 확립하지 못했다. 비유의는 모든 설정의 동등성 증명이 아니다. 정답 문자열 포함 채점도 우리 첫답 완전일치와 다르다.

우리 QPOS에서는 같은 CP/원문/질문·지시를 고정했을 때 앞 질문이 약했고, 앞뒤/뒤두번의 이득은 일관되지 않았다. 이 자체가 현재 모델에 더 직접적인 관측이다. 논문의 큰 모델 결과를 근거로 반복 횟수3/5를 기본 적용하거나, 반대로 모든 반복을 금지하지 않는다.

### 18.3 문맥 교육: 핵심 손실은 이미 있고 다른 문제와 구별해야 한다

[Lee et al., EACL2026 §2~3·Appendix A.1/Table5·Limitations](https://aclanthology.org/2026.eacl-long.320.pdf)는7~8B 모델에서 문맥을 조건으로 응답 토큰만 학습하는 방식과 문맥 없는 교육을 비교한다. 현재 TinyLM의 문맥 입력/assistant-only CE는 이미 이 계열이므로 새 구현이라고 재제안하지 않는다.

Table5의 Llama3.1-8B는 문맥 입력/문맥손실 제외61.2, 대응 응답 문장 앞 문맥/문맥손실 제외61.5다. 임의 질문 반복과는 다른 조작이며0.3pp를93M의 보장 이득으로 사용할 수 없다. 관련·신뢰 가능한 근거를 전제하고, 문맥 attention 증가가 올바른 대상 선택의 충분조건은 아니다. 두 모델 routing의 추가 상주·학습 비용을 엣지 기본안으로 자동 채택하지 않는다.

## 19. 2026-10-19 지도 토큰의 평균과 짧은 답 교육의 비중 — 후속 가설, 현재 목적함수는 보존

### 원문 확인과 적용 한계

[Hugging Face의 공식 gradient accumulation 설명](https://huggingface.co/blog/gradient_accumulation)은 누적 update 전체에서 유효 토큰 CE의 합을 전체 유효 토큰 수로 나누도록 구현한다. micro별 평균을 단순 평균하는 것과 다르다. 현재 Stage4et의 전체 assistant-token 분모는 이 수학적 정의와 맞으며, 짧은 답의 성적이 나쁘다는 이유만으로 구현 오류라고 부르지 않는다.

[NVIDIA Nemotron3 Super 기술보고서 §3.1·식1~2, 인쇄18~19쪽](https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3-Super-Technical-Report.pdf)은 전체 출력 token 평균 뒤에 대화별 출력 token 평균을 다시 대화 수로 평균하는 SFT 단계를 쓴다. 긴 입력·짧은 출력의 열화를 다루려는 목적은 관련되지만, 동시에 packing256k→512k·batch64→32·장문 자료도 바뀌므로 순수 정규화 효과라고 읽지 않는다. 120B/활성12B 연구이지 TinyLM93M 삼진 모델에서 검증된 recipe가 아니다.

[MFTCoder §3.5·식1](https://arxiv.org/pdf/2311.02303)은 과제별 유효 token 평균을 과제 수로 평균하고, yes/no 같은 짧은 출력의 불균형을 논의한다. 더 큰 코드모델·별도의 focal/수렴 균형·QLoRA 연구이므로 보고된 성능이나 과제 가중치를 그대로 이식하지 않는다. 과제 구분 자체의 타당성도 저자들이 한계로 남겼다. 위 두 PDF의 원문 수식과 주변 설정을 직접 대조했으며 새 파일을 다운로드하거나 학습 자료로 취득하지 않았다.

### 무엇이 다른가

대화 i의 지도 CE 합을 S_i, 지도 token 수를 n_i라 하면 현재값은 sum(S_i)/sum(n_i)다. 대화 평균은 mean(S_i/n_i)라 짧은 대화의 token당 계수를 높인다. 과제 평균은 과제별로 합한 CE/target 수를 평균하므로 전혀 다른 재가중이다. 같은 행 quota가 같은 지도량·기울기 크기·학습 진척을 보장하지 않는다. replay 한 행은 여러 assistant turn을 포함하므로 ‘대화 평균’과 ‘답변 turn 평균’도 구분한다.

단순 대화 평균은 종료 EOT의 계수도 바꾼다. 재표현/산수의 내용이 좋아진 것인지, 짧게 끝내기만 더 배운 것인지 분리해야 한다. 실제 EOT 비중과 손실·기울기 지배는 다른 관측이며 현재 비중만으로 원인을 확정하지 않는다.

| 후속안 | 달라지는 것 | 이점·한계 | 현재 상태 |
|---|---|---|---|
| A 현 token 평균 유지 | 목적함수 불변·실제 과제/content/EOT 비중과 자유답부터 회수 | 가장 직접적인 기준선이나 짧은 답의 낮은 계수는 남을 수 있음 | 현재 Stage4et 선택 |
| B content만 대화 길이 재가중·EOT 계수 보존 | 같은 자료/순서/부모에서 content token 내부 비중만 변경 | 종료 지도량 교락을 줄이나 새 목표함수·분모/gradient 회귀 필요 | 결과 회수 후 조건부 후보 |
| C 과제별 평균 | 코드/자연QA/replay 또는 검증된 과제 단위별 objective 균형 | 짧은 과제에 비중을 줄 수 있으나 과제 경계/상대계수 자체가 새 선택 | 별도 후보, 자동 채택 아님 |

B의 한 구체식은 content CE를 C_i, 그 token 수를 c_i, EOT CE 합을 E, N_C=sum(c_i), N=N_C+N_E, 양의 content를 가진 대화 수를 B_+로 두고 다음을 비교하는 것이다.

```text
기준 L0 = (sum(C_i) + E) / N + native_CE_sum / 8192
후보 L1 = (N_C / N) * mean_{c_i>0}(C_i / c_i) + E / N + native_CE_sum / 8192
```

N_C=0인 경우 content 항을0으로 두고 EOT를 유지한다. 이 식은 총 content/EOT **계수 질량**을 보존하는 총괄의 통제 설계 후보이며 인용 논문의 채택식도, 같은 gradient norm의 보장도 아니다. 정해진 미니배치의 실제 수에서 계수가 나오므로 임의 상수를 성능 정답으로 승격하지 않는다.

현재 네 팔에 이 식을 몰래 넣지 않는다. 먼저 실제 target/content/EOT 통계와 같은 부모의 새 표현·위치 결과를 회수한다. 후속을 열면 같은 frozen cell·384회/4epoch·부모/순서/LR/clip/native 벡터·평가64를 유지하고 정규화만 바꾸며, 평가에서는 동일한 비가중 CE/content/EOT와 자유답·망각을 함께 본다. 재가중한 학습손실 감소나 종료만의 개선을 지능 향상으로 부르지 않는다. 새 학습·목적함수 변경은 아직 **NOT_RUN**이다.

### 2026-10-19 조건부 구현 경계 보완 — 현재 네 팔에는 미적용

현재 실제 교과의 pass당75664지도토큰은 content56912/EOT18752다. 산수는2048행이어도 content2570으로 전체content의4.52%다. 이 비중은 기울기 부족의 증명이 아니며 먼저 현재 네팔의 실제 답을 회수한다.

후속 B를 선택한다면 고정된 한 대조 cell의 목적만 바꾼 **별도** reader/head 경로를 만든다. 현재 core.components는 CE를 scalar 합으로 즉시 줄이므로 이후 scalar를 가공해 대화별 재가중을 복구할 수 없다. 기존의 bounded vocabulary-head chunk/checkpoint 안에서 FP32 unreduced CE에 detached weight를 곱해 scalar를 반환한다. weight는 checkpoint 인자로 명시해 backward 재계산 시 loop변수의 늦은 결합을 피한다. logits목록을 보존하지 않되 transient chunk×vocab 메모리는 여전히 측정해야 한다.

전체16micro의 N_C/N/N_E/B_+와 각대화 c_i를 먼저 구하고 content weight=(N_C/N)/(B_+×c_i), EOT weight=1/N, 무시위치0을 모든 chunk/micro에 동일하게 사용한다. eligibility는 양의owner **및** y!=-100이고, C2첫오답의 owner만보고무시라벨을복원하지않는다. 여러지도turn은한encoded대화로묶는다. EOT-only행은 EOT와행수를유지하고B_+에서만제외하며 N_C=0과전부무지도인경우를분리한다. native CE/8192는변경하지않고SFT의EOT재가중을native에적용하지않는다.

EOT-target 손실의 계수를 보존해도 content CE에서 EOT가 경쟁하는 효과 때문에 EOT어휘행의 **전체** gradient가 같다는 보장은 없다. 같은 함수의 dense정답식 대 chunk/16micro의 loss·hidden/head gradient를 길이불균형·chunk경계·checkpoint on/off에서 맞추는 CPU시험, 무시C2/pad/여러turn/EOT-only/nativeterminal의 분모·직접gradient시험이 먼저다. 두목적 자체의gradient가같아야한다는잘못된시험은하지않는다. 이구현과새시험은아직NOT_RUN이다.

저가 진단 후보는 동결 골드의 content가 한토큰인 산수만 사전선정해 첫assistant predictor에서 골드logit-최대비종료경쟁logit과 종료logit-최대비종료logit을 나누는 것이다. 실제 생성에는 정답prefix나후보를주지않고같은max64자유답을그대로평가한다. 답선택분리가개선됐는지종료압력만바뀌었는지구별할보조관찰이지온라인정답판별기나지능점수는아니다.

## 21. 2026-10-19 정규화 후보의 반증 조건 보완 — 수식 검토만, 새 학습 미실행

문헌 보조의 읽기 전용 검토를 총괄이 수식으로 대조했다. §19의 L1은 하나의 **가중 정책 변경**이지만 과제와 무관한 길이 교정이라고 부를 수는 없다. 한 업데이트에서 a=N_C/N, content가 있는 행 수를 B_+, 과제 G의 그런 행 수를 B_G+, content token 수를 C_G라 하면 다음과 같다.

```text
현재 과제G의 content 계수 질량 = C_G / N
후보 과제G의 content 계수 질량 = a * B_G+ / B_+
각 EOT target 자체의 계수 = 두 식 모두 1 / N
```

예를 들어 content가 각1토큰인 코드 행2개와10토큰인 자연QA1행, 각행EOT1개라면 N=15다. 코드 content의 합계 계수는 2/15→8/15, 자연QA는10/15→4/15로 바뀌지만 EOT 합계는3/15다. 과제별 content 평균이라면 각각6/15이므로 세 방법은 다르다. 이는 산수·언어·C2 교정 turn처럼 길이와 연관된 과제의 실질 비중도 바뀐다는 뜻이다. pass 전체의 산수 content4.52%를 실제 업데이트별 계수 합계로 오해하지 않는다. 새 연구를 열 경우 매 업데이트의 실현 계수와 과제·언어·turn별 합계를 보고한다.

EOT는 총합만 아니라 **각 지도 위치의 계수1/N**를 유지하는 설계다. 그래도 content CE에서 EOT와 경쟁하는 gradient, 합친 gradient에 적용하는 global clip 때문에 종료 행동이나 native의 실질 가중치 이동까지 불변인 것은 아니다. 이는 동일 목적 변경의 결과이며, native 항의 명시적 분모8192를 유지했다는 사실과 구분한다. C2 첫 오답은 여전히 무지도 문맥이고 살아 있는 교정 내용만 재가중되므로, 교정 과제 비중 증가를 산수 논리 일반화로 바꾸어 말하지 않는다.

### 작은 대응 진단의 보완

현재 답안을 회수한 뒤, 같은 언어·과제·문구·위치에서 정답이 다른 단일 content-token 두 문항 x_A/x_B와 그 정답 token a/b를 사전 고정할 수 있다. 첫 assistant predictor에서 다음을 측정하면 입력과 무관한 덧셈형 어휘 선호를 상쇄한다.

```text
D = [z(a|x_A) - z(b|x_A)] - [z(a|x_B) - z(b|x_B)]
```

D에는 EOT가 없지만 이것만으로 정답을 보증하지 않는다. 같은 위치의 전체 어휘에서 정답 순위·최강 비종료 경쟁값·종료 압력과, 후보/골드 prefix를 넣지 않은 실제 자유답을 함께 기록해야 한다. D만 좋아지고 실제답이 그대로면 proxy 개선이다. 두 문항의 공통 변형 외 요인도 묶음으로 맞추고 TRAIN/heldout을 나누며, 이 관측을 모델의 모든 사고능력으로 확장하지 않는다.

이는 §19~20의 조건부 설계를 더 엄격히 한 검토다. 현재 Stage4eu 코드·분모·자료·네 조건은 바꾸지 않았고, 가중 CE 구현·이 진단·추가 학습은 모두 **NOT_RUN**이다. 별도 아키텍처 head를 추가하는 안도 아니다.

## 23. 2026-10-19 실제 학습 표면 진단 이후의 조건부 목적함수 대조

**인용과 추론의 구분:** Entity Tracking은 이 절에서 확인한 최종상태 감독의 근거이며, 별도 중간 사고문장/모든 상태표 출력이 TinyLM에 효과 있다는 증거로 쓰지 않는다. ParetoQ의 학습 가능한 스케일/quantizer도 현재 통계 기반 삼진 구현과 같지 않다. BitDistiller의 교사 분포 보존은 교사의 의미 오류까지 고쳐 준다는 뜻이 아니다. 작은 이야기 생성 성공과 특정 질문 대상의 정확한 조회도 별개의 과제다.

현재 root는 실제 scratch native 삼진/float와 각자 SFT, broad 순서, 같은 가중치의 교차 추론·고정 공개팩을 차례로 회수한다. 이 결과 이전에는 어느 문헌을 성공 처방으로 채택하지 않는다. 조건부 분기는 (1)float 실제답 우세+PTQ 손상이면 전환 QAT 후보, (2)같은 질문의 teacher 우세가 확인되면 KD 후보, (3)두 경로 공통 대상 혼동이면 감독/전이 문제를 우선한다. 이런 판단 자체도 새 실행을 대신하지 않는다.

비용의 참고는 현재 native298,975,232 draw의 runlog108.7분이며 새100M의 단순 외삽은 약36.4분/팔이다. 이는 시간영역 차이·새source/LR·QAT/KD overhead를 포함한 새 단독 cost가 아니며 보장하지 않는다. weight-only CP에서 optimizer를 새로 만들면 연속 optimizer 재개가 아니라 새 국면이다. full legacy readback 전에는 잔여 pool을 확정하지 않고, FP 과거299M+향후draw의 누적 노출과2배 풀도 함께 설명해야 한다. 본75M 대화 목표와 native 캐시/학습량은 계속 구분한다.


## 27. 2026-10-20 — DeepSeek 최신 보고서·Engram: 기억 용량과 질문 이해를 구분한다

사용자 추가지시로 기존 문헌 에이전트에 읽기·웹 조사를 할당했고, root도 아래 공식 자료의 관련 절을 확인했다. 설치·가중치 취득·API 호출·모델 실험은0이다. 검토 후보이며 구현/채택 승인이 아니다.

### 27.1 버전과 열람 범위

공식 변경기록의 최신 모델 업데이트는 **2026-10-17 DeepSeek-V4.1-Flash-1017**이다. 공식 공개 카드도 같은 이름이고 기반 구조 보고서를 재사용한다. 별도1017 구조 보고서는 확인하지 못했다. [공식 변경기록](https://api-docs.deepseek.com/updates/), [공개 모델 카드](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017).

기반 보고서는 [DeepSeek-V4.1-Flash 보고서](https://arxiv.org/html/2609.19969v1)(arXiv 2026-09-17)이고, 별도 [Engram v2](https://arxiv.org/html/2601.07372v2)는2026-07-12판이다. 동명의 대화기억 프로그램과 구분한다. 에이전트는 관련 절/표/부록·공식 코드를 읽었고 root는 Engram§2.4~2.5/6.4, V4.1§2.4.2/2.5와 공식 코드의 정규화/설명용 부분을 직접 대조했다. 모든 참고문헌 전문 완독이나 독립 재현이라는 뜻은 아니다. HF PDF 직접 열람 실패는 HTML 관련 본문으로 보완했다.

### 27.2 무엇을 하는가, 무엇을 하지 않는가

Engram은 입력 토큰의 짧은 연쇄로 학습 표를 조회하고, 문맥 hidden으로 주입량을 조절하는 신경망 경로다. 표와 투영은 학습되며 사용자별 사실을 즉석 기록하는 DB나 정답 판정기는 아니다. 모듈의 학습 파라미터와 요청별 KV 상태는 다르다. 원논문의 sparse 용량 재배분/동일계산 대조를 작은 dense 모델의 무료 용량 증가로 읽으면 안 된다. [Engram§2~3](https://arxiv.org/html/2601.07372v2).

V4.1은 원설계를 그대로 복사하지 않았다. 짧은 convolution을 제거하고2/3/4gram·FP8 표/투영과 momentum/Sinkhorn 갱신을 사용한다. 논문 규모를 TinyLM에 옮긴 실측은 없다. 같은 보고서의 Q/K head-wise Muon도 별도 아이디어이며 KV 압축 전체를 Engram 성과로 돌릴 수 없다. [V4.1§2.4.2~2.5](https://arxiv.org/html/2609.19969v1).

공식 demo는 실제 Attention/MoE/mHC 일부를 모사하며 운영용 KV decode 구현이 아니다. 주소용 NFD/StripAccents/소문자화는 chat32 원문 encode/decode 변경과 다르다. 한글 부분토큰/공백·대소문자·부정·숫자의 의미 구분과 정규화 충돌을 따로 확인해야 한다. [공식 코드](https://github.com/deepseek-ai/Engram/blob/main/engram_demo_v1.py).

원논문의 host offload 약2.8% 손실은 H800·512시퀀스·8B dense/100B표의 공급자 실측이다. CPU-only batch1의93M에 그대로 적용하지 않는다. GPU 메모리를 host로 옮겨도 전체 RSS/저장량은 남는다. [Engram§6.4 표4](https://arxiv.org/html/2601.07372v2).

### 27.3 현재 TinyLM에 대한 비판적 적용

현재 목표는 메모리 절감과 조건부 품질/속도 교환이다. dense14에는 MoE의 비활성 전문가 예산이 없으므로 표 추가는 실제 바이트 증가다. 기존 삼진 FFN과 FP16/FP8 표는 파라미터당 저장량이 다르며, 삼진 커널이 새 표를 자동 압축하지 않는다.

캐시 이후 새 토큰만 들어오는 생성 경로에서는 ngram 과거 토큰 상태가 추가로 필요하다. prefix 교체·배치·문서/role 종료·CLA/KV 소유권을 명시해야 한다. 재귀 방문마다 과거 토큰을 다시 추가하면 안 되고, 동일 주소 재사용과 매 방문 hidden gate 재계산도 구분해야 한다. 현재 [forward](../../tinylm/model/transformer.py)의 계약을 바꿔도 된다는 승인이나 기능증거가 아니다.

같은 지문에서 질문 대상만 바뀌는 현재 실패는 고정 국소 연상만으로 해결되지 않는다. 약한 hidden이 잘못된 prior를 통과시킬 수도 있다. 이는 root의 적용 가설이며 논문이 TinyLM에서 입증한 결론이 아니다. **ngram 조회는 오류 문구 blacklist·금지어·온라인 정답 필터가 아니다.** 폐기한 문자열 정답판정을 되살리지 않는다.

### 28.2 선행연구에서 가져올 것과 가져오지 않을 것

- [Scratchpads](https://arxiv.org/abs/2112.00114)의 중간계산 감독은 기존 §15.3의 검토를 계승한다. 단계별로 검산 가능한 짧은 상태/계산을 출력하는 개념은 후보지만, 추론 때 단계를 없애도 이득이 유지된다는 근거가 아니다. 이번에 전문 전체를 재검증한 것은 아니다.
- [DeepSeek-R1 v1 §2.4](https://arxiv.org/html/2501.12948v1)는 이미 학습된 Qwen/Llama를 선별800k 예제로 SFT한 증류다. 최소 학생도1.5B라 현재93M/짧은 문맥에 효과를 보장하지 않는다. 가져올 것은 선별된 문제·풀이·최종답과 간단한 과제의 직접답 구분이지 사고태그 자체가 아니다.
- [Coconut v2 §3–4](https://arxiv.org/html/2412.06769v2)는 이전 hidden을 다음 위치의 embedding으로 넣고 pretrained GPT-2에서 언어풀이→latent 단계교육을 쓴다. 현재 같은 위치의 층 재방문이나 MTP와 다르며 입력·위치·KV·순차 forward 경로의 별도 구현/검산이 필요하다. 논문에 있는 일반 성과를 TinyLM 채택 근거로 바꾸지 않는다.
- [Quiet-STaR v2 §4–6](https://arxiv.org/html/2403.09629v2)는 Mistral7B의 위치별 rationale 생성·전용마스크·mixing·학습보상을 결합한다. 단순히 태그나 작은 헤드만 붙이는 방법이 아니고 미래텍스트 확률을 사실정답으로 오해하지 않는다.
- [Falcon 공식 보고](https://tiiuae-tiny-h1-blogpost.hf.space/)에는90M reasoning 특화 모델도 있으나 기대 이하·반복 함정이 남았다고 적혀 있다. 별도90M tool-calling 혼합의 긴 CoT에서는 반복루프가 나타나 해당 traces를 제외한 저자 관측이 있다. 이는 모든 소형 thinking의 금지가 아니라 **과제·규모·자료복잡도에 따른 상충 근거**다. 우리 모델의 반복 원인을 그 보고만으로 확정하지 않는다.

주요 절·카드·코드 설명은 문헌 agent와 root가 나누어 읽었다. root는 위 원문 관련 절/표와 로컬 코드를 직접 대조했으나 각 논문의 모든 전문·코드를 재현한 것은 아니다. 문헌 agent는 실물CP/데이터/모델/GPU/파일/Git을 실행하지 않았다.

### 28.3 현재 가장 작은 유효 후보

### 28.4 문맥·감독량·비교의 실제 제약

질문+지문+풀이+최종답+EOT가1024 안에 모두 있어야 한다. 1+1 같은 짧은 입력의 실패를 문맥 한계로 설명할 근거는 현재 없으며, 긴 지문은 실제 token 길이를 재야 한다. 먼저 짧은 풀이의 실제 길이를 계측하고 최종답이 잘리면 명시 거부하며 자동 문맥삭제/상한증가를 하지 않는다. 문맥을 늘릴 때는 RoPE/긴문맥 교육·메모리·시간·KV 정합을 별도 축으로 검산한다. 태그2개는 이미 있지만 출력토큰·캐시는 공짜가 아니다.

[101§355~362](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)의8,208,652는4pass 실제입력이고 assistant target은302,656이다. 한 pass의75,664 targets와 고유8M 지식/대화 감독을 혼동하지 않는다. native replay3,145,728과의 token 비율은 별도분모로 정규화한 loss 비율이 아니다. 기존 Broad는 자연질문8192쌍의 두 표현+replay4096+일반2048의 다른 교과/부모이므로 새 scratch 학생과 자료량 단독인과로 비교하지 않는다.

Falcon 공식 Base는800GT 누적학습, 별도 Instruct는 SFT25%를 섞은800GT 학습 뒤 후학습이다. 같은90M대라는 이유로 현재299M 기본학습/302k assistant 감독과 같은 조건으로 놓지 않는다. 해당 반복·혼합비·학습량을 TinyLM의 최적값이나 반드시 필요한 최소량으로 복사하지 않는다. 공급자 성과와 로컬 동일문항 벤치도 별개다.

따라서 Q/K headwise 소형대조(A의 optimizer 후보)와 실제 assistant 감독/일반QA 확대(C의 자료 후보)를 섞지 않고, 긴 기본학습은 별도 한 팔 후보로 남긴다. 이 문헌검토는 신규 thinking·latent·RL 실행 승인이나 효과확정이 아니다.

### 30.2 현재 코드의 정확한 국소식

PyTorch 선형층의 행렬 방향을 사용한다. Q(W)는 현재 그룹 삼진화, a는 anneal, sg는 detach이며,

\[
W_a=Q(W)+(1-a)\operatorname{sg}(W-Q(W))
     \quad\text{(값은 }aQ(W)+(1-a)W\text{)}.
\]

현재 _TernarySTE.backward의 원소별 배율은

\[
S(W)=\frac{1}{1+(|W|/\max(c\alpha,10^{-8}))^4}.
\]

Y=XW_a^T, 상위 gradient G를 고정하면 국소 VJP는

\[
\bar W=(G^TX)\odot S(W),\qquad \bar X=GW_a.
\]

어닐과 무관한 것은 weight 쪽의 surrogate 배율 S이지 전체 모델 gradient가 아니다. 실제 G와 활성값은 forward·학습 상태에 따라 달라진다. a=0은 수학적 forward가 실수 값이어도 weight VJP는 window를 통과한다. 유한정밀도의 bitwise forward 동일성과도 구별한다.

detach는 보간 행렬의 **값을 삭제하지 않는다**. 따라서 P036 계획·현재 코드의 과거 설명 중 “detach 때문에 입력 gradient에 latent W가 들어가지 않는다”는 문구는 weight/input 미분 대상을 혼동한다. Arenas는 W_a에 별도 λW를 더하므로 forward·입력 VJP도 바꾸며, 비-detach 가산은 weight VJP에 λ 항도 더한다. 이 차이를 없애거나 Arenas를 현재 어닐과 같다고 할 수는 없다.

총괄은 현재 원형을 수정하지 않고 기존 Mini의2×2 CPU 합성 계산을 수행했다. a=0/.37/1에서 위 수동식 대비 input/weight VJP 최대오차는 모두0, identity weight VJP와는0.0202183723 차이가 있었고 파라미터는 불변이었다. 별도 float route는 plain-linear input/weight VJP와 정확히 일치했다. 이는 작은 수학 계약 검산이지 실제595M·일반 지능·품질 검증이 아니다. 코드·입력·출력은 WIP_20261021_STE_VJP_REVIEW.json에 보존한다.

### 30.3 외부 근거의 적용 한계

[Bengio 등 §4](https://arxiv.org/html/1308.3432v1)는 STE를 편향된 근사로 다루며 다층에서 보편적인 방향 보장을 주지 않는다. [Yin 등 §1.2·3.1~3.3](https://arxiv.org/html/1903.05662v4)의 이론은 두 선형층·이진 activation·Gaussian 입력 조건이다. 부적절한 STE의 불안정 사례를 현재 TWN weight/4차 window/Muon의 실패 증명으로 옮기지 않는다. 이 문헌은 선택할 surrogate가 중요할 수 있다는 근거이지 현재 window나 identity 중 하나의 승리 보장이 아니다.

[Sherry 식2·§3.2 식7~8](https://arxiv.org/html/2601.07892v1)은 STE와 latent residual을 다룬다. 현재 soft window의 최적성이나 새 TinyLM에서의 이득을 입증하지 않으며, 외부 비트/속도/정확도 배수를 현재 모델에 적용하지 않는다. 총괄의 위 VJP식은 실제 코드에서 직접 유도한 것이지 논문이 현재 코드를 검증했다는 뜻이 아니다.

### 30.4 세 후속 후보 — 현재 새 학습에 적용하지 않음

## 31. 2026-10-21 — E256 입출력 병목의 함수보존 확장 가능성, 아직 미채택

문헌 역할의 별도 가설을 회수하고 총괄이 transformer.py의 생성부·입력/헤드·INT8/packed 회계, init_utils.py, Muon, 결과030 §11과 관련 원문을 읽었다. 모델·CP·GPU·새 초기화/학습·큐 변경은0이다. 현재 Native595와 동일 Broad704의 원형을 우선 회수한다.

### 31.1 가능한 변환과 불가능한 추론

현재 A=[32768,256], U=emb_up.weight=[768,256]이며 입력은 A_t U^T, 출력 logits는 h U A^T다. E축 RMS나 sqrt(E) 배율은 없고 U는 TLinear가 아닌 일반 Linear다. 따라서 A'=[A,0], U'=[U,R]의 **새 열** 확장은 실수 수학에서 양쪽 초기 함수를 보존할 수 있다. 새 A의 gradient는 일반적으로 살아 있고, 새 U는 첫 역전파0이어도 A가 움직이면 열린다. 둘 다0으로 붙이면 죽은 경로다.

R의 규모는 첫 forward에는 영향을 주지 않지만 새 gradient 크기에 영향을 주므로 아직 정해지지 않았다. GEMM 형상·BF16 누산이 바뀌어 bitwise 보존은 보장하지 않는다. 기존 SVD 이식은 축소 전용이어서 단순 emb-rank512 옵션으로 이 변환이 구현되는 것도 아니다. 별도 변환/loader·계보와 초기 logits/생성·공유·RNG·gradient 검산이 필요하며 아직 NOT_RUN이다.

[Net2Net §2.2~2.3](https://arxiv.org/html/1511.05641v4)은 함수 보존 확장의 개념을 뒷받침하지만 위 tied bilinear 변환은 실제 TinyLM 식에서 도출한 것이지 해당 CNN 실험의 재현이 아니다. [Softmax bottleneck §2.1~2.2](https://arxiv.org/html/1711.03953v4)의 논의는 현재 logit 행렬의 랭크 상한을 연구할 이유이지 ‘256개 개념만 이해한다’는 결론이 아니다. [ALBERT §4.4/Table3](https://arxiv.org/html/1909.11942v6)도 embedding 확대의 보편적 단조 이득을 보이지 않는다.

[결과030 §11](../../test_result/030_20260807_P046-무KD-E128은-분해능의-20배-랭크축은-볼록하다.md)의 E256/192/128 손실3.6776/3.6931/3.7450은 당시 축소 비용의 근거다. 이를 뒤집어 E512 이득을 예측하거나 current14층 QA의 원인으로 확정하지 않는다.

### 31.2 정확한 추가량과 optimizer 한계

E256→512의 추가량은 (32768+768)×256=8,585,216 인자다.

|조건|추가량|해석|
|---|---:|---|
|A/U FP32|32.750MiB|고유 parameter tensor만|
|A/U FP16/BF16|16.375MiB|모두 해당 dtype으로 저장한다는 계산|
|두 인자 모두 INT8 값만이라는 가정|8.1875MiB|현재 저장경로가 아님|
|실제 A INT8·U FP32 경로|8.750MiB|행당 scale32768개는 그대로. 복원 scratch/전체 peak 제외|
|packed 회계·g128 가정|약1.7500MiB|추가인자×(log2(3)+16/128)/8. 실물 packed 파일이나 INT8 상주 증거가 아님|

파라미터+gradient와 A의 Adam 두 moment/U의 Muon momentum만 계산하면 지속 학습 tensor 증가량은130.250MiB다. AMP·활성값·NS workspace·allocator·속도는 미측정이다. KV 형상은 그대로지만 E축 연산·복원 scratch는 증가할 수 있다.

현재 U [768,256]→[768,512]에서 Muon rms 계수0.2sqrt(max(out,in))는 둘 다 max768로 같다. ‘행렬이 커졌으니 이 배율부터 달라진다’는 설명은 이 형상에 맞지 않는다. 이상적 [G_old,0]와0 momentum의 NS도 실수 수학에서는 기존 블록을 보존할 수 있다. 그러나 새 A gradient는 global clip norm과 이후 optimizer 이력을 바꿀 수 있고 BF16·eps·GEMM 차이도 남는다. 따라서 **초기 함수 보존과 학습 궤적 보존은 다르다.**
