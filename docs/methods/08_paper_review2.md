## 1. ★★GSQ — **우리 삼진 파라미터화와 같은 식을 쓰는데, 배우는 방법이 다르다**

- arXiv:2604.18556v2 (2026-05-15) · ISTA · Red Hat AI · ETH Zürich · 코드 `github.com/IST-DASLab/GSQ`
- ★**읽은 범위**: 초록 · §1 서론 · §2 관련연구 · §3 방법(3.1 삼진 · 3.2 일반 · 3.3 구현) · §4.1 실험설정.
  ⚠️**§4.2 이후 전체 결과표와 부록은 안 읽었다** — 아래 수치는 초록·§1·§4.1 에서만 인용한다.

### 1.1 무엇을 하는가

레이어별 재구성을 ***미분가능한 이산 배정 문제***로 다시 쓴다. 가중치 좌표마다
**후보 격자점 위의 학습 가능한 로짓**을 두고 **Gumbel-Softmax 로 soft 양자화값**을 얻는다.
온도를 어닐하면 soft 배정이 격자점으로 붕괴해 **완전 이산**이 된다.
그룹 스케일과 이산 배정이 **함께** 최적화된다.

### 1.2 ★★★우리와 정확히 겹치는 자리 — **§3.1 삼진 케이스**

논문의 삼진 제약(식 2):

    C_ternary = { ŵ = s · m ⊙ b ;  s ∈ ℝ,  m ∈ {0,1}^d,  b ∈ {−1,+1}^d }

★**우리 `ternary.py` 의 파라미터화와 같다** — 마스크(0 여부) · 부호 · 스케일 α.
그리고 그룹 규약도 같다: **symmetric · group-wise · 그룹 크기 128** (§4.1) =
우리 `micro_group=128` 과 **정확히 일치**.

★**그런데 배우는 방법이 다르다**:

| | 우리(현행) | GSQ |
|---|---|---|
| 이산 결정 | **STE**(hard threshold + 직통 그래디언트) | ★**Gumbel-Softmax**(로짓 2d개를 학습) |
| 시점 | ★**from-scratch QAT** | 🚫**PTQ**(이미 학습된 fp16 모델을 압축) |
| 초기화 | TWN 임계 | **GPTQ 삼진 해에서 warm-start** |
| 옵티마이저 | AdamW(또는 Muon) | ★**Lion** — Gumbel 포화에서 **AdamW 가 멈추기 때문** |

### 1.3 ★가져올 수 있는 것 넷

| # | 무엇 | 왜 우리에게 값이 있나 | ⚙비용 |
|---|---|---|---:|
| ★**1** | **STE → Gumbel-Softmax 로 이산 결정을 학습** | 우리 삼진 대가는 **아직 정면으로 안 줄여 봤다.** STE 는 1990년대 도구이고, 논문은 *"ternary GSQ 가 **2비트 스칼라 기준선 전부를 이긴다**"* 고 보고한다 | 구현 ⚙1.5h + 학습 1.4h |
| ★★**2** | ★**3:4 마스크를 학습으로 정한다** | §2 가 **MaskLLM** 을 인용한다 — *"Gumbel-Softmax 로 N:M 마스크를 end-to-end 학습"*. 🚫**우리 3:4 는 `\|w\| 최소 하나를 0` 이라는 고정 규칙**이고 대가가 **+0.04203** 이다. **배운 마스크가 그 대가를 줄일 수 있다** | 구현 ⚙1.0h |
| **3** | **Lion 옵티마이저** | Gumbel 을 쓸 때만 의미가 있다(#1·#2 의 부속) | — |
| **4** | **그래디언트 누적이 Gumbel 노이즈 분산을 줄인다** | 우리는 이미 `accum 16` 이다 — **공짜로 만족** | 0 |

### 1.4 🚫가져올 수 없는 것 셋

| # | 무엇 | 왜 |
|---|---|---|
| **1** | ★**방법 전체(PTQ 파이프라인)** | 🚫**우리는 fp16 사전학습 모델이 없다.** from-scratch 삼진이라 *"압축할 원본"* 이 존재하지 않는다 |
| **2** | **GPTQ warm-start** | 같은 이유 — 압축할 원본이 없다. ★**대신 우리 현행 TWN 해에서 warm-start** 하면 된다 |
| **3** | ⚠️**전 모델 동시 최적화** | 보조 로짓이 **가중치의 2~5배** 메모리다(§3.3). 우리 72.5M 삼진이면 ⚙**580 MB~1.45 GB** — 학습 VRAM 이 이미 7~8 GiB 다. 🚫**레이어/블록 단위로만** 가능 |

### 1.5 ⚠️정직한 위험 셋

1. ★★**논문의 이득은 "PTQ 가 STE-QAT 를 따라잡는다" 는 것**일 수 있다. 우리는 **이미 QAT** 다 —
   🚫**그러면 얻을 것이 없다.** 논문은 QAT(EfficientQAT)를 §2 에서 언급만 하고 **직접 비교하지 않는다.**
2. ⚠️**우리 기준선이 좋다는 것이 이미 한 번 손해였다** — Sherry 3:4 때도 *"논문의 이득 원천은
   과희소 회피인데 우리 TWN 은 이미 46.57%"* 라 이득이 없었다(2026-09-06). **같은 형태가 재발할 수 있다.**
3. ⚠️**Gumbel 포화**(§3.3 Optimizer) — AdamW 가 멈춘다고 논문이 직접 말한다.
   🚫**우리는 Muon 승격을 검토 중**이고 **Muon × Gumbel 은 아무도 안 해 봤다.**

### 1.6 ★판정과 후속

| 항목 | 판정 |
|---|---|
| GSQ **전체** | 🚫**미채택** — PTQ 전제가 우리와 안 맞는다 |
| ★**Gumbel 3:4 마스크 학습** | ⏸★**제안 후보 1순위.** 3:4 는 **절감 3.027 MiB 실측**인데 대가 +0.04203 하나로 종결됐다 — **그 하나를 공격하는 유일한 길** |
| ★**Gumbel 삼진 STE 대체** | ⏸**제안 후보 2순위.** 이득이 있다면 **전 모델에 적용**되므로 크지만, ①번보다 구현이 크고 위험 1 이 정면으로 걸린다 |
| ⚠️전제 확인 | ★**돌리기 전에 §4.2 이후 결과표를 읽는다** — 특히 **QAT 와의 비교가 있는지**. 없으면 위험 1 을 못 배제한다 |

## 2. RCO — **정확한 예산 아래 배정을 최적화한다. 그런데 우리 목적함수는 평평하다**

- arXiv:2605.00649v2 (2026-05-07) · ETH Zürich · IST Austria · 코드 `github.com/IST-DASLab/RCO`
- ★**읽은 범위**: 초록 · §1 서론 · §2 예산 다양체(명제 1~3) · Figure 1·2.
  ⚠️**§3(알고리즘 전체)·§4(실험)·부록은 안 읽었다.**

### 2.1 무엇을 하는가

N 개 그룹(예: 층) 각각에 K 개 옵션(예: 비트폭) 중 하나를 배정하되 **총비용 = 예산 B 를 정확히**
만족시킨다. 소프트맥스 확률 `p_i = softmax(α_i)` 로 배정을 완화하면 제약면
`{C(α) = B}` 이 **깨끗한 리만 다양체**가 된다:

- **닫힌 형태 법선** `(∇C)_ik = w_i·p_ik·(c_k − E[c])` → 접선 사영이 **내적 한 번**
- **단조 되돌림** — 로짓을 비용벡터 방향으로 밀면 기대비용이 **단조 증가**하므로 이분탐색이 지수 수렴
- **싼 수송** — 여차원 1 이라 모멘텀 재사영도 내적 한 번

→ 표준 Adam 스텝을 이 셋으로 감싼다. **제약 하이퍼파라미터가 없다**(페널티 λ 튜닝이 사라진다).

### 2.2 ★우리 문제와 형태가 정확히 같다

우리는 **32 / 40 MiB 예산**이 있고 층마다 선택지가 있다(타잉할지 · KV 를 소유할지 · 몇 bpw 로 저장할지).
**RCO 가 푸는 문제가 바로 그것**이고, 우리는 지금 그것을 **균일하게** 정하고 있다.

### 2.3 🚫★★그런데 우리 실측 셋이 "배정은 자유다" 라고 말한다

| 실측 | 무엇을 말하나 | 근거 |
|---|---|---|
| **불균등 타잉 종결** | `mlp_split` 경계를 12/4 · 2/14 · 4/12 로 바꿔도 **3.62375 / 3.62703 / 3.62781** = 균등 3.62672 와 **전부 자 안** | 결과 041 계열 |
| **KV 엔트리 단가가 어디서나 같다** | 머리·꼬리를 푸는 것과 몸통을 묶는 것이 **0.00440 vs 0.00375**(15% 안) | B.16.2 |
| ★**타잉 가격은 "지운 개수" 로 정해진다** | MLP 첫 걸음 0.001873 vs 어텐션 첫 걸음 0.001946 = **4% 안** | [타잉 재평가](../20260908_타잉-세-축의-역할과-가격-재평가.md) §3.3 |

★★★**셋 다 같은 말이다: 우리 손실은 "어느 그룹에 배정하느냐" 에 거의 반응하지 않고
"총량" 에만 반응한다.** 🚫**RCO 는 배정을 최적화하는 도구이고, 우리 배정은 이미 평평하다.**

### 2.4 ⚠️그리고 선결이 하나 더 있다

RCO 를 쓰려면 **층마다 다른 옵션이 실재**해야 한다. 우리는 지금:

| 축 | 층별로 다르게 할 수 있나 |
|---|---|
| bpw | 🚫**아니다** — LUT 커널이 **1.600 고정**. 혼합 정밀도 커널이 없다 |
| 타잉 | ✅가능(`mlp_split`) — **그런데 평평하다**(§2.3) |
| KV 소유 | ✅가능(`cla_edges`) — **그런데 평평하다**(§2.3) |
| 3:4 희소 | ⚠️전역 플래그 하나뿐 |

### 2.5 ★판정과 **재개 조건**

🚫**기각(현시점).** 좋은 도구인데 **우리 문제의 곡률이 없다.**

★**재개 조건 셋 — 하나라도 성립하면 다시 연다**:

1. ★**층별 민감도가 실측된다** — 어느 층이 특히 비싼지가 자를 넘게 보이면 배정이 의미를 갖는다.
   (⚠️U2 층별 기여 연구가 그 자리인데 `attn_group ≥ 4` 에서만 유효하다)
2. ★**혼합 bpw 커널이 생긴다** — T-MAC/bitnet.cpp 경로에서 층마다 다른 비트폭이 가능해지면
   옵션 집합 K 가 실재하게 된다.
3. **예산이 아슬아슬해진다** — 지금은 여유가 1.3~1.5 MiB 라 정밀 배정의 값이 작다.
   ⚙16 MiB 목표에서는 **한 MiB 가 결정적**이다.

⚠️★**그리고 GSQ 논문이 RCO 를 실제로 쓴다**(§1: *"RCO 로 층별 비트 배정을 탐색해 2.37·2.62 bpp"*).
★**둘은 세트**다 — GSQ 를 채택하게 되면 RCO 도 함께 다시 본다.

  §2.3 아키텍처(Table 2 · Figure 5·6) · §2.4 학습 인프라.
  ⚠️**§3 이후(포스트트레이닝·에이전트·평가) 전체와 부록 D 는 안 읽었다.**

### 3.1 ★★MuonClip 알고리즘 (원문 Algorithm 1)

```
1. Muon step:  M_t = μ·M_{t−1} + G_t
               O_t = NewtonSchulz(M_t) · sqrt(max(n, m)) · 0.2      ← "Match Adam RMS"
               W_t = W_{t−1} − η·(O_t + λ·W_{t−1})
2. QK-Clip:    각 어텐션 헤드 h 에서 forward 가 이미 계산한 S_max^h 를 본다
               if S_max^h > τ:  γ = τ / S_max^h
                                W_qc ← W_qc·√γ ,  W_kc ← W_kc·√γ ,  W_qr ← W_qr·γ
```

**τ = 100.** Figure 2: **QK-Clip 없이는 어텐션 로짓이 학습 중반에 1000 을 넘는다.**
있으면 100 에 붙어 있다가 **학습의 약 30% 지점부터 스스로 내려온다.**
Figure 3: 15.5T 토큰 전 구간 **스파이크 0**(스무딩·서브샘플링 없이).

### 3.2 🚫★★QK-Clip 은 우리에게 **불필요하다** — 같은 문제를 이미 다르게 막았다

`modules.py:53` — *"v5: q·k 내적 전에 **파라미터 없는 RMSNorm(QK-norm)** 으로 로짓 폭주를 막는다."*
`q_norm`·`k_norm` 이 각 헤드의 q·k 를 **노름 √head_dim 으로 고정**하므로

    |logit| = |q·k| / √head_dim  ≤  (√64 · √64) / √64  =  √64  =  8

★★**우리 어텐션 로짓은 구조적으로 8 이 상한**이다. Kimi 가 τ=100 으로 막으려던 것을
**우리는 아키텍처로 막았고, 더 세게 막았다.**

★★★**그리고 그 사실이 하나를 정정한다**: 2026-09-06 에 우리는
*"Muon ×30·×45 에서 `grad_max` 가 단조 증가하는데 `n_skip` 은 0 이니 천장은 발산이 아니라 품질"*
이라고 적었다. **Kimi 의 관찰은 그 천장의 흔한 원인이 어텐션 로짓 폭주라는 것**인데
🚫**우리에게는 그 경로가 닫혀 있다** → ★**우리 천장의 원인은 아직 모른다. 다른 데를 봐야 한다.**

|---|---:|---:|---:|

⚠️**정직하게**: Kimi 의 η(Muon 학습률)를 이 발췌에서 못 읽었다.

## 4. ★★QK-Norm 원 논문 — **우리가 반쪽만 구현했다**

- **arXiv:2010.04245** · Henry, Dachapally, Pawar, Chen (Cyndx Technologies) · EMNLP 2020 Findings
- ★**읽은 범위**: 본문 5쪽 전부(§1~§5) + 참고문헌. **식 2·3·5**, Figure 1·2, Table 2·3.

### 4.1 무엇을 하나

| 식 | 내용 |
|---|---|
| (2) | `q̂ᵢ = qᵢ / ‖qᵢ‖` — **head 차원**으로 ℓ2 정규화 |
| (5) | `softmax(g · Q̂K̂ᵀ) V` — ★**학습 가능한 스칼라 `g`** |
| (3) | `g₀ = log₂(L² − L)`, L = 학습 시퀀스 길이의 97.5 분위 |

### 4.2 ★★논문 자신이 경고한 실패 모드 — **바로 우리 상태다**

> §3: 코사인 유사도는 [−1,1] 로 묶여 **"소프트맥스와 반대의 문제"** 를 만든다 —
> 값의 차이가 너무 작아 **주의하지 말아야 할 연결을 효과적으로 무시하지 못한다.**

그래서 `1/√d` 로 **나누는** 대신 학습 가능한 `g` 로 **곱한다.**

### 4.3 ★우리와의 차이 — **숫자 하나**

| | 논문 | 우리 |
|---|---|---|
| 정규화 | ℓ2 (head 축) | RMSNorm (head 축) — **같은 방향** |
| 스케일 | ★**학습 가능한 `g`**, `g₀ = 20.0`(L=1024) | 🚫**없다.** 고정 `1/√head_dim` → **유효 `g = 8`** |
| 로짓 범위 | 학습으로 넓힐 수 있다 | **[−8, +8] 하드** |

★**우리 유효 스케일은 논문 권장 초기값의 40%** 이고 **학습되지도 않는다.**

⚠️**단 산술로 반박도 된다** — 상한 8 에서도 T=1024 의 최대 어텐션 가중치는 **0.99988** 이라
원-핫이 도달 가능하다. ★**그래서 이 물음은 실측(`cosθ` 분포) 없이는 못 닫는다.**

### 4.4 판정

⏸**측정 대기.** 정본 보고서 = [`docs/20260908_QK-norm이-과도-상한인가-QK-Clip과의-대조.md`](../20260908_QK-norm이-과도-상한인가-QK-Clip과의-대조.md).
🚫**`g` 를 지금 넣지 않는다** — 넣으면 무엇을 고쳤는지 모른다. **M1 측정이 먼저다.**

### 4.5 ★★부수 — **`W_q`·`W_k` 는 스케일 불변이고, 그것이 Muon 천장의 후보다**

`q = RMSNorm(W_q x)` 이므로 손실이 `W_q` 의 **스케일에 정확히 불변**이다
(삼진화의 α 도 `mean(|w|)` 라 함께 스케일된다 → 이중으로 불변).
→ **Muon 팔의 wd 0**(기준표 B.23.6)에서 `‖W_q‖` 가 단조 증가하면
**유효 학습률이 `1/‖W‖²` 로 감쇠**한다. ★**발산이 아니라 조기 정지**이고,
그것은 `n_skip` 이 전 배수에서 **0** 인 관측과 맞는다. → 검정은 M2(보고서 §7).

## 6. TTPO — 다수결의 오류를 비대칭 업데이트로 제한하지만 지금 TinyLM 기본 학습에 넣지 않는다

- **논문**: Wang et al., [TTPO: Test-Time Policy Optimization](https://arxiv.org/abs/2608.27448), arXiv:2608.27448v1(2026-08-27). [저자 코드](https://github.com/ZJU-REAL/TTPO).
- **검토 원본**: `article/TTPO TEST-TIME POLICY OPTIMIZATION.pdf`(로컬, SHA-256 `D67E875FFC81FE065C02C0C02808F522653BA8DDAEC5E629507A3A5EE7FA7E22`). `mutool`로 본문 1~9쪽의 방법·결과·ablation, 12~13쪽 설정, 17쪽 한계를 읽었다. 미판독 부록·코드 구현은 결과 근거로 쓰지 않는다.
- **TinyLM 상태**: 모델 약105M, 현재 대화/SFT 경로는 학습 게이트 준비 단계이고 thinking-mode 교사·검증 가능한 64-rollout 수학 과제 계약은 없다. 보호 held-out을 학습 입력으로 사용하지 않는다.

### 6.1 원리와 실제 논문 증거

각 문제에서 `K=64`개 rollout의 최종 답을 추출해 다수결 pseudo-label로 나눈다. 다수결과 **같은 답**의 trajectory에는 답을 힌트로 받은 thinking-on 고정 교사의 분포를 non-thinking 학생에 forward KL로 증류한다(OPSD). **다른 답**의 trajectory에는 집단 상대 보상의 음의 advantage로 GRPO 패널티를 적용한다. 전자는 학생 entropy와 교사/학생 KL이 높은 위치에 가중, 후자는 이상 토큰 점수의 상위 절반만 벌한다. 이 두 분기는 같은 지도신호가 아니다.

논문 Fig.1/§3.2의 “pseudo-label이 틀려도 disagreeing rollout 약79%는 실제로도 틀림”은 **Qwen3-1.7B의 어려운 수학 TTT** 관측이다. 정답이 다수결과 다르다는 사실만으로 TinyLM의 자유 대화 답변을 자동 오답 판정할 근거는 아니다. 반대로 majority가 전부 틀린 문항에서 positive 증류는 참 정답을 가르치지 않고 **자기 답의 reasoning 스타일**을 모사한다.

논문 Table 2의 Qwen3-1.7B TTT 평균은 **38.0→45.2%**(AIME26/HMMT26/BRUMO25)이고 평가 단위는 **temperature1.0의 Avg@12**다. Table 1의 OpenThoughts 비교에서 TTPO와 정답 기반 OPSD는 1.7B **40.1 대39.7%**다. 전체를 “TinyLM 단일답 정확도 +7.2%p”로 복제하지 않는다. 같은 평가 benchmark 문제로 **라벨 없이 적응**한 TTT이므로, 우리 held-out 판정지에 직접 적용하면 독립 평가가 오염된다.

### 6.2 실제 비용·전제와 현재 미충족

| 부분 | 판정 | TinyLM에 맞는 후속 조건 |
|---|---|---|
| **오답 후보에만 보수적 패널티**와 token-level confidence 필터 | **개념 차용 가능**. 정답이 확인된 오답과 P090 rejected 자료가 있는 경우의 손실 설계 힌트 | 먼저 assistant-only SFT·정답/오답 검증·동형 부모 대조를 완성. 불확실한 다수결을 정답으로 쓰지 않음 |
| 다수결로 pseudo-label을 만들고 시험 문제 자체에서 모델 업데이트 | **현 시점 부적합**. 64개 생성의 품질·비용과 benchmark leakage가 가장 큼 | 학습·평가 분리된 공개 수학 데이터, 실제 pass@K/majority 정확도와 비용 측정 뒤만 연구 후보 |
| thinking 교사 조건부 OPSD + full-vocab KL 전체 | **즉시 구현 불가**. 원 논문의 핵심 teacher mode와 검증 가능한 답이 현재 없다 | 독립 teacher/학생 capability, full-vocab KL VRAM, 같은 입력 비교 조건이 먼저 |
| 논문의 +7.2%p / 대규모 무정답 수학 성과 | **TinyLM 예상효과로 사용 불가** | 모델 규모·시험지·평가단위·rollout 예산이 일치하지 않음 |

**즉시 적용 가능하면서 효과가 뛰어날 것으로 입증된 메커니즘은 현재 0건**이다. 따라서 이 요청의 “그런 메커니즘이 있으면 제안서” 조건은 충족하지 않아 **새 제안서는 작성하지 않는다**. P090 SFT·실제 정답 추출·독립 수학 패널에서 기초 정답률과 64-rollout 대비 소형 `K`의 비용을 확인한 뒤, 원안 전체가 아닌 **검증된 오답의 selective negative learning**을 별도 제안할 수 있다. 이는 현재 승인된 A/B/C 구현·M4/M5·SFT 게이트의 선결이 아니다.

### 7.1 백서가 실제로 제시한 메커니즘과 분모

| 항목 | 백서의 증거 | TinyLM에 주는 의미 |
|---|---|---|
| 모델 구조 | §2 표1: Qwen3.8-27B 계보, 언어 backbone 24.35B+embedding/head 2.54B, 별도 vision 0.47B; 약 75% linear attention | 우리 약100M·CLA/GQA/TLinear 구조와 다르다. Bonsai 가중치/회전 계수를 TinyLM에 복사하는 처방 아님 |
| 삼진 저장 | §2.1~2.3: `{-1,0,+1}`, group128 FP16 scale; 순수 삼진 약1.71bpw, 언어 전체 이론1.72bpw, PTQ1_0 1.76bpw/5.93GB, PQ2_0 2.16bpw/7.25GB | 저장 GB(10진)이지 TinyLM runtime MiB·RSS·KV·훈련 마스터가 아니다. 실제 패킹과 배포 지표를 분리 |
| 정밀도 예외 | §2.2 표2: recurrent-state 경로와 norm 등 26,238,464개(언어 파라미터의 0.0976%)를 bf16 등으로 보존 | ‘완전 전층 삼진’ 광고와 구별. 우리에는 동일 recurrent-state 경로가 없으므로 정확한 예외 집합·0.0976%를 복사 못 함 |
| 회전 basis | §2.4: block1024 Hadamard+고정 부호, 가중치는 회전 좌표에서 저장하고 활성값은 런타임 변환 | matrix별 padding/역변환·새 커널이 필요. 백서는 TinyLM의 처음부터 학습하는 TLinear와 같은 최적화/수렴 레시피를 명시하지 않음 |
| packed 직접 실행 | §3/부록 A: 압축 가중치를 FP16 dense로 펼치지 않고 fused low-bit GEMM에서 decode·scale 적용 | 우리 P014D/P025B처럼 **패킹·언팩·전체 호출 wall**을 같이 재야 한다. synthetic event만으로 도입 금지 |

백서 §2.3의 FP16 53.80GB 대비 5.93GB는 *언어모델 저장 파일* 약9.1배의 비교다. 별도 vision 0.63/0.93GB, KV cache, 활성값, 훈련 optimizer는 이 표의 분모 밖이다. TinyLM의 40MiB 배포 목표나 단일 CPU 15tok/s 목표를 27B의 파일 크기와 같은 눈금으로 판정하지 않는다.

### 7.2 성능과 계측: 높은 평균 뒤에 남는 실패 가족

백서 §4/부록 B·C는 H100의 vLLM/EvalScope 동일 경로에서 thinking `xhigh`, 20 benchmark 평균 **83.9 대 Qwen3.8 FP16 85.4**를 보고한다. 이는 백서가 정의한 평균의 98.2%이지 문항별 오류율·한국어 정확도·교사 답변 검증률의 98.2%가 아니다. `medium`은 별도 부록 C 표11에서 **79.3 대82.6**으로 비율도 다르다. 추가 agentic 과제는 Terminal-Bench 2.1 **52.8 대69.7**, SWE-bench Verified **60.8 대80.6**으로 평균 보존율과 다르게 약 3/4 수준이다. 수치는 모두 공급자 백서의 특정 harness·추론 budget 관측이며 TinyLM 전이효과가 아니다.

§3 표5의 RTX 4090에서는 PTQ1_0이 batch1 decode 96.7tok/s 대 PQ2_0 90.9tok/s이나 prefill은 1,634 대3,134tok/s로 반대다. 4070 Ti SUPER·WSL·단일 CPU에서 동일 우열은 미측정이다. 부록 D는 세 반복과 warm-up, `tg128/pp512`, depth0·batch1·vision 제외, NVIDIA board 전력과 Apple powermetrics의 분모 차이를 밝힌다. 회전 transform은 batch1 decode의 주요 부가비용이며 §5도 최적화 과제로 남긴다.

**버전 분리:** 현재 공급자 [모델카드](https://huggingface.co/prism-ml/Ternary-Bonsai-2-27B-gguf/blob/main/README.md)는 14 benchmark 평균 **84.78**, PTQ1_0 5.95GB/PQ2_0 7.21GB라고 적는다. 로컬 2026-09-17 생성 백서의 20 benchmark 83.9, 5.93/7.25GB와 평가 집합·포장 수가 다르다. 어느 쪽이 정정인지 확인 없이 병합·평균하지 않고 각 주장에 PDF SHA 또는 모델카드 revision·벤치 목록을 결합한다. HF 페이지의 자동 `:F16`/일반 llama.cpp 사용 예시는 [공식 데모 README](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/README.md)의 ‘Bonsai 2는 Hadamard-aware PrismML fork 필요’ 계약과 충돌한다. F16은 53GB급으로 이 프로젝트 16GB GPU 교사 후보의 저비트 실행 명령이 아니다. 설치·다운로드·실행은 이번 작업에서 `NOT_RUN`이다.

### 7.3 TinyLM 차용·보류·불가 판정

| 요소 | 분류 | 이유와 최소 후속 검증 |
|---|---|---|
| packed 직접 소비, decode/prefill 분리, 저장·상주·KV·RSS 별도 회계 | **타당·기존 축 보강** | P014D/P025B의 wall/event·실제 모델 결과를 같은 형상에서 비교. 커널보다 unpack/변환이 크면 같은 패킹도 속도 음성 |
| 민감한 소수 텐서를 높은 정밀도로 보존 | **개념 차용** | TinyLM TLinear/embedding/norm의 부위별 오류·상주 증가를 먼저 계측. Qwen hybrid recurrent 경로의 0.0976%를 목표 수치로 복사하지 않음 |
| 고정 Hadamard 회전 뒤 삼진화 | **개선 후에만 연구 후보** | 이미 학습된 FP32↔삼진 TinyLM의 같은 checkpoint·같은 정합/언어 평가와 회전/역회전·padding·decode wall을 분리. 백서에는 우리 from-scratch STE/optimizer 수렴 레시피와 개별 회전 ablation이 없음 |
| Bonsai 2 27B를 외부 텍스트 교사로 평가 | **개념 차용/조건부 pilot** | Apache-2.0 표시·실제 모델 revision·출력 이용 조건, PrismML fork/quant·template·reasoning effort, 16GB VRAM/KV와 accepted sample당 비용·한국어 검증 QA 정답률을 먼저 확인. 교사와 학생은 순차 실행하고 학생 checkpoint/보호 data 접근 없음 |
| 27B 수치·98.2%를 TinyLM 직접 품질/속도 향상으로 이식 | **사용불가** | 모델 규모·아키텍처·벤치/언어·runtime·분모가 다름. 27B packed 5.93GB가 TinyLM 40MiB 안에 든다는 해석도 불가 |
| 백서를 완전한 학습·커널 구현 명세로 취급 | **사용불가** | 공개 문서는 회전 정의·출력·runtime 개요를 제공하지만 훈련 목적/데이터/optimizer·커널 소스 정합을 충분히 고정하지 않음 |

현재 이 백서만으로 TinyLM에 **즉시 적용 가능하면서 큰 효과가 확인된 새 메커니즘은 0건**이다. 따라서 새로운 구현 제안서를 이 결과만으로 만들어 곧바로 기본 경로를 바꾸지 않는다. 최우선 재사용은 기존 P014D/P025B의 전체 호출 실측 계약, 그 다음은 사용자 별도 승인 아래 외부 교사의 **무힌트·독립 검증 pilot**이다. 후자는 본 백서가 TinyLM 증류 성공을 보인 것이 아니라 교사 후보를 비교할 이유를 준다는 뜻이다.
