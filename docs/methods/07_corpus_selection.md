# 07 — 코퍼스 선택 원장 (living document)

> **이 문서의 목적**: 어떤 데이터셋을 **쓰기로 했는지·안 쓰기로 했는지, 그리고 왜인지**를 한 곳에 남긴다.
> 다른 방법론 원장(`01`~`06`)과 같은 규칙 — **채택/기각/보류 각각에 근거를 적고, 근거가 바뀌면 행을 고친다.**
>
> 작성 계기: 사용자 지적(2026-08-02) — `korean-webtext-edu` 의 광고·스팸 오염(결과 018·023).
> **전제**: 지금 데이터의 역할은 **아키텍처의 학습 정도를 재는 것**이지 최고 품질 모델을 만드는 것이 아니다.
> 따라서 **모든 후보를 실험으로 비교할 필요가 없다** — "아키텍처 비교가 성립하고, 데이터가 고품질" 이면 충분하다.

## 0. 판단 기준 — 이 프로젝트의 코퍼스가 만족해야 하는 것

| # | 기준 | 왜 |
|---|---|---|
| **C1** | **풀 ≥ 600M 토큰**(학습 300M 의 2배) | 결과 006: 풀이 작으면 반복 노출로 dense 가 0.12 손해. `CLAUDE.md` 규범 |
| **C2** | **연속 산문**(prose) | 우리는 CLM 이다. QA 쌍·선택지는 문서가 아니다 |
| **C3** | **한국어 + 영어 혼합** | 프로젝트 정체성. 단일 언어면 기존 결과와 비교 불가 |
| **C4** | **스팸·중복이 적을 것** | 결과 018: 스팸 7개가 val 손실의 53% 를 먹었다 |
| **C5** | **평가셋으로 새지 않을 것** | 벤치마크를 학습에 넣으면 그 벤치마크로 평가할 수 없다 |

## 2. 기각 사유 (상세)

### 2.1 `cais/mmlu` — **벤치마크이지 코퍼스가 아니다**

- 크기가 **338MB(≈77M 토큰)** 로 C1 의 13% 다. 단독으로는 물론이고 절반 몫도 못 채운다.
- 형식이 `question` / `choices[4]` / `answer` 다. **산문이 아니다**(C2 위반).
  산문으로 만들려면 "질문 + 선택지 + 정답" 을 템플릿으로 이어붙여야 하는데, 그러면
  **우리가 만든 템플릿의 통계를 학습**하게 된다 — 데이터 품질이 아니라 템플릿 품질을 재게 된다.
- **C5 위반이 가장 크다.** MMLU 는 지식 평가의 사실상 표준이다. 여기에 학습하면
  **앞으로 MMLU 로 이 모델을 평가할 수 없다.** 지금은 안 쓰지만, 스케일업(P033) 이후
  다운스트림 지표가 필요해지면 MMLU 는 가장 먼저 꺼낼 카드다. **태워 없앨 이유가 없다.**

> `auxiliary_train`(161MB) 만 쓰면 test 오염은 피할 수 있다는 반론이 가능하다. 그래도 C1·C2 는 그대로다.

### 2.2 `JosephLee/*_textbook_elementary_kor` — **세 자릿수 부족하다**

- `science` **13.3MB**, `society` **2.2MB**, seed 2종 합 4.2MB. **전부 합쳐 약 20MB ≈ 4.5M 토큰.**
  C1(600M)의 **0.75%** 다. 100 에폭을 돌려도 600M 이 안 된다.
- HF 태그가 `task_categories: question-answering`, 형식이 `*_train.json` 이다 — **QA 세트**다.
- 다운로드 8·13·7회. **검증 이력이 사실상 없다** — 품질을 우리가 직접 확인해야 하는데,
  그 확인 비용이 4.5M 토큰의 가치보다 크다.

> **이건 데이터셋의 결함이 아니다.** 초등 교과서 QA 세트로서는 정상이고, **용도가 다를 뿐**이다.
> 파인튜닝·평가용으로는 쓸 수 있다.

### 2.3 ★핵심 비대칭 — **"교과서" 전략은 한국어에서 막힌다**

| 언어 | 교과서급 대규모 코퍼스 | 상태 |
|---|---|---|
| 영어 | `SciPhi/...lite`(3.2GB), `open-phi/textbooks`(397MB) | **있다** |
| **한국어** | — | **없다**(조사 범위 내) |

C3(한·영 혼합)을 지키려면 한국어 쪽에 600M×0.5 = **300M 토큰**이 필요한데,
제안된 한국어 교과서 데이터는 **4.5M** 이다. **67배 부족하다.**
→ **"Textbooks Are All You Need 스타일로 전면 교체" 는 지금 실행 불가능하다.**

## 3. ★SQuAD 는 학습이 아니라 **평가**로 쓴다 — P028 의 빈 칸을 정확히 메운다

P028 의 미해결 문제는 이것이다(결과 009·011):

> **교차데이터셋 bpb 비교는 무효다** — 토크나이저·val 셋이 다르면 성립하지 않는다.
> 필요한 것은 **공통 원문 eval 셋**이다.

SQuAD v2 의 `context` 는 그 조건을 정확히 만족한다.

| 요건 | SQuAD context |
|---|---|
| 공통 원문(어느 학습 코퍼스에도 안 들어감) | ✅ 우리 `ko-en`·`ko-edu-en` 어디에도 없다 |
| 연속 산문 | ✅ 영문 위키 문단, 평균 **736자** |
| 크기가 eval 에 충분 | ✅ 고유 context **19,029개 / 14.0MB ≈ 3.2M 토큰** (val 1.5M 의 2배) |
| 로컬 보유 | ✅ `datasets/squad/train-v2.0.json` (42MB) |
| 라이선스 | CC BY-SA 4.0 |

**bpb 는 토크나이저 무관**하다(`loss / ln2 / bytes_per_token`). 같은 원문·같은 바이트 수에
서로 다른 토크나이저의 모델을 통과시키면 **처음으로 데이터셋 간 비교가 성립**한다.

> ⚠️ **한계**: SQuAD context 는 **영문 전용**이다. 한국어 쪽 공통 원문은 여전히 없다.
> 한국어 bpb 비교에는 별도 홀드아웃이 필요하다(예: 특정 날짜 이후 위키 덤프).
> **영문만이라도 성립시키는 것이 지금보다 낫다** — 지금은 0건이다.

**→ P028 단계1 을 SQuAD context 기반으로 설계한다.** 배치 `run_P028_stage1_common_bpb.bat`.

## 4. 현행 코퍼스 재평가

### 4.1 `ko-edu-en`(`eliceai/korean-webtext-edu` + fineweb-edu) — **조건부 유지**

- 결과 018: 거대 문서 7개가 **자격증 덤프 SEO 스팸**. val 손실의 53%.
- 결과 023: `--doc-filter` 로 **1,959개 / 388M자(≈13%)** 제거. **검증은 미완**(엉뚱한 캐시를 쟀다).
- **판단**: 필터 후 재검증(`run_P037_stage2b_verify.bat`)이 통과하면 유지, 아니면 폐기.
  **13% 를 걷어내야 하는 코퍼스라는 사실 자체가 이미 감점**이다.

### 4.2 `Salesforce/wikitext` — **사실상 미사용. 그러나 남겨 둔다**

- `DATASETS["en"]` 에만 있고 **어떤 실험도 `--data en` 을 쓴 적이 없다**(전수 검색 0건).
- wikitext-103-raw 는 위키 산문 ~103M 토큰. **C1(600M) 미달**이라 주 코퍼스로는 못 쓴다.
- 품질 자체는 문제없다(정제된 위키). **파이프라인 스모크·소규모 대조용으로 유지**한다.

### 4.3 ★로딩 방법 — **검토 결과 결함 3건**

`prepare._stream()` 을 읽고 확인한 것. **전부 미수정이며, 이 문서가 최초 기록이다.**

| # | 결함 | 왜 문제인가 | 영향 |
|---|---|---|---|
| **L1** | **혼합 비율이 문서 단위**다 — `rng.choice` 가 이터레이터를 고르고 문서 1개를 꺼낸다 | 문서 길이가 소스마다 다르면 **토큰 비율은 0.5/0.5 가 아니다.** 위키 문서와 fineweb-edu 문서의 평균 길이가 다르면 그 비율만큼 어긋난다 | **한·영 실제 토큰 비율을 우리는 모른다.** 지금까지 "0.5/0.5" 라고 적어 온 모든 문서가 미확인 |
| **L2** | **셔플이 없다** — `streaming=True` 는 파일 순서대로 준다 | 풀은 스트림의 **앞부분 600M** 이고, val 은 그 **말미 0.5%** 다. 즉 **val = 특정 구간** | 결과 011 이 관측한 분포이동(H2)의 **구조적 원인일 수 있다.** `shuffle(buffer_size=...)` 미사용 |
| **L3** | `text_key` 가 **단일 필드 고정** | `open-phi`(markdown) 는 되지만 SQuAD(context) · MMLU(question+choices) 처럼 **여러 필드를 조합**해야 하는 형식은 못 읽는다 | 신규 데이터셋 도입 시마다 코드 수정 필요 |

> **L1·L2 는 지금까지의 모든 데이터 실험(006·009·011·012·018·023)에 걸린다.**
> 결론을 뒤집는지는 별개다 — 모든 런이 **같은 로더**를 썼으므로 **런 간 비교는 유효**하다.
> 무효가 되는 것은 **"한국어 50%" 같은 절대 서술**과 **val 대표성**이다.
> → **P037 단계3**(L1·L2 실측·수정) / **단계4**(로더 회귀 게이트) 로 분리한다.

## 6. 한계 — 이 문서가 확인하지 **않은** 것

- 후보 데이터셋의 **내용을 직접 열어 보지 않았다.** 크기·형식·태그는 HF API 실측이지만,
  품질은 **데이터셋 카드 설명과 형식으로 추정**했다. 결과 018 이 보여줬듯 **설명과 실물은 다를 수 있다.**
- `SciPhi/...lite` 는 **LLM 합성 데이터**다. 합성 데이터의 반복·붕괴 특성은 우리가 측정한 적이 없다.
- 토큰 환산은 전부 **bytes/token = 4.4**(우리 `ko-en` 실측값) 가정이다. 영문 전용 코퍼스는
  이 값이 다르다(영문은 보통 더 크다) → **영문 데이터셋의 토큰 수는 과소추정일 수 있다.**
- L1(문서 단위 혼합)이 실제로 얼마나 어긋나 있는지는 **아직 안 쟀다.** P037 단계3 이 잰다.

## ★2026-08-06 갱신 — **필터로 학습하니 모델이 좋아졌다** (결과 011 §2)

| 항목 | 값 |
|---|---|
| `densef`(필터 데이터 학습) 공통 원문 bpb | **1.4124** |
| `dense`(필터 전) | 1.5182 |
| **차이** | **−0.1058 bpb = −0.296 nats = 24.7σ** |

**같은 300M 풀·같은 2289 steps·같은 lr·같은 cosine, 다른 것은 필터 하나.**
판정은 **공통 원문 bpb**(SQuAD)로 했다 — 필터가 문서를 지우면 스트림이 밀려 **val 도 밀리므로**
(L5) 두 런의 `val_loss`(4.2019 vs 6.00125)는 **다른 시험지이고 비교 불가**다.

### ★코퍼스 판정 정정

| 종전 | 지금 |
|---|---|
| 결과 009: `ko-edu-en` 큐레이션이 **열세**(bpb 1.614 vs 1.234) | ⚠️ **부분 철회.** 열세의 **다수가 큐레이션이 아니라 코퍼스에 섞인 SEO 스팸**이었다 |
| 결과 011 §1: `ko-en` 대비 **+0.1685** | **+0.0627** (63%가 스팸) |

**남은 +0.0627 은 영어 예산 교락 상태다** — `ko-en` 영어 49.4% vs `ko-edu-en_300M_filtered` **42.0%**.
**`eliceai/korean-webtext-edu` 자체에 대한 판정은 보류로 되돌린다.**

### 믹스 비율은 **풀 크기의 함수**다 (L1 + L4)

| 캐시 | 한국어 소스 토큰 | 영어 |
|---|---|---|
| `ko-edu-en` 100M | 66.9% | 33.1% |
| `ko-edu-en` 300M(필터) | **58.0%** | 42.0% |
| `ko-en` 100M | 50.6% | 49.4% |
| `ko-en` 1200M | **25.0%** | 75.0% |

**"한국어 50%" 는 어느 캐시에서도 참이 아니다.** 인용할 때 **캐시와 풀 크기를 함께 적는다.**

### ★후속 [필수] — `ko-en` 에도 스팸이 있는가

결과 018 은 **`ko-en` val 이 건강하다**(최대 문서 2.2%)고 했지만 **train 쪽 스팸률은 안 쟀다.**
표준 코퍼스에 필터가 필요하면 **전 기준선 재학습**이라 매우 비싸다 → **먼저 측정만** 한다
(같은 서명으로 스트리밍 카운트, 캐시 빌드 없이 GPU 0).

### 어휘 배분 (결과 025)

| 토크나이저 | korean | latin | 영문 압축 |

교환 재현성만 확인한다([090 §8](../../test_result/090_20260919_P097-세-cache는-완성됐지만-학습은-0step이다.md#8-stage2wb-공통평가-복구2026-09-21--네-recipe를-같은-문항에서-비교했지만-전면-승자는-없다)).

## 8. 2026-09-23 P097 Stage3 — seed는 확보됐고 recipe 순위는 Stage4 대기

[결과 090 §13](../../test_result/090_20260919_P097-세-cache는-완성됐지만-학습은-0step이다.md)에서 control-v2/FineWeb2의 추가 seed2024·31415 네 학습은 모두 exit0·skip0이었다. 각 자체 val의 seed별 값은 control 3.51156/3.51359, FineWeb2 3.89656/3.88172다. 이 값의 서로 다른 계열 차이는 **원천·tokenizer·validation이 동시에 다르므로 품질 순위로 사용할 수 없다**. 같은 recipe 안의 재현성만 보는 숫자다.

Stage2Wb에서 본 common-bpb 대 한국어/영어 과제의 강점 교환이 두 seed에도 유지되는지는 미측정이다. 이미 작성된 `run_P097_Stage4W_ctrl_fw2_seed_panel.sh`가 같은 원문·동일 문항과 seed panel을 수집한 뒤에만 corpus 대체를 논의한다. Wiki 서식 반복의 현재 생성률과 한국어 SFT 대화능력도 Stage3 자기 val에서 추론하지 않는다.

## 9. 2026-09-24 P097 Stage4W 세 시드 공통 문항 — 교환 재현, 기본 교체 보류

[결과090 §14](../../test_result/090_20260919_P097-세-cache는-완성됐지만-학습은-0step이다.md)에서 control-v2/FineWeb2의 세 seed 공통 YNAT/NLI/ARC/HellaSwag 각 1,200 ID와 영문 SQuAD-context bpb가 전부 exit0으로 회수됐다. 문항별 원본 28,800행에서 공통 ID/gold·내부 acc를 직접 확인했다. FineWeb2의 YNAT 정확도 방향은 3/3(대응 유의2/3), control의 영문 bpb 낮음은 3/3이었다. 반면 ARC 방향은 seed별로 달랐고 NLI/Hella는 우연 수준 부근이다. 자기 val은 여전히 서로 다른 시험지이며 전면 승자·기본 recipe 변경은 아니다.

중요한 계측 한계: `common_bpb.py`가 인쇄한 SQuAD 4,000개 중 348개(8.7%) 겹침은 **과거 ko-en 학습 스트림의 관측**이다. 새 두 recipe가 같은 학습 스트림이라는 문구는 사실과 맞지 않아 코드 출력에서 제거했다. 동일 raw byte-bpb 수치는 설명적 비교로 기록하되, 현재 선택한 1,000문서와 recipe별 차등 오염률·한국어 공통 bpb·대화 능력은 별도 `NOT_RUN`이다. 세 seed 방향을 새 혼합 recipe의 설계 동기로만 쓰고 데이터셋 단독 인과효과로 승격하지 않는다.
