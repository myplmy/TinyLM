## 1. ★Fishing for Magikarp — **우리 val_loss 를 오염시키고 있을 수 있다**

### 무엇을 말하는 논문인가

토크나이저는 **학습 코퍼스와 따로** 만들어진다. 그래서 어휘에는 있는데 학습 중 **거의 안 나오는
토큰**(under-trained / glitch token)이 생긴다. 논문은 그걸 **임베딩·언임베딩 가중치 지표**로
자동 검출하는 방법을 제시하고, 다양한 모델에서 **실제로 흔하다**는 것을 보인다.

### ★왜 이게 우리에게 특히 위험한가 — 세 가지가 겹친다

| 조건 | 우리 값 | 함의 |
|---|---|---|
| 어휘 크기 | **32,768** | 고정 |
| 학습 토큰 | **300M** | 어휘당 평균 9,155 토큰. **Zipf 꼬리는 사실상 0회** |
| 토크나이저 학습 표본 | **20만 문서** (`build_tokenizer`) | 코퍼스 전체가 아니다 |

그리고 결정적으로:

> **토크나이저를 학습시킨 그 20만 문서에 SEO 스팸이 들어 있었다.**
> 결과 018 이 `ko-edu-en` 에서 찾은 스팸은 `NRN-511`·`CATV612-ELEC-V6R2012` 같은
> **자격증 코드가 단어 중간까지 박힌** 텍스트다. BPE 는 반복되는 문자열을 토큰으로 만든다 —
> **그 제품 코드들이 어휘를 차지했을 가능성**이 있고, 그것들은 필터 후 코퍼스에서 **사라진다.**
> 즉 **필터가 under-trained 토큰을 새로 만들었을 수 있다.**

### 왜 지금 확인해야 하는가

**val_loss 는 우리가 쓰는 유일한 판정 지표**다. 어휘의 일부가 학습 중 거의 안 나왔다면
그 토큰들의 손실은 **정보가 아니라 잡음**이고, 모든 비교에 상수처럼 얹혀 있다.
σ=0.012 / 분해능 0.024 로 0.0136 짜리 차이를 논하는 중이라, **상수 오프셋이라도 확인은 필요**하다.

### 비용

**거의 0.** 학습 없음. 체크포인트의 `emb`(32768×256) 와 `emb_up` 을 읽어 지표를 계산하고,
학습 캐시(`train.bin`)에서 **토큰별 실제 출현 빈도**를 세면 된다. 후자는 `np.bincount` 한 줄이다.

> ⚠️ **논문 그대로가 아니다.** 논문의 주 지표는 **언임베딩 행렬**을 쓰는데 우리는
> **가중치를 묶어 쓴다**(`logits = x @ emb_up.T @ emb.T`, 팩터라이즈드 rank 256).
> 그래서 논문 지표를 그대로 옮길 수 없다. **우리 조건에서 가장 직접적인 것은
> "학습 캐시에서의 실제 출현 빈도"** 이고, 그건 논문 지표보다 **더 강한 증거**다
> (간접 추정이 아니라 직접 계수). 논문은 학습 데이터에 접근할 수 없을 때의 방법이다.
> **우리는 접근할 수 있으므로 더 쉬운 길이 있다.**

→ **P039 신설**: 어휘 활용도·미학습 토큰 진단. §4 에 설계.

## 2. 선형 어텐션 계열 (GDN-2 / KDA / Kimi-Linear / DeepSeek-V4) — **기각, 단 이유를 적어 둔다**

### 공통 주제

softmax 어텐션의 **무한히 자라는 KV 캐시**를 **고정 크기 순환 상태**로 바꾼다.
디코딩이 **상수 메모리**가 되고 시퀀스 믹싱이 선형 시간이 된다.
GDN-2 는 KDA 의 스칼라 게이트를 **채널별 erase/write 게이트로 분리**해 1.3B·100B 토큰에서
Mamba-2 / GDN / KDA / Mamba-3 대비 최고 성능, 특히 **RULER 롱컨텍스트**에서 강하다고 보고한다.

### 왜 지금 우리가 안 쓰는가

| 이유 | 근거 |
|---|---|
| **우리 병목이 아니다** | `max_seq_len` 2048, 학습 `seq` 1024. KV 캐시는 `n_kv=10층 × 2 × 192 × 2B ≈ 7.5KB/토큰`. 1024 토큰이면 **7.7MB** — 상주 96~278MB 옆에서 반올림 오차다 |
| **비용 구조가 반대다** | 결과 016 §10.4: 우리는 batch 1 에서 **런치 오버헤드 바운드**로 보인다. 선형 어텐션은 **긴 컨텍스트의 O(T²)** 를 없애는 기법인데 우리에겐 그 T² 가 없다 |
| **아키텍처 전면 교체다** | 어텐션을 바꾸면 CLA·삼진·타잉과의 상호작용이 전부 미지가 된다. 결과 006·012·019 가 쌓아 온 기준선이 **전부 무효**가 된다 |
| **검증 스케일이 다르다** | GDN-2 는 1.3B·100B 토큰. 우리는 132M·300M. 결과 019 §9 가 **Arenas 에서 정확히 이 스케일 격차로 데었다** |

### 그래도 보존할 개념 하나

**"고정 크기 상태로 디코딩" 은 우리 목표와 방향이 같다.** 다만 우리에게 먼저 필요한 것은
컨텍스트가 아니라 **가중치**다(96MB 중 KV 는 7.7MB). **롱컨텍스트가 목표가 되는 날**
— 즉 `max_seq_len` 을 16K 이상으로 올릴 때 — 이 절을 다시 읽는다.

> **판정 근거를 숫자로 남기는 이유**: "나중에 좋아 보여서" 다시 검토할 때, 그때의
> KV 캐시 비중을 여기 7.7MB 와 비교하면 **결정이 바뀌었는지 아닌지가 한 줄로 보인다.**

## 3. `slvDev/esp32-ai` — **배포 목표의 현실 점검**

ESP32 급 MCU 는 RAM 이 **수백 KB~수 MB** 다. 우리 상주는 **최선(mC + 단계3) 86.9MB** 다.

| 목표 | 필요 상주 | 우리 현재 | 격차 |
|---|---|---|---|
| ESP32 (512KB SRAM + PSRAM 8MB) | ≤ 8 MB | 86.9 MB | **10.9×** |
| 라즈베리파이급 (1GB) | ≤ 500 MB | 86.9 MB | ✅ 이미 만족 |
| 데스크톱 CPU | — | 86.9 MB | ✅ |

**`CLAUDE.md` 의 "저사양 CPU·엣지·모바일" 이 정확히 무엇인지 정하지 않고 있었다.**
이 표가 그 빈칸을 채운다 — **우리는 이미 라즈베리파이급을 만족하고, MCU 급은 아니다.**
이론값 12.4MB 에 닿아도 ESP32 는 **1.5×** 부족하다(PSRAM 8MB 기준으로는 만족).

> **쓸모**: 목표를 "MCU" 로 잡으면 P034 단계4 는 **필수**가 되고, "라즈베리파이" 로 잡으면
> 단계3 에서 이미 끝났고 **R8 은 선택**이 된다. **이건 실험이 아니라 사용자 결정 사항**이다.

## 4. P039 설계 (신규) — 어휘 활용도·미학습 토큰 진단

| 항목 | 내용 |
|---|---|
| **질문** | 32,768 어휘 중 몇 개가 학습에서 사실상 안 쓰였나? 그것이 val_loss 를 얼마나 오염시키나? |
| **방법** | ① `train.bin` 을 `np.bincount` → 토큰별 출현 빈도 ② 0회·10회 미만 토큰 수 ③ 그 토큰들이 **val 에 나타나는 비율**과 **손실 기여** ④ `emb` 노름 분포와 빈도의 상관 |
| **비용** | **0**(GPU 없음, 수 분). 학습 없음 |
| **선결** | 없음. 지금 가능 |
| **판정** | 미학습 토큰이 val 손실의 **1% 미만** 이면 무시. **5% 이상**이면 어휘 축소 또는 재토큰화가 실험 목록에 올라온다 |
| **한계** | 논문의 언임베딩 지표는 **우리 팩터라이즈드 타이드 임베딩에 그대로 안 맞는다**(§1). 직접 빈도 계수로 대체하며, 그건 논문보다 강한 증거다 |
| **부수 가치** | `ko-edu-en` 필터 전/후 어휘 활용도를 비교하면 **필터가 어휘를 얼마나 죽였는지**가 나온다 — 결과 023 이 아직 못 답한 "13% 를 버린 영향" 의 일부 |

**배치는 구현 후에 만든다**(`CLAUDE.md` 규범 — 지금 돌아가지 않는 배치를 최상위에 두지 않는다).
