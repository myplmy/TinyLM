# 연구 작업폴더 안내

실험 번호나 기법으로 [위키에서 검색](README.md)한 뒤, 현재 판단에 필요한 원문 절과 연결된 산출물만 연다. 여러 경로에 같은 기록을 복사하면 이후 갱신에서 어느 판본을 사용했는지 확인하기 어려워진다.

| 찾는 자료 | 위치와 보관 방식 |
| --- | --- |
| 무엇을 검증하기로 했고 실제로 무엇이 나왔는지 | `test_plan/`의 실험 계획과 `test_result/`의 결과 절을 각각 읽는다. 결과에는 입력·모델·평가 조건과 원자료 연결을 둔다. |
| 어느 프리셋에 기법을 넣었는지 | `docs/research_wiki/`에서 [프리셋별 판정](방법론_적용_판정.md)을 찾는다. 여러 실험의 채택 이유는 위키에서 연결하고 개별 수치는 원결과에서 읽는다. |
| 분석·검토의 근거와 전체 연구 방향 | `docs/research/`, `docs/review/`, [방법론 원장](../METHODS.md), [COMPASS](../../handoff/COMPASS.md)에 있다. |
| 어떤 작업을 이어받고 어떻게 검산하는지 | `handoff/`의 해당 작업원장과 최신 유효 핸드오프를 확인한다. `handoff/audit/`의 검산·종료 영수증은 인용한 원장이나 결과의 링크로 찾는다. |
| 실제 실행과 원답을 복원할 자료 | 해당 결과에서 연결한 `runs/logs/`, `runs/registry.tsv`, `test_result/evidence/` 등의 정확한 원경로를 쓴다. 체크포인트·원본 로그·원답·지문은 해당 실행을 재현할 때 필요하다. |
| 다시 만들 수 있는 문서 검색 DB | `runs/research_catalog/index.sqlite3`는 연구 Markdown과 등록한 어휘로 만든다. 누락되거나 문서가 바뀌면 `python3 -m scripts.research_catalog refresh`로 갱신한다. |

새 작업은 위 위치를 사용한다. 로컬 점검의 큰 콘솔 출력과 중간 산출물은 해당 작업의 전용 임시 폴더에 쓰고, 최종 판단을 재현하는 명세·영수증은 기존 결과나 원장에 연결한다. 기존 근거를 옮기기 전에 결과와 원장에 연결된 위치, 소유자, 지문, 복구 가능성을 확인한다. 로컬에만 남는 증거의 적용 범위는 저장소의 [.gitignore](../../.gitignore)에 기록되어 있다.

## 완료 실행기의 보존과 정리 판정

`python3 scripts/sync_experiments_tsv.py`로 루트의 완료 실행기와 재현 명령, `experiments.tsv`를 대조한다. 이름이 지정된 runlog 실행은 같은 태그의 당시 호출이나, 같은 결과문서 안에서 그 태그의 정확한 원로그 이름과 명령을 함께 확인한다. 큐에서 다시 쓸지와 원래 실행기의 환경·진입 검사·재개 조건까지 보존됐는지는 경로별로 확인한다. [작업규약의 보존 조건](../../ai_dev_tool/Codex/02_핸드오프_규약.md)

11월 24일에는 루트의 완료 실행기 107개를 확인했다. 빠져 있던 78개의 호출을 정확한 원로그가 기록된 결과에 연결한 뒤, 도구 기준으로 106개의 재현 명령을 확인했다. P108B Stage24Wa는 진입 검사에서 종료 코드 2였으며 후속 Stage24Wb와 구별해 보존했다. 최신 공유 큐의 지정 경로는 조사한 완료 실행기와 겹치지 않았다. 전체 실제 할당량은 428 KiB였고, 당시 설정과 재개 조건을 보존하려고 파일 위치를 유지했다.
