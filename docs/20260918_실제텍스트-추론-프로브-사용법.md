# TinyLM 실제 validation 텍스트·임의 프롬프트 추론 프로브 사용법

> 작성: 2026-09-18  
> 상태: 도구·순수함수 계약 `STATIC_ONLY`; 모델·체크포인트·GPU 실행 `NOT_RUN`  
> 실행 주체: 사용자

## 1. 결론

### 가장 쉬운 방법(2026-09-19 추가)

```bash
cd /home/uranus/tinyLM
/home/uranus/miniforge3/envs/tlm_torch/bin/python -B -X utf8 scripts/interactive_infer.py
```

도구가 checkpoint를 로드하기 전에 `runs/logs/*.json`의 `final.val_loss`/`best_val`, preset,
data, arch, steps, seed를 표로 보여 준다. 번호·정확한 tag·고유 부분문자열로 하나를 고르면
모델을 한 번만 로드하고 `prompt>`에 문장을 계속 입력할 수 있다.

| 입력 | 동작 |
|---|---|
| 일반 텍스트 | continuation 생성 |
| `:val` | 해당 모델 data/pool의 실제 validation context·gold·model continuation 한 세트 |
| `:meta` | 선택 checkpoint와 JSON metadata 재출력 |
| `:model` | 모델 목록으로 돌아가기 |
| `:quit` | 종료 |

목록만 보고 모델을 로드하지 않으려면 `scripts/interactive_infer.py --list --limit 50`, 특정
계열은 `--filter d14`를 쓴다. 표의 val은 학습 JSON random-crop 눈금이며 결정적 full-val이나
benchmark 점수가 아니다.

기존 저장소에는 임의 프롬프트 이어쓰기가 이미 있다.

- 한 문장: `python -m tinylm generate ... --prompt "..."`
- 고정 정성 패널: `scripts/probe_prompts.py`

다만 “validation의 실제 문맥과 정답 이어쓰기”를 같은 모델로 보고, teacher-forced NLL/ppl/bpb와
샘플 생성을 함께 출력하는 도구는 없었다. 이를 위해
[`scripts/infer_text_probe.py`](../scripts/infer_text_probe.py)를 추가했다.

이 도구는 캐시·토크나이저·체크포인트를 **찾아 다운로드하거나 생성하지 않는다**. 정확한 기존
경로 하나만 받아 읽는다. 모델 실행은 사용자가 수행한다.

## 2. WikiText라는 말의 정확한 범위

저장소의 데이터 ID `en`은 `Salesforce/wikitext`, config `wikitext-103-raw-v1`의 **train split**을
사용한다. `data_cache/en_*/val.bin`은 프로젝트 `prepare()`가 그 로컬 토큰 스트림의 말미 0.5%를
떼어 만든 validation이다.

따라서 이 도구가 보여 주는 것은 **프로젝트 WikiText-103 계열 캐시의 실제 validation 텍스트**다.
Hugging Face의 공식 `validation` split을 직접 평가한다고 부르면 안 된다.

## 3. 모델 없이 실제 텍스트만 보기

```bash
cd /home/uranus/tinyLM
/home/uranus/miniforge3/envs/tlm_torch/bin/python -B -X utf8 \
  scripts/infer_text_probe.py \
  --cache-data en \
  --cache-dir /home/uranus/tinyLM/data_cache/en_정확한캐시명 \
  --samples 3 \
  --context-tokens 96 \
  --target-tokens 48 \
  --text-only
```

`--cache-dir` 대신 후보가 하나로 특정될 때만 `--pool-tokens 100M`처럼 지정할 수 있다. 둘 이상의
캐시가 걸리면 도구는 추측하지 않고 중단한다. 이 모드는 체크포인트와 모델을 로드하지 않는다.

## 4. 체크포인트로 실제 이어쓰기와 정량값 보기

### 4.1 `ko-en` 토크나이저로 학습한 체크포인트

```bash
cd /home/uranus/tinyLM
/home/uranus/miniforge3/envs/tlm_torch/bin/python -B -X utf8 \
  scripts/infer_text_probe.py \
  --cache-data en \
  --model-data ko-en \
  --cache-dir /home/uranus/tinyLM/data_cache/en_정확한캐시명 \
  --ckpt-path /home/uranus/tinyLM/runs/ckpt/정확한체크포인트.pt \
  --arch dense \
  --device cuda \
  --samples 3 \
  --context-tokens 96 \
  --target-tokens 48 \
  --max-new 80 \
  --temperature 0.7 \
  --top-k 40
```

이 경우 `en` 캐시 토큰 ID를 모델에 그대로 넣지 않는다. 먼저 실제 원문으로 decode한 뒤
`ko-en` 모델 토크나이저로 다시 encode한다. 토크나이저 경계를 가로지르는 토큰은 부분 문자열
NLL로 쪼갤 수 없어 최대 한 토큰을 채점에서 제외하고 그 수를
`boundary_cross_tokens_dropped`로 출력한다.

### 4.2 `en` 토크나이저로 학습한 체크포인트

위 명령에서 `--model-data en`을 쓴다. 캐시와 모델 토크나이저가 같으므로 val.bin ID를 직접
사용한다.

체크포인트에는 현재 tokenizer identity가 완전하게 내장돼 있지 않으므로 `--model-data`는
필수다. 파일명으로 추측하지 않는다. 잘못 지정하면 숫자는 나와도 평가가 무효다.

## 6. 출력 해석

| 출력 | 뜻 | 한계 |
|---|---|---|
| `VAL ... context` | 실제 캐시에서 뽑은 문맥 | 공식 WikiText validation split 보증 아님 |
| `GOLD continuation` | 캐시의 실제 다음 텍스트 | 정답형 QA가 아니라 원문 이어쓰기 |
| `MODEL continuation` | sampling 결과 | 온도·seed와 near-tie에 민감한 정성 증거 |
| `target_nll`, `ppl` | 해당 짧은 target의 teacher-forced 평균 | 표본 1~3개를 full-val로 승격 금지 |
| `sample_bpb` | 표시된 target byte 기준 짧은 표본 bpb | 공식 corpus bpb나 모델 전체 성능 아님 |

TinyLM 체크포인트는 현재 기본적으로 pretraining next-token base LM이다. SFT가 없으므로 질문에
직접 답하거나 지시를 따르지 못해도 로더 실패라는 뜻은 아니다. 먼저 문법·언어 일관성·국소
사실·반복 붕괴·gold continuation NLL을 본다. 후보 승격은 이 정성 probe가 아니라 같은 pool의
paired full-val, P096 독립 held-out, KoBEST·영어 보조 panel과 함께 판단한다.

생성·TTFT·tok/s·배포 메모리 probe는 생성이 실제로 소비하는 마지막 위치 logits만 계산하도록
`logits_last_only=True`를 사용한다. 학습과 teacher-forced target NLL은 모든 위치가 필요하므로
Transformer forward 기본값 `False`를 유지한다. 역사 속도 결과를 재현해야 할 때만
`bench_infer.py --full-logits`를 쓴다.

## 7. 실행 전 확인

1. `--ckpt-path`와 `--arch`가 실제 체크포인트와 맞는지 확인한다.
2. `--model-data`는 그 체크포인트를 학습할 때 쓴 토크나이저 identity와 같아야 한다.
3. `--cache-dir`은 `meta.json`과 `val.bin`이 있는 정확한 기존 디렉터리여야 한다.
4. context+target을 모델 토크나이저로 다시 인코딩한 길이가 checkpoint `max_seq_len` 이하여야 한다.
5. 결과를 보존할 때 checkpoint 경로/hash, cache 경로/meta, 두 tokenizer ID, device,
   temperature/top-k를 함께 기록한다.

이번 작성에서는 data cache, checkpoint, 모델, GPU를 읽거나 실행하지 않았다.
