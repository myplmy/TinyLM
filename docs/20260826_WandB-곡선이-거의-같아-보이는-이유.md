# W&B 곡선이 거의 같아 보이는 이유 — **정상이다. 그리고 왜 그런지 수로 보인다**

- **작성**: 2026-08-26 · **사용자 질문**: *"val_loss, train_loss 등이 거의 모두 비슷한 형상인데
  정상적인 거동인지 아니면 학습방법·아키텍처·코드에 문제가 있는 건지"*
- **자료**: `runs/logs/*.json` 의 `history`(모델 10개 × eval 23점)

---

## 1. ★★결론 — **정상이다. 곡선의 모양은 데이터가 만든다**

| 검정 | 수치 | 뜻 |
|---|---:|---|
| ★**곡선 자체의 진폭** | **1.2313 nats**(4.9313 → 3.7000) | y축이 이만큼 움직인다 |
| ★**같은 스텝에서 모델 간 최대−최소** | 평균 **0.1208** / 최대 0.2519 | **진폭의 9.8%** |
| ★★**"오르내림" 부호 일치율** | ★**99.1%** (무작위면 50%) | ★**모양은 전부 같다** |

★**모델 10개 중 8개가 22/22 구간에서 부호가 완전히 일치**하고, 나머지 둘도 21/22 다.
★**기준선에서 val 이 올라가는 구간은 스텝 1200 · 1800 · 2000 · 2289 넷인데, 전 모델이 같다.**

---

## 2. ★왜 그런가 — **세 가지가 전부 고정돼 있다**

| # | 고정된 것 | 근거 |
|---|---|---|
| ★**1** | ★**학습 데이터의 순서** | `--seed 1337` · 같은 `--pool-tokens 600M` · **`--exact-cache`**. → **모든 런이 같은 토큰을 같은 순서로 본다.** *"어려운 배치"* 가 **같은 스텝에 도착**한다 |
| ★**2** | ★**val 크롭** | `CLAUDE.md`: *"val 크롭은 항상 99 고정(흔들면 비교 무효)"*. → 전 모델이 **같은 문장**으로 평가된다 |
| **3** | 스케줄 | `--sched wsd --anneal-end 0.80 --decay-frac 0.2` 가 전부 같다. LR·어닐의 꺾임이 같은 스텝에 온다 |

→ ★★**곡선의 "모양" 은 아키텍처가 아니라 데이터·스케줄이 만든다.**
**아키텍처는 그 곡선을 위아래로 아주 조금 평행이동시킬 뿐**이다.

```
  y축 1.2313 nats 위에서
  |<------------------ 곡선 진폭 1.2313 ------------------>|
  |======|                                                  <- 모델 간 스프레드 0.1208 (9.8%)
  |=|                                                       <- 무KD 2 sigma 0.0034 (0.28%)
```

★**우리가 판정하는 차이(0.003~0.07)는 y축의 0.2~5.7% 다.** W&B 기본 축에서는 **선 굵기**다.

---

## 3. 🚫★그래서 **W&B 곡선으로 판정하면 안 된다** — 이미 규약이다

| | |
|---|---|
| 🚫**학습로그 val** | 50배치 **랜덤 오프셋 복원추출**(전체의 약 27%). 같은 체크포인트도 부를 때마다 다르다 |
| ✅**판정 정본** | `scripts/paired_eval.py` — **결정적 full-val**(1,464 크롭 전수) + **크롭별 paired 차** |

★**paired 의 SE 가 0.0005~0.0007** 인데 학습로그 val 의 σ 는 **0.012** 다. **20배 차이**다.
→ 🚫**곡선이 겹쳐 보이는 것은 정보가 없는 것이 아니라 이 도구로는 못 보는 것**이다.

---

## 4. ⚠️★그런데 **한 가지는 진짜 주의해야 한다** — 재귀 런의 곡선

| 런 | 학습로그 `final.val_loss` | ★`paired_eval --match-train-repeat` | 차 |
|---|---:|---:|---:|
| `mC_r20_nokd` | 🚫**3.88125** | ✅**3.6573** | **0.224** |
| `mC_d36_ag4_r20_nokd` | 🚫**3.90266** | ✅**3.6691** | **0.234** |

🚫★★**학습 중 `evaluate()` 는 `model.eval()` 이라 `train_repeat` 을 무시**한다(함정 39).
→ **R=2 로 학습하고 R=1 로 평가한 값**이 W&B 에 올라간다.

⚠️★**W&B 에서 재귀 런은 다른 런보다 0.22~0.23 나빠 보인다. 그것은 모델이 아니라 평가 스케줄이다.**
🚫**두 곡선을 나란히 놓고 "재귀가 나쁘다" 고 읽으면 안 된다.**

★**조치 후보**(⏸미착수): 학습 중 eval 에 `train_repeat` 을 반영하거나, W&B 에 **경고 태그**를 붙인다.

---

## 5. ★부수 관찰 — **train_loss 의 톱니는 KD 가 아니다**

첨부 `train_loss` 그림의 규칙적인 톱니(400·700·1100·1500·1800 부근 상승)는
**전 모델에 같은 스텝에서** 나타난다. 이 열 런에는 **KD 런이 없다**(전부 무KD).
→ ★**데이터 순서 효과**로 설명된다. `ms_step_spread` 가 KD 를 잰다는 함정 40 과 같은 계열의
*"지표가 조건을 잰다"* 사례이나, 여기서는 **조건이 아니라 데이터**다.
