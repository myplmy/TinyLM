# DSKDv2 — ACTD와 분리한 표현 투영·정확 정렬의 CPU 선결

2026-11-13 사용자115 위임으로 미완 원장61을 총괄이 착수한다. 진행 중 Qwen 공식 전량,
동결 ACTD/공동쓰기 소스와 다른 정제 세션을 바꾸지 않는다. 이번 선결은 새 학습 성과 평가가 아니다.

## 1. 원문·실제 코드·기존 구현

[DSKDv2 논문](https://arxiv.org/html/2504.11426v1)은 교사/학생의 hidden을 상대 공간으로
투영한 뒤 같은 head로 비교하고, 겹친 어휘 head의 의사역행렬로 투영을 초기화한다.
[저자 distiller](https://github.com/songmzhang/DSKDv2/blob/main/code/distiller.py)와
[정확정렬 criterion](https://github.com/songmzhang/DSKDv2/blob/main/code/criterions/dual_space_kd_v2_with_exact_token_alignment.py)을
읽었다. README의 축약 파일명 with_eta는404였으며 실제 긴 파일명을 디렉터리에서 확인했다.
원 코드/패키지는 설치·다운로드·실행하지 않았다. 저자 코드의 TinyLM 적용 검증은 별도다.

현재 scripts의 DSKD/dual-space 구현은 없었다. ACTD는 원 토큰 앵커와 잔여 확률, ALM은
byte 경계 확률을 다룬다. 둘을 DSKDv2로 재명명하거나 vocab 앞부분을 자른 KL로 대체하지 않는다.
DWA의 불확실성 가중치·Soft-DTW와 on-policy도 이번 최소 선결과 다른 미완이다.

## 3. 수학·TinyLM 차이

정렬된 N위치에서 Hs(N,d), Ht(N,D), Ws(d,Vs), Wt(D,Vt)를 쓴다.
공통 raw-byte token의 명시 ID 쌍으로만 S(d,O), T(D,O)를 만든다. ID 번호가 같은지나
vocab 크기가 같은지는 대응 근거가 아니다. 초기값은 Pts=T pinv(S), Pst=S pinv(T)다.
공통 어휘 수와 rank/잔차를 기록하며 identity 성립을 자동 가정하지 않는다.

TinyLM의 실제 head는 emb_up와 embedding의 곱이며 rank 상한이256이다(폭768과 다름).
이론상 Ws=emb_up·embedding^T지만 정밀도·실제 weight 접근자·return_hidden norm을 포함한
런타임 logits/VJP 대응이 닫히기 전 이 식을 실제 학습 head 호환 증거로 승격하지 않는다.
교사 full248320과 학생 full32768 분모를 각각 보존해야 한다. 큰 logits는 후속 소비자에서
위치 chunk로 묶되 전체 어휘를 유지한다. 추가 메모리/시간은 현재 미측정이다.

최소 CPU 손실은 온도1의 세 합이다. 학생 공간 KL은 stopgrad(softmax(Ht·Pts·stopgrad(Ws)))와
softmax(Hs·Ws)를 비교한다. 투영 CE는 교사 top1이 학생의 같은 완전 token에 대응할 때만
Pts를 학습하며 Ws/Ht/Wt는 이 가지에서 고정한다. 교사 공간 KL은 원 교사 분포와
softmax(Hs·stopgrad(Pst)·stopgrad(Wt))를 비교한다. Pst는 현재 detached Ws에서 갱신하는
사전 계산이며 학생 본체를 초기화하지 않는다. 전역 정렬 위치 분모를 쓰고 원래 CE772는 유지한다.

## 4. 정확 정렬과 보류

ACTD 준비의 같은128 원형/두 tokenizer byte span을 재사용한다. 동일 원문 byte prefix와
동일한 완전 token byte 구간·같은 assistant owner를 갖는 위치만 후보로 삼는다. 부분 문자열,
첫 subtoken, 가장 가까운 미래 경계는 허용하지 않는다. 한번 shift의 predictor=target_raw_index-1을
검산한다. 두 tokenizer의 prefix가 같은 byte에서 끝나는 경우에만 UTF-8 조각도 정확 대응할 수 있다.

이 재고는 **정답 token의 정렬 후보 상한**이다. 원 교사 top1이 학생 전체 token에 정확히
대응하는지까지 실제 교사 신호로 확인해야 최종 DSKD 위치다. CPU 정렬 개수를 실제 신호 수로
발표하지 않는다. 미정렬·top1 미수집/미대응은 이유와 함께 보류하고 원 CE를 지우지 않는다.

## 5. 순서·판정

Stage7l CPU는 의사역행렬/저rank 잔차·full-vocab/stop-gradient·전역 분모·chunk 가산·
독립 dense oracle/미분·같은 byte prefix·조건/owner 변경·shift·부분 token 거부를 검사한다.
Stage7m은 실제 원형128을 모델 없이 전량 재고하고 입력 SHA/정렬/보류/언어/분모를 봉인한다.
raw 정렬 양성은 모델 품질 양성이 아니다. 새 helper가 실제 teacher/head adapter까지 연결된
전체 DSKDv2라고 보고하지 않는다. 본체 optimizer/체크포인트/성능 개선은 미실행이다.

GPU 우선순위는 원래대로 공식 full의 종료/정확legacy→P108 공동쓰기→ACTD 실제 신호/미분이다.
DSKD hidden/head 수집·native VJP와 학습 연결은 이 CPU 재고 및 남은 시간/소유권을 보고 정한다.
모든 산출물은20MB 미만으로 나눈다. 원형과 실패를 덮어쓰지 않는다.

## 6. CPU 실제 head 선결의 추가 범위

CPU13/실제128 재고는557/772 정확 gold-token 후보(KO230/277·EN327/495)를 닫았다.
이어서 새 Stage7n0/7n은 기존 guarded CPU loader로 완료93M을 읽어 head만 호출하고,
native FP32 출력/hidden VJP가 같은 factor 연산과 일치하는지 확인한다. 원 body forward와
optimizer는0이다. 교사 모델은 올리지 않고 이미 검증된 tied embedding의 원 safetensor에서
mode1 exact shared-byte23302개만 chunk로 읽는다. special 의미 대응3개나 첫subtoken224506개는
의사역행렬의 공통 어휘로 섞지 않는다. 원 byte mapping/teacher config/weight/CP SHA를 재검산한다.

같은 helper로 실제 두 overlap head를 초기화해 rank/양방향 logit 잔차·CPU wall/RSS를 기록한다.
투영은 메모리에서만 계산하고 CP/큰 행렬은 저장하지 않는다. 이 결과는 CPU FP32 head 선결이며
BF16 native 본체/teacher hidden·실제 top1·GPU 추가비용·전체 학습 효과가 아니다.
현재13시험 helper의 pinv와 rank 계산이 각각 SVD를 수행하는 비용도 포함한다. 향후 캐시로
줄일 가능성과 이번 실측을 구분한다. CPU 상한900초, 기존 GPU 우선순위는 유지한다.

연산 산술만 보면 교사 head의1024×248320은 student factor의768×256+256×32768보다
위치당 약29.6배 MAC이다. 전체 학습이29.6배 느리다는 뜻은 아니다. 원래 trunk 비용, 실제
정렬 질량·고정 teacher head/hidden 캐시·target chunk를 포함한 비용은 아직 측정 전이다.

## 7. 실제 CPU 회수와 후속 판단

Stage7n0 CPU3은 통과했고, 새 속성 검사의 JSON dict 오인1건을 보존·명확화한 scoped
v27의1321입력6PASS/0ERROR/71NOT_RUN 뒤7n을 실행했다. 실제 session87942 종료0,
전체12.206026초 중 head 추출0.372689초·초기화6.542201초였다. peak process RSS는
2237120KiB이며 GPU VRAM이 아니다. 원 report를 정본으로 한다. native FP32 출력/VJP는 EXACT였으며
원 core/CP·교사 asset 불변, CUDA 초기화false, body forward/optimizer/CP저장0이다.

| 실제 overlap | 학생 | 교사 |
|---|---:|---:|
| shape | 768×23302 | 1024×23302 |
| 수치 rank(rtol1e-8) | 256 | 1024 |
| 상대 Frobenius 재구성 오차 | 교사→학생0.879512486 | 학생→교사0.751508225 |

큰 teacher rank만으로 student head의 row space가 포함되지는 않는다. 예를 들어
S=[0,0,1],T=[[1,0,0],[0,1,0]]는 rank(T)>rank(S)지만 Pst·T로 S를 복원할 수 없다.
이 실제 쌍에서도 초기화가 양쪽 logits의 identity를 보장한다는 가정은 성립하지 않았다.
이것은 정확도87.95% 손실이라는 뜻도, DSKD 전체가 불가능하다는 뜻도 아니다. 실제 hidden의
분포와 projection 학습은 별도이며 CPU head/VJP 양성으로 일반 지능을 주장하지 않는다.

다음 세 경로 중 A를 우선 검토한다. A는 실제 동일 원형의 teacher hidden/native top1과
초기 투영의 예측 일치를 먼저 관찰한다. 구현·품질 원인을 분리하고 새 본체 학습은 하지 않는다.
B는 실제 신호를 얻은 뒤 projection만 먼저 맞추는 별도 대조이며 추가 최적화 조건이 늘어난다.
C는 DSKD를 현재 음성으로 종결하고 다른 큐만 진행하지만 실제 hidden을 보지 않아 성급하다.
초기화 잔차만으로 C를 선택하지 않는다. 원래 full→legacy→공동쓰기→ACTD 순서를 유지하고
A의 새 collector/미분 소비자는 남은 시간과 실제 선결 종료를 보고 봉인한다.
