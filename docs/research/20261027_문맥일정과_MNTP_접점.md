# 문맥 길이 일정과 MNTP의 미완 접점

원장57/58의 선결 검토다. 문헌 보조는 원문·공식 코드를 읽었고 정 보조는 실제 loader/trainer를 읽었다. 총괄이 권한·실제 코드·원문을 대조한다. 보조는 파일수정/시험/모델실행을 하지 않는다. 정제는 타세션 소유이고 추가300M 학습은 금지 상태다. 아래 기술준비를 작은학습의 지능 판정으로 쓰지 않는다.

## 1. 기존 구현과 혼동을 구분한다

[P013](../../test_plan/P013_seq-length-warmup-소규모.md)은 이미256→512→1024 계획을 갖고 있으나 loader/trainer의 일정 구현은 확인되지 않았다. 기존 PAD 말미 축소는 같은 답의 불필요한 padding을 줄이는 기능이며, 실제 이전 문맥을 짧게 만드는 이번 일정과 다르다. 기존 P101A MTP·검산풀이·P078 방문순서/라우터는 별개 완료 이력이므로 다시 학습하지 않는다.

현 loader는 replacement random crop이다. `--tokens`는 캐시/명명과 연결되지만 실제 종료는steps다. 8×16×1024와8×32×512와8×64×256은모두131072 input/update이고2289update는300023808 draw다. 이를정확300000000·고유300M·순방문1회라고부르지않는다. 원문별노출과target분모는별도다.

## 2. 점진 문맥의 세 준비안

| 안 | 변하는 것 | 장점·한계 | 판단 |
|---|---|---|---|
| 고정micro/accum에서길이만축소 | update당token과총draw도감소 | 구현은작지만빠른step을같은총학습가속으로오인하기쉽다 | 첫대조로채택하지않음 |
| 같은1024 window를짧은블록으로분할하고micro8재배치 | 문맥reset/분할수,실행shape | 원래x/y위치와sampler호출을보존하고131072분모를맞춘다. 짧은prefix손실과optimizer·compile비용은남는다 | **기술계약우선** |
| 길이별새random crop과accum조정 | 문맥길이와draw위치/문서노출 | 일반적인warmup에가깝지만원천선택까지바뀌어원인분리가어렵다 | 별도후속 |

선택안은매update기존16개의(8,1024)x/y를먼저얻고,각full window의모든위치를순서대로4개의256또는2개의512로분할한다. y의원래위치를정확1회보존한다. 블록마지막의다음토큰지도도그대로두며,그다음블록에서문맥이초기화되는차이를숨기지않는다. 1024는원래배치를그대로쓴다. 새문서생성·packing·앞부분만crop·추가shuffle은하지않는다.

최초범위는NTP-only/eager/R1이고SFT·KD·MTP는열지않는다. SFT질문과답을갈라지도하거나오프라인1024KD를짧은context와같은조건으로취급하지않기위함이다. 일정·samplerRNG·완료update·실제draw/target·EOS/문서경계·명시source를보존하고,재개시불일치는거부해야한다. cfg최대와val길이는1024로유지한다. optimizer/CUDA graph/compile승격과최종1024품질은본학습후에만판단한다.

[Sequence Length Warmup 원문](https://arxiv.org/abs/2108.06084)과[DeepSpeed공식설명](https://www.deepspeed.ai/tutorials/data-efficiency/)은문맥일정의근거다. 다만고정시퀀스수에서attention의L제곱항비율16을같은token/update의전체시간16배로옮길수없다. 같은token/update의attention항은길이에비례하고MLP/head·재계산·optimizer·호스트비용이남는다. 외부모델의개선수치는TinyLM실측이아니다.

## 3. MNTP는 기존 causal loss에 이름만 붙이는 방법이 아니다

[GPT-BERT v2 §2.1](https://arxiv.org/html/2410.24159v2)은가린원래토큰x[k+1]를h[k]에서복구하는양방향MNTP와causal NTP배치를혼합한다. [공식dataset](https://github.com/ltgoslo/gpt-bert/blob/main/pretraining/dataset.py)은문서간차단을유지하고masked는양방향,causal만삼각제약을쓴다. [공식model](https://github.com/ltgoslo/gpt-bert/blob/main/pretraining/model.py)은두CE를각각평균한뒤혼합한다. official main의commit SHA는아직고정하지못했으므로복제완료가아니다.

MTP는미래offset용보조head,assistant mask는지도위치선택,attention mask는입력가시성이다. causal전용상태에서미래정답한토큰만가리면h[k]는원래그토큰을보지못하므로선택적NTP와같을수있다. 여러prefix를손상시키는변형도원문MNTP와구분해야한다. 반대로가린x[k]를h[k]에서예측하면target shift가다른목표다.

TinyLM의현재attention은기본causal삼각또는KV절대위치mask다. 양방향을넣으려면문서/패딩차단과CLA owner×방문회차의가시성을함께연결해야한다. masked학습의오른쪽문맥을causal incremental KV로재사용할수없다. 최초기술fixture는작은가상두문서에서shift·미래차단/접근·문서간차단·지도교집합·0target·목표별분모를검산하는것이며,그것만으로제품연결완료라고하지않는다.

## 4. 현재 판단

이번에는점진문맥의위치/분모/재개계약부터총괄이별도구현하고,정식MNTP는양방향visibility를명시하는추가설계로분리한다. 이는MNTP기각이아니며causal손상목표를원문재현이라고부르지않겠다는판단이다. 새로운정제자료읽기·새부모학습·추가300M·외부설치/취득은0이다. 비용기술진단이실행되면실제종결·원로그·같은draw분모·memory/time과본학습미완을따로기록한다.
