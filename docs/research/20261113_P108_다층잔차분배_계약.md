# P108 두 층 잔차 분배 — 같은 총 변경량의 마지막 층 대조

사용자115의17시까지 연구·구현·CPU/GPU 위임으로 총괄이 수행한다. Stage20의 한층 공동수정은
fit3/24·dev엄격0/12·기공개표현0/16이었다. 같은 packet을 다시 실행하지 않는다.
[MEMIT 저자 코드](https://github.com/kmeng01/memit/blob/main/memit/memit_main.py)는 마지막 층의
목표 응답과 현재 응답의 차이를 남은 층에 나누고, 앞 층 수정 뒤 현재 key/잔차를 다시 계산한다.
[목표 최적화 코드](https://github.com/kmeng01/memit/blob/main/memit/compute_z.py)도 전체 block 출력을
개입한다. 여기서는 기존 layer11 값을 재사용한 질문 마지막 위치 변형이며 논문 전체 재현이 아니다.

## 세 안과 선택

| 안 | 내용 | 이점 | 한계·비용 |
|---|---|---|---|
| A, 선택 | 마지막층11 단독 대조와8→11 순차 잔차 분배를 같은 절대 Frobenius 한도로 비교 | 기존 한층 문제와 다른 전달 경로를 시험 | 비선형 층간 전달은 근사이며 보호 손상 가능; 구현/회귀와 GPU5~10분 예상 |
| B | 여러 새 질문에서 value를 다시 최적화 | 표현 다양성을 직접 추가 | 새 정답 노출/값/비교조건이 바뀌고 기존값 전이 한계를 분리하기 어려움 |
| C | 현재 직접편집을 보존하고 증류 연결만 진행 | 구현 비용 작음 | 미시도 다층 잔차 분배는 남음 |

A를 먼저 준비한다. 원fit24만의 기존 oracle은 layer8=19/24·11=18/24로 가장 높아8/11을
고정한다. dev/기공개표현/보호의 점수로 층을 고르지 않는다. 값·원형68·통계128은 그대로다.
목표는 일부 fit 개선을 일반 지능으로 선언하는 것이 아니라, 전이와 보호가 함께 회복되는지 보는 것이다.

## 영향·권한·차이

새 helper/CPU회귀/driver·Stage21 SH/namespace와 자기 문서·원장만 수정한다. 기존 value·
covariance/KKT packet·등록 float 편집/원복·생성·원형/샤드 도구를 재사용한다. 제품 모델,
기존 봉인 소스/실패/허용오차·원CP·원로그·타정제/TinyDataset은 불변이다. optimizer/가치 재학습/
체크포인트 저장·설치/다운로드·새환경·Git·삭제·추가300M은0이다.

원native float R1/untied·FP32 MATH·TF32 OFF·greedy64/EOT4를 유지한다. 기준은 원본68과
layer11의 기존 oracle-fit24이며 새 실제글로벌은 단독11/분산8+11/random분산3팔이다.
층 수만 바꾸며 더 큰 변경량을 주지 않도록 두 팔 모두 A=0.05×min(||W8||F,||W11||F)를 쓴다.
단독은 A, 분산은 각 A/sqrt(2) 한도이며 실제 FP32 실현의 합성 norm도 A 이하여야 한다.
이 기준은 Stage20의 layer8 상대5%와 정확히 같은 절대량이라고 주장하지 않는다.

## 알고리즘·구조 적합성

원fit24에서 기존 value11을 down 출력에 주입했을 때 실제 관측한 block11 출력을 Z*로 고정한다.
각 단계 r에서 현재 block11 출력 Z와 key K를 다시 관측한다. TinyLM의 실제 Layer.forward는
x에 gates[1]×MLP를 더하므로, down 목표 응답은 (Z*−Z)/(남은층수×gate_r)다. gate의 부호를
보존하며0 또는 비유한 값이면 중단한다. 마지막 층에서는 이 연산이 기존 value11 목표와 대응한다.
중간8층에서 마지막11층까지의 비선형 전달을 identity로 근사하는 한계는 그대로 남는다.

기존 joint_packet의 공분산 보존/고정norm KKT 해를 쓴다. C는 같은 통계128의 원활성값으로
계산하고, 두 번째 key/잔차는 첫 편집을 실제 적용한 상태에서 얻는다. 모든 packet을 봉인한 뒤
dev/기공개표현/보호 답을 회수한다. random3은 층별 실제norm/spectrum을 맞추며 seed를 고정한다.
전 질문의 after-weight SHA가 팔마다 같고 최종 core/원CP/캐시 원복·CUDA0/0이어야 한다.

## 판정·비용·한계

CPU는 signed gate·균등 잔차·합성절대예산/잘못된입력 거부를 검사한다. GPU는4GiB 여유 입장,
예상5~10분/최장30분·마감15분 유보·다른GPU와 직렬이다. 원답은3MB씩 분할한다.
기술 정합과 답변 품질을 분리하며 pilot의 다음단계 조건은 fit/dev/기공개표현 모두 원본보다
높고 보호≥7/16·반복≤23/68·echo≤9/68이다. 정규식을 바꾸거나 의미상 정답을 엄격형식에
섞지 않는다. GPT가 실제 원답을 읽고 의미/형식·일상 반복의 잔존을 별도로 기록한다.
기공개16은 독립 holdout이 아니며 통과해도 일반 지능·모델 채택을 의미하지 않는다.
