## 1. 질문·기존과 차이·문헌

이전12가족은 각각 편집→생성→원복했으므로 합산 정확도가 한 모델의 동시 능력이 아니다.
값 최적화도 이미 가족별 두 fit 문맥으로 수행했다. 단순히 두 문맥을 쓴다고 새 방법이라
하지 않는다. 새 변수는 **12가족/24 fit key를 한 물리 weight packet에 함께 쓰는 것**이다.
8개 세계 사실의 KO8/EN4 가족이며 새로운 일반지식 전체를 제공하는 작업이 아니다.

[MEMIT 원문](https://arxiv.org/abs/2210.07229)과
[저자 코드](https://github.com/kmeng01/memit/blob/main/memit/memit_main.py#L190)는
여러 key와 공분산을 함께 풀고 층들에 residual을 분배한다. 우리는 TinyLM의 기존
마지막 prompt 위치 value와 단일 down projection을 사용하므로 전체 MEMIT 재현이 아니다.
저자의6B/20B 성과를93M의 예상치로 복사하지 않는다. 아래 norm 제약은 총괄의 추가 설계다.

동결된48 value 후보(12가족×4층)의 **fit 지표만** 합치면 layer2/5/8/11 oracle 정확은
0/4/19/18,각24개다. 마지막 NLL 합도60.503435/33.669559/5.216532/10.026331이다.
(-fit정확,fit NLL,층번호) 사전 규칙으로 공통 layer8을 고른다. dev/공개 표현/보호 답은
층이나 계수 선택에 사용하지 않는다. 이 수치는 기존 실행 재집계이지 새 모델 성과가 아니다.

## 4. 수식·사전 선택

fit key 열행렬 K(2048×24),원값 변화 R(768×24),통계128질문의 마지막8개 key로 만든
C=E[kk^T]+0.01·trace(E[kk^T])/2048·I를 쓴다. 값은 각 fit 쌍에 같은 가족 값을 반복한다.
원 down weight W에 대해 아래 convex 문제를 푼다.

min_D 0.5||DK-R||_F^2 + 0.5 trace(D C D^T),  ||D||_F <= 0.05||W||_F.

S=KK^T+C=Q diag(s) Q^T이면 D(lambda)=R K^T Q diag(1/(s+lambda)) Q^T다.
norm 제약이 없으면 lambda=0이고 필요하면 고유방향별 norm 제곱합의 단조성을 이용해
lambda를 이분한다. dev 점수로 계수를 고르지 않는다. FP32 저장 roundoff를 위해 설계 때
norm 목표를 5%의(1-1e-5)로 잡고, 실제 materialized weight 변화가5%를 넘으면 거부한다.
그 뒤 한도를 올리거나 실험을 통과로 바꾸지 않는다. eigen 비양수/비유한·실현 불일치는 오류다.

R과24열 right factor만 보존해 dense matrix 전체의 큰 JSON을 만들지 않는다. random3은
같은 factor의 작은 QR/SVD를 사용해 의도한 singular spectrum/norm과 열수를 맞춘다.
FP32 실제 실현의 차이는 별도 수치로 기록하고 실제 rank가 영원히 같다고 주장하지 않는다.
