사용자98의 기존 조사와 사용자141의 미완 우선 위임에서 총괄이 보충했다. 2026-10-27 보고서와 11-13 AGC 보충을 다시 실행한 것이 아니다. 이번에는 일차 문헌·공개 코드의 버전과 재현 경계를 확인했다. 외부 코드를 설치·실행하거나 학생 학습·데이터 편입을 수행하지 않았다.

## 2. HRM에서 기존 조사 이후 닫힌 부분

[반복 구현](https://github.com/sapientinc/HRM-Text/blob/aaa948ea674fd84b7bc455c9cfb455ecfefdf914/models/baselines/hrm_nocarry_bp_warmup.py)은 H와 L의 별도 Transformer를 만들고, H 주기와 각 H 안의 L 주기에 대응하는 별도 cache 목록을 만든다. 끝부분의 제한된 방문에서만 gradient를 켜며 bp warmup은 그 범위를 바꾼다. zL 초기 상태는 지속 BF16 buffer다. TinyLM의 한 층 방문 수를 추론 때 늘리는 것과 동일한 방법이 아니다.

[Transformer](https://github.com/sapientinc/HRM-Text/blob/aaa948ea674fd84b7bc455c9cfb455ecfefdf914/models/transformer.py)는 SwiGLU와 pre/post RMSNorm을 명시하며 Attention의 Q/KV head 수를 같게 둔다. 따라서 활성함수 부품은 겹쳐도 Tiny의 GQA·CLA owner·공유 physical tensor·FP32/삼진 경로까지 호환된다는 근거는 아니다.

TinyLM에 옮기려면 module(H/L)×주기×논리층×실제KV owner별 저장소, no-grad 방문 뒤 상태/입력 gradient 경계, 위치/PrefixLM/정답 마스크, 중복된 공유 파라미터 norm 회계와 정확한 RNG·스케줄·역전파 horizon 재개를 정의해야 한다. activation/branch 정규화를 바꾸면 이번 직접편집의 예측식도 새 전달 그래프에서 다시 확인해야 한다. 기존 MTP/방문 정책/라우터 결과를 HRM 재현이라고 부르지 않는다.

## 3. AC-ODM 코드에서 확인한 이식 위험

[공식 학회판](https://proceedings.mlr.press/v306/ma26i.html)이 연결한 [agent.py](https://github.com/DANG-ai/AC-ODM/blob/e95863eb24a1407a03bc23b788ad6155e29ff054/megatron/data/agent.py)를 고정 판독했다. 선택된 parameter 이름의 누적 gradient 차분을 도메인 신호로 모으고, 도메인 gradient 내적 행렬의 대각을 제외한 값을 정규화한다. actor/critic뿐 아니라 target 네트워크, optimizer/scheduler, replay pool, domain counts/losses, 이전 gradient·상태·가중치 통계를 보유한다. 기본 sampler만 바꾸는 작은 패치로 볼 수 없다.

Tiny에서는 같은 latent 공유 tensor를 여러 논리층으로 중복 집계하지 않고, STE 유효 가중치와 master gradient를 구분해야 한다. accumulation 중간/끝과 loss의 유효 target 질량, clipping/all-reduce 전후 중 어느 신호인지 고정해야 한다. 선택 도메인이 그 창에서 나타나지 않을 때 count0과 표준편차0/단일 도메인도 정의해야 한다. 불량 텍스트의 높은 loss를 유용성으로 잘못 보상하지 않는다.

읽은 warmup 경로에는 online_P의 backward 뒤 online_Q의 step을 부르는 조합이 있다. 전체 caller와 의도는 미검증이므로 이를 확정 버그나 논문 실패로 단정하지 않는다. 반대로 코드를 그대로 복사해 검증된 갱신이라고 할 수도 없다. checkpointing.py에서 관련 상태 이름이 보이지 않았지만 다른 저장 경로까지 부재라고 결론내리지 않는다. 정확 재개에는 별도의 전체 상태 추적이 필요하다. 공개 효율 수치는 원논문의 큰 모델/환경 조건이며 Tiny 예상치가 아니다.

## 4. LFR은 무엇으로 확인됐고 무엇이 미확인인가

LFR이라는 이름으로 확인한 일차 논문은 Learn, Focus, and Review다. Learn에서 전체를 보고, Focus에서 어려운 블록에 집중하며, Review에서 전체를 다시 본다. 단순 고손실 우선이나 토큰 masking과 다르다. 단일 epoch 변형은 블록 표현의 군집도 사용한다. [방법 원문](https://arxiv.org/html/2409.06131v2#S4).

이 후보가 사용자의 의도한 LFR인지까지 확인한 것은 아니다. 논문·학회·저자 연구실 링크와 논문명 검색에서 저자 구현을 확정하지 못했다. 공식 코드가 존재하지 않는다는 증명도 아니다. arXiv v2와 학회 PDF의 표/설명은 버전을 나눠 보존하며 숫자를 혼합하지 않는다. 별도 이름의 다른 LFR이라면 해당 링크로 동정을 다시 해야 한다.

구조보다 자료 sampler 쪽 후보로 본다. 정제된 TRAIN의 고정 block ID·유효 분모·이전 loss·표현·단계/노출/RNG를 저장해야 한다. 전체 scoring·군집·Review 비용을 전체 wallclock에 포함하고, benchmark 답으로 Focus를 고르지 않는다. 높은 PPL의 깨진 표/HTML/반복을 더 학습시키는 역효과를 먼저 막아야 한다. 이번 TinyLM 이득이나 가속은 측정하지 않았다.

## 5. NOISE·TST의 남은 STE/cache 계약

NOISE의 forward-only 원규칙과 BP를 섞는 자체 연구를 구분한다. 혼합한다면 동일 snapshot에서 서로 다른 parameter 집합을 갱신하거나 두 추정 gradient를 명시적으로 합쳐야 한다. 단순 CUDA 동시 stream은 비용을 없애지 않는다. 추가 forward가 살아 있는 삼진 view를 갈아끼우는 현 구현에서는 BP graph·checkpoint 재계산·gradient buffer·난수와 충돌할 수 있다. 같은 latent 교란에도 ternary code 변화0일 수 있으므로 master 공간·effective 공간·활성 교란을 각각 계측해야 한다.

TST는 bag 입력/다음 비중첩 bag 목표 뒤 정규 NTP 복구가 핵심이다. 입력 평균에 들어간 토큰을 목표 bag에 다시 넣는 누설, 문서 경계/assistant owner/PAD와 중복 target 질량, MTP horizon과 bag shift를 구분해야 한다. bag화·표현/분포 복구·평가·저장 비용을 포함한 전체 본학습으로 판단한다. 규칙4096행이나 짧은 loss 진단을 일반 지능 성과로 대신하지 않는다.

## 6. 현재 결정

| 구분 | 판단 | 아직 하지 않은 일 |
|---|---|---|
| 채택 | 버전 고정·노출/상태 회계·source와 native 효과를 먼저 검증하는 절차 | 모델의 새 기본 학습법 채택은 아님 |
| 조건부 연구 후보 | 원장59의 관찰 통계 뒤 LFR/AC-ODM sampler, TST→NTP, HRM 방문/gradient 경계 | 정제 입장·코드/CPU·실제 전체 비용·본학습·고정 외부 평가 |
| 비채택 | NOISE/HRM/TST/AGC를 이름만 붙여 기본 trainer에 동시 삽입하거나 배수를 곱하는 안 | 별도 근거 없으므로 실행하지 않음 |

문헌 검토로 공개 수식·코드와 구현 위험을 정리한 것과 그 방법론을 실제 TinyLM에서 재현한 것은 다르다. AGC의 exact clip 지점/축/문턱은 여전히 공개 근거만으로 닫히지 않았다. 현재 보호 원천과 타 정제 작업을 읽거나 수정하지 않았으며 정제 전 추가300M은 수행하지 않았다.
