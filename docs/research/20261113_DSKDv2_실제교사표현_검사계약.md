# DSKDv2 실제 교사 표현과 완전 토큰 대응 — 본학습 전 연결 검사

사용자115의11월13일17시까지 연구·구현·CPU/GPU 위임으로 총괄이 수행한다.
CPU head/VJP EXACT와 overlap23302의 초기화는 완료됐지만 실제 hidden에서 어떤 신호가
전달되는지는 미확인이다. 초기 행렬 오차0.8795/0.7515를 답변 정답률로 바꾸지 않는다.

## 선택·예측

| 안 | 방법 | 장점 | 한계·비용 |
|---|---|---|---|
| A, 선택 | 같은128행에서 실제 정규화된 teacher hidden/native full-vocab top1을 수집 | 원문·CE·모델을 바꾸지 않고 정렬과 투영의 실제 입력을 확보 | GPU 약2분·CPU/디스크 feature 캐시 약수백MB 예상 |
| B | 투영기를 먼저 추가 학습 | 초기 head 근사를 개선할 수 있음 | 새 최적화 목표·학습 노출이 추가되며 원인 분리가 덜 명확 |
| C | 초기 행렬 오차만 보고 방법을 폐기 | 추가 비용 없음 | 실제 hidden 부분공간을 확인하지 않고 효용을 단정하게 됨 |

A는 좋은 품질을 예측하는 실험이 아니다. native top1이 exact 공통 토큰에 없는 경우가 많거나
새 prefix 검사에서 실패할 수 있다. 이런 음성도 보존하고 낮은 표본 점수를 지능 주장으로 쓰지 않는다.
교사의 정답성을 top1이나 낮은 엔트로피만으로 판정하지 않는다.

기존ACTD는 top128 분포만 남겼고 normalized hidden은 저장하지 않았다. 새 hidden 관측과
원캐시 union 밖의 정확 UTF8 조각2위치가 순증분이며, 기존128번의 품질 실험을 재평가하는
목적이 아니다. 소스·원형·토크나이저·init·head를 재사용하고 새 데이터는 만들지 않는다.

## 고정 계약·단계

1. 기존 CPU exact 후보557/보류215, 원128행/x32216/CE772와 CPU native-head/VJP 실제 종료를
   SHA로 고정한다. 원corpus는 정식 편입false이며 이를 새로 승인하지 않는다.
2. CPU4로 full-width 관찰/원full-vocab 보존·변조 로짓 거부·중복 호출 거부·정밀도/예외 시
   hook 제거를 검사한다. 준비는 모델/GPU0이다.
3. Qwen3.5-0.8B의 기존 FP32 MATH·TF32 OFF·B1×1024·use_cacheFalse 경로를 재사용한다.
   head 출력과 qualified 반환 prefix는 EXACT여야 한다. shape를 줄여 교사를 새 경로로
   실행하거나 full vocab248320을 공통23302로 잘라 분포를 대신하지 않는다.
4. 실제 normalized hidden의 유효 prefix를 CPU float32 npy로 저장한다. 각 파일은4.2MB 이하,
   원모델 파일이 아닌 feature cache이며 staging 대상이 아니다. 원답·manifest는3MB씩 분할한다.
5. 첫 한국어/영어 각1prefix 및 기존 union 밖 UTF8 조각2위치를 포함한4canary에서 같은1024폭의
   전체/잘린 prefix logits·hidden을 원atol1e-5/rtol1e-4로 비교한다. 불일치는 즉시 중단한다.
6. exact557 위치에서 native full-vocab argmax와 full LSE를 기록한다. argmax의 바이트 전체가
   학생 토큰1개와 같은 mode1 또는 명시 특수 의미 mode3만 수락한다. 첫 subtoken/최근접/future
   fallback은0이고 나머지는 HOLD로 남긴다. 원CE772에서는 어떤 위치도 삭제하지 않는다.
7. teacher와 학생은 동시에 올리지 않는다. 원source/model/CP·원캐시 불변·모델weakref 해제·
   CUDA allocated/reserved0/0을 닫고 실제 tool 종료를 root가 별도 확인한다.

단독 GPU·입장12288MiB 여유·예상2분/상한30분·마감15분 정리 여유를 둔다. 새환경·설치·
다운로드·optimizer·checkpoint저장·추가300M은0이다. 저장/CPU RSS/VRAM/시간/품질은 분리한다.

## 남는 것

이 단계는 투영 후 native top1 일치나 양공간 실제 GPU 미분을 아직 증명하지 않는다.
고정된 teacher head의 재구성 정합·초기 투영의 실제 신호·native BF16 학생의 전체분모 손실/
stop-gradient·추가 비용이 다음 선결이다. 전체 본학습 이후의 일반 성능은 별도 평가한다.

## 실제 종료기 실패와 부분 산출물 복구

원Stage7u는 실제82911 종료1이며 report는 없다. normalized feature128과 native위치 샤드는
전량 닫혔고 stdout은538수락까지 기록했다. fixed.logits를 직접 호출했으므로 LM adapter의
_model_call trace는 자동으로 쓰이지 않았고, 별도 수동 trace 기록을 누락한 것이 원인이다.
빈 trace close 예외를 finalizer 안에서 독립 처리하지 않아 최종 report 작성도 가렸다.

새 Stage7v/w/x는 이 실패를 보존하고 전체 캐시의 SHA/실제 npy dtype/shape/finite·원CE/원형
대응을 CPU로 검증한다. 그후 원4canary의4행/8실제호출만 새 namespace에서 재생해 원 feature/
native top1/full-LSE·causal prefix를 확인한다. 전체128의 GPU 수집을 중복하지 않는다.
trace는 실제 각 호출을 수동 기록하고 개별close 예외도 report에 모은 뒤 종료한다.
원실행의 peak/CUDA값은 미확인이며 새실행의 실측으로 소급 채우지 않는다.
