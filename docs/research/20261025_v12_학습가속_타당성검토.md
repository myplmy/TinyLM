anneal을1로 강제하면 학습 조건이 바뀐다. 공유 MLP는 논리 호출별 반올림·합산 순서와
compute-weight 기울기를 실제 업데이트까지 보존해야 한다. 기존 STE도 단순 항등식이 아니다.

원 trainer는 checkpoint·compile·공유·MTP·native595 조합을 일부 명시 거부하므로
원형 경로를 제품의 단일 옵션으로 취급하지 않는다.

## 3. 원형의 속도 예측은 어떤 비교인가

원형 비용표의 중간 예상은 native S2 대비1.7376배, 낙관2.0542배다. 같은 선택 저장/CE
조건의 dense 대조와 비교하면 각각1.2341배·1.4216배다. 보수값은 각각1.3623배·1.0183배다.
따라서 INT8 방법만의 공정한 증가분과 checkpoint/CE 설정 변경 효과를 분리해야 한다.
producer만의 중간 추가 이득은 약4.6% 추정이다.

native2.7043초→설정 맞춘 dense1.9207초→native-forward 정수역전파1.6800초→두 항 전방
1.6278초→producer융합1.5564초는 비용 모델이다. 일부 기존 BF16 forward 실측을 기준으로
삼았지만 pack·INT8·기타 항목에는 가정이 있다. 이 숫자를 RTX4070TiSUPER의 새 GPU
실측이나 본학습 가속으로 보고하지 않는다.

## 4. 관련 선행근거가 지지하는 범위

[SwitchBack](https://arxiv.org/html/2304.13013v2)은 INT8 학습의 안정성과 속도를 보되
가중치 기울기 계산에는 고정밀 경로를 남긴다. 모든 역전파를 INT8로 바꿔도 된다는 근거가
아니다. [Jetfire](https://arxiv.org/html/2403.12422v2)는 블록별 양자화와 비선형 연산을
포함한 INT8 흐름을 연구했다. pack·복원·메모리 이동까지 보아야 한다는 개념은 타당하지만
TinyLM의 삼진·공유·Muon·한국어 지능 효과를 직접 입증하지 않는다.
[PyTorch2.10 checkpoint 규약](https://docs.pytorch.org/docs/2.10/checkpoint.html)은 재계산과
상태/난수 보존의 관계를 설명한다. 저장 선택이 달라지면 실제 재계산 및 peak를 함께 측정한다.

## 5. 문헌·정·반·총괄 판단

문헌 에이전트는 정수 학습의 선행근거와 원형 provenance를 대조했다. 정 에이전트는 실제
그룹 스케일·smooth STE·공유 AMP 반올림을 보존하는 조건과 측정기를 제안했다. 반 에이전트는
원 GPU 미실행·비교 분모 혼합·근사 gradient·현재 소스 및 학습기 연결의 차이를 지적했다.
총괄은 원 ZIP·소스·원 JSON과 그 검토를 대조해 **기술 연구 가치는 있으나 즉시 기본
학습 경로로 채택할 증거는 없다**고 판단했다.

| 선택지 | 장점 | 손실·위험 | 현재 결정 |
|---|---|---|---|
|공식 CE 독립 접점부터 검증|본체 gradient 근사 없이 메모리·시간을 분리|저정밀 수치·작은 rank 비용 미확인|기존 B를 유지해 첫 CUDA 수행|
|v12 커널을 모델 없이 분해|구현차·native 근사차·pack 포함 비용을 구분|전체 본학습 품질은 알려주지 못함|Stage3aW/3bW로 준비·실행|
|v12 전체 학습 직결|실제 전체 경로의 효과를 볼 수 있음|anneal·공유·checkpoint·MTP·현재 감독 계약의 구현/수렴 비용|기술 결과 전에는 열지 않음|

## 6. 실제 진행과 판정 소유권

- 새 전체 스모크는 실제 종료0. [결과101§501](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)에 기록했다.
- 공식 Liger/CCE 첫 CUDA는 FP32 기본 수치 통과, BF16 projected gradient 음성으로
  실제 종료8. 부모·자료·update는0이며 [결과093§15](../../test_result/093_20260925_P102A-기능통과-T1-단일순서-속도관측.md)가 소유한다.
- v12 Stage3aW 진단기를 별도 구현했고 Stage3bW 실제 CUDA를 회수했다. 원형 import 전
  exact ZIP/runtime/source를 검산한다. 원식 구현 대조는 완료했지만 모델·기본 학습기는
  바꾸지 않았고 전체 본학습 가속·품질 채택은 없다. 실제 수치는 결과093§17이 소유한다.
- 독립 반 검토에서 worker leader 종료 뒤 compiler 그룹 정리 누락, producer 전방의
  autograd 비용 불일치와 pipeline 동기화 분모 차이를 발견했다. GPU 실행 전 좁은 수리와
  새 회귀를 완료했다. 총괄이 실제63개를1.519초에 통과했고, 종료하지 않는 자식 그룹의
  회수와 동일한 no-grad 전방·단일 동기 pipeline을 확인했다. 첫58 CPU 통과를 이 추가
  반례의 통과로 바꾸지 않는다.
- 원형 기능9개와 producer5개를 현재 환경의 CPU 인터프리터에서 각각5.817310초와
  3.051219초에 재현했다. producer exp 경고는 원 stderr에 보존했다. CPU BF16 저장과
  pack 일치는 실제 CUDA exp·대형 형상·본학습 수렴의 증거가 아니다.
- 첫 source87B8CDE9와 ZIP E1397A0A를 고정한 런처264는 내부870초·외부900초와 절대
  13시를 함께 검사한다. 별도 FP32 실제 부모3팔 런처265도 준비했다. 이 연결의 총괄
  CPU32개 통과는 공식 커널의 공유 head·checkpoint·Muon update 통과를 대신하지 않는다.

현재 실행 pin은 D21DC21C다. 전수 정적이 Triton의 지역 변수 `config`를 TMTConfig로
오인해3항목을 검출했으므로 `triton_config`로 이름만 구분했다. 원 코드·회귀·SH는
`handoff/audit/source_20261025_v12_driver_v1/`에 보존했고 공용 검사기는 그대로다.
재실행한 root CPU63개1.564초·종료0과 속성0건을 회수했다. ZIP·runtime7개·수치와
비용 비교식은 바뀌지 않았으며 실제 CUDA는 계속 별도다.

정확 IQ2 공식 전량은 새 날짜 worker와 원 엄격 수치계약으로 실제 종료0을 회수했다
(결과101§510). 그 뒤 v12도 실제 worker·감독·root0과 정리·원형 불변을 확인했다.
M8192 세 full 경로의 native앞/후보재사용 wall 비는0.8426/0.9386/0.5362배다.
큰 형상의 CPU oracle은8행·8열 표본이며 전체 대조라고 하지 않는다. native 대비
dX/dW의 근사차도 남아 품질 통과나 전체 master gradient의 복원은 아니다.

원형의1.74배 예측이나 본학습 가속·지능 향상으로 바꾸지 않는다.

다음 준비는 기존 구현을 다시 만드는 일이 아니다. 새 thin companion에서 원형의
native 전방+INT8 역전파와 같은 출력의 nativeSwiGLU+별도pack 대 fusedpack을 측정한다.
