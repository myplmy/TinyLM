# MNTP 가시성과 지도 위치의 독립 구현 계약

원장58의 기술 선결이다. 사용자는 미완료 구현·독립 CPU/GPU 연구를27일17시까지 허용했고, 정제 전 추가300M 학습과 본학습 전 작은 지능 판정은 금지했다. 자료 정제는 타세션 소유다. 총괄만 아래 코드를 구현하고 보조는 지정 텍스트를 읽어 메시지로 검토한다.

## 대안과 선택

| 안 | 실제 변화 | 장점 | 한계·비용 | 판단 |
|---|---|---|---|---|
| 목적함수 fixture만 추가 | 가상 logits에서 shift/분모 검산 | 코드 영향 작음 | 실제 TinyLM이 양방향·문서차단을 수행했는지 확인 못함 | 단독 완료로 쓰지 않음 |
| 기존 forward에 명시 mask 선택 인자 추가 | 기본None은 기존호출, 명시 인자에서만 문서별 가시성 전달 | CLA·checkpoint 실제경로와 누설검증 가능, 새파라미터 없음 | core2파일과 신규 helper/시험·전체스모크 필요 | **선택** |
| 모델 forward를 별도 복제/인스턴스 치환 | 연구용 별도 실행경로 | 최초 변경은 격리 가능 | KV/양자화/잔차 규약 중복과 이후 코드이탈 위험 | 제품기능으로 채택하지 않음 |

예: `[사과, 2, 더하기, 3, 정답, 5]`에서 `3`을 가리면 `더하기` 위치의 logits로 원래 `3`을 복구한다. causal은 오른쪽을 못 보고, MNTP는 가린 입력의 오른쪽 문맥을 볼 수 있다. 원래 `3`을 입력에 남겨놓은 채 양방향으로 읽게 하면 정답 노출이므로 검증 fixture에서는 선택 토큰을100%기존 예약ID로 치환한다. 별도 문서의 정답은 보이지 않아야 한다.

## 영향도

- 코드: `Transformer.forward`→`Layer.forward`→`Attention.forward`의 선택 인자만 연결한다. None이면 기존 positional호출 그대로다. 신규 parameter/buffer/state_dict schema와 cfg기본값은 없다. 다른 attention 구현과 생성기의 None경로를 보호한다.
- 기존 수동 추론 메뉴의 소스 고정 기록은 보존하고 새 `research_infer_manifest_mntp_v1.json`으로 연결한다. 같은 여섯 모델의 체크포인트·완료 근거·어휘 descriptor는 바꾸지 않고 현재소스의 None호환 회귀를 별도로 붙인다. 원형 manifest를 덮어쓰지 않으며 새연결이 답변품질 개선을 뜻하지 않는다.
- 데이터: 실제 dataset/원형/tokenizer를 바꾸지 않는다. doc ID는 explicit segment 계약이고 crop의EOS만 보고 실제 문서 계보를 추측하지 않는다. 가상fixture만 실행한다.
- 시험: 옛보관소의 default forward와 로짓/gradient/cache 호출 동률, 문서/패딩 차단, 오른쪽 가시성, shift/분모, checkpoint ON/OFF 및 mask변조 반례를 확인한다. 새core소스는 새전체스모크가 필요하다.
- 문서: P107 및 결과107을 새 실험군으로 관리한다. P013 완료 비용을 재실행하지 않으며 old source pin/프로필/스모크와 새소스의 유효성을 구분한다.
- 기술부채: 생산 trainer/정확재개·동적mask통계·교사KL은 연결하지 않는다. 이들을 완료로 세지 않고 원장58/59에 남긴다.
- 권한/소유권: 현재시간·GPU여유·소스봉인·직렬 실행을 요구한다. 원CP불변/정리·실패종류를 기록한다. 타세션정제 완료를 선언하지 않는다.
- 비교/증거: 기능fixture와실제비용이지 학습효과가 아니다. causal과MNTP는 target개수/가시성이달라 loss값을품질우열로비교하지 않는다. 별도mean으로혼합하고 원input token실행량을기록한다.

## 명시 mask 계약

- bool `[B,1,T,T]`, 같은 device, `True=allowed`, 각 query에1개이상 허용key. 모델 입장에서 clone/detach하고 checkpoint closure에 같은mask를 명시 capture한다. 호출자가 forward뒤 원mask를 바꿔도 backward가 바뀌면 안 된다.
- 최초 범위는 softmax_cla·실제순차R1·n_modes1·MTP/KD off·fresh full forward다. `past_kv`는 빈dict라도 거부하며 use_cache/last-only/aux/hidden/probs·attention출력재사용·반복을 거부한다. maskedKV를 causal추론에 재사용하지 않는다.
- doc블록 밖은 차단한다. valid query는 pad key를 보지 못한다. pad query는 자신의 diagonal만 허용하고 labels=-100으로 처리한다. 이는 공식 customsoftmax의 all-false padding row와 다른 SDPA 안전 이식이며, 효과를 동치라고 가정하지 않는다.

## 손상/목표/회계

- fulltokens/docIDs는 `[B,T+1]`이고 입력은 `[:-1]`, target은 `[1:]`다. causal/MNTP 모두 predictor와 target이같은실제doc구간일때만 지도한다. target의문서첫토큰을앞문서끝에서맞히도록지도하지 않는다.
- MNTP선택은 실제입력에있는 `1 <= j < T`에서만 한다. original selected token은 기존예약ID13으로치환하고 logit `j-1`에원target을연결한다. 최초/문서첫토큰/특수ID0..34/pad와 off-window마지막target은선택하지않는다. 실제chat32 JSON의13은예약토큰이며새행/새토크나이저가아니다.
- ID13이원입력에이미있으면거부한다. 100%치환기술fixture는공식80%mask/10%random/10%keep 재현이아니다. 기존특수ID는입력손상대상에서만보호하고softmax class에서제거하지않는다.
- causal CE mean과masked CE mean을별도로계산한뒤rho가중혼합한다. rho는유한한0..1이고양의가중치를갖는분기의target0은모델호출전에거부한다. `0 * NaN`으로덮지않는다.
- 같은전체accum을두목적에각각돌리면실행token은2배다. 최초기술비용은이를명시하고, 본학습은예컨대accum16중8causal/8masked처럼동일전체input예산을나누는별도설계가필요하다. 작은loss감소로기여를판정하지않는다.

## 선행 원문과 재현 범위

총괄이 [GPT-BERT v2](https://arxiv.org/html/2410.24159v2)의MNTP shift·혼합·mask일정을확인했다. 문헌보조는 저자고정commit `9fc15074d5e2620ea4ad0871d57454c0f35e3ff0`의[dataset](https://github.com/ltgoslo/gpt-bert/blob/9fc15074d5e2620ea4ad0871d57454c0f35e3ff0/pretraining/dataset.py)·[model_extra](https://github.com/ltgoslo/gpt-bert/blob/9fc15074d5e2620ea4ad0871d57454c0f35e3ff0/pretraining/model_extra.py)·train_multi_gpu를읽었다. 총괄웹의고정코드접근은실패해전체코드독립확보완료로쓰지않는다.

공식 span/adaptive score·30→15%일정·80/10/10치환·DDP rank혼합·별도z-loss·attention gate/layerweight 구조를 이번에 복제하지 않는다. 공개외부성과를TinyLM성과로이전하지않는다. 현재선택은MNTP가성립하기위한가시성과shift의기술이식이다.
