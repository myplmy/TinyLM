# 공식 IFEval 541문항의 평가전용 자료 입장

## 1. 왜

현재161의 기존원장 우선 지시로 원48의 독립 자료 선결을 진행한다. 원53/작업지시서§6.7은 공식 평가 문항 취득·평가전용 저장을 이미 허가했다. 패키지/라이브러리 설치·새환경·약관 대리동의와 구분한다. 기존 runtime은 `google/IFEval`, split `train`, zero-shot·1280 max generation과4개 공식 지표를 사용한다. 원48의3패키지 누락·길이 정합/모델 실행은 여전히 선결이다.

[Google 공식 HF 카드](https://huggingface.co/datasets/google/IFEval/blob/966cd89545d6b6acfd7638bc708b98261ca58e84/README.md)는541문항/Apache2.0과key/prompt/instruction_id_list/kwargs를 명시한다. 공개 API 읽기에서 현재main은966cd89545d6b6acfd7638bc708b98261ca58e84·private/gated false·파일3개다. 카드의 과거2024일자를 새2026자료라고 바꾸지 않는다. 현재 기존harness가참조하는공식HF 배포본을고정하고GitHub의다른수정판과섞지않는다.

## 2. 질문

현재official HF revision의원541행과각instruction/kwargs가고정local registry/signature에정적으로대응하는가? 실제prompt/individual instruction 분모와source origin을모델실행전에고정할수있는가?

## 3. 예측

공식자료의541행/고유key와local ID 대응을예상한다. 문항의모든의미/제약일관성이나checker 실제동작을보장하지않는다. source revision·schema가다르면조용히수리/제외하지않고입장을중단한다.

## 4. 단계

공개API revision/access/tree→같은revision README·원JSONL→Git blob/크기/SHA→stdlib 행/key/schema→local AST registry·truthy kwargs 인자대조→정본영수증과결과회수다. current utils는None뿐아니라`if v` truthiness로kwargs를거르므로falsey non-None도별도로기록하며공식행동을고치지않는다.

## 5. 판정

원541행을보존하고key가고유하며모든instruction ID/유효kwargs가선언source에대응해야한다. prompt중복/falsey값/미확인은숨기지않는다. 평가전용자료입장과공식scorer실행허가는구분한다.

## 6. 비용

각HTTP body1MiB/timeout20초·전체180초상한의작은공개자료만취득한다. 라이브러리/모델 다운로드·설치0, 실제generation/점수0이다. sandbox DNS실패는보존하고허가된동일HTTPS GET의host실행만자동검토받는다.

## 7. 실행

소유감사helper를101 Stage8if의원로그로회수한다. 데이터형/registry 검사에는기존Python stdlib만사용하고official checker 모듈을import하지않는다. 학습토큰0·표준300M/풀/품질통계자해당없음이다.

## 8. 한계

실제모델generation/공식4지표·1280출력과native1024정합·NLTK/언어감지·과거모델학습노출/누설은미확인이다. 공개`train`자료를우리TRAIN/SFT/KD로사용하지않는다. 원48/49의패키지/약관등사용자판단은보고시점까지유보한다.

## 9. 현재 이력

기존source5SHA/metadata와공식카드·commit/공개API revision을읽었다. sandbox DNS는실패했고별도host의동일공개API GET은성공했다. 아직자료파일저장/541행검증·official scorer/모델실행은NOT_RUN이다.
