## 2. 원장1: 위키/웹 정제 후보에서 학습자료까지

현재 알려진 마지막66후보의 결과는 구조검사65통과/1경계실패, HOLD7/KEEP33/REWRITE26의
제한 판독이다. 부모 packet은128개이므로 마지막66개만 넣어 strict importer를 통과할 수 없다.
앞62와 뒤66을 원형 보존 상태로 합치거나, 부모 packet SHA와 선택 ID를 명시한 새 봉인
부분 packet을 먼저 만든다. 임의로66개를 전체128개 완료라고 처리하지 않는다.

1. 정확 범위와 원형을 고정한다. 부모 packet·앞62/뒤66·후보·검수문·원 게시 영수증의
   SHA와 ID roster를 연결하고, 이 묶음과 전량 원천 작업(WIP8)을 구분한다.
2. 41163은 새 revision 후보의 source_end를 봉인 원문의 정확 끝 경계와 맞춘다. 원문을
   고치거나 fuzzy 정렬로 추정하지 않는다. 이 검사는 문구의 진실성 판정이 아니다.
3. 40020/40953/42368은 새 replacement의 접합부 LF와 앞뒤 문장 경계를 확인한다.
   목록의 REMOVE 또는 MOVE_TO_PROSE 선택과 근거·보류 사유도 그대로 보존한다.
4. 새 revision을 게시하고 기존 import_packet을 적용한다. coverage/중복/누락/정확 경계와
   shard SHA를 확인하되 게시 성공과 구조 통과는 아직 NOT_ADMITTED다. 옛 final은 덮지 않는다.
5. 총괄 GPT가 원문·정제문을 1차 판독하고 정확 후보 SHA별 채택/보류/제외와 근거를 남긴다.
   선수·지도자·통산기록·역할 목록은 의미를 살려 문장화하거나 불필요한 형식만 제거한다.
   판단 불가능한 대표 사례만 review_request의 사람용 원문/후보 쌍으로 사용자에게 요청한다.
6. 채택분만 원천 문서 계보에 따라 명시 분할하고 native NTP 토큰을 센다. 짧아진 문서·삭제
   분량·보류 분량·새 고유량을 구분한다. 학습 manifest와 shard를 재읽어 검산한 뒤 연결한다.

**완료조건:** 합의한 roster 전부에 처리결과가 있고 구조·의미·출처·권리 판단과 정확 SHA가
연결되며, 채택분의 분할·토큰·shard·학습 manifest가 닫혀야 한다. HOLD가 존재한다는 이유로
모든 자료를 폐기하지 않고, HOLD를 완료 train으로 세지도 않는다. 이 묶음 완료는 WIP8의
전체 위키/웹 전량 정제를 의미하지 않는다.

## 3. 원장2: 용어 보존 번역·재표현에서 학습자료까지

   정확 변형 SHA별 채택/보류/제외와 지도할 assistant 턴을 명시한다.

**완료조건:** 정확 roster별 모든 변형의 판단과 지도 턴이 연결되고, 채택분에서 root/group

승격하지 않으며, 기존 TRAIN에서 온 자료를 새 독립 최종 평가셋이라고 부르지 않는다.
