# GSQ 방식의 삼진 선택과 동일 CE·ALM 목표 연결

사용자109의17시까지 연구 위임과 미완 원장64에 따른 opt-in 연구 설계다.
기존 P093B의 MLP 출력 재구성을 재실행하지 않는다. 현재 소규모 실행의 목적은 계산·
기울기·실제 비용이며,본학습 전 지능/대화 성과를 채택하거나 공식 점수를 발표하지 않는다.

## 근거와 가설

[GSQ 원문](https://arxiv.org/html/2604.18556v1)의3.3은 mask/sign 두 이산 결정과 그룹
scale을 함께 학습하고,3.5는 표본잡음/갱신기·누적의 영향을 설명한다. 원 논문은 PTQ
재구성 연구다. 이 작업의 hard forward·정답 CE/외부 교사 ALM 목표는 새로운 응용이며
원 논문 재현이나 성공한 TinyLM 기법이라고 부르지 않는다.

현재 scripts/p093b_native_repair.py의 GSQProjection은 binary Gumbel/ST 코어를 이미
갖고 있다. 이를 재사용하고,새 제어만 scripts/p106b_gsq_objective.py에 둔다.
tinylm/train/alm.py의 target_nll/chunk_kl/normalized_loss도 그대로 재사용한다.
같은 teacher-forced 정답·정렬 chunk에 대해 CE 합/정답 token 수와 ALM 합/chunk 수를
별도 정규화한다. teacher 신호는 detach하고 입력을 이중 shift하지 않는다.

가설은 기존 나쁜 자유 생성을 복원하는 대신 외부 정답·분포가 삼진 선택/scale을 직접
지도할 수 있다는 것이다. 초기 자유 답변 실패는 착수 금지 조건이 아니다. 유효 gradient가
나온다는 사실과 본학습 품질 향상은 다르다.

## 세 안과 결정

| 안 | 장점 | 비용·제약 |
|---|---|---|
| 마지막 MLP만 GSQ | 가장 작은 비용으로 경로 확인 | embedding/head 제약과 전체 비용을 대표하지 못함 |
| 권장: 전체 TLinear와 공유 embedding/head의 명시 bridge | 같은 hard 초기 계산값·동일 CE/ALM의 STE 대조를 구성 가능 | 학습용 두 logit·scale/gradient/optimizer와 샘플 그래프가 커짐 |
| 기존 ALM+STE만 유지 | 구현 최소 | 원장64의 이산 선택 가설을 시험하지 못함 |

둘째 안의 CPU 계약부터 구현한다. 메모리가 부족하면 첫째 안의 비용을 별도 조건으로
측정할 수 있지만 전체 제약의 성공으로 바꾸지 않는다. fixed 삼진이므로 RCO 혼합 bit
배분을 기본 적용하지 않는다.

## 변경 권한·영향

| 파일·경로 | 예정 동작·권한 | 보호 |
|---|---|---|
| 새 GSQ objective/test/진단/런처 | 사용자109의 구현·CPU/GPU 연구 위임 | 기존 GSQ·ALM·모델 기본 소스 변경0 |
| P106B/결과101·원장/기준표/방법론/COMPASS | 설계·실측·음성/미실행 기록 | 다른 정제·루트09·Git 변경0 |
| 새 기술 evidence·고정된 완료 모델의 읽기 | 새 소형 감사,필요시 허가창의 비용 실행 | TinyDataset·원CP/원로그·기존 캐시 덮어쓰기0 |

코드는 기존 코어를 재사용하는 임시 bridge다. 모델의 refresh_quant와 embedding 계산
접근자만 인스턴스 문맥 안에서 교체하고 원형을 복원한다. 데이터/기본 CLI migration은
없다. 테스트는 공유 alias·동일 수치 초기값·hard 격자·gradient·head/층 checkpoint·
RNG·예외 원복·고유 optimizer 소유를 검사한다. 문서 연쇄가 필요하며 연구 bridge를
제품 trainer 전체 통합으로 보고하지 않는다. 부채는 compile/저장/재개·실제 본학습 연결이다.

GPU 권한은109에 한정되고,영어 교사 pilot/생산과 동시에 비용을 재지 않는다. source,
tokenizer,mask,초기화,손실과 hard 평가 경로를 고정한다. 같은 목적의 완료 PTQ/ALM
실행은 반복하지 않는다. 메모리/속도/품질/정적/실물 증거를 구분해 기록한다.

## 구현 계약과 기술 단계

1. 원래 삼진 STE를 대조로 유지한다. GSQ의 초기 code/scale은 같은 hard 계산 행렬에서
   만들며 공유 물리 가중치는 한 bank로 묶는다. embedding과 head는 같은 bank를 쓴다.
   scale은 직접 FP32 양수 변수로 두어 log/exp 왕복 오차를 피한다. signed-zero의 비트와
   수치 동일성도 구분하며 원본 master byte는 바꾸지 않는다.
2. 한 microbatch의 모든 공유 방문·층 재계산·head 청크에 같은 Gumbel realization을
   재사용한다. 이를 모델 실행 전에 한 번 만들고 checkpoint 중에는 다시 뽑지 않는다.
   다음 microbatch는 다른 seed를 쓴다. sampler가 전역 dropout RNG를 소비하지 않게 한다.
3. GSQ는 hard 삼진 forward와 soft surrogate gradient,eval은 결정적인 hard code다.
   온도·code 분포/변경·mask/sign/scale gradient와 collapse를 계측한다. ST의 실제
   argmax에 일반 finite-difference를 적용해 surrogate의 정답성을 주장하지 않는다.
4. CPU 시험 뒤 실제 완료 모델의 파라미터/저장 경로와 전체 메모리 하한을 검산한다.
   GPU가 비는 시점에만 동일 geometry의 기술 비용을 제한 실행한다. 메모리 부족이나
   실제 불안정은 보존하며 임의로 배치/원형을 바꿔 성공으로 만들지 않는다.

원 논문의 Lion과 기존 Muon/Adam 경로는 서로 다르다. 우선 공통 optimizer의 기술
조건을 명시하고,특정 optimizer가 필요하면 별도 팔로 분리한다. 무승인 설치는 하지 않는다.
기존 Muon에 새3차원 logits를 그대로 넣지 않고 변수 종류별 소유를 검산한다.

## 비용·완료 경계

두 FP32 logit만으로 N가중치에8N바이트가 필요하다. 원본 master·scale·gradient·
optimizer·hard/soft 그래프·activation은 별도다. 이는40MB 배포 목표와 다른 훈련 비용이다.
int8 code/scale 연구 상태를 저장했다고 실제5-trit packed kernel/전체40MB가 된 것도 아니다.
packed 저장·상주·KV·실제 추론 속도는 별도 후속이다.

CPU/전체 bank 비용이 통과해도 본학습 품질은 NOT_RUN이다. 정제 완료 전 추가300M,
새 설치/다운로드/새 환경·현재 교사와 동시 GPU 비용 실행은 하지 않는다. 예상 구현/CPU
계약1~2시간,실제 비용은 admission 뒤 측정하며 속도·품질 향상을 미리 보장하지 않는다.
