# 전용 정적검사의 입력 범위 누락과 정정

사용자104의 정제 외 연구와 기존 공용검사 경로 분리 승인 안에서, 공유 검사기를 바꾸지
않고 이 세션이 검증할 파일 목록을 명시한다. 원검사의 판정 규칙을 완화하거나 타 세션의
문서를 고쳐 전수 검사를 통과시키는 작업이 아니다.

## 실제 발견과 잘못된 주장

이전 전용 어댑터는 제어문자·링크·입력 해시 목록을 제한했지만 계획번호 검사의
`scan_refs()`와 진단 참조 대상, HF 검사 스크립트 목록은 제한하지 않았다. 따라서
PRE_FALCON_MMLU_STATIC_v1의 계획번호 검사가 타 세션 감사 문서의 본문을 읽고 없는
계획번호 참조를 출력했다. 총괄이 그 원문을 직접 열거나 연구자료로 사용한 것은 아니지만,
실행한 도구의 읽기도 세션의 접근이다. 기존의 접근0 표기는 이 검사 실행까지 포함하면
잘못됐다. 이전 70PASS 영수증도 실제 판정 수는 보존하되 읽기 범위 완전분리 증거로는 쓰지 않는다.

타 세션의 해당 문서·자료·코드·원장·캐시·프로세스는 변경하지 않는다. 검사 출력의 경로만
확인했으며 해당 본문을 다시 열지 않는다. 이 문제의 원인은 일부 입력 수집기를 바꾼 것을
전체 파일 접근 격리로 확대 해석하고, 나머지 검사의 수집 경로를 먼저 확인하지 않은 데 있다.

## 대안과 결정

| 안 | 방법 | 장점 | 한계 |
|---|---|---|---|
| A | 별도 어댑터에서 계획 참조·진단 대상·HF 스크립트를 소유 목록으로 제한 | 공유 코드와 타 세션을 바꾸지 않고 같은 검증 규칙을 적용 | 저장소 전역 정합이나 OS 격리는 보증하지 않음 |
| B | 공유 검사기에 새 범위 옵션과 전역 회귀를 추가 | 향후 여러 세션의 공통 기능이 될 수 있음 | 현재 연구 외 공유 인터페이스와 회귀 범위를 확대 |
| C | 계획번호·HF 검사를 미실행으로 남김 | 구현 추가가 작음 | 이쪽의 실제 계획 참조·HF 캐시 결함도 놓침 |

현재는 A를 적용한다. `scoped_plan_inventory_v1.py`는 소유 텍스트만 원 정규식으로 읽고,
공유 진단 registry의 metadata를 소유 대상만 남긴 메모리 뷰로 넘긴다. metadata 자체의 잘못된
행·위험한 경로·틀린 SHA는 원 판정기가 계속 거부한다. 제외한 대상 파일 본문은 읽지 않는다.
공식 계획 파일명과 계획목록의 전역 metadata 정합은 원 검사를 유지한다. HF도 원 검사
함수에 소유 스크립트만 제공한다. 금지 환경·데이터/캐시/모델 경로는 manifest에서 거부한다.

## 영향과 회귀

- 제품·모델·GPU source와 평가 내용에는 변경이 없다. 이 범위의 계획번호·HF·링크·
  제어문자 공유 판정기는 변경0이다. 별도 미완인 시각검사 수리는 다른 연구문서가 소유한다.
- 어댑터·수집기·독립 fixture 시험과 문서만 이쪽 감사 경로에 둔다. 타 세션 대상은 수정하지 않는다.
- CPU6개가 실제0이다. 소유 오류 검출, 외부 reader 미호출, 잘못된 registry/SHA·경로 거부를
  검사했다. 시험 통과를 전체 파일 접근의 OS 차단이나 모델 품질 증거로 해석하지 않는다.
- 새 정적 영수증에는 수집기 교체·원검사 SHA·소유 목록 SHA·제외 개수·범위 한계를 기록한다.
  명시 입력은 실행 전후 hash가 같아야 한다. 검사 중인 파일을 고치면 결과를 폐기하지 않고
  원 영수증을 보존한 새 버전으로 다시 실행한다.
- 사용자의 수정 없는 전체 정적검사는 범위 밖 문서를 포함할 수 있어 결과가 다를 수 있다.
  이쪽 판정 규칙을 낮춘 것이 아니라 검증 대상 목록이 다르기 때문이다. 전체 스모크의
  검사 구성은 바꾸지 않았으며 이번 어댑터 검증과 같은 증거라고 주장하지 않는다.

실제 정적 결과는 `handoff/audit/nov01_independent/PRE_FALCON_MMLU_STATIC_v2.json`의
생성·종료를 회수한 뒤 기록한다. 이 문서 작성 시 해당 새 전수 검사는 아직 미실행이다.

후속 실제 실행은0,70PASS/0ERROR/6NOT_RUN이었다.241개 명시 입력의 전후 hash가 같았고
계획 참조·HF 수집 자식도 각각0이었다. 진단 registry metadata12행 중 소유 대상1행을
검사하고 나머지11개 대상 본문은 열지 않았으며 HF 스크립트는 소유23개를 검사했다.
원판정기/기준 불변을 기록했고 이 검산 뒤 Falcon GPU 후속 대기 큐를 열었다. 최초 범위
누락을 소급 해소한 것으로 쓰지 않으며, 별도 전체 사용자 검사와 대상 범위가 다름을 유지한다.
