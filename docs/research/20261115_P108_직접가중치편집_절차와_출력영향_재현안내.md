# P108 직접 가중치 편집 — 실제 절차, 가중치 선택 이유, 출력 영향과 재현 안내

작성일: 2026-11-15. 이 문서는 이미 수행한 실험을 설명하는 해설이다. 새 실험계획이나 실행 지시가 아니며, 이번 작성 중에는 모델 로딩·추론·학습·새 편집 최적화를 수행하지 않았다.

같은 날 사용자 추가 질문에 따라 **§12에 후보 층 제한·8/11 쌍 선택·절반 잔차 배분의 타당성을 재분석**했다. 보존 인자에서 첫8층 편집의 목표 방향/직교 성분과 문항별 오차 변화를 후행 계산했으며, 새 모델을 실행한 결과가 아니다.

실험 수치와 판정의 정본은 [결과108](../../test_result/108_20261104190525_P108-방향수리는-실행됐지만-정답은-늘지-않았다.md)이다. 아래 수치는 해당 절·원보고서와 연결한 읽기용 설명이며 새로운 판정 기준을 정의하지 않는다. 다음 실험의 미완 목록은 [현재 작업원장 136A~H](../../handoff/WIP_20261022_작업원장-done.md)가 소유한다.

## 1. 실제로 한 일과 확인한 범위

**이미 학습을 마친 TinyLM을 열어 일부 행렬의 수치를 실제로 바꾸었고, 같은 질문에 대한 답변이 달라지는 것을 확인했다.** 최신 단일11층 편집에서는 수도 질문의 지시문 재출력이 `서울`로, 화학식 질문의 반복이 `H2O`로 바뀌었다. 그러나 다른 표현에서는 오답이 남았고 원래 되던 문자열 복사도 일부 손상됐다. 영어 공식 평가의 작은 개선은 있었지만 범용 한국어 대화 개선이나 정식 모델 채택으로 이어지지는 않았다.

이 문서에서 구분할 것은 다음 네 가지다.

| 구분 | 실제 수행 또는 확인한 내용 |
|---|---|
| 편집할 목표 결정 | 사람이 코드로 작성한 사실 질문·정답과 기존 모델의 실제 응답을 사용했다. 최신 실험은 교사가 자동 판정한 정답을 쓴 실험이 아니다. |
| 편집값 계산 | 보조 내부 벡터만 미분으로 최적화한 뒤, 그 효과를 가중치 행렬에 옮기는 선형대수 문제를 풀었다. 사람이 수백만 숫자를 손으로 하나씩 지정한 것은 아니다. |
| 실제 가중치 개입 | 등록된 MLP 행렬에 차분을 더하고 계산 캐시를 갱신했다. 출력 문자열만 바꾸거나 정답을 답변 뒤에 붙인 방식이 아니다. |

주된 설명 대상은 2026-11-13의 **공동쓰기·단일11층·분산8→11층**과 11월13~14일의 동결 편집 재현이다. 11월4~5일의 앞선 방향 수리·삼진 편집·Attention 개입도 별도 방식으로 구분한다. 서로 다른 실험의 좋은 수치만 합쳐 하나의 성공 모델로 취급하지 않는다.

최신 실험은 **ROME/MEMIT을 참고한 TinyLM용 변형**이다. [ROME 원문 §3.1](https://arxiv.org/html/2202.05262v5#S3.SS1)은 주어의 마지막 토큰에서 MLP의 key/value를 구하고 가중치에 쓰는 접근을 설명한다. [MEMIT 원문 §4.1~4.3](https://arxiv.org/html/2210.07229v2#S4)은 여러 연결을 공동으로 쓰고 여러 층에 잔차를 분배하는 접근을 설명한다. TinyLM에서는 질문 마지막 위치, 작은 자체 통계 표본, 명시적인 가중치 수정량 한도와 잔차 게이트 보정을 사용했다. 원논문의 모델·자료·인과 위치추적·전체 절차를 그대로 재현한 결과가 아니다.

## 3. 정확히 어느 가중치를 바꾸었나

### 3.1 모델과 행렬

최신 비교의 원본은 완료된 실수 모델 `new595-broad-f`다.

- 원본 파일: `runs/ckpt/m100s10_ko-en_broad4_p106b_native595_broad_v1_s1337_float.pt`.
- 원본 SHA-256: `2630B4C2862A41CB677AC9CAA89B0F2DD03234C4FD540FCCA6205AA847CF1C71`.
- 14층, hidden768, MLP 중간폭2048, chat32 토크나이저, 최대 문맥1024.
- 학습된 순차 방문1회인 R1, MLP 공유 없음, FP32 실수 계산 경로다.
- 최신 비교에서 MTP는 껐고, Attention·embedding·출력 head·정규화·gate/up 행렬은 직접 수정하지 않았다.

바꾼 대상은 `model.layers[11].mlp[0].down_proj.weight`, 또는 여기에 `model.layers[8].mlp[0].down_proj.weight`를 더한 두 행렬이다. 각각 형상은 **768×2048**이다. 상태 사전에서의 이름은 `layers.11.mlp.0.down_proj.weight`와 `layers.8.mlp.0.down_proj.weight`다.

**층 번호8·11은 코드의 0부터 시작하는 인덱스**다. 사람이 첫 층을1로 세면 각각9번째·12번째 층이다. 논문에 등장하는8층·11층과 위치가 같다는 뜻도 아니다.

### 3.2 이 행렬이 하는 일

일반 경로의 SwiGLU MLP는 다음과 같이 계산한다. 여기서 `u`는 정규화와 층별 변조를 거쳐 MLP에 들어가는 벡터다.

```text
k = SiLU(W_gate u) × (W_up u)       : 2048차원
v = W_down k                       : 768차원
층의 잔차 출력 = 이전 잔차 + gate × v
```

코드 정본은 [MLP와 Layer.forward](../../tinylm/model/modules.py)다. `k`와 `v`는 이 설명에서 사용하는 **MLP 내부 입력과 출력**이다. Attention의 K/V나 생성 이력을 저장하는 KV 캐시와 다른 대상이다.

```mermaid
flowchart LR
    Q[같은 질문과 토큰] --> U[정규화된 층 입력]
    U --> K[SwiGLU 출력 k]
    K --> W[편집한 down 행렬 W + 차분]
    W --> R[gate를 곱해 잔차에 더함]
    R --> H[뒤쪽 층과 출력 head]
    H --> L[다음 토큰 점수]
    L --> A[선택한 토큰과 후속 답변]
```

`down_proj`를 택한 이유는 이 위치에서 이미 만들어진2048차원 특징을768차원 잔차 방향으로 보내는 연결을 바꿀 수 있고, 입력 `k`를 고정하면 행렬 수정의 국소 효과를 직접 계산할 수 있기 때문이다. **‘서울을 저장한 단일 셀’을 발견해서 그 숫자 하나를 교체한 방식은 아니다.**

## 4. 왜 이 층과 가중치를 선택했나

### 4.1 전체 모델을 다 검색한 결과인가

그렇지 않다. 최신 value 실험은 후보 층을 **2·5·8·11**로 사전 고정했다. 각 후보에서 내부 출력에 보조 벡터를 잠시 더하면 목표 답을 만들 수 있는지 먼저 확인했다. 다른 층이나 모든 개별 가중치의 최적성을 증명한 탐색은 아니다.

기존48개 후보, 즉12개 사실·언어 묶음×4개 층의 **fit 질문24개만** 모으면 다음과 같다.

| 후보 층 인덱스 | 보조 value를 임시 주입했을 때 정답/24 | fit 마지막 NLL 합 |
|---|---:|---:|
| 2 | 0 | 60.503435 |
| 5 | 4 | 33.669559 |
| 8 | 19 | 5.216532 |
| 11 | 18 | 10.026331 |

먼저 공동 한 층 쓰기는 `fit 정답 최대 → NLL 최소 → 층 번호`의 규칙으로8층을 골랐다. 이후 다층 비교는 강한 두 후보8·11을 고정하고,11층 목표 표현에 도달하도록 **11층 단독**과 **8→11층 분산**을 비교했다. dev·기공개표현·보호 답의 성적을 보고 층을 다시 고른 것은 아니다. 이 표는 임시 활성 개입의 결과이며 실제 가중치 편집 성적과 다르다.

선정 규칙과 원점수는 [공동쓰기 계약](20261113_P108_단일모델_공동쓰기_계약.md), [다층 잔차 계약](20261113_P108_다층잔차분배_계약.md), [원 profile](../../test_result/evidence/p108_joint_write_v1_20261113/profile.json)에 있다.

**사전 고정했다는 사실만으로 그 범위가 충분하다고 정당화되지는 않는다.** 왜 정확히 이 네 지점이었는지,8/11의 개별 성적이 쌍의 적합성을 보장하는지에 대한 추가 검토는 §12.1~12.3을 참조한다.

### 4.2 이것이 오답 원인을 찾았다는 의미인가

아니다. ‘여기를 바꾸면 특정 답을 유도할 수 있다’는 편집 가능성이고, ‘이 위치의 결함 때문에 원래 오답이 발생했다’는 원인 규명과는 다르다. 높은 활성·큰 gradient·fit 개선만으로 원래 지식의 저장 위치나 반복의 유일한 원인을 확정할 수 없다.

이 모델은 **MLP를 공유하지 않고 R1로 추론해도** 원래 반복·질문 재출력을 보였다. 따라서 해당 현상을 공유 MLP나 추가 재귀 방문만으로 설명할 수는 없다. 반대로 이 실험이 다른 공유·재귀 모델의 구현 오류나 모든 반복 원인을 기각한 것도 아니다.

## 5. 실제 편집 절차 — 목표부터 한 모델의 행렬까지

### 5.1 원본과 비교 조건을 봉인한다

원본 체크포인트·실제 모델 상태·토크나이저·소스·질문·정답·생성 설정의 해시를 기록한다. 원본의 답을 먼저 보존하고, 같은 모델을 열었을 때 생성 토큰까지 같은지 확인한다. 원본과 다른 모델로 조용히 대체하지 않는다.

생성 조건은 `temperature=0`, `top_k=1`, 최대 새 토큰64, 캐시 사용, FP32 MATH, TF32 OFF, MTP OFF다. 답변 종료 토큰은 EOT의 ID4다. 최신 경로에는 별도의 반복 패널티가 적용되지 않았다. 따라서 편집 전후 차이를 샘플링 온도나 반복 패널티 변경으로 만든 것은 아니다.

### 5.2 교정용 질문과 평가용 질문을 나눈다

| dev | 12 | 다른 질문 표현에 대한 진단. 최신 공동/분산 편집의 층·계수 선택에 다시 사용하지 않았다. |
| 기공개표현, 데이터 필드명 `test` | 16 | 앞선 실험에서 이미 공개된 표현이다. 새 독립 holdout으로 부르지 않는다. |
| protect | 16 | 문자열 복사·요청된 정상 반복 등의 손상을 확인한다. |

한국어 수도·물의 화학식·지구의 공전 중심과, 한영 독일/이탈리아 수도·산소 분자·달의 공전 관계를 사용했다. 한영 표현을 포함한12개 묶음이지 독립 세계지식12개를 새로 발견했다는 뜻은 아니다. 입력과 provenance는 [동결 data.json](../../test_result/evidence/p108_distributed_residual_v1_20261113/data.json)에 있다. 공식 벤치마크 문항의 정답을 이 fit에 넣은 실험은 아니다. 다만 과거 전체 사전학습 자료의 전역 오염0까지 증명한 것은 아니다.

### 5.3 먼저 보조 value를 최적화한다

각 사실·언어 묶음과 후보 층에서 질문의 **마지막 prompt 토큰 위치**의 MLP 출력에768차원 보조 벡터를 한 번 더한다. 캐시 decode의 매 토큰에 정답 벡터를 계속 넣는 방식은 아니다. 주어의 마지막 토큰을 사용한 앞선 실험과도 위치가 다르다.

목표는 두 fit 질문에서 **정답 토큰들과 종료 토큰**의 평균 CE를 낮추면서, 같은 주어의 소개 질문2개에서 원래 다음 토큰 분포와 너무 멀어지지 않도록 하는 것이다. 보조 벡터의 크기에도 규제를 둔다.

```text
보조 벡터의 손실
 = 두 fit 질문의 정답+EOT CE 평균
 + 0.0625 × 두 소개 질문의 KL(원본 분포 || 개입 분포) 평균
 + 0.01 × 보조 벡터 norm² / 원래 MLP 출력 평균 norm²
```

실제 설정은 Adam40회·학습률0.01·상대좌표이며, 보조 벡터 norm은 원래 출력 평균 norm의0.75배 이하로 제한했다. **optimizer가 갱신한 것은 이 보조 벡터다.** 모델 본체에 optimizer step을 한 것은 아니지만, 정답을 사용한 미분·최적화까지 없었던 것은 아니다.

예를 들어 `kr_capital`의11층에서는 기록된 fit NLL이4.671132에서0.135197로 낮아졌고 임시 value 주입의 fit 정답은2/2였다. 전체48후보에서 보조 optimizer1,920회·정답 target 노출9,920토큰을 기록했다. 이 수치는 모델 본체의 본학습 토큰과 구분한다. [최적화 코드](../../scripts/diag_p108_value_edit.py), [마지막 위치 적응 코드](../../scripts/p108_query_value.py), [실제 value 보고서](../../test_result/evidence/p108_query_value_v1_20261113/actual/report.json)가 정본이다.

이후 공동쓰기·분산쓰기 단계는 이때 저장한 값을 **재사용**했다. 그 단계의 `value_optimizer_updates=0`을 전체 연구 과정에서 보조 최적화가 전혀 없었다는 뜻으로 해석하면 안 된다.

### 5.4 목표 효과를 어떤 입력에서 보존해야 할지 측정한다

fit 질문24개에서 대상 층의 MLP 입력 `k`를 모아2048×24의 행렬 `K`를 만든다. 별도 통계 질문128개 각각의 마지막8토큰에서1,024개 입력 벡터를 모아 다음 통계를 계산한다.

\[
C=\frac{1}{N}\sum_i k_i k_i^T
  +0.01\operatorname{mean}\left(\operatorname{diag}\left(\frac{1}{N}\sum_i k_i k_i^T\right)\right)I.
\]

`C`는 평균을 뺀 공분산이 아니라 **비중심 2차 모멘트에 작은 대각 안정화 항을 더한 것**이다. 이 표본에서 자주 쓰이는 입력 방향의 출력이 과도하게 변하지 않도록 비용을 부과하는 데 쓴다. 질문128개의 작은 표본이므로 모든 언어·지식을 보호하는 보증은 아니다. 정답이 없는 통계 질문과, 보조값 최적화의 정답 fit24는 역할이 다르다.

### 5.5 행렬 차분을 계산한다

입력 `K`에서 필요한 MLP 출력 변화량을 열로 모은 행렬을 `R`이라 하자. 최신 구현은 다음 문제를 CPU FP64로 푼다.

\[
\min_{\Delta W}\frac12\|\Delta W K-R\|_F^2
 +\frac12\operatorname{tr}(\Delta W C\Delta W^T),
 \qquad\|\Delta W\|_F\le b.
\]

첫 항은 원하는 교정을 만드는 비용, 두 번째 항은 통계 표본에 대한 변화 비용, 마지막 한도는 가중치를 과도하게 바꾸지 않기 위한 제약이다. 행렬 모든 원소를 함께 계산하는 식이지 숫자를 무작위로 고치는 방식이 아니다.

해는 아래 형태이며, norm 한도를 넘으면 `mu`를 이분 탐색한다. 이 `mu`는 가중치 norm 제약의 승수이며 앞의 통계 안정화 계수0.01과 다른 값이다.

\[
\Delta W=RK^T(KK^T+C+\mu I)^{-1}.
\]

실제 구현은 역행렬을 그대로 만드는 대신 대칭 행렬의 고유분해와96회 이분을 사용한다. 목표 norm을 처음부터 한도보다 약간 작게 잡고, FP32로 실제 저장된 변화량까지 한도 안인지 다시 확인한다. 해·독립 계산·잘못된 입력 검사는 [공동쓰기 코드](../../scripts/p108_joint_write.py)와 [회귀시험 코드](../../scripts/test_p108_joint_write.py)를 참조한다.

보존 인자는 `left`768×24, `right`2048×24이고 `delta = (left @ right.T).float()`다. 인자 표현의 랭크는 최대24지만, 차분의 거의 모든 원소가0이 아닐 수 있다. 또한 FP32 반올림 후에도 정확한 수학적 랭크가 항상24 이하라고 보장하지 않는다. **낮은 랭크는 소수 가중치만 수정한다는 뜻이 아니다.**

참고로 초기 단일 key 단계는 [rank_one](../../scripts/p108_value_edit.py)의 다음 특수형을 사용했다.

\[
\Delta W=v\frac{(C^{-1}k)^T}{k^TC^{-1}k}.
\]

이것을 최신24개 key의 공동 제약 해와 같은 실험으로 섞지 않는다.

### 5.6 단일11층과8→11층 분산의 차이

동결된11층 보조 value를 주입했을 때 **실제로 관측한 block11 전체 잔차 출력**을 최종 목표 `Z*`로 정했다. 해당 층의 현재 잔차 출력을 `Z`, 앞으로 수정할 층의 수를 `n`, 실제 잔차 게이트를 `g`라고 하면 down 행렬의 목표 변화는 다음으로 바꾼다.

\[
R=\frac{Z^*-Z}{n g}.
\]

TinyLM은 MLP 출력에 층별 gate를 곱해 더하므로 이 보정이 필요하다. 실제 게이트는8층0.21255465,11층0.32546148이었다. 부호를 보존하고0·비유한 gate는 거부한다.

- **단일11층**: 원본의11층 입력과 잔차를 사용해 한 번에 쓴다.
- **분산8→11층**:8층에 먼저 현재 잔차의 절반을 목표로 요청하고 실제 모델을 다시 순전파한다. 그 요청이 절반의 실제 변화를 달성했다는 뜻은 아니다. 바뀐11층 key와 남은 최종 잔차를 다시 측정한 뒤11층에 **재측정한 잔차 전체**를 목표로 요청한다. 원래 잔차의 절반을 두 층에 고정해서 각각 쓰는 구현이 아니다.

중간8층 수정이 뒤쪽11층으로 전달되는 효과에는 비선형 연산이 있으므로 단순 잔차 배분은 근사다. 실제로 첫8층 수정 후 최종 목표와의 잔차 norm은8,357.04에서8,626.48로 커졌다. ‘층을 나누었으니 같은 교정이 더 잘 전달된다’는 가정은 이 관측으로 지지되지 않았다. 최종 잔차는 단일3,259.78, 분산4,863.82였다. 이 잔차도 정답률이나 대화 점수는 아니다.

총 수정량은 두 방법에 같은 절대 한도를 주었다.

\[
b=0.05\min(\|W_8\|_F,\|W_{11}\|_F)=15.67932752.
\]

단일은 이 한도 하나, 분산은 각 층 `b/sqrt(2)` 이하이며 합성 Frobenius norm도 `b` 이하여야 했다. 단일의 실현 norm은15.67917073, 분산의 합성 norm도15.67917073이었다. **5%는 선택 행렬 norm에 대한 보호 예산이며, 전체 모델 파라미터의5%나 입증된 최적 편집 강도가 아니다.**

자세한 절차와 실제 gate·키 재측정은 [분산 helper](../../scripts/p108_distributed_residual.py), [실제 driver](../../scripts/diag_p108_distributed_residual.py), [원보고서](../../test_result/evidence/p108_distributed_residual_v1_20261113/actual/report.json)에 있다.

### 5.7 실제 가중치에 쓰고 같은 모델인지 확인한다

[편집 문맥 코드](../../scripts/p108_wsp_attention.py)는 다음을 수행했다.

1. 모델이 평가 모드·동결된 실수 경로·R1·비공유 구조인지 확인한다.
2. 원본 행렬과 계산 캐시 객체를 보관한다. 여러 층이면 첫 쓰기 전에 모든 입력을 검증한다.
3. 등록된 `module.weight`에 차분을 더하고 `refresh_quant(1.)`로 실제 계산 경로를 갱신한다.
4. 요청 밖 값이 바뀌었는지, 실제 계산 행렬의 변화량이 요청한 차분과 맞는지, 설치 후 가중치 SHA가 맞는지 확인한다.
5. 해당 편집 행렬을 **질문마다 바꾸지 않고**68문항 모두에 사용한다.
6. 정상 종료·예외 모두 원본 가중치와 원래 캐시 객체를 복원한다. 전체 core SHA와 원본 생성 토큰도 재확인한다.

이 최신 경로는 FP32 실수 가중치 편집이다. 앞선 삼진 실험은 잠재 가중치 일부만 바꿔도 재양자화 그룹 스케일 때문에 선택 밖 약131만 계산값이 변했다. 그 결과를 실수 편집의 작은 국소 수정과 동일하게 해석하거나, 최신 성공 사례가 그대로 삼진 배포에서도 작동한다고 주장하지 않는다.

### 5.8 목표 방향과 단순 교란을 대조한다

원본, 목표에 맞춘 편집, 그리고 norm·인자 스펙트럼을 맞춘 무작위 방향3개를 비교했다. seed는10007·10009·10037이며 분산 대조의 층별 난수는 `기본 seed + 층 인덱스`다. 해당 인자와 패킷을 dev·기공개표현·보호 답 생성 전에 봉인했다.

같은 norm의 무작위 교란도 비슷하게 좋아진다면 ‘목표에 맞춘 교정 방향이 중요했다’고 말하기 어렵다. 최신 단일11층은 fit6/24, 분산은2/24였고 무작위3개는 각각0/24였다. 제한된 fit에서는 목표 방향의 이점이 관측됐다. 이것만으로 새 표현이나 모든 사실에 대한 효과를 입증한 것은 아니다.

## 7. 모델 출력에는 직접 어떻게 영향을 주었나

### 7.1 계산 경로에서 확인할 수 있는 직접 효과

하나의 down 행렬만 바꾸고 그 입력 `k`가 같다면 실수 산술에서 국소 출력 변화는 다음이다.

\[
v'-v=\Delta W k,\qquad \Delta h=g\,\Delta W k.
\]

이 잔차 변화가 뒤쪽 층·정규화·출력 head를 거쳐 다음 토큰 점수를 바꾼다. greedy는 가장 높은 점수의 토큰을 고르므로 첫 토큰이 바뀔 수 있다. 첫 토큰 이후에는 모델이 받는 생성 이력도 달라져 후속 출력이 더 크게 갈라질 수 있다.

전역 편집은 fit 질문의 마지막 토큰만 고치는 조작이 아니다. 같은 행렬이 **모든 질문의 모든 해당 위치**에서 쓰이므로 복사·형식·다른 사실도 영향을 받을 수 있다. 분산 편집에서는8층 수정으로11층 입력까지 변하므로 두 독립 변화의 단순 합으로 전체 출력을 설명할 수 없다.

실제 FP32 연산은 반올림 순서도 중요했다. 공동쓰기 Stage19에서는 `편집 후 출력 - 원출력`을 다른 계산 순서의 이상적 차분과 비교한 검사에서 오류가 났다. Stage20은 같은 전체 입력 shape·stride의 `F.linear`를 편집 전후 각각 재생해 원모듈과 EXACT인지 확인했다. 기존 혼합 차분 기준을 사후에 늘려 통과시키지 않았고, 그 기준의272건 중254불일치도 보존했다. 이 정밀도 복구는 기술 검증이며 품질 개선으로 세지 않는다. [정밀도 계약](20261113_P108_공동쓰기_정밀도_복구계약.md), 결과108 §28~29를 참조한다.

끝나면 RAM 가중치를 원복하고 receipt 디렉터리에 `replay_receipt.json`과 생성 재현 기록을 남긴다. 완료 신호는 receipt의 `status: FROZEN_EDIT_REPLAY_VERIFIED_AND_ORIGINAL_RESTORED`, `sources_unchanged: true`, `model_proof.original_core_restored: true`다. 단일 CLI의 과거 실제1회는68문항+2질문·원복까지20.078초였지만 기계 부하·환경에 따른 실행시간 보장은 아니다. 원본/패킷은 덮어쓰지 않고 전체 편집 체크포인트도 새로 저장하지 않는다.

이는 번호 메뉴를 가진 범용 대화 유틸리티가 아니라, 명시적인 세 모델명 중 하나를 골라 동결 편집을 검증하며 여는 도구다. 사용자가 대화마다 사실별 편집 인자를 손으로 바꿀 필요는 없다.

### 9.4 반드시 멈춰야 하는 조건과 실패 시 전달할 자료

- 원본·토크나이저·코드·패킷·차분·설치 행렬 중 하나라도 해시가 다르거나 필수 manifest가 없으면 멈춘다.
- 다른 GPU 프로세스가 있어 입장 검사가 거부되거나, CUDA·문맥 길이·필수 라이브러리 오류가 나면 멈춘다. 다른 작업을 종료하거나 자동으로 모델/정밀도를 바꾸지 않는다.
- 생성68문항의 일치나 원복 검사가 실패하면 재현 실패로 남긴다. 답이 대략 비슷하다고 통과시키지 않는다.
- 실패 원문, 실행한 명령, 환경, 새 receipt 디렉터리를 보존한다. 원답·패킷을 편집하거나 오류 파일을 삭제하지 않는다.
- GPT에게 다시 전달할 때는 명령·오류 전문·receipt 경로와 사람이 읽을 질문/실제 답을 함께 준다. 후속은 원본/코드/환경 변화인지 수치·생성 차이인지부터 분리한다.

### 9.5 완전히 새로운 교정 목표를 처음부터 수행하려면

수학과 기존 코드로 수행할 수 있지만, 현재 보존 실험 driver를 그대로 재실행하는 것은 맞지 않는다. 옛 driver에는 2026-11-13의 권한 종료시각, 당시 소스·입력 해시, 이미 존재하는 출력 경로를 거부하는 계약이 들어 있다. 날짜·해시 검사를 끄거나 과거 디렉터리를 비워 재사용하지 않는다.

사람이 따라 할 새 편집의 순서는 다음과 같다.

1. 원본과 수정할 사실·정답·근거를 고정하고 기존 결과와 중복되지 않는 가설을 정한다.
2. fit·다른 표현·비편집 사실·복사/정상 반복·일반 언어 보존 평가를 나누고, 동일 출처 변형을 최종 독립 평가에 섞지 않는다.
3. 후보 층과 선택 규칙, 보조 value의 위치/손실, 원형 통계, 수정량 예산을 실행 전에 확정한다.
4. 기존 CPU 회귀와 입장 검사를 통과한 새 namespace에서 value를 만들고, 실제 한 모델에 공동쓰기 또는 순차 재계산으로 적용한다.
5. 원본·무작위 방향·편집모델을 같은 생성 조건으로 비교하고 첫답 전체·문장 관련성·보호 손상·공식 평가를 함께 읽는다.
6. 원본과 편집 인자·코드·환경·원답을 보존하고, 깨끗한 복원에서 SHA와 생성 토큰까지 다시 확인한다.

현재 §9.2~9.3은 **동결된 최신 모델의 복원 안내**다. §9.5 전체를 임의 사실에 대해 한 명령으로 실행하는 범용 편집 마법사가 이미 완성됐다는 뜻은 아니다. 이번 문서 작성에서 새 driver·런처·최적화는 만들지 않았다.

## 10. 현재 방법을 적용할 때의 한계와 다음 연구 연결

- 사실 한두 개를 맞히게 만드는 것과 새로운 표현·관계·일상 대화를 이해하는 것은 다르다. 지금의 편집은 좁은 fit에 더 강했다.
- 일반성을 얻으려고 더 많은 층·더 큰 norm을 쓰면 기존 복사·정상 반복·다른 사실을 더 손상시킬 수 있다. 기존5%는 한계의 증명이 아니지만, 한도를 늘리면 나아질 것이라는 증거도 아니다.
- 공분산 표본128개와 두 소개 질문의 KL은 제한된 보존 장치다. 전체 지식·언어 능력의 보존을 보장하지 않는다.
- 보조 활성 주입은 질문의 한 위치에만 작동하지만 가중치 편집은 다른 위치에도 작동한다. 임시 주입의 성공률이 그대로 행렬 편집의 성공률이 될 수 없다.
- 현재 편집 문맥은 종료 시 원복하는 **평가용**이다. validation 때 편집하고 다음 학습 배치에 유지하는 기능이 이미 검증된 것은 아니다. 학습 누적 경계, optimizer 상태, 실제 삼진 캐시, 교정 유지와 정확 재개를 처리해야 한다.
- 다음 학습에서는 교사가 만든 단일턴 정답·오답 교정 멀티턴을 사용하는 경로와, 실제 가중치를 편집하고 이어 학습하는 경로를 구분해야 한다. 두 방식의 비교와 강도/횟수/유지·추론 설정 대조는 원장136B~G에 대기 상태로 기록돼 있다.
- 새 본학습의 지능 성과를 짧은 예행 학습으로 대신 판정하지 않는다. 이 문서의 사후 편집 비교도 새 본학습의 성과로 보고하지 않는다.

## 12. 추가 재검토 — 후보 층과 균등 분산은 충분히 정당화됐나

### 12.1 왜14개 층을 모두 보지 않았나

**총괄이 최초 진단 범위를 중간 블록의 네 지점으로 줄여 사전 고정했기 때문이다. 전체 층을 시험할 수 없다는 구조적 이유를 확인하고 제외한 것이 아니다.** [최초 Stage12 계획](../../test_plan/P108_직접가중치-방향수리와-학습개입.md)의 §14.3과 [봉인된 최초 profile](../../test_result/evidence/p108_value_edit_v1_20261113/profile.json)에 이미 `layers=[2,5,8,11]`이 있다. 이후 상대좌표·마지막 질문 위치·공동쓰기에서도 저장한 후보 값을 재사용하며 이 범위를 이어받았다.

[실제 원형 manifest](../../handoff/audit/oct27_independent/research_infer_manifest_mntp_v1.json)의 `new595-broad-f`는 `n_prelude=2`, `n_middle=10`, `n_coda=2`다.

| 구조상 구간 | 실제 층 인덱스 | 이번 value 후보 |
|---|---|---|
| 앞쪽2층 | 0·1 | 미시험 |
| 중간10층 | 2~11 | 2·5·8·11만 시험;3·4·6·7·9·10은 미시험 |
| 뒤쪽2층 | 12·13 | 미시험 |

즉 중간 구간의 양 끝을 포함해3층 간격으로 뽑은 **성긴 표본**이다. 원논문의 중간 MLP 편집 가설을 참고한 초기 진단 범위로는 이해할 수 있지만, TinyLM에서 이 네 층이 나머지보다 중요하다거나 이 간격이 충분하다는 인과·품질 실측은 없었다. 정확히 간격3을 택해야 하는 정량 근거나 전체층 탐색을 생략해도 된다는 검증도 당시 기록에서 찾지 못했다.

본체가 비공유 R1이고 [출력 행렬 접근자](../../scripts/p108_wsp_attention.py)의 `outputs()`는 모든 층을 열거하므로, 구조만을 이유로 나머지10개 MLP를 후보에서 배제할 근거는 없다. 그렇다고 미시험 층의 미분·편집이 검증됐다는 뜻은 아니다. 앞선 WSP의 전체168 Attention head 개입은 다른 모듈·다른 조작이며 이번 value 편집의 전층 검색을 대신하지 않는다.

비용 절감은 이런 범위 제한의 실용적 이유가 될 수 있다. 현재12개 사실·언어 묶음에40회 보조 갱신을 하면4층은48후보·1,920회이고, 같은 설정을14층에 적용하면168후보·6,720회다. **보조 갱신 횟수는3.5배**지만 층별 역전파 비용·다른 평가/보존 비용이 달라 전체 wall이 정확히3.5배라는 뜻은 아니다. 실제14층 탐색의 시간·VRAM을 측정하지 않았으므로 ‘마감 내 불가능했다’는 사유도 실측으로 입증되지 않았다.

따라서 수정한 판단은 다음이다. **초기 가능성 진단을 위한 범위 제한은 허용할 수 있으나, 그 결과로 모델 전체의 편집 가능성이나 최적 층을 판정하기에는 탐색이 부족했다.** 당시 연구 권한의 부족이나 모델 구조의 금지 때문이었다고 설명하지 않는다. 사용자의 ‘전체 모델’이 모든 개별 원소의 수정 조합까지 뜻한다면 그것은 별도의 큰 연속 최적화 문제다. 그러나 우선14개 층을 같은 기준으로 확인하는 것조차 하지 않았다는 현재의 누락은 그 어려움과 구분해야 한다.

### 12.2 왜8·11층이었으며, 그 선택에서 빠진 것은 무엇인가

선택의 직접 근거는 기존 fit24에 대한 **임시 value 주입** 성적이8층19/24,11층18/24로 네 후보 중 가장 높았다는 것이다. 두 층을 실행 순서대로 배치하고 이미 저장한11층 목표를 최종 잔차 기준으로 사용했다. 값 재최적화 없이 다층 잔차 분배를 시험할 수 있다는 재사용상 이점도 있었다. 이는 [당시 분산 계약](20261113_P108_다층잔차분배_계약.md)에 적혀 있다.

하지만 그 근거로 확인한 것은 개별 층의 제한된 **개입 가능성**이다. 다음은 확인하지 않았다.

- 두 층을 함께 쓸 때 변화가 같은 방향으로 전달되는지, 서로 상쇄하거나 다른 기능을 손상시키는지.
- 같은 총 수정량에서 각 층의 실제 가중치 쓰기가 목표 응답을 얼마나 실현할 수 있는지.
- 각 층의 key·게이트·통계가 다를 때 어떤 예산 배분이 좋은지.
- 다른 층 쌍이나 다른 최종 목표층이 더 좋은지.

각 층의19/24·18/24는 사실별로 다른 보조 벡터를 주입한 합계다. 하나의 공통 가중치 수정으로 모든 사실을 동시에 쓸 수 있다는 증거가 아니다. **개별 상위 두 층을 골랐다는 것과 좋은 층 쌍을 골랐다는 것은 다르다.**

기존 네 후보에서도 두 층의 조합은6개다. 최종 목표층을11로 고정해도 `(2,11)`, `(5,11)`, `(8,11)`의 세 조합이 있는데 마지막 한 조합만 시험했다. 모델의 실제 마지막 층은13이고,11은 이번 편집 범위의 끝으로 정한 층이다. 12·13층까지 최종 목표를 옮기는 대조도 하지 않았다.

이 선택은 원형 결과를 재사용하는 **탐색적 가설**로는 설명되지만 최선의 쌍이나 모델 전체의 주된 지식 저장 경로를 찾은 것으로 정당화할 수 없다. 이전8층 공동쓰기와 최신11층 단독 성적을 비교할 때도 목표 벡터·절대 예산 등이 달라 순수한 층 효과로 단정하지 않는다.

### 12.3 ‘절반’은 정확히 무엇의 절반인가

원래 목표 잔차를 `E0=Z*−Z0`,8층 게이트를 `g8`, 첫 편집 후 재측정한 잔차를 `E1=Z*−Z1`이라고 하자. 실제 코드는 다음을 요청했다.

\[
R_8=\frac{E_0}{2g_8},\qquad
R_{11}=\frac{E_1}{g_{11}}.
\]

첫 단계의 `1/2`는 **최종 block11 잔차를 두 번의 쓰기에 나누겠다는 목표 배율**이다. 가중치의 절반을 수정하거나, 정답 토큰 확률을 절반 올리거나, 실제 출력이 절반 가까워졌다는 뜻이 아니다. 두 번째 단계는 남은 선택 층이 하나이므로 재측정한 `E1` 전체를 목표로 한다. 첫 단계가 기대대로 작동하지 않았다면 `E1`은 `E0/2`와 다르고, 원래보다 클 수도 있다.

목표 벡터의 균등 배분과 물리적 수정량의 균등 배분도 다른 결정이다.

| 설계 요소 | 당시 선택 | 정당화할 수 있는 범위 |
|---|---|---|
| 첫 목표 잔차 배율 | `E0/2` | 여러 층에 일을 분담하는 간단한 휴리스틱이다. 최적 배율이라고 증명하지 않았다. |
| 게이트 보정 | `1/g8`, `1/g11` | 실제 잔차식의 계수를 반영하는 데 필요하다. 이것만으로 층간 전달이 보정되지는 않는다. |
| 각 층 수정량 한도 | `b/sqrt(2)` | 두 행렬을 이은 파라미터 벡터의 합성 norm이 `b`를 넘지 않게 하는 수학적으로 타당한 예산 분할이다. |
| 예산 분할의 최적성 | 균등한 제곱 norm 예산 | 최적성은 미검증이다. 한 층에 적게, 다른 층에 많이 주는 해를 제외하는 추가 제약이다. |

절반 배분에 전혀 근거가 없는 것은 아니다. 두 층의 효과가 같은 좌표에서 선형으로 더해지고, 같은 크기의 최종 기여를 만드는 비용도 같으며, 어느 쪽도 별도 한도에 막히지 않는 대칭적인 이상 문제를 생각할 수 있다. 이때 `u8+u11=E0`를 만족하면서 `norm(u8)^2+norm(u11)^2`를 최소화하는 해는 각각 `E0/2`다. 하지만 여기서 `u`는 **실현한 최종층 기여**다. TinyLM의 서로 다른 gate·입력 key·통계·층간 전달에서 같은 기여의 비용이 같다는 검증은 없으므로, 이 이상 문제의 해를 실제 가중치 배분의 최적해로 옮길 수 없다.

예를 들어 같은 입력·같은 전달이라는 가정을 두어도 작은8층 게이트 때문에 같은 잔차 기여를 내려면 더 큰 down 응답이 필요하다. 실제 `g11/g8=1.53119`다. 다만 입력의 크기·방향과 이후 연산도 다르므로 이 비율이 곧 실제 가중치 비용이나 실패 원인의 배수는 아니다.

### 12.4 MEMIT의 균등 잔차 개념을 가져온 것이 충분했나

[MEMIT 원문 §4.3, 식(20)과 Algorithm1](https://arxiv.org/html/2210.07229v2#S4.SS3)은 남은 최상위 잔차를 나누고 앞 층 변경 후 활성과 key를 다시 계산한다. 그 아이디어를 차용한 것 자체에는 근거가 있다. 하지만 원문은 해당 모델에서 조사한 편집 경로·주어 위치·표현을 사용한다. TinyLM의 질문 마지막 위치와 비연속8/11 쌍에서 균등 배분이 작동한다는 보증은 아니다.

원논문의 식(20)은 `L−l+1`을 분모로 쓰고, TinyLM helper의 `remaining`은 **선택 목록에 남은 층 수**로2→1을 넣는다. 연속 편집 구간에서는 대응하지만8과11처럼 중간 층을 건너뛴 경우 같은 산술이라고 볼 수는 없다. 이 차이를 곧바로 구현 오류라고 단정하지도 않는다. 선택된 두 층에 분담시키려는 별도 설계이며, 그 이식이 타당한지는 새 구조의 실제 전달로 확인해야 했다. 이번 공개 원문 대조만으로 원저자 최신 코드의 비연속 층 처리를 확인했다고 주장하지 않는다.

핵심 문제는8층의 **국소 출력 변화**와11층의 **최종 목표 변화**를 같은 좌표의 변화처럼 취급한 점이다. 질문의 마지막 위치를 `T`라 하면 실제 전달을 1차 근사한 식에는 다음과 같은 항이 필요하다.

\[
\delta z_{11,T}\simeq
\sum_{t\le T}J_{T,t}^{8\to11}\,g_8\Delta W_8 k_{8,t}.
\]

여기서 `J`는8층의 각 위치 변화가 이후 Attention·정규화·MLP를 거쳐11층 마지막 위치로 전달되는 민감도다. 현재의 단순 목표식은 사실상 마지막 위치의 전달을 항등에 가깝게 보고, 다른 prompt 위치 변화의 기여는 목표 설계에 넣지 않은 근사다. **이 항등 근사를 TinyLM의 실제 입력에서 검증하지 않았다.** 잔차 연결이 있다고 해서 중간의 비선형 변환과 토큰 간 전달이 사라지는 것은 아니다.

마지막11층 자체에서는 down 출력이 게이트를 거쳐 block11에 더해지므로 국소 응답식의 근거가 더 직접적이다. 하지만8층에서는 중간 연산이 더 있고, 전역 가중치 수정은 마지막 위치 외의 prompt 토큰도 바꾼다. 따라서 임시 한 위치 oracle의 효과와 실제 전역 행렬 수정의 효과가 다를 수 있다.

**첫 편집 후11층 key·잔차를 다시 구한 것은 올바른 보완**이다. 그러나 그것이 첫 단계의 전달 방향이나 `1/2` 배율을 최적화해 주지는 않는다. 고유분해·KKT·norm 검사가 통과했다는 사실도 정해 둔 국소 대리문제를 정확히 풀었다는 뜻이지, 그 대리문제가 최종 답변에 적절했다는 증거는 아니다.

### 12.5 보존된 인자로 다시 계산한 첫8층의 실제 영향

이번 추가 분석은 모델을 다시 열지 않고 **동결 패킷의 `left`와 실제 게이트 값**만 사용했다. [첫8층 패킷](../../test_result/evidence/p108_distributed_residual_v1_20261113/actual/distributed8_11_layer8_packet.json)은 `left8=E0/(2g8)`, [그 뒤11층 패킷](../../test_result/evidence/p108_distributed_residual_v1_20261113/actual/distributed8_11_layer11_packet.json)은 `left11=E1/g11`을 보존한다. 따라서 두 잔차와 첫 편집의 실제 최종층 이동을 복원할 수 있다.

\[
E_0=2g_8\,left_8,\qquad E_1=g_{11}\,left_{11},
\qquad D=E_0-E_1=Z_1-Z_0.
\]

두 패킷은 같은24개 fit 열 순서를 사용한다. 복원한 원잔차를 별도 단일11층 패킷에서도 계산해 비교했으며 최대 절대차는 약`2.84e-14`였다. 재구성한 **편집 후** 잔차 norm은 원보고서의 `after_first_layer_final_block_residual`과 `1e-7` 이내에서 일치했다. 새 가중치 편집이나 새 생성 결과가 아니라 기존 실측을 분해한 후행 계산이다.

| 첫8층 편집에 대한 지표 | 계산값 | 의미 |
|---|---:|---|
| 원래 목표 잔차 `norm(E0)` | 8,357.035704 | 편집 전24개 fit의 block11 목표 오차를 합친 norm |
| 편집 후 잔차 `norm(E1)` | 8,626.477919 | 오차가 약3.2241% 증가했다. |
| 실제 이동 `norm(D)` | 6,404.109049 | 변화는 있었지만 크기만으로 개선 여부를 알 수 없다. |
| 목표 방향 투영 `a=<E0,D>/norm(E0)^2` | 0.260857 | 원목표 방향으로는 약26.09%만큼 이동했다. 정답률이 아니다. |
| 목표와 직교하는 이동 `norm(D−aE0)/norm(E0)` | 0.720548 | 목표와 다른 방향의 변화가 원잔차 norm의 약72.05%였다. |
| 실제 이동과 목표 방향 cosine | 0.340405 | 전체 이동이 목표 방향과 충분히 정렬되지 않았다. |
| 문항별 목표 잔차 감소/증가 | 7/24 감소,17/24 증가 | 모든 질문이 나빠졌다는 뜻은 아니지만 다수에서 오차가 늘었다. |

여기서 중요한 정정은 **‘첫 수정이 목표와 완전히 반대 방향이었다’가 아니라는 것**이다.24개 모두 목표 방향 투영은 양수였다. 그럼에도 목표와 다른 방향의 성분이 커서 전체 잔차가 증가했다. norm 증가만 보고 방향이 반대였다고 단정하지 않는다.

기하적으로는 `D=aE0+D직교`이므로 다음 식으로 확인할 수 있다.

\[
\frac{\|E_1\|^2}{\|E_0\|^2}
=(1-a)^2+\frac{\|D_{\perp}\|^2}{\|E_0\|^2}
\approx(1-0.260857)^2+0.720548^2.
\]

이 값을 제곱근 하면 약1.03224다. 이상적으로 첫 단계가 최종 목표의 절반만 같은 방향으로 달성했다면 잔차 norm은 약4,178.52가 됐어야 한다. 실제로는8,626.48이었으므로 **절반을 요청한 것을 절반을 실현한 것으로 설명할 수 없다.** 이 수치는24개 fit 내부 표현의 오차이며 벤치마크·정답 수·일상 대화의 변화율과 다르다.

직교 성분이라는 이유만으로 그 변화가 모든 능력에 해롭거나 무의미하다고 판정하지도 않는다. 여기서 확인한 것은 선택한 `Z*`에 가까워진다는 대리 목표의 달성 정도다. 최초 층의 국소 쓰기 오차와 층간 전달에서 각각 얼마가 발생했는지까지는 보존 자료만으로 분해하지 못했다.

가중치 예산의 영향도 있었다. 동일한 공분산 보존 대리문제에서 **명시 norm 한도를 제거한 해**와 실제 한도는 다음과 같다.

| 쓰기 단계 | norm 제약이 없을 때 대리해의 norm | 코드가 정한 norm 목표 |
|---|---:|---:|
| 단일11층 | 65.565801 | 15.679171 |
| 분산 첫8층 | 229.809316 | 11.086848 |
| 분산 다음11층 | 75.362612 | 11.086848 |

모든 단계에서 한도가 작동했고 첫8층의 요구와 예산 차이가 특히 컸다. 다만 `한도/무제약 norm`이 실제 사용한 균일 축소율은 아니다. 현재 KKT 해는 고유방향마다 다르게 줄인다. 또한 첫 층의 큰 비표적 변화가 작은 norm 한도 하나 때문이라고 입증한 것은 아니다. 전달 근사·key·통계·목표·예산을 아직 분리하지 못했다.

이 후행 계산을 사람이 확인하려면 아래 CPU 표준 라이브러리 코드로 재집계할 수 있다. 모델·torch·GPU를 불러오거나 원파일을 쓰지 않는다.

```python
from pathlib import Path
import hashlib
import json
import math

base = Path('/home/uranus/tinyLM/test_result/evidence/p108_distributed_residual_v1_20261113/actual')
report = json.loads((base / 'report.json').read_text(encoding='utf-8'))
manifest = json.loads((base / 'packet_manifest.json').read_text(encoding='utf-8'))

def packet(name):
    raw = (base / name).read_bytes()
    ref = next(x for x in manifest['packets'] if x['path'] == name)
    assert hashlib.sha256(raw).hexdigest().upper() == ref['sha256']
    return json.loads(raw)

p8 = packet('distributed8_11_layer8_packet.json')
p11 = packet('distributed8_11_layer11_packet.json')
flat = lambda rows: [v for row in rows for v in row]
e0 = [2 * report['gates']['8'] * v for v in flat(p8['left'])]
e1 = [report['gates']['11'] * v for v in flat(p11['left'])]
assert len(e0) == len(e1) == 768 * 24
norm = lambda x: math.sqrt(math.fsum(v * v for v in x))
d = [x - y for x, y in zip(e0, e1)]
a = math.fsum(x * y for x, y in zip(e0, d)) / norm(e0) ** 2
orthogonal = norm([y - a * x for x, y in zip(e0, d)]) / norm(e0)
assert abs(norm(e1) - report['after_first_layer_final_block_residual']) < 1e-7
print('편집 전/후 잔차:', norm(e0), norm(e1))
print('목표 방향 투영:', a)
print('직교 성분 비율:', orthogonal)
improved = worsened = positive = 0
for j in range(24):
    c0, c1 = e0[j::24], e1[j::24]  # 768행×24열의 j번째 fit 질문
    improved += norm(c1) < norm(c0)
    worsened += norm(c1) > norm(c0)
    positive += math.fsum(x * (x - y) for x, y in zip(c0, c1)) > 0
print('잔차 감소/증가 문항:', improved, worsened)
print('양의 목표 방향 투영 문항:', positive)
```

집계에서 목표 표현과의 거리가 커졌다는 사실만으로 ‘8층은 쓸모없다’거나 모든 다른 목적의 편집도 실패한다고 말하지 않는다. 반대로 전체 영어 점수가 소폭 올랐다는 후속 사실이 이 첫 단계의 전달 근사를 검증해 주는 것도 아니다.

### 12.6 이 분산 방법이 적절했는지에 대한 재판정

| 평가 차원 | 재판정 |
|---|---|
| 실제 가중치 개입의 구현 | 원본·패킷·FP32 행렬 재현과 원복이 확인됐다. 기술 실행 자체를 실패로 바꾸지 않는다. |
| 여러 사실을 같은 모델에 쓰는 실험 | 사실별 별도 편집 합계를 하나의 능력으로 오인하지 않게 한 유효한 개선이다. |
| 같은 총 norm의 단일/분산 비교 | 분산에 두 배 예산을 주지 않았다는 장점이 있다. 다만 균등한 층별 한도가 모든 좋은 배분을 허용하는 중립적 제약은 아니다. |
|8·11 선택의 충분성 | 네 후보 중 개별 oracle 상위 둘이라는 제한된 근거다. 전체층·층 쌍·최종 목표층의 최적성은 미검증이다. |
| `1/2`의 수학적 지위 | MEMIT식 잔차 분담을 차용한 휴리스틱이다. TinyLM에서 잔차 절반 감소를 보장하는 공식은 아니다. |
| 층간 전달의 적합성 | signed gate 보정과 재측정은 필요했으나 충분하지 않았다. 실제 첫 단계에서 목표와 큰 직교 성분이 관측됐다. |
| 기존 CPU5시험의 의미 | [회귀 코드](../../scripts/test_p108_distributed_residual.py)는 gate/예산/입력 거부와 항등 전달 toy를 확인한다. 실제 모델의 비선형 전달·의미 보존을 검증한 것은 아니다. |
| 개선 방법으로 채택할 근거 | 현재 결과로는 부족하다. 같은 예산에서 단일11 fit6·dev0·공개1, 분산 fit2·dev0·공개0이며 보호도 원본보다 낮았다. |

**최종 판단: 다층 편집의 제한된 탐색 실험으로는 적절했지만, 검증된 전달 모델이나 최적 배분에 기반한 개선 알고리즘으로 보기에는 근거가 부족했다.** 초기 후보 범위와 잔차 배분의 부족한 부분을 ‘구현 완료’나 원논문의 이름으로 덮을 수 없다. 그렇다고 이것을 MEMIT 전체, 모든 분산 편집, 또는 모델 전체의 개선 불가능성으로 확대해서도 안 된다.

첫8층의 잔차가 증가해도 실험을 중단하지 않고11층까지 수행한 것은 사전 비교 절차였다. 두 번째 단계가 회복할 수도 있어 그 자체가 코드 오류는 아니다. 다만 현재 코드는 첫 단계의 실제 효과로 배율을 줄이거나 원복하는 개선 정책을 구현하지 않았고, 해당 배율이 유익했는지 검증하는 데는 부족했다.

### 12.7 재검토 결과로 비교할 수 있는 세 방향

아래는 방법의 비교·판단이며 새 구현·실행을 확정한 계획이 아니다. 실제 후속 설계는 기존 원장136A/E/F와 당시 허가·계획/preflight에서 정한다.

| 안 | 무엇을 보완하나 | 장점 | 한계·영향 | 비용 |
|---|---|---|---|---|
| A:14층 범위와 단독 쓰기부터 확인 | 전체 층에서 같은 조건의 개입 가능성과 제한된 예산의 실제 쓰기를 구분한다. 필요하면 고정 목표층 아래의 다른 쌍도 비교한다. | 현재 가장 직접적인 탐색 누락을 닫는다. 기존 생성·원복·봉인 도구를 재사용할 수 있다. | 개별 순위만으로 쌍의 시너지는 여전히 보장하지 않는다. 기존 완료 네 층을 그대로 중복 실행하지 않는다. | 중간. 현재48후보 밖의 추가 후보·실제 쓰기 검증 비용이 있다. |
| B: 실제 전달을 반영한 적응 배분 | 방향의 JVP/VJP·작은 실제 개입 등으로 최종층 이동을 확인하고, fit 목표와 보존 비용 안에서 배율·층별 예산을 조정한다. | 고정 절반과 항등 전달 가정을 직접 겨냥한다. 큰 직교 변화·비표적 손상을 검사할 수 있다. | 선형화 오차와 여러 prompt 위치의 영향을 검증해야 한다. 배율을 최종 평가 답으로 고르지 않는다. | 중간~높음. 모델 미분/순전파와 거부·원복·순서 대조가 추가된다. |
| C: 여러 층 차분을 최종 출력 기준으로 공동 최적화 | 낮은 랭크 차분들을 실제 후속 층까지 미분해 정답+종료 손실과 보존 비용으로 함께 최적화한다. | 층별 국소 대리문제보다 목표 답변에 직접 연결된다. | 별도 지도 최적화다. ‘모든 optimizer0인 닫힌형 쓰기’라고 부를 수 없고 과적합·망각과 정확한 전체 예산 관리가 필요하다. | 높음. 구현·미분 메모리·학습/보존 평가가 커진다. |

**권장하는 검토 순서는 A로 층 선정의 누락을 확인하고 B로 전달·배분을 검증하는 것이다.** 기존처럼 네 후보만으로 더 큰 결론을 내리거나,0.5를 다른 고정 상수로 바꾸기만 하는 것보다 근거를 더 직접적으로 확보할 수 있다. C는 그 다음의 비용이 큰 별도 최적화 후보이며 효과를 미리 보장하지 않는다. 평가 정답을 반복 편집에 사용하거나 새 본학습을 작은 후학습으로 대신 판정하는 경계는 유지한다.

### 12.8 이번 추가 분석의 실행 범위

이번에는 당시 계획·profile·코드·원논문을 다시 읽고, 보존된 인자에서24개 fit의 잔차·방향·문항별 변화를 CPU로 집계했다. 새 전층 검색·분산 조합·JVP/VJP·학습·모델 로딩·GPU·새 가중치 저장은 수행하지 않았다. 원래 결과와 음성·무작위 대조·공식 점수도 덮어쓰지 않았다. 기존 문서의 ‘절반의 목표를 쓴다’는 표현은 **절반의 실제 교정이 보장된다는 뜻이 아니며, 첫 목표 요청 뒤 재측정 잔차 전체를 요청했다**는 뜻으로 본문도 보완했다.
