## 동작과 실패 처리

기본 명령은 기존 USER_GLOBAL 입력을 사용한다. TL_VALIDATION_SCOPE와 TL_VALIDATION_SCOPE_SHA256을 모두 명시한 경우에만 별도 manifest의 검사 목록·입력 파일을 사용한다. 명세에 없는 검사를 실행했다고 하지 않고 NOT_RUN으로 기록한다. 디렉터리 view는 명세의 파일과 그 조상만으로 만들며 실제 트리를 순회하지 않는다.

Python audit hook은 저장소 파일 open과 명시 자식 실행을 통제한다. 검사기가 PermissionError를 잡아도 거부 영수증이 있으면 성공을 거부한다. native/shell 자식·임의 exec/fork·범위가 전파되지 않는 실행은 지원하지 않고 거부한다. 이 기능은 임의 네이티브 확장까지 격리하는 OS 보안 sandbox가 아니다. 해당 경로가 필요한 검사는 전역으로 fallback하지 않는다.

소유 모음의 schema는 TINYLM_SCOPED_STATIC_AUDIT_V1이다. 기존 전역 TINYLM_STATIC_AUDIT_V1과 구분해, 전역 검사만 받는 기존 WIP 종결기가 소유 부분 결과를 전체 완료 증거로 수락하지 못하게 한다. 사용자 기본 schema는 그대로 유지한다.

공유 표는 선택한 파서가 실제 선언한 플래그의 행과, 선택 소유 파일을 선언 위치로 주장하는 행을 함께 입력으로 쓴다. declared_in은 과거 메타데이터이며 플래그 목록의 정본이 아니다. 같은 플래그를 새 소유 스크립트가 재사용해도 기존 등급을 읽고, 소유 파일을 주장하는 낡은 행은 계속 검출한다. 원래 missing/stale/grade/evidence 판정은 유지하고 원본 표와 파서 내용은 수정하지 않는다. 입력 SHA가 실행 중 달라지면 결과를 무효 처리한다. 영수증은 읽은 파일 집합·명세 SHA·제외 경계·자식 상태를 기록하고, 데이터·모델 품질을 판정하지 않는다.

새 전체 스모크는 이번에 NOT_RUN이다. 향후 명시 범위로 실행하려면 모든 검사 자식의 명령과 입력을 먼저 등록해야 하며, 모델·학습 자식에는 검사 scope를 주입하지 않는다. 원형 행동 수와 모델 argv의 불변은 CPU에서만 확인한다.
