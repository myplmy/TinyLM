# 야간 평가 산출물의 보존과 Git 후보 분류

이번 작업의 명시된 평가 namespace18개만 파일 메타데이터로 점검했다. 보호 데이터나
모델 경로를 순회하지 않았고 연결 파일을 따라가지 않았다. 기준은 파일별20,000,000바이트
미만이다. 실제376파일721,346,259바이트 중 한도를 넘는 파일은0개였고 최대파일은
19,999,992바이트였다. 정확 대상과 수치는
`handoff/audit/WIP_20261024_EXPLICIT_ARTIFACT_SIZE_REVIEW.json`이 소유한다.
뒤에 새로 생기는 관찰기 출력은 이 시점 집계에 포함되지 않으므로 최종 별도 확인한다.

## 무엇을 왜 남기는가

| 유형 | 용도 | 권장 보존·Git 처리 |
|---|---|---|
| 계획·결과·기준표·방법론·독립 감사 | 조건, 판정, 누락과 원답 근거의 위치를 설명 | 명시 경로별 staging 후보 |
| 실행 소스·합성 회귀·작은 종결 영수증 | 같은 조건의 재현과 실제 종료·해시 연결 | 명시 경로별 staging 후보 |
| bounded runlog와 실패 veto | 실제 명령·종료코드·실패 순서를 보존 | 원형 보존, 명시 staging 후보 |
| 수만 개 전체 문항·보기 우도·token length·native wire JSONL | 공식 집계의 독립 재계수와 수치 진단 | 로컬 원형으로 보존, 일괄 staging하지 않음 |
| 대형 임시 텐서·캐시·모델 가중치 | 실행 및 재개 | 기존 소유 경로·ignore 유지, 새 복사나 staging하지 않음 |

파일이20MB 미만이라는 것만으로 Git에 넣는 것이 적절해지는 것은 아니다. 공개 벤치마크
본문의 사용 조건과 중복량도 고려해야 한다. 새 원답의 경로와 SHA를 소유 report에서
참조하고 있으므로 지금 다른 폴더로 옮기면 증거 연결을 다시 검증해야 한다. 이번에는
이동·재작성·삭제 없이 현재 위치를 유지한다. 향후 새 실행의 대량 출력 경로를 바꾸는 것은
별도 계약이며 기존 기록을 소급 이동시키지 않는다.

## 이번에 실제로 한 일과 하지 않은 일

크기 점검과 분류 문서만 작성했다. `.gitignore` 수정, staging, commit, 원로그·가중치·런처
삭제는0이다. 기존 ignore에는 대형 이진물과 과거 특정 raw namespace 제외가 있지만 새
야간 JSONL을 모두 제외하는 규칙은 없다. 따라서 현재 evidence 디렉터리를 통째로
추가하면 안 된다. 추후 Git 정리 범위가 정해지면 작은 결정 영수증과 소스의 명시 목록만
추가하고, 위 대량 JSONL namespace만 좁게 제외하는 방식이 권장안이다.

추가로 소유7개 명시 경로만 읽기 전용 Git 상태와 대조했다. 새 분류문서·크기감사·범위표·
Qwen3.5 연결기 두 파일·Belebele와LAMBADA 출력 디렉터리는 아직 untracked였다.
전체 저장소 clean 판정이나 다른 세션 변경의 staging 판정은 하지 않았다. 이 상태를
로컬 커밋 완료라고 보고하지 않는다.

이 점검은 크기·보관 적합성 판독이다. 평가의 정답성, 데이터 품질, 모든 저장소 산출물의
완전 감사나 디스크 삭제 가능 판정을 대신하지 않는다.

## 후속 관찰을 포함한 명시 범위 재확인

`handoff/audit/WIP_20261024_EXPLICIT_ARTIFACT_SIZE_REVIEW_V2.json`은 이전18개에
실제 관찰v1/v4 두 namespace를 더한20개를 재확인했다.384파일/722,566,218B이고
최대19,999,992B·한도 초과0이다. 미실행v2/v3 소스는 원형 아카이브이며 실제 모델
출력으로 세지 않는다. 새19개 done SH는전체소스·정확명령·SHA·모드와실행전원형까지
보존한 영수증V2를 작성했다. 원본과 대량 raw 및 런처의 이동·삭제와Git 쓰기는0이다.
