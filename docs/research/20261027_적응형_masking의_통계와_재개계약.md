# 적응형 masking의 통계와 재개 계약

원장59/P107 후속이다. 사용자96/97의독립CPU/GPU허용중총괄이CPU기술모듈만구현한다. 정제담당전용자료/코드/원장에는접근하지않고추가300M·작은학습품질판정은금지한다. 문헌보조는웹/지정텍스트읽기만수행했다.

## 대안과 선택

| 안 | 바꾸는 것 | 장점 | 한계·비용 | 판단 |
|---|---|---|---|---|
| A 균등 Bernoulli | 기존 P107 그대로 | 대조와RNG계약이있음 | 능력/선정이력에적응하지않음 | **원형 보존** |
| B 위치 노출/선정 균형 | 문서 내 위치별 counter·span/선택 | 반복노출편중을겨냥 | 능력추정과다름. 실제문서/위치ID필요,두int64면16D바이트 | 실제편중/계보확인뒤별도 |
| C 유형별 hard 정답률 | 가린gold 유형의성공/전체수를집계 | 손실이상치에덜민감,추가forward불필요 | argmax/전달/통계비용·희귀유형변동·정규화선택은남음 | **CPU기술선결 우선** |
| D 유형별 soft CE | 유형별평균loss로선정가중 | 연속적인어려움차이 | per-token CE·이상치·정규화범위0/빈도편향 | 후속 후보 |

예: 기존과같은15%기대선정량을유지하면서이미자주맞힌토큰은덜가리고계속틀리는토큰은더가리는것이C다. 그러나오표기/질문결손도어려울수있어학습가치판정기가아니다. B는같은원문의특정위치가덜선정된것을보정하며다른질문이다. span/top-k까지바꾸려면같은span/top-k의균등대조가필요해이번Bernoulli대조와합치지않는다.

## 일차 문헌과 명시적 이식 차이

[AMLM §3.1](https://arxiv.org/html/2510.20475v1)의hard는`(correct+0.5)/(total+1)`평활정답률과EMA를사용한다. [고정 저자 코드](https://github.com/Leukas/babylm25/blob/4a519d035cf874785eb754f85e9a3f6e38bedb83/train_mask.py)는문헌보조가읽었으며동일위치의MLM통계를그대로MNTP에복사하지않는다. P107의gold/예측은선택입력j보다한칸앞인target/logit j-1에서집계한다.

GPT-BERT의위치노출/선정횟수를loss적응이라고부르지않는다. 이번은AMLM개념을MNTP에연결하는별도기술이식이다. 원코드의pad포함정규화·상한없는확률·BF16통계는복사하지않는다. hard만선택하고soft CE나원GPT-BERT span을구현한것으로세지않는다.

코드축은기존eligible/shift함수를재사용해중복정의하지않는다. 데이터축은가상ID와명시분류마스크만사용한다. 시험축은독립scalar분모/통계·원Bernoulli/RNG·거부/폐기·stat재개를검산한다. 정본축은CPU기술과실제학습효과를분리한다. 기술부채는본체/optimizer/자료위치재개·GPUargmax/전달·causalKD·fusedCE연결이남는다. 새로운train모듈추가뒤전체스모크가낡으면현재소스의새검증을별도로수행하며완료학습을재실행하지않는다.

## 선정과 통계의 계약

1. CPU전용이며기존P107 eligible와예약ID정책을재사용한다. 각row의eligible위치에대해기대평균rate를맞추고확률을0..1로제한한다. 실현target개수는Bernoulli이므로같거나고정이라고주장하지않는다. eligible0은빈선정이며학습분기의zero-target거부는기존P107이소유한다.
2. 균등가중일때기존함수와선정/다음RNG가같아야한다. 보호위치를포함한fulltokens.shape전체에서같은순서의난수를소비한다. eligible수만큼만뽑는대체는하지않는다.
   원함수의Python scalar는rand Tensor의dtype로반올림된다. float64확률을그대로float32난수와비교하면rate0.7의경계draw에서동률이깨지므로비교threshold를rand dtype로맞춘다. 정규화된float64의분석상기대합과실제표현된threshold합을따로남긴다. 실제이산난수의확률까지무한정밀도로정확하다고주장하지않는다. draw dtype도정책재개지문에고정한다.
3. observer는가린shifted target의원gold ID와같은logit위치의argmax만받는다. TRAIN·성공한완전단위만허용하고eval/test·causal분기·형태불일치를거부한다. checkpoint재계산안에서는수집하지않는다.
4. 하나의update에서선정weight는고정한다. 통계는pending으로모으고성공단위commit때만반영하며실패/skip은통계와선정RNG를복구한다. rate/EMA/갱신주기는명시인자이며생산기본값으로채택하지않는다. 갱신주기의단위는완료update이고논문의200batch와같다고추정하지않는다.
5. 미관측유형은`keep`과`prior`를명시구분한다. keep은관측된유형만갱신하고prior는미관측도50%정답률사전값으로갱신한다. 전자가문헌보조의우선이식권장이고후자는원식확인용대조다. 이번에는둘의기술동작만검증하고품질승자를정하지않는다.
6. 완전한update경계에서만stat/RNG를복원한다. source/run/config지문이달라지면거부한다. 이것은모델/optimizer/실제loader위치까지포함한전체학습재개가아니다.

## 편향과 비용 해석

유형별관측수/마지막관측update와명시된그룹의eligible·선정·기대/실현rate를남긴다. 합성한국어/영어·희귀/숫자표시는단위검산용label이며실제코퍼스언어분포/희귀도나모집단편향측정이아니다. 실제분류와빈도는TRAIN에서만고정해야한다. 겹치는그룹의수를합쳐전체로세지않는다.

통계는CPU int64·weight는float64로유지한다. object의고유typed storage/RNG·pending을실제로계수하고전체RSS/allocator·logits·GPU전달/argmax와구분한다. 추가forward가없어도추가작업이무료는아니다. 미래full logits없는fusedCE에는별도streaming argmax/통계경로가필요하다. 기술비용통과를학습효율/지능향상으로승격하지않는다.

## GPU 통계 전달의 세 대안과 독립 비용 진단

| 안 | 방법 | 이점 | 비용·한계 | 이번 판단 |
|---|---|---|---|---|
| A 전체 로짓 CPU 전송 | 기존 로짓을 모두 옮겨 argmax | 구현 단순 | 8×1024×262144 BF16만4GiB 전송, CPU 복사도 필요 | 구현하지 않음 |
| B GPU argmax 뒤 ID 전송 | 전체 위치 또는 가린 위치만 GPU에서 읽고 int64 ID 전달 | 로짓 전체 전송을 피함 | 전체 reduction 또는 선택 로짓 복사와 GPU 임시 메모리 필요 | 두 경로의 가상 비용을 직접 비교 |
| C GPU 통계 상주 | GPU에서 유형별 count까지 집계 | 전달량 추가 감소 가능 | 통계 소유/재개·실패 롤백과 GPU 결정성 구현 확대 | 후속 후보 |

새 Stage3W는 모델 없이 BF16 가상 로짓을 한 번 만들고, 알려진 최대값 ID와 실제 전달 결과를 대조한다. B의 full/selected를 같은 로짓·같은 가림·같은 CPU observer에서 순/역순으로 측정한다. 어휘32768/262144, batch8·길이1024, uniform15%를 고정하고 각 블록 warm1/실측3이다. 전자는 전체 위치를 reduction하고, 후자는 가린 행을 모으므로 후자의 임시 로짓도 peak에 포함한다. 선택 수·H2D/gather·argmax·CPU 복사·통계 commit을 나누되 동기화가 포함된 기술 비용으로만 보고한다.

CPU 직접 oracle를 선행하고 소스/프로필을 동결한다. 실제 실행은 사용자96/97의17시 권한, GPU 여유8GiB 이상, 단일 실험 소유, 내부300초/외부360초+kill20초와 정리 여유를 지킨다. 원형·실제 코퍼스·모델·optimizer·체크포인트 쓰기0이다. 4GiB 가상 로짓의 비용은 실제 모델과 동시 상주하는 최소 메모리나 fused CE의 streaming 비용을 보증하지 않는다. 제품 trainer·생산 자료 편향·전체 학습 재개와 본학습 품질은 여전히 미완이다.

이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.
