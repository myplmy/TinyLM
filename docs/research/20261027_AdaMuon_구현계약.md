# AdaMuon 독립 적응판의 구현 계약

원장56과 사용자96의 미완료 작업이다. 문헌 보조와 총괄은 [논문v3 Algorithm1·3절](https://arxiv.org/html/2507.11005v3) 및 [저자 구현](https://github.com/Chongjie-Si/AdaMuon/blob/main/adamuon.py), [그룹 설정](https://github.com/Chongjie-Si/AdaMuon/blob/main/opt_config.py)을 직접 읽었다. main의 commit SHA는 확인하지 못했다. 원형 패키지 복제·완전 재현이나 성능 보증은 주장하지 않는다.

후보는 `momentum -> sign -> NS5 -> elementwise second moment -> RMS0.2 -> decay/update` 순서를 쓴다. beta는 공유하며 bias correction은 하지 않는다. 기존 Muon의 NS와 parameter 분류를 재사용하되 최종 RMS를 맞춘 뒤 Muon 형상 배율을 다시 곱하지 않는다. Nesterov 기본은 공식 코드와 같게 true로 하며 논문 의사코드와 다른 점을 명시한다. sign은 가중치가 아닌 업데이트 방향에 적용한다.

첫 후보의 V는 FP32다. 공식 코드의 BF16 V와 다른 정밀도 적응판이고 단일 장치에서 분산 통신 버퍼는 만들지 않는다. 영구 상태는 FP32 모멘텀+FP32 V, 행렬 원소당8B이며 기존 Muon보다4B가 추가된다. 실제 peak에는 gradient·임시값·검증·라이브러리 비용이 더해진다. 이 계산값을 실제 속도나 총학습 절감률로 읽지 않는다.

행렬 그룹은 기존 `muon.split_params`를 먼저 적용한 뒤 명시 출력 head의 파라미터를 제외한다. embedding·벡터/스칼라·별도 출력 head는 AdamW 쪽으로 보내고, 1D는 WD0으로 나눈다. 현재 tied 입력/출력 table을 두 번 넣지 않는다. GSQ code-selection logits는 이 후보에서 구현하지 않는다.

기본 trainer·Muon/NorMuon·NS·학습률·CE/KL는 바꾸지 않는다. 입력 전수 검증은 잘못된 gradient/상태가 있을 때 초기 변경을 막지만, 계산 도중 후반 행렬에서 산술 오류가 나면 앞 행렬/현재 모멘텀은 이미 바뀔 수 있다. 전역 원자적 rollback을 보장하지 않으며 그 경우 실행을 중단하고 정상 상태에서 복원한다.

검증은 다단계 독립 수식, sign 위치·Nesterov·RMS·0/None, 중복/비유한/재개/gradient 보존·STE와 실제 상태·GPU 자원을 포함한다. 본학습과 지능 평가는 추가300M 금지가 해제된 뒤 별도 조건으로 수행해야 한다. 논문이 보고한 token 효율을 TinyLM wall clock 가속으로 옮기지 않는다.
