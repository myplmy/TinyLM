타세션정제/TinyDataset/추가300M/설치·다운로드·새환경·Git은제외한다.

## 1. 원문에서 확인한 방법과 차이

[원논문§3](https://aclanthology.org/2026.emnlp-main.1192.pdf)은교사top-k를재정규화하고,
첫학생subtoken으로어휘를대응한다. 문자경계의가까운단조위치를정렬한다. Eq7은순서있는
k개항의L1, Eq8은고유anchor집합밖학생확률합이다. 학생은전체어휘분모를유지한다.
주실험k128/온도1이며λres의0/0.5/1/2대조도있다. 교사·학생규모와4096문맥은TinyLM과다르다.
[저자README](https://github.com/hyhy892/ACTD/blob/main/README.md)는현재코드공개예고만있다.
저자코드를재현했다고하지않으며원문의경계동률·중복매핑처리에는해석상의여지가있다.

기존ALM은같은바이트chunk의likelihood를맞춘다. ACTD의top-k anchor·문자경계위치·잔여질량과
다르므로기존ALM/K2캐시를ACTD완료로재명명하지않는다.

## 2. 이번 총괄의 구현 선택

1. **literal Eq7**: 여러교사token이같은학생anchor에매핑돼도k개항을합친다. Eq8의보집합만
   고유anchor로계산한다. 예를들어교사0.6/0.4가모두같은anchor이면학생p=1에서도Eq7은1이다.
   확률을합쳐하나의목표1로만드는것은다른변형이다. CPU반례로구분하고채택효과를추정하지않는다.
2. **전체분모**: 학생anchor만softmax하지않는다. 모든학생logit의logsumexp를사용한다.
   보집합확률은별도logsumexp로계산해1에서빼는상쇄를피하고, 보집합이빈행은유한한0gradient다.
   loss는sum과실제지도위치수를돌려줘기존update전체분모와연결한다.
3. **원형과특수token**: 기존ByteLevel/교사raw-byte helper를재사용한다. 공통raw-byte token은
   명시학생ID로직접대응한다. 그외유효UTF-8문자열만학생으로다시encode하고첫subtoken을쓴다.
   encode된바이트전체가원문과같아야한다. 특수token은명시native-ID대응만허용하며불명매핑은HOLD다.
4. **위치의정의**: helper입력은caller가확정한prefix끝의문자좌표와지도할다음token의owner다.
   자체적으로target을두번shift하거나다른대화턴을매칭하지않는다. 동률은앞경계/앞index로
   고정하는TinyLM정책이다. 가장가까운교사경계가미래쪽이면lookahead문자수를반드시기록한다.
   left-only는별도명시변형으로구분한다. 실제token/assistant/EOT소비검증없이학습에자동연결하지않는다.

A를먼저기계검증한다. 작은학습성과판정은하지않는다. 부족한교사신호는기존K2로
대체하지않으며필요시새qualified교사의TRAIN전용K128캐시와93M의정확한head/owner별
미분·비용을별도계획한다. Qwen공식full평가중동시에다른모델을올리지않는다.

Stage7h는 이미 수치 canary가 완료된 Qwen3.5의 **tokenizer 메타데이터만** 추가로 읽어,
Tiny32k와 전체 정적 어휘 대응률도 계측한다. 새 모델을 로딩하거나 학습하지 않는다.
양쪽 ByteLevel 선언과 원본 SHA를 확인하고 ordinary raw-byte 변환은 기존 helper를 쓴다.
teacher native EOS248044는 Tiny 선언 EOS2, literal ChatML start248045/end248046은
Tiny3/4에 명시 대응한다. EOS와 ChatML EOT를 하나로 합치지 않는다. 나머지 불명 특수token과
head 안에서 tokenizer에 선언되지 않은 ID는 HOLD다. 실제 top-k에 HOLD가 끼면 그 row를
불완전 신호로 거부하며 나머지만 다시 정규화하지 않는다. 매핑은 head길이의 ID/상태 배열로
저장해 파일당20MB 미만을 지키고, 정적 어휘 대응률을 실제 확률질량/위치 커버리지로 간주하지 않는다.

이 추가 범위의 회귀는 metadata 선언과 native ID 고정, 미선언 head ID/특수token의 HOLD,
같은 byte의 직접대응과 재토큰화 무손실, source/코드 전후 SHA다. 권한과 문서 영향은 위 표와 같고
CPU 단일 프로세스만 사용한다. 기존 Qwen scorer/라이브러리/진행 중 모델에는 쓰기·hook이 없다.

실제 Stage7g/h는 CPU60와2.528424초의재고로완료했다. 결과101§592에247811대응/509보류,
128 TRAIN export의top-k0을보존했다. metadata added33은HF special=True21/False12다.
v1의HOLD30은보수적**추가control ID묶음**정책이며모두HFspecial=True라는뜻이아니다.
False인literal added12개를엄격UTF-8/첫subtoken으로대응하는정책은v1과구분해
다음실교사캐시에서사전선택한다. 어휘개수대응을확률/위치커버리지로승격하지않는다.

이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.
