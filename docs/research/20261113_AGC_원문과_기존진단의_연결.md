# Activation Gradient Clipping 원문 보충 — 계측과 수정을 분리한다

## 확인 범위

원장98의 미완 문헌 항목을 사용자115 시간창에서 총괄이 직접 보충했다. 지정한
[Microsoft 기술보고서](https://microsoft.ai/pdf/Frontier-Pre-training-at-Microsoft-AI.pdf?v=2)의
9~10쪽 텍스트를 확인했다. 웹 screenshot은 비활성 오류여서 도표 이미지는 직접 확인하지
못했다. 도표의 수치나 전체 모델 효율 주장을 TinyLM 예상치로 인용하지 않는다.
설치·로컬 PDF 다운로드·모델/GPU·코드/학습/자료 변경은0이다.

원문은 전역 가중치 gradient norm을 자르는 방식과 일부 activation의 gradient를 다루는
방식을 구분한다. 후자를 데이터 이상을 찾는 데도 활용했고, 잘린 문서 경계에서 전처리
문제를 발견한 사례를 설명한다. 그러나 공개 본문에서 정확한 삽입 위치·축·임계값·누적과
정밀도 계약은 확인하지 못했다. 따라서 같은 이름의 방법을 완전 재현할 수 있다고 하지 않는다.
원문에 없는 수식을 Adaptive Gradient Clipping이나 activation 값 clipping에서 가져와
같은 기법이라고 부르지 않는다.

## TinyLM에 대한 해석

현재 native KD의 본체 gradient가 CE의33.315배이고 cosine이−0.161인 사실은 큰 신호의
관측이다. 이것만으로 일부 토큰의 이상치가 원인이라고 정하지 않는다. 잘못 정렬된 투영이
모든 위치에 다른 방향의 신호를 줄 수도 있어, 즉시 clip하면 유용한 신호와 원인을 같이
가릴 수 있다. 먼저 투영/owner/causal 경계와 loss별 신호를 구분해야 한다.

정제 담당 세션이 맡은 원문을 이 연구에서 다시 읽거나 수정하지 않았다. 향후 허가된
TRAIN에서 큰 activation-gradient 위치가 발견되더라도 자동 불량 데이터 판정은 금물이다.
검토 단위는 row·assistant owner·토큰 위치·논리층·재귀 방문과 checkpoint 재계산 회차를
구분해야 한다. 드문 정상 이름/숫자/형식 요구도 큰 신호를 만들 수 있다.

## 후속 검토안

| 안 | 범위 | 장점 | 한계·비용 |
|---|---|---|---|
|A, 권장|최종 학생 hidden의 gradient를 수정 없이 관찰|현재 native KD와 가까워 추가 변화가 작음|층 원인까지 특정하지 못하고 계측 overhead는 미측정|
|B|선택 MLP down 입력의 gradient를 방문별로 관찰|직접 편집에서 보던 위치와 연결 가능|checkpoint 재계산의 hook 중복과 CLA/방문 표식 검증이 필요|
|C|전층 관찰과 clipping을 한 번에 도입|범위가 넓음|비용과 개입이 동시에 바뀌어 현재 비권장|

현재는 A의 개념 검토까지만 했다. hook·집계·문턱·GPU 비용·본학습 효과는 NOT_RUN이다.
기존 global clip이나 Muon을 변경하지 않으며, 더 큰 norm을 단순히 불량/불안정/지능 저하로
해석하지 않는다. root 연구의 다음 핵심은 여전히 native 투영·자료·자원 선결이다.
NOISE/LFR/HRM/TST 등 원장98의 나머지 전체 비교가 완료됐다는 뜻도 아니다.
