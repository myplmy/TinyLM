# Falcon5 공식 전량 평가의 오후 실행 계약

사용자105의 소유 커밋과 신규 인계를 먼저 마쳤다. 이 문서는 원장51의 미완5-shot만 닫기 위한 사전 설계다. 실제 실행·점수는 결과101의 새 절이 소유한다.

| 안 | 방법 | 장점 | 단점·비용 | 판단 |
|---|---|---|---|---|
| A | 완료0-shot adapter의 동일 공식 채점 본체를 재사용하고 shot별 차등·영수증·새 마감만 분리 | 기존114문항/456우도 기준과 직접 연결, 중복0-shot 없음 | 새 CPU7과 비용114·조건부 전체14042 필요 | 채택 |
| B | 재사용OFF의 옛5-shot 본체를 그대로 전량 수행 | 계산 경로가 Tiny와 가장 가까움 | 기존 비용 외삽이 약4시간이어서 현재 창에 불리 | 기존 음성 보존 |
| C | 외부5-shot을 보류하고 제품 학습 통계 연결부터 수행 | 구현 시간을 확보 | 사용자가 요청한0/5 외부 비교 미완이 남음 | 전량 실행 중 독립 CPU 작업으로 병행 |

예를 들어 같은 과학 문제의5개 앞 예시와 A/B/C/D 우도를 그대로 두고, 동일 문맥의 한 토큰 선택지만 공식 Collator가 재사용한다. 정답 파일이나 이전 예측을 재활용하는 것이 아니다. Tiny 가중치와 정제 자료는 바꾸지 않는다.

## 영향도와 권한

| 파일·경로 | 동작 | 권한 근거 | 제외 |
|---|---|---|---|
| 새 diag/test 두 파일 | 새 shot별 parity·profile·허가 연결 | 사용자105 미완 연구 구현·실행 | 기존 완료 driver 수정0 |
| 새 cache/evidence 가족 | source/runtime/모델·과제 계약과 새 결과 보존 | 사용자105 기존 평가 이어받기 | 원본 모델·평가 자료 수정0 |
| 새 Stage14h/i/j SH·TSV | CPU→비용→조건부 전량 | 사용자105 주도 실행 | 만료 hold SH 해제0 |
| 계획/결과/기준표/나침반/원장 | 실제 상태·조건·판정 갱신 | 사용자105 작업 절차 | foreign flag·정제·루트09 제외 |

코드는 기존 evaluate 함수를 물리적으로 복사하거나 고치지 않는다. 기존 전용 strict loader·공식 HFLM·NVML watcher를 재사용한다. 테스트는 잘못된 shot/질문/수치/receipt를 거부하는 실제 실패 반례를 포함한다. 같은 자료·tokenizer·초기화·출력계약을 유지하고 학습/CP저장0이다. 새 프로필이 공식 Collator도 archive/source/runtime와 대조한다. 유지보수 부채는 새 얇은 어댑터와 향후 동결 source 확인이다.

## 예측·순서·중단

1. CPU7과 기존 완료 계약의 파일/SHA·112336한토큰 continuation 근거를 검증하고 새 source/profile을 동결한다. 같은14042×두shot 토큰 인코딩을 다시 하지 않는다.
2. Stage14i에서 같은57과제×2=114비용 표본을 수행한다. 기존OFF5-shot의456우도와 atol/rtol1e-4·114argmax가 모두 같아야 한다. 소형 정오 점수는 성능 평가로 게시하지 않는다.
3. 실측 초×전체 제출위치/비용 제출위치×1.8+300초를 사용한다.90분·15시예비120초·소스/원형/자원 문턱을 통과할 때만 Stage14j 전량을 연다. 안전계수나 표본 수를 줄여 억지 통과시키지 않는다.
4. 실제14042·공식56168인자·57집계·forward shape·원형불변·최종CUDA0을 독립 재검산한 뒤 점수를 공개한다.

공식 재사용 덕분에 비용 감소를 기대하지만5-shot은 대부분1024길이이고 작은 수치 차이나 OOM이 생길 수도 있다. 물리 GPU 여유 약15.2GB를 확인했으나 비교 경로의6GiB allocator/8GB 공유 증가 감시는 보수적으로 유지한다. 사용자 상한 해제와 실제 사용량을 혼동하지 않는다. 실패/마감 부족은 원형 보존·미실행으로 남긴다.

비용은 CPU 수초~분·GPU 비용 수분·조건부 전량 약30~90분 예상이며 실측 후에만 확정한다.0-shot/Tiny 완료 팔은 반복하지 않는다. source/profile/공식 runtime·tokenizer·자료는 실행 중 동결하며 다른 CPU 구현이 이 source 목록을 바꾸면 병행하지 않는다.

## 한계

5-shot 문맥은1024 상한으로 앞 예시가 잘릴 수 있고 공개 긴 문맥 점수와 완전히 같지 않다. 모델별 tokenizer/구조/사전학습은 다르다. cache 채점 최적화의 속도를 아키텍처나 학습 가속으로 부르지 않는다. 기존 Tiny의 낮은 분별력·반복을 외부 모델 점수로 개선했다고 주장하지 않는다. 추가300M·정제 편입·설치·다운로드·실제 삭제는0이다.

이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.
