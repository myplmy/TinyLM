# P108 — 사용자 제시 WSP 방법과 실제 실행 범위

2026-11-05 사용자111·112의 재개 지시를 반영한다. 전체 직접 편집 연구는 종료하지 않았다.
기존에 실패한 MLP 방향 제거·국소 지도 보정·원scale 코드 편집과 미실행 원방법을 구분한다.

| 사용자 원방법 | 이전 TinyLM 실행 | 차이와 현재 상태 |
|---|---|---|
| WSP p50c: 소수 MLP 출력 열의 반복 방향 억제 | 실제 GPU 실행 | 가장 가까운 개념 차용이다. 모델·층·열 수·선정 규칙이 달라 저자 재현이 아니다. 독립 정답 증가 없음 |
| WSP p10c: Attention와 MLP 여러 출력 행렬의 공통 방향 제거 | 이번 전까지 미실행 | Stage9 실제 실행. Attention/MLP 각 절반인4/8행렬을 시험했고4행렬 확인의 반복49→129/144로 비채택 |
| WSP p25c: 특정 Attention 헤드의 출력 열을 0으로 만듦 | 이번 전까지 미실행 | Stage9 실제 관찰 후보와 Stage10 전체168head 순전파/생성을 시험했다. test2→8/10이나 echo 증가·보호0으로 비채택 |
| ROME/MEMIT | 원방법 전체 미구현 | key/value 아이디어만 참고한 국소 ridge/SVD는 원논문의 공분산 보정·대상 값 최적화·다층 분배 재현이 아니다 |
| AlphaEdit | 개념 참고만 | 보호/보존 개념 참고이며 원방법 전체·null-space 편집 재현은 미실행 |

저자 [WSP 본문](https://rikiyat.github.io/blog/weight-space-programming/)과
[실험8 README](https://github.com/RikiyaT/lm_understand-logs/blob/main/exp8_math/README.md)를 대조했다.
WSP의 전제는 순전파 정보만 사용하는 것이므로 별도 gradient 후보를 WSP 재현으로 세지 않는다.
원문 전체 실험 스크립트를 모두 재현하거나 저자 모델의 수치를 검증한 것은 아니다.

## 접근 비교와 결정

| 안 | 장점 | 비용·한계 |
|---|---|---|
| A: 미시도 p10c/p25c 순전파 개입 | 사용자 제시 방법의 실제 공백을 메움 | 새 Attention 계측·편집 원복 필요, 제한 진단 GPU 약15~35분 예상 |
| B: 정답 기울기로 삼진 부호 편집 | 질문에 민감한 편집 가능 | WSP와 다른 연구이고 삼진 제약·선택 편향 검증 추가 필요 |
| C: 자료 생산/GSQ 연구로 즉시 이동 | 본목표의 다른 선결 진행 | 직접 편집 원방법의 공백을 남김 |

현재 권장·실행은 A다. 새 gradient 연구보다 원방법의 미시도 부분부터 확인한다.
Q/F는 따로 학습된 모델이므로 이 실수 모델 시험과 과거 삼진 결과를 양자화 단독 효과로 해석하지 않는다.

코드: strict loader/emit/채점/분할기를 재사용하며 제품 기본 동작은 변경하지 않는다.
데이터: 새 코드 정답 질문을 calibration/dev/test로 분리하고 공식 벤치마크는 선정에 쓰지 않는다.
시험: 출력 헤드 열 경계, 실제 master 변경과 계산 반영, no-op·예외 포함 원복을 CPU에서 검증한다.
비교: 동일 완료 실수 모델·FP32 MATH·chat32·R1·greedy·cache ON·MTP OFF다.
상주: 한 모델만 사용하며 GPU는 현재 여유 범위, 저장 checkpoint는 0개다.
기술부채: opt-in 연구 도구로 한정한다. 활성 방향의 상관을 인과로 단정하지 않으며 실제 개입을 평가한다.
