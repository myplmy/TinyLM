# P107의 causal 배치에만 같은 어휘 교사 KL 연결

원장59가 지시한 초기 결합은 causal 배치 KD와 masked 배치 CE를 분리하는 것이다. 기존 일반 trainer의 KL을 GPT-BERT 전체 방법이나 서로 다른 tokenizer 정렬로 재명명하지 않는다. 사용자105의 현재 연구 창에서 기본off 구성요소와 CPU 반례를 준비하고, 진행 중인 Falcon/P107 디스크 진단의 소스 검산이 닫힌 뒤에만 기존 학습 어댑터에 연결한다.

| 안 | 내용 | 장점 | 단점·비용 | 판단 |
|---|---|---|---|---|
| A | 동일 tokenizer/V의 frozen teacher를 같은 causal mask에 넣고 기존 KL 함수를 재사용 | 어휘/미래정보 누설과 KD 연결 비용부터 분리 | 실제 Gemma 교사의 서로 다른 어휘 문제는 해결하지 않음 | 기술선결로 채택 |
| B | 실제 외부 교사의 hidden/projector·tokenizer 대응까지 한 번에 구현 | 실제 지식전이 목표에 가까움 | 별도60~63번의 표현·어휘 정렬과 모델자원 선결 | 기존 백로그 유지 |
| C | causal도 CE만 유지하고 teacher 연결 보류 | 추가비용0 | 이미 지시한 KD 결합의 구현이 미완 | 기본off 대조군으로 유지 |

예를 들어 원 토큰35·36·37을 왼쪽부터 예측하는 causal 배치에서 두 모델은 같은 문서·같은 하삼각 mask를 본다. 반면 일부 토큰을 가리고 양쪽 문맥을 보는 MNTP에는 교사를 호출하지 않는다. 교사가 아는 정답을 새로 판정하거나 질문을 재생성하는 기능은 없다.

코드는 새 `tinylm/train/causal_teacher.py`와 CPU 시험을 추가하고, 선행 source가 닫힌 뒤 `AdaptiveMNTPTrainer`에 선택 인자 하나로 연결한다. None이면 원 loss/state/경로를 그대로 유지해야 한다. teacher/student의 tokenizer SHA와 V가 같고 파라미터가 독립이며 teacher가 eval·requires_grad=False일 때만 허용한다. 형상·유한값·같은 causal visibility를 검사한다. 원 교사의 실제 지문 정답성이나 지능은 이 검사로 확인하지 않는다.

기존 CE 계수를 유지하려고 causal loss는 CE + coefficient×KL로 정의한다. 초기 기술 진단은 coefficient0.1·T1·행청크256만 사용하며 이 수치를 최적/기본값으로 채택하지 않는다. 전체 유효 target 수로 가중한 기존 `_kd_kl` 호출을 재사용해 PAD/문서경계의 무시 target을 제외한다. masked loss·causal/masked 절반 가중·clip과 optimizer는 유지한다. 추가 교사 분포 저장 때문에 GPU 메모리·시간이 늘 수 있다.

CPU는 독립 float64 수식·마스크·gradient·교사 고정·공유 파라미터 거부·masked 거부를 대조한다. 연결 뒤에는 보존한 이전 소스와 None 경로의 여러 optimizer 갱신/state exact를 확인하고 전체 재개가 teacher 계약을 거부/계승하는지 검증한다.

GPU는 별도 새 profile/CPU/source와 물리 여유를 닫은 뒤 같은 Native 교사의 복사본을 사용하는 합성 기술 대조만 고려한다. 이는 능력이 좋은 외부 교사나 실제 코퍼스의 학습 효과가 아니다. 선행 GPU는 단일 직렬이고 새 본300M·정제 자료 편입은 금지다. 메모리 부족·마감 부족이면 추가 실행을 열지 않으며 이미 끝난 메모리/디스크 진단을 반복하지 않는다. 원형·snapshot·실패는 보존한다.

이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.
