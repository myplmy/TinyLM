# ACTD 반복 기울기 차이 — 결정론 실행의 별도 진단 계약

사용자115의 연구·구현·CPU/GPU 위임으로 총괄이 수행한다. 원Stage7k는 실제 종료0과
실제 미분·유한 손실을 확인했지만 같은 역전파의 CE143/ACTD9862개 원소가 원기준 밖이다.
이를 수치 재현성 통과나 학습효과로 해석하지 않는다. 원문턱·원답·교사캐시·소스는 보존한다.

## 목적·가설·세 안

| 안 | 방법 | 이점 | 한계·비용 |
|---|---|---|---|
| A, 선택 | 같은 봉인 함수·자료·전체분모에 strict deterministic dispatch와 cuBLAS workspace를 설정 | 반복 차이가 줄어드는지 직접 확인하고 비결정론 연산 오류도 보존 | 수치 경로가 달라질 수 있고 더 느릴 수 있음; GPU 약1분 예상 |
| B | BF16을 모두 FP32로 바꾸어 반복 | 정밀도 영향을 함께 볼 수 있음 | 메모리·정밀도·커널을 동시에 바꾸므로 원인 분리가 덜 명확 |
| C | 허용오차를 높여 통과로 바꿈 | 실행 비용 작음 | 실제 결함을 숨길 수 있어 기각 |

여러 후보 중 A를 먼저 한다. 같은 입력/손실이어도 GPU reduction/embedding backward의
순서가 달라질 가능성은 가설이며 현재 특정 연산을 원인으로 확정하지 않는다. 결정론 경로에서도
차이가 남으면 이를 그대로 기록하고 실패 텐서 이름별 분포를 남긴다. strict 모드의 명시적
오류가 나면 해당 연산의 미지원 증거이며 자동 fallback이나 warn_only로 완화하지 않는다.

## 영향·권한·고정

새 driver/test·SH2개·namespace `p106b_actd_determinism_v1_20261113`·관련 문서와 자기 원장만
수정한다. 원 driver의 함수 code object를 독립 globals에서 재사용하고 저장 경로와 상세 비교
관측만 바꾼다. 원 read_cache/loss/head/정렬/마스크/global 분모·모델·CP·encoder는 재사용한다.
코드 중복 구현·제품 변경·교사 재호출은0이며 같은128행/x32216/CE772/ACTD607을 유지한다.
`CUBLAS_WORKSPACE_CONFIG=:4096:8`은 해당 자식 프로세스에만 적용한다. 결정론=True와
warn_only=False를 CUDA 최초 초기화 전에 설정하고 기존 BF16/TF32 OFF·ckpt ON을 유지한다.

CPU3은 독립 globals 불변·원 비교 수치/허용오차 보존·원소별 관측/비유한 거부를 확인한다.
GPU는 원ABBA4×16 microbatch, micro8×accum16, width1024이며 optimizer/CP 저장0이다.
CUDA0/0·원core/CP/source/cache 불변을 닫는다. 초기 cold block이 섞인 비용을 가속률로
해석하지 않는다. 17시까지 권한과15분 정리 여유를 준수한다.

확정하지 않는다. 학습 안정성·일반 QA 품질·증류 채택은 본학습 후 별도 평가가 필요하다.
