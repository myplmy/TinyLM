# DSKDv2 제한 입력창의 원문항별 소비와 전역 분모

## 1. 왜

사용자161은 기존 작업을 먼저 수행하고 필요한 구현을 직접 판단하도록 허가했다. 원장61/62의 DSKD 표현·정렬·추가 비용 중 입력창은 결과101§636의 CPU17로 닫았지만 소비 접점은 남았다. `p106b_dskdv2_bridge.native_sums`는 이미 factored 학생 head·전체 교사 어휘·양방향 투영과 stop-gradient를 구현한다. `diag_p106b_dskdv2_bridge.student_cost`는 원문항별 작은 위치 묶음/전체 KD 분모를 쓰지만 feature 전체를 eager dict로 보유한다. 기존 진단은 봉인된 역사이므로 수정하지 않는다.

## 2. 질문

제한 feature batch를 원문항별 원위치 frame으로 소비할 때 기존 양방향 손실과 전체 update 분모·학생/투영 미분을 보존하는가? 위치/정답/owner/매핑·head shape/분모가 잘못되면 입장 또는 현재 update를 중단하는가?

## 3. 예측

독립 FP64 dense 참조와 atol/rtol1e-10 이내의 값/미분을 예상한다. 원문항 간 동일 raw index를 합치거나 마지막 작은 batch에 별도 평균을 주면 틀릴 것으로 예상한다. 원GPU는 GEMM 형상/정밀도에 민감하므로 이 CPU 동률만으로 실제 Native 일치를 예상하지 않는다.

## 4. 단계

window 전체 metadata·mapping/분모/정책 선검사 → 입력 batch와 원기록 대응 → 문항 하나의 공급된 학생 frame/정답/owner → 문항 안의 최대8위치/native_sums/원고정 교사 frame → 전체 분모로 정규화한 손실의 caller backward → batch finish → 전체 window 분모·호출 accounting 종결이다. 한 문항이 batch 경계에 걸치면 같은 공급 frame을 보유하고 해당 문항의 마지막 backward 뒤 놓는다.

## 5. 판정

선택 위치/순서·원정답/owner·인과 predictor/target·mapping을 보존해야 한다. teacher hidden/head/역투영은 gradient가 없어야 하며 학생/정방향 투영은 독립 참조와 같아야 한다. 오류 뒤 partially accumulated gradient는 재사용하지 않고 전체 update를 폐기한다. source-only cursor를 model/optimizer 재개로 쓰지 않는다.

## 6. 비용

CPU thread1/120초·작은 합성 NPY/학생 frame·head만 사용한다. batch와 문항 내 chunk를 제한하고 교사 full-frame output의 논리 value 수를 사전 제한한다. 실제 Native1024×248320 출력 한 개는254279680값이므로 이를 잘라 작은 어휘 분포로 바꾸지 않는다. 이 value cap은 workspace/두 공간 graph·모델·allocator를 포함한 전체 메모리 보장이 아니다. 학습토큰0·표준300M/풀/품질 σ 해당없음이다.

## 7. 실행

`scripts/test_p106b_dskdv2_window.py`와 필요한 기존 CPU 회귀를101 Stage8fc 새 원로그로 회수한다. 태그 `p106b_dskd_feature_consumer_v1_20261118` 조회 충돌0이다. 모델·학습 launcher는 작성하지 않는다.

## 8. 한계

실제 Native checkpoint·전체 교사 head/학생 body·GPU·독립 corpus/dev/test·품질·전체 trainer/optimizer 재개와 online 공존·75M writer는 NOT_RUN이다. caller가 공급한 frame의 실제 모델 provenance와 실제 backward 수행은 caller가 소유한다. 부품은 모델/optimizer를 로드하거나 step하지 않는다. CE/GradScaler/누적·체크포인트 전체 계약을 대신하지 않는다.

학생 head 두 행렬과 정방향 projector는 학습 가능하면 leaf master tensor로 공급해야 한다. 여러 문항이 하나의 trainable nonleaf 변환 graph를 재사용하면 앞 문항의 마지막 backward가 그 graph를 놓을 수 있으므로 feature 읽기 전에 거부한다. 기존 native_sums가 호출별 정밀도 변환을 소유한다. callback은 문항이 batch 경계에 걸릴 때 같은 body graph를 보존하고 마지막 문항 기여 뒤에 놓는 순서를 소유한다.

## 9. 현재 이력

기존 reader와 bridge/native_sums·원정적 student_cost 및 `_head_logits`의 factored 경로를 읽었다. 새 소비자 CPU 실행은 아직 NOT_RUN이다. 이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.

**실행 회수:** [101§638](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md#p106b-dskd-window-native-math-cpu)의 첫39/0 뒤 leaf master 선결을 추가한 최종40/0·고정 두문항7위치의 전체 분모/손실/미분을 닫았다. 예측은 지지됐고 실제 Native/75M/품질·전체 재개는 미완이다.
