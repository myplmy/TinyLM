# P107 후속: 명시 문서 입력과 실행 연결

2026-11-04. 사용자107의 선행 연구 뒤 미완료 작업 착수 범위이며 원장59를 잇는다. P108의 두 수리 방식은 비채택이다. 같은 시험 문항으로 편집 설정을 더 고르지 않는다.

## 현재 코드와 미완료 부분

ExplicitDocumentSource는 명시 토큰/문서 ID와 정확한 RNG 재개를 이미 제공한다. AdaptiveMNTPTrainer는 목적별 target 정규화·관측 통계·optimizer를 연결하고 HybridTrainingSession과 boundary_store는 스케줄/전체 상태/작은 파일 저장을 제공한다. 실제 Native의 비용·디스크·새 프로세스 재개도 결과107§12~17에 있다. 이 기능들을 다시 구현하지 않는다.

남은 연결은 파일로 된 명시 문서와 토크나이저·TRAIN 입장 근거를 검산해 기존 source에 전달하고, 같은 계약으로 명령을 실행하는 부분이다. 이번에는 제한된 입력 크기의 opt-in 경로를 구현한다. 실제 정제 데이터 편입이나 75M 전체 스트리밍까지 완료했다고 주장하지 않는다.

## 세 안과 결정

| 안 | 방법 | 이점 | 한계·비용 |
|---|---|---|---|
| A, 권장 | 별도 입력 검증 모듈과 opt-in CLI에서 기존 source/trainer/session/store를 재사용 | 기본 학습 동작을 유지하고 허가·SHA·문서 경계를 모델 로딩 전에 검사 | CPU 구현/회귀 약1~2시간. 제한 크기를 넘는 실제 자료는 후속 streaming 필요 |
| B | run100m와 일반 trainer에 새 인자/자료 경로를 바로 추가 | 사용자 진입점은 통합 가능 | 공용 기본·resume·다른 실험 영향이 큼. 현재 범위에서 불필요 |

총괄은 A를 선택한다. 예를 들어 서로 다른 네 문서가 JSONL로 주어지면 각 source_id·토큰 목록·언어·선언한 원문 SHA를 읽고, 파일 SHA/토크나이저/훈련 split을 먼저 확인한다. 문서들을 이어 붙여 경계를 추정하지 않는다. 한 문서를 고른 기존 sampler가 그 안에서만 crop한다. 일반 run100m 기본값에는 연결하지 않는다.

## 영향도

코드는 기존 다섯 구성요소의 호출부만 추가한다. 데이터는 새 독립 JSONL/manifest이며 기존 cache 형식이나 원문을 고치지 않는다. 시험은 잘못된 SHA/토크나이저/split/보호경로/중복 ID/예약 mask/부분 파일/경계 재개를 실제 반례로 차단한다. 정본은 결과107과 P107에 누적하고 P108의 지능 판정과 합치지 않는다. 기술부채는 큰 corpus의 streaming·실제 정제 입장·언어/희귀/숫자 편향·본학습 품질이다.

GPU는 새 전체 smoke와 CPU 성공 뒤 단일 기존 모델의 최대2개 논리 갱신/재개 연결만 확인한다. 현재 배치8·누적16·길이1024라 논리 입력은262144토큰이며 재개 대조 때문에 물리 갱신은 별도 센다. 합성 입력의 작은 풀은 기술 fixture이고 품질 학습 표준을 만족했다는 뜻이 아니다. 일반 optimizer·KD·문맥 일정을 동시에 바꾸지 않는다. 기본 uniform/관측/adaptive 동작은 기존 클래스를 사용한다.

원본 체크포인트는 읽기 전용이고 종료 뒤 파일 SHA와 source를 다시 확인한다. 새 연구 상태는 runs/isolated의 별도 경로에 저장하며 각 조각은16MB 이하이다. 입력 파일은20MB 미만, 총 토큰/바이트도 상한을 둔다. 실제 원문 SHA가 선언돼도 원문을 다시 읽지 않았으면 선언값으로 표시하고 사실/권리/누설 검증으로 승격하지 않는다.

모델 전제·초기화·토크나이저·입력·배치·정밀도·목적·스케줄을 profile에 묶는다. CPU/정적/동적 기술 검증과 지능·전체 학습 효율을 분리한다. 추가300M·새 다운로드/설치·타 정제 본문/프로세스·보호 TinyDataset·기존 모델/로그 변경은0이다. 마감 전에 끝나지 않으면 부분 산출물과 첫 미완료를 원장에 남긴다.

이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.
