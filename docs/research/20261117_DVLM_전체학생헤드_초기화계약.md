# DVLM 전체 학생 어휘 head의 초기화와 미분 계약

사용자158의17시 승인과 미완63에서 PTS/HPA 다음 선결을 준비한다. [DVLM 식5~6·부록A](https://arxiv.org/html/2609.33816v1)에 따라 같은 native token 행은 복사하고 미공유 token은 교사 재토큰 행의 평균으로 초기화하는 구조를 검증한다. 입력 경로의 동치와 학습된 head 품질은 별도다. 현재 CPU1 타이밍 중 소스만 작성하며 실행은 하지 않는다.

| 안 | 이득 | 제약 | 선택 |
|---|---|---|---|
| A, 전체 mapping 먼저 |32K 모든 행의 copy/mean/HOLD와 미지원 byte를 전수 기록 | 한 행이라도 정의되지 않으면 full head 준비는 HOLD | 선택 |
| B, 관측 label 일부만 초기화 | 적은 메모리로 미분 경로 확인 가능 | 전체어휘 softmax의 나머지 행을 정의하지 못함 | 이번 full head 증거로 미채택 |
| C, 미지원 행을 random/zero로 채움 | 전체 shape 생성 가능 | 원 초기화와 다른 정책을 숨길 위험 | 자동 수행하지 않음 |

새 helper는 ordinary native byte와 added-token의 kind/content/선언 properties를 구분한다. 같은 native byte 조각은 단독 UTF-8이 아니어도 공유 행으로 복사할 수 있다. 이는 PTS 표본 입장에서 단독 디코딩 가능한 학생 token만 수락하는 정책을 완화하지 않는다. 공유되지 않은 행은 단독 UTF-8/student decode/teacher encode-decode가 모두 무손실이어야 한다. 미지원 행의 정수 ID·사유를 기록하고 random/zero로 채우지 않는다. 원 토크나이저/모델 어휘를 축소하거나 수정하지 않는다.

새 `scripts/p106b_dvlm_head.py`와6계약만 작성한다. 기존 teacher/head·체크포인트/원로그·PTS 동결 소스·제품/타정제·보호 데이터·설치/Git/삭제는 변경하지 않는다. caller는 전체 map과 exact native teacher head tensor를 받아 별도 학습가능 parameter를 메모리에서 만든다. 원 teacher tensor의 미분과 값은 변경하지 않는다.

코드 축은 새 명시 caller에 한정하고 데이터 축은32K 전체 row/원 다음 target을 보존한다. 검사 축은 shared byte fragment·무손실 mean·added semantics·미지원 HOLD·전체 행 FP64 독립 평균·head-only CE 미분/무변화를 대조한다. 문서 축은 P106B/결과101/목록/방법론/기준표/COMPASS/원장63이며 부채 축은 초기화와 본학습 품질을 구분하는 것이다. GPU/동시작업 축은 CPU1 종료 후 직렬이고 비교 축은 실제 native 출력 head SHA·같은 입력/next target·원 atol1e-5/rtol1e-4다.

후속 실행은 기존 head checkpoint tensor를 명시적으로 읽는 작업이다. 전체 모델을 새로 학습하지 않는다. 실제 Qwen native loader가 관측한 출력 head SHA와 tied 여부를 기준으로 정확한 safetensors key를 고르고, FP32 변환 후 SHA가 같아야 한다. 이름만 보고 embedding/head를 바꾸지 않는다. 원 파일은 전후 hash를 대조한다.

전체 mapping이 수락되고 PTS/HPA native 게이트가 통과한 경우에만 같은 원 student next-target의 hidden으로 별도32K head의 forward/backward를 확인한다. 모든 초기 행을 CPU FP64 mean의 독립 참조와 비교한다. teacher hidden은 detach하고 optimizer update/새 CP 저장은0이다. 이는 미학습 head 초기화와 미분 연결이며 학습 성과·정답률·전체 DVLM 재현이 아니다. 충분한 정식 TRAIN/전체 head 학습·OPD/최종 평가는 기존 선결을 유지한다.

예상 mapping/6계약은 CPU10분 이내, head phase는 GPU/회수 포함10분을 상한으로 후속 profile에 봉인한다. 행/packet은20MB 미만으로 나누고 메모리/시간 실측을 기록한다.16:40 새 모델 계산 중지·17시 소유 실행/기록 회수다. 현재 helper/6시험은 NOT_RUN이며 launcher는 게이트 뒤에 만든다.

이 점검은 알려진 설계 실수만 걸러낸 것이고, 실제로 그런지는 돌려봐야 압니다.

## 현재 CPU 계약과 독립 전체 mapping

2026-11-17 10:34KST의 `Stage7mix0W_cpu_contracts`에서head6/Prism10/DWA12는28개모두통과했고CUDA는초기화되지않았다. DVLM별도v3은원HPA gate음성이므로그hidden으로head학습/미분이나품질을진행하지않는다.

새 `diag_p106b_dvlm_head_map.py`는전체32768개학생token의copy/mean/HOLD mapping만CPU에서기록한다. 원teacher/student tokenizer와기존6계약SHA·v3관측head key/SHA·현재source/시간권한을새profile에봉인한다. 원토크나이저의특수token을숨기지않도록decode는명시skip_special_tokens=false다. 한행도제외/임의채움하지않고HOLD사유와모든ID/teacher행을1MB shard로보존한다. phase10분/회수포함11분·총50MB이며모델/체크포인트tensor읽기·head할당·CUDA·optimizer·CP저장0이다. Mapping완료는입력HPA나학습가능성/품질을대신통과시키지않는다. 미완행이있으면원행전체를남기고별도정책설계전head할당을멈춘다.
