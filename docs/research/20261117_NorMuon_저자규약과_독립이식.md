# NorMuon 저자 규약의 별도 CPU 이식 계약

## 1. 왜

사용자161의 필요한 구현 허가 아래 기존 원장55·56을 이어간다. TinyLM 변형판의 완료300M 음성, AdaMuon CPU/Gloo 결과, 기존 matched optimizer 접점을 다시 실행하지 않는다. [P005b](../../test_plan/P005b_Muon-레시피-정렬과-QK-norm-상한.md)의 공식 구현 대조 미완이 대상이다.

[고정 저자 코드](https://github.com/zichongli5/NorMuon/blob/99f2ac72ee61a0e09514856a6dbaad2ecbdecab6/normuon.py)를 GitHub 읽기 도구로 확인했다. commit99f2ac72ee61a0e09514856a6dbaad2ecbdecab6, blob1b87c80b2dea0a4bb21102703e30fdadde4754e1, SHA256706c1a35fb35342f6ff207f8310b814a1c8f55c6ffba0e843537db434a696141이다. 설치하거나 원본 라이브러리 전체를 저장하지 않고, 기존 코드와 공개 수식에서 별도 구현한다. ## 2. 질문

저자 단일/분산 행렬 전용과 보조Adam 결합 네 인터페이스의 수치 규약을 FP32 master에서 보존하는가? 기존 TinyLM 변형의 None skip·행별상태와 다른 점이 드러나는가?

## 3. 예측

같은 수식·NS 연산 순서에서는 독립 reference와 원값 일치를 기대한다. 기존 변형과의 동률이나 품질 향상은 예측하지 않는다. 잔여 모멘텀이 있는 None gradient와 4D 축에서는 동작 차이가 예상된다. 분산 통신을 바꾸므로 속도 재현은 기대하지 않는다.

## 4. 단계

1. 고정 원코드 AST의 함수·클래스·기본값/상태 규약과 해시만 감사한다. 원 라이브러리 설치/전체 원본 저장은 하지 않는다.
2. EMA 모멘텀·gradient의 Nesterov 제자리 변경, BF16 NS 뒤 FP32 복귀, 마지막축 V·마지막두축 norm·원 shape 크기를 별도로 구현한다. None은 zero gradient를 만들고 상태/모멘텀 업데이트를 계속하되 그 step의 WD만 생략한다. 보조Adam도 None의 step/모멘텀을 유지한다.
3. 네 종류를 공통 helper로 구현한다. FP32 master, 명시 `use_muon`, 중복 없는 고정 topology, 입력/상태의 전수 선검사, method/rank/world/topology 재개 계약을 추가한다.
4. 분산은 이미 초기화한 default process group만 받는다. 원코드의 형상별 all_gather 대신 소유 rank의 한 parameter씩 broadcast한다. 분산형의 shape 내림차순 정렬/round-robin 소유와 상태 분할은 유지하되, 이 통신을 원코드 그대로 또는 FSDP2 구현이라고 부르지 않는다. 보조Adam 상태는 원코드처럼 rank마다 복제한다.
5. 합성 CPU 단일 수식·상태/None/4D·save/load를 먼저 닫는다. 이후 별도 두 CPU Gloo rank에서 상한45초로 검증한다. localhost socket이 차단되면 실제 실패를 보존하고 허용 범위의 별도 호스트 승인을 확인한다. GPU로 대체하지 않는다.

## 5. 판정

독립 수식과 weight/momentum/V 및 gradient side effect, 직렬화 뒤 다음 update가 일치해야 한다. NaN·잘못된 method/rank/state는 쓰기 전에 거부한다. 후반 산술 오류의 전역 rollback은 보장하지 않는다. None gradient를 skip하는 기존 변형판과 다르다는 사실을 유지한다.

## 6. 비용

기존 tlm_torch의 작은 CPU tensor, thread1, 단일 시험120초/각 Gloo45초 상한이다. matrix FP32 상태는 2D에서4m(n+1) bytes다. 4D는 원코드의 V 축을 직접 세며 2D 공식으로 대신하지 않는다. 보조Adam 두 moment·임시계산·통신비용은 별도다.

## 7. 실행

새 CPU 시험만 runlog078 Stage20W로 회수한다. 새 학습 SH/실제모델 실행 명령은 이 단계에서 만들지 않는다.

## 8. 한계

네 클래스의 FP32 수치 대응과 CPU 통신 대조가 목표다. BF16 master·희소/비연속/혼합 device·동적 parameter group·FSDP2/NCCL·Native trainer 연결·전체wall/지능은 미검증이다. 외부 라이브러리를 설치한 exact port라고 하지 않는다. 기본 Muon RMS4는 유지한다.
