# 2026년 11월 1일 자율주도 연구 최종보고

이번 연구에서 TinyLM의 일반 지능이나 일상대화가 좋아졌다는 성과는 확인하지 못했다. 실제 성과는 기존 모델의 공식 평가를 전량 마쳐 성능 한계를 수치로 확인하고, 다음 본학습에 필요한 적응형 통계·문서 경계·교사 손실·정확 재개를 연결해 비용과 정합성을 측정한 것이다. 추가300M과 정제 미완 자료의 편입은 하지 않았다.

## 1. 작업 범위와 선택 근거

총괄 GPT가 /home/uranus/tinyLM에서 사용자104의11시·VRAM8GB 범위와 사용자105의15시·여유VRAM 범위를 이어 수행했다. 새 보조 에이전트는 호출하지 않았다. 다른 세션이 원천을 정제 중이고 정제 해결 전 추가300M이 금지돼 있어, 아직 준비되지 않은 자료로 본학습을 반복하는 대신 열린 원장의 공식 평가와 학습 연결 선결을 우선했다. 본학습 전 소규모 성과로 방법론의 우열을 정하지 않는 지시도 유지했다.

15시 이후 사용자106은 A 검사 범위 수정·필요 CPU 검증·한국어 로컬 커밋·보고만 승인했다. 이 구간에는 GPU·모델·전체 스모크·새 연구를 실행하지 않았다. 마지막 소유 GPU 작업은 오후 연구 허가창 안에 종료했고 실제 원로그와 독립 검산을 보존했다.

실험 수치와 원로그 정본은 [결과101 §§563~579](../../test_result/101_20260927_P106B-번역9건으로-문턱미달-학생학습0.md)와 [결과107 §§10~17](../../test_result/107_20261027131747_P107-가시성과-shift는-검산됐고-학습효과는-미확인.md)다. 앞선 [오전 결과안내](20261101_정제외_독립연구_결과안내.md)와 [오후 결과보고](20261101_오후_독립연구_결과보고.md)는 각 작성 시점의 상태를 보존한다.

## 2. 기존 모델의 지능 수준을 어떻게 확인했나

## 4. 문서 경계와 전체 상태 재개

문서가 섞이거나 scheduler/source 위치가 재개 중 바뀌면 이후 본학습 비교가 무효가 될 수 있어 이 선결을 우선했다. CPU token tensor와 고유 문서 ID를 명시적으로 받고 한 문서 안에서 crop하며, PAD는-1로 구분했다. EOS로 문서 경계를 추정하지 않는다. 문서 균일 복원추출은 과거 토큰 균일 추출과 다른 분포라고 명시했다.

micro8×accum16·길이1024·checkpoint-on·BF16 AMP/FP32 master·Muon RMS4/AdamW와 cosine/warmup을 고정했다. 합성4문서에서2회→저장→계속2회와 복원2회를 비교한6회 물리 업데이트의 모델·optimizer·정책·source·RNG·LR·손실이 모두 정확히 같았다. 저장781,352,215B는49개16MB 이하 조각으로 나누고 manifest를 마지막에 확정했다. 저장3.49초·복원2.17초였다.

별도 새 프로세스가 같은 snapshot을 읽기 전용으로 복원해2회만 이어 수행한 시험도 옛 계속 경로와 전체 상태가 같았다. 동일 프로세스 메모리 복사만 확인했던 상태에서 실제 디스크·새 프로세스 재개까지 근거가 확장됐다. 실제 정전·전원 손실은 시험하지 않았다. 연구 snapshot 하나를 로컬에 유지했고 사용자 체크포인트는 삭제하지 않았다.

## 5. causal-only 교사 KL을 연결한 이유와 비용

causal 학생이 교사를 활용할 접점이 빠져 있었으므로 기존 _kd_kl을 재사용했다. causal 배치만 CE+0.1×KL(T1), masked 배치는 기존 CE를 유지한다. 교사는 eval/frozen이며 같은 tokenizer/어휘·teacher SHA·계수·정규화 계약을 상태에 결합했다. 미래 문맥이 보이는 mask, 학생과 parameter/storage 공유, 다른 교사·계수·schema의 재개는 거부한다.

교사 None 기본 경로는 변경 전 모듈과4회 학습의 전체 상태가 비트 단위로 같았다. 같은 동어휘 Native 교사를 두 조건 모두 상주시켜 None/KL/KL/None 네 블록을 각4회 수행하고 각 첫 회를 제외했다.

| 항목 | None | causal KL | 추가 비용 |
|---|---:|---:|---:|
| 업데이트 중앙값 |9.3486초|12.4658초|+33.34%|
| 최대 reserved |7,012,876,288B|8,491,368,448B|+1,478,492,160B|

교사 상주 자체의 allocated 약373MB는 위 추가분과 중복 계산하지 않는다.16업데이트·교사64forward의 반복 경로와 교사 가중치/gradient 불변을 확인했고 새 파일 checkpoint는0이었다. 이 Native 교사는 기술 비용용 대조이며 더 좋은 지식의 교사가 아니다. Gemma cross-tokenizer 지식 이전·KL의 실제 지능 효과·GPU KD 재개·생산 CLI는 아직 미완이다.

## 6. 반복·캐시와 평가 준비의 잔여

긴 반복 이력의15점에서 cache/재계산 로짓·선택은 같았지만 일부 V의 엄격 기준은8건 음성이었다. 출력 선택이 같다는 이유로 이 문턱을 낮추지 않았다. 이 관찰만으로 반복 원인이 KV 또는 공유 MLP 하나라고 확정하지 않는다.

KoBEST는 공식5과제4561test와 CPU 계약을 준비했다. 평가 환경의 evaluate·scikit-learn·scipy·joblib·threadpoolctl이 없어 모델 점수는 미실행이다. 기존 승인에서 새5패키지 설치 권한을 추정하지 않았다. PrismPTQ·Qwen35의 별도 백엔드/수치 선결과 P014E의 실제 고속 커널도 미완 원장에 남긴다. 기존 느린 packed 참조 구현을 새 가속 커널처럼 중복 구현하지 않았다.

## 7. 15시 이후 승인 A와 검증 한계

앞선 소유 정적 어댑터가 검사기 내부의 넓은 scripts 판독까지 제한한다고 판단한 것이 잘못이었다.69PASS/2ERROR/6NOT_RUN 원형과 간접 열람 사고를 보존했다. 정확한 과거 파일별 open 수는 미확인이며, 상대 전용 자료를 다시 열어 추적하지 않았다.

A에서는 사용자 기본 USER_GLOBAL을 유지하고, manifest+SHA를 함께 준 경우만 OWN_SCOPED를 사용한다. 검사 전에 명시 파일과 조상만으로 디렉터리 view를 만들고, 저장소 밖 범위나 누락 의존성에 조용히 fallback하지 않는다. 파일 접근을 잡아 무시해도 거부 영수증이 있으면 실패한다. 명시 Python 자식·손자에도 범위를 전달하며 native/shell·미등록 실행은 거부한다. Python audit은 OS 보안 sandbox가 아니다.

실제160입력의 여섯 원형 검사에서 최초5PASS/1ERROR를 보존하고 수집기 오류를 수정해6PASS/0ERROR/71NOT_RUN을 얻었다. 화이트리스트의 과거 선언 위치만 믿어 정상 재사용 플래그13개를 놓친 것이 원인이었고, 선택 파서의 실제 플래그에 해당하는 기존 등급도 수집하도록 수정했다. 원본 표와 원래 missing/stale/grade/evidence 판정은 유지했다.

CPU는 원래 검사기의 소유 결함 검출·제외 canary 거부·오류를 잡아도 실패·Python 자식/손자·누락 영수증·원본 인수/검사 목록 보존을 검증했다. 관련21·기본 정적9·기존 smoke 계약46·WIP31시험은 각각0이었다. 소유 영수증은 별도 schema를 사용해 기존 전역 WIP 종결 증거로 수락되지 않는다. 스모크의106행동·44자식·33학습 명령은 CPU에서 그대로임을 확인했다. 실제 새 전체 스모크는 수행하지 않았으며 현재 source의 전역 PASS·모델 품질·환경 E2E 완료를 주장하지 않는다. [구현 계약](20261101_A_검사입력범위_구현계약.md)과 [명시 입력 A 감사](../../handoff/audit/nov01_scope_a/OWNED_STATIC_v3.json)가 근거다.
