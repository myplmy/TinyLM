## 0. 결론

> **현재 증거는 “Qwen/Gemma로 KD해도 TinyLM 지능이 늘지 않는다”를 확정하지 않는다.**
> Qwen3-0.6B-Base는 동일 토크나이저·동일 학생 형상의 무교사 대조군보다 공통 영문 원문에서
> **−0.0077 bpb** 좋은 방향이었으나, 저장소의 기존 실무 분해능 **0.008 bpb** 바로 아래인 단일 시드 결과다.
> 이 0.008은 Qwen 조건의 측정 표준편차가 아니라 과거 native 조건에서 정한 실무 규칙이므로 새 원문·seed에서 다시 보정해야 한다.
> Gemma 3 270M은 **250-step backward·메모리 probe만 완료**됐고 full-budget 품질 결과가 없다. 더구나 `grad_max`가 무KD `GT0probe` 36.9, KD 118.8/488.8로 기존 `>10` 안정성 gate를 모두 실패했다.

향상이 작아 보이는 가장 큰 이유는 교사 크기 하나가 아니라 다음 문제가 겹쳤기 때문이다.

1. 현재 외부 KD는 **Base/PT 교사의 raw next-token 분포를 4스텝 중 1스텝만** 따라가는 token-level forward KL이다. 지식 QA·추론·지시이행을 직접 가르치는 목표가 아니다.
2. Qwen/Gemma 체크포인트를 정확한 외부 토크나이저로 재는 downstream 평가 경로가 없어, 지금까지의 핵심 판정은 **영문 SQuAD common-bpb 하나**에 의존한다.
3. 교사 토크나이저를 학생에 통째로 이식해 학생 파라미터가 native 약 **63.5M → Qwen 94.0M → Gemma 122.2M**으로 늘고, 부모초기화 호환성과 배포 메모리 효율을 잃었다.
4. 같은 데이터의 CE, 교사의 해당 과제 우위, 학생-교사 agreement/entropy, CE와 KD gradient의 충돌을 측정하지 않아 “교사가 무엇을 얼마나 더 잘 아는가”가 확인되지 않았다.
5. 내부 실험상 더 큰 효과는 이미 **부모초기화, 데이터 정제, 깊이**에서 관측됐다. KD만 고집하는 것은 우선순위가 아니다.

따라서 권고 순서는 **평가 복구 → 완전한 대조군 → 직접 유사한 pretraining-KD 저비용 비교 → 계산량을 맞춘 sequence-SFT pilot → 조건이 갖춰진 on-policy/cross-tokenizer 증류**다. 동시에 비KD 축인 **부모초기화·고품질 데이터·깊이/재귀·SFT/선호학습**을 병행해야 한다.

## 1. 여기서 “지능 향상”이 뜻하는 것

서로 다른 개선을 한 숫자로 섞지 않는다.

| 층 | 정의 | 주 지표 | 주의 |
|---|---|---|---|
| **언어모델 품질** | 다음 토큰 예측과 텍스트 압축이 좋아짐 | 동일 캐시 CE, 공통 원문 bpb | bpb 개선만으로 추론·지식 향상을 주장할 수 없다 |
| **내재 능력** | 상식·언어이해·추론·한국어 개념관계·지시이행이 좋아짐 | HellaSwag, PIQA, ARC-e, 검증된 TinyDataset held-out, 생성형 규칙 채점 | 반드시 정확한 체크포인트 토크나이저와 다중 시드가 필요하다 |
| **행동 정렬** | 질문 형식 준수, 간결한 답, 선호되는 응답 | SFT/선호 평가, IFEval류 | base-LM KD와 다른 학습 단계다 |
| **시스템 능력** | RAG·도구·test-time compute로 정답률이 오름 | end-to-end 과제 성공률 | 모델 파라미터 자체의 지능과 분리 보고해야 한다 |

P082의 성공 판정은 **내재 능력**을 1차로 하고, CE/bpb는 보조·회귀 방지 지표로 둔다.

## 2. 저장소 실사 결과

### 2.1 현재 KD 구현이 실제로 하는 일

실제 호출 경로는 `run100m.py` → `tinylm/cli.py` → [`trainer.py`](../tinylm/train/trainer.py)다.

- [`_kd_kl`](../tinylm/train/trainer.py)은 교사 분포 `p_t`와 학생 분포 `p_s` 사이의 **full-vocabulary forward KL `KL(p_t || p_s)`**를 계산하고 `T²`를 곱한다.
- 학습 손실은 `L=(1-α)L_CE+αL_KD`다. 외부 교사는 [`HFTeacher`](../tinylm/train/hf_teacher.py)로 불러오며 KL 청크에서 fp32로 계산한다.
- P067 Qwen/Gemma 조건은 `α=0.5`, `T=2`, `kd_every=4`다. 2,289스텝 중 교사 forward는 **573회(약 25%)**다. 단순 계수 평균으로 보면 4스텝당 CE 가중치는 0.875, KD 가중치는 0.125지만, 실제 gradient 기여는 측정되지 않았다.
- 학생과 교사는 같은 입력 crop을 본다. **학생 생성 prefix, 정답/오답 쌍, rationale, hidden state, attention, sequence reward**는 쓰지 않는다.
- `HFTeacher`는 vocab size는 검사하지만 **tokenizer 파일 hash, id↔token 매핑, special-token id의 동일성**은 검사하지 않는다.

즉 현재 방법은 “교사의 지능을 전수”하는 포괄적 증류가 아니라 **일반 원문에서 교사의 다음-token 확률표를 일부 스텝 모사**하는 실험이다.

### 2.2 내부 dense 교사: 300M 예산에서는 명확히 해로웠다

근거는 [결과 038](../test_result/038_20260808_P050-부모초기화가-전부다-KD는-0이다.md),
[결과 042](../test_result/042_20260813_P055-단계0-KD감사-A1만-유효하다.md),
[REVIEW2 확정](review/202608140900_2차리뷰_초안_KD표준조건과-메모리레버-종합.md)이다.

| 관측 | 결과 | 판정 |
|---|---:|---|
| 부모초기화의 loss 감소 기여 | **0.1386** | 큰 효과 |
| KD 단독 loss 감소 기여 | **−0.0032** | 절대크기는 부모초기화보다 43배 작고, 부호는 **악화 방향**(loss +0.0032) |
| 같은 초기화에서 무KD vs KD | **3.6776 vs 3.6984** | KD가 **+0.0208** 나쁨 |
| 두 번째 시드의 KD 대가 | **+0.0219** | 재현됨 |
| 무KD 시드 차 | **0.0017** | KD 대가보다 훨씬 작음 |
| 학습 reserved VRAM | **12.47 → 5.07 GiB** | KD 제거가 −59% |

α sweep도 `α=0/0.1/0.3/0.5/0.7`에서 full-val `3.6776/3.6776/3.6856/3.6984/3.7156`로 단조 악화했다. 다만 과거 **100M 토큰 예산에서는 KD가 −0.110 이겼다.** 결론은 “KD는 항상 해롭다”가 아니라 **교사·예산·학생 용량에 조건부**다.

### 2.3 Qwen3-0.6B-Base: 작은 양의 신호, 결론은 미확정

[P067 결과 053](../test_result/053_20260822_P067-단계0a-두-최신-소형모델은-KV를-버리고-있다.md)의 같은-tokenizer 비교:

| 팔 | 교사 | Qwen tokenizer | same-cache/Qwen-tokenized val CE | 공통 영문 bpb |
|---|---|---|---:|---:|
| `QT0` | 없음 | 사용 | **3.4762** | **1.3440** |
| `Q256T` | Qwen3-0.6B-Base | 사용 | 3.4796 | **1.3363** |
| 차이(KD−무KD) | | | **+0.0034** | **−0.0077** |

- 같은 캐시 CE는 KD가 약간 나쁘고, 공통 원문 bpb는 약간 좋다. 두 지표가 상반된다.
- −0.0077 bpb는 기존 native 조건에서 쓰던 실무 분해능 0.008의 96%로 **좋은 방향이나 서열 미확정**이다. 이 조건의 σ를 측정한 값은 아니므로 새 비중복 corpus·3 seed에서 실무 임계값을 재추정한다.
- 단일 시드이고, HellaSwag·PIQA·ARC-e·한국어·TinyDataset 능력 평가는 없다.
- native `mC_initonly_nc`의 공통 bpb 1.3075보다 Qwen 계열 최선 1.3363이 나쁘지만, 토크나이저·어휘·부모초기화·파라미터 수가 함께 달라 **KD 효과 대조군은 `QT0`뿐**이다.

따라서 “향상이 없었다”보다 정확한 표현은 **“압축률의 작은 양의 신호가 있었으나 지능 평가는 아직 불가능하고 통계적으로도 미확정”**이다.

### 2.4 Gemma 3 270M: 품질 결과가 아직 없다

P067의 250-step probe 결과:

| 팔 | micro/accum | reserved | 250-step 시간 | full 예상 | `grad_max` | skip |
|---|---|---:|---:|---:|---:|---:|
| `G270Tprobe` | 2/64 | **14.77 GB** | 57.7분 | **약 8.8시간** | 118.8 | 0 |
| `G270Tnarrow` | 1/128 | 8.97 GB | 85.9분 | 약 13.1시간 | 488.8 | 0 |

무교사 `GT0probe`도 `grad_max=36.9`(warmup peak 88.7), skip 0이었다. 따라서 이는 **forward/backward 실행성과 비용 측정**이지 품질 판정이 아니며, 수치 불안정을 KD/교사 탓으로 귀속할 수도 없다. Gemma-vocab 학생·짧은 probe·학습 설정의 공통 문제인지 matched 대조가 필요하다. 모든 팔이 저장소의 `grad_max>10` gate를 넘었으므로 **수치 안정성 gate는 실패**했다. full run 배치
[`run_P067_stage2_gemma270m_full.bat`](../run_P067_stage2_gemma270m_full.bat)는 존재하지만 결과·로그·체크포인트는 없다. 더구나 그 배치는 Gemma KD 팔과 native `mC_initonly_nc`만 비교하고 **동일 Gemma tokenizer의 full-budget 무KD `GT0full`을 만들지 않는다.** 따라서 실행하더라도 교사 효과를 분리할 수 없다.

결론: **Gemma 270M의 KD 품질은 미실행이며, matched 무KD 원인 분리·안정화와 `GT0full` 없이 `G270Tfull`을 실행·해석하면 안 된다.**

### 2.5 지금은 외부-tokenizer 모델의 “지능”을 제대로 재지 못한다

- [`common_bpb.py`](../scripts/common_bpb.py)만 `--tokenizer-hf TAG=PATH`를 지원한다.
- [`eval_bench_suite.py`](../scripts/eval_bench_suite.py), [`eval_korean_bench.py`](../scripts/eval_korean_bench.py), [`generate.py`](../tinylm/infer/generate.py)는 `tokenizer_path(data)`로 native tokenizer를 고정 로드한다.
- 따라서 Qwen/Gemma tokenizer 학생에게 native tokenizer를 잘못 적용하거나 평가 자체를 못 한다.
- P069의 13종 벤치에서 현재 native 모델은 HellaSwag·PIQA·ARC-e만 우연 수준을 넘었다. MMLU는 우연, BoolQ는 다수결 미만, BFCLv3는 0%였다. 이 상태에서는 손실 변화와 지능 변화를 분리해야 한다.

또한 `common_bpb.py`의 실제 정본 원문은 `datasets/squad/train-v2.0.json`인데, P075의 12% overlap 진단 명령은 `dev-v2.0.json`을 사용했다. **dev의 12%를 train 정본 오염률로 그대로 옮길 수 없다.** 실제 train-v2.0을 다시 감사하고, 가능하면 학습 코퍼스와 비중복인 영문·한국어 공통 원문을 추가해야 한다.

### 2.6 학습 데이터가 목표 지능 신호를 제공하지 않는다

현재 CLI는 `ko-en`, `ko-edu-en`, `ko`, `en`, `synthetic`만 받고, [`prepare.py`](../tinylm/data/prepare.py)는 원문 `text`를 flat binary stream으로 만든다. [`loader.py`](../tinylm/data/loader.py)는 임의 연속 crop `(x,y)`만 반환한다.

반면 [`stage1_train_900_v2.json`](../datasets/TinyDataset/stage1_dataset/train_v2/stage1_train_900_v2.json)은 900개 record에 `concepts`, `relations`, `paraphrases`, 구조화된 `near_negatives`, `violated_relation`, `why_wrong`를 갖지만 trainer가 읽지 않는다. 즉 현재 모델은 이 풍부한 필드를 **학습 신호로 전혀 쓰지 않는다.** SFT용 example boundary와 assistant-only loss mask도 학습 경로에 연결돼 있지 않다.

native tokenizer에는 현재 PAD/BOS/EOS만 확정돼 있다. [`chat/serialize.py`](../tinylm/chat/serialize.py)의 reserved role-token 전제와 `train_thinking=False` 학습 경로는 P075 완료 전 사용할 수 없다. 현 tokenizer의 평문 경계 문자열로 pilot하면 부모초기화를 보존할 수 있지만, P075 새 tokenizer를 택하면 embedding/head row mapping 또는 새 부모가 필요하다.

### 2.7 cache·checkpoint provenance도 확증 수준이 아니다

- cache 재사용은 이름/token 수 중심이라 `exact=False`에서 tokenizer·filter·raw manifest가 다른 cache가 잡힐 위험이 있다. P082는 `--exact-cache`와 전체 identity hash hard fail이 선결이다.
- 현재 checkpoint는 tokenizer ID/revision/hash를 내장하지 않는다. legacy sidecar에는 내부 `kd_teacher`와 실제 `kd_teacher_hf`가 함께 남을 수 있어, 기존 Qwen artifact는 재평가 가능성과 인과 확증 재사용 가능성을 구분해야 한다.
- [`kd_cache.py`](../tinylm/train/kd_cache.py)는 외부 HF teacher cache를 만들지 못하고 metadata 검사도 불완전하다. naive top-k retained mass는 tail 없이 편향되므로 그대로 쓰지 말고 tail-preserving objective 또는 unbiased sparse sampling을 먼저 검증한다.

## 3. 왜 기대한 지능 향상이 작았는가

| 원인 | 현재 증거 | 개선 방향 |
|---|---|---|
| **목표 불일치** | generic next-token FKL만 사용 | 과제 전문 teacher, sequence/rationale, on-policy 오류 교정 |
| **평가 불일치** | 외부 tokenizer downstream evaluator 없음 | 평가 배선이 첫 선결. bpb와 능력을 별도 판정 |
| **KD 신호가 희박함** | k4로 25% step만 교사 사용 | `every={1,2,4}`를 비용과 함께 비교. gradient 비율 실측 |
| **온도·α 미탐색** | 외부 좋은 교사는 `α=.5,T=2` 한 점 | `T={0.5,1,2}`, 낮은 α, JSD/skew-KL 포함 |
| **teacher advantage 미측정** | 교사 자신의 동일 과제 점수·entropy 없음 | 교사가 학생보다 실제로 나은 위치만 가중 |
| **용량 격차** | 63~122M 학생과 270/600M 교사 | 큰 교사가 항상 최적은 아님. Q/G 비교는 family 전체효과만 말하며, size-only 비교·동일 계보 teacher assistant는 별도 설계 |
| **tokenizer 교락** | native 32k를 151,936/262,144로 교체 | 같은-tokenizer 대조군 유지 또는 native tokenizer cross-token/sequence KD |
| **부모초기화 상실** | 외부 vocab shape 때문에 SVD/parent init 불가 | native-tokenizer sequence KD가 배포 후보에 더 적합 |
| **데이터 신호 부족** | 관계·오답·rationale 미사용 | 검증된 고밀도 데이터와 hard negative를 실제 objective에 연결 |
| **단일 시드·오염 위험** | Qwen 한 seed, SQuAD split 불일치 | 3 seeds, item-paired bootstrap/McNemar, 실제 평가 원문 overlap audit |

선행연구도 같은 경고를 준다.

- MiniLLM과 GKD는 학생이 실제로 생성하는 prefix에서 교사 피드백을 받아 **train–inference 분포 차이**를 줄인다. 단순히 `KL(student||teacher)`로 부호만 뒤집는 것이 아니다.
- DistiLLM은 skew-KL과 학생 생성 출력을 재사용하는 adaptive off-policy를 함께 쓴다. fixed teacher-forced skew-KL 하나만 구현해 DistiLLM 재현이라고 부르면 안 된다.
- TinyLM의 현재 조건과 가장 가까운 ACL 2025 pretraining-distillation 설계공간 연구는 logits 처리·loss·온도·교사/학생 규모·online/offline을 함께 보며, 큰 교사가 항상 낫지 않음을 보고한다. 해당 1.9B급/100B-token 조건에서는 high-α, `T=0.5`, max-LR 구간의 높은 KD 비중을 포함한 WSD schedule이 강했지만, 저장소 내부 300M α sweep은 반대였다. 따라서 low/high α를 모두 bounded screen하고 그대로 외삽하지 않는다.
- CoNLL-BabyLM 2024의 44M/58M 연구는 작은 교사·학생에서도 단순 KD로 더 큰 BabyLlama와 유사한 성능을 더 적은 시간·파라미터로 낼 수 있음을 보였고, 복잡한 contrastive/adversarial 변형은 단순 KD를 명확히 넘지 못했다. 다만 10M-word 영어 workshop 단일 설정이므로 Qwen/Gemma 결과를 보장하지 않는다.
- ACL 2025 capacity-gap 연구는 **더 큰 교사가 항상 더 좋은 학생을 만들지 않으며 최적 교사 규모가 존재**한다고 보고한다.
- ACL 2025 generalization-vs-fidelity 연구는 teacher 전체 성능보다 **해당 과제 전문성**이 중요할 수 있고, 정확도 개선과 teacher reasoning fidelity가 분리될 수 있음을 보고한다.
- 작은 학생은 긴·강한 reasoning trace를 그대로 배우기 어려우며, 짧고 쉬운 trace와 일부 강한 trace를 섞는 편이 낫다는 결과가 있다.

## 4. KD 개선 방향

### 4.1 0순위: 평가와 실험 정합성을 먼저 고친다

1. 외부 tokenizer resolver를 생성·HellaSwag·PIQA·ARC-e·한국어·TinyDataset 평가에 공통 연결한다.
2. checkpoint에 tokenizer ID·파일 hash·vocab size·special-token IDs를 저장하고 로드 시 검증한다.
3. Qwen/Gemma 교사를 학생과 **동일한 prompt·shot·길이·채점기**로 먼저 평가한다.
4. Qwen은 `QT0`, Gemma는 full-budget `GT0`를 직접 대조군으로 둔다. native 모델과의 비교는 배포 관점 보조 비교일 뿐 KD 인과효과가 아니다.
5. seed 3개, 동일 raw document IDs, per-item 결과, paired bootstrap/McNemar와 평균·분산을 기록한다.
6. `train-v2.0` 실제 overlap을 다시 재고, 비중복 공통 영문·한국어 eval을 고정한다.

### 4.2 같은-tokenizer logit KD를 저비용으로 다시 찾는다

기존 FKL을 기준으로 다음만 단계적으로 비교한다.

- divergence: forward KL, reverse KL, generalized JSD, skew-KL
- temperature: `0.5/1/2`
- KD 빈도: `every=1/2/4`
- α: `.25/.5/.9`를 안전 gate 안에서 비교하고, 명목값뿐 아니라 **CE/KD gradient norm 비율**로 해석
- token weighting: raw pretraining에서는 teacher가 학생보다 낮은 held-out token NLL/높은 target margin을 보이는 토큰만 가중. 정답 verifier 기반 가중은 task-tagged sequence 데이터에만 사용
- schedule: 고정 α뿐 아니라 max-LR 구간 high-KD→decay/CE-anchor WSD-α와 LR schedule의 추가 몫을 분리
- teacher target: full distribution FKL과 teacher top-1 NLL(sequence-level top-1과 구분)을 직접 비교

매 step/평가마다 teacher entropy, top-k mass, student-teacher agreement, CE/KD gradient norm·cosine, domain/language slice를 기록한다. `k4→k1`은 교사 비용이 약 4배가 되므로 신호를 확인하기 전 자동 채택하지 않는다.

### 4.3 mixed on-policy KD

학생 prefix 비율 `λ={0.25,0.5}`부터 시작해 교사가 학생 오류 상태에 피드백하게 한다. CE anchor를 유지하고 JSD 또는 RKL을 비교한다. 길이 급감, 반복, 조기 EOS, 무의미한 짧은 문자열을 별도 gate로 막는다. 다만 GKD의 직접 검증 조건은 prompt→response와 일정 품질의 SFT 학생이다. generic raw-document crop에 적용하려면 prefix/continuation 경계·rollout 길이·정답 crop CE를 별도로 정의해야 하며, 그렇지 않으면 GKD 재현이 아니라 새로운 pretraining 외삽이다.

중요: **기존 입력에서 KL 방향만 뒤집은 구현을 MiniLLM이라고 부르면 안 된다.** 학생 rollout, sequence-level 보정과 안정화가 포함돼야 한다.

### 4.4 sequence/rationale 증류

지능 향상 목표에는 raw Base/PT logits보다 다음 경로가 더 직접적이다.

1. Qwen/Gemma의 instruct 계열 또는 검증 가능한 prompt를 사용해 짧은 답·설명을 생성한다. 각 교사의 **공식 chat template**로 생성한 뒤 결과만 native student 형식으로 canonicalize한다.
2. n-best 생성 후 정답 검증, 중복 제거, 길이·언어·형식 필터를 통과한 것만 쓴다.
3. 100M급 학생에는 **짧고 단순한 trace 80~95%, 긴/강한 trace 5~20%**부터 비교한다. 이 비율은 선행연구의 방향을 보수적으로 외삽한 시작점이며 정답이 아니다.
4. TinyDataset의 `paraphrases`는 불변성 학습, `near_negatives`와 `why_wrong`는 pairwise/listwise·margin·preference 신호로 사용한다.
5. 같은 source ID·수락 문항 교집합·assistant token 또는 총 compute를 맞춘 **무추가학습 / reference·gold SFT / teacher answer-only / teacher rationale** 대조를 둔다. rationale 유무·위치·길이를 ablation하고, 성능 향상을 곧바로 “교사의 추론 과정 복제”로 해석하지 않는다.

### 4.5 native 32k tokenizer를 보존하는 cross-tokenizer 경로

큰 교사 vocab 이식은 파라미터·softmax·메모리 비용을 키운다. 배포 후보는 native tokenizer와 부모초기화를 보존하는 편이 유리하다.

권고 순서는 다음과 같다.

1. **sequence KD/SFT**: 가장 단순하고 어휘 정렬이 필요 없다.
2. **ALM**: 같은 원문 span/chunk의 likelihood를 근사 정렬한다. 구현 단순성·비용을 우선하는 prototype 후보이지, TinyLM에서 성능 우위가 입증된 순위는 아니다.
3. **DSKD/CDM/DWA-KD/BLD**: hidden/output space, contextual mapping, time-warp, byte interface를 비교한다. DSKD는 120M 학생 실험이 있어 규모 근거는 ALM보다 직접적이지만 projector·attention 비용을 먼저 재야 한다.
4. **ULD**: tokenizer 차이를 `O(V log V)`의 정렬된 확률 비교로 다루지만 full-vocab 분포 비용, 같은 시점 token 위치/min-length 정렬, 의미 mapping 부재가 Qwen/Gemma 조건의 핵심 한계이므로 후순위다.

cross-tokenizer 연구의 조건은 제각각이다. DSKD에는 GPT-2 120M 학생 근거가 있지만 다른 최신법의 주요 실험은 더 큰 모델·instruction/task 환경이다. **63~122M ternary TinyLM에 그대로 성립한다고 가정하면 안 된다.**

### 4.6 teacher assistant는 마지막 단계다

교사-학생 용량 격차가 실제 병목으로 확인됐을 때만 **큰 교사에서 먼저 증류해 만든 동일 계보의 중간모델**을 다시 TinyLM의 교사로 쓰는 다단계를 비교한다. off-the-shelf Gemma 270M은 Qwen 0.6B에서 증류된 모델이 아니므로 Qwen의 teacher assistant가 아니라 **독립적인 작은 직접 교사 후보**다. Qwen과 Gemma의 단순 비교도 tokenizer·pretraining data·family·학생 형상이 함께 달라 capacity-gap 검증이 아니다. 같은 family의 teacher scale이나 능력/entropy를 통제한 별도 설계가 필요하다.

## 5. KD 외의 지능 개선 방향

### 5.1 우선순위가 높은 저장소 실측 레버

| 레버 | 저장소 실측 | 해석 |
|---|---:|---|
| **부모초기화** | loss 감소 기여 **0.1386** | 현재 외부-vocab KD 신호보다 훨씬 큼 |
| **SEO 스팸 필터 학습** | common bpb **1.5182→1.4124**, −0.1058 bpb | 데이터 품질이 아키텍처/KD보다 큰 효과를 냄. 단 SQuAD 오염 재감사 필요 |
| **표준 `ko-en` 스팸 감사** | 366,819문서 중 6개, 문자 0.06229%, 예상 −0.00098 nats | P047에서 기준선 안전·필터 재학습 불필요로 종결. 위 큰 필터 효과를 현재 표준 corpus에 외삽하지 않음 |
| **깊이 증가** | d8/d12/d16/d20: **3.6776/3.6130/3.5757/3.5418** | 20층까지 포화하지 않음. d12~d20은 일부 단일 시드이고 task 지능 평가는 남음 |
| **재귀** | native HellaSwag 30.0→33.7, PIQA 51.7→53.7 | downstream 양의 신호. “reasoning”인지 단순 용량인지 P078/P079 후속 판정 필요 |
| **데이터 풀 확대** | 고정 학습토큰에서 반복 노출 감소로 개선 | 값싼 레버지만 풀·평가 오염을 함께 통제해야 함 |

### 5.2 데이터 중심 사전학습

- spam·중복·평가 오염을 제거하고, 동일 compute에서 고품질·다양한 원문 비중을 높인다.
- 언어·도메인·난이도 curriculum을 두고 한국어 개념관계, 과학·상식, 짧은 추론, 코드/수학을 의도적으로 배합한다.
- TinyDataset과 고밀도 Stage1 corpus를 실제 loader에 연결하되 held-out은 완전히 격리한다.
- tokenizer를 필터 후 코퍼스에서 다시 학습하는 안은 같은 token budget에 더 많은 원문 정보를 넣을 수 있으나 전 모델 재학습이 필요하므로 별도 실험으로 다룬다.
- TinyStories와 SmolLM2가 보여준 핵심은 작은 모델일수록 **규모보다 데이터 설계·단계별 mixture·품질 관리**가 중요하다는 점이다. 공개 모델의 수치를 TinyLM에 직접 외삽하지는 않는다.

### 5.3 아키텍처와 학습 레시피

- 부모초기화를 기본 강한 대조군으로 유지한다.
- 깊이, dense/tied 혼합, CLA, 재귀를 **같은 파라미터·packed·runtime 예산**에서 비교한다.
- 더 많은 pretraining token은 절대 품질을 올리지만 저장소에서 100→300M보다 300→600M의 수확체감이 컸다. 무작정 연장하기보다 데이터 품질·curriculum을 먼저 개선한다.
- optimizer·LR·schedule은 vocab과 유효배치가 달라질 때 다시 탐색한다. Qwen/Gemma 대형 vocab에 native 최적 LR을 그대로 고정하지 않는다.

### 5.4 SFT와 선호학습

현재는 SFT·DPO·ORPO가 trainer에 연결돼 있지 않다. 모델이 사용자 질문에 답하고 형식을 지키는 “행동 지능”을 원한다면 다음 순서가 필요하다.

1. example boundary와 assistant-only mask가 있는 SFT loader
2. 채팅 serializer와 tokenizer special-token 정합성
3. 짧고 검증 가능한 QA/설명 SFT
4. `near_negatives` 또는 teacher pair를 이용한 preference/ranking loss
5. IFEval류 규칙 채점과 한국어 자체 평가

이 계획에서 SFT의 주목표는 **행동 형식과 과제 지식의 호출 개선**이다. SFT도 반복된 고품질 domain fact를 파라미터에 주입할 수 있으므로, 새로운 사실지식 주입 여부는 별도 비노출 지식 probe로 검증한다. pretraining 지식·task 학습·행동 정렬의 효과는 별도 체크포인트와 평가로 분리한다.

### 5.5 RAG·도구·test-time compute

- RAG는 희귀·최신 사실의 정확도를 올리는 가장 현실적인 시스템 레버다.
- 계산기·검색·코드 실행 도구는 작은 모델의 파라미터 지식 한계를 보완한다.
- self-consistency, reranking, verifier, 재귀/latent compute는 추론 시 계산으로 정답률을 높일 수 있다.

단 이들은 **모델 파라미터 자체가 더 똑똑해진 것**과 구분해 보고한다. 프로젝트에는 tool-call schema/serializer 일부만 있고 retrieval·execution·학습 연결은 아직 없다.

## 10. 한계

- 저장소 결과는 실험별로 seed·tokenizer·평가 원문이 다르다. 이 문서는 인과 비교가 가능한 쌍과 불가능한 교차비교를 구분했다.
- Qwen 결과는 단일 seed이고 Gemma full 품질 결과는 없다.
- 직접 가까운 44M/58M BabyLM 근거도 있지만 영어 10M-word workshop 조건이다. 다른 최신 논문의 대부분은 TinyLM보다 큰 fp16/bf16 모델과 instruction/task-specific 데이터에서 검증됐다. **3진·tied·63~122M** 조건으로의 적용은 여전히 가설이다.
- 공개 모델 카드의 benchmark는 local evaluator와 shot/prompt가 다를 수 있으므로 교사 우위의 최종 근거로 쓰지 않는다. P082에서 같은 채점기로 재측정해야 한다.
- RAG·도구·test-time compute는 유용하지만 내재 모델 지능과 같은 것으로 보고하지 않는다.
