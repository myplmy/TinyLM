# TinyLM 1차 리뷰 — 실험 종합·기법별 판정·최적 모델안 3개

작성 2026-07-30 · 대상 = 결과 001~010 (계획 P001~P028) · 결과 010(P022 게이트) 반영 갱신 · 기준 스케일 m100(132.5M dense) / ko-en / 300M

> **이 문서의 목적**: 여기까지 무엇을 어디까지 확인했고, 각 기법을 **어느 수준까지 적용하는 것이
> 타당한지** 결론을 내리고, 다음 단계로 검증할 **모델안 3개와 그 배치파일**을 확정한다.
> 코드가 정본이므로 이 문서는 판단의 스냅샷이다.

## 0. 한 장 요약

**확정된 것 (3가지)**

1. **삼진 + MLP 타잉 + 부모초기화 + KD** 조합으로 dense 대비 **2.07×** 메모리 감축을 손실 격차
   `+0.005` 수준에 묶었다(결과 002). KD 는 **정적 k4**(교사 forward 25%)가 품질·시간 모두 최적(005).
2. **3:4 희소 삼진(1.25bpw)** 이 실스케일에서 동작한다. **10.3MB(3.00×)에 +0.061**,
   **11.7MB(2.64×)에 +0.036**. 희소 단독 비용은 +0.035~0.056 이고 **학습 시간은 늘지 않는다**(008).
3. **`--no-ckpt` 가 -17.3%** 로 단일 최대 엔지니어링 레버다. **micro_bs↑ 는 이득 0**(연산바운드 확증),
   k4+압축교사+no-ckpt 로 KD 교사 오버헤드가 **+19%** 까지 줄었다(007).

**뒤집힌 것 / 흔들린 것 (3가지)**

4. **"토큰을 더 넣으면 타잉 격차가 닫힌다"는 가설 기각.** 100M→600M 6배에서 격차는 +0.149 →
   +0.168 → +0.166 으로 평평하다. 타잉 손실은 학습 부족이 아니라 **용량 상한**이다(006).
5. **"tied+KD 가 dense 를 능가한다"(005 헤드라인)는 조건부다.** 공정 풀(600M)에서는 +0.062(300M),
   +0.098(600M)로 열세다. 세 데이터점(005·006·009)이 **"dense 가 약할 때만 KD 가 교사를 이긴다"**
   로 일관된다. → **정정하지 않고 병기, 확인런 대기**(§5-B).
6. **데이터 풀 다양성만으로 dense 가 0.12 움직인다.** 같은 300M 학습토큰인데 풀 300M→600M 에서
   3.8241 → 3.7045. **지금까지의 모든 300M 정본 수치가 풀 핸디캡을 안고 있다**(006).

**방법론 경고 (2가지 — 다른 모든 판정에 곱해진다)**

7. **재현 노이즈 σ 를 측정한 적이 없다.** 판정기준 `±0.07` 은 근거 없이 쓰이고 있다.
   (007 §2-(4)의 0.11 nats 는 `grad_max` 10.8~35.4 의 **불안정 구간** 값이라 수렴 구간 σ 의
   추정치로 쓸 수 없다 — 반례로 인용 금지.) → **권고 R4.**
8. **교차데이터셋 bpb 는 무효였다.** 토크나이저·val 셋이 다르면 bpb 로 데이터셋을 비교할 수 없다.
   P012 는 **판정 불가**로 종결(009). → P028.

## 4. 우리가 실제로 알아낸 스케일링 그림

```
품질(val, 낮을수록 좋음)
  ^
  |  4.37 dense@100M
  |         \
  |          \  기울기 -0.66 (100M→300M)
  |           3.70 dense@300M
  |                \  기울기 -0.18 (300M→600M)  <- 수확체감 급격
  |                 3.52 dense@600M
  |
  |  타잉 격차: ------ +0.15 ~ +0.17 (전 예산 평평. 용량 상한) ------
  |  KD 로 회수:  100M -0.11  /  300M +0.06  /  600M +0.10  (예산↑ 회수율↓)
  |  풀 2×:      -0.12 (학습토큰 안 늘리고 얻음)
  |  3:4 희소:   +0.035(g4) / +0.056(g8)  대가로 메모리 1.45×
```

**읽는 법**: 메모리 1순위 목표에서 우리가 지불할 수 있는 총 예산이 판정기준 `+0.07` 이라면,
현재 조합으로 살 수 있는 것은 **타잉 g8(2.07×) + 희소(→3.00×)** 인데 그 합이 이미 예산을
거의 다 쓴다(2.1 표에서 +0.061). 여기서 더 밀려면 **격차 예산을 늘리는 대신 다른 축**
(데이터 품질 P028, 스케줄 P026, 예산↑)에서 val 을 벌어와야 한다.

## 5. 방법론 리스크 (다른 모든 결론에 곱해짐)

### A. ★노이즈 하한 미측정
수학적으로 동일한 두 런이 250스텝에서 **0.11 nats** 벌어졌다(007 §2-(4)).

**단, 그 0.11 을 "우리 실험의 노이즈"로 인용하면 틀린다.** 결과 json 의 `grad_max` 를 보면
두 런 모두 **불안정 구간**이었다:

| 런 | `grad_max`(warmup 이후) |
|---|---|
| `sp_base` (250스텝) | **10.79** |
| `sp_nockpt` (250스텝) | **35.38** |
| `dense` (2289스텝) | **1.22** |
| `t_kd_g8_k4` (2289스텝) | **0.65** |

250스텝 런은 warmup 25스텝뿐이라 anneal 개시 시점에 LR 이 peak 근처이고, `|g|` 가 우리
판정기준의 "10 이상 = 학습 문제" 선을 **두 런 모두 넘었다**. 즉 0.11 은 서로 다른 그래디언트
스파이크(35.4 vs 10.8)를 맞은 결과이고, **수렴 구간 σ 의 상한도 아니다.**

**따라서 정확한 진술은 이것뿐이다: σ 는 미측정이다.**
2289스텝 런들은 `grad_max` 0.5~1.2 로 안정적이라 드리프트가 훨씬 작을 가능성이 높지만,
그 크기를 모르므로 002 의 "+0.005 격차 소멸"·005 의 "-0.037 dense 능가" 의 유효성은 **미정**이다.

- → **권고 R4**: P021 추가검증 A(`nz_a/nz_b/nz_c`). P026 의 `qb_cos` vs 정본 dense 델타가
  **추가 GPU 0 으로 첫 데이터점**을 준다.
- 그때까지 모든 결과문서는 `≤0.05` 급 차이를 **"차이 있음"으로 단정하지 않는다.**
- 부수 규약: **안정성 판정은 인쇄된 `|g|`(10스텝 샘플) 가 아니라 json `grad_max`** 로 한다.
  sp_base 의 인쇄 최대는 4.51 이었지만 실제는 10.79 였다.

### B. 풀 핸디캡 — 005 헤드라인 병기 상태
| 조건 | dense 상태 | tied+KD − dense |
|---|---|---|
| ko-en 300M 풀(005) | 1 epoch 핸디캡 | **-0.0366** (k4) |
| ko-en 600M 풀(006) | 핸디캡 없음 | **+0.0616** (full KD) |
| ko-edu-en 300M 풀(009) | 일반화 실패 | **-0.2109** (full KD) |

600M ≈ +0.057 로 **둘 다 판정기준 안**이다.
→ **사용자 결정(2026-07-30): 정정하지 않고 병기. 공정 풀 k4 확인런 후 확정.**

## 6. ★1차 리뷰 결론 — 최적 모델안 3개

### 설계 근거

- 프로젝트 1순위는 **메모리**이므로 세 안 모두 `삼진 + 타잉 + 부모초기화 + KD k4` 를 공유하고
  **희소·타잉 강도만** 다르게 한다.
- 008 §2-(3): 타잉과 희소는 **경합**한다. 둘을 동시에 최대로 밀지 않는 것이 세 안의 축이다.
- **모든 검증은 600M 풀에서** 한다(§5-B). dense 기준선은 이미 존재하는 **`p6d`(3.7045)** 를
  재사용하므로 **추가 dense 학습이 0** 이다.
- 교사·부모도 **`p6d`** 로 통일해 풀·교사가 일치한다.

### 세 안

| | **A. 균형 정본안 (권장)** | **B. 메모리 상한 도전** | **C. 보수·검증 겸용** |
|---|---|---|---|
| 구성 | tied **g4** + **3:4 희소** + KD k4 | tied **g8** + **3:4 희소** + KD k4 | tied **g8** + KD k4 (희소 없음) |
| 파라미터 | 72.9M | 63.5M | 63.5M |
| **배포 메모리** | **11.7MB** | **10.3MB** | **14.9MB** |
| **감축** | **2.64×** | **3.00×** | **2.07×** |

| KV(1024ctx) | 7.5MB | 7.5MB | 7.5MB |
| 기존 측정 격차 | +0.036 (300M 풀, full KD) | +0.061 (300M 풀, full KD) | -0.037 (300M 풀, k4) |

> **왜 g16+s34(≈9.9MB, 3.11×)를 넣지 않았나**: 008 §2-(3)의 초선형 악화(g8 에서 희소 비용이
> g4 의 1.6배)를 그대로 연장하면 g16+s34 는 +0.15 를 넘길 가능성이 크다. 메모리 이득
> 10.3→9.9MB(4%)에 그 리스크를 지불할 이유가 없다. **B 가 이미 실질 상한.**

### 판정 규칙 (검증 후)

기준 = **`p6d` 3.7045** (600M 풀, 300M 학습토큰).

| 격차 | 판정 |
|---|---|
| `≤ +0.07` | 성립 → 해당 안을 **정본 후보로 승격** |
| `+0.07 ~ +0.15` | prelude·coda↑ 또는 g↓ 로 대응(A→C 방향) |
| `> +0.15` | **먼저 `|g|max` 확인**(10 이상이면 학습 문제) |

단 §5-A 미해결 상태이므로 **`≤0.05` 급 차이는 "차이 있음"으로 단정하지 않는다.**
세 안의 순위가 0.05 안에서 뒤섞이면 **메모리가 작은 쪽을 택한다**(1순위 목표).

if errorlevel 1 goto ERROR

echo.
echo === Compares against the fair-pool dense p6d (3.7045) ===
python run100m.py compare --data ko-en --tokens 300M --tag p6d --vs mA_g4s34_k4
python run100m.py compare --data ko-en --tokens 300M --tag p6d --vs mB_g8s34_k4
python run100m.py compare --data ko-en --tokens 300M --tag p6d --vs mC_g8_k4
echo === sparsity cost isolated, at equal g and equal pool ===
python run100m.py compare --data ko-en --tokens 300M --tag mC_g8_k4 --vs mB_g8s34_k4

echo.
echo ================================================================
echo REFERENCE: p6d val 3.7045  (600M pool, 300M trained, dense, NOT handicapped)
echo.
echo RECORD for each candidate: val, best, bpb, minutes, ^|g^|max, and the gap vs 3.7045.
echo   gap ^<= +0.07        -^> candidate passes, promote
echo   +0.07 .. +0.15      -^> raise prelude/coda or lower g
echo   ^> +0.15             -^> check ^|g^|max FIRST (10+ means a training problem, not capacity)
echo.

echo wrong (see 1st review s5-D). Use the report() block at the top of each training log.
echo.

echo       measured +0.0555 for this on the handicapped pool - see if it holds.
