# 레이어·가중치 그룹 생략과 초기값 대체 — TinyLM 적용 문헌 검토

- 작성: 2026-10-21. 사용자 추가 지시10에 따라 기존 에이전트를 문헌·아이디어 역할로 재배정했다.
- 상태: 문헌·코드 읽기 분석. 이 조사로 새 모델 로드·학습·가중치 개입·GPU 실험을 수행하지 않았다.
- 근거 수준: 아래 primary 논문/저자 공식 구현·설명을 실제 조회했다. 총괄도 JMLR/LayerDrop/LISA/DropBP/LayerSkip 원문을 대조했다. 저장소 전체 코드의 독립 재현·TinyLM 이득 검증은 아니다.
- 관련 정본: [P078](../../test_plan/P078_재귀는-reasoning인가-방문의-선택성.md), [결과066§9~10](../../test_result/066_20260831_P078-이득은-몰려있지만-어느-크롭인지는-재현되지-않는다.md), [기존복원결과103](../../test_result/103_20261010_P093B-MLP잔차와-삼진보정은-실행됐지만-복원문턱에-미달.md).

## 1. 결론

사용자의 아이디어에 직접 대응하는 선행연구가 있다. 다만 **초기값 대체는 기여 진단**, **실제 순전파 생략은 계산 경로 변경**, **역전파 생략·업데이트 동결은 학습비용 변경**으로 나눠야 한다. 초기값으로도 같은 행렬곱을 수행하므로 그 대체 자체가 가속은 아니다. 현 TinyLM의 반복·오답을 단일 레이어 탓으로 확정하는 방법도 아니다.

가장 권장하는 순서는 **동결 체크포인트의 복구 가능한 비학습 개입 A → 손상이 적은 그룹에서 별도 DropBP형 학습 대조 B**다. 메모리 병목이 더 중요하면 C를 독립 비교한다. 현재 본75M/MTP/풀이/방문 실험을 이 조사만으로 취소하거나 새 알고리즘을 기본 채택하지 않는다.

## 2. 선행연구별 정확한 차이

|방법|실제로 바꾸는 것|적용 근거와 한계|
|---|---|---|
|초기값 대체/새 난수 대체|학습된 특정 층을 최초 값 또는 같은 분포의 다른 난수로 바꿔 재학습 없이 평가|[Are All Layers Created Equal?, JMLR2022](https://jmlr.org/papers/volume23/20-069/20-069.pdf). §5.1은12층·약112M Transformer 언어모형도 분석한다. 일부 층은 초기값 대체에 견뎌도 제거에는 악화된다. 학습된 값의 필요성과 그 연산 자체의 필요성이 다르다는 직접 근거다. TinyLM 삼진·공유 구조에서의 재현은 아니다.|
|Stochastic Depth/LayerDrop|학습 중 잔차 가지 또는 층의 순전파를 생략|[Stochastic Depth](https://arxiv.org/abs/1603.09382), [LayerDrop](https://arxiv.org/abs/1909.11556), [공식 구현](https://github.com/facebookresearch/fairseq/blob/main/fairseq/modules/layer_drop.py). 그런 학습을 받은 부분망의 사용 연구이지 기존 CP에서 임의 층을 빼도 안전하다는 뜻이 아니다.|
|Progressive Layer Dropping|학습 단계에 따라 층 생략 확률을 바꿈|[저자 공식 설명](https://www.microsoft.com/en-us/research/publication/accelerating-training-of-transformer-based-language-models-with-progressive-layer-dropping/). BERT 사전학습 비용 연구이며 자기회귀 TinyLM의 동일 이득을 보증하지 않는다.|
|DropBP|순전파값은 유지하고 선택한 잔차 가지의 역전파를 생략|[논문](https://arxiv.org/abs/2402.17812), [공식 코드](https://github.com/WooSunghyeon/dropbp). activation/역전파 비용 절감 후보이나 민감도 측정과 변경된 gradient의 품질 영향이 남는다. 논문의 자원 이득을 TinyLM 예상치로 복사하지 않는다.|
|LISA/FreezeOut|현재 가중치는 유지하며 일부 층의 업데이트를 동결|[LISA](https://arxiv.org/abs/2403.17919), [공식 구현](https://github.com/OptimalScale/LMFlow), [FreezeOut](https://github.com/ajbrock/FreezeOut). forward 생략과 다르다. 이미 할당한 optimizer 상태가 동결만으로 사라지지는 않는다.|
|가중치 되감기|부분망을 초기 또는 초기 학습 시점 값으로 되돌려 다시 학습|[Weight Rewinding](https://arxiv.org/abs/1912.05671). 순간 대체 진단이 아니라 pruning/재학습 절차다.|
|LayerSkip|layer dropout·early-exit loss로 조기 출력을 학습하고 남은 층으로 검증|[논문](https://arxiv.org/abs/2404.16710), [공식 코드](https://github.com/facebookresearch/LayerSkip). 현재 CP에 exit만 추가하는 것과 다르며 전용 학습·KV·검증 구현이 필요하다. MTP 진위 판정기와도 다르다.|

DropBP/LISA의 공식 사용 예와 논문은 확인했으나 일부 핵심 파일의 웹 접근은 실패했다. 전체 구현 안전성이나 버전별 호환을 승인한 조사로 표현하지 않는다. 외부 연구의 품질·속도 수치는 해당 모델/과제/하드웨어의 관측이지 우리 모델의 성과 예측이 아니다.

## 3. TinyLM에서 특히 지켜야 할 것

1. **물리적 공유와 논리층·방문을 분리한다.** 공유 MLP를 바꾸면 여러 논리층과 재귀 방문이 함께 바뀐다. 특정 방문의 출력만 생략하는 개입과 물리 파라미터 전체 대체는 별도 팔이다. gate/up/down 채널의 연결도 일관되게 다뤄야 한다.
2. **CLA의 KV 소유 관계를 보존한다.** attention 출력을 막아도 소유층이 만든 KV가 소비층에 남을 수 있다. KV 생성까지 생략하려면 owner/consumer/방문 회차의 새 계약이 필요하다. 따라서 첫 진단은 MLP 잔차 가지가 더 좁은 변경이다.
3. **삼진 master와 quantization cache를 함께 검산한다.** master만 바꾸고 기존 cache를 쓰면 가짜 대체 시험이다. 동일 anneal/정규화/양자화 경로에서 대체·복구 후 실제 출력과 가중치 SHA를 확인해야 한다.
4. **한 optimizer update의16micro와 checkpoint 재계산 동안 결정을 고정한다.** 재귀 방문마다 새로 mask를 뽑거나 backward 재계산에서 다른 층을 생략하면 같은 함수의 gradient가 아니다. 기존 P078 경로 lease를 완화하지 않는다.
5. **gradient 0과 None을 구분한다.** [PyTorch 공식 설명](https://docs.pytorch.org/docs/stable/generated/torch.optim.Optimizer.zero_grad.html)의 의미처럼 optimizer 처리도 달라질 수 있다. TinyLM Muon 역시 None은 건너뛴다. 동결·재활성화 시 Adam/Muon 상태의 보존·이동·재생성 정책이 필요하다. 현재 P078의 optimizer/trainable 정확 소유권 검사에 단순 requires_grad 변경을 끼우면 실패한다.
6. **민감도는 실제 중요도와 같지 않다.** gradient norm과 실제 Muon NS/global clip 후 업데이트 차이는 비선형이다. 작은 출력오차가 전체 정답 보존을 보장하지도 않는다.

관련 구현은 [공유/방문 본체](../../tinylm/model/transformer.py), [삼진/캐시](../../tinylm/model/ternary.py), [Muon](../../tinylm/train/muon.py), [현재 경로/소유권](../../scripts/p078_route_training.py)이 소유한다. 이 리뷰는 그 수식이나 기본 정책을 재정의하지 않는다.

## 4. 구체 후보 세 가지

|후보|사례와 방법|이득|비용·위험|
|---|---|---|---|
|A 권장: 비학습 진단|같은 질문/teacher-forced prefix에서 정상, MLP 잔차 가지 생략, 최초 동일 초기값 대체, 정상 복구를 비교. 물리그룹3개 예시라면 정상1+두 개입×3+복구1=8번 forward|학습된 값의 필요성과 연산 존재의 효과를 분리, optimizer0|초기값 snapshot/정합 증거가 필요. 내부 분포 교란과 다른 층 상호작용을 고려해야 함. 실제 시간은 선택 문항·batch로 계측 전 미확정|
|B: DropBP형 새 학습 대조|같은 자료/초기화/노출에서 정상 학습 대 특정 MLP 가지의 backward만 생략. 순전파 정합을 먼저 확인|forward 함수 변경을 줄이며 activation/역전파 시간 절감 가능|민감도 측정·gradient/clip/optimizer 상태·checkpoint 재계산 구현 필요. 학습량 또는 비용 두 기준을 따로 비교해야 함|
|C: 물리그룹 순환 동결|전체 forward는 그대로 하고 일부 그룹만 번갈아 업데이트|gradient/optimizer 메모리 절감 후보|고유 파라미터 단위여야 함. 같은 optimizer 상태를 GPU에 계속 두면 메모리 이득 작고 CPU 이동은 전송 비용 발생|

A의 ‘초기값’은 최초 랜덤 초기값, 이미 학습된 SFT 시작 부모, 같은 분포의 새 난수를 명시적으로 나눈다. 동일 seed라고 최초 학습 전 상태가 자동 재현되는 것은 아니며 당시 RNG 순서·구조·버전까지 확인해야 한다. 최초 snapshot이 없으면 첫 번째 팔은 NOT_RUN으로 두고 부모 대체나 새 난수 결과를 대신 부르지 않는다.

## 5. 인과 해석과 평가 설계

개입 효과는 지정한 변경 아래의 **조건부 출력 효과**다. 그 층이 원래 오답의 유일 원인이나 지식 저장소라는 결론은 아니다. 정상/실패·값 변경/유지·KO/EN을 같은 입력 이력에서 비교하고 logit·정답 우도·정답/종료·반복·층변화를 함께 측정해야 한다. 실제 자유 생성은 첫 차이 뒤 이력도 달라지므로 별도 전체 효과로 읽는다.

그룹 선택은 DEV에서, 최종 확인은 분리 TEST에서 한다. 공식 벤치 오답을 보고 답쌍을 TRAIN에 추가하는 경로로 만들지 않는다. 개별 개입 두 개의 효과를 합산해서 공동 제거를 예측하지 말고 필요한 경우 공동 대조를 추가한다. 속도는 출력0 마스킹이 아니라 실제 연산 생략 여부·동기 wall·전체 학습시간으로 확인한다.

장기 아이디어는 진단에서 손상 적은 물리그룹을 찾아 제한된 backward 예산을 배정하는 것이다. 그러나 진단 강건성과 미래 학습 gradient의 효용이 같다는 보장은 없으므로 학습 전후의 원상복구 대조·능력 보존과 실제 비용을 새 실험에서 검증해야 한다. 현재는 제안이며 구현·실행·효과는 NOT_RUN이다.
