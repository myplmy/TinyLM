# 3차 리뷰 **v2 (초안)** — **32 / 40 MiB 예산의 네 가지 안, 다시 짠다**

> ⚠️★★★**2026-09-06 — 이 초안에는 시간 축이 없다.** 그날 사용자가 **속도 목표**를 확정했다:
> **단일 CPU·단일 코어에서 ≥15 tok/s**(**80 tok/s 부터**는 속도를 줄여서라도 품질을 올린다).

> **`d12_cla2_r20` ⚙12.5~13.2 · `d16_cla2_r20` ⚙9.9 로 둘 다 바닥 미달**이다(기준표 **B.19.3**).
> ★**원인은 재귀 R2** 다 — **메모리에는 공짜인데 방문을 2배로 만들고, 방문이 시간을 정한다**
> (20 방문에서 세 모델이 12.54~13.24 로 모인다). 🚫**15 tok/s 는 방문 17~20 이 상한**이다.
> 🚫★**80 tok/s 는 지금 구조로 도달 불가능**하다 — 두 시간식의 절편(15.46 / 13.67 ms)이

> ✅**상주 목표는 확정**: **≤16 MiB**(엔트리) · **32**(메인스트림) · **40**(데스크톱 상한).

> 🚫**네 안을 그대로 쓰지 않는다.** B.19.6 의 조치 셋이 먼저다 —
> ①회계에 `tok/s` 열 추가 ②`d12_cla2_r20` 의 tok/s **실측** ③**무재귀 형상**(`d12` 12방문 ⚙21.8 tok/s)의 품질 대가.

## 1. 회계 규약 — **구동기 제외, 32·40 둘 다**

```
상주(runtime) = 임베딩·기타(int8) + 삼진 가중치(LUT) + KV 캐시(bf16 @ seq 1024)
🚫 저장(packed) 과 섞지 않는다(함정 1)   ·   ⚠️ 단위는 MiB (40 MiB = 41,943,040 B)
🚫 ★구동기(런타임 엔진·프레임워크)는 이 회계에서 제외한다 (2026-09-05 사용자 지시)
```

★**실측에서 뽑은 선형식**(기준표 B.14·B.17):

```
상주 = 9.0  +  1.21 × L  +  0.75 × (방문 / cla_group)      [MiB]
        └임베딩 int8      └LUT 삼진        └KV bf16 @1024
```

검증: `d12_cla2_r20` = 9.0 + 14.52 + 7.5 = **31.0**(실측 30.7, 오차 1.0%) ·
`d16_cla2_r20` = 9.0 + 19.36 + 10.5 = **38.9**(실측 38.5, 오차 1.0%).

⚠️★**KV 는 seq 에 정확히 선형**이다. 위 수는 **컨텍스트 1024** 기준이고,
**2048 이면 KV 가 두 배**가 되어 `d16` 은 **49.0 MiB 로 40 을 넘는다.**
🚫**상주를 인용할 때 `(모델, KV dtype, 컨텍스트)` 셋을 반드시 함께 적는다.**

## 2. ★현재 위치 — **두 예산 다 이미 들어가 있다**

| 예산 | 승자 | full-val | 상주 | 여유 |
|---|---|---:|---:|---:|
| **32 MiB** | `d12_cla2_r20` | **3.6054** | **30.7** | 1.3 |
| **40 MiB** | `d16_cla2_r20` | **3.5642** | **38.5** | 1.5 |

★**v1 초안의 질문(*"어떻게 넣나"*)은 끝났다.** 남은 질문은 ★***"들어간 채로 얼마나 좋아지나"*** 다.
→ **이 v2 의 네 안은 "감축안" 이 아니라 "같은 예산에서 품질을 올리는 안" 이다.**

### 2.1 ★★레버 가격선 — **모든 안이 이 선 위에서 비교된다**

30.7 MiB 기준선에서 **품질 1 nat 을 사는 데 드는 MiB**(결과 071 §4 · 075):

| 레버 | Δ nats | Δ MiB | **nats/MiB** |
|---|---:|---:|---:|

| ★깊이 12→16 | −0.0414 | +7.80 | ★**0.00531** |

🚫**수확체감이 아니다 — 큰 걸음일수록 싸다.** → ★**예산이 남으면 한 번에 크게 쓴다.**

### 2.2 ★★그리고 **선 밖의 레버가 둘 있다** — 상주를 0 쓰고 품질을 준다

| 레버 | Δ nats | Δ MiB | 대가 |
|---|---:|---:|---|

## 4. ★사용자 지시 확인 — **3:4 sparse 의 미구현 사항**

> *"3:4 sparse\[**커널 등 미구현 사항 있는지도 확인해야함**\]"*

### 4.1 실사 — **무엇이 있고 무엇이 없었나**

| 조각 | 상태 |
|---|---|
| 학습 경로(STE 안의 3:4 마스킹) | ✅**있다** — `ternary.py:18` |
| 품질 대가 측정 | ✅**있다** — 결과 008: `g4_s34` **+0.0364** · `g8_s34` +0.0606 |
| 저장(packed) 회계 1.25 bpw | ✅**있다** |
| ★**패킹 포맷 자체** | 🚫**없었다** → ★**2026-09-05 구현**(`lut.py`) |
| ★**상주 회계** | 🚫**없었다** → ★**`sparse34_vs_lut()` 신설** |
| 커스텀 삼진 커널과의 결합 | 🚫**없다** — `trainer.py:356` 이 `SystemExit` 으로 거절 |
| 빠른 커널(Triton/CUDA) | 🚫**없다** |

### 4.2 ★구현한 것 — **4가중치 = 5비트**

```
묶음 4개에 0 이 정확히 하나         -> 자리 2비트 + 나머지 셋의 부호 3비트 = 5비트
1.250 bpw   (LUT 1.600 대비 −21.9%)   ★이론 하한 log2(4)+3 = 5.000비트와 정확히 같다
```

⚠️**빠른 커널은 안 만들었다** — 언패킹해서 곱하는 참조 경로다.
★**우리 목적함수는 상주이지 속도가 아니다.** 속도 판정은 P014D 가 소유하고 **지금 판정 불가**다.

### 4.3 ★★판정 — **숫자가 나왔고, 선 밖이다**

| 모델 | 삼진 항 | 3:4 로 | **절감** | 새 상주 | 대가 | **nats/MiB** | 선(0.00531) 대비 |
|---|---:|---:|---:|---:|---:|---:|---:|
| `d12_cla2_r20` | 14.52 | 11.34 | **3.18** | **27.5** | +0.0364 | **0.01146** | 🚫**2.16배** |
| `d16_cla2_r20` | 19.36 | 15.12 | **4.23** | **34.3** | +0.0364 | **0.00860** | 🚫**1.62배** |

★**읽는 법**: 3:4 로 **판** 3.18 MiB 를 깊이에 **다시 쓰면** 0.0169 nats 를 버는데,
파느라 **0.0364 를 잃었다** → **손해 2.16배**.

🚫**채택하지 않는다.** ⚠️**단 두 조건에서 되살아난다**:
1. **28 MiB 급 예산**이 생기면(그때는 깊이로 되살 자리가 없다)
2. ★**대가 +0.0364 가 dense 몸통에서 다시 재져 더 작게 나오면** — 그 값은 **타잉 + KD 조건**이다.
   `d16` 에서 1.62배까지 내려오므로 **대가가 0.0225 이하면 선 안**이다. ⚙**재학습 3.6h.**

## 8. ★권고 (초안 단계의 잠정)

1. ★★**32 MiB = 안 B · 40 MiB = 안 C.** 둘 다 **메모리 레버를 더 붙이지 않고 학습 시간을 쓴다.**

   ★재개 조건 = *"dense 대가가 0.0225 이하"* 또는 *"28 MiB 급 예산"*.
3. ★**재귀는 R2 로 고정.** R3 은 34~38 MiB 예산이 생기면 되살린다.
4. ★**가장 값진 미개통 축은 P081 StreamingLLM** — 컨텍스트를 늘리는 유일한 길이고 선결이 끝났다.
