# 3차 리뷰 (초안) — **L2+L3 캐시에 넣는 네 가지 안**

- **작성**: 2026-08-23 · **상태**: ⏸**초안.** 미확정 수가 많다(⚙표시)
- **범위**: [REVIEW2](202608140900_2차리뷰_초안_KD표준조건과-메모리레버-종합.md) 이후 — **상주 메모리 감축**
- **사용자 지시(2026-08-23)**: *"리뷰3는 실제 L2+L3 메모리 안에 들어가도록 상주메모리 감축관련
  내용이 될 것이며, 메모리 감축 방법과 메모리 감축에 따른 성능저감을 어떻게 방지할 수 있는지,
  **성능저감을 인정하고 감축하는 최대 메모리 감축안**과 **성능저감을 최대한 방지하면서 L2+L3내에
  넣는 성능최대안**과 그 사이의 **중간안 2개** 정도로 4개정도를 검토할 예정"*

## 0. ★★목표를 숫자로 못 박는다

| | |
|---|---|
| ★**목표** | **상주(runtime) 메모리를 L2+L3 안에** |
| ⚠️**"L2+L3" 가 얼마인가** | 🚫**우리는 이 수를 확정한 적이 없다.** `CLAUDE.md`·결과 016 이 **L3 32 MB** 를 쓰고, P066 이 **40 MiB** 를 목표로 잡았다 |
| ★**이 리뷰의 기준** | ★**40 MiB**(P066 목표) 를 1차선, ★**32 MiB**(L3 단독) 를 2차선으로 **둘 다 표기** |

> ⚠️★**선결 1**: **배포 대상 CPU 의 L2+L3 를 확정해야 한다.** 지금은 목표가 두 개다.
> 🚫**그 전에는 "통과" 라고 쓰지 않는다** — 40 은 되고 32 는 안 되는 안이 여럿이다.

## 0.1 ★상주 회계의 규약 (함정 1)

```
상주 = 삼진 항 + 임베딩 항 + 기타(norm·gate·router)
🚫 저장(packed) 과 섞지 않는다.  ⚠️ MB 는 이 저장소에서 MiB(2^20) 를 뜻한다
```
