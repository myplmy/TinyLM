## 0.1 ★★사용자 물음 셋 (2026-09-08(2차) 지시 2C) — **정본은 기준표 B.24**

### ① *"R5 를 먼저 승격하면 R3·R4 와 어느 쪽이 최신인지 헷갈리지 않나"*

★**헷갈릴 수 있다. 그리고 그것은 이름으로 못 푼다** — `m100R3x` 가 나중에 생기면
**번호는 작은데 시간은 나중**이다. 그래서 이름 대신 **표가 답하게** 했다:

> ★**규칙 39** — `N` 은 **그 프리셋을 정한 리뷰 번호**다. 🚫**최신순이 아니다.**
> *"어느 것이 최신인가"* 는 **기준표 B.24.1 의 `확정일` 열**이 답한다.
>
> ★**규칙 40** — **표준(기준) 프리셋은 언제나 하나**다. B.24.1 의 `표준` 표시와
> B.6 의 표준 명령이 **같은 것을 가리켜야 한다.**

⚠️**그리고 실제로는 충돌이 아니다** — REVIEW3 이 낼 것은 **배포 모델**이고
REVIEW5 가 내는 것은 **학습 기준**이며, REVIEW4 는 **아키텍처 결정이 아니라 지능 축**이다.
🚫**역할이 다른 프리셋은 같은 자리를 놓고 다투지 않는다.**

### ② *"리뷰2는 확정됐는데 왜 `m100R2a` 가 프리셋이 안 됐나"*

✅**누락이 아니다. 설계상 낼 것이 없었다.**

REVIEW2 확정 = **안 A** = `m100R1c` + `--init-from` + **KD 제거**, ★*"추가 플래그 없음"*.
프리셋은 **아키텍처 필드만** 소유하는데(`CLAUDE.md`), 안 A 의 세 요소 중
**아키텍처는 `m100R1c` 하나이고 이미 프리셋**이며 나머지 둘은 **명령줄**이다.

🚫**`m100R2a` 를 만들었다면 `m100R1c` 와 바이트 동일한 두 번째 이름**이 생겼을 것이다 —
**함정 18**(한 개념을 두 곳에서 정의). ★그 결정은 **표준 명령(B.6)** 과
**2차 리뷰 확정본 §8 표**에 이미 기록돼 있다.

### ③ *"누락이면 R2a 위에 R5 를 얹나, 별개 축으로 가나"*

★**②가 "누락 아님" 이므로 이 물음은 형태가 바뀐다**: *"R5 의 기반이 `m100R1c` 인가?"*
🚫**아니다 — 별개의 축이다.** §1 의 표가 그것을 보인다:

| | REVIEW2 가 고정한 것 | ★**실제 승자 계열** |
|---|---|---|
| 몸통 | `m100R1c` = **타잉 g8**, 20층 | **dense**, 12~16층 |
| CLA | 프리셋 기본 | `--cla-group 2` 를 손으로 |
| 옵티마이저 | AdamW | **Muon ×15** |

→ ★**`m100R5` 는 `m100R1c` 의 파생이 아니라 `m100s8/s10/s12` 계열의 정착**이다.
⚠️**그래서 REVIEW2 확정이 폐기되는 것은 아니다** — 안 A 는 *"조건"* 이고
R5 는 *"아키텍처"* 다. **KD 제거와 부모초기화는 R5 에서도 그대로다.**

## 1. 왜 새 기준 프리셋이 필요한가 — **정본과 실제가 갈라져 있다**

| | **정본**(2026-08-22 확정) | ★**실제로 도는 것** |

| 아키텍처 | 타잉 몸통 | ★**dense 몸통 + `--cla-group 2` 를 손으로** |

| grad-ckpt | 기본 ON | ★**무KD 의 기본은 `--no-ckpt`**(사용자 지시) |

> ★**이 리뷰의 목적은 성능이 아니라 *"손으로 붙이는 것을 없애는 것"* 이다.**
> 성능 승격(Muon)은 그 안의 **한 항목**일 뿐이고, 유일하게 품질 경계를 만든다.

## 3. 네 승격 후보 — **품질 하나 + 위생 셋**

### 3.1 후보 A ★**품질** — `--optimizer muon --muon-lr-mult 15` 를 기본으로

| 근거 | 값 |
|---|---|
| 본런 효과(d12 재귀) | **−0.04406** = 자(0.0018)의 **24.5배** |
| ★**다른 아키텍처 전이 4/4** | d12 재귀 −0.0435 · d12 무재귀 **−0.0431** · d14 무재귀 **−0.0392** · d16 무재귀 −0.0363 |
| ★**독립 코퍼스 재현** | 공통 bpb **−0.0145 / −0.0149**(두 계열, 자의 3.8~3.9배) |
| 벽시계 | **+1.6%** |
| 상주 | ★**0** |
| 안정성 | `n_skip` **전 팔 0** · `grad_max` 1.19~1.34 |
| 괄호 | ×1 +0.13437 · ×5 −0.00094 · ★**×15 −0.02922** · ×30 −0.01531 · ×45 +0.01250 → **최적이 괄호 안** |

⚠️★**단 하나 걸린다**: **×15 는 763스텝 프로브 격자에서 고른 값**인데
**본런에서 효과가 1.51배**가 됐다 → ★**최적점도 움직였을 수 있다.**
→ §7 의 **X2**(×10·×20 두 팔, ⚙2.9h)가 그것을 확인한다.

### 3.2 후보 B ★**위생** — `--arch dense` 가 `cla_group` 을 1 로 강제하는 것

`config.py:197` 이 `dataclasses.replace(cfg, tie_mlp=False, cla_group=1)` 이다.
🚫**그래서 우리 승자 전부가 `--cla-group 2` 를 손으로 붙인다.**

★**그리고 CLA 는 승격 근거가 가장 강한 축이다**(2026-09-08 가격표):
**0.00587 nats/MiB 로 깊이(0.00614)를 이기는 유일한 절감 레버**이고
★**컨텍스트가 길어지면 격차가 벌어진다**(seq2048 에서 0.00293 = 깊이의 **0.48배**).

### 3.3 후보 C ★**위생** — `kv_dtype` 기본을 bf16 으로

상주 정본식 `9.0 + 1.21·L + 0.75·(방문/cla_group)` 은 **bf16 KV 를 가정**하는데
**코드 기본은 fp32** 다 → ★**한 이름이 두 값**(함정 1 계열).
2026-09-07 P030 단계7 이 정확히 그 함정을 밟아 **KV 를 식의 2배로 인쇄**했다.

✅**학습 무해 확인**: `transformer.py:780` 한 곳에서만 쓰이고 **반환하는 `kv_bank` 에만** 건다.
✅**bf16 은 argmax 를 하나도 안 바꾼다**(결과 065) · ✅**fp16 도 열려 있다**(여유 2,025~5,531배).

### 3.4 후보 D ★**위생** — `--ce-chunk 2048` · `--no-ckpt` · `--depth-init role`

셋 다 **무KD 표준 경로에서 사실상 항상 켠다.** 🚫**그런데 기본값이 아니다.**

⚠️★**`--no-ckpt` 는 조건부**다 — VRAM 예산이 `M × 방문 ≤ 294,912` 여야 한다.
→ ★**기본값으로 만들되 예산을 넘으면 자동으로 끄고 이유를 인쇄**하는 형태여야 한다.
🚫**무조건 켜면 36층·재귀에서 OOM 이다.**

### 3.5 ⏸**후보 밖으로 뺀 것 둘** — 이유를 적는다

| 무엇 | 왜 지금 아닌가 |
|---|---|
| **재귀 R2** | ⚠️**승자의 부품이지만 프리셋 기본값은 아니다** — `train_repeat` 은 **방문 수를 2배**로 만들어 속도·VRAM 을 바꾼다. 기본값이 되면 **모든 실험의 비용이 2배**가 된다 |
| **깊이** | §2 — **과제마다 판정이 갈린다.** X1 이 먼저다 |
