## 0. 결론부터 — 네 후보와 현재 권고

| 후보 | 역할 | 아키텍처 핵심 | 실측 배포 하한 | 현재 권고 |
|---|---|---|---:|---|
| **A — 32 MiB mainstream** | 32 MiB 배포 균형 | dim768, 14층, dense, CLA2, 무재귀 | **30.8 MiB · 19.19 tok/s** | **32 MiB 대표 후보** |
| **B — 40 MiB research/reference** | 단일 학습 기준 후보 | dim768, 16층, dense, CLA2, 무재귀 | **34.0 MiB · 17.35 tok/s** | **단일 연구 기준 1순위** |
| **C — 40 MiB quality edge** | 40 MiB 안 최대 깊이 | dim768, 18층, dense, CLA2, 무재귀 | **37.1 MiB · 15.84 tok/s** | 조건부 후보; 속도 여유·과제 재검증 필요 |
| **D — narrow/deep challenger** | 폭 축 대안 | dim512, 28층, dense, CLA2, 무재귀 | **31.1 MiB · 15.55 tok/s** | 연구 challenger; 지금 승격하지 않음 |

**현재 권고는 B를 단일 연구·학습 기준의 1순위, A를 32 MiB 배포 프로필의 1순위로 남기는
2단 분리다.** C와 D는 후보군에서 지우지 않지만 바로 승격하지 않는다. C는 속도 바닥보다
0.84 tok/s만 높고 held-out 서열이 불안정하다. D는 폭 손실을 깊이로 상쇄했지만 기준 대비
−0.0011이 현재 자 안이며 사전 채택선 −0.02에 못 미쳤다.

기준 프리셋은 결국 하나여야 한다. 사용자가 “연구 기준”과 “32 MiB 배포 프로필” 중 어느 역할을
`PRESETS`의 단일 표준으로 소유하게 할지 결정하기 전에는 A와 B를 동시에 기본값으로 만들지 않는다.

## 1. 3~5차 리뷰에서 무엇을 이어받고 무엇을 폐기했나

| 원문 | 지금도 유효한 것 | 현재 증거로 정정·폐기한 것 | 6차 반영 |
|---|---|---|---|
| **3차 v1** | packed/storage와 runtime residency를 분리하고 32/40 MiB 예산을 함께 본다 | 20층 tied 몸통 중심 네 안, KV 누락, 미실측 임베딩 가격 | 레버 이력만 보존; 후보 몸통은 실제 dense 승자 계열로 교체 |
| **3차 v2** | 32/40 MiB를 별도 선으로 보고 깊이·재귀·CLA·양자화 가격을 함께 본다 | 재귀 후보의 속도 누락, 3:4 가정, 미측정 d14 공백 | 무재귀 d14/d16/d18과 실제 tok/s·상주로 다시 계산 |
| **4차** | full-val 하나로 지능을 말할 수 없고 외부 모델과 평가 경로가 필요하다 | 당시 held-out 자체가 결함이고 판본 간 패널이 달라 강한 순위 주장이 불가 | 후보 승격에 P096의 새 봉인 final을 요구 |
| **5차** | architecture preset·학습 recipe·배포 profile을 한 이름에 조용히 섞지 않는다; `m100R5` 명명 원칙 | 당시 Muon jordan×15와 미완료 X1~X6를 기준으로 한 네 후보 | RMS4·WD0, 실측 d18, 폭 Stage2b, exact tying 기각을 반영해 후보 재선정 |

2차 확정본의 결론인 **KD 제거**, 부모 초기화, 메모리 허용 시 `--no-ckpt`는 training recipe의
기반으로 이어받는다. 다만 이는 architecture preset 필드가 아니므로 후보 A~D의 구조와 별도 표에 둔다.

## 2. 5차 이후 새로 닫힌 사실

### 2.1 optimizer — jordan×15가 아니라 RMS4·matrix WD 0

[결과 078](../../test_result/078_20260911_P005b-RMS4는-jordan20을-이겼지만-한-형상이다.md)은
`muon_scale=rms`, `muon_lr_mult=4`, matrix WD 0이 다음 경계를 통과했다고 기록한다.

- seed1337의 재귀 d12와 무재귀 d12/d14/d16/d18
- seed2024의 d12/d16
- 600M 학습의 네 형상
- 1.2B 학습의 d16

600M paired full-val에서 RMS4는 d14 **3.4894**, d16 **3.4635**, d18 **3.4557**이었다.
1.2B d16은 **3.3833**이다. 이 수치는 같은 조건 안 optimizer 방향의 근거이지, 한국어 품질이나
다른 데이터 풀·모델 규모의 보편성 증거가 아니다. 특히 해당 1.2B eval은 한국어 0%다.

### 2.2 배포 — d14/d16/d18과 narrow/deep의 실제 경계

배포 수치는 [결과 014](../../test_result/014_20260731003000_P030-CPU추론실측-양자화오버헤드.md),
[결과 074 §26](../../test_result/074_20260904_P085-정답CE는-9쌍-전부-맞고-정확도는-끝까지-못-가른다.md),
[결과 077](../../test_result/077_20260908_P089-폭을-줄이면-같은-예산에-층을-두-배-쌓고-속도-바닥도-넘는다.md)을 따른다.

| 구조 | runtime lower-bound | 단일코어 | 판정 |
|---|---:|---:|---|
| d14 무재귀 | **30.8 MiB** | **19.19 tok/s** | 32 MiB와 15 tok/s 모두 통과 |
| d16 무재귀 | **34.0 MiB** | **17.35 tok/s** | 40 MiB와 15 tok/s 통과 |
| d18 무재귀 | **37.1 MiB** | **15.84 tok/s** | 40 MiB와 15 tok/s 통과, 속도 여유 작음 |
| dim512 d28 | **31.1 MiB** | **15.55 tok/s** | 32 MiB와 15 tok/s 통과, 품질 채택선 미달 |

이 값은 모델 tensor+KV의 현재 계측 경로이지 전체 제품 프로세스 peak의 보증이 아니다. tokenizer,
코드 페이지, allocator와 native runtime까지 포함한 32/40 MiB E2E는 여전히 `NOT_RUN`이다.

### 2.3 폭·타잉·held-out

- [결과 077 §12](../../test_result/077_20260908_P089-폭을-줄이면-같은-예산에-층을-두-배-쌓고-속도-바닥도-넘는다.md):
  dim512 폭 대가 +0.1017을 L14→28 깊이 회복 +0.1028이 상쇄했지만 순이득은 **−0.0011**로
  자 안이다. D는 성공 확정이 아니라 challenger다.
- [결과 079](../../test_result/079_20260911_P045B-작은-g와-어텐션타잉은-모두-기준선에-졌다.md):
  현 Muon·d12·CLA2·무재귀에서 exact MLP `g2/g4`와 attention `ag2`는 dense보다 열세다.
  따라서 네 후보의 기본 몸통에 exact tying을 넣지 않는다.
- [결과 074 §27](../../test_result/074_20260904_P085-정답CE는-9쌍-전부-맞고-정확도는-끝까지-못-가른다.md):
  held-out v3.0은 같은 seed2 패널에서도 v2.9보다 core 세 축이 회귀했다. 현재 held-out만으로
  A~D의 지능 서열을 확정하지 않으며 [P096](../../test_plan/P096_held-out-변별정보-난이도-가족편향-품질향상.md)의
  독립 final이 승격 gate다.

## 3. 한 프리셋에 섞지 말아야 할 세 층

### 3.1 Architecture preset — `PRESETS`가 소유할 후보 필드

| 필드 | A | B | C | D |
|---|---:|---:|---:|---:|
| 기반 preset | `m100s10` | `m100s12` | `m100s14` | `m100w512s24` |
| `dim` | 768 | 768 | 768 | 512 |
| `ffn_dim` | 2048 | 2048 | 2048 | 1408 |
| total / middle layers | 14 / 10 | 16 / 12 | 18 / 14 | 28 / 24 |
| Q/KV heads | 12 / 3 | 12 / 3 | 12 / 3 | 8 / 2 |
| MLP | dense | dense | dense | dense |
| `cla_group` | 2 | 2 | 2 | 2 |
| recurrence | 없음 | 없음 | 없음 | 없음 |
| vocab / emb rank | 32,768 / 256 | 32,768 / 256 | 32,768 / 256 | 32,768 / 256 |

exact MLP/attention tying, recurrence, emb-rank 축소와 3:4 sparse는 어느 후보에도 기본으로 넣지 않는다.
완화 타잉은 P093, 레이어 상태 제어는 P091의 독립 게이트를 통과한 뒤의 후속이다.

### 3.2 Training recipe profile — 구조와 별도 승인할 항목

| 항목 | 현재 후보값 | 근거·경계 |
|---|---|---|
| optimizer | Muon `rms×4`, matrix WD 0 | 결과 078; code default 변경은 아직 미승인 |
| base LR / schedule | `1e-3`, WSD, `anneal_end=0.80`, `decay_frac=0.2` | 현재 A~C RMS4 증거의 조건서명 |
| effective batch | `8×16×1024 = 131,072` tokens/update | microbatch를 바꾸면 accum으로 유지 |
| KD | off | 2차 리뷰 확정 |
| initialization | `--init-from --depth-init role` | 현 비교 계보; 부모 tag/signature 기록 |
| memory knobs | `--ce-chunk 2048`, `--no-ckpt`는 예산 허용 시 | architecture field가 아님 |
| compile | on | 현 학습 조건; backend 변화 시 재검증 |

D는 아직 jordan×15·300M 계보의 본런 근거만 있으므로 이 RMS4 profile과 결합한 품질은
`NOT_RUN`이다. A~C와 같은 표에서 D의 val을 직접 빼지 않는다.

### 3.3 Deployment profile — 학습·architecture와 별도인 항목

현재 상주 근거는 latent 해제, LUT 1.600 bpw, embedding INT8, 1024-token 16-bit KV를 조합한
경로다. 계측은 BF16 KV를 사용했다. FP16 KV도 2 byte지만 dtype 기본값의 소유권과 정확도·range
판정은 별도이므로 이 리뷰에서 조용히 교체하지 않는다. native kernel 속도와 전체 process RSS도
architecture preset의 일부로 넣지 않는다.

## 4. 후보 A — 32 MiB mainstream: d14 dense CLA2 무재귀

### 4.1 구성

- 구조: `m100s10`, dim768, ffn2048, `2+10+2`, Q12/KV3, dense MLP, CLA2, 무재귀.
- 학습 후보: Muon RMS4·matrix WD0, WSD 0.80/0.20, no KD, parent init.
- 배포: LUT1.600 + INT8 embedding + 16-bit KV@1024의 현 계측 경로.

### 4.2 승격후보로 제안한 근거

- **30.8 MiB / 19.19 tok/s**로 32 MiB와 속도 바닥을 동시에 가장 여유 있게 통과한다.
- 600M RMS4 full-val **3.4894**로 optimizer 전이도 확인됐다.
- exact tying이나 recurrence 없이 단순한 dense 경로라 구현·배포 해석이 가장 쉽다.

### 4.3 남은 gate

- RMS4 seed2024는 d14에서 직접 재현되지 않았다. 형상 전이는 있지만 d14 자체 2-seed는 아니다.
- P096 독립 held-out, 한국어 평가와 전체 process RSS가 `NOT_RUN`이다.
- 단일 연구 기준으로 B보다 낮은 용량을 택할 값어치가 있는지는 “32 MiB가 표준 역할인가”라는
  사용자 제품 결정에 달려 있다.

## 5. 후보 B — 40 MiB research/reference: d16 dense CLA2 무재귀

### 5.1 구성

- 구조: `m100s12`, dim768, ffn2048, `2+12+2`, Q12/KV3, dense MLP, CLA2, 무재귀.
- 학습·배포 profile은 §3.2·§3.3과 같다.

### 5.2 승격후보로 제안한 근거

- **34.0 MiB / 17.35 tok/s**로 40 MiB와 속도 바닥에 모두 여유가 있다.
- RMS4는 seed1337·seed2024, 300M·600M·1.2B의 d16에서 방향을 재현했다.
- 600M full-val **3.4635**, 1.2B **3.3833**으로 네 후보 중 조건 전이 증거가 가장 넓다.
- 현 연구 기준으로 삼으면 A/C와 비교할 때 구조 차이가 깊이 하나라 해석이 쉽다.

### 5.3 남은 gate

- 한국어 0% eval인 장기 결과를 한국어 품질로 승격할 수 없다.
- 현재 held-out 판본은 신뢰성 문제가 있어 과제 우위를 확정하지 못한다.
- 32 MiB mainstream 역할은 맡을 수 없으므로 배포 프로필 A와 역할을 명시적으로 분리해야 한다.

---

## 6. 후보 C — 40 MiB quality edge: d18 dense CLA2 무재귀

### 6.1 구성

- 구조: `m100s14`, dim768, ffn2048, `2+14+2`, Q12/KV3, dense MLP, CLA2, 무재귀.
- 학습·배포 profile은 §3.2·§3.3과 같다.

### 6.2 승격후보로 제안한 근거

- 600M RMS4 full-val **3.4557**로 A~C 중 가장 낮다.
- **37.1 MiB / 15.84 tok/s**를 실제로 측정해 40 MiB와 15 tok/s 바닥을 모두 넘겼다.
- d16보다 약 3.1 MiB를 더 써서 같은 계열의 depth capacity를 추가하는 명료한 trade-off다.

### 6.3 남은 gate

- 속도 여유가 **0.84 tok/s**뿐이라 native runtime·전체 process에서 바닥을 잃을 위험이 크다.
- d16→d18의 full-val 개선이 과제별 개선으로 전이한다는 증거가 없고, held-out 판본에 따라
  깊이 서열이 흔들렸다.
- d18 자체 seed2024 RMS4와 1.2B RMS4는 `NOT_RUN`이다. 따라서 지금 B를 밀어내는 단일 기본값이
  아니라 40 MiB quality-edge 조건부 후보다.

---

## 7. 후보 D — narrow/deep challenger: dim512 d28

### 7.1 구성

- 구조: `m100w512s24`, dim512, ffn1408, `2+24+2`, Q8/KV2, dense MLP, CLA2, 무재귀.
- 현 본런 근거: Muon jordan×15, 300M, 별도 dim512 부모 계보.
- 제안 recipe인 RMS4·WD0과의 조합은 아직 실행하지 않았다.

### 7.2 승격후보로 남긴 근거

- **31.1 MiB / 15.55 tok/s**로 32 MiB와 속도 바닥을 동시에 통과한다.
- dim512 폭 대가 **+0.1017**을 L14→28 깊이 회복 **+0.1028**이 상쇄해 32 MiB에서
  폭·깊이 교환이 가능하다는 것을 보여 줬다.
- A와 다른 계산 형태라 향후 narrow CPU kernel이나 cache locality가 바뀔 때 독립 Pareto가 될 수 있다.

### 7.3 지금 승격하지 않는 이유

- 최종 full-val **3.5597**은 당시 dim768 d14 **3.5608**보다 −0.0011뿐이며 자 안이다.
- 사전 채택선 −0.02를 못 넘었고 held-out, dim384, 같은 RMS4 recipe, 다른 seed는 `NOT_RUN`이다.
- 속도도 A의 19.19보다 느리므로 현재 증거에서는 A를 지배하지 않는다.

## 8. 네 안의 동등 비교표

| 축 | A d14 | B d16 | C d18 | D w512 d28 |
|---|---:|---:|---:|---:|
| 예산 역할 | 32 mainstream | 40 research | 40 quality edge | 32 challenger |
| runtime lower-bound MiB | **30.8** | **34.0** | **37.1** | **31.1** |
| 1-core tok/s | **19.19** | **17.35** | **15.84** | **15.55** |
| 600M RMS4 paired full-val | 3.4894 | **3.4635** | **3.4557** | `NOT_RUN` |
| seed2024 RMS4 | 형상 전이만 | ✅직접 | 형상 전이만 | `NOT_RUN` |
| 1.2B RMS4 | `NOT_RUN` | ✅3.3833 | `NOT_RUN` | `NOT_RUN` |
| current held-out 승격근거 | 신뢰판 없음 | 신뢰판 없음 | 신뢰판 없음 | `NOT_RUN` |
| 즉시 승격 준비도 | 조건부 높음 | **가장 높음** | 중간 | 낮음 |

주의: D의 3.5597은 300M jordan×15 계보이고 A~C의 표 수치는 600M RMS4 계보다. 이 행들은
각 후보의 증거 범위를 보여 주기 위한 것이며 D−A 같은 직접 차이를 허용하지 않는다.

## 9. 승격 전 공통 gate와 사용자 검토 항목

### 9.1 공통 gate

| gate | A | B | C | D |
|---|---|---|---|---|
| architecture/default-off 계약 | 기존 preset 기반 | 기존 preset 기반 | 기존 preset 기반 | 기존 preset 기반 |
| RMS4 동일 recipe | ✅600M | ✅seed·600M·1.2B | ✅600M | 🚫 |
| 2-seed 해당 형상 | 🚫 | ✅ | 🚫 | 🚫 |
| P096 독립 held-out final | 🚫 | 🚫 | 🚫 | 🚫 |
| 32/40 MiB 모델+KV | ✅32 | ✅40 | ✅40 | ✅32 |
| 전체 process RSS | 🚫 | 🚫 | 🚫 | 🚫 |

현재 증거로는 B의 연구 기준 승격 심사가 가장 잘 닫혀 있다. 그러나 held-out/P096과 제품 전체
RSS를 모두 요구하면 네 후보 모두 미완료다. 사용자는 승격의 의미를 다음 둘 중 먼저 고정해야 한다.

1. **연구 재현 기준**: 같은 학습 조건·optimizer 비교의 anchor. 이 역할에는 B를 권장한다.
2. **32 MiB 배포 기준**: 모델+KV가 mainstream budget 안에 드는 anchor. 이 역할에는 A를 권장한다.

둘을 동시에 보존할 수는 있지만 `표준 preset` 표시는 하나만 둔다. 다른 하나는 명시적 deploy
profile/비교 preset으로 둔다.

### 9.2 이름

5차 리뷰에서 사용자가 확정한 후보 승격명 `m100R5`를 유지한다. 5차가 실제 승격되기 전에
6차가 열렸다고 `m100R6`를 만들면 구현되지 않은 R5 세대를 건너뛴다. 따라서 A~D는 검토용
ID일 뿐이며, 최종 승자 하나만 별도 사용자 승인 뒤 `m100R5` 이름을 받는다.

### 9.3 사용자에게 필요한 최종 결정

- 단일 표준의 역할을 연구 기준(B 권장)과 32 MiB 배포 기준(A 권장) 중 어디에 둘지.
- architecture 승격과 RMS4 training recipe 승격을 함께 승인할지, 분리 승인할지.
- BF16/FP16 KV와 LUT/embedding INT8을 preset이 아니라 deploy profile로 유지할지.
- C/D의 남은 실험을 승격 선결로 요구할지, 조건부 후보로 보존할지.

## 11. 잠정 권고

1. **후보군 유지:** A/B/C/D 네 안을 사용자 검토 대상으로 유지한다.
2. **상위 두 안:** B는 연구 기준, A는 32 MiB 배포 기준의 1순위다.
3. **조건부 두 안:** C는 P096 과제·속도 여유 확인 뒤, D는 RMS4 동일 recipe와 채택선 재충족
   뒤에만 상위 후보로 올린다.
4. **승격 분리:** architecture, training recipe, deployment profile을 세 승인으로 분리한다.
5. **현재 상태:** 이 문서는 초안이며 실제 preset 승격은 `NOT_RUN`이다.
