# 6차 리뷰 (전면 재작성) — 기준 프리셋 승격후보 네 안과 공통 학습·평가 조건

> **작성·재감사** 2026-09-18 · **후속 증거 갱신** 2026-09-22 · **상태** ⏳사용자 후보군 검토 대기
> **판정** `REVIEW_ONLY` · preset 승격 `NOT_RUN` · 후보 본런용 SH 작성 `NOT_RUN`
> **사용자 확정 recipe** Muon RMS4 기본 · KD off
> **신규 학습 경계** 1.2B 학습토큰 SH 금지, 한국어 학습·평가 문제를 피하기 위해 신규 본런은
> 600M 이하에서만 설계하고 600M 경계에도 언어 구성 gate를 둔다.

이 문서는 3~5차 리뷰를 단순 요약한 것이 아니라 `docs/`, `docs/methods/`, `test_result/`를
다시 대조해 네 후보를 평가하는 정본 초안이다. 구조의 층 수만 비교하지 않고 다음 네 층을
분리한다.

1. **architecture preset**: 폭·깊이·head·CLA·재귀·타잉
2. **공통 training recipe**: optimizer·WD·KD·초기화·schedule·batch·반복 노출
3. **evaluation contract**: 같은 시험지·언어·시드·metric·분해능
4. **deployment profile**: LUT·embedding/KV dtype·context·thread·전체 RSS

최종 preset은 하나일 수 있지만, 연구 기준과 32 MiB 배포 기준은 역할이 다르다. 현재 증거로는
**B를 연구 anchor 1순위, A를 32 MiB 배포 anchor 1순위**로 유지한다. C와 D는 독립 질문을
가진 challenger다. 네 안 모두 사용자 승인과 남은 gate 전에는 승격 완료가 아니다.

2026-09-22 후속에서 A(d14 CLA2)의 LR1.5e-3이 LR1.0e-3보다 3-seed 모두
우세했지만 평균 회수는 0.0027 nats다([078 §16](../../test_result/078_20260911_P005b-RMS4는-jordan20을-이겼지만-한-형상이다.md#16-stage13142026-09-22--cla2의-lr-15e-3-후보가-3-seed-동일-방향으로-재현됐다)).
B/C의 동일 LR panel은 `NOT_RUN`이므로 기존 동일-LR 후보표를 A의 최적화 수치로
조용히 교체하지 않는다. 따라서 A/B 역할 순위는 바뀌지 않으며, LR은 공통값이 아닌
형상별 교정 축으로 재분류한다.

## 0. 결론 요약

| 후보 | 역할 | 구조 | 배포 실측 하한 | 동일 LR1.0·300M RMS4 full-val | 형상별 LR 교정 증거 | 현재 판정 |
|---|---|---|---:|---:|---|---|
| **A** | 32 MiB mainstream | dim768, 14층, dense, CLA2 | **30.8 MiB · 19.19 tok/s** | **3.5509** | LR1.5 seed1337 **3.5480**, 3-seed 평균 **3.5493** | 32 MiB 1순위 |
| **B** | 연구/reference | dim768, 16층, dense, CLA2 | **34.0 MiB · 17.35 tok/s** | **3.5288** | `NOT_RUN` | 연구 기준 1순위 |
| **C** | 40 MiB quality edge | dim768, 18층, dense, CLA2 | **37.1 MiB · 15.84 tok/s** | **3.5193** | `NOT_RUN` | 조건부 후보 |
| **D** | narrow/deep challenger | dim512, 28층, dense, CLA2 | **31.1 MiB · 15.55 tok/s** | `NOT_RUN` | `NOT_RUN` | 지금 승격하지 않음 |

동일 LR1.0 full-val은 [결과 078 §8](../../test_result/078_20260911_P005b-RMS4는-jordan20을-이겼지만-한-형상이다.md)의
**300M draw / 600M pool / seed1337 / 같은 tokenizer·paired evaluation**이다. 600M pool val의
한국어 비율은 **5.5%**라 한영 종합 품질 대표성은 약하다. 그래도 A~C를 같은 시험지에서 비교한
가장 깨끗한 현재 표다.

A의 LR1.5 수치는 A 내부의 최적화 증거이다. B/C와 LR 축이 다르므로
`3.5480-3.5288` 등을 구조 차이로 직접 해석하지 않는다. 새 편성 시에는 A는 LR1.5를
후보로 쓰되, 공정한 승격 비교는 B/C 형상별 LR 교정 전까지 동일 LR1.0 anchor를 보존한다.

역사적 600M RMS4 수치 `A 3.4894 / B 3.4635 / C 3.4557`은 **1.2B pool의 한국어 0% val**에서
측정됐다. optimizer 길이 전이에는 유효하지만 한국어 품질이나 신규 preset 승격의 주 계기로
쓰지 않는다. 1.2B d16의 3.3833도 같은 이유로 참고 이력에만 둔다.

현재 최종 권고는 다음과 같다.

- **architecture**: A/B를 상위 두 안으로 유지. C는 속도 여유·과제 전이 확인 뒤, D는 RMS4 동일
  recipe와 실제 downstream을 확인한 뒤 재심사한다.
- **training recipe**: 사용자 결정대로 **Muon RMS4, matrix WD0, KD off**. 단 embedding·norm·LRM의
  WD는 별도 parameter-group 정책을 따른다.
- **반복 학습**: 이미 1→2→4 epoch-equivalent 이득이 실측됐으므로 승격 설계에 반드시 넣는다.
  다만 순차 epoch가 아니라 복원추출 랜덤 크롭이며, 역사적 4회는 1.2B draw라 **재실행하지 않는다**.
- **실행 파일**: 이 재작성본을 사용자가 검토하기 전 후보 본런 `.sh`는 만들지 않는다.

### 1.3 이번 후보표에 직접 합치지 않은 `docs/` 범위

## 2. 먼저 고정할 공통 조건 — 구조와 무관한 개선 목록

사용자가 지적한 대로 후보 비교는 dense 층 수 표만으로 끝나지 않는다. 아래는 A~D 모두에
공통 적용하거나 공통 gate로 확인해야 하는 조건이다.

### 2.1 채택할 공통 training recipe

| 축 | 공통값 | 내부 근거 | 적용 조건·한계 |
|---|---|---|---|
| optimizer | **Muon RMS4** | 결과 078: 형상 5조건, seed2024 2조건, 길이 전이 | 이번 사용자 결정. post-change smoke 전 구현은 `STATIC_ONLY` |
| matrix WD | **0** | RMS4 WD0 3.5279 vs WD0.1 3.5325 | embedding WD0.1·특수 파라미터 WD0과 구분 |
| KD | **off** | 300M 두 seed 악화, VRAM·시간도 손해 | 100M 예외 이력은 있으나 기준 recipe에는 미사용 |
| initialization | **parent role-init** | 기여 0.1386, KD보다 절대크기 43배 | parent identity·shape·hash 기록 필요 |
| schedule | **WSD 0.80/0.20** | cosine 대비 −0.0755 | 반복량을 늘리면 절대 schedule horizon도 같이 늘어남 |
| learning rate | **형상별 교정**; 동일-조건 anchor `1e-3` | A에서 LR1.5e-3이 3-seed 3/3 우세, B/C/D는 동일 sweep `NOT_RUN` | LR1.5를 공통값이나 전역 기본값으로 승격 금지 |
| effective batch | **131,072 tokens/update** | `8×16×1024`; 기존 비교 계보 | micro-batch를 바꿔도 accum으로 유지 |
| microbatch knee | **`M=micro_bs×seq=8192`** | M4096은 −8.7%, M8192 무릎 | seq 변경 시 micro_bs 역조정 |
| precision | **BF16 autocast** | 현 표준 경로 | optimizer state dtype과 혼동 금지 |
| compile | **on** | 현 비교 계보·속도 조건 | backend 변경 시 재스모크 |
| checkpointing | VRAM 안전 시 **`--no-ckpt`** | 속도 방향은 개선, 정직한 범위 약 6~20% | peak reserved·spill을 먼저 확인; 공짜 기본값 아님 |
| CE memory | `--ce-chunk 2048` | 현 장기런 조건 | 품질 변경축이 아닌 메모리 실행조건 |
| cache | `--exact-cache`, pool/token 명시 | 결과 075의 시험지 교락 방지 | pool이 다르면 log val 직접 비교 금지 |
| ternary micro-group | 현 계보의 **128 유지** | 기존 공통 경로·소규모 대조 | 구조 독립 보편 이득이라고 주장하지 않음 |
| grad clipping | **1.0 고정** | 모든 현 런의 공통 경로 | 값 자체의 대조가 없어 개선 레버가 아니라 비교 통제값 |
| ternary anneal | **미확정: 0.60 vs 0.80** | 기준표는 0.60 유지, A~C RMS4 근거 런은 0.80 | 아래 정합성 gate 전 후보 SH 금지 |

#### 공통 recipe와 실제 CLI 기본값의 정합성

옵션을 생략한 명령이 위 표를 재현하지 않는다. 이 차이는 후보 SH 작성 전에 반드시 명시적으로
닫아야 한다.

| 축 | 승격 검토 recipe | 현재 CLI/코드 기본 | 상태 |
|---|---|---|---|
| optimizer | Muon RMS4 | **Muon RMS4** | 코드 반영 `STATIC_ONLY`; 새 smoke 필요 |
| matrix WD | Muon 행렬 0, optimizer-aware group | `None`이 같은 라우팅을 뜻함 | CPU 계약 PASS; 실제 새 학습 `NOT_RUN` |
| KD | off | off(opt-in `--kd`) | 일치 |
| learning rate | 동일-비교 anchor `1e-3`; A 후보 `1.5e-3`; B/C/D 미교정 | `6e-4` | **불일치**, 후보별 명시 필요; 공통 LR 확정 금지 |
| scheduler | WSD, decay 0.2 | cosine | **불일치**, 모든 후보 명령에 명시 필요 |
| effective batch | accum16, micro8, seq1024 | accum8, micro8, seq1024 | **불일치**, 생략하면 학습토큰이 절반 |
| grad checkpoint | 후보별 VRAM 확인 후 no-ckpt | checkpoint on | 명시 필요 |
| ternary anneal end | 기준표 0.60 / RMS4 증거 0.80 | 0.60 | **미해결 교락** |

`anneal_end=0.80`은 WSD의 stable 80%와 이름이 비슷하지만 다른 축이다. 전자는 삼진화 진행률,
후자는 LR schedule이다. 결과 078의 A~C RMS4 수치를 이어받으려면 0.80을 유지해야 하고, 현재
기준표의 0.60 표준으로 승격하려면 최소한 bridge 대조가 필요하다. 사용자가 둘 중 하나를
승인하기 전에는 “공통 recipe 확정”이나 후보 학습 SH 작성을 하지 않는다.

LR은 이제 공통 recipe의 한 숫자가 아니다. Stage13~14에서 A/d14 CLA2의 후보는
1.5e-3로 교정됐지만, 그 효과는 LR1.0 대비 평균 0.0027 nats로 A/B 간 동일-LR
격차 0.0221을 뒤집지 않는다. B/C/D에는 각 형상의 최적 LR 증거가 없으므로
후보 명령은 구조별 근거를 따로 쓰고, 형상 비교표에서는 LR1.0 anchor를 유지한다.

### 2.3 공통 평가 계약

| 평가 | 역할 | 금지하는 오독 |
|---|---|---|
| 같은 pool의 paired full-val | 미세한 LM loss 차이 | 다른 pool·언어의 값을 직접 빼지 않음 |
| common bpb | pool/tokenizer가 다른 모델의 동일 원문 비교 | 현재 영어 SQuAD만으로 한국어 품질 주장 금지 |

| checkpoint 값 | JSON `final` + paired eval | 주기 50it와 최종 100it가 달라 `best`로 런 비교 금지 |
| 사용자 실제 텍스트 probe | 정성 continuation + teacher-forced NLL/bpb | base LM의 샘플이며 벤치 점수·chat 능력으로 승격 금지 |

### 2.4 deployment profile에만 둘 공통 조건

- LUT 1.600 bpw, embedding INT8/BF16, KV BF16은 **architecture preset이 아니라 배포 profile**이다.
- 현재 MiB는 모델 tensor+KV 회계의 lower-bound다. tokenizer, allocator, 코드 페이지, native runtime을
  포함한 전체 process RSS는 네 후보 모두 `NOT_RUN`이다.
- prefill 전체 vocab logits 대신 마지막 위치만 계산하는 경로는 128 MiB→0.125 MiB 산술 이득과
  argmax 40/40 일치가 있지만 비트 동일하지 않다. architecture 점수가 아니라 native 배포 profile의
  정확성 gate로 둔다.
- BF16 KV는 KV를 절반으로 줄이는 유망 공통 profile이지만, 학습 품질 개선 조건은 아니다.
- 메모리 감소가 속도 증가를 뜻하지 않는다. 현 int8 경로는 오히려 언팩 때문에 느려진 실측이 있다.
- CPU 속도는 batch 1, 1 thread, 현재 배포 경로를 붙여 인용한다. 후보 C/D는 15 tok/s 바닥
  여유가 각각 0.84/0.55뿐이다.

## 3. 반복학습 축 — 6차 리뷰의 필수 설계 변수

### 3.1 이미 측정된 것

[결과 073](../../test_result/073_20260904_P087-두-번째-epoch은-과적합-없이-0.1155를-준다.md)의
같은 300M pool·같은 val·d12 재귀 계열은 다음과 같다.

| 명목 노출 | steps | 학습 draw | final val | 직전 대비 | unique coverage | `val−train_ce` |
|---|---:|---:|---:|---:|---:|---:|
| 1 epoch-equivalent | 2,289 | 300M | **3.64328125** | — | 63.21% | +0.108 |
| 2 epoch-equivalent | 4,578 | 600M | **3.52781250** | **−0.11547** | 86.47% | +0.109 |
| 4 epoch-equivalent | 9,156 | 1.2B | **3.45343750** | **−0.07438** | 98.17% | 꼬리평균 +0.0969 |

관측 범위에서는 4회까지 과적합 징후가 없고 배포 메모리 증가는 0이다. 그러나 다음 네 제한이 있다.

1. **후보 A~D가 아니라 d12 재귀·구 optimizer 계보**의 결과다.
2. Loader는 순차 epoch가 없는 **균일 복원추출 random crop**이다. “2 epoch”은 `draw/pool=2`의
   편의명이지 모든 샘플을 두 번 본다는 뜻이 아니다.
3. draw를 늘리면 WSD의 절대 plateau·cooldown 지평도 함께 길어진다. 순수 반복 횟수만 바뀐
   실험이 아니다.
4. 역사적 e4는 1.2B draw다. 사용자 경계에 따라 **신규 후보에서 재현하거나 SH로 만들지 않는다**.

### 3.2 다양성과 반복을 함께 읽어야 한다

[결과 075 §14.7](../../test_result/075_20260905_P088-토큰은-스텝이었고-full-val-은-학습데이터였다.md)는
같은 600M draw에서 300M pool의 2회 노출 `common_bpb=1.2623`보다 1.2B pool의 0.5회 노출
`1.2262`가 좋았다고 기록한다. 더 다양한 pool이 GPU 시간 절반의 역사적 e4 `1.2342`도 이겼다.

이는 “반복이 무효”라는 뜻이 아니다. **새 텍스트와 더 많은 steps가 둘 다 유효하지만**, 같은
compute라면 충분한 언어 균형을 가진 다양성이 우선이라는 뜻이다. 과거 1.2B pool은 한국어 원천이
소진되어 train 약 25%, val 0%였으므로 그 pool을 신규 한국어 기준으로 재사용하지 않는다.

### 3.3 후보 승격용 반복 설계 — 아직 SH로 만들지 않는 안

사용자 경계와 기존 증거를 동시에 만족하는 권장 설계는 두 단계다.

**R0 — 네 후보 recipe 정렬**

- A/B/C는 300M draw·600M pool·RMS4 결과가 이미 있다.
- 먼저 `anneal_end=0.60/0.80` 중 승격 recipe를 정하거나 bridge를 통과한다.
- 그 뒤 D만 같은 300M/600M/RMS4 조건이 `NOT_RUN`이므로 D 한 팔을 맞춘다.
- 같은 paired full-val과 공통 영어/한국어 원문을 사용해 네 후보의 300M anchor를 닫는다.

**R1 — 상위 두 안 A/B의 반복 노출 2×2**

| 축 | 값 |
|---|---|
| architecture | A d14, B d16 |
| pool | **300M 고정** |
| draw | **300M(1 eq), 600M(2 eq; 한국어 gate 통과 시에만)** |
| optimizer | Muon RMS4, matrix WD0 |
| 공통 | KD off, parent init, WSD, batch 131072, seed1337 |
| 주 평가 | 같은 300M-pool paired full-val + 한국어/영어 common text + P096 final/KoBEST |

이 설계는 draw를 600M에서 멈추면서 실제 1→2 epoch-equivalent 교호작용을 후보 A/B에서 직접
검정한다. 단 300M pool은 다양성 표준보다 작으므로 “최종 학습 recipe”가 아니라 **반복 효과를
분리하는 진단 설계**다. 승자는 이후 언어 균형을 보존한 600M 이하 pool에서 별도 확인해야 한다.

**R2 — C/D 조건부 진입**

- C는 B 대비 300M full-val 개선 **0.0095**가 실제 downstream·전체 RSS·속도 여유에서도 값어치가
  있을 때만 반복 팔을 연다.
- D는 R0에서 RMS4 동일 recipe가 A의 품질/속도/메모리 중 하나를 실질적으로 지배할 때만 반복
  팔을 연다.

R0/R1의 pool 선택과 평가 panel을 사용자가 승인하기 전에는 candidate `.sh`를 만들지 않는다.
특히 1.2B 학습토큰 파일과 48시간을 채우기 위한 padding 실험은 만들지 않는다.

### 5.1 같은 조건의 LM loss와 배포 성능

| 축 | A d14 | B d16 | C d18 | D w512 d28 |

### 5.4 프로젝트 수준의 실제 능력 바닥

[결과 056](../../test_result/056_20260823_P069-벤치13종-hellaswag와-piqa만-살아있다.md)의 구형

## 6. 후보별 상세 판정

### 6.1 A — d14, 32 MiB mainstream

**강점**

- 30.8 MiB와 19.19 tok/s로 32 MiB·15 tok/s를 가장 여유 있게 동시에 통과한다.
- 같은 조건 RMS4 full-val 3.5509로 optimizer 전이가 확인됐다.
- LR1.5e-3이 LR1.0e-3보다 세 seed 모두 낮았고 3-seed 평균 full-val 3.5493을 확보했다.
- 구 held-out v2.7에서 B보다 accuracy·margin이 높아 “얕아서 항상 품질이 낮다”는 단순 결론을
  반박한다.
- 구조가 단순해 배포·디버깅·parent mapping 위험이 가장 낮다.

**한계**

- d14 RMS4 LR panel은 3-seed로 확장됐지만 RMS4 downstream은 `NOT_RUN`이다.
- B/C의 형상별 LR sweep이 없어 A의 LR1.5 값을 A/B/C 구조 직접 비교에 쓰지 못한다.
- 32 MiB는 모델+KV lower-bound일 뿐 전체 process RSS가 아니다.
- B 대비 같은 LR1.0 full-val이 +0.0221 나쁘다. A의 LR1.5 seed1337 값을 참고로
  대입해도 +0.0192지만 LR이 교락되므로 구조 격차로 판정하지 않는다.

**판정**: 32 MiB 배포 기준 1순위. 단일 연구 기준으로는 B 다음이다.

### 6.2 B — d16, research/reference

**강점**

- 34.0 MiB / 17.35 tok/s로 40 MiB와 속도 바닥에 모두 여유가 있다.
- RMS4는 d16에서 seed1337·2024와 여러 길이에서 방향 재현이 가장 넓다.
- A/C와 구조 차이가 깊이뿐이라 optimizer·방법론 연구의 anchor로 해석하기 쉽다.
- A보다 300M RMS4 full-val이 −0.0221 좋고, C와는 0.0095 차이다.

**한계**

- 구 한국어 held-out v2.7에서는 A보다 낮았고 두 seed 모두 d14보다 아래였다.
- 역사적 장기 결과의 val이 한국어 0%라 한국어 품질 근거가 아니다.
- 34 MiB는 32 MiB mainstream 역할을 맡지 못한다.

**판정**: 단일 연구·학습 기준 1순위. downstream panel을 RMS4로 다시 맞춰야 한다.

### 6.3 C — d18, 40 MiB quality edge

**강점**

- A~C 중 300M RMS4 full-val 3.5193으로 가장 낮다.
- 37.1 MiB / 15.84 tok/s를 실제 측정해 40 MiB·15 tok/s를 통과했다.
- Muon15 Stage8에서 v2.7 35.0%, ARC-Easy 38.8%, KoBEST HellaSwag 44.2%로 나쁜 방향만
  나온 후보는 아니다.

**한계**

- B 대비 full-val 이득은 0.0095인데 3.1 MiB를 더 쓰고 1.51 tok/s 느리다.
- 15 tok/s 여유가 0.84뿐이라 전체 process/native runtime에서 바닥을 잃을 위험이 있다.
- d18 RMS4 seed2024, comparable P096 final, 전체 RSS가 `NOT_RUN`이다.

**판정**: 40 MiB quality-edge 조건부 후보. B를 즉시 밀어내지 않는다.

### 6.4 D — dim512 d28 narrow/deep

**강점**

- 31.1 MiB / 15.55 tok/s로 32 MiB와 속도 바닥을 수치상 통과한다.
- 폭 축 대가 +0.1017을 L14→28 깊이 +0.1028이 상쇄해 narrow/deep 교환 가능성을 보였다.
- A와 계산 형태가 달라 향후 narrow CPU kernel/cache locality의 독립 Pareto가 될 수 있다.

**한계**

- 기존 full-val 3.5597은 당시 dim768 d14 3.5608보다 −0.0011뿐이며 사전 채택선 −0.02에 못
  미쳤다.
- A보다 0.3 MiB 크고 3.64 tok/s 느려 현재 배포 표에서 A에 사실상 지배된다.
- RMS4 동일 recipe, 2-seed, held-out/KoBEST/영문 panel이 모두 `NOT_RUN`이다.

**판정**: 연구 challenger. R0 동일 recipe 한 팔이 긍정적일 때만 다음 단계로 간다.

## 10. 사용자 검토가 필요한 결정

1. 단일 `PRESETS` 표준의 역할을 **연구 기준 B**와 **32 MiB 배포 기준 A** 중 어디에 둘지.
2. 다른 하나를 비교 preset으로 둘지, deploy profile 이름으로만 둘지.
3. 기준표의 `anneal_end=0.60`으로 맞출지, RMS4 계보의 0.80을 유지할지, 작은 bridge를 먼저
   둘지. 이 결정이 D와 반복 진단보다 선행한다.
4. R0의 D 동일-recipe 한 팔을 먼저 허용할지.
5. R1의 A/B 반복 진단에서 **300M pool의 1→2 eq**를 사용할지. 이 안은 반복 축을 가장
   깨끗하게 분리하지만 pool 다양성은 표준보다 작다.
6. architecture 승격, training recipe 승격, deployment profile 승격을 세 승인으로 분리할지.

5차에서 제안된 `m100R5` 이름은 아직 실제 승격되지 않았으므로 유지한다. A~D는 검토 ID이며,
최종 승자 하나만 별도 승인 뒤 그 이름을 받는다.

## 11. 이번 리뷰가 하지 않은 것

- A~D 어느 것도 실제 preset으로 승격하지 않았다.
- 후보 본런 `.sh`, 48시간 queue, 1.2B 학습토큰 파일을 만들지 않았다.
- GPU 학습, 모델·체크포인트 로딩, smoke 재실행, 보호 데이터 접근을 하지 않았다.
- historical 1.2B 또는 한국어 0% val 수치를 한국어 품질로 승격하지 않았다.
- 서로 다른 optimizer·pool·tokenizer·panel의 숫자를 하나의 종합점수로 만들지 않았다.
- 기능 계약 PASS를 실제 품질·속도 PASS로 부르지 않았다.

## 12. 잠정 권고

1. **A/B를 상위 두 후보로 유지**한다. B는 연구 anchor, A는 32 MiB 배포 anchor다.
2. **C는 조건부**, D는 동일 RMS4 recipe 전까지 challenger로 둔다.
3. 공통 recipe의 확정 부분은 **Muon RMS4 + matrix WD0 + KD off + parent init + WSD + batch
   131072**다. ternary anneal 0.60/0.80 교락은 architecture와 별도로 먼저 닫는다.
4. 반복 노출을 승격 설계의 독립 축으로 넣되, 신규 draw는 600M 이하이고 1.2B SH는 만들지 않는다.
5. 평가 우선순위는 같은 pool paired full-val → 한국어/영어 common text → P096 final/KoBEST →
   영어 보조 benchmark다. 어느 하나만으로 “지능”을 확정하지 않는다.
6. 사용자 검토 뒤 R0/R1 계획을 확정하고, 그때만 WSL용 `.sh`를 작성한다.
