## 1. ✅확정 ① — **KD 제거**

### 1.1 근거 — 세 겹으로 확인됐다

| 층 | 관측 | 결과 |
|---|---|---|
| **품질** | 무KD 가 KD 를 **−0.0208** 로 이긴다 | 038 |
| **VRAM** | reserved **12.47 → 5.07 GiB (−59%)** | 038 |
| **기여 분해** | 부모초기화 **+0.1386** vs KD **−0.0032** = ★**43배** | 038 |
| ★**교사 품질 가설** | 🚫**기각** — 진짜 외부 교사 `gemma-3-270m` 로도 무KD 가 **−0.00766** 승 | 053 |
| ★**구현 결함 가설** | 🚫**기각** — 실효 α **0.288**(명목 0.5)로 정상 동작 확인 | 042 §11 |

★★**두 반증 가설이 모두 닫혔다.** 종전에는 *"우리 교사(3.8080)가 학생(3.6984)보다 나빠서
그런 것 아닌가"* 라는 여지가 있었는데, **270M 외부 교사에서 부호가 같게 재현**됐다.

### 1.2 ✅**부작용 — 이것이 실은 최대 VRAM 레버였다**

★**학습 VRAM 의 최대 항목은 모델이 아니라 "어휘 전체 위의 KD 손실 계산"** 이다
(+5.48 GiB alloc, 그중 교사 파라미터는 945 MB 뿐).
→ KD 제거가 **`--no-ckpt` 를 열었고**, 그것이 다시 **속도 −20.6%** 를 줬다.

### 1.3 ⚠️확정의 범위

- 🚫**"KD 라는 기법이 무용하다" 가 아니다.** **우리 조건**(100M · 300M 토큰 · 부모초기화 있음)에서
  **부모초기화와 겹친다**는 것이다.
- ⚠️**남은 KD 축은 P082**(rationale · on-policy)이고 **screen 규모 `C0` 가 선결**이다.

## 2. ✅확정 ② — **표준조건 = 안 A**

> 사용자 결정(2026-08-22): *"리뷰2 표준조건은 A로 결정."*

| | 확정값 |
|---|---|
| ★**표준조건** | **안 A** — `--preset m100R1c` + `--init-from` + **KD 제거**. **추가 플래그 없음** |
| ★**표준 명령** | `--data ko-en --tokens 300M --pool-tokens 600M --exact-cache --steps 2289 --micro-bs 8 --accum 16 --seq 1024 --lr 1e-3 --sched wsd --anneal-end 0.80 --decay-frac 0.2 --seed 1337 --eval-every 100 --compile` |
| ★**표준 대조군** | **`mC_initonly`** = full-val **3.6776** (재학습 0) |
| **표준모델**(당시) | `mC_d36_ag4_nokd` = 3.6848 / fp32 상주 379.7 MiB |
| ★**`--no-ckpt`** | **무KD 의 기본값**(사용자 지시). 단 **VRAM 이 허락하는 한** |

### 2.1 ✅**왜 B2(=`--opt-dtype bf16`)가 아닌가** — 근거가 지워졌다

| 조건 | `opt bf16` 의 reserved 이득 | 회계상 절감 |
|---|---:|---:|
| KD | −1.022 GiB | 0.248 |
| ★**무KD** | ★**−0.016 GiB** | 0.248 |

★**회계 절감은 같은데 실측 이득이 64배 다르다** → −1.02 는 대부분 **할당자 파편화**였고
무KD 5.07 GiB 에서는 그럴 여지가 없다. **B2 의 유일한 근거가 사라졌다.**
🚫**그렇다고 `--opt-dtype bf16` 을 폐기하지 않는다** — 예산이 커지면 되살아난다.

### 2.2 ⚠️**`--no-ckpt` 의 조건** — 확정된 것과 아닌 것

| 조건 | reserved | 판정 |
|---|---:|---|
| tied 20층 무KD | **10.31** | ✅**확정** |
| dense 20층 | **12.69** | ✅확정 |
| 🚫**36층 · 재귀** | — | 🚫**OOM**(`--ce-chunk` 로도 안 열린다) |

★**예산식**: `M × 방문 ≤ 294,912`(확인된 최대). **M 을 반으로 하면 방문을 두 배로** 할 수 있다.
⚠️**`M=8192` 에서만 정확**하고 M=4096 에서 −7.8% 과대다 — **예측식이 아니라 안전선**이다.

## 4. ✅확정 ④ — **메모리 레버는 하나의 효율선 위에 있다**

이 리뷰의 §4(초안)가 *"효율선과 볼록성"* 으로 처음 그린 것이 **그 뒤 두 번 확인**됐다.

| 레버 | 실측 |
|---|---|
| g16 vs prelude/coda 1+1 | **0.0167 vs 0.0199 nats/MB(packed)** = 같은 효율선 |
| 어텐션 타잉 vs MLP 타잉 | **0.00083 vs 0.00342 nats/유니크삼진100만** = 어텐션이 4.1배 싸다 |
| ★2026-09 재확인(상주 기준) | cla2e **0.00447** · 세 번째 방문 **0.00493** · 깊이 12→16 **0.00531** nats/MiB |

★★**그리고 방향이 정정됐다** — 초안은 *"레버 가격이 볼록하다(작은 기반 위에서 비싸다)"* 고 적었는데,
**상주 축에서 다시 재니 큰 걸음일수록 싸다.** 🚫**"볼록성" 을 법칙으로 쓰지 않는다**(MLP 축이 반례).

### 4.1 ✅**메모리를 안 쓰고 품질을 사는 레버 둘** — 초안이 처음 지목했고 지금도 유효하다

| 레버 | Δ 품질 | Δ 상주 |
|---|---:|---:|
| **재귀 R2** | **−0.0202** | ★**0** |
| **깊이 36층 + `attn_group 4`** | +0.0072 | ★**−15.9%** |

→ ★**감축과 품질은 제로섬이 아니다.** 이것이 REVIEW3 의 출발점이 됐다.
