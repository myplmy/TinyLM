## 1. 방법

| 검사 | 방법 | 한계 |
|---|---|---|
| 완전 중복 | 공백 정규화 후 문자열 동일 | — |
| ★근접 중복 | **문자 8-gram MinHash(64) + LSH(16밴드)** → 후보에만 정확 Jaccard | ⚠️**근사**. 임계 근처를 놓친다 → **하한**이다 |
| 문장 반복 | `[.!?。]` 분할, 12자 이상 문장만 | 짧은 문장은 안 센다 |
| 조사 오류 | **문장 첫머리 주어 + 조사**만 검사(용언 활용 회피) | `코알라는` 같은 **오탐 2건** 확인됨 |
| 토큰 추정 | UTF-8 바이트 ÷ **4.366**(결과 053 §S1.7.4 실측) | 🚫**영문 코퍼스에서 잰 값**이다. 한국어 실측이 없다 |

🚫**이 검토는 "좋은 데이터인가" 를 판정하지 않는다.** **세는 것만** 했다.

## 3. 🚫고쳐야 할 것 — **넷. 심각도 순**

### 3.1 ★★★**val v04 만 스키마가 다르다** — 가장 심각

| 파일 | 레코드 | `type` | 필드 |
|---|---:|---|---|
| `val_add_150_v01` | 150 | `identity_packet` | `id · text · concepts · relations · type` |
| `val_add_150_v02` | 150 | `identity_packet` | 〃 |
| `val_add_150_v03` | 150 | `identity_packet` | 〃 |
| 🚫**`val_add_150_v04`** | **150** | 🚫**`identity_classification`** | 🚫**`id · prompt · answer · difficulty · key_relations · split`** |

🚫**v04 에는 `text` 필드가 없다.** 예:

```json
{"id": "S1-IDV-0451", "type": "identity_classification", "difficulty": 2, "split": "val",
 "prompt": "다음 개념을 대상·정체성·분류 관점에서 설명하시오: 의복",
 "answer": "사람이 몸에 착용해 신체를 덮거나 보호하거나 꾸미는 물품의 범주다. …",
 "key_relations": ["is_a", "boundary", "classification"]}
```

★**무엇이 문제인가**

| 시나리오 | 결과 |
|---|---|
| val 로더가 `text` 를 읽는다 | 🚫**150건(25%)이 조용히 빠진다.** val 크기가 450 으로 줄고 **아무도 모른다** |
| `prompt + answer` 를 이어 붙인다 | 🚫**train 과 분포가 다르다** — train 은 평서문 packet, v04 는 지시문+답변. **val 손실이 다른 것을 잰다** |

> ⚠️★**결과 031·059 가 지불한 실패 양식**이다 — *"조용한 무동작"*.
> **v04 를 그대로 두면 val 셋이 두 종류가 섞인 채로 학습이 돈다.**

★**권고(택 1)**
1. ✅**v04 를 별도 폴더로 분리**하고 이름에 목적을 적는다(`val_qa/`) — **가장 값싸다**
2. v04 를 `text` 스키마로 변환한다(`prompt` 는 버리고 `answer` 를 `text` 로) — **분포는 여전히 다르다**
3. v04 를 v01~v03 과 같은 방식으로 **재생성**한다 — 가장 깨끗하지만 비용이 있다

### 3.2 ★★**`train_add_150_v20.json` 이 250건이고 id 100개가 중복**

| | |
|---|---|
| 레코드 | **250** (다른 40파일은 전부 150) |
| 고유 id | **150** — `S1-IDH-2951~3100` |
| 중복 | **`S1-IDH-3001~3100` 이 각각 2건** |
| 내용 | ★**두 레코드의 `text` 가 다르다** → **내용 중복이 아니라 id 부여 오류**다 |

```
S1-IDH-3001 | 도움 요청은 다른 주체에게 어떤 문제나 필요를 해결하기 위한 지원을 요구하는 …
S1-IDH-3001 | 둘 이상의 주체가 협력의 역할과 조건을 정한 합의다이다. 이 개념은 …
```

★**원인 추정**: **두 배치가 한 파일에 합쳐졌고 뒤 100건이 앞의 번호를 다시 썼다.**
전체 id 범위가 1~6100 으로 **빈 번호가 없으므로**, 뒤 100건은 **6101~6200 을 받아야 한다.**

★**권고**: v20 의 뒤 100건에 **`S1-IDH-6101~6200` 을 부여**하거나 **별도 파일로 분리**한다.
🚫**레코드를 지우지 않는다** — 내용은 유효하다.

### 3.3 ★**`이다이다` 44건 — 전부 v20**

```
… 여러 주체가 함께 사용하거나 관리하는 자원이다이다. 이 개념은 …
… 둘 이상의 주체가 서로 정보를 주고받는 상호작용이다이다. 이 개념은 …
```

**서술어가 두 번 붙었다**(`{정의}이다` + `이다`). 생성 템플릿이 이미 `~이다`로 끝나는 정의문에
`이다` 를 한 번 더 붙인 것으로 보인다. ★**44건 전부 v20** — 3.2 와 같은 파일이다.

### 3.4 **조사 오류 28건 (0.35%)** — 주로 v31

문장 첫머리 **주어 + 조사** 8,096건 중:

| 조사 | 오용 | 예 |
|---|---:|---|
| `은` (받침 필요) | **17** | `집하은` · `통근자은` · `중지은` · `추가은` · `정리은` |
| `이라는` (받침 필요) | **10** | `홍수이라는` · `산사태이라는` · `한파이라는` · `낙뢰이라는` · `붕괴이라는` |
| `는` (받침 없어야) | **1** | `시장는` |
| ~~`라는`~~ | ~~2~~ | ⚠️**오탐**(`코알라` + `는` 을 `코알` + `라는` 으로 잘랐다) |

★**영향 파일 7개 / 41** — `v31` 20건 · `v15` 3건 · `v12`·`v18` 각 2건 · 나머지 1건씩.
**0.35% 라 학습을 망치지는 않지만**, ★**같은 템플릿이 만든 조직적 오류**라 고치면 한 번에 사라진다.

## 4. ⚠️판단이 갈리는 것 — **결함일 수도, 설계일 수도**

### 4.1 **근접중복 40쌍** — 템플릿 치환

```
0.711  지진은 자연재난의 한 사례다. 지진이라는 사건이나 상태와 그것을 일으킬 수 있는 위험원, …
       낙뢰은 자연재난의 한 사례다. 낙뢰이라는 사건이나 상태와 그것을 일으킬 수 있는 위험원, …
```

**v31 한 파일이 거의 전부**다. 주어만 바꾼 같은 문장 틀이 십수 개.

| 관점 | 판단 |
|---|---|
| ✅**설계라면** | *"같은 관계 패턴을 여러 대상에 적용"* 은 **일반화 학습에 유리**할 수 있다 |
| 🚫**결함이라면** | **정보량이 낮다.** 같은 예산으로 다른 개념을 담을 수 있었다 |

★**우리가 답할 수 없다** — **작성자의 의도가 정본**이다. 다만 ⚠️**40쌍이 한 파일에 몰려 있다**는 것은
*"의도적 패턴"* 보다 *"그 배치를 그렇게 생성했다"* 에 가깝다.

### 4.2 **보일러플레이트 한 문장이 100회**

```
×100  이 개념은 참여하는 주체나 관련 대상 자체와 구분되며, 관계의 구조 또는 상호작용 방식을 나타낸다.
```

**전부 v20.** 나머지 반복은 **2회짜리 21종뿐**(잉여 총 120문장 = 전체 문장의 **0.93%**).
→ ★**v20 을 고치면 문장 반복 문제가 사실상 사라진다.**

### 4.3 ⚠️**`relations` 어휘 1,906종 중 55.6%(1,060종)가 1회만 등장**

상위: `is_a` 3,304 · `boundary` 1,990 · `concept_boundary` 453 · `contrast` 430 · `function` 424 ·
`subclass_of` 416 · `process` 358 · `classification` 315.

🚫★**held-out v2.1 은 관계 어휘를 130종 → 42+10종으로 정리했는데 train 은 안 됐다.**
**두 셋의 관계 어휘가 다른 규약을 쓰고 있다.**

| 영향 | |
|---|---|
| **LM 학습만 한다면** | ⚠️영향 없음 — `relations` 는 텍스트에 안 들어간다 |
| ★**관계를 평가지표로 쓴다면** | 🚫**train 의 1,906종과 val 의 규약이 안 맞는다** → 그 지표는 못 쓴다 |

### 4.4 **val `concepts` 696종 중 45.0%(313종)가 train 과 겹친다**

**일반 val 로는 정상**(같은 분포를 재는 것이 목적)이지만,
🚫**"unseen concept 일반화" 를 재려면 이 셋으로는 못 한다.** 그건 `held-out_v2.1` 의 일이다.

## 5. ★분량 판정 — **필드 결정이 선결이다**

★★**권고**: `scripts/prepare` 경로로 **실제 토크나이저를 한 번 돌려** 확정한다(GPU 0, ⚙2분).

⚠️**val 비중**: 레코드 기준 **8.8%**, 토큰 기준 **5.9~7.7%**. 목표(54/540 = 10%)보다 **약간 작다**.

### 8.1 ★내가 직접 고친 8건 (지시 3 — *"문장 확인하여 직접 수정바람"*)

전부 **문장 첫머리 주어 + 조사** 한 가지 유형이었다(종성 유무 판정 오류).

### 11.1 🚫**먼저 하지 말아야 할 것 — 메타데이터를 학습 스트림에 붙이지 않는다**

🚫**조치 전후의 val 을 직접 비교하면 안 된다**(함정 2). ★**조치 시점을 문서에 박아 둔다.**
